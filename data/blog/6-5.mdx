## 1. Health 클래스 설계 방향

- 이미 **EnemyHealth(적 체력 클래스)** 가 존재.
- 플레이어도 체력 로직이 필요하지만, 다음과 같은 이유로 **분리하는 것**이 합리적임:
  - **플레이어**: 체력 UI, 입력 제어, 무기 등과 밀접하게 연결됨.
  - **적**: 자폭, 남은 적 수 카운트, AI 이동 등 추가 로직 포함.
- 따라서 **EnemyHealth.cs** 와 **PlayerHealth.cs** 를 별도로 관리.

---

## 2. 플레이어 전용 Health 스크립트 작성

```csharp
public class PlayerHealth : MonoBehaviour
{
    [SerializeField] int startingHealth = 5;  // 초기 체력 (인스펙터에서 조정 가능)
    int currentHealth;

    void Awake()
    {
        currentHealth = startingHealth;  // 게임 시작 시 체력 초기화
    }

    public void TakeDamage(int amount)
    {
        currentHealth -= amount;
        if (currentHealth <= 0)
        {
            Destroy(gameObject); // 체력이 0 이하일 때 플레이어 삭제
        }
    }
}
```

- `Awake()`에서 **체력 초기화**.
- `TakeDamage()` 메서드: **피해 누적 → 0 이하 시 캐릭터 삭제**.
- 적 체력 클래스와 구조가 비슷하지만, **자폭 기능은 제외**.

## 3. Explosion 클래스에서 Physics.OverlapSphere 활용

- **Physics.OverlapSphere**:
  - Unity 물리엔진에서 제공하는 메서드로, **구 형태의 영역(원구체)** 안에 들어있는 모든 **Collider**를 탐지.
  - 결과값은 `Collider[]` 배열로 반환 → 이 배열을 순회(for-each)하면서 원하는 대상(플레이어, 적 등)을 판별.

---

### 🔹 기본 사용법

```csharp
Collider[] hitColliders = Physics.OverlapSphere(transform.position, radius);
```

- **매개변수**:
  - `transform.position`:
    - 폭발(또는 중심점)이 발생한 **월드 좌표 위치**.
    - 여기서는 폭발 오브젝트(Explosion)의 위치.
  - `radius`:
    - 폭발 범위를 결정하는 **반지름 값**.
    - 반지름이 클수록 더 넓은 범위의 Collider를 탐지.

---

### 🔹 반환값

- **Collider[] hitColliders**
  - `OverlapSphere`는 단일 값이 아니라, **Collider의 배열**을 반환.
  - 예:
    - 폭발 반경 안에 플레이어 1명 + 박스 2개 + 벽 1개 → 총 4개의 Collider 반환.
  - 따라서 **루프를 돌며** 각각의 Collider가 무엇인지 판별해야 함.

---

### 🔹 활용 방식

1. 폭발 반경 안에 있는 **모든 Collider 가져오기**.
2. 각 Collider가 **플레이어인지 검사**.
3. 플레이어일 경우, `GetComponent<PlayerHealth>()` 를 통해 PlayerHealth 스크립트 접근.
4. `TakeDamage(damage)` 실행하여 피해 적용.

- Explosion 스크립트:

```csharp
public class Explosion : MonoBehaviour
{
    [SerializeField] float radius = 1.5f;
    [SerializeField] int damage = 3;

    void Start()
    {
        Explode();
    }

    void OnDrawGizmos()
    {
        Gizmos.color = Color.red;
        Gizmos.DrawWireSphere(transform.position, radius); // Scene 뷰에서 폭발 반경 확인 가능
    }

    void Explode()
    {
        Collider[] hitColliders = Physics.OverlapSphere(transform.position, radius);

        foreach (Collider hitCollider in hitColliders)
        {
            PlayerHealth playerHealth = hitCollider.GetComponent<PlayerHealth>();
            if (playerHealth != null)
            {
                playerHealth.TakeDamage(damage); // 플레이어에게 피해 전달
            }
        }
    }
}
```

👉 즉, `Physics.OverlapSphere`는 **폭발/스킬 범위 판정**, **근접 공격**, **AOE(범위 공격)** 같은 시스템을 만들 때 핵심적으로 사용되는 함수입니다.

- `OverlapSphere`는 **유지시간 개념이 없고 즉발 판정**만 한다. ( 1 프레임 )
- 지속적인 범위를 원한다면 → **Trigger Collider** 또는 **주기적 OverlapSphere 호출**로 구현해야 한다.

## 4. for-each 루프와 continue/break 키워드 활용

- **for-each 루프**: `OverlapSphere`로 얻은 콜라이더 배열 순회.
- **continue**: 플레이어가 아니면 건너뛰고 다음 콜라이더 검사.
- **break**: 플레이어를 찾으면 바로 루프 종료 (불필요한 반복 방지).
- 예시:

  ```csharp
  foreach (Collider hitCollider in hitColliders)
  {
      PlayerHealth playerHealth = hitCollider.GetComponent<PlayerHealth>();
      if (playerHealth == null) continue;  // 플레이어 아니면 패스

      playerHealth.TakeDamage(damage);
      break; // 플레이어 찾았으니 종료
  }
  ```

## 5. 실제 플레이어 피해 반영 및 디버깅

- **테스트 설정**:
  - 플레이어 체력: `startingHealth = 5`
  - 폭발 데미지: `damage = 3`
  - → 폭발 두 번 → 플레이어 사망.
- **디버깅**:
  - `Debug.Log()` 사용해 피해량과 남은 체력 확인 가능.
  - 예시:
    ```csharp
    Debug.Log(amount + " damage taken. Current health: " + currentHealth);
    ```

## 6. 오류 정리 및 마무리

- 플레이어가 `Destroy()` 될 때 발생하는 오류들:
  1. **NavMeshAgent**: 플레이어가 없는데도 목표를 찾으려 함 → null 체크 후 return 필요.
  2. **카메라 스택 경고**: 플레이어 삭제 시 무기 카메라가 같이 파괴됨.
- 해결 방법:
  - NavMeshAgent 업데이트 시:
    ```csharp
    if (player == null) return;
    ```
  - 카메라는 후속 강의에서 별도로 정리 예정.

## ✅ 강의 핵심 요약

- **Health 클래스 분리**: EnemyHealth ↔ PlayerHealth 개별 관리.
- **Physics.OverlapSphere**: 폭발 범위 내 오브젝트 탐지 → PlayerHealth에 피해 전달.
- **for-each + continue/break**: 불필요한 연산 줄이는 효율적 루프 처리.
- **Destroy(gameObject)**: 플레이어 사망 처리 (추후 UI/리트라이 연동 가능).
- **디버깅 & 오류 처리**: NavMeshAgent, 카메라 스택 문제 해결 과정 소개.

## 1. 문제 상황: 콘솔 경고 메시지 발생

- 플레이어가 파괴될 때, **자식 오브젝트인 무기 카메라**도 함께 파괴됨.
- 이 과정에서 Unity 콘솔에 다음과 같은 경고가 뜸:
  > "카메라 오버레이가 더 이상 존재하지 않으며 카메라 오버레이 스택에서 제거될 것"

👉 원인: **무기 카메라가 플레이어에 종속(Parent)** 되어 있어, 플레이어가 Destroy되면 카메라도 함께 제거됨.

👉 해결: 플레이어가 죽기 직전에 무기 카메라의 **부모를 해제(Unparent)** 하여 독립적으로 남겨야 함.

---

## 2. 시네머신 가상 카메라 개념

- **Cinemachine Virtual Camera**는 실제 렌더링을 담당하지 않음.
- **Main Camera(메인 카메라)** 위에 `Cinemachine Brain` 컴포넌트가 붙어 있고,
  이 Brain이 "어떤 가상 카메라를 바라볼지" 선택함.
- 선택 기준: **Priority (우선순위)** 값이 높은 카메라가 활성화됨.

예시:

- 플레이어 추적 카메라 Priority = 10
- 새로 만든 죽음 카메라 Priority = 20
  → 플레이어가 죽으면 자동으로 **Death Camera**로 전환됨.

---

## 3. 새로운 "죽음 전용 카메라" 생성하기

1. `Hierarchy`에서 **Camera GameObject** 우클릭 → `Cinemachine → Virtual Camera` 생성.
2. 이름: **DeathVirtualCamera**
3. Priority 기본값은 10 → 임시로 **0**으로 낮춰서 기본 카메라에 영향 주지 않도록 설정.
4. 위치 조정: `Scene View`에서 보고 싶은 각도에서 DeathVirtualCamera 선택 후

   **GameObject → Align with View** (뷰에 맞추기) 실행.

   → 원하는 "죽음 시점 뷰"로 고정됨.

## 4. 무기 카메라(Weapon Camera) 처리

- 무기 카메라(Weapon Camera)는 플레이어의 자식으로 붙어 있음.
- 따라서 플레이어가 파괴될 때 함께 Destroy되면서 경고 발생.
- 해결 방법: **체력이 0이 되면 무기 카메라의 parent를 null로 변경**
  ```csharp
  weaponCamera.parent = null;
  ```
- 이렇게 하면 무기 카메라는 독립적으로 남아서 Unity 경고도 사라짐.

---

## 5. PlayerHealth 코드 구현

```csharp
using Cinemachine;
using UnityEngine;

public class PlayerHealth : MonoBehaviour
{
    [SerializeField] int startingHealth = 5;                 // 시작 체력
    [SerializeField] CinemachineVirtualCamera deathVirtualCamera; // 죽음 가상 카메라 참조
    [SerializeField] Transform weaponCamera;                 // 무기 카메라(Transform만 필요)

    int currentHealth;                                       // 현재 체력
    int gameOverVirtualCameraPriority = 20;                  // 죽음 카메라 우선순위

    void Awake()
    {
        currentHealth = startingHealth; // 게임 시작 시 체력 초기화
    }

    public void TakeDamage(int amount)
    {
        currentHealth -= amount;
        if (currentHealth <= 0)
        {
            // 무기 카메라 부모 해제 → 경고 방지
            weaponCamera.parent = null;

            // 죽음 카메라 우선순위 상승 → 자동 전환
            deathVirtualCamera.Priority = gameOverVirtualCameraPriority;

            // 플레이어 파괴
            Destroy(gameObject);
        }
    }
}
```

## 6. DeathVirtualCamera 설정하기

- `Inspector`에서 `PlayerHealth` 스크립트에 다음 참조 할당:

  - **DeathVirtualCamera** → 새로 만든 Death 카메라 드래그.
- DeathVirtualCamera 초기 Priority는 0.
- 코드에서 체력 0일 때 → Priority = 20 으로 변경.

## 7. 카메라 블렌딩(Blend) 설정

- 전환이 너무 딱딱하지 않도록 **부드러운 블렌드 효과** 사용.
- 방법:
  1. Main Camera 선택.
  2. `Cinemachine Brain` 컴포넌트 확인.
  3. **Default Blend** 옵션에서
     - **Style**: Ease In Out (부드럽게 전환)
     - **Time**: 2초 (전환 시간 조절 가능)

→ 죽음 순간 "부드럽게 줌 아웃"되거나 "슬로우 모션 느낌"을 줄 수 있음.

## 5. 체력 UI 반영 로직 구현하기

### (1) AdjustShieldUI 메서드

```csharp
void AdjustShieldUI()
{
    for (int i = 0; i < shieldBars.Length; i++)
    {
        if (i < currentHealth)
        {
            shieldBars[i].gameObject.SetActive(true);
        }
        else
        {
            shieldBars[i].gameObject.SetActive(false);
        }
    }
}
```

- **for 루프**로 모든 쉴드 바 확인.
- 인덱스 `i`가 현재 체력(`currentHealth`)보다 작으면 → 쉴드 활성화.
- 그렇지 않으면 → 비활성화.

### (2) Awake에서 초기화

```csharp
void Awake()
{
    currentHealth = startingHealth;
    AdjustShieldUI();
}
```

- 게임 시작 시 **현재 체력 값**을 UI에 즉시 반영.

### (3) 데미지 처리

```csharp
public void TakeDamage(int amount)
{
    currentHealth -= amount;
    AdjustShieldUI();

    if (currentHealth <= 0)
    {
        weaponCamera.parent = null;
        deathVirtualCamera.Priority = gameOverVirtualCameraPriority;
        Destroy(gameObject);
    }
}
```

- 체력 감소 시 → UI 갱신.
- 체력이 0 이하 → 사망 처리 (무기 카메라 분리, 사망 카메라 우선순위 상승, Player 오브젝트 파괴).

## 6. SpawnGate 스크립트 작성하기

```csharp
using System.Collections;
using UnityEngine;

public class SpawnGate : MonoBehaviour
{
    [SerializeField] GameObject robotPrefab;   // 생성할 로봇 프리팹
    [SerializeField] float spawnTime = 5f;     // 생성 주기 (초 단위)
    [SerializeField] Transform spawnPoint;     // 적 생성 위치

    PlayerHealth player;

    void Start()
    {
        // 게임 내 플레이어의 Health 컴포넌트 참조
        player = FindAnyObjectByType<PlayerHealth>();
        StartCoroutine(SpawnRoutine());
    }

    IEnumerator SpawnRoutine()
    {
        // 플레이어가 살아 있는 동안에만 실행
        while (player)
        {
            Instantiate(robotPrefab, spawnPoint.position, spawnPoint.rotation);
            yield return new WaitForSeconds(spawnTime);
        }
    }
}
```

- **핵심 개념**:
  - `IEnumerator` + `Coroutine` → 일정 시간 간격으로 반복 실행.
  - `Instantiate()` → 프리팹 생성.
  - `yield return new WaitForSeconds(spawnTime)` → 주기 제어.
  - `while (player)` → PlayerHealth 존재 여부가 true일 때만 반복.

## 4. 사용자 정의 폰트 가져오기 (Font Asset Creator)

- 절차:
  1. **Dafont.com** 같은 사이트에서 마음에 드는 폰트를 **OTF/TTF 형식**으로 다운로드.

## 1. C# 삼항 연산자 개념 이해하기

- **정의**: `조건 ? 참일때값 : 거짓일때값`
- 간단한 `if else` 문을 **한 줄**로 표현하는 방식.
- 기본 구문:
  ```csharp
  result = condition ? resultIfTrue : resultIfFalse;
  ```
- 예제:
  ```csharp
  int score = 80;
  string grade = (score >= 60) ? "Pass" : "Fail";
  ```
  → `score`가 60 이상이면 `"Pass"`, 아니면 `"Fail"`
- **장점**: 간결하고, 특정 조건에 따라 값을 빠르게 대입할 수 있음.
- **단점**: 복잡하게 중첩하면 가독성이 떨어짐 → 실무에서는 *“읽기 쉬운 코드”*가 더 중요.

---

## 2. Starter Assets Inputs 클래스 살펴보기

- Unity Starter Assets 패키지 안에 있는 입력 처리 클래스.
- 여기서 **SetCursorState**라는 메소드가 정의되어 있음.
- 이 메소드는 게임 플레이 시 마우스를 숨기거나 표시하는 역할을 담당.
- 실제로는 Unity의 내장 메소드 **OnApplicationFocus**에서 사용됨.

---

## 3. SetCursorState 메소드 분석

- 이 메소드는 **bool 값(newState)** 을 받아서 커서 상태를 제어.
- 코드 동작:
  ```csharp
  Cursor.lockState = newState ? CursorLockMode.Locked : CursorLockMode.None;
  ```
- 의미:
  - `newState == true` → 커서 숨기기 (화면 중앙에 고정, FPS 게임 스타일)
  - `newState == false` → 기본 운영체제 커서 표시

---

## 4. 삼항 연산자 → if else 리팩토링 연습

- 강의에서 직접 삼항 연산자를 **if else 문으로 풀어보는 연습**을 제시.
- 변환 예시:
  **삼항 연산자**
  ```csharp
  Cursor.lockState = newState ? CursorLockMode.Locked : CursorLockMode.None;
  ```
  **if else**
  ```csharp
  if (newState)
  {
      Cursor.lockState = CursorLockMode.Locked;
  }
  else
  {
      Cursor.lockState = CursorLockMode.None;
  }
  ```
- 결론: 두 코드는 **동일한 동작**을 하며, 가독성/취향에 따라 선택 가능.

## 5. Game Over UI 표시하기

- 게임에서 플레이어가 죽을 경우 → **Game Over Container UI**를 활성화해야 함.
- 절차:
  1. `PlayerHealth` 클래스에 **GameObject 변수** `gameOverContainer` 추가.
  2. 유니티 에디터에서 Overlay Canvas 안의 Game Over Container를 **참조 연결**.
  3. 게임 시작 시에는 이 오브젝트를 **비활성화(SetActive(false))**.
  4. 플레이어가 죽는 순간(`GameOver` 메소드 호출 시) → `.SetActive(true)`로 전환.

## 6. PlayerHealth 클래스의 GameOver 메소드 구현

- 강의에서 보여준 최종 코드 (요약):

```csharp
private void GameOver()
{
    // 무기 카메라를 부모에서 분리
    weaponCamera.parent = null;

    // 사망 시 시네머신 카메라 우선순위 변경
    deathVirtualCamera.Priority = gameOverVirtualCameraPriority;

    // Game Over UI 표시
    gameOverContainer.SetActive(true);

    // 플레이어 캐릭터 제거
    Destroy(gameObject);
}
```

- 핵심 흐름:
  - 플레이어 죽음 → 무기 카메라 분리 → Game Over 카메라 활성화 → Game Over UI 표시 → 플레이어 파괴

## 7. 실행 테스트와 마우스 문제

  2. 게임 실행 → 플레이어 죽음.

## 1. 테스트 환경 준비하기

- **디버깅 편의를 위해 적 캐릭터(로봇, 터렛 등)를 비활성화**.
- Hierarchy에서 `Game Over Container`를 **강제로 활성화** → 버튼 테스트 가능.
- 실행 후 확인:
  - 버튼 클릭 시 **커서만 숨겨지고 버튼이 작동하지 않음** → 문제 발생 원인 확인 필요.

---

## 2. 이벤트 시스템(Event System) 다시 생성하기

- **버튼이 작동하지 않는 이유**:
  프로젝트 초기에 UI 캔버스 생성 시 자동으로 만들어졌던 **Event System**을 지워버렸기 때문.
- 해결 방법:
  - `Overlay Canvas`에서 우클릭 → **Create → UI → Event System** 생성.
  - Event System은 **계층 구조 어디에 있든 상관 없음**.
- 새 Event System은 **Unity New Input System**과 연동되어 자동으로 Input Module 포함.

---

## 3. 커서(Cursor) 상태 제어하기

- 버튼이 여전히 클릭 불가 → 이유:
  - `StarterAssetsInput` 클래스 안에서 **커서 잠금 모드(lock)**가 기본으로 `true` (숨김).
- 해결:
  - `StarterAssetsInput` 열기.
  - `OnApplicationFocus()` 안의 커서 제어 코드를 **비활성화(주석 처리)**.
  - 테스트 시 커서가 표시되도록 조정.

추가 수정:

- `SetCursorState(bool)` 메소드를 `public`으로 변경 → 다른 클래스에서도 제어 가능.
- `Start()` 메소드에서 `SetCursorState(true)` 실행 → 게임 시작 시 자동으로 커서 숨김.

## 4. GameManager 스크립트 만들기

### 준비 과정

1. 빈 게임 오브젝트 생성 → 이름: `Game Manager`.
2. `Scripts` 폴더 안에 **Misc 폴더** 생성.
3. `GameManager.cs` 스크립트 생성 후 `Game Manager` 오브젝트에 추가.

### GameManager.cs 코드

```csharp
using UnityEngine;
using UnityEngine.SceneManagement;

public class GameManager : MonoBehaviour
{
    // 🔄 재시작 버튼 동작
    public void RestartLevelButton()
    {
        int currentScene = SceneManager.GetActiveScene().buildIndex;
        SceneManager.LoadScene(currentScene);
    }

    // ❌ 종료 버튼 동작
    public void QuitButton()
    {
        Application.Quit();

        // 유니티 에디터에서는 종료 안 됨 → 경고 표시
        Debug.LogWarning("Application.Quit은 에디터에서 작동하지 않습니다!");
    }
}
```

📌 핵심 포인트

- `RestartLevelButton()` → 현재 씬의 buildIndex를 불러와 다시 로드.
- `QuitButton()` → 실제 빌드된 게임 실행 시만 작동. (에디터에서는 `Debug.LogWarning` 출력).

## 2. 승리 UI(TextMeshPro) 구성하기

### (1) "You Win" 텍스트 UI 만들기

- 목적: 플레이어가 승리했음을 알리는 단순 메시지.
- 구현 방법:
  - **Canvas (Overlay 모드)** 안에 `UI → Text - TextMeshPro` 추가.
  - 이름: `"You Win Text"`.
  - 텍스트 필드 값: `"YOU WIN!"`.
  - **폰트**: 프로젝트에서 사용 중인 커스텀 폰트 에셋.
  - **폰트 크기**: 크고 강조되도록 크게 설정.
  - **Wrapping**: 끄기 (`Text Wrapping Mode → No Wrap`).
  - **위치**: 화면 중앙 근처, 단 약간 위쪽으로 배치 → 크로스헤어를 가리지 않게.
  - **초기 상태**: 비활성화(`SetActive(false)`), 승리 시에만 표시.

## 3. GameManager에서 승리 조건 관리하기

### (1) 변수와 참조 준비

```csharp
[SerializeField] TMP_Text enemiesLeftText;  // 남은 적 수 UI 참조
[SerializeField] GameObject youWinText;     // 승리 텍스트 UI 참조

int enemiesLeft = 0; // 현재 남은 적 수 추적
const string ENEMIES_LEFT_STRING = "Enemies Left: ";
```

### (2) 적 수 조정 메서드 `AdjustEnemiesLeft`

- 적이 생성될 때 +1, 사망할 때 -1 적용.
- 남은 적 수를 `TMP_Text`에 즉시 반영.

```csharp
public void AdjustEnemiesLeft(int amount)
{
    enemiesLeft += amount;
    enemiesLeftText.text = ENEMIES_LEFT_STRING + enemiesLeft.ToString();

    if (enemiesLeft <= 0)
    {
        youWinText.SetActive(true);                 // 승리 UI 표시
        enemiesLeftText.gameObject.SetActive(false); // 카운트는 숨김
    }
}
```

### (3) 승리 시 동작

- `"YOU WIN!"` 메시지를 활성화.
- `"Enemies Left Text"`는 비활성화.

## 4. EnemyHealth에서 적 카운트 연동하기

### (1) 적 생성 시 카운트 증가

- `Start()`에서 GameManager를 찾아서 호출:

```csharp
void Start()
{
    gameManager = FindFirstObjectByType<GameManager>();
    if (gameManager != null)
    {
        gameManager.AdjustEnemiesLeft(1); // 적이 하나 생성될 때 +1
    }
}
```

### (2) 적 사망 시 카운트 감소

- `TakeDamage()`에서 체력이 0 이하일 때:

```csharp
if (currentHealth <= 0)
{
    gameManager.AdjustEnemiesLeft(-1); // 적이 죽을 때 -1
    SelfDestruct();
}
```

## 1. 데미지 효과의 개념과 중요성

### 🎮 데미지 피드백이란?

- **데미지 피드백(Damage Feedback)**: 플레이어가 공격을 받았을 때 시각적, 청각적으로 알려주는 효과
- 게임에서 매우 중요한 이유:
  - 플레이어가 **즉각적으로 위험을 인지**할 수 있음
  - 게임의 **몰입감과 긴장감**을 높임
  - 공격의 **강도와 중요도**를 전달

### 📱 이 강의에서 구현할 두 가지 효과

1. **화면 흔들림 (Screen Shake)**
   - 카메라가 짧은 시간 동안 불규칙하게 떨림
   - 충격의 느낌을 직관적으로 전달
   - Cinemachine의 Noise 기능 사용
2. **붉은 번쩍임 (Red Flash)**
   - 화면 전체가 순간적으로 붉게 빛남
   - 데미지를 받았다는 것을 색상으로 표현
   - UI Image를 전체 화면에 오버레이

## 2. Cinemachine 화면 흔들림 설정하기

### 🎥 Cinemachine이란?

- Unity의 **고급 카메라 시스템**
- 영화같은 카메라 움직임을 쉽게 구현
- Virtual Camera를 통해 다양한 카메라 효과 적용 가능

### ⚙️ Noise 컴포넌트 추가하기

**1단계: Virtual Camera 선택**

- Hierarchy에서 Player Virtual Camera 오브젝트 선택
- 이 카메라가 플레이어를 따라다니는 메인 카메라입니다

**2단계: Noise 컴포넌트 추가**

- Inspector 하단의 **Add Extension** 버튼 클릭
- `CinemachineBasicMultiChannelPerlin` 선택
  - **Perlin Noise**: 자연스러운 무작위 움직임을 만드는 수학적 알고리즘
  - **Multi Channel**: 여러 방향(X, Y, Z)으로 동시에 흔들림

**3단계: Noise Profile 설정**

- Noise 섹션에서 **Noise Profile** 드롭다운 클릭
- `6D Shake` 프로필 선택
  - **6D**: 위치(X, Y, Z) + 회전(X, Y, Z) 총 6개 축 흔들림
  - 가장 자연스럽고 다이나믹한 흔들림 효과

### 📊 Noise의 주요 속성 이해하기

- **Amplitude Gain (진폭 이득)**
  - 흔들림의 **강도(세기)** 조절
  - 값이 클수록 더 크게 흔들림
  - 코드에서 동적으로 조절: 0 = 흔들림 없음, 1.2 = 중간 강도
- **Frequency Gain (주파수 이득)**
  - 흔들림의 **속도(빠르기)** 조절
  - 값이 클수록 더 빠르게 떨림
  - 2.0 = 빠른 진동 느낌

> 💡 팁: 게임이 실행 중일 때는 이 값들이 0으로 설정되어 있어야 합니다. 데미지를 받을 때만 코드로 일시적으로 값을 높입니다.

## 5. 코루틴으로 효과 제어하기

### ⏱️ 코루틴(Coroutine)이란?

- **여러 프레임에 걸쳐** 실행되는 함수
- 일반 함수는 한 프레임에 모두 실행되지만, 코루틴은 중간에 멈췄다가 다음 프레임에 계속 실행
- `yield return null;`을 만나면 다음 프레임까지 대기
- 시간에 따라 변하는 효과(페이드, 애니메이션)에 적합

### 🎬 TakeDamage()에서 코루틴 시작

```csharp
public void TakeDamage(int amount)
{
    currentHealth -= amount;
    AdjustShieldUI();

    // 데미지 효과 실행
    StartCoroutine(DamageEffectCoroutine());

    if (currentHealth <= 0)
    {
        GameOver();
    }
}

```

**StartCoroutine()의 역할:**

- 코루틴 함수를 **비동기적으로** 시작
- TakeDamage()는 즉시 종료되지만 효과는 별도로 계속 진행
- 여러 번 데미지를 받으면 여러 개의 효과가 동시에 실행될 수 있음

### 🔄 DamageEffectCoroutine() 상세 분석

```csharp
IEnumerator DamageEffectCoroutine()
{
    // 1단계: 효과 즉시 시작
    if (noise != null)
    {
        noise.m_AmplitudeGain = shakeAmplitude;
        noise.m_FrequencyGain = shakeFrequency;
    }

    if (damageFlashImage != null)
    {
        damageFlashImage.color = new Color(1, 0, 0, flashColor.a);
    }

```

**효과 시작 부분:**

- **화면 흔들림**: Amplitude와 Frequency를 즉시 최댓값으로 설정
- **붉은 번쩍임**: Alpha를 즉시 설정한 값(0.5)으로 변경
- 둘 다 **동시에** 시작되어 강력한 충격 느낌

```csharp
    float elapsed = 0f;
    float maxDuration = Mathf.Max(shakeDuration, flashDuration);

    while (elapsed < maxDuration)
    {
        elapsed += Time.deltaTime;

```

**시간 추적:**

- `elapsed`: 코루틴 시작 후 경과 시간
- `Time.deltaTime`: 이전 프레임과 현재 프레임 사이의 시간 (약 0.016초 @ 60FPS)
- `maxDuration`: 흔들림과 번쩍임 중 더 긴 시간 사용
- `while 루프`: 최대 시간까지 계속 반복

```csharp
        // 화면 흔들림 점진적 감소
        if (elapsed < shakeDuration && noise != null)
        {
            float shakeProgress = elapsed / shakeDuration;
            noise.m_AmplitudeGain = Mathf.Lerp(shakeAmplitude, 0, shakeProgress);
        }
        else if (noise != null)
        {
            noise.m_AmplitudeGain = 0;
        }

```

**흔들림 감소 로직:**

- `shakeProgress`: 0 → 1로 증가하는 진행도 (0% → 100%)
- `Mathf.Lerp(시작값, 끝값, 진행도)`: 선형 보간 함수
  - 진행도 0일 때 → 시작값 (shakeAmplitude)
  - 진행도 1일 때 → 끝값 (0)
  - 중간값은 부드럽게 변화
- 예시: 0초 = 1.2 강도, 0.15초 = 0.6 강도, 0.3초 = 0 강도
- **시간 초과 시**: 완전히 0으로 설정하여 확실히 멈춤

```csharp
        // 붉은 번쩍임 페이드아웃
        if (elapsed < flashDuration && damageFlashImage != null)
        {
            float flashProgress = elapsed / flashDuration;
            float alpha = Mathf.Lerp(flashColor.a, 0, flashProgress);
            damageFlashImage.color = new Color(1, 0, 0, alpha);
        }
        else if (damageFlashImage != null)
        {
            damageFlashImage.color = new Color(1, 0, 0, 0);
        }

```

**번쩍임 페이드아웃:**

- 색상은 빨강으로 유지, **Alpha만 감소**
- `flashProgress`: 0 → 1로 증가
- Alpha: 0.5 → 0으로 부드럽게 감소
- 완전 투명(0)이 되면 화면에서 사라짐
- **시간 초과 시**: Alpha를 0으로 설정하여 완전히 숨김

```csharp
        yield return null;
    }

    // 확실하게 초기화
    if (noise != null)
    {
        noise.m_AmplitudeGain = 0;
    }
    if (damageFlashImage != null)
    {
        damageFlashImage.color = new Color(1, 0, 0, 0);
    }
}

```

**마무리 작업:**

- `yield return null`: 다음 프레임까지 대기 후 while 루프 재실행
- **루프 종료 후 초기화**: 혹시 모를 오차를 방지하기 위해 확실하게 0으로 설정
- 코루틴 종료 후 다음 데미지 준비 완료

### 🎯 효과의 타이밍 흐름

```
시간 →
0.00초: [번쩍] 흔들림 최대(1.2) + 빨강 최대(0.5 Alpha)
0.08초: 흔들림 중간(0.6) + 빨강 거의 사라짐(0.2 Alpha)
0.15초: 흔들림 약함(0.2) + 빨강 완전 사라짐(0 Alpha)
0.30초: 흔들림 완전 종료(0) + 효과 종료

```

```csharp
using System;
using System.Collections;
using Cinemachine;
using StarterAssets;
using UnityEngine;
using UnityEngine.UI;

public class PlayerHealth : MonoBehaviour
{
    [Range(1, 10)]
    [SerializeField] int startingHealth = 5;
    [SerializeField] CinemachineVirtualCamera deathVirtualCamera;
    [SerializeField] Transform weaponCamera;
    [SerializeField] Image[] shieldBars;
    [SerializeField] GameObject gameOverContainer;

    [Header("Damage Effects")]
    [SerializeField] CinemachineVirtualCamera playerVirtualCamera;
    [SerializeField] float shakeDuration = 0.3f;
    [SerializeField] float shakeAmplitude = 1.2f;
    [SerializeField] float shakeFrequency = 2.0f;
    [SerializeField] Image damageFlashImage;
    [SerializeField] float flashDuration = 0.15f;
    [SerializeField] Color flashColor = new Color(1, 0, 0, 0.5f); // 더 진한 빨강

    int currentHealth;
    int gameOverVirtualCameraPriority = 20;
    CinemachineBasicMultiChannelPerlin noise;

    void Awake()
    {
        currentHealth = startingHealth;
        AdjustShieldUI();

        // Cinemachine Noise 컴포넌트 가져오기
        if (playerVirtualCamera != null)
        {
            noise = playerVirtualCamera.GetCinemachineComponent<CinemachineBasicMultiChannelPerlin>();
        }

        // 데미지 플래시 이미지 초기화
        if (damageFlashImage != null)
        {
            damageFlashImage.color = new Color(1, 0, 0, 0);
            damageFlashImage.raycastTarget = false;
        }
    }

    void AdjustShieldUI()
    {
        for (int i = 0; i < shieldBars.Length; i++)
        {
            if (i < currentHealth)
            {
                shieldBars[i].gameObject.SetActive(true);
            }
            else
            {
                shieldBars[i].gameObject.SetActive(false);
            }
        }
    }

    public void TakeDamage(int amount)
    {
        currentHealth -= amount;
        AdjustShieldUI();

        // 데미지 효과 실행
        StartCoroutine(DamageEffectCoroutine());

        if (currentHealth <= 0)
        {
            GameOver();
        }
    }

    IEnumerator DamageEffectCoroutine()
    {
        // 화면 흔들림 시작
        if (noise != null)
        {
            noise.m_AmplitudeGain = shakeAmplitude;
            noise.m_FrequencyGain = shakeFrequency;
        }

        // 화면 붉게 번쩍임 (즉시 최대 밝기)
        if (damageFlashImage != null)
        {
            damageFlashImage.color = new Color(1, 0, 0, flashColor.a);
        }

        float elapsed = 0f;
        float maxDuration = Mathf.Max(shakeDuration, flashDuration);

        while (elapsed < maxDuration)
        {
            elapsed += Time.deltaTime;

            // 화면 흔들림 감소
            if (elapsed < shakeDuration && noise != null)
            {
                float shakeProgress = elapsed / shakeDuration;
                noise.m_AmplitudeGain = Mathf.Lerp(shakeAmplitude, 0, shakeProgress);
            }
            else if (noise != null)
            {
                noise.m_AmplitudeGain = 0;
            }

            // 붉은 화면 빠르게 페이드아웃
            if (elapsed < flashDuration && damageFlashImage != null)
            {
                float flashProgress = elapsed / flashDuration;
                float alpha = Mathf.Lerp(flashColor.a, 0, flashProgress);
                damageFlashImage.color = new Color(1, 0, 0, alpha);
            }
            else if (damageFlashImage != null)
            {
                damageFlashImage.color = new Color(1, 0, 0, 0);
            }

            yield return null;
        }

        // 확실하게 초기화
        if (noise != null)
        {
            noise.m_AmplitudeGain = 0;
        }
        if (damageFlashImage != null)
        {
            damageFlashImage.color = new Color(1, 0, 0, 0);
        }
    }

    private void GameOver()
    {
        weaponCamera.parent = null;
        deathVirtualCamera.Priority = gameOverVirtualCameraPriority;
        gameOverContainer.SetActive(true);
        StarterAssetsInputs starterAssetsInputs = FindFirstObjectByType<StarterAssetsInputs>();
        starterAssetsInputs.SetCursorState(false);
        Destroy(gameObject);
    }
}
```

## 1. 기존 코드의 문제점 파악하기

### 기존 코드 분석

```csharp
void OnTriggerEnter(Collider other)
{
    if (other.CompareTag(PLAYER_STRING))
    {
        ActiveWeapon activeWeapon = other.GetComponentInChildren<ActiveWeapon>();
        OnPickup(activeWeapon);
        Destroy(gameObject); // 문제가 되는 부분
    }
}
```

### 문제점

- **`Destroy(gameObject)`** 사용 시:
  - 픽업 아이템이 완전히 파괴되어 게임에서 영구적으로 사라짐
  - 다시 나타나게 하려면 새로운 오브젝트를 생성해야 함 (비효율적)
  - 오브젝트 풀링이나 리스폰 시스템 구현이 불가능

### 개선 방향

- 오브젝트를 파괴하지 않고 **재사용**하는 방식으로 변경
- 플레이어가 획득하면 **일시적으로 비활성화**
- **일정 시간 후 자동으로 재활성화**되어 다시 획득 가능하게 만들기

## 2. 리스폰 시스템 개념 이해하기

### 리스폰(Respawn)이란?

- **Respawn** = Re(다시) + Spawn(생성/출현)
- 게임에서 아이템, 적, 플레이어 등이 다시 나타나는 시스템
- 대부분의 멀티플레이어 게임이나 오픈월드 게임에서 사용하는 핵심 메커니즘

### 픽업 리스폰의 동작 흐름

```
1. 플레이어가 픽업 아이템에 접근
   ↓
2. 트리거 충돌 감지 (OnTriggerEnter)
   ↓
3. 픽업 효과 적용 (OnPickup 호출)
   ↓
4. 아이템 비활성화 (보이지 않음 + 충돌 불가)
   ↓
5. 설정된 시간만큼 대기 (respawnTime)
   ↓
6. 아이템 재활성화 (다시 보임 + 충돌 가능)
   ↓
7. 다시 획득 가능한 상태로 복귀

```

### 필요한 변수

```csharp
[SerializeField] float respawnTime = 5f;
```

- **respawnTime**: 아이템이 다시 나타나기까지 걸리는 시간 (초 단위)
- **SerializeField**: Unity Inspector에서 값을 조절할 수 있게 함
- 기본값 5초로 설정, 아이템마다 다르게 조절 가능

## 3. 코루틴을 이용한 리스폰 구현하기

### 코루틴(Coroutine) 개념

- **코루틴**: 시간에 걸쳐 실행되는 함수
- 일반 함수는 한 번에 실행되지만, 코루틴은 **중간에 멈췄다가 나중에 다시 실행** 가능
- Unity에서 시간 지연이 필요한 작업에 주로 사용

### 코루틴 vs 일반 함수

| 구분      | 일반 함수          | 코루틴                  |
| --------- | ------------------ | ----------------------- |
| 반환 타입 | void, int, bool 등 | IEnumerator             |
| 실행 방식 | 즉시 완료          | 여러 프레임에 걸쳐 실행 |
| 시간 제어 | 불가능             | yield return으로 가능   |
| 호출 방법 | 직접 호출          | StartCoroutine() 사용   |

### 코루틴 구현

```csharp
IEnumerator RespawnRoutine()
{
    // 콜라이더와 렌더러 비활성화
    pickupCollider.enabled = false;
    foreach (Renderer renderer in renderers)
    {
        renderer.enabled = false;
    }

    yield return new WaitForSeconds(respawnTime);

    // 다시 활성화
    pickupCollider.enabled = true;
    foreach (Renderer renderer in renderers)
    {
        renderer.enabled = true;
    }
}
```

### 코루틴 구성 요소 상세 설명

### 1. **IEnumerator 반환 타입**

```csharp
IEnumerator RespawnRoutine()
```

- 코루틴 함수는 반드시 **IEnumerator** 타입을 반환해야 함
- IEnumerator는 반복 가능한 객체를 나타내는 인터페이스

### 2. **yield return 키워드**

```csharp
yield return new WaitForSeconds(respawnTime);
```

- **yield return**: "여기서 잠시 멈추고, 조건이 만족되면 다음 줄을 실행해"
- **WaitForSeconds(시간)**: 지정된 시간(초)만큼 대기
- 이 줄에서 코루틴이 멈췄다가 respawnTime 초 후에 다음 코드 실행

### 3. **코루틴 시작하기**

```csharp
StartCoroutine(RespawnRoutine());
```

- 일반 함수처럼 직접 호출하면 안 됨
- 반드시 **StartCoroutine()** 메서드로 실행해야 함

## 4. 컴포넌트 비활성화 방식 이해하기

### 왜 gameObject.SetActive(false)를 사용하지 않나?

처음에는 간단하게 이렇게 하려고 시도했습니다:

```csharp
// ❌ 작동하지 않는 코드
IEnumerator RespawnRoutine()
{
    gameObject.SetActive(false);
    yield return new WaitForSeconds(respawnTime);
    gameObject.SetActive(true); // 이 줄은 실행되지 않음!
}
```

### 문제점: 코루틴 중단

- **핵심 원리**: Unity에서 오브젝트가 비활성화되면, 그 오브젝트에서 실행 중인 모든 코루틴도 멈춤
- `gameObject.SetActive(false)` 실행 순간 코루틴도 함께 정지
- 따라서 `yield return` 이후의 코드가 절대 실행되지 않음
- 결과: 아이템이 비활성화된 상태로 영원히 남음

### 해결책: 개별 컴포넌트 비활성화

오브젝트 자체는 활성화 상태로 유지하고, **필요한 컴포넌트만 선택적으로 비활성화**합니다.

### 필요한 변수 선언

```csharp
private Collider pickupCollider;
private Renderer[] renderers;
```

- **pickupCollider**: 충돌 감지를 담당하는 Collider 컴포넌트
- **renderers**: 시각적 표현을 담당하는 모든 Renderer 컴포넌트들

### Awake에서 컴포넌트 찾기

```csharp
void Awake()
{
    pickupCollider = GetComponent<Collider>();
    renderers = GetComponentsInChildren<Renderer>();
}
```

**GetComponent vs GetComponentsInChildren**

| 메서드                         | 설명                      | 반환 타입         |
| ------------------------------ | ------------------------- | ----------------- |
| `GetComponent<T>()`            | 현재 오브젝트에서만 검색  | 단일 컴포넌트 (T) |
| `GetComponentsInChildren<T>()` | 현재 + 모든 자식에서 검색 | 배열 (T[])        |

**왜 Renderer는 배열로 받나?**

- 픽업 오브젝트가 여러 부분으로 구성될 수 있음
- 예시 구조:
  ```
  Ammo Pickup (부모)├─ Box Model (MeshRenderer)├─ Icon (SpriteRenderer)└─ Glow Effect (ParticleSystemRenderer)
  ```
- `GetComponentsInChildren<Renderer>()`는 모든 자식의 Renderer를 찾아서 배열로 반환
- MeshRenderer, SpriteRenderer, SkinnedMeshRenderer 등 모든 종류의 Renderer 포함

### 컴포넌트 비활성화/활성화

```csharp
// 비활성화
pickupCollider.enabled = false;
foreach (Renderer renderer in renderers)
{
    renderer.enabled = false;
}

// 활성화
pickupCollider.enabled = true;
foreach (Renderer renderer in renderers)
{
    renderer.enabled = true;
}
```

### Collider.enabled = false의 효과

- 충돌 감지 기능만 끔
- `OnTriggerEnter`가 더 이상 호출되지 않음
- 플레이어가 아이템을 다시 획득할 수 없음

### Renderer.enabled = false의 효과

- 화면에 렌더링(표시)하지 않음
- 플레이어 입장에서는 아이템이 사라진 것처럼 보임
- 하지만 오브젝트 자체는 여전히 씬에 존재

### foreach 반복문 설명

```csharp
foreach (Renderer renderer in renderers)
{
    renderer.enabled = false;
}
```

- **foreach**: 배열의 모든 요소를 하나씩 순회
- **Renderer renderer**: 현재 순회 중인 요소를 담는 임시 변수
- **in renderers**: renderers 배열의 모든 요소를 순회
- 배열에 있는 모든 Renderer를 하나하나 비활성화/활성화

## 5. 최종 구현 및 테스트

### 완성된 코드

```csharp
using System.Collections;
using UnityEngine;

public abstract class Pickup : MonoBehaviour
{
    [SerializeField] float rotationSpeed = 100f;
    [SerializeField] float respawnTime = 5f;  // 리스폰 시간 설정
    const string PLAYER_STRING = "Player";

    private Collider pickupCollider;
    private Renderer[] renderers;

    void Awake()
    {
        // 필요한 컴포넌트들을 미리 찾아서 저장
        pickupCollider = GetComponent<Collider>();
        renderers = GetComponentsInChildren<Renderer>();
    }

    void Update()
    {
        // 픽업 아이템 회전 효과
        transform.Rotate(0f, rotationSpeed * Time.deltaTime, 0f);
    }

    void OnTriggerEnter(Collider other)
    {
        if (other.CompareTag(PLAYER_STRING))
        {
            ActiveWeapon activeWeapon = other.GetComponentInChildren<ActiveWeapon>();
            OnPickup(activeWeapon);  // 픽업 효과 적용
            StartCoroutine(RespawnRoutine());  // 리스폰 시작
        }
    }

    IEnumerator RespawnRoutine()
    {
        // 1단계: 비활성화 (플레이어는 아이템이 사라졌다고 인식)
        pickupCollider.enabled = false;
        foreach (Renderer renderer in renderers)
        {
            renderer.enabled = false;
        }

        // 2단계: 대기
        yield return new WaitForSeconds(respawnTime);

        // 3단계: 재활성화 (아이템 다시 나타남)
        pickupCollider.enabled = true;
        foreach (Renderer renderer in renderers)
        {
            renderer.enabled = true;
        }
    }

    protected abstract void OnPickup(ActiveWeapon activeWeapon);
}
```

### 코드 실행 흐름 상세 분석

```
게임 시작
  ↓
Awake() 실행
  - pickupCollider 컴포넌트 찾기
  - renderers 배열에 모든 Renderer 저장
  ↓
매 프레임마다 Update() 실행
  - 아이템이 Y축 기준으로 회전
  ↓
플레이어가 아이템에 접근
  ↓
OnTriggerEnter() 호출
  - 플레이어 태그 확인
  - ActiveWeapon 찾기
  - OnPickup() 실행 (무기/탄약 지급)
  - StartCoroutine(RespawnRoutine()) 호출
  ↓
RespawnRoutine 코루틴 시작
  - pickupCollider.enabled = false (충돌 끔)
  - 모든 renderers.enabled = false (보이지 않음)
  - yield return new WaitForSeconds(respawnTime)
  ↓
[respawnTime 초 동안 대기]
  - 오브젝트는 활성 상태 유지
  - 코루틴은 멈춰있음
  - Update()는 계속 실행 (하지만 보이지 않음)
  ↓
대기 시간 종료
  - pickupCollider.enabled = true (충돌 다시 켬)
  - 모든 renderers.enabled = true (다시 보임)
  ↓
아이템이 다시 획득 가능한 상태가 됨

```

### Unity Inspector 설정

1. **Rotation Speed (회전 속도)**
   - 기본값: 100
   - 아이템이 회전하는 속도 조절
   - 값이 클수록 빠르게 회전
2. **Respawn Time (리스폰 시간)**
   - 기본값: 5초
   - 아이템이 다시 나타나기까지의 시간
   - 아이템 종류에 따라 다르게 설정 가능:
     - 체력 팩: 10초
     - 탄약: 5초
     - 파워업: 30초

### 테스트 체크리스트

- [ ] 플레이어가 아이템에 접근하면 픽업 효과가 작동하는가?
- [ ] 픽업 후 아이템이 즉시 보이지 않게 되는가?
- [ ] 픽업 후 아이템을 다시 획득할 수 없는가? (충돌 비활성화 확인)
- [ ] 설정한 시간이 지나면 아이템이 다시 나타나는가?
- [ ] 재활성화된 아이템을 다시 획득할 수 있는가?
- [ ] Inspector에서 respawnTime 값을 변경하면 리스폰 시간이 바뀌는가?

### 주의사항 및 팁

**⚠️ 주의사항**

- `gameObject.SetActive(false)` 사용하면 코루틴이 멈춤
- Awake에서 컴포넌트를 미리 찾아두지 않으면 NullReferenceException 발생 가능
- MeshRenderer가 없을 경우를 대비해 `GetComponentsInChildren<Renderer>()` 사용

**💡 활용 팁**

- 희귀 아이템은 respawnTime을 길게 (30초~60초)
- 일반 아이템은 respawnTime을 짧게 (3초~5초)
- 파티클 효과를 추가하면 리스폰 시 시각적 피드백 제공 가능

## 📚 핵심 개념 정리

### 배운 내용

1. **리스폰 시스템**: 오브젝트를 파괴하지 않고 재사용하는 효율적인 방법
2. **코루틴**: 시간 지연이 필요한 작업을 처리하는 Unity의 핵심 기능

4. **GetComponentsInChildren**: 자식 오브젝트를 포함한 모든 컴포넌트 찾기

### 실무 적용

- 멀티플레이어 게임의 아이템 리스폰
- 오픈월드 게임의 자원 재생성
- 보스 몬스터 패턴에서 약점 노출/숨김
- UI 요소의 페이드 인/아웃 효과
