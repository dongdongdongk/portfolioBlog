# 저장 프로시저

```jsx
저장 프로시저(Stored Procedure)는 데이터베이스 내에서 미리 정의된 하나 이상의 SQL 문을 실행하는 프로그래밍적인 로직의 집합입니다.

저장 프로시저는 데이터베이스 서버에서 실행되며, 데이터베이스 작업을 수행하고 결과를 반환하는 데 사용됩니다.

이를 통해 데이터베이스 작업을 중앙 집중화하고 보안을 강화하며, 재사용성을 높일 수 있습니다.
```

```jsx
1. 프로그래밍적 로직

저장 프로시저는 SQL 언어를 기반으로 작성되며, 데이터베이스 작업을 수행하기 위한 로직과 비즈니스 룰을 포함할 수 있습니다. 이를 통해 복잡한 데이터 조작 및 처리를 수행할 수 있습니다.

2. 재 사용성

저장 프로시저는 여러 응용 프로그램에서 동일한 로직을 재사용할 수 있습니다. 이로써 코드 중복을 줄이고 일관성을 유지할 수 있습니다.

3. 효율성

저장 프로시저는 데이터베이스 서버 내에서 실행되므로 네트워크 오버헤드를 최소화하고 데이터베이스 내에서 빠르게 작업을 수행할 수 있습니다.

4. 보안

저장 프로시저는 데이터베이스 권한과 연결되며, 데이터베이스 객체에 대한 액세스를 제어하는 데 사용됩니다. 이로써 애플리케이션에서 직접 SQL을 실행하는 것보다 더 강력한 보안을 구현할 수 있습니다.

5. 트랜잭션 관리

저장 프로시저는 트랜잭션을 시작, 커밋 또는 롤백할 수 있는 기능을 제공합니다. 이를 통해 데이터의 일관성과 안전성을 유지할 수 있습니다.

6. 입력 및 출력 매개변수

저장 프로시저는 입력 매개변수를 통해 값을 전달하고, 출력 매개변수를 통해 결과를 반환할 수 있습니다. 이를 통해 저장 프로시저 간에 데이터 교환 및 상호 작용이 가능합니다.

7. 선언적 프로그래밍

저장 프로시저는 SQL과 PL/SQL(Procedural Language/Structured Query Language)과 같은 선언적 프로그래밍 언어를 사용하여 작성됩니다. 이는 데이터베이스 작업을 간단하게 정의할 수 있게 합니다.

8. 예외 처리

저장 프로시저는 예외 처리를 통해 오류 상황을 처리하고 제어할 수 있습니다. 이로써 예기치 않은 상황에 대비할 수 있습니다.

9. 배치 작업

대량 데이터 처리나 정기적인 작업을 자동화하기 위해 저장 프로시저를 사용할 수 있습니다.

요약하면, 저장 프로시저는 데이터베이스 내에서 실행되는 프로그램으로, 데이터 처리, 비즈니스 로직, 보안, 효율성 및 재사용성을 강화하는 데 사용됩니다.

저장 프로시저는 주로 데이터베이스의 중요한 부분을 관리하고 데이터 조작을 수행하는 데 유용한 도구입니다.
```

## 예제

```sql
create or replace PROCEDURE P_STORE_INFO           -- 이 줄은 P_STORE_INFO라는 저장 프로시저를 생성하거나 이미 존재한다면 대체(replace)하는 SQL 문입니다.
(
   P_CODE IN VARCHAR2,          --점포코드PK        -- 이 부분은 저장 프로시저의 파라미터 선언입니다.
   P_STROE_NAME IN VARCHAR2,    --점포명            -- P_CODE, P_STORE_NAME, P_MANAGER는 저장 프로시저를 호출할 때 전달해야 하는 입력 매개변수입니다. 이들은 문자열(VARCHAR2) 형식입니다.
   P_MANAGER IN VARCHAR2        --점장명
)
IS                                 -- 이 부분은 저장 프로시저의 본문 시작을 나타냅니다.
BEGIN
DECLARE
      V_CNT NUMBER(2) := 0;    --초기값              --V_CNT라는 변수를 선언하고 초기값을 0으로 설정합니다. 이 변수는 반복문에서 사용됩니다.
BEGIN                                                -- 저장 프로시저 본문의 시작을 나타냅니다.
    LOOP                        --루프를 시작합니다.
    EXIT WHEN V_CNT = 12;       --조건 (V_CNT가 12이되면 LOOP끝)
      INSERT INTO STORE_INFO(   -- 조건이 맞으면 실행
                              STORE_CD
                            , STORE_NM
                            , SALES_DATE
                            , MANAGER
                            , SALES
                            )
                            VALUES
                            (
                              P_CODE
                            , P_STROE_NAME
                            , (SELECT TO_CHAR(TO_DATE('202101'+V_CNT, 'YYYYMM'), 'YYYYMM') FROM DUAL)
                            , P_MANAGER
                            , (SELECT TRUNC(DBMS_RANDOM.VALUE(3000000, 6000000)) AS RANDOM_NUM FROM DUAL)
                            );
      V_CNT := V_CNT + 1;       -- 증가치 (1씩증가)
    END LOOP;                   -- 루프의 끝을 표시합니다. V_CNT가 12가 될 때까지 루프가 반복됩니다.
END;                            -- 내부 BEGIN 블록의 끝을 표시합니다.
COMMIT;

END P_STORE_INFO;

--예) 프로시저 호출
call P_STORE_INFO('1111', '신도림점', '백종원');
call P_STORE_INFO('2222', '신림점', '김수현');
call P_STORE_INFO('3333', '강남역', '박준수');
call P_STORE_INFO('4444', '수원역점', '최수영');
call P_STORE_INFO('5555', '서울역점', '이정희');
call P_STORE_INFO('6666', '건대역', '양동후');
call P_STORE_INFO('7777', '홍대역점', '장우상');

```
