### 인서트 인데 Select 를 먼저 하는이유

```java
Hibernate은 데이터베이스와 자바 객체를 연결해주는 도구인데,

이 도구가 관련된 정보를 잘 다루려면 그 정보를 일시적으로 저장해두는데, 이게 바로 "영속성 컨텍스트"라고 하는 곳이다.

그래서 Hibernate은 필요한 정보를 먼저 이 곳에 로딩해서 저장한다.

그런데 외래 키 같은 걸 설정할 때, Hibernate은 저장된 정보를 활용해 데이터베이스에 물어보지 않고도 필요한 작업을 할 수 있다.

이렇게 하면 불필요한 질문을 하지 않아도 되고, 정보를 효율적으로 다룰 수 있게 된다.

그래서 Hibernate은 데이터베이스에 덜 물어보고도 똑똑하게 효율적으로 작업할 수 있게 되는것.

( 이렇게 Select 와 insert 를 하는걸 엄격하게 락 이라고 하는데 이것도 원래는 트랜젝션 처리를 하는게 좋다 -- 나중에 더 상세하게 정리필요 )
```

## PageResultDTO 작성

```java
@Data
public class PageResultDTO<DTO, EN> {

    // DTO 리스트
    private List<DTO> dtoList;

    // 총 페이지 번호
    private int totalPage;

    // 현재 페이지 번호
    private int page;

    // 목록 사이즈
    private int size;

    // 시작 페이지 번호, 끝 페이지 번호
    private int start, end;

    // 이전, 다음
    private boolean prev, next;

    // 페이지 번호 목록
    private  List<Integer> pageList;

    // 생성자: Page<EN> 타입의 데이터와 매핑 함수(Function<EN, DTO>)를 받음
    public PageResultDTO(Page<EN> result, Function<EN, DTO> fn) {

        // result 내의 엔티티 데이터를 DTO로 변환하여 리스트로 저장
        dtoList = result.stream().map(fn).collect(Collectors.toList());
        // 총 페이지 수 설정
        totalPage = result.getTotalPages();
        // 페이지 번호 목록 생성
        makePageList(result.getPageable());

    }

    // 현재 페이지 정보를 기반으로 페이지 번호 목록 생성
    public void makePageList(Pageable pageable) {

        this.page = pageable.getPageNumber() + 1; // 0부터 시작하므로 1을 추가
        this.size = pageable.getPageSize();

        //temp end page
        int tempEnd = (int)(Math.ceil(page/10.0)) * 10;

        start = tempEnd - 9;

        prev = start > 1;

        end = totalPage > tempEnd ? tempEnd : totalPage;

        next = totalPage > tempEnd;

        // 페이지 번호 목록 생성 (start부터 end까지)
        pageList = IntStream.rangeClosed(start,end).boxed().collect(Collectors.toList());
        // boxed() 는 IntStream 을 Integer 로 변환하여 List<Integer> pageList 에 수집 가능하도록 래퍼 객체로 바꿔준다
    }
}
```

```java
@Override
    public PageResultDTO<BoardDTO, Object[]> getList(PageRequestDTO pageRequestDTO) {

        log.info(pageRequestDTO);

        Function<Object[], BoardDTO> fn = (en -> entityToDTO((Board)en[0],(Member)en[1],(Long)en[2]));

        Page<Object[]> result = boardRepository.getBoardWithReplyCount(
                pageRequestDTO.getPageable(Sort.by("bno").descending()));

        return new PageResultDTO<>(result, fn);
    }
}
```

```java
getList 메서드를 호출해서 PageRequestDTO 파라미터를 받고

Object[] 의

0 번째 인덱스가 Board

1 번째 인텍스가 Member

2 번째 인덱스가 Long ( replyCount ) 이다

그리고 getBoardWithReplyCount 메서드를 호출하여 페이징 처리된 결과를 가져온다. 이 때, pageRequestDTO를 이용하여 페이징 정보 및 정렬 정보를 적용한다

이후

return new PageResultDTO<>(result, fn);: PageResultDTO 객체를 생성하여 반환

(페이징된 데이터 = result 데이터를 DTO로 변환하는 함수 = fn )

PageResultDTO 는 result 와 fn 을 매개변수로 받는 생성자를 가지고 있다 (PageResultDTO 클래스 확인해봐라)

    // 생성자: Page<EN> 타입의 데이터와 매핑 함수(Function<EN, DTO>)를 받음
    public PageResultDTO(Page<EN> result, Function<EN, DTO> fn) {

        // result 내의 엔티티 데이터를 DTO로 변환하여 리스트로 저장
        dtoList = result.stream().map(fn).collect(Collectors.toList());
        // 총 페이지 수 설정
        totalPage = result.getTotalPages();
        // 페이지 번호 목록 생성
        makePageList(result.getPageable());

    }

이렇게 페이징된 데이터(result) 를 스트림으로 사용하고 데이터를 DTO로 변환하는 함수(fn) 를 .map 에 사용해서 엔티티객체를 DTO 로 바꾼다 그리고 이를 dtoList 에 저장한다

```

    @Transactional
    @Override
    public void modify(BoardDTO boardDTO) {

        // 게시물 ID로 게시물 조회
        Optional<Board> optionalBoard = boardRepository.findById(boardDTO.getBno());

        // 게시물이 존재하는 경우에만
        if(optionalBoard.isPresent()){
            // Optional에서 실제 Board 객체를 추출 ( get 메서드는 Optional 객체 안에 포함된 값을 반환하는 메서드)
            Board board = optionalBoard.get();

            board.changeContent(boardDTO.getContent());
            board.changeTitle(boardDTO.getTitle());

            boardRepository.save(board);
        }
    }
