# { 백엔드 기본 파일 설치 }

```jsx
1. Node.js 설치

2. 프로젝트 폴더 생성

3. npm init -y : package.json 파일을 생성합니다. 여기서 프로젝트의 메타데이터와 의존성 정보를 관리하게 됩니다.

4. npm install typescript : TypeScript 설치

5. npx tsc --init : TypeScript 구성 파일인 tsconfig.json을 생성합니다. 이 파일은 TypeScript 컴파일러 설정을 포함합니다.

요약

package.json: 프로젝트의 메타데이터 및 의존성 정보

tsconfig.json: TypeScript 컴파일러 설정

node_modules/: 프로젝트 의존성들이 설치된 디렉토리
```

# { TypeScript 설정 파일(tsconfig.json) 수정 }

```jsx
**TypeScript 설정 파일(tsconfig.json)**을 수정하는 방법을 다룹니다.

이 설정 파일은 프로젝트에서 TypeScript 컴파일러가 어떻게 동작할지를 정의합니다.
```

## 1. **기존 `tsconfig.json` 파일 확인**

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381329/notion-blog/_/React_Node_/_3_/image_1.png)

```jsx
tsconfig.json 파일을 열어보면 기본적으로 여러 설정들이 주석 처리되어 있습니다.

이 파일에는 TypeScript 컴파일러가 제공하는 다양한 설정 옵션들이 포함되어 있으며,

프로젝트의 요구에 맞게 수정할 수 있습니다.
```

```jsx
{
  "compilerOptions": {
    "target": "ES2015",
    "module": "CommonJS",
    "lib": ["DOM", "ES2015"],
    "baseUrl": "./",
    "outDir": "./build",
    "rootDir": "./src",
    "moduleResolution": "node",
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "strict": true,
    "skipLibCheck": true
  }
}
```

```jsx
compilerOptions: 이 섹션에서는 컴파일러가 어떻게 코드를 처리할지 정의합니다.

target: 컴파일된 JavaScript의 버전을 설정합니다. 여기서는 ES2015로 설정했습니다. 필요에 따라 ES2020 또는 ES2021로 변경할 수 있습니다.

module: CommonJS 모듈 시스템을 사용합니다.

lib: 사용할 라이브러리로 DOM과 ES2015을 설정합니다.

baseUrl: 프로젝트의 루트 디렉토리를 지정합니다.

outDir: 빌드된 파일들이 저장될 폴더를 설정합니다. 여기서는 build 폴더로 지정했습니다.

rootDir: 소스 파일들이 위치하는 디렉토리로, src 폴더로 설정합니다.

moduleResolution: 모듈을 어떻게 찾을지 설정합니다. 여기서는 Node로 설정했습니다.
```

### 강의 세팅

```jsx
{
  "compilerOptions": {
    "target": "es2016",                                  /* 자바스크립트의 어떤 버전으로 컴파일할지 설정합니다. 여기서는 ES2016을 사용합니다. */
    "module": "commonjs",                                /* CommonJS 모듈 시스템을 사용합니다. 주로 Node.js 환경에서 사용됩니다. */
    "lib" : ["DOM","ES2015"],                            /* 코드가 실행될 환경을 정의합니다. DOM과 ES2015 기능을 사용할 수 있도록 설정합니다. */
    "baseUrl": ".",                                      /* 모듈을 찾을 때 기준이 되는 디렉토리를 설정합니다. 여기서는 현재 디렉토리(.)를 기준으로 합니다. */
    "outDir": "./build",                                 /* 컴파일된 파일이 저장될 디렉토리를 지정합니다. 여기서는 'build' 폴더로 지정합니다. */
    "rootDir": "src",                                    /* 소스 파일들이 위치하는 루트 디렉토리를 지정합니다. 여기서는 'src' 디렉토리입니다. */
    "noImplicitAny": true,                               /* any 타입을 명시적으로 선언하지 않으면 오류를 발생시킵니다. */
    "noUnusedLocals": false,                             /* 사용되지 않는 지역 변수를 허용합니다. (false로 설정) */
    "noUnusedParameters": false,                         /* 사용되지 않는 파라미터를 허용합니다. (false로 설정) */
    "moduleResolution": "Node",                          /* 모듈을 어떻게 찾을지를 정의합니다. Node 방식으로 모듈을 찾습니다. */
    "esModuleInterop": true,                             /* CommonJS와 ES 모듈 간의 호환성을 활성화합니다. */
    "sourceMap": true,                                   /* 소스 맵 파일을 생성합니다. (디버깅을 위해 원본 코드와 컴파일된 코드 간의 매핑을 만듭니다.) */
    "experimentalDecorators": true,                      /* 데코레이터 기능을 사용할 수 있도록 활성화합니다. */
    "emitDecoratorMetadata": true,                       /* 데코레이터가 메타데이터를 생성할 수 있도록 허용합니다. */
    "forceConsistentCasingInFileNames": true,            /* 파일 이름의 대소문자를 엄격하게 구분하도록 강제합니다. */
    "allowSyntheticDefaultImports": true,                /* 모듈에서 기본값을 가져올 수 있도록 허용합니다. (주로 ES 모듈을 CommonJS에서 사용할 때 유용합니다.) */
    "pretty": true,                                      /* 터미널에 컴파일 결과를 보기 좋게 출력합니다. */
    "resolveJsonModule": true,                           /* JSON 모듈을 불러올 수 있도록 허용합니다. */
    "strict": true,                                      /* 모든 엄격한 타입 검사를 활성화합니다. (엄격한 타입 검사를 위한 모든 옵션이 활성화됨) */
    "skipLibCheck": true                                 /* .d.ts 파일에 대한 타입 검사를 생략하여 컴파일 속도를 높입니다. */
  }
}

```

# { 모놀리식 애플리케이션을 위한 파일 및 폴더 구조 설계 }

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381330/notion-blog/_/React_Node_/_3_/image_2.png)

```jsx
애플리케이션의 파일 및 폴더 구조를 설정하는 방법을 설명하고 있으며,

특히 미래에 마이크로서비스로 전환할 수 있도록 모놀리식 애플리케이션을 설계하는 방법에 중점을 둡니다.

* 모놀리식 애플리케이션(Monolithic Application)은 애플리케이션의

	모든 구성 요소가 하나의 단일 코드베이스 내에서 동작하는 구조를 말합니다. ( 마이크로 서비스의 반대 )
```

## 1. **기본 폴더 및 파일 구조**

```jsx
프로젝트의 루트 디렉토리는 src로 설정되어 있습니다.

모든 코드는 이 src 디렉토리 내에서 관리됩니다.
```

## 2. **폴더 구조 설명**

```jsx
Features 폴더

		애플리케이션의 기능들을 모듈 단위로 관리할 수 있도록 features 폴더를 생성합니다.

		각 기능별로 나중에 쉽게 분리 가능하게 설계하여, 마이크로서비스로 전환할 때 유리한 구조로 설계됩니다.

		기능은 하나의 애플리케이션 내에서 독립적으로 동작하며, 컨트롤러, 모델, 라우트 등의 코드가 포함됩니다.

Shared 폴더

		애플리케이션 전반에서 재사용 가능한 코드를 관리하는 폴더입니다.

폴더 내부 구조:

		Globals 폴더: 전역적으로 사용될 헬퍼 함수나 유틸리티들이 위치합니다.

		Services 폴더: 여러 서비스와 관련된 코드를 저장합니다.

		DB 폴더: MongoDB와의 연결 및 관련 쿼리 작업을 처리하는 코드들이 위치합니다.

		Email 폴더: 이메일 서비스와 관련된 모든 코드들이 위치합니다.

		Queues 폴더: 메시지 큐 서비스 관련 코드들이 위치합니다 (Redis 기반 메시지 큐).

		Redis 폴더: Redis 관련 코드들이 위치합니다.

		Sockets 폴더: Socket.IO 관련 코드를 관리합니다.

		Workers 폴더: Redis 메시지 큐를 사용하는 워커 프로세스들이 위치합니다.
```

## 3. **루트 디렉토리 내 주요 파일**

```jsx
app.js (또는 main.js)

		프로젝트의 엔트리 파일로, 애플리케이션이 실행될 때 가장 먼저 실행됩니다.

		TypeScript를 사용하는 경우, 이 파일은 TypeScript에서 JavaScript로 변환될 때 생성됩니다.

		package.json 파일에서 정의된 "main" 속성에 따라 파일 이름이 app.js 또는 main.js일 수 있습니다.

config.js

		애플리케이션 전반에 걸쳐 사용할 설정 파일입니다.

		데이터베이스 연결, 서버 포트 등의 전역 설정 값들이 이곳에 정의됩니다.

routes.js

		애플리케이션의 모든 라우트를 정의하는 파일입니다.

		API 엔드포인트나 페이지 라우트에 대한 설정을 이곳에서 관리합니다.

setupDatabase.js

		MongoDB와 애플리케이션의 연결을 설정하는 파일입니다.

		애플리케이션이 시작될 때, MongoDB와 자동으로 연결됩니다.

setupServer.js

		애플리케이션의 서버 설정을 담당하는 파일입니다.

		서버 시작 및 전역 핸들러 추가 등의 설정을 이곳에서 관리합니다.
```

## `ChattyServer` 클래스 작성

```jsx
이 코드는 Express 기반 서버를 쉽게 설정하고, 보안, 라우팅, 오류 처리, 실시간 통신 기능 등을 체계적으로 관리하기 위한 틀을 제공합니다.
```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381332/notion-blog/_/React_Node_/_3_/image_4.png)

```jsx
여기서 작성한 ChattyServer 클래스는 Express 애플리케이션을 설정하고,

미들웨어와 오류 처리, 서버 시작 등을 관리하기 위한 구조를 갖추고 있습니다.
```

```jsx
// 필요한 모듈과 타입을 import 합니다.
import { Application, json, urlencoded, Response, Request, NextFunction } from 'express' // Express 애플리케이션 타입과 필요한 유틸리티들
import http from 'http'; // HTTP 서버를 다루기 위한 모듈

// ChattyServer라는 이름의 클래스를 만듭니다. 이 클래스는 서버와 관련된 모든 설정을 관리합니다.
export class ChattyServer {
    // 이 app은 Express 애플리케이션 인스턴스입니다. 서버의 핵심입니다.
    private app: Application;

    // 생성자(Constructor) 함수는 이 클래스를 처음 사용할 때 호출되며, Express 애플리케이션을 받아와서 내부적으로 저장합니다.
    constructor(app: Application) {
        this.app = app; // 전달받은 Express 애플리케이션 인스턴스를 this.app에 저장합니다.
    }

    // 서버를 시작하는 메서드입니다. 이 메서드를 호출하면 아래에 있는 다른 메서드들이 순서대로 실행됩니다.
    public start(): void {
        // 보안 관련 미들웨어 설정 (추후 구현)
        this.securityMiddleware(this.app);

        // 기본 미들웨어 설정 (예: JSON 파서, URL 인코딩 등)
        this.standardMiddleware(this.app);

        // 라우트 설정 (API 엔드포인트 설정)
        this.routeMiddleware(this.app);

        // 전역 오류 처리기 설정 (에러가 발생했을 때 처리하는 방법)
        this.globalErrorHandler(this.app);

        // HTTP 서버 시작 (서버가 클라이언트 요청을 받을 준비를 합니다)
        this.startServer(this.app);
    }

    // 이 메서드는 보안 관련 미들웨어를 추가하는 부분입니다.
    // 예를 들어, 인증, 데이터 암호화, CORS(교차 출처 자원 공유) 등의 설정을 할 수 있습니다.
    private securityMiddleware(app: Application): void {}

    // 이 메서드는 기본적인 미들웨어를 설정합니다.
    // 예를 들어, JSON 데이터 파싱, URL 인코딩 처리 같은 것들이 여기 들어갑니다.
    private standardMiddleware(app: Application): void {}

    // 이 메서드는 서버에서 사용할 라우트를 정의하는 부분입니다.
    // 예를 들어, 어떤 URL로 요청이 들어오면 어떤 응답을 할지 정합니다.
    private routeMiddleware(app: Application): void {}

    // 이 메서드는 서버에서 발생하는 모든 에러를 처리하는 핸들러입니다.
    // 에러가 발생하면 어떻게 응답할지를 여기서 설정합니다.
    private globalErrorHandler(app: Application): void {}

    // 이 메서드는 서버를 실제로 실행하는 부분입니다.
    // 즉, 클라이언트가 서버에 요청을 보낼 수 있게 됩니다.
    private startServer(app: Application): void {}

    // 이 메서드는 실시간 웹 통신을 위한 Socket.IO를 설정하는 부분입니다.
    private createSocketIO(httpServer: http.Server): void {}

    // 이 메서드는 HTTP 서버를 실행하고, 클라이언트 요청을 처리할 준비를 합니다.
    private startHttpServer(httpServer: http.Server): void {}
}

```

### 클래스 구조 사용 이유

```jsx
클래스를 사용하면 서버 설정과 기능들을 하나의 객체로 묶어서 관리할 수 있습니다.

이렇게 하면 코드를 깔끔하게 유지할 수 있고, 서버의 기능을 추가하거나 수정할 때 필요한 부분만 수정하면 됩니다.

즉, 코드의 유지보수성과 확장성을 높여줍니다.
```

### **메서드의 역할**:

```jsx
securityMiddleware:

		보안 설정을 담당합니다. 서버를 안전하게 운영하려면 인증, 데이터 보호 같은 보안 조치가 필요합니다.

		이 메서드는 그런 보안 설정을 추가하는 역할을 합니다.

standardMiddleware:

		Express 애플리케이션에서 데이터를 처리할 때 사용하는 기본적인 도구들을 설정합니다.

		예를 들어, 클라이언트가 보내는 JSON 데이터를 이해할 수 있도록 하거나, URL을 인코딩/디코딩하는 기능을 추가합니다.

routeMiddleware:

		클라이언트가 서버에 요청을 보낼 때 그 요청을 처리하는 경로(라우트)를 설정합니다.

		예를 들어, /users 경로로 들어오는 요청에 대해 사용자 데이터를 반환할 수 있도록 설정합니다.

globalErrorHandler:

		서버에서 오류가 발생했을 때, 이 오류를 어떻게 처리할지 정하는 부분입니다.

		만약 문제가 발생하더라도 사용자가 친절한 에러 메시지를 받도록 도와줍니다.

startServer:

		이 메서드를 통해 서버가 실제로 클라이언트 요청을 받을 준비를 합니다.

createSocketIO:

		실시간 통신을 위한 Socket.IO 설정을 담당합니다. 예를 들어, 실시간 채팅 같은 기능을 구현할 때 사용됩니다.

startHttpServer:
```

## 라이브러리 오류 발생

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381332/notion-blog/_/React_Node_/_3_/image_5.png)

```jsx
cors는 JavaScript로 작성된 라이브러리입니다.

JavaScript에서는 타입이 없기 때문에 코드에서 변수나 함수의 타입을 미리 알 수 없습니다.

하지만 TypeScript는 정적 타입 검사를 하기 때문에, 사용되는 모든 라이브러리나 함수가 어떤 타입을 반환하는지,

또는 어떤 타입의 인수를 받는지 미리 알고 있어야 합니다.

그러나 cors와 같은 JavaScript 라이브러리에는 TypeScript의 타입 정의가 포함되어 있지 않기 때문에,

TypeScript가 cors가 어떻게 동작하는지 타입 정보를 모르게 됩니다. 이 때문에 TypeScript에서는 오류가 발생합니다.

이 문제를 해결하기 위해 @types/cors 같은 타입 정의 파일을 설치해야 합니다.

이 파일은 cors 라이브러리에서 사용되는 함수나 객체의 타입 정보를 TypeScript에게 제공해 줍니다.
```

## setupServer.ts 작성

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381332/notion-blog/_/React_Node_/_3_/image_6.png)

```jsx
import {
    Application,
    json,
    urlencoded,
    Response,
    Request,
    NextFunction,
    application,
} from "express";
import http from "http";
import cors from "cors";  // CORS (Cross-Origin Resource Sharing) 설정을 위한 라이브러리
import helmet from "helmet";  // 보안 관련 HTTP 헤더 설정을 위한 라이브러리
import hpp from "hpp";  // HTTP Parameter Pollution 공격 방지용 라이브러리
import cookierSession from "cookie-session";  // 쿠키 기반 세션을 설정하는 라이브러리
import HTTP_STATUS from "http-status-codes";  // HTTP 상태 코드를 쉽게 관리하는 라이브러리
import compression from 'compression';  // HTTP 응답을 압축하여 성능을 높이는 라이브러리
import "express-async-errors";  // 비동기 함수의 오류를 자동으로 처리하는 라이브러리

// ChattyServer 클래스는 Express.js 기반 서버를 설정하고 시작하는 역할을 합니다.
export class ChattyServer {
    private app: Application;  // Express 애플리케이션 인스턴스

    // 생성자: 새로운 서버 인스턴스를 생성할 때 애플리케이션 객체를 전달받습니다.
    constructor(app: Application) {
        this.app = app;
    }

    // 서버를 시작하는 메서드. 이 메서드는 보안, 일반, 라우팅, 오류 처리 미들웨어를 설정하고, 서버를 시작합니다.
    public start(): void {
        this.securityMiddleware(this.app);  // 보안 미들웨어 설정
        this.standardMiddleware(this.app);  // 일반 미들웨어 설정
        this.routeMiddleware(this.app);     // 라우팅 설정 (라우트 핸들러 추가 예정)
        this.globalErrorHandler(this.app);  // 전역 오류 처리 핸들러 설정
        this.startServer(this.app);         // 실제 HTTP 서버를 시작
    }

    // 보안 미들웨어 설정: 애플리케이션에 보안 관련 미들웨어를 추가하는 메서드입니다.
    private securityMiddleware(app: Application): void {
        app.use(
            cookierSession({
                name: "session",   // 세션 이름 설정
                keys: ["text1", "test2"],  // 세션 암호화 키 목록 (나중에 환경 변수로 변경 가능)
                maxAge: 24 * 7 * 360000,  // 쿠키 유효 기간 (7일)
                secure: false,  // HTTPS 환경에서만 쿠키 전송 여부 (배포 시에 true로 설정해야 함)
            })
        );
        app.use(hpp());  // HTTP Parameter Pollution 공격 방지를 위한 설정
        app.use(helmet());  // 보안 강화 HTTP 헤더 자동 설정 (XSS, Content Security 등 방지)
        app.use(
            cors({
                origin: '*',  // 모든 도메인에서의 요청 허용 (개발 환경에선 '*' 사용, 배포 시에는 특정 도메인 설정)
                credentials: true,  // 쿠키와 함께 요청을 보내기 위한 설정
                optionsSuccessStatus: 200,  // HTTP OPTIONS 요청에 대한 성공 응답 코드 설정
                methods: ['GET', 'POST', 'PUT', 'DELETE', 'OPTIONS']  // 허용되는 HTTP 메서드 목록
            })
        );
    }

    // 일반 미들웨어 설정: 애플리케이션에 필요한 일반 미들웨어를 추가합니다.
    private standardMiddleware(app: Application): void {
        app.use(compression());  // 응답 압축 (데이터 전송량 줄이기)
        app.use(json({ limit: '50mb'}));  // JSON 형식의 요청 본문을 파싱하고, 최대 50MB까지 허용
        app.use(urlencoded({ extended: true, limit: '50mb'}));  // URL 인코딩된 요청 본문을 파싱하고, 최대 50MB까지 허용
    }

    // 라우트 미들웨어: 이 부분에서 서버의 각 라우트(경로)에 대한 요청을 처리할 라우터를 설정합니다.
    private routeMiddleware(app: Application): void { }

    // 전역 오류 처리 핸들러: 이 메서드는 애플리케이션의 오류를 처리하는 전역 핸들러를 추가합니다.
    private globalErrorHandler(app: Application): void { }

    // 서버 시작 메서드: 이 메서드는 실제로 HTTP 서버를 시작하는 역할을 합니다.
    private startServer(app: Application): void { }

    // WebSocket과 같은 실시간 통신을 위한 소켓 IO 설정 메서드입니다. 아직 구현되지 않았습니다.
    private createSocketIO(httpServer: http.Server): void { }

    // HTTP 서버를 시작하는 로직을 넣는 메서드입니다. 역시 아직 구현되지 않았습니다.
    private startHttpServer(httpServer: http.Server): void { }
}

```

```jsx
보안 미들웨어 (securityMiddleware)

보안 관련 미들웨어를 설정합니다. 보안 미들웨어는 주로 애플리케이션의 공격 방어를 위한 설정들입니다.

		cookie-session:

				세션 데이터를 쿠키에 저장합니다. 이때 쿠키에 저장된 데이터는 암호화되어 있으며,

				keys 배열에서 제공된 키 값들로 암호화됩니다. 세션의 유효 기간은 7일로 설정되어 있습니다.

		hpp (HTTP Parameter Pollution):

				URL 쿼리나 폼 데이터에서 동일한 이름의 매개변수가 여러 번 들어올 때의 공격을 방지합니다.

		helmet:

				다양한 보안 관련 HTTP 헤더를 자동으로 설정해, 잠재적인 공격을 방지합니다.

		cors:

				다른 도메인에서 서버로 요청을 허용하는 CORS 설정입니다. 현재는 모든 도메인(*)을 허용하도록 되어 있고,

				쿠키 사용을 허용(credentials: true)합니다.


일반 미들웨어 (standardMiddleware)

표준 미들웨어는 데이터 전송이나 요청을 처리하는 데 필요한 설정입니다


		compression:

				응답 데이터를 압축해 네트워크 전송 속도를 최적화하고, 성능을 개선합니다.


		json과 urlencoded:

				서버가 클라이언트로부터 들어오는 JSON 데이터나 URL 인코딩된 데이터를 해석할 수 있도록 도와줍니다.

				최대 크기는 50MB로 설정되어 있어, 대용량 파일 전송이 가능합니다.

```

```jsx
이렇게 하면, 우리가 @controllers/User 같은 절대 경로를 사용할 수 있게 돼요.
```

### 수정 이유

```jsx
TypeScript 프로젝트에서 파일을 가져올 때 복잡한 상대 경로(../../folder/file.ts)로 작성해야 하는 경우가 많아요.

이런 경로는 길어지면 헷갈리기도 하고, 나중에 파일 구조가 바뀌면 수정할 곳이 많아져요.

이 문제를 해결하려고 절대 경로로 파일을 가져오는 방식으로 바꿀 수 있는데, TypeScript가 절대 경로를 인식하려면 설정이 필요해요.

그래서 tsconfig-paths를 사용해서 TypeScript가 **경로 설정(tsconfig)**을 제대로 인식하도록 도와주는 거예요.
```

```jsx
    Application, // Express 애플리케이션의 타입 정의
    json, // 요청 본문을 JSON 형식으로 파싱하는 미들웨어
    urlencoded, // 요청 본문을 URL 인코딩된 형식으로 파싱하는 미들웨어

    Request, // 요청 객체 타입

} from "express"; // Express.js 모듈 불러오기
import http from "http"; // HTTP 서버 생성을 위한 Node.js 기본 모듈
import cors from "cors"; // 다른 출처에서 온 요청을 허용하기 위한 미들웨어
import helmet from "helmet"; // 보안 관련 HTTP 헤더를 설정하는 미들웨어
import hpp from "hpp"; // HTTP 파라미터 오염 방지 미들웨어
import cookierSession from "cookie-session"; // 쿠키 기반 세션 관리 미들웨어
import HTTP_STATUS from "http-status-codes"; // HTTP 상태 코드 상수들
import compression from 'compression' // 요청과 응답을 압축하여 성능을 개선하는 미들웨어
import "express-async-errors"; // 비동기 요청에서 발생한 오류를 처리하기 위한 패키지

// 서버가 사용할 포트 번호
const SERVER_PORT = 5000;

// ChattyServer 클래스 정의. 서버의 기본 설정과 실행 로직을 담당.
export class ChattyServer {
    private app: Application; // Express 애플리케이션 인스턴스를 저장할 변수

    // 클래스의 생성자. 새로운 서버 인스턴스를 만들 때 호출되며, 애플리케이션 객체를 인자로 받음.
    constructor(app: Application) {
        this.app = app;
    }

    // 서버 실행을 위한 메인 메서드. 각종 미들웨어와 설정을 적용한 후 서버를 시작함.
    public start(): void {
        this.securityMiddleware(this.app); // 보안 관련 미들웨어 설정
        this.standardMiddleware(this.app); // 일반적인 미들웨어 설정 (요청 파싱 등)
        this.routeMiddleware(this.app); // 라우팅 설정 (API 경로 정의)
        this.globalErrorHandler(this.app); // 전역 오류 처리 미들웨어 설정
        this.startServer(this.app); // 서버 시작
    }

    // 보안 관련 미들웨어를 설정하는 메서드
    private securityMiddleware(app: Application): void {
        app.use(
            cookierSession({
                name: "session", // 세션의 이름을 'session'으로 설정
                keys: ["text1", "test2"], // 세션 암호화에 사용할 키들
                maxAge: 24 * 7 * 360000, // 세션의 유효 기간 (7일)
                secure: false, // HTTPS가 아닌 환경에서도 세션 사용 허용
            })
        );
        app.use(hpp()); // HTTP 파라미터 오염을 방지하는 미들웨어 추가
        app.use(helmet()); // 보안 관련 HTTP 헤더 설정
        app.use(
            cors({
                origin: '*', // 모든 출처의 요청 허용
                credentials: true, // 쿠키 등 자격 증명 허용
                optionsSuccessStatus: 200, // OPTIONS 메서드에 대해 성공 상태로 응답
                methods: ['GET', 'POST', 'PUT', 'DELETE', 'OPTIONS'] // 허용할 HTTP 메서드들
            })
        );
    }

    // 일반적인 미들웨어를 설정하는 메서드 (요청 데이터를 파싱하는 미들웨어들)
    private standardMiddleware(app: Application): void {
        app.use(compression()); // 요청과 응답을 압축하여 전송하는 미들웨어
        app.use(json({ limit: '50mb' })); // 요청 본문을 JSON 형식으로 파싱하며, 최대 크기는 50MB
        app.use(urlencoded({ extended: true, limit: '50mb' })); // URL 인코딩된 요청 데이터를 파싱하며, 최대 크기는 50MB
    }

    // 라우팅 관련 설정을 추가할 수 있는 메서드 (현재는 구현되어 있지 않음)
    private routeMiddleware(app: Application): void { }

    // 전역 오류 처리를 위한 미들웨어 설정 (현재는 구현되어 있지 않음)
    private globalErrorHandler(app: Application): void { }

    // 서버를 실제로 시작하는 메서드 (비동기 함수)
    private async startServer(app: Application): Promise<void> {
        try {
            // HTTP 서버 객체 생성 (Express 애플리케이션을 기반으로)
            const httpServer: http.Server = new http.Server(app);
            this.startHttpServer(httpServer); // HTTP 서버 시작
        } catch (error) {
            console.log(error); // 오류 발생 시 콘솔에 출력
        }
    }

    // 소켓 연결 설정을 위한 메서드 (현재는 구현되어 있지 않음)
    private createSocketIO(httpServer: http.Server): void { }

    // HTTP 서버를 시작하고 특정 포트에서 요청을 듣는 메서드
    private startHttpServer(httpServer: http.Server): void {
        httpServer.listen(SERVER_PORT, () => {
            // 서버가 성공적으로 시작되면 콘솔에 출력
            console.log(`Server running on port ${SERVER_PORT}`);
        });
    }
}
```

```jsx
import mongoose from 'mongoose' // Mongoose: MongoDB와 연결 및 작업을 쉽게 해주는 라이브러리

// 데이터베이스 연결 설정 함수. 서버 시작 시 호출됨.
export default () => {
  // 이런식으로 하면 내가 원하는 이름을 임포트 하는곳에서 사용 가능하다
  // 실제 연결을 시도하는 함수

    // MongoDB 데이터베이스에 연결을 시도
    mongoose
      .connect('mongodb://localhost:27017/chattyyapp-backend')
      .then(() => {
        // 연결이 성공하면 콘솔에 메시지를 출력
        console.log('Successfully connected to database.')
      })
      .catch((error) => {
        // 연결 실패 시 오류 메시지를 출력하고 프로세스를 종료
        console.log('Error connecting to database', error)
        return process.exit(1) // 오류 발생 시 서버 종료
      })
  }

  // 즉시 연결을 시도
  connect()

  // 연결이 끊어졌을 때 자동으로 다시 연결을 시도
  mongoose.connection.on('disconnected', connect)
}
```

## 정리

```jsx
MongoDB와 Mongoose 설정:

		Mongoose는 MongoDB와 직접 코드를 작성하지 않고도 데이터를 관리할 수 있게 해줍니다.

Mongoose 설치:

		npm install mongoose 명령어로 Mongoose를 설치합니다.

		Mongoose는 자체 타입 정의 파일을 포함하고 있어 추가적인 타입 파일 설치가 필요 없습니다.

		Mongoose를 사용하여 MongoDB와 연결하는 방법을 설명합니다. 이를 위해 mongoose.connect() 메서드를 사용하며,

		예를 들어 mongodb://localhost:27017/chattyyapp-backend에서 localhost:27017은 로컬에서 MongoDB가 실행되는 기본 포트이고,

		chattyyapp-backend는 데이터베이스 이름입니다.

연결 성공/실패 처리:

		실패하면 에러 메시지를 출력한 후 process.exit(1)을 호출하여 현재 실행 중인 프로세스를 종료합니다.
```

```jsx
이 파일에는 데이터베이스 URL, JWT 토큰 등 애플리케이션에서 필요한 중요한 값들을 저장할 수 있습니다.
```

```jsx
// dotenv 모듈을 사용하여 .env 파일에 정의된 환경 변수를 불러옵니다.
import dotenv from 'dotenv';

// dotenv.config()를 호출하여 .env 파일의 내용을 process.env로 로드합니다.
// {} 빈 객체는 기본 옵션을 사용한다는 의미입니다.
dotenv.config({})

// Config 클래스는 애플리케이션에 필요한 환경 변수들을 관리하고 검증하는 역할을 합니다.
class Config {
    // 환경 변수들에 대한 속성들을 정의합니다.
    // 각 속성은 string 타입이나 undefined일 수 있습니다.
    public DATABASE_URL: string | undefined;
    public JWT_TOKEN: string | undefined;
    public NODE_ENV: string | undefined;
    public SECRET_KEY_ONE: string | undefined;
    public SECRET_KEY_TWO: string | undefined;
    public CLIENT_URL: string | undefined;

    // 데이터베이스 URL에 대한 기본값을 정의합니다.
    // .env 파일에서 DATABASE_URL이 정의되지 않았을 때 이 기본값이 사용됩니다. ( readonly 는 타입스크립트의 final const 는
    // 속성은 추가 하거나 삭제 가능하지만 readonly 는 불가능
    private readonly DEFAULT_DATABASE_URL = 'mongodb://localhost:27017/chattyapp-backend';

    // 생성자에서 환경 변수를 할당합니다.
    constructor() {
        // process.env에서 값을 가져오고, 없을 경우 기본값을 설정합니다.
        // DATABASE_URL이 없으면 DEFAULT_DATABASE_URL을 사용합니다.
        this.DATABASE_URL = process.env.DATABASE_URL || this.DEFAULT_DATABASE_URL;

        // JWT 토큰이 없으면 기본값 '1234'를 사용합니다.
        this.JWT_TOKEN = process.env.JWT_TOKEN || '1234';

        // NODE_ENV가 정의되지 않으면 빈 문자열을 기본값으로 설정합니다.
        this.NODE_ENV = process.env.NODE_ENV || '';

        // SECRET_KEY_ONE과 SECRET_KEY_TWO가 없으면 각각 빈 문자열을 사용합니다.
        this.SECRET_KEY_ONE = process.env.SECRET_KEY_ONE || '';
        this.SECRET_KEY_TWO = process.env.SECRET_KEY_TWO || '';

        // 클라이언트 URL이 없으면 빈 문자열을 기본값으로 설정합니다.
        this.CLIENT_URL = process.env.CLIENT_URL || '';
    }

    // validateConfig() 메서드는 모든 설정 값들이 정의되어 있는지 확인합니다.
    public validateConfig(): void {
        // Object.entries()를 사용하여 클래스의 모든 속성(key, value 쌍)을 순회합니다.
        for(const [key, value] of Object.entries(this)) {  // this는 Config 클래스에서 만들어진 객체를 나타냅니다 this 안에는 DATABASE_URL, JWT_TOKEN, NODE_ENV 등의 속성들이 들어 있습니다.
            // 각 값이 undefined인 경우, 설정이 제대로 되지 않은 것으로 간주하고 오류를 던집니다.
            if(value === undefined) {
                throw new Error(`Configuration ${key} is undefined`); // 설정 값이 정의되지 않았을 때 에러 메시지를 출력합니다.
            }
        }
    }
}

// Config 클래스의 인스턴스를 생성하고, 이를 애플리케이션에서 사용하기 위해 export합니다.
```

## 2. 쿠키 세션 보안 설정

```jsx
보안 관련 미들웨어에서 config 파일을 사용해 쿠키 세션의 비밀키와 환경 설정을 적용합니다.

import cookieSession from "cookie-session";
import { config } from "./config"; // 설정 파일 가져오기

private securityMiddleware(app: Application): void {
    app.use(
        cookieSession({
            name: "session",
            keys: [config.SECRET_KEY_ONE!, config.SECRET_KEY_TWO!],
            maxAge: 24 * 7 * 360000, // 쿠키 만료 시간
            secure: config.NODE_ENV !== 'development' // 개발 환경이 아닌 경우 보안 설정 활성화 ( config 에 적혀있다 )
        })
    );
    // 추가 보안 미들웨어
    app.use(hpp()); // HTTP 파라미터 오염 방지
    app.use(helmet()); // 보안 헤더 설정
    app.use(
        cors({
            origin: config.CLIENT_URL, // 클라이언트 URL 지정
            credentials: true,
            optionsSuccessStatus: 200,
            methods: ['GET', 'POST', 'PUT', 'DELETE', 'OPTIONS']
        })
    );
}
```

## 3. MongoDB 연결 설정

```jsx
mongoose를 이용해 MongoDB와 연결할 때도 config 파일을 사용하여 데이터베이스 URL을 불러옵니다.

setupDatabase.ts 파일

import mongoose from "mongoose";
import { config } from "./config"; // 설정 파일 가져오기

export default () => {
    const connect = () => {
        mongoose.connect(config.DATABASE_URL!)
            .then(() => {
                console.log('Successfully connected to database.');
            })
            .catch((error) => {
                console.log('Error connecting to database', error);
                process.exit(1); // 연결 실패 시 애플리케이션 종료
            });
    };
    connect();

    // 연결 끊김 시 재연결
    mongoose.connection.on('disconnected', connect);
};
```
