# { Next.js란 무엇인가? }

## Next.js란 무엇인가?

```csharp
Next.js는 리액트(React) 기반의 프레임워크이다.

리액트 라이브러리에 빌드(build) 되어 있으며, 리액트로 만들어진 앱을 더 강력하게 만들어주는 도구이다.

풀스택 React 프레임워크로, 프론트엔드와 백엔드를 모두 처리할 수 있다.
```

## 왜 Next.js가 필요한가?

```csharp
1. 리액트는 라이브러리

		React는 UI를 만들기 위한 라이브러리일 뿐.

		서버 사이드 렌더링(SSR), 라우팅, API 라우트, 인증 처리 등은 직접 구성해야 함.

2. Next.js는 프레임워크

		리액트 위에 만들어진 프레임워크로, 다양한 기능을 내장하고 있다.

		개발자가 애플리케이션 구조와 기능 구현에 집중할 수 있게 도와줌.
```

## Next.js가 제공하는 기능들

| 기능                     | 설명                                               |
| ------------------------ | -------------------------------------------------- |
| 파일 기반 라우팅         | 폴더와 파일 구조로 페이지 라우팅을 자동으로 설정   |
| 서버 사이드 렌더링 (SSR) | SEO와 초기 로딩 성능 향상                          |
| 정적 사이트 생성 (SSG)   | 빌드 타임에 HTML 생성                              |
| API Routes               | 백엔드 API 엔드포인트를 Next.js 안에서 구현 가능   |
| 데이터 가져오기 지원     | `getServerSideProps`, `getStaticProps`, `fetch` 등 |
| 이미지 최적화            | `<Image>` 컴포넌트를 통한 성능 향상                |
| 폼 처리                  | 간단한 폼 제출 처리 지원                           |
| 인증 처리                | NextAuth 등과 쉽게 연동 가능                       |
| 서버 컴포넌트            | 서버에서 렌더링되는 React 컴포넌트 (최근 추가됨)   |

## 왜 최근에 더 중요해졌는가?

```csharp
**SPA(단일 페이지 앱)**에서 풀스택 앱으로 트렌드 변화.

사용자 경험 + SEO + 서버 처리 → 모든 요구사항을 만족시켜야 함.

React 자체도 서버 측 렌더링 기능을 강화 중.

하지만 여전히 풀스택을 만들려면 추가 도구가 필요.

Next.js는 이 과정을 단순화해 준다.
```

# { Pages Router vs App Router – 하나의 프레임워크, 두 가지 접근법 }

## 1. **Pages Router (페이지 라우터)**

```csharp
✅ 기존 방식, 오래전부터 사용됨.

✅ 안정적이고 검증된 방식.

✅ pages/ 디렉토리를 기준으로 파일 기반 라우팅.

✅ 많은 실제 프로젝트에서 사용되고 있어 학습 가치가 있음.

❗ 최신 기능(RSC 등)은 사용하지 못함.
```

### RSC?

```csharp
컴포넌트를 서버에서 실행하고, 결과(HTML)를 브라우저에 보내는 방식이야.

자바스크립트 없이도 렌더링된 HTML을 브라우저에서 볼 수 있음.

이러면:

		더 빠른 초기 로딩 속도

		불필요한 자바스크립트 줄이기

		SEO(검색 최적화)에 유리

		보안적으로도 유리 (민감한 로직 서버에서만 실행)
```

## 2. **App Router (앱 라우터)**

```csharp
✅ Next.js 13에서 도입된 새로운 방식.

✅ app/ 디렉토리를 기준으로 라우팅.

✅ React Server Components, Server Actions 등 최신 기능 사용 가능.

✅ Next.js의 미래 방향성에 해당.

❗ 아직 일부 버그나 러프한 부분이 존재할 수 있음.
```

## 공통점

```csharp
둘 다 파일 기반 라우팅 사용.

둘 다 풀스택 웹 애플리케이션 구축 가능.

페이지는 서버에서 렌더링됨(SSR).
```
