# { React Native란 무엇인가? }

```jsx
React Native는 React.js와 밀접한 관련이 있는 프레임워크로, iOS와 Android용 모바일 앱을 구축할 수 있습니다.

앱스토어에 배포할 수 있는 실제 앱으로, iOS 및 Android 기기 사용자라면 누구나 이용할 수 있는 앱을 만들 수 있습니다.

React Native는 react-dom과 비슷하지만, 웹 브라우저가 아닌 iOS와 Android를 대상으로 하는 프레임워크입니다.

React.js에서 코드를 작성한 후, React Native 컴포넌트와 API를 추가로 사용해 네이티브 모바일 앱을 제작할 수 있습니다.

따라서 React Native를 다루기 위해서는 React.js에 대한 이해가 필수적입니다.
```

## React.js와 React Native의 차이점

```jsx
React.js:

	인터페이스 구축을 위한 JavaScript 라이브러리

	주로 웹 개발에 사용

	플랫폼 애그노스틱(platform-agnostic) ( 특정 플랫폼에 구애받지 않고 여러 플랫폼에서 동일하게 동작할 수 있는 소프트웨어나 기술 )

	웹 지원을 돕는 react-dom 라이브러리와 함께 사용

React Native:

	모바일 앱 개발을 위한 프레임워크

	react-dom의 대안으로, 웹 브라우저 대신 iOS와 Android 플랫폼을 타겟

	네이티브 UI 요소로 컴파일되는 여러 특별한 React 컴포넌트 제공

	네이티브 플랫폼 API를 노출하여 JavaScript 코드에서 기기의 특정 기능 사용 가능
```

## React와 react-dom의 관계

```jsx
React:

	상태(State)를 관리하고 가상의 컴포넌트 트리를 구축하는 툴

	플랫폼에 구애받지 않음

react-dom:

	React가 산출한 결과를 브라우저에 표시

	웹 앱 구축을 위한 필수 라이브러리
```

## React Native의 주요 기능

```jsx
JSX 코드에서 React Native 컴포넌트 사용:

	React Native에 내장된 컴포넌트들을 이용해 iOS 및 Android용 네이티브 UI 요소로 컴파일

네이티브 플랫폼 API 노출:

	기기의 카메라 등 특정 기능을 JavaScript 코드에서 사용할 수 있도록 지원

플랫폼 대상이 iOS와 Android:

	웹 브라우저 대신 모바일 플랫폼과 상호 작용하고, 모바일 앱 구축에 필요한 모든 컴포넌트와 API 제공
```

## React 컴포넌트의 작성

```jsx
React.js와의 유사성

	React Native 앱을 구축할 때 작성하는 코드는 React.js와 유사합니다.

	브라우저 기반 앱을 구축할 때 사용하는 React 컴포넌트와 비슷하게 생겼습니다.

	컴포넌트를 작성하는 방법은 여러 가지가 있으며, 화살표 함수를 사용하거나 function 키워드를 사용하는 방법이 있습니다.

	클래스 기반 컴포넌트도 사용할 수 있습니다.
```

## React Native 코드의 컴파일

```jsx
컴포넌트의 네이티브 앱 코드로의 컴파일

	React Native 코드로 작성한 컴포넌트는 네이티브 앱 코드로 컴파일됩니다.

	최종적으로는 네이티브 앱으로 묶이게 됩니다.


특별한 JSX 요소: View와 Text

	React Native에는 웹 개발에서 볼 수 없는 View와 Text라는 JSX 요소가 있습니다.

	이는 React Native의 특별한 컴포넌트로 컴파일됩니다.

	주의할 점은 JavaScript 논리가 아닌 View라는 JSX 코드만 컴파일된다는 것입니다.
```

## 컴포넌트 매핑 및 플랫폼별 매핑

```jsx
네이티브 요소로의 컴파일

	사용한 JSX 요소는 각 플랫폼의 네이티브 요소로 컴파일됩니다.

	웹에서 사용하는 요소들과 네이티브 플랫폼에서 사용하는 요소들을 비교해보겠습니다:


	웹(react-dom)	     Android	         iOS	          React Native
	  <input>	         EditText	      UITextField	       <TextInput>
	   <div>	           View	          UIView	           <View>


  예를 들어, 사용자가 텍스트를 입력할 수 있는 input 요소를 React Native에서는 <TextInput>으로 작성합니다.

	이 <TextInput> 컴포넌트는 Android에서는 EditText, iOS에서는 UITextField로 컴파일됩니다.
```

## JavaScript 논리 처리

```jsx
JavaScript 코드는 컴파일되지 않음

	JSX 외부에서 작성하는 JavaScript 코드 (예: 다양한 기능, if문, 상태 관리 등)는 컴파일되지 않습니다.

	React Native의 컴포넌트인 UI 요소는 컴파일되지만, JavaScript 논리는 그렇지 않습니다.

JavaScript 스레드에서의 실행

1. JavaScript 코드는 네이티브 앱 안에서 동작

	우리가 작성한 JavaScript 코드는 우리가 만든 앱 안에서 그대로 동작합니다.

2. JavaScript 스레드

	이 JavaScript 코드는 "JavaScript 스레드"라는 별도의 공간에서 실행됩니다.

	이 공간은 앱의 일부로 포함되어 있습니다.

3. React Native의 역할

	React Native는 이 JavaScript 스레드를 관리합니다.

	React Native는 JavaScript 코드가 네이티브 플랫폼(Android나 iOS)과 상호작용할 수 있도록 도와줍니다.

4. 상호작용 예시

	예를 들어, JavaScript 코드에서 버튼을 누르면 화면에 메시지를 띄우는 기능을 만든다고 합시다.

	이 기능은 JavaScript 코드로 작성되지만, React Native가 이 코드를 네이티브 앱에 전달하고 실행하게 해줍니다.

요약

	JavaScript 코드는 React Native를 통해 네이티브 앱 안에서 그대로 실행됩니다.

	React Native는 이 JavaScript 코드가 네이티브 앱과 잘 소통할 수 있도록 돕습니다.
```

## React Native의 이해

```jsx
React Native는 재사용 가능한 컴포넌트를 네이티브 요소로 매핑하고 컴파일합니다.

UI 요소는 컴파일되어 네이티브 플랫폼에서 사용되지만, JavaScript 논리는 컴파일되지 않고 네이티브 앱 내에서 실행됩니다.

React Native의 기본 원리를 이해하고 있다면,

네이티브 앱을 구축할 때 어떻게 JavaScript와 네이티브 요소들이 상호작용하는지 이해할 수 있습니다.
```

## React Native 시작하기

```jsx
1. React Native 공식 웹사이트

	React Native에 대해 더 자세히 배우고 싶다면 공식 웹사이트 reactnative.dev를 방문하세요.

	공식 웹사이트에서 'Get started' 버튼을 클릭하여 React Native 프로젝트 생성 방법을 알아볼 수 있습니다.

2. 개발 환경 설정

	'Get started' 페이지에서 'Environment setup'을 클릭한 후

	'Setting up the development environment'를 선택하면 두 가지 방법을 볼 수 있습니다:

		Expo CLI

		React Native CLI

3. Expo CLI와 React Native CLI 비교

	Expo CLI (추천)

		Expo는 서드 파티 서비스로 완전히 무료입니다.

		가입이나 비용 지불 없이 사용할 수 있으며, 유료 서비스도 있지만 필요 없습니다.

		프로젝트 생성이 쉽고, 코드 작성이 수월하며, 네이티브 기기의 기능을 활용하는 것이 편리합니다.

		필요시 언제든지 Expo를 중지하고 React Native CLI로 전환할 수 있습니다.

React Native CLI

		Expo가 등장하기 전 React Native 팀과 커뮤니티가 제공한 도구입니다.

		추가적인 구성과 설정이 필요하며, 기능 활용이 Expo보다 번거롭습니다.

		네이티브 소스 코드(Java, Objective-C, Swift, Kotlin)와의 통합이 비교적 쉽습니다.

		JavaScript 코드와 네이티브 소스 코드를 합쳐야 하는 경우에 유리합니다.

4. Expo CLI의 장점

	정리된 앱 개발 워크플로우

		프로젝트 생성이 간단하고 코드 작성이 쉬움.

		네이티브 기기의 기능(예: 카메라)을 쉽게 활용 가능.

		필요시 언제든지 React Native CLI로 전환 가능.

5. React Native CLI의 장점

	네이티브 소스 코드와의 통합

		Java, Objective-C, Swift, Kotlin과 같은 네이티브 소스 코드와의 통합이 용이.

		순수 React Native 워크플로우를 사용할 수 있습니다.

6. 이 강의에서 사용할 툴

	Expo 사용

		시작하기 쉽고, React Native 앱을 훨씬 쉽게 구축할 수 있기 때문에 이 강의에서는 Expo를 사용합니다.
```

# `expo init MyNewProject vs npx create-expo-app@latest`

---

## 1️⃣ `expo init MyNewProject`

### 🔹 정체

구버전 Expo CLI 명령어

예전 방식:

```bash
npm install -g expo-cli
expo init MyNewProject
```

### 🔹 특징

- 글로벌로 `expo-cli` 설치 필요
- 템플릿 선택 화면이 나옴
- 예전 Expo SDK 기반 구조
- 지금은 **사실상 deprecated 방향**

👉 2024~2026 기준으로는 거의 권장되지 않음

---

## 2️⃣ `npx create-expo-app@latest`

### 🔹 정체

현재 공식 권장 방식

React 생태계 스타일에 맞춘 새로운 방식

```bash
npx create-expo-app@latest MyNewProject
```

### 🔹 특징

- 글로벌 설치 필요 없음
- 항상 최신 버전 사용
- 최신 Expo SDK 자동 적용
- TypeScript 기본 지원
- Expo Router 기본 옵션 지원
- EAS 중심 구조

👉 **지금은 이게 표준**

---

# 🚀 차이점 정리표

| 항목             | expo init | create-expo-app |
| ---------------- | --------- | --------------- |
| 세대             | 구버전    | 최신            |
| 글로벌 설치 필요 | 있음      | 없음            |
| 유지보수         | 거의 안함 | 적극 지원       |
| 추천 여부        | ❌        | ✅              |
| 최신 Expo SDK    | 제한적    | 항상 최신       |

---

# 🔥 비유로 설명하면

- `expo init` → 예전 `create-react-app`
- `create-expo-app` → 지금 React 공식 방식

## Android 에뮬레이터 실행

```jsx
Android 에뮬레이터 실행

	Android Studio 설치 후, More Actions 버튼 클릭

	Virtual Device Manager에서 가상 기기 생성

	Pixel 5와 같은 프리셋 선택 (Play Store 아이콘이 있는 템플릿 선택) ( 없으면 사용 불가 )

	최신 Android 버전(API 32) 선택 ( 지금은 더 많은 최신 버전이 나왔다 )

	기본값으로 Finish 클릭하여 에뮬레이터 생성

	재생 버튼 클릭하여 에뮬레이터 실행
```

## Expo 앱 실행

```jsx
Expo 앱 실행 방법

	터미널에서 npm start 명령어 실행

	터미널에서 a를 눌러 자동 실행 (안드로이드가 켜져 있어야함)


	* 주의사항

		에뮬레이터 생성 시 Play Store 아이콘이 있는 템플릿 선택

		터미널의 npm start 프로세스를 중단하지 않도록 주의
```
