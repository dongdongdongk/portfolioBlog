# { 🌳 환경음 (Ambient Sound) }

빛나는 검을 손에 쥐고 여러분은 **Woodlands** 쪽으로 향해 **Evil Spit Plant**와 싸우게 됩니다.

다리 쪽으로 걸어가니, 다리 아래에서 **잔잔히 흐르는 강물 소리**가 들려옵니다.

이때, 이런 **River**의 사운드를 게임에 구현하려면 어떻게 해야 할까요?

---

## 🎧 AkEvent를 사용할 경우

가장 먼저 떠오르는 방법은 **`River` 게임 오브젝트에 `AkEvent` 컴포넌트를 추가하는 것**입니다.

하지만 이렇게 하면 **소리가 오브젝트의 한 지점(중심점)** 에서만 재생됩니다.

즉,

- 강 전체가 아닌 **한 점에서만** 물소리가 들리게 되며,
- 자연스럽게 흐르는 **넓은 강의 느낌을 표현하기 어렵습니다.**

---

## 🌊 AkAmbient 컴포넌트 사용하기

이럴 때는 **`AkAmbient` 컴포넌트**를 사용해야 합니다.

이 컴포넌트는 `AkEvent`와 동일한 기능(사운드 이벤트 재생)을 제공하면서,

추가로 **사운드의 위치(Positioning)** 를 세밀하게 지정할 수 있는 기능을 가집니다.

이를 통해 다음과 같은 효과를 낼 수 있습니다.

- 강 전체를 따라 소리가 들리게 만들기
- 강의 여러 부분에서 동시에 물이 흐르는 듯한 공간감 표현하기
- 플레이어가 강 가까이 갈수록 점점 더 크게 들리게 하기

---

## 💡 정리

| 상황                           | 사용할 컴포넌트 | 설명                                                                  |
| ------------------------------ | --------------- | --------------------------------------------------------------------- |
| 소리가 한 위치에서만 들리면 됨 | `AkEvent`       | 단순한 사운드 재생 (예: 버튼 클릭, 폭발음 등)                         |
| 소리가 공간 전체에 퍼져야 함   | `AkAmbient`     | 환경음처럼 넓은 범위에서 들리는 소리 (예: 강물, 바람, 숲의 새소리 등) |

---

## 🔎 요약

> AkEvent → 점(Point) 사운드
>
> `AkAmbient` → **공간(Ambient) 사운드**

## 1. AK Ambient Component 개념 이해하기

### 🎧 AK Ambient Component란?

- Wwise Unity Integration에서 제공하는 **컴포넌트**로,
  **환경음(Ambient Sound)** 을 자동으로 재생하거나 **특정 위치 기반**으로 배치할 때 사용합니다.
- **AK Event** 컴포넌트처럼 사운드를 재생할 수 있지만,
  AK Ambient Component는 추가 기능이 포함되어 있습니다.

---

### ✨ AK Ambient Component의 주요 기능

| 기능                        | 설명                                                                      |
| --------------------------- | ------------------------------------------------------------------------- |
| **Event 재생**              | AK Event처럼 특정 사운드를 재생할 수 있음.                                |
| **Position Type 설정**      | 사운드의 위치 계산 방식을 지정 (예: 2D, 3D, Trigger 기반 등).             |
| **Show Attenuation Sphere** | 감쇠 거리(사운드가 들리는 최대 거리)를 Unity Scene에서 시각적으로 표시함. |
| **Auto-Play / Loop 지원**   | 씬이 시작될 때 자동 재생하거나 반복 재생 가능.                            |

## 3. Wwise 설정: 감쇠(Max Attenuation) 포함시키기

### 🎯 목적

Unity에서 감쇠(Attenuation) 시각화를 하려면,

**Wwise SoundBank에 "Max Attenuation Distance" 정보가 포함**되어 있어야 합니다.

- 새로운 Wwise 프로젝트를 만들 때 Attenuation ShareSet의 Max Distance 값은 SoundBank의 메타데이터에 포함되지 않습니다. 반면 WAG에서는 메타데이터에 포함됩니다.

### 설정 방법

1. **Wwise에서 프로젝트 열기**
2. 상단 메뉴 → **Project → Project Settings** 로 이동
3. 왼쪽 탭 중 **SoundBanks** 선택
4. **“Max Attenuation”** 옵션이 켜져 있는지 확인
   - 이 옵션이 **비활성화되어 있으면 감쇠 정보가 SoundBank에 포함되지 않음**
5. 저장 후 Wwise 닫기

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380515/notion-blog/_/WWISE/Wwise_Unity_/Wwise_301_L2/image_1.png)

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380518/notion-blog/_/WWISE/Wwise_Unity_/Wwise_301_L2/image_2.png)

(추가) AkWwiseProjectInfo.GetData().GetEventMaxAttenuation() 함수를 호출하면 여러분의 사용자 정의 스크립트에서 Max Distance를 가져올 수 있습니다.

## 5. Show Attenuation Sphere로 거리 시각화하기

- **Show Attenuation Sphere** 옵션을 활성화한 후
  **“Current Event Only”** 버튼을 클릭합니다.
- Unity Scene에 **빨간색 반투명 구체(Red Transparent Sphere)** 가 나타납니다.

### 🔴 이 구체의 의미

- 이 구체는 Wwise에서 설정한 **Max Attenuation Distance(최대 감쇠 거리)** 를 나타냅니다.
- 즉, 이 구체의 반지름 안에서는 **Windmill Ambience** 소리가 들리고,
  구체 밖으로 벗어나면 소리가 들리지 않습니다.

## 1. Large Mode 개념 이해하기

### 🎧 AkAmbient란?

- **AkAmbient**는 Unity에서 **Wwise Event**를 재생하기 위한 컴포넌트입니다.
- 이 컴포넌트를 게임 오브젝트에 추가하면,
  해당 오브젝트의 **3D 공간 좌표**를 기준으로 사운드가 재생됩니다.

### 🎚️ Large Mode란?

- **하나의 Wwise Event**로 **여러 위치(Position)**에서 사운드를 재생할 수 있는 기능입니다.
- 각 위치는 “점 형태의 이미터(Point Emitter)”로 작동하며,
  여러 점에서 동시에 소리가 방사되는 것처럼 들리게 합니다.

🔹 **핵심 장점**

| 구분            | 설명                                                        |
| --------------- | ----------------------------------------------------------- |
| **효율성**      | 하나의 보이스 인스턴스(voice)만 사용 → 리소스 절약          |
| **자연스러움**  | 용암, 물, 바람 등 넓은 면적의 사운드를 입체적으로 재현      |
| **간결한 관리** | 여러 개의 오브젝트 대신 하나의 AkAmbient로 여러 지점을 제어 |

💡 즉, **“볼류메트릭(Volumetric) 사운드”**처럼 공간 전체에서 들리는 음향을 구현하는 기술입니다.

## 2. 문제 상황: 용암 환경음의 한계

던전(Dungeon) 지역에는 커다란 조각상이 있고,

그 아래에는 **넓게 퍼진 용암(Lava)**가 흐르고 있습니다.

그런데 현재 용암 사운드는 **Ambient_Lava 오브젝트의 한 지점에서만 재생**되고 있습니다.

즉, **소리가 특정 방향에서만 들리고**,

플레이어가 다리 위를 걸을 때 공간 전체에 울려 퍼지는 느낌이 부족합니다.

🎯 **문제 원인:**

현재 **Position Type**이 `Simple Mode`로 설정되어 있기 때문입니다.

→ 단일 위치에서만 소리가 재생되고 있음.

## 3. Large Mode 설정 과정

1. Unity 상단 메뉴에서

   `Audiokinetic > Certification > 301 > Lesson 2` 로 이동합니다.

2. **AkAmbient Position Types** 씬을 엽니다.
   - 여기서 Dungeon 지역의 환경이 설정되어 있습니다.
3. 게임을 **Play 모드**로 실행한 뒤

   `ESC → Library` 로 **텔레포트**합니다.
   - 다리 위를 걸어가며 Lava 소리가 한 방향에서만 들리는 것을 확인합니다.

4. **Play 모드를 종료(ESC → Play 종료)** 한 후,

   **Hierarchy** 창에서 아래 경로로 이동합니다.

   ```
   L2_3B - Dungeon Environment Scene
   └── Wwise
       └── Ambient_Lava
   ```

5. `Ambient_Lava` 게임 오브젝트를 선택하고,

   **Inspector**에서 `AkAmbient` 컴포넌트를 확인합니다.

6. **Position Type** 항목이 `Simple Mode`로 되어 있다면,

   드롭다운을 클릭하여 `Large Mode`로 변경합니다.

   ```
   AkAmbient Component
   ├── Event: Ambient_Lava
   ├── Position Type: Large Mode
   └── [ Show Attenuation Spheres ] 옵션 표시됨
   ```

## 5. Attenuation Sphere로 사운드 영역 확인하기

### 🟣 Show Attenuation Spheres

- Large Mode에서는 각 Position 오브젝트에 **Attenuation Sphere(감쇠 구)**를 표시할 수 있습니다.
- 이 구체는 사운드가 도달하는 범위를 나타냅니다.

1. **Inspector**에서 `Show Attenuation Spheres` 옵션을

   `Current Event Only` 로 설정합니다.

2. 이제 Scene 뷰에 각 포인트 주변에 **투명한 구체**가 표시됩니다.
   - 구가 겹칠수록 불투명하게 보이며,
     그 부분에서는 사운드 강도가 더 높게 들립니다.
3. 구체들이 잘 이어져 있으면,

   Lava 영역 전체가 고르게 덮여 **자연스러운 볼륨감 있는 환경음**을 얻을 수 있습니다.

💡 **만약 빈 공간이 있다면?**

- **Add Position**으로 새 점을 추가하거나
- **Wwise Attenuation 설정**에서 반경(Radius)을 늘리면 됩니다.

## 1. Multi Position 모드 개념 이해하기

- **정의:**
  Multi Position Mode는 **하나의 Wwise Event를 여러 위치에서 재생**할 때,
  **각 위치별로 별도의 보이스 인스턴스를 생성하지 않고 단 하나의 보이스만 사용**하도록 하는 기능입니다.
- **기본 아이디어:**
  예를 들어, 던전에 횃불이 17개 있다고 가정합시다.
  각 횃불마다 AkAmbient 컴포넌트가 추가되어 있다면,
  단순히 Event를 재생하는 것만으로 **17개의 보이스 인스턴스가 동시에 발생**합니다.
  → CPU와 메모리 낭비.
  하지만 Multi Position 모드를 사용하면
  **17개의 위치 정보는 유지하면서도 단 하나의 보이스 인스턴스만 재생**됩니다.
  즉, **공간적 배치 정보(Positioning)는 그대로** 유지하면서
  **오디오 성능 부하는 1개 인스턴스 수준으로 줄이는 최적화 방법**입니다.

## 2. Prefab과 AkAmbient 컴포넌트의 관계

- **Prefab이란:**
  Unity에서 게임 오브젝트를 재사용하기 위해 만든 **템플릿(청사진)**입니다.
  예를 들어 `301_Torch`라는 Prefab은 Torch의 **위치, 모델, 사운드 설정** 등을 모두 포함하고 있습니다.
- **Prefab의 특징:**
  - Scene에 Prefab을 여러 번 배치하면,
    모든 인스턴스가 **원본 Prefab의 속성을 상속**받습니다.
  - Prefab의 속성을 변경한 뒤 **Apply**하면
    → Scene에 배치된 모든 동일한 Prefab 인스턴스가 **자동으로 업데이트**됩니다.
- **AkAmbient 컴포넌트:**
  각 Torch Prefab에는 AkAmbient 컴포넌트가 붙어 있으며,
  이 컴포넌트가 **Wwise Event(예: Ambient_Torch)**를 실제로 재생시킵니다.

## 3. 현재 Torch 사운드 구조 살펴보기

   Torch마다 Event가 **별도로 재생**되고 있습니다.

   즉, **17개의 Torch → 17개의 보이스 인스턴스**가 생성되는 구조입니다.

## 4. Simple 모드에서의 보이스 확인하기

## 6. Prefab에 변경사항 적용(Apply)

1. 변경한 컴포넌트를 Prefab에 반영해야

   → 나머지 모든 Torch 오브젝트에도 같은 설정이 적용됩니다.

2. 방법:
   - `Inspector` 창의 **AkAmbient 컴포넌트**를 우클릭

3. 이제 모든 Torch Prefab 인스턴스(`301_Torch_02`, `301_Torch_03` …)가

   자동으로 **Multi Position 모드**를 상속받게 됩니다.

- Voice Inspector의 **왼쪽 패널**:
  - Ambient_Torch Event 인스턴스가 이제 **1개만 존재**
- Voice Inspector의 **오른쪽 패널**:
  - 각 횃불의 **Distance Attenuation(거리 감쇠)** 정보가 여전히 표시됨
  - 즉, Torch의 위치 차이에 따라 볼륨 감쇠가 자연스럽게 작동함을 의미함

✅ 결과적으로:

- 이전엔 Torch 17개 → **17개의 보이스 인스턴스**
- Multi Position 적용 후 → **1개의 보이스 인스턴스만 사용**

## 8. Multi Position 모드의 장점과 주의점

### 🌟 장점

1. **성능 최적화:**
   - 동일한 Event를 여러 위치에서 사용할 때 **CPU 및 메모리 사용량 대폭 절감**
2. **공간적 정확도 유지:**
   - 각 오브젝트의 **3D 위치 정보**는 그대로 유지됨
   - 플레이어가 Torch에 가까워질수록 사운드가 커지고 멀어질수록 작아짐
3. **레벨 디자이너 친화적:**
   - 새 Torch Prefab을 추가해도 자동으로 Multi Position 모드가 적용되어
     추가 설정 없이 바로 최적화된 사운드가 사용됨

### ⚠️ 주의점

- Multi Position 모드는 **단일 보이스 인스턴스를 공유**하므로
  각 위치별로 **랜덤화된 소리(Randomizer)**를 적용할 수 없습니다.
  즉, Torch마다 약간씩 다른 소리를 내는 연출은 불가능합니다.
- 하지만 **퍼포먼스 효율성**이 매우 높기 때문에
  **동일한 사운드가 여러 곳에서 동시에 들려야 하는 상황**(예: 횃불, 폭포, 비, 바람 등)에 이상적입니다.

---

✅ **요약**

| 항목               | Simple Mode              | Multi Position Mode             |
| ------------------ | ------------------------ | ------------------------------- |
| 보이스 인스턴스 수 | Torch 수만큼 생성 (중복) | 1개만 생성                      |
| 위치 정보          | 유지됨                   | 유지됨                          |
| 랜덤화된 사운드    | 가능                     | 불가능                          |
| 성능 효율          | 낮음                     | 매우 높음                       |
| 사용 예시          | 개별 사운드              | 반복적 환경음 (불, 비, 바람 등) |

---

💡 **정리 포인트:**

- Multi Position Mode는 **“하나의 Event로 여러 위치를 커버하는 최적화 기법”**이다.
- Prefab 구조를 활용하면 **한 번의 Apply로 전체 인스턴스에 적용 가능**하다.
- **성능 향상과 유지보수 효율** 모두 얻을 수 있는 핵심 기술이다.

## 1. Event Position Confiner 개념 이해하기

### 🎯 목적

- **환경음(Ambient Sound)** 이 넓은 지역에서 일정하게 들리도록 하기 위해 사용.
- 단순히 한 지점에서 소리를 내는 것이 아니라,
  플레이어의 위치에 따라 소리의 “출발점”을 **Collider 안에서 제한**함.

### 🔊 기존 AkAmbient의 한계

Wwise의 **AkAmbient 컴포넌트**에는 여러 모드가 있습니다:

- **Simple Mode** : 한 위치에서 단일 사운드 재생.
- **Large Mode** : 여러 오브젝트에서 하나의 이벤트를 재생해 넓은 공간 커버.
- **Multi-Position Mode** : 여러 위치를 지정해 한 번에 동일한 이벤트 재생.

하지만 이런 방식들은 모두 **“소리의 위치(Point)”** 기반입니다.

즉, 소리의 세기나 감쇠는 “그 위치로부터의 거리”에 따라 달라집니다.

➡️ 문제점:

넓은 지역 전체에 고르게 들리는 환경음을 만들기가 어려움.

매번 위치별로 볼륨 밸런스를 다시 조정해야 함.

### 🧩 해결책

**EventPositionConfiner** 스크립트를 사용합니다.

이 스크립트는 다음과 같이 작동합니다:

1. 특정 **Trigger Collider**(예: Box Collider)를 참조.
2. 플레이어의 **AkAudioListener** 위치를 계속 추적.
3. 소리의 위치를 Collider 내부 또는 가장 가까운 지점으로 “이동”시켜줌.
4. 그 결과:
   - **플레이어가 Collider 내부**일 때:
     → 소리의 감쇠 거리(Attenuation Distance)가 0 (즉, 바로 옆에서 들림)
   - **플레이어가 Collider 외부**일 때:
     → 소리의 위치가 Collider의 가장 가까운 면 쪽으로 이동하며 감쇠 적용

🎧 즉, 이 스크립트는 Collider 영역 전체를 “하나의 볼륨 영역(Volumetric Emitter)”처럼 작동하게 합니다.

## 4. 프로퍼티 설정하기

EventPositionConfiner에는 두 가지 주요 프로퍼티가 있습니다:

| 프로퍼티            | 설명                                     | 권장값          |
| ------------------- | ---------------------------------------- | --------------- |
| **Update Interval** | 소리 위치를 갱신하는 시간 간격 (초 단위) | `0.05`          |
| **Event**           | 재생할 Wwise 이벤트 지정                 | `Ambient_River` |

설정 방법:

1. `Event Name` 필드 클릭
2. **Ambient_River Event** 선택
3. Update Interval은 기본값 0.05 유지

💡 **작동 원리**

- Update Interval마다 플레이어 위치를 감지하고
  소리의 위치를 Collider 내부에서 재조정함.
- 너무 느리면 소리 이동이 지연되고
  너무 빠르면 CPU 부하가 증가할 수 있음.

## 7. 작동 원리 및 믹싱 활용 이해

### ⚙️ 작동 구조 요약

| 단계 | 작동 내용                                                                  |
| ---- | -------------------------------------------------------------------------- |
| 1    | 스크립트가 **Event(Ambient_River)** 를 새로운 GameObject에 Post            |
| 2    | 그 GameObject는 지속적으로 **AkAudioListener(Main Camera)** 의 위치를 추적 |
| 3    | 위치는 Collider 내부로 제한되어, Collider 밖으로 나가지 않음               |
| 4    | Update Interval마다 위치가 새로 계산되어 부드럽게 이동                     |
| 5    | Collider 내부에서는 Attenuation 거리 = 0 (즉, 바로 옆에서 들리는 효과)     |
| 6    | Collider 밖에서는 Collider의 가장 가까운 지점에서 감쇠 계산 적용           |

---

### 🎚️ 믹싱상의 장점

- **균일한 환경음 볼륨 유지**
  → 넓은 지역에서도 일정한 사운드 레벨로 재생됨.
- **자연스러운 감쇠(Attenuation)**
  → Collider 경계에서 부드럽게 볼륨이 줄어듦.
- **믹싱 단순화**
  → 위치별로 개별 볼륨 조정할 필요가 없음.

---

### 💡 개발 팁 (비슷한 스크립트 제작 시)

- **빠른 위치 업데이트 유지:**
  플레이어(AkAudioListener)의 이동 속도를 따라갈 만큼 짧은 간격으로 업데이트해야 함.
- **Spread(확산) 추가:**
  Attenuation ShareSet에서 근거리 스프레드를 살짝 주면
  소리 위치가 빠르게 움직일 때도 부드럽게 들림.
- **Mesh Collider 사용 시:**
  Convex로 설정해야 정상적으로 Collider 안에서 위치 계산 가능.

---

| 항목            | 설명                                                          |
| --------------- | ------------------------------------------------------------- |
| **핵심 목적**   | Collider 안에서만 소리의 위치를 제한해 자연스러운 환경음 구현 |
| **적용 대상**   | 강, 바람, 도시 소음 등 넓게 퍼진 Ambient 사운드               |
| **이점**        | 감쇠 제어 자동화, 믹싱 일관성 향상, CPU 효율적 사용           |
| **시각적 확인** | Scene 뷰에서 파란 구로 표시되는 사운드 위치 확인 가능         |

**EventPositionConfiner 스크립트**는

“환경음을 공간에 맞게 제한하고 균일하게 유지”하기 위한

**사용자 정의 볼류메트릭 사운드 제어 도구**입니다.
