# { 카메라 흔들림(Camera Shake) }

게임에 **카메라 흔들림 효과**를 추가해서 폭발이나 충돌 시 화면이 흔들리게 만듭니다! 🎥

---

## 🎯 1. 카메라 흔들림이란?

### 효과

```
카메라 흔들림 = 화면 흔들림 효과

사용 예:
- 폭발 시 💥
- 충돌 시 💥
- 지진 시 🌍
- 강한 충격 시

→ 게임에 물리적 충격감 부여!
```

### 이 게임에서의 2가지 흔들림

```
1. Hit Camera Shake (약한 흔들림)
   → 발사체 충돌 시

2. Death Camera Shake (강한 흔들림)
   → Tank/Tower 파괴 시
```

### 설정 (BP_HitCameraShake)

```
Details 패널:

1. Shake Pattern: Perlin Noise 선택

2. Location (위치 흔들림)
   - X: Amplitude = 10, Frequency = 10
   - Y: Amplitude = 10, Frequency = 10
   - Z: Amplitude = 10, Frequency = 10

3. Rotation: 사용 안 함 (0으로 유지)

4. Timing
   - Duration: 0.25초 (짧게)
   - Blend In Time: 0.05초
   - Blend Out Time: 0.05초
```

### 주요 설정 의미

```cpp
Amplitude (진폭):
- 흔들림의 크기
- 클수록 크게 흔들림

Frequency (주파수):
- 흔들림의 속도
- 클수록 빠르게 흔들림

Duration (지속 시간):
- 흔들림 지속 시간

Blend In/Out:
- 부드러운 시작/끝
- 자연스러운 효과
```

## 💻 3. C++ 코드 구현

### Projectile.h - 변수 선언

```cpp
UPROPERTY(EditAnywhere)
TSubclassOf<UCameraShakeBase> HitCameraShakeClass;
```

### Projectile.cpp - OnHit에서 재생

```cpp
void AProjectile::OnHit(...)
{
    // ... (데미지, 파티클, 사운드)

    // 카메라 흔들림 재생
    if (HitCameraShakeClass)
    {
        APlayerController* PlayerController =
            UGameplayStatics::GetPlayerController(GetWorld(), 0);

        if (PlayerController)
        {
            PlayerController->ClientStartCameraShake(HitCameraShakeClass);
        }
    }

    Destroy();
}
```

## 🎯 1. 핵심 비유로 이해하기

### 🏗️ 건물로 비유

```
UCameraShakeBase* = 건물 그 자체
  ↓
  실제 지어진 건물
  이미 존재하는 건물

TSubclassOf<UCameraShakeBase> = 건물 설계도
  ↓
  건물을 지을 수 있는 설계도
  아직 짓지 않았지만 지을 수 있음
```

## 💡 2. 실제 코드로 비교

### ❌ 일반 포인터를 쓰면?

```cpp
UPROPERTY(EditAnywhere)
UCameraShakeBase* HitCameraShake;  // 실제 객체

문제점:
1. 게임 시작할 때 이미 메모리에 생성되어 있어야 함
2. C++ 코드에서 직접 생성해야 함
3. 블루프린트 에디터에서 만든 걸 못 씀!

예시:
┌────────────────────┐
│ 이미 만들어진 객체  │ ← 메모리에 존재
│ (인스턴스)         │
└────────────────────┘
```

### ✅ TSubclassOf를 쓰면?

```cpp
UPROPERTY(EditAnywhere)
TSubclassOf<UCameraShakeBase> HitCameraShakeClass;  // 클래스 (설계도)

장점:
1. 블루프린트를 선택할 수 있음!
2. 나중에 필요할 때 생성함
3. 에디터에서 쉽게 바꿀 수 있음

예시:
┌────────────────────┐
│ BP_HitCameraShake  │ ← 설계도 (블루프린트)
│ (클래스)           │
└────────────────────┘
         ↓
   필요할 때 생성
         ↓
┌────────────────────┐
│ 실제 객체          │
└────────────────────┘
```

## 🎮 3. 게임 개발에서 왜 필요한가?

### 상황 설명

```
우리는 C++ 코드를 작성함
  ↓
하지만 BP_HitCameraShake는 블루프린트 에디터에서 만듦
  ↓
C++ 코드는 블루프린트 파일을 직접 볼 수 없음!
  ↓
해결책: "설계도"만 저장해두고, 에디터에서 할당
```

### 작동 방식

```cpp
// C++에서 (코드)
TSubclassOf<UCameraShakeBase> HitCameraShakeClass;
// "이건 UCameraShakeBase 종류의 클래스를 받을 거야"

// 에디터에서 (블루프린트)
HitCameraShakeClass = BP_HitCameraShake 선택
// "이 설계도를 사용해"

// 실행 시 (게임)
ClientStartCameraShake(HitCameraShakeClass);
// "이 설계도로 객체를 만들어서 실행해"
```

```cpp
사용할 때:
// 그냥 사용... 하지만 이미 만들어져 있어야 함
```

```cpp
TSubclassOf<UCameraShakeBase> MyCameraShakeClass;

생성자:
// 아무것도 안 함! 에디터에서 할당!

에디터에서:
MyCameraShakeClass = BP_MyCameraShake 선택
// ✅ 쉬움!
// ✅ 블루프린트 사용 가능!
// ✅ 언제든지 바꿀 수 있음!

사용할 때:
ClientStartCameraShake(MyCameraShakeClass);
// 이때 비로소 객체 생성됨
```

## 🤔 7. 자주 하는 질문

### Q1: 그냥 포인터 쓰면 안 돼요?

```
포인터 (UCameraShakeBase*):
- 이미 존재하는 객체를 가리킴
- C++에서만 만들 수 있음
- 블루프린트 못 씀

TSubclassOf:
- 클래스(설계도)를 저장
- 블루프린트 선택 가능! ✨
- 에디터에서 쉽게 바꿈

→ 게임 개발에서는 TSubclassOf가 훨씬 편함!
```

### Q2: 왜 이름이 "Class"로 끝나나요?

```cpp
HitCameraShakeClass
                 ↑
              "Class"

의미:
"이건 클래스(설계도)야, 실제 객체가 아니야"

명명 규칙:
- 일반 포인터: HitCameraShake
- TSubclassOf: HitCameraShakeClass
```

### Q3: 언제 실제 객체가 만들어지나요?

```cpp
// 이 시점에는 설계도만 있음
TSubclassOf<UCameraShakeBase> ShakeClass;

// 이 함수를 호출할 때 비로소 객체 생성!
ClientStartCameraShake(ShakeClass);
                       ↑
                "이 설계도로 객체 만들어줘"
```
