# 도커 코드 작성

```jsx
완성된 도커 파일 내용이다
```

```jsx
# 이 Dockerfile은 Node.js 애플리케이션을 실행하기 위한 컨테이너 이미지를 구성합니다.

# Node.js 21 버전을 기반으로 하는 Alpine 리눅스 이미지를 사용합니다.
FROM node:21-alpine

# 컨테이너 내부에서 작업할 디렉토리를 /app으로 설정합니다. ( 아무렇게 만들어 줘도 괜찮다 )
WORKDIR /app

# 현재 호스트의 모든 파일과 디렉토리를 컨테이너 내부의 /app 디렉토리로 복사합니다.
# COPY 명령어는 호스트의 파일 시스템에 있는 파일을 컨테이너로 복사하는 역할을 합니다.
# 여기서는 모든 파일과 디렉토리를 복사하므로, 소스 코드 파일부터 설정 파일, 의존성 모듈까지 모든 것을 복사합니다.
COPY . .

# package.json에 명시된 패키지들을 설치합니다.
# npm ci 명령어는 package-lock.json 파일에 명시된 의존성 모듈을 엄격하게 따라가며 설치합니다.
# package-lock.json은 의존성 모듈의 정확한 버전을 포함하고 있으며, 이를 통해 일관된 의존성 환경을 유지할 수 있습니다.
RUN npm ci

# 컨테이너가 외부와 통신할 수 있도록 5000번 포트를 열어줍니다.
# EXPOSE 명령어는 컨테이너가 외부에 노출할 포트를 설정합니다.
# 이렇게 설정된 포트는 호스트와의 네트워크 통신을 위해 사용됩니다.
EXPOSE 5000

# 컨테이너가 실행될 때 실행할 기본 명령을 설정합니다.
# ENTRYPOINT 명령어는 컨테이너가 시작될 때 실행할 명령을 지정합니다.
# 이 경우 node 명령어를 사용하여 server.js 파일을 실행합니다.
ENTRYPOINT [ "node", "server.js" ]
```

# 도커 이미지 만들기

```jsx
이제 위의 내용을 기반으로 도커 이미지를 만들어준다
```

```jsx
Docker 이미지 빌드:

docker build -t 이미지_이름:태그 .

ex) docker build -t my-node-app:v1 .

예를 들어, 이미지 이름을 my-node-app으로 하고 버전을 v1으로 하려면 다음과 같이 명령을 실행
```

```jsx
-t 옵션은 이미지에 이름을 붙이는 역할을 합니다. 이미지_이름은 이미지의 이름을 나타내며,

태그는 이미지의 버전을 나타냅니다. 보통은 latest를 사용하여 최신 버전을 나타냅니다. ( 꼭 필요한건 아니다 )

.은 현재 디렉토리를 나타냅니다. Dockerfile이 있는 디렉토리에서 실행해야 합니다.
```

# 도커 이미지 실행

```jsx
도커 이미지가 성공적으로 빌드되면 다음 명령어를 사용하여 이미지를 실행할 수 있습니다

docker run -p 호스트_포트:컨테이너_포트 이미지_이름:태그

ex) docker run -p 8080:5000 my-node-app:v1

웹 브라우저에서 localhost:8080을 열면 서버에 액세스할 수 있을 것입니다.
```

```jsx
-p 옵션은 포트를 바인딩하는 역할을 합니다. 호스트의 포트와 컨테이너의 포트를 연결시켜주는 역할을 합니다.

호스트_포트는 외부에서 접근할 수 있는 포트를 나타냅니다. 보통은 5000 등을 사용합니다.

컨테이너_포트는 컨테이너 내부의 서비스가 동작하는 포트를 나타냅니다. Dockerfile에서 EXPOSE로 지정한 포트와 일치해야 합니다.

이미지_이름:태그는 실행할 도커 이미지를 가리킵니다.
```

# Docker Hub에 이미지 올리기

## 도커 허브 계정 만들고 로그인

```jsx
Docker 이미지를 로컬에서 빌드한다. 이미지를 빌드할 때는 Dockerfile을 사용하여 빌드하거나 Docker CLI를 사용하여 이미지를 빌드한다. ( 위의 내용)

먼저 Docker Hub에 계정을 만들고 로그인한다. 계정을 만들 때는 https://hub.docker.com/ 에서 가입할 수 있다.

로그인은 docker login 입력
```

## 이미지에 태그 지정

```jsx
빌드된 이미지에 태그를 지정

REPOSITORY   TAG       IMAGE ID       CREATED          SIZE
server       v1        e5654deba90b   6 seconds ago    199MB
socket       v1        2532218ad855   16 minutes ago   155MB

ex) docker tag server:v1 dongdongdongk/server:v1

server:v1: 원본 이미지의 이름과 태그이다. server는 이미지 이름이며, v1은 해당 이미지의 버전을 나타낸다.

dongdongdongk/server:v1: 새로운 이미지의 이름과 태그이다.

dongdongdongk는 Docker Hub의 사용자 이름이며, server는 이미지의 이름, v1은 이미지의 버전을 나타낸다.

이 명령어는 원본 이미지에 새로운 이름과 태그를 부여하여 새로운 이미지를 생성하는 것이다.

( 리포지토리 이름은 이미지가 푸시될 위치를 나타내고, 태그는 이미지의 버전을 나타낸다. )

```

## 이미지 푸시

```jsx

Docker Hub에 푸시한다. 예를 들어, 다음 명령을 사용하여 이미지를 푸시할 수 있다.

docker push username/repository:tag

username: Docker Hub나 다른 Docker 레지스트리에 등록한 사용자 이름입니다. 이는 이미지를 푸시하는 사용자를 식별하는 데 사용됩니다.

repository: 이미지가 저장될 레지스트리의 저장소(repository) 이름입니다. 저장소는 동일한 이름의 이미지를 그룹화하고 관리하는 데 사용됩니다. 사용자 이름 뒤에 슬래시('/')를 사용하여 지정합니다.

tag: 이미지에 부여할 태그입니다. 태그는 이미지의 버전이나 레이블을 식별하는 데 사용됩니다. 보통은 latest나 숫자 또는 문자열을 사용합니다.

예를 들어, docker push johnsmith/myapp:latest 명령은 johnsmith라는 사용자의 Docker Hub 계정에 myapp이라는 이름의 저장소에 latest라는 태그를 가진 이미지를 푸시하는 것입니다.
```

# 최종 정리

## **Dockerfile 작성하기:**

```jsx
# Dockerfile

# 기본 이미지로 Python 3 사용
FROM python:3

# 작업 디렉토리 설정
WORKDIR /app

# 현재 디렉토리의 모든 파일을 컨테이너의 /app 디렉토리로 복사
COPY . /app

# 애플리케이션 실행을 위한 명령어
CMD ["python", "app.py"]
```

## **Docker 이미지 빌드하기:**

```jsx
docker build -t my-python-app .
```

```jsx
docker build: Dockerfile을 사용하여 Docker 이미지를 빌드하는 명령어이다.

-t my-python-app: -t 옵션을 사용하여 이미지에 이름을 지정한다. 여기서는 my-python-app으로 지정했다.

.: Dockerfile이 있는 현재 디렉토리를 가리킨다.
```

## **Docker Hub에 로그인하기:**

```jsx
docker login
```

## **Docker 이미지 푸시하기:**

```jsx
docker tag my-python-app yourdockerhubusername/my-python-app

docker push yourdockerhubusername/my-python-app
```

```jsx
docker tag my-python-app yourdockerhubusername/my-python-app:

빌드한 이미지에 새로운 이름을 지정한다. 이 경우, my-python-app 이미지를 yourdockerhubusername/my-python-app으로 태그한다.

docker push yourdockerhubusername/my-python-app:

태그한 이미지를 도커 허브에 푸시한다.

* 이미지를 새로운 이름으로 태그하는 이유

도커 허브에 이미지를 푸시하려면 해당 이미지를 허브에 업로드할 때 사용할 이름을 지정해야 한다.

도커 허브에 이미지를 업로드하려면 허브 계정의 이름을 이미지 이름에 포함시켜야 한다. 즉, yourdockerhubusername/my-python-app와 같이 이미지의 이름을 변경하여 푸시할 필요가 있다.

보통 애플리케이션을 개발하고 배포할 때, 버전 관리가 필요하다.

새로운 빌드를 하거나 변경을 가할 때마다 새로운 태그를 부여하여 이전 버전과 구분할 수 있다. 이를 통해 특정 버전의 이미지를 쉽게 식별하고 관리할 수 있다.
```
