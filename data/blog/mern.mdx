# **MERN 프로젝트 계획 짜는 순서**

## **계획 수립의 중요성**

```jsx
프로젝트를 시작하기 전에 세심한 계획이 필요하며,

어떤 사항을 고려해야 하는지에 대한 인식이 필요하다.

MERN 프로젝트를 성공적으로 구축하기 위해서는 각 단계를 신중하게 따라가는 것이 중요하다.
```

```jsx
1. 계획의 첫 단계: 아이디어 선정

프로젝트의 첫 단계는 해결할 문제나 개발할 애플리케이션의 아이디어를 선정하는 것이다.

이미 결정된 아이디어를 기반으로 나머지 계획을 세울 것

2. 프론트엔드 디자인 및 스케치

프론트엔드를 위한 디자인 및 스케치를 진행한다.

이는 개발자가 직접 스타일링을 하는 것이 아닌, 프로젝트의 뼈대를 그리는 작업으로, 외부 디자이너에게 위탁할 수도 있다.

3. 데이터 모델링

백엔드에서 다룰 데이터 모델을 구체화한다.

프론트엔드와 백엔드 간의 데이터 흐름을 정의하고, 어떤 종류의 데이터가 필요한지를 계획한다.

4. 백엔드 엔드포인트 및 페이지 계획

백엔드에서는 필요한 엔드포인트를 계획하고, 프론트엔드에서는 여러 컴포넌트로 이뤄진 페이지를 설계한다.

싱글 페이지 애플리케이션의 특성을 고려하여 페이지 간의 이동과 데이터 흐름을 고려한다.

5 .마무리와 향후 진행

모든 계획이 완료되면 프로젝트의 마무리와 향후 진행 방향을 고려한다.

프론트엔드의 뼈대, 데이터 모델, 백엔드 엔드포인트 등이 정의되어 개발자들이 협업하기에 적합한 상태로 만들어진다.
```

## **애플리케이션의 구성**

```jsx
주요 엔티티: 사용자와 장소

사용자 모델 데이터: 이름, 이메일 주소, 비밀번호, 이미지

장소 모델 데이터: 장소명, 설명, 주소(도로명, 도시), 위치 좌표(위도와 경도), 이미지

독립형 엔티티: 사용자는 여러 장소를 생성 가능, 각 장소는 한 명의 사용자에게 귀속
```

## **백엔드 API 엔드포인트**

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381298/notion-blog/_/React_NodeJS_Express_MongoDB_-_MERN_/MERN_/Untitled_1.png)

### 사용자 엔드포인트

```jsx
/api/users: 모든 사용자 목록을 반환하는 GET 요청

/api/users/signup: POST 요청으로 신규 사용자 생성, 필요한 데이터 첨부

/api/users/login: POST 요청으로 로그인, 이메일과 비밀번호 첨부
```

### **장소 엔드포인트**

```jsx
/api/places/user/:uid: GET 요청으로 주어진 사용자 ID의 모든 장소 목록 반환

/api/places/:pid: GET 요청으로 해당 ID의 장소 반환

/api/places/: POST 요청으로 새 장소 생성, 필요한 데이터 첨부

/api/places/:pid: PATCH 요청으로 해당 ID의 장소 업데이트, 업데이트 데이터 첨부

/api/places/:pid: DELETE 요청으로 해당 ID의 장소 삭제
```

# SPA 페이지 계획

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381298/notion-blog/_/React_NodeJS_Express_MongoDB_-_MERN_/MERN_/Untitled_2.png)

```jsx
시작 페이지 (/):

초기 페이지로 mycoolpage.com/에 해당합니다.

사용자 목록을 표시합니다.

사용자를 클릭하면 해당 사용자의 장소로 이동하는 라우트가 필요합니다.

사용자 페이지 (/:uid):

동적 사용자 ID를 가진 라우트입니다.

선택한 사용자의 모든 장소를 불러오는 라우트 (/places)로 이동합니다.

인증 페이지 (/auth):

회원 가입 또는 로그인 양식을 표시합니다.

장소 추가 페이지 (/places/new):

장소를 추가하는 양식을 표시합니다.

이 페이지는 인증된 사용자만 접근 가능합니다.

장소 업데이트 페이지 (/places/:pid):

선택한 장소의 데이터를 업데이트하는 페이지로 연결됩니다.

이 페이지는 해당 장소의 생성자인 인증된 사용자만 접근 가능합니다.

인증 여부에 따른 페이지 표시:

사용자 목록과 선택한 사용자의 장소 목록은 항상 접근 가능합니다.

로그인 여부에 따라 편집 또는 삭제 버튼의 표시 여부가 변경됩니다.

인증 및 권한 관리:

/auth 라우트는 이미 로그인한 사용자에게는 접근할 수 없어야 합니다.

장소 추가 및 업데이트 페이지는 인증된 사용자만 접근 가능하며, 해당 장소의 생성자가 아닌 경우 편집 및 삭제 버튼이 표시되지 않습니다.

페이지 구현 계획:

각 페이지는 React로 작성되며, 프론트엔드 라우팅을 지원하는 라이브러리를 사용합니다.

라우트 구조는 동적 사용자 ID 및 장소 ID를 포함하여 프로젝트 요구 사항을 충족합니다.

프로젝트를 진행할 때는 이러한 페이지 및 라우트 구조를 기반으로 구현을 진행하면 됩니다.
```
