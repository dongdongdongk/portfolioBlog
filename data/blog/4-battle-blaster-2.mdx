## 🎯 왜 Game Mode가 필요한가?

### 현재 방식 vs 새로운 방식

| 방식                            | 장점                | 단점           |
| ------------------------------- | ------------------- | -------------- |
| **Auto Possess** (현재)         | 간단함              | 확장성 없음    |
| **Game Mode + Player Start** ✅ | 게임 규칙 관리 가능 | 설정 단계 많음 |

### Game Mode란?

```
Game Mode = 게임의 규칙을 정하는 관리자 👔

역할:
├─ 어떤 Pawn을 사용할지 결정
├─ 게임 승리/패배 조건 관리
├─ 점수/타이머 관리
└─ UI 표시 제어
```

**비유**: 축구 경기의 심판 + 규칙집

# { 언리얼 엔진 Enhanced Input System 설정 가이드 }

이 코드는 언리얼 엔진에서 새로운 입력 시스템(Enhanced Input)을 설정하는 과정입니다. 단계별로 쉽게 설명드리겠습니다.

## 1. 기본 개념 이해

**Input Mapping Context(IMC)란?**

- 키보드/마우스 입력을 게임 내 행동으로 연결하는 설정 파일
- 예: "W키 = 앞으로 이동", "Space = 점프"

**왜 Tank 클래스에서 설정하나?**

- Tank는 플레이어가 조종하는 캐릭터
- 적(Enemy)은 플레이어 입력이 필요 없음
- 따라서 Tank에만 입력 시스템을 넣어야 효율적

## 2. 코드 분석

### BeginPlay 함수의 역할

```cpp
void ATank::BeginPlay()
{
    Super::BeginPlay();  // 부모 클래스의 초기화 먼저 실행

    // 1단계: 플레이어 컨트롤러 가져오기
    APlayerController* PlayerController = Cast<APlayerController>(GetController());
```

**플레이어 컨트롤러란?**

- 게임에서 플레이어를 대표하는 객체
- 입력을 받아 캐릭터(Pawn)를 조종함

```cpp
    if (PlayerController)  // 컨트롤러가 제대로 있는지 확인
    {
        // 2단계: 로컬 플레이어 가져오기
        ULocalPlayer* LocalPlayer = PlayerController->GetLocalPlayer();
```

**로컬 플레이어란?**

- 이 컴퓨터에서 직접 플레이하는 플레이어
- 온라인 멀티플레이와 구분하기 위한 개념

```cpp
        if (LocalPlayer)  // 로컬 플레이어가 있는지 확인
        {
            // 3단계: Enhanced Input 서브시스템 가져오기
            UEnhancedInputLocalPlayerSubsystem* Subsystem =
            ULocalPlayer::GetSubsystem<UEnhancedInputLocalPlayerSubsystem>(LocalPlayer);

```

**서브시스템이란?**

- 언리얼 엔진의 특정 기능을 담당하는 관리자
- Enhanced Input 서브시스템 = 새 입력 시스템을 관리

```cpp
            if (Subsystem)  // 서브시스템이 제대로 있는지 확인
            {
                // 4단계: 우리가 만든 입력 매핑을 등록
                Subsystem->AddMappingContext(DefaultMappingContext, 0);
                //                           ↑우리가 만든 IMC    ↑우선순위(0=기본)
            }
        }
    }
}
```

## 3. 전체 흐름 요약

```
게임 시작
    ↓
Tank가 생성됨 (생성자 실행)
    ↓
BeginPlay 실행
    ↓
플레이어 컨트롤러 찾기
    ↓
로컬 플레이어 찾기
    ↓
Enhanced Input 서브시스템 찾기
    ↓
우리가 만든 IMC(Input Mapping Context) 등록
    ↓
이제 입력이 작동할 준비 완료!
```

## 4. if문을 여러 번 사용하는 이유

각 단계에서 객체가 제대로 존재하는지 확인해야 안전합니다:

```cpp
if (PlayerController)      // 1. 컨트롤러가 있나?
    if (LocalPlayer)       // 2. 로컬 플레이어가 있나?
        if (Subsystem)     // 3. 서브시스템이 있나?
            // 모두 있을 때만 실행
```

만약 확인 없이 사용하면 프로그램이 죽을(크래시) 수 있습니다.

## 6. 핵심 요약

1. **Enhanced Input System**: 언리얼의 새로운 입력 처리 방식
2. **Input Mapping Context**: 키 입력과 게임 행동을 연결하는 설정
3. **BeginPlay**: 게임 시작 시 IMC를 등록하는 곳

# { 언리얼 엔진 Enhanced Input System 설정 가이드 }

## 1단계: Input Mapping Context 생성

**에디터 작업:**

- Content 폴더에 "Input"이라는 새 폴더 생성
- 우클릭 → Input → Input Mapping Context 선택
- 이름을 "IMC_Default"로 지정

**역할:** Input Mapping Context는 어떤 키보드/마우스 입력이 어떤 게임 액션과 연결되는지 정의하는 설정 파일입니다.

```cpp
void ATank::BeginPlay()
{
    Super::BeginPlay();

    // 1단계: PlayerController 가져오기
    APlayerController* PlayerController = Cast<APlayerController>(GetController());
    if (PlayerController)
    {
        // 2단계: LocalPlayer 가져오기
        ULocalPlayer* LocalPlayer = PlayerController->GetLocalPlayer();
        if (LocalPlayer)
        {
            // 3단계: Enhanced Input Subsystem 가져오기
            UEnhancedInputLocalPlayerSubsystem* Subsystem =
                ULocalPlayer::GetSubsystem<UEnhancedInputLocalPlayerSubsystem>(LocalPlayer);
            if (Subsystem)
            {
                // 4단계: Mapping Context 추가
                Subsystem->AddMappingContext(DefaultMappingContext, 0);
            }
        }
    }
}
```

**각 단계 설명:**

1. **PlayerController**: 게임 월드에서 플레이어를 대표하는 클래스
2. **LocalPlayer**: 로컬 플레이어 정보를 담는 객체
3. **Subsystem**: Enhanced Input 시스템을 관리하는 하위 시스템
4. **AddMappingContext**: 우리가 만든 Input Mapping Context를 게임에 등록 (우선순위 0)

- `&` → "복사하지 말고 원본 그대로 봐"
- `const` → "보기만 하고 바꾸지는 마"

---

### Q2: "왜 `Get<float>()`를 써요?"

**A:** `FInputActionValue`는 "포장 상자"같은 거예요.

```

    └─ float 값 (내용물)

Get<float>() → 상자를 열어서 내용물 꺼내기
```

---

### Q3: "Boolean 타입은 언제 써요?"

**A:**

```cpp

Float   → 이동처럼 "방향과 세기"가 필요할 때
```

## 🤔 왜 Local Space를 써야 하나?

### 상황 1: World Space를 쓴다면? ❌

```
탱크가 북쪽을 보고 있을 때:
앞으로 = Y축 증가

탱크가 동쪽으로 90도 회전:
앞으로 = X축 증가???

탱크가 남쪽으로 180도 회전:
앞으로 = Y축 감소???

→ 탱크가 어디를 보는지 계산해야 함 😵
```

### 상황 2: Local Space를 쓴다면? ✅

```
탱크가 어디를 보든:
앞으로 = X축 양수 (끝!)

북쪽을 보든, 동쪽을 보든, 남쪽을 보든
항상 X축 양수 = 앞!

→ 계산 필요 없음! 😊
```

**비유로 이해하기:**

```
World Space = 나침반
"북쪽으로 가" → 내가 어디를 보든 북쪽으로

Local Space = 자동차
"앞으로 가" → 차가 어디를 보든 앞으로
```

우리는 탱크니까 **자동차 방식(Local Space)**이 편해요!

## ⏱️ DeltaTime 완전 정복

### DeltaTime이 뭔가요?

**"지난 프레임부터 지금까지 걸린 시간"**

```
게임 = 연속된 사진(프레임)의 빠른 재생

프레임1 → (0.016초) → 프레임2 → (0.016초) → 프레임3
         ↑ 이게 DeltaTime!
```

### 왜 필요한가요?

**문제 상황: DeltaTime 없이 코드를 짠다면?**

```cpp
// 나쁜 예
void MoveInput() {
    DeltaLocation.X = 10;  // 매 프레임마다 10cm씩 이동
}
```

**결과:**

```
좋은 컴퓨터 (60fps):
1초 = 60프레임 = 10cm × 60 = 600cm 이동

나쁜 컴퓨터 (30fps):
1초 = 30프레임 = 10cm × 30 = 300cm 이동

→ 컴퓨터 성능에 따라 속도가 다름! ❌
```

**해결: DeltaTime 사용**

```cpp
// 좋은 예
void MoveInput() {
    DeltaLocation.X = 600 * DeltaTime;
}
```

**결과:**

```
좋은 컴퓨터 (60fps, DeltaTime = 0.016초):
1초 = 60프레임
한 프레임당: 600 × 0.016 = 9.6cm
1초 동안: 9.6 × 60 = 576cm ≈ 600cm

나쁜 컴퓨터 (30fps, DeltaTime = 0.033초):
1초 = 30프레임
한 프레임당: 600 × 0.033 = 19.8cm
1초 동안: 19.8 × 30 = 594cm ≈ 600cm

→ 모든 컴퓨터에서 비슷한 속도! ✅
```

## 🔄 회전 이해하기

### 3D 공간의 회전 3가지

```
        ↑ Z축 (위)
        |
        |
    ────┼────→ X축 (앞)
        |
       / Y축 (오른쪽)
      /

Pitch (피치) = X축 중심 회전 (고개 끄덕이기)
Yaw (요)     = Z축 중심 회전 (고개 좌우 돌리기) ← 우리가 쓸 것!
Roll (롤)    = Y축 중심 회전 (비행기 기울이기)
```

**우리가 원하는 것:**

```
A키 → 왼쪽으로 돌기 → Yaw를 음수로
D키 → 오른쪽으로 돌기 → Yaw를 양수로
```

**비유:**

- 피치 = 고개 끄덕이기 "응"
- 요 = 고개 저으기 "아니야" ← 이거!
- 롤 = 체조 선수 옆구르기

```cpp
    // 2. 회전량 계산
    FRotator DeltaRotation = FRotator(0.0f, 0.0f, 0.0f);
    DeltaRotation.Yaw = TurnRate * InputValue * GetWorld()->GetDeltaSeconds();

    // 3. 실제로 회전하기
    AddActorLocalRotation(DeltaRotation, true);
}
```

## 🔍 코드 완전 분해

### FRotator란?

**3D 회전을 나타내는 상자**

```cpp
//                      ↑      ↑    ↑
//                   X축회전 Z축회전 Y축회전
```

### 왜 0으로 시작하나?

```cpp

```

**초기 상태:**


**시각화:**

```
  고개끄덕   고개젓기   비행기기울기
```

### Yaw 값 계산하기

```cpp
DeltaRotation.Yaw = TurnRate * InputValue * GetWorld()->GetDeltaSeconds();
```

**단계별 계산:**

```
설정:
- TurnRate = 100 (초당 100도 회전)
- InputValue = 1.0 (D키)
- DeltaTime = 0.016초 (60fps)

계산:
100 × 1.0 × 0.016 = 1.6도

의미:
"이번 프레임에는 1.6도 오른쪽으로 회전!"
```

**각 부분의 역할:**

```cpp
TurnRate (100)
↓
"초당 회전하고 싶은 각도"

× InputValue (1.0 또는 -1.0)
↓
"왼쪽? 오른쪽?"

× DeltaTime (0.016)
↓
"이번 프레임 동안만"
```

### 해결: Spring Arm의 Lag 기능

2. **Camera Lag 체크박스 ✅**

3. **Camera Rotation Lag 체크박스 ✅**
   - 회전할 때 카메라가 부드럽게 따라옴

**조정 가능한 값들:**

```cpp

→ 낮을수록 더 천천히 (더 많은 지연)

Camera Rotation Lag Speed (기본 10 → 6 추천)
→ 회전할 때 따라오는 속도
→ 낮을수록 더 천천히
```

### Lag Speed 이해하기

```
값이 높음 (10, 15, 20):
탱크 회전 → 카메라가 빠르게 따라옴

탱크 회전 → 카메라가 천천히 따라옴
```

## 📊 이동 vs 회전 비교

### 공통점

```
1. Float 타입 Input Action
2. 입력 값 × 속도 × DeltaTime
3. Local Space 사용
4. Triggered 이벤트 사용
```

### 차이점

| 항목        | 이동 (Move)         | 회전 (Turn)           |
| ----------- | ------------------- | --------------------- |
| 사용 함수   | AddActorLocalOffset | AddActorLocalRotation |
| 데이터 타입 | FVector             | FRotator              |
| 변경 축     | X (앞뒤)            | Yaw (좌우)            |
| 키          | W/S                 | A/D                   |

## 💡 핵심 정리

### 회전의 핵심 공식

```cpp
회전 각도 = TurnRate × InputValue × DeltaTime

D키: 100 × (1.0) × 0.016 = 1.6도 (오른쪽)
A키: 100 × (-1.0) × 0.016 = -1.6도 (왼쪽)
```

### FRotator의 3요소

```
Pitch = X축 회전 (위아래 보기)
Yaw   = Z축 회전 (좌우 돌기) ← 탱크 회전!
Roll  = Y축 회전 (옆으로 기울기)
```

### Lag의 효과

```
Lag 없음 → 로봇 같은 움직임
Lag 있음 → 자연스러운 움직임
```

## 🎯 목표

**포탑(터렛)이 마우스 커서를 따라 회전하게 만들기!**

```
마우스가 여기 → 포탑이 이쪽으로 회전
마우스가 저기 → 포탑이 저쪽으로 회전
```

## 🤔 어떻게 작동하나?

### 전체 과정

```
1. 마우스 커서 위치 찾기
   ↓
2. 화면에서 게임 월드로 선(Line Trace) 쏘기
   ↓
3. 선이 닿는 지점 찾기 (Impact Point)
   ↓
4. 포탑을 그 지점으로 회전 (다음 강의)
```

**비유:**

```
마우스 = 레이저 포인터
Line Trace = 레이저 빔
Impact Point = 레이저가 닿는 지점
```

## 📐 Line Trace란?

### 시각적 이해

```
카메라 (플레이어 시점)
    |
    | 마우스 커서
    ↓
   ═══════════════> (보이지 않는 선)
              |
              ↓
           바닥에 닿음!
           (Impact Point)
```

**실제 게임에서:**

```
마우스가 바닥 위 → 선이 바닥에 닿음
마우스가 벽 위 → 선이 벽에 닿음
마우스가 적 위 → 선이 적에 닿음
```

```
┌──────────────┬──────────┐
│ WorldStatic  │ Ignore   │
│ WorldDynamic │ Ignore   │
│ Pawn         │ Ignore   │
│ Visibility   │ Block ✅ │ ← 이것만!
│ Camera       │ Ignore   │
└──────────────┴──────────┘
```

**왜 이렇게?**

```
다른 것들(Pawn, Camera 등):
→ Ignore (통과)
→ 게임플레이에 영향 없음

Visibility만:
→ Block (막음)
→ Line Trace는 걸림 ✅
```

---

### 4단계: 위치 조정 (선택사항)

**문제: 바닥 위의 Line Trace도 막힘**

```
해결:
Z 위치를 조금 내리기

Before: Z = 0
After:  Z = -100

결과:
가장자리에서만 작동
중앙(바닥)에서는 안 걸림
```

## 🎮 테스트

### 동작 확인

1. **게임 실행**
2. **마우스를 바닥 위로**
   - 빨간 구체가 따라다님 ✅
3. **마우스를 오브젝트 위로**
   - 구체가 오브젝트에 붙음 ✅
4. **마우스를 하늘로**
   - Blocking Volume이 있으면:
     - 구체가 사라지지 않음 ✅
   - Blocking Volume이 없으면:
     - 구체가 사라짐 ❌

## 🔍 코드 전체 흐름

```cpp
void ATank::Tick(float DeltaTime)
{
    Super::Tick(DeltaTime);

    // 1. PlayerController 얻기
    APlayerController* PlayerController = Cast<APlayerController>(GetController());

    if (PlayerController)
    {
        // 2. 충돌 결과 저장할 상자 준비
        FHitResult HitResult;

        // 3. 마우스 커서 아래 Line Trace
        PlayerController->GetHitResultUnderCursor(
            ECC_Visibility,  // 가시성 채널
            false,           // 단순 충돌
            HitResult        // 결과 여기에
        );

        // 4. 충돌 지점 시각화 (빨간 구체)
        DrawDebugSphere(
            GetWorld(),              // 게임 월드
            HitResult.ImpactPoint,   // 충돌 지점
            25.0f,                   // 크기
            12,                      // 세그먼트
            FColor::Red              // 빨간색
        );

        // 다음 강의: 이 ImpactPoint로 포탑 회전!
    }
}
```

## 💡 핵심 개념 정리

### Line Trace 3단계

```
1. 시작: 카메라 (플레이어 시점)
2. 방향: 마우스 커서 방향
3. 충돌: 첫 번째로 닿는 오브젝트

결과 → ImpactPoint (3D 좌표)
```

---

### FHitResult 주요 정보

```cpp
HitResult.ImpactPoint   // 충돌 위치 (우리가 쓸 것!)
HitResult.Actor         // 충돌한 액터
HitResult.Normal        // 표면 법선 벡터
HitResult.bBlockingHit  // 막히는 충돌인가?
```

---

### Tick vs BeginPlay

```
BeginPlay:
- 게임 시작 시 1번만
- 초기 설정용

Tick:
- 매 프레임마다
- 계속 업데이트가 필요한 것
- 마우스 추적 ← 여기!
```
