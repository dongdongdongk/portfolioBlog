# { 🎨 Material Instance로 발사체 색상 구분 }

## 📌 이 강의의 목표

Material Instance를 사용하여 플레이어와 적의 발사체를 시각적으로 구분합니다.

- Material Parameter 생성
- Material Instance 만들기
- 파란색/빨간색 발사체 구분

---

## 🎯 문제 상황

### 현재 상태

```
BP_PlayerBlasterBeam
  └─ 빨간색 (기본)

BP_EnemyBlasterBeam
  └─ 빨간색 (기본)
```

**문제**: 똑같이 생겨서 구분 안 됨! 😕

### 원하는 결과

```
플레이어 발사체 → 파란색
적 발사체 → 빨간색
```

---

## 🎨 해결 방법: Material Instance

### Material Instance란?

```
부모 Material 하나
  ↓
여러 자식 Material Instance 생성
  └─ 색상, 값만 다르게 설정
      └─ 새 Material 안 만들어도 됨!
```

**장점**:

- Material 재사용 ✅
- 파라미터만 변경 ✅
- 가볍고 효율적 ✅

---

## 🔧 1단계: 기존 Material 확인

### M_BlasterBeam 구조

```
Material Editor
  ↓
Color (Vector3 Constant)
  └─ RGB: (1, 0, 0) 빨간색
  ↓
Multiply
  └─ 120 (Scalar)
  ↓
Emissive Color
  └─ 빛남 효과!
```

**핵심**:

- 색상 × 큰 값 = 빛나는 효과
- 120은 "Overdrive" (과구동)

---

## ⚙️ 2단계: Material Parameter 생성

### Parameter란?

```
일반 값
  └─ Material에 고정됨

Parameter
  └─ Material Instance에서 변경 가능!
```

### 방법 1: 기존 노드 변환

### Color Parameter

```
Color 노드 선택
  ↓
우클릭 → Convert to Parameter
  ↓
Name: BeamColor
Group: BeamProperties
```

**Group**: 파라미터를 묶어서 정리

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380734/notion-blog/_/_/_5_/_7_-_1/image.png)

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380731/notion-blog/_/_/_5_/_7_-_1/image_1.png)

### Glow Amount Parameter

```
1. Scalar 노드 추가 (1키 + 클릭)
2. 값: 120 입력
3. 우클릭 → Convert to Parameter
   ↓
   Name: BeamGlowAmount
   Group: BeamProperties
4. Multiply 노드에 연결
```

### 방법 2: 직접 생성

```
우클릭 → Parameter 입력
  ├─ Vector Parameter (색상)
  ├─ Scalar Parameter (숫자)
  └─ Texture Parameter (텍스처)
```

## 💡 Material Instance 장점

### 1. 재사용성

```
부모 Material 하나
  ↓
무한히 많은 자식 생성
  ├─ 빨간색
  ├─ 파란색
  ├─ 노란색
  └─ ...
```

### 2. 효율성

```
Material 복사
  └─ 무거움 (Shader 재컴파일)

Material Instance
  └─ 가벼움 (파라미터만 변경)
```

### 3. 관리 편의성

```
부모 Material 수정
  ↓
모든 Instance에 자동 반영
  └─ 일괄 업데이트 쉬움!
```

# { 🎯 Blueprint Interface로 유연한 피해 시스템 }

## 📌 이 강의의 목표

Blueprint Interface를 사용하여 다양한 객체가 각자의 방식으로 피해를 받도록 만듭니다.

- Blueprint Interface 개념
- Damageable Interface 생성
- 다양한 피해 반응 구현
- 유연한 코드 작성

---

## ⚠️ 기존 방식의 문제점

### BP_BlasterBeam의 현재 로직

```
OnComponentHit
  ↓
Branch (HitActor == TargetPawn?)
  ├─ True → QuitGame
  └─ False → DestroyActor
```

### 문제 1: TargetPawn 제한

```
BP_Bot이 쏜 발사체
  └─ TargetPawn 설정됨 ✓

BP_BotPawn이 쏜 발사체
  └─ TargetPawn 설정 안 됨 ✗
      └─ 작동 안 함!
```

### 문제 2: 경직된 구조

```
새로운 피격 대상 추가할 때마다
  ↓
Branch 계속 추가
  ├─ If BP_Bot → 폭발
  ├─ If BP_BotPawn → 체력 감소
  ├─ If BP_Enemy → 다른 효과
  └─ If BP_Boss → 또 다른 효과
      └─ 코드가 복잡해짐! 😱
```

---

## 💡 해결책: Blueprint Interface

### Interface란?

```
함수 이름만 정의
  └─ 구현은 각 클래스가 알아서!
      └─ 유연한 구조!
```

**비유**:

- 계약서 같은 것
- "GetHurt 함수 구현해야 함" (계약)
- 어떻게 구현할지는 자유 (실행)

## 🧩 BP_BotPawn GetHurt 로직 분석

### 노드 구조

```
Event GetHurt (Damage)
  ↓
SET Health
  └─ Health - Damage
      ↓
      Print String
        └─ "피해 입음! 체력: " + Health
          ↓
          Branch (Health <= 0?)
            ├─ True → QuitGame
            └─ False → (계속)
```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380731/notion-blog/_/_/_5_/_7_-_1/image_12.png)

### 노드별 설명

### Event GetHurt

```
역할: Interface 함수가 호출되면 실행
Input: Damage (Float)
```

**언제 실행?**: 다른 곳에서 GetHurt 호출 시

### Subtract (빼기)

```
노드: Float - Float
입력:
  ├─ A: Health (현재 체력)
  └─ B: Damage (받은 피해)
출력: Health - Damage (남은 체력)
```

**역할**: 체력에서 피해량 빼기

### SET Health

```
역할: Health 변수 값 변경
입력: Health - Damage 결과
```

**결과**: 체력이 줄어듦!

### Append (문자열 합치기)

```
노드: Append
입력:
  ├─ A: "I Took Damage! Health: "
  └─ B: Health (Float를 String으로 자동 변환)
출력: "I Took Damage! Health: 90"
```

**역할**: 디버그 메시지 만들기

### Print String

```
역할: 화면에 텍스트 출력
입력: Append 결과
```

**용도**: 테스트용 디버그

### Branch (Health <= 0)

```
조건 노드
입력: Health <= 0
출력:
  ├─ True: 체력이 0 이하
  └─ False: 체력이 남음
```

### QuitGame

```
역할: 게임 종료
```

**조건**: 체력이 0 이하일 때만

## 🔍 노드별 상세 설명

### Does Implement Interface

```
역할: 객체가 특정 Interface 구현했는지 확인
입력:
  ├─ Test Object: HitActor (충돌한 액터)
  └─ Interface: BPI_Damageable
출력: Boolean (True/False)
```

**True**: HitActor가 BPI_Damageable 구현함
**False**: 구현 안 함

### 사용 예시

```
벽에 충돌
  └─ 벽은 Interface 구현 안 함
      └─ False 반환

BP_BotPawn에 충돌
  └─ BotPawn은 Interface 구현함
      └─ True 반환
```

### GetHurt (Message)

```
역할: Interface 함수 호출
입력:
  ├─ Target: HitActor (누구한테?)
  └─ Damage: Damage 변수 (얼마나?)
```

**Message**: Interface 함수 호출 방식

### 동작 원리

```
GetHurt 호출
  ↓
HitActor가 BPI_Damageable 구현?
  ├─ Yes → HitActor의 GetHurt 실행
  └─ No → 아무것도 안 함 (에러 없음!)
```

**핵심**: 구현 안 해도 에러 안 남!

### DestroyActor

```
역할: 액터 파괴 (삭제)
Target: Self (자기 자신 = 발사체)
```

## 💡 Interface의 장점

### 유연성

```
BP_BotPawn의 GetHurt
  └─ 체력 감소

BP_Bot의 GetHurt
  └─ 폭발하고 사라짐

같은 함수, 다른 동작!
```

### 확장성

```
새 적 추가 시
  ↓
BPI_Damageable 구현
  ↓
GetHurt 원하는 대로 작성
  ↓
BlasterBeam 수정 불필요!
```

### 간결성

```
❌ 기존 방식
If HitActor == A → Do X
Else If HitActor == B → Do Y
Else If HitActor == C → Do Z
...

✅ Interface 방식
GetHurt 호출 (끝!)
```

## ⚠️ Branch는 선택사항

### Branch 있을 때

```
Does Implement Interface?
  ↓
Branch
  ├─ True → GetHurt → Destroy
  └─ False → Destroy
```

### Branch 없을 때

```
Does Implement Interface? (안 써도 됨)
  ↓
GetHurt (구현 안 돼도 에러 안 남!)
  ↓
Destroy
```

**권장**: Branch 없이 바로 호출

- 더 간단
- Message 방식은 안전함
