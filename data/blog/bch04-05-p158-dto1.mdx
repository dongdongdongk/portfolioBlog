# 서비스 계층과 DTO

```java
DTO (Data Transfer Object)
```

## DTO 를 사용하는 이유

```java
* JPA 의 경우 엔티티 객체가 단순한 객체가 아니라

	영속 컨텍스트(**어플리케이션과 데이터베이스 사이에서 객체를 보관하는 가상의 저장소 같은 역할**)에 영향을 받는 객체이므로

	DTO 로 처리하면 순수한 데이터를 사용하는 것이 가능

* 엔티티 객체는 가능하면 불변을 유지하는 것이지만 DTO 는 가변

	(엔티티는 대부분 getter,setter 이 아닌 getter 위주로만 만든다 (불변 유지) 그러나 DTO 는 자유롭다

* 검증(validate) 이나 화면에 필요한 추가적인 기능들을 사용 가능

* 엔티티 클래스와 유사하게 작성되므로 코드의 양이 늘어나는 단점
```

## DTO 와 엔티티 클래스를 구분해서 사용하려는 이유

```java
* 엔티티 클래스를 화면까지 (Ex: jpa,타임리프) 전달하는 것은 위험할 수 있다

* jpa 는 엔티티 객체가 약간 데이터 베이스 역할을 하기 때문에 가능하면 분리하는게 좋다
```

그러나 서비스에서 레파지토리를 호출할 때는 엔티티 객체로 처리를 하고 반환 역시 엔티티 객체로 처리한다

이렇게 엔티티 객체는 영속 영역에 속해있기 때문에 (매니지 먼트를 영속에서 하고 라이프 사이클이 서비스 이후에 돌아가기 때문에 안전해진다)
