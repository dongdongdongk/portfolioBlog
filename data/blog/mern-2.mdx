## MERN 스택"이란 무엇인가

```jsx
MERN은 MongoDB, Express, React, Node.js의 약자로, 이 기술들을 결합하여 사용하는 웹 개발 스택을 나타낸다
```

```jsx
MongoDB (M):

데이터베이스 솔루션으로서, NoSQL 데이터베이스 엔진이다.

애플리케이션 데이터를 저장하며, 스키마를 강요하지 않아 유연성이 뛰어나다.

Express (E):

Node.js를 기반으로 하는 웹 프레임워크로, Node.js 애플리케이션을 보다 쉽게 구축할 수 있도록 도와준다.

미들웨어를 사용하여 요청을 처리하고 경로를 관리한다.

React (R):

클라이언트 사이드 브라우저 라이브러리로, 사용자 인터페이스를 빠르고 반응적으로 구축하는 데에 사용된다.

브라우저에서 실행되는 JavaScript 코드를 작성하여 동적 UI를 생성하고 관리한다.

Node.js (N):

서버 사이드 JavaScript 런타임으로, 브라우저 외부에서 JavaScript 코드를 실행할 수 있게 해준다.

서버 사이드 로직을 실행하고 데이터베이스와 상호작용하는데 사용된다.
```

# **브라우저와 서버 간의 통신 개념 정리**

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381298/notion-blog/_/React_NodeJS_Express_MongoDB_-_MERN_/MERN_/Untitled.png)

```jsx
**HTTP 요청과 응답:**

브라우저와 서버 간의 통신은 주로 HTTP(하이퍼텍스트 전송 프로토콜)를 사용한다.

브라우저는 서버에게 정보를 요청하는 HTTP 요청을 보낸다.

서버는 해당 요청에 대한 응답으로 HTTP 응답을 생성하고 브라우저에게 전송한다.

**데이터 교환 형식:**

주로 JSON(JavaScript Object Notation) 형식을 사용하여 브라우저와 서버 간에 데이터를 교환한다.

JSON은 가독성이 좋고, 데이터를 효과적으로 표현할 수 있는 경량의 데이터 형식이다.

**백그라운드 HTTP 요청**:

프론트엔드에서는 주로 JavaScript를 사용하여 백그라운드에서 서버에 HTTP 요청을 보낸다.

이로써 페이지 새로고침 없이 데이터를 업데이트하거나 추가 정보를 가져올 수 있다.

**React 앱과 서버 통신:**

React JavaScript 앱은 클라이언트 사이드에서 동작하며, 백그라운드에서 Node/Express 앱으로 HTTP 요청을 보낸다.

서버는 이 요청에 대한 응답을 생성하고, 주로 JSON 형식의 데이터를 브라우저에게 전송한다.

**통신의 주요 목적:**

브라우저와 서버 간의 주요 목적은 데이터 교환과 업데이트이다.

사용자가 어떤 동작을 하거나 페이지를 열 때, 서버는 해당 요청에 대한 데이터를 제공하여 브라우저의 화면을 갱신한다.
```

# MERN 큰 그림 이해하기

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381298/notion-blog/_/React_NodeJS_Express_MongoDB_-_MERN_/MERN_/Untitled_1.png)

```jsx
**MERN 스택 구성 요소:**

MongoDB:

 NoSQL 데이터베이스로, 영구 데이터 저장을 담당한다.

Express.js:

 Node.js를 기반으로 하는 웹 애플리케이션 프레임워크로, 서버를 생성하고 관리한다.

React:

클라이언트 측 라이브러리로, 사용자 인터페이스를 생성하고 제어한다.

Node.js:

서버 측 JavaScript 실행 환경으로, Express와 함께 서버를 관리한다.

**MERN 작동 원리:**

React (클라이언트 측):

브라우저 상에서 실행되는 JavaScript 기반 라이브러리로, 사용자 인터페이스를 담당한다.

화면 렌더링 및 업데이트를 통해 사용자 경험을 향상시킨다.

Express.js & Node.js (서버 측):

Node.js와 Express.js를 사용하여 서버를 생성하고 실행한다.

클라이언트와 서버 간에 통신을 담당하며, 서버 측에서 로직을 실행한다.

백엔드 작업 및 데이터베이스와의 상호작용을 수행한다.

MongoDB (데이터베이스):

MongoDB 엔진을 실행하는 데이터베이스 서버로, 영구 데이터 스토리지 역할을 한다.

백엔드 서버와 통신하여 데이터베이스 쿼리를 처리한다.

**클라이언트-서버 통신:**

HTTP 요청 및 응답:

클라이언트와 서버 간에는 AJAX를 통해 비동기적으로 요청과 응답이 이루어진다.

JSON 형식의 데이터를 주고받으며, 클라이언트는 페이지 새로고침 없이 데이터를 업데이트한다.

**보안 및 데이터베이스 접근:**

서버 사이드 처리:

클라이언트에서는 데이터베이스에 직접적으로 접근하지 않고, 서버를 통해 데이터베이스와 상호작용한다.

데이터베이스 쿼리에 필요한 자격 증명은 서버 사이드에서 안전하게 처리된다. ( 로그인 )
```

# 프론트엔드 자세히 알아보기 ( 리액트 )

```jsx
**1. React SPA의 동작 방식:**

싱글 페이지 애플리케이션(SPA)은 하나의 HTML 페이지를 통해 브라우저에 접속하고 React가 작업을 수행하는 방식이다.

화면에 변화가 필요하거나 재렌더링이 필요한 경우 React가 이를 처리한다.

**2. 프론트엔드 및 클라이언트 사이드 라우팅:**

react-router-dom 라이브러리를 활용하여 프론트엔드 또는 클라이언트 사이드 라우팅을 구현한다.

URL 경로에 따라 다른 React 컴포넌트를 렌더링할 수 있어 사용자 경험을 향상시킨다.

SPA 특성 상 JavaScript가 페이지 재렌더링에 핵심 역할을 수행한다.

**3. 상태 관리와 React 컴포넌트:**

React 애플리케이션에서는 상태(state)를 사용하여 화면에 영향을 미치는 데이터를 관리한다.

상태가 변경되면 해당 부분을 자동으로 재렌더링하여 화면을 업데이트한다.

React의 훅(Hook)이나 Redux 라이브러리를 활용하여 상태를 효과적으로 관리할 수 있다.

**4. 컴포넌트와 스타일링**:

React 애플리케이션은 컴포넌트와 컴포넌트 스타일링으로 구성된다.

프론트엔드 작업 또는 근사한 UI를 위한 애플리케이션 작업이 이루어진다.

강의에서는 유틸리티와 UI 컴포넌트를 구축하고, 완성된 스타일을 제공하여 프론트엔드를 구현한다.

**5. 라우팅, 상태 관리, 컴포넌트 구축:**

react-router-dom을 통해 라우트 구성을 설정하고 각 컴포넌트가 어떤 경로를 통해 렌더링되는지 정의한다.

상태 관리는 직접 생성한 React 훅이나 커스텀 훅, Redux를 통해 구현된다.

완성된 UI 컴포넌트와 스타일이 제공되며, 강의는 React 애플리케이션을 처음부터 구축하는 방법을 소개한다.
```

# 백엔드 이해하기 ( Node Express와 MongoDB )

```jsx
**API의 개념과 역할:**

API는 애플리케이션 프로그래밍 인터페이스로, 프로그램 간에 상호작용을 할 수 있게 해주는 역할을 한다.

웹 개발뿐만 아니라 일반적인 프로그래밍에서도 사용되며, 라이브러리와 같은 코드의 진입점과 사용법을 제공한다.

**백엔드 API의 중요성:**

백엔드에서도 API를 구축하여 클라이언트와의 상호작용을 통제하고 실행하려는 동작을 정의한다.

백엔드 API는 클라이언트와 통신할 때 정의되지 않은 진입점으로의 접근을 피하고, 동작과 데이터를 관리한다.

**API 종류:**

주로 사용되는 백엔드 API에는 REST API와 GraphQL API가 있다.

REST API는 여러 URL과 HTTP 동사를 조합하여 엔드포인트를 생성하고, 다양한 동작을 트리거한다.

GraphQL API는 하나의 URL과 POST 요청으로 쿼리 명령어를 받아들이며, 쿼리 언어를 통해 다양한 동작을 정의한다.

**API의 실행과 통신:**

두 API 모두 클라이언트에서 서버로 요청을 전송하고, 서버에서는 해당 동작을 실행한다.

서버에서는 Node Express 앱이 클라이언트의 요청을 받아들여 작업을 수행하고, 데이터베이스와 통신한다.

**데이터베이스와의 통신:**

API는 데이터베이스와 직접적으로 통신하지 않고, Node Express 앱을 통해 중간에서 작업을 처리한다.

서버에서는 API의 동작에 따라 데이터베이스에 데이터 저장, 사용자 입력값 검증, 데이터 읽기 등 다양한 작업을 수행한다.

**API 선택 및 정의:**

개발자는 어떤 동작을 지원할지를 정의하고, 해당 동작을 호출할 수 있는 API를 구축한다.

API는 클라이언트와 서버 간의 통신을 효과적으로 관리하며, 정의된 동작에 따라 작업을 수행한다.

* RESTful API:

RESTful API는 Representational State Transfer의 약어로, 리소스의 표현 상태를 전달하는 방식이다.

RESTful API는 REST 아키텍처 스타일을 따르며, 자원을 URL로 표현하고 HTTP 동사(GET, POST, PUT, DELETE)를 사용하여 상호작용한다.

각 자원에 대한 동작을 트리거하기 위한 엔드포인트가 URL에 정의되어 있다.

예를 들어, /users 엔드포인트는 사용자 자원에 대한 동작을 정의하고, HTTP 동사에 따라 다양한 작업을 수행한다.

RESTful API는 명확한 URL 구조와 HTTP 동사를 통해 직관적으로 작동하며, HTTP 상태 코드를 사용하여 성공 또는 실패를 알린다.

주로 CRUD(Create, Read, Update, Delete) 기능을 지원하며, RESTful한 디자인을 갖추는 것이 중요하다.
```

# Node와 React 연결하기 이론

```jsx
**호스팅 방법 선택:**

1. 하나의 서버 사용:

동일한 서버에서 React 앱과 Node Express 앱을 함께 호스팅. 주소는 동일 도메인 내의 다른 경로로 라우팅됨.

2. 두 개의 서버 사용:

서로 다른 서버에서 React 앱과 Node API를 분리하여 호스팅.

**단일 서버 호스팅:**

1. 라우팅 방식:

/api로 시작하는 요청은 Node Express API로, 그 외의 요청은 React 싱글 페이지 애플리케이션으로 라우팅됨.

2. 서로 다른 기기 사용:

물리적으로 분리되지 않아도, 논리적으로 서로 다른 기기처럼 동작.

**분리된 서버 호스팅:**

1. 서버 역할 분리:

정적 호스트 서버는 HTML 및 JavaScript 파일을 제공하고, API 서버는 API 요청을 처리.

2. 데이터 교환:

두 서버 간에는 JSON 포맷으로 데이터 교환.

**데이터베이스 서버 분리:**

1. MongoDB 위치:

MongoDB 데이터베이스는 별도의 서버에 설치되며, 주로 데이터베이스 요청의 속도를 최적화하기 위해 분리.

2. 서버 위치 선택:

Node Express 앱과는 동일한 기기에 둘 수도 있고, 별도의 기기에 둘 수도 있음.

**서버 측 렌더링:**

1. 렌더링 방식:

REST 또는 GraphQL 대신 서버에서 HTML 페이지를 렌더링하여 반환.

2. React 활용:

React를 사용하더라도 전체 페이지가 아닌 페이지 일부를 React로 관리하면서 서버 측에서 일부 렌더링 가능.
```
