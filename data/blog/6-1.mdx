## 1. 새 프로젝트 생성하기

- **Unity 버전 확인**: Unity 6 (예: `6000.0.10f1`)
- **템플릿 선택**: Universal 3D (URP 포함 → 최신 렌더링 기능 활용 가능)
- **프로젝트 이름**: 예시 – `Sharp Shooter` (자유롭게 설정 가능)
- **Unity Cloud 연결 해제**: “Connect to Unity Cloud” 체크 해제 후 프로젝트 생성.

---

## 2. 프로젝트 정리하기

- 기본 제공되는 **Readme Assets 제거**.
- `InputSystem_Actions.inputactions` 파일 삭제 → Starter Assets에 자체 입력 맵 포함되어 있기 때문에 불필요.

## 3. Starter Assets 가져오기

- **Unity 에셋 스토어** → Unity Technologies 공식 Starter Assets 패키지 설치.
- 가져올 때 종속성(Dependencies) 자동 포함됨 → Install/Upgrade 버튼 선택.
- 설치 완료 후 `StarterAssets` 폴더 생성됨.

## 5. Starter Assets 장면 실행하기

- 폴더 위치: `StarterAssets/FirstPersonController/Scenes/Playground`
- 실행(▶) → 바로 1인칭 컨트롤러 플레이 가능.

## 6. 계단과 메시 콜라이더 개념 이해하기

- 계단 오브젝트는 실제로는 **계단 모양 메시** + **경사면 메시 콜라이더**.
- 보이는 것은 계단이지만, 충돌은 부드러운 경사로 처리됨.
- 게임 제작 시 시각적 메시와 충돌용 메시가 다를 수 있음 → 최적화 & 물리 처리 효율 때문.

  - **Ground Check 기즈모**: 플레이어 하단의 작은 녹색 구 → 지면 감지용.

## 12. 테스트용 바닥 만들기

- `3D Object > Cube` 생성 → 바닥 역할.
- Transform 값 조정:
  - Position = `(0, 0, 0)`
  - Scale = `(50, 1, 50)`
- 플레이어 시작 위치를 Y=0.5로 설정 → 바닥 위에 정확히 배치.
- 실행(▶) → 1인칭 컨트롤러가 바닥 위에서 정상 작동.

## 1. 내비 메쉬(NavMesh) 개념 이해하기

- **NavMesh(내비 메쉬)** : AI 캐릭터가 **걸을 수 있는 영역**을 미리 계산해둔 데이터.
- **NavMesh Agent(내비 메쉬 에이전트)** : NavMesh 위에서 실제로 움직이는 **AI 캐릭터**.
- 활용 예시:
  - 로봇이 장애물을 피해서 플레이어를 쫓아가기.
  - NPC가 정해진 길을 따라 다니기.

👉 즉, NavMesh는 “지도(길)”이고, NavMesh Agent는 “그 위에서 움직이는 캐릭터”라고 생각하면 됨.

---

## 2. 임시 장애물(Obstacle) 배치하기

- 장면이 비어 있으므로 **큐브(Cube)** 를 여러 개 배치해서 장애물 역할을 하게 함.
- **단축키 활용**:
  - **Ctrl + Shift + 드래그** : 큐브를 다른 오브젝트에 맞춰 스냅(Snap) 배치 가능.
- 목적:
  - 로봇이 단순히 직선으로만 이동하는 것이 아니라 장애물을 돌아다니도록 테스트.

---

## 3. 재질(Material) 적용하기

- 오브젝트 구분을 쉽게 하기 위해 색상 변경.

1. **Assets → Materials 폴더 생성**
2. 새로운 Material 생성 (예: `DarkGray`)
3. **Base Map 색상 변경**
   - 약간 푸른색이 섞인 짙은 회색 사용.
4. 큐브에 적용하여 시각적으로 명확하게 만듦.

👉 색상 변경은 단순히 시각적 구분을 위한 용도지만, 플레이 시 경로와 장애물을 더 잘 확인할 수 있음.

## 4. 내비 메쉬 표면(NavMesh Surface) 생성 및 굽기(Bake)

1. **Hierarchy에서 빈 GameObject 생성** → 이름: `NavMesh Surface`
2. **Component 추가** → `NavMesh Surface` 검색
3. **에이전트 타입 선택**
   - 기본값: **Humanoid**
   - 강의에서는 추후 로봇 적군을 만들 것이므로 `Robot` 타입으로 변경.
4. **굽기(Bake)** 버튼 클릭
   - 현재 장애물을 기준으로 이동 가능한 영역(파란색)이 생성됨.
5. **Agent 반지름(Radius) 조정**
   - 예: `0.5` → `2`로 변경 후 다시 Bake → 이동 가능 영역이 좁아짐.
   - 실제 캐릭터 크기와 충돌 크기를 반영.

👉 Bake 과정 = NavMesh 데이터를 생성하는 작업.

## 5. 적 로봇(Robot) 오브젝트 만들기

1. **[3D Object → Cube]** 생성 → 빨간색 Material 적용 → 로봇 역할.
2. **Ctrl + Shift + G** 단축키 사용 → 자동으로 빈 부모 오브젝트 생성 → 이름 `Robot`.
3. 로봇의 모양 꾸미기 (임시 플레이스홀더지만 방향 확인용):
   - **입** : Cube 복제해서 늘리기.
   - **눈** : Sphere 추가 후 위치 조정, Collider 제거.
   - 각각 다른 색상 Material 적용.

## 📌 **NavMesh Agent 주요 속성**

(Inspector에 표시되는 항목 기준)

### 1. **Agent Size 관련**

- **Radius**
  - 에이전트의 반지름 (충돌 크기).
  - NavMesh 위에서 지나갈 수 있는 길의 최소 너비를 결정할 때도 쓰임.
  - 값이 크면 좁은 길을 못 지나가고, 너무 작으면 벽에 붙어버릴 수 있어요.
- **Height**
  - 에이전트의 높이 (캡슐 콜라이더처럼 생각).
  - 장애물 아래를 통과할 수 있는지 여부 판단에 사용돼요.
- **Base Offset**
  - 에이전트의 **기준점(발 위치)와 실제 NavMesh 표면과의 오프셋**.
  - 기본값은 0 → 캐릭터가 NavMesh 바닥에 붙음.
  - 값을 올리면 캐릭터가 공중에 뜬 것처럼 보이게 할 수 있음. (떠다니는 로봇 같은 느낌)

---

### 2. **Agent Movement 관련**

- **Speed**
  - 초당 이동 속도.
- **Angular Speed**
  - 초당 회전 속도(도 단위).
  - 값이 크면 빠르게 방향 전환, 작으면 천천히 돔.
- **Acceleration**
  - 정지 → 최고속도까지 가속하는 속도.
  - 값이 크면 즉각적인 스타트/스톱, 작으면 부드럽게 움직임.
- **Stopping Distance**
  - 목적지에 도착했을 때 멈추는 거리.
  - 0이면 딱 붙어서 멈추고, 1 이상이면 살짝 떨어진 채 멈춤.

---

### 3. **Obstacle Avoidance (회피 관련)**

- **Auto Braking**
  - 목적지에 도착하기 전에 자동으로 감속할지 여부.
  - 체크하면 자연스럽게 서고, 해제하면 계속 속도 유지하다가 갑자기 멈춤.
- **Obstacle Avoidance Quality**
  - 장애물 회피 알고리즘 정밀도.
  - None / Low / Medium / Good / High 선택 가능.
  - 높을수록 충돌 회피가 부드럽지만 CPU 부하가 큼.
- **Avoidance Priority**
  - 여러 에이전트가 있을 때 충돌 회피 우선순위.
  - 값이 낮을수록 우선권이 높음. (0 = 다른 애들이 나를 피해감)

---

### 4. **Path & Navigation 관련**

- **Auto Traverse Off Mesh Link**
  - 점프, 문, 사다리 같은 오프 메쉬 링크를 자동으로 탈지 여부.
  - 체크 시 알아서 이동, 해제 시 스크립트로 제어해야 함.
- **Auto Repath**
  - 길이 막혔을 때 자동으로 새로운 경로를 찾을지 여부.
- **Area Mask**
  - NavMesh의 특정 영역만 이동 가능하도록 제한.
  - 예: "Walkable", "Not Walkable", "Jump Area" 같은 것 선택.

- **에이전트(Nav Mesh Agent)**: 내비메쉬를 따라 움직이는 AI 캐릭터(여기선 로봇).

## 2. 생성된 링크(Generated Off Mesh Links) 설정하기

- 내비메쉬 에이전트는 기본적으로 “걷기”만 가능.
- **Generated Off Mesh Links** 옵션을 통해 자동으로 **점프 / 낙하 경로**를 생성할 수 있음.

### 주요 속성

- **Drop Height (낙하 높이)**
  - 로봇이 내려갈 수 있는 최대 높이.
  - 예: `5`로 설정하면, 5 유닛 높이까지는 떨어질 수 있음.
- **Jump Distance (점프 거리)**
  - 수평으로 점프 가능한 거리.
  - 단, 기본 Generated Links로는 “올라가기” 불가능 → 아래로만 낙하 가능.

1. 내비메쉬 표면(NavMesh Surface)에서 **Generated Off Mesh Links** 토글을 켜기.
2. **Drop Height / Jump Distance** 값 조정 후 다시 **Bake** 실행.
3. 플랫폼 간 거리가 허용 범위 내라면 자동으로 링크가 생성됨.

## 🔎 NavMeshAgent Navigation 옵션 설명

### 1. **Agent Type (Name)**

- 에이전트의 종류 (사람, 드론, 몬스터 등)
- Unity **Navigation → Agents** 설정에서 미리 정의한 타입을 고를 수 있습니다.
- NavMesh를 굽는(Bake) 때도 이 Agent Type에 맞게 NavMesh가 만들어집니다.
  → 예: 사람은 문을 통과할 수 있지만, 큰 몬스터는 못 지나가도록.

---

### 2. **Radius**

- 에이전트의 “가로 크기” (반지름).
- 캐릭터가 지나갈 때 **얼마나 공간이 필요한지**를 의미합니다.
- `Radius = 0.5` → 최소 1m 폭이 있어야 지나갈 수 있음.
- Obstacle Avoidance(장애물 회피) 계산도 이 값을 기준으로 합니다.

---

### 3. **Height**

- 에이전트의 “세로 크기” (키).
- NavMesh Bake할 때 **천장이 너무 낮은 곳**은 못 지나가도록 필터링합니다.
- 예: Height = 2 → 2m 이상 공간이 있어야 통과 가능.
- Obstacle Avoidance에는 직접 영향 없음 (XZ 평면에서만 회피 계산).

---

### 4. **Step Height**

- 계단, 턱 같은 “높이 차이”를 얼마나 넘을 수 있는지.
- 예: Step Height = 0.5 → 0.5m 이하의 턱은 그냥 넘어서 이동 가능.
- 이 값보다 높은 곳은 경로 탐색에서 막혀 있는 걸로 처리.

---

### 5. **Max Slope**

- 에이전트가 이동할 수 있는 **최대 경사각 (도 단위)**.
- 예: Max Slope = 45° → 45° 이하의 경사는 오를 수 있음.
- 그보다 가파른 경사는 NavMesh에서 막혀 있는 걸로 처리.

## 5. 에이전트 Step Height(단차 높이) 이해하기

- **Step Height**: AI가 오를 수 있는 계단/턱의 최대 높이.

### 개념

- 로봇 에이전트의 **Height(높이)** 값과 관련 있음.
- Step Height는 **에이전트 높이보다 작아야 동작**함.
- 높이를 높게 잡으면 작은 장애물을 무시하고 올라갈 수 있음.

### 실습 예시

- Step Height = 1 → 로봇이 1 유닛 크기의 턱을 오를 수 있음.
- Step Height = 50 → 높이가 큰 플랫폼도 단순히 “계단처럼” 취급해 올라감.
- 하지만 로봇의 **Agent Height** 값이 작으면 제한됨.

## 6. 플랫폼 위/아래 통과 여부 제어하기

- 로봇이 **플랫폼 아래를 통과할 수 있는지 여부**는 에이전트의 높이(Height) 값과 연관.

### 예시

- 플랫폼 높이 = 5, 에이전트 높이 = 2 → 통과 불가.
- 에이전트 높이를 1로 줄임 → 플랫폼 밑 공간이 확보되어 통과 가능.

👉 즉, **Agent Height ≤ 플랫폼 밑 공간**이어야 함.

## 7. 최종 테스트 & 결과 확인

1. 로봇의 속도 → 테스트를 위해 `3` 정도로 느리게 조정.
2. Bake 후 게임 실행.
3. 확인할 요소:
   - 로봇이 플랫폼 아래로 이동 가능한지.
   - 낮은 턱은 Step Height 덕분에 오를 수 있는지.
   - 높은 턱은 올라가지 못하는지.

## 1. 레이캐스트(Raycast) 개념

- **레이캐스트**는 한 점(origin)에서 특정 방향(direction)으로 ‘보이지 않는 레이(광선)’을 발사하여, 그 경로 상에 콜라이더가 있는지를 검사하는 과정이다.
- FPS 스타일의 조준에서는 **카메라의 중심**(화면 중심)이 조준 방향이므로, `Camera.main.transform.position`을 origin으로, `Camera.main.transform.forward`를 direction으로 사용하면 된다.
- 레이캐스트 결과로 **무엇을 맞췄는지(충돌한 콜라이더에 대한 정보)** 를 얻어 게임 로직(데미지, 이펙트 등)에 활용할 수 있다.

---

## 2. C# `out` 키워드와 `RaycastHit` 역할

- `out` 키워드: **매개변수를 값이 아닌 참조로 전달**해, 메소드가 호출자 쪽 변수에 값을 직접 채워 넣도록 하는 C# 매개변수 수정자(modifier)이다.
  - 사용법 요약: 호출 전에 **변수를 선언**(초기화는 선택)하고, `out 변수` 형태로 전달하면 메소드 내부에서 해당 변수를 설정한다.
  - `out`을 쓰면 하나 이상의 추가 정보를 메소드에서 반환받을 수 있다(단일 반환값 외 추가값 반환 수단).
- `RaycastHit`은 레이캐스트가 맞춘 대상의 정보를 담는 **구조체**이다. (예: `hit.collider` 로 맞춘 콜라이더 접근 가능)
- `Physics.Raycast(...)`의 특징:
  - 여러 오버로드가 있지만 기본 사용 형태는 `Physics.Raycast(origin, direction, out hit, distance)` 이다.
  - 이 호출은 **bool**을 반환한다 — `true` 면 무언가에 맞았다는 뜻이고, `false` 면 아무 것도 맞지 않았다는 뜻이다. (따라서 `if (Physics.Raycast(...)) { /* hit 안전 사용 */ }` 패턴이 안전하다.)

## 3. Weapon 스크립트 만들기 — 순서 및 코드(강의 예제)

### 순서(강의에서 한 단계씩)

1. `Scripts` 폴더에서 새 C# `MonoBehaviour` 스크립트를 생성 → 이름: `Weapon`
2. 권총(또는 무기) 게임오브젝트에 `Weapon` 컴포넌트로 드래그해서 할당
3. VSCode 등으로 스크립트 열기 → `Update()` 안에서 매 프레임 레이를 쏘고 결과 확인(강의 예제는 임시로 매 프레임 수행)

### 강의에서 제시한 **완성된** 예제 코드 (해당 강의 최종 코드):

```csharp
using System;
using UnityEngine;

// Weapon 클래스는 MonoBehaviour를 상속합니다.
// MonoBehaviour를 상속하면 Unity가 제공하는 생명주기( Awake, Start, Update 등 )를 사용할 수 있습니다.
public class Weapon : MonoBehaviour
{
    // Update()는 Unity가 매 프레임마다 호출하는 콜백 함수입니다.
    // (게임 로직 중 '매 프레임마다 확인/처리'가 필요한 동작을 여기에 작성합니다.)
    void Update()
    {
        // RaycastHit는 레이가 충돌했을 때의 정보를 담는 구조체(struct)입니다.
        // - hit.collider  : 충돌한 Collider (null이면 아무것도 맞지 않음)
        // - hit.point     : 충돌 지점의 월드 좌표(Vector3)
        // - hit.normal    : 충돌 표면의 법선 벡터(Vector3)
        // - hit.distance  : 레이 시작점(origin)으로부터 충돌 지점까지의 거리(float)
        RaycastHit hit;

        // Physics.Raycast(...) 는 물리 레이캐스트를 수행합니다.
        // 이 오버로드(형태)는 다음 인자를 받습니다:
        // 1) origin     : 레이의 시작 위치 (월드 좌표, Vector3)
        // 2) direction  : 레이가 향하는 방향 (단위 벡터 권장, Vector3)
        // 3) out hit    : 충돌 정보가 담길 RaycastHit 변수 (out 키워드로 전달)
        // 4) maxDistance: 레이의 최대 사거리 (float) — 여기서는 Mathf.Infinity(무한대)를 사용
        //
        // 반환값: bool (true면 무언가에 맞음, false면 아무것도 맞지 않음)
        //
        // Camera.main.transform.position :
        //  - Camera.main : 씬에서 "MainCamera" 태그가 붙은 카메라의 Camera 컴포넌트 (없으면 null)
        //  - .transform  : 해당 카메라 GameObject의 Transform 컴포넌트 (모든 게임오브젝트는 Transform을 가짐)
        //  - .position   : Transform의 세계 좌표(Vector3) — 카메라의 위치
        //
        // Camera.main.transform.forward :
        //  - Transform.forward는 '그 transform이 보는(향하는) 전방 방향'을 나타내는 단위 벡터(Vector3).
        //    (즉, 카메라의 앞쪽 방향이 곧 우리가 '조준'하는 방향)
        //
        // out hit : C#의 out 매개변수. Raycast가 true를 반환하면 Unity가 hit 변수에 충돌 정보를 채워 넣습니다.
        if (Physics.Raycast(Camera.main.transform.position, Camera.main.transform.forward, out hit, Mathf.Infinity))
        {
            // 위의 if 구문 내부는 '레이가 무언가에 맞았을 때만' 실행됩니다.
            // 따라서 여기서 hit.collider는 null이 아닙니다(안전하게 사용 가능).
            // Debug.Log는 Unity 콘솔에 메시지를 출력합니다.
            Debug.Log(hit.collider.name);

            // 참고(추가로 유용한 정보 출력 예시):
            // Debug.Log($"Hit {hit.collider.name} at {hit.point} (distance {hit.distance})");
            // hit.point : 충돌한 위치 좌표 (Vector3)
            // hit.distance : origin에서 충돌지점까지의 거리 (float)
        }
        // if 블록을 빠져나오면, 레이가 아무것도 맞추지 못한 경우(else)에는 아무 로그도 찍히지 않습니다.
    }
}

```

- 설명:
  - `RaycastHit hit;` 를 먼저 선언한다(중요 — `out`에 넘기기 위해).
  - `Physics.Raycast(...)` 를 `if`로 감싸서 **맞았을 때만** `hit`를 사용하도록 했다.
  - `Mathf.Infinity`를 거리로 사용 → 거리 제한 없이 레이를 쏜다(강의에서는 간단히 이렇게 사용). 실제 게임에선 `SerializeField`로 거리(예: 권총 100, 저격총 더 멀리)를 제어하면 좋다.

> 강의 포인트: 레이캐스트는 그렇게 계산비싼 작업이 아니다. 수십~수백개의 레이도 자주 쏠 수 있지만, 그래도 필요에 따라 Update가 아닌 다른 주기(입력 시 등)에서 처리해도 된다.

## 4. 자주 발생하는 문제 & 해결법 (NullReference, NavMeshAgent 등)

### A. `NullReferenceException` — 원인과 해결

- **원인:** `Debug.Log(hit.collider.name)` 같은 코드가 항상 실행되는데, 레이가 아무것도 맞히지 못하면 `hit.collider`가 `null`이므로 예외 발생.
- **해결:** `Physics.Raycast(...)`가 `true`일 때만 `hit`를 사용한다. (`if (Physics.Raycast(...)) { Debug.Log(hit.collider.name); }`)
  - 강의에서 소개한 **꿀팁**: 레이캐스트 메소드를 `if`로 감싸면 `hit`값이 안전하게 셋팅된 경우만 내부 코드가 실행된다.

### B. NavMeshAgent가 레이로 안 맞는 문제

- **현상:** 로봇(에이전트)에 NavMeshAgent가 붙어있지만 레이캐스트로 맞지 않음(또는 의도한 대로 상호작용 안 됨).
- **원인:** NavMeshAgent 컴포넌트 자체가 일반적으로 Raycast 충돌을 위해 필요한 콜라이더 역할을 대신하지 않는다(또는 레이와 상호작용하지 않을 수 있음).
- **해결:** 로봇의 최상위 부모 게임오브젝트에 `CapsuleCollider`(혹은 적절한 Collider)를 추가하고 위치/크기를 맞춘다. 그러면 레이가 로봇을 맞추면 `hit.collider`로 감지된다.

### C. 로봇이 플레이어를 밀고 다니는 문제

- **강의에서 한 임시 수정:** NavMeshAgent의 `Stopping Distance`를 `0` → `2` (유닛) 정도로 올려 로봇이 플레이어 바로 옆까지 붙지 않도록 하여 물리적 충돌/밀침 현상 완화.

## 5. 작동 확인 및 디버깅 팁

- **콘솔 출력으로 확인:** `Debug.Log(hit.collider.name)`로 맞춘 대상의 이름을 실시간으로 확인.
  - _주의_: 반드시 레이캐스트 결과를 체크한 뒤에 출력(또는 접근)해야 null 오류를 피함.
- **거리 설정:** `Mathf.Infinity`는 간단하지만, 현실적 거리를 `SerializeField`로 만들어 인스펙터에서 조정하면 권총/저격총 등 무기별로 거리 조절 가능. (강의에서 제안한 방식)
- **Camera.main 접근 관련:**
  - 강의 언급: “`Camera.main`을 매 프레임에 호출해도 최근 Unity에서는 내부적으로 비용이 크지 않으므로 당장 캐싱하지 않아도 괜찮다.”
  - (선택적 최적화) 프레임당 호출이 걱정된다면 `Awake()`에서 `Camera cam = Camera.main;` 하고 `cam.transform.forward`를 쓰는 방식으로 캐싱할 수 있다 — 강의에서 ‘이건 선택 사항’으로 언급됨.
- **레이 여러 개/빈도:** 레이캐스트는 적당히 자주(매 프레임 포함) 사용 가능. 다만 게임 로직과 퍼포먼스 요구에 따라 빈도 조정 권장.

## 요약 — 핵심 포인트 체크리스트

- `Physics.Raycast(origin, direction, out hit, distance)` 사용 → **`out`은 호출된 쪽에 값을 채워준다.**
- 반드시 `Raycast`의 **반환값(bool)** 을 확인한 뒤 `RaycastHit hit`를 안전하게 사용하자. (`if (Physics.Raycast(...)) { ... }`)
- `Camera.main.transform.position` / `Camera.main.transform.forward`를 origin/direction으로 사용하면 **화면 중앙(조준점)** 기반의 레이 발사가 된다.

- 레이가 아무것도 맞추지 못할 때 생기는 `NullReferenceException`은 `if`로 감싸면 방지 가능.
- 거리 제한은 `Mathf.Infinity`로 두고 테스트하되, 실제 무기별로는 `SerializeField` 등에 거리값을 두고 조절하자.
- 그림자 아티팩트는 RenderPipeline Asset의 Depth/Normal Bias를 조정해 완화할 수 있다.

- **체력이 0 이하가 되면 오브젝트 파괴**

### ⚡ 코드

```csharp
using UnityEngine;

public class EnemyHealth : MonoBehaviour
{
    [SerializeField] int startingHealth = 3;  // 초기 체력
    int currentHealth;

    void Awake()
    {
        currentHealth = startingHealth;  // 게임 시작 시 체력 초기화
    }

    public void TakeDamage(int amount)
    {
        currentHealth -= amount;          // 체력 감소
        if (currentHealth <= 0)           // 체력이 0 이하이면
        {
            Destroy(gameObject);          // 게임 오브젝트 파괴
        }
    }
}

```

---

## 3. 무기(Weapon) 스크립트 수정하기

총알이 적을 맞췄을 때 **EnemyHealth.TakeDamage()** 를 호출해야 합니다.

### ⚡ 구현 개념

- **damageAmount** : 무기가 주는 피해량 (직접 숫자를 쓰지 않고 SerializeField로 노출 → 무기마다 다르게 설정 가능)
- **RaycastHit** : 화면 중앙에서 레이 쏘아 맞은 오브젝트 확인
- 맞은 오브젝트에 `EnemyHealth` 컴포넌트가 있으면 `TakeDamage()` 호출

### ⚡ 코드

```csharp
using System;
using StarterAssets;
using UnityEngine;

public class Weapon : MonoBehaviour
{
    [SerializeField] int damageAmount = 1;       // 무기 데미지
    StarterAssetsInputs starterAssetsInputs;

    void Awake()
    {
        starterAssetsInputs = GetComponentInParent<StarterAssetsInputs>();
    }

    void Update()
    {
        HandleShoot();
    }

    void HandleShoot()
    {
        if (!starterAssetsInputs.shoot) { return; }  // 발사 입력 없으면 종료

        RaycastHit hit;

        if (Physics.Raycast(Camera.main.transform.position, Camera.main.transform.forward, out hit, Mathf.Infinity))
        {
            EnemyHealth enemyHealth = hit.collider.GetComponent<EnemyHealth>();
            enemyHealth?.TakeDamage(damageAmount);   // null 조건부 연산자 사용
        }
        // 입력 상태 초기화
         starterAssetsInputs.ShootInput(false);
    }
}
```

---

## 4. 코드 정리와 최적화

### ⚡ Null 조건부 연산자

```csharp
enemyHealth?.TakeDamage(damageAmount);
```

- 의미: `enemyHealth`가 존재하면 `TakeDamage(damageAmount)` 실행
- 존재하지 않으면 아무 일도 일어나지 않음
- `if (enemyHealth != null)` 블록을 간단히 줄일 수 있음

### ⚡ 메서드 추출 (Extract Method)

- `Update()` 안에서 직접 로직을 다루지 않고 → `HandleShoot()` 메소드로 분리
- 코드 가독성과 유지보수성 향상

## 5. 씬에서 테스트하기

1. **EnemyHealth 스크립트**를 로봇 오브젝트에 연결.
2. 로봇을 **Prefab**으로 만들어 여러 개 배치.
3. 플레이 모드에서 로봇을 총으로 쏘면:
   - 총알을 맞을 때마다 체력이 1씩 감소.
   - 3번 맞으면 로봇이 파괴됨.
4. 여러 로봇 배치 후 테스트하면, 각 로봇이 개별적으로 체력을 관리하고 파괴되는 것을 확인할 수 있음.

✅ **이번 강의 핵심 정리**

- 적의 체력을 관리하는 `EnemyHealth` 클래스를 만들었다.
- 무기에서 Raycast로 피격 판정을 하고, `EnemyHealth.TakeDamage()` 호출.
- SerializeField를 활용하여 무기마다 다른 피해량 설정 가능.
- Null 조건부 연산자(`?.`)로 코드 간결화.
- 체력이 0 이하가 되면 `Destroy(gameObject)`로 오브젝트 삭제.

## 4. 파티클 세부 옵션 조정하기

### (1) 크기 조정

- **Scaling Mode** : `Shape → Hierarchy` 변경
  → Transform의 Scale이 파티클 전체 크기에 직접 반영됨.
- 적정 값: `Scale = 0.05`

### (2) 방향 조정

- **Shape** : `Sphere → Cone` 변경 → 총구 방향으로 뿜어져 나오게 설정.
- **Rotation (Y축)** : `90` 또는 `90` → Z축이 총구 전방을 가리키도록 수정.

### (3) 입자 개수 조절

- **Emission → Bursts Count**:
  - 기본값: 150 → 너무 많음.
  - 수정값: **30** → 한 번의 발사 시 적절한 섬광 효과.

### (4) 색상 조정

- **Color over Lifetime**:
  - 기본: 주황 → 붉은색
  - 변경: **주황빛 노랑 → 밝은 노랑** (총구 섬광 느낌 강화).

### (5) 속도와 수명

- **Start Speed**: `10 → 25` (더 강하게 튀도록).
- **Start Lifetime**: `0.33` (짧고 순간적인 섬광 느낌).

### (6) 시뮬레이션 공간

- **Simulation Space**: `World → Local`
  → 총구 움직임을 따라 파티클이 이동하게 됨.

## 6. 코드에서 파티클 제어하기

```csharp
using System;
using StarterAssets;
using UnityEngine;

public class Weapon : MonoBehaviour
{
    [SerializeField] int damageAmount = 1;
    [SerializeField] ParticleSystem muzzleFlash;
    StarterAssetsInputs starterAssetsInputs;

    void Awake()
    {
        starterAssetsInputs = GetComponentInParent<StarterAssetsInputs>();
    }

    void Update()
    {
        HandleShoot();
    }

    void HandleShoot()
    {
        if (!starterAssetsInputs.shoot) { return; }

        // 🔥 총구 섬광 실행
        muzzleFlash.Play();

        RaycastHit hit;
        if (Physics.Raycast(Camera.main.transform.position, Camera.main.transform.forward, out hit, Mathf.Infinity))
        {
            EnemyHealth enemyHealth = hit.collider.GetComponent<EnemyHealth>();
            enemyHealth?.TakeDamage(damageAmount);
        }
         // 입력값 리셋
         starterAssetsInputs.ShootInput(false);
    }
}
```

- `muzzleFlash.Play();` → 발사 입력 시 총구 섬광 재생.
- `Play on Awake` 체크 해제 필요 → 게임 시작 시 자동 실행 방지.
- Simulation Space = Local → 총구 움직임과 정확히 동기화.
