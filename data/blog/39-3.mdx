```java
**Getter 과 Setter 메소드**

// class 를 작성할때 별다른 조건이 없다면. 보통 private 로 필드를 선언한다.

class Car {
private int speed;
private boolean stop;
}

// 이유는 외부에서 객체에 마음대로 접근할 경우 객체의 무결성을 깰 수 있기 때문이다.
//(예를 들어 사람의 키는 음수가 불가능 한데 public 일 경우 어디선가 음수가 들어갈 수 도 있기때문)

public int getSpeed() {        // 외부에서 getSpeed 를 호출하면 내부의 speed 값을 알 수 있다.
	return speed;
}

public void setSpeed(int s) {  // 외부에서 이 메소드를 호출하면 speed 값을 필드에 저장 가능하다.
	this.speed = s;
}

// 이처럼 두개의 메소드를 작성해서 하나는 필드 값을 읽고 외부로 전달하고 (getSpeed)
// 하나는 외부에서 값을 받아서 필드값을 바꾸도록 (setSpeed)
// 메소드로 필드의 값을 읽거나 바꾸도록 설정할 수 있다.
// 이와 같은 메소드를 Getter 와 Setter 이라고 한다. (보통 메소드 명 get , set 으로 시작)
```

```java
**Setter 의 검증**

Setter 메소드를 이용해서 값을 받아도 잘못된 값 (ex 음수) 를 받을 수 도 있다.
이를 방지하기 위해서 **검증 코드**를 작성할 수 있다.
*set+ 변수명의 첫글자를 대문자로 바꾼것 ex)setAge

void setSpeed(double speed) {            //매개값이 음수면 speed에 0을 입력후 메소드 종료)
	if(speed < 0) {
		this.speed = 0;
		return;
	} else {
		this.speed = speed;
	}
}
```

```java
**Getter 메소드**

외부로 필드값을 전달하는 것이 목적
필드의 값을 그대로 전달할 수 도 있겠지만 필드 값을 가공해서 외부에서 사용하기 좋게 가공해
전달 할수도 있다.
*get+ 변수명의 첫 글자를 대문자로 바꾼것 ex)setSpeed

double getSpeed() {             // 필드값 마일을 km 단위로 환산 후 외부로 리턴
double km = speed * 1.6;
return km;
}
```

```java
**접근 제한자** : 클래스. 인터페이스, 멤버들(필드,생성자,메소드) 사용을 제한할 경우 사용

             public : 어디서든 접근 가능

             protected : 상수 배우고
```
