# { ✨ 픽업 아이템에 Juice 추가하기 (Polish & Effects) }

## 🎯 이번 강의 목표

기능적으로는 완성된 픽업 아이템에 **게임의 완성도를 높이는 효과**들을 추가합니다.

- 사운드 효과 추가
- 파티클 효과 (Niagara System)
- 회전 애니메이션
- 스케일 타임라인 (Wink Out)
- 충돌 비활성화

---

## 💡 핵심 개념: Game Juice (게임 주스)

### Game Juice란?

```
Game Juice (게임 주스)
  ↓
게임의 "손맛", "재미 요소"를 높이는 시각/청각 효과
  ├─ 기능적으로는 불필요
  ├─ 하지만 게임 경험에 필수적
  └─ 플레이어의 행동에 대한 피드백

예시:
  버튼 클릭
    ├─ Juice 없음: 그냥 작동
    └─ Juice 있음: 소리 + 애니메이션 + 파티클
         ↓
       훨씬 만족스러운 경험!
```

**왜 중요한가?**

```
게임 완성도 = 기능 + Juice
  ├─ 기능만: 작동하지만 재미없음
  ├─ Juice만: 예쁘지만 의미없음
  └─ 둘 다: 완성도 높은 게임!

플레이어 피드백:
  ├─ "이 게임은 느낌이 좋아"
  ├─ "타격감이 있어"
  └─ "만족스러워"
       ↓
     모두 Juice의 효과!
```

## 🔊 1단계: 사운드 효과 추가

### Spawn Sound at Location

```
Event ActorBeginOverlap 이후
  ↓
Spawn Sound at Location
  ├─ Sound: SFX_JetFuelPickup
  ├─ Location: Get Actor Location
  └─ Auto Destroy: True (기본값)
```

**노드 구성:**

```
Get Actor Location
  ├─ Target: Self (픽업 아이템)
  └─ Return: Vector (위치)
       ↓
Spawn Sound at Location
  ├─ Sound: MS_JetFuel (Assets/Sounds/JetFuel/)
  ├─ Location: Actor Location
  ├─ Auto Destroy: True
  └─ Volume Multiplier: 1.0 (기본값)
```

### Auto Destroy란?

```
Auto Destroy: True
  ↓
사운드 재생이 끝나면 자동으로 제거
  ├─ 메모리 누수 방지
  ├─ 수동 관리 불필요
  └─ 권장 설정

Auto Destroy: False
  ↓
수동으로 제거해야 함
  └─ 반복 재생 등 특수한 경우만
```

## 🔄 3단계: 회전 애니메이션 추가

### Rotation Offset (초기 각도)

```
Viewport에서:
  FuelMesh 선택
    ↓
  Transform → Rotation
    ↓
  Y (Roll): 40도 정도
    ↓
  약간 기울어진 자세
```

**왜 기울이나?**

```
수직 (0, 0, 0):
  └─ 단조로움, 밋밋함

기울어짐 (0, 40, 0):
  └─ 역동적, 흥미로움
```

### Event Tick 회전

```
Event Tick
  ↓
Add World Rotation
  ├─ Target: FuelMesh
  └─ Delta Rotation: (0, 0, Yaw)
```

**노드 구성 상세:**

```
1. Delta Rotation 계산
   Get World Delta Seconds
     ↓
   Multiply (×)
     ├─ A: Delta Seconds
     └─ B: Rotation Speed (변수)
          ↓
        Yaw 값 (프레임당 회전량)

2. Add World Rotation
   FuelMesh
     ↓
   Add World Rotation
     ├─ Delta Rotation:
     │    ├─ Pitch: 0
     │    ├─ Yaw: 계산된 값
     │    └─ Roll: 0
     └─ 효과: 매 프레임 회전
```

### Rotation Speed 변수

```
변수 생성:
  ├─ Name: Rotation Speed
  ├─ Type: Float
  ├─ Default: 45.0
  ├─ Instance Editable: True
  └─ Category: Pickup

효과:
  45.0 = 초당 45도 회전
  90.0 = 초당 90도 회전 (더 빠름)
```

**Delta Seconds 사용 이유:**

```
프레임 독립적 회전:
  60 FPS: 0.0166초 × 45 = 0.75도/프레임
  30 FPS: 0.0333초 × 45 = 1.5도/프레임

결과: 모두 초당 45도 회전! ✅
```

## 📊 4단계: 스케일 타임라인 (Wink Out)

### Timeline 생성

```
Event Graph
  ↓
Add Timeline
  └─ Name: PickupScaleTimeline
```

### Float Track 추가

```
Timeline 더블클릭
  ↓
Add Float Track
  ├─ Name: Scale
  └─ Length: 0.2초 (빠른 애니메이션)
```

### 키프레임 설정

```
Key 1 (시작):
  ├─ Time: 0.0
  ├─ Value: 1.0
  └─ 의미: 원래 크기

Key 2 (끝):
  ├─ Time: 0.2
  ├─ Value: 0.0
  └─ 의미: 완전히 축소
```

### 커브 조정

```
1. Key 2 선택
   우클릭 → Auto
     ↓
   부드러운 곡선

2. Tangent 조정
   ├─ Key 2: 각도 위로 (급격한 축소)
   └─ Key 1: 각도 아래로 (부드러운 시작)
```

**커브 모양:**

```
Value
  1.0 ┤
      │ ╲
      │  ╲   (부드럽게 시작)
      │   ╲╲
  0.0 └────╲╲──→ Time
      0.0  0.2
           (급격하게 축소)

```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380769/notion-blog/_/_/_5_/_8_-_3D_-_7/image_2.png)

### Timeline 업데이트 구현

```
PickupScaleTimeline
  └─ Update 핀
       ↓
     Scale Fuel Mesh 함수

```

**Scale Fuel Mesh 함수:**

```
함수 생성:
  Name: Scale Fuel Mesh
  Input: Scale (Float)

노드 구성:
  FuelMesh
    ↓
  Set World Scale 3D
    ├─ Target: FuelMesh
    └─ New Scale: Make Vector
         ├─ X: Scale
         ├─ Y: Scale
         └─ Z: Scale
              ↓
            균등 스케일

```

**Make Vector 사용 이유:**

```
Set World Scale 3D는 Vector 필요
  ↓
Make Vector (X, Y, Z)
  ├─ 모두 같은 값: Scale
  └─ 균등하게 확대/축소
```

## 🎬 5단계: Wink Out 구현

### Custom Event 생성

```
Custom Event: Wink Out
  ↓
실행 내용:
  1. 충돌 비활성화
  2. 타임라인 재생
```

**노드 구성:**

```
Wink Out (Custom Event)
  ↓
Set Collision Enabled
  ├─ Target: FuelMesh
  ├─ New Type: No Collision
  └─ 효과: 더 이상 충돌 안 함
       ↓
PickupScaleTimeline
  └─ Play from Start
       ↓
     타임라인 시작
```

### 충돌 비활성화가 필요한 이유

```
문제 상황:
  픽업 후 0.2초 동안 아직 존재
    ↓
  충돌 활성화 상태
    ↓
  다시 충돌 가능!
    ↓
  중복 픽업 또는 에러

해결:
  즉시 충돌 비활성화
    ↓
  타임라인 재생 중 충돌 없음
    ↓
  안전하게 제거
```

### Timeline Finished에서 제거

```
PickupScaleTimeline
  └─ Finished 핀
       ↓
     Destroy Actor
       └─ 애니메이션 끝나면 제거
```

## 📝 핵심 노드 정리

```
Spawn Sound at Location
  ├─ Sound: USoundBase

  └─ Auto Destroy: Boolean (권장 True)

용도:
  ├─ 위치 기반 사운드 재생
  └─ 3D 사운드 (거리감 있음)
```

### Spawn System at Location

```
Spawn System at Location (Niagara)
  ├─ System Template: UNiagaraSystem
  ├─ Location: Vector
  ├─ Rotation: Rotator
  ├─ Scale: Vector (기본 1,1,1)
  ├─ Auto Destroy: Boolean
  └─ Pool Method: 풀링 옵션

용도:
  ├─ 파티클 효과 생성
  └─ 일회성 이펙트
```

### Add World Rotation

```
Add World Rotation
  ├─ Target: Scene Component
  ├─ Delta Rotation: Rotator
  └─ 효과: 현재 회전에 추가

vs Set World Rotation:
  ├─ Set: 절대값으로 설정
  └─ Add: 상대값으로 추가 (누적)
```

### Set World Scale 3D

```
Set World Scale 3D
  ├─ Target: Scene Component
  ├─ New Scale: Vector
  └─ 효과: 월드 스케일 설정

균등 스케일:
  Make Vector (X, Y, Z)
    └─ 모두 같은 값 = 비율 유지

비균등 스케일:
  └─ 각각 다른 값 = 변형됨
```

### Timeline (타임라인)

```
Timeline
  ├─ Float/Vector/Linear Color Track 지원
  ├─ Update: 매 프레임 실행
  ├─ Finished: 완료 시 1회 실행
  └─ 제어:
       ├─ Play: 시작부터 재생
       ├─ Play from Start: 0.0부터 재생
       ├─ Reverse: 역재생
       ├─ Stop: 정지
       └─ Set New Time: 특정 지점으로

커브 편집:
  ├─ Linear: 직선
  ├─ Auto: 부드러운 곡선
  └─ User: 수동 조정
```

```
1. Auto Destroy 필수
   ├─ 사운드/파티클 생성 시 True 설정
   ├─ 메모리 누수 방지
   └─ 성능 문제 예방

2. 충돌 비활성화 타이밍
   ├─ 픽업 즉시 비활성화
   ├─ 중복 픽업 방지
   └─ 타임라인 재생 중 안전

3. Timeline Length 조절
   ├─ 너무 짧으면: 보기 어려움
   ├─ 너무 길면: 답답함
   └─ 0.2~0.5초 권장

4. Rotation Speed 적절히
   ├─ 너무 빠르면: 어지러움
   ├─ 너무 느리면: 눈에 안 띔
   └─ 30~60도/초 권장

5. Delta Time 사용
   ├─ 모든 시간 기반 계산에 필수
   ├─ Event Tick의 Delta Seconds
   └─ Get World Delta Seconds
```

## 🎓 Game Polish 원칙

### Juice 추가 우선순위

```
1. 핵심 게임플레이 먼저
   └─ 기능이 완성되어야 Juice 추가

   ├─ 플레이어 행동에 대한 반응
   └─ 사운드 + 비주얼

3. 과하지 않게
   ├─ 너무 많으면 산만함
   └─ 절제된 효과가 더 효과적

4. 성능 고려
   ├─ 파티클 수 제한
   ├─ Auto Destroy 활용
   └─ 풀링 시스템 사용
```

```
시각적:
  ├─ 스케일 애니메이션 (크기 변화)
  ├─ 파티클 효과
  ├─ 색상 변화
  └─ 카메라 쉐이크

청각적:
  ├─ 효과음
  ├─ 음악 변화
  └─ 음향 피드백

촉각적 (선택):
  └─ 컨트롤러 진동
```

## 🚀 완성된 픽업 시스템 정리

### Before vs After

```
Before (이전 강의):
  픽업 충돌
    ↓
  연료 보충
    ↓
  아이템 즉시 제거

## 💡 핵심 개념: Widget과 HUD

### Widget(위젯)이란?

```
Widget
  ↓
화면에 표시되는 UI 요소
  ├─ 체력 바
  ├─ 미니맵
  ├─ 인벤토리
  ├─ 메뉴
  └─ 텍스트, 이미지 등 모든 UI

목적:
  └─ 플레이어에게 정보 전달
       ├─ 현재 상태 (체력, 연료 등)
       ├─ 게임 진행 상황
       └─ 조작 방법
```

### HUD란?

```
HUD (Heads-Up Display)
  ↓
"헤드업 디스플레이" = 게임 화면 위 UI
  ├─ 비행 시뮬레이터 용어에서 유래
  ├─ 화면을 가리지 않고 정보 표시
  └─ 게임에서: 모든 UI 요소 총칭

예시:
  ├─ 체력 바
  ├─ 연료 게이지
  ├─ 미니맵
  ├─ 점수 표시
  └─ 크로스헤어(조준점)
```

---

## 🎓 HUD 관리 방법 비교

### 방법 1: HUD 클래스 (레거시)

```
HUD Class (언리얼 엔진 기본 클래스)
  ↓
Game Mode에서 자동 스폰
  ├─ BP_JetpackGameMode 설정:
  │    └─ HUD Class: 커스텀 HUD 지정 가능
  │
  └─ 장점: 전통적인 방법, 간단
       단점: 레거시 클래스 (구식)
```

**레거시(Legacy)란?**

- "유산", "과거 유물"이라는 뜻
- 오래된 방식이지만 호환성 때문에 남아있음
- 새 프로젝트에서는 권장하지 않음

**왜 여전히 존재?**

```
제거하기 어려운 이유:
  ├─ 많은 기존 프로젝트가 사용 중
  ├─ 엔진 내부 시스템도 의존
  └─ 호환성 깨짐 방지
       ↓
     그냥 남겨둠 (편의성)
```

### 방법 2: Player Controller (권장)

```
Player Controller에서 HUD 관리
  ↓
더 현대적이고 유연한 방식
  ├─ 플레이어마다 다른 UI 가능
  ├─ 멀티플레이어 친화적
  └─ 더 나은 구조

이번 강의 선택:
  └─ BP_KixPlayerController에서 관리
```

## 📌 Anchor (앵커) 시스템

### Anchor란?

```
Anchor (앵커)
  ↓
"닻", "고정점"
  ↓
위젯이 화면에서 고정되는 기준점
  ├─ 화면 크기가 변해도
  ├─ 앵커 기준으로 위치 유지
  └─ 반응형 UI의 핵심
```

### Anchor 설정

```
Text Widget 선택
  ↓
Details → Anchors (앵커 드롭다운)
  ↓
프리셋 선택:
  ├─ 왼쪽 상단 (기본)
  ├─ 오른쪽 상단
  ├─ 가운데
  ├─ 하단 가운데
  └─ 기타 다양한 옵션
```

### Anchor 동작 원리

```
Anchor: 왼쪽 상단
  ↓
Position (위치):
  ├─ X: 왼쪽에서의 거리
  └─ Y: 위에서의 거리

화면 크기 변경 시:
  └─ 왼쪽 상단에서의 거리 유지
       ↓
     항상 같은 상대 위치
```

**예시:**

```
1920x1080 화면:
  Text Position: (100, 50)
    └─ 왼쪽에서 100px, 위에서 50px

1280x720 화면:
  Text Position: (100, 50) 유지
    └─ 여전히 왼쪽에서 100px, 위에서 50px
```

### 중앙 정렬 설정

```
1. Anchor → 가운데 선택
   └─ Anchor Point: 화면 중앙

2. Alignment 설정
   ├─ X: 0.5
   ├─ Y: 0.5
   └─ 위젯 중심점이 중앙

3. Position (X, Y): 0, 0
   └─ 앵커에서의 오프셋 없음
        ↓
      완벽한 중앙 배치!
```

**Alignment란?**

```
Alignment (정렬)
  ↓
위젯의 "중심점" 위치
  ├─ 0.0: 왼쪽/위 끝
  ├─ 0.5: 정중앙
  └─ 1.0: 오른쪽/아래 끝

예시:
  Alignment (0.5, 0.5)
    └─ 위젯 중심이 기준점
         ↓
       Position (0, 0)이면
         ↓
       중심이 앵커 위치에 딱!
```

  ├─ Category: UI
  └─ 저장 완료

```
Before (복잡):
  Create Widget → Set Overlay Widget
                → Add to Viewport

After (깔끔):

                       ↓
                  Add to Viewport
                  (Overlay Widget 변수 사용)

### 함수로 캡슐화

```
노드 선택 → Collapse to Function
  ↓
Name: Create Overlay Widget
  ├─ Category: UI

## 📊 Text vs String 데이터 타입

### Text 타입

```
Text (텍스트 타입)
  ↓
사용자에게 보이는 텍스트 전용
  ├─ 현지화(Localization) 지원

  ├─ 위젯 텍스트
  ├─ 대화문
  ├─ UI 레이블
  └─ 플레이어가 보는 모든 글자
```

### String 타입

```
String (문자열 타입)
  ↓
코드 내부 처리용 텍스트

  └─ 내부 로직

용도:
  ├─ 파일 경로
  ├─ 오브젝트 이름
  ├─ 내부 식별자
  └─ 플레이어가 안 보는 데이터
```

### 비교

```
Text:
  └─ "당신의 체력: 100"
       ├─ 한국어: "당신의 체력: 100"
       ├─ 영어: "Your Health: 100"
       └─ 현지화 가능

String:
  └─ "/Game/Blueprints/BP_Kix"
       ├─ 항상 같음
       └─ 현지화 불필요
```

## 🧮 연료 백분율 계산

### Get Fuel Percentage 함수 생성

```

예시:
  ├─ Jet Fuel: 25
  ├─ Max Jet Fuel: 50
  └─ Percent: 25/50 = 0.5 (50%)
```

### Safe Divide 사용

```
문제:
  일반 Divide (/)
    ├─ Max Jet Fuel = 0일 때
    └─ 0으로 나누기 → 에러!

해결:
  Safe Divide
    ├─ B가 0이면 → 0 반환
    └─ B가 0이 아니면 → A/B 계산
```

**Safe Divide 노드:**

```
Safe Divide
  ├─ A: Jet Fuel
  ├─ B: Max Jet Fuel
  └─ Return Value: Float
       ├─ B ≠ 0: A/B
       └─ B = 0: 0.0 (안전하게 0 반환)
```

## 🎓 캡슐화(Encapsulation) 개념

### 캡슐화란?

```
Encapsulation (캡슐화)
  ↓
내부 구현을 숨기고 인터페이스만 노출
  ├─ 내부: ProgressBar_Fuel, Set Percent
  ├─ 인터페이스: Update Fuel Percent
  └─ 외부는 내부를 몰라도 됨

약 캡슐:
  ├─ 내용물(약): 숨겨짐
  └─ 캡슐 껍질: 인터페이스
```

### 장점

```
1. 변경 용이
   Progress Bar → Slider로 변경 시
     ├─ WBP_Overlay만 수정
     └─ PlayerController는 변경 불필요

2. 이해하기 쉬움
   "Update Fuel Percent 호출"
     └─ 내부 어떻게? 몰라도 됨

3. 재사용성
   다른 곳에서도 같은 함수 호출

4. 버그 감소
   내부 구조 잘못 건드릴 일 없음
```

Set Percent
  ├─ Target: Progress Bar
  ├─ In Percent: 0.0 ~ 1.0
  └─ 효과: 바 채우기 정도 설정
```

### Safe Divide

```
Safe Divide
  ├─ A: 분자
  ├─ B: 분모
  └─ Return:
       ├─ B ≠ 0: A/B
       └─ B = 0: 0.0
```

## ⚠️ 주의사항

```
1. Compile 순서
   ├─ WBP_Overlay에서 변수/함수 추가
   ├─ WBP_Overlay 컴파일 먼저!
   └─ PlayerController 컴파일
        ↓
      순서 안 지키면 에러!

2. Is Variable 필수
   ├─ Progress Bar는 Is Variable 체크
   └─ 안 하면 Graph에서 접근 불가

3. Safe Divide 사용
   ├─ 일반 Divide 대신 Safe Divide
   └─ 0으로 나누기 방지

4. Pure Function 활용
   ├─ Get Fuel Percentage는 Pure
   ├─ 여러 번 호출해도 안전
   └─ 캐싱 필요 없음

5. 캡슐화 유지
   ├─ Widget 내부 구조 노출 금지
   ├─ 커스텀 함수로 인터페이스 제공
   └─ 유지보수성 향상
```
