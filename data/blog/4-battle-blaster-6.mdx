# { 언리얼 엔진 C++ - Game Mode에서 사망 처리 핵심 정리 }

## 📌 이번 강의의 목표

**게임 로직의 중심인 Game Mode에서 사망을 관리하기!**

- 타워 죽으면 → 타워 수 감소 → 0되면 승리!
- 탱크 죽으면 → 게임 오버!

---

## 🎯 왜 Game Mode에서 처리하나요?

### 잘못된 방식 ❌

```cpp
// Health Component에서 직접 처리
void OnDamageTaken(...)
{
    if (Health <= 0)
    {
        GetOwner()->Destroy();  // 그냥 파괴만 함
        // 게임 승리/패배 체크 불가능!
    }
}
```

### 올바른 방식 ✅

```cpp
// Health Component → Game Mode로 알림
void OnDamageTaken(...)
{
    if (Health <= 0)
    {
        GameMode->ActorDied(DamagedActor);  // 게임 모드에 알림
        // Game Mode가 게임 로직 처리!
    }
}
```

---

## 🎮 Game Mode의 역할

```
Game Mode = 게임의 심판/관리자

역할:
├─ 타워 수 추적
├─ 승리 조건 체크
├─ 패배 조건 체크
├─ 게임 시작/종료 관리
└─ 전체 게임 흐름 통제
```

---

## 🔄 전체 시스템 흐름

```
1. 발사체 충돌
   ↓
2. ApplyDamage() 호출
   ↓
3. Health Component의 OnDamageTaken() 실행
   ↓
4. Health <= 0?
   ↓
5. GameMode->ActorDied(죽은 액터) 호출
   ↓
6. Game Mode가 액터 타입 확인
   ├─ 탱크? → 게임 오버 처리
   └─ 타워? → 타워 수 감소
       ↓
       TowerCount == 0? → 승리!
```

### 2단계: Health Component에서 Game Mode 가져오기

### HealthComponent.h

class UHealthComponent : public UActorComponent
{
    GENERATED_BODY()

public:
    ABattleBlasterGameMode* BattleBlasterGameMode;  // 게임 모드 참조

    void OnDamageTaken(...);

### HealthComponent.cpp - BeginPlay

```cpp
void UHealthComponent::BeginPlay()
{
    Super::BeginPlay();

    Health = MaxHealth;

    // 델리게이트 연결
    GetOwner()->OnTakeAnyDamage.AddDynamic(this, &UHealthComponent::OnDamageTaken);

    // 게임 모드 가져오기 (한 번만!)
    AGameModeBase* GameMode = UGameplayStatics::GetGameMode(GetWorld());
    if (GameMode)
    {
        // 커스텀 게임 모드로 캐스팅
        BattleBlasterGameMode = Cast<ABattleBlasterGameMode>(GameMode);
    }
}
```

### 왜 BeginPlay에서 한 번만 가져오나요?

```
❌ 나쁜 방식: 매번 가져오기
void OnDamageTaken(...)
{
    GetGameMode() → 매번 호출
    Cast<>() → 매번 캐스팅
    // 비효율적!
}

✅ 좋은 방식: 한 번만 가져와서 저장
void BeginPlay()
{
    GameMode = GetGameMode()  // 1번만 호출
    BattleBlasterGameMode = Cast<>()  // 1번만 캐스팅
}

void OnDamageTaken(...)
{
    BattleBlasterGameMode->ActorDied()  // 저장된 것 사용
    // 효율적!
}
```

### 3단계: OnDamageTaken에서 Game Mode 호출

```cpp
void UHealthComponent::OnDamageTaken(
    AActor* DamagedActor,
    float Damage,
    const UDamageType* DamageType,
    AController* InstigatedBy,
    AActor* DamageCauser
)
{
    if (Damage > 0.0f)
    {
        // 체력 감소
        Health -= Damage;

        if (Health <= 0.0f)
        {
            // Game Mode에 알림
            if (BattleBlasterGameMode)
            {
                BattleBlasterGameMode->ActorDied(DamagedActor);
            }
        }
    }
}
```

### 코드 해부

```cpp
if (BattleBlasterGameMode)  // 게임 모드 유효성 체크
{
    BattleBlasterGameMode->ActorDied(DamagedActor);
    // 죽은 액터를 게임 모드에 전달
}
```

### 4단계: Game Mode에서 ActorDied 구현

```cpp
void ABattleBlasterGameMode::ActorDied(AActor* DeadActor)
{
    // 1. 탱크가 죽었는지 확인
    if (DeadActor == Tank)
    {
        // 플레이어 패배 처리
        UE_LOG(LogTemp, Display, TEXT("Tank died - DEFEAT"));
        // 다음 강의: Tank->HandleDestruction();
    }
    else  // 2. 탱크가 아니면 타워
    {
        // 타워로 캐스팅
        ATower* DeadTower = Cast<ATower>(DeadActor);

        if (DeadTower)
        {
            UE_LOG(LogTemp, Display, TEXT("A tower just died"));

            // 타워 파괴
            DeadTower->Destroy();

            // 타워 수 감소
            TowerCount--;

            // 승리 조건 체크
            if (TowerCount == 0)
            {
                UE_LOG(LogTemp, Display, TEXT("All towers dead - VICTORY!"));
            }
        }
    }
}
```

## 💡 핵심 개념 상세 설명

### 1️⃣ GetGameMode() 함수

```cpp
AGameModeBase* GameMode = UGameplayStatics::GetGameMode(GetWorld());
```

**무슨 일을 하나요?**

- 현재 레벨의 Game Mode를 가져옴
- 모든 레벨에는 Game Mode가 하나만 존재
- 게임의 "관리자"를 찾는 것

---

### 2️⃣ Cast (캐스팅)

```cpp
BattleBlasterGameMode = Cast<ABattleBlasterGameMode>(GameMode);
```

### 왜 캐스팅이 필요한가요?

```
GetGameMode()가 반환하는 타입:
AGameModeBase* (기본 게임 모드)

우리가 만든 타입:
ABattleBlasterGameMode* (커스텀 게임 모드)

문제:
AGameModeBase에는 ActorDied() 함수가 없음!
ABattleBlasterGameMode에만 있음!

해결:
Cast로 타입 변환
→ ActorDied() 함수 사용 가능!
```

### 캐스팅 비유

```
기본 자동차 (GameModeBase)
  ↓ Cast (개조)
스포츠카 (BattleBlasterGameMode)

기본 자동차: 달리기만 가능
스포츠카: 달리기 + 부스터 + 우리가 추가한 기능들!
```

---

### 3️⃣ 타워 수 감소 연산자

```cpp
TowerCount--;  // 1 감소
```

### 다양한 방법들

```cpp
// 방법 1: 긴 버전
TowerCount = TowerCount - 1;

// 방법 2: 축약 버전
TowerCount -= 1;

// 방법 3: 감소 연산자 (가장 짧음!)
TowerCount--;

// 모두 같은 의미: TowerCount를 1 감소
```

### 시나리오 1: 타워 파괴

```
초기 상태:
- TowerCount = 3
- 타워들: Tower_0, Tower_1, Tower_2

[Tower_0 파괴]

2. ApplyDamage(Tower_0, 25, ...)
3. Health Component: Health = 50 - 25 = 25
   (아직 살아있음)

[Tower_0 다시 맞음]

2. Health = 25 - 25 = 0

   - Tower_0 == Tank? 아니오
   - Tower로 캐스팅 성공!
   - Tower_0->Destroy()
   - TowerCount = 3 - 1 = 2
   - TowerCount == 0? 아니오 (계속 플레이)

[모든 타워 파괴 후]
- TowerCount = 0
- "All towers dead - VICTORY!" 출력
```

## 🔍 코드 개선 포인트

### 매번 가져오기 vs 한 번만 가져오기

### ❌ 비효율적 (매번 가져오기)

```cpp
void OnDamageTaken(...)
{
    if (Health <= 0)
    {
        // 매번 호출!
        AGameModeBase* GM = UGameplayStatics::GetGameMode(GetWorld());
        ABattleBlasterGameMode* BBGM = Cast<ABattleBlasterGameMode>(GM);
        BBGM->ActorDied(DamagedActor);
    }
}
```

**문제점:**

- 죽을 때마다 GetGameMode() 호출
- 죽을 때마다 Cast 수행
- 불필요한 연산 반복

---

### ✅ 효율적 (한 번만 가져오기)

```cpp
// BeginPlay에서 한 번만
void BeginPlay()
{
    BattleBlasterGameMode = Cast<ABattleBlasterGameMode>(
        UGameplayStatics::GetGameMode(GetWorld())
    );
}

// 사용할 때는 저장된 것 사용
void OnDamageTaken(...)
{
    if (Health <= 0 && BattleBlasterGameMode)
    {
        BattleBlasterGameMode->ActorDied(DamagedActor);
    }
}
```

**장점:**

- 게임 시작 시 1번만 호출
- 멤버 변수에 저장해서 재사용
- 빠르고 효율적!

## 🎓 초보자 Q&A

### Q1: 왜 탱크는 바로 비교하고 타워는 캐스팅하나요?

```cpp
// 탱크
if (DeadActor == Tank)  // 직접 비교

// 타워
ATower* DeadTower = Cast<ATower>(DeadActor);  // 캐스팅 필요
```

**이유:**

```
탱크:
- Game Mode가 이미 Tank 포인터를 가지고 있음
- BeginPlay에서 찾아서 저장해둠
- 그냥 비교만 하면 됨! ✅

타워:
- 타워가 여러 개 (Tower_0, Tower_1, Tower_2...)
- Game Mode는 "어떤 타워"인지 모름
- 캐스팅해서 타워 타입인지 확인 필요
```

---

### Q2: else만 써도 되는 이유는?

```cpp
if (DeadActor == Tank)
{
    // 탱크 처리
}
else  // 탱크가 아니면 무조건 타워!
{
    // 타워 처리
}
```

**이 게임의 경우:**

- Health Component를 가진 액터 = 탱크 or 타워만 존재
- 탱크가 아니면 → 100% 타워
- 따라서 `else`만으로 충분!

**다른 액터가 더 있다면:**

```cpp
if (DeadActor == Tank)
{
    // 탱크
}
else if (Cast<ATower>(DeadActor))
{
    // 타워
}
else if (Cast<ACrate>(DeadActor))
{
    // 상자
}
```

---

### Q3: 왜 DeadActor를 전달하나요? Owner면 안 되나요?

```cpp
BattleBlasterGameMode->ActorDied(DamagedActor);
```

**DamagedActor vs GetOwner():**

```cpp
void OnDamageTaken(AActor* DamagedActor, ...)
{
    // 둘 다 같은 액터를 가리킴!
    DamagedActor == GetOwner()  // true

    // 하지만 DamagedActor 사용 이유:
    // 1. 이미 매개변수로 받았으니 바로 사용 (효율적)
    // 2. GetOwner() 호출 불필요
}
```

## 📌 이번 강의의 목표

**부모-자식 클래스에서 같은 함수를 만들고 `Super` 키워드로 연결하기!**

- 공통 기능 = 부모(BasePawn)에서 처리
- 특수 기능 = 자식(Tank/Tower)에서 처리

---

## 🎯 Super 키워드란?

### 간단한 비유

```
가족 구조:
부모(BasePawn) → "파괴될 때 폭발 효과 재생"
  ↓ 상속
자식(Tank)     → "파괴될 때 카메라 유지 + 부모 기능도 실행"
자식(Tower)    → "파괴될 때 액터 제거 + 부모 기능도 실행"
```

**Super = "부모님께 먼저 여쭤보기"**

---

## 🔄 전체 시스템 구조

```
BasePawn (부모)
├─ HandleDestruction()
│  └─ 공통: 폭발 효과, 사운드 재생
│
├─ Tank (자식)
│  └─ HandleDestruction()
│     ├─ Super::HandleDestruction() ← 부모 기능 실행
│     └─ 탱크 전용: 입력 비활성화, 안 보이게
│
└─ Tower (자식)
   └─ HandleDestruction()
      ├─ Super::HandleDestruction() ← 부모 기능 실행
      └─ 타워 전용: Destroy() 호출
```

void ABattleBlasterGameMode::ActorDied(AActor* DeadActor)
{
    if (DeadActor == Tank)
    {
        // 탱크 파괴 처리
        Tank->HandleDestruction();
    }
    else
    {
        ATower* DeadTower = Cast<ATower>(DeadActor);
        if (DeadTower)
        {
            // 타워 파괴 처리
            DeadTower->HandleDestruction();

            TowerCount--;
            if (TowerCount == 0)
            {
                UE_LOG(LogTemp, Display, TEXT("All towers dead!"));
            }
        }
    }
}
```

   │     └─ "Base Pawn Destruction" 출력 ✅

   └─ "Tank Destruction" 출력 ✅

출력 결과:

```

## 🔍 핵심 개념 상세 설명

### 1️⃣ 함수 오버라이드 (Override)

```cpp
// 부모 클래스
class ABasePawn
{
    void HandleDestruction() { }
};

// 자식 클래스
class ATank : public ABasePawn
{
    void HandleDestruction() { }  // ← 같은 이름으로 재정의!
};
```

**오버라이드 = 부모 함수를 자식에서 다시 정의**

---

### 2️⃣ Super vs this

| 키워드    | 의미                | 예시                 |
| --------- | ------------------- | -------------------- |
| **this**  | 현재 객체 (나 자신) | `this->Health`       |
| **Super** | 부모 클래스         | `Super::BeginPlay()` |

```cpp
void ATank::HandleDestruction()
{
    Super::HandleDestruction();  // 부모의 HandleDestruction
    this->SetActorHidden(true);  // 내(Tank)의 함수
}
```

---

### 3️⃣ 호출 순서의 중요성

### ✅ 올바른 순서

```cpp
void ATower::HandleDestruction()
{
    Super::HandleDestruction();  // 1. 부모 먼저
    Destroy();                   // 2. 그 다음 파괴
}
```

**이유:** 부모 기능(폭발 효과) 실행 → 그 다음 파괴

---

### ❌ 잘못된 순서

```cpp
void ATower::HandleDestruction()
{
    Destroy();                   // 1. 먼저 파괴!
    Super::HandleDestruction();  // 2. 이미 없는 객체의 함수 호출 ❌
}
```

**문제:** 타워가 이미 파괴되어 부모 함수 실행 불가!

## 🎓 초보자 Q&A

### Q1: 왜 같은 이름으로 만드나요?

```cpp
// BasePawn
void HandleDestruction() { }

// Tank
void HandleDestruction() { }  // 왜 같은 이름?
```

**이유: 다형성(Polymorphism)**

```cpp
// Game Mode에서
ABasePawn* Pawn = GetRandomPawn();

// Pawn이 Tank든 Tower든 상관없이 호출 가능!
Pawn->HandleDestruction();

// Tank면 → Tank::HandleDestruction() 실행
// Tower면 → Tower::HandleDestruction() 실행
```

같은 이름 덕분에 코드 재사용과 유연성 확보!

---

### Q2: Super를 안 쓰면 어떻게 되나요?

```cpp
void ATank::HandleDestruction()
{
    // Super::HandleDestruction();  ← 주석 처리!
    UE_LOG(LogTemp, Display, TEXT("Tank Destruction"));
}
```

**결과:**

- Tank 로그만 출력
- BasePawn의 공통 기능(폭발 효과) 실행 안됨!
- 부모 기능이 필요 없으면 Super 생략 가능

---

### Q3: Super는 언제 써야 하나요?

```
✅ Super 사용 (부모 기능 + 추가 기능)
void BeginPlay()
{
    Super::BeginPlay();  // 부모 초기화 필수!
    // 내 초기화
}

✅ Super 사용 (공통 기능 필요)
void HandleDestruction()
{
    Super::HandleDestruction();  // 공통 이펙트
    // 특수 처리
}

❌ Super 안 써도 됨 (완전히 새로 작성)
void CustomFunction()
{
    // 부모에 없는 새 기능
}
```

**원칙: 부모 기능이 필요하면 Super, 아니면 생략**

# { 탱크 파괴 시스템 구현 }

이 강의는 탱크가 체력을 모두 잃었을 때 어떻게 처리할지를 구현하는 내용입니다.

---

## 🎯 구현 목표

**기존 상황:**

- 타워는 파괴되면 완전히 사라짐 (`Destroy()` 호출)
- 탱크도 파괴되면? → 카메라도 같이 사라져서 문제 발생!

**해결 방법:**
탱크는 완전히 제거하지 않고 "무력화" 시키기

1. 화면에서 보이지 않게 하기
2. 움직임/사격 등 입력 비활성화
3. 다른 객체들에게 죽었다고 알리기

---

## 📝 구현 단계

### 1단계: 탱크를 보이지 않게 만들기

```cpp
void ATank::HandleDestruction()
{
    Super::HnadleDestruction();

    // 1. 액터를 화면에서 숨기기
    SetActorHiddenInGame(true);  // true = 숨김, false = 보임
}
```

**테스트 결과:** 탱크가 투명해지지만 여전히 움직이고 쏠 수 있음 ❌

---

### 2단계: Tick 함수 비활성화

```cpp
void ATank::HandleDestruction()
{
    Super::HnadleDestruction();

    SetActorHiddenInGame(true);

    // 2. Tick 함수 끄기 (매 프레임 실행되는 함수)
    SetActorTickEnabled(false);  // 포탑 회전 등이 멈춤
}
```

**Tick이 꺼지면:**

- 포탑이 마우스를 따라 회전하지 않음
- 하지만 여전히 WASD 키로 움직이고 발사 가능 ❌

---

### 3단계: 플레이어 입력 완전히 끄기

먼저 `PlayerController`를 멤버 변수로 만들기:

**Tank.h (헤더 파일):**

```cpp
class ATank : public ABasePawn
{
    // ...

    APlayerController* PlayerController;  // 멤버 변수로 선언

    void SetPlayerEnabled(bool Enable);   // 새로운 함수
};
```

**Tank.cpp:**

```cpp
void ATank::BeginPlay()
{
    Super::BeginPlay();

    // PlayerController를 BeginPlay에서 한 번만 가져오기
    PlayerController = Cast<APlayerController>(GetController());
    // ... 입력 설정 코드
}

// 입력을 켜고 끄는 함수
void ATank::SetPlayerEnabled(bool Enabled)
{
    if (PlayerController)
    {
        if (Enabled)
        {
            EnableInput(PlayerController);   // 입력 활성화
        }
        else
        {
            DisableInput(PlayerController);  // 입력 비활성화
        }
    }
}

void ATank::HandleDestruction()
{
    Super::HnadleDestruction();

    SetActorHiddenInGame(true);
    SetActorTickEnabled(false);

    // 3. 플레이어 입력 끄기
    SetPlayerEnabled(false);
}
```

**테스트 결과:** 이제 움직임도 사격도 불가능! ✅
하지만 타워가 계속 죽은 탱크를 공격함 ❌

### 4단계: 생존 여부를 알리는 변수 추가

**Tank.h:**

{
    // 발사 조건 체크:
    // 1. Tank 포인터가 유효한가?
    // 2. Tank가 살아있는가? (새로 추가!)
    // 3. Tank가 사거리 안에 있는가?

## 🔍 전체 흐름 정리

```
1. 탱크가 피해를 받아 체력이 0이 됨
   ↓
2. GameMode가 ActorDied() 호출
   ↓
3. Tank->HandleDestruction() 실행:
   - SetActorHiddenInGame(true)      → 화면에서 사라짐
   - SetActorTickEnabled(false)       → 포탑 회전 멈춤
   - SetPlayerEnabled(false)          → 입력 완전 차단
   - IsAlive = false                  → 죽음 표시
   ↓
4. Tower의 CheckFireCondition()에서
   Tank->IsAlive를 체크하여 더 이상 공격하지 않음
```

## 💡 핵심 개념

### PlayerController란?

- 플레이어의 입력을 관리하는 객체
- `EnableInput()`: 입력 받기 시작
- `DisableInput()`: 입력 무시

### 멤버 변수로 만드는 이유

- BeginPlay, Tick, HandleDestruction 등 여러 함수에서 사용
- 매번 새로 가져올 필요 없이 한 번 저장해두면 편함

### 왜 Destroy()를 안 쓰나?

- Destroy()를 쓰면 탱크와 연결된 **카메라도 같이 사라짐**
- 게임 화면이 이상해지므로 "숨기기" 방식 사용

- 카메라는 정상 작동 (게임 화면 유지)
