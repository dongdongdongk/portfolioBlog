# { 🎯 언리얼 엔진 콜리전(충돌) 시스템 기초 }

## 📌 이 강의의 목표

언리얼 엔진의 충돌 시스템을 처음부터 이해하고 게임에서 활용할 수 있도록 학습합니다.

- 충돌이란 무엇인가
- 충돌이 어떻게 작동하는가
- 충돌 설정을 어떻게 관리하는가

---

## 🔍 충돌(Collision)이란?

### 기본 개념

```
게임 속 물체들이 서로 부딪히거나 겹치는 것
  ↓
예시: 캐릭터가 벽에 막히는 것
      총알이 적에게 맞는 것
      발판 위에 서는 것
```

---

## 🧩 프리미티브 컴포넌트 (Primitive Component)

### 충돌의 시작점

**프리미티브 컴포넌트**: 충돌 데이터를 가질 수 있는 컴포넌트

- 게임 속 물체들이 충돌하려면 반드시 프리미티브 컴포넌트여야 함
- 씬 컴포넌트(Scene Component)는 충돌 불가능

### 프리미티브 컴포넌트 종류

```
프리미티브 컴포넌트
  ├─ Static Mesh Component (3D 모델)
  ├─ Sphere Component (구 모양)
  ├─ Box Component (상자 모양)
  ├─ Capsule Component (캡슐 모양)
  └─ 기타 셰이프 컴포넌트들
```

**중요**: 액터(Actor) 자체가 충돌하는 것이 아니라, 액터 안의 컴포넌트가 충돌합니다.

---

## 🎭 충돌의 두 가지 종류

### 1. 충돌 (Collision)

```
물체끼리 실제로 부딪히는 것
  ↓
예시: 캐릭터가 벽을 통과하지 못함
      공이 바닥에 떨어짐
```

### 2. 쿼리 (Query)

```
"충돌이 있는지 확인하는 검사"
  ↓
종류
  ├─ Line Trace (선 쏘기)
  │   └─ 보이지 않는 선을 쏴서 뭔가 맞는지 확인
  │
  ├─ Shape Sweep (도형 밀기)
  │   └─ 보이지 않는 도형을 밀어서 뭔가 걸리는지 확인
  │
  └─ Overlap (겹침 확인)
      └─ 특정 영역에 뭔가 있는지 확인
```

**예시**:

- Line Trace: 총을 쏠 때 총알이 맞는지 확인
- Shape Sweep: 캐릭터가 이동할 수 있는지 미리 확인
- Overlap: 문 앞에 플레이어가 있는지 확인

---

## 📦 충돌 데이터의 구성

```
충돌 데이터
  ├─ 충돌 지오메트리 (모양)
  └─ 충돌 세팅 (설정)
```

### 충돌 지오메트리 (Collision Geometry)

**물체의 충돌 판정 모양**

### 1. Complex Collision (복잡한 충돌)

```
실제로 보이는 메시 그대로 사용
  ├─ 장점: 정확함
  └─ 단점: 계산이 느림
```

### 2. Simple Collision (단순한 충돌)

```
보이지 않는 단순한 도형 사용
  ├─ 종류: 상자, 구, 캡슐 등
  ├─ 장점: 계산이 빠름
  └─ 단점: 덜 정확함
```

**권장**: 성능을 위해 Simple Collision 사용

### 3. Shape Components (셰이프 컴포넌트)

```
별도로 추가하는 충돌용 도형
  ├─ Sphere Component (구)
  ├─ Box Component (상자)
  └─ Capsule Component (캡슐)
```

---

## ⚙️ 충돌 세팅 (Collision Settings)

### 3가지 핵심 설정

```
충돌 세팅
  ├─ 1. Collision Enabled (충돌 활성화)
  ├─ 2. Object Type (오브젝트 타입)
  └─ 3. Collision Responses (충돌 반응)
```

---

## 🔧 1. Collision Enabled (충돌 활성화)

**"이 물체를 어떤 용도로 쓸 것인가?"**

### 옵션 설명

### No Collision (충돌 없음)

```
충돌 계산 안 함
  └─ 용도: 장식용 물체
```

### Query Only (쿼리만)

```
검사만 가능 (Line Trace 등)
물리 충돌 불가능
  ├─ 할 수 있는 것
  │   ├─ Line Trace에 감지됨
  │   ├─ Overlap 이벤트 발생
  │   └─ Shape Sweep에 걸림
  │
  └─ 할 수 없는 것
      ├─ 물리 시뮬레이션 불가
      ├─ 힘 적용 불가
      └─ 물리적으로 막히지 않음
```

### Physics Only (물리만)

```
물리 충돌만 가능
쿼리 불가능
  ├─ 할 수 있는 것
  │   ├─ 물리 시뮬레이션 가능
  │   ├─ 힘 적용 가능
  │   └─ 물리적으로 막힘
  │
  └─ 할 수 없는 것
      ├─ Line Trace 무시됨
      ├─ Overlap 이벤트 없음
      └─ Shape Sweep 무시됨
```

### Collision Enabled (쿼리 + 물리)

```
쿼리와 물리 모두 가능
  ├─ 장점: 모든 기능 사용 가능
  └─ 단점: 계산량이 가장 많음 (무거움)
```

### Probe (쿼리 + 충돌 감지)

```
쿼리 가능 + 충돌 감지만
힘은 전달되지 않음
  ├─ 할 수 있는 것
  │   ├─ 쿼리 감지
  │   └─ 충돌 감지 (Hit 이벤트)
  │
  └─ 할 수 없는 것
      └─ 충돌 시 힘 전달 안 됨 (막히지 않음)
```

### Query and Probe (쿼리 + 충돌 감지)

```
Probe와 동일 (쿼리 + 충돌 감지)
힘은 전달되지 않음
```

### 선택 가이드

```
용도별 추천 설정
  ├─ 장식용 소품
  │   └─ No Collision
  │
  ├─ 트리거 영역
  │   └─ Query Only
  │
  ├─ 물리 시뮬레이션 물체
  │   └─ Physics Only
  │
  ├─ 캐릭터/중요 물체
  │   └─ Collision Enabled
  │
  └─ 충돌 감지만 필요
      └─ Probe
```

---

## 🏷️ 2. Object Type (오브젝트 타입)

**"이 물체는 충돌 시스템에서 어떤 종류인가?"**

### Collision Channel (충돌 채널)

```
충돌 채널의 두 가지 종류
  ├─ Trace Channel (트레이스 채널)
  │   └─ Line Trace/Shape Sweep용
  │       └─ 오브젝트에 할당 불가능
  │
  └─ Object Channel (오브젝트 채널)
      └─ 물체 분류용
          └─ 오브젝트에 할당 가능
```

### 기본 제공 오브젝트 채널

```
기본 오브젝트 채널
  ├─ WorldStatic (고정된 세계 물체)
  │   └─ 예: 벽, 바닥, 건물
  │
  ├─ WorldDynamic (움직이는 세계 물체)
  │   └─ 예: 움직이는 플랫폼, 문
  │
  ├─ Pawn (캐릭터)
  │   └─ 예: 플레이어, AI
  │
  ├─ PhysicsBody (물리 물체)
  │   └─ 예: 떨어지는 상자, 공
  │
  ├─ Vehicle (탈것)
  └─ Destructible (부서지는 물체)
```

### 커스텀 채널 생성

```
프로젝트 설정에서 새 채널 추가 가능
  ├─ 주의: 제한된 개수만 생성 가능
  └─ 팁: 너무 많이 만들지 말 것
```

---

## 🔀 3. Collision Responses (충돌 반응)

**"각 채널의 물체와 어떻게 반응할 것인가?"**

### 세 가지 반응

### Ignore (무시)

```
충돌 없음
  ├─ 서로 통과함
  ├─ 이벤트 없음
  └─ 예: 유령처럼 통과
```

### Overlap (겹침)

```
통과하지만 감지됨
  ├─ 서로 통과함
  ├─ Overlap 이벤트 발생
  └─ 예: 트리거 영역 진입
```

### Block (차단)

```
충돌하여 막힘
  ├─ 서로 통과 못함
  ├─ Hit 이벤트 발생
  └─ 예: 벽에 막힘
```

### 충돌 반응 설정 예시

```
플레이어 캐릭터 설정
  ├─ WorldStatic → Block (벽에 막힘)
  ├─ WorldDynamic → Block (움직이는 물체에 막힘)
  ├─ Pawn → Block (다른 캐릭터와 부딪힘)
  ├─ PhysicsBody → Overlap (물리 물체 통과하며 감지)
  └─ Projectile → Ignore (총알 무시)
```

---

## 📋 Collision Preset (충돌 프리셋)

**미리 만들어진 충돌 설정 묶음**

### 프리셋의 구성

```
Collision Preset
  ├─ Collision Enabled (충돌 활성화)
  ├─ Object Type (오브젝트 타입)
  └─ Collision Responses (충돌 반응들)
```

### 프리셋 사용

```
컴포넌트 Details 패널
  └─ Collision Preset 선택
      ├─ 프리셋 선택 시
      │   └─ 모든 설정 자동 적용 (수정 불가)
      │
      └─ Custom 선택 시
          └─ 개별 설정 직접 조정 가능
```

### 기본 제공 프리셋 예시

```
주요 프리셋
  ├─ NoCollision
  │   └─ 충돌 없음
  │
  ├─ BlockAll
  │   └─ 모든 것 차단
  │
  ├─ OverlapAll
  │   └─ 모든 것 겹침
  │
  ├─ BlockAllDynamic
  │   └─ 움직이는 것만 차단
  │
  └─ PhysicsActor
      └─ 물리 물체용 설정
```

### 커스텀 프리셋 생성

```
프로젝트 설정에서 생성
  ├─ 제한 없음 (많이 만들어도 됨)
  ├─ 장점: 한 번 설정으로 여러 곳 적용
  └─ 예: "Wall" 프리셋을 모든 벽에 적용
```

## 🔍 Collision Filtering (충돌 필터링)

**"두 물체가 만났을 때 어떤 반응이 일어날까?"**

### 충돌 판정 규칙

```
충돌 상호작용 결정 과정
  ↓
1. 물체 A의 Object Type 확인
2. 물체 B의 A 타입에 대한 Response 확인
3. 물체 B의 Object Type 확인
4. 물체 A의 B 타입에 대한 Response 확인
  ↓
5. 두 Response 비교
  ↓
6. 더 약한 반응 선택
```

### 반응 강도 순서

```
약함 ←―――――――――――――――→ 강함
Ignore  <  Overlap  <  Block
```

**핵심 규칙**: 두 물체의 반응이 다르면 더 약한 쪽 선택

### 예시 1: Overlap 결과

```
물체 A
  ├─ Object Type: Pawn
  └─ Responses
      ├─ WorldStatic → Block
      └─ Pawn → Ignore

물체 B
  ├─ Object Type: WorldStatic
  └─ Responses
      ├─ WorldStatic → Block
      └─ Pawn → Overlap

물체 A와 B가 만나면
  ├─ A의 B에 대한 반응: Block (B는 WorldStatic)
  ├─ B의 A에 대한 반응: Overlap (A는 Pawn)
  └─ 결과: Overlap (더 약한 반응)
```

### 예시 2: Block 결과

```
물체 C
  ├─ Object Type: Pawn
  └─ Responses
      ├─ WorldStatic → Block
      └─ Pawn → Block

물체 D
  ├─ Object Type: WorldStatic
  └─ Responses
      ├─ WorldStatic → Block
      └─ Pawn → Block

물체 C와 D가 만나면
  ├─ C의 D에 대한 반응: Block (D는 WorldStatic)
  ├─ D의 C에 대한 반응: Block (C는 Pawn)
  └─ 결과: Block (둘 다 Block)
```

**중요**: Block을 얻으려면 **양쪽 모두** Block이어야 함

## 📞 Collision Callbacks (충돌 콜백)

**충돌 발생 시 실행되는 이벤트**

### Overlap 콜백

```
Overlap 발생 시 실행
  ├─ OnComponentBeginOverlap
  ├─ OnComponentEndOverlap
  ├─ OnActorBeginOverlap
  └─ OnActorEndOverlap

조건
  ├─ 충돌 반응이 Overlap이어야 함
  └─ 양쪽 모두 "Generate Overlap Events" 체크
```

**Generate Overlap Events**: Details 패널의 체크박스

### Hit 콜백

```
Block 발생 시 실행
  └─ OnComponentHit

조건 - 물리 충돌인 경우
  └─ "Simulation Generates Hit Events" 체크

조건 - 비물리 충돌인 경우
  └─ Sweep으로 이동했어야 함
```

**주의**: Sweep 없이 이동하면 Block이어도 Hit 콜백 없음

---

## 🚀 물체 이동 방식

**이동 방식에 따라 충돌 결과가 달라짐**

### 1. 위치 직접 설정

```
함수 예시
  ├─ SetActorLocation
  └─ AddActorWorldOffset

Sweep 옵션
  ├─ Sweep = True
  │   └─ 경로에 Block 물체 있으면 멈춤
  │
  └─ Sweep = False
      └─ Block 물체 무시하고 통과
```

**Sweep**: 이동 경로를 검사하여 막히는 물체 확인

### 2. 물리 시스템

```
물리 시뮬레이션 사용
  ├─ AddForce (힘 추가)
  ├─ AddImpulse (충격 추가)
  └─ 물리 엔진이 자동으로 충돌 처리
```

### 3. Movement Component

### Projectile Movement Component

```
발사체 이동용
  ├─ 물리 ON → 힘 적용 후 물리에 맡김
  └─ 물리 OFF → Sweep으로 위치 업데이트
```

### Character Movement Component

```
캐릭터 이동용
  ├─ 쿼리 시스템 사용 (Sweep)
  └─ 물리 물체에 힘 전달 가능
  └─ 계산량 많음 (쿼리 + 물리)
```

---

## ⚠️ 주의사항

### Sweep의 중요성

```
Sweep 없이 이동하면
  ├─ Block 설정이어도 통과 가능
  ├─ Hit 콜백 발생 안 함
  └─ 물체가 겹쳐질 수 있음
```

### 성능 고려사항

```
계산량 비교 (가벼움 → 무거움)
  ├─ No Collision
  ├─ Query Only / Physics Only
  ├─ Collision Enabled (Query + Physics)
  └─ 복잡한 Collision Geometry
```

**권장**: 필요한 것만 활성화

### 채널 관리

```
Collision Channel
  ├─ 제한된 개수만 생성 가능
  ├─ 새 채널 추가 시 모든 물체가 반응 설정해야 함
  └─ 최소한으로 사용 권장

Collision Preset
  ├─ 무제한 생성 가능
  └─ 많이 사용 권장
```

## 📝 핵심 정리

### 충돌 시스템의 기본

```
충돌 = 프리미티브 컴포넌트 간 상호작용
  ├─ 충돌 지오메트리 (모양)
  └─ 충돌 세팅 (설정)
```

### 충돌 세팅 3요소

```
1. Collision Enabled
   └─ 이 물체의 용도는?

2. Object Type
   └─ 이 물체의 종류는?

3. Collision Responses
   └─ 각 종류에 어떻게 반응?
```

### 충돌 판정 규칙

```
두 물체가 만나면
  ↓
각자의 Object Type과 Responses 비교
  ↓
더 약한 반응 선택
  ↓
Ignore < Overlap < Block
```

### 이동 방식의 영향

```
Sweep 사용
  └─ 경로 검사 + 충돌 처리 + Hit 콜백

Sweep 미사용
  └─ 즉시 이동 + 충돌 무시

물리 시뮬레이션
  └─ 물리 엔진 자동 처리
```

## 💡 학습 팁

### 실습 방법

```
1. 충돌 예제 프로젝트 사용
   └─ 강의 자료 다운로드

2. 다양한 설정 테스트
   ├─ Collision Enabled 변경
   ├─ Object Type 변경
   └─ Responses 변경

3. 이동 방식 비교
   ├─ Sweep On/Off 비교
   ├─ 물리 시뮬레이션 테스트
   └─ Movement Component 사용
```

## 🔺 Complex Collision (복잡한 충돌)

### 정의

```
  ├─ 삼각형 개수만큼 계산 필요
```

### 위치

### 3가지 옵션

### 1. Use Complex Collision As Simple

```

  ↓

  ├─ Simple Collision이 없어도 작동
  ├─ Triangle Mesh 사용
  └─ 성능 나쁨 (권장 안 함)
```

**상황**:

- Simple Collision을 만들지 않은 경우
- Complex를 Simple처럼 사용

### 2. Use Simple Collision As Complex

```
단순한 충돌만 사용
  ↓

  ├─ Simple Collision만 사용
  ├─ Triangle Mesh 사용 안 함

```

```
  ├─ 물리 충돌
  └─ 쿼리 (Line Trace 등)
```

### 3. Use Simple And Complex

```
상황에 따라 선택 사용
  ↓
물리 = Simple Collision
쿼리 = Complex/Simple 선택 가능
```

**용도**:

- 물리는 빠르게 (Simple)
- 정확한 검사 필요 시 Complex 선택 가능

# { 🎯 쿼리와 Trace Complex 설정 }

## 📌 이 강의의 목표

Line Trace(라인 트레이스) 쿼리를 이해하고 Simple/Complex Collision을 선택적으로 사용하는 방법을 학습합니다.

- Query(쿼리)란 무엇인가
- Line Trace 사용 방법
- Trace Complex 옵션의 역할
- Project Settings의 Default Shape Complexity

## 🔍 Query (쿼리)란?

### 기본 개념

```
Query = "질문하기"
  ↓
"이 경로에 뭔가 있나요?"
"이 영역에 물체가 있나요?"
```

**쿼리**: 충돌이 있는지 검사하는 기능

### 쿼리의 종류

```
Query 종류
  ├─ Line Trace (선 추적)
  │   └─ 보이지 않는 선을 쏴서 충돌 확인
  │
  ├─ Shape Sweep (도형 밀기)
  │   └─ 보이지 않는 도형을 밀어서 충돌 확인
  │
  └─ Overlap Query (겹침 확인)
      └─ 특정 영역에 물체가 있는지 확인
```

## 📏 Line Trace (라인 트레이스)

### 정의

```
보이지 않는 광선을 우주로 쏘기
  ↓
무언가에 부딪히는지 확인
  ↓
Hit Result 반환
```

**Line Trace**: 가장 기본적인 쿼리 방식

### 사용 예시

```
게임에서 활용
  ├─ 총 쏘기 (총알이 맞는지 확인)
  ├─ 시선 체크 (플레이어가 보고 있는 물체)
  ├─ 거리 측정
  └─ 장애물 감지
```

## 🚀 Add Actor World Offset 노드

**Delta Location**: 이동할 거리 (벡터)

### 파라미터 설명

### DeltaLocation 계산

```
Get Actor Forward Vector
  ↓
× (Get World Delta Seconds × Speed)
  ↓
= 이동할 벡터
```

**계산 과정**:

```
World Delta Seconds (프레임 간 시간)
  ×
Speed (100)
  =
초당 이동 거리

이것을 Forward Vector에 곱함
  =
앞 방향으로 초당 100 유닛 이동
```

**World Delta Seconds**: 이전 프레임과 현재 프레임 사이의 시간 (초 단위)
**Speed**: 초당 이동 속도 (100 유닛/초)

```
bSweep 파라미터
  ├─ True → 경로 검사, 충돌 시 멈춤
  └─ False → 충돌 무시, 통과
```

## 🔧 쿼리 시스템 vs 물리 시스템

### Sweep은 쿼리 시스템 사용

```
Sweep = True
  ↓
Query System 사용
  ↓
물리 시스템 필요 없음
```

### 테스트: Collision Enabled 변경

```
SM_Sphere30 → Collision Preset: Custom
  ↓
Collision Enabled
  └─ Query and Physics → Query Only
```

**Query Only**: 물리 시뮬레이션 불가, 쿼리만 가능

### 결과

```
Play 실행
  ↓
여전히 서로 막힘 ✅
  ↓
Sweep은 Query만 사용하므로 작동
```

## 💡 핵심 개념 정리

### Sweep의 역할

```
Sweep = Query System 사용
  ↓
이동 경로에 Block 물체 있는지 검사
  ↓
있으면 → 멈춤
없으면 → 계속 이동
```

### 물리 vs 쿼리

```
물리 시스템
  └─ Physics Collision
      └─ 힘, 중력, 물리 시뮬레이션

쿼리 시스템
  └─ Query
      ├─ Line Trace
      ├─ Sweep
      └─ Overlap
```

**Sweep은 쿼리 시스템의 일종**

## 📊 Sweep 비교표

| 설정         | Sweep = False  | Sweep = True      |
| ------------ | -------------- | ----------------- |
| 이동 방식    | 위치 직접 설정 | 경로 검사 후 이동 |
| 충돌 검사    | 안 함          | 쿼리로 검사       |
| Block 물체   | 통과           | 멈춤              |
| 시스템       | 없음           | Query System      |
| Hit Callback | 발생 안 함     | 발생 가능         |

## ⚙️ Collision Enabled 비교

| 설정              | 물리 | 쿼리 | Sweep 작동 |
| ----------------- | ---- | ---- | ---------- |
| No Collision      | ❌   | ❌   | ❌         |
| Query Only        | ❌   | ✅   | ✅         |
| Physics Only      | ✅   | ❌   | ❌         |
| Query and Physics | ✅   | ✅   | ✅         |

**Sweep 작동 조건**: Query System 활성화 필요
