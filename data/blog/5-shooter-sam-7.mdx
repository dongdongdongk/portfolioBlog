# C++ 매크로 (Macro) - 완전 초보 버전

## 🎯 매크로란?

**컴파일 전에 텍스트를 자동으로 치환하는 기능**

```cpp
#define PI 3.14159f

// 코드에서:
float radius = PI * 2;

// 컴파일 전에 자동으로:
float radius = 3.14159f * 2;
```

**비유:**

```
워드의 자동 고침 기능과 비슷

"ㅋㅋ" 입력 → 자동으로 "ㅎㅎ"로 변경
"PI" 입력 → 자동으로 "3.14159f"로 변경
```

---

## 🔧 매크로가 작동하는 방식

### 전처리기 (Preprocessor)

**컴파일 과정:**

```
1. 코드 작성 (.cpp)
    ↓
2. 전처리기 실행 ← 매크로 처리!
    ↓
3. 컴파일러 실행
    ↓
4. 실행 파일 생성
```

**전처리기가 하는 일:**

```cpp
// 원본 코드:
#define PI 3.14159f
float x = PI;

// 전처리기가 변환:
// (매크로 정의 제거)
float x = 3.14159f;

// 컴파일러가 컴파일
```

## 🎨 매크로 vs 변수

### 변수 방식

```cpp
const float PI = 3.14159f;  // 메모리 할당됨

void Test()
{
    float x = PI;  // 메모리에서 읽기
}
```

### 매크로 방식

```cpp
#define PI 3.14159f  // 메모리 할당 안 됨!

void Test()
{
    float x = PI;  // 컴파일 전에 3.14159f로 치환
}
```

---

### 비교

| 항목            | 변수      | 매크로    |
| --------------- | --------- | --------- |
| **메모리**      | 사용 O    | 사용 X    |
| **디버깅**      | 쉬움      | 어려움    |
| **타입 안정성** | 있음      | 없음      |
| **성능**        | 약간 느림 | 약간 빠름 |
| **유연성**      | 낮음      | 높음      |

**언제 뭘 쓸까?**

```
변수 사용:
  - 일반적인 경우
  - 디버깅 중요할 때
  - 타입 안정성 필요할 때

매크로 사용:
  - 조건부 컴파일
  - 코드 생성 자동화
  - 성능이 매우 중요할 때
```

## ⚠️ 매크로 사용 시 주의사항

### 1. 괄호를 꼭 사용하세요!

```cpp
// ❌ 나쁜 예
#define SQUARE(x) x * x

int result = SQUARE(2 + 3);
// 전처리: 2 + 3 * 2 + 3 = 2 + 6 + 3 = 11 (틀림!)

// ✅ 좋은 예
#define SQUARE(x) ((x) * (x))

int result = SQUARE(2 + 3);
// 전처리: ((2 + 3) * (2 + 3)) = 5 * 5 = 25 (맞음!)
```

---

### 2. 세미콜론 주의

```cpp
// ❌ 나쁜 예
#define LOG(x) UE_LOG(LogTemp, Display, TEXT(x));
//                                               ^ 세미콜론!

if (condition)
    LOG("Test");  // if 끝
else
    DoSomething();  // 에러! (세미콜론 때문에 if/else 망가짐)

// ✅ 좋은 예
#define LOG(x) UE_LOG(LogTemp, Display, TEXT(x))

if (condition)
    LOG("Test");  // OK
else
    DoSomething();  // OK
```

---

### 3. 타입 체크 없음

```cpp
#define ADD(a, b) ((a) + (b))

int x = ADD(1, 2);        // OK
float y = ADD(1.5f, 2.5f);  // OK
FString z = ADD("A", "B");  // 컴파일 에러! (타입 체크 안 됨)
```

**해결:**

```cpp
// 템플릿 함수 사용
template<typename T>
T Add(T a, T b) { return a + b; }

// 타입 체크 됨!
```

## 🎯 Protected란?

**상속받은 자식 클래스에서만 접근 가능한 접근 제어자**

```cpp
class Shape
{
protected:
    int Sides;  // 자식 클래스에서 접근 가능!
};

class Rectangle : public Shape
{
public:
    void SetSides()
    {
        Sides = 4;  // ✅ OK! (자식이라서)
    }
};

void AGun::BeginPlay()
{
    Rectangle rect;
    rect.Sides = 4;  // ❌ 에러! (외부라서)
}
```

---

## 🔐 접근 제어자 완전 정리

### 3가지 접근 제어자

**Public (공개):**

```cpp
public:
    int Health;  // 누구나 접근 가능
```

**Private (비공개):**

```cpp
private:
    int Health;  // 클래스 내부에서만
```

**Protected (보호):**

```cpp
protected:
    int Health;  // 클래스 + 자식 클래스
```

---

### 접근 가능한 곳

| 접근 위치       | Public | Protected | Private |
| --------------- | ------ | --------- | ------- |
| **클래스 내부** | ✅     | ✅        | ✅      |
| **자식 클래스** | ✅     | ✅        | ❌      |
| **외부 코드**   | ✅     | ❌        | ❌      |

---

### 시각적 비교

```cpp
class Parent
{
public:
    int A;        // 🌍 누구나

protected:
    int B;        // 👨‍👩‍👧 가족만 (자식 포함)

private:
    int C;        // 🔒 나만
};

class Child : public Parent
{
    void Test()
    {
        A = 1;  // ✅ OK (Public)
        B = 2;  // ✅ OK (Protected)
        C = 3;  // ❌ 에러! (Private)
    }
};

void External()
{
    Parent p;
    p.A = 1;  // ✅ OK (Public)
    p.B = 2;  // ❌ 에러! (Protected)
    p.C = 3;  // ❌ 에러! (Private)
}
```

## 📝 Protected 상세 설명

### Private vs Protected

**Private (비공개):**

```cpp
class Parent
{
private:
    int Secret = 10;
};

class Child : public Parent
{
    void Test()
    {
        Secret = 20;  // ❌ 에러!
        // 자식도 못 봄!
    }
};
```

**Protected (보호):**

```cpp
class Parent
{
protected:
    int Secret = 10;
};

class Child : public Parent
{
    void Test()
    {
        Secret = 20;  // ✅ OK!
        // 자식은 볼 수 있음!
    }
};
```

---

### 왜 Protected가 필요한가요?

**시나리오:**

```cpp
// 캐릭터 기본 클래스
class ACharacter
{
private:
    float Health;  // ❌ 자식이 못 씀!

    // 자식 클래스에서 체력 수정하려면
    // Getter/Setter 필요 (불편!)
};

// 적 캐릭터
class AEnemy : public ACharacter
{
    void Die()
    {
        Health = 0;  // ❌ 에러!
        // Setter 사용해야 함 (번거로움)
    }
};
```

**Protected 사용:**

```cpp
class ACharacter
{
protected:
    float Health;  // ✅ 자식이 직접 접근!
};

class AEnemy : public ACharacter
{
    void Die()
    {
        Health = 0;  // ✅ OK! (직접 접근)
    }
};
```

## 🎓 언리얼의 Protected 사용

### Character 클래스 확인

**ShooterSamCharacter.h:**

```cpp
class AShooterSamCharacter : public ACharacter
{
protected:
    // ===== Protected 함수들 =====

    virtual void BeginPlay() override;

    virtual void SetupPlayerInputComponent(UInputComponent* PlayerInputComponent) override;

    void Move(const FInputActionValue& Value);
    void Look(const FInputActionValue& Value);
    void Shoot();

    // ===== Protected 변수들 =====

    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = Input)
    UInputAction* MoveAction;

    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = Input)
    UInputAction* LookAction;
};
```

---

### 왜 Protected를 사용했나요?

**1. BeginPlay가 Protected인 이유:**

```cpp
protected:
    virtual void BeginPlay() override;
```

**이유:**

```
BeginPlay는 엔진이 호출함
→ 외부에서 직접 호출하면 안 됨!
→ 하지만 자식 클래스는 오버라이드해야 함
→ Protected가 딱 맞음!
```

**만약 Public이면:**

```cpp
public:
    virtual void BeginPlay() override;

// 어디서든 호출 가능 (위험!)
MyCharacter->BeginPlay();  // ❌ 하면 안 되는데 됨!
```

**만약 Private이면:**

```cpp
private:
    virtual void BeginPlay() override;

// 자식에서 오버라이드 못 함!
class MyCharacter : public ACharacter
{
    void BeginPlay() override;  // ❌ 에러!
};
```

---

**2. Input Action이 Protected인 이유:**

```cpp
protected:
    UPROPERTY(EditAnywhere, BlueprintReadOnly)
    UInputAction* MoveAction;
```

**이유:**

```
블루프린트에서 설정 가능 (EditAnywhere)
→ 하지만 외부 코드에서 함부로 바꾸면 안 됨
→ 자식 클래스는 사용할 수 있어야 함
→ Protected + BlueprintReadOnly
```

## 📚 핵심 정리

### Protected 키워드

**정의:**

```
자식 클래스에서만 접근 가능한 접근 제어자
```

**접근 가능:**

```
✅ 클래스 내부
✅ 자식 클래스
❌ 외부 코드
```

**사용 시기:**

```
- 자식이 수정해야 하는 변수
- 자식이 오버라이드할 함수
- 상속 계층 내부 공유 로직
```

**Private와 차이:**

```
Private: 나만
Protected: 나 + 자식들
```

**언리얼에서:**

```
BeginPlay, SetupPlayerInputComponent 등
대부분의 오버라이드 함수가 Protected
```

## 🎓 요약

**3가지 접근 제어자:**

```cpp
public:     // 🌍 모두
protected:  // 👨‍👩‍👧 가족 (자식 포함)
private:    // 🔒 나만
```

**Protected = Private + 자식 접근**

```
외부 차단 (Private와 같음)
자식 허용 (Private와 다름)
```

**실전 팁:**

```
- 기본은 Private
- 상속 고려하면 Protected
- 외부 API는 Public
```

---

Protected는 상속을 사용할 때 매우 중요한 개념입니다!

클래스 설계 시 "자식 클래스가 이걸 써야 하나?"를 생각하면 Protected를 써야 할지 알 수 있어요! 👍

# { 가상 함수 (Virtual Functions) }

## 🎯 가상 함수란?

**자식 클래스에서 재정의(Override)할 수 있는 함수**

```cpp
class Parent
{
public:
    virtual void Describe()  // virtual = 재정의 가능!
    {
        UE_LOG(LogTemp, Display, TEXT("I am a Shape"));
    }
};

class Child : public Parent
{
public:
    virtual void Describe() override  // 재정의!
    {
        UE_LOG(LogTemp, Display, TEXT("I am a Rectangle"));
    }
};
```

---

## 🤔 왜 필요한가요?

### 문제 상황

**가상 함수 없을 때:**

```cpp
class Shape
{
public:
    void Describe()  // virtual 없음!
    {
        UE_LOG(LogTemp, Display, TEXT("I am a Shape"));
    }
};

class Rectangle : public Shape
{
public:
    void Describe()  // 재정의 시도
    {
        UE_LOG(LogTemp, Display, TEXT("I am a Rectangle"));
    }
};

void Test()
{
    Rectangle rect;

    // 직접 호출
    rect.Describe();  // "I am a Rectangle" ✅

    // 포인터로 호출
    Shape* ptr = &rect;
    ptr->Describe();  // "I am a Shape" ❌ 잘못됨!
    // Rectangle이지만 Shape 함수 호출!
}
```

**출력:**

```
I am a Rectangle  (직접 호출)
I am a Shape      (포인터 호출 - 잘못됨!)
```

---

### 해결: virtual 사용

**가상 함수 사용:**

```cpp
class Shape
{
public:
    virtual void Describe()  // virtual 추가!
    {
        UE_LOG(LogTemp, Display, TEXT("I am a Shape"));
    }
};

class Rectangle : public Shape
{
public:
    virtual void Describe() override
    {
        UE_LOG(LogTemp, Display, TEXT("I am a Rectangle"));
    }
};

void Test()
{
    Rectangle rect;

    // 포인터로 호출
    Shape* ptr = &rect;
    ptr->Describe();  // "I am a Rectangle" ✅ 올바름!
    // Rectangle 함수 제대로 호출!
}
```

**출력:**

```
I am a Rectangle  (올바르게 자식 함수 호출!)
```

## 📝 가상 함수의 2가지 핵심

### 1. 함수 재정의 (Override)

**자식에서 부모 함수를 덮어쓸 수 있음**

```cpp
class Parent
{
public:
    virtual void BeginPlay()
    {
        // 부모 구현
    }
};

class Child : public Parent
{
public:
    virtual void BeginPlay() override
    {
        // 자식 구현 (부모 덮어씀!)
    }
};
```

---

### 2. 동적 디스패치 (Dynamic Dispatch)

**부모 포인터로 자식 함수 호출 가능**

```cpp
Child child;
Parent* ptr = &child;  // 부모 포인터

ptr->BeginPlay();  // 자식의 BeginPlay 호출!
// virtual이 없으면: 부모의 BeginPlay 호출
// virtual이 있으면: 자식의 BeginPlay 호출 ✅
```

## 🔍 virtual이 필요한 이유 상세

### C++의 성능 최적화

**virtual 없으면:**

```cpp
// 컴파일 시점에 결정 (빠름)
Shape* ptr = &rect;
ptr->Describe();
// "포인터 타입이 Shape니까 Shape::Describe 호출!"
```

**virtual 있으면:**

```cpp
// 실행 시점에 결정 (약간 느림, 하지만 정확함)
Shape* ptr = &rect;
ptr->Describe();
// "실제 객체가 Rectangle이네? Rectangle::Describe 호출!"
```

---

### 비유로 이해하기

**virtual 없음 = 겉모습만 보고 판단**

```
외투 입은 사람 발견
→ "외투 입었으니 추울 거야"
→ 실제로는 안에 반팔 입음 (확인 안 함)
```

**virtual 있음 = 실제를 확인하고 판단**

```
외투 입은 사람 발견
→ 외투 벗겨보기
→ "안에 반팔이네! 안 추워하겠군"
→ 정확한 판단!
```

## ⚙️ override 키워드

### override란?

**"이 함수는 부모 함수를 재정의합니다"라고 명시**

```cpp

void Describe() override

void Descirbe()  // 오타

{
public:
    virtual void Func() override;
    // 증손자도 재정의 가능
};
```

**언리얼에서:**

```cpp
AActor
  └─ BeginPlay (virtual)
      └─ AGun
          └─ BeginPlay (virtual + override)
              └─ AMyGun
                  └─ BeginPlay (override)
```

| **성능**        | 빠름         | 약간 느림    |

## 🎯 핵심 정리

### 가상 함수

**정의:**

```cpp
virtual void FunctionName();
```

**의미:**

```
자식이 재정의할 수 있음
포인터로 호출 시 자식 함수 실행
```

---

### override

**정의:**

```cpp
void FunctionName() override;
```

**의미:**

```
부모 함수 재정의 중
컴파일러가 확인해줌
```

---

### 언제 사용?

**virtual 사용:**

```
- 자식이 재정의할 함수
- 다형성 필요할 때
- BeginPlay, Tick 등
```

**override 사용:**

```
- 부모 함수 재정의할 때
- 오타 방지
- 가독성 향상
```

---

### 실전 팁

```cpp
// ✅ 좋은 패턴
class Parent
{
public:
    virtual void Func();  // 부모: virtual
};

class Child : public Parent
{
public:
    virtual void Func() override;  // 자식: 둘 다
};

// ❌ 나쁜 패턴
class Parent
{
public:
    void Func();  // virtual 없음!
};

class Child : public Parent
{
public:
    void Func();  // 재정의 안 됨!
};
```

## 🚀 요약

**가상 함수 = 재정의 가능 + 동적 호출**

```
virtual: 재정의 가능하게 만듦
override: 재정의 중임을 명시
```

**핵심 개념:**

```
1. 부모: virtual
2. 자식: override
3. 포인터로 호출 → 자식 함수 실행!
```

**언리얼에서:**

```
BeginPlay, Tick, SetupPlayerInputComponent
모두 가상 함수!
```

**실전 사용:**

```
- 무기 시스템
- AI 시스템
- 데미지 처리
- 모든 다형성 필요 상황
```

가상 함수는 객체지향 프로그래밍의 핵심 개념입니다!
