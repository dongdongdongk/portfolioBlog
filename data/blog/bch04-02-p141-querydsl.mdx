```java
기록을 하는것이 일반적이다

JPA 를 쓸때는 2가지 방식으로 기록이 가능하다

1. 하이버 네이트 고유의 어노테이션을 사용하는 방법

2. JPA 에서 지원하는 어노테이션을 활용하는 방법

* 최근에는 JPA 를 활용해서 많이 사용한다

이를 상속으로 빼 놓으면 편하게 처리가 가능해서 BaseEntity 를 설계해서 사용할것이다
```

# 자동으로 처리되는 날짜/시간 설정

```java
데이터 베이스 테이블을 만들면 등록된 시간, 최종 수정된 시간 등을 컬럼으로 만들어서 기록을 하기위한 설정을 추가한다

BaseEntity 패키지와 추상클래스를 만든다
```

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381204/notion-blog/_/_/_/_/BCh04_02_p141_Querydsl_/Untitled.png)

```java
@MappedSuperclass
@EntityListeners(value = { AuditingEntityListener.class})
@Getter
abstract class BaseEntity {
    @CreatedDate // 엔티티의 생성 시간을 자동으로 관리하고 엔티티가 언제 생성되었는지 추적하기 위한 기능
    @Column(name = "regdate", updatable = false)   // updatable = false로 설정되어 엔티티를 업데이트할 때 수정되지 않도록한다
    private LocalDateTime regDate;
    @LastModifiedDate  // 엔티티의 수정 시간을 자동으로 관리하고 엔티티가 언제 수정되었는지 추적하기 위한 기능을 제공
    @Column(name = "moddate")
    private LocalDateTime modDate;
}
```

## **@MappedSuperclass**

```java
이 어노테이션을 사용하면 공통 부분을 한 번에 정의하고, 나머지 엔티티 클래스에서 재사용할 수 있다

( 예를 들어, 여러 엔티티 클래스가 공통적으로 생성일자(createdDate)와 수정일자(modifiedDate)를 가지고 있다 )

* @Entity 클래스는 엔티티나 @MappedSuperclass로 지정한 클래스만 상속 가능

* 추상 클래스로 선언할 것을 권장 (abstract)
```

## @CreatedDate

```java
데이터베이스 레코드가 생성될 때 해당 필드의 값을 현재 시간으로 설정 이는 데이터의 생성 시간을 추적하거나 데이터베이스 레코드의 생성 시간을 감사하는 데 유용하다.
```

## **@EntityListeners(value = { AuditingEntityListener.class})**

```html
엔티티의 특정 작업을 자동화하고 코드를 간단하게 유지하기 위해사용 예를 들어, 데이터를 저장할 때
자동으로 날짜를 업데이트하거나 로그를 남기는 작업을 자동화할 때 사용 * **Spring Data JPA에서
제공하는 이벤트 리스너로 엔티티의 영속, 수정 이벤트를 감지하는 역할**
```

## @LastModifiedDate

```java
엔티티의 수정 시간을 자동으로 관리하고 엔티티가 언제 수정되었는지 추적하기 위한 기능을 제공
```

```java

위의 **@EntityListeners(value = { AuditingEntityListener.class})** 를 사용하기 위해서는 이 어노테이션을 붙여줘야한다  ****
```

# MyBatis 를 이용했을 경우와 JPA 를 이용하는 경우의 차이

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381201/notion-blog/_/_/_/_/BCh04_02_p141_Querydsl_/Untitled_2.png)

## MyBatis 를 이용했을 경우

```java
실제로 어떤 객체를 파라미터로 전달했을 떄 그 객체의 내용물을 뽑아서 sql 로 만든다 (sql에서 jdbc 로 사용) 그리고 그 객체의 용도는 거기서 끝난다

반대로 말하면 조회를 하게되면 그냥 sql 문이 조회가 되는거고 그 sql문이 가져온 데이터를 객체화 해서 전달하는 것이다
```

## JPA 를 이용하는 경우

```java
MyBatis 같은 경우에는 1,3번 객체들이 (전달되는) 같지가 않다 (3번은 db에서 나온 결과기 때문에)

JPA 는 첫 객체를 Persistence Context 에 넣어주면 거기서 보관을 한다

한마디로 Persistence Context 랑 통신을 하지 DB랑 통신을 하는것이 아니란 것이다
```

## 요약

```java
요약하면, MyBatis는 SQL 중심의 방식으로 SQL을 직접 작성하고 실행하며,

객체는 쿼리 파라미터 및 결과로 사용된다.

반면에 JPA는 객체 지향 방식으로 객체를 데이터베이스에 영속화 *( 객체를 지속적으로 보존하거나 저장하는 것을 의미) 하고

JPQL *( JPQL은 엔티티 객체를 검색하고 필터링하기 위한 언어로, 데이터베이스와 상호 작용할 때 SQL을 사용하는 대신 엔티티 객체를 대상으로 쿼리를 작성)

을 사용하여 데이터베이스와 상호 작용한다.

MyBatis는 SQL을 더 직접적으로 다루며, JPA는 객체와 데이터베이스 사이의 중간 계층을 제공하여 객체 지향 프로그래밍을 강화한다.
```

# 쿼리 DSL(QueryDSL)의 'q 도메인’

```java
엔터티 클래스(Entity Class)에 대한 쿼리를 생성하고 사용하기 쉽게 도와주는 도메인 모델

이 도메인 모델은 QueryDSL을 사용하여 데이터베이스에서 정보를 검색하거나 필터링할 때 도움이 된다
```

```java
보통 엔터티 클래스의 이름 뒤에 "Q"를 붙이고 해당 엔터티의 필드 및 속성에 대한 정보를 포함한다

이 정보는 QueryDSL을 사용하여 동적 쿼리를 작성하고 실행할 때 사용된다.

"q 도메인"을 사용하면 정적인 문자열 쿼리 대신 Java 코드를 사용하여 쿼리를 구성할 수 있다

예를 들어, "Person" 엔터티 클래스에 대한 "q 도메인"을 사용하면 "Person" 엔터티에 대한 쿼리를 다음과 같이 작성할 수 있다:
```

```java
QPerson person = QPerson.person;

List<Person> persons = new JPAQueryFactory(entityManager)
    .select(person)
    .from(person)
    .where(person.age.gt(30))
    .fetch();
```
