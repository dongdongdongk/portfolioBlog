```jsx
프로토콜(protocol)은 컴퓨터나 다른 전자 장치들이 서로 통신할 때 사용하는 규칙과 절차의 집합이다.

프로토콜은 데이터를 어떻게 형식화하고 전송하며,

에러를 어떻게 처리할지 등을 정의한다.

마치 사람들이 서로 대화할 때 지키는 언어와 문법 규칙처럼, 프로토콜은 네트워크 장치 간의 통신을 원활하게 하기 위한 표준이다.

프로토콜은 데이터 전송의 형식, 순서, 오류 처리 방법 등을 정의하며, 네트워크 통신의 기초를 이룬다
```

# 프로토콜의 주요 구성 요소

```jsx
1. 구문 (Syntax):

데이터가 전송될 때 그 데이터의 구조를 정의한다.

데이터 패킷의 형식, 비트나 바이트의 순서, 헤더와 트레일러의 정보 등을 포함한다.

2. 의미 (Semantics):

어떤 데이터가 전송되는지, 그 데이터가 의미하는 바를 정의한다.

오류 제어 정보, 신호의 의미, 상태 정보 등을 포함한다.

3. 타이밍 (Timing):

데이터가 전송되는 시점을 정의한다.

데이터의 전송 속도, 동기화, 순서 제어 등을 포함한다.
```

# 프로토콜의 역할

```jsx
데이터 캡슐화: 데이터를 전송할 수 있도록 작은 패킷으로 나누고, 각 패킷에 필요한 제어 정보를 추가한다.

주소 지정: 데이터가 목적지에 도달할 수 있도록 출발지와 목적지 주소를 패킷에 포함한다.

연결 관리: 데이터 전송 전에 연결을 설정하고, 전송이 끝난 후 연결을 종료한다.

흐름 제어: 송신자와 수신자 간의 데이터 전송 속도를 조절하여 데이터 손실을 방지한다.

오류 제어: 데이터 전송 중 발생할 수 있는 오류를 검출하고, 오류를 수정하거나 재전송을 요청한다.

순서 제어: 전송된 데이터가 올바른 순서로 도착하도록 관리한다.
```

# 네트워크 프로토콜의 계층

```jsx
네트워크 프로토콜은 여러 계층으로 나누어져 있으며, 각 계층은 특정 기능을 담당한다. 대표적인 계층 모델로 OSI 7 계층 모델과 TCP/IP 모델이 있다.

* 계층은 복잡한 네트워크 통신 시스템을 여러 단계로 나누어 설명하는 방법이다.

	각 계층은 특정한 역할을 담당하며, 계층 간에는 정의된 인터페이스를 통해 데이터를 주고 받는다
```

## OSI 7 계층 모델

```jsx
1. 물리 계층 (Physical Layer):

	전기적, 기계적, 기능적 규격을 정의합니다.

	케이블, 핀, 전기 신호, 전압 등을 포함합니다.

2. 데이터 링크 계층 (Data Link Layer):

	물리적 네트워크에서 데이터 전송을 담당합니다.

	프레임, MAC 주소, 오류 제어, 흐름 제어 등을 포함합니다.

3. 네트워크 계층 (Network Layer):

	데이터가 여러 네트워크를 통해 전달되는 경로를 결정합니다.

	IP 주소, 라우팅, 패킷 포워딩 등을 포함합니다.

4. 전송 계층 (Transport Layer):

	종단 간 데이터 전송을 담당합니다.

	TCP/UDP, 오류 복구, 데이터 재전송, 흐름 제어 등을 포함합니다.

5. 세션 계층 (Session Layer):

	응용 프로그램 간의 세션을 관리합니다.

	세션 설정, 유지, 종료, 동기화 등을 포함합니다.

6. 표현 계층 (Presentation Layer):

	데이터의 형식과 표현을 변환합니다.

	데이터 암호화, 압축, 변환 등을 포함합니다.

7. 응용 계층 (Application Layer):

	최종 사용자가 네트워크 서비스를 사용할 수 있게 합니다.

	HTTP, FTP, SMTP, DNS 등 다양한 응용 프로그램 프로토콜을 포함합니다.
```

## TCP/IP 모델

```jsx
1. 네트워크 인터페이스 계층 (Network Interface Layer):

	OSI의 물리 계층과 데이터 링크 계층에 해당합니다.

	데이터의 물리적 전송을 담당합니다.

2. 인터넷 계층 (Internet Layer):

	OSI의 네트워크 계층에 해당합니다.

	IP 주소 할당, 라우팅 등을 담당합니다.

3. 전송 계층 (Transport Layer):

	OSI의 전송 계층에 해당합니다.

	TCP/UDP 프로토콜을 통해 데이터 전송을 관리합니다.

4. 응용 계층 (Application Layer):

	OSI의 응용, 표현, 세션 계층을 포함합니다.

	다양한 네트워크 서비스를 제공합니다.
```

# 주요 프로토콜 설명

```jsx
1. HTTP (HyperText Transfer Protocol):

웹 브라우저와 웹 서버 간의 통신을 위한 프로토콜입니다.

주로 웹 페이지 요청과 전송에 사용됩니다.

2. FTP (File Transfer Protocol):

파일을 전송하기 위한 프로토콜입니다.
파일 업로드와 다운로드에 사용됩니다.

3. SMTP (Simple Mail Transfer Protocol):

이메일 전송을 위한 프로토콜입니다.

이메일 클라이언트와 서버 간의 메일 전송에 사용됩니다.

4. TCP (Transmission Control Protocol):

신뢰성 있는 데이터 전송을 위한 프로토콜입니다.

데이터 패킷의 순서 보장, 오류 복구 등을 포함합니다.

5. UDP (User Datagram Protocol):

비신뢰성 있는 데이터 전송을 위한 프로토콜입니다.

빠른 전송이 필요하지만 오류 복구가 필요 없는 경우에 사용됩니다.

6. IP (Internet Protocol):

데이터를 패킷 단위로 분할하고, 각 패킷에 주소를 붙여 전달합니다.

패킷의 라우팅을 담당합니다.
```

# 예제 상황: 웹 브라우저로 웹 페이지 요청

```jsx
네트워크 통신에서 프로토콜이 어떻게 작동하는지 설명하기 위해 웹 페이지를 요청하고 받는 간단한 예제를 들어보겠다.

이 과정에서 주요 프로토콜과 계층의 역할을 단계별로 설명
```

```jsx
1. 사용자가 웹 브라우저에 URL 입력:

	사용자가 웹 브라우저에 "http://www.example.com"을 입력


2. DNS 요청 (응용 계층):

	웹 브라우저는 URL에 해당하는 IP 주소를 찾기 위해 DNS (Domain Name System) 서버에 요청을 보냅니다.

	DNS 서버는 URL에 해당하는 IP 주소를 응답합니다.

	* DNS : 인터넷에서 사용되는 도메인 이름과 IP 주소를 서로 매핑해주는 시스템이다.

		쉽게 말해, 사람이 이해하기 쉬운 도메인 이름(예: www.example.com)을 컴퓨터가 이해할 수 있는 IP 주소(예: 192.0.2.1)로 변환해주는 역할을 한다.


3. TCP 연결 설정 (전송 계층):

	웹 브라우저는 IP 주소를 이용해 웹 서버와 TCP 연결을 설정합니다.

	이 과정은 3-way handshake로 불립니다.

		1. 클라이언트가 서버에 SYN 패킷을 보냅니다. 클라이언트가 서버에게 "연결하고 싶어"

		2. 서버가 클라이언트에 SYN-ACK 패킷을 응답합니다. 서버가 "연결을 받아들일게"라고 응답

		3. 클라이언트가 서버에 ACK 패킷을 보내 연결이 확립됩니다. 클라이언트가 "좋아, 이제 연결됐어"라고 확인


4. HTTP 요청 전송 (응용 계층):

	TCP 연결이 설정되면, 웹 브라우저는 HTTP GET 요청을 통해 웹 페이지를 요청합니다.

	예를 들어, "GET /index.html HTTP/1.1\r\nHost: www.example.com\r\n\r\n"



5. 데이터 캡슐화 및 전송 (네트워크 계층 및 데이터 링크 계층):

	HTTP 요청이 전송되기 전에, 데이터는 여러 계층을 거쳐 캡슐화됩니다.

		응용 계층: HTTP 요청을 생성합니다.

		전송 계층: TCP 세그먼트로 캡슐화합니다. (포트 번호 포함)

		네트워크 계층: IP 패킷으로 캡슐화합니다. (IP 주소 포함)

		데이터 링크 계층: 프레임으로 캡슐화합니다. (MAC 주소 포함)

	캡슐화된 데이터가 물리 계층을 통해 전송됩니다.

6. 웹 서버에서 데이터 수신 및 응답 (전송 계층 및 응용 계층):

	웹 서버는 요청을 수신하고, 캡슐화를 역순으로 해제합니다.

		물리 계층: 신호를 수신합니다.

		데이터 링크 계층: 프레임을 해제합니다.

		네트워크 계층: IP 패킷을 해제합니다.

		전송 계층: TCP 세그먼트를 해제합니다.

		응용 계층: HTTP 요청을 처리합니다.

	웹 서버는 요청된 웹 페이지를 준비하고, HTTP 응답을 생성합니다.

		예: "HTTP/1.1 200 OK\r\nContent-Type: text/html\r\n\r\n<html>...</html>"


7. 웹 페이지 데이터 전송 (네트워크 계층 및 데이터 링크 계층):

	HTTP 응답이 클라이언트로 전송되기 전에, 데이터는 다시 캡슐화됩니다.

	클라이언트로 전송됩니다.


8. 웹 브라우저에서 데이터 수신 및 표시:

	클라이언트는 데이터를 수신하고, 캡슐화를 역순으로 해제합니다.

	응용 계층: HTTP 응답을 처리하고, 웹 페이지를 렌더링하여 사용자에게 표시합니다.
```
