## 1. 새 프로젝트 생성하기

- **New Project → Universal 3D Core** 템플릿 사용
- 이름: `Rocket Boost` (원하는 이름으로 지정 가능)
- **Unity Cloud 연결 해제** 후 `Create Project` 선택
- 불필요한 `ReadMe` 에셋 삭제

> 🔑 개념:
>
> Unity는 프로젝트 단위로 리소스와 설정을 관리.
>
> 새 프로젝트 생성 시 템플릿을 잘 선택해야 필요한 기능과 패키지가 기본 포함됨.

---

## 2. 에셋 가져오기와 폴더 구조

- `.unitypackage` 파일을 드래그하여 **Assets 폴더**에 추가
- Import 창에서 원하는 항목 선택 (보통 전체 Import)
- 결과: `GameDevTV Assets` 폴더 생성

> 🔑 개념:

- Unity 패키지는 **모델, 텍스처, 프리팹, 스크립트** 등을 포함하는 압축된 리소스 묶음.
- Import 후 **폴더 구조 정리**가 중요 → 추후 프로젝트 관리 용이.

---

## 3. 재질(Material) 누락 문제 해결

- 오브젝트가 **핑크색** → 재질(Material) 참조가 끊겼다는 의미
- 해결: 오브젝트 선택 → Inspector에서 **다른 Sci_Fi 팔레트** 지정 → `Apply`

> 🔑 개념:
>
> 핑크색은 **Shader/Material Missing** 상태.
>
> Unity는 해당 머티리얼을 찾을 수 없을 때 기본 경고 색상으로 표시.

---

## 4. 좌표계와 방향 이해하기

- **빨간 화살표(X): 오른쪽**
- **초록 화살표(Y): 위쪽**
- **파란 화살표(Z): 화면 안쪽(Depth)**
- 중요한 점: **프로젝트마다 앞·뒤·위·아래 기준을 일관되게 정해야 혼동이 없음**

---

## 5. 유니티 크기 단위 이해하기

- Unity 기본 단위 = **1 Unit (유닛)**
- **1 Unit ≈ 1미터**로 간주하는 경우가 많음 (권장)
- Rocket 모델 높이: 약 **2 Units**
- 사람 캐릭터 평균: 약 **1.8 Units (≈180cm)**
- 확인 방법:
  - `Cube` 생성 (기본 크기 1,1,1) → 실제 오브젝트 옆에 두어 비교
  - **Scale** 값은 비율, 실제 크기는 모델링된 Mesh에 의해 결정됨

> 🔑 개념:

- **Scale** = 오브젝트 크기 배율 (기본값 1,1,1 = 원본 크기 유지)
- **Size(실제 크기)** = 모델링 단계에서 정해진 Mesh의 실제 치수
- 따라서 "Scale 1"이라도 모델에 따라 실제 크기는 다를 수 있음.
- 게임 내 **플레이어 크기(1.8m 기준)**에 맞춰 비교하면서 배치해야 현실감 확보 가능.

## 6. Ground(땅) 만들기

- `3D Object → Cube` 생성 → 이름 `Ground` 변경
- **Scale Y = 10** 으로 두께 부여
- 오브젝트 Pivot(중심)이 가운데이므로, Y 위치를 `5`로 설정
- → 결과적으로 Ground의 윗면이 **세계 좌표 (0,0,0)**에 맞춰짐

> 🔑 개념:
>
> Unity 오브젝트의 **Pivot**은 기본적으로 중심.
>
> 즉, 높이 10인 Cube라면 Pivot은 중간 (5 지점).
>
> 따라서 위쪽 면을 정확히 0에 맞추려면 Y = -5로 이동해야 함.

## 7. 발사대와 착륙대 배치하기

- 에셋 중 작은 구조물 선택 후 이름 `Launch Pad`로 변경
- 복제(Ctrl+D) → `Landing Pad`로 이름 변경
- 플레이어(우주선)를 Launch Pad 위에 배치 → 착륙대까지 비행하는 구조

> 🔑 개념:
>
> 게임 오브젝트의 이름을 명확히 바꾸고, 복제 후 배치하여 **게임 플레이의 레이아웃**을 설계.

## 8. 씬(Scene) 저장 및 정리하기

- 현재 Scene 이름: `SampleScene` → 새로 `Sandbox`로 저장
- `Scenes` 폴더 내 `SampleScene` 삭제 → Sandbox만 유지

> 🔑 개념:

- Unity Scene = 게임의 **하나의 레벨 또는 상태**
- `File → Save As`로 다른 이름 저장 가능
- 프로젝트 구조를 정리할 때, 필요 없는 Scene은 삭제하여 관리 효율 ↑

## 1. 스크립트 생성과 기본 구조

- **Scripts 폴더**를 생성 → 새 C# 스크립트 만들기.
- 예: `Movement.cs` → 자동으로 `Movement`라는 클래스 생성.
- Unity에서 기본적으로 만들어지는 구조:

  ```csharp
  using UnityEngine;

  public class Movement : MonoBehaviour
  {
      // 변수와 메서드 작성
  }
  ```

---

## 2. 네임스페이스(Namespace) 개념

- **네임스페이스 = 클래스의 컨테이너**
- 코드의 범위를 구분하고 정리하는 역할.
- 예: `UnityEngine`, `UnityEngine.SceneManagement`
- 네임스페이스를 불러와야 해당 안의 클래스, 메서드 사용 가능.

---

## 3. 클래스(Class) 개념

- **클래스 = 변수와 메서드의 컨테이너**
- 코드의 기능 단위를 묶어서 관리.
- 예: `Movement` 클래스 안에 플레이어 이동 관련 메서드 정의.

---

## 4. 러시아 인형 비유로 이해하기

- 큰 인형 속에 작은 인형이 들어 있는 구조.
- **네임스페이스 → 클래스 → 메서드** 순으로 계층화.
- 예시:
  - `UnityEngine` (네임스페이스)
    - `Debug` (클래스)
      - `Log()` (메서드)

---

## 5. 캡슐화(Encapsulation)의 의미

- **코드를 보호하는 캡슐을 씌우는 것.**
- 코드가 불필요하게 외부에서 수정되지 않도록 함.
- 장점:
  - 예기치 못한 버그 방지
  - 코드의 책임을 명확히 구분
- 예:
  - `Movement` 클래스만 플레이어 속도 변경 권한을 가짐.
  - `Pickups` 클래스는 직접 수정하지 않고 `Movement`에 요청.

---

## 6. 클래스의 단일 책임 원칙

- **하나의 클래스는 하나의 주요 역할만 담당해야 함.**
- 예시:
  - `Movement` = 이동 전담
  - `Pickups` = 아이템 효과 전담
  - `EnemyAI` = 적 인공지능 전담
- 장점:
  - 코드가 깔끔해지고, 버그 추적이 쉬워짐.
  - 협업할 때 역할 분담이 명확해짐.

---

## 7. 네임스페이스 사용법과 문서 활용

- 필요한 네임스페이스만 불러오기.
- 예:
  ```csharp
  using UnityEngine;
  using UnityEngine.InputSystem; // 입력 시스템 사용 시 필요
  ```
- 불필요한 네임스페이스를 다 불러오면:
  - 코드가 무거워짐
  - 불필요한 기능에 실수로 접근 가능 → 버그 발생 위험

---

## 8. 점 연산자(Dot Operator)와 클래스 접근

- 클래스 내부 기능에 접근할 때 사용.
- 구조: `클래스명.메서드명()`
- 예시:

  ```csharp
  Debug.Log("Hello Unity!");
  ```

  - `Debug` = 클래스
  - `Log` = 메서드

---

## 9. 스크립트 이름과 클래스 이름 관계

- Unity는 새 스크립트를 만들 때 **파일명과 클래스명을 동일하게 생성**.
- 예: `Movement.cs` → `public class Movement`.
- 일반적으로 **스크립트당 하나의 클래스만 작성**하는 것이 권장됨.
  - 이유: 클래스의 역할과 책임이 명확해지기 때문.

---

✅ **정리 요약**

- **네임스페이스**: 클래스의 집합 (큰 인형).
- **클래스**: 변수와 메서드의 집합 (중간 인형).
- **메서드/변수**: 실제 동작을 정의 (작은 인형).
- **캡슐화**: 코드 보호 및 역할 분리.
- **단일 책임 원칙**: 클래스는 한 가지 기능만 담당.
- **점 연산자**: 클래스 내부 기능 접근 방식.
- **파일명 = 클래스명**: Unity의 기본 규칙.

## 7. Update에서 입력 감지하기

```csharp
using UnityEngine;
using UnityEngine.InputSystem;

public class Movements : MonoBehaviour
{
    [SerializeField] InputAction thrust;

    void OnEnable()
    {
        thrust.Enable();
    }

    void Update()
    {
        if (thrust.IsPressed())
        {
            Debug.Log("공간이 필요합니다.");
        }
    }
}
```

## 5. Update vs FixedUpdate 실행 차이

- **Update()**
  - 매 프레임 실행
  - 게임 로직(키 입력 확인, UI 업데이트 등)에 적합
- **FixedUpdate()**
  - 물리 루프 주기에 맞춰 실행
  - Rigidbody, AddForce 같은 물리 관련 코드에 적합
  - 입력 확인은 Update에서, 물리 연산은 FixedUpdate에서 처리하는 패턴도 있음

## 6. AddForce vs AddRelativeForce

- **AddForce(Vector3 force)**
  - **월드 좌표계(World 기준)** 방향으로 힘을 가함.
  - 오브젝트의 **회전 상태와 무관**하게 `(x, y, z)` 방향 벡터가 그대로 적용됨.
  - 예: `(0, 0, 10)`을 적용하면, 오브젝트가 어디를 보든 **월드의 Z+ 방향**으로 밀림.
  - 주로 **중력, 바람, 외부 충격** 같은 **환경적 힘**을 표현할 때 적합.
- **AddRelativeForce(Vector3 force)**
  - **로컬 좌표계(Local 기준, 오브젝트 자신이 바라보는 방향)** 에 맞춰 힘을 가함.
  - 오브젝트가 회전하면, 힘의 방향도 **오브젝트의 방향에 따라 함께 변함**.
  - 예: `(0, 0, 10)`을 적용하면, 오브젝트의 **앞 방향(Forward)** 으로 힘이 가해짐.
  - 🚀 로켓, 자동차, 비행기 등 **자체 방향에 맞춰 움직이는 객체**에 적합.
  - 방향 제어(회전)과 힘(추진력)이 결합된 **자율적 이동체**에 자주 사용됨.

---

👉 간단히 정리하면,

- **AddForce** = "세상이 기준" (월드 좌표계)
- **AddRelativeForce** = "내가 기준" (오브젝트 로컬 좌표계)

---

## 7. Vector3 방향 벡터 이해하기

- `Vector3(0, 1, 0)` = Y축 위쪽 방향
- Unity는 자주 쓰는 방향을 단축 제공:
  - `Vector3.up` → (0, 1, 0)
  - `Vector3.forward` → (0, 0, 1)
  - `Vector3.right` → (1, 0, 0)

## 8. Thrust(추진력) 변수와 DeltaTime 적용

- 추진력 크기를 Inspector에서 조절 가능하도록 `SerializeField` 사용.
- **DeltaTime 곱하기 이유**: 프레임 독립적인 움직임 보장.
  - `Update()` → `Time.deltaTime`
  - `FixedUpdate()` → `Time.fixedDeltaTime`

```csharp
[SerializeField] float thrustStrength = 1000f;

void FixedUpdate()
{
    if (thrust.IsPressed())
    {
        rb.AddRelativeForce(Vector3.up * thrustStrength * Time.fixedDeltaTime);
    }
}
```

## 9. 최종 코드 구조

```csharp
using UnityEngine;
using UnityEngine.InputSystem;

public class Movements : MonoBehaviour
{
    [SerializeField] InputAction thrust;         // 스페이스바 입력
    [SerializeField] float thrustStrength = 1000f; // 추진력 세기
    Rigidbody rb;

    void Start()
    {
        rb = GetComponent<Rigidbody>(); // Rigidbody 캐싱
    }

    void OnEnable()
    {
        thrust.Enable(); // InputAction 활성화
    }

    void FixedUpdate()
    {
        // 스페이스바가 눌려 있으면 로켓에 위쪽 힘 가하기
        if (thrust.IsPressed())
        {
            rb.AddRelativeForce(Vector3.up * thrustStrength * Time.fixedDeltaTime);
        }
    }
}
```

## 1. Input System 복습

- Unity의 **새 Input System**은 다양한 입력 장치(키보드, 패드, 조이스틱)를 유연하게 처리할 수 있도록 설계됨.
- `InputAction`은 입력을 정의하는 핵심 단위:
  - 어떤 입력 장치/키를 사용할지 **바인딩(Binding)** 가능.
  - 입력 값을 읽을 수 있음 (`ReadValue<T>()`).
  - 버튼이 눌렸는지 확인할 수 있음 (`IsPressed()`).

## 2. 회전 입력 변수 생성하기

```csharp
[SerializeField] InputAction rotation;
```

- `thrust`와 동일하게 `rotation`이라는 **InputAction 변수** 생성.
- `SerializeField`로 선언 → 인스펙터에서 키보드/패드 입력을 직접 바인딩 가능.

## 3. OnEnable()에서 입력 활성화하기

```csharp
void OnEnable()
{
    thrust.Enable();
    rotation.Enable();
}
```

- `InputAction`은 반드시 `Enable()` 해야 작동함.
- `Enabled`(읽기 전용 상태 확인)과 달리 `Enable()`은 실제 활성화 명령.

## 4. 바인딩 옵션 이해하기

Unity의 Input System에서 입력을 바인딩할 때는 여러 옵션이 있음. 상황에 맞게 선택해야 함.

### 1) 단일 버튼 바인딩 (Button Binding)

- 특정 버튼을 눌렀을 때만 `1`(Pressed) 또는 `0`(Not pressed) 값을 반환.
- 예: 점프(Jump), 발사(Shoot).
- 키보드 Spacebar → `Pressed`면 1, 아니면 0.

### 2) Positive/Negative Binding (1D Axis)

- \*하나의 입력 축(1D Axis)\*\*으로 양수/음수 값을 동시에 처리.
- 왼쪽(-1) / 오른쪽(+1) 같이 **양쪽 방향 입력**을 다루기 좋음.
- 설정 시 자동으로 `1, 0, +1` 값 반환:
  - Negative(음수) 키만 누름 → -1
  - Positive(양수) 키만 누름 → +1
  - 둘 다 안 누름 → 0
  - 둘 다 동시에 누름 → 0 (기본 설정, 하지만 옵션에 따라 다를 수 있음)

➡️ 이번 회전 입력에서는 이 방식을 사용함.

### 3) Composite Binding

- 여러 입력을 조합해서 하나의 값으로 만듦.
- 예: **2D Vector Composite** → (WASD)나 (Arrow Keys)로 하나의 Vector2 값 생성.
  - W = (0,1), S = (0,-1), A = (-1,0), D = (1,0).
  - 이 네 입력을 합쳐서 `(x,y)` 좌표 반환.
- 캐릭터 이동이나 카메라 조작에 주로 사용.

## 1. 프리팹과 부모-자식 관계 이해하기

- **프리팹(Prefab)** : 게임 오브젝트를 재사용 가능한 "템플릿"으로 만드는 기능.
- 강의에서는 **Player Rocket 전체를 Prefabs 폴더에 드래그 → 프리팹화** 함.
- **부모-자식 관계의 특징**:
  - 부모는 **월드 좌표** 기준으로 위치/회전/스케일 유지.
  - 자식은 **부모에 상대적 좌표**를 가짐.
  - 즉, 부모를 이동/회전시키면 자식도 같이 변함.

---

## 2. 피벗(Pivot)과 중심(Center)의 차이

- **Pivot** : 실제 오브젝트가 회전/스케일을 기준으로 삼는 지점.
- **Center** : 오브젝트의 중앙 지점.
- 유니티 좌측 상단에서 **Pivot ↔ Center 버튼 전환 가능**.
- 로켓이 원치 않는 위치에서 회전하는 문제는 **Pivot 기준** 때문이었음.

---

## 3. Z축 회전 개념과 적용

- 유니티 좌표계:
  - **X축** → 좌우
  - **Y축** → 위아래
  - **Z축** → 화면 안/밖 방향
- 로켓을 화면에서 좌우로 회전하려면 → **Z축 회전** 사용.
- `transform.Rotate(Vector3.forward * 값)`
  - `(0, 0, 1)` = Z축 양의 방향.
  - 양수 → 한쪽 회전, 음수 → 반대 방향 회전.

---

## 4. if / else if 문으로 상호 배타적 로직 구현하기

- 문제: 왼쪽/오른쪽 입력을 동시에 누르면?
- **if 문만 사용**하면 둘 다 실행될 가능성 존재.
- 해결: **if / else if** 사용.
  ```csharp
  if (rotationInput < 0) { ... }
  else if (rotationInput > 0) { ... }
  ```
- 이렇게 하면 **동시에 실행되지 않음 (상호 배타적 로직)**.

---

## 5. 회전 속도 제어와 프레임 독립성

- 단순 회전 → 너무 느리거나 빠름.
- 해결 방법:
  - **조절 가능한 변수**: `rotationStrength`
  - **프레임 독립성**: `Time.fixedDeltaTime` 곱하기
- 최종:
  ```csharp
  transform.Rotate(Vector3.forward * rotationStrength * Time.fixedDeltaTime);
  ```
- `rotationStrength` 값을 조정해서 회전 속도 변경 가능.

---

## 6. 코드 중복 줄이기 – 메소드 추출

- 문제: **거의 동일한 코드가 왼쪽/오른쪽 회전에서 반복**됨.
- 해결: **메소드 추출 (Extract Method)**
- `ApplyRotation()` 메소드 생성:
  ```csharp
  private void ApplyRotation(float rotationThisFrame) {
      transform.Rotate(Vector3.forward * rotationThisFrame * Time.fixedDeltaTime);
  }
  ```
- 이제 중복 코드 제거 가능.

---

## 7. 매개변수(Parameter)와 인수(Argument) 활용

- `ApplyRotation()`에 **매개변수**를 추가해 **방향과 세기**를 전달.
- 매개변수(Parameter): 메소드 정의할 때 선언한 변수.
  - 예: `float rotationThisFrame`
- 인수(Argument): 메소드 호출 시 전달하는 실제 값.
  - 예: `ApplyRotation(rotationStrength)`
- 장점:
  - 코드 가독성 ↑
  - 중복 ↓
  - 다양한 상황(좌/우 회전)에 맞게 **동적으로 제어 가능**

---

## 8. 최종 코드 흐름 정리

1. **입력값 읽기**

   ```csharp
   float rotationInput = rotation.ReadValue<float>();
   ```

2. **조건 분기 (if / else if)**
   - 왼쪽 입력 시 → `ApplyRotation(rotationStrength)`
   - 오른쪽 입력 시 → `ApplyRotation(-rotationStrength)`
3. **회전 메소드 실행**

   ```csharp
   private void ApplyRotation(float rotationThisFrame) {
       transform.Rotate(Vector3.forward * rotationThisFrame * Time.fixedDeltaTime);
   }-
   ```

## 7. Dead Zone & Soft Zone

- **Dead Zone**
  - 대상이 Dead Zone 안에서 움직이는 동안 카메라는 움직이지 않는다.
  - 카메라가 불필요하게 흔들리지 않게 하는 장치.
- **Soft Zone**
  - Dead Zone 바깥, 화면 가장자리에 가까워졌을 때 카메라가 천천히 따라간다.
  - “부드러운 추적” 연출 가능.

## 8. Hard Limits

- **개념**: 카메라가 움직일 수 있는 절대 범위를 제한
- **사용 예시**:
  - 플레이어가 화면 끝까지 벗어나지 않도록 방지
  - 스테이지 바깥(빈 공간)이 보이지 않도록 제한

## 9. 업데이트 방식(Fixed vs Smart Update)

- **Smart Update**: 자동으로 상황에 맞게 업데이트 (기본값)
- **Fixed Update**: 물리 연산과 함께 업데이트 → Rigidbody 기반 오브젝트 추적 시 흔들림 방지
- **설정 위치**: Main Camera → Cinemachine Brain → `Update Method`

## 1. 플레이 영역 설정하기

- 사이드 스크롤 게임에서는 **X축(좌우)와 Y축(상하)** 만 사용.
- **Z축(앞뒤 이동)** 은 필요하지 않으므로 고정하는 것이 좋음.
- 플레이어(로켓) 오브젝트의 위치를 `(0,0,0)`에 맞추면 충돌 기준선이 명확해짐.

👉 **핵심 개념**: 불필요한 축을 고정해주면 물리 충돌 계산이 단순해지고, 예측 가능한 움직임을 얻을 수 있다.

---

## 2. 벽(Obstacle) 만들고 배치하기

- FBX 모델이나 에셋을 가져와서 **벽 역할을 하는 오브젝트**로 사용.
- Transform 도구를 사용해 **이동(W), 회전(E), 크기(R)** 를 조정.
- **공중에 떠 있는 장애물**을 만들면 플레이어가 이를 피하면서 진행하도록 유도.

👉 **핵심 개념**: 장애물은 단순한 장식이 아니라 **게임플레이 난이도를 조절하는 핵심 요소**다.

---

## 3. Collider(콜라이더) 이해하기

- **Collider**: 오브젝트의 **물리적 충돌 범위**를 정의.
- 종류:
  - Box Collider → 직육면체 모양
  - Capsule Collider → 원통+반구 모양 (이번 강의에서 사용)
  - Sphere Collider → 구체 모양
- **Direction 옵션**으로 X, Y, Z 축을 기준으로 캡슐 모양을 회전시킬 수 있음.

👉 **핵심 개념**: Collider는 **보이는 Mesh**와는 별개로, 실제 **물리 충돌 영역**을 담당한다.

---

## 4. Rigidbody(리지드바디) 이해하기

- Rigidbody는 오브젝트를 **물리 법칙**(중력, 충돌, 힘)으로 움직이게 해주는 컴포넌트.
- 주요 옵션:
  - **Mass**: 질량
  - **Use Gravity**: 중력 적용 여부
  - **Linear Damping (옛 이름 Drag)**: 직선 운동 감속
  - **Angular Damping (옛 이름 Angular Drag)**: 회전 운동 감속

👉 **핵심 개념**: Rigidbody 없이는 Collider가 있어도 충돌 시 **물리 반응**이 발생하지 않는다.

---

## 5. Constraints(제약) 옵션 사용하기

- Rigidbody → **Constraints** 탭에서 특정 축의 **위치(Position)와 회전(Rotation)** 을 고정 가능.
- 적용 예시:
  - **Freeze Position Z** → 로켓이 앞뒤로 움직이지 않음.
  - **Freeze Rotation X, Y** → 로켓이 옆으로 기울지 않고, **Z축 기준 회전만 허용**.

👉 **핵심 개념**: 불필요한 축 움직임을 고정하면 **버그 예방**과 **예측 가능한 제어**가 가능하다.

---

## 6. Drag(Damping) 개념과 적용

- **Drag(현재는 Linear Damping으로 이름 변경됨)**
  - 공기 저항 같은 효과.
  - 값이 클수록 움직임이 빨리 멈춤.
- 실험:
  - Drag = 58 → 거의 움직이지 않음.
  - Drag = 5 → 천천히 감속.
  - Drag = 1 → 적당한 저항, 자연스러운 움직임.

👉 **핵심 개념**: Drag는 **속도를 줄이는 힘**으로, 게임의 **조작감**을 크게 바꾼다.

---

## 7. 중력(Gravity) 조정하기

- **Project Settings → Physics → Gravity** 에서 설정.
- 기본값: `(0, -9.81, 0)` → 지구 중력.
- 변형 예시:
  - `(0, -4, 0)` → 달 같은 가벼운 중력.
  - `(5, 0, 0)` → 바람처럼 옆으로 밀리는 효과.

👉 **핵심 개념**: 중력은 단순히 Y축에만 적용하는 것이 아니라, **게임 플레이 효과**로 변형할 수 있다.

## 8. Prefab과 Prefab 변형 이해하기

- **Prefab**: 재사용 가능한 오브젝트 템플릿.
- **Prefab Variant(변형)**: 원본 Prefab을 기반으로, 일부 속성만 수정한 버전.
- FBX 모델은 **수정 불가** → Prefab Variant로 만들어야 Collider 등 변경 가능.

👉 **핵심 개념**: Prefab을 사용하면 오브젝트를 **여러 번 배치**해도 수정이 일괄 반영된다.

## 9. 충돌 버그와 해결 방법

- 문제: **물리 시스템의 자동 회전**과 **사용자 입력 회전**이 충돌.
- 해결 방법:
  - `rb.freezeRotation = true;` → Unity 물리 회전을 잠시 멈춤.
  - 사용자 입력으로 직접 회전 제어.
  - 입력 종료 후 `rb.freezeRotation = false;` 로 다시 해제.

👉 **핵심 개념**: **물리 엔진과 사용자 제어는 충돌할 수 있으므로**, 필요한 순간에만 제어권을 가져온다.

```csharp
    private void ProcessRotation()
    {
        float rotationInput = rotation.ReadValue<float>();
        if (rotationInput < 0)
        {
            ApplyRotation(rotationStrength);
        }

        else if (rotationInput > 0)
        {
            ApplyRotation(-rotationStrength);
        }
    }

    private void ApplyRotation(float rotationThisFrame)
    {
        rb.freezeRotation = true;
        transform.Rotate(Vector3.forward * rotationThisFrame * Time.fixedDeltaTime);
        rb.freezeRotation = false;
    }
```
