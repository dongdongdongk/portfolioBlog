# 1. **Maximo(믹사모)란 무엇인가?**

### ✔ 무료 캐릭터 & 애니메이션 라이브러리

- Adobe에서 제공하는 **무료 애니메이션 사이트**

  - **애니메이션(Animation)** 수천 개
  - 전부 Unity에서도 사용 가능

### ✔ 이 강의에서 필요한 것

- “Slim Shooter”라는 **총 쏘는 모션 묶음(Pack)**을 다운로드해서 Unity에서 사용할 것

# 4. **FBX 애니메이션 설정 변경(핵심)**

모든 애니메이션은 Unity 안에서 바로 사용 가능한 것이 아니다.

강의에서는 아래 **3가지를 반드시 설정**해야 한다고 설명한다:

---

## **A. Rig 타입 변경 — Generic → Humanoid**

### ✔ 왜 바꾸나요?

- Maximo 애니메이션은 **사람 형태(Humanoid)**
- Unity도 Humanoid 방식으로 처리해야
  - Retargeting 가능
  - 정상적으로 움직임 적용 가능

### ✔ 변경 방법:

1. 애니메이션 파일 모두 선택
2. Inspector → **Rig 탭**
3. **Animation Type → Humanoid**
4. **Apply** 클릭

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380464/notion-blog/_/3D_/_/_2_Unit_Movement_Selection_-_2/image_2.png)

## **B. Animation 이름 변경**

다운로드한 파일(.fbx)의 이름이 아니라

**애니메이션 클립 자체 이름을 바꿔야 한다.**

### ✔ 왜?

FBX 파일 이름은 의미가 없고

내부 애니메이션 클립은 대부분 전부 **“mixamo.com”** 같은 이름으로 되어 있음.

→ Unity Animator에서 어떤 애니메이션인지 알아보기 어려움

### ✔ 변경 방법:

1. FBX 파일 클릭
2. 작은 ▼ 삼각형 클릭 → 애니메이션 클립 보임
3. Animation 탭으로 이동
4. **Name** 텍스트 변경
   - 예:
     - Firing Rifle
     - Reload
     - Run Forward
5. Apply

# 1. Animator(애니메이터) 개념 이해하기

### 🎬 **Animator란?**

Unity에서 애니메이션을 재생하고 전환하며 관리하는 **애니메이션 엔진**.

- Animator 컴포넌트를 캐릭터에 붙여야 애니메이션을 재생할 수 있음.
- Animator는 **Animator Controller**라는 “애니메이션 그래프”를 필요로 함.
- 캐릭터 모델은 **Avatar(아바타)** 라는 골격 정보가 필요함.

---

### 🎭 애니메이터에 필요한 2가지 핵심 요소

| 요소                    | 설명                                         |
| ----------------------- | -------------------------------------------- |
| **Animator Controller** | 애니메이션 상태(State)들이 들어있는 그래프   |
| **Avatar**              | 캐릭터의 뼈 구조 정보를 담은 파일 (FBX 내부) |

---

### ❗ 중요 개념 – 어떤 Avatar를 선택해야 할까?

**항상 “캐릭터의 Mesh FBX” 안에 있는 Avatar를 사용해야 한다!**

🔸 애니메이션 클립도 Avatar를 가지고 있지만 그것을 사용하면 오류 발생

🔸 총정리: **메시는 Skeleton(뼈) 구조를 가짐 → Avatar 필요 → 애니메이션은 그 뼈 구조를 따라가기만 함**

# 6. Transition 옵션 상세 이해

Transition을 선택하면 Inspector에 옵션이 보임.

### 옵션 리스트 (설명을 *완전 초보용*으로 단순화)

---

## ✔ 1. **Has Exit Time**

- 애니메이션이 끝나면 자동으로 다음 상태로 넘어감
- Idle → Run 같은 자동 전환
  즉, **타이밍 기반 자동 전환**

체크 해제하면?

- 애니메이션이 끝나도 아무 변화 없음
- 반드시 Code 또는 Parameter로 전환해야 함

---

## ✔ 2. Exit Time

- 0 ~ 1 사이 숫자
- 애니메이션의 몇 % 지점에서 전환할지 결정

예:

- 0.9 = 90% 지점에서 다음 상태로 넘어감
- 0.5 = 절반에서 전환

---

## ✔ 3. Fixed Duration

- 전환 시간이 **초 단위인지** 또는 **비율(%)인지** 선택
- 체크하면 → 시간(초)
- 체크 해제 → 비율(애니메이션 길이에 대한 %)

---

## ✔ 4. Transition Duration

전환이 얼마나 부드럽게 이어질지 (Blend 시간)

예:

- 0.25(%) = 애니메이션 길이의 25% 동안 섞임
- 0.1초 = 0.1초 동안 기존 애니메이션과 새 애니메이션이 섞임

---

## ✔ 5. Transition Offset

- 도착 애니메이션을 “중간부터” 시작할지 결정

예:

- 0 = 처음 프레임부터
- 0.5 = 절반 프레임에서 시작

가급적 **0**으로 유지하는 것이 일반적

(자연스러운 흐름)

---

## ✔ Interruptions

- 전환 중 다른 전환이 끼어들 수 있는지 설정
- 초보자는 거의 사용하지 않음
- 강의에서도 사용하지 않음

# 7. 애니메이션 미세 수정: Read-Only → 수정 가능한 애니메이션 만들기

Unity 외부에서 가져온 애니메이션(FBX 내부)은 기본적으로:

✔ Read-Only

✔ 직접 수정 불가능

✔ Record 버튼 비활성화

---

### ▶ 해결: 복제해서 새 애니메이션 만들기

1. Project 창 → 애니메이션 클립 선택(FBX 내부)
2. **Ctrl + D (Duplicate)**
3. 새로 생긴 애니메이션은 Read-Only ❌
4. 이름 변경해 구분
   - `RifleRun_ReadOnly`
   - `RifleRun` (편집 가능)

---

### ▶ Animator에서 이 새 애니메이션으로 교체

- Animator → Run State 클릭
- Motion 교체
- 새로 복제한 애니메이션 할당

# 1. Animator 파라미터 개념 이해하기

### 🎮 **Animator 파라미터(Parameters)는 무엇인가?**

- 애니메이션 전환을 **코드에서 조종하기 위한 입력값**이다.
- Animator Controller 안에 존재한다.
- 파라미터는 “변수”처럼 사용된다.
- 예:
  - 캐릭터가 걷는 중이다 → `IsWalking = true`
  - 걷는 중이 아니다 → `IsWalking = false`

### 🔢 파라미터 타입 종류 (Unity 공식 기능)

| 타입        | 설명                                              |
| ----------- | ------------------------------------------------- |
| **Float**   | 소수 포함 숫자(속도, 체력 등)                     |
| **Int**     | 정수값                                            |
| **Bool**    | true / false                                      |
| **Trigger** | 한 번만 작동하는 스위치 (자동으로 false로 돌아감) |

### 🧠 어떤 때 Bool? 어떤 때 Trigger?

- **Bool**
  - 상태가 유지될 때 사용 (걷는 중/걷지 않는 중)
- **Trigger**
  - “딱 한 번 반응하는" 애니메이션에서 사용 (총 쏘기, 점프)

이번 강의에서는 **걷기 상태를 지속적으로 표현해야 하므로 → Bool 사용!**

# 6. Unit 스크립트 동작 분석하기

아래는 완성된 코드:

```csharp
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class Unit : MonoBehaviour
{
    [SerializeField] private Animator unitAnimator;
    private Vector3 targetPosition;

    private void Update()
    {
        float stoppingDistance = 0.5f;

        // 1. 아직 목표까지 멀다면 → 이동 중
        if (Vector3.Distance(transform.position, targetPosition) > stoppingDistance)
        {
            Vector3 moveDirection = (targetPosition - transform.position).normalized;
            float moveSpeed = 4f;
            transform.position += moveDirection * Time.deltaTime * moveSpeed;

            unitAnimator.SetBool("IsWalking", true); // 이동 중
        }
        else
        {
            unitAnimator.SetBool("IsWalking", false); // 멈춤
        }

        // 2. 마우스 클릭 시 이동
        if (Input.GetMouseButtonDown(0))
        {
            Move(MouseWorld.GetPosition());
        }
    }

    private void Move(Vector3 targetPosition)
    {
        this.targetPosition = targetPosition;
    }
}
```

# 🚀 유닛의 회전(로테이션) 제어하기

이번 강의는 유닛이 **이동 방향을 바라보도록 회전시키는 방법**을 배우는 강의입니다.

---

## 📋 목차

1. 왜 회전이 필요한가?
2. 유니티에서 회전하는 3가지 방법
3. transform.forward 로 회전하기 (가장 쉬운 방법)
4. 바로 회전하면 어색한 이유와 부드럽게 회전하는 법
5. Vector3.Lerp 의 동작 원리
6. 회전 속도(rotationSpeed) 적용하기
7. 최종 코드 구조 이해하기

---

## 1. 왜 회전이 필요한가?

현재 유닛은…

- 마우스를 클릭하면 이동한다.
- 걷는 애니메이션도 잘 나온다.
- 하지만 **유닛이 이동 방향을 보지 않는다.**
  → 캐릭터가 옆으로 미끄러지듯 이동 → 매우 어색함.

그래서 **“이동하는 방향을 향하도록 회전”** 시켜야 한다.

---

## 2. 유니티에서 회전하는 3가지 방법

강의에서는 회전 방식 3가지가 등장한다.

### ① Quaternion 을 직접 조작하기

- 유니티에서 실제 회전값은 Quaternion 이다.
- 하지만 초보에게 매우 어렵고 직관적이지 않음.
- 수학적인 배경도 복잡함.
  👉 **강의에서는 사용하지 않음**

### ② transform.eulerAngles 수정하기

- 우리가 흔히 아는 0~360° 회전값.
- 비교적 이해 쉬움.
- 하지만 직접 회전 수치를 만들어야 해서 계산 필요.

### ③ transform.forward 를 원하는 방향으로 바꾸기

👉 **강의에서 선택한 방법 (가장 쉽고 직관적)**

---

## 3. transform.forward 로 회전하기

### ✨ 핵심 개념

- **transform.forward = 내가 바라보는 방향 벡터**
- 이 forward 를 → moveDirection(이동 방향) 으로 바꾸면
  → 유닛이 “그 방향을 바라보도록” 자동 회전됨.

### 📌 적용 전 준비

이미 이동 방향을 계산하고 있음:

```csharp
Vector3 moveDirection = (targetPosition - transform.position).normalized;
```

### 📌 바로 회전시키는 기본 코드

```csharp
transform.forward = moveDirection;
```

→ 이것만 하면 “즉시 회전” 한다.

**문제점:**

회전이 너무 빠르게 “탁!” 하고 바뀌어 어색함.

---

## 4. 바로 회전하면 어색한 이유와 부드럽게 회전하는 법

“순간 회전”은 사람이 보기에 부자연스럽다.

그래서 **부드럽게 천천히 방향을 맞추는 smoothing(보간)** 이 필요하다.

그 방법이 바로 **Vector3.Lerp()** 사용.

---

## 5. Vector3.Lerp 의 동작 원리

### Lerp 함수 형태

```
Vector3.Lerp( 시작값(A), 목표값(B), t(0~1) );
```

- t = 0 → A 반환
- t = 1 → B 반환
- 0~1 사이 → A와 B 사이의 중간 값

### 이 강의에서는 이렇게 사용

```csharp
transform.forward = Vector3.Lerp(transform.forward, moveDirection, Time.deltaTime);
```

- A = 현재 바라보는 방향 (transform.forward)
- B = 바라보고 싶은 방향 (moveDirection)
- t = Time.deltaTime (매 프레임마다 매우 작은 값)

💡 **이 방식이 완전 선형(Linear)으로 보이지 않는 이유**

- A 값이 계속 변화하고 있기 때문
  → “ease out(처음엔 빠르고 끝에 갈수록 천천히)" 효과처럼 보이는 자연스러운 회전 발생

---

## 6. 회전 속도(rotationSpeed) 적용하기

`Time.deltaTime` 값만으로는 회전 속도가 너무 느림.

그래서 강의에서는 **회전 속도 변수**를 추가한다.

```csharp
float rotationSpeed = 10f;

transform.forward = Vector3.Lerp(
    transform.forward,
    moveDirection,
    Time.deltaTime * rotationSpeed
);
```

회전 속도를 키우면

→ 더 빠르게 방향을 맞추고

회전 속도를 줄이면

→ 더 천천히 회전한다.

---

## 7. 최종 코드 구조 이해하기

### ✔ 캐릭터가 이동 중일 때만 회전

- 이동 중이면 `IsWalking = true`
- 회전도 이동 중에만 수행됨

### ✔ 최종 회전 & 이동 로직 (정리)

```csharp
float stoppingDistance = 0.5f;

if (Vector3.Distance(transform.position, targetPosition) > stoppingDistance)
{
    Vector3 moveDirection = (targetPosition - transform.position).normalized;
    float moveSpeed = 4f;

    // 이동
    transform.position += moveDirection * Time.deltaTime * moveSpeed;

    // 회전
    float rotationSpeed = 10f;
    transform.forward = Vector3.Lerp(
        transform.forward,
        moveDirection,
        Time.deltaTime * rotationSpeed
    );

    unitAnimator.SetBool("IsWalking", true);
}
else
{
    unitAnimator.SetBool("IsWalking", false);
}

```

결과:

- 자연스럽게 이동
- 자연스럽게 회전
- 애니메이션도 정상 동작

# 🎉 최종 코드

### UnitActionSystem.cs

```csharp
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

/// <summary>
/// 씬에서 선택된 유닛을 관리하고, 마우스 입력을 받아
/// 유닛 선택 또는 선택된 유닛의 이동 명령을 내리는 시스템입니다.
/// 모든 입력 관련 로직은 이 스크립트가 담당하며 유닛(Unit) 클래스는
/// 오직 '이동하는 방법'만 알고 있습니다.
/// </summary>
public class UnitActionsSystem : MonoBehaviour
{
    // 에디터에서 드래그해서 넣어주는 현재 선택된 유닛(즉, 우리가 조작할 유닛)
    [SerializeField] private Unit selectedUnit;

    // 어떤 레이어에 있는 오브젝트들을 '유닛'으로 간주할지 지정하는 LayerMask
    // (유닛 전용 레이어를 만들어서 이 값에 설정해 주세요)
    [SerializeField] private LayerMask unitLayerMask;

    private void Update()
    {
        // 매 프레임마다 마우스 입력을 체크합니다.
        // 0번 버튼 = 왼쪽 마우스 버튼
        if (Input.GetMouseButtonDown(0))
        {
            // 먼저 클릭한 위치에서 '유닛을 선택'하려 시도합니다.
            // TryHnadleUnitSelection()이 true를 반환하면 '선택 성공'이므로
            // 이 프레임에서는 더 이상의 행동(이동 등)을 하지 않습니다.
            if (TryHnadleUnitSelection())
            {
                return; // 선택만 하고 그 프레임 내의 이동 명령은 실행하지 않음
            }

            // 만약 유닛을 선택하지 않았다면(즉, 빈 바닥을 클릭했다면)
            // 현재 선택된 유닛(selectedUnit)을 마우스 위치로 이동시키는 명령을 보냅니다.
            // MouseWorld.GetPosition()은 화면의 마우스 좌표를 월드 좌표로 변환해주는 유틸입니다.
            // (MouseWorld 스크립트는 별도 구현되어 있어야 합니다)
            if (selectedUnit != null) // selectedUnit이 null인지 체크해 안전하게 호출
            {
                selectedUnit.Move(MouseWorld.GetPosition());
            }
            else
            {
                // 선택된 유닛이 없을 경우 안전하게 무시하거나 디버그 로그를 남길 수 있습니다.
                Debug.Log("이동할 선택된 유닛이 없습니다.");
            }
        }
    }

    /// <summary>
    /// 마우스 클릭 위치에서 레이캐스트를 쏘아 '유닛'을 클릭했는지 검사합니다.
    /// 유닛을 클릭하면 selectedUnit에 그 유닛을 넣고 true를 반환합니다.
    /// 클릭했지만 유닛이 아니면 false를 반환합니다.
    /// </summary>
    /// <returns>유닛을 선택했다면 true, 아니면 false</returns>
    private bool TryHnadleUnitSelection()
    {
        // 카메라에서 마우스 포인터 위치를 향한 Ray를 생성합니다.
        Ray ray = Camera.main.ScreenPointToRay(Input.mousePosition);

        // Physics.Raycast는 레이와 충돌한 첫번째 객체 정보를 out 파라미터로 반환합니다.
        // float.MaxValue를 거리로 주면 사실상 무한대(씬 내의 모든 거리)를 검사합니다.
        // unitLayerMask를 지정하면 해당 레이어에만 충돌 여부를 검사하므로 성능/정확성에 유리합니다.
        if (Physics.Raycast(ray, out RaycastHit raycastHit, float.MaxValue, unitLayerMask))
        {
            // Ray가 어떤 콜라이더와 충돌했고, 그 콜라이더의 Transform에서 Unit 컴포넌트를 찾아봅니다.
            // TryGetComponent는 GetComponent 후 null 체크를 합친 안전하고 빠른 방법입니다.
            if (raycastHit.transform.TryGetComponent<Unit>(out Unit unit))
            {
                // 유닛이 맞다면 selectedUnit에 그 유닛을 저장(선택)합니다.
                selectedUnit = unit;

                // 선택 성공을 알리기 위해 true 반환
                return true;
            }
        }

        // 레이가 아무 것도 맞추지 못했거나, 맞춘 오브젝트가 Unit이 아닌 경우
        return false;
    }
}

```

# ✅ 1. `out` 이란?

`out` 키워드는

**메서드가 값을 “추가로” 돌려주기 위해 사용하는 매개변수 방식**이다.

C# 메서드는 원래 **리턴값 하나만** 돌려줄 수 있다.

하지만 `out` 을 사용하면,

- **리턴값 1개**
- **out 매개변수 1개**

이렇게 **두 개**를 동시에 돌려줄 수 있다.

즉:

**“이 변수는 메서드 안에서 값이 채워져서 돌아온다.”**

---

# ✅ 2. out 매개변수의 특징

- 호출할 때 반드시 **초기화하지 않고** 넘긴다
  (메서드 안에서 값이 채워지기 때문에)
- 메서드가 끝날 때 **반드시 값이 설정되어 있어야 한다**
- 메서드 밖에서는 바로 이 값 사용 가능

---

# ✅ 3. TryGetComponent에서 out이 쓰이는 이유

`TryGetComponent<T>` 는

**두 가지 정보를 한 번에 반환해야 하기 때문**이다.

1. 찾았는지 여부 → `bool` 반환값
2. 찾았다면 실제 컴포넌트 → `out` 매개변수

그래서 구조가 이렇게 되어 있음:

```csharp
bool success = TryGetComponent<T>(out T component);
```

---

# ✅ 4. 코드에 대입해서 정확히 설명

네가 적은 코드:

```csharp
if (raycastHit.transform.TryGetComponent<Unit>(out Unit unit))
{
    selectedUnit = unit;
    return true;
}
```

여기서

### ✔ `out Unit unit` 의 의미

- **TryGetComponent 메서드에게 빈 변수(unit)를 넘긴다**
- 메서드 내부에서:
  - Unit 컴포넌트를 찾으면 → `unit` 변수 안에 넣어줌
  - 못 찾으면 → 아무 값도 들어가지 않음
- 마지막에 메서드는 true 또는 false를 반환한다

---

# 🔍 TryGetComponent 내부 동작을 단순화하면 이렇게 된다:

```csharp
bool TryGetComponent<Unit>(out Unit result)
{
    // transform에 Unit 컴포넌트가 있는지 검사
    Unit found = this.GetComponent<Unit>();

    if (found == null)
    {
        // out 매개변수에 값을 설정
        result = null;
        return false;
    }
    else
    {
        // out 매개변수에 값을 설정
        result = found;
        return true;
    }
}
```

즉,

- `result` → 네 코드에서는 `unit`
- 결과 값이 메서드 종료 후 바깥으로 나오게 됨

### Unit.cs

```csharp
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

/// <summary>
/// 개별 유닛의 이동 로직과 (간단한) 애니메이션 처리를 담당합니다.
/// 입력 처리는 UnitActionsSystem이 담당하므로 이 스크립트는 외부에서
/// 주어지는 Move(Vector3) 호출만 처리하면 됩니다.
/// </summary>
public class Unit : MonoBehaviour
{
    // 유닛 모델에 붙은 Animator (걷기 애니메이션 전환 등)
    // 에디터에서 드래그해서 연결하세요.
    [SerializeField] private Animator unitAnimator;

    // 유닛이 향해가야 할 목표 위치 (월드 좌표)
    private Vector3 targetPosition;

    // Awake는 Start보다 먼저 호출되는 초기화 메서드입니다.
    // 유닛이 씬에 생성될 때 자신의 현재 위치를 목표 위치로 설정하여
    // 프리팹을 인스턴스화했을 때 즉시 움직이지 않도록 합니다.
    private void Awake()
    {
        targetPosition = transform.position;
    }

    private void Update()
    {
        // 유닛이 목표 위치에 도달했는지 판단할 때 사용할 허용 오차 거리
        float stoppingDistance = 0.5f;

        // 현재 위치와 목표 위치의 거리가 stoppingDistance보다 크면 이동이 필요
        if (Vector3.Distance(transform.position, targetPosition) > stoppingDistance)
        {
            // 목표 방향(정규화된 단위 벡터)
            Vector3 moveDirection = (targetPosition - transform.position).normalized;

            // 이동 속도 (원하면 SerializeField로 빼서 에디터에서 조절 가능)
            float moveSpeed = 4f;

            // 실제 이동: 프레임 간 시간(Time.deltaTime)을 곱해 프레임 독립성 보장
            transform.position += moveDirection * Time.deltaTime * moveSpeed;

            // 부드러운 회전: 유닛의 앞 방향을 이동 방향으로 서서히 맞춤
            float rotationSpeed = 10f;
            transform.forward = Vector3.Lerp(transform.forward, moveDirection, Time.deltaTime * rotationSpeed);

            // 애니메이터에 걷는 상태 전송(애니메이션 파라미터 이름에 맞게 사용)
            if (unitAnimator != null)
            {
                unitAnimator.SetBool("IsWalking", true);
            }
        }
        else
        {
            // 목표에 거의 도달했거나 정지 상태라면 걷기 애니메이션 끄기
            if (unitAnimator != null)
            {
                unitAnimator.SetBool("IsWalking", false);
            }
        }
    }

    /// <summary>
    /// 외부에서 이 유닛에게 '해당 월드 좌표로 이동하라'는 명령을 줄 때 호출합니다.
    /// 예: UnitActionsSystem에서 selectedUnit.Move(MouseWorld.GetPosition()) 호출
    /// </summary>
    /// <param name="targetPosition">이동할 월드 좌표</param>
    public void Move(Vector3 targetPosition)
    {
        // 받은 좌표를 내부의 목표 좌표로 저장하면 Update에서 실제로 이동합니다.
        this.targetPosition = targetPosition;
    }
}

```

# 1. 선택된 유닛 시각화 개념 이해하기

- 현재 시스템은 **유닛을 선택하면 selectedUnit 이 바뀌고**,

  - 선택된 유닛의 발 아래에 **원형(Outline) 오브젝트(Selected Visual)** 를 표시한다.

즉,

> “선택된 유닛임을 쉽게 보여주는 시각적 이펙트를 추가하는 과정”

# 2. Selected Visual 오브젝트 만들기

### 🎯 목표

각 유닛 프리팹 내부에 **Selected Visual** 이라는 **Quad(평면)** 을 추가하여 바닥에 깔린 원을 만든다.

# 4. 프리팹 문제: 왜 Scene 오브젝트를 Drag&Drop 할 수 없는가?

Selected Visual 스크립트에는 **UnitActionSystem** 이 필요하다.

그래야 이벤트를 구독해 “현재 선택된 유닛이 나인가?" 체크할 수 있기 때문.

그러나 문제는:

> SelectedVisual 은 Prefab 내부에 존재한다.
>
> Prefab 내부에서는 Scene 오브젝트를 Drag&Drop 할 수 없다.

왜?

- Prefab 은 **어떤 Scene 에서든** Instantiate 될 수 있는 일종의 “설계도"
- 특정 Scene 에만 존재하는 오브젝트(UnitActionSystem)은
  Prefab 내부에서 알 수 없다.
- 따라서 **SerializedField 로 연결 불가능**

즉, 아래는 불가능:

```csharp
[SerializeField] UnitActionSystem unitActionSystem; // X (Scene 오브젝트)
```

이 문제 때문에 **싱글톤 패턴**이 필요해진다.

# 5. C# 이벤트(Event) 개념 완전 이해하기

유니티 이벤트 시스템 완전 정복하기

### 📌 이벤트란?

- 특정 클래스(발행자, Publisher)가 **어떤 일이 발생했음을 다른 객체에게 알리는 시스템**
- 이벤트에 “구독”(Subscribe)한 객체들은
  이벤트가 발생하면 자동으로 호출된다.

### 🔥 아주 쉬운 개념화

- 유튜브 채널(발행자)
- 구독자(Subscribers)
- 영상 업로드(Event 발생)
- 구독자 알림 받음 → 반응함

### C# 문법 요소

- `event` 키워드
- Delegate(보낼 함수의 형태)
- `EventHandler` : 가장 많이 쓰는 표준 delegate

### EventHandler 시그니처

```csharp
void Handler(object sender, EventArgs e)
```

- sender: 이벤트를 발생시킨 객체
- e: 추가 정보 (지금은 EventArgs.Empty 사용)

---

# 6. Observer 패턴과 이벤트의 관계

- 이벤트 시스템은 바로 **Observer Pattern(옵저버 패턴)** 의 구현이다.
- Publisher 는 구독자가 누군지 모른다.
- Subscriber 는 이벤트가 발생하면 자동으로 반응한다.

이 강의에서는:

- Publisher → **UnitActionSystem**
- Subscriber → **UnitSelectedVisual**

즉,

> "선택된 유닛이 바뀌는 순간(이벤트 발생),
>
> 모든 SelectedVisual 오브젝트들이 이 사실을 알게 된다."

**옵저버 패턴은 어떤 객체에서 “변경 사항이 생기면”, 그걸 지켜보는(=옵저버) 다른 객체들에게 자동으로 알려주는 방식이다.** 예를 들어, “선택된 유닛”이 바뀌면 이 사실을 알고 싶어 하는 표시 오브젝트들이 여러 개 있을 수 있는데, 옵저버 패턴을 쓰면 선택 시스템이 “나 바뀌었어!”라고 한 번만 알려주면, 그걸 구독하고 있던(옵저버 역할) 오브젝트들이 자동으로 반응한다. 이렇게 하면 업데이트가 필요한 객체들이 **직접 서로를 찾거나 검사하지 않아도 되고**, 변화가 있을 때만 알려주기 때문에 **코드가 깔끔하고 효율적**이 된다. 즉, **한 객체가 변경될 때 여러 객체가 자동으로 반응하도록 연결해주는 구조**가 옵저버 패턴이다.

# 7. UnitActionSystem에 이벤트 구현하기

### ✔️ 이벤트 정의

```csharp
public event EventHandler OnSelectedUnitChanged;
```

### ✔️ 선택 변경 시 이벤트 발행

```csharp
private void SetSelectedUnit(Unit unit)
{
    selectedUnit = unit;
    OnSelectedUnitChanged?.Invoke(this, EventArgs.Empty);
}
```

### ✔️ 왜 ?.Invoke 사용?

- 구독자가 0명일 경우, 이벤트는 `null`
- null.Invoke 를 부르면 에러 발생
- ?. 는 `null 이 아닐 때만 실행` 이라는 의미

# 8. Selected Visual 스크립트에서 이벤트 구독하기

SelectedVisual 은 다음이 필요하다:

1. 자신의 Unit (프리팹에서 Drag)
2. MeshRenderer (켜고 끄기 위해)
3. UnitActionSystem (이벤트 구독을 위해)

하지만 UnitActionSystem 은 Scene 오브젝트 → **싱글톤으로 접근**

### 기본 구조

```csharp
private void Start()
{
    UnitActionSystem.Instance.OnSelectedUnitChanged += UnitActionSystem_OnSelectedUnitChanged;

    UpdateVisual();
}

private void UnitActionSystem_OnSelectedUnitChanged(object sender, EventArgs e)
{
    UpdateVisual();
}

private void UpdateVisual()
{
    bool isSelected = UnitActionSystem.Instance.GetSelectedUnit() == unit;
    meshRenderer.enabled = isSelected;
}
```

- 선택된 유닛 ≠ 나 → 숨기기
- 선택된 유닛 = 나 → 보이기

# 9. 싱글톤 패턴이 필요한 이유

> “Prefab 내부의 스크립트가 Scene 의 특정 시스템에 접근해야 할 때
>
> **Drag&Drop 을 사용하지 못하므로**
>
> 코드로 ‘전역적 접근 방식’이 필요함”

그 해결책이 **Singleton**.

예시:

```csharp
public static UnitActionSystem Instance { get; private set; }

private void Awake()
{
    Instance = this;
}
```

이제 어디서든:

```csharp
UnitActionSystem.Instance
```

로 접근 가능.

# 1. 유닛 선택 시스템 개념 이해하기

이 시스템에는 **두 가지 역할**이 있습니다.

### ✔ 1) UnitActionsSystem

- **선택을 담당하는 중앙 관리자**
- 마우스 클릭을 감지하고,
- 어떤 유닛이 선택되었는지 저장하고,
- 선택 변경이 발생하면 **이벤트를 통해 알림을 보내는 역할**을 수행함.

### ✔ 2) UnitSelectedVisual

- **각 유닛에 붙어 있는 표시 렌더러(예: 링, 빛 등)**
- 특정 유닛이 선택되었을 때만 켜고
- 선택되지 않았으면 끄는 역할을 함.

이 둘이 합쳐져서…

👉 “마우스를 클릭하면 유닛이 선택되고,

선택된 유닛에만 표시가 뜨는 시스템”

이 완성된다.

# 2. UnitActionsSystem 분석하기 (유닛 선택 담당)

### 📌 코드는 크게 3가지로 이루어짐

1. **싱글톤 생성 및 준비 (Awake)**
2. **마우스 입력 처리 (Update)**
3. **Raycast로 유닛 선택 / 이동 명령 처리**
4. **이벤트로 선택 변경 알림**

---

## 🔹 2-1. 싱글톤 패턴 (Awake)

```csharp
public static UnitActionsSystem Instance { get; private set; }

private void Awake()
{
    if( Instance != null )
    {
        Debug.LogError("There is more than one UnitActionsSystem!");
        Destroy(gameObject);
        return;
    }
    Instance = this;
}
```

### ✔ 왜 싱글톤?

- 게임 전체에서 “선택된 유닛”을 하나만 관리해야 함.
- 여러 오브젝트에서 쉽게 이 시스템에 접근해야 함.

---

## 🔹 2-2. Update() — 마우스 클릭 처리

```csharp
if (Input.GetMouseButtonDown(0))
{
    if (TryHnadleUnitSelection())
    {
        return;
    }
    selectedUnit.Move(MouseWorld.GetPosition());
}
```

### ✔ 흐름

1. **왼쪽 마우스를 클릭**
2. 먼저 "**유닛을 선택하려는 클릭인가?**" 체크
   - 유닛을 클릭했다면 선택 처리하고 **즉시 return**
3. 유닛 선택이 아니라면 → 이미 선택된 유닛을 이동시킴

즉,

👉 클릭 = “선택 시도”

👉 빈 공간 클릭 = “이동”

---

## 🔹 2-3. TryHandleUnitSelection() — 유닛 선택 시도 기능

```csharp
Ray ray = Camera.main.ScreenPointToRay(Input.mousePosition);

if (Physics.Raycast(ray, out RaycastHit raycastHit, float.MaxValue, unitLayerMask))
{
    if (raycastHit.transform.TryGetComponent<Unit>(out Unit unit))
    {
        SetSelectedUnit(unit);
        return true;
    }
}
return false;
```

### ✔ 이 함수의 역할

1. 카메라 → 마우스 방향으로 Ray 발사
2. 해당 Ray가 **unitLayerMask**에 충돌하면
3. 충돌된 오브젝트에 **Unit 컴포넌트가 있는지 검사**
4. 있다면 그 유닛을 **선택**
5. 성공하면 true(= 선택 완료) 반환

### ✔ 중요한 옵션: unitLayerMask

- Raycast가 “유닛만 맞추도록” 하는 필터
- 땅이나 벽은 무시함

---

## 🔹 2-4. 선택된 유닛 설정 + 이벤트 날리기

```csharp
private void SetSelectedUnit(Unit unit)
{
    selectedUnit = unit;
    OnSelectedUnitChanged?.Invoke(this, EventArgs.Empty);
}
```

### ✔ 이 부분이 시스템의 핵심

- selectedUnit 값을 새로 지정
- OnSelectedUnitChanged 이벤트 호출
- 이 이벤트는 “시각화 오브젝트”들이 듣고 있음
  → 따라서 자동으로 표식 업데이트가 발생함
