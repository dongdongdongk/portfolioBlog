# { 리눅스 명령 구문 }

```jsx
1. 명령어 구문 소개

	명령어: 수행하려는 작업입니다. 예: ls (파일 및 디렉토리 나열).

	옵션: 명령어의 동작 방식을 변경합니다. 일반적으로 하이픈(-) 뒤에 문자 하나가 옵니다. 옵션은 그룹화할 수도 있습니다. 예: -l (자세한 형식), -t (시간순 정렬).

	인자: 명령어의 대상이 되는 항목을 지정합니다. 파일명, 디렉토리명 등이 될 수 있습니다. 인자는 선택적일 수도 있고 필수적일 수도 있습니다. 예: Bart (특정 파일).

2. 기본 명령어와 옵션

	ls 명령어:

		옵션 없이 사용: ls는 현재 디렉토리의 파일 및 디렉토리를 나열합니다.

		옵션 -l 사용: ls -l은 파일의 권한, 소유자, 크기, 수정 날짜 등 자세한 정보를 제공합니다.

		옵션 -ltr 사용: ls -ltr은 긴 형식으로 파일을 나열하며 수정 시간 순서로 정렬합니다 (최신 파일이 아래에 위치).

3. 인자 사용

	예제:

		ls -l Bart는 특정 파일 Bart에 대한 자세한 정보를 나열합니다.

4. 파일 및 디렉토리 삭제

	rm 명령어:

		파일 삭제: rm -f filename은 파일을 삭제하며 확인을 묻지 않습니다.

		디렉토리 삭제: rm -r directoryname은 디렉토리와 그 안의 모든 내용을 삭제합니다. (-r은 디렉토리와 그 내용을 재귀적으로 삭제하는 옵션입니다.)

5. 작업 확인하기

	rm -r Seinfeld 명령어로 디렉토리를 삭제한 후, ls -ltr을 사용하여 디렉토리가 삭제되었는지 확인합니다.

	디렉토리를 다시 생성하려면: mkdir Seinfeld 명령어를 사용합니다. ls -ltr을 다시 실행하여 디렉토리가 생성되었는지 확인합니다.

6. 명령어 옵션 찾기

	매뉴얼 페이지:

		man ls 명령어를 사용하여 ls의 매뉴얼 페이지를 열 수 있습니다. 이 페이지는 모든 사용 가능한 옵션과 설명을 보여줍니다.

		매뉴얼 페이지를 스페이스바로 아래로 스크롤하고, q를 눌러 종료할 수 있습니다.
```

# { 파일 및 디렉토리 권한 (chmod) }

```jsx
 파일과 디렉토리의 권한을 변경하는 방법에 대해 배우겠습니다. 이를 통해 다른 사용자가 파일을 열람하거나 삭제하는 것을 방지할 수 있습니다.
```

## 다중 사용자 시스템

```jsx
UNIX는 다중 사용자 시스템입니다. 계정의 모든 파일과 디렉토리는 접근 권한을 변경함으로써 다른 사용자로부터 보호하거나 접근을 허용할 수 있습니다.

모든 사용자는 파일 접근을 제어할 책임이 있습니다.
```

## 권한의 종류

```jsx
파일 또는 디렉토리의 권한은 읽기, 쓰기, 실행의 세 가지로 나뉩니다.

	읽기 (Read): 파일 내용을 읽을 수 있는 권한입니다.

	쓰기 (Write): 파일 내용을 수정할 수 있는 권한입니다.

	실행 (Execute): 파일을 실행할 수 있는 권한입니다. 프로그램이나 스크립트인 경우 실행 권한이 필요합니다.
```

## 권한 수준

```jsx
권한은 세 가지 수준에서 제어할 수 있습니다.

	사용자 (User): 파일을 소유한 사용자입니다.

	그룹 (Group): 같은 프로젝트나 부서의 사용자 그룹입니다.

	기타 (Others): 모든 다른 사용자입니다.
```

## 파일 및 디렉토리 권한 확인

```jsx
파일 또는 디렉토리의 권한을 확인하려면 ls -l 명령어를 사용합니다.

	예시: ls -l

		결과: -rw-rw-r-- 1 username groupname 0 Jul 24 15:40 filename

		파일 타입 및 권한: -rw-rw-r--

			-: 일반 파일
			rw-: 소유자 권한 (읽기, 쓰기)
			rw-: 그룹 권한 (읽기, 쓰기)
			r--: 기타 사용자 권한 (읽기)



* 첫 번째 비트는 파일 타입을 나타내고, 다음 세 개의 비트는 소유자 권한, 그 다음 세 개의 비트는 그룹 권한, 마지막 세 개의 비트는 기타 사용자 권한을 나타냅니다.
```

## 권한 변경

```jsx
권한을 변경하려면 chmod 명령어를 사용합니다.

	예시: chmod g-w filename

		그룹의 쓰기 권한을 제거합니다.

또는 모든 사용자에게서 읽기 권한을 제거하려면:

	예시: chmod a-r filename

특정 사용자에게서 쓰기 권한을 제거하려면:

	예시: chmod u-w filename
```

## 디렉토리 권한

```jsx
디렉토리의 권한은 파일과 비슷하지만, 실행 권한이 CD 명령어로 디렉토리에 접근할 수 있는 권한을 의미합니다.

	예시: 디렉토리에 접근 권한을 제거하려면 chmod a-x directoryname

	다시 접근 권한을 추가하려면 chmod a+x directoryname
```

## 요약

```jsx
파일과 디렉토리의 권한은 읽기, 쓰기, 실행으로 나뉘며, 사용자, 그룹, 기타 사용자를 대상으로 설정할 수 있습니다.

chmod 명령어를 사용하여 권한을 추가하거나 제거할 수 있으며,

이는 파일뿐만 아니라 디렉토리에도 적용됩니다. 권한 관리를 통해 파일과 디렉토리를 안전하게 보호할 수 있습니다.
```

# { 숫자 모드를 사용한 파일 권한 }

```jsx
파일과 디렉토리의 권한을 설정하는 방법에는 문자와 숫자를 사용하는 두 가지 방법이 있습니다.
```

## 숫자를 사용한 권한 설정의 원리

```jsx
기본 원리:

	chmod 명령어를 사용하여 파일이나 디렉토리의 권한을 설정할 수 있습니다.

	예를 들어, chmod 444 파일 명령어는 chmod ugo+r 파일과 동일한 권한을 설정합니다.

	숫자를 사용하여 권한을 설정하는 방법은 파일의 각 사용자(소유자), 그룹, 그리고 기타 사용자에 대한 권한을 지정하는 것입니다.
```

## 권한 비트 구조

```jsx
파일이나 디렉토리에는 다음과 같은 세 가지 유형의 권한이 있습니다:

	읽기 (Read): 파일을 읽을 수 있는 권한.

	쓰기 (Write): 파일을 수정할 수 있는 권한.

	실행 (Execute): 파일을 실행할 수 있는 권한.

이러한 권한은 세 그룹으로 나누어집니다:

	사용자 (User): 파일의 소유자.

	그룹 (Group): 파일이 속한 그룹의 사용자.

	기타 사용자 (Other): 모든 다른 사용자.
```

## 권한 숫자 테이블

```jsx
각 권한에 대한 숫자 값을 외워야 합니다:
	0: 권한 없음
	1: 실행 권한
	2: 쓰기 권한
	3: 실행 + 쓰기 권한
	4: 읽기 권한
	5: 읽기 + 실행 권한
	6: 읽기 + 쓰기 권한
	7: 읽기 + 쓰기 + 실행 권한
```

## 예제

```jsx
기본 파일 생성 및 권한 설정:

	파일 생성: touch sam

	기본 권한 확인: ls -ltr

	764 권한 설정: chmod 764 sam

	결과: 사용자에게는 읽기, 쓰기, 실행 권한, 그룹에게는 읽기, 쓰기 권한, 기타 사용자에게는 읽기 권한이 부여됨.

모든 권한 제거:

	chmod 000 sam

	결과: 모든 사용자에게 모든 권한이 제거됨.

특정 권한 설정:

	사용자에게 읽기 및 쓰기 권한 부여: chmod 600 sam

	결과: 사용자에게 읽기, 쓰기 권한, 그룹과 기타 사용자에게는 권한 없음.

다른 사용자에게 읽기 권한 추가:

	chmod 604 sam

	결과: 사용자에게 읽기, 쓰기 권한, 기타 사용자에게 읽기 권한 부여.

실행 권한 추가:

	모든 사용자에게 실행 권한 부여: chmod 111 sam

	결과: 모든 사용자에게 실행 권한 부여.

읽기 및 실행 권한 추가:

	chmod 511 sam

	결과: 사용자에게 읽기 및 실행 권한, 그룹과 기타 사용자에게는 실행 권한 부여.
```

# { 파일 소유권 명령 (chown, chgrp) }

```jsx
파일과 디렉터리의 소유권은 사용자 및 그룹 수준에서 관리됩니다.

파일이나 디렉터리는 두 가지 소유자가 있습니다.

첫 번째는 파일이나 디렉터리를 생성한 사용자이고, 두 번째는 해당 사용자가 속한 그룹입니다.
```

## 파일 소유권 변경

```jsx
파일 소유권 변경 (chown)

	파일의 소유권을 변경하는 명령어입니다.

	chown [새 사용자] [파일명]

	예시: chown root myfile.txt

그룹 소유권 변경 (chgrp)

	파일의 그룹 소유권을 변경하는 명령어입니다.

	chgrp [새 그룹] [파일명]

	예시: chgrp root myfile.txt

재귀적 소유권 변경

	-R 옵션을 사용하면 해당 디렉터리뿐만 아니라 그 안의 모든 파일과 디렉터리의 소유권도 변경할 수 있습니다.

	예시: chown -R root /mydirectory
```

```jsx
	소유자는 두 그룹(System, Administrator)과 한 사용자(iafzal)로 표시됩니다.

	이러한 소유자에 따라 읽기, 쓰기, 실행 권한이 부여됩니다.

	whoami 명령어로 현재 사용자를 확인합니다.

	세 번째 열이 파일의 소유자, 네 번째 열이 그룹 소유자를 나타냅니다.

파일 소유권 변경 예시
```

## ACL(Access Control List)이란?

```jsx
ACL은 파일 시스템에 대한 유연한 권한 부여 메커니즘으로,

특정 사용자 또는 그룹에게 권한을 부여할 수 있게 해줍니다. 이는 UNIX 파일 권한을 보완하는 추가적인 기능입니다.
```

## ACL의 목적

```jsx
예를 들어, 사용자가 특정 그룹에 속해 있지 않지만 특정 파일에 대한 읽기 또는 쓰기 권한을 부여하고 싶을 때 ACL을 사용할 수 있습니다.

일반적인 파일 권한 설정으로는 이와 같은 세밀한 권한 부여가 어렵기 때문에 ACL이 필요합니다.
```

## 사용자 권한 부여 예제

```jsx
파일 생성 및 초기 상태 확인

	파일 생성: touch /tmp/TX

	초기 권한 확인: ls -l /tmp/TX

특정 사용자에게 쓰기 권한 부여

	명령어: setfacl -m u:iafzal:rw /tmp/TX

	결과 확인: getfacl /tmp/TX

			setfacl:

				setfacl 명령어는 ACL을 설정하거나 변경하는 데 사용됩니다.

			-m:

				-m 옵션은 ACL을 수정하는(modify) 옵션입니다. 이 옵션을 사용하여 특정 사용자나 그룹에 대해 새로운 권한을 추가하거나 기존 권한을 변경할 수 있습니다.

			u:iafzal:

				u: 이 부분은 ACL을 적용할 대상이 사용자(user)임을 의미합니다.


			iafzal: 이 부분은 권한을 부여할 특정 사용자의 이름입니다.


			rw: 이 부분은 권한의 종류를 나타냅니다. 여기서 r은 읽기(read) 권한을, w는 쓰기(write) 권한을 의미합니다.

설정 후 사용자가 파일을 수정할 수 있게 됩니다.
```

```jsx
특정 사용자에 대한 ACL 제거

	명령어: setfacl -x u:iafzal /tmp/TX

	결과 확인: getfacl /tmp/TX

모든 ACL 제거

	명령어: setfacl -b /tmp/TX

	결과 확인: getfacl /tmp/TX
```

## 주의사항

```jsx
ACL이 설정된 파일은 ls -l 명령어로 확인할 때 권한 표시 끝에 + 기호가 추가됩니다.

ACL을 통해 쓰기 권한을 부여하더라도 해당 사용자가 파일을 삭제할 수는 없습니다. 파일 삭제 권한은 여전히 파일 소유자에게 있습니다.
```

## 요약

```jsx
ACL은 특정 사용자나 그룹에게 세밀한 파일 권한을 부여할 수 있는 유연한 메커니즘입니다.

setfacl과 getfacl 명령어를 사용해 ACL을 설정 및 조회할 수 있으며,

이를 통해 특정 사용자에게만 권한을 부여하거나 제거할 수 있습니다.

ACL을 사용하면 일반적인 파일 권한 설정으로는 불가능한 세밀한 권한 관리를 할 수 있습니다.
```

## 기초 개념

```jsx
리눅스에서 모든 것은 파일로 취급됩니다. 여기에는 우리가 보는 텍스트 파일, 디렉토리뿐만 아니라,

키보드 입력과 화면 출력도 포함됩니다. 이러한 파일들은 파일 디스크립터(file descriptor)라는 숫자로 식별됩니다:
```

## 표준 입력 (STDIN)

```jsx
표준 입력은 키보드로부터 입력된 데이터를 의미합니다. 기본적으로 명령어는 표준 입력을 통해 데이터를 받아들입니다.
```

## 표준 출력 (STDOUT)

```jsx
표준 출력은 명령어 실행 결과를 화면에 보여주는 것을 의미합니다. 기본적으로 명령어의 출력은 표준 출력으로 터미널에 표시됩니다.
```

## 표준 오류 (STDERR)

```jsx
표준 오류는 명령어 실행 중 발생하는 오류 메시지를 화면에 보여주는 것을 의미합니다. 기본적으로 오류 메시지는 표준 오류로 터미널에 표시됩니다.
```

## 출력 리다이렉트 (STDOUT Redirect)

```jsx
명령어 실행 결과를 파일로 저장할 수 있습니다.
```

```jsx
ls -l 명령어의 출력이 output.txt 파일에 저장됩니다.
```

```jsx
ls -la 명령어의 출력이 output.txt 파일에 추가됩니다.

기존 output.txt 파일 내용은 유지되고, 새로운 내용이 파일 끝에 추가됩니다.
```

```jsx
* 만약 예를들어 ls -l 내용을 명령어로 실행하려면 bash 또는 sh와 같은 셸을 통해 파일 내용을 읽고 실행할 수 있습니다.
```

## tee 명령어

```jsx
tee 명령어는 명령어의 출력을 파일에 저장하고 동시에 화면에 표시하는 데 사용됩니다.

이 명령어는 배관에서 사용되는 T-스플리터에서 이름을 따왔으며, 입력을 두 방향으로 나눕니다.

표준 출력(화면)과 파일 출력을 동시에 처리할 수 있어 유용합니다.
```

## 기본 사용법

```jsx
명령어 기본 형식

	명령어 | tee 파일명: 명령어의 출력을 화면과 파일에 동시에 출력합니다.

	예시: echo "Hello, World!" | tee hello.txt

		echo 명령어의 출력("Hello, World!")을 화면에 표시하고, hello.txt 파일에도 저장합니다.


* 장점

	명령어 출력을 파일에 저장하면서 동시에 화면에서 결과를 확인할 수 있습니다.

	파일에 저장된 출력이 올바른지 즉시 확인 가능합니다.
```

## 예제와 실습

```jsx
예제 1: 기본 사용

	파일에 출력 저장: echo "David Puddy is Eliane's boy friend." > eliane-david

		eliane-david 파일에 텍스트를 저장하지만 화면에는 출력되지 않음.

	파일 출력 확인: cat eliane-david

		파일 내용을 화면에 출력.

예제 2: tee 사용

	출력 화면 및 파일 저장: echo "David Puddy is Eliane's boy friend." | tee eliane-david

		텍스트를 화면과 eliane-david 파일에 동시에 출력.

	출력 확인: cat eliane-david

		파일 내용을 확인하여 제대로 저장되었는지 확인.
```

## 추가 기능

```jsx
출력 덮어쓰기

	기본적으로 tee 명령어는 파일의 내용을 덮어씁니다.

	예시: echo "David and Eliane" | tee eliane-david

		eliane-david 파일의 기존 내용이 새 내용으로 대체됩니다.

		기존 내용 뒤에 새로운 내용을 덧붙임.

출력 문자 수 확인

	wc -c 명령어를 사용하여 파일의 문자 수를 확인합니다.

	예시: wc -c eliane-david

		eliane-david 파일의 총 문자 수를 출력합니다.

		* wc 는 총 문자 수 확

ls 명령어 출력 저장

	ls -l | tee listdir: 현재 디렉토리의 파일 목록을 화면과 listdir 파일에 저장합니다.

	여러 파일에 동시에 저장: ls -l | tee file1 file2 file3

		동일한 출력을 여러 파일에 동시에 저장.
```

# { Pipe 명령어 }

## 소개 및 개요

```jsx
**파이프(pipe)**는 셸에서 한 명령어의 출력을 다른 명령어의 입력으로 직접 연결하는 데 사용됩니다.

파이프의 기호는 수직 막대(|)입니다.

명령어 구문은 명령어 | 다른 명령어 형식입니다.

파이프를 사용하면 첫 번째 명령어의 출력을 두 번째 명령어로 전달할 수 있습니다.
```

## 기본 사용법

```jsx
명령어 기본 형식

명령어 | 다른 명령어: 첫 번째 명령어의 출력을 두 번째 명령어로 전달합니다.

예시: ls -l | more

		ls -l 명령어의 출력을 more 명령어로 전달하여 한 페이지씩 출력합니다.

키보드에서 파이프 기호 찾기

	Mac 키보드: 파이프 기호는 키보드의 오른쪽 끝에 있습니다.

	일반 키보드: 파이프 기호는 백스페이스 키 아래에 있으며, Shift 키와 함께 사용합니다.
```

# { 파일 유지 관리 명령 (cp, rm, mv, mkdir, rmdir) }

```jsx
파일을 유지, 변경하는 데 사용되는 여러 명령어를 다룹니다.
```

## 명령어 설명 및 사용 예제

```jsx
2.1. cp (Copy)

파일을 복사하는 명령어입니다.

예시:

	cp source_file destination_file

	cp George David (George 파일을 복사하여 David로 저장)

	echo "David Puddy is Elaine's boyfriend" > David (David 파일에 내용 추가)

	cp David /tmp (David 파일을 /tmp 디렉토리로 복사)

2.2. rm (Remove)

파일을 삭제하는 명령어입니다.

예시:

	rm filename

	touch Apoho (Apoho 파일 생성)

	echo "Apoho is an Indian character" > Apoho (Apoho 파일에 내용 추가)

	rm Apoho (Apoho 파일 삭제)

2.3. mv (Move)

파일을 이동하거나 이름을 변경하는 명령어입니다.

예시:

	mv source_file destination_file

	mv Lex Luther (Lex 파일의 이름을 Luther로 변경)

	mv David Puddy (David 파일의 이름을 Puddy로 변경)

	mv Puddy /tmp (Puddy 파일을 /tmp 디렉토리로 이동)

	mv /tmp/Puddy ~/ (/tmp 디렉토리에서 Puddy 파일을 홈 디렉토리로 이동)

2.4. mkdir (Make Directory)

새로운 디렉토리를 만드는 명령어입니다.

예시:

	mkdir directory_name

	mkdir GameOfThrone (GameOfThrone 디렉토리 생성)

2.5. rmdir (Remove Directory)

빈 디렉토리를 삭제하는 명령어입니다.

예시:

	rmdir directory_name

	rmdir GameOfThrone (GameOfThrone 디렉토리 삭제)

	rm -r directory_name (디렉토리와 그 안의 모든 파일 삭제)

	rm -r GameOfThrone (GameOfThrone 디렉토리와 그 안의 모든 파일 삭제)

2.6. chgrp (Change Group)

파일의 그룹 소유권을 변경하는 명령어입니다.

예시:

	chgrp group_name file_name

	chgrp root Puddy (Puddy 파일의 그룹 소유권을 root로 변경)

	그룹 소유권을 변경하려면 root 권한이 필요합니다.

2.7. chown (Change Ownership)

파일의 소유자를 변경하는 명령어입니다.

예시:

	chown owner_name file_name

	chown root Puddy (Puddy 파일의 소유자를 root로 변경)

	chown owner:group file_name (파일의 소유자와 그룹 소유권을 동시에 변경)

	chown iafzal:iafzal Puddy (Puddy 파일의 소유자와 그룹 소유권을 iafzal로 변경)
```

```jsx
rmdir: 빈 디렉토리 삭제

rm -r: 디렉토리와 그 안의 파일 삭제
```

## 명령어 설명 및 사용 예제

```jsx
2.1. cat (Concatenate and Display)

파일의 전체 내용을 표시합니다.

예시:

	cat filename

	cat messages (messages 파일의 전체 내용 표시)

2.2. more

파일 내용을 한 페이지씩 표시합니다.

예시:

	more filename

	more messages (messages 파일을 한 페이지씩 표시)

	스페이스 바를 눌러 다음 페이지로 이동, Q를 눌러 종료

2.3. less

more와 유사하지만, 더 강력한 파일 탐색 기능을 제공합니다.

예시:

	less filename

	less messages (messages 파일을 한 페이지씩 표시)

	스페이스 바를 눌러 다음 페이지로 이동, J를 눌러 한 줄씩 이동, K를 눌러 위로 이동


2.4. head

파일의 상위 몇 줄을 표시합니다.

예시:

	head -n filename (filename 파일의 상위 n 줄을 표시)

	head -2 messages (messages 파일의 상위 2줄 표시)


2.5. tail

파일의 하위 몇 줄을 표시합니다.

예시:

	tail -n filename (filename 파일의 하위 n 줄을 표시)

	tail -2 messages (messages 파일의 하위 2줄 표시)
```

```jsx
		파일의 첫 번째 열만 출력합니다.

		파일에서 'error' 또는 'fail'이 포함된 라인만 출력합니다.

2.4. sort

	설명: 파일의 내용을 알파벳 순서로 정렬합니다.

		파일 내용을 기본 알파벳 순서로 정렬합니다.

	역순 정렬: sort -r filename

		파일 내용을 역순으로 정렬합니다.

2.5. uniq

설명: 중복된 라인을 제거합니다.

사용 예제:

중복 제거: uniq filename

	파일에서 중복된 라인을 제거하여 출력합니다.

중복 횟수 표시: uniq -c filename

	각 라인의 중복 횟수를 표시합니다.

2.6. wc (Word Count)

설명: 파일의 단어 수, 문자 수, 라인 수를 계산합니다.

사용 예제:

전체 계산: wc filename

	파일의 단어 수, 문자 수, 라인 수를 출력합니다.

라인 수만 계산: wc -l filename

	파일의 라인 수만 출력합니다.

단어 수만 계산: wc -w filename

	파일의 단어 수만 출력합니다.

문자 수만 계산: wc -m filename

	파일의 문자 수만 출력합니다.
```

# { 파일 크기 자르기 (truncate) }

```jsx
파일의 크기를 조정하는 방법, 즉 파일을 잘라내거나 확장하는 방법을 다룹니다.

이 작업은 주로 파일의 크기를 지정된 크기로 맞추기 위해 사용됩니다.

자르기 명령어는 압축과는 다르며, 파일 내용을 잘라내어 크기를 줄이거나, 확장할 경우 빈 데이터를 추가해 파일 크기를 키우게 됩니다.
```

## 1. **파일 자르기 개념**

```jsx
파일 자르기와 압축의 차이:

	파일 자르기: 파일의 크기를 지정된 크기로 자르거나 늘립니다. 자를 경우 일부 데이터를 잃게 되며, 늘릴 경우 빈 데이터를 추가합니다.

	파일 압축: 데이터의 무결성을 유지하면서 파일의 크기를 줄입니다.

명령어 사용의 예:

	파일의 크기를 100바이트에서 50바이트로 줄이면, 데이터의 절반이 손실됩니다.

	파일 크기를 줄이는 과정에서 중요한 데이터가 손실될 수 있으므로 주의가 필요합니다.
```

## 실습

### 2. **파일 생성 및 확인**

```jsx
파일 생성:

파일 내용 추가:

파일 크기 확인:

	파일의 크기는 ls -l 명령어를 통해 확인할 수 있으며, 예시에서는 57바이트로 표시됩니다.
```

### 3. **파일 자르기 (Truncate)**

```jsx
파일 자르기 명령어:

파일 자르기 후 확인:

	파일 크기를 다시 확인하면 40바이트로 줄어들어 있으며, 일부 데이터가 손실됩니다.

	cat filename 명령어로 파일 내용을 확인할 수 있으며, 일부 텍스트가 잘린 상태로 나타납니다.
```

```jsx
파일 확장:

	이때, 확장된 부분에는 빈 데이터가 추가됩니다.

파일 확장 후 내용 확인:

	확장된 파일의 내용을 확인하면, 원래 있던 데이터는 그대로 남아 있고, 추가된 부분에는 빈 데이터가 들어갑니다.

	확장된 파일에 새로운 내용을 추가할 수 있습니다.
```

```jsx
여러 파일을 하나로 결합하거나 하나의 파일을 여러 개로 분할하는 방법에 대해 다룹니다.

이러한 작업은 파일 관리에서 매우 유용하며, 특히 큰 파일을 다룰 때 필요합니다.
```

## 1. **파일 결합 (Combining Files)**

```jsx
파일 결합의 개념:

		여러 파일을 하나의 파일로 합치는 작업을 의미합니다.

		예를 들어, 파일 file1, file2, file3의 내용을 하나의 파일인 file4에 결합할 수 있습니다.

파일 결합 명령어 사용:

	cat file1 file2 file3 > file4 명령어를 사용해 파일을 결합할 수 있습니다.

	이 명령어는 file1, file2, file3의 내용을 결합하여 file4에 저장합니다.

	결과적으로, file4는 file1, file2, file3의 모든 내용을 포함하게 됩니다.
```

## 2. **파일 분할 (Splitting Files)**

```jsx
파일 분할의 필요성:

	큰 파일을 작은 파일로 나누는 작업을 의미합니다.

	주로 큰 파일을 다른 컴퓨터로 전송하거나 제3자에게 제공할 때 유용합니다.

	압축이 불가능하거나 비효율적일 때 파일을 분할하여 처리할 수 있습니다.

파일 분할 명령어 사용:

	split -l number_of_lines filename prefix 명령어를 사용해 파일을 분할할 수 있습니다.

	-l 옵션은 각 분할 파일에 포함될 라인 수를 지정합니다.

	예를 들어, split -l 2 countries Sep를 실행하면, countries 파일을 두 줄씩 분할하여 Sep이라는 접두사를 가진 파일들로 나눕니다.

파일 분할 결과 확인:

	분할된 파일들은 자동으로 Sepaa, Sepab, Sepac 등의 이름으로 생성됩니다.

	각 파일은 두 줄씩 데이터를 포함하며, 남은 데이터가 있는 경우 마지막 파일에 저장됩니다.
```
