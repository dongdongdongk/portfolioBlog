# GitHub API란 무엇인가? (개념적인 부분)

GitHub API는 GitHub 플랫폼의 데이터를 프로그램으로 읽거나 수정할 수 있게 해주는 인터페이스입니다. GitHub은 코드 저장소(Repository)를 관리하는 서비스인데,

이 API를 사용하면 웹 브라우저나 GitHub 앱 없이도 자동으로 사용자 정보 조회, 저장소 목록 가져오기, 이슈 생성 등의 작업을 할 수 있어요. 초보자 관점에서 보면, GitHub API는 "GitHub 서버에 요청을 보내서 답을 받는" 시스템입니다.

- **왜 사용하나요?**
  - 자동화: 예를 들어, 매일 저장소의 스타 수를 확인하거나, 버그 리포트를 자동으로 생성할 때 유용합니다.
  - 통합: 다른 앱(예: 슬랙, 웹사이트)과 GitHub을 연결할 수 있습니다.
  - 데이터 분석: GitHub의 공개 데이터를 모아서 분석할 수 있어요.

GitHub API는 주로 **REST API** 형태로 되어 있어요. REST는 "Representational State Transfer"의 약자로, 간단히 말해 HTTP 프로토콜(웹에서 사용하는 표준)을 이용해 데이터를 주고받는 방식입니다. 주요 개념:

- **엔드포인트(Endpoint)**: API를 호출할 때 사용하는 URL 주소예요. 예: `https://api.github.com/users/octocat` (octocat 사용자의 정보 가져오기).
- **HTTP 메서드**: 요청의 종류를 나타냅니다.
  - GET: 데이터 읽기 (조회).
  - POST: 데이터 생성 (새로운 것 만들기).
  - PUT/PATCH: 데이터 수정.
  - DELETE: 데이터 삭제.
- **인증(Authentication)**: GitHub은 보안을 위해 인증이 필요합니다. 가장 쉬운 방법은 **Personal Access Token (PAT)**입니다.
- GitHub 계정 설정에서 생성할 수 있어요. (설정 > Developer settings > Personal access tokens > Tokens (classic)에서 생성. 필요한 권한 선택하고 복사하세요.)
- **율 제한(Rate Limit)**: 무료로 사용하면 1시간에 60회 요청 제한이 있지만, PAT를 사용하면 5,000회로 늘어요.
- **페이지네이션(Pagination)**: 데이터가 많으면 한 번에 다 주지 않고 페이지로 나눠줍니다. 응답에 `Link` 헤더나 `page` 파라미터로 다음 페이지를 알려줘요.
- **에러 처리**: 요청이 실패하면 HTTP 상태 코드(예: 404 - 찾을 수 없음)와 에러 메시지를 반환합니다. 코드에서 이를 잡아 처리하세요.

API의 기본 베이스 URL은 `https://api.github.com`입니다. 요청 시 헤더에 PAT를 넣어 인증합니다: `Authorization: token YOUR_PAT`.

### GitHub API의 문법적인 부분 (사용법)

API 호출은 HTTP 요청으로 합니다. 기본 문법:

- **헤더(Headers)**: 요청에 포함되는 메타 정보.
  - `Accept: application/vnd.github.v3+json` (API 버전 지정, 추천).
  - `Authorization: token YOUR_PAT` (인증).
  - `User-Agent: YourAppName` (GitHub이 요구함, 앱 이름 넣기).
- **파라미터(Parameters)**: URL 쿼리나 바디에 넣음.
  - GET: URL에 `?key=value`로 붙임.
  - POST: JSON 형식으로 바디에 넣음.
- **응답**: JSON 형식으로 데이터가 돌아옵니다. 성공 시 200대 코드, 실패 시 400/500대.

일반적인 엔드포인트 예시:

- 사용자 정보 조회 (GET): `/users/{username}` → `https://api.github.com/users/octocat`
- 저장소 목록 (GET): `/users/{username}/repos` → `https://api.github.com/users/octocat/repos`
- 이슈 생성 (POST): `/repos/{owner}/{repo}/issues` → `https://api.github.com/repos/octocat/hello-world/issues` (바디: `{"title": "제목", "body": "내용"}`)

공식 문서에서 더 많은 엔드포인트를 확인하세요: [https://docs.github.com/en/rest](https://docs.github.com/en/rest).

### Node.js와 TypeScript로 바로 사용할 수 있는 예제

Node.js에서 GitHub API를 사용하려면 HTTP 라이브러리가 필요합니다. 여기서는 `axios`를 사용하겠습니다. (쉬운 JSON 처리와 에러 핸들링 때문에 추천.) TypeScript로 작성하니, 타입 안전성을 더했습니다.

### 1. 프로젝트 설정 (초보자 단계별)

- Node.js 설치 확인: `node -v` (없으면 node.js.org에서 다운로드).
- 새 폴더 만들기: `mkdir github-api-example` → `cd github-api-example`
- 초기화: `npm init -y`
- 패키지 설치: `npm install axios dotenv typescript @types/node @types/axios`
- TypeScript 설정: `npx tsc --init` (tsconfig.json 생성. "target": "es6", "module": "commonjs"로 설정.)
- .env 파일 생성: `GITHUB_TOKEN=your_pat_here` (PAT 복사 붙여넣기. .gitignore에 .env 추가해 깃에 안 올라가게.)
- 스크립트 실행: package.json에 `"scripts": { "start": "ts-node index.ts" }` 추가. (ts-node 설치: `npm install -g ts-node`)

### 2. 예제 코드 (index.ts 파일에 작성)

이 코드는:

- 사용자 정보 가져오기 (GET).
- 저장소 목록 가져오기 (GET, 페이지네이션 간단 처리).
- 이슈 생성 (POST).
  에러 처리 포함. 바로 복사해서 사용하세요!

```tsx
import axios, { AxiosError, AxiosResponse } from 'axios'
import * as dotenv from 'dotenv'

dotenv.config() // .env 파일 로드

const GITHUB_API_BASE = '<https://api.github.com>'
const GITHUB_TOKEN = process.env.GITHUB_TOKEN

if (!GITHUB_TOKEN) {
  console.error('GITHUB_TOKEN이 .env에 설정되지 않았습니다!')
  process.exit(1)
}

// GitHub API 요청을 위한 Axios 인스턴스 (헤더 기본 설정)
const api = axios.create({
  baseURL: GITHUB_API_BASE,
  headers: {
    Accept: 'application/vnd.github.v3+json',
    Authorization: `token ${GITHUB_TOKEN}`,
    'User-Agent': 'MyGitHubApp', // 당신의 앱 이름으로 변경
  },
})

// 타입 정의 (TypeScript의 장점: 데이터 구조 명확히)
interface User {
  login: string
  name: string
  followers: number
  // 더 많은 필드 추가 가능
}

interface Repo {
  name: string
  description: string
  stargazers_count: number
}

interface Issue {
  title: string
  body: string
}

// 함수: 사용자 정보 가져오기
async function getUser(username: string): Promise<User | null> {
  try {
    const response: AxiosResponse<User> = await api.get(`/users/${username}`)
    console.log(`사용자 정보: ${response.data.name} (팔로워: ${response.data.followers})`)
    return response.data
  } catch (error) {
    handleError(error)
    return null
  }
}

// 함수: 저장소 목록 가져오기 (페이지 1만, 필요시 페이지네이션 추가)
async function getRepos(username: string): Promise<Repo[] | null> {
  try {
    const response: AxiosResponse<Repo[]> = await api.get(`/users/${username}/repos`, {
      params: { per_page: 5 }, // 한 페이지에 5개만 (페이지네이션 예)
    })
    console.log('저장소 목록:')
    response.data.forEach((repo) =>
      console.log(
        `- ${repo.name}: ${repo.description || 'No desc'} (스타: ${repo.stargazers_count})`
      )
    )
    return response.data
  } catch (error) {
    handleError(error)
    return null
  }
}

// 함수: 이슈 생성 (POST)
async function createIssue(
  owner: string,
  repo: string,
  title: string,
  body: string
): Promise<void> {
  try {
    const payload: Issue = { title, body }
    const response: AxiosResponse = await api.post(`/repos/${owner}/${repo}/issues`, payload)
    console.log(`이슈 생성 성공: ${response.data.html_url}`)
  } catch (error) {
    handleError(error)
  }
}

// 에러 처리 함수
function handleError(error: unknown): void {
  if (error instanceof AxiosError) {
    console.error(
      `에러: ${error.response?.status} - ${error.response?.data.message || error.message}`
    )
  } else {
    console.error('알 수 없는 에러:', error)
  }
}

// 실행 예시
async function main() {
  await getUser('octocat') // octocat은 GitHub 마스코트 사용자
  await getRepos('octocat')
  // await createIssue('your-username', 'your-repo', '새 이슈 제목', '이슈 내용'); // 실제로 사용하려면 주석 해제 (자신의 repo로 변경)
}

main()
```

### 3. 실행 및 테스트

- `npm start`로 실행.
- 콘솔에 결과 출력됨.
- 에러 발생 시 (예: 잘못된 토큰) 에러 메시지 보임.
- 페이지네이션: 응답 헤더에 `link`가 있으면 다음 URL 추출해 반복 호출하세요.
- 팁: 실제 앱에서는 Express로 서버 만들어 API 엔드포인트 노출. (예: 처럼.) TypeScript로 변환 시 interface로 타입 추가하면 안전해집니다.

이 예제로 바로 시작할 수 있어요! 더 궁금한 점 있으면 공식 문서 참조하거나 물어보세요.

# GitHubAPI 클래스 전체 설명 ( 블로그 프로젝트 게시글 삭제하기 )

안녕하세요! 이 코드는 TypeScript로 작성된 GitHubAPI 클래스예요. 이 클래스는 GitHub API를 사용해 GitHub 저장소(리포지토리)에서 블로그 파일(주로 Markdown 파일)을 관리하는 서비스예요. 예를 들어,

파일을 가져오거나 삭제하거나 검색하는 기능을 제공하죠. 이는 블로그나 콘텐츠 관리 시스템에서 GitHub를 백엔드로 사용하는 경우에 유용해요.

**주요 동작 원리**:

- **환경 변수 사용**: GITHUB_OWNER (소유자 이름), GITHUB_REPO (저장소 이름), GITHUB_TOKEN (인증 토큰), GITHUB_BRANCH (브랜치, 기본 'main') 같은 환경 변수를 읽어 설정해요. 이걸로 GitHub에 연결합니다.
- **API 요청**: fetch 함수를 사용해 GitHub API에 HTTP 요청을 보내요. 모든 요청에 인증 토큰과 헤더를 붙여요.
- **메서드들**: 파일 가져오기(getFile), 삭제(deleteFile), 검색(searchPostFiles), 제목으로 찾기(findPostByTitle), 블로그 포스트 삭제(deleteBlogPost) 등이 있어요.
- **에러 처리**: 요청이 실패하면 에러를 던지고, 콘솔에 로그를 남겨요.
- **동작 흐름**: 생성자(constructor)에서 설정을 초기화하고, makeRequest 메서드로 모든 API 호출을 처리해요. 각 메서드는 이걸 기반으로 동작합니다.

이 클래스는 Node.js 환경에서 동작하도록 설계됐어요. 예를 들어, Next.js나 Express 같은 서버에서 사용할 수 있어요. 초보자라면, 이 코드를 사용하려면 환경 변수를 설정하고, import 해서 인스턴스를 만들어 메서드를 호출하세요.

이제 원본 코드에 **한 줄 한 줄 주석을 달아** 상세히 설명한 버전을 보여드릴게요. 주석은 // 로 시작하고, 초보자도 이해하기 쉽게 간단한 한국어로 썼어요. 각 줄의 역할과 왜 필요한지 설명했어요.

### 주석이 달린 코드

```tsx
/**
 * GitHub API service for managing blog files
 */ // 이건 클래스 전체에 대한 주석이에요. GitHub API를 사용해 블로그 파일을 관리하는 서비스라고 설명합니다. 초보자: 이 주석은 코드의 목적을 알려줘요.

interface GitHubConfig {
  // GitHub 설정을 위한 인터페이스(틀)를 정의해요. 인터페이스는 객체의 모양을 미리 정하는 거예요.
  owner: string // 저장소 소유자 이름 (예: 'myusername'). string은 문자열 타입이에요.
  repo: string // 저장소 이름 (예: 'myblog').
  token: string // GitHub 인증 토큰 (비밀번호 같은 키).
  branch?: string // 브랜치 이름 (선택적, ?는 옵션이라는 뜻. 기본 'main').
} // 인터페이스 끝. 이걸로 config 객체가 어떤 속성을 가져야 하는지 규칙을 정해요. 초보자: 인터페이스는 실수 방지를 위해 타입을 강제해요.

interface GitHubFile {
  // GitHub 파일 정보를 위한 인터페이스. 파일의 속성들을 정의해요.
  name: string // 파일 이름 (예: 'post.md').
  path: string // 파일 경로 (예: 'content/posts/post.md').
  sha: string // 파일의 SHA 해시 (GitHub에서 파일 버전을 식별하는 고유 코드).
  size: number // 파일 크기 (바이트 단위). number는 숫자 타입.
  url: string // API URL.
  html_url: string // 웹에서 볼 수 있는 HTML URL.
  git_url: string // Git URL.
  download_url: string // 다운로드 URL.
  type: string // 타입 (예: 'file' 또는 'dir').
  content?: string // 파일 내용 (base64 인코딩된 문자열, 옵션).
  encoding?: string // 인코딩 방식 (예: 'base64', 옵션).
} // 인터페이스 끝. GitHub API에서 반환되는 파일 객체의 모양을 맞춰요. 초보자: 이걸로 파일 데이터를 안전하게 다룰 수 있어요.

export class GitHubAPI {
  // GitHubAPI 클래스 내보내기. export는 다른 파일에서 사용할 수 있게 해요. class는 객체의 설계도예요.
  private config: GitHubConfig // 클래스 내부에서만 접근 가능한 config 속성. GitHub 설정을 저장해요.
  private baseUrl = '<https://api.github.com>' // GitHub API 기본 URL. 모든 요청의 시작점.

  constructor() {
    // 클래스 인스턴스를 만들 때 자동 호출되는 생성자 함수.
    this.config = {
      // config 객체 초기화.
      owner: process.env.GITHUB_OWNER || '', // 환경 변수에서 소유자 읽기. 없으면 빈 문자열.
      repo: process.env.GITHUB_REPO || '', // 저장소 이름 읽기.
      token: process.env.GITHUB_TOKEN || '', // 토큰 읽기.
      branch: process.env.GITHUB_BRANCH || 'main', // 브랜치 읽기, 기본 'main'.
    } // config 설정 끝.

    if (!this.config.owner || !this.config.repo || !this.config.token) {
      // 필수 설정이 없으면 체크.
      throw new Error(
        'Missing required GitHub configuration. Please set GITHUB_OWNER, GITHUB_REPO, and GITHUB_TOKEN environment variables.'
      ) // 에러 던지기. 초보자: throw는 프로그램을 멈추고 에러 메시지 보여줘요.
    } // if 끝.
  } // constructor 끝. 초보자: 이 부분은 클래스를 만들 때 설정을 확인해요.

  private async makeRequest(endpoint: string, options: RequestInit = {}) {
    // API 요청을 위한 내부 메서드. private는 클래스 안에서만 사용. async는 비동기(기다림) 처리.
    const url = `${this.baseUrl}${endpoint}` // 기본 URL + 엔드포인트로 전체 URL 만들기. 예: '<https://api.github.com/repos/owner/repo>'.

    console.log(`GitHub API Request: ${url}`) // 콘솔에 요청 URL 로그 남기기. 디버깅용.
    console.log(
      `Using token: ${this.config.token ? this.config.token.substring(0, 10) + '...' : 'NOT SET'}`
    ) // 토큰 일부만 로그. 보안 위해 전체 안 보여줌.

    const response = await fetch(url, {
      // fetch로 HTTP 요청 보내기. await는 응답 기다림.
      ...options, // 추가 옵션 병합 (예: method, body).
      headers: {
        // 헤더 설정.
        Authorization: `token ${this.config.token}`, // 인증 토큰 붙이기.
        Accept: 'application/vnd.github.v3+json', // GitHub API 버전 3 지정.
        'Content-Type': 'application/json', // JSON 형식으로 데이터 주고받기.
        'User-Agent': 'Digital-Marketing-Hub-Blog', // 사용자 에이전트 (앱 이름).
        'X-GitHub-Api-Version': '2022-11-28', // API 버전 헤더.
        ...options.headers, // 추가 헤더 병합.
      }, // headers 끝.
    }) // fetch 끝.

    if (!response.ok) {
      // 응답이 성공(200대)이 아니면.
      const error = await response.text() // 에러 메시지 읽기.
      console.error(`GitHub API Error: ${response.status} ${response.statusText}`) // 에러 로그.
      console.error(`Error details: ${error}`) // 상세 에러 로그.
      throw new Error(`GitHub API error: ${response.status} ${response.statusText} - ${error}`) // 에러 던지기.
    } // if 끝.

    const data = await response.json() // 응답을 JSON으로 변환.
    console.log(`GitHub API Response: Success`) // 성공 로그.
    return data // 데이터 반환.

  async getFile(filePath: string): Promise<GitHubFile> {

  /**
   * Delete a file from the repository
   */ // 메서드 주석: 저장소에서 파일 삭제.
  async deleteFile(filePath: string, message: string): Promise<void> {
    // 파일 삭제. message는 커밋 메시지. void는 아무것도 안 반환.
    try {
      // 에러 잡기 위한 try-catch.
      // First, get the file to obtain its SHA
      const file = await this.getFile(filePath) // 파일 가져와 SHA 얻기. 삭제하려면 SHA 필요.

      const endpoint = `/repos/${this.config.owner}/${this.config.repo}/contents/${filePath}` // 엔드포인트.

      await this.makeRequest(endpoint, {
        // makeRequest로 DELETE 요청.
        method: 'DELETE', // DELETE 메소드.
        body: JSON.stringify({
          // body에 JSON 데이터.
          message, // 커밋 메시지.
          sha: file.sha, // 파일 SHA.
          branch: this.config.branch, // 브랜치.
        }), // body 끝.
      }) // makeRequest 끝.
    } catch (error) {
      // 에러 발생 시.
      if (error instanceof Error) {
        // 에러 타입 체크.
        throw new Error(`Failed to delete file ${filePath}: ${error.message}`) // 새 에러 던지기.
      } // if 끝.
      throw error // 다른 에러는 그대로 던지기.
    } // try-catch 끝.
  } // deleteFile 끝. 초보자: 삭제 전에 파일 SHA를 확인해야 GitHub가 허락해요.
```

### 각 부분의 동작 상세 설명

- **인터페이스 (GitHubConfig, GitHubFile)**: 코드의 타입을 정의해요. TypeScript의 장점으로, 잘못된 데이터 넣으면 컴파일 에러가 나서 안전해요. 동작: 클래스에서 이 타입을 사용해 변수나 반환값을 강제합니다.
- **constructor()**: 클래스를 new GitHubAPI()로 만들 때 호출돼요. 환경 변수를 읽어 config를 세팅하고, 필수 값 없으면 에러. 동작: 초기화 단계로, GitHub 연결 준비를 해요.
- **makeRequest()**: 모든 메서드가 이걸 호출해 API 요청을 보냅니다. URL 만들기 → 로그 → fetch 요청 → 에러 체크 → JSON 반환. 동작: 인증과 헤더를 자동으로 붙여 GitHub와 통신해요. 예: GET으로 파일 가져올 때 사용.
- **getFile()**: 특정 파일의 정보와 내용을 가져와요. 동작: 엔드포인트를 만들어 makeRequest 호출. GitHub가 base64 인코딩된 내용을 줘요.
- **deleteFile()**: 파일을 삭제해요. 동작: 먼저 getFile로 SHA 얻고, DELETE 요청. GitHub는 SHA 없이 삭제 안 해요 (버전 충돌 방지).
- **searchPostFiles()**: 'content/posts' 폴더의 .md 파일 목록을 가져와 패턴으로 필터링. 동작: GET으로 폴더 내용 가져와 배열 필터. 에러 시 빈 배열.
- **findPostByTitle()**: 모든 포스트 파일을 검색해 내용에서 'title: "제목"'을 찾아 매치. 동작: searchPostFiles → 각 파일 getFile → base64 디코딩 → 정규식 매치. 느릴 수 있지만 정확해요.
- **deleteBlogPost()**: 파일명이나 제목으로 포스트 삭제. 동작: 파일명으로 시도 → 실패 시 제목으로 찾기 → deleteFile 호출. 결과 객체 반환으로 성공/실패 알려줘요.

1. **GitHub API 사용**: `GitHubAPI` 클래스는 GitHub의 REST API(`DELETE /repos/{owner}/{repo}/contents/{path}`)를 호출합니다. 파일 삭제 시 파일의 SHA(고유 버전 ID)를 알아야 하므로, 내부적으로 파일 정보를 조회(GET)한 후 삭제 요청(DELETE)을 보냅니다.
2. **인증**: `GitHubAPI` 클래스 내부에서 `GITHUB_TOKEN`(Personal Access Token)을 사용해 인증합니다. 토큰은 `.env` 파일에 저장되어야 합니다.
3. **토큰 검증**: `TokenManager`는 삭제 요청의 유효성을 확인하는 커스텀 클래스입니다. 예: JWT로 토큰을 검증해 파일 이름과 제목을 추출.
4. **GET vs POST**:
   - GET: URL 쿼리로 토큰을 받아 처리, 성공/실패 시 페이지로 리다이렉트.
   - POST: JSON 바디로 토큰을 받아 JSON 응답 반환 (API 클라이언트용).
5. **에러 처리**: HTTP 상태 코드(400, 401, 404, 500)와 메시지로 에러를 명확히 구분해 처리.
6. **GitHub API의 DELETE 요청**: 파일 삭제는 `DELETE /repos/{owner}/{repo}/contents/{path}` 엔드포인트를 호출하며, 요청 바디에 `{ "message": "Delete commit message", "sha": "file_sha" }`를 포함합니다.

### 실행 방법

1. `.env`에 `GITHUB_TOKEN` 설정.
2. `GitHubAPI` 클래스 구현 확인 (예: `lib/github-api.ts`에 axios로 GitHub API 호출 로직 포함).
3. `TokenManager` 구현 확인 (토큰 검증 로직 포함).
4. `npm run dev`로 Next.js 서버 실행.
5. GET 요청: `http://localhost:3000/api/delete-blog?token=your_token`
6. POST 요청: `curl -X POST -H "Content-Type: application/json" -d '{"token":"your_token"}' <http://localhost:3000/api/delete-blog`>

### GitHub API 삭제 요청 예시 (참고)

`GitHubAPI.deleteBlogPost` 내부는 대략 이렇게 생겼을 가능성:

```tsx
async deleteBlogPost(filename: string, title: string) {
  const response = await axios.delete(`https://api.github.com/repos/owner/repo/contents/${filename}`, {
    headers: { Authorization: `token ${process.env.GITHUB_TOKEN}` },
    data: { message: `Delete ${title}`, sha: await getFileSha(filename) }
  });
  return { success: true, deletedFile: filename, message: 'Deleted' };
}

```
