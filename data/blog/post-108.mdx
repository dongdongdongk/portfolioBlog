# 인증과 권한

```jsx
인증 ( AUTHENTICATION )

이란 특정 사용자가 누구인지 확인하거나 그 사용자가 제대로 된 사용자가 맞는지 확인하는 과정

( 인증이란 누군가의 신원을 확인하는 것 )

권한 ( AUTHORIZATION )

권한이란 특정 사용자가 가능한 행동을 확인하는 것을 말한다

접근 가능 대상과 편집, 삭제가 가능한 대상 웹사이트의 어느 부분에 접근이 가능한지 등을 설정

( 보통 권한 부여는 사용자가 인증된 후 일어난다 )
```

# 해시 함수

## **해시 함수 소개**

```jsx
해시 함수는 여러 함수의 집합으로, 다양한 종류와 쓰임새를 가지고 있다.

이는 단순히 암호화에만 국한되지 않고, 컴퓨터 공학에서 해시 테이블이나 해시 맵 등과 관련이 있다.

다양한 분야에서 사용되며, 여러 함수들이 그 일부로 간주될 수 있다.

* 모든 해시 함수가 암호 저장에 적합한 것은 아니다 ( 너무 단순하거나 등등 )
```

## **암호화 해시 함수의 특징**

```jsx
**1. 단방향 함수**

암호화 해시 함수는 단방향 함수로, 한 번 해시된 값을 역추적하여 입력 값을 알아내는 것이 불가능하다 ( 돌아가는게 불가능 )

이 특징은 암호를 안전하게 보호하는 데 중요한 역할을 한다.

사용자의 비밀번호와 같은 민감한 정보를 저장할 때, 이러한 함수를 사용하여 원본 값을 안전하게 숨길 수 있다.

**2. 변화에 민감한 특성**

해시 함수는 입력 값의 작은 변화에도 출력 값이 크게 달라져야 한다.

이는 입력 값의 각 비트가 출력 값에 고르게 영향을 미치게 하는 것을 의미하며,

유사한 입력이라도 출력 값이 전혀 다르게 나와야 한다. 이 특성은 해시 함수의 안전성을 높이고, 입력 값의 다양성을 유지하는 데 도움을 준다.

**3. 결정론적 알고리즘**

해시 함수는 결정론적 알고리즘을 사용하여 동일한 입력 값은 항상 동일한 출력 값을 가져야 한다.

이는 사용자가 로그인할 때마다 같은 비밀번호로 생성된 해시 값과 저장된 해시 값을 비교하여 인증할 수 있게 한다.

결정론적 알고리즘은 예측 가능하고 일관된 결과를 제공함으로써 시스템의 안정성을 유지한다.

**4. 충돌 최소화**

충돌은 서로 다른 입력 값이 동일한 출력 값을 가지는 상황을 의미한다.

암호화 해시 함수에서는 충돌이 최소화되어야 한다.

두 개의 서로 다른 입력 값이 같은 해시 값으로 매핑되면 보안이 약화되고,

해시 함수의 신뢰성이 훼손될 수 있다. 따라서 충돌이 거의 발생하지 않도록 하는 것이 중요하다.

이러한 특징들은 암호화 해시 함수가 안전하게 사용되고 데이터의 무결성을 보호하는 데에 기여한다.

그러나 이외에도 각종 해시 함수가 사용되는 다양한 분야에서의 특징 및 요구사항이 존재하므로,

특정한 상황에 맞게 적절한 함수를 선택하는 것이 중요하다.
```

## **느린 함수의 사용**

```jsx
암호화 해시 함수는 느린 함수를 사용해야 한다.

빠른 함수를 사용하면 침입이 쉬워지므로, 고의적으로 느린 함수를 선택하여 속도를 늦추는 전략이 필요하다.

특히, 고의적으로 느린 함수를 사용함으로써 암호 해시의 보안을 강화할 수 있다.

* 암호를 위한 게 아니라서 빠르게 작동해야 하는 함수도 있다 예전에 쿠키를 다뤘을 때 살펴봤던 것처럼 전자 서명 등에

이용되는 함수들이다 그때 쿠키를 서명한 암호화 해시 함수가 SHA-256 이다
```

## **솔트의 필요성과 동작 원리**

```jsx
1 솔트 개념

솔트를 사용하는 이유는 동일한 암호에 대해 항상 동일한 해시 값을 얻지 못하게 하기 위함이다.

솔트는 무작위 값을 암호에 추가하는데, 이를 통해 미리 계산된 해시 테이블 공격을 어렵게 만든다.

2 솔트의 실제 활용

Bcrypt와 같은 라이브러리를 사용하여 솔트를 자동으로 생성하고, 사용자 암호에 솔트를 추가하여 해시를 생성한다.

이를 통해 미리 계산된 테이블을 사용한 대입 공격을 방지한다.

3 솔트의 보안성

솔트를 추가함으로써 해커들이 암호를 미리 계산한 테이블을 사용하여 암호를 찾는 것을 어렵게 만든다.

 각각의 암호에 대해 다른 솔트를 사용하면서 출력 값을 완전히 다르게 만든다.
```

## **Bcrypt 패키지 선택: `bcrypt` vs. `bcrypt.js`**

```jsx
bcrypt 패키지:  npm i bcrypt

C++로 구현되어 있어 속도가 빠르며 Node.js 서버에서 사용하기 적합. 브라우저에서는 실행 불가.
```

```jsx
bcrypt.js 패키지:  npm i bcrypt.js

 JavaScript로만 작성되어 브라우저에서도 실행 가능. 주간 다운로드 수는 bcrypt와 유사.
```

## **Bcrypt 사용예제**

```jsx
const bcrypt = require('bcrypt')

async function hashPassword(pw) {
  const saltRound = 12
  const salt = await bcrypt.genSalt(saltRound)
  console.log('Generated Salt:', salt)

  const hash = await bcrypt.hash(pw, salt)
  console.log('Hashed Password:', hash)
}

async function login(pw, hashedPw) {
  const result = await bcrypt.compare(pw, hashedPw)
  if (result) {
    console.log('LOGGED YOU IN! SUCCESSFUL MATCH!')
  } else {
    console.log('INCORRECT!')
  }
}

// 예제 실행
hashPassword('monkey')
login('monkey', 'hashed_password_from_database')
```

## **Bcrypt 주요 메서드 설명**

```jsx
genSalt(rounds: number): Promise<string>

암호의 솔트를 생성한다.

rounds: 해시의 난이도를 나타내는 숫자. 클수록 더 복잡한 해시가 생성된다.

hash(data: string, salt: string): Promise<string>

솔트와 함께 주어진 데이터를 해시화 한다.

data: 해시할 데이터 (평문 암호).

salt: genSalt 메서드로 생성된 솔트.

compare(data: string, hashedData: string): Promise<boolean>

주어진 데이터와 이미 해시된 데이터를 비교한다.

반환값은 일치하면 true, 불일치하면 false.
```

## **주의사항**

```jsx
해시의 난이도(rounds)를 적절히 설정하여 보안을 강화할 수 있다. 현재 추천되는 값은 12 정도이다.

솔트는 해시에 무작위성을 부여하며, 별도로 저장하지 않아도 해시된 결과에 포함되어 있다.

사용자 로그인 시 compare 메서드를 사용하여 입력된 암호를 저장된 해시 값과 비교할 수 있다.
```

## index.js

```jsx
const express = require('express')
const cors = require('cors')
const User = require('./models/user')
const mongoose = require('mongoose')
const app = express()
const bcrypt = require('bcrypt')

app.use(express.urlencoded({ extended: true }))
app.use(express.json()) // 쿼리스트링
app.use(cors())

main().catch((err) => console.log(err))

async function main() {
  await mongoose.connect('mongodb://127.0.0.1:27017/authDemo') // 마지막 부분이 DB명
  console.log('Mongo Connect Success')
}
// 연결 확인 코드
const db = mongoose.connection // MongoDB 연결에 대한 정보를 얻는다. 이 정보를 db 변수에 할당
db.on('error', console.error.bind(console, 'connection error'), {
  useNewUrlParser: true, // 최신 버전의 드라이버와의 호환성을 유지
  useUnifiedTopology: true,
})
db.once('open', () => {
  // 한 번만 실행되는 이벤트 리스너 등록 MongoDB에 성공적으로 연결되었을 때 메세지
  console.log('Database connected')
})

// 사용자 등록 엔드포인트
app.post('/register', async (req, res) => {
  // 클라이언트에서 전송된 사용자 정보를 받아옵니다.
  const { password, username } = req.body

  // 받아온 비밀번호를 bcrypt를 사용해 해시값으로 변환합니다.
  const hash = await bcrypt.hash(password, 12)

  // 새로운 사용자 객체를 생성하고 MongoDB에 저장합니다.
  const user = new User({
    username,
    password: hash,
  })
  await user.save()

  // 클라이언트에게 해시값을 응답으로 보냅니다.
  res.send(hash)
})

// 사용자 로그인 엔드포인트
app.post('/login', async (req, res) => {
  // 클라이언트에서 전송된 사용자 정보를 받아옵니다.
  const { username, password } = req.body

  // MongoDB에서 해당 사용자를 찾습니다.
  const user = await User.findOne({ username }) // 사용자명이 고유하다고 가정하고 있기 때문에 findOne

  // 비밀번호를 bcrypt.compare를 사용해 해시와 비교하여 인증을 수행합니다.
  const validPassword = await bcrypt.compare(password, user.password)

  // 인증이 성공하면 "Success"를, 실패하면 "Fail"을 클라이언트에게 응답으로 보냅니다.
  if (validPassword) {
    res.send('Success')
  } else {
    res.send('Fail')
  }
})

app.listen(4000, () => {
  console.log('Success')
})
```

## Login.jsx

```jsx
import axios from 'axios'
import { useState } from 'react'
import { Link, useNavigate } from 'react-router-dom'

const Login = () => {
  const navigate = useNavigate()

  //상태 초기화
  const [formData, setFormData] = useState({
    username: '',
    password: '',
  })

  // 입력값 변경 핸들러
  const handleChange = (e) => {
    const { name, value } = e.target
    setFormData((prevDate) => ({
      ...prevDate,
      [name]: value,
    }))
  }

  // 폼 제출 핸들러
  const onSubmitHandler = async (e) => {
    e.preventDefault()

    const form = e.currentTarget

    // 폼 데이터 전송
    try {
      await axios.post('http://localhost:4000/login', formData)
      // navigate('/')
    } catch (error) {
      console.error('SAVE FAIL', error)
    }
  }

  return (
    <>
      <h1>SignUp</h1>
      <form onSubmit={onSubmitHandler}>
        <div>
          <label htmlFor="username">Enter Username:</label>
          <input
            type="text"
            name="username"
            id="username"
            value={formData.username}
            onChange={handleChange}
          />
        </div>
        <div>
          <label htmlFor="password">Enter PassWord:</label>
          <input
            type="text"
            name="password"
            id="password"
            value={formData.password}
            onChange={handleChange}
          />
        </div>
        <button type="submit">Submit</button>
      </form>
    </>
  )
}

export default Login
```

```jsx
import axios from 'axios'
import Secret from './pages/secret'
import Login from './pages/login'
import Register from './pages/register'
import Home from './pages/home'

function App() {
  // 로그인 상태와 사용자 정보를 관리하는 state
  const [loggedIn, setLoggedIn] = useState(false)
  const [user, setUser] = useState(null)

  // React Router의 네비게이션을 활용하기 위한 함수

      {/* 네비게이션을 위한 링크 목록 */}
      <ul>
        <li>
          <Link to="/">Home</Link>
        </li>
        <li>
          {/* 로그인 상태에 따라 로그인 또는 로그아웃 버튼 및 Secret 페이지로 이동하는 링크 표시 */}
          {loggedIn ? (
            <>
              <button onClick={() => setLoggedIn(false)}>Logout</button>
              <Link to="/secret">Secret</Link>
            </>
          ) : (
            <Link to="/login">Login</Link>
          )}
        </li>
      </ul>

      {/* 페이지 컴포넌트를 라우팅하기 위한 Routes 컴포넌트 */}
      <Routes>
        {/* Home 페이지: 로그인된 상태에서만 접근 가능, 사용자 정보 전달 */}
        <Route path="/" element={loggedIn ? <Home user={user} /> : <Navigate to="/" />} />
        {/* Login 페이지: 로그인되지 않은 상태에서만 접근 가능 */}
        <Route path="/login" element={<Login />} />
        {/* Register 페이지: 로그인되지 않은 상태에서만 접근 가능 */}
        <Route path="/register" element={<Register />} />
        {/* Secret 페이지: 로그인된 상태에서만 접근 가능, 사용자 정보 전달 */}
        <Route path="/secret" element={loggedIn ? <Secret user={user} /> : <Navigate to="/" />} />
      </Routes>
    </div>
  )
}

export default App
```

```jsx
const mongoose = require('mongoose')
const bcrypt = require('bcrypt')
const userSchema = new mongoose.Schema({
  username: {
    type: String,
    required: [true, 'UserName Required'],
  },
  password: {
    type: String,
    required: [true, 'Password Required'],
  },
})

userSchema.statics.findAndValidate = async function (username, password) {
  const foundUser = await this.findOne({ username })
  const isValid = await bcrypt.compare(password, foundUser.password)
  return isValid ? foundUser : false
}

module.exports = mongoose.model('User', userSchema)
```

```jsx
User 모델에 정적 메서드를 선언해준다

username 과 password 를 받아서

예전 방식과 같이 username 으로 유저를 찾고

compare 을 사용해서 비밀번호를 비교한다

그리고 3항 연산자를 사용해서 찾은 유저를 반환 하거나 false 를 반환한다
```

## 회원 가입 리팩터링

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381416/notion-blog/_/The_Web_Developer_2022/node_js/_/Untitled_7.png)

```jsx
userSchema.pre('save', async function (next) {
  if (!this.isModified('password')) return next()
  this.password = await bcrypt.hash(this.password, 12)
  next()
})
```

```jsx
Mongoose의 pre 미들웨어를 사용하여 데이터베이스에 저장하기 전에 실행되는 코드이다.

save 메서드가 호출되기 전에 이 미들웨어가 실행된다. 이 미들웨어는 비밀번호를 해싱하는 역할을 한다.

this: 현재 작업 중인 문서(document)를 나타낸다. 여기서는 User 모델의 인스턴스를 나타낸다.

bcrypt.hash: bcrypt 라이브러리를 사용하여 비밀번호를 해싱하는 함수이다. this.password는 현재 사용자 인스턴스의 비밀번호를 나타낸다.

next(): pre 미들웨어가 완료되었음을 알리고, 다음 단계로 진행할 수 있도록 콜백 함수를 호출한다.

this.isModified('password'): 현재 문서의 'password' 필드가 변경되었는지 여부를 확인하는 Mongoose의 메서드

이 메서드는 이전과 현재의 필드 값을 비교하여 변경 여부를 판단

( 이 코드는 주로 사용자 정보를 업데이트할 때, 비밀번호 필드가 변경되었을 때만 해당 비밀번호를 해싱하도록 하는 용도로 활용된다.

	왜냐하면 비밀번호가 변경되지 않았다면 이미 해싱되어 있는 값이 그대로 사용되기 때문이다.

	이렇게 함으로써 불필요한 해싱 연산을 피하고 성능을 최적화할 수 있다. )

* 쉽게 말하면 여기서 this 는 현재 추가되는 save() 되는 유저의 password 를 말하는거
```
