# 양방향 단방향

```java
양방향, 단방향이 존재하는데 이는 데이터 베이스에서 존재하는것이 아니다

요즘 트렌드에서는 가능한 단방향으로 설계를 잡는걸 추구한다

단방향 관계 (1-way):

한 엔티티에서 다른 엔티티를 참조할 수 있지만, 반대로는 참조할 수 없는 경우
예를 들어, 부서(Department) 엔티티가 사원(Employee) 엔티티를 참조할 수 있지만, 사원은 부서를 알 필요가 없는 경우

양방향 관계 (2-way):

양쪽 엔티티가 서로를 참조할 수 있는 경우
예를 들어, 부서(Department) 엔티티가 사원(Employee)을 참조하고 동시에 사원도 어떤 부서에 속하는지를 알고 있는 경우
```

### 무한 순환 참조 (Infinite Recursion):

```java

Board 클래스에서 writer 필드가 있는데, 이 필드의 타입이 member 클래스로 지정되어 있다.

@ToString 어노테이션을 사용하지 않고 toString() 메서드를 생성하면, 이 때 writer 필드를 포함하여 문자열 표현을 만들려고 할 때 member 클래스의 toString() 메서드가 호출될 수 있다.

그런데 만약 member 클래스에서 다시 Board 클래스를 참조하는 형태의 코드가 있다면, 무한 순환 참조가 발생하여 스택 오버플로우나 무한 루프 등의 에러가 발생할 수 있다.
```
