# { Room Node Graph Editor 구현 }

```jsx
이 강의는 Unity에서 커스텀 편집기 창을 만들어 간단한 노드 그래프 에디터를 구현하는 과정을 다룹니다.
```

## 1. 프로젝트 구조 설정

```jsx
목표: 편집기 스크립트를 체계적으로 관리하기 위해 폴더를 구성.

단계:

		1 Assets 폴더에서 새 폴더 생성:

				Scripts 폴더: 모든 스크립트 저장.

				NodeGraph 폴더: 노드 그래프 관련 스크립트 저장.

				Editor 폴더: Unity가 편집기 스크립트로 인식하도록 필수. (Unity는 Editor 폴더 내 스크립트를 편집기용으로 간주)

		2. Editor 폴더 내에 C# 스크립트 생성: 이름은 RoomNodeGraphEditor.


개념:

		Editor 폴더: Unity에서 커스텀 에디터 스크립트를 저장하는 특수 폴더. 이 폴더에 있는 스크립트는 게임 런타임이 아닌 Unity 편집기에서만 실행됨.

		스크립트 정리: 폴더 구조를 체계적으로 구성하면 유지보수가 쉬워짐.
```

```jsx

[MenuItem]: Unity 메뉴에 사용자 지정 항목을 추가. 경로를 지정해 메뉴 위치 설정 (예: Window > Dungeon > Room Node Graph Editor).

GetWindow<T>: 지정한 타입의 편집기 창을 열거나, 이미 열려 있으면 포커스. 제목도 설정 가능.
```

### 3. OnEnable 메서드에서 스타일 초기화:

```csharp
// OnEnable 메서드는 Unity의 MonoBehaviour 생명주기 메서드로,
// 해당 스크립트가 활성화될 때 호출됩니다.
private void OnEnable()
{
    // 새로운 GUIStyle 객체를 생성하여 roomNodeStyle 변수에 할당합니다.
    // GUIStyle은 Unity 에디터에서 GUI 요소의 시각적 스타일을 정의하는 데 사용됩니다.
    roomNodeStyle = new GUIStyle();

    // roomNodeStyle의 기본 상태(normal) 배경 텍스처를 설정합니다.
    // EditorGUIUtility.Load를 사용하여 "node1"이라는 이름의 텍스처를 로드하고 Texture2D로 캐스팅합니다.
    // "node1"은 Unity 에디터의 기본 노드 텍스처로, 노드 그래프 UI에서 자주 사용됩니다.
    roomNodeStyle.normal.background = EditorGUIUtility.Load("node1") as Texture2D;

    // roomNodeStyle의 기본 상태 텍스처에 표시될 텍스트 색상을 흰색(Color.white)으로 설정합니다.
    roomNodeStyle.normal.textColor = Color.white;

    // roomNodeStyle의 패딩(padding)을 설정합니다.
    // RectOffset은 사각형의 네 변(왼쪽, 오른쪽, 위, 아래)에 여백을 정의하는 클래스입니다.
    // 여기서 nodePadding 값(별도로 정의된 상수로 추정)을 사용하여
    // 왼쪽, 오른쪽, 위, 아래 모두 동일한 패딩 값을 적용합니다.
    // 예: nodePadding이 10이라면, 콘텐츠와 경계 사이에 10픽셀의 여백이 생깁니다.
    roomNodeStyle.padding = new RectOffset(nodePadding, nodePadding, nodePadding, nodePadding);

    // roomNodeStyle의 테두리(border)를 설정합니다.
    // RectOffset을 사용하여 테두리의 두께를 정의하며,
    // nodeBorder 값(별도로 정의된 상수로 추정)을 네 변에 적용합니다.
    // 테두리는 GUI 요소의 외곽선을 그리는 데 사용되며,
    // 예를 들어 nodeBorder가 5라면 각 변에 5픽셀 두께의 테두리가 추가됩니다.
    roomNodeStyle.border = new RectOffset(nodeBorder, nodeBorder, nodeBorder, nodeBorder);
}
```

```jsx
개념:

OnEnable: 스크립트가 활성화될 때 호출. 초기화 작업에 적합.

EditorGUIUtility.Load: Unity의 내장 자산(예: node1 텍스처)을 로드. node1은 노드 배경으로 적합한 기본 텍스처.

padding/border: UI 요소의 내부 여백과 외부 테두리 크기 설정.
```

## 4. 노드 그리기 (OnGUI)

### 1. OnGUI 메서드 구현

```jsx
Unity는 OnGUI를 사용해 편집기 창의 UI를 그림. 창이 갱신될 때마다 호출됨.

두 개의 노드를 각각 다른 위치에 그림
```

```csharp
// OnGUI 메서드는 Unity의 IMGUI 시스템에서 사용되며,
// 에디터 창이나 커스텀 GUI를 그릴 때마다 프레임마다 호출됩니다.
private void OnGUI()
{
    // GUILayout.BeginArea는 지정된 사각형 영역(Rect) 내에서 GUI 요소를 그리기 시작합니다.
    // Rect는 위치와 크기를 정의하며, 여기서는 Vector2로 위치와 크기를 설정합니다.
    // - new Vector2(100f, 100f): 화면에서 x=100, y=100 픽셀 위치에 노드를 배치.
    // - new Vector2(nodeWidth, nodeHeight): 노드의 너비와 높이를 nodeWidth, nodeHeight로 설정.
    //   (nodeWidth와 nodeHeight는 클래스 내에서 정의된 변수로 추정).
    // roomNodeStyle은 이전에 정의된 GUIStyle로, 노드의 배경, 패딩, 테두리 등을 스타일링.
    GUILayout.BeginArea(new Rect(new Vector2(100f, 100f), new Vector2(nodeWidth, nodeHeight)), roomNodeStyle);

    // EditorGUILayout.LabelField는 지정된 텍스트를 라벨로 표시합니다.
    // "Node 1"이라는 텍스트를 현재 영역(BeginArea로 정의된 사각형) 내에 렌더링.
    // EditorGUILayout은 Unity 에디터 전용 레이아웃 기반 GUI 메서드로, 자동으로 레이아웃을 관리.
    EditorGUILayout.LabelField("Node 1");

    // GUILayout.EndArea는 BeginArea로 시작한 영역을 종료합니다.
    // 이로써 첫 번째 노드의 GUI 그리기가 완료됩니다.
    GUILayout.EndArea();

    // 두 번째 노드를 그리기 위해 새로운 영역을 시작합니다.
    // - new Vector2(300f, 300f): x=300, y=300 픽셀 위치에 노드를 배치.
    // - new Vector2(nodeWidth, nodeHeight): 첫 번째 노드와 동일한 크기 사용.
    // 동일한 roomNodeStyle을 사용하여 일관된 스타일을 적용.
    GUILayout.BeginArea(new Rect(new Vector2(300f, 300f), new Vector2(nodeWidth, nodeHeight)), roomNodeStyle);

    // 두 번째 노드에도 "Node 1"이라는 라벨을 표시.
    // 동일한 텍스트를 사용했으므로 두 노드는 시각적으로 비슷해 보입니다.
    EditorGUILayout.LabelField("Node 1");

    // 두 번째 영역을 종료하여 GUI 그리기를 마무리.
    GUILayout.EndArea();
}
```

```jsx
개념:

OnGUI: 편집기 창의 UI를 그리기 위해 호출. 마우스 클릭, 이동 등 이벤트에 반응해 자주 호출됨.

GUILayout.BeginArea/EndArea: 특정 화면 영역에 UI를 그림. Rect로 위치와 크기 지정.

EditorGUILayout.LabelField: 텍스트 라벨을 그림. 여기선 "Node 1" 표시.

Rect: 위치(x, y)와 크기(width, height)를 정의하는 구조체.
```

# { Unity ScriptableObject를 활용한 Room Node Graph 구현 }

```csharp
이 강의는 Unity에서 ScriptableObject를 사용해 던전의 방 노드 그래프(Room Node Graph)를 구성하는

데이터 구조를 설계하고 구현하는 과정을 다룹니다.
```

## 1. ScriptableObject란?

```csharp
정의: ScriptableObject는 Unity에서 데이터를 저장하고 관리하기 위한 클래스입니다.

		  일반적으로 MonoBehaviour를 상속받는 스크립트는 게임 오브젝트에 붙지만,

		  ScriptableObject는 독립적인 데이터 컨테이너로 사용됩니다.


주요 특징:

		데이터 저장: Unity 에디터에서 입력한 데이터는 에셋으로 저장되어 런타임과 에디터에서 사용 가능.

		에셋 생성: Unity 메뉴를 통해 .asset 파일로 생성.

		용도: 게임 설정, 캐릭터 데이터, 방 구조 등 정적 데이터를 관리.

		장점: 코드와 데이터를 분리해 유지보수와 확장성을 높임.


활용 예: 이 강의에서는 던전의 방 노드와 타입을 저장해 노드 그래프를 구성.
```

## 2. Room Node Graph 데이터 구조

```csharp
던전의 방 노드 그래프는 계층적 구조로, 노드(방) 간 부모-자식 관계를 통해 던전 레이아웃을 표현합니다. 아래는 데이터 구조의 개요입니다.
```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380409/notion-blog/_/2D_/_5_Dungeon_Room_Editor/image_5.png)

### **데이터 구조 다이어그램**

```csharp
1. RoomNodeGraphSO:

		전체 그래프를 나타내는 최상위 ScriptableObject.

		모든 방 노드와 타입 리스트를 관리.

2. RoomNodeSO:

		개별 방 노드를 나타냄.

		고유 ID, 부모/자식 노드 ID, 방 타입 등을 저장.

3. RoomNodeTypeSO:

		방의 타입(예: 입구, 보스 방, 복도)을 정의.

		Boolean 플래그로 타입 특성을 표시.

4. RoomNodeTypeListSO:

		모든 방 타입을 리스트로 관리.

		Enum 대신 유연한 데이터 관리.

계층 구조

		노드 연결: 각 노드는 GUID(Globally Unique Identifier)로 식별되며, 부모와 자식 노드의 ID를 리스트로 저장.

		예: 노드 ID 1은 자식 노드 ID 2, 3을 가짐. 노드 ID 2는 부모 ID 1을 가짐.

		특징: 던전에서는 단일 부모만 가지지만, 다중 부모를 지원하도록 설계해 다른 프로젝트(예: 대화 시스템)에서도 활용 가능.

		용도: 노드 그래프 에디터에서 노드를 배치하고 연결해 던전 구조를 시각적으로 구성.
```

## 3. 클래스별 상세 코드 및 설명

```csharp
강의에서 생성한 각 클래스의 코드와 역할, 그리고 주요 요소를 상세히 설명합니다.
```

### (1) RoomNodeGraphSO

```csharp
역할: 전체 방 노드 그래프를 관리하는 ScriptableObject. 모든 노드와 타입 리스트를 포함.

주요 요소:

		[CreateAssetMenu]: Unity 에디터의 Assets > Create 메뉴에 이 클래스를 추가해 .asset 파일 생성 가능.

				fileName: 기본 파일 이름("RoomNodeGraph").

				menuName: 메뉴 경로("Scriptable Objects/Dungeon/Room Node Graph").

		[HideInInspector]: 인스펙터에서 필드를 숨김. 에디터에서 노출되지 않도록 설정.

		roomNodeTypeList: 모든 방 타입을 포함하는 리스트 참조.

		roomNodeList: 그래프 내 모든 방 노드를 저장하는 리스트.

		roomNodeDictionary: GUID를 키로 사용해 노드를 빠르게 조회.

설명: 이 클래스는 던전의 전체 구조를 관리하며, 노드 그래프 에디터에서 생성된 데이터를 저장.

* 딕셔너리(Dictionary) 타입 설명

		정의: Dictionary<TKey, TValue>는 C#에서 제공하는 키-값 쌍을 저장하는 컬렉션입니다. 키를 사용해 값을 빠르게 조회할 수 있습니다.

		키(Key): 고유한 식별자(여기서는 string 타입의 GUID).

		값(Value): 키에 연결된 데이터(여기서는 RoomNodeSO 객체).

		예: roomNodeDictionary["1234-5678"] → 특정 RoomNodeSO 반환.
```

### (5) HelperUtilities

```jsx
역할: 데이터 검증을 위한 정적 유틸리티 클래스.

주요 요소:

		정적 클래스: static으로 선언해 인스턴스화 없이 호출 가능(예: HelperUtilities.ValidateCheckEmptyString).

		ValidateCheckEmptyString: 문자열이 비어 있는지 확인하고, 비어 있으면 콘솔에 오류 메시지 출력.

		ValidateCheckEnumerableValues: 리스트/배열이 null이거나, 비어 있거나, null 요소를 포함하는지 확인.

		반환값: 오류가 있으면 true, 없으면 false.

설명: ScriptableObject 데이터의 무결성을 보장하며, 에디터에서 실수로 누락된 데이터를 감지.
```

```csharp
using UnityEngine; // Unity의 Debug.Log 등을 사용하기 위한 네임스페이스

// 정적 유틸리티 클래스: 인스턴스화 없이 직접 호출 가능 (예: HelperUtilities.메서드명)
public static class HelperUtilities
{
    // 문자열이 비어 있는지 확인하는 메서드
    // 매개변수:
    // - thisObject: 검증 중인 오브젝트 (예: ScriptableObject 에셋)
    // - fieldName: 검증 대상 필드의 이름 (예: "roomNodeTypeName")
    // - stringToCheck: 확인할 문자열 값
    // 반환: 비어 있으면 true (오류), 아니면 false
    public static bool ValidateCheckEmptyString(Object thisObject, string fieldName, string stringToCheck)
    {
        if (stringToCheck == "") // 문자열이 비어 있는지 확인
        {
            // 오류 메시지 출력: 필드 이름과 오브젝트 이름을 포함
            Debug.Log(fieldName + " is empty and must contain a value in object " + thisObject.name);
            return true; // 오류 발생
        }
        return false; // 정상
    }

    // 리스트/배열이 null이거나 비어 있거나 null 요소를 포함하는지 확인
    // 매개변수:
    // - thisObject: 검증 중인 오브젝트
    // - fieldName: 검증 대상 필드의 이름
    // - enumerableObjectToCheck: 검사할 리스트/배열 (IEnumerable 타입)
    // 반환: 오류가 있으면 true, 없으면 false
    public static bool ValidateCheckEnumerableValues(Object thisObject, string fieldName, IEnumerable enumerableObjectToCheck)
    {
        bool error = false; // 오류 플래그 초기화
        int count = 0; // 유효한 요소 개수 카운트

        // 리스트/배열 자체가 null인지 확인
        if (enumerableObjectToCheck == null)
        {
            Debug.Log(fieldName + " is null in object " + thisObject.name);
            return true; // 오류: 리스트가 null
        }

        // 리스트/배열의 각 요소를 순회
        foreach (var item in enumerableObjectToCheck)
        {
            if (item == null) // 요소가 null인지 확인
            {
                Debug.Log(fieldName + " has null values in object " + thisObject.name);
                error = true; // 오류: null 요소 발견
            }
            else
            {
                count++; // 유효한 요소 카운트 증가
            }
        }

        // 요소가 하나도 없는 경우 확인
        if (count == 0)
        {
            Debug.Log(fieldName + " has no values in object " + thisObject.name);
            error = true; // 오류: 리스트가 비어 있음
        }

        return error; // 최종 오류 여부 반환
    }
}
```

## 주요 개념 정리

```jsx
1. GameResources 클래스와 싱글톤 패턴

		GameResources는 게임 전반에서 공유되는 리소스(예: RoomNodeTypeListSO)를 저장하는 중앙 저장소 역할을 함.

		싱글톤 패턴을 변형하여 사용: static 변수 instance를 통해 전역적으로 접근 가능. 첫 호출 시 Resources 폴더에서 프리팹을 로드해 초기화.

		장점: 모든 스크립트에서 동일한 리소스에 쉽게 접근 가능하며, Unity 에디터에서 직렬화된 데이터를 유지.

2. Resources 폴더

		Unity에서 Resources 폴더는 Resources.Load<T>() 메서드로 런타임에 에셋을 로드할 수 있는 특수 폴더.
```

## 1. 프로젝트 설정 및 초기화

### 1.1 개념: Unity Editor와 ScriptableObject

```csharp
Unity Editor: Unity는 개발자가 에디터 환경을 커스터마이징할 수 있도록 EditorWindow 클래스를 제공합니다.
```

## 2. 에셋 더블 클릭 처리

### 2.1 개념: OnOpenAsset 콜백

```csharp
UnityEditor.Callbacks 네임스페이스의 [OnOpenAsset] 속성은 에셋을 더블 클릭했을 때 호출되는 정적 메서드를 정의합니다.

EditorUtility.InstanceIDToObject: 에셋의 인스턴스 ID를 객체로 변환.

용도: 특정 에셋(RoomNodeGraphSO)을 더블 클릭하면 에디터 창을 열고 해당 그래프를 로드.
```

### 2.2 코드 흐름: OnDoubleClickAsset

```csharp
OnDoubleClickAsset 메서드는 더블 클릭된 에셋이 RoomNodeGraphSO인지 확인하고, 맞다면 에디터 창을 열어 현재 그래프를 설정.
```

```csharp
// Unity 에디터에서 에셋을 더블 클릭했을 때 호출되는 메서드를 정의하는 속성
// (0)은 실행 우선순위를 나타내며, 여러 OnOpenAsset 메서드가 있을 때 이 메서드가 먼저 실행됨
[OnOpenAsset(0)]
// 정적 메서드로, 에셋의 인스턴스 ID와 줄 번호를 받아 처리
// 반환값: true(에셋 열기 처리 완료), false(처리 안 함)
public static bool OnDoubleClickAsset(int instanceID, int line)
{
    // instanceID를 사용해 더블 클릭된 에셋을 RoomNodeGraphSO 타입의 객체로 변환
    // EditorUtility.InstanceIDToObject: Unity 에디터에서 에셋의 고유 ID를 실제 객체로 매핑
    // as RoomNodeGraphSO: 객체가 RoomNodeGraphSO 타입이 아니면 null 반환
    RoomNodeGraphSO roomNodeGraph = EditorUtility.InstanceIDToObject(instanceID) as RoomNodeGraphSO;

    // roomNodeGraph가 null이 아니면 더블 클릭된 에셋이 RoomNodeGraphSO 타입임
    if (roomNodeGraph != null)
    {
        // OpenWindow 메서드를 호출해 RoomNodeGraphEditor 창을 엶
        // 이 창은 방 노드 그래프를 시각적으로 편집하는 에디터 창
        OpenWindow();

        // 현재 선택된 그래프를 roomNodeGraph로 설정
        // currentRoomNodeGraph는 정적 변수로, 에디터 창에서 작업할 그래프 데이터를 저장
        currentRoomNodeGraph = roomNodeGraph;

        // true 반환: Unity에 이 메서드가 에셋 열기를 성공적으로 처리했음을 알림
        return true;
    }

    // roomNodeGraph가 null이면 RoomNodeGraphSO 타입의 에셋이 아님
    // false 반환: Unity에 이 메서드가 에셋 열기를 처리하지 않았음을 알림
    return false;
}
```

```csharp
설명:

		[OnOpenAsset(0)]: 0은 메서드 실행 우선순위를 나타내며, 여러 메서드가 있을 경우 순서를 정의.

		OpenWindow: EditorWindow.GetWindow를 호출해 에디터 창을 염
```

```csharp
private static void OpenWindow()
{
    GetWindow<RoomNodeGraphEditor>("Room Node Graph Editor");
}
```

```csharp
currentRoomNodeGraph: 현재 선택된 그래프를 저장하는 정적 변수.
```

### as 연산자란?

```csharp
C#의 as 연산자는 객체를 특정 타입으로 안전하게 형변환하는 데 사용됩니다. 주요 특징은 다음과 같습니다:

		형식: object as Type

				object: 형변환하려는 객체.

				Type: 변환하려는 대상 타입.


		동작:

				객체가 지정된 타입(Type)이거나 그 타입의 파생 클래스라면 해당 타입으로 변환하여 반환.

				객체가 해당 타입이 아니면 null을 반환.

안전성: 일반적인 형변환((Type)object)과 달리, as는 타입이 맞지 않을 경우 예외(InvalidCastException)를 던지지 않고 null을 반환하여 코드 안정성을 높임.
```

```csharp
object obj = "Hello";
string str = obj as string; // obj가 string이므로 str = "Hello"
object num = 123;
string str2 = num as string; // num은 string이 아니므로 str2 = null
```

```csharp
private void ProcessEvents(Event currentEvent)
{

private void ProcessRoomNodeGraphEvents(Event currentEvent)
{
    // currentEvent.type을 확인하여 이벤트 종류에 따라 분기
    // switch 문으로 깔끔하게 이벤트별 처리 로직 분리

    {
        // 마우스 클릭 이벤트가 발생했을 때
        case EventType.MouseDown:
            // 마우스 클릭 이벤트를 처리하는 메서드 호출
            ProcessMouseDownEvent(currentEvent);
            break;

        // 다른 이벤트 타입은 처리하지 않음
        // 필요 시 여기에 추가 이벤트 처리 로직을 확장 가능
        default:
            break;
    }
}

// currentEvent를 받아 클릭된 마우스 버튼을 확인
private void ProcessMouseDownEvent(Event currentEvent)
{

    if (currentEvent.button == 1)

        ShowContextMenu(currentEvent.mousePosition);
    }
}
```

```csharp
    RoomNodeSO roomNode = ScriptableObject.CreateInstance<RoomNodeSO>();

    // 생성한 노드를 현재 그래프의 노드 리스트에 추가
    // currentRoomNodeGraph.roomNodeList: RoomNodeGraphSO가 관리하는 노드 목록
    currentRoomNodeGraph.roomNodeList.Add(roomNode);

    // 노드의 초기 설정 (위치, 크기, 그래프, 타입)

    roomNode.Initialise(new Rect(mousePosition, new Vector2(nodeWidth, nodeHeight)), currentRoomNodeGraph, roomNodeType);

    AssetDatabase.SaveAssets();
```

### AssetDatabase.SaveAssets();

```csharp
무엇을 하나?:

		이 줄은 Unity의 에셋 데이터베이스에 적용된 변경 사항(예: RoomNodeSO 추가)을 디스크에 저장합니다.

		Unity는 메모리에서 에셋 변경을 추적하지만, SaveAssets를 호출해야 실제 파일 시스템(하드 드라이브)에 저장됨.

어디에 저장되나?:

		디스크의 파일 시스템, 구체적으로 Unity 프로젝트 폴더 내 에셋 파일(예: Assets/ScriptableObjects/Dungeon/MyGraph.asset)에 저장됩니다.

		MyGraph.asset 파일은 RoomNodeGraphSO와 그 하위 객체(RoomNodeSO들)를 포함하는 직렬화된 데이터 파일.

예시:

		프로젝트 폴더: C:/MyUnityProject/Assets/ScriptableObjects/Dungeon/MyGraph.asset.

		이 파일은 RoomNodeGraphSO의 데이터(노드 리스트, 노드 속성 등)를 포함하며, 새로 추가된 RoomNodeSO도 함께 저장됨.

왜 필요한가?:

		AssetDatabase.AddObjectToAsset는 메모리에서만 에셋 구조를 변경.

		SaveAssets를 호출하지 않으면 디스크에 저장되지 않아, 에디터를 닫으면 변경 사항이 사라짐.

		영속성 보장: 에디터를 다시 열었을 때도 노드가 유지되도록.
```

```csharp
2. 노드 그리기:

		Draw 메서드에서 노드를 GUI로 렌더링.

		EditorGUILayout.Popup으로 노드 타입을 선택하고, 변경 시 SetDirty 호출
```

```csharp
// RoomNodeSO 객체를 에디터 창에 시각적으로 그리는 메서드
// 노드를 사각형 박스로 표시하고, 드롭다운 메뉴로 노드 타입을 선택할 수 있게 함
// 매개변수:
// - nodeStyle: 노드의 시각적 스타일 (배경, 텍스트 색상, 패딩 등)
public void Draw(GUIStyle nodeStyle)
{
    // 지정된 위치(rect)와 스타일(nodeStyle)로 UI 영역 시작
    // GUILayout.BeginArea: rect 영역 내에서 UI 요소를 그리기 시작
    // rect는 노드의 위치와 크기, nodeStyle은 노드의 배경과 테두리 스타일
    GUILayout.BeginArea(rect, nodeStyle);

    // GUI 변경을 감지하기 시작
    // EditorGUI.BeginChangeCheck: UI 변경(예: 드롭다운 선택 변경)을 추적
    EditorGUI.BeginChangeCheck();

    // 현재 노드 타입의 인덱스를 찾음
    // roomNodeTypeList.list.FindIndex: 노드 타입 목록에서 현재 roomNodeType과 일치하는 항목의 인덱스를 반환
    // 람다 식(x => x == roomNodeType): 리스트에서 현재 노드 타입과 동일한 객체를 찾음
    int selected = roomNodeTypeList.list.FindIndex(x => x == roomNodeType);

    // 드롭다운 메뉴를 표시하여 노드 타입 선택
    // EditorGUILayout.Popup: 드롭다운 메뉴를 그림
    // "": 레이블(빈 문자열, 레이블 없이 메뉴만 표시)
    // selected: 현재 선택된 인덱스 (드롭다운의 기본 선택값)
    // GetRoomNodeTypesToDisplay(): 드롭다운에 표시할 문자열 배열 (노드 타입 이름들)
    int selection = EditorGUILayout.Popup("", selected, GetRoomNodeTypesToDisplay());

    // 선택된 드롭다운 항목의 인덱스로 노드 타입 업데이트
    // roomNodeTypeList.list[selection]: 선택된 인덱스에 해당하는 RoomNodeTypeSO 객체
    roomNodeType = roomNodeTypeList.list[selection];

    // GUI 변경 여부 확인
    // EditorGUI.EndChangeCheck: BeginChangeCheck 이후 UI 변경이 있었는지 반환
    // 변경이 있으면(예: 드롭다운에서 새 타입 선택) 노드를 더티(dirty) 상태로 표시
    if (EditorGUI.EndChangeCheck())
        // EditorUtility.SetDirty: 객체가 변경되었음을 Unity에 알림, 저장 필요
        EditorUtility.SetDirty(this);

    // UI 영역 종료
    // GUILayout.EndArea: BeginArea로 시작한 영역을 닫음
    GUILayout.EndArea();
}
```

```csharp
설명:

		BeginArea: 지정된 rect 영역에 스타일(nodeStyle)로 노드를 그림.

		FindIndex: 현재 노드 타입의 인덱스를 찾아 팝업 메뉴의 기본값으로 설정.

		EditorGUILayout.Popup: 노드 타입을 선택할 드롭다운 메뉴를 표시.

		SetDirty: 변경 사항을 저장하도록 표시.
```

## 1. 룸 노드 그래프 에디터 스크립트 수정 (RoomNodeGraphEditor.cs)

### (1) 현재 선택된 노드 변수 추가

```csharp
설명: RoomNodeSO 타입의 변수로, 현재 마우스가 위치한 노드를 저장. 초기값은 null.
```

```csharp
private RoomNodeSO currentRoomNode = null;
```

### (2) 마우스 위치 확인 메서드 추가 (IsMouseOverRoomNode)

```csharp
목적: 마우스가 룸 노드 위에 있는지 확인하고, 해당 노드를 반환.

설명:

		roomNodeList를 역순으로 순회하며 마우스 위치(currentEvent.mousePosition)가 노드의 rect 영역에 포함되는지 확인.

		포함되면 해당 노드를 반환, 아니면 null 반환.
```

```csharp
// 마우스가 룸 노드 위에 있는지 확인하는 메서드
// 입력: currentEvent (현재 마우스 이벤트 정보, 예: 마우스 위치)
// 출력: 마우스가 위치한 룸 노드(RoomNodeSO)를 반환, 없으면 null 반환
private RoomNodeSO IsMouseOverRoomNode(Event currentEvent)
{
    // 룸 노드 리스트를 역순으로 순회 (최상단 노드부터 확인)
    // 역순인 이유: 나중에 추가된 노드가 위에 렌더링되므로 먼저 확인해야 함
    for (int i = currentRoomNodeGraph.roomNodeList.Count - 1; i >= 0; i--)
    {
        // 현재 노드의 사각형 영역(rect)이 마우스 위치를 포함하는지 확인
        // rect.Contains: 마우스 좌표가 노드의 경계(rect) 안에 있는지 판단
        if (currentRoomNodeGraph.roomNodeList[i].rect.Contains(currentEvent.mousePosition))
        {
            // 마우스가 노드 위에 있으면 해당 노드를 반환
            return currentRoomNodeGraph.roomNodeList[i];
        }
    }
    // 마우스가 어떤 노드 위에도 없으면 null 반환
    return null;
}
```

### (3) 이벤트 처리 로직 수정 (ProcessEvents)

```csharp
목적: 마우스가 노드 위에 있는지, 드래그 중인지 확인해 적절한 이벤트를 처리.

설명:

		currentRoomNode가 null이거나 드래그 중이 아니면, 마우스가 노드 위에 있는지 확인.

		노드가 없으면 그래프 전체 이벤트(ProcessRoomNodeGraphEvents)를 처리.

		노드가 있으면 개별 노드 이벤트(currentRoomNode.ProcessEvents)를 처리.
```

```csharp
// Unity 에디터에서 마우스 이벤트를 처리하는 메서드
// 입력: currentEvent (현재 마우스 이벤트 정보, 예: 클릭, 드래그, 위치 등)
// 목적: 마우스가 노드 위에 있는지 확인하고, 노드 또는 그래프 이벤트를 처리
private void ProcessEvents(Event currentEvent)
{
    // 현재 선택된 노드가 없거나(currentRoomNode == null), 드래그 중이 아닌 경우
    // 마우스가 노드 위에 있는지 확인하여 currentRoomNode를 업데이트
    if (currentRoomNode == null || currentRoomNode.isLeftClickDragging == false)
    {
        // IsMouseOverRoomNode를 호출해 마우스가 위치한 노드를 찾음
        // 마우스가 노드 위에 있으면 해당 노드를, 없으면 null을 반환
        currentRoomNode = IsMouseOverRoomNode(currentEvent);
    }

    // 마우스가 노드 위에 없으면(currentRoomNode == null)
    // 그래프 전체에 대한 이벤트를 처리 (예: 컨텍스트 메뉴 표시)
    if (currentRoomNode == null)
    {
        ProcessRoomNodeGraphEvents(currentEvent);
    }
    // 마우스가 노드 위에 있으면
    // 해당 노드의 이벤트를 처리 (예: 드래그, 클릭, 선택)
    else
    {
        currentRoomNode.ProcessEvents(currentEvent);
    }
}
```

```csharp
{
```

```csharp
    isLeftClickDragging = true;

    DragNode(currentEvent.delta);

}

// 매개변수: delta - 마우스의 이동 거리 (x, y 좌표 변화량)
public void DragNode(Vector2 delta)
{

    rect.position += delta;

    // Unity 에디터에 이 객체가 수정되었음을 알림 (변경 사항 저장 및 Undo/Redo 지원)
    EditorUtility.SetDirty(this);
}
```

## 강의 목표

```csharp
룸 노드 간 연결선 드래그 기능 구현: 사용자가 마우스 오른쪽 버튼을 눌러 한 노드에서 다른 노드로 선을 끌어당길 수 있게 만듦.

시각적 피드백 제공: 드래그 중에 실시간으로 선을 그림.

드래그 종료 처리: 마우스를 놓으면 선이 사라지도록 초기화.
```

## 1. 연결선 드래그 기능 개요

```csharp
룸 노드 그래프란?

		Unity 에디터에서 던전의 방을 시각적으로 나타내는 노드 기반 그래프.

		각 노드는 RoomNodeSO(ScriptableObject)로 정의되며, 방의 위치와 타입(예: 복도, 보스 방)을 저장.

		RoomNodeGraphSO는 모든 노드를 관리하는 컨테이너 역할.

연결선 드래그란?

		사용자가 노드 A에서 오른쪽 마우스 버튼을 눌러 드래그하면, 노드 A에서 마우스 커서 위치까지 선이 그려짐.

		드래그를 멈추면 선이 사라짐(아직 부모-자식 관계는 설정하지 않음).

		선의 시작점은 노드의 중심, 끝점은 마우스 위치.


Unity 에디터 전용 코드

		#if UNITY_EDITOR와 #endif로 감싼 코드는 Unity 에디터에서만 실행.

		에디터 전용 클래스(예: RoomNodeGraphEditor)는 에디터 창을 커스터마이징해 그래프를 표시.

핵심 클래스

		RoomNodeSO: 개별 노드의 데이터(위치, 타입 등)와 이벤트 처리.

		RoomNodeGraphSO: 모든 노드와 연결선 관련 데이터를 관리.

		RoomNodeGraphEditor: 에디터 창에서 노드와 선을 렌더링하고 사용자 입력 처리.
```

```csharp
/// 오른쪽 마우스 드래그 이벤트를 처리하는 메서드.
/// 노드 간 연결선을 그리고 있는 중이라면, 마우스 이동에 따라 선의 위치를 업데이트.
```

```csharp
/// <summary>
/// 현재 드래그 중인 연결선을 화면에 그리는 메서드.
/// 사용자가 어떤 노드에서 다른 노드로 선을 연결하기 위해 드래그할 때,
/// 시작점에서 마우스 위치까지 임시 베지어 곡선을 그려줌.
/// </summary>
private void DrawDraggedLine()
{
    // 드래그 선의 끝 위치(linePosition)가 기본값(Vector2.zero)이 아닐 경우에만 실행
    // 즉, 현재 선을 그리고 있는 중일 때만 동작
    if (currentRoomNodeGraph.linePosition != Vector2.zero)
    {
        // Handles.DrawBezier는 Unity 에디터 상에서 곡선을 그려주는 함수
        Handles.DrawBezier(
            // 선의 시작점: 연결을 시작한 노드의 중앙 위치
            currentRoomNodeGraph.roomNodeToDrawLineFrom.rect.center,

            // 선의 끝점: 마우스 커서 위치를 따라 이동하는 선의 현재 위치
            currentRoomNodeGraph.linePosition,

            // 시작점에서 곡선을 유도하는 핸들 위치 (이 경우 시작점과 동일)
            currentRoomNodeGraph.roomNodeToDrawLineFrom.rect.center,

            // 끝점에서 곡선을 유도하는 핸들 위치 (이 경우 끝점과 동일)
            currentRoomNodeGraph.linePosition,

            // 선의 색상 (흰색)
            Color.white,

            // 커스텀 텍스처 없음 (null)
            null,

            // 선의 두께
            connectingLineWidth
        );
    }
}
```

```csharp
/// <summary>
```
```csharp
/// 마우스 버튼이 떼어졌을 때의 이벤트를 처리하는 메서드.
/// 오른쪽 버튼으로 드래그 중이었다면 선 그리기를 중단하고 초기화.
/// </summary>
/// <param name="currentEvent">현재 이벤트 정보</param>
private void ProcessMouseUpEvent(Event currentEvent)
{
    // 오른쪽 마우스 버튼(1번 버튼)을 떼었고, 선을 그리고 있는 노드가 있다면
    if (currentEvent.button == 1 && currentRoomNodeGraph.roomNodeToDrawLineFrom != null)
    {
        // 드래그 상태 초기화 (선 그리기 종료)
        ClearLineDrag();
    }
}

/// <summary>
/// 선 그리기 상태를 초기화하는 메서드.
/// 현재 드래그 중이던 시작 노드 및 선 위치를 초기 상태로 되돌림.
/// </summary>

{

    currentRoomNodeGraph.roomNodeToDrawLineFrom = null;

    // 선의 끝 위치도 초기화

    // GUI에 변화가 있음을 알리고 다시 그리기 요청
    GUI.changed = true;
```

```csharp
/// <summary>
/// 노드 그래프 상에서 발생한 입력 이벤트를 처리하는 메서드.
/// 마우스 클릭, 드래그, 업 이벤트를 분기 처리함.
/// </summary>
/// <param name="currentEvent">현재 이벤트 정보</param>
private void ProcessRoomNodeGraphEvents(Event currentEvent)
{
    switch (currentEvent.type)
    {
        // 마우스 클릭 이벤트 처리
        case EventType.MouseDown:
            ProcessMouseDownEvent(currentEvent);
            break;

        // 마우스 드래그 이벤트 처리 (ex. 노드를 이동하거나 선을 드래그)
        case EventType.MouseDrag:
            ProcessMouseDragEvent(currentEvent);
            break;

        // 마우스 버튼에서 손을 뗐을 때 이벤트 처리 (예: 선 그리기 중지)
        case EventType.MouseUp: // ← 오타 수정됨 (기존에는 EventTypeMouseDragEvent로 잘못 작성됨)
            ProcessMouseUpEvent(currentEvent);
            break;

        // 기타 이벤트는 처리하지 않음
        default:
            break;
    }
}
```

```csharp
MouseUp 이벤트
```

## 전체 작동 흐름

```csharp
1. 드래그 시작:

		사용자가 노드 위에서 오른쪽 마우스를 클릭.

		RoomNodeSO::ProcessRightClickDownEvent가 호출되어 roomNodeToDrawLineFrom에 노드 저장, linePosition에 마우스 위치 저장.

2. 드래그 중:

		마우스를 끌면 RoomNodeGraphEditor::ProcessRightMouseDragEvent가 linePosition을 currentEvent.delta만큼 업데이트.

		DrawDraggedLine이 매 프레임 선을 그림.

3. 드래그 종료:

		마우스를 놓으면 ProcessMouseUpEvent가 ClearLineDrag를 호출해 드래그 상태 초기화.

		선이 사라지고 다음 입력 대기.
```
