## 1. 프로젝트 브라우저와 새 프로젝트 생성하기

### 프로젝트 브라우저 화면

언리얼 엔진을 실행하면 가장 먼저 **프로젝트 브라우저(Project Browser)** 가 나타납니다.

- **최근 프로젝트(Recent Projects)** 섹션:
  - 이전에 작업했던 모든 프로젝트 목록이 표시됩니다.
  - 프로젝트를 클릭한 후 "열기" 버튼을 누르면 해당 프로젝트로 바로 이동할 수 있습니다.
- **새 프로젝트 만들기**:
  - 최근 프로젝트 아래에 있는 **게임(Games)** 섹션을 클릭합니다.
  - 여기에는 게임 제작을 위한 다양한 템플릿들이 준비되어 있습니다.

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380611/notion-blog/_/_/_5_C_/_1_Introduction_Setup/image.png)

### 업종별 섹션

프로젝트 브라우저에는 게임 외에도 다른 산업 분야(건축, 영화 등)를 위한 템플릿 섹션들이 있지만, 게임 개발이 목표라면 **게임 섹션**만 사용하면 됩니다.

## 2. 템플릿 선택과 프로젝트 설정

### 템플릿이란?

**템플릿(Template)** 은 기본 코드와 에셋이 미리 포함된 시작 프로젝트입니다.

- 처음부터 모든 것을 만들 필요 없이, 기본적인 기능이 이미 구현되어 있어 빠르게 시작할 수 있습니다.
- 예시:
  - **1인칭 템플릿**: 1인칭 캐릭터 컨트롤러가 포함됨
  - **3인칭 템플릿**: 3인칭 캐릭터 컨트롤러와 간단한 맵이 포함됨

### 3인칭 템플릿 선택

이 강의에서는 **3인칭(Third Person) 템플릿**을 선택합니다.

- 3인칭 캐릭터 컨트롤러
- 간단한 3인칭 맵 포함
- 언리얼 엔진 인터페이스를 배우기에 적합한 구성

### 프로젝트 기본 설정

오른쪽에 프로젝트 설정 옵션들이 나타납니다:

1. **블루프린트(Blueprint) vs C++**:
   - **블루프린트**: 언리얼의 비주얼 스크립팅 언어 (코드를 그림으로 연결)
   - **C++**: 게임 프로그래밍 업계 표준 언어
   - 이 강의에서는 아직 컴파일러가 설치되지 않아 **블루프린트**를 선택합니다.
   - 컴파일러 설치 후에는 C++로 전환 가능합니다.
2. **프로젝트 이름 설정**:
   - 예: "IntroProject" (인트로 프로젝트)
3. **저장 위치 선택**:
   - 언리얼 프로젝트들을 저장할 전용 폴더를 만드는 것을 권장합니다.
   - 폴더 선택 창에서 원하는 위치로 이동 → 마우스 우클릭 → "새 폴더" 생성 → 예: "My Unreal Projects"

### ⚠️ 중요한 주의사항 - 클라우드 동기화 폴더 피하기

- **Google Drive, OneDrive 같은 클라우드 동기화 서비스 폴더에는 프로젝트를 저장하지 마세요!**
- 클라우드 동기화 중에 프로젝트 파일이 손상될 수 있습니다.
- 반드시 로컬 하드 드라이브의 일반 폴더에 저장해야 합니다.

### 프로젝트 생성

설정을 모두 완료한 후 **"만들기(Create)"** 버튼을 클릭합니다.

- 프로젝트 생성 과정이 시작됩니다.
- 컴퓨터 사양에 따라 시간이 다소 걸릴 수 있습니다.

## 3. 언리얼 에디터 인터페이스 구성 이해하기

프로젝트가 로드되면 언리얼 엔진 에디터가 열립니다. 각 영역의 역할을 이해하는 것이 중요합니다.

### 상단 - 현재 맵 이름 표시

- 왼쪽 상단에 **"Level_ThirdPerson"** 같은 텍스트가 보입니다.
- 이것이 현재 편집 중인 **맵(Map)** 의 이름입니다.
- **맵(Map)** = 게임의 단일 레벨이라고 이해하면 됩니다.

### 중앙 - 뷰포트(Viewport)

**뷰포트(Viewport)** 는 화면에서 가장 큰 공간을 차지하는 영역입니다.

- 게임 세계를 3D로 시각적으로 보여주는 창입니다.
- 여기서 레벨이 어떻게 생겼는지 확인하고, 맵을 디자인할 수 있습니다.
- 실시간으로 게임 세계를 볼 수 있는 가장 중요한 작업 공간입니다.

### 오른쪽 - 아웃라이너(Outliner)

**아웃라이너(Outliner)** 는 뷰포트 오른쪽에 위치한 패널입니다.

- 레벨을 **텍스트 기반 목록**으로 표현합니다.
- 레벨에 있는 모든 게임 오브젝트의 리스트가 나열됩니다.
- 언리얼 엔진에서는 게임 오브젝트를 **액터(Actor)** 라고 부릅니다.

**아웃라이너에 표시되는 것들**:

- 경사로(Ramp)
- 원통(Cylinder)
- 지면(Ground)
- 조명(Light)
- 기타 레벨에 배치된 모든 오브젝트

이 모든 것들이 3인칭 템플릿과 함께 자동으로 제공된 것입니다.

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380608/notion-blog/_/_/_5_C_/_1_Introduction_Setup/image_1.png)

### 오른쪽 하단 - 세부 정보 패널(Details Panel)

**세부 정보 패널(Details Panel)** 은 아웃라이너 아래에 위치합니다.

- 선택한 게임 오브젝트(액터)의 상세 정보를 표시합니다.
- 아무것도 선택하지 않으면 비어 있습니다.
- 액터를 선택하면 해당 액터의 속성, 위치, 회전, 크기 등의 정보가 나타납니다.

### 액터(Actor) 선택하는 방법

**방법 1 - 뷰포트에서 직접 선택**:

- 뷰포트에서 오브젝트를 **마우스 왼쪽 버튼**으로 클릭합니다.
- 선택된 액터는 **노란색 윤곽선**으로 강조 표시됩니다.
- 세부 정보 패널에 해당 액터의 정보가 나타납니다.

**방법 2 - 아웃라이너에서 선택**:

- 아웃라이너의 목록에서 액터 이름을 클릭합니다.
- 뷰포트에서도 해당 액터가 강조 표시됩니다.
- 세부 정보 패널에 정보가 나타납니다.

---

### 카메라 이동 속도 조절

뷰포트 오른쪽 위에 **숫자(예: 1)**가 표시됩니다. 이것이 현재 카메라 이동 속도입니다.

**속도 조절 방법**:

- **마우스 오른쪽 버튼을 누른 상태**에서 **마우스 휠(스크롤)**을 위아래로 굴립니다.
- 숫자가 증가하면 이동 속도가 빨라집니다.
- 숫자가 감소하면 이동 속도가 느려집니다.

**사용 예시**:

- **속도 0.5**: 매우 느린 이동 - 정밀한 위치 조정이 필요할 때 유용
- **속도 1**: 기본 속도
- **속도 2 이상**: 빠른 이동 - 레벨의 먼 곳까지 빠르게 이동할 때 유용

### 플레이어 시작(Player Start) 액터

레벨 가운데에 **게임 컨트롤러 아이콘** 모양의 오브젝트가 있습니다.

- 아웃라이너에서 확인하면 **"Player Start"** 라는 이름입니다.
- **플레이어 시작(Player Start)** 은 특수한 유형의 액터입니다.
- 역할: 게임이 시작될 때 플레이어가 **스폰(생성)되는 위치**를 결정합니다.
- 이 액터가 배치된 위치에서 캐릭터가 나타나기 때문에, 게임 시작 위치를 변경하려면 Player Start 액터를 이동시키면 됩니다.

## 1. 셰이프 액터 레벨에 배치하기

### 📌 셰이프 액터란?

- **셰이프 액터(Shape Actor)**: 언리얼 엔진에서 제공하는 기본 3D 형태 오브젝트
- 빠른 프로토타이핑이나 레벨 디자인 테스트에 주로 사용

### 🔧 배치 방법

**Step 1: 프로젝트에 빠르게 추가 메뉴 열기**

- 화면 왼쪽에 있는 **"프로젝트에 빠르게 추가"** 메뉴를 좌클릭

**Step 2: 모양(Shape) 섹션 선택**

- 메뉴에서 **"모양(Shape)"** 섹션으로 이동
- 선택 가능한 기본 셰이프:
  - **정육면체(Cube)**: 육면체 형태
  - **구(Sphere)**: 공 형태
  - **원통(Cylinder)**: 원기둥 형태
  - **원뿔(Cone)**: 뾰족한 원뿔 형태
  - **평면(Plane)**: 평평한 면 형태

**Step 3: 레벨에 드래그 앤 드롭**

1. 원하는 셰이프(예: 정육면체)를 **좌클릭 후 길게 누르기**
2. 마우스를 **뷰포트(게임 화면)로 드래그**
3. 드래그하는 동안 **미리보기**가 표시됨
4. 원하는 위치에서 **마우스 버튼을 놓으면 배치 완료**

**Step 4: 배치 확인**

- 새로운 액터가 레벨에 생성됨
- **아웃라인(Outliner)** 패널에 "Cube"라는 이름으로 표시됨
- 자동으로 **선택 상태**가 되며, 3개의 화살표(기즈모)가 표시됨

## 6. 스냅(Snap) 기능으로 정밀 조정하기

### 🧲 스냅(Snap)이란?

**스냅 기능의 의미:**

- 오브젝트를 이동/회전/크기 조절할 때 **일정 단위로 끊어서** 움직이게 하는 기능
- 예: 10씩 증가, 50씩 증가 등
- **정확한 정렬**과 **일관된 배치**에 매우 유용

### 📍 위치 스냅 설정

**스냅 크기 확인 및 변경:**

1. 화면 상단에 **숫자가 표시된 버튼** 찾기 (예: "10")
2. 이 버튼을 **클릭**하면 스냅 크기 설정 메뉴 열림

**스냅 크기 선택:**

- **10 단위 (기본값)**: 10cm씩 이동
- **50 단위**: 50cm씩 이동 (더 큰 단위로 빠르게 배치)
- **5 단위**: 5cm씩 이동 (더 정밀한 조정)
- **사용자 지정**: 원하는 값 직접 입력 가능

**실제 동작:**

```
스냅이 10으로 설정된 상태:
- 오브젝트를 드래그하면 X값이 10, 20, 30... 이렇게 10단위로만 변경됨
- 7이나 13 같은 중간 값은 나타나지 않음

스냅이 50으로 설정된 상태:
- 오브젝트를 드래그하면 50, 100, 150... 이렇게 50단위로만 이동

```

### 🔄 회전 스냅 설정

**회전 스냅 동작:**

- 회전 도구(E) 사용 시 **일정 각도씩** 회전
- 예: 5도, 10도, 15도 단위로 회전
- **정확히 90도 회전**이 필요할 때 매우 유용

### 📏 스케일 스냅 설정

**스케일 스냅 예시:**

- 기본값: 0 (자유롭게 크기 조절)
- 0.25로 설정: 0.25, 0.5, 0.75, 1.0... 이런 식으로 25%씩 변경
- 오브젝트 크기를 **일정 비율로 통일**할 때 유용

### 💡 스냅 활용 팁

**스냅을 높게 설정하면:**

- **빠른 배치**에 유리
- 넓은 공간을 빠르게 채울 때

**스냅을 낮게 설정하면:**

- **정밀한 조정**에 유리
- 세밀한 위치 조정이 필요할 때

## 7. 액터 복제하기 (Ctrl+C/V, Alt 드래그)

### 📋 복제 방법 1: Ctrl+C/V (복사-붙여넣기)

**사용 순서:**

1. 복제할 액터를 **좌클릭으로 선택**
2. 키보드에서 **Ctrl + C** 누르기 (복사)
3. 키보드에서 **Ctrl + V** 누르기 (붙여넣기)
4. 새로운 액터가 **같은 위치에 생성**됨 (겹쳐져 있음)
5. 이동 도구로 원하는 위치로 **이동**

**확인 방법:**

- **아웃라인(Outliner) 패널**에 같은 이름의 액터가 하나 더 생김
- 예: "Cube", "Cube2" 처럼 번호가 붙음

### ⚡ 복제 방법 2: Alt + 드래그 (빠른 복제)

**사용 순서:**

1. 복제할 액터 선택
2. **이동 도구(W)** 활성화
3. 키보드에서 **Alt 키를 누른 채로 유지**
4. 화살표 중 하나를 **드래그**
5. 드래그하는 순간 **즉시 복제**됨
6. 원하는 위치에서 **마우스 버튼을 놓으면 배치 완료**

**장점:**

- **복사-붙여넣기보다 훨씬 빠름**
- 한 번의 동작으로 복제+이동을 동시에 수행
- 연속으로 여러 개 복제할 때 특히 유용

**실전 예시:**

```
계단 만들기:
1. 첫 번째 계단 배치
2. Alt 키 누른 채로 Z축(파란 화살표) 위로 드래그
   → 위쪽에 복제됨
3. 다시 Alt 키 누른 채로 Z축 위로 드래그
   → 또 위쪽에 복제됨
4. 이 과정을 반복하여 계단 완성

```

### 🔄 복제와 스냅 조합

**정렬된 복제:**

- **스냅을 활성화**한 상태에서 Alt 드래그 사용
- 예: 스냅 50으로 설정 → Alt 드래그로 복제하면 정확히 50cm 간격으로 배치됨
- **깔끔하게 정렬된 오브젝트 배치**에 매우 유용

## { C++ 개발 프로세스 상세 정리 }

### 1. 소스 코드 (Source Code)

- **정의**: 사람이 읽고 이해할 수 있는 프로그래밍 언어로 작성된 코드
- **파일 형식**: `.cpp`, `.h` 확장자
- **특징**: 텍스트 기반으로 약 40줄 정도의 명령어들로 구성
- **문제점**: CPU는 이 코드를 직접 이해하지 못함

### 2. 컴파일러 (Compiler)

- **역할**: 소스 코드를 머신 코드로 변환하는 프로그램
- **변환 과정**: 사람이 읽을 수 있는 텍스트 → CPU가 이해하는 0과 1
- **플랫폼별 컴파일러**:
  - Windows: Visual Studio 컴파일러
  - Mac: Xcode 컴파일러
- **결과물**: 실행 가능한 파일 생성 (Windows의 경우 .exe)

### 3. 소스 코드 편집기 (IDE)

- **정의**: 코드 작성을 돕는 고급 텍스트 편집기
- **주요 기능**:
  - **코드 완성**: 자동으로 코드 추천
  - **구문 강조**: 다른 종류의 코드를 색상으로 구분 (예: 주석은 녹색)
  - **오류 표시**: 코드의 실수를 미리 알려줌
  - **파일 관리**: 프로젝트 내 여러 파일을 쉽게 관리
- **구문(Syntax)**: C++에서 코드를 작성하는 규칙과 방식
- **IDE 종류**:
  - Visual Studio (Windows) - 컴파일러 + 편집기 통합
  - Xcode (Mac) - 컴파일러 + 편집기 통합
  - IDE = Integrated Development Environment (통합 개발 환경)

### 4. 언리얼 엔진 개발 워크플로우

**전체 과정**:

```
1단계: C++ 소스 코드 작성 (.cpp 파일)
   ↓
2단계: 컴파일러가 머신 코드로 변환 (0과 1)
   ↓
3단계: 언리얼 엔진에 전달
   ↓
4단계: 에디터 내에서 테스트 (90%의 작업)
   ↓
5단계: 독립형 게임으로 패키징 (배포용)

```

**특이점**:

- 언리얼에서는 .exe 파일을 직접 만들지 않음
- 에디터 내에서 머신 코드를 직접 실행
- 최종 완성 시에만 독립형 게임으로 패키징하여 공유

### 핵심 이해

- 사람은 머신 코드를 직접 작성할 수 없음 (불가능에 가까움)
- 그래서 C++ 같은 고급 언어로 작성하고 컴파일러가 변환
- IDE는 이 모든 과정을 편리하게 만들어주는 도구

# { 언리얼 엔진: C++ vs 블루프린트 }

## 1. 두 가지 프로그래밍 방식

언리얼 엔진에서 게임을 만들 때 선택할 수 있는 두 가지 방법:

### C++ (텍스트 기반 코딩)

- 범용 프로그래밍 언어
- `.cpp`, `.h` 파일로 작성
- Visual Studio 같은 외부 편집기 필요
- 컴파일 과정 필수

### 블루프린트 (비주얼 스크립팅)

- 언리얼 에디터 내장 시스템
- 노드를 연결하는 시각적 방식
- 외부 편집기 불필요
- 컴파일 불필요 (즉시 테스트 가능)

## 2. 블루프린트의 장단점

### ✅ 장점

- **배우기 쉬움**: 시각적이라 초보자 친화적
- **빠른 프로토타이핑**: 즉각적인 수정과 테스트
- **에디터 통합**: 언리얼 내에서 모든 작업 가능

### ❌ 단점

- **규모 확장 어려움**: 큰 게임에서 관리 복잡
- **게임플레이 한정**: 주로 게임 로직 작성용
- **성능 제한**: C++보다 느림

## 3. C++의 장단점

### ✅ 장점

- **완전한 제어**: 언리얼 엔진 모든 기능 접근
- **뛰어난 성능**: 블루프린트보다 훨씬 빠름
- **코드 간결성**: 적은 코드로 더 많은 로직 구현
- **확장성**: 대규모 프로젝트에 유리
- **범용성**: 외부 라이브러리 사용 가능

### ❌ 단점

- **학습 곡선**: 초기 진입 장벽 높음
- **개발 속도**: 컴파일 시간 소요

## 4. 관계와 활용

### 접근 권한 구조

```
언리얼 엔진 라이브러리 (C++)
    ↓ 접근 가능
내가 작성한 C++ 코드
    ↓ 접근 가능
내가 작성한 블루프린트

```

### 핵심 규칙

- ✅ **블루프린트 → C++ 접근 가능**
- ❌ **C++ → 블루프린트 접근 불가**

> 📌 의미: 블루프린트로 C++ 코드를 확장할 수 있지만, 그 반대는 안 됨

## 5. 사용 가이드

| 상황                 | 추천 방식                        |
| -------------------- | -------------------------------- |
| 빠른 프로토타입 제작 | 블루프린트                       |
| 게임 로직 테스트     | 블루프린트                       |
| 성능이 중요한 기능   | C++                              |
| 복잡한 시스템 구축   | C++                              |
| 대규모 프로젝트      | C++ (베이스) + 블루프린트 (확장) |
| 게임플레이 외 기능   | C++                              |

## 6. 실전 활용 전략

### 이 강의의 접근법

```
C++ (핵심 기능) + 블루프린트 (일부 확장)

```

### 학습 순서의 이점

1. **C++ 먼저 배우기** → 어렵지만 기초 탄탄
2. **블루프린트는 쉬워짐** → C++ 이해하면 금방 습득

## 핵심 요약

💡 **C++와 블루프린트는 경쟁 관계가 아닌 보완 관계**

- **C++**: 견고한 기반, 성능, 확장성
- **블루프린트**: 빠른 작업, 직관적 수정, C++ 확장

🎯 **최적의 조합**: C++로 핵심 시스템 구축 → 블루프린트로 게임플레이 디테일 추가
