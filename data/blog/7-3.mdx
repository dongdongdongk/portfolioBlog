## 📦 4단계: Box Component 추가 및 설정

### 🎯 Box Component란?

보이지 않는 박스 형태의 충돌 감지 영역입니다.

- 플레이어가 이 영역에 들어오면 감지
- 게임에서는 보이지 않음 (편집 모드에서만 표시)

### 🔧 추가 방법

**1. Component 추가**

```
BP_BotSpawner 열기
  ↓
Components 패널
  ↓
+ Add → Box 검색
  ↓
Box Collision 선택
  ↓
이름: Box (기본값 사용)
```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380740/notion-blog/_/_/_5_/_7_-_3/image.png)

### 🎨 시각화 설정 (보기 편하게)

**디테일 패널에서 설정**

```
Box Component 선택
  ↓
Shape 카테고리
  ↓
Advanced (▼ 클릭하여 펼치기)
  ├─ Shape Color: 녹청색 (파란색 계열)
  └─ Line Thickness: 5
```

**효과**

- 선택 안 했을 때: 녹청색으로 표시
- 선택했을 때: 노란색으로 표시
- 두께가 5라서 잘 보임

### ⚠️ 중요한 주의사항

**크기 조정 방법**

```
❌ 잘못된 방법
  └─ Transform의 Scale 변경
      (나중에 계산이 복잡해짐)

✅ 올바른 방법
  └─ Box Extent 값 조정
      (정확한 크기 제어 가능)
```

**위치 조정 주의**

```
액터를 움직이고 싶을 때:
  ├─ ✅ 아웃라이너에서 BP_BotSpawner 자체 선택 후 이동
  └─ ❌ Box Component 선택 상태로 이동
      (Box만 움직이고 액터 루트는 그대로)
```

## 🗺️ 5단계: 레벨에 배치 및 크기 조정

### 📍 배치 위치

두 기둥 사이 입구 중앙에 배치합니다.

**배치 과정**

```
Content Browser에서 BP_BotSpawner 드래그
  ↓
두 기둥 사이 입구 중앙에 Drop
  ↓
정확한 중앙 위치로 조정
```

### 📏 크기 조정 (Instance별 설정)

**개별 인스턴스에서 Box 크기 조정 가능**

```
레벨에 배치된 BP_BotSpawner 선택
  ↓
Details 패널
  ↓
Box (Instance Editable) 컴포넌트 선택
  ↓
Box Extent 조정
  ├─ X: 입구 너비에 맞게
  ├─ Y: 입구 깊이에 맞게
  └─ Z: 플레이어 높이 정도
```

**조정 예시**

```
두 기둥 사이를 완전히 커버하도록:
  ├─ X Extent: 200-300 정도
  ├─ Y Extent: 100-150 정도
  └─ Z Extent: 150-200 정도
      (플레이어가 지나갈 높이)
```

### 💡 Instance Editable의 장점

같은 BP_BotSpawner를 여러 곳에 배치할 때:

- 각 위치마다 다른 크기 설정 가능
- 블루프린트 자체는 수정 안 해도 됨
- 레벨 디자인에 유연하게 대응

## ⚙️ 6단계: Collision 설정 수정

### 🔍 현재 문제

```
Box Component의 기본 Collision Preset
  ↓
"OverlapAllDynamic"
  ├─ 대부분: Overlap (통과 가능)
  └─ Player와 Enemy: Block (막힘!)
      ⚠️ 입구를 통과할 수 없음
```

### 🔧 해결 방법

**Project Settings에서 Preset 수정**

```
Edit → Project Settings
  ↓
Engine - Collision 카테고리
  ↓
Preset 섹션
  ↓
OverlapAllDynamic 찾기
  ↓
Edit 클릭
  ├─ Player Response: Overlap으로 변경
  └─ Enemy Response: Overlap으로 변경
```

**OverlapAll 프리셋도 동일하게 수정**

```
OverlapAll 찾기
  ↓
Edit 클릭
  ├─ Player Response: Overlap
  └─ Enemy Response: Overlap
```

### ✅ 수정 후 결과

```
Before:
플레이어가 입구에서 막힘

After:
플레이어가 자유롭게 통과
  ↓
Box와 Overlap 이벤트 발생 (다음 강의에서 활용)
```

## 🎯 7단계: Target Point 시스템 설정

### 💡 Target Point란?

```
Target Point
  └─ 3D 공간의 특정 위치를 표시하는 액터
      ├─ Billboard Component만 가짐 (매우 가벼움)
      ├─ 위치 정보만 필요할 때 사용
      └─ 스폰 위치, 웨이포인트 등에 활용
```

### 📦 Target Point 배치

**1. 레벨에 추가**

```
Place Actors 패널
  ↓
All Classes 섹션
  ↓
"Target" 검색
  ↓
Target Point 드래그하여 마당에 배치
```

**2. 외형**

```
선택 안 함: 작은 빌보드 아이콘
선택함: 강조 표시된 빌보드
  └─ 게임 실행 시에는 안 보임
```

**3. 여러 개 배치**

```
동상 옆에 하나
  ↓
Alt + 드래그로 복제
  ↓
다른 위치에도 배치
  (예: 2개 배치)
```

## 🎯 3단계: Overlap 이벤트 추가 (핵심)

### 📌 Event ActorBeginOverlap

**이벤트 추가**

```

  ↓
"Begin Overlap" 검색
  ↓
Event ActorBeginOverlap 선택

### 💡 Event ActorBeginOverlap란?

```
Event ActorBeginOverlap
  └─ 다른 액터가 이 액터의 충돌 영역에 들어올 때 발생하는 이벤트
      ├─ 자동으로 실행됨 (매 프레임 체크하지 않아도 됨)
      ├─ 충돌한 상대방 정보를 알려줌
      └─ 한 번만 발생 (계속 겹쳐있어도 들어올 때만)
```

### 🔌 출력 핀 설명

```
Event ActorBeginOverlap
  ├─ 실행 핀 (빨간색 삼각형)
  │   └─ 이벤트가 발생하면 여기서부터 실행 시작
  │
  └─ Other Actor (파란색)
      └─ 충돌한 상대방 액터의 참조
          (예: 플레이어, 적, 발사체 등)
```

## 🔄 4단계: For Each Loop로 배열 순회

### 📌 For Each Loop 노드

**노드 추가**

```
Event ActorBeginOverlap 실행 핀에서 드래그
  ↓
"For Each Loop" 검색
  ↓
For Each Loop 노드 연결
```

### 💡 For Each Loop란?

```
For Each Loop
  └─ 배열의 모든 요소를 하나씩 꺼내서 처리하는 반복문

예시:
Target Points 배열 = [위치1, 위치2, 위치3]
  ↓
Loop 1회: 위치1에서 봇 스폰
Loop 2회: 위치2에서 봇 스폰
Loop 3회: 위치3에서 봇 스폰
```

### 🔌 핀 설명

```
For Each Loop
  ├─ 입력
  │   ├─ 실행 핀 (좌측 빨간 삼각형)
  │   │   └─ 루프 시작 신호
  │   │
  │   └─ Array (파란색)
  │       └─ 순회할 배열
  │           (여기서는 Target Points 배열)
  │
  └─ 출력
      ├─ Loop Body (빨간 삼각형)
      │   └─ 배열의 각 요소마다 실행
      │       (요소 개수만큼 반복)
      │
      ├─ Array Element (파란색)
      │   └─ 현재 처리 중인 요소
      │       (현재 Target Point)
      │
      ├─ Array Index (정수)
      │   └─ 현재 요소의 인덱스
      │       (0, 1, 2, ...)
      │
      └─ Completed (빨간 삼각형)
          └─ 모든 반복이 끝나면 실행
              (배열의 마지막까지 다 돌았을 때)
```

### 📝 배열 연결

```
Target Points 변수를 드래그
  ↓
Get으로 배치 (Getter)
  ↓
For Each Loop의 Array 핀에 연결
```

      ├─ 실행 시점에 동적으로 생성
      ├─ 레벨에 미리 배치한 것이 아님
      └─ 원하는 위치, 회전, 크기로 생성 가능
```

### 🔌 핀 설명

```
Spawn Actor from Class
  ├─ 입력
  │   ├─ 실행 핀 (좌측 빨간 삼각형)
  │   │   └─ 스폰 명령 실행
  │   │
  │   ├─ Class (주황색)
  │   │   └─ 생성할 액터의 종류
  │   │       (여기서는 BP_Bot)
  │   │
  │   ├─ Spawn Transform (노란색)
  │   │   └─ 생성 위치, 회전, 크기
  │   │       ├─ Location: 어디에 생성할지
  │   │       ├─ Rotation: 어떤 방향을 볼지
  │   │       └─ Scale: 크기 (보통 1,1,1)
  │   │
  │   ├─ Collision Handling Override
  │   │   └─ 충돌 처리 방식
  │   │       (기본값: Default 사용)
  │   │
  │   └─ Instigator
  │       └─ 생성을 일으킨 주체
  │           (보통 비워둠)
  │
  └─ 출력
      ├─ 실행 핀 (우측 빨간 삼각형)
      │   └─ 스폰 후 다음 실행
      │
      └─ Return Value (파란색)
          └─ 생성된 액터의 참조
              (생성된 봇을 제어하고 싶을 때 사용)
```

### 🔧 설정 방법

**1. Class 설정**

```

  ↓
BP_Bot 선택
  └─ 적 봇을 생성하도록 설정
```

**2. Spawn Transform 분할**

```

  └─ Transform이 Location, Rotation, Scale로 분리됨
```

**분할 후 구조**

```
Spawn Transform
  ├─ Location (X, Y, Z)
  ├─ Rotation (Roll, Pitch, Yaw)
  └─ Scale (X, Y, Z)
```

**3. Location 연결**

```
Get Actor Location의 Return Value
  ↓
Spawn Transform Location에 연결
  └─ Target Point의 위치에서 봇 생성
```

**4. Rotation과 Scale**

```
Rotation
  └─ 연결 안 함 (봇이 알아서 플레이어를 향함)

Scale
  └─ 기본값 (1, 1, 1) 사용
      (원본 크기 그대로)
```

  ↓
Details 패널
  ↓

  ↓

### 💡 Pickup Preset이란?

```
Pickup (기존에 만들었던 Preset)
  ├─ Collision Enabled: Query Only
  ├─ Object Type: WorldDynamic
  └─ Collision Responses:
      ├─ Default: Ignore (무시)
      └─ Player: Overlap (겹침)
          → 오직 플레이어와만 반응
```

### 🎨 Preset 이름 변경 (선택사항)

**더 명확한 이름으로 변경**

```
Edit → Project Settings
  ↓
Engine - Collision
  ↓
Preset 섹션
  ↓
Pickup 찾기
  ↓
Edit 클릭
  ├─ Name: OverlapOnlyPawn 또는 OverlapOnlyPlayer
  ├─ Description: "플레이어와만 겹침을 감지하는 컴포넌트용"
  └─ Accept
```

**변경 후**

```
Box Component의 Collision Preset
  └─ OverlapOnlyPawn으로 표시됨
      (기능은 동일, 이름만 명확해짐)
```

### ✅ 최종 최적화 결과

```
최적화 조합:
  ├─ Collision Preset: OverlapOnlyPawn
  │   └─ 플레이어만 트리거 (적 봇은 트리거 X)
  │
  └─ Destroy Actor 사용
      └─ 스폰 후 Spawner 제거 (재트리거 불가)

결과:
  ├─ CPU 효율: 최상 (불필요한 충돌 감지 없음)
  ├─ 메모리: 최상 (사용 후 즉시 해제)

## 🎨 4단계: DecrementHealth 로직 구현

### 🔗 노드 구조

```

  │
  ├─ Input: Damage (받은 피해)
  │
  ↓

  │   └─ 현재 체력에서 피해량 빼기
  │

  └─ IsDead: <= 연산 결과 (true/false)
```

### 📝 상세 노드 설명

**1. Set Health (체력 감소)**

```
Set Health
  └─ 변수 값을 변경하는 노드

연결:
  ├─ 새 값: [Health - Damage] (빼기 노드 결과)
  └─ 효과: 현재 체력에서 받은 피해만큼 감소

예시:
Health = 30.0
Damage = 10.0
  ↓
Set Health = 30.0 - 10.0 = 20.0
```

**2. 빼기 노드 (-)**

```
Float - Float
  ├─ A: Health (Get)
  ├─ B: Damage (Input Parameter)
  └─ 결과: A - B

예시:
30.0 - 10.0 = 20.0
```

**3. <= (Less Than or Equal)**

```
<= 노드
  └─ A가 B보다 작거나 같은지 확인
      ├─ A: Health
      ├─ B: 0.0
      └─ 결과: Boolean (true/false)

예시:
Health = 5.0
  ├─ 5.0 <= 0.0 → false (아직 살아있음)

Health = 0.0
  ├─ 0.0 <= 0.0 → true (죽음!)

Health = -5.0
  └─ -5.0 <= 0.0 → true (죽음!)
```

**4. Return Node**

```
Return Node
  └─ 함수의 출력 값을 반환

IsDead (Output)
  └─ <= 노드의 결과 연결
      ├─ true: 체력이 0 이하 (죽음)
      └─ false: 체력이 0 초과 (생존)
```

### 💡 Class Reference란?

```
Object Reference vs Class Reference

Object Reference (파란색)
  └─ 이미 생성된 특정 액터의 참조
      예: 레벨에 배치된 특정 Target Point

Class Reference (보라색)
  └─ 액터의 '종류(클래스)' 자체를 가리킴
      예: BP_Bot 클래스, BP_BotBoss 클래스
      └─ Spawn Actor에서 "어떤 종류를 만들지" 지정할 때 사용
```

### 🔍 타입 선택 과정

**검색: BP_Bot**

```
두 가지 옵션 표시:
  ├─ Object Reference (파란색)
  │   └─ 특정 인스턴스
  │
  └─ Class Reference (보라색) ✅
      └─ 클래스 자체
```

**Class Reference 선택**

```
BP_Bot (Class Reference)
  ├─ BP_Bot 클래스 저장 가능
  └─ BP_Bot의 자식 클래스도 저장 가능
      └─ BP_BotBoss도 저장 가능! (상속)
```

### 💡 다형성(Polymorphism)

```
상속의 강력한 기능:

BP_Bot 타입 변수
  ├─ BP_Bot 저장 가능 ✅
  └─ BP_Bot의 자식들도 저장 가능 ✅
      ├─ BP_BotBoss
      ├─ BP_FlyingBot (만들면)
      └─ BP_TankBot (만들면)

이유:
  └─ 자식은 부모이기도 하기 때문
      "BP_BotBoss는 BP_Bot이다" (참)
```

  └─ 하나의 Spawner로 다양한 봇 스폰

```
Bake Transform
  └─ 임시 변형을 영구적으로 적용

적 봇이 발사하는 블래스터 빔이 플레이어를 정확히 조준하도록 개선합니다.

- 현재 문제점 파악 (빗나가는 발사)
- Find Look at Rotation으로 정확한 조준 구현
- 보스 전용 강력한 발사체 생성
- 시각적 차별화 (색상 변경)

## 🐛 1단계: 문제 발견

### 🔍 현재 상황

**보스전 테스트**

```
플레이어가 가만히 서 있으면:
  ├─ 발사체가 플레이어를 빗나감
  ├─ 전혀 맞지 않음
  └─ 너무 쉬움
```

**원인 분석**

```
일반 봇:
  ├─ 크기가 작음
  ├─ 무기가 중앙에 가까움
  └─ 우연히 자주 맞춤

보스 봇:
  ├─ 크기가 큼 (5배)
  ├─ 무기가 양쪽 끝에 멀리 떨어짐
  ├─ 발사체가 앞으로만 날아감
  └─ 플레이어를 정확히 조준 안 함
```

### 💡 플레이어 발사체는 왜 정확한가?

```
BP_BotPawn (플레이어)
  ↓
Line Trace로 조준점 계산
  ↓
발사체 방향 = Line Trace 방향
  └─ 항상 십자선이 가리키는 곳에 명중

적 봇도 같은 원리 필요:
  └─ 발사 방향 = 플레이어를 향하는 방향
```

## 🔧 2단계: SpawnBlasterBeam 함수 분석

### 📍 현재 코드 확인

**BP_Bot → Functions → SpawnBlasterBeam**

```
Get Socket Transform
  ├─ Socket Name: 입력 파라미터
  ├─ Return Value: Transform
  │   ├─ Location (위치)
  │   ├─ Rotation (회전)
  │   └─ Scale (크기)
  │
  ↓
Spawn Actor from Class
  ├─ Class: BP_EnemyBlasterBeam
  └─ Spawn Transform: Socket Transform (그대로 사용)
```

### ⚠️ 문제점

```
Socket Transform의 Rotation
  └─ 소켓이 향하는 방향
      ├─ 봇의 앞쪽 방향
      └─ 플레이어를 향하지 않음

결과:
  └─ 발사체가 봇의 정면으로만 날아감
```

## 🎯 3단계: Find Look at Rotation 적용

### 📌 Split Struct Pin

**Spawn Transform 분할**

```
Spawn Actor 노드
  ↓
Spawn Transform 핀 우클릭
  ↓
Split Struct Pin 선택
  ↓
분할 결과:
  ├─ Location
  ├─ Rotation
  └─ Scale
```

### 💡 Split Struct Pin이란?

```
Transform = Location + Rotation + Scale

Split 전:
  └─ Transform (하나의 핀)

Split 후:
  ├─ Location (위치만)
  ├─ Rotation (회전만)
  └─ Scale (크기만)

장점:
  └─ 각각 따로 제어 가능
      예: Location은 소켓 위치
          Rotation은 플레이어 방향
```

### 🔗 Location 연결

**소켓 위치 사용**

```
Get Socket Transform → Return Value Location
  ↓
Spawn Transform Location
  └─ 무기 소켓 위치에서 발사
```

## 🎯 4단계: Find Look at Rotation 노드

### 📌 노드 추가

**노드 검색**

```
우클릭
  ↓
"Find Look at Rotation" 검색
  ↓
Find Look at Rotation 선택
```

### 💡 Find Look at Rotation이란?

```
Find Look at Rotation
  └─ 시작점에서 목표점을 바라보는 회전값 계산

Input:
  ├─ Start (시작 위치)
  │   └─ 어디서 보는가
  │
  └─ Target (목표 위치)
      └─ 어디를 보는가

Output:
  └─ Return Value (Rotation)
      └─ Start에서 Target을 정확히 향하는 회전값

예시:
총구(Start)에서 플레이어(Target)를 향하는 방향
```

### 🔌 입력 연결

**Start 위치 (발사 시작점)**

```
Get Socket Transform → Return Value Location
  ↓
Find Look at Rotation → Start
  └─ 무기 소켓 위치
```

**Target 위치 (플레이어)**

```
Target Pawn (변수 Get)
  ↓
Get Actor Location
  ↓
Find Look at Rotation → Target
  └─ 플레이어의 위치
```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380739/notion-blog/_/_/_5_/_7_-_3/image_18.png)

### 🔗 출력 연결

**정확한 조준 방향**

```
Find Look at Rotation → Return Value
  ↓
Spawn Transform Rotation
  └─ 플레이어를 정확히 향하는 회전값
```

## 📊 5단계: 완성된 노드 구조

### 🎨 전체 Blueprint

```
[SpawnBlasterBeam 함수]
  │
  ├─ Input: SocketName (어느 무기에서 발사?)
  │
  ↓
[Get Socket Transform]
  ├─ Socket Name: SocketName
  ├─ Return Value Location → ①
  └─ (Rotation은 사용 안 함)

  ↓
[Get Target Pawn]
  ↓
[Get Actor Location]
  └─ Return Value → ②

  ↓
[Find Look at Rotation]
  ├─ Start: ① (무기 위치)
  ├─ Target: ② (플레이어 위치)
  └─ Return Value → ③

  ↓
[Spawn Actor BP_EnemyBlasterBeam]
  ├─ Spawn Transform Location: ①
  ├─ Spawn Transform Rotation: ③
  └─ Spawn Transform Scale: (1, 1, 1)
```

### 💡 작동 원리

```
매 발사마다:
  1. 무기 소켓의 현재 위치 가져오기
  2. 플레이어의 현재 위치 가져오기
  3. 무기 → 플레이어 방향 계산
  4. 그 방향으로 발사체 생성

결과:
  └─ 발사체가 항상 플레이어를 정확히 향함
```

## 💡 핵심 개념 정리

### 📌 Find Look at Rotation

```
용도:
  └─ 한 지점에서 다른 지점을 바라보는 회전값 계산

활용 예:
  ├─ 적이 플레이어 조준
  ├─ 카메라가 대상 추적
  ├─ 터렛이 목표물 겨냥
  └─ 캐릭터가 특정 방향 보기

입력:
  ├─ Start: Vector (시작 위치)
  └─ Target: Vector (목표 위치)

출력:
  └─ Rotator (회전값)
```

### 📌 Split Struct Pin

```
Transform 같은 구조체를 개별 요소로 분리
  ├─ Location (X, Y, Z)
  ├─ Rotation (Roll, Pitch, Yaw)
  └─ Scale (X, Y, Z)

장점:
  └─ 각 요소를 독립적으로 제어
      예: 위치는 A, 회전은 B 사용
```

### 📌 Class Reference 변수

```
변수로 클래스를 저장
  └─ Spawn Actor에서 동적으로 클래스 선택 가능

활용:
  ├─ 봇마다 다른 발사체
  ├─ 레벨마다 다른 적
  └─ 난이도별 다른 무기
```

### 📌 Material Instance

```
Material의 경량 복사본
  ├─ 같은 구조
  └─ 파라미터만 변경 (색상, 밝기 등)

장점:
  ├─ 빠른 생성
  ├─ 실시간 수정
  └─ 성능 효율적
```

## ⚠️ 주의사항

### 🔴 흔한 실수

**1. Split 안 하고 Rotation 연결**

```
❌ Transform 전체를 연결하면:
  └─ Find Look at Rotation 결과가 무시됨

✅ Split Struct Pin으로 분리:
  └─ Location: 소켓 위치
  └─ Rotation: Look at Rotation 결과
```

**2. Start와 Target 순서 바꿈**

```
❌ Start = Target Pawn
    Target = Socket Location
  └─ 반대 방향으로 발사됨

✅ Start = Socket Location (발사 시작점)
    Target = Target Pawn (조준 대상)
```

**3. Material vs Material Instance 혼동**

```
Material 직접 수정:
  └─ 모든 발사체 색상이 바뀜

Material Instance 사용:
  └─ 특정 발사체만 색상 변경
```

### ✅ Best Practices

**발사체 다양화**

```
상속 구조 활용:
BP_BlasterBeam
  ├─ BP_PlayerBlasterBeam
  ├─ BP_EnemyBlasterBeam
  └─ BP_BossBlasterBeam
      └─ 각각 다른 속성
```

**시각적 피드백**

```
위험한 발사체:
  ├─ 다른 색상 (경고색)
  ├─ 더 밝게 빛남
  └─ 플레이어가 즉시 인지
```

**난이도 조절**

```
속도와 데미지의 균형:
  ├─ 너무 빠르고 강하면: 불가능
  ├─ 너무 느리고 약하면: 지루함
  └─ 테스트로 적절한 값 찾기
```

보스 봇을 위한 5배 크기의 폭발 나이아가라 시스템을 만듭니다.

- 기존 폭발 시스템 복제
- 각 이미터 파라미터 조정
- 메시 크기 변경
- 봇별로 다른 폭발 이펙트 사용

## 🔍 1단계: 문제 인식

### ⚠️ 현재 상황

**보스 폭발 테스트**

```
보스를 처치하면:
  ├─ 작은 폭발 이펙트 발생
  ├─ 크기가 보스와 어울리지 않음
  └─ 아쉬운 느낌
```

### 🎯 목표

```
보스에 어울리는 폭발:
  ├─ 5배 큰 크기
  ├─ 더 많은 파티클
  ├─ 더 화려한 효과
  └─ 보스 처치의 성취감
```

## 🔨 5단계: Emitter 1 - 폭발 메시 (구체)

### 🔍 구조 파악

**이미터 1 선택 (다른 것 체크 해제)**

```

  ↓

  ↓

  └─ Sprite Renderer 대신 3D 메시 사용
```

### 💡 Mesh Renderer vs Sprite Renderer

```
Sprite Renderer (스프라이트)
  └─ 2D 이미지 (항상 카메라 향함)
      ├─ 불, 연기, 빛 등
      └─ 가볍고 빠름

Mesh Renderer (메시)
  └─ 3D 모델 (입체적)
      ├─ 파편, 잔해, 구체 등
      └─ 더 현실적이지만 무거움
```

### 📦 현재 사용 중인 메시

**Details 패널**

```
Mesh Renderer
  ↓
Meshes (배열)
  ↓
Element 0: Sphere
  └─ Shared 폴더의 구체 메시
```

## ⚡ 8단계: Emitter 2 - 스파크 조정

### 🔍 이미터 2 격리

**체크박스 설정**

```
Emitter 1: ✅ (구체 - 크기 비교용)
Emitter 2: ✅ (스파크 - 조정 대상)
나머지: ☐ (숨김)
```

### 📝 조정할 파라미터

**1. Spawn Burst Instantaneous (스폰 개수)**

```
Emitter Update 섹션
  ↓
Spawn Burst Instantaneous
  ↓
Spawn Count
  ├─ 기본값: 50
  └─ 변경값: 70
      └─ 더 많은 파티클 생성
```

### 💡 Spawn Burst Instantaneous란?

```
Spawn Burst Instantaneous
  └─ 한 번에 대량으로 파티클 생성

Spawn Count
  └─ 생성할 파티클 개수
      ├─ 50 = 스파크 50개
      └─ 70 = 스파크 70개 (더 풍성)
```

**2. Particle Spawn - Sprite Size (크기)**

```
Particle Spawn 섹션
  ↓
Initialize Particle
  ↓
Sprite Attributes
  ↓
Sprite Size Mode: Random Uniform
  ├─ Sprite Size Min
  │   ├─ 기본: (1, 1)
  │   └─ 변경: (3, 3)
  │
  └─ Sprite Size Max
      ├─ 기본: (4, 4)
      └─ 변경: (8, 8)
```

### 💡 Sprite Size Mode란?

```
Random Uniform
  └─ Min과 Max 사이에서 무작위 크기

예시:
Min (3, 3) ~ Max (8, 8)
  ├─ 각 파티클마다 다른 크기
  ├─ 3에서 8 사이의 값
  └─ 더 다양하고 자연스러움
```

**3. Lifetime (수명)**

```
Initialize Particle
  ↓
Lifetime Mode: Random
  ├─ Lifetime Min
  │   ├─ 기본: 0.5
  │   └─ 변경: 0.75
  │
  └─ Lifetime Max
      ├─ 기본: 1.0
      └─ 변경: 1.25
```

### 💡 Lifetime이란?

```
Lifetime (수명)
  └─ 파티클이 존재하는 시간 (초)

0.75 ~ 1.25:
  ├─ 각 스파크마다 다른 수명
  ├─ 짧으면 빨리 사라짐
  └─ 길면 오래 남음
      → 적절한 잔상 효과
```

**4. Shape Location (스폰 위치)**

```
Initialize Particle
  ↓
Shape Location
  ↓
Sphere Radius
  ├─ 기본: 8
  └─ 변경: 48 (6배)
```

### 💡 Shape Location이란?

```
Shape Location - Sphere
  └─ 구체 영역 내에서 파티클 생성

Sphere Radius
  └─ 구체의 반지름
      ├─ 8 = 작은 영역에서 스폰
      └─ 48 = 큰 영역에서 스폰
          → 더 넓게 퍼짐
```

**5. Add Velocity (속도)**

```
Particle Spawn
  ↓
Add Velocity from Point
  ├─ Velocity Minimum
  │   ├─ 기본: 200
  │   └─ 변경: 400
  │
  └─ Velocity Maximum
      ├─ 기본: 800
      └─ 변경: 1600 (2배)
```

### 💡 Add Velocity from Point란?

```
Add Velocity from Point
  └─ 중심점에서 바깥으로 파티클 발사

Velocity (속도)
  ├─ 400 ~ 1600
  ├─ 초당 이동 거리
  └─ 2배 빠르면 2배 멀리 날아감
      → 더 역동적인 폭발
```

  ├─ Min

```

예시:
  ├─ "75*5" 입력 → 자동으로 375
  ├─ "100/2" 입력 → 50
  └─ "200+50" 입력 → 250
      → 계산기 없이 편리하게 조정
```

## 💡 핵심 개념 정리

### 📌 나이아가라 이미터 구조

```
Niagara System (나이아가라 시스템)
  └─ 여러 Emitter의 집합

Emitter (이미터)
  ├─ 파티클 생성 규칙
  ├─ 렌더링 방식
  └─ 업데이트 로직

Particle (파티클)
  └─ 실제 보이는 개별 요소
```

### 📌 주요 파라미터

**Spawn (생성)**

```
Spawn Count
  └─ 파티클 개수
      ├─ 많으면: 풍성함
      └─ 적으면: 희소함
```

**Size (크기)**

```
Sprite Size
  └─ 파티클 크기
      ├─ Random: 다양한 크기
      └─ Uniform: 같은 크기
```

**Lifetime (수명)**

```
Lifetime
  └─ 지속 시간 (초)
      ├─ 짧으면: 빠르게 사라짐
      └─ 길면: 오래 남음
```

**Position (위치)**

```
Shape Location
  └─ 스폰 영역
      ├─ Sphere: 구체 영역
      ├─ Box: 상자 영역
      └─ Cylinder: 원통 영역
```

**Velocity (속도)**

```
Add Velocity
  └─ 이동 속도
      ├─ From Point: 중심에서 방사
      ├─ In Cone: 원뿔 방향
      └─ Directional: 특정 방향
```

### 📌 Renderer 타입

2D 이미지
  ├─ 항상 카메라 향함
  ├─ 가벼움
  └─ 대부분의 이펙트에 사용

**Mesh Renderer**

```
3D 메시
  ├─ 입체적

  └─ 현실적인 파편/잔해 등
```

## ⚠️ 주의사항

### 🔴 흔한 실수

**1. 원본 파일 수정**

```
❌ 복제 안 하고 원본 수정
  └─ 모든 봇 폭발이 바뀜

✅ 복제본 만들어서 수정
  └─ 필요한 곳만 사용
```

**2. 한 번에 모든 이미터 조정**

```
❌ 여러 이미터 동시 수정
  └─ 효과 파악 어려움

✅ 격리해서 하나씩 조정
  └─ 정확한 결과 확인
```

**3. 너무 큰 값 설정**

```
파티클 수:
  ├─ 너무 많으면 성능 저하
  └─ 적절한 범위 유지

크기:
  ├─ 너무 크면 부자연스러움
  └─ 주변 환경과 비교하며 조정
```

**4. Bake Transform 잊기**

```
❌ Scale만 조정하고 Bake 안 함
  └─ 임시 변형 (비효율)

✅ Bake Transform으로 고정
  └─ 영구 적용 (최적화)
```

### ✅ Best Practices

**나이아가라 작업 순서**

```
1. 복제본 만들기
2. 원본 닫기
3. 이미터별로 격리
4. 하나씩 조정
5. 전체 확인
6. 반복 조정
```

**파라미터 조정 팁**

```
점진적 증가:
  ├─ 한 번에 2배씩
  ├─ 너무 크면 절반으로
  └─ 미세 조정
```

**성능 고려**

```
파티클 수:
  └─ 필요한 만큼만
      (70개도 충분히 많음)

Lifetime:
  └─ 너무 길면 누적되어 느려짐
```

**시각적 일관성**

```
관련된 이미터:
  └─ 비슷한 비율로 증가
      (스파크 + 스파크 블랙)
```
