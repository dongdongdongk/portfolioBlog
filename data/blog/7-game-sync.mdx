## 1. Game Sync와 사운드 관계

- **Game Sync**란: 게임에서 발생하는 특정 값(상태, 변수 등)에 따라 오디오가 동적으로 반응하도록 연결하는 시스템.
- Cube 게임 예시:
  - **심장 박동 사운드**
    - 볼륨은 두 가지 값에 영향을 받음
      1. 플레이어가 **살아 있는지/패배했는지** 여부 (State)
      2. 플레이어의 **체력(PlayerHealth)** (RTPC)
  - **발자국 사운드**
    - 플레이어가 걷는 **표면 종류(Surface Type)**에 따라 달라짐 (Switch)

👉 여러 Game Sync가 동시에 사운드에 영향을 주면, 왜 특정 사운드가 의도와 다르게 들리는지 이해하기 어려워질 수 있음.

---

## 2. 여러 값이 동시에 사운드에 영향을 줄 때 문제

- 사운드가 **제대로 안 들리거나**, **예상과 다르게 작동**할 때 원인이 무엇인지 추적이 필요함.
- 예시 문제:
  - 심장 박동 소리가 아예 안 들린다 → 체력이 0인데 PlayerLife State도 패배 상태라서 둘이 충돌했을 가능성.
  - 발자국 소리가 특정 표면에서만 안 난다 → Switch 값이 잘못 들어왔을 수 있음.
- 이런 문제를 빠르게 찾아내려면 **프로파일링 도구**를 사용해야 함.

---

## 3. Wwise 레이아웃 재배치하기

- **레이아웃(Layout)**: Wwise에서 창(탭) 구성을 어떻게 배치할지 정의한 것.
- 필요성:
  - **여러 속성을 동시에** 보면서 문제를 진단해야 하는 경우가 많음.
  - 예를 들어, **심장 박동 오브젝트의 볼륨 속성**과 **Game Sync 적용 상태**를 나란히 보고 싶을 때.
- 방법:
  - 두 개의 속성 탭(Properties)을 동시에 열 수 있도록 레이아웃을 변경.
  - 예시: 한쪽은 Actor-Mixer Hierarchy 속성, 다른 한쪽은 State/RTPC 탭.

---

## 4. Voice Profiler로 속성 값 확인하기

- **Voice Profiler**: 실제 게임 플레이 중 재생되는 사운드의 속성 값을 실시간으로 확인하는 기능.
- 주요 확인 가능 항목:
  - 현재 어떤 사운드가 재생 중인지
  - 적용된 RTPC 값이 얼마인지
  - State/ Switch 값이 정상적으로 반영되고 있는지
- 활용 예시:
  - "심장 박동 소리가 너무 작게 들린다" → Voice Profiler에서 RTPC 값이 체력에 맞게 적용되고 있는지 확인.

---

## 5. Profiler 레이아웃으로 게임 호출 모니터링하기

- **Profiler 레이아웃**: 게임이 실행되는 동안 Wwise와 연결해 **게임 호출(Game Calls)**을 모니터링하는 기능 제공.
- 모니터링 가능한 요소:
  - **Event 호출 기록** (Play, Stop 등)
  - **RTPC 값 변화** (체력 수치가 정확히 전달되는지)
  - **State 전환** (Alive ↔ Defeated가 정상적으로 바뀌는지)
  - **Switch 변경** (Surface Type이 올바르게 전달되는지)
- 장점:
  - "게임에서 값이 Wwise로 잘 전달되고 있는지"를 바로 확인 가능.
  - 문제의 원인이 **게임 쪽 코드 전달 문제인지**, **Wwise 내 설정 문제인지** 빠르게 구분할 수 있음.

---

✅ **정리**

- Cube 게임에서 사운드는 여러 Game Sync 값(State, RTPC, Switch)에 의해 제어된다.
- 값이 복잡하게 얽히면, 사운드 문제의 원인을 찾기 어려움.
- 이를 해결하기 위해 **Wwise 레이아웃 재배치, Voice Profiler, Profiler 레이아웃**을 활용하여 실시간으로 확인하고 디버깅한다.

## 1. 심장 박동 사운드에 영향을 주는 요소

- **RTPC (Real-Time Parameter Control)**
  → 플레이어의 **체력 값**에 따라 심장 박동 사운드의 크기·속도 등이 변합니다.
- **State (상태 시스템)**
  → 플레이어가 **살아 있는지 / 패배했는지** 여부에 따라 사운드가 재생되거나 멈춥니다.

즉, **심장 박동 사운드 = RTPC(체력) + State(생존 여부)의 조합**

👉 그래서 두 개의 뷰를 동시에 확인하는 것이 편리합니다.

## 4. Voice Monitor 캡처 및 그래프 확인

1. **Start Capture 버튼** 클릭
   - Voice Profiler가 오디오 데이터를 기록 시작.
2. Transport Control → **Play 버튼(스페이스바)** 클릭
   - Heartbeat 사운드 재생 시도.
3. 현재는 소리가 안 들리고, 그래프 변화 없음 → 이유는 **RTPC 곡선 설정 때문**.
   - PlayerHealth 값이 50~100일 때는 볼륨 -200dB → **완전히 무음 처리됨**.
   - PlayerHealth 값이 50 이하로 떨어져야 점차 0dB(정상 볼륨)으로 올라옴.

## 5. RTPC(PlayerHealth) 값 조정하기

1. Transport Control에서 **PlayerLife State = Alive**로 설정
2. **Display RTPCs 버튼** 클릭 → PlayerHealth 값 슬라이더 표시
3. PlayerHealth 값을 **50 이하로 천천히 낮추기**
   - 그래프 선이 상승 → 볼륨 커짐
   - 실제로 **심장 박동 소리 들림**

## 6. Voice Explorer와 Voice Inspector 활용

- **Voice Explorer**에서 `Heartbeat` 행 선택
- **Voice Inspector (왼쪽 창)**
  - 현재 Sound SFX 오브젝트의 볼륨, 필터 값이 **사각형 다이어그램**으로 표시
  - Heartbeat가 **Master Audio Bus**를 통해 라우팅됨 확인 가능

## 7. Driver(드라이버) 확인하기

- **Voice Inspector (오른쪽 창)** → 현재 보이스 볼륨에 영향을 주는 기능 목록 표시
- 이 기능들이 바로 **Driver(드라이버)**
  - 예: State, RTPC, Bus Routing 등
- 만약 소리가 재생되지 않으면, **어떤 Driver가 원인인지** 추적할 수 있음 → 디버깅에 매우 유용.

---

✅ 마지막으로

- Transport Control에서 **Stop 버튼** 클릭 → Heartbeat 정지
- **Stop Capture 버튼** 클릭 → 데이터 캡처 종료

---

정리하면, 이번 강의는 **Voice Profiler로 심장 박동 사운드가 RTPC와 State 값에 따라 어떻게 반응하는지 시각적으로 확인하는 방법**을 다루고 있어요.

즉, 단순히 "들린다/안 들린다" 확인이 아니라, **왜 안 들리는지**, **어떤 값이 소리에 영향을 주는지**를 추적하는 게 핵심입니다.

## 1. Profiler 레이아웃 이해하기

- **개념**
  - Profiler는 게임 실행 중 발생하는 **실시간 오디오 이벤트와 Game Sync 동작**을 모니터링할 수 있는 레이아웃입니다.
  - RTPC, Switch, State, 이벤트 호출 같은 다양한 데이터를 확인할 수 있습니다.
  - 디버깅과 최적화, 동작 검증에 핵심적으로 사용됩니다.
- **실습**
  - 메뉴 바에서 **`Layouts > Profiler`** 선택
  - Profiler 레이아웃이 열리면 기본적으로 여러 정보가 표시됩니다.

## 2. Display Options(디스플레이 옵션)으로 필터링

- **개념**
  - Profiler는 표시할 수 있는 데이터가 매우 많습니다.
  - 특정 항목만 보이도록 **Display Options**에서 필터링해 필요 없는 정보를 제거할 수 있습니다.

  2. `Capture Log Display Options` 대화 상자가 열림
  3. **States와 Switches만 남기고**, 나머지 모든 체크박스 해제
  4. 대화 상자 닫기

## 3. 게임과의 원격 연결(Remote Connect)

- **개념**
  - Wwise Profiler는 **게임 실행 환경(예: Cube 게임)**과 직접 연결해야 데이터(이벤트 호출, Game Sync 변화)를 받을 수 있습니다.
  - 이 과정을 **Remote Connection**이라고 부릅니다.
- **실습**
  1. Wwise 툴바에서 **Connect to Remote Platform (Shift+H)** 클릭
  2. Remote Connections 대화 상자에서:
     - (1) 연결할 **컴퓨터 선택**
     - (2) **Start capture on connect** 체크 (연결 즉시 캡처 시작)
     - (3) **Connect 버튼 클릭**

## 4. Capture(캡처) 기능 사용하기

- **개념**
  - Capture는 게임과 Wwise 간의 통신 로그(오디오 이벤트, Game Sync 호출 등)를 기록하는 기능입니다.
  - 연결 시 자동으로 시작할 수도 있고, 수동으로 시작/중지할 수도 있습니다.
- **실습**
  - Cube 게임을 실행하고, 캐릭터를 움직여 보면서 이벤트가 발생하도록 합니다.
  - Wwise에서는 자동으로 Capture Log가 기록됩니다.

---

## 5. Switch와 State 동작 확인하기

- **개념**
  - **Switch**: 오브젝트의 상태나 상황에 따라 다른 사운드를 재생하도록 만드는 Game Sync (예: 걷는 표면에 따라 다른 발자국 소리)
  - **State**: 게임의 전역적 상태를 반영하는 Game Sync (예: 플레이어가 살아있음 vs 패배 상태)
  - Profiler를 통해 **게임에서 실제로 어떤 Switch/State가 호출되었는지** 확인할 수 있습니다.
- **실습**
  - Cube에서 캐릭터를 움직이면 Wwise의 **Capture Log**에 Switch 호출 기록이 나타납니다.
  - 예: “플레이어가 어떤 표면 위에 있는지” → Switch 호출 확인 가능

- **실습**
