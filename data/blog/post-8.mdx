## 1. 이벤트 시스템이란 무엇인가?

### 🎯 **정의 — "어떤 일이 발생했음을 알리는 신호"**

프로그램 실행 중 특정 일이 일어나면

→ 이벤트(Event)를 **발생(Invoke)** 시킴

→ 다른 스크립트들이 그 이벤트를 **듣고(Subscribe)** 반응함

### ✔ 아주 쉽게 말하면?

- **발신자**: "야! 지금 ○○ 일어났어!"
- **수신자**: "오! 그럼 난 이걸 실행해야지!"

### ✔ 예시로 보면 바로 이해됨

- 캐릭터 체력이 0이 됨 → GameOver 이벤트 발송
- UI(HUD)가 이를 듣고 → 게임 오버 화면 표시
- 사운드 매니저가 듣고 → 게임 오버 효과음 재생

**이벤트가 없으면?**

UI, 사운드, 게임오버 시스템이 모두 PlayerHealth 스크립트를 직접 찾아가야 함 → 스파게티 코드

## 2. 이벤트를 왜 사용하는가?

### 👍 **1) 코드 간 의존도 ↓ (Decoupling)**

A 시스템이 B 시스템을 직접 몰라도 됨

→ 유지보수 쉬워짐

→ 코드가 깔끔함

### 👍 **2) 여러 시스템이 동시에 반응 가능**

하나의 사건에 대해

UI, 애니메이션, 사운드, 점수 시스템 등

**여러 개가 동시에 반응 가능**

### 👍 **3) 확장성 ↑**

나중에 기능을 추가해도

이벤트만 구독하면 바로 기능이 추가됨

## 3. C# 이벤트 기본 문법 이해하기(delegate / event)

### 🔷 기본 요소 2개

1. **delegate (델리게이트)**

   👉 “함수의 형태(Signature) 정의”

2. **event (이벤트)**

   👉 “다른 스크립트가 구독/발생할 수 있는 신호”

---

## 📌 3-1. delegate 만들기

함수 형태를 먼저 정의함.

```csharp
public delegate void OnSelected(Unit unit);
```

- 반환값: void
- 매개변수: Unit
  → 이 형태의 함수만 이벤트에 등록할 수 있음

---

## 📌 3-2. event 만들기

```csharp
public static event OnSelected OnUnitSelected;
```

---

## 📌 3-3. 이벤트 발생(Invoke)

```csharp
OnUnitSelected?.Invoke(unit);
```

`?.Invoke` → 구독자가 있을 때만 실행

---

## 📌 3-4. 이벤트 구독(Subscribe)

```csharp
private void OnEnable() {
    UnitActionSystem.OnUnitSelected += UpdateUI;
}
```

## 📌 3-5. 이벤트 구독 해제(Unsubscribe)

```csharp
private void OnDisable() {
    UnitActionSystem.OnUnitSelected -= UpdateUI;
}
```

## 추가 설명 **delegate(델리게이트)**

**delegate(델리게이트)는 “어떤 형태의 함수만 넣을 수 있다”라고 규칙을 만드는 것**이다.

즉,

- "이벤트에 등록될 함수들은 **반환값이 뭐고**,
- **매개변수가 뭐인지**"
  그 **형태(Signature)** 를 정하는 것.

그걸 “함수의 형태를 정의한다”라고 표현하는 거야.

---

# 🔥 더 쉽게, 핵심만 한 줄로 설명

> 델리게이트 = '이 이벤트에는 이런 모양(입력/출력)의 함수만 넣을 수 있어!' 라고 정하는 규칙.

---

# ❓ 그런데 왜 이런 규칙이 필요해?

이벤트에 함수들을 등록할 때

**모양(입력/출력)이 다르면 연결할 수 없음**.

예:

이벤트에서 **유닛 정보를 전달하려고 한다면**

👉 이벤트가 Unit 매개변수를 보내니까

👉 그걸 받을 함수도 반드시 `void 함수(Unit unit)` 형태여야 함.

---

# 📌 예시로 10초 만에 이해시키기

이벤트를 만들고 싶어:

### 🎯 "유닛이 선택되면, 그 유닛을 다른 곳에도 전달하고 싶다."

그러면 이벤트는 반드시

- `Unit`을 입력으로 받는 함수만 등록할 수 있어야 함.

그래서 이렇게 규칙을 만든다:

```csharp
public delegate void UnitSelectedDelegate(Unit unit);
```

읽는 법:

> "이 delegate를 사용하는 함수들은
>
> Unit을 입력으로 받고
>
> 반환값은 없고(void),
>
> 이름은 아무거나여도 된다."

---

# 📌 그럼 이 delegate를 사용하는 이벤트는 이렇게 생김

```csharp
public static event UnitSelectedDelegate OnUnitSelected;
```

---

# 📌 이제 이 이벤트는 이런 함수만 구독할 수 있다:

```
void UpdateUI(Unit unit) { ... }
void PlaySound(Unit unit) { ... }
void Highlight(Unit unit) { ... }
```

✔ Unit을 매개변수로 받음

✔ 반환값은 void

→ 이벤트 규칙에 맞음 → 등록 가능!

---

# ❌ 반대로 이런 함수들은 못 넣음:

```
void UpdateUI() {} // Unit 매개변수가 없음 → ❌

int UpdateUI(Unit unit) { return 0; } // 반환값이 int → ❌

void UpdateUI(int number) {} // 매개변수가 Unit이 아니고 int → ❌
```

왜?

delegate에서 **함수 형태가 이미 정해져 있기 때문**.

---

# 📌 비유 없는 초간단 정리

| 개념            | 실제 의미                                                  |
| --------------- | ---------------------------------------------------------- |
| delegate 정의   | “이 이벤트는 이런 모양(매개변수/반환값)의 함수만 받아!”    |
| event 생성      | “이 규칙을 가지고 이벤트를 만들게!”                        |
| 구독(Subscribe) | “내 함수가 이 규칙에 맞으니까 이벤트가 일어나면 실행해줘!” |

2. `UnitUI` : 이벤트를 듣고 **UI 업데이트**
3. `UnitSound` : 이벤트를 듣고 **선택 사운드 재생**

3개의 독립된 클래스가 이벤트로 연결된다.

## 🧩 1. 이벤트 발신자 (UnitActionSystem)

```csharp
using UnityEngine;
using System;

public class UnitActionSystem : MonoBehaviour
{
    public static event Action<Unit> OnUnitSelected;
    // Action<Unit> 은 "Unit을 받는 void 함수" 형태만 가능

    [SerializeField] private LayerMask unitLayerMask;

    private void Update()
    {
        if (Input.GetMouseButtonDown(0))
        {
            TrySelectUnit();
        }
    }

    private void TrySelectUnit()
    {
        Ray ray = Camera.main.ScreenPointToRay(Input.mousePosition);

        if (Physics.Raycast(ray, out RaycastHit hit, 100f, unitLayerMask))
        {
            if (hit.transform.TryGetComponent<Unit>(out Unit unit))
            {
                Debug.Log("유닛 선택됨: " + unit.name);

                // 🔥 이벤트 발송
                OnUnitSelected?.Invoke(unit);
            }
        }
    }
}

```

## 🧩 2. 이벤트 구독자 #1 — UI 업데이트 (UnitUI)

```csharp
using UnityEngine;
using UnityEngine.UI;

public class UnitUI : MonoBehaviour
{
    [SerializeField] private Text unitNameText;
    [SerializeField] private GameObject panel;

    private void OnEnable()
    {
        UnitActionSystem.OnUnitSelected += UpdateUI;
    }

    private void OnDisable()
    {
        UnitActionSystem.OnUnitSelected -= UpdateUI;
    }

    private void UpdateUI(Unit selectedUnit)
    {
        panel.SetActive(true);
        unitNameText.text = selectedUnit.unitName;

        Debug.Log("UI 업데이트됨: " + selectedUnit.unitName);
    }
}

```

- 선택 로그 시스템

  이벤트 구독만 하면 자동 연결됨.

# { 이벤트에서 += 를 사용하는 이유? }

## 1️⃣ 이벤트는 "리스트" 같은 구조다

이벤트는 내부적으로

**“나중에 실행할 함수 목록(List)”** 을 가지고 있어.

예시로 보면 바로 이해됨:

```
OnUnitSelected = [ ]
```

아무도 구독하지 않았으면 비어있음.

---

## 2️⃣ += 는 “이 리스트에 내 함수도 넣어줘!”

```csharp
UnitActionSystem.OnUnitSelected += UpdateUI;
```

이 코드를 실행하면:

```
OnUnitSelected = [ UpdateUI ]
```

만약 다른 클래스에서도 구독하면:

```
OnUnitSelected = [ UpdateUI, PlaySound, HighlightUnit, LogSelection ]
```

👉 이벤트가 발생할 때

→ 이 리스트 안에 있는 함수들이 **전부 실행됨**

---

## 3️⃣ -= 는 “리스트에서 제거해줘!”

```csharp
UnitActionSystem.OnUnitSelected -= UpdateUI;
```

실행되면:

```
OnUnitSelected = [ PlaySound, HighlightUnit, LogSelection ]

```

즉,

⭐ **OnDisable()에서 제거하는 이유는
오브젝트가 꺼지면 더 이상 이벤트 받으면 안 되기 때문!**

---

## 4️⃣ 만약 -= 를 안 하면 어떻게 될까?

❌ UI 오브젝트가 비활성화되었는데도

이벤트가 계속 날아옴 → 에러 발생

❌ 씬이 바뀌어도 이전 UI가 계속 이벤트를 듣고 있어 → 에러 & 메모리 누수

그래서

`+=` 는 구독

- `=` 는 구독 해제

가 반드시 쌍으로 있어야 함.

## 1. 이벤트 시스템이란?

### 🔥 **이벤트(Event)란?**

특정 상황이 발생했음을 _다른 객체에게 알려주는 신호_.

예)

- “유닛이 선택되었습니다”
- “체력이 0이 되었습니다”
- “버튼이 눌렸습니다”

→ 이 **사건(Event)** 을 “들을 사람(Listener)”들이 있다면, 그들에게 알려주게 됨.

---

### 🤝 **왜 이벤트를 쓰는가?**

게임은 많은 객체들이 서로 영향을 주고받음.

하지만 아래처럼 직접 연결해버리면?

```
Unit → UI → Audio → Camera → Log
```

→ **엉키고 의존성 지옥 발생**

그래서 이렇게 바꿈:

```
UnitActionSystem -----(이벤트 발생)-----> UI
                    -----> Audio
                    -----> Camera
                    -----> Log
```

**하나의 이벤트를 여러 시스템이 동시에 듣는 구조**

→ 유지보수 쉽고, 확장 쉬움

---

---

## 2. 델리게이트(delegate) 이해하기

### 🎯 델리게이트란?

➡ **“이벤트가 호출할 수 있는 함수 형태(템플릿)”**

즉, **함수의 타입**이라고 보면 됨.

---

### ▶ 예시: 델리게이트 직접 만들기

```csharp
public delegate void MyDelegate(int value);
```

이건 "정수 하나를 받는 함수" 라는 의미.

이 델리게이트는 아래 함수와 호환됨:

```csharp
void PrintNumber(int value) {
    Debug.Log("값: " + value);
}
```

---

### 📌 델리게이트는 이벤트의 기반

이벤트는 내부적으로 **델리게이트를 사용해 함수들을 묶어둘 수 있음**.

---

---

## 3. EventHandler 개념과 표준 형태

### 🌍 EventHandler란?

C#에서 **표준으로 정해둔 델리게이트 형태**

즉, "이벤트는 이런 형태의 함수를 가진다!"라고 규칙을 정해둔 것.

---

### 📑 EventHandler의 실제 정의

```csharp
public delegate void EventHandler(object sender, EventArgs e);
```

즉, **항상 2개 파라미터를 받는 함수 틀**

| 파라미터      | 의미                      |
| ------------- | ------------------------- |
| `sender`      | 이벤트를 발생시킨 객체    |
| `EventArgs e` | 이벤트에 대한 추가 데이터 |

---

### ✔ 왜 많이 쓰냐?

- Unity/C# 개발자들이 바로 알아봄 (표준)
- EventArgs를 상속하면 추가 정보를 쉽게 실을 수 있음
- 유지보수가 좋음
- 여러 시스템이 이벤트를 공유하기 쉬움

---

---

## 4. 이벤트 선언하기

### ▶ 이벤트 선언 기본 형태

```csharp
public event EventHandler OnSelectedUnitChanged;
```

- `event` → “이건 이벤트입니다”
- `EventHandler` → 함수 형태 지정
- `OnSelectedUnitChanged` → 이벤트 이름

---

### ✔ 이벤트 이름 규칙

보통 다음 형태로 짓는다:

```
On + 과거형 + Event + 이름
```

예)

- OnSelectedUnitChanged
- OnHealthZero
- OnButtonClicked

---

---

## 5. 이벤트 구독과 해제

### 🎧 이벤트 구독(+=)

“이 이벤트가 일어나면 이 함수를 실행시켜줘!”

```csharp
UnitActionSystem.OnSelectedUnitChanged += UpdateUI;
```

---

### 🔌 이벤트 해제(-=)

OnDisable에서 꼭 해줘야 하는 이유:

- 씬이 바뀌거나 오브젝트가 사라질 때
- 이벤트는 살아있는데 구독한 오브젝트는 사라져버리면
  → **NullReferenceException** 발생

그래서 꼭 해제해야 함:

```csharp
UnitActionSystem.OnSelectedUnitChanged -= UpdateUI;
```

---

---

# ## 6. 이벤트 트리거(Invoke)하기

### ▶ 이벤트 호출하는 법

```csharp
OnSelectedUnitChanged?.Invoke(this, EventArgs.Empty);
```

여기서 중요한 점:

| 요소              | 설명                           |
| ----------------- | ------------------------------ |
| `?.`              | 구독자가 없으면 null 예외 방지 |
| `this`            | 이벤트를 발생시킨 객체         |
| `EventArgs.Empty` | 아무 정보가 없을 때            |

---

---

# ## 7. 완성 예제

### 🎯 **유닛 선택 이벤트 시스템 전체 흐름**

---

## 📌 UnitActionSystem.cs (핵심 이벤트 시스템)

```csharp
using System;
using UnityEngine;

public class UnitActionSystem : MonoBehaviour
{
    // 싱글턴 패턴: 어디서든 쉽게 접근하기 위해 Instance를 제공
    // Instance는 이 클래스의 유일한 객체가 된다.
    public static UnitActionSystem Instance { get; private set; }

    // 유닛이 선택될 때 호출되는 이벤트
    // EventHandler: (object sender, EventArgs e) 형태의 함수를 구독할 수 있음
    public event EventHandler OnSelectedUnitChanged;

    // 현재 선택된 유닛을 저장하는 변수
    private Unit selectedUnit;

    private void Awake()
    {
        // Awake에서 싱글턴 Instance 설정
        Instance = this;
    }

    // 외부에서 유닛을 선택할 때 호출하는 함수
    public void SelectUnit(Unit unit)
    {
        // 내부 selectedUnit 값을 갱신
        selectedUnit = unit;

        // 이벤트 호출
        // ?. → 구독자가 있을 때만 Invoke 실행 (Null 방지)
        // this → 이벤트를 발생시킨 객체 전달
        // EventArgs.Empty → 전달할 데이터가 없을 때 사용
        OnSelectedUnitChanged?.Invoke(this, EventArgs.Empty);
    }

    // 현재 선택된 유닛을 반환하는 getter
    public Unit GetSelectedUnit()
    {
        return selectedUnit;
    }
}

```

---

## 📌 UnitSelectedUI.cs (UI가 이벤트를 듣는 역할)

```csharp
using System;
using UnityEngine;

public class UnitSelectedUI : MonoBehaviour
{
    private void OnEnable()
    {
        // 이벤트 구독(+=)
        // "유닛이 선택되었습니다" 라는 이벤트가 발생하면
        // 내 UpdateUI 함수가 자동으로 실행되도록 등록한다.
        UnitActionSystem.Instance.OnSelectedUnitChanged += UpdateUI;
    }

    private void OnDisable()
    {
        // 이벤트 구독 해제(-=)
        // 오브젝트가 비활성화될 때 이벤트에서 제거하지 않으면
        // 이미 삭제된 오브젝트가 호출되어 오류 발생 가능 → 반드시 해제해야 한다.
        UnitActionSystem.Instance.OnSelectedUnitChanged -= UpdateUI;
    }

    // 이벤트가 발생했을 때 자동으로 호출될 함수
    // EventHandler 표준 형태에 맞춰 (object sender, EventArgs e) 를 받는다.
    private void UpdateUI(object sender, EventArgs e)
    {
        // 현재 선택된 유닛 가져오기
        Unit selected = UnitActionSystem.Instance.GetSelectedUnit();

        // 콘솔에 선택된 유닛 이름 출력
        Debug.Log("선택된 유닛 UI 갱신: " + selected.name);
    }
}

// “OnEnable()을 내가 호출한 적이 없는데 왜 실행되지?”
// OnEnable()은 우리가 직접 호출하는 함수가 아니라 Unity가 알아서 자동으로 호출해주는 생명주기 함수이기 때문이야. 스크립트가 들어있는 게임오브젝트가 씬에 등장해서 활성화될 때, 혹은 비활성화되어 있던 오브젝트가 다시 켜질 때, Unity가 자동으로 OnEnable()을 실행해 준다. 그래서 우리는 OnEnable()을 부른 적이 없어도 Unity가 내부적으로 “아, 이 오브젝트가 켜졌네? 그럼 OnEnable 실행해야지!” 하고 자동으로 호출하는 것이다. 이런 생명주기 함수 덕분에 개발자는 굳이 직접 호출하지 않고도 필요한 초기 설정(예: 이벤트 등록)을 자연스럽게 처리할 수 있다.
```

## 📌 Unit.cs (유닛이 클릭되었을 때 이벤트 보내는 역할)

```csharp
using UnityEngine;

public class Unit : MonoBehaviour
{
    // 마우스로 클릭했을 때 자동으로 호출되는 Unity 이벤트 함수
    private void OnMouseDown()
    {
        // UnitActionSystem에게 "나(이 유닛)를 선택해!" 라고 요청
        UnitActionSystem.Instance.SelectUnit(this);
    }
}

```

# ✅ 위의 코드 **전체 흐름을 한눈에 보기**

## **1) 게임이 시작되면**

### **(1) UnitActionSystem이 먼저 깨어난다(Awake 실행)**

- `UnitActionSystem` 오브젝트가 씬 안에 있으므로
  Unity가 자동으로 `Awake()`를 호출한다.
- 여기에서
  ```csharp
  Instance = this;
  ```
  를 실행해서 **싱글톤을 준비**한다.
  → "프로젝트 전체에서 단 하나의 UnitActionSystem만 쓰자" 라는 의미.

---

## **2) UnitSelectedUI 오브젝트가 활성화될 때**

### **(2) Unity가 자동으로 OnEnable() 실행**

- 스크립트가 붙은 UI 오브젝트가 켜지면 Unity가 자동으로 `OnEnable()` 호출.
- 여기에서 이벤트 구독이 이루어진다:
  ```csharp
  UnitActionSystem.Instance.OnSelectedUnitChanged += UpdateUI;
  ```

📌 **즉, “유닛이 선택되었다는 소식이 오면, UpdateUI를 불러줘!” 라고 등록하는 단계.**

---

## **3) 플레이어가 유닛을 클릭한다**

### **(3) Unit의 OnMouseDown() 실행**

- 마우스로 유닛 클릭 → Unity가 자동으로 `OnMouseDown()` 실행.
- 여기서:
  ```csharp
  UnitActionSystem.Instance.SelectUnit(this);
  ```
  이 코드가 실행되어 클릭된 유닛을 UnitActionSystem에 전달한다.

---

## **4) UnitActionSystem 이 유닛을 선택함**

### **(4) SelectUnit() 실행**

- 클릭된 유닛이 `selectedUnit` 변수에 저장됨.
- 그리고 이벤트를 발동한다:
  ```csharp
  OnSelectedUnitChanged?.Invoke(this, EventArgs.Empty);
  ```

📌 여기서 중요한 점

→ **이벤트가 “소리치듯” 알림을 보내는 순간**

“모두들! 방금 유닛이 선택되었어!!”

---

## **5) 이벤트를 듣고 있던 UI가 반응함**

### **(5) UnitSelectedUI.UpdateUI() 실행됨**

- 이벤트를 구독해 둔 덕분에 자동으로 호출된다.
- 이 함수 안에서:
  ```csharp
  Unit selected = UnitActionSystem.Instance.GetSelectedUnit();
  Debug.Log("선택된 유닛 UI 갱신: " + selected.name);
  ```
- 즉, UI가 최신 선택된 유닛을 가져와 화면에 표시함.

📌 개발자가 UpdateUI()를 직접 호출한 적 **없다**.

→ **이벤트 시스템이 자동으로 불러준 것**이다.

---

## **정리: 흐름을 7줄로 끝내기**

1. 게임 실행
2. `UnitActionSystem.Awake()` → 싱글톤 설정
3. `UnitSelectedUI.OnEnable()` → "유닛 선택되면 알려줘" 구독
4. 플레이어가 유닛 클릭
5. `Unit.OnMouseDown()` → SelectUnit() 호출
6. `UnitActionSystem.SelectUnit()` → 이벤트 발동
7. 이벤트를 듣고 있던 `UnitSelectedUI.UpdateUI()` 자동 실행 → UI 갱신

---

# { 🎯 Update() vs Event 비교 }

👉 **상태가 자주 변하고 매 프레임 체크해야 하는 것 → Update()**

👉 **특정 상황이 발생했을 때만 반응하면 되는 것 → 이벤트(Event)**

---

## 🔥 Update() vs Event 비교

| 항목      | Update()                      | 이벤트(Event)                           |
| --------- | ----------------------------- | --------------------------------------- |
| 호출 시점 | 매 프레임 (초당 60~200번)     | 상황 발생 시 한 번                      |
| 성능      | 불필요한 체크가 많으면 느려짐 | 체크 없이 바로 실행 → 효율적            |
| 구조      | 스크립트마다 계속 실행됨      | 실행해야 할 때만 실행                   |
| 의존성    | 직접 조건을 체크해야 함       | 간접적(발생 → 수신) 구조                |
| 사용 사례 | 움직임, 물리, 입력            | UI 갱신, 선택 변경, 딱 한번 발생하는 일 |

---

---

## 🧠 Update()가 필요한 경우

### ✔ 입력(Input) 처리

키보드 / 마우스 입력은 항상 체크해야 하므로 Update가 맞음.

### ✔ 로직이 **지속적으로 변화**하는 경우

- 캐릭터 움직임
- 카메라 따라가는 기능
- 애니메이션 상태 계산
- 타이머 감소

→ 이런 것들은 매 프레임 변화하니까 이벤트로 처리할 수 없음.

---

---

## 🛎️ 이벤트(Event)가 필요한 경우

### ✔ "상태가 바뀔 때만 반응"하면 되는 모든 일

예)

- 유닛이 선택되었을 때 UI 업데이트
- 체력이 변할 때 UI 게이지 변경
- 인벤토리에 아이템 추가되었을 때 알림 표시
- 레벨 완료되었을 때 효과 실행
- 적이 죽었을 때 점수 증가

이런 것들은 매 프레임 체크할 필요가 없음.

---

---

void Update()
