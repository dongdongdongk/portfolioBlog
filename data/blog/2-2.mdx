## 1. 메소드란 무엇인가?

- **메소드(Method)** = 함수(Function)와 유사한 개념
- 코드 블록을 실행시켜 게임을 동작하도록 하는 **작업 단위**
- 현실 세계로 치면 "지시 사항"을 미리 정의해두고, 필요할 때 실행하는 것

---

## 2. 메소드의 기본 구조

- **반환 유형(Return Type)** → `void`, `int`, `bool` 등
- **이름(Name)** → 의미 있는 이름 사용 (PascalCase 권장: CleanYourRoom)
- **괄호(Parameters)** → 매개변수를 담는 공간
- **중괄호(Code Block)** → 실제 실행할 코드 작성
- **세미콜론(;)** → 각 문장 마무리에 필요

```csharp
ReturnType MethodName(ParameterType parameterName) {
    // 실행할 코드
    return 값; // 반환값이 있을 경우
}
```

---

## 3. 선언(Declare), 정의(Define), 호출(Call)

- **선언(Declare)**: 메소드의 이름과 반환값, 매개변수 지정 (존재를 알림)
- **정의(Define)**: 메소드가 실제로 무슨 일을 하는지 코드 작성
- **호출(Call)**: 필요할 때 메소드를 실행 (`MethodName();`)

---

## 4. 매개변수(Parameter)와 인수(Argument)

- **매개변수(Parameter)** = 메소드가 필요로 하는 **정보의 형식**
- **인수(Argument)** = 호출 시 실제로 전달하는 **구체적인 값**

예:

```csharp
void CleanYourRoom(int deadline) { ... }  // deadline = 매개변수
CleanYourRoom(30); // 30 = 인수
```

---

## 5. 반환(Return)과 반환 유형

- 메소드 실행 후 **값을 돌려주는 것**
- 반환 유형이 없다면 `void` 사용
- 예:

```csharp
bool IsRoomDirty() {
    return true; // 방이 더럽다
}
```

---

## 6. 메소드 이름 짓기 규칙

- 첫 글자는 대문자 (PascalCase)
- 의미 있는 이름 사용 (`CleanYourRoom` > `Clean`)
- 메소드 이름만 봐도 어떤 동작인지 알 수 있도록 작성

---

## 7. 괄호의 종류와 의미

- **() 소괄호** → 메소드 호출, 매개변수 위치
- **[] 대괄호** → 배열
- **{} 중괄호** → 코드 블록

---

## 8. 실제 예시: CleanYourRoom 메소드

- **설정**: 옷 줍기, 쓰레기 버리기, 곰팡이 낀 피자 제거
- **매개변수**: 언제까지 해야 하는지 (예: 30분, 저녁 전까지)
- **반환**: 방이 깨끗해졌는지 `true/false`로 알려주기
- **현실 비유**: 어머니가 “방 청소해!”라고 지시 = 메소드 호출

---

## 9. 유니티에서의 메소드와 콜백

- 유니티는 특정 상황에서 자동으로 메소드를 호출함 → **콜백(Callback)**
- **Start()**: 오브젝트가 활성화되면 자동 실행
- **Update()**: 매 프레임마다 자동 실행
- 개발자는 메소드를 정의만 하고, 호출은 유니티가 알아서 처리

---

## 10. 핵심 정리

- 메소드는 **작업을 묶어서 재사용** 가능하게 하는 코드 블록
- 구조 = `반환 유형 + 이름 + 괄호(매개변수) + 중괄호(실행 코드)`
- **매개변수** = 필요 정보, **인수** = 실제 값
- **반환값** = 메소드 실행 후 돌려주는 결과 (`void`는 없음)
- **콜백 메소드**: 유니티가 자동으로 호출해주는 특별한 메소드 (Start, Update 등)

## 1. 도전 과제: ObjectHit 스크립트 만들기

- **새로운 C# 스크립트 생성** → 이름은 `ObjectHit`.
- 이 스크립트를 **모든 벽과 장애물**에 붙여야 함.
- Unity에서 여러 개 오브젝트를 **한 번에 선택 후 컴포넌트 추가**하면 효율적으로 작업 가능.

> 💡 도전 과제를 통해 "스크립트를 원하는 오브젝트에 적용하는 방법"을 학습.

## 2. 스크립트 오브젝트에 부착하기

## 3. 콜백 메소드: OnCollisionEnter 이해하기

- `OnCollisionEnter`는 **Unity 콜백 메소드** 중 하나.
- **콜백(Callback)**: 우리가 직접 호출하지 않아도, Unity가 특정 상황에서 자동 실행하는 메소드.
- 이 경우:
  - 오브젝트의 **Collider**와 **Rigidbody**가 다른 Collider와 충돌할 때 실행됨.

---

## 4. Collider와 Rigidbody의 관계

- 충돌이 감지되려면 최소한 한쪽 오브젝트에 **Rigidbody**가 있어야 함.
- 벽(Obstacle) → Collider만 있음.
- 플레이어(Player) → Collider + Rigidbody 있음.
- 이 조합으로 충돌이 감지되고, Unity가 `OnCollisionEnter`를 호출.

---

## 5. 접근 제한자 (public vs private)

- `private`: 스크립트 내부에서만 사용 가능 (Unity 기본값).
- `public`: 외부(다른 스크립트/에디터)에서도 접근 가능.
- 이번 예제에서는 깊게 다루지 않지만, **정보 공유 범위**를 결정하는 중요한 개념.

---

## 6. 충돌 시 메시지 출력하기

- 충돌 이벤트 발생 시 콘솔에 출력:

```csharp
void OnCollisionEnter(Collision other) {
    Debug.Log("Something hit me!");
}
```

- 실행 후 벽에 부딪히면 콘솔에 메시지 표시.

---

## 7. OnCollisionEnter 동작 방식

- `OnCollisionEnter`는 **Collider A가 Collider B에 "처음 들어갈 때"** 실행.
- 계속 충돌 상태에 있더라도 **한 번만 호출**됨.
- 동일한 충돌을 반복하면 콘솔에서 **메시지가 묶여 카운트**로 표시됨.

---

## 8. 활용 예시: 점수, 체력 감소 처리

- 현재는 단순히 콘솔 출력만 하지만,
- 실제 게임에서는 충돌을 활용해:
  - 플레이어 체력 감소
  - 점수 차감
  - 아이템 획득
  - 장애물 파괴
    등 다양한 게임 로직을 구현할 수 있음.

---

✅ **핵심 정리**

- `OnCollisionEnter`는 Unity가 자동으로 호출하는 **충돌 콜백 메소드**다.
- 충돌 감지는 **Collider + Rigidbody** 조합으로 이루어진다.
- 충돌 이벤트를 활용해 콘솔 출력, 점수 처리, 체력 감소 등 **게임의 핵심 로직**을 구현할 수 있다.

## 1. 컴포넌트(Component) 개념 이해하기

- 유니티에서 **게임 오브젝트(GameObject)** 는 여러 **컴포넌트(Component)** 로 구성됩니다.
- 컴포넌트는 오브젝트의 기능과 특징을 정의하는 블록 같은 존재입니다.
  - 예: `Mesh Renderer`(보이게 함), `Box Collider`(충돌 영역), `Script`(행동 정의).
- 우리가 코드로 접근할 때는 오브젝트가 가진 컴포넌트들을 가져와서 활용합니다.

---

## 2. 벽 오브젝트가 가진 요소들

벽에는 기본적으로 다음과 같은 컴포넌트가 있습니다:

- **Mesh Renderer** → 벽의 모양을 화면에 렌더링하는 요소
- **Box Collider** → 벽과 충돌할 수 있도록 하는 요소
- **ObjectHit (Script)** → 우리가 작성하는 스크립트, 벽의 동작을 제어

---

## 3. Mesh Renderer와 Material

- **Mesh Renderer** 는 오브젝트의 외형을 담당합니다.
- 그 안에는 **Material(재질)** 이 포함되어 있으며, 색상, 질감, 광택 등의 시각적 특성을 정의합니다.
- 예를 들어 벽에 파란색 재질을 넣어두면, 벽이 파란색으로 보이게 됩니다.

---

## 4. GetComponent의 역할

- `GetComponent<T>()` 는 게임 오브젝트에 붙어 있는 **특정 컴포넌트**를 가져오는 함수입니다.
- 예:
  ```csharp
  GetComponent<MeshRenderer>()
  ```
  → 현재 오브젝트에 붙어 있는 `MeshRenderer`를 가져옵니다.
- 가져온 컴포넌트를 통해 내부 속성(`material.color` 등)에 접근할 수 있습니다.

---

## 5. OnCollisionEnter와 충돌 감지

- `OnCollisionEnter(Collision collision)` 메서드는 유니티의 **콜백 함수**로,
  오브젝트가 다른 오브젝트와 부딪힐 때 자동으로 실행됩니다.
- 즉, 플레이어가 벽에 부딪히면 이 함수가 호출됩니다.

---

## 6. 코드로 색상 변경하기

벽이 충돌했을 때 색상을 바꾸는 기본 코드:

```csharp
using UnityEngine;

public class ObjectHit : MonoBehaviour
{
    void OnCollisionEnter(Collision collision)
    {
        // 벽의 MeshRenderer를 가져와서 색상 변경
        GetComponent<MeshRenderer>().material.color = Color.red;

        Debug.Log("뭔가 부딪혔습니다.");
    }
}
```

- `GetComponent<MeshRenderer>()` → 벽의 Mesh Renderer 가져오기
- `.material.color = Color.red` → 재질의 색상을 빨간색으로 변경

---

## 7. 색상 실습과 도전 과제

- 기본 예시는 **빨강(Color.red)** 으로 변경했지만, 다른 색상도 실습할 수 있습니다.
- 예:
  ```csharp
  GetComponent<MeshRenderer>().material.color = Color.black; // 검은색
  GetComponent<MeshRenderer>().material.color = Color.green; // 초록색
  GetComponent<MeshRenderer>().material.color = Color.gray;  // 회색
  ```
- 색상은 **피드백의 의미**도 가집니다.
  - 빨강 → 경고, 충돌, 잘못됨
  - 초록 → 안전, 성공
  - 검정/회색 → 차분함, 중립

---

👉 이번 강의의 핵심은 **오브젝트의 컴포넌트에 접근해 동작을 제어하는 방법**을 익히는 것입니다.

즉, **충돌 이벤트 → GetComponent → 속성 변경** 의 흐름을 이해하면 다른 기능(소리, 이펙트 등)도 동일한 방식으로 확장할 수 있습니다.

## 1. 책임 분배 개념 이해하기

- **프로그래밍 핵심**: 누가 무엇을 책임지는가?

## 1. 조건문(Condition)과 if 문 이해하기

- **조건문**은 특정 상황이 **참(True)**일 때만 실행되는 코드 구조.
- **if 문**은 가장 기본적인 조건문이며, `if (조건식) { 실행할 코드 }` 형태를 가짐.
- 조건식은 반드시 **참 또는 거짓**으로 평가될 수 있어야 함.
  - 예: `if (1 > 0)` → 참(True) → 코드 실행.
  - 예: `if (Time.time > 3)` → 3초가 지나면 참 → 코드 실행.

---

## 2. Time.time 활용하기

- `Time.time`은 **게임 시작 후 경과된 시간(초 단위)**을 의미.
- 프레임마다 증가하는 값이므로, 특정 시간이 지났는지를 체크하는 데 유용.
- 예: `if (Time.time > 3)` → 게임이 시작되고 3초가 지난 순간 조건이 참이 됨.

---

## 3. if 문으로 조건 체크하기

- `Update()` 메서드 안에서 `if` 조건을 주면 **실시간 체크** 가능.
- 예제 코드:

  ```csharp
  void Update()
  {
      if (Time.time > 3)
      {
          Debug.Log("아래를 조심하세요");
      }
  }

  ```

- 문제: `Update()`는 매 프레임마다 실행되므로, **조건이 만족되면 계속 출력**됨.

---

## 4. 매직 넘버(Magic Number)와 문제점

- 코드에 직접 숫자를 넣는 것을 **매직 넘버**라고 부름.
- 예: `if (Time.time > 3)` → 여기서 `3`은 하드코딩된 값.
- 문제점:
  - 의미가 불분명함.
  - 나중에 수정할 때 코드 전체를 찾아야 함.
  - 유지보수와 가독성이 떨어짐.

---

## 5. 변수 활용과 직렬화(SerializeField)

- 매직 넘버 대신 **변수**를 사용.
- `SerializeField` 키워드를 붙이면 Unity **Inspector 창에서 수정 가능**.
- 예제 코드:

  ```csharp
  [SerializeField] float timeToWait = 2f;

  void Update()
  {
      if (Time.time > timeToWait)
      {
          Debug.Log("추락합니다");
      }
  }
  ```

- 장점: 코드 수정 없이 Inspector에서 값만 바꿔도 동작이 변경됨.

---

## 6. Inspector에서 변수 제어하기

- `timeToWait` 변수는 Inspector 창에서 노출됨.
- 오브젝트별로 서로 다른 대기 시간을 줄 수 있음.
- 예:
  - Dropper A → 2초
  - Dropper B → 5초
  - Dropper C → 10초

---

## 7. 여러 오브젝트에 적용하기

- Dropper 스크립트를 여러 오브젝트에 붙이면, Inspector에서 각각 다른 `timeToWait` 값 설정 가능.
- 결과: 여러 오브젝트가 서로 다른 타이밍에 떨어지는 효과 구현 가능.
- 이는 **재사용성**과 **유연성**을 높여줌.

---

👉 요약

- **if 문**은 특정 조건이 참일 때만 코드를 실행.
- **Time.time**을 활용해 게임 경과 시간을 조건으로 사용 가능.
- **매직 넘버** 대신 변수를 사용해 유지보수성을 높임.
- `[SerializeField]`를 사용하면 Inspector에서 손쉽게 값 변경 가능.
- 여러 오브젝트에 동일 스크립트를 적용하고, Inspector에서 변수만 다르게 설정하면 다양한 동작을 구현할 수 있음.

## 1. 컴포넌트(Component)와 캐싱 이해하기

- **컴포넌트(Component)**: Unity 오브젝트의 기능을 담당하는 개별 모듈 (예: Mesh Renderer, Rigidbody).
- **캐싱(Caching)**: 자주 쓰는 컴포넌트 참조를 **변수에 저장**해서 필요할 때마다 빠르게 접근하는 것.
  - `GetComponent<T>()`를 매번 호출하면 성능 낭비가 생길 수 있음.
  - 따라서 한 번만 가져와서 변수에 저장해두면 여러 번 사용할 때 유리.

---

## 2. Rigidbody 추가 및 중력 제어하기

- **Rigidbody**는 오브젝트가 물리 법칙(중력, 충돌 등)을 따르게 함.
- 기본 속성 중 **Use Gravity**를 제어하면 오브젝트가 떨어질지/떠 있을지 조정 가능.
- 이번 예제에서는:
  - 시작할 때 `useGravity = false` → 공중에 떠 있음.
  - 시간이 지나면 `useGravity = true` → 땅으로 떨어짐.

---

## 3. Mesh Renderer로 보이기/숨기기 제어하기

- **Mesh Renderer**는 오브젝트가 화면에 보이도록 렌더링해주는 컴포넌트.
- `enabled` 속성을 제어하여 보이게(`true`) 또는 숨기게(`false`) 할 수 있음.
- 이번 예제에서는:
  - 시작할 때 `enabled = false` → 플레이어가 처음에 못 봄.
  - 시간이 지나면 `enabled = true` → 나타남.

---

## 4. GetComponent와 캐싱의 차이

- `GetComponent<MeshRenderer>().enabled = false;`
  → 가져오기와 설정을 한 줄에서 처리.
- **캐싱 방식**:

  ```csharp
  MeshRenderer myMeshRenderer;
  void Start() {
      myMeshRenderer = GetComponent<MeshRenderer>();
      myMeshRenderer.enabled = false;
  }

  ```

  → 나중에 `myMeshRenderer`를 여러 번 활용 가능.

**장점**:

- 코드 가독성 ↑
- 성능 최적화 ↑ (GetComponent 반복 호출 방지)
- 재사용성 ↑

---

## 5. Dropper 스크립트 구현하기

```csharp
public class Dropper : MonoBehaviour
{
    [SerializeField] float timeToWait = 2f;

    MeshRenderer myMeshRenderer;
    Rigidbody myRigidBody;

    void Start()
    {
        // 캐싱
        myMeshRenderer = GetComponent<MeshRenderer>();
        myRigidBody = GetComponent<Rigidbody>();

        // 시작 시 보이지 않고 중력도 꺼짐
        myMeshRenderer.enabled = false;
        myRigidBody.useGravity = false;
    }

    void Update()
    {
        // 일정 시간 지나면 보이고 중력 적용
        if (Time.time > timeToWait)
        {
            myMeshRenderer.enabled = true;
            myRigidBody.useGravity = true;
        }
    }
}

```

## 6. 작동 원리와 실행 흐름

1. 게임 시작 시:
   - Mesh Renderer 꺼짐 → 오브젝트가 보이지 않음.
   - Rigidbody 중력 꺼짐 → 공중에 멈춤.
2. 일정 시간(`timeToWait`) 경과 후:
   - Mesh Renderer 켜짐 → 오브젝트가 다시 보임.
   - Rigidbody 중력 켜짐 → 오브젝트가 아래로 떨어짐.

---

## 7. 정리: 캐싱의 장점

- 컴포넌트를 매번 찾지 않고 변수에 저장 → 효율적.
- 여러 번 사용할 때 코드를 간결하게 유지 가능.
- 초보 단계에서는 "무엇이 타입이고, 무엇이 변수 이름인지" 명확히 구분하는 습관이 중요.
