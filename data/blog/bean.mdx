```jsx
스프링에서 **빈(Bean)**을 사용하는 이유는 객체의 생명주기 관리, 의존성 주입,

효율적인 애플리케이션 구조를 지원하기 위해서입니다.

이 개념을 이해하면 왜 스프링이 빈을 사용하고, Node.js 같은 환경에서는 빈을 사용하지 않는지 알 수 있습니다.
```

## 1. **빈(Bean)이란?**

```jsx
스프링에서 빈은 스프링 컨테이너가 관리하는 객체입니다. 보통 빈은 특정 기능을 수행하는 객체로,

스프링이 애플리케이션 실행 중에 빈을 생성하고, 관리하며, 필요한 곳에 주입합니다.

빈을 사용하면 객체 간의 의존성을 쉽게 관리할 수 있으며, 객체 생성과 관리의 복잡도를 줄일 수 있습니다.
```

## 2. **스프링에서 빈을 사용하는 이유**

### (1) 의존성 주입 (Dependency Injection)

```jsx
스프링은 객체 간의 의존성을 주입하여 관리합니다.

이를 통해 개발자는 객체를 직접 생성하거나 초기화할 필요 없이 스프링이 적절한 시점에 필요한 객체를 자동으로 제공해줍니다.

이는 코드의 유연성과 재사용성을 높여주며, 테스트하기 쉬운 구조를 만들 수 있습니다.
```

```jsx
@Service
public class UserService {
    private final UserRepository userRepository;

    @Autowired  // 스프링이 UserRepository 빈을 주입
    public UserService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }

    public User getUserById(Long id) {
        return userRepository.findById(id).orElse(null);
    }
}
```

```jsx
여기서 UserService는 UserRepository에 의존하고 있지만,

스프링이 알아서 UserRepository 빈을 주입해줍니다. 개발자가 직접 객체를 생성할 필요가 없습니다.
```

### (2) 객체 생명주기 관리

```jsx
스프링 컨테이너는 빈의 생성, 초기화, 소멸까지 객체의 생명주기를 관리합니다.

이로 인해 메모리 관리나 객체 관리에 대한 복잡성이 줄어듭니다.

**스코프(scope)**를 통해 싱글턴, 프로토타입 등으로 객체를 관리할 수 있습니다.
```

```jsx
싱글턴(Singleton): 스프링에서 기본적으로 빈은 싱글턴으로 관리되어 애플리케이션에서 하나의 인스턴스만 생성됩니다.

프로토타입(Prototype): 매번 요청할 때마다 새로운 인스턴스를 생성할 수도 있습니다.
```

### (3) 모듈화 및 유지보수성

```jsx
스프링은 빈을 통해 모듈화된 코드 작성을 돕습니다. 객체 간의 결합도를 낮추고, 각 객체가 독립적으로 동작하도록 설계할 수 있습니다.

이를 통해 코드를 확장하거나 변경하는 작업이 훨씬 쉬워집니다.

각 빈은 특정한 책임을 맡고 있으므로, 의존성 관리가 간결해지고 유지보수성이 높아집니다.
```

## 3. **Node.js에서는 왜 빈을 사용하지 않는가?**

```jsx
Node.js와 같은 환경에서는 스프링의 빈과 같은 컨테이너 기반의 의존성 주입 시스템을 사용하지 않습니다.

주로 CommonJS나 ES 모듈 시스템을 사용해 필요한 모듈을 직접 가져오고(import), 생성하며 사용하는 방식이 일반적입니다.
```

## 1. **Spring 빈 관리와 의존성 주입**

### 1-1. Spring 빈 (Bean) 관리

```jsx
Spring의 빈은 애플리케이션에서 관리되는 객체입니다.

빈 관리는 Spring의 핵심 기능 중 하나로,

Spring 컨테이너가 애플리케이션에서 객체를 생성하고, 관리하고, 의존성 주입을 자동으로 해줍니다.
```

### 1-2. 의존성 주입 (Dependency Injection)

```jsx
@Autowired 애너테이션을 사용하면, Spring이 객체를 자동으로 주입해 줍니다.

의존성 주입은 객체가 다른 객체에 의존할 때, 그 의존성(객체)을 외부에서 주입받는 방식입니다.
```

## 2. **예제: HmacRequestValidator를 Spring 빈으로 등록하는 방법**

### 2-1. `@Component`로 빈 등록

```jsx
@Component는 Spring에 이 클래스를 빈으로 등록하라고 알려주는 애너테이션입니다. ( service 등등 도 사실 다 똑같다 )

이를 통해 Spring은 HmacRequestValidator를 빈으로 관리하고,

필요한 곳에서 자동으로 객체를 주입할 수 있게 됩니다.
```

@Component // 이 클래스가 Spring의 빈으로 관리됨

### 빈으로 등록하지 않으면 `@Autowired`를 사용할 수 없습니다.

```jsx
빈으로 등록된 클래스: @Component, @Service, @Repository, @Controller 등의

애너테이션을 사용하여 클래스를 빈으로 등록합니다.

빈으로 등록되지 않은 클래스: 만약 @Component나 다른 애너테이션을 사용하지 않으면,

Spring은 해당 클래스를 빈으로 인식하지 않아서 @Autowired를 사용할 수 없습니다.
```

### 2-2. `@Autowired`로 의존성 주입

```jsx
HmacRequestValidator는 ApimServerInfo에 의존하고 있습니다.

@Autowired 애너테이션을 사용해서 Spring이 ApimServerInfo를 주입해줍니다.

Spring은 ApimServerInfo 빈을 자동으로 찾아서 생성자에 주입합니다.
```

### 2-3. `@Component`가 왜 필요한가?

```jsx
@Component를 사용하여 빈으로 등록하지 않으면, HmacRequestValidator는

객체를 수동으로 생성해야 하며, Spring의 의존성 주입 기능을 사용할 수 없습니다.
```

## 3. **빈이 필요한 이유**

### 3-1. 객체 관리

```jsx
Spring은 빈으로 등록된 객체들을 관리합니다.

객체를 new로 직접 생성하는 대신,

Spring이 관리하도록 하면 객체의 생성과 소멸을 자동으로 처리해줍니다.
```

### 3-2. 의존성 주입

```jsx
Spring 빈을 사용하면 객체 간의 의존성을 관리하기 쉽습니다.

예를 들어, HmacRequestValidator가 ApimServerInfo에 의존하고 있을 때,

Spring은 HmacRequestValidator의 생성자에 ApimServerInfo를 자동으로 주입해줍니다.

이를 의존성 주입이라고 합니다.
```

### 3-3. 코드 간결성 및 유지보수성

```jsx
Spring 빈을 사용하면 코드가 간결해지고, 객체의 생명 주기를 자동으로 관리하므로,

유지보수가 쉬워집니다. 예를 들어, HmacRequestValidator 클래스에서 ApimServerInfo를 @Autowired로 주입받으면,

이를 사용하는 클래스에서는 new로 객체를 만들지 않고, Spring 컨테이너에서 자동으로 주입받을 수 있습니다.
```

## 4. **빈 등록 없이 객체를 사용하는 방법 (수동 객체 생성)**

```jsx
빈 등록 없이 객체를 사용할 때는 @Autowired 대신 수동으로 객체를 생성해야 합니다.

이 방식은 Spring의 의존성 주입 기능을 사용하지 않기 때문에, 객체 간의 의존성 관리가 복잡해집니다.
```

### 4-1. 수동 객체 생성

```jsx
public class HmacRequestValidator {

    private ApimServerInfo apimServerInfo;
    private String SHARED_SECRET_KEY;

    // 생성자에서 수동으로 객체를 전달
    public HmacRequestValidator(ApimServerInfo apimServerInfo) {
        this.apimServerInfo = apimServerInfo;
        this.SHARED_SECRET_KEY = apimServerInfo.getSharedSecretKey();
    }

    public boolean validateHMAC(String receivedHash, String timestamp, String appName, String transactionId) {
        // HMAC 해시 검증 로직
        // ...
        return receivedHash.equals(generatedHash);
    }
}

```

```jsx
이 방식은 객체를 사용할 때마다 new 키워드로 객체를 생성해야 하며,

의존성 관리가 수동으로 이루어집니다.

단점은 객체 간의 의존성이 복잡해지고, 코드가 길어지고, 객체의 생명 주기를 관리하기 어려워진다는 점입니다.
```
