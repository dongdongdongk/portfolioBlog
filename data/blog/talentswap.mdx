# { 1. 채팅 시스템 개요 }

## 1.1. 시스템의 역할

```jsx
TalentSwap의 채팅 시스템은 사용자들이 실시간으로 1:1 메시지를 주고받을 수 있는 기능입니다.

예를 들어, 사용자 A가 사용자 B에게 "안녕하세요!"를 보내면, B는 즉시 메시지를 받고 답장할 수 있습니다.

이 시스템은 Next.js로 프론트엔드를 구현하고, Supabase로 백엔드(데이터베이스와 실시간 기능)를 처리합니다.
```

## 1.2. 사용된 기술

```jsx
프론트엔드: Next.js (React 기반, 파일 기반 라우팅, 서버/클라이언트 컴포넌트), TypeScript (타입 안전성)

백엔드: Supabase (PostgreSQL 데이터베이스, 실시간 WebSocket)

상태 관리: React 훅 (useState, useEffect, useCallback)

실시간 통신: Supabase Realtime (데이터베이스 변화 감지 및 알림)

보안: Supabase Row Level Security (RLS)
```

## 2.1. chats 테이블

```jsx
역할: 채팅방의 메타데이터를 저장합니다. 각 채팅방은 두 사용자를 연결하는 고유한 "방"입니다.
```

```jsx
CREATE TABLE chats (
  id uuid PRIMARY KEY,                    -- 채팅방 고유 ID
  user1_id uuid,                         -- 첫 번째 사용자 ID
  user2_id uuid,                         -- 두 번째 사용자 ID
  type varchar(20) DEFAULT 'direct',     -- 채팅 타입 (현재는 1:1만 사용)
  last_message_at timestamp,             -- 마지막 메시지 시간
  last_message_content text,             -- 마지막 메시지 내용
  user1_unread_count integer,            -- user1의 읽지 않은 메시지 수
  user2_unread_count integer,            -- user2의 읽지 않은 메시지 수
  is_active boolean DEFAULT true,        -- 채팅방 활성 여부
  created_at timestamp,                  -- 생성 시간
  updated_at timestamp                   -- 업데이트 시간
);
```

```jsx
id: 각 채팅방을 구분하는 고유 식별자.

user1_id, user2_id: 채팅에 참여한 두 사용자의 ID.

last_message_at, last_message_content: 채팅 목록 페이지(/chat)에서 최근 메시지를 보여줍니다.

user1_unread_count, user2_unread_count: 각 사용자가 읽지 않은 메시지 수를 추적.

예: 사용자 A와 B가 대화하면, 이 테이블에 한 행이 추가되고, 새 메시지가 올 때마다 last_message_content와 last_message_at이 업데이트됩니다.
```

## 2.2. messages 테이블

```jsx
역할: 주고받은 메시지의 내용을 저장합니다.
```

```jsx
CREATE TABLE messages (
  id uuid PRIMARY KEY,                   -- 메시지 고유 ID
  chat_id uuid,                         -- 메시지가 속한 채팅방 ID
  sender_id uuid,                       -- 메시지를 보낸 사용자 ID
  content text NOT NULL,                -- 메시지 내용 (텍스트)
  message_type varchar(20),             -- 메시지 타입 (text, image, file 등)
  attachment_url text,                  -- 첨부파일 URL (사진/파일인 경우)
  reply_to_message_id uuid,             -- 답장 대상 메시지 ID
  is_edited boolean DEFAULT false,      -- 메시지 편집 여부
  is_deleted boolean DEFAULT false,      -- 메시지 삭제 여부
  read_by uuid[],                      -- 메시지를 읽은 사용자 ID 배열
  created_at timestamp,                -- 메시지 생성 시간
  updated_at timestamp                 -- 메시지 수정 시간
);
```

```jsx
chat_id: 메시지가 어느 채팅방에 속하는지 연결.

sender_id: 메시지를 보낸 사용자를 식별.

content: 메시지의 텍스트 내용 (예: "안녕하세요!").

read_by: 메시지를 읽은 사용자의 ID를 배열로 저장 (예: ['user1_id', 'user2_id']).

예: 사용자 A가 "안녕!"을 보내면, messages 테이블에 새 행이 추가됩니다.
```

# { 3. 실시간 기능 }

Supabase Realtime

## 3.1. Supabase Realtime이란?

```jsx
Supabase Realtime은 데이터베이스의 변화(예: 새 메시지 추가)를 실시간으로 클라이언트에 알리는 WebSocket 기반 기술입니다.

이를 통해 사용자 A가 메시지를 보내면, 사용자 B의 화면에 즉시 메시지가 나타납니다.
```

## 3.2. 실시간 메시지 구독

```jsx
Supabase는 postgres_changes 이벤트를 사용해 데이터베이스 변화를 감지합니다.

예를 들어, 특정 채팅방(chat_id)에 새 메시지가 추가되면, 구독한 클라이언트에 알림을 보냅니다.
```

```jsx
// Supabase JavaScript 클라이언트 라이브러리에서 createClient 함수를 가져옵니다.
// 이 함수는 Supabase 데이터베이스와 연결할 수 있는 클라이언트를 생성하는 역할을 합니다.
import { createClient } from '@supabase/supabase-js'

// Supabase 클라이언트를 초기화합니다.
// 'SUPABASE_URL'은 Supabase 프로젝트의 URL로, 데이터베이스와 통신할 수 있는 주소를 나타냅니다.
// 'SUPABASE_KEY'은 공개 키(anon key)로, 클라이언트가 Supabase에 안전하게 접근하도록 인증합니다.
// 이 두 값은 Supabase 프로젝트 설정 페이지에서 확인할 수 있습니다.
const supabase = createClient('SUPABASE_URL', 'SUPABASE_KEY')

// subscribeToMessages 함수를 정의합니다.
// 이 함수는 특정 채팅방의 새 메시지를 실시간으로 구독하는 역할을 합니다.
// 매개변수:
// - chatId: 구독하려는 채팅방의 고유 ID (문자열, 예: 'chat123').
// - callback: 새 메시지가 도착했을 때 실행할 함수. 이 함수는 새 메시지 데이터를 받아 처리합니다.
const subscribeToMessages = (chatId, callback) => {
  // supabase.channel()을 호출해 WebSocket 채널을 생성합니다.
  // `messages:${chatId}`는 고유한 채널 이름으로, 특정 채팅방에 대한 이벤트를 구분합니다.
  // 예: chatId가 'chat123'이면 채널 이름은 'messages:chat123'이 됩니다.
  const channel = supabase
    .channel(`messages:${chatId}`)
    // .on() 메서드는 데이터베이스의 변화를 감지하도록 설정합니다.
    // 첫 번째 인자 'postgres_changes'는 PostgreSQL 데이터베이스의 변화 이벤트를 감지하라는 명령입니다.
    .on(
      'postgres_changes', // 이벤트 타입: PostgreSQL 테이블의 변화(INSERT, UPDATE, DELETE 등)를 감지.
      {
        // 감지할 이벤트와 조건을 객체로 지정합니다.
        event: 'INSERT', // 'INSERT' 이벤트를 감지. 즉, 새 데이터가 테이블에 추가될 때만 반응.
        schema: 'public', // 데이터베이스의 스키마 이름. Supabase에서는 기본적으로 'public' 스키마 사용.
        table: 'messages', // 감지할 테이블 이름. 여기서는 'messages' 테이블의 변화를 감시.
        filter: `chat_id=eq.${chatId}`, // 필터 조건: chat_id가 특정 chatId와 일치하는 경우만 감지.
        // 예: 'chat_id=eq.chat123'은 특정 채팅방의 메시지만 대상.
      },
      // 변화가 감지되면 실행되는 콜백 함수입니다.
      // payload는 Supabase가 보내주는 데이터 객체로, 변화에 대한 정보를 포함합니다.
      (payload) => {
        // payload.new는 새로 추가된 데이터(여기서는 새 메시지 객체)를 포함합니다.
        // 예: { id: 'uuid', chat_id: 'chat123', content: 'Hello!', sender_id: 'user123', created_at: '2025-07-30T15:40:00Z' }
        // callback(payload.new)를 호출해, 외부에서 전달받은 callback 함수에 새 메시지 데이터를 전달합니다.
        // 이렇게 하면 호출자가 원하는 방식으로 새 메시지를 처리할 수 있습니다 (예: 화면에 표시).
        callback(payload.new)
      }
    )
    // .subscribe()를 호출해 WebSocket 연결을 시작하고, 실시간 구독을 활성화합니다.
    // 이 메서드는 채널을 Supabase 서버에 연결해 데이터베이스 변화를 감지하기 시작합니다.
    .subscribe()

  // 생성된 채널 객체를 반환합니다.
  // 이 채널 객체는 나중에 구독을 종료하거나 상태를 관리할 때 사용됩니다 (예: supabase.removeChannel(channel)).
  return channel
}
```

```jsx
1. 클라이언트가 특정 chatId로 채널을 구독합니다.

2. messages 테이블에 새 메시지가 추가되면, Supabase가 이를 감지해 구독자들에게 payload.new(새 메시지 데이터)를 전송합니다.

3. 클라이언트는 이 데이터를 받아 화면에 즉시 표시합니다.
```

## 3.3. 실시간 알림

```jsx
새 메시지가 도착하면 헤더의 종 모양 아이콘에 알림(빨간 점)이 표시됩니다. 이를 위해 사용자별 전역 구독을 설정합니다.
```

```jsx
// subscribeToGlobalMessages 함수를 정의합니다.
// 이 함수는 특정 사용자가 관련된 모든 채팅방의 새 메시지를 실시간으로 구독하여 알림을 처리하는 역할을 합니다.
// 매개변수:
// - userId: 알림을 받을 사용자의 고유 ID (문자열, 예: 'user123').
// - callback: 새 메시지가 도착했을 때 실행할 함수. 이 함수는 알림 데이터를 받아 처리합니다.
const subscribeToGlobalMessages = (userId, callback) => {
  // supabase.channel()을 호출해 WebSocket 채널을 생성합니다.
  // `user-notifications-${userId}`는 고유한 채널 이름으로, 특정 사용자의 알림 이벤트를 구분합니다.
  // 예: userId가 'user123'이면 채널 이름은 'user-notifications-user123'이 됩니다.
  const channel = supabase
    .channel(`user-notifications-${userId}`)
    // .on() 메서드는 데이터베이스의 변화를 감지하도록 설정합니다.
    // 첫 번째 인자 'postgres_changes'는 PostgreSQL 데이터베이스의 변화 이벤트를 감지하라는 명령입니다.
    .on(
      'postgres_changes', // 이벤트 타입: PostgreSQL 테이블의 변화(INSERT, UPDATE, DELETE 등)를 감지.
      {
        // 감지할 이벤트와 조건을 객체로 지정합니다.
        event: 'INSERT', // 'INSERT' 이벤트를 감지. 즉, 새 데이터가 'messages' 테이블에 추가될 때만 반응.
        schema: 'public', // 데이터베이스의 스키마 이름. Supabase에서는 기본적으로 'public' 스키마 사용.
        table: 'messages', // 감지할 테이블 이름. 여기서는 'messages' 테이블의 변화를 감시.
        // filter는 생략되었으므로, 'messages' 테이블의 모든 INSERT 이벤트를 감지합니다.
        // 특정 채팅방으로 제한하지 않고, 모든 메시지를 대상으로 합니다.
      },
      // 변화가 감지되면 실행되는 콜백 함수입니다.
      // payload는 Supabase가 보내주는 데이터 객체로, 변화에 대한 정보를 포함합니다.
      (payload) => {
        // payload.new는 새로 추가된 메시지 데이터를 포함합니다.
        // 예: { id: 'uuid', chat_id: 'chat123', sender_id: 'user456', content: 'Hello!', created_at: '2025-07-30T15:40:00Z' }
        // 조건문: 새 메시지의 발신자(sender_id)가 현재 사용자(userId)와 다를 경우에만 처리.
        // 이는 사용자가 자신이 보낸 메시지에 대해 알림을 받지 않도록 방지합니다.
        if (payload.new.sender_id !== userId) {
          // callback 함수를 호출하여 외부에서 전달받은 callback에 알림 데이터를 전달합니다.
          // 전달되는 데이터는 객체 형태로, 알림의 타입, 제목, 메시지 내용, 채팅방 ID를 포함합니다.
          callback({
            type: 'chat_message', // 알림의 유형. 여기서는 채팅 메시지임을 나타냄.
            title: 'New Message', // 알림의 제목. UI에서 표시될 때 사용 (예: "New Message").
            message: payload.new.content, // 새 메시지의 내용 (예: "Hello!").
            chatId: payload.new.chat_id, // 메시지가 속한 채팅방의 ID (예: 'chat123').
          })
        }
      }
    )
    // .subscribe()를 호출해 WebSocket 연결을 시작하고, 실시간 구독을 활성화합니다.
    // 이 메서드는 채널을 Supabase 서버에 연결해 데이터베이스 변화를 감지하기 시작합니다.
    .subscribe()

  // 생성된 채널 객체를 반환합니다.
  // 이 채널 객체는 나중에 구독을 종료하거나 상태를 관리할 때 사용됩니다 (예: supabase.removeChannel(channel)).
  return channel
}
```

```jsx
모든 메시지 추가 이벤트를 감지하지만, 자신이 보낸 메시지는 제외합니다.

새 메시지가 도착하면 알림을 추가하고, 헤더에 읽지 않은 알림 수를 표시합니다.
```

      {currentChatId && <ChatWindow chatId={currentChatId} />}
    </div>
  )
}

## 4.3. /src/hooks/useChat.ts

```jsx
역할: 채팅 관련 로직을 관리하는 커스텀 훅입니다. 메시지 로드, 전송, 실시간 구독 등을 처리합니다.

주요 기능:

		채팅방 생성/조회

		메시지 전송 (Optimistic Update 포함)

		실시간 메시지 구독
```

```jsx
// React에서 상태 관리와 부수 효과 처리를 위한 훅들을 가져옵니다.
// - useState: 컴포넌트의 상태를 관리하기 위한 훅.
// - useEffect: 부수 효과(예: 데이터 가져오기, 구독 설정)를 처리하기 위한 훅.
// - useCallback: 함수를 메모이제이션하여 불필요한 재생성을 방지하는 훅.
import { useState, useEffect, useCallback } from 'react';

// Supabase JavaScript 클라이언트 라이브러리에서 createClient 함수를 가져옵니다.
// 이 함수는 Supabase 데이터베이스와 통신할 수 있는 클라이언트를 생성합니다.
import { createClient } from '@supabase/supabase-js';

// Supabase 클라이언트를 초기화합니다.
// 'SUPABASE_URL'은 Supabase 프로젝트의 URL로, 데이터베이스와 통신할 주소를 나타냅니다.
// 'SUPABASE_KEY'은 공개 키(anon key)로, 클라이언트가 Supabase에 안전하게 접근하도록 인증합니다.
// 이 두 값은 Supabase 프로젝트 설정 페이지에서 확인할 수 있습니다.
const supabase = createClient('SUPABASE_URL', 'SUPABASE_KEY');

// useChat 커스텀 훅을 정의하고 내보냅니다.
// 이 훅은 채팅 관련 데이터를 관리하고, 메시지 로드, 전송, 실시간 구독 기능을 제공합니다.
// 매개변수:
// - chatId: 선택적 매개변수로, 특정 채팅방의 ID (문자열, 예: 'chat123'). undefined일 경우 구독하지 않음.
export function useChat(chatId?: string) {
  // messages 상태를 정의합니다. 채팅방의 메시지 목록을 저장합니다.
  // 초기값은 빈 배열([])이며, 각 메시지 객체는 id, chat_id, sender_id, content 등을 포함합니다.
  const [messages, setMessages] = useState([]);

  // chats 상태를 정의합니다. 채팅방 목록을 저장합니다.
  // 초기값은 빈 배열([])이며, 각 채팅방 객체는 id, user1_id, user2_id 등을 포함합니다.
  const [chats, setChats] = useState([]);

  // loading 상태를 정의합니다. 데이터 로드 중인지 여부를 나타냅니다.
  // 초기값은 false이며, 데이터 가져오기 시작 시 true로 설정, 완료 시 false로 복귀.
  const [loading, setLoading] = useState(false);

  // error 상태를 정의합니다. 오류 발생 시 오류 메시지를 저장합니다.
  // 초기값은 null이며, 오류 발생 시 문자열로 설정됩니다.
  const [error, setError] = useState(null);

  // loadMessages 함수를 정의합니다. 특정 채팅방의 메시지를 가져오는 비동기 함수입니다.
  // useCallback으로 메모이제이션하여 불필요한 함수 재생성을 방지합니다.
  // 의존성 배열([])이 비어 있으므로 이 함수는 컴포넌트 생애주기 동안 한 번만 생성됩니다.
  // 매개변수:
  // - chatId: 메시지를 가져올 채팅방의 ID.
  const loadMessages = useCallback(async (chatId: string) => {
    // 데이터 로드 시작을 표시하기 위해 loading 상태를 true로 설정.
    setLoading(true);
    try {
      // Supabase에서 messages 테이블의 데이터를 조회합니다.
      // .from('messages'): messages 테이블을 대상으로 합니다.
      // .select('*'): 모든 컬럼(id, chat_id, content 등)을 선택.
      // .eq('chat_id', chatId): chat_id가 주어진 chatId와 일치하는 데이터만 가져옵니다.
      // .order('created_at', { ascending: true }): 메시지를 생성 시간 순으로 정렬(오래된 순).
      const { data, error } = await supabase
        .from('messages')
        .select('*')
        .eq('chat_id', chatId)
        .order('created_at', { ascending: true });

      // 오류가 있으면 예외를 발생시켜 catch 블록으로 이동.
      if (error) throw error;

      // 조회된 메시지 데이터를 messages 상태에 저장.
      setMessages(data);
    } catch (err) {
      // 오류 발생 시 error 상태에 오류 메시지를 저장.
      setError(err.message);
    } finally {
      // 데이터 로드 완료 후 loading 상태를 false로 설정.
      // try나 catch 블록이 끝나면 항상 실행됩니다.
      setLoading(false);
    }
  }, []); // 빈 의존성 배열: 함수가 컴포넌트 생애주기 동안 한 번만 생성됨.

  // sendMessage 함수를 정의합니다. 새 메시지를 전송하는 비동기 함수입니다.
  // useCallback으로 메모이제이션하여 불필요한 함수 재생성을 방지.
  // 의존성 배열([])이 비어 있으므로 이 함수는 컴포넌트 생애주기 동안 한 번만 생성됩니다.
  // 매개변수:
  // - chatId: 메시지를 보낼 채팅방의 ID.
  // - content: 전송할 메시지 내용 (문자열).
  const sendMessage = useCallback(async (chatId: string, content: string) => {
    // Optimistic Update를 위해 임시 메시지 객체를 생성합니다.
    // 이 메시지는 서버 응답을 기다리지 않고 즉시 UI에 표시됩니다.
    // - id: 임시 ID로, 고유성을 위해 현재 타임스탬프 사용.
    // - chat_id: 메시지가 속한 채팅방 ID.
    // - sender_id: 메시지 발신자의 ID. 실제로는 Supabase auth에서 가져옴(여기서는 하드코딩).
    // - content: 메시지 내용.
    // - created_at: 현재 시간을 ISO 문자열로 저장.
    const tempMessage = {
      id: `temp-${Date.now()}`, // 임시 ID 생성 (예: 'temp-1623456789').
      chat_id: chatId,
      sender_id: 'current_user_id', // 실제 구현에서는 Supabase auth에서 사용자 ID를 가져옴.
      content,
      created_at: new Date().toISOString(),
    };

    // messages 상태를 업데이트하여 임시 메시지를 즉시 추가.
    // 함수형 업데이트((prev) => [...prev, tempMessage])를 사용하여 최신 상태를 보장.
    setMessages((prev) => [...prev, tempMessage]);

    try {
      // Supabase에 새 메시지를 삽입합니다.
      // .from('messages'): messages 테이블에 데이터를 추가.
      // .insert({...}): 새로운 메시지 데이터를 삽입.
      // .select().single(): 삽입된 메시지 데이터를 반환.
      const { data, error } = await supabase
        .from('messages')
        .insert({ chat_id: chatId, sender_id: 'current_user_id', content })
        .select()
        .single();

      // 오류가 있으면 예외를 발생시켜 catch 블록으로 이동.
      if (error) throw error;

      // 서버에서 반환된 실제 메시지 데이터로 임시 메시지를 교체.
      // messages 상태를 업데이트하여 tempMessage의 id와 일치하는 메시지를 실제 데이터로 변경.
      setMessages((prev) =>
        prev.map((msg) => (msg.id === tempMessage.id ? data : msg))
      );

      // chats 테이블의 last_message_content와 last_message_at을 업데이트.
      // .from('chats'): chats 테이블을 대상.
      // .update({...}): 마지막 메시지 내용과 시간을 업데이트.
      // .eq('id', chatId): 특정 채팅방 ID와 일치하는 행만 업데이트.
      await supabase
        .from('chats')
        .update({ last_message_content: content, last_message_at: new Date().toISOString() })
        .eq('id', chatId);
    } catch (err) {
      // 오류 발생 시 임시 메시지를 제거하여 UI를 롤백.
      // messages 상태에서 tempMessage.id와 일치하는 메시지를 필터링하여 제외.
      setMessages((prev) => prev.filter((msg) => msg.id !== tempMessage.id));

      // 오류 메시지를 error 상태에 저장.
      setError(err.message);
    }
  }, []); // 빈 의존성 배열: 함수가 컴포넌트 생애주기 동안 한 번만 생성됨.

  // useEffect 훅을 사용하여 실시간 메시지 구독을 설정합니다.
  // chatId가 변경될 때마다 실행되며, Supabase Realtime으로 새 메시지를 감지합니다.
  // 의존성 배열 [chatId]는 chatId가 변경될 때마다 useEffect가 재실행되도록 합니다.
  useEffect(() => {
    // chatId가 없으면(즉, undefined이면) 아무 작업도 하지 않고 종료.
    if (!chatId) return;

    // Supabase Realtime 채널을 생성하여 특정 채팅방의 메시지를 구독합니다.
    // `messages:${chatId}`는 고유한 채널 이름 (예: 'messages:chat123').
    const channel = supabase
      .channel(`messages:${chatId}`)
      // .on() 메서드는 데이터베이스의 변화를 감지하도록 설정.
      // 'postgres_changes'는 PostgreSQL 데이터베이스 변화 이벤트를 감지합니다.
      .on(
        'postgres_changes', // 이벤트 타입: PostgreSQL 테이블의 변화 감지.
        {
          event: 'INSERT', // 'INSERT' 이벤트를 감지. 새 메시지가 추가될 때만 반응.
          schema: 'public', // 데이터베이스 스키마. 기본적으로 'public' 사용.
          table: 'messages', // 감지할 테이블. messages 테이블의 변화를 감시.
          filter: `chat_id=eq.${chatId}`, // chat_id가 주어진 chatId와 일치하는 메시지만 감지.
        },
        // 변화가 감지되면 실행되는 콜백 함수.
        // payload는 Supabase가 보내주는 데이터 객체로, 새 메시지 정보를 포함.
        (payload) => {
          // payload.new.sender_id가 현재 사용자와 다를 경우에만 메시지를 추가.
          // 이는 Optimistic Update로 이미 추가된 자신의 메시지가 중복되지 않도록 방지.
          if (payload.new.sender_id !== 'current_user_id') {
            // messages 상태를 업데이트하여 새 메시지를 추가.
            // 함수형 업데이트((prev) => [...prev, payload.new])로 최신 상태를 보장.
            setMessages((prev) => [...prev, payload.new]);
          }
        }
      )
      // .subscribe()를 호출해 WebSocket 연결을 시작하고 실시간 구독을 활성화.
      .subscribe();

    // useEffect의 cleanup 함수. 컴포넌트가 언마운트되거나 chatId가 변경될 때 호출.
    // supabase.removeChannel(channel)을 호출하여 구독을 종료하고 메모리 누수를 방지.
    return () => supabase.removeChannel(channel);
  }, [chatId]); // 의존성 배열: chatId 변경 시 useEffect 재실행.

  // 훅이 반환하는 객체. 컴포넌트에서 사용할 상태와 함수를 제공합니다.
  // - messages: 메시지 목록.
  // - chats: 채팅방 목록.
  // - loading: 데이터 로드 상태.
  // - error: 오류 메시지.
  // - loadMessages: 메시지 조회 함수.
  // - sendMessage: 메시지 전송 함수.
  return { messages, chats, loading, error, loadMessages, sendMessage };
}
```

## 6.2. useChat 훅의 주요 함수

### createOrFindChat:

```jsx
const createOrFindChat = useCallback(async (receiverId: string) => {
  const userId = 'current_user_id'; // 실제로는 auth에서 가져옴
  const { data: existingChats } = await supabase
    .from('chats')
    .select('*')
    .or(`and(user1_id.eq.${userId},user2_id.eq.${receiverId}),and(user1_id.eq.${receiverId},user2_id.eq.${userId})`);
  if (existingChats?.length) return existingChats[0];
  const { data: newChat } = await supabase
    .from('chats')
    .insert({ user1_id: userId, user2_id: receiverId, type: 'PRIVATE' })
    .select()
    .single();
  return newChat;
}, []);

or 조건으로 양방향 채팅방(A→B, B→A) 중복 방지.
```

### sendMessage:

```jsx
const sendMessage = useCallback(async (chatId: string, content: string) => {
  const tempMessage = { id: `temp-${Date.now()}`, chat_id: chatId, content, sender_id: 'current_user_id' };
  setMessages((prev) => [...prev, tempMessage]);
  try {
    const { data, error } = await supabase
      .from('messages')
      .insert({ chat_id: chatId, sender_id: 'current_user_id', content })
      .select()
      .single();
    if (error) throw error;
    setMessages((prev) => prev.map((msg) => (msg.id === tempMessage.id ? data : msg)));
  } catch (err) {
    setMessages((prev) => prev.filter((msg) => msg.id !== tempMessage.id));
    setError(err.message);
  }
}, []);
```
