# 데이터베이스 개요

## **1. MongoDB 소개**

```jsx
MongoDB는 클라우드 환경에서 분산된 데이터를 효율적으로 저장하고 다루기 위해 개발된 데이터베이스이다.

몇몇 대규모 애플리케이션 및 회사들이 사용하며, 사용자들은 MongoDB를 통해 데이터를 쉽게 관리하고 활용할 수 있다.
```

## **2. 데이터베이스의 필요성**

```jsx
**데이터 지속성**:

서버를 재시작하거나 코드를 재배포해도 데이터가 유지되어야 한다.

**효율적인 관리**:

데이터베이스는 대량의 데이터를 효율적으로 저장, 압축하고 관리할 수 있다.

**쉬운 조작 및 검색**:

다양한 도구와 메서드를 사용하여 데이터를 쉽게 삽입, 조회, 갱신, 삭제하고 검색할 수 있다.
```

## 4. MongoDB의 기능

```jsx
**데이터 압축 및 관리**:

대량의 데이터를 효율적으로 저장, 압축하고 다룰 수 있다.

**다양한 도구 및 레이어**:

다양한 메서드와 언어로 데이터를 다룰 수 있는 도구와 레이어를 제공한다.

**보안 및 관리 기능**:

데이터베이스 관리 시스템을 통해 데이터에 대한 보안 및 관리자 제어가 가능하다.
```

# SQL과 NoSQL 데이터베이스

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381388/notion-blog/_/The_Web_Developer_2022/node_js/MongoDB/Untitled.png)

## **1. 데이터베이스의 두 종류**

```jsx
데이터베이스는 SQL 데이터베이스와 NoSQL 데이터베이스로 크게 나눌 수 있다.

NoSQL은 SQL을 제외한 모든 것을 포괄하는 범주로, 다양한 형태의 데이터베이스를 포함한다.
```

## **2. SQL 데이터베이스 소개**

```jsx
**SQL (Structured Query Language)**:

SQL은 구조화된 쿼리 언어로, MySQL, Postgres, Oracle, Microsoft SQL Server, SQLite 등의 유명한 데이터베이스가 사용한다.

**테이블 중심 구조**:

SQL에서는 모든 작업이 테이블에서 이루어지며, 스키마와 테이블을 정의한 후에야 데이터를 추가할 수 있다.
```

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381385/notion-blog/_/The_Web_Developer_2022/node_js/MongoDB/Untitled_1.png)

## **3. SQL 데이터 모델링 예시**

```jsx
**블로그 앱 구조**:

게시물과 댓글을 저장하기 위해 각각의 테이블을 생성한다.

게시물에는 ID, 작성자, 내용이 있고, 댓글에는 ID, 텍스트 등이 있다.

**관계 형성**:

게시물과 댓글을 관계 짓기 위해 댓글 테이블에 게시물 ID를 넣어 참조하도록 한다.
```

## **4. NoSQL 데이터베이스 소개**

```jsx
**포괄적인 특성**:

NoSQL은 SQL과 다르게 구조화된 쿼리 언어를 사용하지 않고, 다양한 형태의 데이터베이스를 포함한다.

( 일반적인 유형이 몇 가지 있긴하다 )

**유연한 문서 데이터 저장소**:

 MongoDB와 같은 NoSQL 데이터베이스는 문서 기반으로, 별도의 테이블이나 스키마를 정의하지 않고도 데이터를 자유롭게 저장할 수 있다.
```

## **5. 문서 데이터 저장소의 특징**

```jsx
NoSQL 의 한가지 유형이다 ( MongoDB 가 이 유형 )

json이나 xml도 포맷의 일종이다

여기서는 객체나 데이터 조각 안에 정보를 직접 끼워 넣을 수 있다

왜 특정 게시물에 댓글을 바로 추가할 수 없죠?

왜 그걸 분리해야 하죠?

SQL과 달리 문서 데이터 저장소에서는

원하는 건 뭐든지 밀어 넣은 다음 이렇게 말하면 된다

'데이터베이스야, 이걸 갖고 있다가 내가 달라고 할 때 돌려 줘'
```

```jsx
**유연성과 자유로움**:

문서 데이터 저장소에서는 미리 정의된 스키마가 없어도 데이터를 저장할 수 있다.

객체나 데이터 조각을 직접 저장하고 필요할 때 꺼내올 수 있다.

**NoSQL의 다양성**:

NoSQL에는 여러 유형이 있으며, MongoDB, CouchDB, Neo4j, Cassandra, Redis 등이 있다.
```

## **6. NoSQL과 SQL의 차이**

```jsx
**유연성과 간결성**:

NoSQL은 데이터를 자유롭게 저장하고 필요한 부분을 가져오는 데 강점이 있다.

SQL은 미리 정의된 스키마와 구조를 따라야 한다.

**NoSQL의 다양한 유형**:

키-값 저장소, 칼럼 데이터베이스, 그래프 데이터베이스 등 다양한 NoSQL 유형이 존재한다.
```

```jsx
**1. MEAN 스택**:

**MongoDB**: NoSQL 데이터베이스로서, JSON 형식의 도큐먼트를 사용하며 확장이 용이하다.

**Express.js**: Node.js 웹 애플리케이션 프레임워크로, 서버 사이드 로직을 구현하는 데 사용

**Node.js**: JavaScript를 사용하여 서버 사이드 로직을 실행할 수 있게 해주는 런타임 환경이다.

MEAN 스택은 모두 JavaScript 기반으로 구성되어 있어 전체적인 개발 환경을 통일시킬 수 있다.

**2. MERN 스택**:

**MongoDB**: 동일하게 NoSQL 데이터베이스로 사용된다.

**Express.js**: 역시 Node.js 웹 애플리케이션 프레임워크로, 서버 사이드 로직을 다룬다.

**React**: Facebook에서 개발한 UI 라이브러리로, 사용자 인터페이스를 만들기 위한 라이브러리이다.

**Node.js**: 역시 JavaScript를 사용하여 서버 사이드 로직을 처리한다.

**3. MEN 스택**:

**MongoDB**: 여전히 NoSQL 데이터베이스로 사용된다.

**Express.js**: 마찬가지로 Node.js 웹 애플리케이션 프레임워크이다.

**Node.js**: 여전히 JavaScript를 사용하여 서버 사이드 로직을 담당한다.

MEN 스택은 Angular나 React 없이 Node.js와 Express.js로만 구성되어 있는 스택이다.

클라이언트 사이드 라이브러리나 프레임워크를 사용하지 않고, 서버 사이드에서 모든 로직을 다루는 경우에 적합하다.
```

## **JSON과 BSON 비교**

```jsx
JSON은 텍스트 기반 형식으로,

텍스트 파싱이 느리고 읽을 수 있는 형식으로 저장되므로 공간 효율성이 떨어진다.

BSON은 JSON의 이진 버전으로,

데이터를 더 압축적으로 저장하여 메모리에서 더 효율적으로 사용한다.
```

## **BSON의 장점**

```jsx
BSON은 JSON과 호환되며, 더 많은 데이터 유형을 지원한다.

예를 들어, BSON에는 String, Boolean, Number, Array, Date, Raw Binary

등이 있어 더 다양한 데이터를 표현할 수 있다.

날짜를 JSON에 저장하기 어려운 문제를 해결할 수 있다

MongoDB는 BSON 형식으로 데이터를 저장하므로, 입력되는 데이터는 BSON으로 변환된다
```

## **MongoDB 문서 삽입**

```jsx
문서를 삽입할 때는 insertOne 또는 insertMany 메서드를 사용한다.

집합(Collection)은 데이터베이스 안에서 데이터를 그룹화한 것이며, 여러 개의 문서를 포함할 수 있다.
```

### **`insertOne` 메서드**

```jsx
db.collection.insertOne({}) 형식으로 사용

하나의 문서를 삽입한다.

집합이 없으면 자동으로 생성된다.
```

### **`insertMany` 메서드**

```jsx
db.collection.insertMany([{}, {}]) 형식으로 사용한다.

다수의 문서를 배열로 전달하여 삽입한다.

집합이 없으면 자동으로 생성된다.
```

### **`insert`메서드**

```jsx
둘을 통합한 메서드
```

## **문서 삽입 예시**

### 데이터베이스 생성 및 선택:

```jsx
use animalShelter
```

### 강아지 집합에 하나의 문서 삽입:

```jsx
db.dogs.insertOne({
  name: 'Charlie',
  age: 3,
  breed: 'corgi',
  catFriendly: true,
})
```

### 강아지 집합에 다수의 문서 삽입:

```jsx
db.dogs.insertMany([

  },
])
```

### 고양이 집합에 하나의 문서 삽입:

```jsx
// 모든 고양이 조회
```

```jsx
// 특정 필드만 조회 (예: 이름과 나이만 조회)
```

### 첩된 문서의 특정 필드에 접근

```jsx
중첩된 문서가 있는 콜렉션에서 find 메서드를 사용하는건 조금 다르다

"details.species" 이런식으로 중첩된 필드를 .으로 이어줘야한다
```

```jsx
// 동물 콜렉션 예제 문서
// {
//   _id: ObjectId("문서 고유 식별자"),
//   name: "동물 이름",
//   details: {
//     species: "종",
//     habitat: "서식지",
//     age: 3,
//     characteristics: {
//       color: "색깔",
//       size: "크기"
//     }
//   }
// }

// MongoDB에서 동물 콜렉션에서 특정 조건을 만족하는 문서를 찾는 예제

// 1. 특정 종(species)의 동물 찾기
db.animals.find({ 'details.species': '사자' })

// 2. 특정 크기(size) 이상인 동물 찾기
db.animals.find({ 'details.characteristics.size': { $gte: '대형' } })

// 3. 특정 색깔(color)의 동물 중 나이(age)가 어린 것 찾기
db.animals.find({
  'details.characteristics.color': '갈색',
  'details.age': { $lt: 5 },
})

// 4. 중첩된 연산자 사용 예제 - 특정 서식지(habitat)에 있는 대형 크기 동물 찾기
db.animals.find({
  'details.habitat': '사하라 사막',
  'details.characteristics.size': '대형',
})
```

## **다양한 쿼리 연산자**

```jsx
쿼리 연산자를 사용하여 다양한 비교 및 조건을 지정하여 원하는 데이터를 찾을 수 있다
```

### **비교 연산자 활용**

```jsx
// 나이가 5보다 큰 개 찾기
db.dogs.find({ age: { $gt: 5 } })
```

### **배열 연산자 활용**

```jsx
// skills 배열에 "Jumping"이 포함된 개 찾기
db.dogs.find({ skills: 'Jumping' })
```

### **정규 표현식 사용**

```jsx
// 이름이 "Max"로 시작하는 개 찾기
db.dogs.find({ name: /^Max/ })
```

### **요소의 존재 여부 확인**

```jsx
// vaccination 필드가 존재하는 개 찾기
db.dogs.find({ vaccination: { $exists: true } })
```

### **범위 기반 매치**

```jsx
// 나이가 3에서 6 사이인 개 찾기
db.dogs.find({ age: { $gte: 3, $lte: 6 } })
```

### **배열의 길이에 대한 조건**

```jsx
// skills 배열의 길이가 3인 개 찾기
db.dogs.find({ skills: { $size: 3 } })
```

### **`$or` 연산자**

```jsx
$or 연산자는 여러 개의 조건 중 하나라도 참인 문서를 찾는다.
```

```jsx
// 나이가 20 이상이거나 이름이 'Charlie'인 개를 찾는 쿼리
db.dogs.find({
  $or: [{ age: { $gte: 20 } }, { name: 'Charlie' }],
})
```

### **`$and` 연산자**

```jsx
$and 연산자는 여러 개의 조건이 모두 참인 문서를 찾는다.

MongoDB는 여러 조건을 $and로 처리하므로 명시적으로 사용하지 않아도 된다.
```

```jsx
// 나이가 3 이상이고 이름이 'Buddy'인 개를 찾는 쿼리
db.dogs.find({
  age: { $gte: 3 },
  name: 'Buddy',
})
```

### **`$eq` 연산자**

```jsx
$eq 연산자는 필드의 값이 특정 값과 정확하게 일치하는 문서를 찾는다
```

```jsx
// 나이가 5인 개를 찾는 쿼리
db.dogs.find({
  age: { $eq: 5 },
})
```

### **`$ne` 연산자**

```jsx
$ne 연산자는 필드의 값이 특정 값과 일치하지 않는 문서를 찾는다
```

```jsx
// 나이가 5가 아닌 개를 찾는 쿼리
db.dogs.find({
  age: { $ne: 5 },
})
```

### **`$in` 연산자**

```jsx
$in 연산자는 필드의 값이 주어진 배열 중 하나와 일치하는 문서를 찾는다.

배열 안에 있는 어떤 값 과도 일치하는 문서를 선택하여 갱신. 따라서 두 값 중 하나라도 값이 일치하면 해당 문서가 선택되어 갱신
```

```jsx
// 코기나 불독 품종인 개를 찾는 쿼리
db.dogs.find({
  breed: { $in: ['Corgi', 'Bulldog'] },
})
```

### **`$regex` 연산자**

```jsx
$regex 연산자는 정규표현식을 사용하여 필드의 값을 검색하는 데 사용
```

```jsx
// 이름이 'Max'로 시작하는 개를 찾는 쿼리
db.dogs.find({
  name: { $regex: /^Max/ },
})
```

## **MongoDB 문서 업데이트**

```jsx
필요한 두 가지 인수를 제공해야 한다

업데이트할 대상 및 업데이트 방법이다.
```

### **updateOne() 메서드**

```jsx
updateOne 메서드를 사용하여 개를 찾아 업데이트한다.

업데이트할 대상을 찾기 위해 선택자(selector)를 사용한다. (예: 이름이나 나이 등)

업데이트 연산자(operator)로 $set을 사용하여 필드 값을 새로운 값으로 설정한다.

( 없는 필드를 추가 하는것도 가능하다 )
```

```jsx
// 예시: Charlie의 나이를 4살로 업데이트하는 방법
db.dogs.updateOne({ name: 'Charlie' }, { $set: { age: 4 } })
```

### **updateMany() 메서드**

```jsx
updateMany 메서드를 사용하여 여러 개를 한 번에 업데이트할 수 있다.

선택자로 일치하는 모든 문서를 찾아 업데이트한다.
```

```jsx
// catFriendly가 true인 모든 개를 catFriendly를 false로 업데이트
db.dogs.updateMany({ catFriendly: true }, { $set: { catFriendly: false, isAvailable: false } })
```

### **replaceOne() 메서드**

```jsx
replaceOne 메서드를 사용하여 문서의 내용을 완전히 대체할 수 있다.

기존 문서를 새로운 문서로 완전히 교체하는 것이므로 일부 필드가 변경되더라도 다른 필드는 유지되지 않는다
```

```jsx
// 예시: 고양이 컬렉션에서 특정 ID를 가진 고양이 문서를 완전히 새로운 문서로 대체
db.cats.replaceOne({ _id: ObjectId("고양이의ID") }, { name: "Whiskers", age: 4, color: "Gray" }))
```

## **다양한 연산자 활용**

```jsx
$set 이외의 다양한 연산자 활용 가능 (예: $currentDate 등)
```

```jsx
// currentDate 연산자를 사용하여 나이를 업데이트하고 lastChanged 필드에 현재 날짜 설정
db.cats.updateOne({ age: 6 }, { $set: { age: 7, $currentDate: { lastChanged: true } } })
```

## **MongoDB 문서 삭제**

```jsx
deleteOne과 deleteMany 두 가지 방식으로 문서를 삭제할 수 있다.
```

## **`deleteOne` 메서드**

```jsx
deleteOne 메서드는 특정 기준을 충족하는 문서 중 첫 번째 문서를 삭제
```

```jsx
// 예시: 이름이 "Blue Steele"인 고양이를 삭제하는 방법
db.cats.deleteOne({ name: 'Blue Steele' })
```

## **`deleteMany` 메서드**

```jsx
deleteMany 메서드는 특정 기준을 충족하는 모든 문서를 삭제
```

```jsx
// 예시: isAvailable이 true인 모든 개를 삭제하는 방법
db.dogs.deleteMany({ isAvailable: true })

// 모든 항목 삭제
db.collection.deleteMany({})

// 예시: $or 연산자 또는 $lt 연산자를 사용하여 나이가 20살 이상인 문서를 삭제하는 방법
db.collection.deleteMany({
  $or: [
    //러 개의 조건 중 어느 하나라도 참인 문서를 찾는다
    { age: { $gte: 20 } }, // 나이가 20 이상인 경우
    { price: { $lt: 값 } }, // 특정 필드가 특정 값보다 작은 경우
  ],
})
```
