### 제약 조건

```sql
이상한 (결함이 있는) Data가 입력되는 것을 방지 : 무결성 원칙
무결성 원칙을 위반 하면 에러 발생 시킴

1. 제약 조건 조회
	- SELECT * FROM USER_CONSTRAINTS;
	- SELECT * FROM USER_CONSTRAINTS WHERE TABLE_NAME='테이블명';

2. 제약 조건 종류
	1) NULL          : NULL값 허용, Default
	2) Not Null      : NULL값 허용하지 않음
	3) Unique        : 값은 값을 허용하지 않음(중복 불가), NULL 입력 가능
	4) Primary Key   : NOT NULL + Unique
	5) Default       : 값을 넣지 않으면 기본값 적용
	6) Check         : 조건에 맞는 값만 허용 (WHERE의 조건식 과 같은 형식)
	7) Foreign Key
			- 다른 테이블을 참조
			- 다른 테이블과 관계(Relation) 처리
			- 참조 되는 테이블 부모테이블, 참조하는 테이블은 자식테이블
			- 부모테이블의 컬럼은 기본키(Primary key or Unique)로 지정된 컬럼이어야 함
			- 부모테이블의 테이블을 삭제하려면 자식테이블에서 참조하는 row가 없어야만 삭제 가능

3. 제약 조건 설정 방식
	1) 제약 조건 이름 : 테이블명_컬럼명_제약조건의약칭
	2) 제약 조건 약칭
		a. PRIMARY KEY   : PK  (P)
		b. FOREIGN KEY   : FK  (R)
		c. UNIQUE        : U
		d. NOT NULL      : NN  (C)
		e. CHECK         : C

4. DB 모델링 용어 정리
		Table   -> 릴레이션(Relation)
		Column  -> 속성 (Attribute)
		Row     -> 튜플 (Tuple)
							 인스턴스(Instance) : Data들의 집합
							 스키마(Schema)     : 기본 구조(뼈대, 컬럼명), 어떤 컬럼(Attribute) 들로 구성
							 도메인(Domain)     : 한 컬럼(Attribute)에 있는 Data들의 집합

5. Key의 종류
	1) 후보키 (Candidate Key)
			- 릴레이션을 구성하는 속성들 중에서 튜플을 유일하게 식별할 수 있도록 하는 것들
			- 모든 릴레이션은 하나 이상의 후보키 가 있어야 함
			- 중복이 안되는 Data가 있는 속성들(Attribute)
			- Primary key(기본키) 가 될 수 있는 속성들

	2) 기본키 (Primary Key)
			- 후보키 중에서 하나를 선택
			- 릴레이션 에서 하나의 tuple 을 구별할 수 있는 속성

	3) 대체키 (Alternate Key)
			- 후보키 중에서 Primary key를 제외한 나머지

	4) 슈퍼키 (Super key)
			- 복합키
			- 유일성 만족, 최소성은 만족하지 않은것
			- 두개 의 속성(Attribute)을 모아서 하나의 키로 만드는것

	5) 외래키 (Foreign Key)
			- 다른 릴레이션(Table)과 참조 관계를 맺을 때 사용
			- 외래키로 지정되면 Primary Key에 없는값은 입력 할 수 없음
			- 참조당하는 부모의 Attribute의 제약 조건은 Unique나 PK 여야 함
			- 참조당하는 Table(Parent, 부모), 참조하는 Table(Child, 자식)
			- 부모의 Tuple(Row)를 삭제 하려면 참조하는 자식 Tuple(Row)가 없어야 함
			- 자식이 있으면 자식을 모두 삭제 하고 부모를 삭제
			- Table 생성시 부모의 Tuple(Row)가 삭제 될 때 자동으로 자식의 Tuple(Row)을 변경하는 옵션

				a. 자식의 Tuple(Row)도 같이 삭제    : ON DELETE CASCADE
				b. 자식의 Attribute(Column)에 NULL : ON DELETE SET NULL
				ex) CONSTRAINT POINT_NUM_FK REFERENCES STUDENT (NUM) ON DELETE SET NULL --  ON DELETE CASCADE


```

### Table 생성 수정 삭제

```sql
1. Table 생성
 CREATE TABLE 테이블명 (
	컬럼명1 데이터타입,
	컬럼명2 데이터타입,
	컬럼명3 데이터타입,
	...
	컬럼명4 데이터타입

)

a. 컬럼레벨 방식
	CREATE TABLE 테이블명(
		컬럼명1 데이터타입 CONSTRAINT 제약조건이름 제약조건,
		컬럼명2 데이터타입 CONSTRAINT 제약조건이름 제약조건,
		컬럼명3 데이터타입 CONSTRAINT 제약조건이름 REFERENCES 참조할테이블명 (참조할컬럼명)
		-- 컬럼명과 참조할 컬럼명이 같다면 (참조할컬럼명) 생략 가능
		...
	)

b. 테이블레벨 방식
	CREATE TABLE 테이블명(
		컬럼명1 데이터타입,
		컬럼명2 데이터타입,
		...
		CONSTRAINT 제약조건이름 제약조건 (적용할 컬럼명),
		CONSTRAINT 제약조건이름 제약조건 (적용할 컬럼명),
		CONSTRAINT 제약조건이름 FOREIGN KEY (지정할컬럼명) REFERENCES 참조할테이블명 (참조할컬럼명)
		-- 지정할컬럼명 참조할컬럼명이 같을 경우 (참조할컬럼명)은 생략 가능
	)
		...
	)

c. 제약 조건 없이 테이블 생성 후 제약 조건 추가

- NOT NULL 과 DEFAULT는 컬럼 레벨 방식에서만 가능
- 컬럼 레벨 방식과 테이블 레벨 방식은 혼용이 가능

2. Table 삭제
	1) DROP
		- Table 자체를 삭제
		- DROP TABLE 테이블명

	2) TRUNCATE
		- Table을 삭제 하는 것이 아니라 모든 ROW(Tuple)을 삭제
		- Table 구조를 유지
		- TRUNCATE TABLE 테이블명

	3) DML의 DELETE
		- WHERE없이 사용하면 모든 Row가 삭제

	ex) Test Table에 3개의 Data가 있는 경우
		- DROP      : 구조와 Data가 삭제    -- 완전 제거
		- TRUCATE   : 구조 유지, 데이터 삭제 --조금더 깔끔하게 제거
		- DELETE    : 구조 유지, 데이터 삭제, 데이터가 있던 3칸도 유지

	4) RecycleBin (휴지통) --사용할일 거의 없음 개념
		- DB에서 삭제된 Table은 휴지통으로 이동
		- SELECT * FROM RECYCLEBIN               : 휴지통 조회
		- PURGE RECYCLEBIN                       : 휴지통 비우기(삭제), 복원 X
		- DROP TABLE 테이블명 PURGE               : 휴지통에 저장하지 않고 바로 삭제, 복원 X
		- FLASHBACK TABLE 테이블명 TO BEFORE DROP : 휴지통에서 복원

3. Table 수정
	1) Column 추가
		ALTER TABLE 테이블명 ADD (Column명 DataType)

	2) Column 삭제
		ALTER TABLE 테이블명 DROP COLUMN Column명

	3) Column 이름 변경
		ALTER TABLE 테이블명 RENAME COLUMN 기존컬럼명 TO 새로운컬럼명

	4) Column DataType 변경
		ALTER TABLE 테이블명 MODIFY (Column명 DataType)
		- 변경 전에는 해당 컬럼의 데이터를 NULL로 수정(UPDATE)
		- 같은 DataType으로 변경 할 경우는 바로 변경 가능
		- 같은 DataType 이라도 Size가 맞지 않으면 바로 변경 불가능

	5) Table의 이름을 변경
		RENAME 변경전테이블명 TO 새로운테이블명

		- 부모테이블이라 하더라도 자식테이블과 상관없이 변경 가능

4. Constraint (제약조건) 수정
	- 만들어진 제약 조건은 수정이 불가능 함
	- 삭제하고 새로 추가

	1) 새로운 제약 조건 추가
		ALTER TABLE 테이블명 ADD CONSTRAINT 제약조건이름 제약조건 (컬럼명)

	2) 제약 조건 삭제
		- ALTER TABLE 테이블명 DROP CONSTRAINT 제약조건이름
		- ALTER TABLE 테이블명 DROP CONSTRAINT 제약조건명

```

### SEQUENCE

```sql
- 자동 번호 발생기
- 순차적인 정수 값을 자동으로 생성하는 오라클 객체
- MYSQL은 Sequence 대신 INCREMENT 함수가 존재(AUTO INCREMENT)
- Sequence는 한 테이블에 종속적이지 않음
- 하나의 Sequence는 여러 Table에서 사용이 가능

1. Sequence 생성
- Table 생성시 (  ) 쓰지만 Sequence는 ( ) 사용하지 않음
- , 사용하지 않음

CREATE SEQUENCE 시퀀스명
[ INCREMENT BY 정수 ]          : 시퀀스 번호 증가 간격, 기본값 1
[ START WITH 정수 ]            : 시퀀스 시작 번호, 기본값 1
[ MAXVALUE 정수 ]              : 시퀀스의 최대값 지정
[ NOMAXVALUE ]                 : 시퀀스의 최대값 지정 하지 않음
[ MINVALUE 정수 ]              : 시퀀스의 최소값 지정
[ NOMINVALUE ]                 : 시퀀스의 최소값 지정 하지 않음
[ CYCLE OR NOCYCLE ]           : 최대 OR 최소 도달시 반복 여부 결정
[ CASHE OR NOCASHE ]           : 지정한 수량 만큼 메모리에 생성 여부 (최소 2, 최대 20개)

2. 시퀀스명
- 테이블명_SEQ
- 대표이름_SEQ

3. SEQUENCE 조회
- SELECT * FROM USER_SEQUENCES
- SELECT * FROM SEQ

4. SEQUENCE 사용
	1) NEXTVAL
		- 새로운 시퀀스값을 반환
		- 시퀀스명.NEXTVAL
		- 연습이든, 사용 후 Error가 나든 번호는 증가

	2) CURRVAL
		- 현재 시퀀스값을 반환
		- 이전 NEXTVAL 의해 가장 마지막으로 반환 된 시퀀스값
		- 시퀀스명.CURRVAL
		- CURRVAL은 같은 쿼리내에 NEXTVAL을 실행하고 나서 사용 가능함
		- 단독으로 사용 불가

5. SEQUENCE 수정
	- START WITH 수정 불가
	- 시퀀스를 생성하고 한번도 사용하지 않은 경우 수정 불가
	- START WITH을 변경하려면 삭제 후 새로 생성

	ALTER SEQUENCE 시퀀스명
	[ INCREMENT BY 정수 ]
	[ MAXVALUE 정수 ]
	[ NOMAXVALUE ]
	[ MINVALUE 정수 ]
	[ NOMINVALUE ]
	[ CYCLE OR NOCYCLE ]
	[ CASHE OR NOCASHE ]

6. SEQUENCE 삭제
	DROP SEQUENCE 시퀀스명
```
