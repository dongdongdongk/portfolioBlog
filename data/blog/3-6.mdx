# { 🎮 UI 위젯 시스템 구현하기 (Widget Blueprint) }

## 🎯 목표

게임 화면에 UI 텍스트 표시 및 제어

- Widget Blueprint 생성
- 화면에 텍스트 표시
- Blueprint에서 텍스트 동적 변경
- 핸드브레이크 상태 표시 예제

---

## 💡 핵심 개념

### UI (User Interface)란?

```
사용자와 게임이 소통하는 화면 요소
  ↓
예시:
  ├─ 체력 바
  ├─ 미니맵
  ├─ 점수 표시
  ├─ 버튼
  └─ 이 강의: 스로틀/상태 텍스트

중요성:
  - 게임 정보 전달
  - 플레이어 피드백
  - 조작 가이드
```

### Widget Blueprint란?

```
언리얼 엔진의 UI 제작 도구
  ↓
특징:
  ├─ 비주얼 편집 (드래그 앤 드롭)
  ├─ Blueprint 시스템 통합
  ├─ 실시간 미리보기
  └─ 반응형 UI 지원

일반 Blueprint와 차이:
  - 일반: 게임 로직, 오브젝트 제어
  - Widget: UI 전용, 화면 표시
```

## 🔧 2단계: Widget Blueprint 생성


## 🔧 3단계: Widget Blueprint 에디터 이해

### 에디터 열기

```
WB_F18_UI 더블클릭
  ↓
Widget Blueprint 에디터 표시
```

### 주요 패널 구성

**1. Viewport (뷰포트)**

```
기능: UI 디자인 화면
  ↓
표시:
  - UI 요소 배치
  - 시각적 미리보기
  - 실시간 편집
```

**2. Palette (팔레트)**

```
기능: UI 요소 목록
  ↓
포함:
  ├─ Text (텍스트)
  ├─ Button (버튼)
  ├─ Image (이미지)
  ├─ Progress Bar (진행 바)
  └─ 드래그로 Viewport에 추가
```

**3. Hierarchy (계층 구조)**

```
기능: UI 요소 트리 구조
  ↓
표시:
  - 부모-자식 관계
  - 요소 계층
  - 선택/편집 용이
```

**4. Details (상세 정보)**

```
기능: 선택한 요소의 속성
  ↓
조정:
  ├─ 위치, 크기
  ├─ 색상, 폰트
  ├─ 정렬, 앵커
  └─ 모든 시각적 속성
```

### Graph 탭

```
Designer 탭 옆에 위치
  ↓
포함:
  ├─ Event Construct (생성 이벤트)
  └─ Event Tick (틱 이벤트)

Event Construct:
  - Event BeginPlay와 유사
  - UI 생성 시 1회 실행
  - 초기화 작업

Event Tick:
  - 매 프레임 실행 (초당 60회)
  - 실시간 업데이트
```

## 🔧 4단계: Canvas Panel 추가

### Canvas Panel이란?

```
UI 요소를 배치하는 기본 컨테이너
  ↓
특징:
  ├─ 자유로운 위치 지정
  ├─ Anchor 시스템 지원
  ├─ 반응형 레이아웃
  └─ 화면 = Canvas Panel

비유:
  - 그림을 그리는 캔버스
  - 모니터 화면 전체
  - 모든 UI의 배경
```

### 추가 방법

```
Palette → Panel 섹션
  ↓
Canvas Panel 드래그
  ↓
Viewport로 드롭
  ↓
Hierarchy에 Canvas Panel 생성
```

## 🔧 6단계: Size To Content 설정

### Size To Content란?

```
기능: 텍스트 길이에 맞춰 박스 크기 자동 조절
  ↓
효과:
  - 텍스트 짧음 → 박스 작게
  - 텍스트 길음 → 박스 크게
  - 자동 조정으로 편리함

비활성화 시:
  - 고정된 크기
  - 텍스트가 잘리거나 넘침
```

### 설정 방법

```
Text 선택
  ↓
Details 패널 → Slot (Canvas Panel Slot) 섹션
  ↓
Size To Content 체크박스 ✅
```

## 🔧 7단계: Anchor 시스템 이해

### Anchor (앵커)란?

```
UI 요소의 기준점 설정
  ↓
역할:
  - 화면 크기가 변해도 상대적 위치 유지
  - 다양한 해상도 지원
  - 반응형 UI 핵심

비유:
  - 배를 묶는 닻
  - UI를 화면에 고정하는 기준점
```

### Anchor 설정

```
Text 선택
  ↓
Details 패널 → Anchors 드롭다운
  ↓
가운데 아이콘 선택 (Center)
  ↓
Anchor가 화면 중앙에 위치
```

**Anchor 옵션들**

```
Top Left: 좌측 상단 고정
Top Center: 상단 중앙 고정
Top Right: 우측 상단 고정
Center: 화면 정중앙 고정 ✅
Bottom Left: 좌측 하단 고정
등등...
```

## 🔧 8단계: Position과 Alignment로 정중앙 배치

### Position 설정

```
Text 선택
  ↓
Details 패널 → Position X: 0
                Position Y: 0
  ↓
Anchor 위치로 이동 (좌측 상단 모서리가 중앙)
```

**현재 문제점**

```
텍스트의 좌측 상단이 중앙에 위치
  ↓
텍스트가 중앙에서 오른쪽으로 치우침
  ↓
텍스트 자체를 중앙에 배치 필요
```

### Alignment로 해결

```
Details 패널 → Alignment
  ↓
X: 0.5
Y: 0.5
  ↓
텍스트의 중심점이 Anchor로 이동
  ↓
완벽한 화면 정중앙 배치 ✅
```

**Alignment 이해**

```
0.0 = 좌측/상단 끝
0.5 = 가운데
1.0 = 우측/하단 끝

Alignment X: 0.5, Y: 0.5
  ↓
텍스트 박스의 정중앙을
Anchor 위치(화면 중앙)에 배치
```

## 🔧 9단계: Blueprint에서 Widget 생성 및 표시

### 노드 구성

```
BP_F18 → Event Graph
  ↓
Event BeginPlay
  ↓
[Create Widget]
  ├─ Class: WB_F18_UI
  └─ Owning Player: Get Player Controller
  ↓
[Add to Viewport]
```

### Create Widget 노드

```
기능: Widget Blueprint 인스턴스 생성
  ↓
입력:
  ├─ Class: 생성할 Widget 타입
  └─ Owning Player: 소유 플레이어 컨트롤러

출력:
  └─ Return Value: 생성된 Widget 객체

중요:
  - 생성만 하고 표시는 안 함
  - Add to Viewport 필요
```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380599/notion-blog/_/_/BG/3/image.png)

**Owning Player란?**

```
이 UI를 소유하는 플레이어
  ↓
멀티플레이어 게임:
  - 플레이어 1 → UI 1
  - 플레이어 2 → UI 2
  - 각자의 UI 표시

싱글플레이어:
  - Get Player Controller 사용
  - 현재 플레이어 자동 연결
```

### Add to Viewport 노드

```
기능: 생성된 Widget을 화면에 표시
  ↓
입력:
  └─ Target: 표시할 Widget

효과:
  - 화면에 UI 표시
  - 플레이어가 볼 수 있게 됨
```

### 테스트

```
컴파일 → 저장 → 게임 실행
  ↓
결과: "Hello World" 화면 중앙에 표시 ✅
```

## 🔧 10단계: Widget을 변수로 저장

### Promote to Variable

```
Create Widget의 Return Value
  ↓
우클릭 → Promote to Variable
  ↓
이름: F18_UI
```

**왜 변수로 저장하나?**

```
변수 없이:
  - Widget 생성만 가능
  - 나중에 접근 불가
  - 내용 변경 불가 ❌

변수 저장:
  - 언제든 접근 가능
  - 텍스트 업데이트 가능
  - 다른 함수에서 사용 가능 ✅
```

### 노드 연결

```
[Event BeginPlay]
  ↓
[Create Widget] → Class: WB_F18_UI
  ↓
Return Value → [SET] F18_UI (변수 저장)
  ↓
F18_UI → [Add to Viewport]
```

## 📝 핵심 정리

### 전체 시스템 구조

```
WB_F18_UI (Widget Blueprint)
  ├─ Canvas Panel (컨테이너)
  │   └─ Text (Is Variable: ✅)
  │       ├─ Content: "F-18" (기본값)
  │       ├─ Anchor: Center
  │       ├─ Alignment: 0.5, 0.5
  │       └─ Size To Content: ✅
  └─ Set_My_Text 함수
      ├─ 입력: My_Text (Text 타입)
      └─ 기능: Text 위젯의 내용 변경

BP_F18 (게임 로직)
  ├─ Event BeginPlay
  │   ├─ Create Widget → WB_F18_UI
  │   ├─ 변수 저장 → F18_UI
  │   └─ Add to Viewport
  └─ IA_Handbrake
      ├─ Started → Set_My_Text("핸드브레이크")
      └─ Completed → Set_My_Text("핸드브레이크 해제")
```

```
UI 전용 Blueprint
  ├─ Designer: 시각적 편집

  └─ 두 탭을 오가며 작업
```

**2. Canvas Panel**

```
UI 컨테이너
  ├─ 자유로운 배치
  ├─ Anchor 시스템
  └─ 반응형 레이아웃
```

**3. Anchor & Alignment**

```
Anchor: 화면 내 기준점
Alignment: 요소 내 기준점
  ↓
조합으로 정확한 위치 지정
```

**4. Is Variable**

```
UI 요소를 Graph에서 접근 가능하게
  ↓
동적 제어의 핵심
```

**5. 함수 입력 파라미터**


## 💡 추가 설명

### Alpha vs Visibility

```
Alpha (투명도):
  - 0.0 ~ 1.0 범위
  - 부드러운 페이드 가능
  - 공간은 차지 (레이아웃 유지)

Visibility (표시/숨김):
  - Visible / Hidden / Collapsed
  - 즉시 켜짐/꺼짐 (페이드 X)
  - Collapsed는 공간도 제거

페이드 애니메이션:
  - Alpha 사용 권장 ✅
  - 부드러운 전환
```

### 키프레임 보간 (Interpolation)

```
엔진이 자동으로 중간값 계산
  ↓
예시:
  0.75초: A = 1.0
  3초: A = 0.0
  ↓
  2.875초: A = 0.5 (중간)
  ↓
  자동으로 부드러운 곡선 생성

보간 타입:
  - Linear: 직선 (일정한 속도)
  - Ease In: 천천히 시작
  - Ease Out: 천천히 끝
  - 이 강의: Linear (기본값)
```

### Event Construct vs Event Tick

```
Event Construct:
```

## 💡 핵심 개념: Pitch란?

### Pitch (피치) 이해

```

  └─ Roll: 굴림 (X축) 다음에
```

**왜 Pitch부터인가?**

```
비행에서 가장 중요한 조작:
  - 이륙/착륙
  - 고도 조절
  - 타겟 조준
```

## 🔧 4단계: 중립 복귀 (매우 중요!)

### ⚠️ 발생하는 문제

```
W 누르고 떼기
  ↓
Triggered 이벤트만 발생
  ↓
Pitch가 1.0으로 고정 ❌
  ↓
계속 회전함
  ↓
결국 땅에 박히거나 하늘로 날아감
```

**왜 이런 일이 발생하나?**

```
Set Pitch Input은:
  - 값을 "설정"하는 것
  - 자동으로 0으로 돌아가지 않음

예시:
  온도 조절기를 30도로 설정
  ↓
  손을 떼도 30도 유지
  ↓
  다시 조작하기 전까지 계속 30도

Pitch도 동일:
  1.0으로 설정
  ↓
  손을 떼도 1.0 유지
  ↓
  다시 0으로 설정하기 전까지 계속 회전 ❌
```

### ✅ 해결: Completed 이벤트

```
[IA_Pitch] Completed
  ↓
[Set Pitch Input]
  ├─ Target: Vehicle Movement Component
  └─ Pitch: 0.0
```

**Completed 이벤트란?**

```
키를 떼는 순간 발생하는 이벤트
  ↓
용도:
  - 입력 종료 감지
  - 초기화 작업
  - 중립 상태 복귀 ✅

Triggered와 차이:
  - Triggered: 키 누르는 동안
  - Completed: 키 떼는 순간
```

**효과**

```
W 누름:
  Triggered → Pitch 1.0 → 회전 시작
  ↓
W 떼기:
  Completed → Pitch 0.0 → 회전 정지 ✅
  ↓
직진 비행 유지

S도 동일:
  누름 → 회전
  떼기 → 정지
```

**만약 Completed가 없다면?**

```
W 누르고 떼기
  ↓
Pitch = 1.0 고정
  ↓
계속 위로 회전
  ↓
결국 뒤집혀서 추락 ❌

실제 비행기와 비교:
  - 실제: 조종간 놓으면 중립 복귀 ✅
  - 없으면: 조종간이 고정된 채로 ❌
```

```
  Elevator는 항상 일정한 방식으로 회전 ✅
```

### Split Struct Pin의 장점

```
분리 전:
  Rotation = (X, Y, Z) 한 덩어리
  ↓
  Y만 바꾸려면?
  전체를 새로 만들어야 함

분리 후:
  Rotation Y만 따로 제어
  ↓
  X, Z는 0으로 유지
  ↓
  간단하고 명확 ✅
```

## ⚠️ 주의사항

### Translation/Scale 숨기기

```
꼭 숨겨야 하나?
  - 아니요, 선택사항

하지만 권장:
  - 실수로 값 변경 방지
  - 노드가 깔끔해짐
  - 집중도 향상 ✅
```

### Rotation Mode 실수

```
잘못된 설정:
  Ignore 또는 Replace
  ↓
  Elevator가 이상한 각도로
  ↓
  비현실적 움직임

올바른 설정:
  Add to Existing ✅
  ↓
  기본 자세 + 조종 입력
  ↓
  자연스러운 움직임
```

## 🎯 핵심 요약

**3가지 핵심 설정:**

```
1. Rotation Mode: Add to Existing
   → 기존 회전 유지하며 추가

2. Rotation Space: Bone Space
   → 부모 기준 상대 회전

3. Split Struct Pin
   → Y축(Pitch)만 제어
```

**현재까지 완성:**

```
✅ Elevator 뼈대 찾기
✅ Transform (Modify) Bone 노드 설정
✅ 변수로 제어 가능
✅ Anim Preview Editor로 테스트

다음:
  Blueprint → Animation Blueprint 연동
```
