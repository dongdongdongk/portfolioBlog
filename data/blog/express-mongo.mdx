```jsx
const mongoose = require('mongoose')
const { Schema } = mongoose // 몽구스를 요청, DB연결은 필요없다 index 에서 요청할거니까

// 상품 스키마 정의
const productSchema = new Schema({
  name: {
    type: String,
    required: [true, 'name cannot be blank'],
  },
  price: {
    type: Number,
    required: true,
    min: 0,
  },
  category: {
    type: String,
    lowercase: true,
    enum: ['fruit', 'vegetable', 'dairy'],
  },
  farm: {
    // 농장 모델과 쌍방 관계 설정
    type: Schema.Types.ObjectId,
    ref: 'Farm',
  },
})

// 모델 정의
const Product = mongoose.model('Product', productSchema)

// 모델을 다른곳에서 사용 가능하게 익스포트
module.exports = Product
```

## **쌍방 관계의 활용**

```jsx
이제 쌍방 관계가 형성되었으므로 농장과 상품 간의 관계를 활용하여 대시보드나 다양한 페이지에서 필요한 정보를 얻을 수 있다.

예를 들어, 특정 농장의 모든 상품을 보여주는 페이지 등을 구현할 수 있다.

* 쌍방 관계는 데이터 일관성과 효율적인 데이터 관리를 제공하지만,

	모델의 복잡성과 성능 저하, 유지보수 어려움 등의 단점도 고려해야 한다.

	적절한 상황에서 적절히 사용하는 것이 중요
```

```jsx
// 농장에 상품 등록
app.post(
  '/farm/:id/products/new',
  wrapAsync(async (req, res, next) => {
    const { id } = req.params
    const farm = await Farm.findById(id)
    const { name, price, category } = req.body
    const product = new Product({ name, price, category })
    farm.products.push(product) // farm 에 product 넣어주기
    product.farm = farm // product 에 farm 넣어주기 양방향이니 둘다 해줘야한다
    await farm.save()
    await product.save()
    res.send(farm)
  })
)
```

```jsx
주소의 id 를 req.params 를 통해 가져오고 ( 농장 id)

그걸로 농장 데이터를 찾는다 (findId)

그리고 폼에서 제출된 req.body 의 상품 정보들을 product 에 저장하고

farm 에 push 로 상품 정보를 넣어준다  ( farm 에서 product 는 배열이니까 (One-to-Many) push 로 넣는것 )

이후 product 에도 farm 의 정보를 넣어준다 ( farm 은 하나기 때문에 .farm 으로 간단하게 넣어준다

그리고 save()
```

## 첫번째 방법 ( 수동 삭제 )

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381376/notion-blog/_/The_Web_Developer_2022/node_js/Express_Mongo_/Untitled_10.png)

```jsx
app.delete(
  '/farm/:id',
  wrapAsync(async (req, res, next) => {
    const { id } = req.params

    // 해당 Farm의 products를 먼저 찾아서 삭제
    const farm = await Farm.findById(id)
    const productIds = farm.products.map((product) => product._id) // 각 product 객체에서 _id 속성을 추출하는 화살표 함수

    // products가 비어있지 않으면 해당 상품들 삭제
    if (productIds.length > 0) {
      // Product 컬렉션에서 _id 값이 productIds 배열에 속한 값 중 하나인 모든 문서를 삭제
      await Product.deleteMany({ _id: { $in: productIds } })
    }

    // Farm 삭제
    await Farm.findByIdAndDelete(id)

    res.send({ message: '농장 및 농장에 속한 상품들을 삭제했습니다.' })
  })
)
```

```jsx
위와 같이 Farm 의 id 를 찾아서 삭제를 하면서

Farm 에 포함되어 있는 products 의 배열을 모두 삭제해주면 모든 내용이 지워진다

* $in은 MongoDB 쿼리 언어에서 사용되는 연산자 중 하나이다.

이 연산자는 배열에 속한 값들 중 하나라도 조건을 만족하는 문서를 검색하는 데 사용된다
```

## **쿼리 미들웨어(Query Middleware):**

```jsx
**역할:**

쿼리 미들웨어는 데이터베이스 쿼리가 실행되기 전이나 후에 특정 작업을 수행할 수 있게 해준다.

**예시:**

특정 쿼리가 실행되기 전에 데이터를 가공하거나, 쿼리의 결과를 처리할 수 있다.
```

```jsx
const farmSchema = new mongoose.Schema({
  name: String,
  // 다른 필드들...
})

// 쿼리 미들웨어 설정 (pre 함수 사용)
farmSchema.pre('findOneAndDelete', async function (next) {
  // 쿼리 실행 전 작업
  console.log('삭제 전 미들웨어 동작')
  next()
})
```

## **문서 미들웨어(Document Middleware):**

```jsx
**역할:**

문서 미들웨어는 MongoDB 문서(레코드)가 저장되기 전이나 후에 특정 작업을 수행할 수 있게 해줍니다.

**예시:**

문서가 저장되기 전에 필드를 가공하거나, 저장 후에 다른 동작을 수행할 수 있습니다.
```

```jsx
const farmSchema = new mongoose.Schema({
  name: String,
  // 다른 필드들...
})

// 문서 미들웨어 설정 (pre 함수 사용)
farmSchema.pre('save', async function (next) {
  // 문서 저장 전 작업
  console.log('저장 전 미들웨어 동작')
  next()
})
```

```jsx
위의 예제에서 'findOneAndDelete'는 쿼리 미들웨어의 예시이며,

'save'는 문서 미들웨어의 예시이다. 이러한 미들웨어를 사용하면 데이터베이스 작업 전후에 원하는 로직을 추가하여 데이터를 보다 유연하게 다룰 수 있다.
```
