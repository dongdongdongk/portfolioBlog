## 이 JSON 파일은 어떤 정보가 들어 있을까?

```jsx
1. 전체적인 맵 정보

"width":10, "height":10" → 맵 크기 (가로 10칸 × 세로 10칸)

"tilewidth":16, "tileheight":16" → 타일 하나의 크기 (16px × 16px)

"orientation":"orthogonal" → 직교 방식(2D 탑뷰 스타일)

2. 레이어 정보 (layers 부분)

"type": "tilelayer" → 이건 타일이 배치된 레이어예요.

"data" → 맵을 구성하는 타일 ID 배열이 들어 있습니다.

0 → 아무 타일도 없는 빈 공간

1103, 1104, 1167, 1168, 1231, 1232 → 타일셋에서 특정 타일을 의미

여기서 숫자는 타일셋의 타일 ID를 의미합니다.

예를 들어, 1103이라는 숫자가 있으면 타일셋에서 1103번 타일을 가져와서 배치한다는 뜻!

3. 타일셋 정보 (tilesets 부분)

"source": "../../main_lev_build_1.tsx" → 사용한 타일셋 파일의 경로

"firstgid":1 → 타일 ID의 시작값
```

# { 타일맵을 불러와 표시하기 }

## 1. **타일맵(Tilemap)과 레이어(Layer) 개념**

```jsx
1. 타일맵(Tilemap): 게임에서 사용하는 맵을 타일(Tile) 단위로 구성하여 저장한 것.

2. 레이어(Layer): 타일맵을 여러 개의 층으로 나누어 표시하는 것.

		environment(배경)

		platforms(플레이어가 점프할 수 있는 발판)
```

## 2. **타일맵을 Phaser에서 불러오기**

### 1) **프리로드(Preload) 단계**

```jsx
게임에 필요한 모든 데이터를 미리 로드하는 과정.

PreloadScene을 만들어 타일맵과 이미지(타일셋)를 로드함.
```

```jsx
class Preload extends Phaser.Scene {
  constructor() {
    super('PreloadScene')
  }

  preload() {
    this.load.tilemapTiledJSON('map', './assets/crystal_world_map.json')
    this.load.image('tiles-1', './assets/main_lev_build_1.png')
    this.load.image('tiles-2', './assets/main_lev_build_2.png')
  }

  create() {
    this.scene.start('PlayScene') // 로드 완료 후 PlayScene 실행
  }
}
```

```jsx
this.load.tilemapTiledJSON("map", "./assets/crystal_world_map.json")

		JSON 형태로 저장된 타일맵 데이터를 로드.

		"map"은 나중에 참조할 키값.

this.load.image("tiles-1", "./assets/main_lev_build_1.png")

		타일셋 이미지(main_lev_build_1.png)를 불러옴.

this.scene.start("PlayScene")

		데이터 로드 후 PlayScene으로 이동.
```

### 2) **맵을 Phaser에서 표시**

```jsx
class Play extends Phaser.Scene {
  constructor() {
    super('PlayScene')
  }

  create() {
    const map = this.make.tilemap({ key: 'map' }) // 타일맵 데이터 불러오기

```

```jsx

PlayScene에서 타일맵을 불러와서 화면에 배치.
```

# { 타일맵 로딩 및 코드 리팩토링 }

```jsx
이 강의에서는 Phaser 3에서 타일맵을 로딩하고, 코드의 가독성을 높이기 위해 리팩토링하는 과정을 다루었습니다.
```

## 1. 기존 코드 문제점

```jsx
기존 코드에서는 create() 메서드에서 맵, 타일셋, 레이어를 한 번에 생성하고 있어 코드가 복잡하고 가독성이 떨어졌습니다.
```

## 2. 코드 리팩토링 과정

```jsx
리팩토링을 통해 create() 내부의 코드들을 별도의 함수로 분리했습니다.
```

### (1) `createMap()` 함수 생성

```jsx
맵을 생성하는 역할을 합니다.

타일셋을 추가한 후, map 객체를 반환합니다.
```

```jsx
createMap() {
    // 1. 타일맵 객체를 생성합니다. "map"은 사전에 로드된 타일맵 데이터의 키입니다.
    const map = this.make.tilemap({ key: "map" });

    // 2. 타일셋을 추가합니다.
    //    - "main_lev_build_1": 타일맵 JSON 파일에서 정의된 타일셋의 이름
    //    - "tiles-1": Phaser에서 사전에 로드한 이미지의 키 ( 프리로드에서 )
    map.addTilesetImage("main_lev_build_1", "tiles-1");

    // 3. 생성한 타일맵 객체를 반환합니다.
    return map;
}
```

### (2) `createLayers()` 함수 생성

```jsx
생성된 map을 받아서 환경 및 플랫폼 레이어를 생성합니다.

map.getTileset()을 사용하여 타일셋을 가져옵니다.

생성된 레이어들을 객체로 반환합니다
```

```jsx
createLayers(map) {
    const tileset = map.getTileset("main_lev_build_1"); // 타일셋 가져오기
    const environment = map.createStaticLayer("environment", tileset);
    const platforms = map.createStaticLayer("platforms", tileset);

    return { environment, platforms };
}

```

## 3. `create()` 메서드 변경

```jsx
리팩토링한 함수들을 활용하여 create()를 간결하게 변경했습니다.
```

```jsx
create() {
    const map = this.createMap(); // 맵 생성
    const layers = this.createLayers(map); // 레이어 생성
}
```

## 4. `createStaticLayer` vs `createDynamicLayer` 차이점

```jsx
createStaticLayer()

		성능이 더 좋고, 수정할 필요 없는 레이어에 적합함.

createDynamicLayer()

		더 많은 기능을 제공하며, 수정 가능한 타일맵 레이어를 만들 때 사용함.

		하지만 더 많은 자원을 사용하므로 필요할 때만 사용해야 함.
```

# { 플레이어와 플랫폼 충돌 처리 }

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380503/notion-blog/_/Game_Development_in_JS_TS_-_The_Complete_Guide_w_/_4_Platformer_game_intro/image_16.png)

```jsx
이번 강의에서는 플레이어가 플랫폼과 충돌할 수 있도록 하는 기능을 추가합니다.

현재는 플레이어가 플랫폼을 통과해버리는 문제가 있습니다.

이를 해결하기 위해 충돌을 활성화하는 방법을 배우겠습니다.
```

## 1. 플랫폼을 충돌 가능하게 만들기

### 1) `setCollisionByExclusion` 함수 사용

```jsx
플랫폼 레이어를 만들 때, setCollisionByExclusion

메서드를 사용하여 충돌을 활성화할 수 있습니다.
```

```jsx
platforms.setCollisionByExclusion(-1, true)
```

```jsx
setCollisionByExclusion(excludedIndexes, collides)

		excludedIndexes: 충돌을 제외할 타일 인덱스를 지정합니다.

		collides: true로 설정하면 제외되지 않은 모든 타일이 충돌 가능해집니다.

여기서는 -1을 제외하고 모든 타일이 충돌 가능하도록 설정합니다.

즉, 타일 인덱스가 0 또는 -1인 경우는 충돌이 발생하지 않고, 나머지 타일은 충돌 가능하게 설정됩니다.
```

## 2. 플레이어와 플랫폼 간 충돌 설정

```jsx
플레이어가 실제로 플랫폼과 충돌하도록 add.collider 메서드를 사용합니다.
```

```jsx
this.physics.add.collider(player, layers.platforms)
```

```jsx
this.physics.add.collider(object1, object2)

		두 개의 객체(object1, object2)가 충돌할 수 있도록 설정합니다.

		여기서는 플레이어와 플랫폼이 충돌할 수 있도록 합니다.

이제 플레이어는 플랫폼과 충돌하여 떨어지지 않게 됩니다.
```

## 3. 충돌 문제 해결 (플랫폼이 보이지 않는 공간까지 충돌하는 문제)

```jsx
🔹 문제 원인

		일부 플랫폼 타일은 보이는 부분(텍스처)만 차지하지만,

		실제로는 전체 타일 크기(16px)를 차지하고 있습니다.

		따라서, 플레이어가 공중에 떠 있는 것처럼 보이는 현상이 발생합니다.

🔹 해결 방법

		이 문제를 해결하는 가장 간단한 방법은 충돌 전용 레이어를 만드는 것입니다.

		1. 새로운 충돌 전용 레이어를 만들고,

		2. 플랫폼 레이어 뒤에 배치한 후

		3. 플레이어와 이 충돌 레이어를 연결하면 해결됩니다.
```

## 3. **코드에서 충돌 레이어 적용**

### 3-1. **충돌 레이어 생성 코드 추가**

```jsx
createLayers(map) {
    const tileset = map.getTileset("main_lev_build_1");

    // 기존 레이어
    const environment = map.createStaticLayer("environment", tileset);
    const platforms = map.createStaticLayer("platforms", tileset);

    // 새로운 충돌 레이어 추가
    const platformsColliders = map.createStaticLayer("platforms_colliders", tileset);
    platformsColliders.setCollisionByExclusion(-1, true); // 충돌 설정

    return { environment, platforms, platformsColliders };
}
```
