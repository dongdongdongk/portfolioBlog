# { State Machine (스테이트 머신) 만들기 }

## 1. 왜 State Machine이 필요한가?

### 현재 문제점

- ✅ **지상 이동 애니메이션**: Blend Space로 잘 작동
- ❌ **점프 애니메이션**: 점프해도 계속 걷기/달리기 애니메이션만 재생

### 점프의 복잡성

**점프는 여러 단계로 구성:**

1. **점프 시작** (Jump Start)
2. **공중 정점** (Apex/Peak) - 가장 높은 지점
3. **착지** (Landing)

→ 단순한 Blend Space로는 관리 어려움

### 해결책: State Machine

**State Machine = 상태 관리 시스템**

- 캐릭터의 여러 "상태"를 관리
- 각 상태마다 다른 애니메이션 재생
- 조건에 따라 상태 간 전환

---

## 2. State Machine 기본 개념

### State (상태)란?

**캐릭터가 할 수 있는 각각의 행동**

**예시:**

- **Grounded (지상)**: 걷기, 달리기, 정지
- **Airborne (공중)**: 점프 중, 낙하 중
- **Landing (착지)**: 땅에 닿는 순간
- **Jump Start (점프 시작)**: 발을 구르는 순간

### Transition (전환)이란?

**한 상태에서 다른 상태로 바뀌는 것**

**예시:**

- Grounded → Airborne: 점프 키를 누름
- Airborne → Grounded: 땅에 착지
- Idle → Walk: 이동 키를 누름

### Step 1: State Machine 노드 생성

1. **Animation Graph** 내부에서 우클릭
2. **"State Machines"** 검색
3. **"Add New State Machine"** 선택
4. 이름 변경: **"Locomotion"** (또는 Movement)

**이름이 Locomotion인 이유:**

- 점프도 이동의 일부
- 모든 이동 관련 상태를 포함

### Step 2: State Machine 구조

**생성된 노드:**

- **입력**: 없음 (내부에서 자체 관리)
- **출력**: Pose (최종 애니메이션)
- Output Pose에 연결할 수 있음

**작동 방식:**

- **입력이 True**: 전환 실행 (Grounded → Airborne)
- **입력이 False**: 전환 안 함 (Grounded 유지)

### Step 2: 전환 규칙 설정

**Airborne to Grounded 더블클릭**

**목표:**

- IsAirborne이 **False일 때** 전환

### NOT 연산자 노드

1. **IsAirborne** 변수를 그래프로 드래그 → **Get**

4. NOT 출력 → **Result** 입력 연결

**NOT 연산자란?**

```
입력: True  → 출력: False
입력: False → 출력: True

```

**C++와 비교:**

```cpp
// C++
bool result = !isAirborne;

// Blueprint
IsAirborne → NOT → Result
```

## 2. Event Graph 코드 정리하기

### Sequence 노드로 정리

**Sequence 노드란?**

- 여러 작업을 순서대로 실행
- 코드를 깔끔하게 정리

**정리 과정:**

1. Event Graph에서 **우클릭** → **"Sequence"** 검색
2. **IsValid의 Is Valid 출력** → **Sequence 입력** 연결
3. **Sequence의 Then 0** → 기존 **Set Speed** 연결
4. **Then 1**은 IsAirborne 설정용으로 남겨둠

**정리된 구조:**

```
IsValid
    ↓
[Sequence]
    ↓
Then 0 → Set Speed → Set Angle
    ↓
Then 1 → (IsAirborne 설정 추가 예정)
```

## 3. IsAirborne 자동 설정 구현

### Character Movement Component 활용

**Is Falling 함수:**

- 캐릭터가 공중에 있는지 확인
- 반환: True (공중) / False (지상)
- 점프와 낙하 모두 포함

### 단계별 구현

**Step 1: Pawn Owner에서 Movement Component 가져오기**

1. **Sequence의 Then 1** 근처에서 우클릭
2. **"Try Get Pawn Owner"** 검색 (새로 생성)
3. 반환값 드래그 → **"Get Movement Component"** 검색

**Step 2: Is Falling 함수 호출**

1. **Get Movement Component** 반환값 드래그
2. **"Is Falling"** 검색 (Movement 카테고리)
3. Boolean 값 반환됨

**완성된 흐름:**

```
Then 1 → Try Get Pawn Owner → Get Movement Component
         → Is Falling → Set IsAirborne
```

# { 애니메이션 블루프린트에 사용된 노드 분석 }

## **이벤트 노드**

**Event BlueprintUpdateAnimation (K2Node_Event_0)**

- 애니메이션 블루프린트 전용 이벤트
- 매 프레임마다 애니메이션 업데이트 시 호출됨
- Tick 이벤트와 비슷하지만 애니메이션 시스템에 특화됨
- DeltaTimeX 출력: 프레임 간 시간 간격

## **검증 노드**

**IsValid (K2Node_MacroInstance_0)**

- 매크로 노드 (표준 매크로)
- 객체가 유효한지(null이 아닌지, 파괴되지 않았는지) 확인
- InputObject: TryGetPawnOwner의 결과를 받음
- "Is Valid" / "Is Not Valid" 두 경로로 분기

## **Pawn/Movement 관련**

**TryGetPawnOwner (K2Node_CallFunction_0, K2Node_CallFunction_8)**

- 애니메이션이 적용되는 Pawn(캐릭터) 참조 가져오기
- 애니메이션 블루프린트 전용 함수
- Pure 함수 (실행 핀 없음, 값만 반환)

**GetVelocity (K2Node_CallFunction_2)**

- Actor의 현재 속도 벡터 반환
- Vector(X, Y, Z) 형태로 이동 속도 정보 제공

**GetTransform (K2Node_CallFunction_4)**

- Actor의 위치, 회전, 스케일 정보를 담은 Transform 반환
- 로컬 좌표계 계산에 필요

**GetMovementComponent (K2Node_CallFunction_9)**

- Pawn의 Movement Component 참조 가져오기
- CharacterMovementComponent 등의 이동 컴포넌트 접근

**IsFalling (K2Node_CallFunction_10)**

- 캐릭터가 낙하 중인지 확인 (공중에 있는지)
- boolean 반환: true = 공중, false = 지상

## **수학 연산 노드**

**VSize (K2Node_CallFunction_3)**

- Vector Size의 약자
- Vector의 크기(길이)를 float 값으로 변환
- √(X² + Y² + Z²) 계산
- 용도: 속도 벡터의 크기 = 실제 이동 속력

**InverseTransformDirection (K2Node_CallFunction_1)**

- 월드 좌표계의 방향을 로컬 좌표계로 변환
- T (Transform): 기준이 되는 Transform
- Direction: 변환할 방향 벡터
- 용도: 캐릭터 기준에서 앞/뒤/좌/우 이동 방향 파악

**Conv_VectorToRotator (K2Node_CallFunction_6)**

- Vector를 Rotator로 변환
- 방향 벡터를 회전값(Roll, Pitch, Yaw)으로 변환
- 이 경우 Yaw(좌우 회전각)만 사용

## **흐름 제어**

**Sequence (K2Node_ExecutionSequence_0)**

- 실행 흐름을 여러 갈래로 분기
- then_0: Speed, Angle 계산
- then_1: IsAirborne 계산
- 순서대로 실행됨

## **변수 설정**

**Set Speed (K2Node_VariableSet_0)**

- Speed 변수에 값 저장
- VSize의 결과(속력)를 저장
- 애니메이션에서 블렌드 스페이스 등에 사용

**Set Angle (K2Node_VariableSet_1)**

- Angle 변수에 값 저장
- Yaw 회전값(좌우 방향각) 저장
- 8방향 이동 애니메이션 블렌딩에 사용

**Set IsAirborne (K2Node_VariableSet_2)**

- IsAirborne(공중 상태) 변수에 값 저장
- IsFalling의 boolean 결과 저장
- 점프/낙하 애니메이션 전환에 사용

## **전체 로직 요약**

이 블루프린트는 **캐릭터 애니메이션을 위한 기본 변수들을 매 프레임 업데이트**하는 구조예요:

1. **Event BlueprintUpdateAnimation** 실행 (매 프레임)
2. **TryGetPawnOwner**로 캐릭터 참조 획득
3. **IsValid**로 유효성 검증
4. **Sequence**로 두 갈래 동시 실행:
   - **경로 1**: 속도와 방향 계산
     - GetVelocity → 이동 속도 벡터
     - VSize → 속력(Speed) 계산 및 저장
     - GetTransform + InverseTransformDirection → 로컬 좌표계로 변환
     - Conv_VectorToRotator → Yaw 값(Angle) 추출 및 저장
   - **경로 2**: 공중 상태 확인
     - GetMovementComponent → IsFalling → IsAirborne 저장

이 세 변수(Speed, Angle, IsAirborne)는 애님 그래프의 블렌드 스페이스나 상태 머신에서 사용되어 달리기/걷기/점프 애니메이션을 자연스럽게 전환하는데 쓰일 거예요.

## **이벤트 노드 (Events)**

**BeginPlay**

- 액터가 게임에 생성될 때 한 번 실행
- 초기화 작업에 주로 사용 (변수 설정, 컴포넌트 세팅 등)

**Tick**

- 매 프레임마다 실행 (보통 60fps면 초당 60번)
- Delta Seconds 출력: 이전 프레임과의 시간 간격
- 성능 주의: 무거운 로직 넣으면 fps 떨어짐

**Event Dispatcher**

- 커스텀 이벤트를 다른 블루프린트로 브로드캐스트
- 예: "적이 죽었다"는 신호를 UI, 사운드, 퀘스트 시스템에 동시에 알림

**Input Events (InputAction, InputAxis)**

- 키보드/마우스/게임패드 입력 감지
- InputAction: 눌렀다/뗐다 (점프, 공격)
- InputAxis: 연속 값 (-1~1, 이동 방향)

## **흐름 제어 (Flow Control)**

**Branch**

- if문, 조건이 True/False에 따라 실행 경로 분기
- Condition 입력에 boolean 값

**Sequence**

- 실행 핀을 여러 개로 분기, 순서대로 실행
- Then 0, Then 1, Then 2... 순서로 진행

**ForLoop / ForEachLoop**

- 반복문
- ForLoop: 0부터 N-1까지 반복
- ForEachLoop: 배열의 각 요소마다 실행

**Switch (on Int/String/Enum)**

- switch-case문
- 값에 따라 여러 경로 중 하나를 선택

**DoOnce / DoN**

- DoOnce: 한 번만 실행, Reset 핀으로 초기화 가능
- DoN: N번만 실행

**Gate**

- Open/Close로 실행 흐름을 제어
- 문처럼 열어야 통과, 닫으면 차단

**Delay**

- 일정 시간 후 실행
- Duration 입력에 초 단위

**Retriggerable Delay**

- 다시 호출되면 타이머가 리셋되는 Delay
- 예: 마지막 입력 후 0.5초 뒤에 실행

# 애디티브 애니메이션으로 캐릭터 조준 구현하기

## 문제 상황

게임에서 마우스로 위아래를 봐도 캐릭터가 반응하지 않는 문제가 있습니다. 좌우 회전은 캐릭터 전체가 돌아가면 되지만, 위아래를 보려면 특별한 애니메이션 처리가 필요합니다.

## 해결 방법: 애디티브 애니메이션

**애디티브 애니메이션**은 기존 애니메이션 위에 추가로 덧붙이는 애니메이션입니다. 걷기/뛰기 같은 기본 애니메이션을 유지하면서 팔과 머리만 따로 조준 동작을 추가할 수 있습니다.

## 단계별 구현

### 1단계: 조준 오프셋 애니메이션 찾기

- Paragon 폴더 → Heroes → Wraith로 이동
- "AO"(Aim Offset) 라벨이 붙은 애니메이션 찾기
- "Idle_AO_Combat" 애니메이션 열기

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380656/notion-blog/_/_/_5_C_/_5_Shooter_Sam_-_3/image_9.png)

### 2단계: 블렌드 스페이스 이해하기

- **피치(Pitch)**: 위아래 보기
  - 90 = 위를 똑바로 봄
  - 0 = 정면
  - 90 = 아래를 똑바로 봄
- **요(Yaw)**: 좌우 보기 (이번에는 사용 안 함)

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380653/notion-blog/_/_/_5_C_/_5_Shooter_Sam_-_3/image_10.png)

### 3단계: 애니메이션 블루프린트에 적용

1. 애니메이션 그래프에서 작업
2. Asset Browser에서 "Idle AO" 검색하여 추가
3. State Machine → Idle AO → Output Pose 순으로 연결
4. 이렇게 하면 기본 애니메이션에 조준 동작이 추가됩니다

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380654/notion-blog/_/_/_5_C_/_5_Shooter_Sam_-_3/image_11.png)

### 4단계: 피치 변수 만들기

- 새 변수 "AimPitch" 생성 (Float 타입)
- Aim Offset 노드의 Pitch 입력에 연결
- 이제 값을 조절하면 캐릭터가 위아래를 봅니다

### 5단계: 실제 마우스 회전과 연결

Event Graph에서 작업:

1. **Pawn Owner**에서 **Get Control Rotation** 가져오기
   - 마우스 회전 정보를 가져옴
2. **문제 발생**: 아래를 볼 때 0→-90이 아니라 360→270으로 표시됨
3. **해결책**: Delta 계산

   ```
   Control Rotation - Actor Rotation = 원하는 값
   ```

4. 결과에서 Pitch만 분리해서 AimPitch 변수에 할당

# 프리뷰 베이스 포즈(Preview Base Pose)

애디티브 애니메이션을 미리보기할 때 **어떤 기본 애니메이션 위에 덧붙여서 볼 것인지** 지정하는 설정입니다.

## 왜 필요한가?

애디티브 애니메이션은 **단독으로는 의미가 없고**, 항상 다른 애니메이션 위에 추가되어야 합니다.

예를 들어:

- 조준 오프셋 애니메이션만 보면 → 이상하게 보임
- 달리기 애니메이션 + 조준 오프셋 → 자연스러움
- 점프 애니메이션 + 조준 오프셋 → 자연스러움

## 실제 사용 예시

강의에서 본 "Idle_AO_Combat" 애니메이션의 경우:

```
Asset Details(에셋 세부 정보)에서
└─ Additive Settings
   └─ Preview Base Pose: Idle_Combat
```

이 설정 덕분에:

- 에디터에서 애니메이션을 열면
- 자동으로 "Idle_Combat" 포즈 위에 조준 동작이 덧붙여진 모습을 미리볼 수 있습니다

## 요약

**프리뷰 베이스 포즈 = 에디터에서 미리보기용 기본 애니메이션**

실제 게임에서는 State Machine에서 나온 애니메이션이 베이스가 되지만, 에디터에서 애디티브 애니메이션을 단독으로 열어볼 때는 이 설정값을 사용해서 보여줍니다.

작업자가 "이 애디티브 애니메이션이 실제로 어떻게 보일지" 확인하기 편하도록 도와주는 기능이에요.

### 3-1: C++ 헤더 파일 수정

**ShooterSamPlayerController.h** 파일 열기

```cpp
// 맨 위에 추가
#include "HUDWidget.h"

class AShooterSamPlayerController : public APlayerController
{
    // 블루프린트에서 지정할 위젯 클래스
    UPROPERTY(EditAnywhere)
    TSubclassOf<UHUDWidget> HUDWidgetClass;

    // 실제로 생성된 위젯을 담을 변수
    UPROPERTY()
    UHUDWidget* HUDWidget;
};
```

**용어 설명:**

- `UPROPERTY(EditAnywhere)` = 언리얼 에디터에서 수정 가능
- `TSubclassOf<>` = 클래스 타입을 담는 변수
- `UHUDWidget*` = HUDWidget을 가리키는 포인터

---

### 3-2: C++ 구현 파일 수정

**ShooterSamPlayerController.cpp** 파일 열기

**BeginPlay() 함수 안에 추가:**

```cpp
void AShooterSamPlayerController::BeginPlay()
{
    Super::BeginPlay();

    // ... 기존 모바일 코드 ...

    // ===== 여기부터 추가 =====

    // 1단계: 위젯 생성 (메모리에 만들기)
    HUDWidget = CreateWidget<UHUDWidget>(this, HUDWidgetClass);

    // 2단계: 제대로 생성되었는지 확인
    if (HUDWidget)
    {
        // 3단계: 화면에 표시
        HUDWidget->AddToViewport();
    }
}
```

**코드 한 줄씩 이해하기:**

```cpp
HUDWidget = CreateWidget<UHUDWidget>(this, HUDWidgetClass);
```

- `CreateWidget` = 위젯 만드는 함수
- `<UHUDWidget>` = 어떤 타입인지 알려줌
- `this` = 이 PlayerController가 주인
- `HUDWidgetClass` = 어떤 블루프린트로 만들지 (나중에 지정)

```cpp
if (HUDWidget)
```

- 제대로 만들어졌는지 확인
- 만약 실패했으면 게임이 터지니까 체크!

```cpp
HUDWidget->AddToViewport();
```

- 만든 위젯을 실제 화면에 표시
- 이제 비로소 게임에서 보임!

위젯들을 배치할 수 있는 공간

### Anchor = 닻

화면 크기가 바뀌어도 위치 유지

### Alignment = 기준점

위젯의 어느 지점을 위치 기준으로 삼을지

### CreateWidget = 생성

메모리에 위젯 만들기 (아직 안 보임)

### AddToViewport = 표시

화면에 실제로 띄우기 (이제 보임!)
