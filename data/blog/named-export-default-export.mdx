```jsx
JavaScript와 TypeScript에서 클래스(class)를 모듈로 내보낼 때

Named Export와 Default Export 방식에 따라 가져오는 방법이 달라집니다.

각각의 방식과 예제를 살펴보겠습니다.
```

# { 1. Named Export (이름 있는 내보내기) }

```jsx
Named Export는 특정 이름으로 클래스(또는 변수, 함수)를 내보내는 방식입니다.

모듈을 가져오는 쪽에서 이 이름을 그대로 사용해야 합니다.
```

```jsx
예제: Named Export 사용하기

Config라는 클래스를 config.ts 파일에서 Named Export 방식으로 내보낸다고 가정해보겠습니다.
```

```jsx
// config.ts
export class Config {
  // 클래스 내용
  getConfig() {
    return 'This is the configuration'
  }
}
```

```jsx
이 경우 export 키워드 뒤에 클래스 이름을 명시적으로 작성하여 내보냅니다.

이렇게 하면 가져올 때 중괄호 {}를 사용하여 같은 이름으로 불러와야 합니다.
```

```jsx
// 다른 파일에서 Named Import 방식으로 가져오기
import { Config } from './config'

const myConfig = new Config()
console.log(myConfig.getConfig()) // "This is the configuration"
```

```jsx
export class Config는 Config 클래스를 Named Export로 내보낸 것입니다.

import { Config }처럼 중괄호 {} 안에 클래스 이름을 넣어서 가져와야 합니다.

주의: Config 이름을 그대로 사용해야 하며, 다른 이름으로 가져올 수 없습니다.
```

# { 2. Default Export (기본 내보내기) }

```jsx
Default Export는 모듈에서 하나의 항목을 기본으로 내보내는 방식입니다.

기본 내보내기는 가져오는 쪽에서 이름을 자유롭게 지정할 수 있습니다.
```

```jsx
예제: Default Export 사용하기

Config 클래스를 config.ts 파일에서 Default Export 방식으로 내보내 보겠습니다.
```

```jsx
// config.ts
export default class Config {
  // 클래스 내용
  getConfig() {
    return 'This is the configuration'
  }
}
```

```jsx
이렇게 export default로 클래스를 내보내면, 다른 파일에서 이름을 자유롭게 정해서 가져올 수 있습니다.

중괄호 {}는 필요하지 않습니다.
```

```jsx
// 다른 파일에서 Default Import 방식으로 가져오기
import MyConfiguration from './config'

const myConfig = new MyConfiguration()
console.log(myConfig.getConfig()) // "This is the configuration"
```

```jsx
export default class Config는 Config 클래스를 Default Export로 내보낸 것입니다.

가져올 때는 import MyConfiguration from './config'처럼 자유롭게 이름을 지정할 수 있습니다.

중괄호 {}를 사용하지 않습니다.
```

# { 싱글턴 패턴(Singleton Pattern) 으로 내보내기 }

```jsx
export const config: Config = new Config();처럼 특정 클래스의 인스턴스를 직접 생성해 내보내기하면,

다른 파일에서 이 인스턴스를 가져와서 바로 사용할 수 있으며, 새로 new Config()를 할 필요가 없습니다.
```

```jsx
// Config 클래스 정의
export class Config {
  getConfig() {
    return "This is a shared configuration";
  }
}

// Config 클래스의 인스턴스를 생성하여 내보냄
export const config: Config = new Config();
```

```jsx
이제 다른 파일에서 config 인스턴스를 가져와서 바로 사용할 수 있습니다.

여기서 config는 이미 생성된 인스턴스이므로, new Config()를 다시 호출할 필요가 없습니다.

애플리케이션의 다른 모듈에서 동일한 config 인스턴스를 불러와 재사용할 수 있습니다.
```

```jsx
// 다른 파일에서 import하여 사용
import { config } from './config'

console.log(config.getConfig()) // "This is a shared configuration"
```

## 왜 싱글턴 패턴을 사용해야 할까요?

```jsx
싱글턴 패턴은 클래스의 인스턴스를 하나만 생성하고, 여러 모듈에서 이 인스턴스를 공유할 수 있도록 만들어주는 패턴입니다.

설정 값, 데이터베이스 연결, 로그 기록 등 전역에서 하나의 인스턴스를 공유해야 할 때 유용합니다.
```

```jsx
메모리 절약:

		객체가 한 번만 생성되므로, 여러 번 인스턴스를 생성할 필요 없이 하나의 인스턴스를 재사용할 수 있습니다.

일관성:

		하나의 인스턴스를 사용하므로, 인스턴스의 상태가 일관성 있게 유지됩니다.

		예를 들어, 설정 값 같은 경우 여러 군데에서 동일한 값을 사용해야 할 때 유용합니다.

전역 접근:

		앱 어디에서든 이 설정 인스턴스를 가져다 쓸 수 있기 때문에,

		설정이 변경되면 애플리케이션 전반에 걸쳐 동일한 설정을 사용할 수 있습니다.
```
