# { 🎯 Set Actor Location과 Sweep }

## 📌 이 강의의 목표

Set Actor Location으로 물체를 이동시킬 때 Sweep의 역할을 이해합니다.

- Set Actor Location 사용법
- Add Actor World Offset과의 차이
- 한쪽만 Sweep할 때 결과
- 한 번만 이동시킬 때 (텔레포트)

---

## 🔄 BP_Ball_SetActorLocation

### Event Graph 구조

```
Event Tick
  ↓
Parent Tick
  ↓
ShouldMove 확인
  ↓
True이면
  ↓
Set Actor Location
```

### Event BeginPlay

```
Event BeginPlay
  ↓
NewLocation = Get Actor Location
  ↓
Parent BeginPlay 호출
```

**NewLocation**: 현재 위치를 저장하는 변수

---

## 📍 Set Actor Location 노드

### 위치 계산

```
매 프레임마다
  ↓
NewLocation 업데이트
  ├─ Forward Vector × (Delta Seconds × Speed)
  └─ NewLocation에 더하기
  ↓
Set Actor Location (NewLocation)
```

**핵심**: 절대 위치를 직접 설정

### Add Actor World Offset과 차이

```
Add Actor World Offset
  └─ 현재 위치 + 오프셋
      └─ 상대적 이동

Set Actor Location
  └─ 새 위치로 설정
      └─ 절대적 위치 지정
```

**결과는 비슷**: 둘 다 매 프레임 조금씩 이동


**이유**: Sweep이 충돌 감지

---

## 🧪 테스트 3: 한쪽만 Sweep (중요!)

### 설정

```
왼쪽 공 (Object A)
  └─ ShouldSweep: True ✓

오른쪽 공 (Object B)
  └─ ShouldSweep: False ✗
```

### 결과

```
Play 실행
  ↓
Object A → Sweep으로 이동 → 멈춤 ✅
Object B → Sweep 안 함 → 계속 진행 ❌
  ↓
Object B가 Object A를 통과!
```

**핵심**: Sweep은 본인만 멈춤, 상대를 못 막음!

### 왜 이렇게 되나?

```
Object A (Sweep = True)
  └─ "앞에 뭐 있나?" 검사
      └─ Object B 발견
          └─ 멈춤

Object B (Sweep = False)
  └─ 검사 안 함
      └─ 그냥 위치 설정
          └─ 겹쳐도 상관없음
```

**교훈**: 충돌하려면 **둘 다 Sweep** 해야 함!

## 💡 핵심 정리

### Sweep의 역할

```
Sweep = True
  └─ 이동 경로 검사
      ├─ 장애물 발견 → 멈춤
      └─ 장애물 없음 → 이동

Sweep = False
  └─ 검사 안 함
      └─ 무조건 이동 (겹쳐도 상관없음)
```

### 한쪽만 Sweep하면?

```
A (Sweep O) + B (Sweep X)
  ↓
A는 멈춤
B는 통과
  ↓
결국 겹침!
```

### 텔레포트 구현

```
Add Actor World Offset (1회만)
  ├─ Sweep = False → 벽 통과
  └─ Sweep = True → 벽 앞에 멈춤
```

# { 🎯 Add Force로 물리 이동 }

## 📌 이 강의의 목표

힘(Force)을 사용하여 물체를 이동시키는 방법과 Physics System의 특징을 이해합니다.

- Add Force 노드 사용법
- Physics System vs Query System
- Collision Enabled: Physics Only
- Probe 옵션의 역할

---

## 🚀 BP_Ball_AddForce

### Start Moving 로직

```
Start Moving 호출
  ↓
Add Force (BallMesh)
  ├─ Force: Forward Vector × Force Magnitude
  └─ 한 번만 실행
```

**특징**: Tick이 아닌 Start Moving에서 1회만 실행

### Force 계산

```
Force (벡터)
  ├─ 방향: Get Actor Forward Vector
  └─ 크기: Force Magnitude (큰 숫자)
```

**Force**: 방향과 크기를 가진 벡터

---

## ⚙️ 물리 시뮬레이션 설정

### BallMesh 설정

```
Collision Preset: PhysicsActor
  ├─ Collision Enabled: Query and Physics
  ├─ Object Type: PhysicsBody
  └─ Responses: Block All

Physics 섹션
  ├─ Simulate Physics: ✓ True
  └─ Enable Gravity: ✗ False
```

**Simulate Physics**: 물리 법칙 적용 (필수!)
**Enable Gravity**: 중력 사용 안 함

## 🔧 Physics System의 특징

### 자동 충돌 처리

```
Add Force
  ↓
물리 엔진이 자동으로 처리
  ├─ 충돌 감지
  ├─ 반발력 계산
  └─ 튕겨내기
```

**Sweep 불필요**: 물리 엔진이 알아서 함

### Query System과 비교

```
Query System (Sweep)
  └─ 경로 검사 → 막힘 → 멈춤

Physics System (Force)
  └─ 물리 계산 → 충돌 → 튕김
```

```

```

```
  ├─ Physics 불가능 ✗
  ├─ Simulate Physics 불가능 ✗
  └─ Add Force 불가능 ✗
```

### 에러 메시지


**결과**: 작동 안 함!

## 🔍 Probe 옵션

### Probe Only 설정

```
Collision Enabled: Probe Only
  └─ 충돌 감지만 함
      ├─ 힘 전달 안 함 ✗
      └─ Hit Callback은 실행 ✓
```

### 테스트

```
Play 실행
  ↓
공들이 만남
  ↓
서로 통과! 😱
  └─ 힘이 없어서 안 튕김
```

**Probe**: 충돌 감지만 하고 물리적 반응 없음

### 용도

```
Probe Only
  └─ "충돌했다"는 것만 알고 싶을 때
      └─ OnComponentHit 같은 이벤트만 필요
          └─ 실제로 막거나 튕기진 않음
```

## 📊 Collision Enabled 비교

### Physics Only

```
Physics Only
  ├─ Physics System: ✓
  ├─ Query System: ✗
  ├─ 물리 충돌: ✓ 튕김
  ├─ Line Trace: ✗ 무시됨
  └─ Sweep: ✗ 작동 안 함
```

### Query and Physics

```
Query and Physics
  ├─ Physics System: ✓
  ├─ Query System: ✓
  ├─ 물리 충돌: ✓ 튕김
  ├─ Line Trace: ✓ 감지됨
  └─ Sweep: ✓ 작동함
```

### Probe Only

```
Probe Only
  ├─ 충돌 감지: ✓
  ├─ 힘 전달: ✗
  ├─ Hit Callback: ✓
  └─ 튕김: ✗
```

---

## 💡 핵심 개념

### Add Force 사용 조건

```
필수 조건
  ├─ Simulate Physics = True
  └─ Collision Enabled
      ├─ Physics Only ✓
      ├─ Query and Physics ✓
      └─ Query Only ✗ (안 됨!)
```

### 두 가지 시스템

```
Query System
  └─ Sweep, Line Trace, Overlap
      └─ 직접 위치 설정할 때 사용

Physics System
  └─ 힘, 중력, 물리 법칙
      └─ 물리 엔진이 자동 처리
```

---

## 🎯 실전 활용

### 캐릭터 이동

```
Add Actor World Offset (Sweep)
  └─ Query System
      └─ 직접 제어
```

### 발사체 (총알, 미사일)

```
Add Force
  └─ Physics System
      └─ 물리적으로 날아감
```

### 떨어지는 물체

```
Simulate Physics + Enable Gravity
  └─ Physics System
      └─ 자연스럽게 떨어짐
```

### 감지만 필요

```
Probe Only
  └─ 이벤트만 발생
      └─ 막거나 튕기진 않음
```

```
  ├─ Query Only
  └─ Query and Physics
```

| 설정 옵션     | Simulation Generates Hit Events | Generate Overlap Events |

| 발생 빈도     | 충돌 순간                       | 진입/퇴장 시            |

---

## 💡 핵심 정리

### Hit 콜백 (OnComponentHit)

```
발생 조건
  ├─ Block 상호작용
  └─ 방법 1: Sweep 사용 (Query)
      또는
      방법 2: Physics + Simulation Generates Hit Events
```

### Overlap 콜백 (OnComponentBeginOverlap)

```
발생 조건
  ├─ Overlap 상호작용
  └─ 양쪽 모두 Generate Overlap Events = True
```

### From Sweep

```
Overlap 이벤트에서
  ├─ True → Sweep Hit Result 유효 (Impact Point)
  └─ False → Hit Result 비어있음 (Actor Location)
```

### Probe

```
충돌 감지만 함
  ├─ Hit 이벤트 발생
  └─ 물리력 없음 (통과함)
```

---

## ⚠️ 중요 주의사항

### Generate Overlap Events

```
양쪽 컴포넌트 모두 True여야 함!
  └─ 하나라도 False면 작동 안 함
```

### Simulation Generates Hit Events

```
Physics 충돌의 Hit 이벤트에만 필요
  └─ Sweep Hit는 이거 없어도 됨
```

### Probe 스팸

```
Probe는 접촉 중 계속 이벤트 발생
  └─ Do Once 같은 로직 필요
```

## 📚 용어 정리

| 용어                            | 설명                                |
| ------------------------------- | ----------------------------------- |
| OnComponentHit                  | 충돌(Block) 시 발생하는 이벤트      |
| OnComponentBeginOverlap         | 겹침(Overlap) 시작 시 이벤트        |
| Generate Overlap Events         | Overlap 콜백 활성화 옵션            |
| Simulation Generates Hit Events | Physics 충돌 Hit 콜백 활성화        |
| From Sweep                      | Overlap이 Sweep의 결과인지 확인     |
| Sweep Hit Result                | Sweep 결과 데이터 (Impact Point 등) |
| Impact Point                    | 충돌 지점 좌표                      |
| Probe Only                      | 충돌 감지만 하고 힘 전달 안 함      |

## Object Channel이란?

**Object Channel은 "충돌 카테고리"를 새로 만드는 기능입니다.**

언리얼에 기본으로 있는 `WorldStatic`, `WorldDynamic`, `Pawn` 같은 것들이 바로 Object Channel인데, 이것만으로 부족할 때 `Player`, `Enemy`, `Projectile` 같은 **나만의 카테고리**를 추가로 만들 수 있습니다.

예를 들어, "적은 적의 총알에 안 맞게 하고 싶다"면 `Enemy`라는 Object Channel을 만들고, 적 메시는 `Object Type: Enemy`로 설정한 뒤, 적 총알은 `Enemy에 대한 반응: Ignore`로 설정하면 됩니다. 이렇게 하면 적끼리는 서로 무시하고, 플레이어만 맞출 수 있게 됩니다.

**핵심**: Object Channel = 충돌 그룹을 새로 만드는 것. "너는 Player팀", "너는 Enemy팀" 이렇게 나눠서 팀별로 다른 충돌 규칙을 적용할 수 있게 해줍니다.

## 메시용 Preset을 왜 만드나?

**메시(캐릭터 몸체)와 발사체(총알)는 충돌 규칙이 달라야 하기 때문입니다.**

예를 들어 플레이어 캐릭터는 벽도 막아야 하고, 적도 막아야 하고, 다른 플레이어도 막아야 합니다. 하지만 플레이어의 총알은 플레이어 자신은 통과해야 하고, 적만 맞춰야 합니다. 이렇게 **역할이 다르면 Collision Preset도 따로 만들어야** 합니다.

`PlayerMesh` Preset은 "플레이어 캐릭터 몸체용"으로 벽/적/다른 플레이어를 모두 Block하고, `PlayerProjectile` Preset은 "플레이어 총알용"으로 플레이어는 Ignore하고 적만 Block합니다. 같은 Player 팀이지만 메시와 발사체는 **해야 할 일이 다르니까** 각각 전용 Preset을 만드는 겁니다.

**핵심**: 캐릭터 몸 ≠ 총알. 역할이 다르면 Preset도 따로 만들어서 각자에게 맞는 충돌 규칙을 적용합니다.

### PlayerProjectile Preset

```
Presets → New...
```

```
Name: PlayerProjectile
Description: 플레이어를 무시하는 발사체

Collision Enabled: Query Only ✅
  └─ Projectile Movement가 Sweep 사용
  └─ Physics 불필요

Object Type: Player ✅

Responses:
  ├─ 모두 → Ignore
  ├─ WorldStatic → Block
  ├─ WorldDynamic → Block
  ├─ Player → Ignore ✅ (자기편 무시!)
  └─ Enemy → Block ✅ (적만 맞춤!)
```

## ⚠️ 실습 문제 사례 (중요!)

### 문제 상황

```
EnemyProjectile Preset 생성 시
  ├─ Object Type: WorldDynamic (잘못된 설정!)
  └─ Enemy → Block
```

### 왜 문제?

```
EnemyMesh
  ├─ Object Type: Enemy
  └─ WorldDynamic → Block

EnemyProjectile
  ├─ Object Type: WorldDynamic (잘못!)
  └─ Enemy → Block

충돌 판정
  ↓
적 메시(Enemy)의 WorldDynamic 반응: Block
발사체(WorldDynamic)의 Enemy 반응: Block
  ↓
Block + Block = Block
  ↓
적이 자기 발사체에 맞음! 😱
```

### 해결 방법

```
EnemyProjectile Preset → Edit
  ↓
Object Type: Enemy로 변경 ✅
  ↓
Responses
  └─ Enemy → Ignore ✅
```

### 충돌 판정 (수정 후)

```
EnemyMesh
  ├─ Object Type: Enemy
  └─ Enemy → Block

EnemyProjectile
  ├─ Object Type: Enemy ✅
  └─ Enemy → Ignore ✅

충돌 판정
  ↓
적 메시(Enemy)의 Enemy 반응: Block
발사체(Enemy)의 Enemy 반응: Ignore
  ↓
Block + Ignore = Ignore
  ↓
적이 자기 발사체를 무시! ✅
```

### 핵심 교훈

```
발사체의 Object Type
  =
발사한 주체의 Object Type
  ↓
같은 팀끼리 무시 가능!
```

## 🔄 추가: 발사체끼리 충돌 방지

### 문제

```
플레이어 발사체 + 적 발사체 충돌
  ↓
불필요한 Hit 이벤트
```

### 해결 방법 1: WorldDynamic 사용

### PlayerProjectile 수정

```
Edit PlayerProjectile
  ↓
Object Type: WorldDynamic
Responses:
  ├─ WorldDynamic → Ignore ✅
  ├─ Player → Ignore
  └─ Enemy → Block
```

### EnemyProjectile 수정

```
Edit EnemyProjectile
  ↓
Object Type: WorldDynamic
Responses:
  ├─ WorldDynamic → Ignore ✅
  ├─ Enemy → Ignore
  └─ Player → Block
```

**주의**: 다른 WorldDynamic 물체도 무시됨!

### 해결 방법 2: Projectile Channel 생성 (권장)

```
New Object Channel: Projectile
  ↓
PlayerProjectile
  ├─ Object Type: Projectile
  └─ Projectile → Ignore

EnemyProjectile
  ├─ Object Type: Projectile
  └─ Projectile → Ignore
```

**장점**: 다른 WorldDynamic 물체는 여전히 맞춤

## 💡 핵심 개념 정리

### Object Channel vs Object Type

```
Object Channel
  └─ 충돌 카테고리 (Player, Enemy 등)

Object Type
  └─ 내가 어떤 카테고리인지
```

### 같은 팀 무시하기

```
발사체 Object Type = 발사한 주체 Type
  ↓
자기 Type에 대한 반응 = Ignore
  ↓
같은 팀끼리 무시!
```

### Query Only 사용

```
발사체는 Sweep으로 이동
  └─ Query Only면 충분
  └─ Physics 불필요
```

## ⚠️ 흔한 실수와 해결

### 실수 1: Object Type 잘못 설정

```
❌ EnemyProjectile Object Type: WorldDynamic
✅ EnemyProjectile Object Type: Enemy

이유
  └─ 같은 Type끼리 Ignore해야 자기편 안 맞춤
```

### 실수 2: Compile 안 함

```
Preset 변경 후
  └─ Blueprint Compile 필수!
      └─ 안 하면 반영 안 됨
```

### 실수 3: Preset이 안 보임

```
새 Preset 생성 후
  ↓
다른 곳 클릭 → Collision으로 다시 이동
  ↓
드롭다운 다시 열기
  ↓
Preset 나타남
```

## 💡 최종 요약

### 문제

```
1. 자기 자신 맞히기
2. 발사체끼리 충돌
3. 같은 팀 공격
```

### 해결

```
1. 커스텀 Object Channel 생성
   └─ Player, Enemy

2. 메시 Preset 생성
   └─ PlayerMesh, EnemyMesh

3. 발사체 자식 클래스 생성
   └─ BP_PlayerBlasterBeam
   └─ BP_EnemyBlasterBeam

4. 발사체 Preset 생성
   └─ Object Type = 발사 주체
   └─ 자기 Type은 Ignore
   └─ 상대 Type은 Block
```

### 핵심

```
같은 Object Type끼리
  └─ Ignore 설정
      └─ 자기편 안 맞춤!
```
