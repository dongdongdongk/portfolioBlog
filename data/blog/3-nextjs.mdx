# { Next.js 프로젝트가 화면에 보이기까지 (App Router 기준) }

## 최신 Next.js는 `app/` 폴더 구조를 쓴다

```csharp
예전에는 pages/ 폴더였지만, 최신 버전(특히 App Router 기반)은 app/ 디렉토리를 핵심으로 사용함.

이 app 폴더는 페이지, 레이아웃, 로딩 상태 등을 폴더와 파일 구조로 선언함.
```

## `app/page.js`는 루트 페이지다

```csharp
app/page.js는 **홈페이지(/)**에 해당.

이름이 page.js로 고정되어 있어야 함 → 이것이 Next.js에게 “여기는 페이지다”라고 알려주는 신호.

📌 page.js는 보호된(reserved) 파일명이다

(같은 예: layout.js, loading.js, error.js 등)
```

## 이 `page.js` 안에는 리액트 컴포넌트 함수가 있다

```csharp
export default function HomePage() {
  console.log("Executing...");
  return <h1>Hello, world!</h1>;
}
```

```csharp
이처럼 일반적인 React 함수형 컴포넌트지만,

Next.js는 이것을 서버 컴포넌트(Server Component) 로 다룬다
```

## 서버 컴포넌트란?

### 일반적인 React 컴포넌트 vs 서버 컴포넌트

| 항목        | 일반 React 컴포넌트           | 서버 컴포넌트 (Next.js)        |
| ----------- | ----------------------------- | ------------------------------ |
| 실행 위치   | 클라이언트(브라우저)          | 서버 (Node.js 환경)            |
| 콘솔 출력   | 브라우저 개발자 도구에서 보임 | 터미널(서버)에서 보임          |
| 데이터 접근 | 클라이언트 제한 있음          | DB, 파일 시스템 직접 접근 가능 |
| 장점        | 인터랙션 중심                 | 초기 렌더링 빠름, SEO 좋음     |

## 콘솔 확인 예시

```csharp
브라우저 개발자 도구에서 콘솔을 열어도 "Executing..." 메시지는 보이지 않음

대신 npm run dev 같은 명령으로 열어둔 터미널 콘솔에서 출력됨

📌 왜냐하면 이 컴포넌트는 서버에서 실행되기 때문임
```

## 서버 컴포넌트의 렌더링 흐름

```csharp
[ 서버 실행 중 ]
   ↓
page.js 컴포넌트 함수 실행 (console.log도 여기서)
   ↓
JSX 반환 (React 요소 트리)
   ↓
HTML로 변환
   ↓
브라우저에 전송
   ↓
화면에 렌더링됨

```

# { Next.js에서 내부 페이지 이동의 두 가지 방식 }

## 1. 전통적인 방법: `<a>` 태그 사용

```csharp
HTML에서 쓰는 기본적인 방식.

문제점:

		페이지가 완전히 새로고침됨 (브라우저가 전체 HTML을 다시 요청).

		**SPA(Single Page Application)**의 장점을 살리지 못함.

		새로고침 아이콘이 동작하면서 전체 페이지가 바뀌는 느낌.
```

```csharp
<a href="/about">About Us</a>
```

## 2. Next.js 방식: `Link` 컴포넌트 사용

```csharp
next/link에서 제공하는 컴포넌트

장점:

		페이지 전체가 새로고침되지 않음.

		React의 SPA 구조를 유지.

		내부적으로 자바스크립트를 통해 필요한 부분만 교체.

		브라우저 뒤로가기/앞으로가기 기능도 자연스럽게 작동.
```

```csharp
import Link from 'next/link';

<Link href="/about">About Us</Link>
```

## Next.js의 멋진 점

```csharp
Next.js는 둘 다 가능하게 합니다:

최초 페이지 진입: 서버에서 HTML을 미리 만들어 보내줌 (SSR, Static).

사이트 내 이동: 클라이언트 사이드에서 자바스크립트로 빠르게 전환 (SPA).

이렇게 SSR(서버 사이드 렌더링) + SPA(싱글 페이지 앱) 의 장점을 모두 누릴 수 있는 프레임워크입니다.
```

# { Next.js `layout.js`와 `page.js` 핵심 정리 }

## 1. `page.js`란?

```csharp
각 페이지의 실제 콘텐츠를 정의하는 파일.

Next.js에서 경로를 기반으로 라우팅되며, 사용자에게 보여질 주요 내용을 렌더링함.

리액트 컴포넌트를 export default로 내보냄.

예시: app/about/page.js → /about 경로로 접근 가능.
```

## 2. `layout.js`란?

```csharp
**레이아웃(껍데기)**을 정의하는 특별한 파일.

하나 이상의 페이지를 감싸는 공통 틀 역할.

layout.js도 리액트 컴포넌트로 동작하며, children 속성으로 포함된 page의 내용을 감쌈.

html 및 body 태그도 직접 렌더링할 수 있음 → 전체 HTML 구조 설정 가능.

프로젝트의 app 폴더 최상단에는 반드시 **근본 레이아웃(layout.js)**이 하나 있어야 함.

예시:

		app/layout.js → 모든 페이지에 공통 적용

		app/about/layout.js → /about 및 그 하위 페이지에만 적용됨 (중첩 레이아웃)
```

### layout.js를 사용하는 이유

```jsx
// ✅ app/layout.js
// 모든 페이지에 공통 적용되는 근본 레이아웃

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>
        <Header /> {/* 모든 페이지에 공통으로 들어가는 헤더 */}
        <main>{children}</main> {/* 각각의 페이지 콘텐츠 */}
        <Footer /> {/* 모든 페이지에 공통으로 들어가는 푸터 */}
      </body>
    </html>
  )
}

/*
📌 layout.js를 사용하는 이유 요약:

1. ✅ 공통 UI 요소 재사용
   - Header, Footer, Navigation 등을 layout.js에 한 번만 정의하면
     모든 페이지에 자동으로 적용됨.

2. ✅ 중첩 레이아웃 구성 가능
   - app/layout.js            → 모든 페이지에 공통 적용
   - app/about/layout.js     → /about 및 하위 페이지에만 적용

3. ✅ 성능 최적화
   - 레이아웃은 변경되지 않으면 캐시됨.
   - 페이지 전환 시 레이아웃은 그대로 유지되고, 페이지 내용만 바뀜 → 빠름!

4. ✅ 코드 분리 및 유지보수 용이
   - layout.js: 전체 구조(껍데기) 관리
   - page.js: 페이지 별 내용만 집중적으로 관리

*/
```

## 3. `children`이란?

```csharp
현재 활성화된 page.js의 리턴값(내용).

레이아웃 컴포넌트에서 <body>{children}</body> 형태로 감싸 사용.

레이아웃과 페이지가 함께 작동하는 구조의 핵심!
```

## 4. `metadata`란?

```csharp
layout.js 또는 page.js에 설정하는 특별한 이름의 변수.

export된 객체로 페이지의 title, description 등 메타데이터를 정의함.

별도의 <head> 태그 없이도 Next.js가 이 메타데이터를 이용해 <head> 부분을 구성함.
```

```csharp
// 예시
export const metadata = {
  title: 'NextJS Course App',
  description: 'Your first NextJS app!',
};
```

## 5. 전체 구조 예시

```csharp
// app/layout.js
import './globals.css'

export const metadata = {
  title: 'NextJS Course App',
  description: 'Your first NextJS app!',

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  );
}

```

```csharp
// app/about/page.js

  return <p>This is the About Page!</p>;
}

```

```csharp

→ 둘은 children을 통해 연결되며, metadata로 <head>를 대체함
```

## **{ 보호된 파일명 }**

```jsx
배우신 것과 같이 NextJS에는 일부 보호된 파일명이 있습니다.

중요:

		이 파일명들은  app/폴더(부 폴더 포함) 내부에서 생성될 때만 보호됩니다.  app/폴더 외부에서 생성될 경우 이 파일명들을 특별한 방식으로 처리하지 않습니다.

page.js => 신규 페이지 생성 (예: app/about/page.js은 <your-domain>/about page을 생성)

layout.js => 형제 및 중첩 페이지를 감싸는 신규 레이아웃 생성

not-found.js => ‘Not Found’ 오류에 대한 폴백 페이지(형제 또는 중첩 페이지 또는 레이아웃에서 전달된)

error.js => 기타 오류에 대한 폴백 페이지(형제 또는 중첩 페이지 또는 레이아웃에서 전달된)

loading.js => 형제 또는 중첩 페이지(또는 레이아웃)가 데이터를 가져오는 동안 표시되는 폴백 페이지

route.js => API 경로 생성(즉, JSX 코드가 아닌 데이터를 반환하는 페이지, 예: JSON 형식)

공식 문서에 지원되는 모든 파일 이름과 자세한 설명이 포함된 목록을 찾을 수 있습니다:

https://nextjs.org/docs/app/api-reference/file-conventions
```

# { Next.js의 동적 라우트(Dynamic Routes) }

## Next.js 동적 라우트(Dynamic Route) 개념 정리

```jsx
🔸 기본 라우팅 방식

		Next.js에서는 app 디렉토리 내부의 폴더와 page.js 파일 구조가 URL 경로(/경로)와 자동으로 매핑됩니다.

		예시:

		app/blog/page.js → /blog

🔸 문제 상황

		블로그 게시물을 각각의 폴더로 만들면 어떻게 될까요?

		예: app/blog/post-1/page.js, app/blog/post-2/page.js 등

		문제점: 새 게시물이 생길 때마다 새로운 폴더를 수동으로 추가해야 함 → 확장성과 유지보수에 매우 비효율적
```

## ✅ 해결책: 동적 라우트 (Dynamic Route)

### 동적 라우트란?

```jsx
경로 일부를 변수처럼 사용하는 라우트

대괄호 [ ] 를 사용해 동적 세그먼트를 정의
```

```jsx
app / blog / [slug] / page.js
```

```jsx
이렇게 하면 /blog/post-1, /blog/hello-world 같은 여러 경로를 하나의 파일로 처리할 수 있습니다.
```

## 동작 방식

```jsx
// app/blog/[slug]/page.js
export default function BlogPostPage({ params }) {
  return (
    <main>
      <h1>Blog Post</h1>
      <p>{params.slug}</p>
    </main>
  )
}
```

```jsx
params.slug에는 URL의 마지막 부분(예: /blog/post-1의 "post-1")이 자동으로 들어옴

이 slug를 활용해 데이터베이스에서 해당 게시물 정보를 가져올 수 있음
```

## 동적 라우트에서 `params`란?

# {`Image` 컴포넌트를 기존 `img` 태그 대신 사용 }

## 개념 정리: Next.js의 `Image` 컴포넌트를 사용하는 이유

### 1. **기본 `img` 태그 vs Next.js의 `Image` 컴포넌트**

```jsx
기본 img 태그도 작동하지만, 성능 최적화 측면에서 부족함

Next.js의 Image 컴포넌트는 성능을 자동으로 향상시켜주는 기능 내장
```

### 2. **Next.js `Image` 컴포넌트의 주요 장점**

| 기능                        | 설명                                                         |
| --------------------------- | ------------------------------------------------------------ |
| 🔄 지연 로딩 (Lazy Loading) | 화면에 보일 때만 이미지를 로드하여 초기 로딩 속도 개선       |
| 📐 자동 크기 추론           | `import`된 이미지의 크기를 자동 인식하여 width/height 설정   |
| 📱 반응형 이미지 (`srcset`) | 디바이스/화면 크기에 따라 최적 해상도 이미지 제공            |
| 📁 자동 포맷 변환           | 크롬 등에서 `.webp`처럼 효율적인 포맷으로 자동 변환하여 전송 |
| ⏱ `priority` 속성          | 페이지 로드 시 가장 먼저 로드해야 하는 이미지를 우선 로딩    |

## 적용 방법 요약

### 1. 이미지 import 방식 변경

```jsx
import Image from 'next/image'
import logoImg from '@/assets/logo.png' // 정적 import
```

### 2. 기존 `img` 태그 → `Image` 컴포넌트로 교체

```jsx
<Image src={logoImg} alt="A plate with food on it" priority />
```

```jsx
src: 정적 이미지 객체 (import된 이미지)

alt: 접근성을 위한 대체 텍스트

priority: 해당 이미지가 페이지 로드 시 가장 먼저 보여야 할 경우 설정
```

## 기타 참고 사항

### 자동 기능

```jsx
loading="lazy" 속성 자동 적용 (단, priority가 있을 경우 제외)

srcset, sizes 자동 생성 → 반응형 이미지 지원

이미지 포맷 자동 변환 → .webp, .avif 등으로 압축 효율 ↑
```

### 주의점

```jsx
Image 컴포넌트를 사용하려면 next.config.js에서 외부 도메인 이미지 로딩 시 domains 설정이 필요

크기(width/height) 자동 설정은 정적으로 import된 이미지에 한정됨
```

## 외부 이미지 URL을 사용 ?

```jsx
<Image src="https://example.com/image.jpg" alt="External image" />
```

```jsx
위처럼 **외부 도메인(example.com)**의 이미지를 직접 Image 컴포넌트에 넣으면,

Next.js는 "허용되지 않은 호스트" 라며 오류를 발생시켜요.
```

### 해결 방법: `next.config.js` 설정

```jsx
// next.config.js

module.exports = {
  images: {
    domains: ['example.com'], // 허용할 외부 이미지 도메인
  },
}
```

```jsx
여기서 'example.com'은 이미지가 호스팅된 외부 서버 주소예요.

이걸 명시하면 Next.js는 https://example.com/...에서 이미지를 가져올 수 있게 허용합니다.
```

### 왜 이렇게 제한하나요?

```jsx
보안: 악성 이미지 또는 해커가 조작한 이미지 URL을 막기 위해

성능 최적화: Next.js는 이미지를 자동 최적화 (크기, 포맷 등)하는데, 무분별하게 외부 URL을 허용하면 오버헤드가 커짐
```

## `image-slideshow.js` 코드 + 주석 설명

```jsx
'use client' // ✅ 이 컴포넌트가 클라이언트에서 실행되어야 함을 명시 (useState, useEffect 사용 때문)

import { useEffect, useState } from 'react'
import Image from 'next/image'

// 📁 미리 import한 음식 이미지들
import burgerImg from '@/assets/burger.jpg'
import curryImg from '@/assets/curry.jpg'
import dumplingsImg from '@/assets/dumplings.jpg'
import macncheeseImg from '@/assets/macncheese.jpg'
import pizzaImg from '@/assets/pizza.jpg'
import schnitzelImg from '@/assets/schnitzel.jpg'
import tomatoSaladImg from '@/assets/tomato-salad.jpg'

import classes from './image-slideshow.module.css' // 💅 CSS 모듈 불러오기

// 📸 슬라이드쇼에 사용될 이미지 배열
const images = [
  { image: burgerImg, alt: 'A delicious, juicy burger' },
  { image: curryImg, alt: 'A delicious, spicy curry' },
  { image: dumplingsImg, alt: 'Steamed dumplings' },
  { image: macncheeseImg, alt: 'Mac and cheese' },
  { image: pizzaImg, alt: 'A delicious pizza' },
  { image: schnitzelImg, alt: 'A delicious schnitzel' },
  { image: tomatoSaladImg, alt: 'A delicious tomato salad' },
]

// 🖼️ 슬라이드쇼 컴포넌트 정의
export default function ImageSlideshow() {
  // 현재 보여질 이미지 인덱스를 상태로 관리
  const [currentImageIndex, setCurrentImageIndex] = useState(0)

  useEffect(() => {
    // ⏱️ 5초마다 이미지 인덱스를 바꾸는 타이머 설정
    const interval = setInterval(() => {
      setCurrentImageIndex((prevIndex) => (prevIndex < images.length - 1 ? prevIndex + 1 : 0))
    }, 5000)

    // 💡 컴포넌트가 사라질 때(setInterval 정리)
    return () => clearInterval(interval)
  }, [])

  return (
    <div className={classes.slideshow}>
      {images.map((image, index) => (
        <Image
          key={index}
          src={image.image}
          alt={image.alt}
          // 🌟 현재 인덱스일 경우 활성화 스타일 부여
          className={index === currentImageIndex ? classes.active : ''}
        />
      ))}
    </div>
  )
}
```

| 항목             | 설명                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------ |
| `useState`       | 현재 보여줄 이미지 인덱스를 저장 (시간에 따라 값 변경)                               |
| `useEffect`      | 컴포넌트 마운트 시 interval을 설정하여 5초마다 이미지 변경, 언마운트 시 정리         |
| `setInterval`    | 일정 시간 간격(5초)마다 이미지 인덱스를 변경함                                       |
| `Image` 컴포넌트 | Next.js에서 사용하는 최적화된 이미지 컴포넌트                                        |
| `CSS 모듈`       | `.module.css` 파일로 각 이미지에 맞는 스타일을 지정 (예: `active` 클래스)            |
| `'use client'`   | 이 컴포넌트가 **클라이언트 컴포넌트**임을 명시 (서버 컴포넌트에서 상태 훅 사용 불가) |

# { 리액트 서버 컴포넌트 vs 클라이언트 컴포넌트 – 적절한 사용 선택 방법 }

## 1. 리액트의 기본: 클라이언트 컴포넌트

### CRA(Create React App)나 Vite 기반의 React 앱

```jsx
리액트는 기본적으로 클라이언트 사이드 라이브러리입니다.

따라서 일반 리액트 앱에서는 모든 컴포넌트가 브라우저에서 실행됩니다.

useState, useEffect, event handler(onClick) 등을 사용하는 것이 자연스럽습니다.

브라우저가 코드를 받아 실행하기 전까지는 빈 HTML이 렌더링됩니다 (CSR: Client Side Rendering).
```

## 2. Next.js의 기본: 서버 컴포넌트

### Next.js는 풀스택 프레임워크

```jsx
Next.js는 프론트엔드와 백엔드 역할을 모두 수행합니다.

기본적으로 모든 컴포넌트는 서버에서 렌더링됨 → 이를 **리액트 서버 컴포넌트(React Server Component)**라고 부릅니다.

서버에서 HTML을 생성해서 클라이언트에 전달하는 방식 → SSR(Server Side Rendering)
```

### 서버 컴포넌트의 특징

```jsx
브라우저에서 실행되지 않음

따라서 console.log()는 브라우저 개발자 도구가 아닌 **터미널(서버 로그)**에 찍힘

useEffect, useState, onClick 등의 클라이언트 전용 기능 사용 불가

주로 정적 페이지, SEO 최적화, 데이터베이스 접근 등 서버 관련 작업에 적합
```

## 3. 클라이언트 컴포넌트는 언제 필요한가?

### 브라우저에서 실행되어야 하는 로직이 있을 때

```jsx
상태 관리 (useState)

효과 처리 (useEffect)

사용자 이벤트 처리 (onClick, onChange, 등)

브라우저 API 사용 (localStorage, window, navigator, 등)
```

### 사용 방법

```jsx
해당 컴포넌트 파일의 최상단에 다음 지시어 추가:

이것은 Next.js에게 **"이 컴포넌트는 클라이언트에서 실행되어야 한다"**고 명시적으로 알려주는 것
```

```jsx
'use client'
```

## 4. 서버 컴포넌트와 클라이언트 컴포넌트의 관계

### 기본 규칙

```jsx
모든 컴포넌트는 기본적으로 서버 컴포넌트

클라이언트에서 작동하는 기능이 필요할 경우에만 'use client' 선언
```

### 포함 관계

```jsx
서버 컴포넌트는 클라이언트 컴포넌트를 포함할 수 있음

클라이언트 컴포넌트는 다른 클라이언트 컴포넌트만 포함 가능

따라서, 서버 → 클라이언트 방향으로는 가능하지만, 클라이언트 → 서버 컴포넌트로는 불가능
```

## 5. 작동 방식과 페이지 이동 시 동작

### 초기 페이지 로딩

```jsx
서버에서 HTML을 렌더링하여 브라우저에 전달

서버 컴포넌트는 서버에서 실행됨 (콘솔 출력은 터미널에서 확인 가능)
```

### 이후의 클라이언트 내비게이션 (SPA 동작)

```jsx
Next.js는 기본적으로 **하이드레이션(hydration)**을 사용하여, 서버에서 렌더된 HTML에 클라이언트 스크립트를 연결

하지만 서버 컴포넌트는 여전히 브라우저에서는 실행되지 않음

클라이언트 전용 기능은 클라이언트 컴포넌트 안에서만 작동
```

## 6. SEO와 성능 측면에서의 장점

| 항목             | 일반 React 앱(CRA 등)             | Next.js 서버 컴포넌트               |
| ---------------- | --------------------------------- | ----------------------------------- |
| HTML 렌더링 시점 | 클라이언트 실행 후 생성           | 서버에서 HTML 완성                  |
| 검색엔진 최적화  | ❌ 어려움 (초기 페이지 비어 있음) | ✅ 매우 유리                        |
| 초기 로딩 속도   | ❌ 느릴 수 있음                   | ✅ 빠름                             |
| JS 다운로드 크기 | 많음 (모든 UI 로직 포함)          | 적음 (클라이언트 컴포넌트만 전송됨) |

### 구조

### nav-link.js

```jsx
// 이 파일은 클라이언트 컴포넌트임을 명시합니다.
// usePathname 훅은 클라이언트에서만 작동하므로 필수입니다.
'use client'

// next/link에서 Link 컴포넌트를 불러옵니다.
// 이는 페이지 간 이동 시 전체 페이지 리로딩 없이 부드럽게 이동시켜줍니다.
import Link from 'next/link'

// 현재 경로(pathname)를 가져오는 훅입니다.
// 예: 사용자가 "/community" 페이지에 있다면 "path"는 "/community"가 됩니다.
import { usePathname } from 'next/navigation'

// 이 파일에서 사용할 CSS 모듈을 불러옵니다.
// link와 active 클래스가 정의되어 있어 스타일링에 사용됩니다.
import classes from './nav-link.module.css'

// NavLink라는 이름의 함수형 컴포넌트를 정의하고 이를 기본으로 내보냅니다.
// props로 href (링크 주소)와 children (링크에 표시될 텍스트 또는 내용)을 받습니다.
export default function NavLink({ href, children }) {
  // 현재 브라우저의 경로를 얻습니다.
  // 예를 들어 현재 경로가 "/meals/share"이면 path는 "/meals/share"가 됩니다.
  const path = usePathname()

  // JSX를 반환합니다. 여기서는 Link 컴포넌트를 사용하여 내비게이션 링크를 만듭니다.
  return (
    <>
      <Link
        href={href} // 이동할 대상 주소를 지정합니다.
        className={
          // 현재 경로가 href로 시작하면 (예: "/meals"가 "/meals/share"와 일치)
          // link와 active 두 클래스를 모두 적용합니다.
          // 그렇지 않으면 link 클래스만 적용합니다.
          path.startsWith(href) ? `${classes.link} ${classes.active}` : classes.link
        }
      >
        {children} // 링크 안에 표시할 텍스트 혹은 요소입니다.
      </Link>
    </>
  )
}
```

### startsWith

```jsx
startsWith는 자바스크립트에서 문자열(string)이 특정 문자나 단어로 시작하는지를 확인할 때 사용하는 메서드

		console.log(text.startsWith("/meals")); // true

		console.log(text.startsWith("/community")); // false

		"/meals/share"는 "/meals"로 시작하므로 true

		"/community"로 시작하지 않으므로 false
```

### 그럼 === 와 차이는?

| 비교 방식      | 설명                   | 예시 결과                                       |
| -------------- | ---------------------- | ----------------------------------------------- |
| `===`          | **정확히 일치**해야 함 | `"/meals" === "/meals/share"` → ❌ false        |
| `startsWith()` | **시작만 같으면** 됨   | `"/meals/share".startsWith("/meals")` → ✅ true |

# { 로컬 **SQLite 데이터베이스 }**

"MealsGrid 컴포넌트에서 음식을 보여주고 싶다 → 음식을 저장할 데이터베이스가 필요하다 →

## 1. 왜 데이터베이스가 필요할까?

```jsx
웹사이트에서 음식 목록(meals)을 보여주려면, 그 정보를 어딘가에 저장해두어야 합니다.

이를 위해 사용하는 것이 **데이터베이스(Database)**입니다.

이 강의에서는 **SQLite (SQL 라이트)**라는 데이터베이스를 사용하는데, 이유는:

		별도 서버 없이 로컬 파일 형태로 사용할 수 있음

		설정이 간단해서 빠르게 테스트 가능

		SQL 문법도 사용 가능
```

## 2. SQLite를 쉽게 쓰기 위해 설치한 도구

```jsx
npm install better-sqlite3
```

```jsx
better-sqlite3는 Node.js에서 SQLite를 쉽게 사용할 수 있게 도와주는 라이브러리입니다.
```

## 3. 데이터를 저장할 구조 만들기 (테이블 생성)

```jsx
SQL에서 데이터를 저장하려면 **테이블(table)**이 필요해요.
```

```jsx
CREATE TABLE IF NOT EXISTS meals (
   id INTEGER PRIMARY KEY AUTOINCREMENT,
   slug TEXT NOT NULL UNIQUE,
   title TEXT NOT NULL,
   image TEXT NOT NULL,
   summary TEXT NOT NULL,
   instructions TEXT NOT NULL,
   creator TEXT NOT NULL,
   creator_email TEXT NOT NULL
)
```

```jsx
이 테이블은 각각의 음식(meal)을 다음과 같은 정보로 저장합니다:

NOT NULL은 반드시 값이 있어야 한다는 뜻이고, UNIQUE는 중복되면 안 된다는 의미예요.
```

| 항목            | 설명                                                 |
| --------------- | ---------------------------------------------------- |
| `id`            | 자동으로 숫자가 증가하는 고유한 번호                 |
| `slug`          | URL에 쓰이는 고유 식별자 (예: `juicy-cheese-burger`) |
| `title`         | 음식 이름                                            |
| `image`         | 이미지 경로 (`/images/burger.jpg` 등)                |
| `summary`       | 간단한 설명                                          |
| `instructions`  | 요리 방법 설명                                       |
| `creator`       | 만든 사람 이름                                       |
| `creator_email` | 만든 사람 이메일                                     |

## 4. 임시 데이터(dummyMeals)를 집어넣기

```jsx
const stmt = db.prepare(`
   INSERT INTO meals VALUES (
      null,
      @slug,
      @title,
      @image,
      @summary,
      @instructions,
      @creator,
      @creator_email
   )
`)
```

```jsx
이 코드에서 stmt.run(meal)은 각 meal 객체의 데이터를 데이터베이스에 넣는 동작입니다.

null은 자동으로 id를 증가시키기 위한 자리입니다.

dummyMeals에는 우리가 샘플로 넣을 음식 정보들이 배열로 준비되어 있어요.
```

## 5. 전체 실행 흐름 (initdb.js)

```jsx
const sql = require('better-sqlite3')
const db = sql('meals.db') // meals.db 파일 연결 (없으면 새로 만듦)

// 테이블 생성
db.prepare(`CREATE TABLE IF NOT EXISTS ...`).run()

// 데이터 삽입 함수
async function initData() {
  const stmt = db.prepare(`INSERT INTO meals VALUES (...)`)
  for (const meal of dummyMeals) {
    stmt.run(meal) // 하나씩 집어넣기
  }
}

initData() // 실행
```

```jsx
이 파일을 실행하면:

1. meals.db라는 데이터베이스 파일이 생성되고

2. meals라는 테이블이 만들어지고

3. dummyMeals에 있는 음식 정보들이 저장됩니다
```

## 1. 서버 컴포넌트와 클라이언트 컴포넌트

```jsx
🔸 서버 컴포넌트 (기본)

		Next.js에서 만든 컴포넌트는 기본적으로 서버에서 실행됩니다.

		서버 컴포넌트는 데이터베이스에 직접 접근할 수 있습니다.

		useEffect를 사용할 수 없습니다 (클라이언트 전용 기능이기 때문).

🔸 클라이언트 컴포넌트

		use client 지시문을 맨 위에 적어야 함.

		브라우저에서 실행되므로 useEffect, useState 등 사용 가능.

		하지만 데이터베이스 직접 접근은 안 됨. 대신 fetch 요청으로 서버 API에 요청해야 함.
```

## 2. 데이터를 불러오는 두 가지 방식

| 방식 | 설명                                             | 예시                         |
| ---- | ------------------------------------------------ | ---------------------------- |
| 1    | 클라이언트 컴포넌트에서 `useEffect`로 fetch 사용 | React에서 자주 사용하는 방식 |
| 2    | **서버 컴포넌트에서 직접 DB 접근**               | Next.js에서 추천하는 방식    |

React 기본에서는 컴포넌트를 async로 만들 수 없지만, Next.js에서는 가능해요.

### lib/meals.js

```jsx
import sql from 'better-sqlite3'

// ✅ SQLite 데이터베이스 연결
const db = sql('meals.db')

export async function getMeals() {
  // ✅ 2초 지연을 주어 로딩 효과 시뮬레이션
  await new Promise((resolve) => setTimeout(resolve, 2000))

  // ✅ meals 테이블에서 모든 행 조회
  return db.prepare('SELECT * FROM meals').all()
}
```

| 문법                               | 설명                                   |
| ---------------------------------- | -------------------------------------- |
| `import sql from 'better-sqlite3'` | SQLite DB를 불러오기 위한 모듈         |
| `sql('meals.db')`                  | meals.db라는 SQLite 데이터베이스 열기  |
| `db.prepare(...)`                  | SQL 문을 준비 (보안/성능 좋음)         |
| `.all()`                           | SQL 결과를 "모든 행"으로 가져오기      |
| `async / await`                    | 비동기 함수, 기다리면서 코드 실행 가능 |

```jsx
📌 await new Promise(resolve => setTimeout(resolve, 2000)) → 2초 동안 기다리는 가짜 지연입니다.
```
