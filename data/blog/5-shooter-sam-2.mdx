## 1. 스켈레탈 애니메이션이란?

### 기본 개념

**스켈레탈 애니메이션(Skeletal Animation):**

```
정의:
스켈레톤(뼈대)에 애니메이션을 적용하여 만드는 애니메이션

작동 원리:
1. 뼈대(Skeleton) 생성
2. 뼈대에 외형(Mesh) 입히기
3. 뼈대를 움직이면 → 메시도 따라 움직임
```

---

### 실생활 비유

**인형의 구조와 비슷합니다:**

```
장난감 인형:
├── 뼈대 (관절이 있는 골격) → Skeleton
├── 피부/옷 (겉모습)          → Skeletal Mesh
└── 포즈 (관절 위치)          → Animation

움직임:
뼈대 관절을 움직임 → 피부/옷도 자동으로 따라 움직임
```

---

### 정적 메시와의 차이

**Static Mesh (정적 메시):**

```
구조:
- 뼈대 없음
- 고정된 3D 모델
- 변형 불가능

용도:
- 건물, 바위, 가구
- 움직이지 않는 오브젝트
```

**Skeletal Mesh (스켈레탈 메시):**

```
구조:
- 뼈대 있음
- 변형 가능한 3D 모델
- 애니메이션 적용 가능

용도:
- 캐릭터, 동물
- 움직이는 생명체
```

## 2. 4가지 핵심 에셋 이해하기

### 시스템 구성 요소

언리얼 엔진의 스켈레탈 애니메이션은 4가지 에셋으로 구성됩니다:

```
스켈레탈 애니메이션 시스템:
├── 1. Skeleton (스켈레톤)
├── 2. Skeletal Mesh (스켈레탈 메시)
├── 3. Animation Sequence (애니메이션 시퀀스)
└── 4. Animation Blueprint (애니메이션 블루프린트)
```

---

### 1. Skeleton (스켈레톤)

**역할: 뼈대 구조 정의**

```
Skeleton Asset:
├── Bone(뼈)들의 집합
├── 뼈들의 계층 구조
├── 각 뼈의 이름과 관계
└── 뼈들의 기본 위치

기능:
- 모델의 구조를 만드는 뼈의 모음
- 애니메이션 적용의 기준점
- Mesh와 Animation을 연결하는 접착제
```

**중요한 특징:**

```
스켈레톤은 보이지 않습니다!
- 뼈대 자체는 눈에 보이지 않음
- 메시를 입혀야 시각적으로 확인 가능
```

---

### 2. Skeletal Mesh (스켈레탈 메시)

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380653/notion-blog/_/_/_5_C_/_5_Shooter_Sam_-_2/image.png)

**역할: 시각적 외형**

```
Skeletal Mesh Asset:
├── 3D 모델의 외형 (피부, 옷 등)
├── 특정 Skeleton에 연결됨
├── Skeleton의 뼈에 가중치로 바인딩
└── 뼈가 움직이면 따라서 변형됨

기능:
- Skeleton의 시각적 표현
- 실제로 화면에 보이는 부분
- 텍스처, 재질 포함
```

---

### 3. Animation Sequence (애니메이션 시퀀스)

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380649/notion-blog/_/_/_5_C_/_5_Shooter_Sam_-_2/image_1.png)

**역할: 실제 움직임 데이터**

```
Animation Sequence Asset:
├── 키프레임(Keyframe)들의 집합
├── 각 프레임에서의 뼈 위치/회전
├── 시간에 따른 뼈의 변화
└── 특정 Skeleton 전용

기능:
- 걷기, 뛰기, 점프 등 개별 동작
- 뼈대를 조작하여 애니메이션 생성
- 재생 가능한 움직임 시퀀스
```

---

### 4. Animation Blueprint (애니메이션 블루프린트)

**역할: 애니메이션 로직 관리**

```
Animation Blueprint:
├── 여러 애니메이션 간 전환
├── 블렌딩(부드러운 전환)
├── 게임 로직과 연동
└── State Machine (상태 기계)

기능:
- Idle → Walk → Run 자동 전환
- 속도에 따라 애니메이션 선택
- 복잡한 애니메이션 시스템 구축
```

**이 강의에서는 처음 3가지에 집중합니다.**

---

### 에셋 간 관계도

**스켈레톤이 중심:**

```
                Skeleton (중심)
                    ↓
        ┌───────────┼───────────┐
        ↓           ↓           ↓
  Skeletal     Skeletal    Animation
   Mesh 1       Mesh 2      Sequence 1
                             ↓
                        Animation
                        Sequence 2
```

**호환성 규칙:**

```cpp
// 같은 Skeleton을 사용하면
if (Mesh.Skeleton == Animation.Skeleton) {
    // 모든 조합 가능 ✓
    Mesh1 + Animation1 = OK
    Mesh1 + Animation2 = OK
    Mesh2 + Animation1 = OK
    Mesh2 + Animation2 = OK
}

// 다른 Skeleton이면
else {
    // 호환 안 됨 ✗
    MannequinMesh + WraithAnimation = Error
}
```

---

### 접착제로서의 스켈레톤

**Skeleton의 핵심 역할:**

```
Skeleton = 메시와 애니메이션을 연결하는 접착제

예시:
SK_Wraith (Skeleton)
  ↓ 연결
├── SKM_Wraith (메시)
├── SKM_Wraith_Red (메시)
├── SKM_Wraith_Green (메시)
└── Animations:
    ├── Walk_Fwd
    ├── Walk_Bwd
    ├── Idle
    └── Run

결과:
- 3개의 메시 × 4개의 애니메이션
- = 12가지 조합 모두 가능!
```

### 뼈 조작 실험

**회전 모드로 뼈 움직이기:**

```
1. Skeleton Tree에서 "Spine_01" 선택
   ↓
2. Viewport에서 회전 툴(E) 활성화
   ↓
3. 척추 뼈를 회전
   ↓
결과:
- 척추가 회전
- 상체 전체가 함께 회전 (자식 뼈들)
```

**이것이 애니메이션의 원리:**

```
애니메이션 = 시간에 따른 뼈의 회전/이동 기록

Walk 애니메이션:
프레임 1: Spine 0°,  Leg 10°
프레임 2: Spine 2°,  Leg 20°
프레임 3: Spine 4°,  Leg 30°
...
→ 연속 재생하면 걷는 동작
```

## 4. 애니메이션 그래프 기초

### Output Pose 노드

- **최종 애니메이션을 결정하는 노드**
- "Result" 입력 핀으로 애니메이션을 받음
- 이 노드에 연결된 애니메이션이 실제로 재생됨

### 첫 애니메이션 연결하기

1. **Asset Browser**에서 원하는 애니메이션 검색 (예: "Idle_Combat")
2. 마우스로 **드래그 → Animation Graph에 드롭**
3. 애니메이션 노드의 **출력 핀**(Pose 오른쪽) 클릭
4. **Output Pose의 Result 핀**으로 드래그하여 연결
5. **컴파일** 버튼 클릭 (상단 체크 아이콘)
6. 미리보기 창에서 애니메이션 재생 확인

### Loop 설정

- 애니메이션 노드 선택
- Details 패널에서 **"Loop Animation"** 체크
- 체크하지 않으면 1회 재생 후 정지
- 다시 컴파일하면 반복 재생

## 8. 핵심 개념 정리

### 핀(Pin) 이해

- **좌측 핀 = 입력 (Input)**
- **우측 핀 = 출력 (Output)**
- 출력 → 입력 방향으로만 연결 가능
- **색상**으로 타입 구분 (초록색 = Float)

### 컴파일의 중요성

- 노드 구조나 설정 변경 시 **반드시 컴파일**
- 컴파일 = 변경사항을 실제 시스템에 적용
- 변수 사용 시는 컴파일 없이 실시간 변경 가능

### 실제 게임에서의 작동 방식

1. **플레이어가 이동 키를 누름**
2. **게임플레이 코드**가 캐릭터 속도 계산
3. 코드가 **Speed 변수 값 변경**
4. Animation Blueprint가 **자동으로 적절한 애니메이션 재생**
   - 정지 → Speed = 0 → Idle
   - 걷기 시작 → Speed 증가 → Walk 블렌딩
   - 뛰기 → Speed = 1 → 완전한 Walk

## 5. Speed 축 이해하기

### 속도 값의 의미

**그래프 위치별 의미:**

- **하단 (Speed = 0)**: 정지 상태 (Idle)
- **중간 (Speed = 100)**: 걷기 (Walk)
- **상단 (Speed = 200)**: 달리기/조깅 (Jog)

**블렌딩 구간:**

- **0 ~ 100 사이**: Idle에서 Walk로 부드럽게 전환
- **100 ~ 200 사이**: Walk에서 Jog로 부드럽게 전환

- 위아래로 움직이면 속도 변화 확인 가능

## 6. Angle 축 이해하기

### 각도 값의 의미 (게임 내 방향)

```
        앞 (0°)
         ↑
         |
왼쪽 (-90°) ← ● → 오른쪽 (90°)
         |
         ↓
    뒤 (±180°)

```

**각도별 방향:**

- **0°**: 앞으로 이동
- **90°**: 오른쪽으로 이동
- **180° (또는 -180°)**: 뒤로 이동
- **90°**: 왼쪽으로 이동

### 중요 포인트

- **±180도는 같은 뒤쪽 방향**
- 그래프 왼쪽 끝(-180)과 오른쪽 끝(180) = 둘 다 뒤로 이동
- 음수/양수는 회전 방향만 다를 뿐 결과는 동일

## 6. Event Graph 소개

### Animation Graph vs Event Graph

**Animation Graph (애니메이션 그래프):**

- **애니메이션 관련 작업만** 가능
- 노드 연결로 애니메이션 블렌딩
- 값 표시 및 연결만 가능

**Event Graph (이벤트 그래프):**

- **로직 작성 가능** (블루프린트 코드)
- 캐릭터에서 데이터 가져오기
- 변수 계산 및 설정
- 함수 호출 등 프로그래밍 작업

### 왜 Event Graph가 필요한가?

Animation Graph에서는:

- ❌ 캐릭터 포인터 가져오기 불가
- ❌ 속도 계산 불가
- ❌ 함수 호출 불가

Event Graph에서:

- ✅ Shooter Character 접근 가능
- ✅ 속도 가져오기 가능
- ✅ 변수 설정 가능

## 8. 블루프린트 노드 구현

### 단계별 구현

### Step 1: 포인터 유효성 검사

**포인터 사용 전 항상 확인 필수!**

1. **Try Get Pawn Owner**의 반환값 드래그
2. **"IsValid"** 검색 → 물음표 아이콘 선택
3. **IsValid 노드 생성됨**

**IsValid 노드 구조:**

- **입력 실행 핀**: Event에서 연결
- **출력 실행 핀 2개**:
  - **Is Valid**: 포인터가 유효할 때 실행
  - **Is Not Valid**: 포인터가 null일 때 실행

**연결:**

- Event Blueprint Update Animation → IsValid 입력

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380651/notion-blog/_/_/_5_C_/_5_Shooter_Sam_-_2/image_17.png)

---

### Step 2: Speed 변수 설정 노드

1. **Speed 변수**를 Event Graph로 드래그
2. **"Set Speed"** 선택
3. **Set 노드 생성**

**Set Speed 노드:**

- **입력 실행 핀**: IsValid의 **Is Valid**에서 연결
- **Speed 입력 핀**: 설정할 새 값 (Float)

**의미:**

- 포인터가 유효할 때만 Speed 설정

---

### Step 3: 캐릭터의 속도 가져오기

1. **Try Get Pawn Owner** 반환값 다시 드래그
2. **"Get Velocity"** 검색 → 선택
3. **Get Velocity 노드 생성**

**Get Velocity 노드:**

- 캐릭터의 현재 이동 속도 반환
- **반환 타입: Vector** (X, Y, Z 방향 속도)
- 실행 핀 없음 (값만 반환)

---

### Step 4: 벡터를 Float로 변환

**문제:** Get Velocity는 Vector를 반환하지만, Speed는 Float 필요

**해결:**

1. **Get Velocity** 반환값 드래그
2. **"Vector Length"** 검색 → 선택
3. **Vector Length 노드 생성**

**Vector Length란?**

- 벡터의 **크기(magnitude)** 계산
- 3D 공간에서의 실제 이동 속도
- 공식: √(X² + Y² + Z²)
- Float 값 반환

**예시:**

- Velocity = (300, 400, 0)
- Vector Length = √(300² + 400²) = 500

---

### Step 5: 최종 연결

**Vector Length 출력** → **Set Speed의 Speed 입력**

## 12. 키보드 vs 게임패드 차이

- 엄지스틱 조절로 **중간 속도 가능**
- Idle → Walk → Jog **자연스러운 전환**
- 훨씬 부드러운 게임플레이

**테스트 결과:**

- 엄지스틱 살짝 → 천천히 걷기
- 엄지스틱 끝까지 → 최고 속도 조깅
- 중간 값으로 부드러운 가속

# { 캐릭터 각도(Angle)를 Blend Space에 연결하기 }

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380651/notion-blog/_/_/_5_C_/_5_Shooter_Sam_-_2/image_20.png)

## 1. 목표 이해하기

### 현재 상황

- ✅ **Speed는 연결 완료** → 속도에 따라 Idle/Walk/Jog 전환
- ❌ **Angle은 아직 0으로 고정** → 앞으로만 이동 가능

### 이번 강의 목표

**Angle 값을 자동으로 계산하여 모든 방향 이동 구현**

**필요한 Angle 값:**

- **0°**: 앞으로 이동
- **90°**: 오른쪽으로 이동
- **90°**: 왼쪽으로 이동
- **180° (또는 -180°)**: 뒤로 이동

---

## 2. 핵심 개념: Velocity(속도)의 두 가지 의미

### Velocity 벡터란?

**Velocity = 방향 + 속도**

- 3D 공간에서의 이동 정보를 담은 벡터
- **X, Y, Z** 세 값으로 구성

**예시:**

```
Velocity = (500, 0, 0)
→ X축(앞) 방향으로 500 속도
→ 캐릭터가 정면으로 달림

Velocity = (0, 500, 0)
→ Y축(오른쪽) 방향으로 500 속도
→ 캐릭터가 오른쪽으로 달림

Velocity = (353, 353, 0)
→ 대각선 방향으로 이동
→ 앞쪽 + 오른쪽 45도
```

### 이전 강의 복습

**Vector Length (벡터 길이):**

- Velocity에서 **속도만** 추출
- √(X² + Y² + Z²)
- 방향 무시, 크기만 계산

**이번 강의:**

- Velocity에서 **방향(각도)만** 추출
- 속도 무시, 각도만 계산

---

## 3. World Space vs Local Space

### 문제 상황

**Get Velocity는 World Space 반환**

- World Space = 게임 월드 기준 좌표
- 캐릭터가 어디를 보든 같은 방향이 같은 값

**예시:**

- 캐릭터가 북쪽 보고 있을 때 앞으로 이동 = (1, 0, 0)
- 캐릭터가 동쪽 보고 있을 때 앞으로 이동 = (0, 1, 0)
- **같은 "앞"인데 다른 값!**

### 해결책: Local Space로 변환

**Local Space = 캐릭터 기준 좌표**

- 캐릭터가 어디를 보든 "앞"은 항상 같은 값
- 캐릭터 시점에서의 상대적 방향

**변환 후:**

- 앞으로 이동 = **항상 (1, 0, 0)**
- 뒤로 이동 = **항상 (-1, 0, 0)**
- 오른쪽 이동 = **항상 (0, 1, 0)**
- 왼쪽 이동 = **항상 (0, -1, 0)**

---

## 4. 단계별 구현

### 전체 흐름

```
Get Velocity (World Space)
    ↓
InverseTransformDirection (Local Space로 변환)
    ↓
MakeRotFromX (벡터 → 회전값 변환)
    ↓
요(Yaw) 값 추출
    ↓
Set Angle
```

---

### Step 1: Get Velocity 재사용

**이전 강의에서 만든 노드 활용**

- 이미 **Get Velocity** 노드 있음
- 같은 노드를 Speed와 Angle 둘 다에서 사용

---

### Step 2: Local Space로 변환

### InverseTransformDirection 노드 생성

1. **Get Velocity** 반환값 드래그
2. **"InverseTransformDirection"** 검색
3. 노드 선택

### 노드 구조

**입력 1 - Vector (벡터):**

- Get Velocity 연결
- World Space의 속도 벡터

**입력 2 - Transform (변환 기준):**

- 무엇을 기준으로 변환할 것인가?
- 캐릭터의 Transform 필요

---

### Step 3: 캐릭터의 Transform 가져오기

### Transform이란?

**게임 오브젝트의 3가지 정보:**

- **Location (위치)**: X, Y, Z 좌표
- **Rotation (회전)**: 어느 방향을 보는지
- **Scale (크기)**: 얼마나 큰지

**Outliner에서 Actor 선택하면 Details 패널에 표시됨**

### Get Actor Transform 노드

### MakeRotFromX 노드

## 6. Yaw 값의 의미

### Yaw가 나타내는 각도

**Local Space 기준:**

```
         앞 (Yaw = 0°)
              ↑
              |
왼쪽 (-90°) ← ● → 오른쪽 (90°)
              |
              ↓
         뒤 (±180°)
```

### 실제 값 예시

**앞으로 이동 (W 키):**

- Velocity (Local) = (1, 0, 0)
- Yaw = **0°**
- Blend Space의 앞 애니메이션 재생

**오른쪽으로 이동 (D 키):**

- Velocity (Local) = (0, 1, 0)
- Yaw = **90°**
- Blend Space의 오른쪽 애니메이션 재생

**왼쪽으로 이동 (A 키):**

- Velocity (Local) = (0, -1, 0)
- Yaw = **90°**
- Blend Space의 왼쪽 애니메이션 재생

**뒤로 이동 (S 키):**

- Velocity (Local) = (-1, 0, 0)
- Yaw = **180°** (또는 -180°)
- Blend Space의 뒤 애니메이션 재생

**대각선 이동 (W+D 키):**

- Velocity (Local) = (0.707, 0.707, 0)
- Yaw = **45°**
- 앞과 오른쪽 애니메이션 **자동 블렌딩**

**원인:**

- Angle 값 범위가 Blend Space와 불일치

- InverseTransformDirection 사용 확인
- Get Actor Transform 연결 확인

- Blend Space에 ±180도 둘 다 배치했는지 확인

- Blend Space에 중간 애니메이션 부족
