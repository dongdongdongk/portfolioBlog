# 함수 범위 (스코프)

```jsx
JavaScript에서 스코프(scope)는 변수와 함수의 유효범위를 나타낸다.

스코프는 변수와 함수가 어디서 접근 가능한지를 결정하며, **전역 스코프**와 **지역 스코프**로 나뉜다.
```

## **1. 전역 스코프(Global Scope)**

```jsx
전역 스코프는 코드의 가장 바깥쪽에서 정의된 변수와 함수로서 어디서든 접근할 수 있다
```

```jsx
// 전역 스코프에 변수 선언
let globalVariable = '전역 변수'

function globalFunction() {
  console.log(globalVariable) // 전역 변수에 접근 가능
}

globalFunction() // "전역 변수" 출력
```

## **2. 지역 스코프(Local Scope):**

```jsx
지역 스코프는 함수 내에서 선언된 변수와 함수로서 해당 함수 내부에서만 접근할 수 있다.
```

```jsx
function localFunction() {
  // 지역 스코프에 변수 선언
  let localVariable = '지역 변수'
  console.log(localVariable) // 지역 변수에 접근 가능
}

localFunction() // "지역 변수" 출력

// 아래의 코드에서는 localVariable에 접근할 수 없습니다.
// console.log(localVariable); // ReferenceError: localVariable is not defined
```

## **3. 블록 스코프(Block Scope):**

```jsx
ES6에서 도입된 블록 스코프는 중괄호 {}로 둘러싸인 영역을 말한다

let과 const로 선언된 변수는 블록 스코프를 가진다.
```

```jsx
if (true) {
  // 블록 스코프에 변수 선언
  let blockVariable = '블록 변수'
  const constantVariable = '상수 변수'
  console.log(blockVariable) // 블록 변수에 접근 가능
  console.log(constantVariable) // 상수 변수에 접근 가능
}

// 아래의 코드에서는 blockVariable과 constantVariable에 접근할 수 없습니다.
// console.log(blockVariable); // ReferenceError: blockVariable is not defined
// console.log(constantVariable); // ReferenceError: constantVariable is not defined
```

## **4. 스코프 체이닝(Scope Chaining)**

```jsx
함수가 중첩되어 있는 경우 내부 함수는 외부 함수의 변수와 전역 변수에 접근할 수 있다.

이러한 구조를 스코프 체이닝이라고 한다.

(외부 변수는 내부 함수의 변수에 접근 불가능 하다)
```

```jsx
function outerFunction() {
  let outerVariable = '외부 변수'

  function innerFunction() {
    console.log(outerVariable) // 외부 변수에 접근 가능
  }

  innerFunction()
}

outerFunction() // "외부 변수" 출력
```

## 렉시컬 스코프(Lexical Scope)

```jsx
함수가 어디에서 호출되었는지가 아니라 어디에 선언되었는지에 따라 스코프가 결정되는 개념

함수의 스코프는 함수를 어디에 쓰여있는지, 어떤 위치에 있는지에 따라 정적으로(코드가 작성된 시점에) 결정된다
```

```jsx
function outer() {
  const outerVariable = '외부 변수'

  function inner() {
    console.log(outerVariable) // outer 함수의 스코프에서 outerVariable에 접근
  }

  inner()
}

outer()
```

```jsx
이 예제에서 inner 함수는 외부 함수인 outer 함수 내에 선언되어 있다.

그래서 **inner 함수는 외부 함수인 outer 함수의 스코프에 접근할 수 있다. 이것이 렉시컬 스코프의 핵심이다.**

반대로 함수가 호출된 위치에 따라 스코프가 동적으로(실행 시점에) 변경되는 동적 스코프와는 대조적이다.

JavaScript는 렉시컬 스코프를 따르므로 함수의 스코프는 코드 작성 시점에 결정되며 호출 위치와는 상관이 없다.
```

# 함수 표현식(Function Expression)

```jsx
함수 표현식(Function Expression)은 함수를 변수에 할당하는 방식으로 정의하는 JavaScript의 문법이다.

함수 표현식은 함수를 생성하고 해당 함수를 변수에 저장할 수 있게 해준다.
```

## **함수 표현식의 기본 구문**

```jsx
let 변수명 = function (매개변수) {
  // 함수 내용
  return 결과값
}
```

```jsx
* 함수 정의:

function(매개변수) { ... } 부분은 함수를 정의하는 부분

* 변수에 할당:

let 변수명은 함수를 저장할 변수를 선언하고, 그 변수에 함수를 할당

* 사용:

변수명을 통해 함수를 호출하거나 다른 함수에 전달할 수 있다
```

## **기명 함수 표현식 (Named Function Expression)**

```jsx
let add = function sum(a, b) {
  return a + b
}

console.log(add(3, 4)) // 7
// console.log(sum(3, 4)); // 오류: sum은 변수에만 존재하므로 외부에서 접근 불가
```

```jsx
sum은 함수 표현식의 이름으로 사용되었지만, 함수 내부에서만 유효하다. 외부에서는 add로 함수에 접근한다
```

## **익명 함수 표현식 (Anonymous Function Expression)**

```jsx
let multiply = function (x, y) {
  return x * y
}

console.log(multiply(5, 6)) // 30
```

```jsx
함수에 이름이 없는 경우 함수는 익명 함수로 간주되며, 변수 multiply를 통해 함수에 접근한다
```

## **IIFE (즉시 실행 함수 표현식, Immediately Invoked Function Expression)**

```jsx
let result = (function (x, y) {
  return x + y
})(2, 3)

console.log(result) // 5
```

```jsx
함수를 정의하자마자 즉시 실행

사용이유는 변수를 전역으로 선언하는 것을 피하기 위해서 이다.

전역에 변수를 추가하지 않아도 되기 때문에 코드 충돌 없이 구현할 수 있어서 플러그인이나 라이브러리 등을 만들 때 많이 사용된다.
```

# 고차함수 (Higher-Order Function)

```jsx
고차 함수(Higher-Order Function)는 다른 함수를 매개변수로 받거나 함수를 반환하는 함수를 말한다.

JavaScript에서는 함수가 일급 객체로 취급되기 때문에 고차 함수를 자유롭게 활용할 수 있다.

* 일급 객체 : 프로그래밍 언어에서 일반적으로 갖춰야 하는 세 가지 조건을 만족하는 객체 (저장, 전달 , 반환)

 ex) 함수를 변수에 저장하거나, 함수를 다른 함수에 전달하거나, 함수를 반환할 수 있는 객체를 의미
```

## 예제

### **매개변수로 함수 받기**

```jsx
function applyOperation(x, y, operation) {
  return operation(x, y)
}

function add(a, b) {
  return a + b
}

function multiply(a, b) {
  return a * b
}

let result1 = applyOperation(2, 3, add) // 덧셈: 2 + 3 = 5
let result2 = applyOperation(4, 5, multiply) // 곱셈: 4 * 5 = 20

console.log(result1)
console.log(result2)
```

```jsx
applyOperation 함수는 세 개의 매개변수를 받는다 x, y, 그리고 operation.

operation은 함수로 전달되며, 이 함수를 통해 x와 y를 조작한다.

add 함수와 multiply 함수가 applyOperation에 전달되어 각각 덧셈과 곱셈이 수행된다.
```

### **함수를 반환하기**

```jsx
function createMultiplier(factor) {
  return function (x) {
    return x * factor
  }
}

let double = createMultiplier(2) // 2 를 받아서 내부에 x * 2 를 수행하는 함수를 반환해서 double 에 넣어준다
let triple = createMultiplier(3)

console.log(double(4)) // 4 * 2 = 8
console.log(triple(5)) // 5 * 3 = 15
```

```jsx
createMultiplier 함수는 factor를 매개변수로 받아서, 이를 이용하여 새로운 함수를 반환한다.

반환된 함수는 x를 매개변수로 받아서 x * factor를 반환

double과 triple은 각각 2배와 3배를 수행하는 함수이다.
```

### **배열 메서드에서의 활용**

```jsx
let numbers = [1, 2, 3, 4, 5]

// map 함수는 배열의 각 요소에 대해 주어진 함수를 호출하여 새로운 배열을 생성
let squared = numbers.map(function (x) {
  return x * x
})

console.log(squared) // [1, 4, 9, 16, 25]
```

```jsx
map 함수는 배열의 각 요소에 대해 주어진 함수를 호출하고 그 결과를 새로운 배열로 반환

여기서는 각 숫자를 제곱하여 새로운 배열을 생성
```

### **콜백 함수로 활용**

```jsx
function processArray(arr, callback) {
  let result = []
  for (let i = 0; i < arr.length; i++) {
    result.push(callback(arr[i]))
  }
  return result
}

let square = function (x) {
  return x * x
}

let doubled = function (x) {
  return x * 2
}

let numbers = [1, 2, 3, 4, 5]
let squaredNumbers = processArray(numbers, square)
let doubledNumbers = processArray(numbers, doubled)

console.log(squaredNumbers) // [1, 4, 9, 16, 25]
console.log(doubledNumbers) // [2, 4, 6, 8, 10]
```

```jsx
processArray 함수는 배열과 콜백 함수를 매개변수로 받아 각 요소에 대해 콜백 함수를 호출하여 새로운 배열을 생성

square 함수와 doubled 함수가 각각 배열의 요소를 제곱하고 2배로 만드는 역할을 한다
```

# 메서드 정의하기

```jsx
메서드(Method)는 객체에 속한 함수로, 해당 함수가 객체의 속성(property)으로 추가된 것을 의미한다.

객체의 행동을 정의하고 수행하는 함수를 객체의 일부로서 사용할 때 메서드라고 부른다
```

## **메서드 정의의 기본 구문**

```jsx
let 객체 = {
  메서드명: function (매개변수) {
    // 메서드 내용
    return 결과값
  },
}
```

### 예제

```jsx
let 사람 = {
  이름: 'John',
  나이: 30,
  인사: function () {
    console.log('안녕하세요! 제 이름은 ' + this.이름 + '이고, ' + this.나이 + '살입니다.')
  },
}

// 객체의 메서드 호출
사람.인사() // "안녕하세요! 제 이름은 John이고, 30살입니다."
```

```jsx
이처럼 메서드를 사용하면 객체의 상태를 나타내는 속성과 그 상태를 조작하는 함수를 하나의 단위로 묶을 수 있다.

객체 지향 프로그래밍에서 메서드는 객체의 특징과 동작을 캡슐화하여 코드를 모듈화하고 재사용성을 높이는 데 사용된다
```

# JavaScript에서 this

```jsx
현재 실행 중인 코드에서 참조하는 객체를 나타낸다.

그러나 this의 값은 어떻게 결정되느냐에 따라서 매우 동적이다
```

## **전역 컨텍스트에서의 `this`**

```jsx
console.log(this) // 전역 객체 (브라우저에서는 window)
```

```jsx
전역 컨텍스트에서 this는 전역 객체를 참조한다. 브라우저에서는 보통 window 객체가 전역 객체로 사용된다.
```

## **함수에서의 `this`**

```jsx
function showThis() {
  console.log(this)
}

showThis() // 전역 객체 (브라우저에서는 window)
```

```jsx
일반 함수 내에서 this는 호출 컨텍스트에 따라 결정

브라우저에서는 전역 컨텍스트에서 호출하였으므로 전역 객체가 출력
```

## **객체 메서드에서의 `this`**

```jsx
let person = {
  name: 'John',
  sayHello: function () {
    console.log('안녕하세요, 제 이름은 ' + this.name + '입니다.')
  },
}

person.sayHello() // "안녕하세요, 제 이름은 John입니다."
```

```jsx
객체의 메서드 내에서 this는 해당 메서드를 호출한 객체를 참조

위의 예제에서 sayHello 메서드는 person 객체에 속해 있으므로 this는 person 객체를 참조
```

## **생성자 함수에서의 `this`**

```jsx
function Person(name) {
  this.name = name
  this.sayHello = function () {
    console.log('안녕하세요, 제 이름은 ' + this.name + '입니다.')
  }
}

let person1 = new Person('Alice')
let person2 = new Person('Bob')

person1.sayHello() // "안녕하세요, 제 이름은 Alice입니다."
person2.sayHello() // "안녕하세요, 제 이름은 Bob입니다."
```

```jsx
생성자 함수에서 this는 새로 생성되는 인스턴스를 참조

위의 예제에서 Person 함수는 new 키워드를 사용하여 두 개의 다른 인스턴스를 생성했고,

각 인스턴스의 sayHello 메서드에서 this는 각 인스턴스를 참조
```

## **이벤트 핸들러에서의 `this`**

```jsx
let button = document.getElementById('myButton')

button.addEventListener('click', function () {
  console.log(this) // 버튼 요소 (클릭한 요소)
})
```

```jsx
이벤트 핸들러 내에서 this는 이벤트를 발생시킨 DOM 요소를 참조

위의 예제에서는 버튼 요소가 클릭 이벤트를 발생시키므로 this는 버튼 요소를 참조
```

## **화살표 함수에서의 `this`**

```jsx
let obj = {
  value: 42,
  getValue: function () {
    return () => {
      console.log(this.value)
    }
  },
}

let func = obj.getValue()
func() // 42
```

```jsx
화살표 함수 내에서 this는 화살표 함수가 정의된 컨텍스트가 아니라, 화살표 함수가 생성될 때의 컨텍스트(전역,함수,객체,블록)를 유지

위의 예제에서 getValue 메서드 내에서 반환되는 화살표 함수는 obj를 참조하므로, 호출 시에도 obj의 value 속성을 출력한다.
```

## arrow 함수를 객체 내에서 사용할 때 발생하는 문제와 해결 방법

```jsx
JavaScript에서 this는 함수가 어떻게 호출되었는지에 따라 다르게 동작한다.

Arrow 함수는 일반 함수와는 다르게 자체적인 this를 생성하지 않고, 외부 스코프의 this 값을 그대로 사용한다.

이 특성 때문에 객체 내에서 arrow 함수를 사용할 때에는 주의가 필요하다
```

### **객체 내에서 일반 함수 사용**

```jsx
const person = {
  name: 'John',
  sayHello: function () {
    console.log(`안녕하세요, ${this.name}입니다.`)
  },
}

person.sayHello() // 출력: 안녕하세요, John입니다.
```

### **객체 내에서 arrow 함수 사용**

```jsx
const person = {
  name: 'John',
  sayHello: () => {
    console.log(`안녕하세요, ${this.name}입니다.`)
  },
}

person.sayHello() // 출력: 안녕하세요, undefined입니다.
```

### **해결 방법**

```jsx
arrow 함수 내에서 외부 스코프의 this를 사용하지 않고, 대신 일반 함수를 사용하거나 메서드를 일반 함수로 정의하면 된다
```

```jsx
const person = {
  name: 'John',
  sayHello() {
    console.log(`안녕하세요, ${this.name}입니다.`);
  },
};

person.sayHello(); // 출력: 안녕하세요, John입니다.

* arrow 함수 내에서 외부 스코프의 this를 사용하지 않고, 대신 일반 함수를 사용하거나 메서드를 일반 함수로 정의하면 된다
```

```jsx
const person = {
  name: 'John',
  sayHello: function() {
    const greet = () => {
      console.log(`안녕하세요, ${this.name}입니다.`);
    };

    greet();
  },
};

person.sayHello(); // 출력: 안녕하세요, John입니다.

* greet 함수는 arrow 함수이기 때문에 외부의 this를 사용하지 않고,

	person.sayHello 메서드에서 호출될 때 외부 스코프의 this가 greet 함수 내부로 전달되어 this.name이 정상적으로 동작
```

# JavaScript의 **`try-catch`**

```jsx
JavaScript의 try-catch 구문은 예외(에러)가 발생할 수 있는 코드 블록을 감싸고,

예외가 발생하면 해당 예외를 처리할 수 있는 코드 블록을 제공

try-catch 구문을 사용하면 예외가 발생했을 때 프로그램의 중단을 방지하고, 에러 메시지를 적절히 처리하거나 로깅할 수 있다.
```

## **`try-catch` 구문의 기본 구조:**

```jsx
try {
  // 예외가 발생할 수 있는 코드
} catch (error) {
  // 예외를 처리하는 코드
} finally {
  // 항상 실행되는 코드 (선택적)
}
```

```jsx
* try 블록 안에는 예외가 발생할 수 있는 코드가 들어감

* catch 블록은 예외가 발생했을 때 실행되는 블록으로, 발생한 예외를 처리하는 코드가 들어감

* finally 블록은 예외 발생 여부에 상관없이 항상 실행되는 코드 블록 (선택적).
```

```jsx
try {
  // 예외가 발생할 수 있는 코드
  let result = 10 / 0 // Division by zero
  console.log(result) // 이 부분은 실행되지 않음
} catch (error) {
  // 예외를 처리하는 코드
  console.error('에러 발생:', error.message) // 에러 발생: Cannot divide by zero
} finally {
  // 항상 실행되는 코드
  console.log('finally 블록 실행')
}
```
