# MongoDB란?

```jsx
데이터 저장 구조:

MongoDB는 NoSQL 데이터베이스로, '컬렉션' ( collection ) 에 '문서' ( Document ) 를 저장한다.

SQL에 비유하면 '문서'는 '레코드'( 예를 들어 사용자 정보, 제품 정보 등과 같은 하나의 데이터 조각) ( 테이블의 한 행 )

에 해당하며, '컬렉션'은 '테이블'로 비유할 수 있다.

데이터 관리의 유연성:

MongoDB에서는 엄격한 데이터 스키마나 관계가 없어, 개발자가 직접 스키마를 지정하고 관계를 설정할 수 있다.

Node/Express와의 연동:

MongoDB는 Node/Express와 쉽게 연동되며, 백엔드와의 간편한 통합이 가능합니다.

프론트엔드에 직접 연결하지 않고, 백엔드를 통해 데이터를 다루는 구조로 설계됩니다.

다양한 데이터베이스 선택:

별도의 스키마와 관계 없이 MongoDB와 함께 다른 데이터베이스도 사용 가능합니다.

SQL 데이터베이스 등을 선택할 수 있어 프로젝트의 요구에 따라 적절한 데이터베이스를 선택할 수 있습니다.

```

# SQL vs NoSQL

```jsx
NoSQL vs SQL: 기본 개념

NoSQL 데이터베이스(CouchDB, MongoDB)는 특정 데이터 스키마를 요구하지 않음.

SQL 데이터베이스(MySQL, MS SQL)는 엄격한 스키마 규칙을 가짐.

NoSQL에서는 컬렉션과 문서를 사용하며, SQL에서는 테이블과 레코드를 사용함.

스키마 유연성의 차이

NoSQL에서는 문서의 스키마를 동적으로 변경 가능.

SQL에서는 특정 스키마를 생성하고, 변경이 어려움.

데이터베이스의 관계성

NoSQL은 관계를 상대적으로 덜 강조.

SQL은 테이블 간의 관계가 중요하며, 외래 키 등을 사용하여 연결.

NoSQL의 독립된 문서 작업

NoSQL에서는 독립된 문서로 작업하며, 문서 간의 관계가 적음.

SQL에서는 레코드가 서로 연관되어 있고, 관계가 핵심.

데이터베이스 선택 가이드라인

NoSQL은 주로 기록, 주문, 채팅 메시지와 같이 빈번한 정보 저장 및 조회에 적합.

SQL은 장바구니, 연락처, 대규모 소셜 네트워크 등에 적합.

어플리케이션의 특성에 따라 NoSQL과 SQL을 혼용할 수도 있음.

MERN 스택 및 MongoDB

MERN 스택은 여러 기술을 조합한 스택으로, MongoDB와 Mongoose를 사용하여 데이터 효율적으로 다룸.

MongoDB는 NoSQL 데이터베이스로, MERN 스택에서 프론트엔드와 연동하여 사용 가능.

```

# React를 데이터베이스에 연결하기?

```jsx
프론트엔드와 데이터베이스의 직접 연결: 안 좋은 아이디어

프론트엔드(React)와 데이터베이스를 직접 연결하는 것은 현명하지 않음.

데이터베이스에 직접 연결하면 강력한 인증이 불가능하며, 보안 상의 위험이 존재.

인증의 문제

프론트엔드에서 직접 데이터베이스에 연결하면 자격 증명이 누구나 접근 가능한 코드에 노출됨.

브라우저에서 실행되는 프론트엔드 코드에 자격 증명을 포함시키면 보안이 취약해짐.

자격 증명이 노출되면 데이터베이스 액세스가 가능하며, 데이터베이스의 악용 가능성 증가.

프론트엔드와 백엔드의 중간 계층 필요

React 프론트엔드를 Node/Express 백엔드에 연결하여 사용.

백엔드에서 프론트엔드로부터의 요청을 받고, 데이터베이스와의 통신을 담당.

React와 Node/Express 연결의 장점

React가 백엔드에 요청을 보내고, 백엔드가 정보를 처리하며 데이터베이스와 연동.

보안 유지 및 자격 증명 노출 방지로 안전한 데이터베이스 액세스 가능.

Node/Express와 MongoDB 연결

본 강의에서는 Node/Express를 사용하여 MongoDB에 연결하는 방법을 다룸.

MERN 애플리케이션에서도 React와 MongoDB를 직접 연결하지 않고 백엔드를 통해 연동.

왜 React 앱에 직접 연결하지 않고 백엔드에 연결하는가?

보안 유지와 자격 증명 보호를 위해 프론트엔드와 데이터베이스 간 직접 연결은 피해야 함.

백엔드를 중간 계층으로 사용하여 안전한 데이터베이스 액세스 구현 가능.
```

## 아틀라스란?

```jsx
**개요**:

MongoDB Atlas는 MongoDB의 공식 클라우드 서비스로, 관리형 클라우드 데이터베이스 플랫폼을 제공함.

사용자가 MongoDB를 쉽게 설정, 관리하고, 확장할 수 있도록 하는 클라우드 기반 서비스.

**특징 및 장점**:

자동 확장: 데이터베이스 요구사항에 따라 자동으로 확장되어 성능을 최적화.

보안 및 규정 준수: Atlas는 데이터 암호화, 네트워크 보안 및 규정 준수를 강조하여 안전한 환경 제공.

관리 편의성: 클라우드에서 MongoDB를 쉽게 관리하며, 백업, 모니터링, 스케일링 등을 제공.

**클러스터 및 지역**:

클러스터: MongoDB Atlas에서는 여러 노드로 구성된 클러스터를 생성하여 데이터베이스를 운영.

( 무료 버전에서는 사용 불가능 )

지역 선택: 사용자는 클라우드 공급자 및 지역을 선택하여 데이터를 저장할 위치를 지정할 수 있음.

**백업 및 복원**:

자동 백업: MongoDB Atlas는 자동으로 정기적인 백업을 수행하며, 사용자는 설정을 통해 주기를 조정할 수 있음.

복원 옵션: 실수로 삭제한 데이터를 복원하거나 특정 시점으로 복구할 수 있는 다양한 복원 옵션 제공.

**클라우드 통합**:

AWS, Azure, GCP: MongoDB Atlas는 Amazon Web Services (AWS),

Microsoft Azure, Google Cloud Platform (GCP)와 통합되어 다양한 클라우드 환경에서 이용 가능.

**확장성 및 유연성**:

수직 및 수평 확장: 클러스터 크기를 동적으로 조정하여 수직 및 수평 확장이 가능.

다양한 인스턴스 유형: 필요에 따라 다양한 인스턴스 유형을 선택하여 데이터베이스 성능을 최적화할 수 있음.

**서버리스 특성**:

Atlas 서버리스 티어: MongoDB Atlas에서는 특정 티어에서 서버리스 서비스를 제공하여 서버 운영과 유지보수의 부담을 줄일 수 있음.

**종합적인 관리 대시보드**:

웹 대시보드: MongoDB Atlas는 웹 대시보드를 통해 클러스터 상태, 성능 메트릭, 로그, 백업 정보 등을 통합적으로 관리 가능.

**유연한 가격 정책**:

티어 및 요금제: 다양한 티어와 유연한 요금제를 제공하여 사용자의 예산 및 요구에 맞게 선택할 수 있음.
```

```jsx
  'mongodb+srv://dhk9309:kim1458@cluster0.ckluwao.mongodb.net/products_test?retryWrites=true&w=majority'

// 상품을 생성하는 함수입니다.
const createProduct = async (req, res, next) => {
  // HTTP 요청에서 받은 데이터를 새 상품 객체로 만듭니다.
  const newProduct = {
    name: req.body.name,
    price: req.body.price,
  }

  // MongoDB 클라이언트 객체를 생성합니다.
  const client = new MongoClient(url)

  try {
    // MongoDB에 연결합니다.
    await client.connect()

    // 연결된 데이터베이스 객체를 가져오고 'products' 컬렉션에 새 상품을 추가합니다.

    client.close()

  res.json(newProduct)
}
```

```jsx
  res.json(newProduct)

const getProducts = async (req, res, next) => {
  // MongoDB 클라이언트 객체를 생성합니다.
  const client = new MongoClient(url)

  let products
  try {
    // MongoDB에 연결합니다.
    await client.connect()

    // 연결된 데이터베이스 객체를 가져오고 'products' 컬렉션에서 모든 상품을 조회합니다.
    const db = client.db()
    products = await db.collection('products').find().toArray()
  } catch (error) {
    // 오류가 발생하면 오류 메시지를 응답으로 전송합니다.
    return res.json({ message: '조회 실패' })

    // 연결을 항상 닫도록 finally 블록에서 처리합니다.

  // 조회된 상품 목록을 응답으로 전송합니다.
  res.json(products)
```

```jsx
1. MongoDB와 Mongoose 소개:

MongoDB는 데이터베이스와 상호작용하기 위해 공식 MongoDB 드라이버를 사용하고 있다.

그러나 번거로운 부분이 있어서 더 좋은 솔루션으로 Mongoose를 사용 가능하다

Mongoose는 공식 MongoDB 드라이버 기반의 서드 파티 라이브러리이며, MongoDB와의 상호작용을 간편하게 만들어준다.

2. Mongoose의 특징 및 장점:

Mongoose는 스키마를 사용하여 데이터베이스에 저장하려는 문서의 구조를 정의할 수 있다.

정형 데이터가 필요한 경우, 스키마를 사용하면 데이터 저장 및 페치(fetch)가 간편해진다.

비정형 데이터가 프로젝트에 있을 경우에는 Mongoose가 최선은 아닐 수 있다

* ( 정형 데이터는 구조가 고정되어 있고, 비정형 데이터는 유연하게 구조가 변할 수 있는 데이터 )

3. Mongoose 설치:

Mongoose를 설치하기 위해 npm install mongoose 명령어를 사용한다.
```

# 모델 및 스키마 이해하기

```jsx
// Mongoose 모듈을 불러옵니다.
const mongoose = require('mongoose')

// Product 스키마를 정의합니다.
const productSchema = new mongoose.Schema({
  // 상품의 이름을 나타내는 속성입니다.
  name: {
    type: String, // 데이터 형식은 문자열(String)입니다.
    required: true, // 필수 항목으로 지정되어 있습니다.
  },
  // 상품의 가격을 나타내는 속성입니다.
  price: {
    type: Number, // 데이터 형식은 숫자(Number)입니다.
    required: true, // 필수 항목으로 지정되어 있습니다.
  },
})

// 'Product' 모델을 생성하고, 해당 모델을 'productSchema' 스키마와 연결합니다.
mongoose.model('Product', productSchema)

// 'Product' 모델을 외부에서 사용할 수 있도록 내보냅니다.
module.exports = mongoose.model('Product', productSchema)
```

```jsx
const mongoose = require('mongoose');:

Mongoose 모듈을 불러온다.

const productSchema = new mongoose.Schema({ ... });:

Mongoose의 Schema 클래스를 사용하여 상품의 스키마를 정의한다.

스키마는 데이터베이스에 저장할 문서의 구조를 정의하는 역할을 한다.

name: { type: String, required: true }:

상품 스키마에는 'name' 속성이 정의되어 있다.

이 속성은 문자열 형식이며 필수(required)로 지정되어 있다.

price: { type: Number, required: true }:

상품 스키마에는 'price' 속성이 정의되어 있다.

이 속성은 숫자(Number) 형식이며 필수(required)로 지정되어 있다.

mongoose.model('Product', productSchema);:

'Product'라는 이름의 Mongoose 모델을 생성하고, 해당 모델을 'productSchema' 스키마와 연결한다.

이를 통해 'Product' 모델은 'productSchema' 스키마에 정의된 구조를 따르게 된다.

module.exports = mongoose.model('Product', productSchema);:

'Product' 모델을 외부에서 사용할 수 있도록 내보낸다.

모델 (Model) 이란? :

모델은 데이터베이스에서 사용되는 문서의 구조를 정의하고,

해당 데이터에 접근하고 조작할 수 있는 인터페이스를 의미한다.

Mongoose에서 모델은 스키마에 기반하여 실제 데이터베이스에 저장되는 문서를 나타낸다.

모델은 데이터베이스와의 효율적인 상호작용을 도와주며, 개발자에게 데이터를 조작할 수 있는 강력한 도구를 제공한다.
```

# 모델 및 스키마 이해하기

```jsx
// mongoose 라이브러리 불러오기
const mongoose = require('mongoose')

// models 폴더의 product 파일에서 Product 모델 불러오기
const Product = require('./models/product')

// 상품 생성 로직 정의
const createProduct = async (req, res, next) => {
  // 요청 본문에서 name과 price 프로퍼티 추출
  const { name, price } = req.body

  // Product 모델을 기반으로 새로운 상품 객체 생성
  const newProduct = new Product({
    name: name,
    price: price,
  })

  // 새로운 상품 객체를 데이터베이스에 저장 (비동기식 작업)
  try {
    await newProduct.save()

    // 성공적으로 상품이 생성되었을 때 응답
    res.status(201).json({ message: 'Product created successfully', product: newProduct })
  } catch (error) {
    // 데이터베이스 저장 중 에러 발생 시 다음 미들웨어로 전달
    next(error)
  }
}

// createProduct 함수를 외부에서 사용할 수 있도록 내보내기
exports.createProduct = createProduct
```

```jsx
mongoose 라이브러리와 Product 모델을 불러온다.

createProduct 함수를 정의하고, 이 함수는 비동기식으로 동작한다.

요청 본문에서 name과 price 프로퍼티를 추출한다.

Product 모델을 기반으로 요청 받은 데이터를 사용하여 새로운 상품 객체를 생성한다.

newProduct.save()를 사용하여 새로운 상품 객체를 데이터베이스에 저장한다 (비동기식 작업).

데이터베이스 저장이 성공하면 201 상태 코드와 함께 성공 메시지와 생성된 상품 정보를 응답한다.

데이터베이스 저장 중 에러가 발생하면 next(error)를 통해 다음 미들웨어로 에러를 전달한다.

createProduct 함수를 외부에서 사용할 수 있도록 exports.createProduct = createProduct;를 추가한다.
```

### .exec()

```jsx

사용 예시에서 어떤 때에는 exec()을 사용하고, 어떤 때에는 exec()을 사용하고 있지 않다.

exec()을 사용하고 안 하고가 어떤 차이가 있는 것일까?

공식 문서를 보면 find, findOne, findById, findOneAndUpdate 등의 메서드의 리턴값은 Query라고 되어 있다.

Mongoose Query는 프로미스가 아니고, then을 사용할 수 있는 일종의 유사 프로미스라고 할 수 있다.



find, findOne 등의 메서드 뒤에 exec()을 붙이든 안 붙이든 기능은 동일하다.

대신 exec()을 사용하면 유사 프로미스가 아닌 온전한 프로미스를 반환값으로 얻을 수 있으며,

에러가 났을 때 stack trace에 오류가 발생한 코드의 위치가 포함되기 때문에 공식 문서에서도 exec()을 사용할 것을 권장하고 있다.
```

# ObjectID 이해하기

```jsx
Mongoose에서는 MongoDB 문서의 각각에 대해 고유한 식별자로 사용되는 ID가 있다.

이 ID는 MongoDB가 자동으로 생성하며, 일반적으로 _id라는 이름으로 알려져 있다.

이 ID는 ObjectId라는 특별한 객체 타입으로 표현되며, 자바스크립트에서 직접 이 객체를 조작할 수는 없다.

Mongoose를 사용하여 MongoDB에 문서를 저장할 때, 이 ID는 자동으로 생성되고 문서에 추가된다.

예를 들어, 아래와 같은 Product 모델이 있다고 가정한다.
```

```jsx
const banana = new Product({
  name: 'Banana',
  price: 1.5,
})

banana
  .save()
  .then((createdProduct) => {
    console.log('Created Product:', createdProduct)
    console.log('Product ID:', createdProduct._id)
  })
  .catch((error) => {
    console.error('Error creating product:', error)
  })
```

```jsx
새로운 상품을 생성하고 MongoDB에 저장하면, 해당 상품 문서에는 자동으로 생성된 _id가 추가된다.

getter (._id) 를 사용하여 ID를 문자열로 변환하는 방법을 보여준다

( ._id 는 문자열이 아닌 일종의 객체이다 몽구스만의 )
```
