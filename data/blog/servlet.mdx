# **Servlet**

## **Servlet 개념**

```html
서블릿은 웹 서버에서 가동되는 자바 기반 프로그램이며, HTTP 기반 통신에서 client와 server 사이의
request와 response를 다루기 위해 설계됨
```

```html
서블릿은 client의 request에 기반한 동적인(동적인 웹 페이지나 데이터는 매번 다른 내용을 가질 수
있으며, 서버 측에서 동적으로 생성된다) HTML 페이지나, json, xml 형태의 데이터들을 만들기 위해
사용되며, 이 뿐만 아니라 cookie, session 등을 다뤄 stateless한(이전 요청과 현재 요청 간에 상태
정보를 유지하지 않는다 각각 요청에 독립적) HTTP 통신에서 상태 정보를 다룰 수 있도록 돕는다.
```

```html
**쉬운 설명** 서블릿은 웹 서버에서 동적인 웹 페이지나 데이터를 만들어주는 특별한 프로그램이에요. 이
프로그램은 사용자의 요청에 따라 매번 다른 내용을 생성할 수 있어요. 예를 들면, 사용자가 웹 브라우저를
통해 웹 페이지를 요청하면, 서블릿이 그 요청을 받아서 웹 페이지를 만들어줍니다. 서블릿은 다양한
종류의 데이터를 만들 수 있어요. 가장 흔하게는 HTML 페이지를 생성하지만, JSON 또는 XML 형식의
데이터도 만들 수 있어요. 이 데이터를 웹 브라우저로 전송해서 사용자에게 보여줍니다. 또한, 서블릿은
HTTP 통신에서 상태 정보를 다루는 데 도움을 줍니다. HTTP는 웹에서 데이터를 주고받는 프로토콜인데,
기본적으로 상태 정보를 유지하지 않습니다. 서블릿은 이것을 처리하기 위해 쿠키와 세션 같은 기술을
사용해 이전 요청과 현재 요청 사이의 상태 정보를 저장하고 관리할 수 있게 도와줍니다. 요약하면,
서블릿은 동적인 웹 페이지와 데이터를 만들고, HTTP 통신에서 상태 정보를 다루는 데 사용되는 도구라고
할 수 있어요. 이를 통해 웹 애플리케이션을 만들고 사용자와 상호작용할 수 있게 됩니다.
```

## Servlet 의 담당

```html
위 그림을 보면, HTTP 통신에 따라 client - server간에 request를 보내고 response를 받아오는 과정에서
진행해야할 작업이 굉장히 많음을 파악할 수 있다. 여기서 핵심적인 **비즈니스 로직 구현을 제외한 다른
부분을 Servlet이 담당** 함으로써, 웹 애플리케이션 개발에만 집중할 수 있도록 지원한다. 정확하게는
나머지 작업들은 서블릿을 지원하는 WAS(Web Application Server)가 담당한다. (ex. Tomcat)
```

## WAS

```html
WAS (Web Application Server)를 간단하게 정리하자면, 기존의 정적인 resources 제공의 역할만 담당하는
web server에 프로그램 코드를 실행할 수 있는 기능이 가미되어, 사용자 요청에 따라 동적인 resources를
제공할 수 있는 서버를 의미 한다고 볼 수 있다.
```

## 요약

```html
서블릿을 요약 1. 자바 웹 애플리케이션 프로그램을 만들기 위해 사용하는 자바 기반의 기술이다. 2. HTTP
기반 통신에서 비즈니스 로직을 제외한 반복적인 작업을 편리하게 처리해준다. 3. 즉, request, response를
처리하는 중간 과정에 대한 처리를 도맡아 해준다고 볼 수 있다
```

# **Servlet Container (서블릿 컨테이너)**

```html
WAS 안에서 서블릿을 어떻게 다루는지 그림과 함께 일련의 과정을 살펴본다
```

![Untitled](<Servlet%20(%EC%84%9C%EB%B8%94%EB%A6%BF)%20%EC%9D%B4%EB%9E%80/Untitled%201.png>)

```html
1. Client가 WAS에게 Request를 보내면, WAS는 Servlet container라는 것을 운영하면서, 요청에 알맞은
servlet를 찾아 Request에 따른 Response를 만들어낸다. 2. 이렇게 만들어낸 Response는 WAS에 의해
만들어진 Response 객체를 이용한 것이며, client가 해당 Response를 전달받게 되는 방식으로 HTTP 기반
통신이 이루어진다. 다시 서블릿 컨테이너를 설명해 보자면, WAS안에 위치하여 서블릿의 생명주기를
관리하고, client의 request에 따른 서블릿을 선택하고, 그에 따른 response를 client에게 전달하는 과정을
담당한다. 그러니깐 개발자가 서블릿을 코드로 짜는 작업만 진행하면, WAS의 서블릿 컨테이너가 client -
server 간의 일련의 통신 과정을 담당한다고 볼 수 있다.
```
