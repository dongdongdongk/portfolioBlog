## 🔘 Sphere Collision Component 추가

### 왜 필요한가?

```
현재:
  Sphere_Mesh만 존재
  ↓
  메시는 시각적 표현용
  ↓
  Overlap 감지 전용 컴포넌트 필요

해결:
  Sphere Collision 추가
  ↓
  Overlap 전용으로 사용
```

### Mesh vs Collision Component

**Mesh (메시)**

```
용도: 보이는 것
역할: 시각적 표현
충돌: 설정 가능하지만 복잡
```

**Collision Component**

```
용도: 충돌/겹침 감지
역할: 보이지 않는 판정 영역
충돌: 이것만의 목적
```

## 🏗️ Component 구조 재구성

### 문제 상황

**초기 구조**

```
Sphere_Mesh (Root)
  └─ Sphere Collision 추가 시도
```

**문제**

```
Sphere_Mesh를 Scale 조정 (Timeline)
  ↓
자식인 Sphere Collision도 함께 Scale
  ↓
Collision 크기 변함 (원하지 않음!)
```

**비유**

```
부모가 몸 키우면
  ↓
자식도 따라서 커짐
  ↓
자식은 그대로 크기 유지하고 싶은데!
```

### 해결: Scene Root 추가

**최종 구조**

```
Scene Root (새로 추가)
  ├─ Sphere_Mesh
  └─ Sphere Collision
```

### 구현 단계

### 1. Scene Component 추가

```
Components 패널
  ↓
Add Component
  ↓
Scene (검색)
  ↓
Scene Component
  ↓
이름: Scene Root
```

### 2. Sphere Collision 추가

```
Scene Root 선택
  ↓
Add Component
  ↓
Sphere Collision (검색)
  ↓
이름: Sphere Volume
```

**주의: Sphere 아님!**

```
❌ Sphere (Static Mesh)
  → "No mesh" 툴팁
  → 메시용

✓ Sphere Collision
  → 충돌/겹침 전용
```

### 3. Sphere_Mesh 재배치

```
Sphere_Mesh를 Scene Root로 드래그
  ↓
"Attach to Scene Root?" 선택
  ↓
계층 구조 변경
```

**최종 계층**

```
Scene Root
  ├─ Sphere_Mesh (Scale 변화 O)
  └─ Sphere Volume (Scale 변화 X)
```

### 4. Scene Root를 Root로 설정

```
Scene Root를 DefaultSceneRoot로 드래그
  ↓
"Set as new root?" → Yes
```

## 📡 Overlap Event 구현

### Delegate란?

**간단히**

```
Delegate = 이벤트 알림 시스템

예:
  구체가 겹침
    ↓
  Delegate가 "겹쳤어!" 브로드캐스트
    ↓
  등록된 Event들 실행
```

### Event 등록 방법 3가지

### 1. Assign (자동 생성)

```
Sphere Volume 드래그
  ↓
"On Component Begin Overlap" 검색
  ↓
Assign 선택
  ↓
자동으로 Custom Event 생성
```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380703/notion-blog/_/_/_5_/_-_-_7/image_4.png)

**결과**

```
1. Bind 노드 (파란색)
2. OnComponentBeginOverlap_Event (빨간색)
   자동 생성됨
```

### 2. Bind (수동 연결)

```
Sphere Volume 드래그
  ↓
"On Component Begin Overlap" 검색
  ↓
Bind 선택
  ↓
파란색 Bind 노드만 생성
  ↓
Custom Event는 직접 만들어서 연결

```

**단점**

```
Custom Event를
  ├─ 같은 파라미터로
  └─ 직접 만들어야 함
  ↓
번거로움
```

### 3. 기타

```
Unbind Event: 연결 해제
Unbind All Events: 전부 해제
```

### Assign 사용 (권장)

```
Event Begin Play
  ↓
Bind (파란색 노드)
  └─ On Component Begin Overlap

OnComponentBeginOverlap_Event
  ↓
[여기서 처리]
```

**왜 Begin Play에서 Bind?**

```
게임 시작 시 1회 등록
  ↓
이후 Overlap 발생하면
  ↓
자동으로 Event 실행

# Is A vs Cast to - 차이점 정리 \* 추가

난 다른 노드를 사용했다 cast 가 아니라 Is A

## 🔍 두 노드 비교

### Cast to Pawn

```
입력: Object (Actor)
  ↓
출력 1: Success/Failure 핀 (실행)
출력 2: As Pawn (변환된 Pawn 참조)

특징:
  ├─ 타입 확인 + 변환
  ├─ 실행 핀 있음 (흰색)
  └─ 변환된 객체 사용 가능
```

### Is A

```
입력: Object (Actor)
  ↓
출력: Boolean (True/False)

특징:
  ├─ 타입 확인만
  ├─ 실행 핀 없음 (Pure Function)
  └─ True/False만 반환
```

---

## 🎯 언제 뭘 쓰나?

### Is A 사용 (당신이 쓴 것)

```
OnComponentBeginOverlap_Event
  ↓
Is A (Pawn)
  ├─ Object: Other Actor
  └─ Return: Boolean
  ↓
Branch
  ├─ Condition: Is A 결과
  ├─ True → Wink Out
  └─ False → 무시
```

**장점:**

- 간단하고 직관적
- Pawn 참조 필요 없을 때 완벽
- Pure Function (어디서든 사용)

### Cast to Pawn 사용 (강의 방법)

```
OnComponentBeginOverlap_Event
  ↓
Cast to Pawn
  ├─ Object: Other Actor
  ├─ Success → Wink Out
  └─ Failure → (무시)
```

**장점:**

- 실행 핀으로 바로 분기
- Branch 노드 불필요
- 변환된 Pawn 참조 사용 가능

---

## 💡 핵심 차이

```
Is A = "Pawn이야?"
  → Yes/No 대답만
  → Branch 필요

Cast = "Pawn이면 이거 해"
  → Success/Failure로 바로 분기
  → Branch 불필요
```

---

## ✅ 결론

**당신의 방법 (Is A + Branch):**

```
Is A → Branch → Wink Out
정확히 작동함! ✓
```

**강의 방법 (Cast to):**

```
Cast to Pawn → Success → Wink Out
조금 더 간결함
```

**둘 다 정답!** 현재 상황에서는 결과가 같습니다. 나중에 Pawn의 함수를 호출하거나 변수에 접근해야 할 때는 Cast가 필수지만, 지금처럼 타입만 확인하면 되는 경우는 **Is A가 오히려 더 깔끔**합니다!

### 3. Wink Out 호출

```
OnComponentBeginOverlap_Event
  ↓
Cast to Pawn
  ├─ Object: Other Actor
  └─ Success → Call Wink Out
```

**현재까지 흐름**

```
플레이어가 구체에 닿음
  ↓
Overlap Event 발생
  ↓
Cast to Pawn 성공
  ↓
Wink Out 호출
  ↓
구체 축소 시작
```

## 🚫 중복 실행 방지

### 문제 상황

```
경우 1: Lifetime 끝남
  → Wink Out 호출

경우 2: 플레이어 충돌
  → Wink Out 호출

만약 동시에?
  → Wink Out이 2번 실행
  → Timeline이 2번 시작
  → 불안정한 애니메이션
```

### 해결: Winking 플래그

### 1. 변수 생성

```
Variables 패널
  ↓
+ 버튼
  ↓
이름: Winking
  ├─ Type: Boolean
  ├─ Default: False
  └─ Private (체크 안 함)
```

**의미**

```
Winking = False: 아직 안 사라짐
Winking = True: 이미 사라지는 중
```

### 2. 로직 구현

```
Wink Out (Event)
  ↓
Branch
  ├─ Condition: Winking (Get)
  │
  ├─ True → 아무것도 안 함 (이미 실행 중)
  │
  └─ False
      ↓
      Set Winking = True
      ↓
      Wink Out Timeline → Play
```

### 작동 원리

**첫 번째 호출**

```
Winking = False (초기값)
  ↓
Branch False 실행
  ↓
Winking = True 설정
  ↓
Timeline 시작
```

**두 번째 호출 (중복)**

```
Winking = True (이미 설정됨)
  ↓
Branch True 실행
  ↓
아무것도 안 함
  ↓
Timeline 중복 시작 방지 ✓
```

### 시각화

```
Timeline 진행 중
  ├─ Winking = True
  ├─ 다시 Wink Out 호출해도
  └─ Branch에서 막힘
  ↓
안전!
```

## 💡 핵심 개념 정리

### Collision vs Overlap

```
Collision (충돌):
  Block - 막음
  예: 벽, 바닥

Overlap (겹침):
  Ignore - 통과 가능
  but Event 생성
  예: 아이템, 트리거
```

```

자식 Collision도 커짐 (문제!)

해결:
  공통 부모 (Scene Root) 생성
  ↓
  Mesh, Collision 분리
```

### Cast의 역할

```
Actor가 특정 타입인지 확인
  ↓
맞으면 Success
틀리면 Failure
  ↓
타입 안전성 보장
```

### 플래그 변수 패턴

```
Boolean 플래그로
  ├─ 상태 추적
  └─ 중복 실행 방지
  ↓
일회성 이벤트에 유용
```

### 왜 필요한가?

```

  ↓
  정확하지 않음
