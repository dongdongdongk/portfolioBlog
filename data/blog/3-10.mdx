## 스프링 프로젝트의 구조

```sql
Project 구성
	1) src/main/java      : java의 class 파일들이 있는곳
	2) src/main/resources : Back-end에서 java이외의 자원들
	3) src/test/java      : java Test 파일
	4) src/test/resources : java Test시에 필요한 java 이외의 자원들

	5) src/main/webapp/resources      : css, js, image 등 저장
	6) src/main/webapp/WEB-INF/spring : Spring Framework 설정 파일들
	7) src/main/webapp/WEB-INF/views  : jsp 파일들

	8) pom.xml             : maven 설정파일=버전관리, 라이브러리, 배포관리

	9) target              : 개발이 끝나고 배포파일을 생성하면 target 폴더에 저장

*위의 src 폴더에서 오류가 발생하면 아래쪽 src에도 오류표시가 생김
```

## DI(Dependency Injection , 의존성 주입)

```sql
**객체의 생명주기(만들어지고 소멸) 이것을 관리 하는걸 Container 라고 부름**

Tomcat Container : 내장 객체 관리

Spring Container : java 객체 관리

*Spring 에서는 객체를 직접 생성하지 않고 **Spring Container 에게 맡긴다.(IOC)**

*Spring Container 은 객체를 생성하고 **bean pool 에 저장한다.**

*객체는 **Singletone으로 생성한다.**(어플리케이션 전체에 하나만 생성)
```

```sql
**멤버 변수에 값을 대입하는 방법(DI, 의존성 주입)**

1.생성자

2.초기화 블럭

3.직접 대입

4.Setter

5.객체를 생성하고 참조변수명 or 멤버변수명 = 값
```

```sql
**IOC(Inversion of Control, 제어의 역전)**

-java 개발자가 직접 객체를 생성하고 직업 DI 작업을 진행하지 않고 Spring 에게 객체 생성과

주입을 위임하는것 (핵심개념)
```

# 객체 위임

```java
Annotation
	- 실행 + 설명
	- servlet-context.xml에 선언된 scan package 범위 안에 있어야 인식 함

      **객체 생성** (new 생성자()) 대신
			- 클래스 선언부 위에 작성
			**a. @Controller("이름")**     : 객체 생성, Controller 역할
			**b. @Service("이름")**        : 객체 생성, Service 역할
			**c. @Repository("이름")**     : 객체 생성, DAO 역할
			**d. @Component("이름")**      : 객체 생성, Controller, Service, DAO가 아니 그외 나머지

	- 객체(Bean)의 이름을 지정 할 수 있음(참조변수와 비슷)
	- 이름을 지정하지 않으면 클래스명의 첫글자를 소문자로 만든것이 이름으로 자동지정

		**객체 주입**
		- Setter(메서드) 선언부 위에
		- 생성자 (매개변수가 있는 생성자)선언부 위에
		- 멤버변수 선언부 위에

		**@Autowired**
		1. pool(객체를 만들어 저장하는곳)에서 Data Type이 일치하는 객체를 검색
		2. 같은 Type이 여러개 있으면 bean name(변수명)으로 검색
			@AutoWired
			@Qualifier("대입할 bean의 이름")

		@Resource
		1. Bean name으로 검색
		2. Name이 없으면 Data type으로 검색
```

## @Autowired

```java
@Autowired는 스프링 프레임워크에서 제공하는 의존성 주입(Dependency Injection) 기능 중 하나이다

의존성 주입이란,

객체 간의 의존 관계를 런타임 시에 스프링 컨테이너가 자동으로 연결해주는 것을 말한다.

예를 들어, 객체 A가 객체 B를 사용하는 경우,

A 객체가 직접 B 객체를 생성하거나 참조하는 것이 아니라,

스프링 컨테이너가 B 객체를 생성하고 A 객체에 주입해준다.

이렇게 하면 객체 간의 결합도가 낮아져서 코드의 유지보수성이 좋아지고,

 코드의 재사용성도 높아진다.

@Autowired 어노테이션은 자동으로 의존성 주입을 수행하는 역할을 한다.

스프링 컨테이너에서 해당 타입의 빈을 찾아서 자동으로 멤버 변수에 할당해준다.

@Autowired 어노테이션은 생성자, 메소드, 멤버 변수에 적용할 수 있다.

위 코드에서 @Autowired 어노테이션은 MemberService 타입의 빈을 찾아서

memberService 멤버 변수에 자동으로 할당해준다.

이렇게 하면 MemberController 객체가 생성될 때 스프링 컨테이너에서

MemberService 객체를 찾아서 자동으로 주입해준다.
```

## 메서드 리턴 타입

```java
메서드의 리턴 타입
	- Controller의 return은 Spring Container가 ModelAndView라는 객체로 바꿔서 리턴

	1) String
		- view(jsp)의 경로명
		- ex) return "dept/insert"
					- Spring Container가 내부에서 다음작업을 진행하고 return
					ModelAndView mv = new ModelAndView();
					mv.setViewName("dept/insert")

	2) void
		- 요청한 URI주소와 View(jsp)의 경로명이 일치 할 경우
		- 요청한 URI주소가 View(jsp)의 경로명이 됨

	3) ModelAndView
		- Model + view
		- View : jsp의 경로명을 담고 있는 객체

7. @ModelAttribute
	 1) 작성위치 : 멤버메서드 선언부

	 2) Controller의 모든 메서드에 공통 Data들을 model에 담으려 할 때 사용

	 3)
			@ModelAttribute("속성명")
			public 리턴타입 메서드명(){
				return 속성값
			}
			=> model.addAttribute("변수이름", 변수에 넣을 데이터 값)
		 ex) model.addAttribute("id", "hongku");
```
