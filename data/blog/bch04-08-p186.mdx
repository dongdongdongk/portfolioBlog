# 컨트롤러와 화면 처리

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381213/notion-blog/_/_/_/_/BCh04_08_p186_/Untitled.png)

```java
package org.zerock.guestbook.controller;

@Controller
@RequestMapping("/guestbook")
@Log4j2
@RequiredArgsConstructor
public class GuestbookController {

    private final GuestbookService service;

    @GetMapping("/list")
    public void list(@ModelAttribute PageRequestDTO pageRequestDTO, Model model) {
        log.info("list..........." + pageRequestDTO);
				// 실제 "result" 에 있는건 PageResultDTO
        model.addAttribute("result", service.getList(pageRequestDTO));
    }
}
```

```java
list 페이지로 가기 위해서 컨트롤러를 수정 해준다

* 서비스를 주입 받을 수 있도록 @RequiredArgsConstructor ,  private final GuestbookService service; 를 작성해주고

* 현재 파라미터로 받는 pageRequestDTO 에 페이지 번호, 페이지 사이즈 등등 정보를 담고있다 (화면에서 넘어온)

* model.addAttribute("result", service.getList(pageRequestDTO)); 여기서 실제로 "result" 에 추가되는건 PageResultDTO 이다 (변환해서 돌아오기 때문에)

	(목록 데이터도 다 DTO 로 바껴있고 페이지 번호도 다 들어가 있다)

* @ModelAttribute 자동으로 pageRequestDTO 를 model 에 추가해주지만 @RequestParam 과 혼동 등을 피하기 위해서 그냥 작성해주자 (속성이 적으면 생략)
```

```java
<!--페이저-->
        <ul class="pagination h-100 justify-content-center align-items-center">
            <li class="page-item" th:if="${result.prev}">
                <a class="page-link" th:href="@{/guestbook/list(page = ${result.start - 1})}" tabindex="-1">Previous</a>
            </li>
            <li th:class="'page-item' +' '+ ${result.page == page ? 'active':''}" th:each="page : ${result.pageList}">
                <a class="page-link" th:href="@{/guestbook/list(page = ${page})}">
                    [[${page}]]
                </a>
            </li>
            <li class="page-item" th:if="${result.next}">
                <a class="page-link" th:href="@{/guestbook/list(page = ${result.end + 1})}">Next</a>
            </li>
        </ul>
```

```java
페이저는 예를들어

/guestbook/list?page=5 같은 경우 5 페이지가 출력 되어야 한다

* <li class="page-item" th:if="${result.prev}"> 이 부분은 만약 result.prev 값이 있으면 표시 없으면 표시하지 않는다  (end 또한 마찬가지)

* <li th:class="'page-item' +' '+ ${result.page == page ? 'active':''}" 이 부분을 보면 현재 페이지(클릭한 페이지) 는 active 라는 클래스를 추가하여 파란색으로 불이 들어오게 한다
```

### active 못하는 오류

```java
위의 코드를 작성하기 전에는 <li th:class="'page-item' + ${result.page == page ? 'active ':''}" 이렇게 작성했었다

이렇게 하니 page-item 뒤에 바짝 붙어나와 page-itemactive 이렇게 나와서 현재 페이지에 파란불이 들어와야 하는데 들어오지 않았다

<li th:class="'page-item' +' '+ ${result.page == page ? 'active':''} 그래서 중간에 공백 하나를 넣어줬더니 실행 되었다 ( + ' ' +)
```

## 리다이렉트 이후 등록번호 출력 모달 추가

```java
컨트롤러에서 RedirectAttributes 객체를 이용해서 리다이렉트 한 페이지에서 값을 출력한다

* RedirectAttributes 객체의 addFlashAttribute() 메서드와 addAttribute() 메서드의 차이점은 다음과 같다

1) addFlashAttribute()

addFlashAttribute는 리다이렉션 후에 일회성으로만 사용 가능한 데이터를 전달할 때 쓴다.

이 데이터는 한 번만 읽을 수 있으며, 한 번 읽으면 자동으로 삭제 된다.

이 메서드를 사용하면 URL에 노출되지 않고, 세션을 통해 데이터가 전달된다.

redirectAttributes.addFlashAttribute("message", "일회성 데이터");

2) addAttribute()

addAttribute는 리다이렉션 후에도 여러 번 사용 가능한 데이터를 전달하는 데 사용된다.

데이터는 URL에 쿼리 매개변수로 노출되므로 보안에 유의해야 한다.

세션을 통해 데이터를 전달하지 않고, URL에 노출되므로 주로 적은 양의 간단한 데이터를 전달할 때 사용된다.

redirectAttributes.addAttribute("key", "값");
```
