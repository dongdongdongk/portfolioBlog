# 🔍 Supabase란?

```jsx
Supabase는 클라우드에서 제공되는 PostgreSQL 데이터베이스입니다.

PostgreSQL은 강력한 데이터베이스 시스템으로, 데이터를 체계적으로 저장하고 관리합니다.

장점:

		무료 플랜이 있어 비용 걱정 없이 시작 가능.

		설정이 간단하고, 실시간 데이터 업데이트 기능 제공.

		Next.js 같은 프론트엔드 프레임워크와 쉽게 연결 가능.

용도: 심리 테스트 데이터, 사용자 정보, 테스트 결과 등을 저장하고 관리.
```

# 📋 연결 방법 2가지

```jsx
Next.js와 Supabase를 연결하는 두 가지 방법이 있습니다.

이 가이드에서는 Prisma를 사용하는 방법을 주로 설명하고, Supabase JavaScript 클라이언트를 보조적으로 다룹니다.
```

## 1. Prisma를 통한 연결 (주로 서버에서 사용, 추천)

```jsx
Next.js → Prisma (데이터베이스 관리 도구) → Supabase PostgreSQL
```

```jsx
장점: 타입 안정성(TypeScript) 뛰어남, 데이터베이스 작업이 체계적.

단점: 설정이 약간 복잡, 실시간 기능은 없음.
```

## 2. Supabase JavaScript 클라이언트 (클라이언트와 서버 모두 사용):

```jsx
Next.js → Supabase JavaScript 클라이언트 → Supabase API
```

```jsx
장점: 설정이 더 쉬움, 실시간 데이터 업데이트 가능.

단점: 타입 안정성이 약간 부족, 보안 설정 주의 필요.
```

```jsx
이 가이드에서는 Prisma를 중심으로 설명하지만, Supabase 클라이언트 사용법도 간단히 다룹니다su.
```

# supabase 클라이언트(Client) 를 이용한 연결 & Prisma 를 이용한 연결

```jsx
클라이언트(Client)는 사용자의 브라우저에서 실행되는 코드로, 주로 화면을 보여주고 사용자 입력을 받아 Supabase 같은 외부 서비스에 데이터를 요청할 때 사용됩니다.

반면, Prisma는 서버에서만 실행되는 데이터베이스 접근 도구로, 직접 DB(PostgreSQL 등)에 연결해 데이터를 안전하게 읽고 쓰는 데 사용됩니다.

클라이언트는 로그인, 게시글 보기 등 비민감한 데이터 처리에 적합하고, Prisma는 회원정보 수정, 관리자 기능처럼 보안이 필요한 서버 로직에 적합합니다.

만약 Next.js에서 서버사이드 렌더링(SSR)을 한다면 Supabase로도 충분히 가능하며, 반드시 Prisma를 써야 하는 것은 아닙니다.
```

## 1. 클라이언트(Client)란?

```jsx
✨ 사용자 쪽 화면, 즉 브라우저에서 실행되는 코드

📱 예시:

우리가 웹사이트에 접속했을 때 보는 화면

버튼 클릭, 로그인, 게시글 보기 등 브라우저에서 일어나는 모든 것

👩‍💻 사용하는 이유:

사용자와 직접 소통 (화면을 보여주고, 입력을 받음)

Supabase에 데이터 요청 (예: 게시글 가져오기)

하지만 보안이 약해서 민감한 작업은 할 수 없음!

🔑 사용할 수 있는 도구:

NEXT_PUBLIC_SUPABASE_URL

NEXT_PUBLIC_SUPABASE_ANON_KEY

➡️ 이건 브라우저에서도 써도 되는 공개 키예요.
```

## 2. Prisma란?

```jsx
🔐 서버에서 사용하는 도구

데이터베이스(PostgreSQL)에 안전하게 접속해서 데이터를 관리하는 용도

📦 비유:

클라이언트가 “데이터 주세요!” 라고 말하면,

Prisma는 서버에서 직접 데이터베이스에 가서 꺼내주는 관리자예요.

📱 예시:

서버에서 주문 목록 가져오기

서버에서 유저 데이터 추가/삭제하기

민감한 비즈니스 로직 처리 (ex. 결제 후 상태 변경 등)

👨‍💻 사용하는 이유:

보안이 필요한 작업은 반드시 서버에서만 해야 돼요

Prisma는 그 서버 안에서 DB에 안전하게 연결하는 도구예요

🔑 필요한 정보:

DATABASE_URL (DB 비밀번호까지 포함)

절대 클라이언트에서는 쓰면 안 되는 정보
```

| 구분        | 클라이언트 (Client)         | Prisma                                  |
| ----------- | --------------------------- | --------------------------------------- |
| 위치        | 사용자 브라우저             | 서버 내부                               |
| 용도        | 화면 보여주기, 데이터 요청  | 데이터베이스 직접 관리                  |
| 보안        | 낮음 (공개 환경)            | 높음 (비공개 환경)                      |
| 예시        | 게시글 목록 보기, 로그인 폼 | 게시글 추가, 회원정보 수정              |
| Supabase 키 | `anon key` 사용             | `service role` 또는 `DATABASE_URL` 사용 |

## 최종 예시 `.env` 파일

```jsx
# 브라우저에서도 사용할 Supabase 정보
NEXT_PUBLIC_SUPABASE_URL=https://abcd1234.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI...

# 서버 사이드에서만 사용할 관리자 키 (절대 노출 금지!)
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI...

# Prisma가 Supabase DB에 연결하기 위한 주소
DATABASE_URL="postgresql://postgres:your_db_password@db.abcd1234.supabase.co:5432/postgres"
```

### ① `NEXT_PUBLIC_SUPABASE_URL`

```jsx
내 Supabase 프로젝트의 주소 (URL)

Supabase에서 만든 나만의 서버 주소라고 보면 돼요.

클라이언트(브라우저)에서 Supabase에 접근할 때 이 주소를 사용해요.

🔍 어디서 찾나요?

Supabase 콘솔 접속

프로젝트 클릭 → Settings → API → Project URL 복사
```

### ② `NEXT_PUBLIC_SUPABASE_ANON_KEY`

```jsx
🔐 익명 사용자용 공개 키

클라이언트(브라우저)에서 Supabase에 접근할 수 있게 해줘요.

이 키는 로그인하지 않은 사람도 쓸 수 있는 키예요.

주로 읽기 작업 등에 사용돼요.

🔍 어디서 찾나요?

Supabase 콘솔 → Settings → API → Project API Keys → anon public

✅ NEXT_PUBLIC_으로 시작하는 건 Next.js가 브라우저에서도 접근할 수 있게 해주는 변수라는 뜻이에요!
```

### ③ `SUPABASE_SERVICE_ROLE_KEY`

```jsx
🚫 절대 브라우저에 노출하면 안 되는 관리자용 키

이건 Supabase 서버를 전체 통제할 수 있는 강력한 키예요.

예를 들어, 로그인 안 해도 데이터 다 지우는 요청을 보낼 수 있어요.

오직 서버 사이드 코드에서만 사용해야 해요.

🔍 어디서 찾나요?

Supabase 콘솔 → Settings → API → service_role 키 복사
```

## 예시 (Prisma용 DATABASE_URL)

### Direct Connection (가장 이상적)

```jsx
DATABASE_URL = 'postgresql://postgres:[PASSWORD]@db.ktudkjtqjhkmnxegjgqr.supabase.co:5432/postgres'
```

```jsx
IPv6 기반 (IPv4-only 환경에서 실패할 수 있음)

Vercel 등 일부 플랫폼에서 안 될 수 있음
```

### Session Pooler (IPv4도 지원)

```jsx
DATABASE_URL =
  'postgresql://postgres.ktudkjtqjhkmnxegjgqr:[PASSWORD]@aws-0-ap-northeast-2.pooler.supabase.com:5432/postgres'
```

```jsx
안정적이고 대부분 환경에서 잘 작동

Prisma에서 안정적으로 사용 가능
```

### Transaction Pooler (비추천)

```jsx
DATABASE_URL =
  'postgresql://postgres.ktudkjtqjhkmnxegjgqr:[PASSWORD]@aws-0-ap-northeast-2.pooler.supabase.com:6543/postgres'
```

```jsx
Prisma에서 작동 안 됨

Supabase JS 클라이언트는 가능
```

| 사용 환경                                                              | 추천 연결 방식                            | 이유                                           |
| ---------------------------------------------------------------------- | ----------------------------------------- | ---------------------------------------------- |
| **일반 서버(VM, Vercel edge functions X)**                             | ✅ Direct Connection                      | 가장 빠르고 안정적                             |
| **IPv4-only 환경**(Vercel, Netlify 등 서버리스 플랫폼 일부)            | ✅ Session Pooler                         | Direct가 안 될 수 있으니 IPv4 가능해야 함      |
| **서버리스 (짧은 실행, 연결 짧음)**예: Serverless 함수, Edge, Cron job | ⚠️ Transaction Pooler(단 Prisma는 미지원) | Prisma는 지원 안 함, Supabase client만 써야 함 |

## 5단계: Supabase 클라이언트 설정

```jsx
Supabase JavaScript 클라이언트를 사용하려면 클라이언트를 초기화해야 합니다.
```

### 1. src/lib 폴더를 만들고, 그 안에 supabase.ts 파일을 생성:

```jsx
mkdir -p src/lib
touch src/lib/supabase.ts
```

### 2. src/lib/supabase.ts에 다음 코드를 추가

```jsx
import { createClient } from '@supabase/supabase-js'

// 환경변수에서 URL과 Anon Key 가져오기
const supabaseUrl = process.env.NEXT_PUBLIC_SUPABASE_URL!
const supabaseAnonKey = process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!

// Supabase 클라이언트 생성
export const supabase = createClient(supabaseUrl, supabaseAnonKey)
```

```jsx
이 코드는 Supabase와 통신할 클라이언트를 설정합니다.
!는 TypeScript에게 변수가 반드시 존재한다고 알려주는 문법입니다.
```

## 6단계: Prisma 설정

```jsx
Prisma는 데이터베이스와 쉽게 작업할 수 있도록 도와주는 도구입니다.
```

### 1. Prisma 초기화:

```jsx
npx prisma init
```

```jsx
이 명령어는 prisma 폴더와 prisma/schema.prisma 파일을 생성합니다.

.env 파일에 DATABASE_URL이 이미 추가되어 있어야 합니다.
```

### 2. Prisma 스키마 설정: prisma/schema.prisma 파일을 열고 다음 내용으로 수정

```jsx
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model Test {
  id           String   @id @db.VarChar(50)
  title        String   @db.VarChar(255)
  description  String?  @db.Text
  thumbnailUrl String?  @map("thumbnail_url") @db.VarChar(500)
  testUrl      String   @map("test_url") @db.VarChar(500)
  isActive     Boolean  @default(true) @map("is_active")
  createdAt    DateTime @default(now()) @map("created_at")
  updatedAt    DateTime @updatedAt @map("updated_at")
  responses    UserResponse[] @relation("TestToResponses")

  @@map("tests")
}

model UserResponse {
  id        String   @id @db.VarChar(50)
  testId    String   @map("test_id") @db.VarChar(50)
  userId    String   @map("user_id") @db.VarChar(50)
  response  Json     @db.Json
  createdAt DateTime @default(now()) @map("created_at")
  test      Test     @relation("TestToResponses", fields: [testId], references: [id])

  @@map("user_responses")
}
```

```jsx
이 스키마는 심리 테스트(Test)와 사용자 응답(UserResponse) 테이블을 정의합니다.

Test: 테스트의 제목, 설명, 썸네일 URL 등을 저장.

UserResponse: 사용자가 테스트에 답한 결과를 저장.
```

### 1. src/app/tests/page.tsx 파일을 수정:

```jsx
'use client'

import { useEffect, useState } from 'react'
import { supabase } from '@/lib/supabase'

export default function TestsPage() {
  const [tests, setTests] = useState<any[]>([])

  useEffect(() => {
    async function fetchTests() {
      const { data, error } = await supabase
        .from('tests')
        .select('*')
        .eq('is_active', true)

      if (error) {
        console.error('Error:', error)
        return
      }
      setTests(data)
    }
    fetchTests()
  }, [])

  return (
    <div>
      <h1>심리 테스트 목록</h1>
      <ul>
        {tests.map((test) => (
          <li key={test.id}>
            <a href={test.test_url}>{test.title}</a>
          </li>
        ))}
      </ul>
    </div>
  )
}
```


## 🎯 Prisma와 Supabase 클라이언트의 차이

| **항목**        | **Prisma**                  | **Supabase 클라이언트**              |
| --------------- | --------------------------- | ------------------------------------ |
| **사용 위치**   | 서버사이드 (API Routes)     | 클라이언트 + 서버사이드              |
| **타입 안정성** | 강력 (TypeScript 자동 생성) | 보통 (수동 타입 정의 필요)           |
| **실시간 기능** | 없음                        | 지원 (예: 실시간 채팅, 알림)         |
| **설정 복잡도** | 약간 복잡                   | 매우 쉬움                            |
| **보안**        | 서버에서만 실행, 안전       | 클라이언트에서 실행 시 RLS 설정 필요 |

```jsx
서버에서 데이터 작업 → Prisma (안전하고 체계적).

실시간 기능이나 간단한 작업 → Supabase 클라이언트.
```
