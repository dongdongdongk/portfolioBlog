# Mongoose 개념

## **MongoDB와의 기본 상호작용**

```jsx
지금까지는 MongoDB 셸을 사용하여 간단한 데이터베이스 상호작용을 학습다.

dogs, cats 등의 데이터를 생성하고 검색하며 CRUD 작업을 수행했다.
```

## **애플리케이션과의 상호작용**

```jsx
현실적으로 대부분의 상황에서는 몽고디비를 직접 사용하는 대신

애플리케이션과 데이터베이스 간의 상호작용이 필요하다.

사용자가 웹사이트나 앱을 통해 로그인할 때와 같이 사용자 계정을 MongoDB에 생성하려면

Express나 Node와 같은 툴을 사용해야 한다.
```

## **MongoDB 드라이버**

```jsx
MongoDB와 여러 프로그래밍 언어 간에 연결을 지원하는 다양한 드라이버가 있다.

예를 들어, Node.js용 MongoDB 드라이버를 사용하여 Node 앱과 MongoDB를 연결할 수 있다.
```

## **Mongoose 소개**

```jsx
Mongoose는 MongoDB와 Node.js를 연결하는데 사용되는 ODM(Object Data Mapper)이다.

이것은 MongoDB 문서를 JavaScript 객체로 매핑하여 보다 편리하게 다룰 수 있도록 해준다.

( 마이바티스(MyBatis)와 유사한 역할 )
```

## **ODM vs. ORM**

```jsx
ODM은 객체 데이터 매퍼를 의미하며, Mongoose는 MongoDB 문서를 JavaScript 객체로 매핑한다.

ORM은 SQL 데이터를 프로그래밍 언어의 객체로 매핑하는 개념이며, SQL 데이터베이스에 대한 매퍼를 ORM이라고 한다.
```

## **Mongoose 활용**

```jsx
Mongoose를 사용하면 MongoDB와 Node.js 간의 연결이 더욱 간단해지며,

유효성 검사, 사전에 정의된 스키마, 복잡한 쿼리 작성 등을 보다 쉽게 수행할 수 있다.

* 스키마는 데이터베이스 테이블의 구조와 유사하며, 몽구스에서는 JavaScript 객체 형태로 정의
```

## **몽구스 연결 문제 해결에 관한 참고 사항**

```jsx
Solving mongoose 문제 해결
최신 버전의 Node.js에서 몽구스를 사용 중인데 앱을 데이터베이스에 연결할 때 ECONNREFUSED 연결 거부 메시지가 나타나면, mongoose.connect 데이터베이스 연결 문자열에서 localhost 를127.0.0.1 로 변경해야 합니다.

mongoose.connect('mongodb://127.0.0.1:27017/your_database_name_here')
또한, 최신 몽구스 버전에서는 mongoose.connect 메서드에서 두 번째 인수로 옵션 오브젝트를 전달할 필요가 없습니다.

따라서 최신 몽구스 버전을 사용할 때 mongoose.connect 호출은 위와 같이, useNewUrlParser, useUnifiedTopology, useCreateIndex, useFindAndModify 같은 옵션으로 오브젝트를 추가하지 않고 작성합니다.

strictQuery 경고 메시지
앱을 시작할 때 최신 몽구스 버전에서 다음과 같은 경고 메시지가 나타날 수 있습니다.

DeprecationWarning: Mongoose: the `strictQuery` option will be switched back to `false` by default in Mongoose 7. Use `mongoose.set('strictQuery', false);` if you want to prepare for this change. Or use `mongoose.set('strictQuery', true);` to suppress this warning.

이 경고 메시지 자체는 앱의 기능에 영향을 주지 않지만 언급된 mongoose.set('strictQuery', true);라인을 코드의 mongoose.connect 라인 위에 추가하면 경고를 사라지게 할 수 있습니다.

앞으로 이 강의 참고 사항을 메모해 둔 후, 이후의 강의에서 동일한 문제가 발생하면 참고 사항의 해결 방법을 적용하세요.
```

# **모델 이해하기**

```jsx
Mongoose를 사용하여 생성되는 모델은 MongoDB 정보를 나타내는 JavaScript 클래스이다.

모델은 특정 집합의 정보를 나타내는데 사용된다.

이를 통해 MongoDB에서 가져온 데이터로 모델을 만들고 상호 작용하여

데이터베이스에 새로운 정보를 보내거나 삭제, 업데이트하는 데 도움이 된다.
```

## **Mongoose 쿼리**

```jsx
MongoDB와 상호작용하기 위한 Mongoose의 메서드들은 결과로 Promise 객체가 아닌 Mongoose 쿼리 객체를 반환

**Promise와의 차이**:

이 쿼리 객체는 Promise 객체와는 다르지만,

.then 메서드를 통해 비슷한 방식으로 결과를 처리할 수 있다.

그러나 Mongoose 쿼리는 완전한 Promise가 아니므로 몇 가지 주의가 필요하다.

**thenable 객체**:

Mongoose 쿼리는 thenable 객체로 취급된다.

따라서 .then을 사용하여 비동기적으로 결과를 다루게 된다.

즉, Mongoose를 사용할 때는 Promise와는 조금 다른 방식으로 결과를 처리하며,

.then 메서드를 사용하여 비동기 작업을 수행한다는 것이 핵심이다.
```

# Mongoose로 생성 ( 생성 : C )

## **모델 생성 - 스키마 정의**

```jsx
첫 번째로 정의해야 할 모델은 스키마(Schema)이다.

스키마는 MongoDB의 각 키에 대한 JavaScript의 다른 타입으로 구조를 정의한다.

스키마를 정의함으로써 데이터를 구체화한다. 예를 들어, 영화 앱을 위해 영화 정보를 구성한다고 가정해보자
```

```jsx
const movieSchema = new mongoose.Schema({
  title: String,
  year: Number,
  score: Number,
  rating: String,
})
```

```jsx
위의 코드에서 movieSchema는 각 키에 대한 데이터 타입을 정의한 것이다.

제목은 문자열, 개봉 연도는 숫자, 평점은 숫자, 등급은 문자열이다.
```

## **모델 생성 - mongoose.model()**

```jsx
이제 스키마를 사용하여 모델을 생성한다
```

```jsx
const Movie = mongoose.model('Movie', movieSchema)
```

```jsx
여기서 중요한 것은 모델의 이름이다.

이 이름은 단수형이면서 첫 문자는 대문자로 작성되어야 한다.

Mongoose는 이 이름을 기반으로 자동으로 복수형의 집합을 생성한다.

예를 들면, 위의 코드에서 Movie 모델은 movies 집합과 매핑된다.
```

# Mongoose로 찾기 (조회 : R)

## **find 메서드**

```jsx
find 메서드는 네이티브 MongoDB의 find와 유사하게 동작한다.

쿼리와 키-값 쌍을 전달하여 검색하며, 일치하는 문서를 반환한다.

결과는 Mongoose 쿼리 객체로 비동기적으로 처리되며, .then을 사용하여 데이터를 다룬다.
```

```jsx
const Movie = require('Movie') // Movie 모델을 가져옴

// 모든 영화를 찾음
Movie.find().then((data) => console.log(data))

// 특정 조건으로 영화를 찾음 (예: 15세 관람가)
Movie.find({ rating: '15' }).then((data) => console.log(data))

// 특정 연도 이후의 영화를 찾음 (예: 2015년 이후)
Movie.find({ year: { $gte: 2015 } }).then((data) => console.log(data))
```

## **findOne 메서드**

```jsx
findOne 메서드는 find와 유사하지만, 결과 중 첫 번째 문서만 반환한다.

주로 하나의 문서를 찾을 때 사용되며, 특정 조건을 지정할 수 있다.
```

## **findById 메서드**

```jsx
findById 메서드는 주로 Express 앱에서 사용되며, 주어진 ID에 해당하는 문서를 찾는다.

단일 인자로 ID만 전달하면 된다.
```

```jsx
const express = require('express')
const app = express()
const Movie = require('Movie')

// 영화 ID에 해당하는 문서 찾기
app.get('/movies/:id', (req, res) => {
  const movieId = req.params.id

  Movie.findById(movieId)
    .then((movie) => res.json(movie))
    .catch((err) => res.status(404).json({ error: 'Movie not found' }))
})
```

# Mongoose로 업데이트 ( 업데이트 : U)

## **Mongoose의 update 메서드**

```jsx
MongoDB에서는 갱신된 정보를 반환하지 않고,

대신 'nModified'를 통해 몇 개의 문서가 갱신되었는지를 알려준다.

Mongoose에서도 이와 유사한 방식으로 작동한다. 그러나 때로는 갱신된 데이터가 필요할 수 있다.
```

## **updateOne 메서드**

```jsx
updateOne 메서드는 첫 번째 항목을 갱신한다. 쿼리에 매치되는 첫 번째 항목을 주어진 정보로 갱신한다

(첫번째 인자가 대상조건 , 두번째 인자가 변경 내용)

(set 이 필요없어졌다
```

```jsx
// 'name: Jean-Luc Picard'를 'ship: USS Enterprise'로 변경하는 과정
Movie.updateOne({ name: 'Jean-Luc Picard' }, { ship: 'USS Enterprise' })

// 영화 'Amadeus'의 개봉 연도를 1986에서 1984로 변경하는 예시
Movie.updateOne({ title: 'Amadeus' }, { year: 1984 }).then((res) => console.log(res))
```

## **updateMany 메서드**

```jsx
updateMany 메서드는 여러 항목을 동시에 갱신한다
```

```jsx
// 'Amadeus'와 'Stand By Me' 두 영화의 평점을 동시에 10점으로 변경하는 과정 ( 둘중 하나라도 같으면 갱신시킴 in )
Movie.updateMany({ title: { $in: ['Amadeus', 'Stand By Me'] } }, { $set: { rating: 10 } })
```

## **findOneAndUpdate 메서드**

```jsx
findOneAndUpdate 메서드는 특정 기준에 맞는 문서를 찾아서 갱신하며, 갱신된 정보를 반환

기본적으로는 갱신 전의 문서를 반환한다. 그러나 갱신된 문서를 반환받고 싶다면, { new: true }라는 옵션을 설정해야 한다.
```

```jsx
Movie.findOneAndUpdate({ title: 'The Iron Giant' }, { $set: { rating: 7.8 } }, { new: true }).then(
  (updatedMovie) => console.log(updatedMovie)
)
```

### **경고 메시지 해결**

```jsx
Mongoose에서는 findOneAndUpdate와 관련된 경고 메시지가 나타날 수 있다.

이 경고는 Mongoose에서 findOneAndUpdate를 내부적으로 사용하는데, 이에 대한 설정이 필요하다는 것을 알려주는 것
```

```jsx
mongoose.set('useFindAndModify', false)
```

```jsx
위 예시에서처럼 mongoose.set('useFindAndModify', false)를 사용하여 경고를 해결할 수 있다.

이 설정은 Mongoose가 내부적으로 사용하는 findOneAndUpdate 대신 MongoDB의 findOneAndUpdate를 사용하도록 한다.

이 설정을 적용하면, 더 이상 findOneAndUpdate에 관한 경고가 표시되지 않는다.

이 옵션은 Mongoose 6.x 버전부터는 더 이상 디폴트로 설정되어 있지 않으므로, 사용자가 명시적으로 설정해주어야 한다.
```

# Mongoose로 삭제 ( 삭제 : D)

## **Mongoose에서의 삭제 방법**

```jsx
Mongoose를 사용하여 데이터를 삭제하는 데는 두 가지 유형의 메서드가 있다.

갱신과 마찬가지로 모델 메서드를 사용할 수 있다.
```

## remove( 사용 권장 x)

```jsx
remove 메서드는 MongoDB에 직접 삭제 명령을 전달하며 관련 문서가 없다.

remove 메서드는 삭제된 개수만 반환하며, 갱신과 비슷한 메서드 이름을 사용한다.

경고: deleteOne, deleteMany, bulkWrite를 사용하도록 권고됨.
```

```jsx
const result = await Movie.remove({ title: 'Amelie' })
console.log(`${result.deletedCount}개의 영화가 삭제되었습니다.`)
```

## **deleteOne메서드**

```jsx
특정 조건에 맞는 문서 중 첫 번째 문서를 삭제하는 메서드

deleteOne 메서드는 조건에 맞는 첫 번째 문서만 삭제하며, 해당 문서가 없어도 오류를 발생시키지 않는다.

반환 값은 삭제된 문서의 개수를 나타내는 객체이다.
```

```jsx
// Movie 모델 정의
const Movie = mongoose.model('Movie', {
  title: String,
  year: Number,
})

// 예제: deleteOne 메서드 사용
const result = await Movie.deleteOne({ title: 'Inception' })

// 결과 출력
console.log(`${result.deletedCount}개의 영화가 삭제되었습니다.`)
```

## **deleteMany 메서드**

```jsx
특정 조건에 맞는 여러 데이터를 삭제
```

```jsx
const result = await Movie.deleteMany({ year: { $gte: 1999 } })
console.log(`${result.deletedCount}개의 영화가 삭제되었습니다.`)
```

## **findOneAndDelete 메서드**

```jsx
findOneAndDelete 메서드를 사용하여 특정 문서를 찾아 삭제

삭제된 데이터가 반환되어 출력
```

```jsx
const deletedMovie = await Movie.findOneAndDelete({ title: 'Alien' })
console.log(`삭제된 영화: ${deletedMovie}`)
```

# **MongoDB 스키마**

```jsx
스키마에 제약조건을 만드는 방법에 대해서 배워본다
```

```jsx
const mongoose = require('mongoose')

main().catch((err) => console.log(err))

async function main() {
  await mongoose.connect('mongodb://127.0.0.1:27017/ShopApp')
  console.log('ConnectSuccess')
}

const productSchema = new mongoose.Schema({
  // 제약 조건을 걸어본다
  name: {
    type: String,
    required: true, // 값이 필수적임
  },
  price: {
    type: Number,
  },
})

const Product = mongoose.model('Product', productSchema) // 모델 정의

const bike = new Product({ price: 300 }) // 상품 생성 및 저장

bike
  .save()
  .then((data) => {
    console.log('Success')
  })
```

# 가상 Mongoose

```jsx
* 가상 Mongoose에서는 실제 데이터베이스에 저장되지 않지만, 코드에서 사용할 수 있는 가상 특성을 정의할 수 있다.

* "특성"은 객체의 속성이나 필드를 나타낸다.

* 이러한 기능을 통해 코드에서 데이터를 다룰 때 편리하고 유연한 방식으로 작업할 수 있다.

* 예를 들어, 실제 데이터베이스에는 없는 "fullName"과 같은 특성을 가상 Mongoose를 사용하여 모델에 추가할 수 있다.

* 이렇게 추가된 가상 특성은 코드에서 데이터베이스에 있는 것처럼 활용할 수 있고,

	필요한 경우 가공이나 변환 작업을 통해 활용할 수 있다.

* 이는 개발자에게 데이터 모델을 풍부하게 만들어주며,

	데이터에 접근하거나 조작할 때 편리한 인터페이스를 제공한다.

* 가상 특성은 실제 데이터베이스에 저장되지 않고 코드에서 사용하는 용도로 활용된다.
```

## **가상 특성 추가**

```jsx
// fullName 가상 특성 추가
personSchema.virtual('fullName').get(function () {
  return `${this.first} ${this.last}`
})
```

```jsx
virtual: 가상 특성을 정의할 때 사용하는 키워드.

'fullName': 추가하려는 가상 특성의 이름.

get: 가상 특성에 대한 Getter 함수를 정의.
```

## **가상 특성 Setter 추가**

```jsx
// fullName 가상 특성의 Setter 정의
personSchema.virtual('fullName').set(function (value) {
  const [firstName, lastName] = value.split(' ')
  this.first = firstName
  this.last = lastName
})
```

```jsx
set: 가상 특성에 대한 Setter 함수를 정의.

value: Setter 함수에 전달되는 값을 나타내는 매개변수.
```

## **가상 특성 활용**

```jsx
// 사용 예제
const person = new Person({ first: 'John', last: 'Doe' })
console.log(person.fullName) // 출력: John Doe
```

```jsx
person.fullName: 가상 특성에 접근하여 값을 얻는 방법.
```

## **가상 특성 Getter 및 Setter 함께 정의**

```jsx
// fullName 가상 특성의 Getter 및 Setter 정의
personSchema
  .virtual('fullName')
  .get(function () {
    return `${this.first} ${this.last}`
  })
  .set(function (value) {
    const [firstName, lastName] = value.split(' ')
    this.first = firstName
    this.last = lastName
  })
```

```jsx
get 및 set을 연이어 사용하여 가상 특성의 Getter 및 Setter를 함께 정의.
```

## 전체적인 예시

```jsx
const mongoose = require('mongoose')

// MongoDB 연결 설정
mongoose.connect('mongodb://localhost/shopApp', { useNewUrlParser: true, useUnifiedTopology: true })

// Person 모델의 스키마 정의
const personSchema = new mongoose.Schema({
  first: String,
  last: String,
})

// fullName 가상 특성 추가 (Getter 및 Setter 함께 정의)
personSchema
  .virtual('fullName')
  .get(function () {
    return `${this.first} ${this.last}`
  })
  .set(function (value) {
    const [firstName, lastName] = value.split(' ')
    this.first = firstName
    this.last = lastName
  })

// Person 모델 생성
const Person = mongoose.model('Person', personSchema)

// MongoDB 연결 후 동작
mongoose.connection.once('open', function () {
  console.log('MongoDB 연결 성공!')

  // Person 모델을 사용하여 데이터 조작
  const tammy = new Person({ first: 'Tammy', last: 'Chow' })

  // fullName 가상 특성 활용
  console.log(tammy.fullName) // 출력: Tammy Chow

  // fullName 가상 특성의 Setter 활용
  tammy.fullName = 'Tammy Xiao'
  console.log(tammy.fullName) // 출력: Tammy Xiao

  // MongoDB에 데이터 저장
  tammy.save(function (err) {
    if (err) return console.error(err)
    console.log('데이터 저장 완료.')

    mongoose.connection.close()
  })
```

# **Mongoose 미들웨어 소개**

```jsx
Mongoose에서 미들웨어는 특정 동작(삭제, 저장, 업데이트 등)이 실행되기 전이나

후에 특정 코드를 실행할 수 있게 해주는 강력한 기능 중 하나
```

## **미들웨어의 역할과 종류**

```jsx
역할:

Mongoose 미들웨어는 특정 메서드 호출 전후에 코드를 실행하여 데이터 조작, 검증, 로깅 등 다양한 작업을 수행할 수 있다.

종류:

Mongoose에서는 **pre**와 **post** 훅을 사용하여 각각 메서드 호출의 앞과 뒤에서 실행되는 미들웨어를 정의할 수 있다.
```

## **기본적인 미들웨어 사용 예제**

### **예제: 사용자 삭제 시 관련 데이터 삭제**

```jsx
예제 시나리오:

사용자를 삭제할 때 관련된 모든 데이터를 삭제하는 상황을 가정한다.

코드 구현:

 Mongoose 미들웨어를 사용하여 사용자 삭제 시 동작할 pre 미들웨어를 구현한다.
```

```jsx
personSchema.pre('remove', async function (next) {
  // 사용자 삭제 전에 실행될 코드
  await Comment.deleteMany({ user: this._id })
  await Post.deleteMany({ user: this._id })
  // 다른 관련 데이터 삭제 로직 추가 가능
  next()
})
```

### 예제: 사용자 정보를 저장하기 전에 특정 처리를 하고 싶은 경우

```jsx
const mongoose = require('mongoose')

const userSchema = new mongoose.Schema({
  username: String,
  email: String,
  // 다른 필드들...
})

// pre 미들웨어: 사용자 정보를 저장하기 전에 실행됨
userSchema.pre('save', async function (next) {
  // 특정 처리 수행
  console.log(`사용자 ${this.username} 정보를 저장하기 전에 실행됨`)

  // 다음 미들웨어로 제어를 전달
  next()
})

const User = mongoose.model('User', userSchema)
```

## **비동기 미들웨어 및 Promise 활용**

### 특정 비동기 작업을 수행한 후에 다음 동작을 실행하고 싶은 경우

```jsx
userSchema.pre('save', async function (next) {
  // 비동기 작업 수행 (예: API 호출, 파일 업로드 등)
  await someAsyncTask()

  // 다음 미들웨어로 제어를 전달
  next()
})

// 비동기 작업을 Promise를 반환하여 처리하는 경우
userSchema.pre('save', function () {
  return someAsyncTask().then(() => {
    // 다음 미들웨어로 제어를 전달
  })
})
```

### 다음 미들웨어란?

```jsx
Mongoose의 미들웨어에서 비동기 작업을 수행할 때,

해당 작업이 완료된 후에 다음 미들웨어로 제어를 전달하기 위해 next() 함수를 사용한다.

여기서 next() 함수는 현재 미들웨어를 종료하고 다음 미들웨어로 실행 흐름을 이동시키는 역할을 한다.
```

```jsx
Express에서 미들웨어는 요청 처리를 위해 연속적으로 적용되는 함수들의 체인이다.

각각의 미들웨어는 요청 객체(req), 응답 객체(res), 그리고 다음 미들웨어로 넘어갈 수 있는 함수를 받는다.

이 함수를 통해 현재 미들웨어의 작업이 끝나면 다음 미들웨어로 제어를 전달할 수 있다.
```

```jsx
app.use((req, res, next) => {
  // 현재 미들웨어에서 수행할 작업
  console.log('현재 미들웨어 동작 중')

  // 다음 미들웨어로 제어를 전달
  next()
})

app.use((req, res) => {
  // 다음 미들웨어에서 수행할 작업
  console.log('다음 미들웨어 동작 중')
})
```

## **this 키워드 활용 및 데이터 업데이트**

### 사용자 정보를 저장하기 전에 데이터를 업데이트하고 싶은 경우.

```jsx
userSchema.pre('save', function (next) {
  // this 키워드를 사용하여 현재 문서에 접근
  this.lastUpdated = new Date()
  next()
})
```

## **미들웨어 순서와 실행 확인**

### pre 미들웨어와 post 미들웨어의 실행 순서를 확인하고 싶은 경우.

```jsx
userSchema.pre('save', function (next) {
  console.log('pre 미들웨어 실행')
  next()
})

userSchema.post('save', function () {
  console.log('post 미들웨어 실행')
})

// 위의 예제에서 save 메서드 호출 시, 먼저 pre 미들웨어가 실행되고 그 후 post 미들웨어가 실행된다.
```
