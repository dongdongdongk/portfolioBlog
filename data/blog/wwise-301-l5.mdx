## 1. Game Parameter와 RTPC 개념 이해하기

🎯 **Game Parameter**란?

Wwise에서 사운드를 **게임의 변수에 따라 제어**할 수 있게 해주는 시스템입니다.

예를 들어,

- 속도(speed)에 따라 바람소리를 점점 세게 만들거나,
- 체력(health)에 따라 숨소리를 거칠게 만들거나,
- 낮과 밤(time of day)에 따라 환경음을 바꾸는 것 등이 가능합니다.

🎚️ **RTPC (Real-Time Parameter Control)**

RTPC는 Game Parameter의 값을 **실시간으로 제어**하는 기능입니다.

이 값을 코드에서 직접 업데이트하여 사운드를 부드럽게 변화시키는 데 사용됩니다.

예시:

- 낮(0.0) → 밤(1.0) 으로 갈수록 **밤의 환경음**이 점차 커지고
- 낮의 새소리나 바람소리는 점점 줄어듭니다.

🧠 **핵심 개념 요약**

| 개념                | 설명                                                                   |
| ------------------- | ---------------------------------------------------------------------- |
| **Game Parameter**  | 게임 속 변수를 Wwise로 전달하여 사운드를 제어하는 매개체               |
| **RTPC**            | 이 Game Parameter의 값을 프레임마다 업데이트하거나 제어하는 실제 기능  |
| **Blend Container** | Game Parameter의 값에 따라 자동으로 다른 사운드를 혼합(Blend)하는 구조 |

## 2. Wwise Adventure Game의 Day/Night 시스템 구조

Wwise Adventure Game (WAG)에서는 이미 **낮/밤 시스템(DayNightCycle)**이 구현되어 있습니다.

- **Sun (태양 오브젝트)**
  - 하늘의 태양 위치를 조정하며,
  - `DayNightCycle` 스크립트를 통해 시간의 흐름을 제어합니다.
- **TimeOfDay**
  - GameManager에 등록된 전역 변수입니다.
  - `0.0`은 **낮**, `1.0`은 **밤**을 의미합니다.
- **Time_of_Day Game Parameter**
  - Wwise 안에 이미 존재하는 RTPC입니다.
  - 이 값이 바뀔 때마다 낮 또는 밤 환경음으로 점진적으로 전환됩니다.

🌞 → 🌙

낮 → 밤으로 갈수록 RTPC 값이 서서히 변하며, **Blend Container**에서 자동으로 다른 사운드가 재생됩니다.

## 3. 새로운 스크립트 생성하기 – SetTimeOfDayRTPC

1. **Hierarchy**에서 **Sun** 오브젝트를 선택합니다.
2. **Inspector** 창 하단에서

   `Add Component > New Script`를 선택합니다.

3. 새 스크립트 이름을 `SetTimeOfDayRTPC`로 입력합니다.
4. **Create and Add** 버튼을 눌러 컴포넌트를 추가합니다.
5. 스크립트를 더블클릭하여 코드 편집기(VS Code 또는 Visual Studio)에서 엽니다.

📄 기본 코드 구조는 다음과 같습니다.

```csharp
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class SetTimeOfDayRTPC : MonoBehaviour {
    public AK.Wwise.RTPC
    // Use this for initialization
    void Start () {
    }

    // Update is called once per frame
    void Update () {
    }
}
```

## 4. RTPC 설정 코드 작성하기

이제 `AK.Wwise.RTPC` 타입의 변수를 생성하여

Wwise의 Game Parameter를 스크립트에서 접근할 수 있게 합니다.

1. `public` 접근 제한자를 붙여서 인스펙터에서 보이게 합니다.
2. 변수 이름은 `TimeOfDayRTPC`로 설정합니다.
3. 세미콜론 `;`으로 마무리합니다.

```csharp
public class SetTimeOfDayRTPC : MonoBehaviour {
    public AK.Wwise.RTPC TimeOfDayRTPC;

    void Start() {
    }

    void Update() {
    }
}
```

이제 Unity로 돌아가면 Inspector에 **TimeOfDayRTPC** 필드가 보입니다.

## 5. SetGlobalValue vs SetValue 차이 이해하기

이제 매 프레임마다 RTPC 값을 업데이트할 차례입니다.

이를 위해 `Update()` 함수에 코드를 추가합니다.

### 두 가지 함수의 차이점

| 함수                 | 적용 범위       | 설명                                 |
| -------------------- | --------------- | ------------------------------------ |
| **SetValue()**       | 개별 GameObject | 이 스크립트가 붙은 오브젝트에만 적용 |
| **SetGlobalValue()** | 전체(Global)    | 모든 오브젝트에 동일한 값 적용       |

🌍 **이번 강의에서는 전역(Game-wide)** 으로 낮/밤 사운드를 바꾸어야 하므로

`SetGlobalValue()`를 사용해야 합니다.

```csharp
void Update() {
    TimeOfDayRTPC.SetGlobalValue();
}
```

## 6. GameManager와 연동하여 값 전달하기

이제 RTPC에 보낼 값을 `GameManager`에서 가져와야 합니다.

`GameManager`는 게임 내 전역 상태(예: 점수, 시간, 날씨 등)를 추적하는 전역 스크립트입니다.

`GameManager`에는 `TimeOfDay`라는 **float 변수**가 존재하며,

낮과 밤의 진행 정도를 나타냅니다.

따라서, RTPC에 이 값을 전달하면 됩니다:

```csharp
void Update() {
    TimeOfDayRTPC.SetGlobalValue(GameManager.TimeOfDay);
}
```

✅ **이 코드의 역할**

- 매 프레임마다 `GameManager.TimeOfDay` 값을 읽어옵니다.
- 이 값을 `Wwise`의 `Time_of_Day` Game Parameter로 전달합니다.
- 그 결과, 환경음이 시간에 따라 부드럽게 변화합니다.

## 7. Wwise-Type RTPC를 인스펙터에 연결하기

2. Inspector에서 **SetTimeOfDayRTPC** 컴포넌트가 보일 것입니다.
3. 거기서 **TimeOfDayRTPC** 필드에 Wwise-Type을 할당합니다.
4. 드롭다운 목록에서

   **Game Parameter → Ambient → Time_of_Day** 를 선택합니다.

이제 이 스크립트가 Wwise의 **Time_of_Day RTPC**를 조정하게 됩니다.

## 1. 현재 문제 이해하기

- 현재 Player가 달리거나 걸을 때 **모든 발소리(Event: Player_Footstep)** 가
  **동일한 표면(‘Dirt’, 흙)** 소리를 재생합니다.
- 이유는 **표면 재질(Surface Type)** 을 구분하지 않고
  **항상 기본 Switch 값**(Dirt)으로만 설정되어 있기 때문입니다.

🎯 **목표:**

플레이어가 **밟고 있는 표면(Grass, Dirt 등)** 을 감지해

그에 맞는 발소리로 동적으로 바꾸는 것입니다.

---

## 2. Wwise Switch 개념 이해하기

- **Switch**는 게임 내의 **상황에 따라 사운드 동작을 바꾸는 기능**입니다.
- 예를 들어:
  - Surface_Type Switch → ‘Grass’, ‘Dirt’, ‘Wood’ 등의 표면 구분
  - State와 달리 **Switch는 특정 게임 오브젝트 단위로 동작**합니다.
- 즉, 같은 Switch Group을 여러 오브젝트가 사용하더라도
  각각의 오브젝트에 설정된 Switch 값은 독립적입니다.

🔹 **State vs Switch 비교**

| 구분   | 적용 범위             | 사용 예시                  |
| ------ | --------------------- | -------------------------- |
| State  | 전역(Global)          | BGM 모드 전환, 전투/비전투 |
| Switch | 개별(GameObject 단위) | 표면 재질, 무기 타입       |

## 3. Surface_Type Switch Group 구조 살펴보기

Wwise 프로젝트에는 이미 **Surface_Type Switch Group**이 설정되어 있습니다.

이 Group에는 다음과 같은 Switch 값이 들어있습니다:

- **Dirt** (기본)
- **Grass**
- **Wood**
- (기타 재질)

그리고 이 Group은 **Footstep_Surface Switch Container**에 연결되어 있습니다.

🎧 **작동 원리:**

1. Player_Footstep Event → Footstep_Surface Container로 이동

예를 들어,

- `Surface_Type = Dirt` → 흙 소리
- `Surface_Type = Grass` → 잔디 소리

하지만 아직 표면 타입 Switch를 설정하지 않아

## 6. MaterialChecker와 PlayerManager 연결하기

### 🧩 MaterialChecker

- Player의 발(Toe)에 붙어 있는 스크립트입니다.
- Player가 밟고 있는 표면(GameObject)을 감지하고,
  그 표면의 `SoundMaterial.material` 값을 가져옵니다.

> 즉, MaterialChecker → SoundMaterial → Switch 값 순으로 접근합니다.

MaterialChecker에는 이런 함수가 있습니다:

```csharp
public AK.Wwise.Switch GetMaterial()
```

이 함수는 발 밑의 재질을 확인하여 **해당 Switch**를 반환합니다.

```csharp
플레이어의 발 스크립트 위에 보면

public AK.Wwise.Switch GetMaterial() 가 있다
```

### 🧩 PlayerManager

- Player 관련 오브젝트(왼발, 오른발, 애니메이션 등)를 관리합니다.
- `MaterialChecker`를 직접 찾지 않아도
  `PlayerManager`를 통해 `foot_L`, `foot_R` 접근이 가능합니다.

## 7. Switch를 Event 게시 전에 설정하기

이제 본격적으로 Switch를 설정해봅시다.

`PostWwiseEvent` 스크립트를 수정합니다.

### ✍ 수정된 코드

```csharp
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class PostWwiseEvent : MonoBehaviour {
    public AK.Wwise.Event MyEvent;

    public void PlayFootstepSound(){
        PlayerManager.foot_L.GetMaterial().SetValue(gameObject);
        MyEvent.Post(gameObject);
    }

    void Update () {
    }
}
```

### 🧠 코드 해설

1. **`PlayerManager.foot_L.GetMaterial()`**
   - Player의 왼발 밑에 있는 `MaterialChecker`를 통해
     현재 표면의 `Wwise Switch`(예: Grass, Dirt)를 가져옵니다.
2. **`.SetValue(gameObject)`**
   - 해당 Switch 값을 Player(GameObject)에 설정합니다.
   - `gameObject`를 전달하는 이유:
     - Switch는 **게임 오브젝트 단위**로 작동하기 때문입니다.
     - 즉, Player 객체에 Switch를 설정해야
       같은 객체에 게시되는 Event에 적용됩니다.
3. **`MyEvent.Post(gameObject)`**
   - Player_Footstep Event를 Player 객체에서 게시합니다.
   - 이미 Switch가 설정되어 있으므로
     해당 표면 재질에 맞는 발소리가 재생됩니다.

### 🎯 `MaterialChecker` 정리

```csharp
public class MaterialChecker : MonoBehaviour
{
    public LayerMask layermask; // 감지할 레이어 설정 (예: Ground)

    private RaycastHit hit;             // Raycast 충돌 정보 저장
    private Vector3 direction = Vector3.down; // 아래 방향으로 레이 발사
    private Transform trn;              // 이 스크립트가 붙은 오브젝트의 Transform
    private Vector3 checkOffset = Vector3.up * 0.1f; // 바닥 뚫림 방지용 오프셋

    void Awake()
    {
        trn = transform;

        // toe_left / toe_right 오브젝트라면 PlayerManager에 등록
        if (gameObject.name == "toe_right")
            PlayerManager.foot_R = this;
        else if (gameObject.name == "toe_left")
            PlayerManager.foot_L = this;
    }

    // 🧩 표면 감지 및 스위치 설정
    public void CheckMaterial(GameObject go)
    {
        // 아래로 레이 발사해서 바닥을 감지
        if (Physics.Raycast(trn.position + checkOffset, direction, out hit, layermask))
        {
            // 부딪힌 오브젝트에서 SoundMaterial 컴포넌트 찾기
            SoundMaterial sm = hit.collider.gameObject.GetComponent<SoundMaterial>();

            if (sm != null)
            {
                // 표면이 가지고 있는 Wwise 스위치를 현재 오브젝트(go)에 적용
                sm.material.SetValue(go);
            }
        }
    }

    // 🧱 현재 표면의 Wwise Switch를 반환 (필요 시 직접 사용)
    public AK.Wwise.Switch GetMaterial()
    {
        if (Physics.Raycast(trn.position + checkOffset, direction, out hit, layermask))
        {
            SoundMaterial sm = hit.collider.gameObject.GetComponent<SoundMaterial>();

            if (sm != null)
                return sm.material;
        }
        return null;
    }
}
```

## 1. Game Sync 개요

### 🎛 Game Sync란?

Wwise의 **Game Sync(게임 동기화 시스템)** 은

게임의 상태 변화나 동작에 따라 **오디오를 제어**하는 핵심 구조입니다.

각 Sync는 서로 다른 목적을 가지고 설계되어 있습니다.

| 종류               | 설명                                            | 사용 예시                                 |
| ------------------ | ----------------------------------------------- | ----------------------------------------- |
| **Game Parameter** | 수치 값에 따라 소리를 점진적으로 변경할 때 사용 | 속도, 체력, 거리, 온도 등                 |
| **State**          | 게임의 전역적 상태를 나타냄                     | 메뉴, 전투, 탐험 등 게임 전체 분위기 변화 |
| **Switch**         | 개별 오브젝트의 상황에 따라 소리를 변경         | 발소리 재질, 무기 충돌 재질 등            |

---

### 🧩 Game Sync의 범위 개념

Wwise에서 Sync의 범위는 **두 가지 수준**으로 구분됩니다.

| 범위                           | 설명                    | 특징                          |
| ------------------------------ | ----------------------- | ----------------------------- |
| **Global(전역)**               | 게임 전체에 영향을 미침 | 모든 오브젝트에 동일하게 적용 |
| **Game Object(게임 오브젝트)** | 특정 오브젝트에만 적용  | 개별적인 제어 가능            |

---

## 2. Switch의 작동 범위와 예시

### 🎚 Switch 개념

Switch는 게임 오브젝트 수준에서 작동합니다.

즉, **어떤 게임 오브젝트에 설정되었는가에 따라 소리의 결과가 달라집니다.**

- 전역이 아닌, **해당 오브젝트 범위 안에서만** 유효
- 예를 들어 `Player` 오브젝트의 발에는 **Surface_Type = Grass**,
  무기에는 **Surface_Type = Stone** 이 적용될 수 있음

---

### 🦶 예시: Player의 발소리 & 무기 충돌음

### ① Switch Group: `Surface_Type`

- Player의 **Footstep_Surface** 와
  **Impact_Weapon_Type** 두 컨테이너 모두 같은 Switch Group을 사용 (`Surface_Type`)
- 따라서 동일한 논리(재질별 사운드)를 재사용 가능

### ② 문제 상황:

이동과 공격을 번갈아 하면,

**서로 다른 Switch Group이 충돌하지 않을까?**

예를 들어,

- Player가 Grass 위를 걸을 때 → Surface_Type = Grass
- 바로 돌(Stone)을 공격할 때 → Surface_Type = Stone
  이렇게 바뀌면 충돌이 생길 것처럼 보임.

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380526/notion-blog/_/WWISE/Wwise_Unity_/Wwise_301_L5/image_14.png)

## 3. Game Parameter의 작동 범위와 예시

### ⚙ Game Parameter 개념

Game Parameter는 Switch와 달리

**전역(Global)** 과 **게임 오브젝트 범위** **모두 사용 가능**합니다.

- 전역으로 설정: `SetGlobalValue()`
- 오브젝트 단위로 설정: `SetValue(gameObject, value)`

---

### 👾 예시: `Enemy_EvilHead_MovementSpeed`

- **단 하나의 Game Parameter**(`Enemy_EvilHead_MovementSpeed`)로
  여러 개체의 속도를 각각 제어 가능.

## 4. 전역(Global)과 게임 오브젝트(Game Object) 범위의 관계

### ⚖ 동시 사용 시 우선순위

| 상황            | 적용 함수                     | 우선순위 | 설명                                                |
| --------------- | ----------------------------- | -------- | --------------------------------------------------- |
| 전역적 설정     | `SetGlobalValue()`            | 낮음     | 전체적으로 적용되지만 개별 설정이 있으면 덮어씌워짐 |
| 오브젝트별 설정 | `SetValue(gameObject, value)` | **높음** | 해당 오브젝트의 전역 설정을 무시하고 자신의 값 사용 |

---

### ☀ 예시: `Time_of_Day` Game Parameter

- 전역적으로 낮/밤을 제어하는 파라미터
- 만약 같은 오브젝트 안의 **Woodlands Ambience** 스크립트가
  `SetValue()`로 Game Object 범위 값을 설정한다면?

→ 이후 전역 Time_of_Day 값은 이 오브젝트에는 **더 이상 영향을 주지 않음**.

즉,

- **SetValue() → Game Object 우선 적용**
- **SetGlobalValue() → 전체 적용, 그러나 개별 설정 시 무시됨**

---

## 🎯 요약 정리

| 구분               | 적용 범위                      | 특징                             | 예시                 |
| ------------------ | ------------------------------ | -------------------------------- | -------------------- |
| **Switch**         | Game Object                    | 개별 오브젝트의 상태에 따라 변경 | 발소리, 무기 충돌    |
| **State**          | Global                         | 전역 게임 상태를 관리            | 탐험/전투/메뉴       |
| **Game Parameter** | Global / Game Object 모두 가능 | 수치 기반 변화 (속도, 거리 등)   | Evil Head의 이동속도 |

## 🚀 핵심 포인트 정리

- **Switch** → 오브젝트별 독립 동작 (예: 발소리 vs 무기 충돌음 간섭 없음)
- **Game Parameter** → 전역/개별 설정 모두 가능
- **SetValue()** 는 **SetGlobalValue()** 를 덮어씀
- **Profiler 활용**으로 실제 오브젝트 단위 값 변화를 시각적으로 확인 가능

## 1. Game Sync 통합 개념 이해하기

### 🎮 Game Sync란?

Wwise의 **Game Sync**는 게임 내 상황(예: 시간, 환경, 상태 등)에 따라 **사운드를 동적으로 변화시키는 시스템**이다.

Game Sync는 다음과 같은 네 가지 주요 유형으로 구성된다.

| 유형                                   | 설명                                                                                 | 사용 예시                                  |
| -------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------ |
| **RTPC (Real-Time Parameter Control)** | 게임 값(예: 속도, 시간 등)을 사운드 파라미터에 연동하여 점진적으로 변화를 줄 때 사용 | 플레이어 속도에 따라 발걸음 소리 크기 조절 |
| **State**                              | 게임 전체의 전역적 상태를 반영하여 사운드를 전환                                     | ‘전투 중’, ‘탐험 중’과 같은 전역 상태      |
| **Switch**                             | 각 오브젝트별로 다른 소리를 재생할 때 사용                                           | 다른 재질 위를 걸을 때 발소리 변경         |
| **Trigger**                            | 특정 순간에 이벤트를 실행할 때 사용                                                  | 버튼 클릭, 공격, 점프 등                   |

---

## 2. 컴포넌트 vs 사용자 정의 스크립트

### 🧩 (1) 미리 만들어진 컴포넌트 사용하기

- **Wwise Unity Integration**에는 이미 여러 **Wwise-Type 컴포넌트**가 포함되어 있다.
- 예: `AK.Wwise.Event`, `AK.Wwise.RTPC`, `AK.Wwise.Switch` 등.
- Unity Inspector에서 손쉽게 설정할 수 있다.

### ✅ 장점

- **Trigger On 옵션**을 이용해
  이벤트 실행 시점을 쉽게 정의할 수 있음 (예: On Start, On Trigger Enter 등).
- 코드 작성이 필요 없음.
- 빠르고 직관적인 설정 가능.

### ⚠️ 단점

- 특정한 **게임 로직**이나 **조건 분기**가 필요한 경우에는 한계가 있음.
- 예를 들어, 플레이어가 밟은 표면의 재질을 감지하여 다른 사운드를 내는 기능은
  별도의 **사용자 정의 스크립트**가 필요함.

---

### 💻 (2) 사용자 정의 스크립트 사용하기

- 직접 C# 스크립트를 작성해 Wwise-Type을 호출함.
- 예: Wwise Adventure Game의 **MaterialChecker**처럼
  다른 시스템(재질 감지, 상태 관리 등)과 통합 가능.

### ✅ 장점

- Unity의 다른 시스템(물리, 애니메이션, 재질 등)과 **유기적 연동 가능**.
- 복잡한 조건 제어나 사용자 정의 로직에 적합.

### ⚠️ 단점

- 코드 작성 필요.
- 컴포넌트보다 구현이 다소 복잡할 수 있음.

---

## 3. Game Sync의 범위: 전역(Global) vs 게임 오브젝트(Game Object)

이 부분이 **가장 중요한 핵심 포인트**이다.

| 구분                                | 설명                                                               | 예시                                 |
| ----------------------------------- | ------------------------------------------------------------------ | ------------------------------------ |
| **전역적(Global) 범위**             | 게임 전체에 공통으로 적용되는 값. 모든 사운드에 영향을 줄 수 있음. | 낮/밤 시간에 따라 전체 배경음이 변함 |
| **게임 오브젝트(Game Object) 범위** | 특정 오브젝트에만 적용되는 값. 오브젝트마다 개별 사운드 제어 가능. | 특정 캐릭터의 발소리만 다르게 변경   |

즉, 어떤 Game Sync를 사용할지 정할 때는 **그 사운드의 영향 범위가 어디까지인지**를 항상 고려해야 한다.

---

## 4. 참조 스크립트 ① SetTimeOfDayRTPC

### 🎯 목적

Wwise-Type `RTPC`를 사용해 **게임 시간(TimeOfDay)** 값에 따라

사운드의 분위기(예: 낮/밤)를 실시간으로 변경하기.

---

### 🧱 코드 구조

```csharp
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class SetTimeOfDayRTPC : MonoBehaviour {
    public AK.Wwise.RTPC TimeOfDayRTPC;
    // Use this for initialization.
    void Start () {

    }

    // Update is called once per frame.
    void Update () {
        TimeOfDayRTPC.SetGlobalValue(GameManager.TimeOfDay);
    }
}
```

---

### 🔍 코드 분석

| 코드                                  | 설명                                                                               |
| ------------------------------------- | ---------------------------------------------------------------------------------- |
| `public AK.Wwise.RTPC TimeOfDayRTPC;` | Wwise에서 만든 RTPC를 Unity Inspector에 연결할 수 있도록 공개(public) 필드로 선언. |
| `Update()`                            | 매 프레임마다 실행됨. 게임 내 시간 값(GameManager.TimeOfDay)을 Wwise에 전달.       |
| `SetGlobalValue()`                    | **전역 RTPC 값**을 설정하는 함수. 모든 사운드에 영향을 줌.                         |

---

### 💡 개념 요약

- **RTPC**는 실시간으로 사운드의 매개변수를 제어하는 기능이다.
  (예: 음악의 밝기, 음색, 필터 등)
- 이 스크립트는 **전역적(Global) Game Sync**에 해당한다.
  → 게임 내 전체 사운드가 `GameManager.TimeOfDay` 값에 반응하게 된다.
- 따라서 “낮 → 밤”으로 시간이 변할 때
  전체 사운드 분위기도 부드럽게 전환될 수 있다.

---

## 5. 참조 스크립트 ② PostWwiseEvent

### 🎯 목적

Wwise-Type `Event`를 사용해 플레이어가 **특정 상황(예: 발걸음)**에서

사운드를 재생하고, 재질(Switch)을 감지하여 적절한 소리를 낼 수 있도록 하는 스크립트.

---

### 🧱 코드 구조

```csharp
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class PostWwiseEvent : MonoBehaviour {
    public AK.Wwise.Event MyEvent;

    public void PlayFootstepSound(){
        PlayerManager.foot_L.GetMaterial().SetValue(gameObject);
        MyEvent.Post(gameObject);
    }

    void Update () {

    }
}
```

---

### 🔍 코드 분석

| 코드                                                       | 설명                                                                                   |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `public AK.Wwise.Event MyEvent;`                           | Unity Inspector에서 연결할 수 있는 Wwise Event. (예: Footstep 이벤트)                  |
| `PlayFootstepSound()`                                      | 플레이어가 발걸음 사운드를 재생할 때 호출되는 메서드.                                  |
| `PlayerManager.foot_L.GetMaterial().SetValue(gameObject);` | 플레이어의 왼발(`foot_L`)이 밟은 표면 재질을 감지하고, 그에 맞는 **Switch 값**을 설정. |
| `MyEvent.Post(gameObject);`                                | 해당 게임 오브젝트에서 Wwise 이벤트를 실제로 실행.                                     |
| `Update()`                                                 | 현재는 비워져 있지만, 향후 주기적인 체크나 자동 실행 로직을 추가할 수 있음.            |

---

### 💡 개념 요약

- 이 스크립트는 **게임 오브젝트(Game Object) 범위**에 해당한다.
  → 각 플레이어 오브젝트마다 다른 재질 사운드(Switch)를 적용 가능.
- 예를 들어, 플레이어가 **돌길**을 걷다가 **나무 바닥**으로 이동하면
  `GetMaterial()`에 따라 자동으로 Switch가 변경되어 발소리가 달라진다.
- `MyEvent.Post(gameObject)`를 통해 사운드는 해당 오브젝트의 위치에서 재생된다.

---

## 6. 정리 및 핵심 포인트

| 구분                      | 설명                                                               |
| ------------------------- | ------------------------------------------------------------------ |
| **컴포넌트 방식**         | 미리 정의된 옵션(Trigger On 등)으로 손쉽게 사운드 실행. 설정 중심. |
| **스크립트 방식**         | 다른 시스템(재질, 시간, 상태 등)과 긴밀하게 연동 가능. 로직 중심.  |
| **Global Game Sync**      | RTPC, State 등 전역적인 사운드 변화 제어에 사용.                   |
| **Game Object Game Sync** | Switch, Event 등 개별 오브젝트별 사운드 제어에 사용.               |

---

### 🎯 결론 요약

- 단순히 사운드를 트리거하고 싶다면 **Wwise 컴포넌트**를 사용하자.
- 다른 시스템과 연결하거나 조건별로 사운드를 제어해야 한다면 **사용자 정의 스크립트**를 제작하자.
- 그리고 항상 기억할 것:
  🔸 **“이 Game Sync는 전역적인가? 개별 오브젝트에 속하는가?”**
