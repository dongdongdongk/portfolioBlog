# AJP(Apache JServ Protocol)

```jsx
정의:

	AJP는 웹 서버 (Web) (예: Apache)와 애플리케이션 서버(Was) (예: Tomcat) 사이의 통신을 위해 설계된 바이너리 프로토콜입니다.

	WEB -> WAS 로 가는 프로토콜
```

# 정리

## 웹 서버와 WAS의 통합 vs 분리

```jsx
a) Apache Tomcat의 특징:

	WEB 서버와 WAS 기능을 모두 포함

	소규모 애플리케이션에 적합

b) 대규모 엔터프라이즈 환경:

	WEB 서버와 WAS를 분리하여 사용

	이유: 보안 강화, 성능 최적화, 확장성 향상
```

## 일반적인 웹 아키텍처

```jsx
구조: 클라이언트 -> WEB -> WAS -> DB

주요 이점:

	보안: 각 계층별 접근 제어 가능

	성능: 각 서버가 특화된 작업에 집중

	확장성: 필요에 따라 특정 계층만 확장 가능
```

## IP 할당 전략

```jsx
a) WEB 서버:

	공개 IP 사용

	목적: 외부에서 직접 접근 가능

b) WAS:

	사설 IP 사용

	목적: 내부 네트워크에서만 접근 가능, 보안 강화
```

## 네트워크 구성 및 방화벽

```jsx
a) 네트워크 구성:

	WEB 서버: DMZ(Demilitarized Zone)에 위치

	WAS와 DB: 내부 네트워크에 위치

b) 방화벽 확인:

	부적절한 방법: tracepath (네트워크 경로 추적용)

	적절한 방법:

		nmap: 포트 스캔

		telnet: 특정 포트 연결 테스트
```

## WEB 서버의 주요 기능

```jsx
정적 콘텐츠 제공 (HTML, CSS, 이미지 등)

로드 밸런싱

SSL/TLS 암호화

기본적인 보안 기능 제공

예시: Apache HTTP Server, Nginx
```

## WAS(Web Application Server)의 주요 기능

```jsx
동적 콘텐츠 생성

비즈니스 로직 처리

데이터베이스 연동

예시: Tomcat, JBoss
```

## WEB 서버와 WAS 분리의 이점

```jsx
a) 보안 강화:

	WAS를 직접적인 외부 접근으로부터 보호

	다층 방어 전략 구현 가능

b) 성능 최적화:

	WEB 서버: 정적 콘텐츠 처리에 특화

	WAS: 동적 콘텐츠 및 비즈니스 로직 처리에 집중

c) 확장성 향상:

	트래픽 증가 시 필요한 계층만 독립적으로 확장 가능

	자원의 효율적 사용
```

## 규모에 따른 구조 선택

```jsx
a) 대규모 시스템:

	WEB 서버와 WAS 분리

	이유: 보안, 성능, 확장성 최적화

b) 소규모 애플리케이션:

	Apache Tomcat과 같은 통합 솔루션 사용

	이유: 구조 단순화, 관리 용이성
```
