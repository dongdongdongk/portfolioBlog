# { 📁 프로젝트 구조 }

```jsx
src/
├── app/                    # Next.js 애플리케이션의 핵심 폴더
│   ├── [locale]/           # 다국어 라우팅을 위한 동적 경로
│   │   ├── layout.tsx      # 전체 페이지의 기본 레이아웃
│   │   ├── page.tsx        # 메인 페이지 (홈)

├── components/             # 재사용 가능한 UI 컴포넌트

├── messages/               # 번역 파일
│   ├── en.json             # 영어 번역
│   ├── ko.json             # 한국어 번역
│   └── ja.json             # 일본어 번역
├── styles/                 # CSS 스타일
│   └── globals.scss        # 전역 스타일
└── middleware.ts           # 다국어 라우팅을 처리하는 미들웨어
```

## 1. 각 폴더/파일의 역할

```jsx
app/: Next.js의 App Router를 사용하여 페이지와 라우팅을 관리합니다. [locale] 폴더는 동적 경로로, /en, /ko, /ja 같은 언어별 URL을 처리합니다.

components/: 버튼, 헤더 등 여러 페이지에서 재사용할 수 있는 UI 컴포넌트를 저장합니다.

i18n/: 다국어(Internationalization) 설정을 관리합니다.

messages/: 각 언어별 번역 텍스트를 JSON 파일로 저장합니다.

styles/: 앱의 디자인을 위한 CSS 스타일을 정의합니다.

middleware.ts: 사용자의 요청을 받아 언어별로 올바른 페이지를 라우팅합니다.
```

## 1. 언어 설정 (src/i18n/config.ts)

```jsx
export const locales = ['en', 'ko', 'ja'] as const;
export type Locale = typeof locales[number];
export const defaultLocale: Locale = 'en';

export const localeNames = {
  en: 'English',     // 🇺🇸
  ko: '한국어',       // 🇰🇷
  ja: '日本語'        // 🇯🇵
} as const;
```

```jsx
export const locales = ['en', 'ko', 'ja'] as const;

		지원하는 언어 코드를 배열로 정의합니다: 'en'(영어), 'ko'(한국어), 'ja'(일본어).

export:

		다른 파일에서 이 변수를 사용할 수 있게 합니다.

const:

		변수의 값을 변경할 수 없게 합니다.

as const:

		TypeScript에서 배열을 **읽기 전용 튜플(Readonly Tuple)**로 만듭니다. 이로 인해 TypeScript는 값을 'en' | 'ko' | 'ja'로 제한합니다.

export type Locale = typeof locales[number];

		Locale라는 타입을 정의합니다. typeof locales[number]는 배열 locales의 각 요소 타입('en', 'ko', 'ja')을 가져옵니다.

결과: Locale는 'en' | 'ko' | 'ja'라는 유니온 타입이 됩니다.

export const defaultLocale: Locale = 'en';

		기본 언어를 영어('en')로 설정합니다. 사용자가 언어를 지정하지 않으면 영어로 표시됩니다.

export const localeNames = { ... } as const;

		언어 코드와 표시 이름을 매핑합니다. 예: 'en' → 'English'.

as const:

		객체를 읽기 전용으로 만들어 TypeScript가 키와 값을 고정된 타입으로 추론하게 합니다.
```

### 초보자를 위한 추가 설명

```jsx
TypeScript란?:

		JavaScript에 타입을 추가한 언어로, 코드에서 실수를 줄이는 데 도움을 줍니다.

		예를 들어, Locale 타입은 변수가 'en', 'ko', 'ja'만 가질 수 있도록 제한합니다.

왜 as const를 사용할까?:

		일반 배열이나 객체는 TypeScript에서 값이 바뀔 수 있다고 가정합니다.

		as const를 사용하면 값이 고정된 상수로 간주되어 더 엄격한 타입 검사를 할 수 있습니다.
```

## 2. 라우팅 구조

```jsx
/                  → 영어(/en)로 리다이렉트
/en                → 영어 (기본)
/ko                → 한국어
/ja                → 일본어
```

```jsx
URL 경로에 언어 코드(/en, /ko, /ja)를 포함해 각 언어로 페이지를 제공합니다.

루트 URL(/)은 기본 언어인 영어(/en)로 리다이렉트됩니다.

[locale] 폴더와 미들웨어가 이를 처리합니다.
```

## 3. 미들웨어 설정 (src/middleware.ts)

```jsx
import createMiddleware from 'next-intl/middleware'
import { locales, defaultLocale } from './i18n/config'

export default createMiddleware({
  locales,
  defaultLocale,
  localePrefix: 'always', // 모든 URL에 언어 접두어 포함
})
```

```jsx
import createMiddleware from 'next-intl/middleware';

		next-intl 라이브러리에서 다국어 라우팅을 처리하는 함수를 가져옵니다.

import { locales, defaultLocale } from './i18n/config';

		i18n/config.ts에서 locales 배열과 defaultLocale을 가져옵니다.

export default createMiddleware({ ... });

		모든 요청에 대해 실행되는 미들웨어 함수를 생성합니다.

		locales: 지원하는 언어 목록을 제공합니다.

		defaultLocale: 기본 언어('en')를 지정합니다.

		localePrefix: 'always': 모든 URL에 언어 접두어(예: /en)를 포함하도록 설정합니다.
```

## 언어 선택은 어떻게 이루어지나?

```jsx
JsonFormatter.tsx 등에는 코드 자체는 언어 선택 로직을 포함하지 않지만,

다국어 지원은 프로젝트 구조와 next-intl 라이브러리를 통해 구현됩니다.

	언어 선택은 주로 URL 경로와 LanguageSelector 컴포넌트를 통해 처리됩니다. 아래에서 이를 상세히 설명합니다.
```

### 1. URL 기반 언어 선택

```jsx
라우팅 구조:

		프로젝트 구조에서 src/app/[locale] 폴더는 동적 경로로, 언어 코드(en, ko, ja)를 URL에 포함합니다.

		예:

				/en: 영어

				/ko: 한국어

				/ja: 일본어

		사용자가 /ko/formatter에 접속하면 JsonFormatter 컴포넌트가 한국어 번역(ko.json)을 사용하여 렌더링됩니다.



미들웨어 역할 (src/middleware.ts):

import createMiddleware from 'next-intl/middleware';
import { locales, defaultLocale } from './i18n/config';

export default createMiddleware({
  locales, // ['en', 'ko', 'ja']
  defaultLocale, // 'en'
  localePrefix: 'always' // URL에 항상 언어 접두어 포함
});

미들웨어는 사용자의 요청 URL을 확인하여 언어를 결정합니다.

예: /에 접속하면 defaultLocale인 /en으로 리다이렉트됩니다.

브라우저의 언어 설정(예: Accept-Language 헤더)을 참고하여 적절한 언어로 리다이렉트할 수도 있습니다.
```

### 언어 선택의 전체 흐름

```jsx
URL에서 언어 결정:

		사용자가 /ko/formatter에 접속하면 미들웨어가 locale = 'ko'로 설정하고, next-intl이 ko.json을 로드합니다.

번역 적용:

		JsonFormatter에서 useTranslations('formatter')가 ko.json의 번역을 사용하여 UI를 렌더링합니다.

언어 변경:

		사용자가 LanguageSelector에서 "日本語"를 선택하면, URL이 /ja/formatter로 바뀌고, ja.json의 번역이 로드됩니다.

		예: t('title')가 "JSON Formatter & TypeScript Interface Generator"(영어)에서

		"JSONフォーマッター＆TypeScriptインターフェースジェネレーター"(일본어)로 변경됩니다.

자동 감지:

		미들웨어는 브라우저의 언어 설정을 참조하여 초기 언어를 결정할 수 있습니다(예: 한국어 브라우저 → /ko).
```

### 초보자를 위한 추가 설명

```jsx
다국어 지원의 핵심:

		next-intl은 URL의 언어 코드([locale])와 번역 파일(messages/.*.json)을 연결하여 자동으로 적절한 언어를 로드합니다.

		useTranslations은 현재 언어에 맞는 텍스트를 쉽게 가져옵니다.

언어 선택 UI:

		LanguageSelector는 사용자가 언어를 직접 변경할 수 있는 인터페이스입니다.

		드롭다운, 버튼, 또는 링크 형태로 구현될 수 있습니다.

URL 기반 라우팅:

		Next.js의 동적 경로([locale])를 사용하면 언어별로 별도의 페이지를 만들지 않아도 됩니다.

		미들웨어가 URL을 분석하여 언어를 결정합니다.

왜 LanguageSelector가 JsonFormatter에 없나?

		JsonFormatter는 JSON 처리 UI에 집중하고, 언어 선택은 보통 헤더나 푸터 같은 공통 컴포넌트에서 처리됩니다.

		이는 코드의 책임 분리(Separation of Concerns)를 위한 설계입니다.
```

# { 핵심 컴포넌트 구현 }

## 1. JSON 포맷터 로직 (JsonFormatter.tsx)

```jsx
이 컴포넌트는 JSON 입력을 처리하고 TypeScript 인터페이스를 생성하는 핵심 기능입니다.
```

### 주요 기능

```jsx
실시간 JSON 검증 및 포맷팅

JSON을 기반으로 TypeScript 인터페이스 자동 생성

에러 처리 및 사용자 피드백

포맷된 출력 복사 및 다운로드 지원
```

```jsx
// React의 useCallback 훅을 사용하여 함수를 메모이제이션합니다.
// 이는 컴포넌트가 불필요하게 다시 렌더링될 때 함수가 새로 생성되지 않도록 합니다.
// 매개변수: input (사용자가 입력한 JSON 문자열), name (TypeScript 인터페이스 이름)
// 두 번째 인자 []는 의존성 배열로, 이 함수가 의존하는 상태나 변수가 없음을 의미합니다.
const formatJson = useCallback((input: string, name: string) => {
  // try-catch 블록으로 JSON 파싱 중 발생할 수 있는 에러를 처리합니다.
  try {
    // JSON.parse: 문자열 형태의 JSON을 JavaScript 객체로 변환합니다.
    // 예: '{"name": "John"}' → { name: "John" }
    const parsed = JSON.parse(input);

    // JSON.stringify: JavaScript 객체를 JSON 문자열로 변환합니다.
    // 두 번째 인자 null은 replacer 함수(사용 안 함)를 의미하고,
    // 세 번째 인자 2는 들여쓰기 공백 수를 지정하여 가독성 있게 포맷합니다.
    // 예: { name: "John" } → '{\n  "name": "John"\n}'
    const formatted = JSON.stringify(parsed, null, 2);

    // setFormattedJson: React 상태를 업데이트하여 포맷된 JSON을 저장합니다.
    // 이 상태는 UI에 포맷된 JSON을 표시하는 데 사용됩니다.
    setFormattedJson(formatted);

    // generateTypeScriptInterface 함수를 호출하여 JSON 객체를 기반으로
    // TypeScript 인터페이스를 생성합니다. name은 인터페이스 이름으로 사용됩니다.
    const tsInterface = generateTypeScriptInterface(parsed, name);

    // setTypescriptInterface: 생성된 인터페이스를 상태에 저장하여 UI에 표시합니다.
    setTypescriptInterface(tsInterface);

    // setError: 이전에 발생한 에러가 있다면 지웁니다. 에러가 없음을 나타냅니다.
    setError('');
  } catch (err) {
    // try 블록에서 에러가 발생하면 이 catch 블록이 실행됩니다.
    // err instanceof Error: 에러 객체가 Error 클래스의 인스턴스인지 확인합니다.
    // 참이면 err.message(에러 메시지)를 사용하고, 아니면 기본 메시지 'JSON 파싱 오류'를 설정합니다.
    // 예: 잘못된 JSON 입력 시 "Unexpected token" 같은 메시지가 표시됩니다.
    setError(err instanceof Error ? err.message : 'JSON 파싱 오류');
  }
}, []); // 빈 배열: 이 함수는 외부 상태에 의존하지 않으므로 재생성되지 않습니다.

// JSON 객체를 받아 TypeScript 인터페이스 문자열을 생성하는 함수입니다.
// obj: JSON에서 파싱된 JavaScript 객체
// name: 생성할 인터페이스의 이름 (예: "User")
// 반환값은 문자열 형태의 TypeScript 인터페이스 코드입니다.
const generateTypeScriptInterface = (obj: any, name: string): string => {
  // getType: 재귀적으로 값의 TypeScript 타입을 결정하는 내부 함수입니다.
  // value: 타입을 확인할 값 (객체, 배열, 기본 타입 등)
  // depth: 들여쓰기 수준 (중첩된 객체를 포맷팅하기 위해 사용)
  // 반환값은 TypeScript 타입을 나타내는 문자열입니다.
  const getType = (value: any, depth = 0): string => {
    // indent: 현재 depth에 맞는 공백 문자열을 생성합니다.
    // 예: depth가 1이면 "  " (2칸 공백), 2이면 "    " (4칸 공백)
    const indent = '  '.repeat(depth);

    // 값이 null인 경우 TypeScript 타입으로 'null'을 반환합니다.
    if (value === null) return 'null';

    // Array.isArray: 값이 배열인지 확인합니다.
    // 배열인 경우, 배열의 첫 번째 요소의 타입을 기반으로 타입을 결정합니다.
    if (Array.isArray(value)) {
      // 배열이 비어 있으면 'any[]'를 반환합니다 (어떤 타입의 배열인지 알 수 없음).
      if (value.length === 0) return 'any[]';
      // 첫 번째 요소의 타입을 재귀적으로 확인합니다.
      // 예: ["hello"] → getType("hello") → "string" → "string[]"
      const itemType = getType(value[0], depth);
      return `${itemType}[]`; // 배열 타입을 반환 (예: "string[]")
    }

    // typeof value === 'object': 값이 객체인지 확인합니다 (null은 제외).
    if (typeof value === 'object') {
      // Object.entries: 객체의 키-값 쌍을 배열로 반환합니다.
      // 예: { name: "John" } → [["name", "John"]]
      // map을 사용해 각 속성을 TypeScript 속성으로 변환합니다.
      const properties = Object.entries(value)
        .map(([key, val]) => {
          // 재귀적으로 속성 값의 타입을 구합니다 (depth + 1로 들여쓰기 증가).
          // 예: "name: string;"
          return `${indent}  ${key}: ${getType(val, depth + 1)};`;
        })
        // join('\n'): 속성들을 줄바꿈으로 연결하여 문자열로 만듭니다.
        // 예: "  name: string;\n  age: number;"
        .join('\n');
      // 객체 타입을 중괄호로 감싸고 들여쓰기를 추가합니다.
      // 예: "{\n  name: string;\n}"
      return `{\n${properties}\n${indent}}`;
    }

    // 기본 타입 (string, number, boolean 등)을 반환합니다.
    // 예: "hello" → "string", 42 → "number"
    return typeof value;
  };

  // 최종적으로 인터페이스 문자열을 반환합니다.
  // 예: "interface User { name: string; }"
  return `interface ${name} ${getType(obj)}`;
};
```

### 초보자를 위한 추가 설명

```jsx
JSON이란?: 데이터를 저장하고 교환하는 형식. 예: {"name": "홍길동"}.

TypeScript 인터페이스: 객체의 구조를 정의합니다. 예: interface User { name: string; }.

React 훅: useCallback은 함수가 매번 새로 생성되지 않도록 하여 성능을 최적화합니다.

재귀(Recursion): getType 함수가 자신을 호출하여 중첩된 객체와 배열을 처리합니다.
```

## 2. SSR 문제 해결 (JsonFormatterClient.tsx)

```jsx
// Next.js의 dynamic 함수를 가져옵니다.
// dynamic은 컴포넌트를 필요할 때만 로드하는 "지연 로딩(lazy loading)"을 구현하는 데 사용됩니다.
import dynamic from 'next/dynamic'

// JsonFormatter 컴포넌트를 동적으로 임포트합니다.
// () => import('./JsonFormatter'): JsonFormatter.tsx 파일을 비동기적으로 가져옵니다.
// loading: 컴포넌트가 로드되는 동안 표시할 UI를 정의합니다.
// ssr: false: 서버 사이드 렌더링을 비활성화하여 수화(hydration) 에러를 방지합니다.
const JsonFormatter = dynamic(() => import('./JsonFormatter'), {
  // 로딩 중일 때 표시할 JSX를 반환합니다.
  // 사용자가 컴포넌트 로딩을 기다리는 동안 "JSON 포맷터를 로딩 중..."이라는 메시지를 봅니다.
  loading: () => <div>JSON 포맷터를 로딩 중...</div>,

  // ssr: false는 이 컴포넌트가 서버에서 렌더링되지 않도록 설정합니다.
  // 즉, 클라이언트(브라우저)에서만 렌더링됩니다.
  // 이는 서버와 클라이언트 간 HTML 불일치로 인한 수화 에러를 방지합니다.
  ssr: false,
})

// JsonFormatterClient라는 기본 컴포넌트를 내보냅니다.
// 이 컴포넌트는 동적으로 로드된 JsonFormatter 컴포넌트를 렌더링하는 래퍼(wrapper) 역할을 합니다.
export default function JsonFormatterClient() {
  // JsonFormatter 컴포넌트를 JSX로 반환하여 화면에 표시합니다.
  // 동적 임포트로 로드된 JsonFormatter가 여기서 실제로 렌더링됩니다.
  return <JsonFormatter />
}
```

```jsx

수화(Hydration) 에러: 서버와 클라이언트에서 렌더링된 HTML이 달라 발생하는 문제입니다. ssr: false로 이를 방지합니다.

지연 로딩: 페이지 로드 시간을 줄이기 위해 필요한 시점에만 코드를 로드합니다.
```

## 2. 사이트맵 생성 (sitemap.ts)

export default function sitemap(): MetadataRoute.Sitemap {
  const baseUrl = 'https://jsonformatter.roono.net';

  return locales.flatMap(locale =>
    pages.map(page => ({
      url: `${baseUrl}/${locale}${page}`,
      lastModified: new Date(),
      changeFrequency: 'weekly',
      priority: page === '' ? 1 : 0.8,
    }))
  );
}
