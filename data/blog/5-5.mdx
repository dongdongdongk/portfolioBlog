# { 🎮 Yaw (요) 제어 구현하기 }

## 🎯 목표

전투기 좌우 회전(Yaw) 조종 구현

- E 키: 오른쪽 회전
- Q 키: 왼쪽 회전
- Rudder(방향타) 사용

---

## 💡 핵심 개념: Yaw란?

### 3가지 회전축 완성

```
Pitch (Y축): 상하 회전 ✅
Roll (X축): 굴림 회전 ✅
Yaw (Z축): 좌우 회전 ✅ (이번 강의)
```

**Yaw 비유:**

```
비행기를 위에서 봤을 때
  ↓
기수가 왼쪽/오른쪽으로 회전
  ↓
헬리콥터의 꼬리 로터와 유사
```

---

## 🔧 1단계: Rudder(방향타) 확인

### Skeletal Mesh에서 찾기

```
F18_Skeletal_Mesh 열기
  ↓
검색: "rudder"
  ↓
발견: Rudder 뼈대
  ↓
Z축 회전 테스트 (파란색 축)
```

**Rudder란?**

```
위치: 꼬리 수직 날개
역할: 좌우 회전 제어
회전축: Z축 (Yaw) ✅
```

---

## 🔧 2단계: Input Action 생성

### IA_Yaw 생성

```
Input 폴더 → 우클릭
  ↓
Input → Input Action
  ↓
이름: IA_Yaw
```

### Value Type 설정

```
IA_Yaw 더블클릭
  ↓
Value Type: Axis1D
  ↓
저장 & 닫기
```

---

## 🔧 3단계: IMC 매핑

### E 키 매핑

```
IMC_FighterJet 열기
  ↓
+ Mapping → IA_Yaw
  ↓
키: E
  ↓
기본값: 1.0 (오른쪽 회전)
```

### Q 키 매핑 (음수)

```
+ 버튼으로 추가 매핑
  ↓
키: Q
  ↓
Modifiers → + Add → Negate
  ↓
값: -1.0 (왼쪽 회전)
```

---

## 🔧 4단계: Blueprint 구성

### Triggered 이벤트

```
[IA_Yaw] Triggered
  ↓
[Set Yaw Input]
  ├─ Target: Vehicle Movement Component
  └─ Yaw: Action Value
```

### 첫 번째 테스트

```
게임 실행 → 이륙
  ↓
E 키 누름:
  오른쪽으로 회전 ✅
  ↓
하지만 E 떼도:
  계속 회전 ❌
```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380605/notion-blog/_/_/BG/5/image.png)

---

## 🔧 5단계: Completed 이벤트 추가

### 중립 복귀

```
[IA_Yaw] Completed
  ↓
[Set Yaw Input]
  ├─ Target: Vehicle Movement Component
  └─ Yaw: 0.0
```

---

## ⚠️ 발견된 문제

### Rudder가 움직이지 않음

```
E/Q 입력:
  비행기는 회전함 ✅
  ↓
하지만:
  Rudder는 정지 상태 ❌
  ↓
시각적 피드백 없음
```

---

## 📝 현재 상태 정리

### 구현 완료

```
✅ IA_Yaw 생성
✅ E/Q 키 매핑
✅ Set Yaw Input
✅ Completed로 중립 복귀
✅ 좌우 회전 작동
```

### 미완성

```
⏳ Rudder 애니메이션 없음
⏳ 부드러운 변화 없음 (스냅)
⏳ FInterp To 미적용
⏳ Timeline 미적용
```

---

## 💡 Pitch/Roll/Yaw 비교

### 완전히 동일한 패턴!

```
공통 구조:
  1. Input Action (Axis1D)
  2. IMC 매핑 (하나는 Negate)
  3. Set Input (Triggered)
  4. 0으로 복귀 (Completed)

차이점:
  - Pitch: W/S, Set Pitch Input
  - Roll: A/D, Set Roll Input
  - Yaw: E/Q, Set Yaw Input ✅
```

---

## 🎯 핵심 요약

**Yaw 기본 구현 완료:**

```
✅ IA_Yaw (Axis1D)
✅ E: +1.0 / Q: -1.0
✅ Set Yaw Input
✅ Completed 중립 복귀
✅ 좌우 회전 가능
```

**다음 단계:**

```
1. Yaw_Value 변수 추가
2. Rudder 애니메이션
3. FInterp To (부드럽게)
4. Timeline (중립 복귀)
```

기본 **Yaw 제어 작동** 완료! (시각화만 남음) 🛩️

# { 🎮 Rudder(방향타) 애니메이션 구현하기 }

## 🎯 목표

Yaw 조작 시 Rudder가 실제로 움직이도록 구현

- 좌우 Rudder 회전
- Rotation Z (Yaw) 축 사용
- 적절한 각도 조정

---

## 🔧 1단계: BP_F18에 Yaw_Value 변수 생성

### 변수 생성 및 저장

```
BP_F18 → Variables
  ↓
+ 버튼
  ↓
이름: Yaw_Value
타입: Float
```

### IA_Yaw에 연결

```
[IA_Yaw] Triggered
  ↓
Action Value
  ├────────────────────┐
  ↓                    ↓
[SET] Yaw_Value     [Set Yaw Input]
  (Alt 드래그)        (엔진 제어)

[IA_Yaw] Completed
  ↓
[SET] Yaw_Value: 0.0
  ↓
[Set Yaw Input]: 0.0
```

```
  └─ [Get Yaw Value] → [SET] Yaw_Value (추가!)
```

**Promote to Variable:**

```
Get Yaw Value 우클릭
  ↓
Promote to Variable
  ↓
이름: Yaw_Value (ABP_F18의 변수)
```

---

## 🔧 4단계: Rudder 노드 추가

### 노드 복제

```
기존 노드 2개 선택
  ↓
Ctrl + C → Ctrl + V
  ↓
연결:
  이전 노드 → 새 Rudder 노드들 → Output
```

### Bone 설정

**왼쪽 Rudder:**

```
Transform (Modify) Bone
  ├─ Bone: lf_rudder_jnt
  └─ Rotation Z (Yaw): ? (설정 예정)
```

**오른쪽 Rudder:**

```
Transform (Modify) Bone
  ├─ Bone: rt_rudder_jnt
  └─ Rotation Z (Yaw): ? (설정 예정)
```

**왜 Rotation Z인가?**

```
Pitch: Rotation Y (상하)
Roll: Rotation Y (Elevator/Aileron)
Yaw: Rotation Z (좌우) ✅

Z축 = 파란색 축
  ↓
Rudder의 올바른 회전축
```

```
  ↓
```

## 🔧 6단계: 게임 테스트 및 방향 수정

### 첫 번째 테스트

```

  ↓

  ↓

  ↓

```

### 방향 반전 (× -50)

```
문제:
  E 키 누름 → Rudder가 반대 방향

해결:
  × 50 → × -50 (음수로 변경)
  ↓
  방향 반전 ✅
```

---

## 🔧 7단계: 각도 미세 조정

### 50은 너무 큼

```
× -50:
  너무 과도한 회전
  ↓
  비현실적

× -25:
  조금 작음
  ↓
  테스트 필요

× -30:
  적당함 ✅
  ↓
  최종 선택
```

### 최종 설정

```
양쪽 Rudder:
  [Yaw_Value] × -30
  ↓
  [Transform (Modify) Bone]
    └─ Rotation Z (Yaw)
```

**각도 선택 기준:**

```
너무 작으면:
  - 움직임이 잘 안 보임
  - 효과 미미

너무 크면:
  - 과도한 회전
  - 비현실적

적당히 (30도 내외):
  - 명확한 움직임 ✅
  - 현실적
```

```

  - Rotation Z (Yaw) ✅

```

### 좌우 Rudder 동일한 값?

```
Elevator/Aileron (Roll):
  - 좌우 반대 (× 10, × -10)
  - 양력 차이 생성

Rudder (Yaw):
  - 좌우 동일 (× -30, × -30)
  - 같은 방향 회전
  ↓
  역할이 다름!
```

### 각도 조정의 자유

```
× -20: 작은 움직임
× -30: 적당 ✅
× -40: 큰 움직임
× -50: 과도함

비행기 종류나
개인 취향에 따라 조정 가능
```

# { 🎮 Landing Gear (착륙 장치) 애니메이션 시작하기 }

## 🎯 목표

비행기 바퀴를 접고 펼치는 기능 구현

- 앞쪽 착륙 장치(Front Landing Gear) 먼저
- Transform (Modify) Bone으로 회전 제어
- Gear 변수로 0~1 범위 제어

---

## 💡 핵심 개념

### Landing Gear란?

```
착륙 장치 = 비행기 바퀴 시스템
  ↓
지상:
  - 바퀴 펼침 (Gear Down)
  - 착륙/이륙 가능

비행 중:
  - 바퀴 접음 (Gear Up)
  - 공기 저항 감소
  - 속도 향상
```

---

## 🔧 1단계: Skeletal Mesh에서 확인

### 앞쪽 Chassis 뼈대 찾기

```
F18_Skeletal_Mesh 열기
  ↓
Skeleton 탭 → 검색: "front"
  ↓
발견:
  ├─ front_chassis_0_jnt (섀시 메인)
  └─ front_chassis_rail_jnt (섀시 레일)
```

### 회전 테스트

```
front_chassis_0_jnt 선택
  ↓
Rotation Y (Pitch): 100도
  ↓
결과: 안쪽으로 접힘 ✅

front_chassis_rail_jnt 선택
  ↓
Rotation Y (Pitch): 30도
  ↓
결과: 레일도 접힘 ✅
```

**왜 Pitch(Y축) 회전인가?**

```
바퀴를 접으려면:
  앞뒤로 회전 (Pitch)
  ↓
좌우 회전(Yaw): 의미 없음
굴림 회전(Roll): 의미 없음
  ↓
Pitch가 올바름 ✅
```

---

## 🔧 4단계: Gear 변수 생성

### 변수 생성

## 먼저 상황을 상상해봐요

캐릭터가 **오른쪽으로 10만큼 이동하는 애니메이션**이 이미 있어요.
여기에 "오른쪽으로 5 더 이동해!" 라는 새 명령을 추가한다고 할 때...

---

## 세 가지 모드

### 🚫 Ignore (무시)

> "몰라, 신경 안 써"

새 명령이 있어도 **완전히 무시**해버려요.
캐릭터는 원래대로 10만 이동해요.

```
원래: 10 → 결과: 10 (변화 없음)
```

---

### 🔄 Replace Existing (교체)

> "기존 건 지우고 새 걸로 써"

원래 있던 이동 값을 **완전히 덮어써요.**
오른쪽 10이었는데, 새 값 5로 바꿔치기돼요.

```
원래: 10 → 결과: 5 (교체됨)
```

💡 **언제 쓰냐면?** 특정 상황에서 캐릭터 위치를 "이 지점으로 고정!" 할 때

---

### ➕ Add to Existing (합산)

> "기존 값에 새 값을 더해"

원래 이동 값에 새 값을 **더해서** 움직여요.
10 + 5 = 15만큼 이동하게 돼요.

```
원래: 10 → 결과: 15 (합산됨)
```

💡 **언제 쓰냐면?** 걷기 애니메이션 위에 "비틀거림" 같은 **보조 움직임을 얹을 때**

---

| ------- | ------------ | ---- |

| Replace | 새 걸로 교체 | 5    |
