# { 🔑 인증 기능 구현 가이드 }

> 회원가입 / 로그인 / 현재 유저 조회 + Sentry 에러 추적

---

## 📋 이번 강의에서 구현하는 것

```
lib/appwrite.ts
├── createUser()     — 회원가입: 인증 계정 생성 + DB에 유저 저장
├── signIn()         — 로그인: 이메일/비밀번호 세션 생성
├── getCurrentUser() — 현재 로그인된 유저 정보 조회
├── getMenu()        — 메뉴 목록 조회 (카테고리/검색 필터)
└── getCategories()  — 카테고리 목록 조회
```

---

## 1. 회원가입의 두 단계

부동산 앱(구글 OAuth)과 달리, 이메일 인증은 **두 가지 작업을 동시에** 해야 합니다.

```
createUser() 실행 순서:

1. account.create()       → Appwrite 인증 시스템에 계정 생성
                            (ID/이메일/비밀번호 저장)
2. signIn()               → 가입 즉시 자동 로그인
3. avatars.getInitialsURL() → 이름으로 이니셜 아바타 URL 생성
4. databases.createDocument() → DB users 컬렉션에 유저 정보 저장
                                (이름/이메일/accountId/아바타)

왜 DB에도 저장하나?
  Appwrite 인증 시스템: 로그인/로그아웃만 관리
  DB users 컬렉션: 주문내역, 배송주소 등 다른 데이터와 관계 형성 가능
```

## 2. 전체 코드 + 주석

```tsx
// lib/appwrite.ts

import { Account, Avatars, Client, Databases, ID, Query } from 'react-native-appwrite'
import { CreateUserParams, SignInParams, GetMenuParams } from '@/types'

export const appwriteConfig = {
  endpoint: process.env.EXPO_PUBLIC_APPWRITE_ENDPOINT!,
  projectId: process.env.EXPO_PUBLIC_APPWRITE_PROJECT_ID!,
  platform: 'com.jsm.foodordering',
  databaseId: '...',
  userCollectionId: '...',
  categoriesCollectionId: '...',
  menuCollectionId: '...',
}

export const client = new Client()
client
  .setEndpoint(appwriteConfig.endpoint)
  .setProject(appwriteConfig.projectId)
  .setPlatform(appwriteConfig.platform)

export const account = new Account(client)
export const databases = new Databases(client)
const avatars = new Avatars(client) // 내부에서만 사용 → export 불필요

// ── 회원가입 ────────────────────────────────────────────
export const createUser = async ({ email, password, name }: CreateUserParams) => {
  try {
    // STEP 1: Appwrite 인증 계정 생성
    const newAccount = await account.create(
      ID.unique(), // 고유 ID 자동 생성
      email,
      password,
      name
    )
    if (!newAccount) throw Error

    // STEP 2: 가입 즉시 자동 로그인
    await signIn({ email, password })

    // STEP 3: 이니셜 아바타 URL 생성
    // 예: "Adrian" → "A" 이니셜이 들어간 원형 이미지 URL
    const avatarUrl = avatars.getInitialsURL(name)

    // STEP 4: DB에 유저 문서 생성 (인증 계정과 연결)
    return await databases.createDocument(
      appwriteConfig.databaseId,
      appwriteConfig.userCollectionId,
      ID.unique(),
      {
        email,
        name,
        accountId: newAccount.$id, // 인증 계정 ID — 나중에 조회 시 사용
        avatar: avatarUrl,
      }
    )
  } catch (e) {
    throw new Error(e as string)
  }
}

// ── 로그인 ──────────────────────────────────────────────
export const signIn = async ({ email, password }: SignInParams) => {
  try {
    // 이메일/비밀번호로 세션 생성 → 로그인 상태 유지
    await account.createEmailPasswordSession(email, password)
  } catch (e) {
    throw new Error(e as string)
  }
}

// ── 현재 유저 조회 ──────────────────────────────────────
export const getCurrentUser = async () => {
  try {
    // STEP 1: 현재 로그인된 인증 계정 가져오기
    const currentAccount = await account.get()
    if (!currentAccount) throw Error

    // STEP 2: accountId로 DB에서 유저 문서 찾기
    const currentUser = await databases.listDocuments(
      appwriteConfig.databaseId,
      appwriteConfig.userCollectionId,
      [Query.equal('accountId', currentAccount.$id)] // accountId가 일치하는 문서만
    )
    if (!currentUser) throw Error

    // 첫 번째(유일한) 유저 문서 반환
    return currentUser.documents[0]
  } catch (e) {
    console.log(e)
    throw new Error(e as string)
  }
}

// ── 메뉴 조회 ───────────────────────────────────────────
export const getMenu = async ({ category, query }: GetMenuParams) => {
  try {
    const queries: string[] = []

    // 카테고리 필터가 있을 때만 추가
    if (category) queries.push(Query.equal('categories', category))

    // 검색어가 있을 때만 추가
    if (query) queries.push(Query.search('name', query))

    const menus = await databases.listDocuments(
      appwriteConfig.databaseId,
      appwriteConfig.menuCollectionId,
      queries // 조건 없으면 빈 배열 → 전체 조회
    )
    return menus.documents
  } catch (e) {
    throw new Error(e as string)
  }
}

// ── 카테고리 조회 ───────────────────────────────────────
export const getCategories = async () => {
  try {
    const categories = await databases.listDocuments(
      appwriteConfig.databaseId,
      appwriteConfig.categoriesCollectionId
    )
    return categories.documents
  } catch (e) {
    throw new Error(e as string)
  }
}
```

## 3. 로그인 화면에 Sentry 연동

```tsx
// app/(auth)/signin.tsx

import * as Sentry from '@sentry/react-native'

const submit = async () => {
  const { email, password } = form
  if (!email || !password)
    return Alert.alert('Error', 'Please enter valid email address & password.')

  setIsSubmitting(true)
  try {
    await signIn({ email, password })
    router.replace('/')
  } catch (error: any) {
    Alert.alert('Error', error.message)
    Sentry.captureEvent(error) // ← 에러를 Sentry 대시보드에 전송
  } finally {
    setIsSubmitting(false)
  }
}
```

### Sentry란?

```
개발 중 에러:
  터미널/콘솔에서 바로 확인 → 문제 없음

앱 출시 후 에러:
  사용자 폰에서 발생 → 개발자는 모름 😱

Sentry가 하는 일:
  앱에서 에러 발생
      ↓
  Sentry.captureEvent(error) 호출
      ↓
  Sentry 대시보드에 자동 전송
      ↓
  개발자가 어떤 에러가, 어디서, 몇 번 났는지 확인 가능
```

---

## 4. `account.create` vs `databases.createDocument` 차이

```
account.create()
  → Appwrite 인증 시스템에 저장
  → 로그인/로그아웃/세션 관리에 사용
  → 이메일, 비밀번호, 이름만 저장

databases.createDocument()
  → Appwrite DB에 저장
  → 다른 컬렉션(주문, 배송주소 등)과 관계 형성 가능
  → accountId, 이메일, 이름, 아바타 등 커스텀 필드 저장

둘 다 필요한 이유:
  인증: account (세션 관리)
  데이터 관계: databases (주문 ↔ 유저 연결 등)
```

## 5. `getCurrentUser`의 2단계 조회

```tsx
// 1단계: 현재 세션의 인증 계정 가져오기
const currentAccount = await account.get()
// → { $id: "auth_123", email: "...", name: "..." }

// 2단계: accountId로 DB 유저 문서 찾기
const currentUser = await databases.listDocuments(databaseId, userCollectionId, [
  Query.equal('accountId', currentAccount.$id),
])
// → DB에 저장된 유저 문서 (아바타, 주문내역 관계 등 포함)

// 왜 2단계?
// account.get()은 인증 정보만 줌 → 아바타 URL 같은 커스텀 데이터 없음
// DB 조회를 통해 우리가 저장한 모든 유저 정보를 가져옴
```

## ⚠️ 흔한 에러와 해결

| 에러                                             | 원인                                                     | 해결                                                              |
| ------------------------------------------------ | -------------------------------------------------------- | ----------------------------------------------------------------- |
| "Not authorized to perform the requested action" | DB 컬렉션 권한 미설정                                    | Appwrite → 컬렉션 → Settings → Permissions → Any → CRUD 모두 허용 |
| "Session already active"                         | 회원가입 시 signIn 호출 → 세션 생성됨 → 다시 로그인 시도 | 정상 동작. 이미 로그인 상태이므로 홈으로 이동                     |
| "Password must be at least 8 characters"         | 비밀번호 8자 미만                                        | 8자 이상 입력                                                     |

---

## 🔑 핵심 요약

1. **`createUser`의 4단계** = 인증 계정 생성 → 자동 로그인 → 아바타 URL 생성 → DB에 유저 저장
2. **`account.createEmailPasswordSession`** = 이메일/비밀번호로 세션 생성 (= 로그인)
3. **`getCurrentUser`의 2단계** = 인증 계정 ID 조회 → 그 ID로 DB 유저 문서 찾기
4. **`Query.equal("accountId", id)`** = 특정 accountId와 일치하는 문서만 필터링
5. **`Sentry.captureEvent(error)`** = 에러 발생 시 Sentry 대시보드로 자동 전송
6. **동적 쿼리 배열** = 조건이 있을 때만 `push()` → 없으면 전체 조회 (`getMenu` 패턴)

## 💡 Sentry가 필요한 이유

```
개발 중:
  에러 발생 → 내 터미널에 바로 표시 → 즉시 확인 가능

앱 출시 후:
  에러 발생 → 사용자 폰에서만 발생 → 개발자는 전혀 모름 😱
  사용자 피드백: "앱이 그냥 안 돼요..." (context 없음)

Sentry 있을 때:
  에러 발생 → Sentry 대시보드에 자동 전송
  → 어떤 에러인지, 어디서 났는지, 어떤 기기인지 모두 확인 가능
```

## 3. 에러 수동 캡처 — `Sentry.captureEvent`

```tsx
// app/(auth)/signin.tsx

import * as Sentry from '@sentry/react-native'

const submit = async () => {
  try {
    await signIn({ email, password })
    router.replace('/')
  } catch (error: any) {
    Alert.alert('Error', error.message)

    // Sentry 대시보드로 에러 전송
    Sentry.captureEvent(error)
  }
}
```

> 💡 `Sentry.captureEvent()`를 catch 블록에 추가하면
> 에러 발생 시 자동으로 대시보드에 전송됩니다.
> 로그인, 회원가입, 장바구니 등 중요한 기능의 catch 블록마다 추가하세요.

## 4. Sentry 대시보드에서 볼 수 있는 정보

```
에러 하나당 제공되는 정보:
├── 에러 메시지 (예: "Session is already active")
├── 에러가 발생한 파일 + 라인 번호
├── 스택 트레이스 (에러 경로 전체)
├── 사용자 기기 (예: iPhone 13 Pro Max)
├── OS 버전 (예: iOS 18.6)
├── 발생 시각
└── 발생 횟수
```

## 5. Seer — AI 에러 해결 에이전트

Sentry의 AI 기능으로, GitHub 저장소와 연결하면 에러의 원인과 해결책을 자동으로 분석합니다.

```
사용 방법:
1. Sentry 대시보드 → 에러 클릭
2. "Find Root Cause" 버튼 클릭
3. GitHub 저장소 연결 (첫 사용 시)
4. Seer가 코드를 분석해서 원인과 해결책 제시

예시 분석 결과:
"401 Unauthorized on /account/sessions/email →
 The authentication token may be expired or invalid.
 A session already exists. Check if the user is already
 logged in before calling createEmailPasswordSession."
```

## 7. Session Replay란?

```
Session Replay:
  사용자가 에러를 만나기 직전까지 어떤 행동을 했는지
  화면 녹화처럼 재생해서 볼 수 있는 기능

웹에서는 오래전부터 지원 → 최근 모바일도 지원 시작

활용 예:
  "결제 화면에서 앱이 죽었다"는 에러가 들어옴
  → Session Replay로 사용자가 무엇을 눌렀는지 그대로 재생
  → 재현하기 어려운 버그도 쉽게 원인 파악 가능
```

## 💡 왜 Zustand인가?

|             | React Context        | Redux                     | Zustand  |
| ----------- | -------------------- | ------------------------- | -------- |
| 설정 복잡도 | 중간 (Provider 필요) | 높음 (reducer, action 등) | **낮음** |
| 코드 양     | 중간                 | 많음                      | **최소** |
| 성능        | 리렌더링 이슈 있음   | 좋음                      | **좋음** |
| 학습 난이도 | 쉬움                 | 어려움                    | **쉬움** |

> 💡 Zustand는 "그냥 JavaScript 객체"처럼 쓸 수 있습니다.

## 3. 전체 코드 + 주석

```tsx
// store/auth.store.ts

import { create } from 'zustand'
import { User } from '@/types'
import { getCurrentUser } from '@/lib/appwrite'

// 이 store에서 관리할 상태와 함수의 타입 정의
type AuthState = {
  // 상태값
  isAuthenticated: boolean // 로그인 여부
  user: User | null // 현재 유저 정보
  isLoading: boolean // 유저 정보 로딩 중 여부

  // setter 함수들
  setIsAuthenticated: (value: boolean) => void
  setUser: (user: User | null) => void
  setLoading: (loading: boolean) => void

  // 서버에서 유저 정보를 가져와 상태를 업데이트하는 함수
  fetchAuthenticatedUser: () => Promise<void>
}

// create(): Zustand 스토어 생성
// set: 상태를 업데이트하는 함수 (React의 setState와 유사)
const useAuthStore = create<AuthState>((set) => ({
  // ── 초기 상태값 ──────────────────────────────────
  isAuthenticated: false,
  user: null,
  isLoading: true, // 앱 시작 시 유저 확인 중이므로 true로 시작

  // ── setter 함수들 ─────────────────────────────────
  // set({ 키: 값 }) → 해당 키만 업데이트 (나머지는 유지)
  setIsAuthenticated: (value) => set({ isAuthenticated: value }),
  setUser: (user) => set({ user }),
  setLoading: (value) => set({ isLoading: value }),

  // ── 유저 조회 함수 ────────────────────────────────
  fetchAuthenticatedUser: async () => {
    set({ isLoading: true })
    try {
      // Appwrite에서 현재 로그인된 유저 정보 조회
      const user = await getCurrentUser()

      if (user) {
        // 유저 있음 → 로그인 상태로 업데이트
        set({ isAuthenticated: true, user: user as User })
      } else {
        // 유저 없음 → 비로그인 상태로 업데이트
        set({ isAuthenticated: false, user: null })
      }
    } catch (e) {
      console.log('fetchAuthenticatedUser error', e)
      set({ isAuthenticated: false, user: null })
    } finally {
      set({ isLoading: false }) // 성공/실패 관계없이 로딩 종료
    }
  },
}))

export default useAuthStore
```

## 4. React Context vs Zustand 비교

### React Context (부동산 앱 방식)

```tsx
// 1. Context 생성
const GlobalContext = createContext()

// 2. Provider로 전체 앱 감싸기 (필수!)
export const GlobalProvider = ({ children }) => {
  const [user, setUser] = useState(null)
  return <GlobalContext.Provider value={{ user, setUser }}>{children}</GlobalContext.Provider>
}

// 3. 사용 (Context 안에 있어야만 동작)
const { user } = useContext(GlobalContext)
```

### Zustand (음식 배달 앱 방식)

```tsx
// 1. store 생성 (auth.store.ts에서 한 번만)

// 2. Provider 불필요 — 그냥 import해서 바로 사용
const { user, isAuthenticated } = useAuthStore()
// 어느 컴포넌트에서든, Provider 밖에서도 동작
```

## 새로 나온 것 — 플로팅 탭바 스타일

부동산 앱에서는 탭바가 화면 하단에 붙어 있었지만, 이번 앱은 **떠 있는(floating) 탭바**를 만듭니다.

```
일반 탭바:                 플로팅 탭바:
┌──────────────┐           ┌──────────────┐
│              │           │              │
│    화면       │           │    화면       │
│              │           │              │
├──────────────┤           │  ╭────────╮  │  ← 둥근 모서리 + 공중에 떠 있음
│ 🏠 🔍 🛒 👤 │           │  │🏠🔍🛒👤│  │
└──────────────┘           │  ╰────────╯  │
                           └──────────────┘
```

**핵심 CSS 속성:**

```tsx
tabBarStyle: {
  borderRadius: 50,       // 모든 모서리 둥글게
  marginHorizontal: 20,   // 좌우 여백 → 화면 너비보다 좁아짐
  position: "absolute",   // 화면 레이어 위에 올라옴
  bottom: 40,             // 아래에서 40px 띄움
}
```

**그림자 iOS vs Android:**

```tsx
// iOS 그림자
shadowColor: "#1a1a1a",
shadowOffset: { width: 0, height: 2 },  // 아래쪽으로 2px 그림자
shadowOpacity: 0.1,
shadowRadius: 4,

// Android 그림자 (iOS 속성과 별개로 설정 필요)
elevation: 5,
```

> ⚠️ React Native에서는 iOS와 Android의 그림자 설정이 다릅니다.
> iOS는 `shadow*` 속성을, Android는 `elevation` 속성을 씁니다.

---

## 탭바 하단 여백 문제

탭바가 `position: absolute`이면 콘텐츠 위에 떠 있어서 **FlatList의 마지막 항목이 탭바에 가릴 수 있습니다.**

```tsx
// 해결: contentContainerClassName에 pb(padding-bottom)를 탭바 높이 이상으로 설정
<FlatList
  contentContainerClassName="pb-28" // 탭바(80px) + 여백(40px) = 120px 이상
/>
```

---

## 🔑 핵심 요약

1. **플로팅 탭바** = `position: absolute` + `bottom: 40` + `marginHorizontal: 20` + `borderRadius: 50`
2. **그림자** = iOS는 `shadow*` 속성, Android는 `elevation` (둘 다 설정해야 함)
3. **`tabBarShowLabel: false`** = 기본 라벨 숨기고 `TabBarIcon`에서 직접 텍스트 렌더링
4. **콘텐츠 가림 방지** = `contentContainerClassName="pb-28"` 등으로 하단 여백 확보

> 카테고리 → 메뉴 → 커스터마이제이션 → 조인 테이블까지

## 📋 전체 컬렉션 구조

```
DB: app
├── users                  ← 로그인 유저 정보 (이전 강의에서 생성)
├── categories             ← 음식 카테고리 (버거, 피자 등)
├── menu                   ← 개별 메뉴 아이템
├── customizations         ← 재사용 가능한 옵션 (토핑, 사이드 등)
└── menu_customizations    ← 메뉴 ↔ 옵션 연결 테이블 (조인 테이블)

Storage:
└── assets bucket          ← 메뉴 이미지 파일 저장
```

---

## 1. categories 컬렉션

```
메뉴를 카테고리로 묶어서 필터링을 쉽게 만들기 위한 컬렉션
```

| 속성          | 타입         | 필수 | 설명                              |
| ------------- | ------------ | ---- | --------------------------------- |
| `name`        | String (100) | ✅   | 카테고리 이름 (Burgers, Pizza 등) |
| `description` | String (100) | ✅   | 카테고리 설명                     |

---

## 2. menu 컬렉션

```
각 음식 아이템의 모든 정보를 담는 핵심 컬렉션
```

| 속성          | 타입              | 필수 | 설명                   |
| ------------- | ----------------- | ---- | ---------------------- |
| `name`        | String (200)      | ✅   | 메뉴 이름              |
| `description` | String (2000)     | ✅   | 메뉴 설명              |
| `image_url`   | URL               | ✅   | 이미지 URL             |
| `rating`      | Float             | ✅   | 평점 (1~5)             |
| `calories`    | Integer (1~10000) | ✅   | 칼로리                 |
| `protein`     | Integer (0~10000) | ✅   | 단백질(g)              |
| `price`       | Float (1~10000)   | ✅   | 가격                   |
| `categories`  | Relationship      | ✅   | 카테고리 연결 (다대일) |

**관계 설정:**

```
menu → categories: 다대일 (many-to-one)
메뉴 아이템 하나는 카테고리 하나에 속함
하나의 카테고리에 여러 메뉴 아이템이 속할 수 있음
```

---

## 3. customizations 컬렉션

```
옵션(토핑, 사이드 등)을 별도 컬렉션으로 분리해서 재사용

이렇게 하는 이유:
  감자튀김 가격이 $3 → $5로 바뀌면?
  ✅ customizations 컬렉션 한 곳만 수정하면 전체 반영
  ❌ 각 메뉴마다 직접 수정 → 실수 발생 가능
```

| 속성    | 타입            | 필수 | 설명                        |
| ------- | --------------- | ---- | --------------------------- |
| `name`  | String (100)    | ✅   | 옵션 이름 (Extra Cheese 등) |
| `price` | Float (1~10000) | ✅   | 추가 가격                   |
| `type`  | Enum            | ✅   | 옵션 종류                   |

**type Enum 선택지:**

```
Topping / Side / Size / Crust / Bread / Spice / Base / Sauce
```

---

## 4. menu_customizations 컬렉션 (조인 테이블)

### 왜 필요한가? — 다대다(Many-to-Many) 관계

```
문제:
  버거에는 Extra Cheese 옵션이 있음
  피자에도 Extra Cheese 옵션이 있음
  → Extra Cheese는 여러 메뉴에 속할 수 있음

  버거에는 여러 옵션이 있음
  → 하나의 메뉴에도 여러 옵션이 있을 수 있음

  결론: 메뉴와 옵션은 "다대다" 관계
```

```
다대다 관계를 직접 연결하면:
  menu.customizations = [Extra Cheese, Fries, Coke, ...]
  → 같은 데이터가 여러 메뉴에 중복 저장 → 비효율적

조인 테이블(menu_customizations)로 해결:
  menu_customizations 레코드 하나 = (메뉴 하나, 옵션 하나)
  예: { menu: "버거", customization: "Extra Cheese" }
      { menu: "버거", customization: "Fries" }
      { menu: "피자", customization: "Extra Cheese" }
```

| 속성             | 타입         | 설명               |
| ---------------- | ------------ | ------------------ |
| `menu`           | Relationship | 연결된 메뉴 아이템 |
| `customizations` | Relationship | 연결된 옵션        |

**관계 설정:**

```
menu_customizations → menu:           다대일 (cascade 삭제)
menu_customizations → customizations: 다대일 (cascade 삭제)
```

## 새로 나온 것 — Appwrite Storage 업로드

부동산 앱에서는 이미지를 Unsplash URL로 저장했지만, 이번 앱은 이미지를 **Appwrite Storage 버킷에 직접 업로드**합니다.

```tsx
// lib/appwrite.ts에 추가
```

## 1. SearchBar 컴포넌트

### 왜 디바운싱 대신 submit 방식인가?

```
디바운싱 방식 문제:
  FlatList의 ListHeaderComponent 안에 TextInput 넣으면
  → 키스트로크마다 FlatList 리렌더링
  → 키보드가 자동으로 닫히는 버그 발생 (React Native 알려진 이슈)

해결책: 사용자가 엔터/검색 버튼 누를 때만 URL 업데이트
  → 타이핑 중에는 local state만 업데이트
  → 키보드 유지
```

```tsx
// components/SearchBar.tsx

import { images } from '@/constants'
import { router, useLocalSearchParams } from 'expo-router'
import { useState } from 'react'
import { Image, TextInput, TouchableOpacity, View } from 'react-native'

const SearchBar = () => {
  const params = useLocalSearchParams<{ query?: string }>()

  // local state: 타이핑 즉시 반영 (화면에 보이는 텍스트)
  const [query, setQuery] = useState(params.query)

  const handleSearch = (text: string) => {
    setQuery(text) // 즉시 입력창 업데이트
    if (!text) router.setParams({ query: undefined }) // 빈 값이면 URL 파라미터 제거
  }

  // 엔터 키 눌렀을 때 실행
  const handleSubmit = () => {
    if (query?.trim()) router.setParams({ query }) // URL 파라미터 업데이트 → 검색 실행
  }

  return (
    <View className="searchbar">
      <TextInput
        className="flex-1 p-5"
        placeholder="Search for pizzas, burgers..."
        value={query}
        onChangeText={handleSearch}
        onSubmitEditing={handleSubmit} // 엔터 키 → handleSubmit 실행
        placeholderTextColor="#A0A0A0"
        returnKeyType="search" // 키보드 엔터 버튼에 "search" 표시
      />
      {/* 검색 아이콘 버튼 — 클릭 시 URL 파라미터 업데이트 */}
      <TouchableOpacity className="pr-5" onPress={() => router.setParams({ query })}>
        <Image source={images.search} className="size-6" resizeMode="contain" tintColor="#5D5F6D" />
      </TouchableOpacity>
    </View>
  )
}

export default SearchBar
```

### `onSubmitEditing` + `returnKeyType`

```tsx
// 엔터 키를 눌렀을 때 실행할 함수

// 키보드 엔터 버튼 모양 변경
```

## 2. Filter 컴포넌트

```tsx
// components/Filter.tsx

import { Category } from '@/types'
import { router, useLocalSearchParams } from 'expo-router'
import { useState } from 'react'
import { FlatList, Platform, Text, TouchableOpacity } from 'react-native'
import cn from 'clsx'

const Filter = ({ categories }: { categories: Category[] }) => {
  const searchParams = useLocalSearchParams()

  // 현재 선택된 카테고리 (URL 파라미터에서 초기값 읽기)
  const [active, setActive] = useState(searchParams.category || '')

  const handlePress = (id: string) => {
    setActive(id)
    if (id === 'all')
      router.setParams({ category: undefined }) // 전체 선택 → 필터 제거
    else router.setParams({ category: id }) // 특정 카테고리 선택
  }

  // "All" 옵션을 맨 앞에 추가 + 실제 카테고리 목록 이어붙이기
  const filterData: (Category | { $id: string; name: string })[] = categories
    ? [{ $id: 'all', name: 'All' }, ...categories]
    : [{ $id: 'all', name: 'All' }]

  return (
    <FlatList
      data={filterData}
      keyExtractor={(item) => item.$id}
      horizontal // 가로 스크롤
      showsHorizontalScrollIndicator={false}
      contentContainerClassName="gap-x-2 pb-3"
      renderItem={({ item }) => (
        <TouchableOpacity
          key={item.$id}
          className={cn(
            'filter',
            active === item.$id ? 'bg-amber-500' : 'bg-white' // 선택 시 주황색
          )}
          style={Platform.OS === 'android' ? { elevation: 5, shadowColor: '#878787' } : {}}
          onPress={() => handlePress(item.$id)}
        >
          <Text className={cn('body-medium', active === item.$id ? 'text-white' : 'text-gray-200')}>
            {item.name}
          </Text>
        </TouchableOpacity>
      )}
    />
  )
}

export default Filter
```

## 3. Zustand 장바구니 스토어

### 장바구니의 핵심 문제 — 유니크한 아이템이란?

```
단순히 메뉴 ID로만 구분하면?
  "치즈버거 (기본)" 추가
  "치즈버거 (엑스트라 치즈)" 추가
  → 같은 메뉴 ID → 수량만 증가 (틀림!)

올바른 구분:
  메뉴 ID + 커스터마이제이션 조합으로 구분
  → 다른 옵션이면 다른 아이템으로 취급
```

### `areCustomizationsEqual` 유틸 함수

```tsx
// 두 커스터마이제이션 배열이 동일한지 비교
const areCustomizationsEqual = (a: CartCustomization[], b: CartCustomization[]): boolean => {
  if (a.length !== b.length) return false

  // 정렬 후 ID 비교 (순서 상관없이 같은 옵션이면 동일하게 취급)
  const sortedA = [...a].sort((x, y) => x.id.localeCompare(y.id))
  const sortedB = [...b].sort((x, y) => x.id.localeCompare(y.id))

  return sortedA.every((item, idx) => item.id === sortedB[idx].id)
}
```

### 스토어 전체 구조

```tsx
// store/cart.store.ts

import { create } from 'zustand'
import { CartCustomization, CartItemType, CartStore } from '@/types'

export const useCartStore = create<CartStore>((set, get) => ({
  items: [], // 장바구니 아이템 배열

  // ── 아이템 추가 ──────────────────────────────
  addItem: (item) => {
    const { items } = get()

    // 같은 메뉴 + 같은 옵션이 이미 있으면 수량만 증가
    const existing = items.find(
      (i) =>
        i.id === item.id &&
        areCustomizationsEqual(i.customizations ?? [], item.customizations ?? [])
    )

    if (existing) {
      set({ items: items.map((i) => (i === existing ? { ...i, quantity: i.quantity + 1 } : i)) })
    } else {
      // 없으면 새 아이템 추가 (수량 1로 시작)
      set({ items: [...items, { ...item, quantity: 1 }] })
    }
  },

  // ── 수량 증가 ──────────────────────────────
  increaseQty: (id, customizations) => {
    set({
      items: get().items.map((i) =>
        i.id === id && areCustomizationsEqual(i.customizations ?? [], customizations)
          ? { ...i, quantity: i.quantity + 1 }
          : i
      ),
    })
  },

  // ── 수량 감소 (0이 되면 자동 제거) ──────────
  decreaseQty: (id, customizations) => {
    set({
      items: get()
        .items.map((i) =>
          i.id === id && areCustomizationsEqual(i.customizations ?? [], customizations)
            ? { ...i, quantity: i.quantity - 1 }
            : i
        )
        .filter((i) => i.quantity > 0), // 수량 0 이하인 아이템 제거
    })
  },

  // ── 특정 아이템 제거 ───────────────────────
  removeItem: (id, customizations) => {
    set({
      items: get().items.filter(
        (i) => !(i.id === id && areCustomizationsEqual(i.customizations ?? [], customizations))
      ),
    })
  },

  // ── 전체 비우기 ────────────────────────────
  clearCart: () => set({ items: [] }),

  // ── 총 수량 ────────────────────────────────
  getTotalItems: () => get().items.reduce((sum, i) => sum + i.quantity, 0),

  // ── 총 가격 ────────────────────────────────
  getTotalPrice: () => get().items.reduce((sum, i) => sum + i.price * i.quantity, 0),
}))
```
