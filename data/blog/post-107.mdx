# Express 앱의 오류 처리

```jsx
대개의 서버가 가동 중일 때 발생한 오류의 원인은 둘 중 하나이다

1. MongoDB 외 다양한 DB와 연결하거나 인터랙션할 때

2. API, 외부 서비스, 라이브러리와 연결하거나 인터랙션할 때 발생한 불완전 데이터 때문
```

```jsx
Express에 내장된 오류 핸들러가 앱에서 발생한 모든 오류를 처리한다

Express는 라우트나 미들웨어에서 발견된 모든 오류를 처리하여 기본적으로 상태 코드 500으로 응답한다

( HTML 페이지를 통해서 (오류 났을때 브라우저에 보여주는 스텍트레이서) )
```

# **오류 핸들러 작성**

```jsx
Express에서는 오류 처리 미들웨어 함수를 정의할 수 있음.

오류 처리 함수를 만들 때 네 개의 인수를 전달해야 함: err, req, res, next.

이 변수들을 정의해야 오류 처리 미들웨어로 인식됨.

보통 app.use 아래에 위치시키며, 콜백 함수 내에서 적절한 로깅 또는 처리를 수행함.
```

# 오류 핸들러 예제

```jsx
const express = require('express')
const app = express()
const morgan = require('morgan')

const AppError = require('./AppError')

// Morgan 미들웨어를 사용하여 요청 로그를 기록
app.use(morgan('tiny'))

// 모든 요청에 대해 현재 시간을 기록하고 요청 메서드와 경로를 출력하는 미들웨어
app.use((req, res, next) => {
  req.requestTime = Date.now()
  console.log(req.method, req.path)
  next()
})

// '/dogs' 경로에 대한 미들웨어. "I LOVE DOGS!!"를 출력하고 다음 미들웨어로 이동
app.use('/dogs', (req, res, next) => {
  console.log('I LOVE DOGS!!')
  next()
})

// 비밀번호를 확인하는 미들웨어
const verifyPassword = (req, res, next) => {
  const { password } = req.query
  if (password === 'chickennugget') {
    next()
  } else {
    // AppError를 활용하여 사용자 정의 오류를 생성하고 401 상태 코드로 응답
    throw new AppError('Password required', 401)
  }
}

// 홈 페이지 라우트. 현재 요청 시간을 출력
app.get('/', (req, res) => {
  console.log(`REQUEST DATE: ${req.requestTime}`)
  res.send('HOME PAGE!')
})

// '/error' 경로에서 오류를 인위적으로 발생시키는 라우트
app.get('/error', (req, res) => {
  // 정의되지 않은 변수 'chicken'으로 인한 오류 발생
  chicken.fly()
})

// '/dogs' 경로에서 "WOOF WOOF!"를 출력하는 라우트
app.get('/dogs', (req, res) => {
  console.log(`REQUEST DATE: ${req.requestTime}`)
  res.send('WOOF WOOF!')
})

// '/secret' 경로에서 비밀번호 확인 후 시크릿 내용을 출력하는 라우트
app.get('/secret', verifyPassword, (req, res) => {
  res.send('MY SECRET IS: Sometimes I wear headphones in public so I dont have to talk to anyone')
})

// '/admin' 경로에서 403 상태 코드로 "You are not an Admin!" 오류를 발생시키는 라우트
app.get('/admin', (req, res) => {
  throw new AppError('You are not an Admin!', 403)
})

// 404 Not Found 처리 미들웨어
app.use((req, res) => {
  res.status(404).send('NOT FOUND!')
})

// 오류 처리 미들웨어. 발생한 오류를 콘솔에 출력하고 다음 미들웨어로 전달
app.use((err, req, res, next) => {
  console.log('******************************************')
  console.log('*****************ERROR*****************')
  console.log('******************************************')
  console.log(err)
  next(err) // 기본에러 핸들러를 사용 next 에 (err) 필수
})

// 에러 처리를 마무리하는 미들웨어. 상태 코드와 메시지를 응답으로 전송
// 주석 처리된 부분은 다른 방식으로 에러를 처리하는 예시
// app.use((err, req, res, next) => {
//     const { status = 500, message = 'Something Went Wrong' } = err;
//     res.status(status).send(message);
// });

// 서버를 3000번 포트에서 실행
app.listen(3000, () => {
  console.log('App is running on localhost:3000')
})
```

```jsx
**오류 핸들러 예제 구현**

맨 아래 app.use를 이용하여 오류 처리 미들웨어를 정의함.

이 미들웨어는 콘솔에 오류 메시지를 출력함.

오류를 일으키지 않는 라우트인 '/'로 가면 아무 것도 출력되지 않음.

오류가 있는 라우트인 '/error'로 가면 오류 메시지와 상태 코드 500이 출력됨.

( 다른 미들웨어와 마찬가지로 next를 호출하지 않으면 코드가 끝난다 그러면 내장된 오류 핸들러 기능으로 응답할 수 없다 )

**기본 오류 핸들러 우회**

기본 오류 핸들러를 사용하고 싶을 때는 next를 호출하여 오류를 전달함.

단, **반드시 next에 err를 전달해야** Express가 오류를 인식함.

이를 통해 사용자 정의 오류 핸들러와 Express 기본 오류 핸들러를 조합하여 사용 가능함.

**Express 내장 오류 핸들러**

Express의 내장 오류 핸들러는 디폴트로 동작하며, 코드에서 발생한 오류를 처리함.

next에 오류를 전달하면 Express는 해당 오류를 처리하고 내장 오류 핸들러로 전달함.

Express의 디폴트 오류 핸들러는 스택 추적과 함께 HTML 응답을 생성함.

**커스텀 오류 핸들러 활용**

사용자 정의 오류 핸들러를 통해 스택 추적, 상태 코드 등을 커스터마이징할 수 있음.

오류 핸들러에는 반드시 next를 호출하여 다음 미들웨어로 전달해야 함.

비동기적 오류 처리 및 Mongoose 등 라이브러리에서 발생한 오류도 효과적으로 처리 가능함.
```

# 사용자 지정 오류 클래스

## Express에서 오류를 다루기 어려운 점

```jsx
Express에서 오류를 다루는 것은 어려운 점이 있다.

이는 처리하는 방법이 한 가지뿐이 아니라 다양하기 때문이다.

Express는 간결하고 유연한 프레임워크로 소개되었으며, 개발자들은 권한을 가지고 앱을 제작할 수 있다.

그러나 때로는 단일 방법으로 앱을 만들기 보다는 방향이 주어질 때 편리할 수 있다.
```

## 커스텀 오류 클래스 사용

```jsx
Express에서 오류 처리의 일반적인 패턴 중 하나는 커스텀 오류 클래스를 사용하는 것이다.

대부분의 경우 Express 앱에서 생성된 오류를 확인하고 특정 상태 코드와 메시지로 응답하는 것이 일반적이다.

주로 400번대 또는 500번대 상태 코드를 처리하며, 예를 들면 500은 서버 문제를 나타내고 401은 권한이 없음을 의미한다.

Express에서 상태 코드를 처리할 때 각 코드에는 다른 의미가 있으며,

이를 능숙하게 처리해야 한다. 이를 위해 커스텀 오류 클래스를 사용하여 앱 오류나 Express 오류를 생성할 수 있다.

이렇게 하면 상태 코드와 메시지를 쉽게 설정할 수 있다
```

### index.js

```jsx
const express = require('express')
const app = express()
const morgan = require('morgan')

const AppError = require('./AppError')

app.use(morgan('tiny'))

app.use((req, res, next) => {
  req.requestTime = Date.now()
  console.log(req.method, req.path)
  next()
})

// '/admin' 경로에 대한 GET 요청을 처리하는 라우트 핸들러를 추가합니다.
app.get('/admin', (req, res) => {
  // AppError를 활용하여 'You are not an Admin!' 메시지와 상태 코드 403으로 예외를 발생시킵니다.
  throw new AppError('You are not an Admin!', 403)
})
app.use((req, res) => {
  res.status(404).send('NOT FOUND!')
})

// 오류 핸들러 미들웨어를 추가합니다.
app.use((err, req, res, next) => {
  // 오류 객체에서 상태 코드와 메시지를 추출합니다. 디폴트 값은 500과 'Something Went Wrong'입니다.
  const { status = 500, message = 'Something Went Wrong' } = err
  // 상태 코드와 메시지로 응답합니다.
  res.status(status).send(message)
})

app.listen(3000, () => {
  console.log('App is running on localhost:3000')
})
```

### AppError 클래스

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381413/notion-blog/_/The_Web_Developer_2022/node_js/_/Untitled.png)

```jsx
// AppError 클래스를 정의합니다. 이 클래스는 Error 클래스를 확장합니다.
class AppError extends Error {
  // constructor 메서드를 정의합니다. 이 메서드는 객체를 생성할 때 호출됩니다. (생성자)
  constructor(message, status) {
    // 부모 클래스인 Error 클래스의 constructor를 호출합니다.
    super()
    // 현재 객체의 message 속성을 전달받은 message 값으로 설정합니다.
    this.message = message
    // 현재 객체의 status 속성을 전달받은 status 값으로 설정합니다.
    this.status = status
  }
}

// AppError 클래스를 모듈로 내보냅니다.
module.exports = AppError
```

```jsx
AppError 클래스는 JavaScript의 내장 클래스인 Error를 확장하여 정의되었다.

이로써 사용자 정의 오류를 만들 수 있게 되었다.

클래스는 생성자 메서드(constructor)를 가지고 있으며, 이 메서드는 오류 객체를 생성할 때 호출된다.

생성자 메서드는 오류 메시지(message)와 상태 코드(status)를 매개변수로 받아, 오류 객체의 속성으로 설정한다.
```

    // findByIdAndUpdate 대신 findById 와 save 를 사용하여 업데이트
    const product = await Product.findById(id)

    if (!product) {
      return res.status(404).send('상품을 찾을 수 없습니다.')

    await product.save()

    res.send(product)

    res.status(500).send('상품 업데이트 중 오류 발생')

})

// 상품 삭제
app.delete('/product/:id', async (req, res) => {
  const { id } = req.params
  try {
    const result = await Product.deleteOne({ _id: id })
    // 삭제 성공 여부에 따라 응답
    if (result.deletedCount > 0) {
      res.status(200).send('DELETE SUCCESS')
    } else {
      res.status(404).send('ID NOT FOUND')
    }
  } catch (error) {
    console.error('DELETE FAIL')
    res.status(500).send('DELETE FAIL')
  }
})

  const { status = 500, message = 'Something went wrong' } = err
  res.status(status).send(message)
})

  console.log('Success')

# 비동기 유틸리티 정의하기

```jsx
Express에서 쓰는 거의 모든 게 비동기 함수라서 다 try로 감싸주고 끝에 catch 처리를 한 다음

next를 호출하고 오류를 전달하는 작업이 상당히 번거롭다

**Wrap Async Function** 함수를 만들고 함수에 콜백 전체( 라우터 엔드포인 뒤의 async 부분부터 전부 )

를 전달한다 그러면 굉장히 작업이 간단해지는 게

그냥 그 함수 안에서 이 코드를 가져다가

오류가 발생되면 모두 catch해서 next로 전달하기만 하면 된다
```

## **Wrap Async Function 생성**

```jsx
function wrapAsync(fn) {
  return function (req, res, next) {
    fn(req, res, next).catch((e) => next(e))
  }
}
```

```jsx
wrapAsync 함수는 비동기 함수를 감싸는 함수이다.

전달된 함수 fn은 Express의 미들웨어나 라우트 핸들러이다.

반환된 함수는 (req, res, next)를 인자로 받아 해당 함수 내에서 fn을 호출한다.

비동기 함수 안에서 발생한 오류는 .catch(e => next(e))를 통해 Express의 오류 핸들러로 전달된다.

* Express 5에서는 자동으로 비동기 함수에서 발생하는 오류를 처리해주므로 wrapAsync 사용이 줄어들 것으로 예상
```
