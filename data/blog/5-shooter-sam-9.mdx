## 🤔 왜 Behavior Tree를 쓰나요?

### 기존 방식 (AI Controller)

**Tick 함수에 전부 작성:**

```cpp
void Tick(float DeltaTime)
{
    // 플레이어 찾기
    // 시야 확인
    // 이동
    // 쏘기
    // 순찰
    // ... (계속 추가)
}
```

**문제점:**

```
간단한 AI: OK ✅
복잡한 AI: 관리 어려움 ❌

코드가 길어짐
→ 읽기 어려움
→ 수정 어려움
→ 버그 많아짐
```

---

### Behavior Tree 방식

**비주얼 노드 그래프:**

```
Root
  ↓
Sequence
  ├─ Find Player
  ├─ Check Line of Sight
  ├─ Move To Player
  └─ Shoot
```

**장점:**

```
✅ 시각적으로 보임
✅ 이해하기 쉬움
✅ 수정하기 쉬움
✅ 재사용 가능
✅ 복잡한 AI 가능
```

## 🌲 Behavior Tree란?

### 비유

**의사 결정 트리:**

```
아침에 일어남
    ↓
배고픔?
  ├─ Yes → 밥 먹기
  └─ No → 안 먹기
    ↓
학교 가기
```

**AI도 마찬가지:**

```
게임 시작
    ↓
플레이어 보임?
  ├─ Yes → 쫓아가기
  │         ↓
  │       가까움?
  │         ├─ Yes → 쏘기
  │         └─ No → 계속 이동
  └─ No → 순찰하기
```

---

## 📊 Behavior Tree 구성 요소

### 2가지 주요 에셋

**1. Behavior Tree (BT)**

```
AI의 "행동"
→ 무엇을 할까?
→ 이동, 공격, 순찰 등
```

**2. Blackboard (BB)**

```
AI의 "데이터"
→ 어디로 갈까?
→ 누구를 쫓을까?
→ 위치, 타겟 등
```

---

### 비유로 이해하기

**요리사 (AI):**

```
Behavior Tree (레시피):
  1. 재료 준비
  2. 볶기
  3. 간 맞추기
  4. 완성

Blackboard (재료):
  - 양파 위치
  - 불 온도
  - 소금 양
```

## 🎮 Step 4: 첫 Behavior Tree 만들기

### Behavior Tree 그래프

**BT_EnemyAI 열기:**

**구조:**

```
┌─────────┐
│  Root   │  ← 시작점 (매 프레임 실행)
└────┬────┘
     ↓
  (여기에 노드 연결)
```

---

### 노드 종류

**1. Composite (복합 노드)**

```
자식 노드들을 관리
→ 어떤 순서로?
→ 어떤 조건으로?

종류:
  - Sequence: 순차 실행
  - Selector: 선택 실행
  - Simple Parallel: 병렬 실행
```

**2. Task (작업 노드)**

```
실제 행동
→ 이동하기
→ 쏘기
→ 대기하기
```

**3. Decorator (조건 노드)**

```
조건 검사
→ 거리 확인
→ 시야 확인
(나중에 배움)
```

# { Behavior Tree 초기화 시스템 }

## 🎯 이번에 할 것

**Game Mode에서 모든 AI를 한 번에 초기화!**

```
기존: 각 AI가 개별적으로 시작
    ↓
개선: Game Mode가 한 번에 시작
    ↓
효율적이고 관리하기 쉬움! 🎮
```

---

## 🤔 왜 개선하나요?

### 기존 방식의 문제점

**각 AI의 BeginPlay:**

```cpp
void AShooterAI::BeginPlay()
{
    // 플레이어 찾기
    APawn* Player = GetPlayerPawn(...);  // ← 문제!

    // Behavior Tree 실행
    RunBehaviorTree(BT);
}
```

**적이 1000명이면?**

```
적 1: 플레이어 찾기 (GetPlayerPawn)
적 2: 플레이어 찾기 (GetPlayerPawn)
적 3: 플레이어 찾기 (GetPlayerPawn)
...
적 1000: 플레이어 찾기 (GetPlayerPawn)

→ 1000번 반복! ❌
→ 비효율적!
```

---

### 개선된 방식

**Game Mode에서 한 번만:**

```cpp
void GameMode::BeginPlay()
{
    // 1. 플레이어 찾기 (1번만!)
    Player = GetPlayerPawn(...);

    // 2. 모든 AI 찾기 (1번만!)
    AllAI = GetAllActorsOfClass(AShooterAI);

    // 3. 각 AI에게 플레이어 전달
    for (AI in AllAI)
    {
        AI->StartBehaviorTree(Player);  // 이미 찾은 플레이어 전달!
    }
}
```

**장점:**

```
✅ GetPlayerPawn 1번만 호출
✅ 중앙에서 관리
✅ 효율적
✅ 나중에 추가 설정 쉬움
```

---

## 📝 Step 1: StartBehaviorTree 함수 만들기

### 1-1: 헤더 파일 (ShooterAI.h)

```cpp
#pragma once

#include "CoreMinimal.h"
#include "AIController.h"
#include "ShooterSamCharacter.h"  // 👈 Include 추가!
#include "ShooterAI.generated.h"

UCLASS()
class SHOOTERSAM_API AShooterAI : public AAIController
{
    GENERATED_BODY()

protected:
    virtual void BeginPlay() override;

public:
    virtual void Tick(float DeltaTime) override;

    // ===== Behavior Tree =====
    UPROPERTY(EditAnywhere)
    UBehaviorTree* EnemyAIBehaviorTree;

    // ===== 캐릭터 포인터들 =====
    AShooterSamCharacter* PlayerCharacter;   // 플레이어
    AShooterSamCharacter* MyCharacter;       // 나 자신 (적)

    // ===== 새 함수 =====
    void StartBehaviorTree(AShooterSamCharacter* Player);
};
```

---

### 변수 설명

**PlayerCharacter:**

```cpp
AShooterSamCharacter* PlayerCharacter;
```

**용도:**

```
플레이어 캐릭터 저장
→ Behavior Tree에서 사용
→ 쫓아갈 타겟
```

---

**MyCharacter:**

```cpp
AShooterSamCharacter* MyCharacter;
```

**용도:**

```
AI가 조종하는 적 캐릭터
→ 나 자신
→ 매번 Cast 안 해도 됨!
```

---

### 1-2: 구현 파일 (ShooterAI.cpp)

```cpp
void AShooterAI::StartBehaviorTree(AShooterSamCharacter* Player)
{
    if (EnemyAIBehaviorTree)
    {
        // 1. 내 캐릭터 가져오기
        MyCharacter = Cast<AShooterSamCharacter>(GetPawn());

        // 2. 플레이어 저장
        if (Player)
        {
            PlayerCharacter = Player;
        }

        // 3. Behavior Tree 실행!
        RunBehaviorTree(EnemyAIBehaviorTree);
    }
}
```

---

### 코드 완벽 이해하기

**Step 1: Behavior Tree 확인**

```cpp
if (EnemyAIBehaviorTree)
```

**의미:**

```
BT가 설정됐나?
→ nullptr이면 실행 안 함
→ 안전한 코딩
```

---

**Step 2: 내 캐릭터 가져오기**

```cpp
MyCharacter = Cast<AShooterSamCharacter>(GetPawn());
```

**분해:**

**GetPawn():**

```cpp
APawn* GetPawn()
```

- AI Controller가 조종하는 Pawn 반환
- APawn\* 타입

**Cast:**

```cpp
Cast<AShooterSamCharacter>(...)
```

- APawn* → AShooterSamCharacter*로 변환
- 적 캐릭터 타입으로 변환

**왜 필요한가요?**

```
GetPawn()은 APawn* 반환
→ AShooterSamCharacter의 기능 못 씀

Cast하면:
→ AShooterSamCharacter* 얻음
→ 모든 기능 사용 가능!
```

**MyCharacter에 저장:**

```
나중에 사용하려고
→ 매번 Cast 안 해도 됨
→ 효율적!
```

---

**Step 3: 플레이어 저장**

```cpp
if (Player)
{
    PlayerCharacter = Player;
}
```

## 🔄 while 루프 vs for 루프

### while 루프 복습

```cpp
// 1. 변수 선언

```

## 📝 for 루프 문법

```cpp
    // 반복할 코드
}
```

### 각 부분 설명

**1. 초기화 (Initialization)**

```cpp
int32 LoopIndex = 0
```

**의미:**

```
루프 시작 전 1번만 실행
→ 카운터 변수 생성
→ 초기값 설정
```

**예시:**

```cpp
int32 i = 0      // 0부터 시작
int32 i = 1      // 1부터 시작
int32 i = 10     // 10부터 시작
```

---

**2. 조건 (Condition)**

```cpp

```

**의미:**

```
매 반복마다 체크
→ true면 계속
→ false면 종료
```

**예시:**

```cpp

i <= 100     // i가 100 이하
i != 5       // i가 5가 아님
```

**3. 증가 (Increment)**

```cpp

```

**의미:**

```
매 반복 끝에 실행
→ 보통 변수 증가
→ 다음 반복 준비
```

**예시:**

```cpp
i++          // +1씩 증가
i += 2       // +2씩 증가
i--          // -1씩 감소
```

### 실행 순서

```cpp

{
```

**단계별 실행:**

```

    ↓

    ↓

    ↓
5. i < 3 체크 (1 < 3 = true)
    ↓
6. 로그 출력: "i = 1"
    ↓
7. i++ 실행 (i = 2)
    ↓
8. i < 3 체크 (2 < 3 = true)
    ↓
9. 로그 출력: "i = 2"
    ↓
10. i++ 실행 (i = 3)
    ↓
11. i < 3 체크 (3 < 3 = false) ← 종료!
```

**출력:**

```

i = 2
```

```cpp
{
    Super::BeginPlay();

    // ===== 1. 플레이어 가져오기 =====
```

## 🔍 for 루프 부분 상세 분석

### Step 1: for 루프 시작

```cpp

```

**분해:**

**초기화:**

```cpp
int32 LoopIndex = 0
```

```cpp

```

- `ShooterAIActors.Num()`: 배열 길이
- 예: 배열에 3개 → Num() = 3

```cpp

```

### Step 2: 배열 인덱싱


**배열 인덱싱이란?**

```cpp

ShooterAIActors[1]  →  AI_1 (두 번째)
```

```
반복 3: LoopIndex = 2

```

```
    ↓
Cast<AShooterAI>(...)
    ↓
```

```
  → 안전! ✅
```

## 📚 핵심 개념 정리

### for 루프

```cpp
for (초기화; 조건; 증가)
{
    // 반복 코드
}
```

### 배열 인덱싱

```cpp
Array[Index]
Array[0]  // 첫 번째
Array[1]  // 두 번째
```

### Num()

배열 길이

```cpp
Array.Num()  // 요소 개수
```

### while vs for

```
while: 조건만 체크
for: 초기화 + 조건 + 증가 (한 줄에)
```

### Cast 필요성

```
AActor* → AShooterAI*
타입 변환 필수
```

## 💡 실전 팁

### for 루프 vs while 루프

**for 루프 사용:**

```
배열 순회
정해진 횟수 반복
카운터 필요
→ 대부분의 경우!
```

**while 루프 사용:**

```
조건만 중요
횟수 모름
특수한 종료 조건
→ 드문 경우
```

---

### 범위 기반 for 루프 (C++11)

**더 간단한 방법:**

```cpp
// 기존 방식
for (int32 i = 0; i < ShooterAIActors.Num(); i++)
{
    AActor* Actor = ShooterAIActors[i];
    // ...
}

// 범위 기반 (Range-based)
for (AActor* Actor : ShooterAIActors)
{
    // 자동으로 순회!
}
```

**장점:**

```
✅ 더 짧음
✅ 인덱스 불필요
✅ 읽기 쉬움
```

**적용:**

```cpp
for (AActor* ShooterAIActor : ShooterAIActors)
{
    AShooterAI* ShooterAI = Cast<AShooterAI>(ShooterAIActor);
    if (ShooterAI)
    {
        ShooterAI->StartBehaviorTree(Player);
    }
}
```

---

### 역순 반복

**뒤에서부터:**

```cpp
for (int32 i = ShooterAIActors.Num() - 1; i >= 0; i--)
{
    AActor* Actor = ShooterAIActors[i];
    // 마지막부터 첫 번째까지
}
```

---

### 2씩 증가

```cpp
for (int32 i = 0; i < 10; i += 2)
{
    // 0, 2, 4, 6, 8
}
```

## 🐛 문제 해결

### for 루프가 실행 안 돼요!

**확인:**

```cpp
ShooterAIActors.Num()  // 0이면 실행 안 됨

UE_LOG(LogTemp, Warning, TEXT("AI Count: %d"), ShooterAIActors.Num());
```

---

### Cast가 실패해요!

**확인:**

```cpp
if (ShooterAI)
{
    // 여기 들어오나요?
    UE_LOG(LogTemp, Warning, TEXT("Cast Success!"));
}
else
{
    UE_LOG(LogTemp, Error, TEXT("Cast Failed!"));
}
```

---

### 무한 루프!

**원인:**

```cpp
for (int32 i = 0; i < 10; )  // 증가 없음!
{
    // i++가 없어서 무한 루프
}
```

**해결:**

```cpp
for (int32 i = 0; i < 10; i++)  // i++ 필수!
```
