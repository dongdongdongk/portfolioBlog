## 함수형 업데이트 방식 (콜백 문법 사용)

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381437/notion-blog/_/The_Web_Developer_2022/REACT/_State_/Untitled_1.png)

```jsx
		* 전
		const incrementCount = () => {
        setCount(count + 1);
    }

		* 후
		const incrementCount = () => {
        setCount(c => c + 1);
    }

		setCount(현재 값 => 현재값 + 1)
```

```jsx
함수는 함수형 업데이트를 사용한다.

setCount 함수에 전달되는 콜백 함수는 현재 상태를 나타내는 매개변수 c를 받아와서

c + 1로 계산한 값을 반환한다.

이렇게 하면 리액트는 이전 상태를 알고 있기 때문에 안정적으로 상태를 업데이트하고 최적화할 수 있다.

이는 비동기성 및 렌더링 최적화 문제를 방지하고 가독성을 높여준다.
```

## 함수형 초기화

```jsx
간단한 State 의 경우에는 굳이 초기 State  함수를 사용하지 않고 직접 초기 값을 전달하는 것이 더 간편할 수 있다.

초기 State 값을 전달하면 렌더시 다시 계산을 하지만 리턴 함수로 넣어두면 다시 계산하지 않는다
```

## 함수형 초기화를 사용하는 경우

```jsx
**복잡한 초기 상태 로직**:

상태의 초기 값을 계산하는 로직이 복잡하거나 시간이 오래 걸릴 때, 초기 상태 함수를 사용하여 계산 로직을 분리할 수 있다.

이로써 컴포넌트가 렌더링될 때마다 계산이 반복되지 않고, 첫 렌더링 시에만 실행된다.

**의존성이 있는 초기 상태**:

초기 상태가 외부 데이터나 다른 상태에 의존적일 때 초기 상태 함수를 활용할 수 있다.

이 함수 안에서 외부 데이터를 가져와 초기 상태를 계산하면, 해당 데이터가 변경될 때마다 초기 상태가 업데이트된다.

**비동기 로직 수행**:

초기 상태 함수 내에서 비동기 작업을 수행할 수 있다.

예를 들어, 서버에서 데이터를 가져와 초기 상태를 설정하는 경우 초기 상태 함수를 사용하여 비동기 호출을 처리할 수 있다
```

```jsx
import React, { useState } from 'react'

// 복잡한 초기 상태를 생성하는 함수
const generateInitialData = () => {
  console.log('Generating Initial Data...')
  // 실제로는 여기에 복잡한 로직이 들어갈 수 있습니다.
  return Math.floor(Math.random() * 100)
}

const ExampleComponent = () => {
  // 초기 상태를 설정할 때 generateInitialData 함수를 사용
  const [data, setData] = useState(generateInitialData)

  return (
    <div>
      <h1>초기 데이터: {data}</h1>
      <button onClick={() => setData(generateInitialData)}>새로운 데이터 생성</button>
    </div>
  )
}

export default ExampleComponent
```

# 추가적인 State 관리 정보

## State 값 **변경 및 재 렌더링**

```jsx
import React, { useState } from 'react'

const Counter = () => {
  const [count, setCount] = useState(0)

  const setToTen = () => {
    // 항상 count를 10으로 설정
    setCount(10)
  }

  return (
    <div>
      <h1>Counter: {count}</h1>
      <button onClick={() => setCount(count + 1)}>Increment</button>
      <button onClick={setToTen}>Set to 10</button>
    </div>
  )
}

export default Counter
```

```jsx
State 가 변경될 때마다 컴포넌트가 재렌더링된다.

Increment 버튼을 클릭하면 count가 증가하고, 이로 인해 컴포넌트가 다시 렌더링된다.

Set to 10 버튼을 클릭하면 항상 count가 10으로 설정되는데, 값이 같다면 재 렌더링은 이뤄지지 않는다

React는 상태값이 변경되었을 때에만 컴포넌트를 리렌더링하도록 최적화되어 있다.
```

## State **업데이트 묶음 처리**

```jsx
**State 업데이트**를 묶음으로 처리하여 한 번만 재렌더링이 일어나도록 할 수 있다.

(State 업데이트다!)
```

```jsx
import React, { useState } from 'react'

const Example4 = () => {
  const [count, setCount] = useState(0)

  const increaseByTwo = () => {
    setCount((prevCount) => prevCount + 2)
  }

  const increaseByThree = () => {
    setCount((prevCount) => prevCount + 3)
  }

  return (
    <div>
      <p>Count: {count}</p>

      <button onClick={increaseByThree}>Increase by 3</button>

  )

export default Example4
```

## **`setState`**를 호출하는 것만으로는 즉시 재렌더링이 되지 않는다

```jsx
**비동기 동작**:

setState 호출은 비동기적으로 처리된다.

React는 성능을 향상시키기 위해 여러 setState 호출을 모아서 처리하거나, 다른 비동기 작업과 함께 일괄적으로 처리할 수 있도록 설계되어 있다.

**재렌더링 시점**:

setState를 호출하면 React는 컴포넌트의 상태가 업데이트되었음을 감지하고,

재렌더링을 스케줄링한다. 그러나 실제 재렌더링이 언제 발생할지는 React의 내부 알고리즘에 의해 결정된다.

즉, setState를 호출하는 시점에서 즉시 재렌더링이 발생하지 않고, React가 최적의 시점에 여러 업데이트를 일괄 처리할 수 있도록 한다.

**성능 최적화**:

React는 불필요한 재렌더링을 피하기 위해 여러 최적화 기법을 사용한다.

예를 들어, 상태나 속성이 변경되었을 때, 실제 DOM이 변경되기 전에 가상 DOM에서 이전과 새로운 상태를 비교하고 변경 사항만을 반영한다.

**setState 콜백 사용**:

setState 함수는 두 번째 매개변수로 콜백 함수를 받을 수 있다. 이 콜백 함수는 setState가 완료된 후에 호출되며, 이때 업데이트된 상태를 사용할 수 있다.

콜백을 사용하여 setState 호출 이후에 특정 작업을 수행하거나, 업데이트된 상태를 기반으로 추가적인 로직을 처리할 수 있다.
```

```jsx
이때, React는 현재의 상태와 변경된 상태를 비교하여 실제로 변경이 일어났는지를 판단한다.
```

## 해결 방법

```jsx
import { useState } from 'react'

function ScoreKeeper() {
  const [score, setScores] = useState({ p1Score: 0, p2Score: 0 })

  function increaseP1Score() {
    // 전개 연산자를 사용하여 score의 복사본을 생성하고 p1Score를 업데이트
    const newScore = { ...score, p1Score: score.p1Score + 1 }
    console.log(newScore)
    setScores(newScore)
  }

  return (
    <div>
      <p>Player 1: {score.p1Score} </p>
      <p>Player 2: {score.p2Score}</p>
      <button onClick={increaseP1Score}>+1 Player 1</button>
      <button>+1 Player 2</button>
    </div>
  )
}

export default ScoreKeeper
```

```jsx
이때는 ... 전개연산자 (스프래드) 를 사용해서 score 의 복사본을 생성하고 p1Score 를 업데이트 해준다

( 함수 내에서 score 오브젝트를 직접 수정하는 대신에, 기존의 score 오브젝트를 전개하여 새로운 오브젝트를 생성하고,

그 중 p1Score를 업데이트한 새로운 오브젝트를 setScores에 전달 ) ( score 에는 {p1Score: score.p1Score, p2Score: score.p2Score} 이렇게 들어있는데 p1만 직접 수정)
```

## 기존 버전 상태에 의존해서 업데이트 하는건 x

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381437/notion-blog/_/The_Web_Developer_2022/REACT/_State_/Untitled_4.png)

```jsx
import { useState } from 'react'
function ScoreKeeper() {
  const [score, setScores] = useState({ p1Score: 0, p2Score: 0 })

  function increaseP1Score() {
    setScores((oldScores) => {
      return { ...oldScores, p1Score: oldScores.p1Score + 1 }
    })
  }

  return (
    <div>
      <p>Player 1: {score.p1Score} </p>
      <p>Player 2: {score.p2Score}</p>
      <button onClick={increaseP1Score}>+1 Player 1</button>
      <button>+1 Player 2</button>
    </div>
  )
}

export default ScoreKeeper
```

```jsx
새로운 상태 버전이 기존 버전에 의존하게 되는데 이때는 콜백 문법을 쓰는게 더 낫다

하나의 값만 있는 setScores가 아니라 setScores에 oldScores라고 하는

값을 넣고 화살표 함수를 사용한다

매개변수 이름은 oldScores로 정했다, 이걸 가져가서 새 오브젝트로 복사하고

반환해야겠다, 그 다음엔 p1Score를 oldScores.p1Score+1로 설정
```

함수형 업데이트 방식 (콜백 문법 사용)

## 리액트는 전개를 늘 사용

```jsx
리액트는 전개를 늘 사용한다

배열을 다룰 때도 똑같이 해야 한다, 기존 배열을 복사해서 그 복사본에 변경을 가하는 것

오브젝트를 다룰 때도 기존 오브젝트를 복사해서 변경한다

좀 짜증나지만 스스로 되뇌면서 기억해야 한다, **오브젝트를 그대로 변경하지 않는다, 상태의 배열을 변경하지 않는다

대신에 항상 복사본을 만든다**
```

## 최종

```jsx
import { useState } from 'react'
function ScoreKeeper() {
  const [score, setScores] = useState({ p1Score: 0, p2Score: 0 })

  function increaseP1Score() {
    setScores((oldScores) => {
      return { ...oldScores, p1Score: oldScores.p1Score + 1 }
    })
  }

  function increaseP2Score() {
    setScores((oldScores) => {
      return { ...oldScores, p2Score: oldScores.p2Score + 1 }
    })
  }

  return (
    <div>
      <p>Player 1: {score.p1Score} </p>
      <p>Player 2: {score.p2Score}</p>
      <button onClick={increaseP1Score}>+1 Player 1</button>
      <button onClick={increaseP2Score}>+1 Player 2</button>
    </div>
  )
}

export default ScoreKeeper
```

```jsx

oldScores를 복사할 때는 p1Score와 p2Score를 복사한 다음 p1Score나 p2Score를 바꾼다

지금은 변경할 프로퍼티가 하나뿐이지만 오브젝트에 다른 프로퍼티가 20개 있다고 생각해보면 매우 복잡해진다

그떄 위의 방법 ... 을 사용하면 쉽게 해결 가능하다
```

# State 에 배열 사용

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381438/notion-blog/_/The_Web_Developer_2022/REACT/_State_/Untitled_5.png)

```jsx
import { useState } from 'react'

function EmojiClicker() {
  const [emojis, setEmojis] = useState(['😁'])
  const addEmoji = () => {
    setEmojis((oldEmojis) => [...oldEmojis, '😘'])
  }
  return (
    <div>
      {emojis.map((e) => (
        <span style={{ fontSize: '4rem' }}>{e}</span>
      ))}
      <button onClick={addEmoji}>Add Emoji</button>
    </div>
  )
}

export default EmojiClicker
```

```jsx
**상태와 배열을 다루는 공통된 문제**:

상태와 배열은 변경 가능한 객체로, 기존 상태를 변경하면 리액트가 변화를 감지하지 못한다는 공통된 문제가 있다.

**이모티콘 클릭기 컴포넌트**:

위의 코드는 버튼을 클릭하면 배열에 무작위 이모티콘을 추가하도록 구현했다

**상태 업데이트**:

상태를 업데이트할 때 배열을 복사하고, 이 복사본을 변경하여 상태를 업데이트하는 방식을 사용한다.

배열이나 오브젝트를 직접 변경하지 않고 새로운 복사본을 만들어야 한다.

**배열 메서드를 활용한 상태 업데이트**:

배열에 요소를 추가할 때 push 대신 전개 연산자를 사용하여 배열을 복사하고 새로운 요소를 추가한다.

**콜백 문법 사용**:

상태를 업데이트할 때 기존 상태 버전을 기준으로 하는 것이 중요하다.

setEmojis(oldEmojis => [...oldEmojis, newEmoji])와 같이 콜백 문법을 사용하여 이전 상태를 활용한다.
```

# UUID로 ID 생성

```jsx
현재 이모지를 새로 추가하면 key 가 없다고 오류가 뜬다

이는 삭제같은 기능을 사용할 때 리액트가 삭제대상을 구분하지 못할것 같아 오류를 출력하는것

여기에 npm uuid 를 사용해서 무작위 id 를 추가해준다
```

```jsx
import { useState } from 'react'
import { v4 as uuid } from 'uuid'
function EmojiClicker() {
```

# 배열을 업데이트하는 일반적인 패턴 정리

```jsx
// 상태 배열 업데이트에 대한 공통 패턴
const shoppingCart = [
  { id: 1, product: 'HDMI Cable', price: 4 },
  { id: 2, product: 'Easy Bake Oven', price: 28 },
  { id: 3, product: 'Peach Pie', price: 6.5 },
]

// 배열에 항목 추가
;[...shoppingCart, { id: 4, product: 'Coffee Mug', price: 7.99 }]

// 요소 제거
shoppingCart.filter((item) => item.id !== 2)

// 배열의 모든 요소 업데이트
shoppingCart.map((item) => {
  return {
    ...item,
    product: item.product.toLowerCase(),
  }
})

// 특정 요소 수정
shoppingCart.map((item) => {
  if (item.id === 3) {
    return { ...item, price: 10.99 }
  } else {
    return item
  }
})
```

```jsx
**배열의 추가 및 삭제**:

기존 배열을 변경하지 않고 새로운 배열을 생성하는 것이 중요하다.

새로운 요소를 배열에 추가할 때는 전개 연산자(...)를 사용하여 새로운 배열을 만든다.

요소를 삭제할 때는 filter 함수를 활용하여 삭제할 요소를 제외한 새로운 배열을 생성한다.

**배열의 모든 요소 업데이트**:

map 함수를 사용하여 배열의 모든 요소를 순회하고 각 요소를 복사한 후 수정하여 새로운 배열을 생성한다.

전개 연산자를 이용하면 간편하게 배열을 복사하고 수정할 수 있다.

**특정 요소 업데이트**:

특정 요소를 찾아 업데이트할 때는 map 함수를 사용하고, 해당 요소만을 수정하여 새로운 배열을 생성한다.

ID를 활용하여 특정 요소를 찾는 것이 흔히 사용되는 패턴이다.

**불변성 유지**:

리액트에서는 원본 배열을 직접 변경하지 않고 새로운 복사본을 만들어서 상태를 업데이트한다.

배열 메서드나 연산자를 활용하여 새로운 배열을 생성하고 이를 상태로 설정한다.

**배열 정렬**:

배열을 정렬할 때도 기존 배열을 변경하지 않고 새로운 배열을 만든다.

전개 연산자를 사용하여 배열을 복사한 후 정렬을 수행한다.

이러한 불변성을 유지하는 방법은 리액트에서 상태를 다룰 때 핵심적인 원칙 중 하나이다.

적응 기간이 필요할 수 있지만, 불변성을 유지하면서 코드를 작성하는 것이 안전하고 예측 가능한 상태 관리를 가능케 한다.
```
