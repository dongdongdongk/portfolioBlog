## 📖 이 문서는 무엇에 관한 건가요?

이 문서는 **웹사이트에서 브라우저 탭을 바꾸면 페이지가 새로고침되는 문제**를 해결한 과정을 설명합니다. 예를 들어, 여러분이 웹사이트에서 글을 쓰다가 다른 탭으로 갔다가 돌아오면, 작성하던 글이 사라지는 짜증 나는 상황이 있었어요. 이 문제를 어떻게 찾아내고, 어떻게 고쳤는지, 초보자도 이해할 수 있게 설명할게요.

### 😕 어떤 문제가 있었나요?

상상해보세요. 여러분이 블로그에 글을 쓰고 있는데, 중간에 구글에서 자료를 찾으려고 다른 탭으로 이동합니다. 다시 돌아왔을 때, **작성하던 글이 사라지고 페이지가 새로고침**된 거예요! 😣 이건 사용자에게 정말 불편한 경험입니다. 주요 문제들은 다음과 같아요:

- **탭 전환 시 새로고침**: 탭을 바꾸면 페이지가 다시 로드돼요.
- **글 사라짐**: 작성 중이던 내용이 날아가요.
- **로딩 스피너**: 페이지가 계속 "로딩 중" 상태로 보여요.
- **불필요한 서버 요청**: 웹사이트가 서버에 자꾸 데이터를 요청해서 느려져요.

### 🧑‍💻 어떤 상황에서 발생했나요?

예를 들어, 사용자가 이런 일을 겪었어요:

1. 커뮤니티 페이지에서 글을 쓰기 시작.
2. 자료를 찾으려고 다른 탭으로 이동.
3. 다시 원래 탭으로 돌아옴.
4. **작성하던 글이 사라지고 페이지가 새로 로드됨** 😢.

### 🛠 어떤 도구를 사용했나요?

이 웹사이트는 아래와 같은 기술로 만들어졌어요:

- **Next.js 14**: 웹사이트를 빠르게 만드는 도구 (React 기반).
- **TypeScript**: JavaScript에 타입을 추가해 코드 실수를 줄이는 언어.
- **Supabase Auth**: 사용자 로그인/로그아웃을 관리하는 도구.
- **Zustand**: 웹사이트의 데이터를 한 곳에서 관리하는 도구.
- **React + SCSS**: 웹사이트의 화면과 스타일을 만드는 도구.

이제 문제를 왜 일어났는지, 그리고 어떻게 고쳤는지 하나씩 쉽게 풀어볼게요!

## 🔍 왜 이런 문제가 생겼나요?

문제의 원인을 이해하려면, 웹사이트가 어떻게 동작하는지 간단히 알아야 해요. 웹사이트는 여러 "컴포넌트"로 구성되어 있고, 각 컴포넌트는 특정 작업(예: 사용자 정보 불러오기, 글 저장하기)을 합니다. 이 문서에서는 세 가지 주요 원인을 찾았어요. 비유를 들어 쉽게 설명할게요.

### 1. **React의 useEffect가 너무 민감했어요**

**React**는 웹사이트의 화면을 관리하는 도구예요. 그중 **useEffect**는 "특정 상황에만 실행해!"라고 명령하는 기능입니다. 예를 들어, "사용자가 바뀌면 데이터를 새로 불러와!" 같은 식으로요.

**문제 비유**: 여러분이 친구에게 "옷 색깔이 바뀌면 전화해!"라고 했는데, 친구가 옷 색깔이 같아도 새 옷을 입을 때마다 전화하는 거예요. 😅

**코드 예시**:

```jsx
// ❌ 잘못된 코드
useEffect(() => {
  console.log('데이터를 다시 불러옴!')
}, [user]) // user는 객체 { id: 1, name: "Alice" }
```

여기서 `user`는 객체예요. 객체는 같은 내용이라도 새로 만들면 "다른 것"으로 인식돼요. 그래서 탭을 바꿀 때마다 `useEffect`가 실행되면서 페이지가 새로고침됐어요.

**해결 비유**: "옷 색깔 대신 친구의 이름이 바뀔 때만 전화해!"라고 바꾼 거예요. 이름은 단순한 텍스트라서 같은 이름이면 동일하게 인식돼요.

**개선된 코드**:

```jsx
// ✅ 좋은 코드
useEffect(() => {
  console.log('데이터를 불러옴!')
}, [user?.id]) // user.id는 숫자 1, 바뀌지 않으면 실행 안 함
```

**왜 좋아졌나요?** `user.id`는 숫자(원시값)라서 같은 값이면 동일하게 인식됩니다. 이렇게 하면 불필요한 새로고침이 줄어들어요.

---

### 2. **로그인 확인을 너무 많이 했어요**

**Supabase**는 로그인 정보를 관리하는 도구예요. 웹사이트의 여러 부분(예: 헤더, 프로필 페이지)에서 "지금 로그인한 사용자가 누구지?"를 확인했어요. 하지만 각 부분이 따로따로 확인하니까 서버에 요청이 너무 많이 갔어요.

**문제 비유**: 여러분이 집에 들어갈 때마다 문마다 열쇠를 확인하는 거예요. 한 번만 확인하면 되는데, 매번 확인하니까 시간이 걸리죠. 😓

**코드 예시**:

```jsx
// ❌ 잘못된 코드
// 헤더에서
const {
  data: { session },
} = await supabase.auth.getSession()
// 프로필 페이지에서
const {
  data: { session },
} = await supabase.auth.getSession()
```

**해결 비유**: 집 열쇠를 한 곳에 보관하고, 필요할 때마다 그곳에서 가져오는 거예요. 이렇게 하면 한 번만 확인하면 돼요.

**개선된 코드**:

```jsx
// ✅ 좋은 코드
const { getAccessToken } = useAuthStore.getState()
const token = await getAccessToken() // 한 곳에서 관리
```

**왜 좋아졌나요?** **Zustand**라는 도구로 로그인 정보를 한 곳에서 관리해서, 중복 요청이 줄어들었어요.

---

### 3. **로그인 이벤트가 불필요하게 반복됐어요**

Supabase는 사용자가 로그인하거나 로그아웃할 때 이벤트를 보내요. 그런데 **탭을 바꾸는 것도 이벤트로 인식**해서, 같은 사용자인데도 불필요하게 데이터를 다시 불러왔어요.

**문제 비유**: 여러분이 집에 들어왔다고 친구에게 전화했는데, 방에서 방으로 이동할 때마다 다시 전화하는 거예요. 😅

**코드 예시**:

```jsx
// ❌ 잘못된 코드
if (event === 'SIGNED_IN' && session?.user) {
  set({ user: session.user })
  await refreshProfile() // 항상 데이터를 새로 불러옴
}
```

**해결 비유**: "같은 사람이면 전화하지 마!"라고 조건을 추가한 거예요.

**개선된 코드**:

```jsx
// ✅ 좋은 코드
if (event === 'SIGNED_IN' && session?.user) {
  const currentUser = get().user
  if (currentUser && currentUser.id === session.user.id) {
    console.log('같은 사람이야, 새로 안 불러!')
    return
  }
  set({ user: session.user })
  await refreshProfile()
}
```

**왜 좋아졌나요?** 같은 사용자라면 데이터를 다시 안 불러오니까 성능이 좋아졌어요.

## 🔧 어떻게 고쳤나요? (단계별로 쉽게)

이제 문서에 나온 **7단계 해결 과정**을 하나씩 쉽게 설명할게요. 각 단계는 특정 파일에서 문제를 고친 거예요. 비유와 함께 이해하기 쉽게 풀어볼게요!

### 🛠 단계 1: 로그인 정보 관리 개선 (authStore.ts)

**문제**: 탭을 바꿀 때마다 Supabase가 "로그인 됐다!"고 이벤트(`SIGNED_IN`)를 보내서, 같은 사용자의 프로필을 계속 새로 불러왔어요.

**비유**: 여러분이 친구에게 "집에 왔어!"라고 매번 전화하는데, 같은 집에 있는데도 전화하는 거예요.

**해결 방법**: 같은 사용자면 프로필을 새로 안 불러오도록 조건을 추가했어요.

```jsx
// ❌ 잘못된 코드
if (event === 'SIGNED_IN' && session?.user) {
  await refreshProfile() // 매번 실행
}

// ✅ 개선된 코드
if (event === 'SIGNED_IN' && session?.user) {
  const currentUser = get().user
  if (currentUser && currentUser.id === session.user.id) {
    console.log('같은 사용자, 스킵!')
    return
  }
  await refreshProfile()
}
```

**왜 좋아졌나요?** 불필요한 프로필 로드를 막아서 페이지가 새로고침되지 않았어요.

---

### 🛠 단계 2: 헤더에서 로그인 확인 개선 (Header.tsx)

**문제**: 헤더 컴포넌트가 직접 Supabase에 로그인 정보를 물어보는 바람에 서버 요청이 늘어났어요.

**비유**: 집 열쇠를 매번 금고에서 꺼내 확인하는 대신, 열쇠를 한 곳에 보관하고 필요할 때 가져오는 거예요.

**해결 방법**: Zustand의 `useAuthStore`를 사용해 로그인 정보를 한 곳에서 관리했어요.

```jsx
// ❌ 잘못된 코드
const {
  data: { session },
} = await supabase.auth.getSession()

// ✅ 개선된 코드
const { getAccessToken } = useAuthStore.getState()
const accessToken = await getAccessToken()
```

**왜 좋아졌나요?** 서버에 직접 요청하지 않고, 이미 저장된 정보를 사용해서 빠르고 효율적이에요.

---

### 🛠 단계 3: 채팅 기능 최적화 (useChat.ts)

**문제**: 채팅 기능을 관리하는 코드가 `user` 객체 전체를 의존성으로 사용해서, 탭 전환 시마다 불필요하게 실행됐어요.

**비유**: 친구의 옷 전체가 바뀔 때 전화하라고 했는데, 같은 옷인데 새로 입을 때마다 전화하는 거예요.

**해결 방법**: `user.id`만 사용해서 필요한 경우에만 실행되도록 했어요.

```jsx
// ❌ 잘못된 코드
useEffect(() => {
  if (user) subscribeToChats()
}, [user]) // user 객체 전체

// ✅ 개선된 코드
useEffect(() => {
  if (user?.id) subscribeToChats()
}, [user?.id]) // user.id만
```

**왜 좋아졌나요?** `user.id`는 바뀌지 않으면 실행 안 되니까 불필요한 채팅 로드가 없어졌어요.

---

### 🛠 단계 4: 프로필 기능 최적화 (useProfile.ts)

**문제**: 프로필 정보를 가져오는 코드도 `user` 객체를 의존성으로 사용하고, 직접 Supabase에 요청했어요.

**비유**: 매번 친구에게 이름과 전화번호를 물어보는 대신, 이미 저장된 친구 목록에서 확인하는 거예요.

**해결 방법**: `user.id`를 사용하고, Zustand로 로그인 정보를 관리했어요.

```jsx
// ❌ 잘못된 코드
const fetchProfileData = useCallback(async () => {
  const {
    data: { session },
  } = await supabase.auth.getSession()
}, [user])

// ✅ 개선된 코드
const fetchProfileData = useCallback(async () => {
  const { getAccessToken } = useAuthStore.getState()
  const accessToken = await getAccessToken()
}, [user?.id])
```

**왜 좋아졌나요?** 불필요한 요청과 새로고침이 줄어들었어요.

---

### 🛠 단계 5: 인증 초기화 최적화 (AuthProvider.tsx)

**문제**: 인증을 초기화하는 코드가 불필요하게 자주 실행됐어요. `initialize` 함수를 의존성에 넣어서 함수가 바뀔 때마다 실행된 거예요.

**비유**: 집에 들어갈 때마다 집 전체를 청소하는 거예요. 한 번만 하면 되는데 말이죠.

**해결 방법**: 의존성 배열을 비워서 한 번만 실행되도록 했어요.

```jsx
// ❌ 잘못된 코드
useEffect(() => {
  initialize()
}, [initialize]) // 함수가 바뀔 때마다 실행

// ✅ 개선된 코드
useEffect(() => {
  initialize()
}, []) // 한 번만 실행
```

**왜 좋아졌나요?** 초기화가 한 번만 실행되니까 성능이 좋아졌어요.

---

### 🛠 단계 6: 글 작성 페이지 최적화 (edit/page.tsx)

**문제**: 글 작성 페이지에서 데이터를 불러오는 코드가 `user` 객체를 의존성으로 사용해서, 탭 전환 시마다 새로고침됐어요.

**비유**: 글을 쓰는데, 책상 서랍을 매번 새로 정리하는 거예요.

**해결 방법**: `user.id`만 사용해서 필요한 경우에만 데이터를 불러왔어요.

```jsx
// ❌ 잘못된 코드
useEffect(() => {
  loadPostData()
}, [params.id, user])

// ✅ 개선된 코드
useEffect(() => {
  loadPostData()
}, [params.id, user?.id])
```

**왜 좋아졌나요?** 작성 중인 글이 사라지지 않고 유지됐어요.

---

### 🛠 단계 7: 인증 유틸리티 중앙화 (auth.ts)

**문제**: 로그인 확인 함수가 직접 Supabase에 요청해서 비효율적이었어요.

**비유**: 매번 은행에 가서 잔고를 확인하는 대신, 앱으로 잔고를 관리하는 거예요.

**해결 방법**: Zustand를 사용해 중앙화된 로그인 확인을 했어요.

```jsx
// ❌ 잘못된 코드
export const checkSessionWithRedirect = async () => {
  const {
    data: { session },
  } = await supabase.auth.getSession()
}

// ✅ 개선된 코드
export const checkSessionWithRedirect = async () => {
  const { getAccessToken } = useAuthStore.getState()
  const accessToken = await getAccessToken()
}
```

**왜 좋아졌나요?** 중복 요청이 줄어들어 성능이 좋아졌어요.

## 🎯 핵심 개념 쉽게 이해하기

문서에 나온 개념들을 초보자도 이해할 수 있도록 비유와 함께 설명할게요.

### 1. **React 의존성 배열**

**의존성 배열**은 `useEffect`가 언제 실행될지 결정하는 리스트예요. 여기에 잘못된 값을 넣으면 문제가 생깁니다.

**비유**: 여러분이 "친구가 새 옷을 입으면 전화해!"라고 했는데, 친구가 같은 옷을 새로 입을 때마다 전화하면 짜증나죠. 😅

**코드 예시**:

```jsx
const user1 = { id: 1, name: 'Alice' }
const user2 = { id: 1, name: 'Alice' }
console.log(user1 === user2) // false (다른 객체)
console.log(user1.id === user2.id) // true (같은 숫자)
```

**교훈**: 객체 대신 숫자나 문자열 같은 단순한 값(`id`)을 사용하세요.

---

### 2. **중앙화된 상태 관리**

**Zustand**는 데이터를 한 곳에 모아서 관리하는 도구예요. 여러 컴포넌트가 각자 데이터를 관리하면 혼란이 생깁니다.

**비유**: 집에 열쇠를 각 방마다 두는 대신, 한 곳에 보관하면 찾기 쉬워요.

**코드 예시**:

```jsx
// ❌ 각자 관리
const session1 = await supabase.auth.getSession() // 헤더
const session2 = await supabase.auth.getSession() // 프로필

// ✅ 한 곳에서 관리
const { getAccessToken } = useAuthStore.getState()
const token = await getAccessToken()
```

**교훈**: 데이터를 한 곳에서 관리하면 코드가 간단하고 빠릅니다.

### 3. **불필요한 리렌더링 방지**

웹사이트가 불필요하게 다시 그려지면 느려져요. 이를 방지하려면 안정적인 값을 사용해야 해요.

**비유**: 매번 새 노트에 같은 메모를 쓰는 대신, 기존 노트를 재사용하는 거예요.

**코드 예시**:

```jsx
// ❌ 매번 새 객체
const userInfo = { id: user.id } // 새 객체 생성
useEffect(() => {}, [userInfo]) // 매번 실행

// ✅ 안정적인 값
useEffect(() => {}, [user.id]) // user.id가 바뀔 때만 실행
```

**교훈**: 단순한 값(`id`)을 사용해 불필요한 작업을 줄이세요.

## 🔧 초보자를 위한 코드 팁

### 1. **안전한 useEffect**

`useEffect`는 꼭 필요한 값만 의존성에 넣으세요.

```jsx
// ✅ 좋은 코드
useEffect(() => {
  if (!user?.id) return
  fetchData()
}, [user?.id])

// ❌ 잘못된 코드
useEffect(() => {
  fetchData()
}, [user]) // 객체 전체 사용
```

**비유**: 친구 이름이 바뀔 때만 전화, 옷 전체가 바뀌면 전화하지 마!

// ✅ 좋은 코드
const token = await useAuthStore.getState().getAccessToken()

const {
  data: { session },

**비유**: 열쇠를 한 곳에 보관하세요!
