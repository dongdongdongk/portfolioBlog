# { SignIn 컨트롤러 테스트 작성 }

```jsx
이 강의는 SignIn 컨트롤러에 대한 테스트 코드를 작성하는 과정을 다룹니다.

테스트는 주로 입력값 검증, 오류 처리, 성공적인 응답 확인을 중심으로 이루어집니다.
```

## 필요한 모듈 및 목(mock) 가져오기

```jsx
테스트를 위해 필요한 모듈과 목(mock)을 가져옵니다.

		authMock, authMockRequest, authMockResponse:

				목 객체와 요청/응답 객체를 만듭니다.


		jest.useFakeTimers():

				테스트에서 시간을 다룰 때 Jest의 가짜 타이머를 사용합니다.


		jest.mock('@service/queues/base.queue'):

				의존성을 목(mock) 처리하여 큐 서비스의 실제 호출을 방지합니다.
```

## 테스트 사례 (Test Cases)

### 필수 필드 검증

```jsx
사용자 이름(username)과 비밀번호(password)가 요청(req.body)에 없을 경우를 테스트합니다.

요구사항:

		username이 없으면 "Username is a required field" 오류 반환.

		password가 없으면 "Password is a required field" 오류 반환.
```

```jsx
it('should throw an error if username is not available', () => {
  const req = authMockRequest({}, { username: '', password: PASSWORD }) as Request;
```

### 성공적인 응답

```jsx
모든 검증이 통과하고 로그인에 성공했을 때 반환 값을 확인합니다.
```

## 비밀번호 테스트

```jsx
비밀번호 관련 컨트롤러는 create(비밀번호 초기화 이메일 전송)와 update(비밀번호 재설정) 두 가지 주요 메서드로 구성됨.

각각의 테스트는 다양한 입력 상황과 기대 결과를 확인.
```

### `create` 메서드 테스트

```jsx
이메일 형식이 잘못되었을 때

		joi 라이브러리로 이메일 형식 검증.

		잘못된 형식의 이메일(INVALID_EMAIL) 입력 시, 400 상태코드와 에러 메시지 반환 확인.
```

```jsx
it('should throw an error if email is invalid', () => {
  // Mock 요청 객체 생성: 이메일 필드에 INVALID_EMAIL 사용
  const req = authMockRequest({}, { email: INVALID_EMAIL }) as Request;
  const res = authMockResponse(); // Mock 응답 객체 생성

  // Password 컨트롤러의 create 메서드를 실행하고 에러 검증
  Password.prototype.create(req, res).catch((error: CustomError) => {
    // 에러 상태 코드가 400인지 확인
    expect(error.statusCode).toEqual(400);
    // 에러 메시지가 "Field must be valid"인지 확인
    expect(error.serializeErrors().message).toEqual('Field must be valid');
  });
});

```

```jsx
authMockRequest는 테스트 환경에서 가짜 요청 객체를 생성합니다.

Password.prototype.create는 비밀번호 재설정 요청을 처리하는 메서드입니다.

catch 구문으로 예외가 발생했는지 확인하며, 이를 통해 입력 유효성 검사를 테스트합니다.

expect는 Jest의 단언문으로, 결과가 기대값과 일치하는지 확인합니다.
```

### 존재하지 않는 이메일일 때

```jsx
이메일이 데이터베이스에 없으면 Invalid credentials 에러 반환 확인.

```

```jsx

이 테스트는 데이터베이스에 없는 이메일로 요청을 보냈을 때의 동작을 확인합니다.
```

### 성공적으로 이메일 전송

```jsx
데이터베이스에 유효한 이메일이 있을 경우, emailQueue.addEmailJob 호출 확인.

반환된 응답(JSON 형식)의 상태 코드와 메시지를 확인.
```

```jsx
it('should send correct json response', async () => {
  const req = authMockRequest({}, { email: CORRECT_EMAIL }) as Request;
  const res = authMockResponse();

  // 이메일로 사용자 조회 시 Mock 데이터 반환 설정
  jest.spyOn(authService, 'getAuthUserByEmail').mockResolvedValue(authMock);

  // 이메일 전송 작업을 Mock 처리
  jest.spyOn(emailQueue, 'addEmailJob');

  // 비밀번호 재설정 요청 처리
  await Password.prototype.create(req, res);

  // 이메일 작업이 호출되었는지 확인

  // HTTP 상태 코드 200 확인
  expect(res.status).toHaveBeenCalledWith(200);

  // JSON 응답이 예상과 일치하는지 확인

    message: 'Password reset email sent.'
  });
});

```

```jsx
await 키워드를 사용하여 비동기 처리를 기다립니다.

res.json은 응답 본문이 정확한지 확인합니다.
```

## 현재 사용자 테스트 파일

```jsx
// 필요한 모듈과 클래스, 데이터를 import합니다.
import { Request, Response } from 'express';
import { CurrentUser } from '@auth/controllers/current-user'; // 현재 사용자 정보를 처리하는 컨트롤러
import { authMockRequest, authMockResponse, authUserPayload } from '@root/mocks/auth.mock'; // 모의 요청 및 응답 객체
import { existingUser } from '@root/mocks/user.mock'; // 기존 사용자 데이터를 포함한 목 데이터
import { UserCache } from '@service/redis/user.cache'; // Redis 캐시 서비스
import { IUserDocument } from '@user/interfaces/user.interface'; // 사용자 데이터 인터페이스 정의

// Jest를 사용해 Redis 캐시, DB 서비스 및 큐를 모의(mock) 처리
jest.mock('@service/queues/base.queue');
jest.mock('@service/redis/user.cache');
jest.mock('@service/db/user.service');

// 테스트를 위한 사용자 이름과 비밀번호 상수
const USERNAME = 'Manny';
const PASSWORD = 'manny1';

// 테스트 파일의 최상위 describe 블록
describe('CurrentUser', () => {
  // 각 테스트 전에 기존의 모의 객체 및 설정을 초기화합니다.
  beforeEach(() => {
    jest.restoreAllMocks();
  });

  // 각 테스트 후 모의 객체를 정리합니다.
  afterEach(() => {
    jest.clearAllMocks();
  });

  // 현재 사용자 상태 확인 테스트 블록
  describe('token', () => {
    // **케이스 1**: 사용자가 존재하지 않을 때
    it('사용자가 없을 경우 세션 토큰을 null로 설정하고 JSON 응답을 반환한다.', async () => {
      // 요청과 응답 객체를 모의로 생성
      const req: Request = authMockRequest({}, { username: USERNAME, password: PASSWORD }, authUserPayload) as Request;
      const res: Response = authMockResponse();

      // Redis 캐시에서 사용자 데이터를 빈 객체로 모의 처리
      jest.spyOn(UserCache.prototype, 'getUserFromCache').mockResolvedValue({} as IUserDocument);
      // prototype은 JavaScript에서 모든 클래스가 공유하는 속성입니다 이를 사용하면 UserCache 클래스의 모든 인스턴스에서 공통으로 사용하는 메서드를 가리킵니다.
      // 즉, UserCache.prototype.getUserFromCache는 UserCache의 모든 객체에서 호출될 수 있는 메서드를 가리킵니다.
      // UserCache.prototype에 정의된 메서드 중 'getUserFromCache' 메서드만 감시하거나 가로채겠다는 뜻입니다.

      // 현재 사용자 컨트롤러의 read 메서드를 호출
      await CurrentUser.prototype.read(req, res);

      // 응답 코드와 JSON 데이터를 검증
      expect(res.status).toHaveBeenCalledWith(200);
      expect(res.json).toHaveBeenCalledWith({
        token: null, // 세션 토큰이 없음

      jest.spyOn(UserCache.prototype, 'getUserFromCache').mockResolvedValue(existingUser);

      // 현재 사용자 컨트롤러의 read 메서드를 호출
      await CurrentUser.prototype.read(req, res);

      expect(res.status).toHaveBeenCalledWith(200);
      expect(res.json).toHaveBeenCalledWith({

      });
```

```jsx
1. describe 블록: 테스트의 그룹을 정의합니다. 여기서는 CurrentUser라는 컨트롤러 테스트를 묶음.

3. Redis 캐시와의 연동 모의 (jest.spyOn): Redis에서 데이터를 가져오는 부분을 목(mock)으로 처리해 테스트 환경에서 DB에 접근하지 않도록 합니다.

4. 테스트 케이스:

		사용자가 없을 때: 캐시에서 빈 데이터를 반환하며, JSON 응답으로 null, false를 반환하는지 확인.

		사용자가 있을 때: 캐시에서 사용자 데이터를 반환하며, 세션에 저장된 JWT 토큰 및 사용자 데이터를 응답하는지 확인.

5. expect 메서드: 결과 검증으로, 응답 상태 코드와 JSON 데이터를 비교합니다.
```
