## 1. 스카이박스 교체 & 회전 값

- Hierarchy 우클릭 → **Lighting → Skybox** 선택
- Inspector 상단 **Material 슬롯**에 `Dream` 스카이박스 드래그
- Rotation: **Y = 90** (석양 방향) → 실시간으로 그림자 방향 바뀜
- 팁: 회전 값은 0~360 사이 실수로도 입력 가능

## 2. 환경광(Environment Lighting) 세팅

1. **Window → Rendering → Lighting → Environment** 탭 열기
2. **Source = Skybox** (기본값) 유지
3. **Intensity Multiplier = 1** (0.8~1.2 사이로 조정 가능)
4. **Ambient Mode = Skybox** (색이 스카이박스 색 그대로 반영)
5. **Reflections → Source = Skybox** (또는 Custom 컬러로 분위기 전환 가능)
   - Custom으로 바꾸면 아래 **Ambient Color** 피커 활성화 → 원하는 톤으로 변경

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380779/notion-blog/_/_/_3D_/image_1.png)

## 3. 포그(Fog)로 깊감 & 최적화

- **Window → Rendering → Lighting → Other Settings → Fog** 체크
- Mode = **Exponential** (Linear도 가능)
- **Density = 0.15** (0.05 단위로 조절)
- **Color**는 스카이박스 하늘색과 동일하게 맞춤 → 멀리 있는 물체가 자연스럽게 사라짐
- **최적화 포인트**: 멀리 있는 오브젝트를 실제로 제거하지 않아도 보이지 않게 되므로 **LOD 그룹·카메라 Far Clip**과 함께 사용 시 성능 ↑

## 4. 그림자 품질 2단계 올리기

### 4-1. Shadow Atlas (그림자 텍스 atlas 크기)

- **Edit → Project Settings → Graphics → 현재 사용 중 SRP Asset(URP Asset) 선택**
- **Lighting → Shadow Atlas Resolution = 2048** → 4096 또는 8192로 올릴수록 선명
  - 8192은 **메모리 4배** 소비 → 모바일은 2048 권장

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380781/notion-blog/_/_/_3D_/image_2.png)

### 4-2. Shadow Resolution per Light

- **Directional Light(태양) 선택 → Shadow → Resolution = High**
  - **Medium → High → Very High** 순으로 증가, 메모리 ↑
- **Normal Bias = 0** (기본 0.5 → 0으로 내리면 틈새 그림자 제거)
- **Near Plane = 0.2** (너무 낮으면 도형 겹침 그림자 깨짐)

## X. 벽에 그림자가 생기지 않는 오류 해결하기

### X-1. 원인: 메시 뒷면(Backface)이 없음

- 대부분의 환경 오브젝트(벽, 얇은 판넬 등)는 **앞면만 존재하는 단면(mesh single face)** 구조
- **뒷면이 존재하지 않기 때문에** 빛이 닿는 면(Front Face) 외에는 **그림자를 받을 면 자체가 없음**
- 결과 → **벽이 그림자를 받지 않거나 구멍 난 것처럼 보임**

---

### X-2. 해결: Material → Render Face 를 Both(양면)으로 변경

- Unity에서는 재질 단위로 면의 렌더링 방향을 설정할 수 있음
- 문제 오브젝트가 사용하는 **Material → Rendering → Render Face → Both** 설정
- **양면 렌더링 = Backface도 시각적으로 생성**되어 그림자 정상 수신됨

**설정 경로:**

- **오브젝트 선택 → Inspector → Material → Rendering → Render Face → Both**

---

### X-3. 주의사항: 성능 비용 증가

- Render Face = Both 는 **앞면 + 뒷면 두 번 렌더링**
- 실제로 강의에서도 “연산량이 2배라서 꼭 필요한 벽만 적용” 강조
- 최적화 기준:
  - **필수 벽 / 실내 구조물** → Both
  - **작은 디테일 오브젝트(파이프, 선, 장식물 등)** → 그대로 Front 유지 (성능 절약)

---

### X-4. 여러 벽이 사용할 경우: Material 공유 여부 확인

- 벽이 여러 개라도 같은 머티리얼을 쓰면 **한 번 수정하면 전부 반영됨**
- Material 클릭 시 씬에서 **하이라이트로 어디에 적용됐는지 표시됨**
- 벽/천장/조인트 등 특정 부분만 문제 있을 경우,
  해당 머티리얼만 따로 분리하여 Both 적용하는 것이 안전

---

### X-5. 그림자 문제 해결 후: 라이트맵 베이크 준비

- 그림자 문제를 해결한 뒤에는 **라이트맵을 굽기 전에 구조 단순화 필요**
- 라이트맵에는 **큰 구조물(벽/바닥/천장)**만 포함
- 파이프나 작은 장식물은 **라이트맵 제외**하고 나중에 Light Probe/Reflection Probe로 커버

**이유:**

- 작은 기물까지 포함하면 베이크 시간이 급격히 증가
- 그림자가 핵심인 큰 구조물만 굽는 것이 효율적

## X. 프리팹 내부 오브젝트 정리 및 그룹핑하기

### X-1. 여러 오브젝트 선택 시 확인 절차

- 복잡한 씬에서 다수의 메시를 선택할 때는
  **선택 범위(예: 132번 ~ 143번)**가 정확한지 반드시 확인
- **Hierarchy에서 선택 ON/OFF(활성/비활성)** 하여
  내가 선택한 오브젝트만 맞는지 시각적으로 체크

---

### X-2. 선택한 오브젝트를 부모로 묶는 기능 (Create Empty Parent)

Unity는 **한 번에 여러 오브젝트를 묶는 전용 기능**을 제공함.

**사용 방법:**

- 여러 오브젝트 선택 → **우클릭 → Create Empty Parent**
- 선택된 오브젝트의 **상위에 새로운 Empty GameObject 생성**
- 기존 자식 구조는 그대로 유지하면서 부모만 생김
  → 정리 및 라이트맵 작업 시 매우 편리

---

### X-3. “Create Empty Parent”가 안 되는 이유: 프리팹 모드 외부에서 실행했기 때문

- 프리팹 내부 오브젝트의 **Hierarchy 구조 변경(부모/자식 수정)** 은
  **Prefab Mode** 안에서만 가능
- 강의에서 기능이 안 되었던 이유 → **프리팹 모드가 아닌 일반 씬에서 편집 중**

**해결:**

- 프리팹 더블클릭 → **Prefab Mode 진입**
- 씬 상단에 **파란 헤더**가 뜨면 정상적으로 진입된 상태

---

### X-4. Prefab Mode에서 다시 정상적으로 그룹핑

Prefab Mode에서 다시 선택 후 Create Empty Parent 실행:

- 벽 그룹 → **Walls**
- 바닥 그룹 → **Ground**
- 파이프/잔해/소품류 → **Props**

이 과정을 통해 프리팹 내부 구조가 **정갈하게 정리**됨.

---

### X-5. 결과: 가독성과 라이트맵 작업 효율 상승

- 복잡한 FPS/스텔스 맵에서도 구조가 한눈에 보임
- 라이트맵 베이크 시
  - **Walls/Ground → Lightmap Static**
  - **Props → Static 해제 or Light Probe 사용**
    로 관리하기 쉽게 됨
- 향후 레벨 디자인/최적화 작업도 훨씬 수월

### 5-1. Static 설정

- 벽·바닥·큰 구조물만 **Hierarchy Ctrl+선택** → **Inspector 상단 Static 체크**

### 5-2. Light 모드 변경

- **Directional Light → Mode = Mixed** (Baked도 가능)
  - Mixed: 실시간 + 베이크 혼용, Bake: 완전 고정, Realtime: 매 프레임 연산

### 5-3. Lighting 창 열기

- **Window → Rendering → Lighting → New Lighting Settings** 클릭
- 이름: **Stealth** (임의)

## 6. GPU Residency Draw로 DrawCall 100→50↓

- **Project Settings → Graphics → SRP Asset → Rendering → GPU Resident Drawer**
  - **Default = Disabled** → **Instanced Drawing** 로 변경
- **Settings → Graphics → Batch Renderer Group Variants** 체크 (자동 팝업)
- **Play Mode** 진입 → **Game 창 → Stats** → **Batches** 비교
  - 꺼졌을 때: **157** → 켰을 때: **100** → 다시 풀옵션 켜고 비교 → **최종 50**
- 원리: **동일 Mesh+Material 조합을 GPU가 한 번에 그림** → CPU 부하 ↓

## 7. Adaptive Probe Volume(라이트 프로브 최신판)

- **Project Settings → Graphics → Light Probe System = Adaptive Probe Volume** 선택
- **Hierarchy → Light → Adaptive Probe Volume** 추가 → 전체 맵을 Box로 감싸게 자동 확장
- **Inspector → Bake Probe Volume** 버튼 클릭 (라이트맵 베이크 후 실행)
- 작은 소품(파이프, 데브리, 튜브 등)은 **Mesh Renderer → Receive Global Illumination = Light Probes** 로 변경
  → 베이크 대상에서 제외 → Lightmap 텍스처 크기 ↓, 빌드 시간 ↓

## Light Probes (기존 방식) vs Adaptive Probe Volume(APV)

| 항목      | **Light Probes**              | **Adaptive Probe Volume(APV)**     |
| --------- | ----------------------------- | ---------------------------------- |
| 무엇?     | 오래된 간접광 시스템 (Legacy) | 최신 버전의 발전형 GI 시스템       |
| 설치 방식 | 수동으로 Light Probe 배치     | 자동으로 씬에 Probe를 촘촘히 배치  |
| 업데이트  | 베이크 필요 / 거의 고정       | 자동 업데이트 / 실시간 보정도 가능 |
| 정확도    | 낮음                          | 매우 높음 (상황 따라 실시간 대응)  |
| 성능      | 가벼움                        | 더 무거움 (하지만 효율적)          |
| 용도      | 작은 씬, 간단한 GI            | 큰 맵, 오픈월드, 사실적 GI         |

---

### 🎨 1) Light Probes (기존 방식)

### ✔ 어떤 기능?

- **간접광(Indirect Lighting)을 보간해서 제공**
- \*Dynamic Object(움직이는 오브젝트)\*\*에 간접광을 줄 때 사용
- 플레이어, 적 NPC, 아이템 같은 **움직이는 것에만 적용됨**
- **전통 Bake 방식**이라 정적임

### ✔ 어떻게 사용해?

1. 개발자가 Light Probe를 일일이 배치
2. 베이크 버튼 누름
3. 움직이는 오브젝트들이 그 근처 Probes를 보간해서 색을 받음

### ✔ 장점

- 매우 가벼움
- 유니티 오래된 프로젝트와 호환됨

### ✔ 단점

- 정확도가 낮음
- 수동 배치가 번거로움
- 오픈 월드에서는 관리 불가 수준

---

### 🚀 2) Adaptive Probe Volume(APV)

**유니티 최신 “GI 시스템”**(특히 HDRP에서 많이 사용).

### ✔ 어떤 기능?

- **Probe를 씬 전체에 자동으로 촘촘하게 채움**
- **오브젝트를 움직여도 자동으로 조명 업데이트**
- 대규모 맵에서 **고퀄리티 간접광(GI)** 제공
- **Light Probe Volume의 완전 상위 버전**

### ✔ 왜 “Adaptive”?

씬을 분석해서 필요한 곳에는 조밀하게

불필요한 곳은 느슨하게 배치함.

즉 GI 품질과 성능 사이에서 자동으로 균형 잡음.

### ✔ 장점

- 정확도 뛰어남 (빛이 더 자연스럽고 부드럽게 반사됨)
- 오픈 월드에 적합
- 자동 Probe 생성 → 작업량 줄음
- 움직이는 오브젝트도 자연스럽게 GI 적용

### ✔ 단점

- 비교적 무거움
- HDRP 또는 최신 렌더 파이프라인 필요

---

# 📌 **0. 전체 라이팅 파이프라인 구조부터 이해하자**

씬에 빛을 넣는 과정은 사실 이렇게 4단계로 나뉜다:

### 1) 장면 분위기 세팅

- 스카이박스
- 환경광
- 포그

### 2) 그림자를 더 선명하고 자연스럽게 만들기

- Shadow Atlas
- Light Shadow Resolution
- Normal Bias 조절

### 3) 성능을 최적화하며 실제처럼 보이게 하는 조명

- Lightmap Bake
- Light Probe / Adaptive Probe Volume

### 4) CPU 부담 줄이는 렌더링 최적화

- GPU Resident Drawer
- Static vs Dynamic 구분

이걸 순서대로 하면 **이쁘고 + 빠르고 + 안정적인 씬**이 완성됨.

---

# 1️⃣ 스카이박스(Skybox) — “장면의 기본 색”을 정하는 하늘 배경

### ✔️ 초보 설명

스카이박스는 씬을 감싸는 **커다란 하늘 박스**야.

빛의 색, 그림자 색, 전체 장면의 분위기는 거의 "하늘색"에 의해 결정돼.

- 파란 하늘 → 파란 환경광
- 붉은 석양 → 주황빛 그림자
- 실내(검은 스카이박스) → 어둡고 대비 강함

### ✔️ 왜 회전이 중요한데?

스카이박스의 태양 위치가 그림자 방향을 결정할 수 있기 때문.

---

# 2️⃣ 환경광(Environment Lighting) — “그림자가 완전히 까맣지 않게 하는 기본 빛”

### ✔️ 초보 설명

빛이 닿지 않는 곳도 적당히 보이게 만들어주는 조명.

방 안에 불을 껐는데도

벽이나 책상이 완전 까만 실루엣은 아니잖아?

그 이유가 **환경광** 같은 역할 때문이야.

### ✔️ 핵심

- Source: Skybox
  → 하늘색을 기준으로 전체 씬에 빛을 깔아준다.
- Intensity Multiplier
  → 전체 밝기 총괄 스위치
- Ambient Mode = Skybox
  → 대부분 이렇게 둔다. 실무에서도 99% Skybox.

---

# 3️⃣ 포그(Fog) — 멀어지면 희미해져서 더 고퀄처럼 보이는 기술

### ✔️ 초보 설명

현실에서도 멀리 있는 산은 흐릿하게 보여.

게임에서도 똑같이 구현하는 게 **포그**야.

장점:

1. **원근감 생김**
2. **멀리 있는 오브젝트를 사실상 안 보여주므로 최적화**
3. **스카이박스와 자연스럽게 연결됨**

### ✔️ Exponential Fog가 자주 쓰이는 이유

거리에 따라 점점 빠르게 농도가 증가해서 현실에 더 가까움.

---

# 4️⃣ Shadow 품질 — 그림자가 왜 깨지고, 왜 부자연스럽게 보이는가?

Shadow Atlas = “그림자 저장하는 큰 종이”

종이가 작으면?

→ 그림자가 픽셀처럼 깨짐 (블러리, 계단현상)

종이가 크면?

→ 선명한 고해상도 그림자

그래서 2048 → 4096 → 8192로 늘리는 것.

### ✔️ Normal Bias를 0으로 줄이면 좋은 이유

Bias는 “그림자가 살짝 떠 있는 것처럼 밀어내는 값”.

- Bias 높음 → 그림자가 벽에서 떨어져 뜬 것처럼 보임
- Bias 낮음 → 벽에 밀착된 자연스러운 그림자

---

# 5️⃣ 라이트맵 베이크 — 성능과 퀄리티를 동시에 잡는 진짜 핵심 기술

### ✔️ 초보 설명

라이트맵은 **“빛과 그림자를 이미지로 구워놓는 기술”**이야.

원래 빛은 프레임마다 매번 계산해야 하지만

라이트맵은 계산을 아예 '이미지'로 미리 그려놓음.

→ 성능 폭등 (CPU/GPU 부하 거의 없음)

→ 정적인 오브젝트는 고퀄 그림자 얻음

→ 빌드 파일 사이즈는 조금 늘어남

### ✔️ 왜 큰 구조물만 Static?

바닥·벽·지붕 같은 애들은 절대 안 움직이니까

그림자를 이미지로 구워놓는 게 최고 효율.

작은 소품이나 오브젝트는 Light Probe로 해결하면 됨.

---

# 6️⃣ GPU Resident Drawer — “동일 오브젝트는 한 번에 그리는 기술”

### ✔️ 초보 설명

CPU가 모든 오브젝트를 하나씩 그리라고 명령하는 건 힘들다.

하지만 GPU는 동일한 메쉬·재질이면 한 번에 그릴 수 있음.

이걸 **Instance Rendering(인스턴싱)**이라고 함.

### GPU Resident Drawer는 이걸 자동화해주는 최신 기능

- 켜기 전:
  CPU: “이거 그려, 이거도, 이거도, 이거도…(157번)”
- 켠 후:
  CPU: “같은 박스 100개? GPU야 니가 알아서 해줘”
  → 50번으로 줄어드는 이유

---

# 7️⃣ Adaptive Probe Volume — “Light Probe의 자동 업그레이드 버전”

### ✔️ 초보 설명

Light Probe는 **움직이는 오브젝트가 반사광/간접광을 받게 하는 기술**

(라이트맵은 정적인 오브젝트만 가능)

APV(Adaptive Probe Volume)는

이걸 자동으로 높은 퀄리티로 계산해주는 최신 기능.

기존에는 Probe를 수동으로 바둑판처럼 깔아야 했지만

APV는 공간을 자동으로 채워줘서 실무에서 선호됨.

장점:

1. 소품은 Lightmap 필요 없음 (용량↓, 시간↓)
2. 캐릭터·적군·무기 등에 간접광이 매우 자연스럽게 적용됨
3. 큰 맵도 걱정 없음

---

# 8️⃣ Static vs Dynamic 구분

**왜 구분해야 하는가?**

- Static = 절대 안 움직임 → Lightmap 가능 → 성능 최고
- Dynamic = 움직임 있음 → Lightmap 불가 → Probe 사용

즉 Static은 “그림자까지 구워서” 항구적

Dynamic은 “빛을 즉시 받아서” 실시간 반응

---

# 9️⃣ 베이크 후 색상 조절 왜 다시해야 해?

라이트맵은 **빛을 이미지로 구워둔 것**

그런데 외부 조명을 나중에 바꾸면?

→ lightmap이 그 정보를 모르기 때문에 다시 굽기 필요

“빛의 정보가 이미지 안에 저장된 것”이라는 개념만 이해하면 끝.

---

# 🔥 **한 문단 요약**

스카이박스와 환경광으로 기본 분위기를 만들고, 포그로 원근감을 잡고, 그림자 품질을 올린 후, 움직이지 않는 큰 오브젝트만 라이트맵에 굽는다. 나머지 소품과 캐릭터는 Adaptive Probe Volume으로 간접광을 받고, GPU Resident Drawer로 같은 오브젝트를 한 번에 그려 DrawCall을 확 줄인다. 이렇게 하면 고퀄리티 + 고성능 URP 씬이 완성된다.
