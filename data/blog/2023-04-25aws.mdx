### 8. 스토리지 구성

```markdown
EBS는 인스턴스 내부 저장장치가 아닌 네트워크로 연결된 가상 저장 장치이다.
이러한 특징 때문에 인스턴스를 삭제하더라도 EBS는 따로 남아있기 때문에 데이터 자체를 보존할 수 있고
인스턴스 업그레이드가 용이하다는 장점이 있다.

또한 인스턴스 입장에서 여러 개의 EBS를 연결시거나, 하나의 EBS를 여러 개의 인스턴스로 연결이 가능하다.

EBS는 종류에따라 나뉜다.
범용(GP2, SSD) - 일반적으로 사용됨.
프로비전된 IOPS(Provisioned IOPS, SSD) - IOPS가 중요한 경우 (IOPS: 저장장치의 성능)
쓰로풋 최적화 HDD (Throughput Optimized HDD, SSD)
콜드 HDD (HDD)
마그네틱 (HDD) - 가장 저렴하지만 IOPS가 낮음

범용(GP2) 선택 후 용량 30 입력(Free tier 최대 용량)
```

# EC2 Background 실행

### 1. Background 실행

```markdown
nohup java -jar 파일명 1>log.out 2>err.out &

# nohup

프로세스를 실행한 터미널의 세션 연결이 끊어지더라도
지속적으로 동작 할 수 있게 해주는 명령어

# &

백그라운드 실행

# 0 : 표준 입력, 1 : 표준 출력, 2 : 표준 에러

nohup [실행파일] 1>/dev/null 2>&1 &

1 > /dev/null
표준 출력(1)의 결과를 /dev/null(버림)로 전달

2>&1
표준 에러(2)를 표준 출력(1)이 전달되는 곳(/dev/null)으로 동일하게 전달
```
