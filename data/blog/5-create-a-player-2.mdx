## 1. 점프 애니메이션 추가

```jsx
플레이어가 점프할 때 적절한 애니메이션을 재생해야 합니다.

이를 위해 PlayerAnims.js에 점프 애니메이션을 추가합니다.
```

### 1.1 점프 애니메이션 정의

```jsx
anims.create({
  key: 'jump',
  frames: anims.generateFrameNumbers('player', { start: 17, end: 23 }),
  frameRate: 8,
  repeat: 1, // 애니메이션을 한 번만 실행
})
```

```jsx
start: 17, end: 23 → 점프 애니메이션의 프레임 범위를 설정합니다.

frameRate: 8 → 초당 8프레임 속도로 실행합니다.

repeat: 1 → 애니메이션을 한 번만 실행하도록 설정합니다.
```

## 2. 플레이어가 점프할 때 애니메이션 변경

```jsx
이제 플레이어가 점프할 때 jump 애니메이션을 실행하도록 코드를 수정합니다.
```

### 2.1 새로운 애니메이션 처리 방식

```jsx
onFloor
  ? this.body.velocity.x !== 0
    ? this.play('run', true)
    : this.play('idle', true)
  : this.play('jump', true)
```

### 2.2 이중 삼항 연산자 (Double Ternary Operator)

```jsx
이 코드에서 이중 삼항 연산자가 사용되었으며, 이를 해석하면 다음과 같습니다.

① 첫 번째 조건: 바닥에 닿아있는가? (onFloor)

		true → 추가적인 조건 검사 수행 (달리는지, 가만히 있는지 판단)

		false → 점프 애니메이션 실행

② 두 번째 조건: 바닥에 닿아 있을 때 (onFloor가 true일 때)

		this.body.velocity.x !== 0

		→ 플레이어가 움직이고 있다면 run 애니메이션 실행

		→ 그렇지 않다면 idle 애니메이션 실행
```

# { Player 기능 리팩토링 및 Mixin 도입 }

## 1. **기존 코드 리팩토링 (Collider 기능 이동)**

### 기존 코드 문제점

```jsx
1. Play 씬에서 this.physics.add.collider(player, platformsColliders)를

직접 호출하여 플레이어와 충돌 처리를 설정하고 있음.

2. 하지만 충돌 처리는 플레이어와

관련된 기능이므로 Player 클래스 내부로 이동하는 것이 더 적절함.
```

### 리팩토링 방법

```jsx
1. Player 클래스 내부에 addColliders 메서드를 새로 추가함.

2. this.scene.physics.add.collider(this, otherGameObject, callback, null, this);

를 활용하여 충돌을 설정.

3. 이제 Play 씬에서는 player.addColliders(layers.platformsColliders);

처럼 호출하면 자동으로 충돌이 적용됨.
```

### 1. `addColliders` 메서드의 정의

```jsx
Player 클래스에 addColliders 메서드를 추가하여 충돌 처리를

Play 씬이 아니라 Player 클래스 내부에서 관리할 수 있도록 함.

매개변수로 전달받은 다른 게임 오브젝트(otherGameObject)와의 충돌을 설정.

충돌 발생 시 실행할 **콜백 함수(callback)**를 선택적으로 제공할 수 있음.
```

```jsx
addColliders(otherGameObject, callback) {
    this.scene.physics.add.collider(this, otherGameObject, callback, null, this);
}
```

```jsx
Phaser에서 physics.add.collider는 두 개의 게임 오브젝트(또는 그룹)가

충돌할 때 자동으로 물리 엔진이 처리해 주도록 설정하는 메서드입니다.
```

```jsx
this.scene.physics.add.collider(this, otherGameObject, callback, null, this)
```

### 3. `Play` 씬에서 `addColliders` 호출 방법

```jsx
이제 Play 씬에서는 기존처럼 physics.add.collider를 직접 호출하는 대신,
```

```jsx
동작 과정

4. 플레이어가 플랫폼 위에 올라서거나 부딪히면 정상적으로 충돌이 발생함.
```

## 2. **Mixin을 활용한 기능 분리 (Collidable Mixin 생성)**

### Mixin이란?

```jsx
여러 클래스에서 공통으로 사용되는 기능을 별도의 객체로 분리하여 재사용하는 패턴.

상속 없이 기능을 공유할 수 있음.
```

### 적용 방법

```jsx
새로운 Mixin 파일 생성

		src/mixins/collidable.js 파일을 만들고 addColliders 메서드를 정의.

		export default { addColliders } 형태로 내보냄.

Player 클래스에서 Mixin 적용

		import collidable from "../mixins/collidable";로 Mixin을 가져옴.

		Object.assign(this, collidable);를 이용하여 Player 클래스에 기능을 추가.
```

### 1. `Object.assign()`이란?

```jsx
Object.assign(target, ...sources)는 JavaScript의 내장 함수로,

하나 이상의 소스 객체(sources)에서 속성을 가져와 타겟 객체(target)에 복사하는 기능을 합니다.
```

```jsx
Object.assign(target, source)
```

```jsx
target: 속성을 복사할 대상 객체

source: target에 복사할 속성을 가진 객체 (하나 이상 가능)
```

### 예제

```jsx
const target = { a: 1 }
const source = { b: 2, c: 3 }

Object.assign(target, source)

console.log(target) // { a: 1, b: 2, c: 3 }
```

```jsx
source의 b와 c가 target 객체에 복사됨.
```

### `Object.assign(this, collidable);`의 역할

```jsx
Object.assign(this, collidable)
```

```jsx
이 코드의 역할은 collidable 객체의 모든 속성과 메서드를 this(현재 Player 인스턴스)에 추가하는 것입니다.
```

```jsx
import collidable from '../mixins/collidable'

class Player extends Phaser.Physics.Arcade.Sprite {
  constructor(scene, x, y) {
    super(scene, x, y, 'player')

    scene.add.existing(this)
    scene.physics.add.existing(this)

    Object.assign(this, collidable) // mixin 추가

    this.init()
    this.initEvents()
  }
}
```

```jsx
collidable은 collidable.js에서 가져온 객체입니다.

Object.assign(this, collidable);을 실행하면

collidable에 정의된 속성과 메서드가 Player 인스턴스에 복사됩니다.
```

### `collidable` 객체 내부 구조

```jsx
export default {
  addColliders(otherGameObject, callback) {
    this.scene.physics.add.collider(this, otherGameObject, callback, null, this)
  },
}
```

```jsx
collidable 객체는 addColliders()라는 메서드를 포함하고 있음.

이 객체를 Object.assign()을 이용해 Player 인스턴스에 추가하면,

Player 클래스 내부에서 마치 addColliders()가 직접 정의된 것처럼 사용할 수 있게 됨.
```

### 실제 실행 과정

```jsx
1. Object.assign(this, collidable);이 실행됨.

2. collidable 객체의 모든 속성이 this(Player 인스턴스)에 복사됨.

3. 이제 Player 인스턴스에서 직접 정의한 것처럼 addColliders()를 사용할 수 있음.

결과적으로 다음과 같이 사용 가능
```

```jsx
player.addColliders(layers.platformsColliders)
```

```jsx
Player 클래스에서 addColliders()를 정의하지 않았지만,

Object.assign(this, collidable); 덕분에 사용할 수 있음.
```

### 효과

```jsx
addColliders 기능이 Player 클래스에 직접 포함되지 않고 외부에서 관리됨.

같은 기능을 여러 클래스(예: 적 캐릭터, 아이템 등)에서 쉽게 공유할 수 있음.
```

## 1. Mixins(믹스인)이란?

```jsx
믹스인은 "특정 기능을 따로 만들어서 필요한 클래스와 합치는 것" 이라고 생각하면 돼요.

예를 들어, 우리가 만든 게임의 Player(플레이어) 클래스에 충돌 기능(Collision 기능) 을 추가하고 싶다면?

👉 충돌 기능을 따로 mixins 폴더에 만들어서 Player와 합칠 수 있어요!

✔ 이렇게 하면 여러 개의 클래스에서 같은 기능을 쉽게 재사용 할 수 있어요.

현재 강의에서는 mixins 폴더에 collidable 을 만들어서 Player에 추가했어요.
```

# { 맵 크기와 화면 크기 조정 }

```jsx
게임을 만들 때, 맵(게임 배경) 전체 크기와 사용자가 실제로 볼 수 있는 화면 크기를 맞추는 것이 중요합니다.

현재 코드를 보면, 화면 크기를 잘못 설정해서 전체 맵이 다 보이지 않는 문제가 있어요.

이 강의에서는 맵의 크기를 정확하게 설정하고, 브라우저 화면 크기에 맞춰 조정하는 방법을 배웁니다.

또한, 플레이어가 이동할 때 맵이 자연스럽게 움직이도록 "맵 오프셋 (offset)" 값을 계산하는 기초 작업을 합니다.
```

## 1. 현재 코드의 문제점: 캔버스 크기 오류

```jsx
코드를 보면, 캔버스 크기를 이렇게 설정하고 있어요

이렇게 하면 게임 화면 크기가 1280 x 600 픽셀로 고정됩니다.

하지만 게임 맵의 실제 크기는 어떻게 될까요?
```

```jsx
const canvasWidth = 1280
const canvasHeight = 600
```

### ✅ 실제 맵 크기 계산하기

```jsx
맵은 **100개의 타일(칸)**로 구성되어 있음

각 타일은 16 픽셀 크기

따라서 100 × 16 = 1600 픽셀

즉, 맵의 가로 크기는 1600픽셀인데,

화면은 1280픽셀이라 맵이 잘려서 일부만 보이는 문제가 발생합니다.
```

## 2. 캔버스 크기를 동적으로 조정하기

```jsx
우리는 캔버스 크기를 브라우저 크기에 맞게 자동 조정할 수도 있어요.

브라우저 크기를 가져오는 방법은 다음과 같습니다.
```

```jsx
document.body.offsetWidth
```

```jsx
document.body.offsetWidth는 현재 웹 브라우저에서 표시 가능한 너비를 가져오는 함수입니다.

따라서, 캔버스 크기를 이렇게 설정할 수 있어요.

이렇게 하면 사용자의 브라우저 크기에 맞춰 자동으로 화면이 조정됩니다.
```

```jsx
const width = document.body.offsetWidth // 현재 브라우저 크기
```

## 3. 패딩(padding)과 마진(margin) 문제 해결

```jsx
지금 document.body.offsetWidth를 사용하면 이상하게 큰 값이 나올 수 있어요.

이유는 바로 패딩(padding) 때문입니다.

✅ 패딩과 마진 차이

		padding: 요소 내부의 여백 → 크기에 영향을 줌 ❌

		margin: 요소 외부의 여백 → 크기에 영향을 주지 않음 ✅

즉, 패딩을 사용하면 offsetWidth 값이 실제 브라우저 크기보다 커질 수 있음
```

### 해결 방법: 패딩 제거하고 마진 사용하기

```jsx
body {
  margin: 200px; /* 마진 사용 */
  padding: 0; /* 패딩 제거 */
}
```

## 맵 오프셋 (Offset) 계산: 보이지 않는 영역 찾기

```jsx
맵이 1600픽셀인데, 브라우저 화면에서 보이는 영역은 1280픽셀뿐이에요.

그렇다면, 남은 320픽셀(1600 - 1280)은 보이지 않는 부분이죠.

이 부분을 **오프셋(offset)**이라고 부릅니다.
```

### 오프셋을 계산하는 코드

```jsx
const mapOffset = mapWidth - width
```

```jsx
여기서,

mapWidth = 1600 (전체 맵 크기)

width = 1280 (브라우저에서 보이는 화면 크기)

mapOffset = 1600 - 1280 = 320

즉, 320픽셀만큼의 맵이 처음에는 보이지 않고 숨겨져 있음.

```

## 최종 코드 정리: 화면 크기와 맵 오프셋 설정

```jsx
// 1. 맵 크기 설정
const mapWidth = 1600

// 2. 브라우저 크기에 맞춰 캔버스 크기 설정
const width = document.body.offsetWidth
const height = document.body.offsetHeight

// 3. 오프셋 계산 (보이지 않는 영역 크기)
const mapOffset = mapWidth - width
```

## Phaser 설정 값 (SHARED_CONFIG)

```jsx
이제 우리가 계산한 값들을 Phaser 게임에서 사용할 수 있도록 설정 값을 만듭니다.
```

```jsx
const SHARED_CONFIG = {
  mapOffset: mapOffset,
  width: width,
  height: height,
}
```

## 왜 이 작업이 필요한가? (카메라 시스템을 위한 기초 작업)

```jsx
우리는 게임에서 플레이어가 이동할 때 화면이 따라 움직이도록 만들고 싶어요.

그러려면 맵 전체 크기와 보이지 않는 영역을 정확히 알아야 함.

이 강의에서는 맵 크기와 화면 크기를 설정하고, 보이지 않는 오프셋을 계산하는 것까지 배웠어요!

다음 강의에서는 카메라 시스템을 구현해서 플레이어가 이동할 때 화면이 자연스럽게 움직이도록 만들 예정입니다.
```

# { Phaser 3에서 카메라 설정하기 }

```jsx
이번 강의에서는 Phaser 3에서 카메라(Camera)를 설정하고,

플레이어를 따라 움직이게 만드는 방법을 배웁니다.
```

## 1. 맵 크기와 화면 크기 설정하기

```jsx
게임에서는 보통 맵(게임 공간)이 브라우저 화면보다 더 크기 때문에,

카메라를 이용해 특정 영역을 보여줄 수 있도록 조정해야 합니다.
```

```jsx
// 맵 전체의 너비(가로 길이)
const mapWidth = 1600

// 현재 브라우저의 화면 크기 가져오기
const width = document.body.offsetWidth
const height = 600 // 화면 높이는 600px로 고정

// 카메라가 따라갈 맵의 오프셋(추가로 보여줄 공간 크기)
const mapOffset = mapWidth - width
```

```jsx
mapWidth = 1600 → 게임 맵의 총 가로 크기 (1600px)

width = document.body.offsetWidth → 브라우저 창 크기에 맞춤

mapOffset = mapWidth - width → 화면보다 큰 맵의 남은 영역 크기 계산
```

### 맵 오프셋(mapOffset)이란?

```jsx
맵 전체가 1600px인데 브라우저 화면이 1280px이라면,

320px만큼 추가로 이동할 공간이 있다는 의미입니다.

이 값을 활용해 카메라가 플레이어를 따라갈 범위를 설정할 수 있습니다.
```

## 2. 카메라를 설정하는 함수 만들기

```jsx
카메라는 기본적으로 고정되어 있기 때문에, 플레이어를 따라 움직이도록 설정해야 합니다.

이를 위해 setupFollowupCameraOn(player) 함수를 생성합니다.
```

```jsx
setupFollowupCameraOn(player) {
    const { height, width, mapOffset, zoomFactor } = this.config;

    // 1. 게임 전체 맵의 물리적 한계를 설정
    this.physics.world.setBounds(0, 0, width + mapOffset, height);

    // 2. 카메라가 이동할 수 있는 영역을 설정
    this.cameras.main.setBounds(0, 0, width + mapOffset, height)
                     .setZoom(zoomFactor); // 줌(확대) 설정 추가

    // 3. 카메라가 플레이어를 따라가도록 설정
    this.cameras.main.startFollow(player);
}
```

```jsx
this.physics.world.setBounds(...) → 물리 세계의 크기 설정

		플레이어가 이동할 수 있는 최대 범위를 설정합니다.

		플레이어가 이동할 수 있는 전체 맵의 크기를 설정하는 코드입니다.

				(0, 0) → 맵의 시작 위치 (왼쪽 상단)

				width + mapOffset → 맵의 전체 너비 (화면 크기 + 추가 맵 영역)

				height → 맵의 전체 높이

this.cameras.main.setBounds(...) → 카메라 이동 가능 범위 설정

		화면이 움직일 수 있는 최대 범위를 설정합니다.

		카메라가 보여줄 화면의 크기를 정하는 코드입니다.

				setBounds(0, 0, width + mapOffset, height)

				→ 카메라가 볼 수 있는 최대 영역을 맵 전체 크기로 설정

				setZoom(zoomFactor)

				→ 카메라 줌(확대/축소) 설정

this.cameras.main.startFollow(player) → 카메라가 플레이어를 따라가도록 설정

		플레이어의 움직임에 따라 카메라도 함께 움직입니다.
```

## \*`setBounds`가 뭔가?

```jsx
setBounds는 "이 영역까지만 카메라가 볼 수 있어!" 라고 카메라의 한계를 정해주는 기능이에요.

즉, 카메라가 볼 수 있는 최대 크기(경계)를 설정하는 역할을 해요.
```

### 게임에서 맵 크기가 1000 x 600 이라고 가정해봅시다.

```jsx
만약 setBounds를 설정하지 않으면?

➡ 카메라가 무한대로 움직일 수도 있고, 플레이어가 맵을 벗어나면 화면이 엉망이 될 수도 있어요! 😵

그래서 이렇게 setBounds(0, 0, 1000, 600)를 설정하면:

		카메라는 왼쪽(0, 0)에서 시작

		오른쪽 끝(1000), 아래 끝(600)까지만 볼 수 있음

💡 쉽게 말하면?

➡ "카메라야! 0,0 ~ 1000,600까지만 움직이고 그 이상 나가지 마!" 라고 제한을 주는 거예요.
```

### 코드로 보면 이렇게

```jsx
this.cameras.main.setBounds(0, 0, width + mapOffset, height)
```

```jsx
0, 0	카메라가 볼 수 있는 시작 위치 (왼쪽 상단)

width + mapOffset	카메라가 볼 수 있는 최대 가로 길이

height	카메라가 볼 수 있는 최대 세로 길이
```

## 3. 맵 끝까지 이동할 수 있도록 설정

```jsx
기본적으로 카메라는 화면 너비(1280px)까지만 따라오지만,

맵 전체(1600px)까지 이동할 수 있도록 설정하려면 mapOffset을 추가해야 합니다.

width + mapOffset → 전체 맵 크기(1600px)로 설정

이렇게 하면 맵의 끝까지 이동할 수 있습니다.
```

```jsx
// 카메라가 이동할 수 있는 영역을 맵 전체 크기로 설정
this.cameras.main.setBounds(0, 0, width + mapOffset, height)
```

## 4. 월드(물리 세계) 경계를 설정하여 플레이어가 빠지지 않도록 하기

```jsx
게임에서는 플레이어가 화면 밖으로 나가버리는 것을 방지해야 합니다.

이를 위해 물리 세계(World)의 경계를 설정합니다.
```

```jsx
// 물리 세계의 경계를 설정하여 플레이어가 나가지 못하도록 함
this.physics.world.setBounds(0, 0, width + mapOffset, height)
```

```jsx
물리 경계(Physics World Bounds)란?

게임 내에서 플레이어가 이동할 수 있는 최대 범위를 의미합니다.

이 설정이 없으면 플레이어가 맵 밖으로 빠져버릴 수도 있습니다.
```

## 5. 카메라 줌(확대) 설정

```jsx
기본적으로 카메라는 **기본 줌(1배율)**로 설정되어 있습니다.

하지만 플랫폼 게임에서는 플레이어가 중심이 되도록 확대하는 것이 좋습니다.
```

```jsx
// 카메라 줌을 1.5배로 설정
this.cameras.main.setZoom(1.5)
```

### 줌(Zoom)이란?

```jsx
1 → 기본 크기

1.5 → 1.5배 확대

2 → 2배 확대

플랫폼 게임에서는 1.5~2배 확대가 일반적입니다.

확대하면 플레이어 주변에 집중할 수 있어 게임이 더 몰입감 있어집니다.
```

### 줌 값을 설정 파일에서 가져오도록 개선

```jsx
const SHARED_CONFIG = {
  mapOffset: mapOffset,
  width: width,
  height: height,
  zoomFactor: 1.5,
}

// 설정 값을 가져와서 사용
this.cameras.main.setZoom(this.config.zoomFactor)
```

## 2. **엔드존 (End Zone) 생성**

```jsx
플레이어가 목표 지점에 도착하면 게임이 종료됨을 감지하는 역할

Tiled 맵에서 endZone을 가져옴

createEndOfLevel() 함수에서 해당 위치에 게임 오브젝트 생성

엔드존은 충돌(Collision)이 아닌 오버랩(Overlap) 을 감지하도록 설정
```

```jsx
createEndOfLevel(end) {
    this.physics.add.sprite(end.x, end.y, 'end')
        .setSize(5, 200) // 너비 5px, 높이 200px
        .setAlpha(0) // 투명하게 설정
        .setOrigin(0.5, 1); // 기준점을 아래쪽 중심으로 설정
}
```

```jsx
setSize(5, 200): 엔드존의 크기를 지정 (너비: 5px, 높이: 200px)

setAlpha(0): 투명하게 만들어 화면에서 보이지 않도록 설정

setOrigin(0.5, 1): 기준점을 아래쪽 중심으로 조정하여 정확한 위치 배치
```

```jsx
createEndOfLevel(end, player) {
    const endOfLevel = this.physics.add.sprite(end.x, end.y, 'end')
        .setSize(5, this.config.height) // 엔드 존 크기 설정
        .setAlpha(0) // 투명하게 설정
        .setOrigin(0.5, 1); // 중심점 설정
}
```

```jsx
physics.add.sprite(end.x, end.y, 'end'): 물리 엔진을 이용해 엔드 존을 추가합니다.

.setSize(5, this.config.height): 엔드 존의 크기를 설정합니다.

.setAlpha(0): 엔드 존을 보이지 않게 설정합니다.

.setOrigin(0.5, 1): 중심점을 설정하여 원하는 위치에 배치합니다.
```

### 1.2 오버랩(Overlap) 이벤트 추가

```jsx
이제 플레이어가 엔드 존과 겹쳤을 때 실행될 이벤트를 추가합니다.
```

```jsx
const eolOverlap = this.physics.add.overlap(player, endOfLevel, () => {
  console.log('Player has won!')
})
```

```jsx
this.physics.add.overlap(player, endOfLevel, callback): 플레이어가 엔드 존에 닿으면 callback이 실행됩니다.

console.log("Player has won!");: 플레이어가 엔드 존을 통과했을 때 콘솔에 메시지를 출력합니다.
```

## 2. **오버랩 이벤트가 여러 번 실행되는 문제 해결**

```jsx
현재 상태에서는 플레이어가 엔드 존을 계속 통과할 때마다 console.log("Player has won!")가

여러 번 실행됩니다. 이를 방지하기 위해 한 번만 실행되도록 설정합니다.
```

### 2.1 오버랩 이벤트 비활성화

```jsx
const eolOverlap = this.physics.add.overlap(player, endOfLevel, () => {
  eolOverlap.active = false // 이벤트 비활성화
  console.log('Player has won!')
})
```

```jsx
eolOverlap.active = false;: 이벤트가 한 번 실행된 후에는 더 이상 실행되지 않도록 비활성화합니다.
```
