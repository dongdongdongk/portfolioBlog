## 🌳 클래스 계층구조란?

### 기본 개념

```
언리얼 엔진 = 클래스 계층구조 기반

계층구조 = 나무 구조
  ├─ 위: 부모 (Parent)
  └─ 아래: 자식 (Child)
```

**비유: 가계도**

```
할아버지
  ├─ 아버지
  │   └─ 나
  └─ 삼촌
      └─ 사촌
```

## 📊 언리얼 엔진 기본 계층구조

### Object (최상위)

```
Object (오브젝트)
  ↓
모든 것의 조상
  ├─ 데이터 저장 가능
  ├─ Blueprint로 만들 수 있음
  └─ 가장 기본적인 기능만
```

### Actor (중간)

```
Object
  └─ Actor (액터)
      ↓
      추가 기능:
      ├─ 레벨에 배치 가능
      ├─ 스폰 가능
      ├─ Components 가질 수 있음
      └─ Transform (위치, 회전, 크기)
```

### 우리가 만든 것들

```
Object
  └─ Actor
      ├─ BP_Bot
      ├─ BP_Blaster_Beam
      ├─ BP_Small_Sphere
      └─ BP_Sphere_Spawner
```

## 🎭 상속 (Inheritance) 이해

### 개념

```
상속 = 부모의 특성을 물려받음

자식 클래스:
  ├─ 부모의 모든 기능 ✓
  └─ + 자신만의 새 기능
```

### 예시: BP_Bot

```
Object (조상)
  └─ Actor (부모)
      └─ BP_Bot (자식)

BP_Bot이 가진 것:
  ├─ Object의 기능 (데이터 저장)
  ├─ Actor의 기능 (레벨 배치, 스폰)
  └─ BP_Bot만의 기능 (레이저 발사)
```

---

## 🐕 동물 비유로 이해하기

### 계층구조

```
동물 (Animal)
  ├─ 포유류 (Mammal)
  │   ├─ 개 (Dog)
  │   │   └─ 저먼 셰퍼드
  │   ├─ 고양이 (Cat)
  │   └─ 말 (Horse)
  │
  └─ 파충류 (Reptile)
      ├─ 뱀
      └─ 도마뱀
```

### IS-A 관계 (상속)

```
✓ 저먼 셰퍼드는 개다
✓ 개는 포유류다
✓ 포유류는 동물이다
✓ 저먼 셰퍼드는 동물이다

✗ 동물은 포유류다 (틀림!)
✗ 포유류는 개다 (틀림!)
```

**화살표 방향**

```
저먼 셰퍼드 → 개 → 포유류 → 동물
(자식)              (부모)
  ↑
  한 방향만!
```

## 🔧 Component 계층구조

### Actor Component 계열

```
Object
  └─ Actor Component
      └─ Scene Component
          └─ Primitive Component
              ├─ Static Mesh Component
              └─ Sphere Collision
```

### 특징별 기능

**Actor Component (최상위)**

```
기능:
  ├─ Actor에 추가 가능
  └─ 기본 Component 기능
```

**Scene Component**

```
Actor Component +
  ├─ Transform (위치, 회전, 크기)
  └─ Attachment (부착) 지원
```

**Primitive Component**

```
Scene Component +
  ├─ Collision (충돌)
  ├─ Overlap (겹침)
  └─ On Component Begin Overlap ← 여기!
```

**Static Mesh Component**

```
Primitive Component +
  └─ 시각적 메시
```

**Sphere Collision**

```
Primitive Component +
  └─ 구 모양 충돌
```

## 💡 왜 계층이 중요한가?

### 1. 기능 상속

```
Static Mesh Component가
  ↓
Attachment 가능한 이유?
  ↓
Scene Component 상속!
```

### 2. Overlap 이벤트

```
Sphere Volume에
  ↓
On Component Begin Overlap 있는 이유?
  ↓
Primitive Component 상속!
```

**증명**

```
Scene Component (부모)
  ├─ Overlap 기능 없음 ✗

Primitive Component (자식)
  ├─ Overlap 기능 있음 ✓

Static Mesh Component (손자)
  ├─ Overlap 기능 있음 ✓ (상속!)
```

### Cast의 원리

```
부모 타입 → 자식 타입 변환

조건:
  실제로 그 타입이어야 함!

예:
  "개"를 "저먼 셰퍼드"로 Cast
  ✓ 실제로 저먼 셰퍼드면 성공
  ✗ 고양이면 실패
```

## 🏗️ IS-A vs HAS-A 관계

### IS-A (상속)

```
BP_Bot은 Actor다 (IS-A)
  ↓
상속 관계
  ├─ BP_Bot이 Actor 상속
  └─ Actor의 모든 기능 가짐
```

**특징**

```
한 방향
  자식 → 부모 (O)
  부모 → 자식 (X)
```

### HAS-A (구성/컴포지션)

```
Actor는 Component를 가진다 (HAS-A)
  ↓
소유 관계
  ├─ Actor가 Component 소유
  └─ Component는 Actor 아님
```

**특징**

```
독립적
  ├─ Actor와 Component는 다른 계층
  └─ 상속 관계 아님
```

## 📐 두 관계 비교

### IS-A (상속)

```
예시:
  Pawn은 Actor다

관계:
  └─ Actor
      └─ Pawn (상속)

특징:
  ├─ Actor의 기능 자동 보유
  └─ + Pawn만의 추가 기능
```

### HAS-A (구성)

```
예시:
  Actor는 Static Mesh를 가진다

관계:
  Actor
    └─ Static Mesh (소유)

특징:
  ├─ 추가/제거 가능
  └─ 독립적 존재
```

## 🎯 기능 확장 2가지 방법

### 1. 상속 (Inheritance)

```
기존 클래스 기반 새 클래스 생성
  ↓
부모 기능 + 새 기능

예:
  Actor → BP_Bot
  ├─ Actor 기능 (배치, 스폰)
  └─ + 레이저 발사
```

### 2. 구성 (Composition)

```
기존 클래스에 Component 추가
  ↓
기본 기능 + Component 기능

예:
  BP_Bot + Static Mesh
  ├─ BP_Bot 기능 (이동)
  └─ + 시각적 표현
```

```

  ├─ 상속 사용
  ├─ 컴포넌트 시스템
  └─ Cast (타입 변환)
```

  └─ Actor

```

```

  ├─ 키보드 입력
  ├─ 마우스 입력
  └─ 게임패드 입력
  ↓
직접 제어 가능!

Actor는:
  Event Graph 로직으로만 이동

Pawn은:
  키 누르면 바로 이동!
```

## 💡 핵심 개념 정리

### 클래스 계층구조

```
위로 갈수록: 범용적, 기본적
  ↑
Object → Actor → Pawn → Character
  ↓
아래로 갈수록: 구체적, 전문적
```

### 상속의 법칙

```
✓ 자식은 부모다
✗ 부모는 자식 아니다
  ↓
한 방향 관계
```

### IS-A vs HAS-A

```
IS-A (상속):
  "~은 ~이다"
  예: Pawn은 Actor다

HAS-A (구성):
  "~은 ~을 가진다"
  예: Actor는 Component를 가진다
```

---

## 🎨 용어 정리

### 같은 의미

**부모 클래스**

```
= Base Class (베이스 클래스)
= Parent Class (부모 클래스)
= Super Class (상위 클래스)
```

**자식 클래스**

```
= Child Class (자식 클래스)
= Derived Class (파생 클래스)
= Sub Class (하위 클래스)
```

**관계 설명**

```
"~을 기반으로"
= "~에서 파생된"
= "~을 상속받은"
= "~의 자식"
```

### 1. 계층 = 상속

## 🎮 Enhanced Input System이란?

```

   "어떤 키로" 할 것인가
   예: 마우스 클릭, F키

3. Pawn 연결
   "누가" 받을 것인가

## 🎮 Trigger 종류

### Pulse (펄스)

```
일정 간격으로 트리거
  ├─ Interval: 시간 간격
  └─ Trigger on Start: 즉시 발사

용도: 연사, 반복 동작
```

### Hold (홀드)

```
일정 시간 누르고 있어야 트리거
  ├─ Hold Time: 필요 시간
  └─ Is One Shot: 1회만

용도: 차지 공격
```

### Tap (탭)

```
짧게 눌러야 트리거
  ├─ 길게 누르면 취소
  └─ 빠른 입력만 인정

용도: 더블 탭, 빠른 반응
```

### Chorded Action

```
여러 키 조합
  예: Ctrl + C

용도: 복합 입력
```

## 💡 핵심 개념 정리

### Local Variable 장점

```
1. 함수 내부에만 존재
   └─ 메모리 효율적

2. 함수끼리 독립적
   └─ 이름 충돌 없음

3. 일시적 계산용
   └─ 임시 데이터 저장
```

### Trigger vs Modifier

```
Trigger:
  언제 트리거되는지
  예: 0.15초마다

Modifier:
  트리거된 값을 어떻게
  예: 2배 증폭, 반전
```

### Input Action vs Mapping Context

```
Input Action에 설정:
  ├─ 모든 키에 공통 적용
  └─ 추천! ✓

Mapping Context에 설정:
  ├─ 각 키마다 개별 적용
  └─ 번거로움 ✗
```
