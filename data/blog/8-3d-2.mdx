# { 🎮 게임패드(콘솔 컨트롤러) 입력 추가 }

## 🎯 목표

Xbox/PlayStation 컨트롤러 입력을 간단하게 추가합니다.

---

## ⚙️ 설정 방법

### 1. IA_Look에 오른쪽 스틱 추가

```
IMC_KickActions 열기
  ↓
IA_Look 매핑 확장
  ↓
+ 버튼 → Gamepad → Right Thumbstick 2D-Axis

2개 Modifier 추가:
  ├─ Dead Zone (표류 방지)
  └─ Negate Y축 (상하 반전)
```

### 2. IA_Move에 왼쪽 스틱 추가

```
IA_Move 매핑 확장
  ↓
+ 버튼 → Gamepad → Left Thumbstick 2D-Axis

1개 Modifier 추가:
  └─ Dead Zone (표류 방지)
```

### 3. IA_Jump에 A 버튼 추가

```
IA_Jump 매핑 확장
  ↓
+ 버튼 → Gamepad → Face Button Bottom
(Xbox A 버튼, PlayStation X 버튼)
```

## 🔧 핵심 개념

### Dead Zone이란?

```
문제:
스틱을 안 눌러도 미세한 입력 발생
  ↓
캐릭터가 저절로 움직임 (표류)

해결:
Dead Zone = 임계값 이하 입력 무시
  ↓
표류 방지
```

### 압력 감도

```
키보드:
  └─ 0 또는 1 (눌림/안눌림)

게임패드 스틱:
  └─ 0~1 사이 값 (압력 정도)

장점:
  ├─ 천천히 이동 가능
  └─ 걷기/달리기 섞기 가능
```

## 🔄 Event Graph - 데이터 수집

### Blueprint Update Animation 이벤트

```
Event Graph에 기본 생성:

[Event Blueprint Update Animation]

기능:
매 프레임 실행 (Actor의 Tick과 유사)
  ↓
애니메이션 업데이트 전에 실행
  ↓
여기서 데이터 수집/계산
```

### Pawn Owner 가져오기

```
우클릭 → Try Get Pawn Owner

기능:
이 Animation BP를 사용하는 Pawn 반환

반환값:
  └─ BP_Kicks (우리 캐릭터)
```

### 움직임 감지 - Is Velocity Zero

**전체 흐름**

```
[Event Blueprint Update Animation]
  ↓
[Try Get Pawn Owner]
  ↓
[Get Movement Component]
  ↓
[Get Velocity] (속도 벡터)
  ↓
[Vector Is Zero] (속도가 0인가?)
  ↓
[SET Is Velocity Zero] (변수에 저장)
```

**각 단계 설명**

```
1. Get Movement Component
   Pawn → Movement Component 가져오기

2. Get Velocity
   Movement Component의 Velocity 속성
   └─ Vector 타입 (방향 + 속도)

3. Vector Is Zero
   입력: Vector
   출력: Bool
   기능: Vector가 (0,0,0)인지 확인

4. Is Velocity Zero 변수
   타입: Bool
   의미:
     ├─ True: 정지 중
     └─ False: 이동 중
```

## 🎭 Blend Poses by Bool - 조건부 블렌딩

### 노드 추가

```
Anim Graph에서 우클릭
  ↓
"Blend Poses by bool" 검색
  ↓
노드 생성

[Blend Poses by bool] → [Output Pose]
```

### 입력 이해

```
Blend Poses by bool:

입력:
  ├─ True Pose: 조건이 참일 때 포즈
  ├─ False Pose: 조건이 거짓일 때 포즈
  ├─ Active Value: Bool (조건)
  ├─ True Blend Time: True로 전환 시간
  └─ False Blend Time: False로 전환 시간

출력:
  └─ Result Pose
```

### 연결하기

**True Pose (정지 시)**

```
A_Kix_Idle Sequence Player
  ↓
True Pose

✅ Loop Animation 체크
```

**False Pose (이동 시)**

```
A_Kix_RunForward Sequence Player
  ↓
False Pose

✅ Loop Animation 체크
```

**Active Value (조건)**

```
Is Velocity Zero (변수)
  ↓
드래그 → Active Value

의미:
  ├─ True (속도 0): Idle 재생
  └─ False (이동 중): Run 재생
```

---

## ⏱️ Blend Time - 전환 속도

### 설정값 의미

```
Blend Time = 전환에 걸리는 시간 (초)

예:
  ├─ 0.0: 즉시 전환 (뚝뚝 끊김)
  ├─ 0.1: 매우 빠른 전환 (권장)
  ├─ 0.5: 부드러운 전환
  └─ 2.0: 매우 느린 전환 (어색함)

권장값: 0.1 ~ 0.3
```

### 테스트

```
Blend Time: 0.1 설정
  ↓
Compile & Save
  ↓
Play 테스트:
  ├─ 정지 시: Idle 애니메이션
  └─ 이동 시: Run 애니메이션

부드럽게 전환됨!
```

```
  ↓
Movement Component 속도 변화
  ↓
Animation BP 감지
  ├─ Event Graph: 속도 → 변수
  └─ Anim Graph: 변수 → 포즈 선택

  ↓
```

## 💡 핵심 개념 정리

### Animation Blueprint 역할

```
역할 분담:

Character Blueprint:
  └─ 움직임 로직 (이동, 점프 등)

Animation Blueprint:
  └─ 애니메이션 선택 및 재생

분리의 장점:
  ├─ 코드 정리
  ├─ 재사용 가능
  └─ 애니메이터와 프로그래머 협업 용이
```

### Event Graph vs Anim Graph

```
Event Graph:
  ├─ 언제: 매 프레임
  ├─ 역할: 데이터 수집 및 계산
  └─ 예: 속도, 공중 여부, 방향 등

Anim Graph:
  ├─ 언제: 애니메이션 업데이트 시
  ├─ 역할: 포즈 선택 및 블렌딩
  └─ 예: Idle, Run, Jump 포즈 결정
```

### Sequence Player

```
기능:
단일 Animation Sequence 재생

설정:
  ├─ Sequence: 재생할 애니메이션
  ├─ Loop: 반복 여부
  └─ Play Rate: 재생 속도

출력:
  └─ Animation Pose
```

### Blend Poses by Bool

```
기능:
Bool 값에 따라 2개 포즈 중 선택

장점:
  └─ 부드러운 전환 (Blend Time)
```

# { 🎨 Blend Space - 속도에 따른 애니메이션 블렌딩 }

## 🎯 이번 강의 목표

Blend Space를 만들어 속도에 따라 Idle → Walk → Run 애니메이션을 부드럽게 전환합니다.
게임패드 압력 감도에 맞춰 자연스러운 애니메이션을 구현합니다.

---

## 🔍 현재 문제점

### Bool 방식의 한계

```
현재 시스템:
Is Velocity Zero (Bool)
  ├─ True: Idle
  └─ False: Run

문제:
  ├─ 걷기 애니메이션 없음
  ├─ 속도 차이 무시
  └─ 0 또는 100만 존재
```

### 게임패드 압력 감도 문제


## 🎨 Blend Space란?

### 정의

```
Blend Space:
여러 애니메이션을 값에 따라
부드럽게 섞는 시스템

예:
속도 0 → Idle

속도 300 → Run
속도 150 → Walk + Run 혼합
```

### 일반 Blend Space vs 1D Blend Space

```
Blend Space (2D):
  ├─ 가로축: 예) 속도
  └─ 세로축: 예) 방향

  2개 값으로 애니메이션 선택
  (더 복잡한 시스템)

Blend Space 1D:
  └─ 가로축만: 예) 속도

  1개 값으로 애니메이션 선택
  (우리가 사용할 것)
```

## 🔍 노드 기능 요약

## Event Blueprint Update Animation


## Get Movement Component

```

```

## Get Velocity

```
입력: Movement Component
출력: Vector (X, Y, Z)

현재 이동 속도 벡터 반환
- X: 좌우 속도
- Y: 전후 속도
- Z: 상하 속도
```

## Vector Length XY

```
입력: Vector (X, Y, Z)
출력: Float

공식: √(X² + Y²)
Z축을 제외한 XY 평면의 길이 계산
→ 지면 이동 속도만
```

```
입력: String (자동 변환 가능)

디버깅/테스트용 (나중에 제거)
```

**왜 Vector Length XY?**

```
Velocity = (X, Y, Z) 벡터
  ├─ X: 좌우
  ├─ Y: 전후
  └─ Z: 상하 (점프 등)

지면 이동은 XY만 필요
  ↓
Vector Length XY 사용
  └─ Z 제외, XY만 계산

```

```
높은 곳에서 떨어질 때:
  └─ 긴 낙하 (Start → Mid 반복 → End)

공중 시간이 다양함
  ↓
Mid는 반복 가능해야 함
  ↓
3개로 분리
```

## 🔄 Transition Rule - 전환 규칙

```
시퀀스 플레이어가 끝나면 자동 전환

장점:
  └─ 별도 조건 필요 없음

언제 사용:
  └─ 애니메이션 끝 = 전환 조건
```

## 🔍 전체 State Machine 흐름

### 시각화

```
Entry → IdleWalkRun
         ↓ (Is In Air = True)
      JumpStart
         ↓ (애니메이션 끝)
      JumpMid (Loop)
         ↓ (Is In Air = False)
      JumpEnd
         ↓ (애니메이션 끝)
      IdleWalkRun
```

### 상황별 흐름

**평지 점프**

```
1. 지면에서 대기 (IdleWalkRun)
2. 스페이스바 누름
3. Is In Air = True
4. JumpStart (0.3초)
5. 자동 전환
6. JumpMid (0.2초)
7. 땅 닿음 → Is In Air = False
8. JumpEnd (0.3초)
9. IdleWalkRun 복귀
```

**높은 곳에서 낙하**

```
1. 걷다가 절벽에서 떨어짐
2. Is In Air = True
3. JumpStart
4. JumpMid (Loop 계속 반복)
   ├─ 3초간 낙하
   └─ Mid 계속 재생
5. 땅 닿음
6. JumpEnd
7. IdleWalkRun
```

## 💡 핵심 개념 정리

### State Machine

```
정의:
여러 상태를 가지고
조건에 따라 전환

구성 요소:
  ├─ State: 특정 애니메이션
  └─ Transition: 전환 규칙

장점:
  ├─ 복잡한 애니메이션 관리
  ├─ 직관적인 시각화
  └─ 조건부 전환
```

### State (상태)

```
하나의 애니메이션 또는
애니메이션 조합

내부:
  └─ 포즈 생성 노드들
      (Sequence Player, Blend Space 등)

출력:
  └─ Result (Animation Pose)
```

### Transition (전환)

```
State 간 이동 규칙

화살표 = Transition

조건:
  ├─ Bool 변수
  ├─ 애니메이션 종료
  └─ 기타 조건
```

### Automatic Rule

```
기능:
애니메이션 끝나면 자동 전환

설정:
Transition 선택
  ↓
Automatic Rule... 체크

편리함:
별도 조건 코드 불필요
```

### NOT Boolean

```
기능:
Bool 값 반전

True → False
False → True

용도:
"아닐 때" 조건 만들기
```
