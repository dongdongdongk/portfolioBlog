# **복습**

```jsx

네트워크의 데이터 전송 과정을 두 개의 중요한 계층인 물리 계층과 데이터 링크 계층 설명
```

```jsx
물리 계층

	물리 계층은 데이터를 전기 신호로 변환하여 네트워크 상에서 실제로 전송하는 역할을 합니다.

	예를 들어, 컴퓨터에서 생성된 데이터가 전기적 신호로 변환되어 케이블을 통해 네트워크 장비로 전달됩니다.

	또한, 물리 계층에는 리피터와 허브와 같은 장비들이 있습니다. 이 장비들은 신호를 증폭하거나 중계하여 데이터가 멀리까지 전달될 수 있도록 합니다.

데이터 링크 계층

	데이터 링크 계층은 네트워크 장비 간에 신호를 주고받는 규칙을 정하는 계층입니다.

	주로 랜(Local Area Network)에서 데이터를 정상적으로 주고받기 위한 규칙을 제공합니다.

	이 계층에서는 데이터 전송의 핵심인 프레임이라는 단위로 데이터를 처리합니다. 프레임은 이더넷 헤더와 트레일러가 추가된 형태로 만들어집니다.
```

```jsx
주요 포인트:

	이더넷: 데이터 링크 계층에서 주로 사용되는 규칙으로, 네트워크 장비들이 데이터를 어떻게 주고받을지를 정의합니다.

	스위치: 데이터 링크 계층의 주요 장비 중 하나로, MAC 주소 테이블을 가지고 있습니다. 이 테이블을 사용하여 데이터를 올바른 장비로 전달합니다.
```

# **LESSON 17 네트워크 계층의 역할**

```jsx
네트워크 계층의 역할

	네트워크 계층은 다른 네트워크로 데이터를 전달하는 역할을 합니다. 데이터 링크 계층은 같은 네트워크 내의 컴퓨터 간 데이터 전송을 처리하지만,

	다른 네트워크로 데이터를 보내려면 네트워크 계층의 기술이 필요합니다.


라우터의 역할

	라우터는 데이터의 목적지까지 가는 최적의 경로를 결정해 주는 중요한 장비입니다. 각 목적지까지의 경로 정보를 관리하기 위해 라우터는 라우팅 테이블을 사용합니다.

	이 테이블에는 목적지 IP 주소와 해당 목적지까지의 경로 정보가 등록되어 있습니다.


IP 주소의 역할

	네트워크에서는 데이터를 전송하기 위해 목적지의 IP 주소를 사용합니다. IP 주소는 어떤 네트워크의 어떤 컴퓨터인지를 식별하는 주소로,

	데이터를 목적지로 전달하기 위한 기본적인 식별 수단입니다.


라우팅 과정

	라우팅은 데이터를 목적지 IP 주소로 전달하기 위해 어떤 경로를 선택할지 결정하는 과정을 말합니다.

	라우터는 라우팅 테이블을 참조하여 최적의 경로를 결정하고, 데이터를 목적지로 전송합니다.
```

## IP 패킷

```jsx
IP 프로토콜을 사용하여 데이터를 전송할 때 IP 패킷이라는 형태로 패킷을 구성합니다.

이 패킷은 여러 정보를 포함하는데, 각각의 요소를 이해하기 쉽게 정리
```

```jsx
버전(Version): IPv4인지 IPv6인지를 나타내는 4비트 값.

헤더 길이(Header Length): IP 프로토콜 헤더의 길이를 나타내는 4비트 값. 단위는 4바이트(32비트) 단위로 되어 있음.

서비스 유형(Service Type): 패킷의 전송 우선순위 정보를 담고 있는 8비트.

전체 패킷 길이(Total Length): 전체 IP 패킷의 길이를 바이트 단위로 나타내는 16비트 값.

ID(Identification): 패킷이 단편화 되었을 때 데이터를 식별하는 데 사용되는 16비트 식별번호.

	조각 상태(Flags):

		첫 번째 비트는 항상 0으로 고정.

		두 번째 비트는 May Fragment (분열 가능 여부)를 나타내며, 0은 분열 가능, 1은 분열 방지.

		세 번째 비트는 More Fragment (더 많은 조각 존재 여부)를 나타내며, 0은 마지막 조각, 1은 더 많은 조각 존재.

조각의 위치(Fragment Offset): 조각의 원래 데이터에서의 위치를 바이트 단위로 나타내는 13비트 값.

TTL(Time-To-Live): 패킷이 라우터를 통과할 수 있는 최대 횟수를 나타내는 8비트 값. 각 라우터를 지날 때마다 1씩 감소.

프로토콜(Protocol): IP 패킷이 포함하고 있는 상위 계층 프로토콜을 나타내는 8비트 값. 예를 들어, 1은 ICMP, 6은 TCP, 17은 UDP를 나타냄.

헤더 체크섬(Header Checksum): IP 헤더의 내용이 정확하게 전달되었는지 확인하는 데 사용되는 16비트 체크섬 값.

출발지 IP 주소(Source IP address): 데이터를 보내는 컴퓨터의 IP 주소를 나타내는 32비트 값.

목적지 IP 주소(Destination IP address): 데이터를 받는 컴퓨터의 IP 주소를 나타내는 32비트 값.

Option: 필요에 따라 추가적인 정보를 담을 수 있는 부가적인 40바이트까지의 옵션 정보.
```

### 예시 IP 패킷:

```jsx
버전(Version): 4 (IPv4를 나타내는 값)

헤더 길이(Header Length): 5 (헤더 길이가 20바이트이므로 5 * 4 = 20바이트)

서비스 유형(Service Type): 0 (기본 서비스)

전체 패킷 길이(Total Length): 1500 바이트

ID(Identification): 12345

조각 상태(Flags): 0 (첫 번째 비트는 항상 0)

	May Fragment: 0 (분열 가능)

	More Fragment: 0 (마지막 조각)

조각의 위치(Fragment Offset): 0 (첫 번째 조각이므로 0)

TTL(Time-To-Live): 64 (64번의 라우터 통과 가능)

프로토콜(Protocol): 6 (TCP 프로토콜)

헤더 체크섬(Header Checksum): 0x1E2F (16진수로 표시된 체크섬 값)

출발지 IP 주소(Source IP address): 192.168.1.10

목적지 IP 주소(Destination IP address): 203.0.113.5

이 예시에서는 TCP 프로토콜을 사용하여 192.168.1.10에서 203.0.113.5로 가는 IP 패킷을 표현하고 있습니다.

패킷의 전체 길이는 1500바이트이며, 데이터가 단편화되지 않고 한 번에 전송되는 상태입니다.
```
