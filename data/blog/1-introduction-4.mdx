# { Electron 개요 }

```jsx
Electron은 GitHub에서 개발한 오픈소스 프레임워크로, Changzhou라는 개발자가 만들었습니다.

JavaScript, HTML, CSS와 같은 웹 기술을 사용해 데스크탑 GUI 애플리케이션을 개발할 수 있게 해줍니다.

Electron은 Chromium 렌더링 엔진(Google Chrome과 Microsoft Edge에서 사용)

과 Node.js 런타임을 결합하여 웹 개발자들이 네이티브 데스크탑 앱을 만들 수 있게 해줍니다.
```

## 데스크탑 앱의 장점:

```jsx
데이터 보안: 데스크탑 애플리케이션은 데이터를 로컬(예: 로컬 데이터베이스나 파일)에 저장하므로 보안이 더 강할 수 있습니다.

웹 애플리케이션은 클라우드에 데이터를 저장하는 경우가 많습니다.

네이티브 API 접근: 데스크탑 앱은 운영 체제, 하드웨어, 네트워크, 포트, 카메라 등과 상호작용할 수 있습니다.

성능: 데스크탑 앱은 네트워크 서버와의 통신이 필요 없기 때문에 성능이 더 좋을 수 있습니다.

배포: 데스크탑 애플리케이션은 보통 패키징 후 설치만 하면 되지만, 웹 애플리케이션은 배포에 어려움이 있을 수 있습니다.
```

## Electron 사용의 장점:

```jsx
단일 코드베이스:

Electron은 하나의 코드베이스로 모든 주요 플랫폼(Windows, macOS, Linux)에서 실행될 수 있어 개발이 간편하고 비용 효율적입니다.

개발 용이성:

Electron은 JavaScript, HTML, CSS와 같은 익숙한 웹 기술을 사용하여, 다른 데스크탑 개발 언어(Java, C# 등)보다 배우기 쉽습니다.

크로스 플랫폼 앱:

Electron을 사용하면 데스크탑 앱과 웹 앱을 쉽게 모두 만들 수 있습니다.

예를 들어, Slack은 Electron을 사용하여 데스크탑 버전과 웹 버전을 모두 개발했습니다.
```

# { Electron 의 작동 원리 }

## 1. **Electron은 뭘까?**

```jsx
Electron은 **웹 기술(HTML, CSS, JavaScript)**을 이용해 데스크톱 애플리케이션을 만드는 도구입니다.

쉽게 말하면, 웹사이트처럼 코드를 짜지만 결과물은 프로그램처럼 동작합니다.

이 프로그램은 Windows, Mac, Linux 어디서나 실행될 수 있습니다.
```

## 2. **Electron의 내부 구조**

```jsx
Electron 앱은 크게 두 가지 중요한 부분으로 나눌 수 있어요:

		메인 프로세스(Main Process)

		렌더러 프로세스(Renderer Process)

이 두 가지는 서로 다른 역할을 합니다.
```

### (1) 메인 프로세스(Main Process)

```jsx
프로그램을 실행하면 가장 먼저 시작하는 부분이에요.

프로그램의 "백엔드" 같은 역할을 합니다.

예를 들어, 파일을 열거나, 저장하거나, 윈도우를 띄우는 등의 작업을 맡아요.

메인 프로세스는 Node.js라는 자바스크립트 환경을 사용합니다.

이 덕분에 파일 시스템이나 데이터베이스 같은 운영체제와 직접 상호작용할 수 있어요.
```

### (2) 렌더러 프로세스(Renderer Process)

```jsx
사용자 인터페이스(UI)를 만드는 곳이에요.

즉, 화면에 보이는 버튼, 텍스트, 창 등을 담당하죠.

HTML, CSS, JavaScript로 화면을 디자인할 수 있습니다.

(웹 개발을 해본 적 있다면 익숙할 거예요!)

브라우저처럼 동작합니다. Electron 내부에 Chromium 엔진이 있어서 화면을 렌더링해줍니다.

또한, Node.js 기능도 사용 가능하니 백엔드와 프론트엔드를 모두 다룰 수 있죠.
```

## 3. **Electron이 어떻게 작동하나요?**

```jsx
1. 메인 프로세스 시작

		프로그램을 실행하면 메인 파일(main.js 또는 main.ts)이 실행됩니다.

		이 파일에서 **"창을 만들라!"**는 명령을 내립니다.

2. 렌더러 프로세스 생성

		메인 프로세스는 BrowserWindow라는 모듈을 사용해서 새로운 "창(Window)"을 만듭니다.

		그리고 이 창에서 HTML 파일을 로드합니다.

3. 화면 렌더링

		렌더러 프로세스가 이 HTML을 기반으로 화면을 보여줍니다.

		사용자가 화면에서 버튼을 클릭하거나 입력하면, 그에 따라 동작이 실행됩니다.
```

## 4. **메인 프로세스와 렌더러 프로세스는 어떻게 대화하나요?**

```jsx
Electron 앱에서 메인 프로세스와 렌더러 프로세스는 서로 완전히 독립적인 프로세스로 실행됩니다.

그래서 서로 "대화"가 필요할 때는 특별한 방법을 사용해야 합니다.

IPC (Inter-Process Communication)

		이건 "프로세스 간 통신"을 뜻합니다.

		메인 프로세스는 ipcMain 모듈을, 렌더러 프로세스는 ipcRenderer 모듈을 사용합니다.

		서로 메시지를 주고받으며 필요한 정보를 전달합니다.

		예: 렌더러에서 "파일을 열어줘!"라고 메인에 요청 → 메인이 파일을 열고 렌더러로 결과를 전달.
```

## 비유로 이해하기

```jsx
Electron 앱을 웹 애플리케이션에 비유해 보면:

메인 프로세스 = 백엔드 서버

		서버가 데이터를 처리하거나 요청에 응답하듯,

		Electron의 메인 프로세스는 앱의 내부 동작을 제어합니다.

렌더러 프로세스 = 프론트엔드

		사용자가 보는 화면과 상호작용하는 역할을 합니다.

HTTP 통신 대신 IPC 사용

		일반 웹 앱에서는 서버와 클라이언트가 HTTP 요청/응답으로 소통하지만,

		Electron에서는 IPC를 사용해 프로세스끼리 소통합니다.
```
