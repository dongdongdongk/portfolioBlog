# 웹 작동 방식

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381047/notion-blog/_/Node_js/NodeJS_MVC_REST_APIs_GraphQL_Deno/Node_js_/Untitled.png)

```jsx
1. 웹이 작동하는 방식은 유저와 클라이언트가 있고

	 우리는 브라우저 앞에 앉아서 웹 페이지를 방문하거나

   이미 웹 페이지에 접속한 상태로 양식을 보내는 등의 웹 페이지와 상호작용하고 있다

2. URL 입력 및 도메인 확인:

	 브라우저는 입력한 URL에서 도메인을 확인하기 위해 도메인 네임 서버(DNS)에 접근한다.

	 브라우저가 DNS 로 접근하여 해당 도메인을 찾는 이유는

	 도메인은 사용자가 이해하기 쉽게 주소를 표현한 것이며(http:// ---- )( 도메인 주소는 사람이 읽을 수 있도록 IP 주소를 인코딩 한 버전 )

	 이를 실제 서버의 IP 주소로 변환한다 ( 서버의 경우 단순히 IP 주소를 가지고 있다 )

3. 서버 접속:

	 변환된 IP 주소를 사용하여 브라우저는 해당 서버에 연결을 시도한다.

	 서버는 이 IP 주소를 기반으로 들어오는 요청을 처리할 수 있도록 설정되어 있다.

4. Node.js 코드 실행:

	 서버에 연결된 상태에서 Node.js 코드가 중요한 역할을 시작한다.

	 이 코드는 서버에서 실행되며 들어오는 요청을 처리하고 해당 요청을 활용하여 다양한 작업을 수행한다.

5. 서버 구동 및 응답 처리:

	 Node.js 코드는 서버를 구동하고, 들어오는 요청을 처리하며 응답을 생성한다.

	 이 코드에서는 사용자 입력 유효성 검사, 데이터베이스와의 상호작용 등을 다룰 수 있다.

	 ( 이 경우 Node.js를 꼭 쓸 필요는 없고 PHP, asp.net, Ruby on Rails 등 뭐든지 사용해도 좋지만 여기는 node.js )

6. 클라이언트 응답 처리:

	 수행된 작업에 대한 응답은 HTML 텍스트와 HTML 코드 등 다양한 형태가 될 수 있다.

	 이 응답은 클라이언트(브라우저)에 전송되어 처리된다.

	 이후 클라이언트를 통해 처리되나 파일, JSON 또는 XML을 비롯한 다른 종류의 데이터일 수도 있다

7. 프로토콜과 헤더:

	 모든 요청과 응답은 프로토콜(HTTP 또는 HTTPS)에 따라 이루어진다.

	 이는 표준화된 통신 방법을 의미하며, 요청과 응답에는 메타 정보인 헤더가 포함된다. 헤더는 내용의 종류와 관련된 정보 등을 설명한다.
```

```jsx
종합하면, 브라우저에서 입력한 URL을 통해 서버에 연결하고,

Node.js 코드를 실행하여 서버에서의 작업을 수행한 뒤, 클라이언트에 응답을 전송하는

것이 웹의 기본 동작 구조이다.

이 과정은 HTTP 또는 HTTPS 프로토콜을 따라 표준화된 방식으로 이루어진다, 사용자와 서버 간의 효과적인 통신을 가능케 한다.
```

### HTTP

```jsx
* HTTP는 웹에서 데이터를 주고받을 때 사용되는 규약으로, 클라이언트와 서버 간의 통신을 조정

* HTTPS는 HTTP의 보안 버전으로, SSL 암호화를 통해 데이터를 안전하게 전송

* 보통 코드를 개발할 때는 HTTP를 사용하고, 제품이나 서비스를 운영할 때는 HTTPS를 사용하여 데이터 보안을 강화
```

# Node.js 에서 서버 생성

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381046/notion-blog/_/Node_js/NodeJS_MVC_REST_APIs_GraphQL_Deno/Node_js_/Untitled_1.png)

```jsx
// 1. http 모듈을 불러옵니다.
const http = require('http')

// 2. http.createServer()를 호출하여 HTTP 서버를 생성합니다.
//    이 함수는 콜백 함수를 받습니다. 콜백 함수는 요청(request)이 발생할 때마다 호출됩니다.
const server = http.createServer((req, res) => {
  // 3. 콜백 함수 내에서는 요청(req) 객체를 통해 클라이언트로부터의 요청 정보를 확인할 수 있습니다.
  //    여기서는 간단히 요청 객체를 콘솔에 출력합니다.
  console.log(req)

  // 4. 응답(res) 객체를 통해 클라이언트에게 응답을 보낼 수 있습니다.
  //    현재 코드에서는 아무 응답도 전송하지 않습니다.
})

// 5. 서버가 특정 포트(여기서는 3000)에서 대기하도록 설정합니다.
server.listen(3000)
```

# { Node의 라이프사이클 및 이벤트 루프 }

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381046/notion-blog/_/Node_js/NodeJS_MVC_REST_APIs_GraphQL_Deno/Node_js_/Untitled_2.png)

## 1. Node.js 서버 생성 및 실행

```jsx
서버 생성

	http 모듈을 사용하여 서버를 생성합니다.

	createServer 메서드를 사용하여 서버를 만들고, 요청이 올 때마다 실행될 함수를 작성합니다.
```

```jsx
const http = require('http')
const server = http.createServer((req, res) => {
  res.statusCode = 200
  res.setHeader('Content-Type', 'text/plain')
  res.end('Hello, World!\n')
})
```

```jsx
파일 실행

	app.js 파일을 터미널에서 실행합니다

	node app.js

	이 명령어는 Node.js가 파일을 읽고 실행하여 서버를 시작하게 합니다.
```

## 2. 이벤트 루프(Event Loop)

```jsx
개념

	이벤트 루프는 Node.js의 중요한 개념으로, Node.js가 작업이 끝날 때까지 계속 작동하게 합니다.

	예를 들어, 서버에 요청이 들어오면 그 요청을 처리하는 함수가 실행됩니다.

서버 지속성

	createServer로 만든 이벤트 리스너(요청을 처리하는 함수)가 계속 존재하기 때문에, 이벤트 루프가 멈추지 않고 계속 작동합니다.
```

```jsx
server.listen(3000, '127.0.0.1', () => {
  console.log('Server running at http://127.0.0.1:3000/')
})
```

```jsx
이 코드에서 server.listen 메서드가 서버를 특정 포트에서 실행하도록 합니다. 서버가 실행 중인 한, 이벤트 루프는 계속 작동합니다.
```

## 3. 이벤트 드리븐 접근

```jsx
서버 관리

	Node.js는 이벤트 드리븐(event-driven) 방식으로 작동합니다. 이는 요청이 들어올 때마다 이벤트가 발생하고, 그 이벤트를 처리하는 방식입니다.

데이터베이스 접근

	데이터베이스에 접근할 때도, 비슷한 패턴이 사용됩니다

	이 코드는 데이터베이스에 요청을 보내고, 요청이 완료되면 결과를 처리하는 함수를 실행합니다.
```

```jsx
const db = require('db')
db.query('SELECT * FROM users', (err, result) => {
  if (err) throw err
  console.log(result)
})
```

```jsx
단일 스레드

	Node.js는 단일 스레드에서 작동합니다. 이는 하나의 스레드가 모든 요청을 처리한다는 뜻입니다.

	하지만 비동기 방식 덕분에, 많은 요청을 효율적으로 처리할 수 있습니다.
```

## 4. 프로세스 종료

```jsx
프로세스 종료 방법

	서버를 종료하고 싶다면 process.exit를 사용합니다.

process.exit();
```

```jsx
효과

	이 메서드는 이벤트 루프를 종료하고 프로그램을 중지시킵니다.

사용 사례

	일반적으로 서버를 중지하지 않지만, 테스트나 유지보수를 위해 사용될 수 있습니다.
```

# { 요청의 이해 }

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381047/notion-blog/_/Node_js/NodeJS_MVC_REST_APIs_GraphQL_Deno/Node_js_/Untitled_3.png)

## 요청 객체 다루기

```jsx
요청 객체

	생성: Node.js가 생성하는 요청 객체는 들어오는 요청에 대한 모든 데이터를 포함하고 있습니다.

	복잡성: 요청 객체는 많은 양의 데이터와 다양한 기능을 포함한 복잡한 객체입니다.

헤더

	메타데이터: 요청 및 응답에 대한 메타 정보를 담고 있습니다.

	예시: 호스트 정보, 브라우저 정보, 응답 데이터 캐시 방법, 응답 유형(html, xml 등), 응답 축소 방법(암호화 응답) 등.

	쿠키: Google Analytics 쿠키와 같은 정보도 포함됩니다.

	HTTP 버전: 사용된 HTTP의 버전 정보도 포함됩니다.
```

## 요청 객체 필드 다루기

```jsx
중요 필드

	req.url: 요청의 URL 정보를 담고 있습니다.

	req.method: 요청의 HTTP 메서드(GET, POST 등)를 담고 있습니다.

	req.headers: 요청에 포함된 모든 헤더 정보를 담고 있습니다.
```

```jsx
코드 예시

	아래는 요청 객체의 필드를 콘솔에 출력하는 코드 예시입니다.

const http = require('http');

const server = http.createServer((req, res) => {
  console.log('URL:', req.url);
  console.log('Method:', req.method);
  console.log('Headers:', req.headers);

  res.statusCode = 200;
  res.setHeader('Content-Type', 'text/plain');
  res.end('Hello, World!\n');
});

server.listen(3000, '127.0.0.1', () => {
  console.log('Server running at http://127.0.0.1:3000/');
});
```

## 응답 객체 사용하기

```jsx
응답 객체 설정

	setHeader: 브라우저가 이해하는 형식으로 응답 헤더를 설정할 수 있습니다.

	Content-Type: 응답의 콘텐츠 유형을 설정합니다. 예를 들어, text/html은 HTML 문서를 나타냅니다.
```

```jsx
res.setHeader('Content-Type', 'text/html')
```

```jsx
HTML 코드 전송

res.write: 응답 객체에 데이터를 기록할 수 있습니다.

res.write('<html>');
res.write('<head><title>My First Page</title><head>');
res.write('<body><h1>Hello from my Node.js Server!</h1></body>');
res.write('</html>');

res.end: 응답을 종료합니다. 이 메서드를 호출하면 응답이 클라이언트로 전송됩니다

res.end();
```
