# { 🎵 3단원: 적은 자원으로 다양한 소리 만들기 }

## 1. 🎮 왜 적은 자원으로 소리를 만들어야 할까?

- 비디오 게임 개발에서는 **그래픽, 물리 연산, 네트워크** 같은 요소들이 많은 리소스를 차지합니다.
- 반면 **오디오**는 보통 “필수적이지만 큰 예산은 받지 못하는 영역”입니다.
- 따라서 **제한된 용량과 CPU 사용량 안에서 최대한 다양한 소리를 만들어내는 기술**이 중요합니다.

👉 즉, **같은 소리를 단순 반복하지 않고, 최소한의 파일로 최대한 다양한 느낌을 주는 방법**을 배우는 단원이에요.

---

## 2. 📦 랜덤 컨테이너(Random Container) 개념

- **문제**: 같은 효과음을 계속 재생하면 **부자연스럽게 반복**됨.
- **해결책**: 여러 개의 비슷한 사운드를 준비하고, **매번 랜덤으로 선택**해서 재생하기.

💡 예시:

얼음 보석이 떨어질 때 → 5개의 다른 "땅에 부딪히는 소리"를 녹음해 두고, 매번 그 중 하나가 랜덤하게 재생됨.

- 덕분에 플레이어는 "매번 다른 소리"처럼 느끼게 됩니다.

---

## 3. 🎚️ 피치 랜덤화(Pitch Randomization)

- 같은 오디오 파일을 그대로 반복하면 금방 질리거나 인위적으로 들려요.
- **재생할 때마다 조금씩 피치를 바꿔서** (예: 높게/낮게) 변주를 줄 수 있음.
- 실제로는 **하나의 파일만 있어도** 매번 다른 소리처럼 들릴 수 있음.

👉 예를 들어, 유리 조각이 깨지는 소리의 피치를 약간 올리면 작은 조각 같고, 피치를 낮추면 큰 조각처럼 느껴짐.

---

## 4. ⏱️ 사운드 시퀀스(Sequence) 만들기

- 여러 개의 소리를 **순서대로 재생**하는 구조.
- 예:
  - "보석이 땅에 떨어짐" → "잔해가 굴러감" → "작게 멈추는 소리"
- 이렇게 하면 현실감이 높아짐.

---

## 5. 🔇 무음 삽입(Silence in Sequence)

- 모든 소리가 꽉꽉 채워져 있으면 **인위적**이고 **예측 가능**함.
- 시퀀스 안에 **짧은 무음**을 랜덤하게 섞어주면 더 자연스럽게 들림.
- 예:
  - "쾅!" → (0.2초 무음) → "딸깍"
- 이렇게 하면 실제로 물건이 땅에 부딪히고 반응하는 **시간 간격**까지 표현 가능.

---

## 6. 🛠️ 이 단원에서 배우는 기술 요약

1. **WAV 파일 가져오기** → 여러 개의 효과음을 프로젝트로 불러옴.
2. **랜덤화 설정하기** → 랜덤 컨테이너로 매번 다른 파일 재생.
3. **피치 랜덤화** → 같은 파일도 높낮이를 달리해 새롭게 들리도록.
4. **사운드 시퀀스 만들기** → 소리들을 순서대로 이어 붙여 현실감 추가.
5. **무음 삽입하기** → 빈 공간을 활용해 자연스러움 강화.

---

✅ 정리하면:

이 단원은 **“적은 리소스로 다채로운 소리를 만드는 법”**을 배우는 과정이에요.

- 같은 소리를 그대로 반복하지 않고,
- **랜덤 + 변형 + 시퀀스 + 무음** 같은 기법을 통해
  플레이어가 들을 때마다 새로운 소리를 경험하게 하는 것이 핵심입니다.

---

# { 🎵 오디오 파일 폴더 가져오기 (Wwise & Cube 연동) }

## 1. 🖥️ 기본 준비

- **Cube 실행** → Cube는 게임 실행 환경(테스트용 샘플 게임).
- **Wwise 실행 & 프로젝트 열기** → _Module 3_ 프로젝트 파일을 열어야 함.
- Cube와 Wwise를 연결하면, **실시간으로 게임 속 오디오 변화를 테스트**할 수 있음.

👉 즉, Cube는 "게임 실행기", Wwise는 "사운드 편집기", 둘을 연결해놓고 작업한다는 개념이에요.

---

## 2. 📂 오디오 파일 폴더 가져오기

- OS에서 `Module 3\Audio files for Module 3` 경로로 이동.
- 그 안에 있는 **Gem Head**와 **Gem Tail** 폴더를 **Wwise의 Actor-Mixer Hierarchy > Default Work Unit** 으로 **드래그**.

➡️ 이렇게 하면 **Audio File Importer** 창이 열림.

## 3. 📦 Import 옵션 선택 (Random Container 만들기)

- 원래는 폴더가 그대로 **Virtual Folder(가상 폴더)** 로 들어옴.
  - Virtual Folder = 단순 정리용 폴더 (실제 동작에는 영향 없음).
- 여기서 **Object Type/Action → Random Container**로 바꿔 Import.

👉 그러면 Gem Head / Gem Tail 폴더가 단순한 폴더가 아니라 **Random Container 오브젝트**로 변환됨.

- Random Container = 여러 사운드 중 하나를 **랜덤 재생**하는 특수한 컨테이너.

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380562/notion-blog/_/WWISE/Wwise_/3_/image_1.png)

```jsx
여러가지 컨테이너
```

## 4. 🎲 Random Container 특징

- Sound SFX 오브젝트처럼 **Transport Control(재생 버튼)** 으로 재생 가능.
- 하지만 Random Container는 → **재생할 때마다 안에 있는 여러 사운드 중 하나를 무작위로 선택**해서 재생.

💡 효과:

- 같은 사운드만 계속 반복되는 지루함 방지.
- 플레이어가 매번 “새로운 소리”처럼 듣게 만들어 **자연스러운 경험** 제공.

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380562/notion-blog/_/WWISE/Wwise_/3_/image_2.png)

```jsx
실제 랜덤 컨테이너 표시
```

---

## 5. 🔍 Random Container 안의 구조 확인

- Gem Head / Gem Tail Random Container를 **확장**해보면 → 안에 여러 개의 보석 깨지는 사운드(Sound SFX)가 포함되어 있음.
- **재생 버튼(스페이스바)** 을 여러 번 누르면:
  - 노란 화살표가 현재 선택된 사운드를 표시.
  - 매번 다른 보석 깨지는 소리가 재생됨.

👉 이렇게 해서 랜덤 기능이 실제로 작동하는지 확인 가능.


---

## 6. 🗑️ 특정 사운드 제외하기 (삭제 아님!)

- 어떤 소리는 게임 분위기와 맞지 않을 수 있음.
- 하지만 Wwise에서는 그 파일을 **삭제하지 않고 “플랫폼에서 제외”**할 수 있음.
  - 이유 ① : 필요 없으면 제외해서 **메모리 절약**.
  - 이유 ② : 나중에 필요할 때 다시 쉽게 포함 가능.

💡 방법:

- Gem Head와 Gem Tail Random Container 안에서 마지막 두 개의 **Gem_Breaking Sound SFX** 오브젝트 → **플랫폼 포함/제외 체크박스 해제**.
- 다시 재생해보면, 제외된 사운드는 더 이상 랜덤 선택되지 않음.

---

# ✅ 개념 정리

1. **Cube + Wwise 연결** → 게임 속 사운드를 실시간으로 테스트하기 위함.
2. **오디오 파일 Import** → 폴더를 드래그하면 기본은 Virtual Folder로 들어오지만, Random Container로 바꿔 Import 가능.
3. **Random Container** = 여러 사운드를 담고, 매번 무작위 재생 → 반복의 지루함 해결.
4. **Virtual Folder** = 단순 정리용, 실제 기능 없음.
5. **플랫폼 제외 기능** = 필요 없는 사운드를 삭제하지 않고, 메모리 절약 + 추후 재사용 가능.

👉 요약: **"적은 리소스로 다양한 소리를 만들어내기 위해 Wwise의 Random Container와 오디오 제외 기능을 활용한다."**

# { 🎲 제어된 랜덤화 사용하기 (Controlled Randomization) }

## 1. ❓ 문제 상황

- Random Container는 매번 다른 소리를 랜덤으로 선택하지만, **운이 나쁘면 같은 소리가 연속으로 재생**될 수 있음.
- 예:
  - "쨍그랑" → 다시 "쨍그랑" → 또 "쨍그랑"
- 이렇게 되면 **자연스럽지 않고 반복감이 심해짐**.

👉 해결책: **Random Container 속성에서 랜덤 방식을 제어**할 수 있음.

---

## 2. 🛠️ Limit Repetition To (반복 제한)

1. **Project Explorer**에서 `Gem Head` 오브젝트 선택.
2. **Property Editor**에서 `Random Container` 카테고리 선택.
3. `Limit Repetition To` 값을 **2**로 설정.

➡️ 의미:

- 같은 소리가 연속해서 2번 이상 나오지 않도록 제한.
- 즉, 한 번 재생된 소리는 최소한 1번은 다른 소리가 재생된 후에야 다시 나올 수 있음.

💡 효과:

- 같은 사운드가 “우연히” 연속해서 들리는 상황 방지 → **더 다양하고 자연스럽게** 들림.

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380562/notion-blog/_/WWISE/Wwise_/3_/image_4.png)

```jsx
같은 사운드 재생 방지
```

---

## 3. 🔄 Random Type → Shuffle

- `Property Editor`에서 `Random Type`을 **Shuffle**로 설정.

➡️ Shuffle의 의미:

- 모든 사운드를 한 번씩 다 재생하기 전까지는 **같은 사운드가 반복되지 않음**.
- 카드 덱을 섞어서 뽑는 것과 같은 방식.

💡 예:

- A, B, C, D 네 개의 소리가 있다면:
  - 순서는 랜덤하지만 → A-B-C-D가 다 나오기 전까지 A는 다시 나오지 않음.
- 따라서 훨씬 **공평하고 덜 반복적인 랜덤화**를 구현할 수 있음.

---

## 4. 🎧 확인하기

- `Gem Head Random Container`에서 재생 버튼을 눌러 Shuffle과 Repetition 제한 효과 확인.
- 같은 방식으로 `Gem Tail Random Container`에도 동일하게 적용.

---

# ✅ 개념 정리

1. **문제**: 랜덤은 진짜 랜덤이라, 같은 소리가 연속 재생될 수 있음 → 부자연스러움.
2. **Limit Repetition To**: 같은 소리가 연속으로 나오지 않게 최소 간격 설정.
3. **Random Type: Shuffle**: 모든 소리가 한 번씩 나오기 전까지는 중복되지 않음.
4. **결과**: 플레이어는 항상 “랜덤하면서도 반복되지 않는” 다양한 소리를 경험하게 됨.

👉 핵심: **진짜 랜덤(random)** 대신 **제어된 랜덤(controlled random)** 을 사용해 **자연스러운 다양성**을 만든다.

---

# { 🎛️ 속성 랜덤화 (Property Randomization) }

## 1. ❓ 왜 속성을 랜덤화할까?

- 지금까지는 **여러 개의 오디오 파일**을 준비해 랜덤으로 선택하는 방식으로 다양성을 줬음.
- 하지만 파일을 많이 준비하면 **메모리 사용량 증가**라는 단점이 있음.
- 해결책 → **오디오 파일은 그대로 두고, 속성(볼륨, 필터, 피치 등)을 재생할 때마다 조금씩 랜덤하게 바꿔주기.**

👉 효과:

- **메모리를 늘리지 않고도** 매번 다른 느낌을 줄 수 있음.
- 같은 녹음이라도 항상 새롭게 들림.

---

## 2. 🛠️ Pitch 속성 랜덤화하기

1. **Project Explorer**에서 `Gem Head` 오브젝트 선택.
2. **Property Editor → General** 카테고리에서 `Pitch` 속성 찾기.
3. Pitch 옆에 있는 **Randomizer 아이콘** 더블 클릭.

➡️ 그러면 **Randomizer 창**이 열림.

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380563/notion-blog/_/WWISE/Wwise_/3_/image_5.png)

---

## 3. ✅ Randomizer 활성화

- `Enable` 체크박스를 클릭 → Pitch 속성의 랜덤화 활성화.
- 아이콘이 **주황색**으로 바뀌면 활성화된 것.
- 단, 아직 **Min/Max Offset 값**을 설정하지 않으면 차이를 느낄 수 없음.

---

## 4. 🎼 Offset 값 설정하기

- `Min Offset = -150`, `Max Offset = +150` 입력.
- 단위: **센트(cent)**
  - 100 cent = 반음(Semitone)
  - 1200 cent = 1 옥타브

➡️ 결과:

- 보석 깨지는 소리의 피치가 원래보다 **최대 -150 ~ +150 cent** 범위 안에서 랜덤하게 변동.
- 즉, 매번 같은 파일이지만 → 조금 더 낮게/높게 들려서 항상 새롭게 느껴짐.

---

## 5. 🎧 테스트 & 반복 적용

- `Gem Head Random Container`를 여러 번 재생 → 매번 피치가 달라지는 것을 확인.
- `Gem Tail Random Container`에도 똑같은 설정 적용.

---

# ✅ 개념 정리

1. **속성 랜덤화란?** → 파일 개수를 늘리지 않고, 사운드 속성(볼륨/피치/필터 등)을 실행할 때마다 변동시켜 다양성을 만드는 기법.
2. **Pitch Randomizer** → 피치를 일정 범위 안에서 무작위로 바꿔줌.
3. **Offset 범위 설정** → Min/Max 값으로 랜덤 변화폭 조정.
4. **장점**:
   - 메모리 추가 사용 없음.
   - 같은 소리도 매번 새롭게 들려서 반복감 감소.

👉 핵심: **“사운드를 다양하게 만드는 방법은 꼭 파일만 늘리는 게 아니라, 속성을 랜덤화해서도 가능하다.”**

# { 🔗 시퀀스 만들기 (Sequence Container) }

## 1. ❓ 문제 상황

- 지금까지는 **Gem Head**(머리 사운드), **Gem Tail**(꼬리 사운드)가 각각 랜덤으로 잘 재생됨.
- 하지만 “보석이 발사될 때 → 머리 소리 먼저 → 꼬리 소리 다음”이라는 **자연스러운 순서**가 필요함.
- 현재 구조는 별개라서 → 머리만 재생되거나 꼬리만 재생될 수 있음.

👉 해결책: **Sequence Container** 사용!

---

## 2. 🎼 Sequence Container 개념

- **Random Container**: 여러 소리 중 하나를 **무작위**로 재생.
- **Sequence Container**: 여러 소리를 **정해진 순서대로** 재생.

➡️ 즉, Sequence Container는 “사운드 재생 시나리오(순서)”를 만들 수 있는 오브젝트.

---

## 3. 🛠️ 단계별 만들기

### (1) 컨테이너 생성

1. **Project Explorer**에서 `Gem Head` + `Gem Tail Random Containers`를 **Ctrl + 클릭**으로 동시 선택.
2. 선택 후 **우클릭 → New Parent → Sequence Container**.
3. 새로 생긴 오브젝트 이름을 **Gem Drop**으로 변경.

👉 이제 Gem Drop 안에 Gem Head와 Gem Tail이 들어옴.

---

### (2) Playlist 만들기

- Sequence Container 안에서도 단순히 나열된 순서는 의미 없음.
- **Playlist**라는 설정에서 실제 재생 순서를 정해야 함.

1. 기본 편집기 오른쪽의 **+ 버튼** 클릭 → `Gem Head` 추가.
2. 다시 **+ 버튼** 클릭 → `Gem Tail` 추가.

➡️ Playlist에 [Gem Head → Gem Tail] 순서가 등록됨.

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380563/notion-blog/_/WWISE/Wwise_/3_/image_6.png)

---

### (3) Play Mode 설정

- 지금 상태에서 **Gem Drop**을 재생해보면:
  - 첫 번째 Play → Gem Head 중 하나만 재생.
  - 두 번째 Play → Gem Tail 중 하나만 재생.

👉 이렇게 되면 실제 게임에서도 머리만 나오고 꼬리는 따로 나옴 → 우리가 원하는 “연속 시퀀스”가 아님.

🔧 해결:

- **Property Editor → Sequence Container → Play Mode = Continuous** 로 변경.

➡️ Continuous 모드 = Playlist 순서를 따라 연속 재생.

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380563/notion-blog/_/WWISE/Wwise_/3_/image_7.png)

---

## 4. 🎧 결과 확인

- 이제 Gem Drop Sequence Container를 재생할 때마다:
  1. 랜덤 Gem Head 사운드 하나 재생 →
  2. 이어서 랜덤 Gem Tail 사운드 하나 재생.

👉 매번 새로운 조합이 만들어지면서도, **머리 → 꼬리** 순서가 자연스럽게 유지됨.

---

# ✅ 개념 정리

1. **Random Container** = 무작위 선택 (다양성 ↑).
2. **Sequence Container** = 정해진 순서로 재생 (자연스러운 흐름 ↑).
3. **Playlist** = 순서 정의하는 곳.
4. **Play Mode: Continuous** = 순서를 끊기지 않고 이어서 재생.
5. **결과**: Gem Drop = 머리(Random) + 꼬리(Random) 조합이 자연스럽게 연결된 보석 사운드.

👉 핵심: **“랜덤의 다양성 + 시퀀스의 자연스러움”을 결합해 더 생생한 게임 사운드 구현!**

# { 🎵 무음(Silence) 사용하기 정리 }

## 1. 왜 무음을 사용하는가? (개념)

- 머리 부분 사운드(보석 발사 소리)와 꼬리 부분 사운드(보석이 떨어지는 소리)를 연속해서 붙이면 너무 빠르게 이어져 **자연스럽지 않은 느낌**이 납니다.
- 실제 상황을 생각해 보면, 보석이 발사되자마자 바로 땅에 닿지는 않습니다. 공중에 잠깐 떠 있다가 **잠시 지연된 후 충돌음**이 들려야 현실적으로 들립니다.
- 그래서 Wwise에서는 단순히 오디오 파일만 쓰는 게 아니라 **Silence(무음 플러그인)** 을 활용해, 사운드 사이에 의도적으로 정지 시간을 넣을 수 있습니다.

---

## 3. 사운드 재생 확인 (결과)

- Transport Control에서 ▶ Play(스페이스바)를 누르면
  - **머리 부분 사운드 → 0.25초 무음 → 꼬리 부분 사운드** 순서로 들림.
- 이제 보석이 발사된 후, 실제로 잠깐 공중에 떠 있는 것 같은 **자연스러운 템포**가 생김.

---

## 4. 이벤트 지연(Delay) 추가하기 (응용)

- 단순히 Silence만 추가하는 것보다, 이벤트에서 Delay를 주면 더 사실적으로 연출 가능.

1. **이벤트에 Gem Drop 연결**
   - Project Explorer → Events 탭에서 `Fire_IceGem_Player` 선택
   - Audio 탭에서 `Gem Drop`을 Event Editor의 Actions 창으로 드래그
2. **Delay 적용**
   - Actions 창에서 `Gem Drop` 선택
   - Delay 값을 **0.4초**로 설정
     → 보석 발사 후 충돌음이 약간 늦게 들리도록 설정됨.
3. **랜덤화(Randomizer) 적용**
   - Delay 매개변수 오른쪽의 🎲 Randomizer 아이콘 더블클릭
   - `Enabled` 체크 후, **Max Offset = 0.3** 설정
     → 이제 Delay가 **0.4 ~ 0.7초 사이**에서 무작위로 변동
     → 보석이 항상 똑같은 속도로 땅에 떨어지지 않고, **매번 다른 타이밍**으로 들림 → 더 현실적!

---

## 5. Cube에서 테스트 (게임 내 확인)

- Pin 고정을 해제하고 게임 Cube로 돌아감
- 클릭해서 얼음 보석 발사 → 여러 번 반복
- 매번 머리 → 무음 → 꼬리 부분 사운드가 조금씩 다른 타이밍에 나와 **다채롭고 자연스러운 오디오 경험** 제공.

---

## 6. 정리 (핵심 개념)

- **Silence 플러그인** : 사운드 사이에 의도적 무음(정지 시간)을 넣어주는 도구
- **Delay + Randomizer** : 실제 물리적인 다양성을 모방하여, 똑같은 소리가 반복되지 않도록 함
- 이를 통해 최소한의 에셋만으로도 **더 사실적이고 몰입감 있는 오디오**를 제작할 수 있음

---

👉 즉, 무음과 지연(Randomized Delay)을 적절히 활용하면, "게임 오디오가 기계적으로 들리지 않고, 실제 물리적 사건처럼 자연스럽게" 들리게 만들 수 있는 거예요.
