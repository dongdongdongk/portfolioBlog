# 4. Security Config

```jsx
Spring Security 5.7.0-M2 부터 WebSecurityConfigureAdapter는 Deprecated 됨
대신 SecurityFilterChain 을 Bean으로 등록하는 방식을 권장

**1. WebSecurity 설정 클래스 생성**

@Configuration //설정과 관련된 어노테이션
@EnableWebSecurity // 시큐리티 적용 어노테이션 추가
public class SecurityConfig  {

	@Bean            // @Component 와 비슷한 어노테이션 객체를 만들
	//public 을 선언하면 default로 바꾸라는 메세지 출력 (public WebSecurityCustromizer)
	WebSecurityCustomizer webSecurityConfig() {
		**//Security에서 무시해야하는 URL 패턴 등록 (이미지 css 등 시큐리티가 필요없는 부분)**
		return web -> web //-> :람다함수
			   .ignoring() //"."으로 연결: 메서드 체이닝 //ignoring():무시하겠다
			   .antMatchers("/images/**")
			   .antMatchers("/css/**")
			   .antMatchers("/js/**")
			   .antMatchers("/favicon/**")  //웹브라우저에 들어가는 이미지
			   .antMatchers("/resources/**");
	}

// 메서드 체이닝 예시) person.setName("John").setAge(30).setAddress("New York");
// 여러 개의 메서드 호출을 한 줄로 연결하여 사용하는 것

@Bean          //public 을 사용하지 않고 매개변수로 http Security 를 받는다
	SecurityFilterChain fiterChain(HttpSecurity httpSecurity)throws Exception{
		httpSecurity
					.cors()   //cors
					.and()    // 와
					.csrf()   // csrf 를
					.disable() // 활성화 하지 않겠다.
				.authorizeRequests()          // 권한 과 관련된 메서드
					.antMatchers("/").permitAll() //루트 밑에 시작하는걸 모두 허용하겠다(permitAll) 이후 아래에서 제한을 시작
					.antMatchers("/admin").hasRole("ADMIN") // /adimn 을 가진 주소는 role ADMIN 만 허용
					.antMatchers("/manager").hasAnyRole("ADMIN","MANAGER") //ADMIN 을 가지거나 MANAGER를 가진 사람만 허용 => 회원 한명당 하나의 ROLE를 가질때
					.anyRequest().authenticated() //그외 나머지는 로그인 해야 볼수 있어요 (authenticated = 로그인 해야 )
					.and()
				.formLogin()      // 로그인 포폼은
					.permitAll()    // 모두 허용
					.and()
				.logout()         // 로그아웃도
					.permitAll();   // 모두 허용

		return httpSecurity.build(); //빌드해서 만들어 준다

	}

}

```

```java
import lombok.Getter;
import lombok.Setter;

@Setter
@Getter
public class MemberVO implements UserDetails, OAuth2User{

	private String username;

	@Future

	private List<RoleVO> roleVOs;

	private Map<String, Object> attributes;
```

# 11. CSRF

```jsx
=> CSRF는 Cross-Site Request Forgery의 약자로, 한국어로는 사이트간 요청 위조라고 번역
로그인한 사용자가 다른 계좌로 이체
	/bank/transfer?account=받을계좌&amount=금액

	1. 사용자가 은행에 로그인 됨
	2. 해커가 사용자에게 이메일전송
	3. <img src="/bank/transfer?account=해커의계좌&amount=1000만원">
	4. 이미지를 클릭하거나 하는 순간 송금이 됨

- 해결방안
1. **GET 메서드는 제외하고  POST 요청**
2. **서버에서 CSRF 토큰을 발행**하고 **사용자는 서버 요청시 CSRF 토큰을 같이 보냄**
3. Tocken은 계속 바뀜
4. 위 예제에서는 CSRF 토큰이 없기 때문에 Reject
```

```jsx
1. **Security Config에서 CSRF 활성화**
	 **.csrf().disable() 삭제**

2. **CSRF Token 적용**
	 1)
		<form >
			**<input type="hidden" name="${_csrf.parameterName}" value="${_csrf.token}">**
		</form>
//서버에서 발행한 csrf 의 token
	2) **sec**
	<form>
			**<sec:csrfInput/>**
	</form>
```

### UserVO

```jsx
SecurityContext의 Authentication내에 저장 할 수 있는 객체 타입은
UserDetails타입과 OAuth2User 타입으로 정해져 있음

**일반 로그인**의 경우 **UserDetails 타입** 사용
**Social 로그인**의 경우 **OAuth2User 타입** 사용

JSP에서 두개의 타입을 판별 하는 번거로움을 방지 하기 위해

하나의 VO에 UserDetails, OAuth2User 둘다 구현.

@Data
public class MemberVO implements UserDetails, **OAuth2User**{

	@NotBlank(message = "ID는 꼭 필요해!!!")
	private String id;
	@NotBlank
	private String pw;
	private String pwCheck;
	@NotBlank
	private String name;
	@Email
	@NotBlank
	private String email;

	@Range(max = 150, min = 0)
	private int age;

	@Past
	private Date birth;
	private boolean enabled;

	private List<RoleVO> roleVOs;

	**//OAuth2User, Token등 정보 저장
	private Map<String, Object> attributes;**




	@Override
	public Collection<? extends GrantedAuthority> getAuthorities() {

		List<GrantedAuthority> authorities = new ArrayList<>();
		for(RoleVO roleVO : roleVOs) {
			authorities.add(new SimpleGrantedAuthority(roleVO.getRoleName()));

		}

		return authorities;
	}

	@Override
	public String getPassword() {
		// PW 반환
		return this.getPw();
	}

	@Override
	public String getUsername() {
		// ID 반환
		return this.id;
	}

	@Override
	public boolean isAccountNonExpired() {
		// TODO Auto-generated method stub

		return true;

	@Override
```

## 4. Logout

```java
로그아웃은 크게 2가지 종류
1) 단순 로그아웃 (다시 로그인하면 남아있어 자동 로그인 됨)
2) 카카오계정과 함께 로그아웃

단순 로그아웃은 토큰을 만료 시키지만, 사용자 정보가 웹브라우저에 남아 있어서
다시 로그인 할 때 ID, PW를 입력 없이 바로 로그인 됨

로그아웃시, 카카오계정과 함계 로그아웃해야 함
```

```java
security는 sercurityContext를 추가하는 형태였다
=> 근데 sociallogin이 늘어났다
- 실제로 로그인서비스를 요청하는 건 카카오
- 쿠키를 발급하더라도 서버에 저장하지 못함
- 세션에다가 저장하지 못한다
```
