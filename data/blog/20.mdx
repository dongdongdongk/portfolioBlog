# { 🎧 플랫폼 성능에 맞춘 사운드 디자인 }

사운드 디자인 완료 단계에서는 실제 **플랫폼 성능에 맞게 최적화**해야 합니다.

이 단원에서는 **연산 부하(Spike)** 를 관리하고, **중요한 사운드를 유지**하는 방법을 배웁니다.

---

## 🎯 학습 내용 요약

- **게임 프로파일링**: 사운드의 CPU·메모리 사용량 분석
- **Capture Log 필터링**: 핵심 성능 데이터만 확인
- **볼륨 스레숄드 설정**: 너무 작은 소리 재생 방지
- **최대 보이스 수 제한**: 플랫폼별 동시 재생 수 조정
- **인스턴스 제한**: 같은 사운드의 중복 재생 방지
- **우선순위 지정**: 중요한 사운드가 먼저 재생되도록 설정

---

🎮 **결과:** 성능은 안정적으로, 사운드는 더 선명하게!

## 1. 🎮 게임 오디오 처리 개념 이해하기

- **게임 오디오도 CPU 자원을 사용한다.**
  - 사운드는 그래픽보다는 적은 처리 능력을 요구하지만,
    게임 전체에서는 그래픽, 물리 연산, 인공지능 등 여러 시스템과 CPU 자원을 공유합니다.
- **따라서 오디오 성능을 관리해야 하는 이유**
  - 사운드가 많아질수록 CPU 부하가 커지고,
    게임 프레임이 떨어지거나 소리 재생이 지연될 수 있습니다.
  - 이를 방지하기 위해 Wwise에서는 “Profiler”를 통해 실시간 분석이 가능합니다.

---

## 2. 🔊 보이스(Voice) 개념과 역할

- **Voice란?**
  - 게임 내에서 **사운드를 재생하기 위한 메커니즘(엔진 내부의 단위)**.
  - 즉, **하나의 소리가 재생될 때마다 하나의 보이스가 활성화**됩니다.
  - BGM, 효과음, 대사 등 각각의 사운드 재생 시 고유한 보이스를 사용합니다.
- **중요 포인트**
  - 여기서 말하는 **“Sound Voice 오브젝트”**와는 다릅니다.
    - Sound Voice 오브젝트: Wwise 프로젝트 내의 오디오 리소스 단위.
    - 보이스(Voice): 실제 재생 시 메모리와 CPU에서 사용되는 실행 단위.
- **보이스가 많아질수록 → CPU 부하 증가**
  - 예: Cube 게임의 “독 보석(Poison Gem)”을 빠르게 던지면
    발사음이 겹쳐 재생되며 동시에 여러 개의 보이스가 활성화됩니다.
  - 이처럼 **겹치는 사운드**는 **보이스 수를 폭발적으로 증가**시킵니다.

## 3. 🧩 Cube 게임과 Wwise 연결하기

1. **Cube 실행하기**
   - 먼저 Cube 게임을 실행해 Wwise와 연결할 준비를 합니다.
2. **Wwise에서 프로젝트 열기**
   - “Module 20” 프로젝트 파일을 엽니다.
3. **Profiler 레이아웃 열기**
   - 메뉴 바에서
     ```
     Layouts > Profiler (단축키: F6)
     ```
   - Profiler 레이아웃은 오디오 실시간 성능 데이터를 시각화해주는 Wwise의 주요 분석 도구입니다.

## 4. ⏺️ 프로파일링(Capture) 시작하기

1. **Start Capture 버튼 클릭**
   - Wwise 툴바에서
     ```
     Start Capture (Windows: Alt + C / macOS: Option + C)
     ```
   - 클릭 시 **Capture Log**에 데이터가 쌓이기 시작합니다.
   - 하단의 **Performance Monitor 그래프**에 노란색 커서가 움직이면서
     실시간 CPU 사용률 및 보이스 수 등을 기록합니다.
2. **Cube에서 테스트 수행**
   - Cube로 돌아가 다음을 수행합니다:
     1. 시작 위치에서 **왼쪽으로 회전**
     2. \*초록색 독 보석(Poison Gem)**을 **수집\*\*
     3. **숫자키 3번**을 눌러 독 보석을 **지팡이에 장착**
     4. **마우스 클릭을 길게 눌러** 독 보석을 **최대한 빠르게 발사**
     5. **남은 보석이 0개가 될 때까지 반복**
3. **Stop Capture 클릭**
   - 다시 Wwise로 돌아와
     ```
     Stop Capture (Alt + C / Option + C)
     ```
   - 데이터 캡처를 중단합니다.
   - 이제 Capture Log에 Cube 플레이 중 발생한 모든 **Event**와 **Action**이 기록되어 있습니다.

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380557/notion-blog/_/WWISE/Wwise_/20_/image_1.png)

## 5. 🔍 사운드 이벤트 필터링하기

- **Capture Log에는 수많은 이벤트가 표시**됩니다.
  - 예: BGM 재생, 환경음, 효과음, 대사 등
  - 하지만 이번 실습의 초점은 “독 보석 사운드”입니다.
- **필터 적용하기**
  1. Capture Log 상단의 **텍스트 필터 입력창**에

     ```
     poisongem
     ```

     입력합니다.

  2. 이름에 poisongem이 포함되지 않은 오브젝트들은 모두 숨겨집니다.

- 이렇게 하면 **Poison Gem 관련 이벤트만 남아**,
  실제 사운드가 트리거된 시점과 횟수를 쉽게 확인할 수 있습니다.

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380557/notion-blog/_/WWISE/Wwise_/20_/image_2.png)

## 6. 📊 퍼포먼스 모니터 그래프 분석하기

- **Performance Monitor 영역**에서는 여러 그래프를 동시에 확인할 수 있습니다:
  | 그래프 이름 | 설명 |
  | ------------------------------- | ---------------------------------------------------------------------------------------------------- |
  | **CPU Usage** | 오디오 관련 연산이 CPU를 얼마나 사용하는지 보여줍니다. 사운드 재생이 집중될수록 사용량이 급증합니다. |
  | **Number of Voices (Physical)** | 실제 재생 중인 보이스의 개수. 이 값이 높을수록 더 많은 사운드가 동시에 재생 중이라는 의미입니다. |
  | **Number of Voices (Virtual)** | 재생은 중단되었지만, 논리적으로는 유지 중인 사운드(메모리에 남아 있는 상태). |
- **View Settings (오른쪽 상단 톱니바퀴 버튼)**
  - 클릭하면 표시할 그래프 항목을 추가하거나 숨길 수 있습니다.
  - 예: Memory Usage, Streaming Bandwidth 등 추가 가능.

## 1. 사운드 처리 성능의 개념 이해하기

- 게임에서 **모든 사운드는 보이스(Voice)** 로 재생됩니다.
  - 보이스는 사운드를 실제로 재생하기 위한 하드웨어 리소스 단위입니다.
  - CPU는 각 보이스를 실시간으로 처리하며, 보이스가 많을수록 부하가 증가합니다.
- 하지만 **모든 사운드가 플레이어에게 중요한 것은 아닙니다.**
  예를 들어,
  - 100m 떨어진 몬스터의 조용한 발소리와
  - 2m 앞에서 터지는 마법 이펙트 소리
    → 둘 다 동일한 연산 리소스를 소모하지만, 플레이어는 멀리 있는 소리를 거의 인지하지 못합니다.

🎯 **핵심 아이디어**

→ 플레이어가 듣지 못하는, 혹은 중요하지 않은 사운드는 보이스로 렌더링하지 않도록 제한함으로써 CPU 부하를 줄인다.

### 🔹 Volume Threshold (볼륨 임계값)

- **기본값:** `80 dB`
  - 80dB보다 큰(더 큰 음량을 가진) 사운드만 실제 보이스로 처리됩니다.
  - 즉, **이보다 작은 음량의 사운드는 무시됨**.
- **설정값 변경:** `50 dB`
  - 50dB로 높이면, 볼륨이 작은(거의 안 들리는) 사운드는 보이스로 변환되지 않습니다.
  - 그만큼 처리 성능을 절약할 수 있습니다.
  - 단, 너무 높이면 **섬세한 앰비언스(ambient sound)** 나 **배경 소리**가 끊길 수 있습니다.

---

### 🔹 Max Voice Instances (최대 보이스 개수)

- **기능:** 동시에 재생할 수 있는 전체 보이스의 최대 개수를 제한.
- **설정값:** `40`
  - 이 수를 줄이면 CPU 부하를 크게 줄일 수 있습니다.
  - 하지만, 전투 중 등 사운드가 많은 순간에는 **일부 사운드가 재생되지 않거나 중단될 수도 있음.**

## 3. 가상 보이스(Virtual Voice)의 개념 이해하기

- **가상 보이스(Virtual Voice)** : 실제로 재생되지 않지만, 엔진이 내부적으로 추적하는 “비활성화된” 보이스입니다.
- 소리가 너무 작거나, 보이스 제한 수를 초과하면 가상 보이스로 전환됩니다.
- 이후 다음 조건에서 **물리적(Physical) 보이스** 로 다시 활성화됩니다.
  - 해당 사운드의 볼륨이 커짐
  - 전체 보이스 수가 감소함

> 즉, 보이스는 게임 상황에 따라 가상 ↔ 물리 상태를 오가며 동적으로 관리됩니다.

## 4. 보이스 개수 제한(Limit Sound Instances) 설정하기

### 🎯 목표

특정 사운드(예: 독 보석 Magic Sound)가 동시에 너무 많이 재생되지 않도록 제한.

---

### 🔹 단계

1. `메뉴 바 → Layouts → Designer (F5)` 클릭
2. `Project Explorer`에서

   `Actor-Mixer Hierarchy → Default Work Unit → Magic`

   → `PoisonGem Magic` 선택

3. `Property Editor`에서 **Advanced 탭** 선택

---

### 🔹 Limit Sound Instances 설정

- **Limit Sound Instances** 체크
- **Sound Instance Limit:** `4`
- **Limitation Scope:** `Globally`

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380558/notion-blog/_/WWISE/Wwise_/20_/image_7.png)

---

### 🔹 설정 의미

| 항목                                | 설명                                                   |
| ----------------------------------- | ------------------------------------------------------ |
| **Sound Instance Limit (4)**        | 동일한 사운드가 동시에 최대 4개까지만 재생됨           |
| **Limitation Scope: Globally**      | 전역 제한. (모든 독 보석 사운드를 합쳐 4개까지만 허용) |
| **Local(각 오브젝트별)** 로 설정 시 | 각 독 보석이 최대 4개의 보이스를 개별로 가질 수 있음   |

💡 **디자인 의도:**

플레이어는 동시에 4개 이상의 독 보석 소리를 구분하기 어렵기 때문에, 전역(Global)으로 4개만 들리도록 제한.

## 5. 사운드 우선순위(Priority) 부여하기

보이스 수가 한계에 도달하면, 사운드 엔진은 일부 보이스를 “Kill(중단)”해야 합니다.

이때 **Priority** 값이 높은 사운드는 중단되지 않도록 설정할 수 있습니다.

---

### 🔹 단계

1. `Project Explorer`에서 `Magic` 폴더 접기
2. `Cube_Main_Theme` 오브젝트 선택
3. `Property Editor → Advanced 탭`에서
   - **Priority:** `80` 설정

---

### 🔹 설정 의미

- 음악이나 플레이어 대사처럼 **항상 재생되어야 하는 사운드**의 우선순위를 높여줌.
- 우선순위가 높을수록, 보이스 수 초과 시에도 해당 사운드는 유지됩니다.

---

### [Tip] Offset Priority

- **Use Offset Priority** 옵션을 체크하면, 사운드가 리스너로부터 멀어질수록 우선순위가 자동으로 낮아집니다.
- 이 기능은 **발소리, 바람소리** 등 거리 기반으로 중요도가 달라지는 오브젝트에 유용합니다.
- 관련 설정은 **Attenuation Editor**(8단원: 3D 공간화)에서 다룸.

### 🎵 **Playback Limit & Priority 정리 ( 최신 버전)**

### 📘 **개요**

게임에서는 특정 시점에 **프로젝트 팀이 설정한 재생 제한 개수보다 많은 오브젝트가 동시에 재생될 수 있습니다.**

이때, 어떤 오브젝트를 재생하고 어떤 것을 멈출지 효율적으로 관리하기 위해

**Wwise는 세 가지 주요 속성**을 제공합니다.

---

### ⚙️ **Wwise의 세 가지 관리 속성**

| 속성                  | 설명                                                                                |
| --------------------- | ----------------------------------------------------------------------------------- |
| **Playback Limit**    | 동시에 재생할 수 있는 인스턴스(보이스)의 최대 개수를 제한합니다. (가상 보이스 제외) |
| **Playback Priority** | 다른 오브젝트에 비해 이 오브젝트가 얼마나 중요한지를 나타냅니다. (우선순위 결정)    |
| **Volume Threshold**  | 오브젝트의 볼륨이 특정 수준 이하일 경우 재생하지 않도록 설정합니다.                 |

➡️ 이 세 가지 설정을 통해

게임 내 오디오 자원을 **효율적으로 관리**하면서 **메모리 사용 한도를 초과하지 않도록** 조정할 수 있습니다.

---

### 🎼 **Playback Limit & Priority 예시**

**상황:**

매우 제한된 대역폭을 가진 게임에서 음악을 작곡한다고 가정합니다.

이 게임은 **동시에 최대 5개의 보이스**만 재생할 수 있습니다.

1. **Playback Limit 설정**
   - 상위 계층 오브젝트의 **Playback Limit을 4로 설정**합니다.
   - 각 **Music Segment**에는 두 개의 트랙만 넣습니다.
   - 이렇게 하면 두 세그먼트가 동시에 재생될 때도
     → 총 4개의 보이스만 사용하여 제한 수를 넘지 않습니다.
2. **문제 상황**
   - 전환 효과 도중 **Stinger(짧은 악센트 음악)**가 재생되면
     → 보이스 수가 **최대 4개를 초과**하게 됩니다.
3. **Wwise의 처리 방식**
   - 재생 제한을 초과할 경우,
     **Wwise는 각 오브젝트의 Playback Priority를 기준으로**
     어떤 오브젝트를 중지할지 결정합니다.
4. **해결 방법**
   - **Stinger의 우선순위를 낮게 설정**하여
     중요한 **‘일반 음악’이 끊기지 않도록** 보장할 수 있습니다.
   - 모든 오브젝트의 우선순위가 동일할 경우,
     **가장 오래되었거나 가장 최근에 생성된 인스턴스**부터 제거되도록 설정할 수 있습니다.

---

| 항목                  | 요약                                                                   |
| --------------------- | ---------------------------------------------------------------------- |
| **Playback Limit**    | 동시 재생 수 제한 (보이스 관리)                                        |
| **Playback Priority** | 어떤 사운드를 우선적으로 유지할지 결정                                 |
| **Volume Threshold**  | 너무 작은 소리는 아예 재생하지 않도록 설정                             |
| **활용 예시**         | Stinger의 우선순위를 낮춰 일반 음악이 끊기지 않게 조정                 |
| **결과**              | 메모리와 보이스 수를 효율적으로 관리하면서도 자연스러운 음악 전환 구현 |

---

이처럼 **Playback Limit**, **Playback Priority**, **Volume Threshold**는

게임 오디오의 품질을 유지하면서도 **시스템 자원을 효율적으로 관리하는 핵심 도구**입니다.

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380559/notion-blog/_/WWISE/Wwise_/20_/image_8.png)

## 1️⃣ **Playback Limit**

> 동시에 재생 가능한 인스턴스를 제한하고, 초과 시 처리 방식을 정의하는 영역입니다.

| 옵션                  | 설명                                                                                                                                                        |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Ignore Parent**     | 상위 오브젝트(Parent)의 Playback Limit 설정을 무시하고, 현재 오브젝트의 설정만 사용합니다.                                                                  |
| **Enable**            | Playback Limit 기능을 켤지 여부. 체크하면 제한이 적용됩니다.                                                                                                |
| **Limit**             | 동시 재생 가능한 최대 인스턴스 수. 예: `20` → 동시에 최대 20개만 재생.                                                                                      |
| **Scope**             | 제한 적용 범위 선택: - `Global`: 모든 오브젝트 합쳐서 제한 적용 - `Local`: 오브젝트 개별로 제한 적용                                                        |
| **If Limit Reached**  | 제한 초과 시 행동 지정: - `Kill voice`: 기존 보이스를 종료 - `Virtualize voice`: 일부 보이스를 가상화(일시 중단)                                            |
| **If Priority Equal** | 동일한 우선순위(Priority)를 가진 보이스가 제한 초과 시 처리 방식: - `Discard oldest`: 가장 오래된 인스턴스 종료 - `Discard newest`: 가장 최근 인스턴스 종료 |

---

## 2️⃣ **Virtual Voice**

> 실제 재생은 하지 않지만, 조건 충족 시 재생될 보이스의 동작을 정의합니다.

| 옵션                            | 설명                                                                                                                                                                             |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Override Parent**             | 상위 오브젝트의 Virtual Voice 설정을 무시하고, 현재 오브젝트 설정 사용                                                                                                           |
| **Behavior**                    | 가상 보이스 처리 방식 선택: - `Kill if finite else virtual`: 재생 횟수가 정해진 보이스는 종료, 아니면 가상화 - 다른 옵션도 있지만, 일반적으로 CPU 부하를 줄이기 위해 가상화 활용 |
| **On Return to Physical Voice** | 가상 보이스가 다시 물리적 보이스(Physical Voice)로 전환될 때 행동: - `Play from elapsed time`: 중단된 시점부터 이어서 재생 - `Play from start`: 처음부터 재생                    |

---

## 3️⃣ **Playback Priority**

> 보이스가 제한 상황에서 어떤 오브젝트가 우선 재생될지 결정합니다.

| 옵션                       | 설명                                                                                                              |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **Override Parent**        | 상위 오브젝트의 Priority를 무시하고 현재 오브젝트 설정 사용                                                       |
| **Priority**               | 우선순위 수치. 높을수록 보이스 유지 우선권이 높음. 예: `80`                                                       |
| **Use Offset Priority**    | Max Distance 도달 시 우선순위를 자동 조정할지 여부. 체크하면 거리감에 따라 Priority가 감소/증가                   |
| **Offset at Max Distance** | Use Offset Priority 활성화 시, 최대 거리에서 적용할 우선순위 오프셋 값. 예: `-10` → 멀어지면 Priority가 10 낮아짐 |

---

### 💡 **정리**

1. **Playback Limit** → 동시에 몇 개까지 재생 가능한지, 초과 시 어떤 보이스를 종료할지 설정
2. **Virtual Voice** → CPU를 절약하기 위해 일부 보이스를 잠시 가상화하고 필요 시 복구
3. **Playback Priority** → 제한 상황에서 중요한 오디오를 우선 재생
