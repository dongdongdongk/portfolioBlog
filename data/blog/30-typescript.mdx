# { 무엇을 & 왜 }

```jsx
타입스크립트는 자바스크립트의 “슈퍼셋” 언어로, 자바스크립트를 기반으로 하지만 추가적인 기능을 제공합니다.

주요 기능 중 하나는 정적 타입을 지원하는 것입니다.

이로 인해 코드를 작성하는 데 더 많은 안전성과 유연성을 제공하죠.

아래에서 타입스크립트의 주요 특징과 사용 이유를 간단히 정리하겠습니다.
```

## 1. **타입스크립트란?**

```jsx
정의:

	타입스크립트는 자바스크립트의 슈퍼셋으로, 자바스크립트에 몇 가지 기능을 추가한 언어입니다.

기본 문법:

	자바스크립트의 문법을 그대로 사용하며, if 문, for 반복문, 객체 사용법 등을 그대로 쓸 수 있습니다.

확장된 기능:

	자바스크립트에 정적 타입 기능을 추가하여 더 안전한 코드를 작성할 수 있게 합니다
```

## 2. **정적 타입과 동적 타입의 차이**

```jsx
동적 타입:

자바스크립트는 동적 타입 언어로, 변수의 타입을 실행 중에 결정합니다. 이로 인해 런타임에서 타입 관련 오류가 발생할 수 있습니다.

	예: 두 숫자를 더하는 함수가 문자열을 받아도 실행될 수 있으며, 이는 의도하지 않은 결과를 초래할 수 있습니다.

정적 타입:

타입스크립트는 정적 타입 언어로, 변수를 선언할 때 타입을 명시합니다. 이를 통해 코드 작성 시점에서 타입 관련 오류를 사전에 발견할 수 있습니다.

	예: 함수에 숫자 타입만 허용하면 문자열을 전달할 때 컴파일러가 오류를 표시합니다.
```

## 3. **타입스크립트를 사용하는 이유**

```jsx
오류 방지:

	타입스크립트는 코드 작성 시점에서 타입 오류를 발견할 수 있어, 런타임 오류를 줄입니다.

코드 명확성:

	변수와 함수의 타입을 명확히 정의함으로써 코드의 의도를 명확히 할 수 있습니다.

협업 개선:

	대규모 프로젝트에서 여러 개발자가 작업할 때, 타입 정의가 있어야 코드의 사용 방법을 쉽게 이해할 수 있습니다.

IDE 지원:

	타입스크립트는 많은 IDE와 편집기에서 강력한 코드 분석 및 자동 완성 기능을 지원합니다.
```

## 5. **타입스크립트의 코드 예시**

```jsx
자바스크립트 코드:

function add(a, b) {
  return a + b;
}

* 이 코드는 문자열과 숫자 모두 처리할 수 있으며, 의도하지 않은 결과를 초래할 수 있습니다.

타입스크립트 코드:

function add(a: number, b: number): number {
  return a + b;
}

* 이 코드는 매개변수와 반환값의 타입을 명확히 정의하여, 문자열이나 다른 타입을 전달하면 컴파일 오류를 발생시킵니다.
```

## 2. 타입스크립트 컴파일러 사용하기

```jsx
타입스크립트는 브라우저에서 직접 실행되지 않기 때문에, 타입스크립트 코드를 자바스크립트로 컴파일해야 합니다.
```

```jsx

		컴파일러의 설정을 위해 tsconfig.json 파일을 생성합니다.

		이 파일은 프로젝트의 루트 폴더에 위치해야 하며, tsc --init 명령어로 생성할 수 있습니다.

			npx tsc --init


	타입스크립트 파일 작성

		example.ts 파일을 생성하고 아래와 같은 예제 코드를 작성합니다.

		// example.ts
		function add(a: number, b: number): number {
		    return a + b;
		}

		const result = add(5, 7);
		console.log(result); // 12


	타입스크립트 컴파일

		npx tsc 명령어를 사용하여 타입스크립트 파일을 컴파일합니다. 기본적으로 tsconfig.json 파일의 설정에 따라 컴파일됩니다.

			npx tsc

		컴파일 후 example.js 파일이 생성됩니다.


	파일 직접 컴파일

		특정 파일만 컴파일하려면 파일명을 직접 지정합니다.

			npx tsc example.ts

		이렇게 하면 example.js 파일이 생성됩니다.
```

## 5. 타입스크립트와 자바스크립트의 차이

```jsx
타입스크립트는 자바스크립트의 슈퍼셋으로, 자바스크립트에 타입 표기와 클래스 기반의 객체 지향 프로그래밍 기능을 추가합니다.

자바스크립트 코드는 타입스크립트에서 유효하지만, 타입스크립트 코드에 있는 타입 표기는 자바스크립트에서 직접 사용될 수 없습니다.

타입스크립트는 코드 작성 시 타입 검사를 통해 버그를 줄일 수 있으며, 자바스크립트로 컴파일 후 실행될 수 있습니다.
```

## 1. 기본형 타입(Primitives)

```jsx
타입스크립트는 자바스크립트의 기본형 자료형을 지원합니다. 이 자료형은 다음과 같습니다:

	number: 숫자형

	string: 문자열

	boolean: 논리형

	null

	undefined
```

```jsx
// 숫자형 예제
let age: number;
age = 30;  // 올바른 할당

// age = "30";  // 오류 발생: 문자열을 숫자형에 할당할 수 없음

// 문자열 예제
let userName: string;
userName = "John Doe";  // 올바른 할당
// userName = 123;  // 오류 발생: 숫자를 문자열에 할당할 수 없음

// 논리형 예제
let isInstructor: boolean;
isInstructor = true;  // 올바른 할당
isInstructor = false;  // 올바른 할당
// isInstructor = "true";  // 오류 발생: 문자열을 논리형에 할당할 수 없음
```

## 배열 타입 지정하기

```jsx
배열 타입을 지정하는 것은 TypeScript에서 특정 타입의 요소들을 포함하는 배열을 선언하는 방법입니다.

문자열 배열을 예로 들어 설명해 보겠습니다.
```

### 예제: 문자열 배열

```jsx
let hobbies: string[];
hobbies = ['Reading', 'Gaming', 'Traveling']; // 올바른 할당
hobbies.push('Cooking'); // 올바른 추가

// hobbies = 'Reading'; // 오류 발생: 문자열 배열이 아닌 단일 문자열 할당
// hobbies.push(42); // 오류 발생: 숫자는 문자열 배열에 추가할 수 없음
```

```jsx
위의 코드에서 hobbies 변수는 문자열 배열로 선언되었기 때문에, 문자열만을 포함해야 하며,

숫자나 다른 타입의 값이 포함되면 오류가 발생합니다.
```

### 예제: 숫자 배열

```jsx
let numbers: number[];
numbers = [1, 2, 3, 4, 5]; // 올바른 할당

// numbers.push('Six'); // 오류 발생: 문자열은 숫자 배열에 추가할 수 없음
```

### 예제: 부울 배열

```jsx
let flags: boolean[];
flags = [true, false, true]; // 올바른 할당

// flags.push(1); // 오류 발생: 숫자는 부울 배열에 추가할 수 없음
```

## 타입 추론 (Type Inference)

```jsx
타입스크립트(TypeScript)에서 타입 추론이란,

변수의 타입을 명시적으로 지정하지 않아도 타입스크립트가 자동으로 변수의 타입을 추론하는 기능을 말합니다.

이는 코드의 간결성을 높여주고, 개발자가 타입을 일일이 지정하지 않아도 되는 장점을 제공합니다.
```

### 예제: 타입 추론의 기본 개념

```jsx
변수 선언과 동시에 값을 할당하면, 타입스크립트가 할당된 값의 타입을 기준으로 변수의 타입을 추론합니다.
```

```jsx
let course = 'React 완벽 가이드' // course는 자동으로 string 타입으로 추론됩니다

// course = 12345; // 오류 발생: string 타입 변수에 숫자를 할당할 수 없음
```

### 타입 추론이 이루어지는 과정

```jsx
1. 변수 선언 및 초기화

let course = 'React 완벽 가이드';

이 코드에서 course 변수는 선언되었고, 문자열 값이 할당되었습니다. 타입스크립트는 course 변수의 타입을 string으로 추론합니다.

2. 타입 추론 후 타입 검증

course = 12345; // 오류 발생

타입스크립트는 course 변수를 string 타입으로 추론했기 때문에, 숫자 값을 할당하려고 하면 오류가 발생합니다.
```

### 명시적 타입 지정 vs 타입 추론

```jsx
명시적으로 타입을 지정하는 것도 가능하지만, 타입 추론을 사용하면 코드가 더 간결해집니다.

// 명시적 타입 지정
let course: string = 'React 완벽 가이드';

// 타입 추론
let course = 'React 완벽 가이드';
```

### 권장사항

```jsx
타입스크립트는 타입 추론을 매우 잘 수행하므로,

불필요하게 타입을 명시적으로 지정하는 것을 피하는 것이 좋습니다.

타입 추론을 최대한 활용하는 것이 권장되는 코딩 방식입니다.
```

## 타입스크립트에서 타입 추론을 사용하는 것과 자바스크립트와의 차이점

```jsx
타입 추론을 사용한다고 해서 타입스크립트의 모든 기능을 포기하는 것은 아닙니다.

타입스크립트는 타입 추론과 함께 명시적 타입 지정, 인터페이스, 고급 타입 시스템,

컴파일 타임 타입 검사 등의 기능을 제공하여 자바스크립트보다 더 안전하고 유지 보수하기 쉬운 코드를 작성할 수 있게 해줍니다.

따라서, 타입스크립트는 자바스크립트보다 강력한 정적 타입 검사와 개발자 도구 지원을 제공하며, 이는 큰 차별점이 됩니다.
```

# { 유니온 유형 사용하기 }

## 유니온 타입 (Union Types)

```jsx
타입스크립트에서 유니온 타입은 한 변수에 여러 종류의 타입을 저장할 수 있게 하는 기능입니다.

이는 변수에 하나의 타입만 저장할 수 있는 경우보다 더 유연한 코드를 작성할 수 있게 해줍니다.
```

### 예제: 유니온 타입 기본 개념

```jsx
유니온 타입을 사용하면 변수에 여러 가지 타입을 허용할 수 있습니다.

이는 파이프 문자(|)를 사용하여 여러 타입을 지정하는 방식으로 이루어집니다
```

```jsx
let course: string | number;
course = 'React 완벽 가이드'; // 문자열 할당, 올바른 사용
course = 12345; // 숫자 할당, 올바른 사용

// course = true; // 오류 발생: 부울 값은 허용되지 않음
```

### 유니온 타입의 사용 사례

```jsx
유니온 타입을 사용하면, 예를 들어 강좌의 이름(문자열)과 강좌 ID(숫자)를 같은 변수에 저장할 수 있습니다.
```

```jsx
1. 변수에 여러 타입 저장

	let course: string | number;
	course = 'React 완벽 가이드'; // 문자열 저장
	course = 12345; // 숫자 저장


2. 타입 추론과 유니온 타입

	타입 추론을 사용할 경우 유니온 타입을 명시적으로 지정하지 않아도 됩니다.

	하지만 타입 추론을 사용하지 않거나 여러 타입을 허용해야 하는 경우 유니온 타입을 지정하는 것이 필요합니다.

	let course: string | number = 'React 완벽 가이드';
	course = 12345; // 오류 없음, 숫자도 허용됨



3. 다양한 타입의 객체 저장

	유니온 타입을 사용하면 서로 다른 형태의 객체를 동일한 변수에 저장할 수 있습니다.


	let user: { name: string } | { age: number };

	user = { name: 'Alice' }; // 올바른 사용
	user = { age: 30 }; // 올바른 사용

	// user = { isStudent: true }; // 오류 발생: 정의된 타입과 맞지 않음



4. 유니온 타입과 배열

	유니온 타입은 배열에도 사용할 수 있습니다. 예를 들어, 사용자 이름을 문자열 또는 문자열 배열로 저장할 수 있습니다.

	let userName: string | string[];

	userName = 'John Doe'; // 문자열 저장
	userName = ['John', 'Doe']; // 문자열 배열 저장
```

## 유니온 타입의 장점

```jsx
유연성: 한 변수에 여러 타입을 저장할 수 있어, 다양한 상황에 대처할 수 있습니다.

타입 안전성: 타입스크립트는 유니온 타입을 사용하여 타입 검사를 수행하므로, 잘못된 타입의 값이 할당되는 것을 방지할 수 있습니다.

코드 가독성: 변수에 허용되는 타입을 명시적으로 지정함으로써, 코드의 가독성이 높아지고 유지 보수가 쉬워집니다.
```

# { Type Aliases의 이해 }

## 타입 별칭 (Type Alias)

```jsx
타입스크립트에서 타입 별칭(Type Alias)은 복잡한 타입을 정의하고,

이를 여러 곳에서 재사용할 수 있게 하는 기능입니다. 이를 통해 코드 중복을 줄이고, 코드의 가독성과 유지 보수성을 높일 수 있습니다.
```

### 예제: 타입 별칭 기본 개념

```jsx
타입 별칭을 사용하면, 동일한 타입 정의를 여러 번 반복할 필요 없이,

한 번 정의한 타입을 여러 곳에서 재사용할 수 있습니다.
```

```jsx
// 타입 별칭 정의
type Person = {
  name: string;
  age: number;
};

// 타입 별칭 사용
let person1: Person = {
  name: 'Alice',
  age: 30
};

let person2: Person = {
  name: 'Bob',
  age: 25
};
```

## 타입 별칭의 정의와 사용

### 타입 별칭 정의

```jsx
타입 별칭은 type 키워드를 사용하여 정의합니다.

	type Person = {
	  name: string;
	  age: number;
	};
```

### 타입 별칭 사용

```jsx
타입 별칭을 정의한 후, 해당 타입을 변수나 함수 매개변수 등의 타입으로 사용할 수 있습니다

	let person: Person = {
	  name: 'Alice',
	  age: 30
	};
```

### 타입 별칭을 사용한 배열 정의

```jsx
타입 별칭을 사용하여 동일한 타입을 갖는 객체 배열을 정의할 수 있습니다.

	let people: Person[] = [
	  { name: 'Alice', age: 30 },
	  { name: 'Bob', age: 25 }
	];
```

## 타입 별칭의 장점

```jsx
코드 중복 제거: 동일한 타입 정의를 여러 번 반복할 필요가 없습니다.

가독성 향상: 코드가 간결해지고, 타입이 명확하게 정의되므로 가독성이 높아집니다.

유지 보수성 개선: 타입 정의를 한 곳에서 관리할 수 있어, 타입이 변경되더라도 여러 곳에서 쉽게 업데이트할 수 있습니다.
```

# { 함수 및 함수 유형 }

## 함수에 타입 지정하기

```jsx
타입스크립트에서는 함수의 매개변수와 반환 값에 타입을 지정할 수 있습니다.

이를 통해 함수의 입력과 출력이 어떤 타입이어야 하는지 명확하게 정의할 수 있습니다.
```

### 1.1 매개변수에 타입 지정하기

```jsx
function add(a: number, b: number): number {
  return a + b;
}
```

```jsx
위의 add 함수는 두 개의 숫자 매개변수 a와 b를 받고, 그 합을 반환합니다.

a와 b의 타입을 number로 지정했기 때문에, 이 함수는 오직 숫자만 인수로 받을 수 있습니다.
```

```jsx
const sum = add(2, 3) // 정상 실행, sum의 타입은 number

const result = add('2', 3) // 오류 발생, '2'는 string 타입이므로
```

### 1.2 반환 타입 지정하기

```jsx
함수의 반환 값에 타입을 지정하는 것도 중요합니다. 위의 add 함수에서는 반환 타입을 number로 지정했습니다.
```

```jsx
function add(a: number, b: number): number {
  return a + b;
}
```

```jsx
타입스크립트는 반환 값을 자동으로 추론할 수 있습니다.

따라서 반환 타입을 명시적으로 지정하지 않아도 됩니다. 하지만, 반환 타입을 명확히 하고 싶을 때는 위와 같이 지정할 수 있습니다.
```

### 1.3 타입 추론

```jsx
타입스크립트는 함수의 반환 값에 따라 자동으로 반환 타입을 추론합니다.

예를 들어, add 함수에서 반환 값이 a + b이므로, 타입스크립트는 이 값이 number 타입임을 추론합니다.
```

```jsx
function add(a: number, b: number) {
  return a + b;
}

const sum = add(5, 10);  // sum은 자동으로 number 타입으로 추론됨
```

```jsx
함수가 아무런 값을 반환하지 않을 때는 void 타입을 사용합니다.

void는 함수가 값을 반환하지 않음을 나타내며, 이는 자바스크립트의 undefined나 null과는 다른 개념입니다.
```

### 2.1 void 타입 사용 예제

```jsx
function printOutput(value: any): void {
  console.log(value);
}
```

```jsx
위의 printOutput 함수는 value를 받아 콘솔에 출력하지만,

반환 값은 없습니다. 따라서 반환 타입을 void로 지정했습니다.

void 타입은 함수에만 사용되며, 반환 값이 없는 함수임을 명시적으로 나타냅니다.
```

# { 제네릭으로 뛰어들다 }

## 제네릭(Generic) 타입 이해하기

```jsx
타입스크립트에서 제네릭(Generic) 타입은 함수, 클래스, 인터페이스를 여러 타입에서 재사용할 수 있도록 해주는 기능입니다.

제네릭은 타입 안정성을 유지하면서도 코드의 유연성을 극대화할 수 있도록 도와줍니다.
```

```jsx
제네릭(Generics): 여러 타입에 대해 재사용 가능한 코드를 작성할 수 있게 해주는 타입스크립트 기능입니다.

배열과 제네릭: number[]는 실제로 Array<number>로 표현됩니다. Array는 제네릭 타입으로, 배열 요소의 타입을 지정합니다.

제네릭 함수: 함수에서 제네릭을 사용해 특정 타입에 의존하지 않는 코드를 작성할 수 있습니다.
```

## 1. 제네릭 함수 만들기

```jsx
제네릭 타입을 사용하지 않고 간단한 함수를 만들어 보겠습니다.

이 함수는 배열의 맨 앞에 새로운 값을 추가하고, 새로운 배열을 반환하는 역할을 합니다.
```

```jsx
function insertAtBeginning(array: any[], value: any): any[] {
    const newArray = [value, ...array];
    return newArray;
}

const demoArray = [1, 2, 3];
const updatedArray = insertAtBeginning(demoArray, -1);

console.log(updatedArray); // [-1, 1, 2, 3]
```

```jsx
위 함수는 insertAtBeginning이라는 이름으로, 배열과 값을 인수로 받아 새로운 배열을 반환합니다.

그러나 이 함수의 문제는 배열의 타입을 any로 지정했기 때문에, 반환되는 updatedArray의 타입도 any로 추론된다는 점입니다.

이렇게 되면 타입스크립트는 이 배열이 숫자 배열인지, 문자열 배열인지, 혹은 다른 타입의 배열인지 알 수 없게 됩니다.
```

### 2. 제네릭 함수로 변환하기

```jsx
function insertAtBeginning<T>(array: T[], value: T): T[] {
    const newArray = [value, ...array];
    return newArray;
}

const demoArray = [1, 2, 3];
const updatedArray = insertAtBeginning(demoArray, -1);

console.log(updatedArray); // [-1, 1, 2, 3]
```

```jsx
위 코드에서 T는 제네릭 타입으로, 함수가 호출될 때 실제 타입으로 대체됩니다.

이 경우, insertAtBeginning 함수는 T[] 타입의 배열과 T 타입의 값을 받습니다.

이렇게 하면 함수가 어떤 타입의 배열과 값을 받아도, 반환되는 배열의 타입이 자동으로 일치하게 됩니다.
```

```jsx
const stringArray = ['a', 'b', 'c']
const updatedStringArray = insertAtBeginning(stringArray, 'z')

console.log(updatedStringArray) // ['z', 'a', 'b', 'c']
```

```jsx
위 예제에서 insertAtBeginning 함수는 문자열 배열(string[])을 받아서 새로운 문자열 배열을 반환합니다.

 타입스크립트는 제네릭을 사용하여 이 배열이 문자열 배열임을 추론하고, 반환 타입도 자동으로 string[]으로 설정합니다.
```

### 3. 제네릭의 유용성

```jsx
제네릭을 사용하면, 함수의 타입을 보다 유연하게 설정할 수 있습니다.

예를 들어, 아래와 같은 경우에도 제네릭을 사용해 여러 타입에 대한 유틸리티 함수를 작성할 수 있습니다.
```

```jsx
const numberArray = [1, 2, 3]
const updatedNumberArray = insertAtBeginning(numberArray, 0)

const booleanArray = [true, false, true]
const updatedBooleanArray = insertAtBeginning(booleanArray, false)

console.log(updatedNumberArray) // [0, 1, 2, 3]
console.log(updatedBooleanArray) // [false, true, false, true]
```

```jsx
위 코드에서 제네릭 T는 number 타입과 boolean 타입으로 각각 사용되었습니다.

이렇게 제네릭을 사용하면 코드의 재사용성이 높아지고, 다양한 상황에서 동일한 함수를 활용할 수 있습니다.
```

### 4. 타입스크립트의 타입 안정성


## 5. **React.FC의 장점과 제네릭 타입**

```jsx
React.FC는 제네릭 타입입니다. 우리가 React.FC<TodosProps>라고 작성한 것은,

이 함수형 컴포넌트가 TodosProps 타입의 props를 받아야 한다는 것을 의미합니다.

제네릭 타입을 사용하면 컴포넌트마다 다른 타입을 쉽게 정의하고 적용할 수 있습니다.

이 방법의 장점은 모든 함수형 컴포넌트가 갖는 기본 props (예: children)를 자동으로 포함시킬 수 있다는 점입니다.

이를 통해 코드가 더 명확해지고, 타입스크립트의 강력한 타입 체크 기능을 적극 활용할 수 있습니다.

* 컴포넌트가 외부에서 전달받는 props가 없을 때 굳이 제네릭 타입을 명시하지 않아도 된다 React.FC 이런식으로 사용
```

## 두 가지 방법

```jsx
두가지 방식의 함수형 컴포넌트 타입 정의 방식이 있다

방식은 본질적으로 동일한 결과를 달성하지만, 사용법과 유지보수 측면에서 약간의 차이가 있습니다.

둘 다 유효한 방법이지만, 각각의 장단점이 있습니다.
```

### 인 라인 방식

```jsx
import React from "react";

const Todos: React.FC<{ items: string[] }> = (props) => {
    return (
        <ul>
            {props.items.map((item) => (
                <li key={item}>{item}</li>
            ))}
        </ul>
    );
};

export default Todos;
```

```jsx
장점

	간결함: 이 방식은 코드가 짧고 간결합니다. 작은 컴포넌트나 간단한 프로젝트에 적합합니다.

	직관성: props의 타입이 컴포넌트 정의 바로 옆에 있으므로, 이해하기 쉽습니다.

단점

	재사용성: props의 타입 정의가 인라인으로 되어 있어, 같은 타입을 여러 곳에서 사용할 때 중복 코드가 생길 수 있습니다.

	유지보수성: 나중에 props 구조가 변경되면, 타입 정의가 분리되어 있지 않아서 변경이 어려울 수 있습니다.
```

### 별도의 타입 정의 방식

```jsx
import React from "react";

type TodosProps = {
    items: string[];
};

const Todos: React.FC<TodosProps> = (props) => {
    return (
        <ul>
            {props.items.map((item) => (
                <li key={item}>{item}</li>
            ))}
        </ul>
    );
};

export default Todos;
```

```jsx
장점

	재사용성: TodosProps 타입을 별도로 정의함으로써, 이 타입을 다른 컴포넌트에서 재사용할 수 있습니다.

	유지보수성: 타입 정의가 분리되어 있어, props 구조가 변경되더라도 타입 정의를 수정하기 쉽습니다. 특히, 대규모 프로젝트에서 유용합니다.

	확장성: 만약 props가 늘어나거나 복잡해지면, 별도의 타입 정의는 더 쉽게 관리할 수 있습니다.

단점

	장황함: 작은 컴포넌트나 간단한 프로젝트에서는 코드가 약간 더 장황해질 수 있습니다.

	간결성 감소: 단순한 컴포넌트에서 타입을 별도로 정의하면 코드가 더 길어지고, 한눈에 파악하기 어려울 수 있습니다.
```

# { refs 및 useRef 작업하기 }

```jsx
// React에서 useRef 훅을 가져옵니다.
import { useRef } from "react";

// NewTodo 컴포넌트를 정의합니다.
const NewTodo = () => {
    // useRef를 사용하여 todoTextInputRef라는 레퍼런스를 생성합니다.
    // 이 레퍼런스는 <input> 요소와 연결되며, 초기값으로 null을 가집니다.
    const todoTextInputRef = useRef<HTMLInputElement>(null);

    // 폼이 제출될 때 호출되는 함수입니다.
    const submitHandler = (event: React.FormEvent) => {
        // 기본 폼 제출 동작을 방지합니다.
        event.preventDefault();

        // 레퍼런스를 통해 <input> 요소에 접근하고, 입력된 텍스트 값을 가져옵니다.
        // ?. 연산자는 레퍼런스가 아직 연결되지 않았을 경우 안전하게 접근할 수 있도록 합니다.
        const enteredText = todoTextInputRef.current?.value;

        // 입력된 텍스트가 공백만으로 이루어졌거나 비어있다면 처리하지 않고 함수를 종료합니다.
        // trim()은 문자열의 앞뒤 공백을 제거하는 함수입니다.
        if(enteredText?.trim().length === 0) {
            // 현재는 아무 작업도 하지 않지만, 오류를 발생시키거나 사용자에게 피드백을 줄 수 있습니다.
            return;
        }

        // 입력이 유효한 경우 이후 작업을 여기서 처리합니다.
        // 예를 들어, 부모 컴포넌트로 데이터를 전달하는 등의 작업을 할 수 있습니다.
    }

    // JSX를 반환하여 렌더링합니다.
    return(
        // 폼 요소를 정의하고, 폼이 제출될 때 submitHandler가 호출되도록 설정합니다.
        <form onSubmit={submitHandler}>
            {/* 텍스트 입력 필드의 레이블을 설정합니다. */}
            <label htmlFor="text">Todo text</label>

            {/* 텍스트 입력 필드를 생성하고, todoTextInputRef 레퍼런스를 ref 속성에 연결합니다. */}
            <input type="text" id="text" ref={todoTextInputRef}/>

            {/* 폼 제출을 위한 버튼을 생성합니다. */}
            <button>Add Todo</button>
        </form>
    )
}

// NewTodo 컴포넌트를 내보내어 다른 곳에서 사용할 수 있도록 합니다.
export default NewTodo;

```

## 1. `useRef`의 개요 및 사용법

```jsx
useRef란?

	리액트에서 useRef는 특정 DOM 요소에 접근하거나 컴포넌트의 상태를 저장하지 않고 값의 변화를 추적할 때 사용됩니다.

사용 방법

	useRef()를 호출하면 레퍼런스를 생성할 수 있습니다.

	이 레퍼런스는 객체로 반환되며, .current 프로퍼티를 통해 접근할 수 있습니다.

	생성된 레퍼런스를 ref 속성에 지정하여 DOM 요소와 연결할 수 있습니다.
```

```jsx

	연결된 input 요소의 값을 추출할 때는 todoTextInputRef.current.value로 접근합니다.

	이때, .current가 null일 수 있기 때문에 타입스크립트는 자동으로 ?. (optional chaining) 연산자를 추가해 안전하게 접근하려고 합니다.
```

## 5. Optional Chaining과 Non-null Assertion

```jsx
Optional Chaining (?.)

	레퍼런스가 null일 수 있는 가능성을 고려하여 안전하게 값에 접근하는 연산자입니다.

Non-null Assertion (!)

	개발자가 레퍼런스가 null이 아님을 확신할 때 사용할 수 있는 연산자입니다.

	!를 사용하면 타입스크립트에게 이 값이 null이 아님을 명시적으로 알려줄 수 있습니다.
```

### 1.2. `NewTodo` 컴포넌트의 역할

```jsx
NewTodo 컴포넌트는 사용자가 새로운 할 일을 입력하고 제출할 수 있는 폼을 제공합니다.

사용자가 할 일을 제출하면, 이 컴포넌트는 App 컴포넌트에서 전달된 함수를 호출해 새로운 할 일을 추가하도록 요청합니다.
```

```jsx
import { useRef } from "react";

// NewTodo 컴포넌트에 전달될 props의 타입을 정의
interface NewTodoProps {
  // onAddTodo는 문자열을 인수로 받고 반환값이 없는 함수 타입임
  onAddTodo: (text: string) => void;
}

// NewTodo 함수형 컴포넌트 정의
const NewTodo: React.FC<NewTodoProps> = (props) => {
  // useRef 훅을 사용해 input 요소에 접근할 수 있는 참조 객체 생성
  // 초기값은 null로 설정되며, 이후 input 요소가 DOM에 렌더링된 후 참조됨
  const todoTextInputRef = useRef<HTMLInputElement>(null);

  // form 제출 시 호출되는 함수
  const submitHandler = (event: React.FormEvent) => {
    event.preventDefault(); // 폼의 기본 동작(페이지 새로고침)을 방지
    handleTodoSubmit(); // 할 일 추가 처리 함수 호출
  };

  // 입력된 텍스트를 읽어와 유효성을 검사하고, 유효하면 상위 컴포넌트로 전달하는 함수
  const handleTodoSubmit = () => {
    // useRef를 통해 참조된 input 요소의 현재 값을 가져옴
    const enteredText = todoTextInputRef.current!.value;

    // 입력된 텍스트가 비어있거나 공백만 있는 경우 에러 처리를 위해 return
    if (enteredText.trim().length === 0) {
      // 필요시 에러 메시지를 출력하거나 다른 처리 가능
      return;
    }

    // 입력된 텍스트가 유효한 경우, 상위 컴포넌트(App)에서 전달받은 onAddTodo 함수 호출
    props.onAddTodo(enteredText);
  };

  return (
    <form onSubmit={submitHandler}>
      {/* 텍스트 입력을 위한 label과 input 요소 */}
      <label htmlFor="text">Todo text</label>

      {/* ref 속성을 통해 input 요소에 접근할 수 있는 참조 객체를 연결 */}
      <input type="text" id="text" ref={todoTextInputRef} />

      {/* 할 일 추가 버튼, 클릭 시 폼이 제출되고 submitHandler가 호출됨 */}
      <button>Add Todo</button>
    </form>
  );
}

export default NewTodo;
```

## 섹션 3: `state`를 사용하여 동적 데이터 관리하기

### 3.1. `useState`로 상태 관리하기

```jsx
앞으로 todos 배열을 useState 훅을 이용해 상태로 관리하고,

addTodoHandler 함수에서 상태를 업데이트할 것입니다. useState를 사용하면 상태가 변경될 때마다 해당 컴포넌트가 다시 렌더링됩니다.
```

```jsx
// React의 useState 훅을 가져옵니다.
import { useState } from 'react';
// Todo 모델을 가져옵니다. 이는 사용자 정의 클래스일 것으로 추정됩니다.
import Todo from './models/todo';

// App 컴포넌트를 정의합니다.
function App() {
  // useState 훅을 사용하여 todos 상태를 관리합니다.
  // Todo[] 타입의 배열로, 초기값으로 두 개의 Todo 객체를 가집니다.
  const [todos, setTodos] = useState<Todo[]>([
    new Todo('리액트 배우기'),
    new Todo('타입스크립트 배우기')
  ]);

  // 새로운 할 일을 추가하는 함수입니다.
  // todoText를 매개변수로 받아 새 Todo 객체를 생성합니다.
  const addTodoHandler = (todoText: string) => {
    const newTodo = new Todo(todoText);
    // setTodos 함수를 사용하여 상태를 업데이트합니다.
    // 이전 상태(prevTodos)를 받아 새로운 할 일을 추가한 새 배열을 반환합니다.
    setTodos((prevTodos) => prevTodos.concat(newTodo)); // concat 메서드는 하나 이상의 배열이나 값을 기존 배열에 병합하여 새로운 배열을 반환
  };

  // JSX를 반환합니다.
  return (
    <div>
      {/* NewTodo 컴포넌트에 addTodoHandler 함수를 props로 전달합니다. */}
      <NewTodo onAddTodo={addTodoHandler} />
      {/* Todos 컴포넌트에 todos 배열을 props로 전달합니다. */}
      <Todos items={todos} />
    </div>
  );
}
```

```jsx
이제 addTodoHandler 함수에서 새로운 할 일을 todos 배열에 추가하면 App 컴포넌트가 다시 렌더링되고,

Todos 컴포넌트에 새로운 할 일 목록이 전달됩니다.
```

### `bind()` 메서드란?

```tsx
bind() 메서드는 JavaScript에서 사용되는 함수로, 함수가 호출될 때 this가 무엇인지 미리 정해주는 역할을 합니다.

쉽게 말해서, 함수가 실행될 때 어떤 객체를 this로 쓸지 미리 정해두는 거예요.

예를 들어, 어떤 객체의 메서드를 다른 곳에서 호출하려고 할 때, 원래 객체의 this를 그대로 유지하고 싶다면 bind()를 사용할 수 있어요.

또한, 함수가 호출될 때 기본으로 들어가는 값을 미리 정해둘 수도 있습니다.

const person = {
  name: 'Alice',
  greet() {
    console.log(`Hello, my name is ${this.name}`);
  }
};

const greet = person.greet;
greet(); // 결과: "Hello, my name is undefined"

const boundGreet = greet.bind(person);
boundGreet(); // 결과: "Hello, my name is Alice"

위 예시에서 bind()를 사용하지 않고 greet() 함수를 호출하면, this가 undefined가 되어버려서 이름이 제대로 출력되지 않아요.

그런데 bind(person)를 사용하면 this가 항상 person 객체를 가리키도록 고정되기 때문에 Alice가 제대로 출력됩니다.

요약하면, bind()는 함수의 this와 기본 인자를 고정시키는 방법이에요.
```

```tsx
bind(null, item.id)의 의미:

null:

bind()에서 첫 번째 인자는 this가 무엇인지 정해주는 역할을 해요. 하지만 이 경우엔 this를 바꾸고 싶지 않아서 null을 넣은 거예요.

즉, "그냥 기존의 this를 그대로 써라" 라는 뜻이에요.

item.id:

이건 onRemoveTodo 함수에 미리 넘겨줄 첫 번째 인자예요. 그래서 나중에 이 함수를 호출할 때 굳이 인자를 넘겨주지 않아도 item.id가 자동으로 전달돼요.
```

```tsx
function removeTodo(id) {
  console.log(`Removing todo with id: ${id}`);
}

const boundRemoveTodo = removeTodo.bind(null, 42);

// 이제 boundRemoveTodo를 호출하면 자동으로 id 42가 전달됩니다.
boundRemoveTodo(); // 출력: Removing todo with id: 42

위 예시처럼, bind(null, 42)는 removeTodo 함수를 새로운 함수로 만들어주는데, 이 함수는 호출될 때 항상 id로 42를 사용하게 돼요.

이런 식으로 props.onRemoveTodo.bind(null, item.id)는 item.id를 미리 고정해서 함수에 넘겨주고, this는 변경하지 않겠다는 뜻입니다.
```

### 3.1. `App` 컴포넌트 수정

```jsx
이제 App.tsx 파일로 가서 실제 Todo 항목을 삭제하는 removeTodoHandler 함수를 구현합니다.
```

```jsx
import './App.css'; // 전체 애플리케이션에 스타일을 적용하기 위해 CSS 파일을 임포트함.
import { useState } from 'react'; // React의 useState 훅을 임포트하여 컴포넌트에서 상태 관리를 할 수 있게 함.
import Todo from './models/todo'; // Todo 클래스 모델을 임포트하여 새로운 Todo 항목을 생성할 수 있게 함.
import Todos from './components/Todos'; // Todos 컴포넌트를 임포트하여 할 일 목록을 렌더링함.
import NewTodo from './components/NewTodo'; // NewTodo 컴포넌트를 임포트하여 새로운 할 일을 추가하는 폼을 렌더링함.

function App() {
  // todos라는 상태를 선언하고 초기 값으로 두 개의 할 일 항목을 설정함.
  // useState<Todo[]>는 Todo 객체의 배열을 상태로 관리함.
  const [todos, setTodos] = useState<Todo[]>([
    new Todo('리액트 배우기'), // 첫 번째 할 일 항목
    new Todo('타입스크립트 배우기') // 두 번째 할 일 항목
  ]);

  // 새로운 할 일을 추가하는 함수.
  // todoText라는 문자열을 인자로 받아 새로운 Todo 객체를 생성하고, 이전 상태에 추가함.
  const addTodoHandler = (todoText: string) => {
    const newTodo = new Todo(todoText); // 새로운 Todo 객체 생성
    setTodos((prevTodos) => prevTodos.concat(newTodo)); // 이전 할 일 목록에 새 할 일을 추가
  };

  // 특정 할 일을 제거하는 함수.

  const removeTodoHandler = (todoId: string) => {
    setTodos((prevTodos) => {
      return prevTodos.filter(todo => todo.id !== todoId); // 주어진 id와 일치하지 않는 항목들만 남김
    });
  };

  return (
    <div>
      {/* 새로운 할 일을 추가할 수 있는 폼을 렌더링하고, 폼이 제출될 때 addTodoHandler를 호출함 */}
      <NewTodo onAddTodo={addTodoHandler} />

      {/* 현재 할 일 목록을 렌더링하고, 각 항목이 삭제될 때 removeTodoHandler를 호출함 */}
      <Todos items={todos} onRemoveTodo={removeTodoHandler} />
    </div>
  );
}

export default App; // App 컴포넌트를 기본 내보내기로 설정하여 다른 파일에서 이 컴포넌트를 임포트할 수 있게 함.

```

## 2. **Context 생성 및 Provider 설정**

```jsx
리액트 Context를 사용해 전역 상태를 관리하기 위해, 먼저 Context와 Provider를 정의해야 합니다.
```

### `TodosContextProvider` 컴포넌트

```jsx
import React, { ReactNode, useState } from "react";
import Todo from "../models/todo";

// Context에서 사용할 데이터의 타입을 정의합니다.
type TodosContextObj = {
    items: Todo[]; // Todo 항목의 배열
    addTodo: (text: string) => void; // 새 Todo를 추가하는 함수
    removeTodo: (id: string) => void; // Todo를 제거하는 함수
};

// 기본값을 설정한 Context 객체를 생성합니다.
// 실제 사용 시에는 이 기본값을 Context.Provider를 통해 제공되는 값으로 덮어씁니다.
export const TodosContext = React.createContext<TodosContextObj>({
    items: [], // 기본값: 빈 배열
    addTodo: () => {}, // 기본값: 빈 함수
    removeTodo: (id: string) => {} // 기본값: 빈 함수
});

// ContextProvider의 Props 타입을 정의합니다.
// children은 ReactNode 타입으로, 이 컴포넌트의 자식 컴포넌트를 의미합니다.
interface TodosContextProviderProps {
    children: ReactNode;
}

// TodosContextProvider 컴포넌트를 정의합니다.
// 이 컴포넌트는 Context를 사용하여 상태를 관리하고, 하위 컴포넌트에 상태를 제공합니다.
const TodosContextProvider: React.FC<TodosContextProviderProps> = ({ children }) => {
    // todos 상태를 useState를 사용하여 관리합니다.
    // 초기값은 빈 Todo 배열입니다.
    const [todos, setTodos] = useState<Todo[]>([]);

    // 새 Todo를 추가하는 핸들러 함수입니다.
    const addTodoHandler = (text: string) => {
        const newTodo = new Todo(text); // 새 Todo 객체를 생성합니다.
        setTodos((prevTodos) => [...prevTodos, newTodo]); // 기존 Todo 배열에 새 Todo를 추가합니다.
    };

    // 특정 ID의 Todo를 제거하는 핸들러 함수입니다.
    const removeTodoHandler = (todoId: string) => {
        setTodos((prevTodos) => prevTodos.filter(todo => todo.id !== todoId)); // ID가 일치하지 않는 Todo만 남기고 필터링합니다.
    };

    // Context에 제공할 값입니다.
    // items는 현재 상태의 todos 배열을, addTodo와 removeTodo는 핸들러 함수들을 포함합니다.
    const contextValue: TodosContextObj = {
        items: todos,
        addTodo: addTodoHandler,
        removeTodo: removeTodoHandler
    };

    // Context.Provider를 사용하여 하위 컴포넌트에 상태와 핸들러를 제공합니다.
    // children은 TodosContextProvider 컴포넌트의 자식 요소들입니다.
    return (
        <TodosContext.Provider value={contextValue}>
            {children} {/* children은 이 컴포넌트의 자식 컴포넌트입니다. */}
        </TodosContext.Provider>
    );
};

export default TodosContextProvider;

```

```jsx
Context 객체 생성:

TodosContext를 생성하여 Context를 정의합니다. 이 Context는 TodosContextObj 타입을 사용하여 데이터를 명확하게 정의합니다.

초기값은 빈 배열과 빈 함수들입니다.

Props 타입 정의:

TodosContextProviderProps를 정의하여 children의 타입을 ReactNode로 명시합니다. ReactNode는 React의 모든 자식 요소를 포함할 수 있는 타입입니다.

TodosContextProvider 컴포넌트:

이 컴포넌트는 React.FC<TodosContextProviderProps>를 사용하여 children을 props로 받고,

이 자식 요소들을 Context를 통해 상태를 관리하는 컴포넌트로 만듭니다.

useState 훅을 사용하여 todos 상태를 관리합니다.

addTodoHandler와 removeTodoHandler 함수는 Todo 항목을 추가하거나 제거하는 로직을 포함합니다.

contextValue 객체를 통해 Context에 제공할 값을 정의하고, 이 값은 TodosContext.Provider의 value 속성으로 설정됩니다.

{children}을 통해 이 컴포넌트의 자식 요소들을 렌더링합니다.
```

## 3. **Context를 사용하는 컴포넌트들**

### App 컴포넌트

```jsx
import './App.css'
import TodosContextProvider from './store/todos-context'
import NewTodo from './components/NewTodo'
import Todos from './components/Todos'

function App() {
  return (
    <TodosContextProvider>
      <NewTodo /> {/* Todo 항목을 추가하는 컴포넌트 */}
      <Todos /> {/* Todo 리스트를 보여주는 컴포넌트 */}
    </TodosContextProvider>
  )
}

export default App
```

```jsx
TodosContextProvider: 애플리케이션의 최상위에서 하위 컴포넌트들에 Context 값을 제공합니다.
```

### NewTodo 컴포넌트

```jsx
import { useRef, useContext } from "react";
import classes from "./NewTodo.module.css";
import { TodosContext } from "../store/todos-context";

const NewTodo: React.FC = () => {
    const todosCtx = useContext(TodosContext); // Context에 접근
    const todoTextInputRef = useRef<HTMLInputElement>(null); // 입력 필드 참조

    const submitHandler = (event: React.FormEvent) => {
        event.preventDefault();
        const enteredText = todoTextInputRef.current!.value; // 입력된 텍스트 가져오기
        if (enteredText.trim().length === 0) {
            return; // 입력이 비어있다면 아무 작업도 하지 않음
        }
        todosCtx.addTodo(enteredText); // 새로운 Todo 추가
    };

    return (
        <form onSubmit={submitHandler} className={classes.form}>
            <label htmlFor="text">Todo text</label>
            <input type="text" id="text" ref={todoTextInputRef} />
            <button>Add Todo</button>
        </form>
    );
};

export default NewTodo;

```

```jsx
useContext(TodosContext): TodosContext를 통해 Todo 항목을 추가하는 함수를 가져옵니다.

useRef: 사용자가 입력한 텍스트를 참조합니다.

submitHandler: 폼 제출 시 호출되며, 입력된 텍스트를 검증한 후 Todo 항목을 추가합니다
```

### Todos 컴포넌트

```jsx
import React, { useContext } from "react";
import TodoItem from "./TodoItem";
import classes from "./Todos.module.css";
import { TodosContext } from "../store/todos-context";

const Todos: React.FC = () => {
    const todosCtx = useContext(TodosContext); // Context에 접근

    return (
        <ul className={classes.todos}>
            {todosCtx.items.map((item) => (
                <TodoItem
                    key={item.id}
                    text={item.text}
                    onRemoveTodo={todosCtx.removeTodo.bind(null, item.id)} // 클릭 시 Todo 제거
                />
            ))}
        </ul>
    );
};

export default Todos;

```

```jsx
useContext(TodosContext): TodosContext를 통해 Todo 리스트와 항목을 제거하는 함수를 가져옵니다.

map: Todo 리스트를 순회하며, 각 항목을 TodoItem으로 렌더링합니다.
```

### TodoItem 컴포넌트

```jsx
import classes from "./TodoItem.module.css";

type TodoText = {
  text: string;
  onRemoveTodo: (event: React.MouseEvent) => void;
};

const TodoItem: React.FC<TodoText> = (props) => {
  return (
    <li className={classes.item} onClick={props.onRemoveTodo}>
      {props.text}
    </li>
  );
};

export default TodoItem;
```

```jsx
TodoItem: Todo 항목을 화면에 렌더링하며, 클릭 시 해당 항목을 삭제하는 onRemoveTodo 함수를 호출합니다.
```

## 1. **tsconfig.json 파일의 역할**

```jsx
컴파일 설정: TypeScript 코드가 자바스크립트로 변환되는 방식을 설정합니다.

컴파일러 옵션: 코드를 어떻게 변환할지, 어떤 자바스크립트 버전으로 변환할지, 어떤 라이브러리를 포함할지 등을 결정합니다.

프로젝트 구조: 프로젝트의 타입스크립트 파일을 어떻게 관리할지 정의합니다.
```

## 2. **주요 컴파일러 옵션**

```jsx
target:

	타입스크립트 코드를 변환할 자바스크립트의 버전을 설정합니다.

	예: "target": "es5"는 ES5로 변환하여 오래된 브라우저와의 호환성을 유지합니다.

lib:

	TypeScript가 기본적으로 사용할 라이브러리를 설정합니다.

	예: "lib": ["dom", "dom.iterable", "esnext"]는 DOM과 최신 ECMAScript 기능을 사용합니다.

allowJs:

	자바스크립트 파일을 타입스크립트 프로젝트에 포함할 수 있도록 허용합니다.

	"allowJs": true로 설정하면, 자바스크립트 파일을 프로젝트에 포함할 수 있습니다.

skipLibCheck:

	타입 정의 파일의 검사를 건너뛸지 여부를 설정합니다.

	"skipLibCheck": true로 설정하면, 라이브러리의 타입 정의 검사를 생략하여 컴파일 속도를 높일 수 있습니다.

esModuleInterop:

	CommonJS 모듈과 ES 모듈 간의 호환성을 허용합니다.

	"esModuleInterop": true로 설정하면, ES 모듈과 CommonJS 모듈을 더 쉽게 함께 사용할 수 있습니다.

allowSyntheticDefaultImports:

	ES 모듈의 기본 내보내기와의 호환성을 허용합니다.

	"allowSyntheticDefaultImports": true로 설정하면, 기본 내보내기를 명시하지 않고도 import를 사용할 수 있습니다.

strict:

	엄격한 타입 검사를 활성화합니다.

	"strict": true로 설정하면, TypeScript는 모든 가능한 타입 검사를 활성화하여 코드의 안정성을 높입니다.

forceConsistentCasingInFileNames:

	파일 이름의 대소문자 일관성을 강제합니다.

	"forceConsistentCasingInFileNames": true로 설정하면, 대소문자 일관성을 유지하게 됩니다.

noFallthroughCasesInSwitch:

	switch 문에서 case 문이 fall-through(다음 case로 넘어가는 것)를 방지합니다.

	"noFallthroughCasesInSwitch": true로 설정하면, 각 case 문에 break 문이 없을 경우 오류를 발생시킵니다.

module:

	모듈 시스템을 설정합니다.

	예: "module": "esnext"는 최신 ECMAScript 모듈을 사용합니다.

moduleResolution:

	모듈을 어떻게 해석할지 설정합니다.

	"moduleResolution": "node"로 설정하면, Node.js 방식으로 모듈을 해석합니다.

resolveJsonModule:

	JSON 파일을 모듈로 사용할 수 있도록 설정합니다.

	"resolveJsonModule": true로 설정하면, JSON 파일을 직접 import할 수 있습니다.

isolatedModules:

	모든 파일이 독립적으로 처리되도록 설정합니다.

	"isolatedModules": true로 설정하면, 모든 파일이 독립적으로 타입 검사됩니다.

noEmit:

	컴파일러가 파일을 생성하지 않도록 설정합니다.

	"noEmit": true로 설정하면, 실제로 파일을 생성하지 않고 타입 검사만 수행합니다.

jsx:

	JSX 코드의 변환 방식을 설정합니다.

	"jsx": "react-jsx"로 설정하면, React 17의 JSX 변환 방식을 사용합니다.
```
