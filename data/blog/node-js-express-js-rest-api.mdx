# 라우터

```jsx
라우터(Router)는 Express 프레임워크에서 URL과 관련된 라우팅 로직을 모듈화하여 처리하는 기능을 말한다.

Express 애플리케이션에서 라우터를 사용하면 코드를 모듈 단위로 분리하고 유지보수성을 높일 수 있다.
```

## **1. 라우터 객체 생성**

```jsx
라우터를 사용하려면 express.Router() 메서드를 호출하여 라우터 객체를 생성한다.

이 객체는 Express 앱과 유사하게 동작하며, 해당 라우터에 대한 미들웨어 및 라우트를 등록할 수 있다.
```

```jsx
const express = require('express')
const router = express.Router()
```

## **2. 라우트 등록**

```jsx
라우터 객체에는 다양한 HTTP 메서드에 대한 라우트를 등록할 수 있다.

가장 일반적으로 사용되는 메서드는 get, post, put, delete 등이 있다. 라우트 등록 시 경로와 함께 콜백 함수를 전달한다.
```

```jsx
router.get('/', (req, res, next) => {
  // GET 요청에 대한 로직 수행
})
```

## **3. 라우터 미들웨어 등록**

```jsx
라우터에는 라우트 이외에도 미들웨어를 등록할 수 있다. 이 미들웨어는 해당 라우터에 도달하는 모든 요청에서 실행된다.
```

```jsx
router.use((req, res, next) => {
  // 라우터 전역에서 실행되는 미들웨어
  next()
})
```

## **4. 외부 라우터를 앱에 등록**

```jsx
외부에서 생성한 라우터를 앱에 등록하려면 app.use() 메서드를 사용한다.

이때 등록할 경로를 지정하여 해당 경로에 도달하는 요청에 대해 라우터가 동작하도록 설정한다.
```

```jsx
const placeRoutes = require('./routes/places-routes')
app.use('/places', placeRoutes)
```

## **5. 라우터 파일에서 내보내기**

```jsx
라우터 파일에서는 구성된 라우터 객체를 module.exports를 사용하여 외부로 내보낸다.

이렇게 외부에서 해당 라우터를 불러와 재사용할 수 있다.
```

```jsx
// places-routes.js

const express = require('express')
const router = express.Router()

router.get('/', (req, res, next) => {
  // GET 요청에 대한 로직 수행
})
```

```jsx

DUMMY_PLACES.find()는 JavaScript 배열 메서드로, 배열에서 특정 조건을 만족하는 첫 번째 요소를 찾아준다.

res.json({ place })는 클라이언트에게 JSON 형식으로 응답을 보낸다. 이때, { place }는 ES6의 단축 문법으로, { place: place }와 같다.
```

```jsx
이 모듈은 /api/places 경로로 들어오는 요청에 대한 라우팅을 담당한다.

app.use('/api/places', placesRoutes);는 /api/places로 시작하는 모든 요청을 placesRoutes에게 전달하여 처리하도록 설정한다.
```

```jsx
// /api/places/:pid 라우트를 처리하는 미들웨어 함수입니다.
router.get('/:pid', (req, res, next) => {

  // 요청 파라미터에서 사용자 ID를 추출합니다.
  const userId = req.params.uid

  // DUMMY_PLACES 배열에서 해당 사용자가 작성한 장소를 찾습니다.
  const place = DUMMY_PLACES.find((p) => {
    return p.creator === userId
```

```jsx
라우트 순서의 중요성:

라우트의 순서가 중요하며, /api/places로 시작하는 모든 요청을 처리하는 첫 번째 라우트가 있다.

/api/places/user/uid로 시작하는 요청을 처리하는 두 번째 라우트가 있다.

주의할 점은 라우트의 순서가 중요하며, Express는 먼저 등록된 라우트부터 순서대로 매칭한다는 것이다.

라우트 순서 조정:

만약 /user 라우트가 /api/places 뒤에 와서는 안 되는데, 그렇게 되면 라우트가 잘못 해석될 수 있다.

예를 들어, /user만 입력하면 /api/places 라우트에 더해져 잘못된 결과를 반환할 수 있다.

따라서 라우트의 순서를 조정하여 정확한 매칭이 이루어지도록 해야 한다.

* 동적인 세그먼트가 사용되는 경우, Express는 정적인 부분과 동적인 부분이 섞인 라우트를 더 우선시한다.

따라서 /api/places/user/:uid가 /api/places/:pid보다 앞에 위치하면,

/api/places/user/:uid가 먼저 매칭되어 사용자 ID를 잘못하여 장소를 찾을 수 있다.

즉, 동적인 :uid가 정적인 user와 섞여 우선순위를 가지게 되는 것이 문제이다.

* 일반적으로 /api/places/:pid와 같이 동적인 세그먼트를 포함하는 라우트는

더 구체적인 정적인 라우트보다 먼저 정의되어야 한다.

따라서 /api/places/:pid가 /api/places/user/:uid보다 먼저 등록되어야 한다.

이렇게 하면 Express는 /api/places/:pid로 들어오는 요청을 먼저 매칭시키고,

:pid에는 해당하는 값이 들어가게 된다. 그리고 /api/places/user/:uid는 더 구체적인 라우트이기 때문에

/api/places/:pid 이후에 나와도 올바르게 동작한다.

따라서, 올바른 동작을 위해서는 /api/places/:pid 라우트가 먼저 등록되어야 한다.
```

```jsx
/api/places/:pid 라우트의 에러 핸들링 부분:

Error 객체에 HTTP 상태 코드를 추가하고, 여기서는 404를 설정한다.

그리고 생성한 에러 객체를 다음 미들웨어 함수에 전달하기 위해 next(error)를 호출한다.

그에 따른 HTTP 상태 코드를 반환하여 적절한 오류 처리를 할 수 있도록 한다.
```

```jsx
// index.js

const express = require('express')
const bodyParser = require('body-parser')

const app = express()

app.use('/api/places', placesRoutes) // => /api/places/ 로 시작하는 요청 라우팅

  if (res.headerSent) {
```

```jsx
에러 핸들링 미들웨어:

app.use((error, req, res, next) => {...} 부분은 애플리케이션 전반에서 발생한 에러를 처리하는 미들웨어이다.

이 미들웨어는 에러를 받아 HTTP 응답을 처리한다.

만약 응답 헤더가 이미 전송된 경우(res.headerSent가 true), 다음 미들웨어로 에러를 전달한다.

그렇지 않으면, 에러의 상태 코드 또는 기본값으로 500을 설정하고 에러 메시지를 JSON 형태로 클라이언트에게 반환한다.

이러한 구성은 주로 에러 핸들링에 중점을 둔 구조로,

클라이언트에게 명시적인 에러 메시지를 전달하여 문제가 발생했을 때 적절한 조치를 취할 수 있도록 도와준다.

* return next(error); 구문은 현재 미들웨어 함수를 즉시 종료하고 다음 미들웨어 함수로 제어를 전달하는 역할을 한다.

이는 이미 응답 헤더가 전송된 상태에서 에러가 발생했을 때 중복 응답을 방지하기 위한 것

만약에 이미 응답이 전송되었다면, 새로운 응답을 보내는 것은 문제를 일으킬 수 있다.

따라서 return next(error);를 사용하여 미들웨어 함수를 종료하고 ( next() 뒤에 미들웨어 없으면 종료 )

다음 미들웨어로 넘어가게끔 하는 것은 올바른 접근이다.

종종 미들웨어 체인에서 에러가 발생하더라도 모든 미들웨어가 실행되어야 하는 경우가 있을 수 있다.

그렇지 않으면 중간에 끊겨버리면서 예상치 못한 동작이 발생할 수 있다.

하지만 현재의 코드에서는 이미 응답이 전송된 경우에는 다음 미들웨어로 이동하지 않도록 하는 것이 안전한 방법이다.

그러나 아직도 중복되는 코드가 많으므로 모델을 만들어서 처리해보도록 한다
```

```jsx
두 번째 에러 핸들링 미들웨어:

app.use((error, req, res, next) => {...});에서는 두 번째 에러 핸들링 미들웨어이다.

첫 번째 미들웨어에서 생성된 에러를 처리한다.

이미 응답이 전송된 경우에는 다음 미들웨어로 넘어가고, 그렇지 않다면 에러에 따라 적절한 응답을 클라이언트에게 전송한다.

에러 객체(HttpError)는 에러의 상태 코드(code)와 메시지(message)를 가지고 있다.

두 번째 에러 핸들링 미들웨어에서는 해당 정보를 이용하여 클라이언트에게 응답한다.
```

```jsx
업데이트와 관련된 코드를 작성해준다

요청 데이터 추출:

const { title, description } = req.body;에서 요청 본문에서 title과 description을 추출한다.

이는 클라이언트가 전송한 업데이트할 장소의 정보이다.

장소 식별:

const placeId = req.params.pid;에서 요청 파라미터에서 pid를 추출하여 업데이트할 장소를 식별한다.

장소 정보 복제:

const updatePlace = { ...DUMMY_PLACES.find(p => p.id === placeId) };에서

DUMMY_PLACES 배열에서 해당 ID와 일치하는 장소를 찾아 객체를 복제한다.

이렇게 복제함으로써 원래 배열의 데이터를 직접 수정하지 않고 새로운 객체에 업데이트를 진행할 수 있다.

( 잘못하면 부분적으로만 수정되버릴 수도 있기 때문에 )

장소 인덱스 확인:

const placeIndex = DUMMY_PLACES.findIndex(p => p.id === placeId);에서 DUMMY_PLACES 배열에서 해당 장소의 인덱스를 확인한다.

장소 정보 업데이트:

updatePlace.title = title;와 updatePlace.description = description;에서 복제한 장소 정보의 title과 description을 업데이트한다.

이 때, 원시값이기 때문에 직접 수정이 가능하다.

* 더 상세한 설명

updatePlace는 DUMMY_PLACES 배열에서 찾은 해당 장소의 정보를 복제한 원시 값이다.

복제된 값은 새로운 메모리 공간에 저장되어 있으며, 해당 객체는 원래 객체와는 별개의 독립적인 개체이다.

따라서 updatePlace.title = title;와 updatePlace.description = description;는 복제된 객체의 속성에 직접적으로 값을 할당하는 것으로,

이는 불변성이 아닌 직접적인 수정이 가능한 특성을 가지고 있다.

이러한 특성 때문에 updatePlace 객체의 속성을 직접 수정해도, 원본 배열에 있는 객체의 속성은 변경되지 않는다.

이는 객체를 복제함으로써 새로운 메모리 주소에 새로운 값이 저장되어, 복제된 객체를 수정하더라도 원본 객체에 영향을 미치지 않게 된다.

장소 정보 저장:

DUMMY_PLACES[placeIndex] = updatePlace;에서 업데이트된 장소 정보를 원래 배열에 저장한다.

클라이언트 응답:

res.status(200).json({ place: updatePlace });에서 클라이언트에게 업데이트된 장소 정보를 응답한다.

이로써 클라이언트는 업데이트된 정보를 받아 확인할 수 있다.
```

```jsx
// axios 패키지 및 HttpError 클래스를 불러옵니다.
const axios = require('axios')
const HttpError = require('../models/http-error')

// Google Geocoding API 키를 상수로 선언합니다.
const API_KEY = 'AIzaSyA0wS4G4nwdMiyOyvrsmjEOpRlu1mcXvj8'

// 입력된 주소를 좌표로 변환하는 비동기 함수를 정의합니다.
async function getCoordsForAddress(address) {
  // Google Geocoding API에 GET 요청을 보내기 위해 axios를 사용합니다.
  const response = await axios.get(
    `https://maps.googleapis.com/maps/api/geocode/json?address=${encodeURIComponent(
      address
    )}&key=${API_KEY}`
  )

  // 응답에서 데이터를 추출합니다.
  const data = response.data

  // 데이터가 없거나 ZERO_RESULTS인 경우 오류를 생성하고 throw 합니다.
  if (!data || data.status === 'ZERO_RESULTS') {
    const error = new HttpError('Could not find location for the specified address.', 422)
    throw error
  }

  // 응답 데이터에서 좌표 정보를 추출합니다.
  const coordinates = data.results[0].geometry.location

  // 추출한 좌표를 반환합니다.
  return coordinates
}

// 모듈로 내보냅니다.
module.exports = getCoordsForAddress
```

```jsx
encodeURIComponent 함수는 문자열을 받아서 해당 문자열 안의 특수 문자들을 URI 구성 요소에 적합한 형태로 변환한다.

이때 공백은 %20으로 변환되고, 다른 특수 문자들도 적절한 형태로 변환된다.

예를 들어, 만약 주소 중에 공백이 있을 경우 이를 안전하게 처리하기 위해 encodeURIComponent를 사용할 수 있다
```
