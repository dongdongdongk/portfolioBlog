- 자바 에서는 문자열을 값 이라고 하지 않고 스트링 객체 라고 이야기 한다.
- 1.리터럴로 “독서” 라는 문자열을 작성하면
- 2.자바는 String 이라는 객체를 생성하고 그 안에 “독서” 라는 문자열을 저장한다.
- 3.객체는 자기가 생성된 번지를 가지고 있다.
- 모든 변수는 스택 영역에 저장이 된다(기본,참조 모두) 여기서 참조 타입은 번지를 참조하여 객체를 이용한다 해서 참조 타입 변수라고 불린다.
- 고로 참조 타입에는 값이 바로 저장 되는 것이 아니라 힙 영역에 생성된 객체의 번지를 저장하는것이다.
- String 은 여러 참조 타입 변수 중 클래스에 속해있다.

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380985/notion-blog/_/JAVA/_/20_/Untitled_2.png)

- 자바는 메모리 사용 영역을 3가지로 나눠 사용한다. 메소드 , 힙 , JVM
- 메소드는 클래스 코드 들이 저장되는 곳이다.
- .java 라는 소스 코드를 작성하고 저장하면 컴파일 하여 class 라는 byte 코드 파일(JVM이 이해할수 있는 코드파일)이 생성된다.
- 코드에서 이 바이트 코드 파일을 사용하면 메소드 영역에 loading (class byte 코드를 메소드 영역에 저장 하는 것) 이 되고 이렇게 저장한 클래스 를 가지고 객체를 생성하거나 변수를 생성한다.

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380987/notion-blog/_/JAVA/_/20_/Untitled_3.png)

- JVM 스택은 메소드가 호출할 때 프레임이 추가되고 메소드가 종료되면 해당 프레임이 제거된다.
- if 와 전체 블록 내에서 스택 영역이 어떻게 생성되고 사라지는지 주의
- 기본 타입 이 아닌 참조 타입은 객체 자체가 저장되는 것이 아닌 힙 영역의 배열 객체의 번지가 저장되는 것 이다.
- 이와같이 메소드 내부에서 기본 타입,참조 타입 변수가 생성이 되면 프레임 내부에 스택 형태로 생성이 되었다가 메소드가 종료되면 프레임이 제거되는 구조가 JVM스택 영역이다.

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380987/notion-blog/_/JAVA/_/20_/Untitled_4.png)

- 참조 타입의 비교 연산자 사용 시 스택 영역에서 번지의 값을 비교 하는 것 이 아니라 참조 하는 객체가 다르냐 , 같으냐 로 이해 한다. (우리는 번지 값을 알지 못하기 때문)

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380987/notion-blog/_/JAVA/_/20_/Untitled_5.png)

- 참조 타입 변수 에서 현재 참조 하는 객체가 없다면 null 을 사용할 수 있다.

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380987/notion-blog/_/JAVA/_/20_/Untitled_6.png)

- 자바에서는 Error 과 Exeption 을 구분해서 사용한다
- Error 은 os , 하드웨어 에서 발생하는 것이다 - 이는 개발자가 조치할 수 있는 영역은 아니다.
- Exeption 은 자바 프로그램을 실행하는 도중에 발생한다. - 이는 프로그램 소스를 수정해서 개발자가 수정 가능하다.
- NullPointException 이 일어난다면 참조타입 변수가 null 상태에서 참고할 객체가 존재하지 않는다는 것 이기 때문에 객체를 참조 하도록 수정해서 해결 해준다.
