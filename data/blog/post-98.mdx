# 인증 작동 방식(MERN 앱에서)

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381323/notion-blog/_/React_NodeJS_Express_MongoDB_-_MERN_/_/Untitled.png)

```jsx
**프론트엔드와 백엔드 간의 통신:**

현재의 로그인 로직에서는 사용자가 성공적으로 로그인한 경우에 대한 구체적인 확인 방법이 불분명하다.

이를 보완하기 위해 토큰 기반의 인증 체계를 도입할 필요가 있다.

로그인 후에 서버에서 발급한 토큰은 프론트엔드에서 안전하게 저장되어야 한다.

이 토큰은 일종의 식별자로 사용되며,

사용자가 다음 요청을 보낼 때마다 토큰이 함께 전송되어 서버가 해당 사용자를 식별하고 인증하는 데 사용된다.

**세션과 토큰의 차이 설명:**

과거에는 세션을 사용하여 사용자의 상태를 서버에 저장하고 관리다.

그러나 현대의 웹 애플리케이션에서는 세션 대신 토큰을 사용하는 추세이다.

세션은 서버 측에서 상태를 유지하며, 사용자의 식별 및 인증 정보를 저장한다.

반면에 토큰은 클라이언트 측에서 상태를 유지하고, 사용자의 인증 정보를 안전하게 저장하며 필요할 때 서버에 제공한다.

**토큰의 작동 원리:**

토큰은 특정 데이터가 암호화된 문자열로, 특정 알고리즘과 프라이빗 키에 의해 생성된다.

서버는 이 프라이빗 키를 사용하여 토큰의 유효성을 검증할 수 있다.

토큰은 클라이언트에게 발급되어 안전한 저장소(쿠키 또는 로컬 스토리지)에 저장되며,

클라이언트가 서버에 요청을 보낼 때 토큰이 함께 전송되어 서버가 해당 사용자를 인증한다.

토큰은 무결성을 보장하고, 사용자가 변경하거나 위조할 수 없도록 설계되어 있다.

**SPA에서의 인증 원리:**

싱글 페이지 애플리케이션에서는 세션을 사용하는 전통적인 방식이 아닌 토큰 기반의 인증 체계가 사용된다.

프론트엔드에서는 로그인 후에 발급받은 토큰을 안전한 위치에 저장하고,

서버에 요청을 보낼 때 토큰을 함께 전송하여 인증을 수행한다. 이로써 클라이언트와 서버는 느슨하게 연결되어 있으며,

효과적으로 사용자를 식별하고 인증할 수 있다.
```

# 사용자 비밀번호 해싱하기

```jsx
// users-controllers.js

const { v4: uuid } = require('uuid')
const { validationResult } = require('express-validator')
const bcrypt = require('bcryptjs')

const HttpError = require('../models/http-error')
const User = require('../models/user')

// 유저 목록 조회
const getUsers = async (req, res, next) => {
  let users
  try {
    // 데이터베이스에서 모든 사용자 정보를 불러옴 (비밀번호 제외)
    users = await User.find({}, '-password')
  } catch (err) {
    // 에러 발생 시 500 상태코드로 에러 응답
    const error = new HttpError('유저 정보를 불러오지 못했습니다', 500)
    return next(error)
  }
  res.json(users)
}

// 회원가입
const signup = async (req, res, next) => {
  const errors = validationResult(req)
  if (!errors.isEmpty()) {
    // 유효성 검사 에러가 있을 경우, 해당 에러를 422 상태코드로 응답
    const error = new HttpError(`${errors.errors[0].path}는 비어있을 수 없습니다`, 422)
    return next(error)
  }

  const { name, email, password } = req.body

  let existingUser
  try {
    // 이메일 중복 체크
    existingUser = await User.findOne({ email: email })
  } catch (err) {
    // 에러 발생 시 500 상태코드로 에러 응답
    const error = new HttpError('회원가입 실패', 500)
    return next(error)
  }

  if (existingUser) {
    // 중복된 이메일이 이미 존재할 경우, 422 상태코드로 에러 응답
    const error = new HttpError('이미 유저가 있습니다.', 422)
    return next(error)
  }

  let hashedPassword
  try {
    // 비밀번호 암호화
    hashedPassword = await bcrypt.hash(password, 12)
  } catch (err) {
    // 암호화 중 에러 발생 시, 500 상태코드로 에러 응답
    const error = new HttpError('사용자를 생성하지 못했습니다', 500)
    return next(error)
  }

  const createdUser = new User({
    name,
    email,
    image: req.file.path,
    password: hashedPassword,
    places: [],
  })

  try {
    // 새로운 사용자 정보 저장
    await createdUser.save()
  } catch (err) {
    // 저장 중 에러 발생 시, 500 상태코드로 에러 응답
    const error = new HttpError('회원 저장에 오류가 발생했습니다', 500)
    return next(error)
  }

  // 회원가입 성공 시, 201 상태코드로 응답
  res.status(201).json({ user: createdUser })
}

// 로그인
const login = async (req, res, next) => {
  const { email, password } = req.body

  let existingUser
  try {
    // 이메일로 사용자 찾기
    existingUser = await User.findOne({ email: email })
  } catch (err) {
    // 조회 중 에러 발생 시, 500 상태코드로 에러 응답
    const error = new HttpError('로그인 실패', 500)
    return next(error)
  }

  if (!existingUser || existingUser.password !== password) {
    // 사용자가 없거나 비밀번호가 일치하지 않을 경우, 401 상태코드로 에러 응답
    const error = new HttpError('유저 정보가 틀립니다', 401)
    return next(error)
  }

  // 로그인 성공 시, 성공 메시지와 사용자 정보를 JSON 형태로 응답
  res.json({ message: '로그인 성공', user: existingUser })
}

// 모듈 내보내기
exports.getUsers = getUsers
exports.signup = signup
exports.login = login
```

```jsx
    existingUser = await User.findOne({ email: email })
  } catch (err) {
    // 조회 중 에러 발생 시, 500 상태코드로 에러 응답
    const error = new HttpError('로그인 실패', 500)
    return next(error)
  }

  if (!existingUser) {
    // 사용자가 없거나 비밀번호가 일치하지 않을 경우, 401 상태코드로 에러 응답
    const error = new HttpError('유저 정보가 틀립니다', 401)
    return next(error)
  }

  let isValidPassword = false
  try {
    // 해시된 비밀번호 비교
    isValidPassword = await bcrypt.compare(password, existingUser.password)
  } catch (err) {
    // 해시 비교 중 에러 발생 시, 500 상태코드로 에러 응답
    const error = new HttpError('해싱 암호를 비교하는데 실패 했습니다', 500)
    return next(error)
  }

  if (!isValidPassword) {
    // 비밀번호 불일치 시, 401 상태코드로 에러 응답
    const error = new HttpError('유저 정보가 틀립니다', 401)
    return next(error)
  }

  let token
  try {
    token = jwt.sign({ userId: existingUser._id, email: existingUser.email }, 'secretKey', {
      expiresIn: '1h',
    })
  } catch (err) {
    const error = new HttpError('토큰 생성에 실패하였습니다', 500)
    return next(error)
  }

  // 로그인 성공 시, 성공 메시지와 사용자 정보를 JSON 형태로 응답
  res.status(201).json({
    userId: existingUser._id,
    email: existingUser.email,
    token: token,
  })
}

// 모듈 내보내기
exports.getUsers = getUsers
exports.signup = signup
exports.login = login
```

```jsx
const jwt = require('jsonwebtoken')
const HttpError = require('../models/http-error')

// 토큰 검증 미들웨어
module.exports = (req, res, next) => {
  // 1. 요청 헤더에서 토큰 추출
  const token = req.headers.authorization.split(' '[1])

  try {
    // 2. 토큰이 존재하지 않으면 에러 발생
    if (!token) {
      throw new Error('인증 실패')
    }

    // 3. 토큰 검증
    const decodedToken = jwt.verify(token, 'secretKey')

    // 4. 검증이 성공하면 사용자 데이터를 요청 객체에 추가
    req.userData = { userId: decodedToken.userId }

    // 5. 다음 미들웨어로 진행
    next()
  } catch (err) {
    // 6. 토큰 검증 실패 시 401 상태코드와 함께 에러 응답
    const error = new HttpError('인증 실패', 401)
    return next(error)
  }
}
```

```jsx
**요청 헤더에서 Authorization 헤더를 찾고, 해당 헤더의 값을 공백을 기준으로 나누어 토큰을 추출한다:**

클라이언트에서 서버로 요청을 보낼 때, 보통 토큰은 Authorization 헤더에 담겨져 전송된다.

일반적으로 HTTP의 Authorization 헤더에서 사용되는 토큰의 형식이 "Bearer 토큰값"이기 때문이다.

예를 들어, Authorization 헤더에

"Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6Ik"와 같이 전송될 수 있다.

이 경우 "Bearer"는 토큰 타입을 나타내는 문자열이고, 실제 토큰은 뒤에 이어지는 문자열이다.

split(' ')을 사용하면 공백을 기준으로 문자열을 나눠 배열로 만들게 되는데,

이때 배열의 첫 번째 요소(인덱스 0)에는 "Bearer"와 같은 토큰 타입이 들어가게 딘다.

따라서 실제 토큰은 두 번째 요소(인덱스 1)에 위치하게 되므로 이를 추출하여 사용하는 것이다.

**토큰이 존재하지 않으면 "인증 실패"라는 에러를 발생시킨다:**

얻어온 토큰이 존재하지 않으면, 즉 Authorization 헤더가 부적절하게 전송되었거나 토큰이 누락된 경우, 에러를 발생시킨다.

throw new Error("인증 실패")를 통해 "인증 실패"라는 에러를 생성한다.

**jwt 패키지를 사용하여 토큰을 검증한다:**

jwt.verify(token, 'secretKey')를 통해 받아온 토큰을 서버에서 사용한 시크릿 키를 이용하여 검증한다.

토큰의 유효성을 확인하는 과정으로, 검증이 성공하면 다음 단계로 진행한다.

**검증이 성공하면 사용자 데이터를 요청 객체에 추가한다:**

jwt.verify()에서 반환한 decodedToken에는 토큰에 담긴 정보가 들어있다. ( 토큰발급때 담은 값 )

여기서는 사용자 ID를 추출하여 req.userData에 저장한다. 이 정보는 뒷 단계에서 다루어질 보호된 라우트에서 활용된다.

**검증이 성공하면 다음 미들웨어로 진행한다:**

토큰의 검증이 성공하면, 즉 유효한 토큰이라면 다음 미들웨어로 넘어간다.

이 부분에서는 더 이상의 검증이 필요하지 않으므로 다음 단계로 흐름이 이어진다.

**토큰 검증 실패 시 401 상태코드와 함께 "인증 실패"라는 에러를 생성하고, 다음 미들웨어에 에러를 전달하여 처리한다:**

토큰 검증이 실패한 경우, 즉 유효하지 않거나 변조된 토큰인 경우, 401 상태코드와 함께 "인증 실패" 에러를 생성한다.

이 에러는 다음 미들웨어에 전달되어, 예외처리 미들웨어나 에러 핸들러에서 처리할 수 있다.

클라이언트에게 적절한 오류 응답이 전달된다.
```

## Authorization: Bearer ${auth.token} 헤더를 추가하는 이유

```jsx
Authorization:

Bearer ${auth.token} 헤더를 추가하는 이유는 주로 사용자 인증을 위한 토큰을 서버로 전달하기 위함이다.

여기서 Bearer는 토큰의 유형을 나타내는 표준화된 방법 중 하나이다.

인증 및 보안:

대부분의 웹 애플리케이션은 사용자를 인증하고 보안을 강화하기 위해 토큰 기반의 인증 시스템을 사용한다.

사용자가 로그인하면 서버에서는 유효한 사용자에게 토큰을 발급하고, 이 토큰은 사용자가 인증된 상태를 유지하는 데 사용된다.

토큰의 종류:

Bearer 토큰은 OAuth 2.0 및 JSON Web Token (JWT)과 같은 보안 표준에서 사용되는 일반적인 방식 중 하나이다.

토큰의 유형을 명시하기 위해 Authorization 헤더에 Bearer를 사용한다.

Bearer 토큰 구성:

Bearer 토큰은 일반적으로 Bearer 다음에 실제 토큰이 붙어 있다.

예를 들어, Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...와 같이 헤더에 추가된다.

HTTP 헤더의 활용:

Authorization 헤더는 HTTP 요청에서 자주 사용되며, 서버에게 클라이언트가 특정 자격 증명(credential)을 가지고 있다고 알리는 역할을 한다.

Bearer 토큰을 Authorization 헤더에 추가하여 서버에게 현재 사용자의 인증 토큰을 제공한다.

토큰의 전송:

Bearer 토큰은 주로 HTTPS를 통해 안전하게 전송된다.

HTTPS를 사용하면 통신이 암호화되어 중간에서 토큰을 가로채는 공격을 방지할 수 있다.

장소 업데이트 요청에서의 활용:

위에서 제시한 코드는 장소를 업데이트하는 PATCH 요청을 서버에 보내기 위한 것이다.

이 때, 해당 장소에 대한 권한이 필요하며, 이 권한을 확인하기 위해 사용자의 토큰이 필요하다.

따라서 Authorization: Bearer ${auth.token} 헤더를 추가하여 현재 사용자의 토큰을 서버로 전달한다.

보안 강화:

헤더에 포함된 Bearer 토큰을 통해 서버는 해당 요청이 유효한 사용자에 의한 것임을 확인하고, 권한이 부여된 작업을 수행할 수 있다.

이렇게 함으로써 헤더에 Bearer 토큰을 추가하여 보안적인 측면을 강화하고, 서버가 요청을 올바르게 처리할 수 있도록 한다.
```

```jsx
// check-auth.js

const jwt = require('jsonwebtoken')
const HttpError = require('../models/http-error')

// 토큰 검증 미들웨어
module.exports = (req, res, next) => {
  if (req.method === 'OPTIONS') {
    return next()
  }

  // 1. 요청 헤더에서 토큰 추출
  const token = req.headers.authorization.split(' ')[1]

  try {
    // 2. 토큰이 존재하지 않으면 에러 발생
    if (!token) {
      throw new Error('인증 실패')
    }

    // 3. 토큰 검증
    const decodedToken = jwt.verify(token, 'secretKey')

    // 4. 검증이 성공하면 사용자 데이터를 요청 객체에 추가
    req.userData = { userId: decodedToken.userId }

    // 5. 다음 미들웨어로 진행
    next()
  } catch (err) {
    // 6. 토큰 검증 실패 시 401 상태코드와 함께 에러 응답
    const error = new HttpError('인증 실패', 401)
    return next(error)
  }
}
```

## **OPTIONS 요청이란?**

```jsx
OPTIONS는 HTTP 프로토콜에서 제공하는 메서드 중 하나로, 클라이언트가 서버에게 어떠한 요청이 가능한지를 확인하기 위한 메서드이다.

이 메서드는 주로 사전 검사(preflight) 요청에서 사용되며, 브라우저에서 자동으로 생성된다.

사전 검사 (Preflight) 요청:

클라이언트에서 실제 요청을 보내기 전에 서버에게 해당 요청이 안전하고 허용되는지 미리 확인하기 위해 사용된다.

브라우저는 본격적인 요청을 보내기 전에 OPTIONS 메서드를 사용하여 사전 검사 요청을 전송한다.

목적:

서버가 특정 리소스에 대한 요청을 수락할지, 어떤 메서드를 사용할 수 있는지, 어떤 헤더를 사용할 수 있는지 등을 확인하는 데 사용된다.

실제 데이터를 보내기 전에 서버와 클라이언트 간의 통신이 안전하게 이루어질 수 있는지 사전에 확인한다.

헤더 필드:

OPTIONS 요청은 일반적으로 Access-Control-Request-Method 및 Access-Control-Request-Headers 헤더를 포함한다.

Access-Control-Request-Method: 실제 요청에서 사용될 메서드를 서버에게 알린다.

Access-Control-Request-Headers: 실제 요청에서 사용될 헤더를 서버에게 알린다.

응답:

서버는 OPTIONS 요청에 대한 응답으로 Access-Control-Allow-Methods 및 Access-Control-Allow-Headers 헤더를 포함하여 허용되는 메서드 및 헤더를 클라이언트에게 알린다.

이를 통해 브라우저는 실제 요청을 전송하기 전에 서버의 허용 여부를 확인하고 안전한 CORS (Cross-Origin Resource Sharing) 통신을 보장한다.

인증 필요 없음:

OPTIONS 요청은 주로 사전 검사를 위한 것이므로, 이 요청에는 일반적으로 인증이 필요하지 않다.

따라서 인증 헤더를 포함하지 않고 서버에게 허용된지 여부만을 확인한다.

서버 처리:

서버는 OPTIONS 요청을 받으면 헤더 정보를 확인하고 클라이언트의 요청이 허용되는지 여부를 결정한다.

서버에서는 특별한 처리가 필요 없는 경우, 간단히 200 OK 응답을 보내고 허용되는 메서드 및 헤더 정보를 헤더에 포함시켜 응답한다.

CORS (Cross-Origin Resource Sharing):

OPTIONS 요청은 주로 CORS에서 중요한 역할을 합니다.

클라이언트가 서로 다른 도메인에서 리소스를 요청할 때 브라우저는 OPTIONS를 통해 사전 검사를 수행하여 안전한 교차 출처 통신을 유지한다.

이러한 방식으로 OPTIONS 요청은 브라우저와 서버 간의 통신을 안전하게 하기 위한 사전 검사 단계로 활용되며,

CORS와 함께 사용되어 웹 애플리케이션 간의 안전한 데이터 교환을 가능하게 한다.
```

```jsx
      password: {
        value: '',
        isValid: false,
      },
    },
    false
  )

  // 로그인 및 회원 가입 모드 전환
  const switchModeHandler = () => {
    if (!isLoginMode) {
      // 회원 가입 모드에서 로그인 모드로 전환 시, 이름 입력 필드 추가
      setFormData(
        {
          ...formState.inputs,
          name: undefined,
          image: undefined,
        },
        formState.inputs.email.isValid && formState.inputs.password.isValid
      )
    } else {
      // 로그인 모드에서 회원 가입 모드로 전환 시, 이름 입력 필드 제거
      setFormData(
        {
          ...formState.inputs,
          name: {
            value: '',
            isValid: false,
          },
          image: {
            value: null,
            isValid: false,
          },
        },
        false
      )
    }
    setIsLoginMode((prevMode) => !prevMode)
  }

  // 로그인 또는 회원 가입 시도
  const authSubmitHandler = async (event) => {
    event.preventDefault()

    if (isLoginMode) {
      // 로그인 모드일 때
      try {
        const responseData = await sendRequest(
          'http://localhost:5000/api/users/login',
          'POST',
          JSON.stringify({
            email: formState.inputs.email.value,
            password: formState.inputs.password.value,
          }),
          {
            'Content-Type': 'application/json',
          }
        )
        console.log(responseData)
        auth.login(responseData.userId, responseData.token)
        navigate('/')
      } catch (error) {
        // 오류 발생 시
        console.error('Login Error:', error)
      }
    } else {
      // 회원 가입 모드일 때
      try {
        const formData = new FormData()
        formData.append('name', formState.inputs.name.value)
        formData.append('email', formState.inputs.email.value)
        formData.append('password', formState.inputs.password.value)
        formData.append('image', formState.inputs.image.value)

        const responseData = await sendRequest(
          'http://localhost:5000/api/users/signup',
          'POST',
          formData
        )
        auth.login(responseData.userId, responseData.token)
        navigate('/')
      } catch (error) {
        // 오류 발생 시
      }
    }
  }

  return (
    <>
      {/* HTTP 요청 오류를 표시하는 모달 및 로딩 스피너 */}
      <ErrorModal error={error} onClear={clearError} />
      {isLoading && <LoadingSpinner asOverlay />}

      {/* 로그인/회원 가입 양식 */}
      <Card className="authentication">
        <h1>Login Required</h1>
        <hr />

        {/* 로그인/회원 가입 양식 */}
        <form onSubmit={authSubmitHandler}>
          {/* 회원 가입 모드에서만 보이는 이름 입력 필드 */}
          {!isLoginMode && (
            <Input
              element="input"
              id="name"
              type="text"
              label="Name"
              validators={[VALIDATOR_REQUIRE()]}
              errorText="Please enter a name"
              onInput={inputHandler}
            />
          )}
          {!isLoginMode && <ImageUpload center id="image" onInput={inputHandler} />}

          {/* 이메일 및 비밀번호 입력 필드 */}
          <Input
            element="input"
            id="email"
            type="email"
            label="E-Mail"
            validators={[VALIDATOR_EMAIL()]}
            errorText="Please enter a valid email address."
            onInput={inputHandler}
          />
          <Input
            element="input"
            id="password"
            type="password"
            label="Password"
            validators={[VALIDATOR_MINLENGTH(6)]}
            errorText="Please enter a valid password at least 5 Ch."
            onInput={inputHandler}
          />

          {/* 로그인/회원 가입 버튼 */}
          <Button type="submit" disabled={!formState.isValid}>
            {isLoginMode ? 'LOGIN' : 'SIGNUP'}
          </Button>
        </form>

        {/* 로그인/회원 가입 모드 전환 버튼 */}
        <Button inverse onClick={switchModeHandler}>
          SWITCH TO {isLoginMode ? 'SIGNUP' : 'LOGIN'}
        </Button>
      </Card>
    </>
  )
}

export default Auth
```

```jsx
  // AuthContext에서 사용자 정보를 가져옴

  // useHttpClient 훅을 통해 로딩 상태 및 에러 처리에 관련된 함수들을 가져옴
  const { isLoading, error, sendRequest, clearError } = useHttpClient()

  const [loadedPlaces, setLoadedPlaces] = useState()

  // URL 파라미터에서 placeId 추출
  const placeId = useParams().placeId

  // useForm 훅을 사용하여 양식 상태 및 관련 함수 초기화
  const [formState, inputHandler, setFormData] = useForm(
    {
      title: {
        value: '',
        isValid: false,
      },
      description: {
        value: '',
        isValid: false,
      },
    },
    false
  )

  // useEffect를 사용하여 페이지 로딩 시 특정 장소의 데이터를 가져오는 비동기 함수 호출
  useEffect(() => {

      try {
        // sendRequest 함수를 사용하여 특정 장소의 데이터 가져오기
        const responseData = await sendRequest(`http://localhost:5000/api/places/${placeId}`)

        // 가져온 데이터로 loadedPlaces state 업데이트

        // 가져온 데이터를 사용하여 폼 데이터 업데이트

          {
            title: {
              value: responseData.places.title,
              isValid: true,
            },
            description: {
              value: responseData.places.description,
              isValid: true,
            },
          },
          true
        )
      } catch (error) {
        // 오류 발생 시 처리
      }
    }

    // 페이지 로딩 시 fetchPlaces 함수 호출
    fetchPlaces()
  }, [sendRequest, placeId, setFormData])

  // 장소 업데이트를 위한 submit 핸들러
  const placeUpdateSubmitHandler = async (event) => {
    event.preventDefault()
    try {
      // sendRequest 함수를 사용하여 장소 업데이트 요청 보내기
      await sendRequest(
        `http://localhost:5000/api/places/${placeId}`,
        'PATCH',
        JSON.stringify({
          title: formState.inputs.title.value,
          description: formState.inputs.description.value,
        }),
        {
          'Content-Type': 'application/json',
          Authorization: 'Bearer ' + auth.token,
        }
      )

      // 업데이트 성공 시 사용자를 해당 사용자의 장소 개요 페이지로 리디렉션
      navigate('/' + auth.userId + '/places')
    } catch (error) {
      // 오류 발생 시 처리
    }
  }

  // 로딩 중일 때 LoadingSpinner 출력
  if (isLoading) {
    return (
      <div className="center">
        <LoadingSpinner />
      </div>
    )
  }

  // 로드된 장소가 없고 오류가 없을 때 Card 컴포넌트를 사용한 메시지 출력
  if (!loadedPlaces && !error) {
    return (
      <div className="center">
        <Card>
          <h2>Could not find place!</h2>
        </Card>
      </div>
    )
  }

  // 오류가 있을 때 ErrorModal 출력
  return (
    <>
      <ErrorModal error={error} onClear={clearError} />
      {/* 로딩 중이 아니고 로드된 장소가 있을 때 양식 렌더링 */}
      {!isLoading && loadedPlaces && (

          {/* Input 컴포넌트를 사용하여 제목 입력란 렌더링 */}
          <Input
            id="title"
            element="input"
            type="text"
            label="Title"
            validators={[VALIDATOR_REQUIRE()]}
            errorText="Please enter a valid title."
            onInput={inputHandler}
            initialValue={loadedPlaces.title}
            initialValid={true}
          />
          {/* Input 컴포넌트를 사용하여 설명 입력란 렌더링 */}
          <Input
            id="description"
            element="textarea"
            label="Description"
            validators={[VALIDATOR_MINLENGTH(5)]}
            errorText="Please enter a valid description (min. 5 characters)."
            onInput={inputHandler}
            initialValue={loadedPlaces.description}
            initialValid={true}
          />
          {/* 장소 업데이트 버튼 */}
          <Button type="submit" disabled={!formState.isValid}>
            UPDATE PLACE
          </Button>
        </form>
      )}
    </>
  )
}

export default UpdatePlace
```

## **헤더(Header)란 무엇인가요?**

```jsx
헤더는 컴퓨터 과학 및 웹 개발에서 중요한 개념 중 하나로,

데이터의 시작 부분에 위치하는 정보를 포함하는 부분을 가리킨다.

특히, HTTP 헤더는 웹 브라우저와 웹 서버 간에 이루어지는 통신에서 메타데이터 및 추가 정보를 전송하기 위해 사용된다.
```

```jsx
HTTP 헤더의 주요 역할:

통신 제어:

헤더는 클라이언트와 서버 간의 통신 방식 및 프로토콜을 제어한다.

예를 들어, Content-Type 헤더는 전송되는 데이터의 유형을 지정하며, Content-Length 헤더는 전송되는 데이터의 크기를 나타낸다.

캐싱 및 유효성 검사:

Cache-Control 및 ETag 헤더는 캐싱과 관련된 정보를 전달한다.

클라이언트는 이 정보를 기반으로 캐시를 활용하거나 다시 검색한다.

인증 및 권한 부여:

Authorization 헤더는 클라이언트의 인증 정보를 전송하고,

서버는 이를 확인하여 접근 권한을 결정한다.

사용자 에이전트 정보: User-Agent 헤더는 클라이언트의 브라우저나 애플리케이션 정보를 전송한다.

이를 통해 서버는 적절한 콘텐츠를 제공하거나 최적화된 경험을 제공할 수 있다.

리다이렉션 및 위치 지정: Location 헤더는 리다이렉션 시 새로운 위치를 알려주며,

클라이언트는 이를 통해 다시 지정된 위치로 이동한다.
```

```jsx
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
Content-Length: 123
Date: Wed, 02 Feb 2024 12:34:56 GMT
Server: Apache

위 예시에서 Content-Type, Content-Length, Date, Server 등이 헤더의 일부로,

각각 데이터의 유형, 크기, 전송 날짜, 사용된 서버 등의 정보를 제공한다.
```

```jsx
// places-controllers.js

const { v4: uuid } = require('uuid')
const { validationResult } = require('express-validator')
const fs = require('fs')

// HttpError 모델을 불러와 사용합니다.
const HttpError = require('../models/http-error')
const getCoordsForAddress = require('../util/location')
const Place = require('../models/places')
const User = require('../models/user')
const { default: mongoose } = require('mongoose')

// 특정 장소 ID에 대한 정보를 반환하는 함수입니다.
const getPlacesById = async (req, res, next) => {
  // 요청 파라미터에서 장소 ID를 추출합니다.
  const placeId = req.params.pid

  let places

  try {
    places = await Place.findById(placeId)
  } catch (err) {
    const error = new HttpError('오류발생 장소를 찾지 못했습니다', 500)
    return next(error)
  }

  // 만약 장소를 찾지 못했다면 HttpError를 발생시키지 않고, next 함수를 통해 에러를 전달합니다.
  if (!places) {
    const error = new HttpError('유효한 장소 아이디를 찾지 못했습니다', 404)
    return next(error)
  }

  // 찾은 장소를 JSON 형태로 응답합니다.
  res.json({ places: places.toObject({ getters: true }) })
}

// 특정 사용자 ID에 대한 장소 정보를 반환하는 함수입니다.
const getPlaceByUserId = async (req, res, next) => {
  // 요청 파라미터에서 사용자 ID를 추출합니다.
  const userId = req.params.uid

  // let place;
  let userWithPlaces
  try {
    userWithPlaces = await User.findById(userId).populate('places')
  } catch (err) {
    const error = new HttpError('장소를 불러오는데 실패했습니다', 500)
    return next(error)
  }

  // 만약 사용자를 찾지 못했다면 HttpError를 발생시킵니다.
  if (!userWithPlaces) {
    return next(new HttpError('유저를 찾을 수 없습니다', 404))
  }

  // 찾은 장소를 JSON 형태로 응답합니다.
  res.json({ places: userWithPlaces.places.map((place) => place.toObject({ getters: true })) })
}

const createPlace = async (req, res, next) => {
  // express-validator를 사용하여 요청의 유효성을 검사합니다.
  const errors = validationResult(req)
  if (!errors.isEmpty()) {
    console.log(errors)
    // 에러가 배열로 나와서 첫 번째 인덱스의 경로를 사용하여 클라이언트에게 에러를 전달합니다.
    next(new HttpError(`${errors.errors[0].path}는 비어있을 수 없습니다`, 422))
  }

  // 요청에서 필요한 데이터를 추출합니다.
  const { title, description, address, creator } = req.body

  let coordinates

  try {
    // 주소를 좌표로 변환하는 유틸리티 함수를 사용하여 좌표를 얻습니다.
    coordinates = await getCoordsForAddress(address)
  } catch (error) {
    // 좌표 얻기가 실패하면 에러를 핸들링하여 다음 미들웨어로 전달합니다.
    return next(error)
  }

  // 새로운 장소 객체를 생성합니다.
  const createPlace = new Place({
    title,
    description,
    address,
    location: coordinates, // 얻은 좌표 정보를 사용하여 새로운 장소의 위치를 설정합니다.
    image: req.file.path,
    creator,
  })

  let user
  try {
    // 생성자(creator) ID를 사용하여 해당 사용자를 데이터베이스에서 찾습니다.
    user = await User.findById(creator)
  } catch (err) {
    const error = new HttpError('새로운 장소 추가에 실패 했습니다', 500)
    return next(error)
  }

  // 찾은 사용자가 없을 경우 에러를 생성하여 핸들링합니다.
  if (!user) {
    const error = new HttpError('제공된 ID의 유저를 찾을 수 없습니다', 404)
    return next(error)
  }

  try {
    // Mongoose 세션을 시작하고 트랜잭션을 시작합니다.
    const sess = await mongoose.startSession()
    sess.startTransaction()

    // 새로운 장소를 데이터베이스에 저장합니다.
    await createPlace.save({ session: sess })

    // 사용자 문서에 새로운 장소의 ID를 추가합니다.
    user.places.push(createPlace)
    await user.save({ session: sess })

    // 트랜잭션을 커밋합니다.
    await sess.commitTransaction()
  } catch (err) {
    console.log(err)
    const error = new HttpError('새 장소 추가 실패', 500)
    // 저장 중에 에러가 발생하면 500 상태 코드와 함께 에러를 생성합니다.
    return next(error)
  }

  // 클라이언트에게 성공적인 응답을 전송합니다.
  res.status(201).json({ place: createPlace })
}

const updatePlaceById = async (req, res, next) => {
  const errors = validationResult(req)
  if (!errors.isEmpty()) {
    console.log(errors)
    throw new HttpError(`${errors.errors[0].path}는 비어있을 수 없습니다`, 422)
  }
  // 요청에서 필요한 데이터를 추출합니다.
  const { title, description } = req.body
  const placeId = req.params.pid

  let place
  try {
    place = await Place.findById(placeId)
  } catch (err) {
    const error = new HttpError('업데이트 실패', 500)
    return next(error)
  }

  if (place.creator.toString() !== req.userData.userId) {
    const error = new HttpError('장소를 수정할 권한이 없습니다.', 401)
    return next(error)
  }

  place.title = title
  place.description = description

  try {
    await place.save()
  } catch (err) {
    const error = new HttpError('문제가 발생하였습니다 업데이트 할 수 없습니다', 500)
    return next(error)
  }

  // 클라이언트에게 업데이트된 장소 정보를 응답합니다.
  res.status(200).json({ place: place })
}

const deletePlaceById = async (req, res, next) => {
  // 요청 파라미터에서 장소의 ID를 가져옵니다.
  const placeId = req.params.pid
  let place

  // 장소를 찾아서 해당 ID로 검색한 결과를 가져옵니다.
  try {
    place = await Place.findById(placeId).populate('creator')
  } catch (err) {
    // 에러가 발생하면 500 상태 코드와 함께 에러 메시지를 반환합니다.
    const error = new HttpError('문제발생 삭제에 실패했습니다', 500)
    return next(error)
  }

  // 검색된 장소가 없으면 404 상태 코드와 함께 에러 메시지를 반환합니다.
  if (!place) {
    const error = new HttpError('장소 id 를 찾지 못하였습니다', 404)
    return next(error)
  }

  // 이미지 주소 가져오기 (req.file.path 로 이미지 주소 들어가 있음)
  const imagePath = place.image

  // MongoDB 세션을 사용하여 트랜잭션을 시작합니다.
  try {
    const sess = await mongoose.startSession()
    sess.startTransaction()

    // 검색된 장소를 삭제합니다.
    await place.deleteOne({ session: sess })

    // 해당 장소를 생성한 사용자의 데이터에서 해당 장소를 제거합니다.
    place.creator.places.pull(place)

    // 수정된 사용자 데이터를 저장합니다.
    await place.creator.save({ session: sess })

    // 트랜잭션을 커밋하여 변경 사항을 영구적으로 반영합니다.
    await sess.commitTransaction()
  } catch (err) {
    // 트랜잭션 도중 에러가 발생하면 500 상태 코드와 함께 에러 메시지를 반환합니다.
    const error = new HttpError('삭제에 실패했습니다', 500)
    return next(error)
  }

  fs.unlink(imagePath, (err) => {
    console.log(err)
  })

  // 모든 작업이 성공적으로 완료되면 200 상태 코드와 함께 성공 메시지를 반환합니다.
  res.status(200).json({ message: '삭제성공' })
```
```jsx
}

place.creator.toString():

place 객체의 creator 속성은 MongoDB에서 ObjectId 형태로 저장되어 있다.

이를 toString() 메서드를 사용하여 문자열로 변환한다. 이렇게 하면 사용자 ID를 문자열로 얻을 수 있다.

req.userData.userId:

현재 로그인한 사용자의 ID가 저장된 userData 객체에서 userId를 가져온다.

if(place.creator.toString() !== req.userData.userId):

위에서 얻은 두 사용자 ID를 비교한다. 만약 둘이 다르다면,

현재 로그인한 사용자가 해당 장소의 생성자가 아니므로 권한이 없다는 의미이다.
```

```jsx
문제 식별:

로그인 후 페이지를 새로 고치면 로그아웃되는 문제를 확인.

문제 원인:

새로 고침으로 인해 React 애플리케이션이 재시작되며, 상태가 메모리에만 저장되기 때문에 토큰이 사라지는 것이 원인.

토큰 저장 위치 선정:

Local Storage를 사용하여 토큰을 브라우저에 저장하기로 결정.

Local Storage는 쉬운 JavaScript 액세스와 데이터 보존이 가능하며, 앱이 다시 시작되어도 유지됨.

Local Storage 활용:

토큰 및 사용자 데이터를 JSON 형식으로 Local Storage에 저장. 이를 통해 새로 고쳐도 유지되는 설정을 구현.

토큰 및 사용자 데이터 저장:

	* 로그인 후 데이터 저장 시점:

	사용자가 로그인에 성공하면, 서버에서 받은 토큰과 사용자 관련 데이터(예: userId)를 로컬 스토리지에 저장해야 한다.


	* Local Storage의 userData 엔트리:

	설명: Local Storage는 브라우저에 데이터를 영구적으로 저장할 수 있는 메커니즘 중 하나이다.

	이름 선택: userData로 명명한 것은 해당 데이터가 사용자와 관련이 있고, 토큰 및 사용자 데이터를 함께 저장하기 위함이다.


	* 데이터 저장 방법:

	localStorage.setItem('userData', JSON.stringify({ token, userId })) 코드를 사용하여 데이터를 저장한다.

	localStorage.setItem 메서드는 로컬 스토리지에 데이터를 설정하는 메서드이다.

	'userData'는 저장할 데이터의 키이다.


	* JSON.stringify 활용:

	목적: 로컬 스토리지에는 텍스트 데이터만 저장할 수 있다.

	해결책: JSON.stringify를 사용하여 JavaScript 객체를 JSON 문자열로 변환한다.

	예시: { token, userId } 객체가 JSON 형식의 문자열로 변환되어 저장된다.


	* 저장된 데이터 예시:

	만약 토큰이 'abc123'이고 userId가 'user123'이라면, 저장된 데이터는 다음과 같을 것이다: { "token": "abc123", "userId": "user123" }


	* 새로 고침 시 데이터 유지:

	이렇게 저장된 데이터는 페이지를 새로 고침해도 유지된다. 따라서 애플리케이션을 다시 시작할 때마다 로그인 상태가 유지된다.


	* 보안 주의사항:

	민감한 정보(예: 비밀번호)는 로컬 스토리지에 저장하지 않아야 한다.

	토큰은 세션 관리 용도로 사용되므로 비밀번호와 같은 민감한 정보를 저장하지 않는 것이 안전하다.

보안 고려 사항: 크로스 사이트 스크립팅에 취약한 문제는 React의 내장된 안전장치로 충분하게 대응 가능하며,

토큰이나 사용자 정보를 도용하는 것은 해당 앱의 기본적인 보안 문제.

( React 애플리케이션은 XSS에 취약할 수 있지만, React는 크로스 사이트 스크립팅 공격에 대응하기 위한 안전장치를 갖추고 있다 )
```

```jsx
a. **토큰 만료 시간 설정**

    - `login` 함수 내에서 토큰의 만료 시간을 1시간으로 설정.

		- `tokenExpirationDate` 변수에 현재 시각에 1시간을 더한 시간을 저장.

		- `expiration` 키를 추가하여 `tokenExpirationDate`를 ISO 문자열로 변환하여 저장.

		toISOString() 메서드는 JavaScript의 Date 객체를 ISO 8601 형식의 문자열로 변환한다.

    ISO 8601 형식은 날짜와 시간을 표현하는 국제 표준이며, 날짜와 시간 정보를 안전하게 저장하고 전송할 수 있는 형태로 정의되어 있다.

    간단히 말해, toISOString()을 사용하면 Date 객체의 날짜와 시간 정보를 표준화된 문자열 형식으로 변환할 수 있다

	  ( YYYY-MM-DDTHH:mm:ss.sssZ )

		YYYY: 연도 (4자리)
		MM: 월 (01부터 12까지)
		DD: 일 (01부터 31까지)
		T: 날짜와 시간을 구분하는 문자
		HH: 시간 (00부터 23까지)
		mm: 분 (00부터 59까지)
		ss: 초 (00부터 59까지)
		sss: 밀리초 (000부터 999까지)
		Z: Zulu 시간, UTC를 나타냄

    setUserId(userId);
```

```jsx
useAuth라는 커스텀 훅을 만들고, 필요한 라이브러리(react)와 변수(useState, useCallback, useEffect)를 import 한다.

logoutTimer를 파일 상단에 선언한다.

2. Auth-hook 내부 구현:

useAuth 함수 내부에서, useState를 사용하여 token, tokenExpirationDate, userId 상태를 관리한다.

login 함수는 userId, token, expirationDate를 받아와 상태를 업데이트하고, localStorage에 사용자 데이터를 저장한다.

logout 함수는 상태를 초기화하고 localStorage에서 사용자 데이터를 삭제한다.

useEffect를 활용하여 자동 로그아웃 및 자동 로그인 처리를 구현한다.

3. Auth-hook의 반환값 설정:

useAuth 함수는 { token, login, logout, userId } 객체를 반환한다.

4. App.js에서 Auth-hook 사용:

useAuth를 import하고, 해당 훅을 호출하여 반환된 객체를 구조 분해하여 사용한다.

기존의 로그인, 로그아웃 관련 로직을 삭제하고, useAuth에서 얻은 token, login, logout, userId를 사용한다.
```

```jsx
const createPlace = async (req, res, next) => {
  // express-validator를 사용하여 요청의 유효성을 검사합니다.
  const errors = validationResult(req)
  if (!errors.isEmpty()) {
    console.log(errors)
    // 에러가 배열로 나와서 첫 번째 인덱스의 경로를 사용하여 클라이언트에게 에러를 전달합니다.
    next(new HttpError(`${errors.errors[0].path}는 비어있을 수 없습니다`, 422))
  }

  // 요청에서 필요한 데이터를 추출합니다.
  const { title, description, address } = req.body

  let coordinates

  try {
    // 주소를 좌표로 변환하는 유틸리티 함수를 사용하여 좌표를 얻습니다.
    coordinates = await getCoordsForAddress(address)
  } catch (error) {
    // 좌표 얻기가 실패하면 에러를 핸들링하여 다음 미들웨어로 전달합니다.
    return next(error)
  }

  // 새로운 장소 객체를 생성합니다.
  const createPlace = new Place({
    title,
    description,
    address,
    location: coordinates, // 얻은 좌표 정보를 사용하여 새로운 장소의 위치를 설정합니다.
    image: req.file.path,
    creator: req.userData.userId,
  })

  let user
  try {
    // 생성자(creator) ID를 사용하여 해당 사용자를 데이터베이스에서 찾습니다.
    user = await User.findById(creator)
  } catch (err) {
    const error = new HttpError('새로운 장소 추가에 실패 했습니다', 500)
    return next(error)
  }

  // 찾은 사용자가 없을 경우 에러를 생성하여 핸들링합니다.
  if (!user) {
    const error = new HttpError('제공된 ID의 유저를 찾을 수 없습니다', 404)
    return next(error)
  }

  try {
    // Mongoose 세션을 시작하고 트랜잭션을 시작합니다.
    const sess = await mongoose.startSession()
    sess.startTransaction()

    // 새로운 장소를 데이터베이스에 저장합니다.
    await createPlace.save({ session: sess })

    // 사용자 문서에 새로운 장소의 ID를 추가합니다.
    user.places.push(createPlace)
    await user.save({ session: sess })

    // 트랜잭션을 커밋합니다.
    await sess.commitTransaction()
  } catch (err) {
    console.log(err)
    const error = new HttpError('새 장소 추가 실패', 500)
    // 저장 중에 에러가 발생하면 500 상태 코드와 함께 에러를 생성합니다.
    return next(error)
  }

  // 클라이언트에게 성공적인 응답을 전송합니다.
  res.status(201).json({ place: createPlace })
}

const updatePlaceById = async (req, res, next) => {
  const errors = validationResult(req)
  if (!errors.isEmpty()) {
    console.log(errors)
    throw new HttpError(`${errors.errors[0].path}는 비어있을 수 없습니다`, 422)
  }
  // 요청에서 필요한 데이터를 추출합니다.
  const { title, description } = req.body
  const placeId = req.params.pid

  let place
  try {
    place = await Place.findById(placeId)
  } catch (err) {
    const error = new HttpError('업데이트 실패', 500)
    return next(error)
  }

  if (place.creator.toString() !== req.userData.userId) {
    const error = new HttpError('장소를 수정할 권한이 없습니다.', 401)
    return next(error)
  }

  place.title = title
  place.description = description

  try {
    await place.save()
  } catch (err) {
    const error = new HttpError('문제가 발생하였습니다 업데이트 할 수 없습니다', 500)
    return next(error)
  }

  // 클라이언트에게 업데이트된 장소 정보를 응답합니다.
  res.status(200).json({ place: place })
}

const deletePlaceById = async (req, res, next) => {
  // 요청 파라미터에서 장소의 ID를 가져옵니다.
  const placeId = req.params.pid
  let place

  // 장소를 찾아서 해당 ID로 검색한 결과를 가져옵니다.
  try {
    place = await Place.findById(placeId).populate('creator')
  } catch (err) {
    // 에러가 발생하면 500 상태 코드와 함께 에러 메시지를 반환합니다.
    const error = new HttpError('문제발생 삭제에 실패했습니다', 500)
    return next(error)
  }

  // 검색된 장소가 없으면 404 상태 코드와 함께 에러 메시지를 반환합니다.
  if (!place) {
    const error = new HttpError('장소 id 를 찾지 못하였습니다', 404)
    return next(error)
  }

  if (place.creator.id !== req.userData.userId) {
    const error = new HttpError('장소를 삭제할 권한이 없습니다.', 401)
    return next(error)
  }

  // 이미지 주소 가져오기 (req.file.path 로 이미지 주소 들어가 있음)
  const imagePath = place.image

  // MongoDB 세션을 사용하여 트랜잭션을 시작합니다.
  try {
    const sess = await mongoose.startSession()
    sess.startTransaction()

    // 검색된 장소를 삭제합니다.
    await place.deleteOne({ session: sess })

    // 해당 장소를 생성한 사용자의 데이터에서 해당 장소를 제거합니다.
    place.creator.places.pull(place)

    // 수정된 사용자 데이터를 저장합니다.
    await place.creator.save({ session: sess })

    // 트랜잭션을 커밋하여 변경 사항을 영구적으로 반영합니다.
    await sess.commitTransaction()
  } catch (err) {
    // 트랜잭션 도중 에러가 발생하면 500 상태 코드와 함께 에러 메시지를 반환합니다.
    const error = new HttpError('삭제에 실패했습니다', 500)
    return next(error)
  }

  fs.unlink(imagePath, (err) => {
    console.log(err)
  })

  // 모든 작업이 성공적으로 완료되면 200 상태 코드와 함께 성공 메시지를 반환합니다.
  res.status(200).json({ message: '삭제성공' })
}
```

```jsx
// check-auth.js

const jwt = require('jsonwebtoken')
const HttpError = require('../models/http-error')

// 토큰 검증 미들웨어
module.exports = (req, res, next) => {
  if (req.method === 'OPTIONS') {
    return next()
  }

  // 1. 요청 헤더에서 토큰 추출
  const token = req.headers.authorization.split(' ')[1]

  try {
    // 2. 토큰이 존재하지 않으면 에러 발생
    if (!token) {
      throw new Error('인증 실패')
    }

    // 3. 토큰 검증
    const decodedToken = jwt.verify(token, 'secretKey')

    // 4. 검증이 성공하면 사용자 데이터를 요청 객체에 추가
    req.userData = { userId: decodedToken.userId }

    // 5. 다음 미들웨어로 진행
    next()
  } catch (err) {
    // 6. 토큰 검증 실패 시 403 상태코드와 함께 에러 응답
    const error = new HttpError('인증 실패', 403)
    return next(error)
  }
}
```
