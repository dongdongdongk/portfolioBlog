# { 언리얼 엔진 기초 개념 정리 }

## 게임 엔진이란?

게임 엔진은 **여러 기능들이 하나로 묶인 거대한 소프트웨어**입니다. 게임을 만드는 데 필요한 다양한 도구들을 모아놓은 것이라고 생각하면 됩니다.

## 게임 엔진의 주요 구성 요소

**렌더링 시스템**
화면에 이미지를 그려주는 기능입니다. 게임 화면이 빠르게 바뀌면서 캐릭터나 사물이 움직이는 것처럼 보이게 만듭니다.

**입력 시스템**
키보드, 마우스, 컨트롤러, 터치스크린 등의 조작을 게임 속 행동으로 바꿔주는 기능입니다.

**오디오 시스템**
게임의 효과음과 배경음악을 재생하고 관리합니다.

**물리 시스템**
물체가 떨어지고, 튕기고, 구르는 등의 움직임을 계산해서 자연스럽게 보이도록 만듭니다.

**에셋 관리**
3D 모델, 텍스처, 이미지, 사운드, 애니메이션 같은 파일들을 게임에서 사용할 수 있게 처리합니다.

**UI 시스템**
버튼, 메뉴, 인벤토리, 체력바 같은 화면 요소들을 만들고 작동시킵니다.

**파티클 시스템**
연기, 불, 폭발, 번개 같은 특수 효과를 만듭니다.

**네트워킹 시스템**
멀티플레이어 게임에서 전 세계 플레이어들을 연결합니다.

## 스크립팅 시스템

게임 개발자가 이런 시스템들을 활용해서 게임을 만들 수 있게 해주는 도구입니다.

언리얼 엔진의 특별한 점은 **블루프린트**라는 시각적 스크립팅 도구가 있다는 것입니다. 복잡한 코드를 직접 작성하지 않아도 그래픽 인터페이스로 게임 로직을 만들 수 있어서 초보자도 접근하기 쉽습니다.

## 알아두면 좋은 점

- 언리얼 엔진은 매우 방대한 시스템이라서 모든 걸 다 알 필요는 없습니다
- 전문 개발자들도 보통 특정 분야를 전문적으로 다룹니다
- 직접 게임을 만들면서 필요한 시스템들을 하나씩 배워가면 됩니다

당신의 오디오 경험이 있다는 점에서, 특히 오디오 시스템 부분은 다른 초보자들보다 훨씬 빠르게 이해하고 활용할 수 있을 것입니다.

# { 언리얼 엔진 - 스태틱 메시와 FBX 임포트 가이드 }

## 1. 스태틱 메시(Static Mesh)란?

**스태틱 메시**는 언리얼 엔진의 특정 유형의 에셋입니다.

- 3D 모델을 표현하는 기본 단위
- 콘텐츠 서랍(Content Drawer)에서 확인 가능
- 에셋 이름 아래에 "Static Mesh"라고 표시됨

### 스태틱 메시 찾기

1. 뷰포트에서 오브젝트 **우클릭**
2. **"에셋 찾아보기"** 선택
3. 콘텐츠 서랍이 해당 폴더로 열리며 에셋이 강조 표시됨

---

## 2. 스태틱 메시 에디터

### 열기 방법

- 스태틱 메시를 **더블 클릭**하면 스태틱 메시 에디터가 열림

### 주요 기능

- 메시의 프로퍼티 확인 및 수정
- 머티리얼 슬롯 관리
- 디테일 패널에서 세부 설정 조정

### 뷰포트 조작법

- **클릭 + 드래그**: 이동 및 둘러보기
- **Alt + 좌클릭**: 오브젝트 중심으로 회전
- **Alt + 우클릭 + 위아래 드래그**: 확대/축소

---

## 3. 언리얼 에셋 파일 (.uasset)

### 파일 위치 확인

1. 콘텐츠 서랍에서 에셋 **우클릭**
2. **"탐색기에 표시"** 선택
3. Windows 탐색기가 열리며 실제 파일 위치 표시

### 중요 사항

- 모든 프로젝트 에셋은 **Content 폴더**에 저장됨
- 파일 확장자: **.uasset**
- 언리얼 엔진 전용 파일 형식
- ⚠️ **절대 직접 삭제하지 말 것** (에디터에서만 관리)

---

## 4. FBX 파일 임포트

### FBX란?

- **FilmBox**의 줄임말
- 3D 모델링 프로그램(블렌더, 마야 등)에서 생성
- 언리얼 엔진에서 가장 많이 사용하는 메시 파일 형식

### 임포트 방법 1: 드래그 & 드롭

1. Windows 탐색기에서 FBX 파일 선택
2. 콘텐츠 서랍의 원하는 폴더로 **드래그**

### 임포트 방법 2: 가져오기 버튼

1. 콘텐츠 서랍에서 원하는 폴더로 이동
2. **"추가"** 옆 **"가져오기"** 버튼 클릭
3. FBX 파일 선택
4. 임포트 옵션 확인
   - **균일한 스케일**: 크기 조정 (기본값 1)
   - 기타 설정들은 기본값 사용 권장
5. **"모두 가져오기"** 클릭

---

## 5. 임포트 후 생성되는 파일

### 자동 생성 파일

FBX를 임포트하면 언리얼 엔진이 자동으로 생성:

1. **SM\_파일명** (Static Mesh)
   - 실제 3D 메시 에셋
2. **M\_파일명** (Material)
   - 기본 머티리얼 (흰색)
   - FBX에 머티리얼 정보가 없을 때 자동 생성

---

## 6. 머티리얼(Material) 관리

### 머티리얼 변경하기

1. 스태틱 메시 에디터 열기
2. 디테일 패널 → **"머티리얼 슬롯"** 섹션
3. 드롭다운 클릭하여 다른 머티리얼 선택

### 엔진 콘텐츠 표시

- 검색창 옆 **톱니바퀴 아이콘** 클릭
- **"엔진 콘텐츠 표시"** 옵션 체크
- 언리얼 엔진 기본 머티리얼 접근 가능

### 기본 머티리얼

- **World Grid Material**: 회색 체크무늬
- 머티리얼이 할당되지 않았을 때 표시되는 기본 머티리얼

---

## 7. 파일 저장

### 저장 필요 표시

- 에셋 옆에 **별표(\*)** 표시 = 저장 안 됨

### 저장 방법

1. 상단 **"모두 저장"** 클릭
2. 콘텐츠 저장 팝업에서 저장할 에셋 선택
3. **"선택한 항목 저장"** 클릭
4. 별표 사라짐 = 저장 완료

---

## 8. 레벨에 메시 배치

### 배치 방법

- 콘텐츠 서랍에서 스태틱 메시를 **클릭 + 드래그**하여 뷰포트로

### 변형(Transform) 조작

- **이동(Translate)**: W 키
- **회전(Rotate)**: E 키
- **크기(Scale)**: R 키
  - 가운데 상자 클릭 → 세 축 동시 크기 조정
  - 디테일 패널에서 수치 입력 가능
  - 곡선 화살표 → 기본 크기로 리셋

---

## 9. 에디터 창 관리

### 탭 도킹

- 탭을 **클릭 + 드래그**하여 다른 위치에 도킹
- 탭 제목을 클릭하여 **"도킹 해제"** → 독립 창으로 분리

### 패널 크기 조정

- 섹션 사이 경계선을 **클릭 + 드래그**하여 크기 조정

---

## 10. 다음 단계: 텍스처

### TGA/Targa 파일

- 텍스처 이미지 파일
- 머티리얼에 색상과 디테일 추가
- 다음 강의에서 임포트 및 적용 방법 학습 예정

# { 언리얼 엔진 - FBX 임포트 스케일 최적화 가이드 }

## 1. 문제 상황: 스케일 조정의 성능 영향

### 일반적인 실수

```
❌ 잘못된 방법:
1. 작은 메시를 임포트
2. 레벨에 배치 후 스케일 툴(R)로 확대
3. 크기가 맞았으니 완료!
```

### 왜 문제가 될까?

**성능에 영향을 주는 이유:**

- 레벨에 배치된 메시의 스케일이 1이 아니면 → **추가 정보 저장**
- 메시에 **변환(Transform)이 적용**됨
- 엔진이 **추가 수학 계산** 수행 필요

---

## 2. 언제 문제가 되는가?

### 문제가 되는 경우

- **움직이는 오브젝트** (예: 드론, 캐릭터, 차량)
  - 런타임에 위치 변경 시 스케일 계산도 함께 수행
  - CPU 부담 증가
  - 많은 오브젝트일수록 성능 저하 누적

### 문제가 안 되는 경우

- **정적 소품/환경** (예: 건물, 바위, 나무)
  - 그냥 놓아두기만 함
  - 추가 계산 없음

---

## 3. 올바른 해결 방법

### ✅ 방법 1: FBX 임포트 시 스케일 조정 (권장)

**절차:**

### 1단계: 기존 에셋 삭제

```
1. 레벨의 드론 오브젝트 선택 → Delete
2. 콘텐츠 서랍 → SM_Drone 에셋 선택 → Delete
3. "에셋 삭제" 메뉴에서 확인
```

### 2단계: FBX 재임포트

```
방법 A: 임포트 버튼
- 콘텐츠 서랍 → "임포트" 클릭
- FBX 파일 선택 → "열기"

방법 B: 우클릭 메뉴
- 콘텐츠 서랍 빈 공간 우클릭
- "게임/드론으로 가져오기" 선택
- FBX 파일 선택
```

---

## 4. FBX 임포트 옵션 상세 설정

### 핵심 옵션 1: 균일한 스케일 (Uniform Scale)

**설정 방법:**

```
임포트 균일 스케일: 1 → 6으로 변경
```

**효과:**

- ✅ 메시가 6배 크기로 임포트됨
- ✅ 레벨에 배치 시 스케일 = 1 유지
- ✅ 추가 계산 불필요
- ✅ 성능 최적화

**적절한 스케일 찾기:**

- 테스트로 임포트 → 레벨에 배치
- 얼마나 확대했는지 확인
- 그 수치를 임포트 스케일로 사용
- 이 강의 예시: 6이 적절

### 핵심 옵션 2: 머티리얼 가져오기 방식

**기본 설정:**

```
머티리얼 가져오기 방식: "새 머티리얼 만들기"
→ 자동으로 M_파일명 머티리얼 생성
```

**변경 옵션:**

```
"머티리얼 생성 안 함" 선택
→ 머티리얼 파일 생성하지 않음
```

**언제 "생성 안 함" 사용?**

- 이미 머티리얼이 존재할 때
- 재임포트할 때
- 불필요한 중복 파일 방지

**스마트 기능:**

- 언리얼 엔진이 자동으로 기존 머티리얼 연결
- 예: SM_Drone → M_Drone 자동 할당

## 5. 결과 확인

### 임포트 후 확인사항

**1. 크기 확인:**

```
스태틱 메시 에디터에서:
- Alt + 좌클릭: 회전
- Alt + 우클릭 + 드래그: 확대/축소
→ 이전보다 6배 큰 모습 확인
```

**2. 레벨 배치 확인:**

```
콘텐츠 서랍 → SM_Drone 드래그
→ 디테일 패널에서 Scale 확인
→ X: 1.0, Y: 1.0, Z: 1.0 ✅
```

**3. 머티리얼 확인:**

```
스태틱 메시 에디터 → 머티리얼 슬롯
→ M_Drone 자동 할당됨 ✅
```

## 6. 장점 비교

### ❌ 나쁜 방법: 레벨에서 스케일 조정

```
문제점:
- Scale ≠ 1.0 (예: 6.0, 6.0, 6.0)
- 추가 변환 계산 필요
- 런타임 성능 저하
- 여러 개 배치 시 매번 조정 필요
```

### ✅ 좋은 방법: 임포트 시 스케일 조정

```
장점:
- Scale = 1.0 유지
- 추가 계산 없음
- 성능 최적화
- 여러 개 배치 시 추가 작업 불필요
- 이미 적절한 크기
```

## 7. 추가 스케일 조정 방법 (참고)

### 다른 방법들

1. **FBX 임포트 옵션** (이번 강의 ✅)
2. **엔진 내 메시 데이터 직접 변경** (추후 강의 예정)
3. **원본 3D 프로그램에서 조정** (블렌더, 마야 등)

## 8. 실전 워크플로우

### 권장 작업 순서

```
1단계: 테스트 임포트
   └─ 기본 설정으로 임포트
   └─ 레벨에 배치하여 크기 확인

2단계: 적절한 스케일 파악
   └─ 얼마나 확대/축소 필요한지 측정
   └─ 수치 기록

3단계: 최적화 재임포트
   └─ 기존 에셋 삭제
   └─ 임포트 균일 스케일에 수치 입력
   └─ 머티리얼 옵션 설정 (필요시)
   └─ "모두 가져오기"

4단계: 확인
   └─ Scale = 1.0 인지 확인
   └─ 크기가 적절한지 확인
   └─ 머티리얼 할당 확인
```

# { 언리얼 엔진 - 머티리얼 에디터 완벽 가이드 }

## 1. 머티리얼(Material)이란?

**머티리얼**은 3D 오브젝트의 표면이 어떻게 보일지를 정의하는 에셋입니다.

- 색상, 광택, 거칠기 등을 제어
- 오브젝트의 시각적 품질 결정
- 복잡한 표면 효과 구현 가능

### 머티리얼 명명 규칙

- **M\_** 접두사 사용 (예: M_Drone)
- FBX 임포트 시 자동 생성됨

---

## 2. 머티리얼 에디터 기본

### 열기 방법

- 콘텐츠 서랍에서 머티리얼 에셋 **더블 클릭**

### 인터페이스 구성

**1. 머티리얼 그래프 (Material Graph)**

- 노드 기반 시각적 프로그래밍 공간
- 우클릭 + 드래그: 이동
- 스크롤 휠: 확대/축소

**2. 프리뷰 뷰포트**

- 좌클릭 + 드래그: 회전
- 우클릭 + 드래그: 확대/축소 (Alt 키 불필요)
- 머티리얼이 적용된 샘플 메시 표시

**3. 디테일 패널**

- 선택한 노드의 속성 표시
- 파라미터 이름 변경 가능

**4. 팔레트 (Palette)**

- 우측에 위치
- 사용 가능한 모든 노드 목록
- 검색 기능 제공

## 3. 프리뷰 메시 변경

### 뷰포트 우측 하단 5개 아이콘

1. **원통형 (Cylinder)**
2. **평면 (Plane)** - 한쪽 면만 보임
3. **큐브 (Cube)**
4. **구체 (Sphere)** - 기본 프리뷰
5. **커스텀 메시**

### 커스텀 메시 설정 방법

```
1. 콘텐츠 서랍에서 원하는 메시 선택
2. 머티리얼 에디터로 돌아가기
3. 5번째 아이콘(메시 선택) 클릭
→ 선택한 메시가 프리뷰로 표시됨
```

## 4. 결과 노드 (Result Node)

### 개념

- 머티리얼 그래프의 **최종 출력 노드**
- 에셋 이름과 동일한 이름
- 여기에 연결된 값들이 최종 머티리얼 결정

### 주요 입력 핀들

각 핀은 머티리얼의 특정 속성 제어

## 5. 기본 색상 (Base Color)

### 역할

- 오브젝트의 기본 색상 정보
- 가장 기본적인 시각 속성

### 벡터 파라미터 이해

**벡터 = 여러 값의 집합**

- **R (Red)**: 빨간색
- **G (Green)**: 녹색
- **B (Blue)**: 파란색
- **A (Alpha)**: 투명도 (일부 핀에서만 사용)

### 색상 선택기 사용법

**색상환 (Color Wheel)**

- 클릭 + 드래그: 색상(Hue) 변경
- RGB 값 자동 조정

**HSV 리본**

1. **H (Hue)**: 색상
   - 좌우 슬라이더
   - 빨강 → 보라 → 빨강 순환
2. **S (Saturation)**: 채도
   - 첫 번째 세로 리본
   - 흰색(무채색) ↔ 완전 채도
3. **V (Value)**: 명도
   - 두 번째 세로 리본
   - 검정 ↔ 밝은 색

### 색상 변경 절차

```
1. 기본 색상 노드 더블 클릭
2. 색상 선택기에서 원하는 색 선택
3. 확인 클릭
4. 저장 또는 적용
```

---

## 6. 저장 vs 적용

### 저장 (Save)

```
상단 저장 아이콘 클릭
```

- 변경사항을 **디스크에 영구 저장**
- 머티리얼이 복잡하면 시간 소요
- 나중에 프로젝트 재시작해도 유지

### 적용 (Apply)

```
상단 적용 버튼 클릭
```

- 변경사항을 **임시로 월드에 반영**
- 실제 저장은 안 됨
- 빠르게 테스트할 때 유용
- 저장 안 하고 닫으면 변경사항 손실

**작업 흐름 권장:**

```
1. 변경 작업
2. "적용" 클릭하여 미리보기
3. 마음에 들면 "저장"
4. 마음에 안 들면 계속 수정
```

## 7. 레벨의 개별 오브젝트에 머티리얼 적용

### 스태틱 메시 에셋 변경 vs 인스턴스 변경

**스태틱 메시 에셋 변경:**

```
❌ 모든 인스턴스에 영향
```

- 메시 파일 자체를 변경
- 새로 배치하는 모든 오브젝트에 적용

**인스턴스만 변경 (권장):**

```
✅ 선택한 오브젝트만 변경
```

### 인스턴스 머티리얼 변경 방법

**절차:**

```
1. 레벨에서 오브젝트 선택
2. 디테일 패널 아래로 스크롤
3. "Materials" 섹션 찾기
4. 드롭다운 클릭
5. 원하는 머티리얼 검색 및 선택
   예: "M_Drone" 입력
```

**실습 예시:**

```
시작 콘텐츠 → Shapes → Shape_Sphere
레벨에 배치 → 디테일 패널에서 M_Drone 적용
→ 구체만 드론 머티리얼 적용됨 ✅
```

## 8. 노드 시스템 기초

### 노드란?

- 머티리얼 그래프의 기본 단위
- 각 노드는 특정 기능 수행
- 와이어(선)로 연결하여 데이터 전달

### 노드 조작법

**이동:**

```
노드 클릭 + 드래그
```

**연결:**

```
출력 핀 클릭 + 드래그 → 입력 핀에 드롭
→ 와이어(선) 생성
```

**복제:**

```
방법 1: Ctrl + C → Ctrl + V
방법 2: 노드 선택 후 Ctrl + D (빠른 복제)
```

**삭제:**

```
노드 선택 후 Delete 키
```

## 9. 상수 노드 (Constant)

### 종류와 용도

**Constant (상수)**

- 단일 값 (0~1 사이)
- 정수 하나만 반환
- 메탈릭, 스페큘러, 러프니스 등에 사용

**Constant 2/3/4 Vector**

- 2개/3개/4개 값
- 기본 색상은 4 Vector (RGBA)

### 상수 노드 생성 방법

**방법 1: 팔레트 사용**

```
1. 우측 팔레트 열기
2. "Constant" 검색
3. 클릭 + 드래그하여 배치
```

**방법 2: 단축키 (빠른 방법 ✅)**

```
키보드 "1" 키 누른 채 + 좌클릭
→ 상수 노드 즉시 생성
```

### 값 변경

```
텍스트 박스 클릭 → 숫자 입력 → Enter
```

## 10. 메탈릭 (Metallic)

### 개념

- 금속 같은 표면의 외관 제어
- 값 범위: **0 ~ 1**

### 효과

```
Metallic = 0
→ 비금속 (플라스틱, 천, 나무 등)
→ 평평한 표면

Metallic = 1
→ 금속 (철, 구리, 금 등)
→ 반사가 강한 표면
```

### 설정 방법

```
1. 키보드 "1" + 좌클릭 → 상수 노드 생성
2. 출력 핀 → Metallic 입력 핀 연결
3. 값을 0 또는 1로 설정
4. 적용 클릭하여 확인
```

**주의:**

- 값을 10으로 해도 1 이상은 의미 없음
- 최대값은 1

---

## 11. 스페큘러 (Specular)

### 개념

- **비금속 표면**의 반사광 양 조절
- 값 범위: **0 ~ 1**
- 기본값: **0.5**

### 중요 포인트

```
⚠️ Metallic = 1 일 때는 효과 없음!
→ 금속 표면은 스페큘러 사용 안 함
→ Metallic = 0 일 때만 의미 있음
```

### 효과

```
Specular = 0
→ 반사 없음
→ 매우 평평하고 무광

Specular = 1
→ 강한 반사광
→ 광택 있는 표면
```

### 실습 예시

```
1. Metallic을 0으로 설정 (비금속)
2. 상수 노드 생성 → Specular 연결
3. 값 0 → 평평함
4. 값 1 → 빛남
5. 적용으로 월드에서 확인
```

---

## 12. 러프니스 (Roughness)

### 개념

- 표면의 **거칠기** 제어
- 값 범위: **0 ~ 1**

### 효과 스펙트럼

```
Roughness = 0
→ 매끄러운 표면
→ 거울 같은 반사 (Mirror Finish)
→ 명확한 반사

Roughness = 0.1
→ 약간 흐릿한 반사
→ 유리/대리석 같은 느낌

Roughness = 0.5
→ 중간 거칠기
→ 반사가 희미함

Roughness = 1
→ 완전 무광택 (Matte)
→ 확산 반사만 있음
→ 반사 안 보임
```

### 스페큘러와의 조합

**최고 광택 효과:**

```
Metallic = 0 (비금속)
Specular = 1 (강한 반사)
Roughness = 0 (매끄러움)
→ 유리, 광택 플라스틱, 광택 나무
```

**중간 광택:**

```
Metallic = 0
Specular = 0.5
Roughness = 0.2
→ 일반적인 플라스틱, 세라믹
```

**무광:**

```
Metallic = 0
Specular = 0.5
Roughness = 1
→ 천, 종이, 무광 페인트
```

## 13. 노멀 맵 (Normal Map)

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380705/notion-blog/_/_/_5_/_1_Introduction/image_3.png)

### 개념

- 평평한 표면에 **입체감**을 부여
- 실제 지오메트리 추가 없이 디테일 표현
- RGB 색상값으로 빛 반사 방향 제어

### 노멀 맵의 색상 의미

```
Red (빨강): X축 방향
Green (녹색): Y축 방향
Blue (파랑): Z축 방향 (표면 법선)

→ 각 픽셀이 빛을 어느 방향으로 반사할지 지정
```

### 특징

- 보통 **푸른색 계열**로 보임
- 미세한 RGB 변화로 입체감 표현
- 성능 최적화 핵심 기술

### 장점: 성능 최적화

```
❌ 실제 지오메트리 추가:
   많은 폴리곤 = 높은 연산 비용

✅ 노멀 맵 사용:
   평평한 메시 + 노멀 맵 = 저렴한 비용
   → 입체감 있어 보이지만 실제론 평평함
```

## 14. 텍스처 샘플 노드 (Texture Sample)

### 개념

- 이미지 파일을 머티리얼에 사용
- 텍스처를 노드로 표현

### 텍스처 샘플 생성 방법

**방법 1: 드래그 & 드롭 (권장 ✅)**

```
1. 콘텐츠 서랍에서 텍스처 찾기
2. 텍스처를 머티리얼 그래프로 드래그
3. 자동으로 텍스처 샘플 노드 생성
```

**방법 2: 수동 생성**

```
1. 우클릭 → "Texture Sample" 검색
2. 노드 생성
3. 디테일 패널에서 텍스처 할당
```

### 출력 핀

```
RGB: 색상 정보 (빨강+녹색+파랑)
R: 빨강 채널만
G: 녹색 채널만
B: 파랑 채널만
A: 알파(투명도) 채널
```

## 15. 노멀 맵 적용 실습

### 스타터 콘텐츠에서 노멀 맵 찾기

**경로:**

```
콘텐츠 서랍
└─ StarterContent
   └─ Materials
      └─ M_Brick_Clay_New (머티리얼)
```

**노멀 맵 찾기:**

```
1. M_Brick_Clay_New 더블 클릭
2. 머티리얼 에디터에서 스크롤
3. 파란색 텍스처 샘플 찾기
4. 클릭 → 디테일 패널에서 "Texture" 속성 확인
5. 찾아보기 아이콘 클릭
→ T_Brick_Clay_New_N (노멀 맵 텍스처)
```

### 드론 머티리얼에 적용

**절차:**

```
1. T_Brick_Clay_New_N 선택된 상태 유지
2. M_Drone 머티리얼 에디터로 이동
3. 콘텐츠 서랍에서 노멀 맵 드래그
4. 머티리얼 그래프에 드롭
→ 텍스처 샘플 노드 생성됨

5. RGB 출력 핀 → Normal 입력 핀 연결
6. 적용 클릭
```

### 효과 확인

```
Before: 매끄러운 표면
After: 벽돌 텍스처의 굴곡과 틈 표현
→ 실제 지오메트리는 그대로
→ 빛 반사만 변화하여 입체감
```

✅ 노멀 맵 활용

## 1. 머티리얼 적용의 다양한 방법

### 방법 1: 디테일 패널 사용 (이전 방법)

```
1. 레벨에서 오브젝트 선택
2. 디테일 패널 → Materials 섹션
3. 드롭다운에서 머티리얼 선택
```

### 방법 2: 드래그 & 드롭 (빠른 방법 ✅)

```
1. 콘텐츠 서랍에서 머티리얼 찾기
2. 머티리얼을 클릭 + 드래그
3. 레벨의 메시 위에 드롭
→ 즉시 머티리얼 적용됨!
```

**장점:**

- 훨씬 빠르고 직관적
- 디테일 패널 찾을 필요 없음
- 여러 오브젝트에 빠르게 적용 가능

## 2. 머티리얼과 메시의 궁합

### 범용 머티리얼

```
예: 벽돌, 나무, 금속판 등
→ 다양한 메시에 적용 가능
→ 바닥, 벽, 기둥 등에 사용
```

**실습 예시:**

```
M_Brick_Clay_New를 바닥에 드래그
→ 벽돌 바닥처럼 자연스러움 ✅

M_Brick_Clay_New를 큐브에 드래그
→ 모서리가 날카로워 어색함 ⚠️
```

### 전용 머티리얼

```
예: 드론 머티리얼
→ 특정 메시를 위해 제작
→ 해당 메시에만 어울림
→ 다른 메시에는 부자연스러움
```

**왜 그럴까?**

- 텍스처가 메시의 UV 맵핑에 맞춰 제작됨
- 특정 형태를 전제로 디자인됨
- 다른 형태에 적용하면 텍스처가 이상하게 늘어남

## 3. 실제 게임 개발 워크플로우

### 에셋 제공 형태

**일반적으로 받게 되는 파일들:**

```
📦 에셋 패키지
├─ 📄 SM_Drone.fbx (3D 메시)
└─ 🖼️ 텍스처 세트
   ├─ T_Drone_BC.tga (기본 색상)
   ├─ T_Drone_N.tga (노멀 맵)
   ├─ T_Drone_M.tga (발광)
   └─ T_Drone_ORM.tga (오클루전/러프니스/메탈릭)
```

**중요한 점:**

- ❌ 언리얼 엔진 머티리얼(.uasset)은 **포함되지 않음**
- ✅ 개발자가 직접 머티리얼 에셋을 **생성해야 함**
- ✅ 제공된 텍스처를 사용하여 **조합**

### 개발자가 해야 할 일

```
1. FBX 파일 임포트 → 스태틱 메시 생성
2. 텍스처 파일 임포트 → 텍스처 에셋 생성
3. 머티리얼 에셋 생성
4. 텍스처를 머티리얼 그래프에 연결
5. 메시에 머티리얼 적용
```

## 10. 발광(Emissive) 텍스처 적용

### 발광이란?

- 스스로 빛을 내는 효과
- 어두운 곳에서도 빛남
- 전자기기의 LED, 네온사인 등에 사용

### 적용 방법

```
1. T_Drone_M을 머티리얼 그래프로 드래그
2. RGB 출력 핀 → Emissive Color 입력 핀 연결
```

### 텍스처 특징

```
- 대부분 검은색 (RGB: 0, 0, 0)
- 특정 부분만 색상 있음 (예: 빨간색)

검은색 부분: 발광 없음
색상 부분: 발광 효과
→ 메시의 특정 부분만 빛남
```

### 효과 확인

```
프리뷰에서:
- 드론의 특정 부분만 빛남
- 그림자 속에서도 빛 발산
- 선택적 발광 효과
```

## 11. ORM 패킹 텍스처 이해

### ORM이란?

**O R M의 의미:**

```
O = Occlusion (오클루전)
R = Roughness (러프니스)
M = Metallic (메탈릭)
```

**왜 하나의 텍스처에?**

```
✅ 최적화 기법
- 각각 별도 텍스처 = 3개 파일 = 메모리 3배
- 하나로 패킹 = 1개 파일 = 메모리 절약
```

### RGB 채널의 역할

**텍스처의 색상 채널 분리:**

```
Red 채널 (R) → Ambient Occlusion
Green 채널 (G) → Roughness
Blue 채널 (B) → Metallic
```

**각 채널은 그레이스케일:**

- 검은색 (0) ~ 흰색 (1)
- 회색 = 중간 값

---

## 12. 채널별 적용 방법

### 텍스처 에디터에서 채널 분리 확인

**RGB 아이콘 사용:**

```
1. T_Drone_ORM 더블 클릭 (텍스처 에디터 열기)
2. 상단 RGB 아이콘 확인
   [R] [G] [B] 세 개의 체크박스

3. 빨간색만 보기:
   [✓] [ ] [ ] → Red 채널만 활성화

4. 녹색만 보기:
   [ ] [✓] [ ] → Green 채널만 활성화

5. 파란색만 보기:
   [ ] [ ] [✓] → Blue 채널만 활성화
```

## 13. Ambient Occlusion (앰비언트 오클루전) 적용

### 개념

- **자체 그림자 시뮬레이션**
- 틈새나 움푹한 곳이 더 어둡게 보임
- 입체감 증가

### 효과

```
예시:
- 벽돌 사이 틈새 → 어둡게
- 돌출된 표면 → 밝게
→ 더 사실적인 깊이감
```

### 적용 방법

```
1. T_Drone_ORM을 머티리얼 그래프로 드래그
2. R (Red) 출력 핀 → Ambient Occlusion 입력 핀
```

### 효과 확인 (실습)

**다른 핀 분리하여 확인:**

```
1. Alt + 좌클릭으로 다른 핀들 분리
   (Base Color, Normal, Emissive)
2. Red 채널 → Base Color에 임시 연결
3. 프리뷰 확인:
   - 균열/틈새 → 어둡게 (검은색)
   - 평평한 표면 → 밝게 (흰색)
4. 다시 원래대로 복구
5. Red 채널 → Ambient Occlusion 연결
```

## 14. Roughness (러프니스) 적용

### Green 채널 확인

```
텍스처 에디터:
- Green 채널만 활성화
- 그레이스케일 이미지 확인
- 밝기 차이 = 거칠기 차이
```

### 적용 방법

```
G (Green) 출력 핀 → Roughness 입력 핀
```

### 효과

```
밝은 부분 (흰색에 가까움):
→ Roughness = 1에 가까움
→ 거친 표면, 무광택

어두운 부분 (검은색에 가까움):
→ Roughness = 0에 가까움
→ 매끄러운 표면, 광택

중간 회색:
→ 중간 정도의 거칠기
```

### 실제 드론 예시

```
- 유리 돔: 거의 검은색 → 매우 반짝임 ✨
- 금속 부분: 어두운 회색 → 약간 광택
- 플라스틱 부분: 밝은 회색 → 거친 무광
```

## 15. Metallic (메탈릭) 적용

### Blue 채널 확인

```
텍스처 에디터:
- Blue 채널만 활성화
- 금속 부분 = 밝음
- 비금속 부분 = 어두움
```

### 적용 방법

```
B (Blue) 출력 핀 → Metallic 입력 핀
```

### 효과

```
흰색 (1):
→ 완전한 금속
→ 강한 반사, 환경 반사

검은색 (0):
→ 비금속
→ 플라스틱, 고무, 유리 등

회색:
→ 혼합 (드물게 사용)
```

## 20. 일반적인 텍스처 세트 구성

### 표준 텍스처 패키지

```
게임 에셋 구매/다운로드 시 일반적 구성:

1️⃣ Base Color (또는 Albedo, Diffuse)
   → 기본 색상 정보

2️⃣ Normal (또는 Normal Map)
   → 입체감, 디테일

3️⃣ Emissive (선택적)
   → 발광 효과 (있는 경우만)

4️⃣ ORM 또는 분리된 텍스처
   Option A: ORM 패킹 (1개 파일)
   Option B: 개별 파일 (3개 파일)
      - Ambient Occlusion
      - Roughness
      - Metallic
```

### 추가 텍스처 (고급)

```
- Height Map (높이 맵)
- Opacity (투명도)
- Subsurface Color (반투명)
```

## 22. 왜 ORM을 패킹할까?

### 성능 최적화 이유

**개별 텍스처 방식:**

```
❌ 파일 3개:
   - T_Object_AO.tga (2048x2048)
   - T_Object_R.tga (2048x2048)
   - T_Object_M.tga (2048x2048)
→ 총 메모리: 약 12MB

❌ 텍스처 샘플 노드 3개
❌ GPU가 3번 텍스처 읽기
```

**ORM 패킹 방식:**

```
✅ 파일 1개:
   - T_Object_ORM.tga (2048x2048)
→ 총 메모리: 약 4MB

✅ 텍스처 샘플 노드 1개
✅ GPU가 1번 텍스처 읽기
→ 3배 효율적! 🚀
```

### 왜 가능한가?

```
각 속성이 그레이스케일(흑백)만 필요하기 때문:
- AO: 0~1 값 하나
- Roughness: 0~1 값 하나
- Metallic: 0~1 값 하나

RGB 채널 활용:
- R 채널 = AO의 0~1
- G 채널 = Roughness의 0~1
- B 채널 = Metallic의 0~1
```

## 23. 그레이스케일 vs 컬러의 이해

### 그레이스케일 (Grayscale)

```
- 색상 없음, 밝기만 있음
- 값: 0 (검은색) ~ 1 (흰색)
- 회색 = 중간값
- 단일 숫자로 표현 가능
```

### 컬러 (Color)

```
- RGB 세 채널 조합
- Red + Green + Blue
- 각각 0~1 값
- 세 숫자 필요
```

### 채널의 비밀

```
🔴 Red 채널 = 그레이스케일
🟢 Green 채널 = 그레이스케일
🔵 Blue 채널 = 그레이스케일

Red + Green + Blue = 컬러 이미지

따라서:
각 채널을 따로 쓰면 = 그레이스케일 3개!
```
