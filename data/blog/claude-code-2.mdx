```jsx
WSL과 docker-desktop(Alpine Linux)이란?

		WSL(Windows Subsystem for Linux): Windows 컴퓨터에서 Linux를 실행할 수 있게 해주는 도구입니다.

		Windows에서 Linux 명령어와 환경을 사용할 수 있게 해줘요. 즉, Windows 안에 Linux를 띄우는 거예요.

docker-desktop: Docker라는 프로그램이 사용하는 WSL 환경으로, Alpine Linux라는 아주 가벼운 Linux를 사용합니다.

		하지만 Alpine은 최소한의 기능만 있어서 개발 도구(예: VS Code)가 제대로 작동하기 어려울 수 있어요.

왜 Ubuntu로 전환해야 하나?

		Ubuntu: 개발자들에게 친숙하고, VS Code, Node.js, npm 같은 도구를 쉽게 지원하는 Linux 환경이에요.

		필요한 파일과 설정이 기본적으로 포함되어 있어서 오류가 적어요.

더 안정적: Ubuntu는 개발에 필요한 모든 도구를 쉽게 설치할 수 있고,

		VS Code와의 통합이 잘 되어서 프로젝트 작업이 훨씬 편해요.

디폴트 설정: WSL에서 Ubuntu는 가장 널리 사용되는 표준 Linux 환경이라 초보자에게도 쉽게 추천돼요.
```

### Plan 모드 vs Auto 모드

```jsx
1. Plan 모드 (계획 모드)

		특징:

				AI가 먼저 작업 계획을 세우고 사용자에게 제시

				사용자가 계획을 검토하고 승인한 후 실행

				각 단계별로 확인 과정을 거침

				더 신중하고 안전한 접근 방식


		장점:

				예상치 못한 변경사항 방지

				복잡한 작업의 전체 흐름 파악 가능

				사용자가 통제권을 유지

				실수나 오류 가능성 감소

		사용 시기:

				중요한 프로젝트 작업

				복잡한 리팩토링

				데이터베이스 스키마 변경

				프로덕션 환경 관련 작업

2. Auto 모드 (자동 모드)

		특징:

				AI가 즉시 작업을 실행

				별도 승인 과정 없이 자동으로 진행

				빠른 작업 처리

				사용자 개입 최소화

		장점:

				빠른 개발 속도

				반복적인 승인 과정 생략

				효율적인 워크플로우

				즉각적인 결과 확인

		사용 시기:

				간단한 코드 수정

				반복적인 작업

				프로토타이핑

				테스트 코드 작성
```

# { Hooks 사용하기 }

```jsx
Claude Code의 Hooks는 Claude Code가 작업을 수행할 때 자동으로 실행되는 사용자 정의 명령어들입니다.

쉽게 말해, 특정 상황에서 자동으로 실행되는 "자동화 규칙"이라고 생각하면 됩니다.
```

## 🤔 Hooks가 왜 필요한가요?

```jsx
Claude Code는 AI이기 때문에 때로는 일관성 없는 동작을 할 수 있습니다. 예를 들어:

		코드를 작성한 후 포맷팅을 깜빡할 수 있어요

		알림을 보내는 것을 잊을 수 있어요

		특정 규칙을 지키지 않을 수 있어요

Hooks를 사용하면 이런 작업들을 자동으로, 항상 실행되도록 보장할 수 있습니다.
```

## Hook의 종류

```jsx
1. PreToolUse (작업 전)

		Claude가 어떤 작업을 하기 전에 실행됩니다.

		예: 파일을 수정하기 전에 백업 만들기

		예: 민감한 파일 수정을 차단하기

2. PostToolUse (작업 후)

		Claude가 어떤 작업을 완료한 후에 실행됩니다.

		예: 코드 파일을 수정한 후 자동으로 포맷팅하기

		예: 작업 완료 로그 남기기

3. Notification (알림)

		Claude가 알림을 보낼 때 실행됩니다.

		예: 사용자 정의 알림 방식 사용하기

4. Stop (작업 종료)

		Claude가 작업을 끝낼 때 실행됩니다.

		예: 작업 완료 보고서 생성하기
```

## WSL 환경에서 알림 관련 경험 및 개선 방법 정리

```jsx
1. 기존 강의 방식 문제점

		기존 강의(특히 Mac OS 환경 기준)에서는 echo 명령어로 WSL에서 알림을 출력하는 방법을 알려줬음.

		하지만 WSL(Linux 환경)에서는 echo로 출력해도 알림이 명확하게 인식되지 않아 실용성이 떨어짐.

		Mac OS에서는 모달 창 등 시각적 알림이 가능했으나, WSL 환경에서는 이런 UI 알림이 지원되지 않음.

2. 대안 탐색 및 시도

		여러 알림 방법을 시험해 봤으나 WSL 환경에서는 한계가 많았음.

		결국, 외부 알림 채널 활용이 현실적인 대안으로 판단됨.

3. 디스코드를 활용한 알림 구현

		작업 완료 시 디스코드 메시지로 알림을 보내는 방식을 도입.

		디스코드 봇 또는 웹훅(Webhook)을 활용하여 bash 스크립트 내에서 작업 완료 신호를 디스코드로 전송.

		이를 통해 WSL 환경에서도 확실하고 직관적인 알림 수신 가능.
```
