## 3. UI와 Canvas의 개념

### UI란?

```csharp
User Interface (사용자 인터페이스)

👉 말 그대로 **사용자(플레이어)**가 게임과 직접 상호작용하는 모든 화면 요소를 말해요.

✅ UI의 대표적인 예시:

		버튼: "시작하기", "다음", "다시 하기" 등 클릭 가능한 요소

		텍스트: 점수, 설명, 대사 같은 글자

		슬라이더: 볼륨 조절 바 같은 거

		체크박스나 드롭다운 메뉴: 설정 화면에서 많이 봤죠?

		미니맵: 화면 구석에 나오는 게임 맵

		게임 HUD: 체력, 탄약, 스코어 표시 등

📝 정리하면,

		게임 안에서 플레이어가 보는 정보나 조작하는 부분은 전부 UI입니다.
```

### 캔버스(Canvas)란?

```csharp
UI 요소들을 담는 그릇이자, 화면에 표시되는 위치와 방식을 조절하는 공간이에요.

✅ 캔버스의 역할

		UI 요소들을 한 곳에 모아서 관리함

		UI를 화면에 어떻게 보여줄지 결정함

		UI가 월드 안의 오브젝트들과 혼동되지 않게 따로 분리함
```

### 화면 공간(SCREEN SPACE) vs 월드 공간(WORLD SPACE)

```csharp
스크린 공간(Screen Space)	카메라나 3D 월드와는 독립적으로, 화면 위에 고정되는 영역	점수, 버튼, 체력바 등

월드 공간(World Space)	게임 내 3D 또는 2D 월드 상의 실제 위치에 존재	캐릭터, 배경, 몬스터 등

🧠 쉽게 말해:

UI는 스크린 공간에 위치하고

게임 오브젝트들은 월드 공간에 위치합니다.
```

### 캔버스의 3가지 종류

```csharp
유니티에서는 캔버스가 어떻게 UI를 배치할지에 따라 세 가지 방식이 있어요.
```

```csharp
Screen Space - Overlay	화면 위에 직접 오버레이됨. 가장 단순하고 일반적	대부분의 UI

Screen Space - Camera	특정 카메라와 연결되어 표시됨	카메라 움직임에 따라 UI 위치 연동할 때

World Space	UI가 월드 안에 배치됨 (UI도 하나의 오브젝트처럼)	3D 게임에서 캐릭터 머리 위 HP 표시 등
```

### 캔버스 안의 구조

```csharp
캔버스는 계층 구조를 가집니다.

		부모인 Canvas 안에

				Image, Text, Button 같은 UI 요소들이 자식으로 들어감


		UI는 항상 캔버스 안에 있어야 화면에 보입니다.
```

### UI 요소의 위치와 크기 조절: RectTransform

```csharp
UI 요소들은 일반 Transform 대신 RectTransform을 사용해요.

		📏 Width & Height: 너비/높이

		🎯 Anchors: 어디를 기준으로 위치를 잡을지

		💠 Pivot: 중심점 (회전, 스케일의 기준)

		📌 Position: 현재 위치

UI를 정밀하게 배치하거나 다양한 화면 해상도에 맞추기 위해 꼭 알아야 하는 개념입니다.
```

## 7. UI 위치 조정: Anchor & Pivot 사용법

```csharp
1. Rect Transform 왼쪽 상단의 네모 아이콘 클릭 → Anchor Presets 열기

2. 원하는 기준점(anchor)을 선택 가능

		예: 왼쪽 상단, 중앙, 오른쪽 하단 등

3. Shift 키를 누르면 **Pivot(기준점)**도 함께 설정

4. Alt 키를 누르면 **Position(위치)**도 함께 설정

🧠 Tip: Shift + Alt를 함께 누르고 Preset을 클릭하면 한 번에 기준점 + 위치 + 피벗 설정 완료!
```

### 앵커(Anchor)란?

```csharp
"UI가 어디를 기준으로 붙어 있을지 정하는 점"

예시:

		버튼을 화면 왼쪽 위에 고정하고 싶다면, 앵커를 왼쪽 위로 설정하면 돼.

		화면 크기가 바뀌어도 앵커에 맞춰 UI가 따라 움직여.

🧠 쉽게 말하면:

		"이 버튼은 화면의 왼쪽 위 모서리를 기준으로 배치할게!" 라고 알려주는 거야.
```

### 피벗(Pivot)이란?

```csharp
"UI 요소 안에서 위치 계산의 중심점"

예시:

		버튼의 가운데를 기준으로 회전하거나 크기를 조절하려면 피벗을 가운데로 설정.

		피벗은 해당 UI 요소 자체의 기준점이야.

🧠 쉽게 말하면:

		"이 UI의 어느 지점을 중심으로 움직이고 회전할까?"를 정하는 거야.
```

### 정리: Anchor Presets 사용 팁

```csharp
1. Anchor만 바꾸고 싶을 때
→ 그냥 클릭

2. Anchor + Pivot 같이 바꾸고 싶을 때
→ Shift 누르고 클릭

3. Anchor + Position 같이 바꾸고 싶을 때
→ Alt 누르고 클릭

4. Anchor + Pivot + Position 한 번에 바꾸고 싶을 때
→ Shift + Alt 누르고 클릭
```

### 비유로 이해하면?

```csharp
Anchor: 벽에 못을 박고 그림을 거는 위치 (벽에서 어디에 걸 건지)

Pivot: 그림 안에서 고리의 위치 (그림의 어디를 걸 건지)
```

### Override Sorting

```csharp
✅ 기본 동작

		유니티에서는 UI 요소들이 Hierarchy 상의 순서와 Sorting Layer / Order에 따라 화면에 앞뒤로 보이게 됩니다.

		자식 캔버스는 기본적으로 부모 캔버스의 정렬 방식을 따라가요.

📌 하지만!

		특정 UI 요소를 무조건 위에 보여주고 싶을 때,

		혹은 자식 UI가 따로 정렬돼야 할 때,

		Override Sorting을 켜주면, 부모의 정렬을 무시하고 자신의 정렬 기준으로 따로 작동합니다.
```

## 1. TextMeshPro란?

```csharp
TextMeshPro는 Unity에서 더 정교하고 멋진 텍스트를 표현할 수 있게 해주는 고급 텍스트 시스템이에요.

기본 텍스트보다 폰트 제어, 스타일링, 효과가 더 뛰어나요.
```

## 2. TextMeshPro 설치 및 설정

### 2-1. 설치

```csharp
1. Unity 상단 메뉴 → Window → Package Manager로 이동

2. 왼쪽 드롭다운에서 Packages: Unity Registry 선택

3. TextMeshPro 검색

4. 아직 설치되지 않았다면 Install 클릭

		→ 이미 설치되어 있으면 Remove나 Update 버튼이 있을 수 있어요
```

### 2-2. 필수 리소스 가져오기

```csharp
1. 다시 Window → TextMeshPro → Import TMP Essential Resources 선택

2. Import 창이 뜨면 모두 선택 상태에서 Import 클릭

3. Assets 폴더 안에 TextMeshPro 관련 폴더가 생깁니다
```

## 스크립터블 오브젝트란?

```csharp
간단히 말해, “데이터만 저장하는 스크립트”입니다.

유니티에서 우리가 보통 사용하는 스크립트는 게임 오브젝트에 붙여서 행동을 정의하죠. (MonoBehaviour)

하지만 스크립터블 오브젝트는 게임 오브젝트에 붙지 않고, 단순히 데이터를 저장해 놓는 용도로 사용합니다.
```

### 왜 사용할까요?

```csharp
1. 데이터와 코드를 분리

		게임 데이터를 코드에 직접 쓰면 수정이 어려움 → 실수도 많아짐 😵

		데이터만 따로 빼서 보관하면 훨씬 유지보수가 쉬워져요

2. 재사용 가능

		하나의 스크립터블 오브젝트를 여러 오브젝트가 공유해서 쓸 수 있어요

		예: 무기 데이터를 여러 캐릭터가 공유해서 사용

3. 메모리 효율성

		매번 복사하지 않고, 참조만 하니까 메모리도 덜 먹음

4. 인스펙터에서 쉽게 편집 가능

		코드 몰라도 인스펙터에서 값만 바꾸면 게임 데이터를 수정할 수 있어요
```

### Unity에서 실제 활용 예

```csharp
퀴즈 게임

		질문과 답변 저장

RPG 게임

		무기/아이템 스탯 저장

카드 게임

		카드 정보 (이름, 이미지, 효과) 저장

튜토리얼 게임

		각 단계 설명 텍스트 저장
```

### 정리하자면

```csharp
목적

		데이터만 저장하는 용도

위치

		씬에 존재하지 않음

특징

		코드와 분리되어 관리가 쉬움

장점

		재사용성, 메모리 절약, 인스펙터 편집 가능

예시

		퀴즈 질문, 무기 정보, 카드 속성 등
```

### 새 스크립트 만들기

```csharp
QuestionSO.cs라는 이름으로 생성

기본 함수 Start(), Update()는 삭제

MonoBehaviour → ScriptableObject로 변경
```

```csharp
using UnityEngine;
// Unity의 기본 기능들을 사용하기 위해 꼭 필요한 선언입니다.
// 예: ScriptableObject, SerializeField, TextArea 등을 사용하기 위해 필요합니다.

// CreateAssetMenu 속성(attribute)을 추가합니다.
// 이 코드를 통해 Unity 에디터 내에서 스크립터블 오브젝트를 쉽게 만들 수 있게 됩니다.
//
// menuName: 유니티의 "Create" 메뉴에 표시될 이름입니다. (예: Create > Quiz Question)
// fileName: 새로 생성될 스크립터블 오브젝트의 기본 이름입니다. (예: New Question)
[CreateAssetMenu(menuName = "Quiz Question", fileName = "New Question")]
public class QuestionSO : ScriptableObject
{
    // TextArea 속성은 에디터 인스펙터에서 문자열을 여러 줄로 입력할 수 있게 해줍니다.
    // 괄호 안의 숫자는 (최소 줄 수, 최대 줄 수)를 의미합니다.
    // 예: 최소 2줄, 최대 6줄까지 확장 가능한 텍스트 박스를 만듭니다.
    [TextArea(2, 6)]

    // SerializeField는 private 변수라도 유니티 에디터의 인스펙터에서 값을 설정할 수 있도록 해줍니다.
    // 이 변수는 코드 외부에서는 직접 접근할 수 없지만, 에디터에서는 값을 입력할 수 있습니다.
    // question 변수는 퀴즈의 질문 텍스트를 담는 곳입니다.
    [SerializeField]
    string question = "새로운 질문을 입력하세요";
    // 초기값은 "새로운 질문을 입력하세요"이며, 이후 에디터에서 자유롭게 수정 가능합니다.
}
```

```csharp
CreateAssetMenu: 프로젝트에서 직접 생성 가능하게 만듦

TextArea: 인스펙터에서 편하게 텍스트 편집 가능 (최소 2줄 ~ 최대 6줄)

SerializeField: 외부 클래스는 접근 불가하지만 인스펙터에서는 보임
```

## private 변수 + SerializeField

```csharp
[SerializeField] string question = "새로운 질문을 입력하세요";
```

```csharp
private으로 설정하면 외부에서 직접 접근할 수 없습니다.

하지만 SerializeField를 붙이면 Unity Inspector에서 값은 편집 가능하게 할 수 있습니다.

이렇게 하면 데이터는 보호하면서도 유니티 에디터에서 쉽게 조정할 수 있죠.
```

## Getter 메서드의 개념

```csharp
[CreateAssetMenu(menuName = "Quiz Question", fileName = "New Question")]
public class QuestionSo : ScriptableObject
{
    [TextArea(2,6)]
    [SerializeField] string question = "새로운 질문을 입력하세요";

    public string GetQuestion()
    {
        return question;
    }
}
```

```csharp
Getter 메서드는 외부에서 private 변수의 값을 읽기 전용으로 접근하게 해주는 메서드입니다.

외부 스크립트에서는 question에 직접 접근할 수 없지만, GetQuestion()을 통해 복사본을 얻을 수 있습니다.

이렇게 하면 스크립트 외부에서 데이터를 바꾸는 실수를 방지할 수 있습니다.
```

## 외부 클래스에서 ScriptableObject 사용하기

```csharp
questionText = questionSO.GetQuestion();
```

```csharp
questionSO는 QuestionSo 타입의 ScriptableObject 인스턴스입니다.

외부 클래스에서는 .question처럼 변수에 직접 접근할 수는 없고,

대신 .GetQuestion()처럼 공개된 메서드를 통해 간접적으로 접근합니다.
```

## 접근 제어를 통한 데이터 보호

```csharp
데이터를 무분별하게 바꾸는 것을 막기 위해 private + getter 구조를 사용합니다.

ScriptableObject의 데이터는 읽기는 가능하지만 쓰기는 제한되도록 만드는 것이 좋습니다.
```

요약하자면, ScriptableObject는 재사용 가능한 데이터 저장소이고,

## 1. **스크립터블 오브젝트(ScriptableObject)의 구조**

```csharp
ScriptableObject는 게임 데이터(여기선 퀴즈 데이터)를 에디터에서 직접 입력하고 재사용할 수 있는 방법입니다.
```

```csharp
이 스크립터블 오브젝트는 다음 데이터를 포함합니다:

		문제 텍스트 (question)

		4개의 보기 (answers) – 배열을 사용

		정답 인덱스 (correctAnswerIndex)
```

```csharp
[CreateAssetMenu(menuName = "Quiz Question", fileName = "New Question")]
public class QuestionSo : ScriptableObject
{
    [TextArea(2,6)]
    [SerializeField] string question = "새로운 질문을 입력하세요";
    [SerializeField] string[] answers = new string[4];
    [SerializeField] int correctAnswerIndex;

    public string GetQuestion() => question;
    public string GetAnswer(int index) => answers[index];
    public int GetCorrectAnswerIndex() => correctAnswerIndex;
}
```

## 2. **배열(Array)에 대한 이해**

```csharp
배열이란?

		같은 타입의 변수들을 그룹화할 수 있는 구조

		0번부터 인덱스가 시작됨 (제로 인덱싱)

		데이터를 유연하고 반복적으로 다루기 쉬움
```

```csharp
int[] oddNumbers = { 1, 3, 5, 7, 9 };     // 직접 값 입력
int[] oddNumbers = new int[5];           // 크기만 선언 후 나중에 값 입력
```

## 3. **퀴즈 보기를 배열로 저장하는 이유**

```csharp
각 보기를 따로따로 변수로 만들면 복잡하고 비효율적

배열을 사용하면 4개의 보기를 하나로 관리할 수 있고, 인덱스로 쉽게 접근 가능
```

## 4. **정답을 저장하는 방법**

```csharp
**correctAnswerIndex**라는 정수형 변수로 배열의 정답 위치를 저장

예: 정답이 4번째 보기라면, correctAnswerIndex = 3 (인덱스는 0부터 시작하므로)
```

어디에 추가?

		깔끔한 프로젝트 구조를 위해 Assets/Scripts 폴더로 옮김

// Quiz.cs
// 이 스크립트는 퀴즈 질문 데이터를 UI 텍스트에 표시하는 역할을 합니다.

public class Quiz : MonoBehaviour  // MonoBehaviour는 Unity의 기본 컴포넌트 클래스입니다.
{
    // Inspector에서 설정할 수 있도록 SerializeField를 사용합니다.

    [SerializeField] TextMeshProUGUI questionText;
    // UI에 있는 TextMeshPro 텍스트 요소를 참조합니다.
    // 이 텍스트 박스에 퀴즈 질문을 표시할 것입니다.

    [SerializeField] QuestionSo questions;
    // ScriptableObject 형태로 만든 질문 데이터(QuestionSo)를 참조합니다.
    // 여기에 질문 내용, 보기, 정답 등이 들어있습니다.

    void Start()
    {
        // 게임이 시작될 때(오브젝트가 활성화될 때) 자동으로 실행됩니다.

        questionText.text = questions.GetQuestion();
        // ScriptableObject에서 질문 텍스트를 가져와
        // UI 텍스트 컴포넌트(questionText)에 표시합니다.
    }
}

## Unity에서 인스펙터를 통해 **오브젝트끼리 연결 (** `Quiz` 스크립트를 `QuizCanvas` 연결 원리 )

### 1. `Quiz` 스크립트를 `QuizCanvas`에 붙임

```csharp
먼저 Unity에서 QuizCanvas라는 UI 오브젝트를 선택하고

Quiz.cs 스크립트를 Add Component 해서 붙이죠

그럼 이제 이 오브젝트는 Quiz 스크립트를 실행하게 됩니다.
```

### 2. `[SerializeField] TextMeshProUGUI questionText;` ← 여기가 포인트!

```csharp
이 줄은 TextMeshProUGUI 타입의 컴포넌트를 연결할 공간이에요.

private이지만 [SerializeField] 덕분에 인스펙터에서 보이게 됩니다.

👉 이건 그냥 "이 변수에 뭔가를 넣을 수 있게 해줘!" 라는 뜻이에요.
```

### 3. 인스펙터에서 연결하는 방법

```csharp
1. QuizCanvas를 클릭

2. Inspector에 Quiz (Script)라는 컴포넌트가 보일 거예요

3. 그 안에 Question Text라는 슬롯이 있어요

4. 여기에 Canvas 안에 있는 TextMeshPro 오브젝트 (예: Question Text)를 드래그해서 넣기만 하면 됨!

이제 Quiz.cs 안의 questionText 변수는 그 드래그한 UI 텍스트 컴포넌트를 가리키게 돼요.
```

### 이렇게 연결되면…

```csharp
questionText.text = questions.GetQuestion();
```

```csharp
"이 연결된 텍스트 박스(questionText)의 글자를, 질문 데이터에서 받아온 텍스트로 바꿔줘!"

라는 뜻이 되는 거예요.
```
