## 🎮 캐릭터 이동 모드 개념

### Movement Mode란?

```
Character Movement Component의 상태
  ├─ Walking (걷기) - 기본값
  ├─ Flying (비행)
  ├─ Swimming (수영)
  ├─ Falling (낙하)
  └─ Custom (커스텀)
```

**각 모드의 특징**

**Walking**

```
특징
  ├─ 중력 적용됨
  ├─ 바닥에 붙어서 이동
  ├─ 점프 가능
  └─ 마찰력 있음
```

**Flying**

```
특징
  ├─ 중력 무시됨 ✅
  ├─ 공중에 떠 있음
  ├─ 모든 방향 이동 가능
  └─ 낮은 마찰력
```

## 🔧 코드 정리: Activate Thruster Visual 함수

### 1. 기존 문제

```
Event Start Jetpack
  ├─ Activate (Thruster_Effect_R)
  └─ Activate (Thruster_Effect_L)

Event Stop Jetpack
  ├─ Deactivate (Thruster_Effect_R)
  └─ Deactivate (Thruster_Effect_L)

문제
  └─ 같은 로직이 두 번 반복됨
```

### 2. 함수 생성

```
새 함수: Activate Thruster Visual
  └─ 입력: Active (Boolean)
```

**Boolean 입력이란?**

```
True 전달
  └─ 추진기 활성화

False 전달
  └─ 추진기 비활성화

장점
  └─ 하나의 함수로 켜기/끄기 모두 처리
```

### 3. 함수 내부 구조

```
Activate Thruster Visual
  ↓
입력: Active (Boolean)
  ↓
Branch
  ├─ True → Activate
  │   ├─ Thruster_Effect_R
  │   └─ Thruster_Effect_L
  │
  └─ False → Deactivate
      ├─ Thruster_Effect_R
      └─ Thruster_Effect_L
```

**Branch 노드란?**

```
기능
  └─ if-else 조건문

입력
  └─ Condition (Boolean)

출력
  ├─ True: 조건이 참일 때 실행
  └─ False: 조건이 거짓일 때 실행

예시
  └─ Active가 True면 Activate 실행
  └─ Active가 False면 Deactivate 실행
```

### 4. 사용 방법

```
Event Start Jetpack
  └─ Activate Thruster Visual (Active = True)

Event Stop Jetpack
  └─ Activate Thruster Visual (Active = False)
```

## 🎮 Movement Component 타입 변경

### 1. 왜 타입 변경이 필요한가?

**현재 상태**

```
Movement Component 변수
  └─ 타입: Pawn Movement Component

문제
  └─ Set Movement Mode 함수가 없음

이유
  └─ Pawn Movement Component는 기본 클래스
  └─ 고급 기능 없음
```

**상속 구조**

```
Pawn Movement Component (부모 클래스)
  └─ 기본 이동 기능만

Character Movement Component (자식 클래스)
  └─ 기본 기능 + 걷기/비행/수영 등 고급 기능 ✅
```

**비유**

```
Pawn Movement Component
  └─ "이동 가능한 물체" (일반)

Character Movement Component
  └─ "사람처럼 이동하는 캐릭터" (구체적)
  └─ 걷기, 점프, 비행 등 사람 움직임 특화
```

### 2. 타입 변경 과정

**Store Essential Variables에서 Cast 추가**

```
기존
  Get Movement Component
    ↓
  Set (Movement Component)

변경
  Get Movement Component
    ↓
  Cast to Character Movement Component
    ↓
  Set (Movement Component)
```

**Cast to Character Movement Component란?**

```
기능
  └─ 타입 변환 + 유효성 검사

입력
  └─ Pawn Movement Component

출력 (성공)
  └─ Character Movement Component
  └─ 고급 기능 사용 가능

출력 (실패)
  └─ Cast Failed 실행
  └─ 변환 불가능
```

**왜 Cast가 필요한가?**

```
상황
  └─ 변수는 부모 타입 (Pawn Movement)
  └─ 실제 오브젝트는 자식 타입 (Character Movement)

해결
  └─ Cast로 "이건 Character Movement야!"라고 확인
  └─ 그제야 고급 기능 사용 가능
```

### 3. 변수 타입 직접 변경

**방법 1: 새 변수 생성 (안전)**

```
1. 새 변수 생성
   └─ 타입: Character Movement Component

2. Cast 결과를 새 변수에 저장

3. 기존 변수 삭제
```

**방법 2: 기존 변수 타입 변경 (빠름)**

```
1. Movement Component 변수 선택

2. Variable Type → Character Movement Component

3. 경고 메시지
   "연결이 끊어질 수 있습니다. 계속할까요?"

4. "Change Variable Type" 클릭

5. 끊어진 연결 수동 수정
```

**경고가 나타나는 이유**

```
타입 변경 시
  └─ 기존 연결이 호환 안 될 수 있음

예시
  └─ Set 노드가 Pawn Movement 받는데
  └─ Character Movement로 바뀌면 불일치

해결
  └─ Cast 결과를 Set에 연결
```

### 4. 수정 작업

```
기존 연결 끊김
  Set (Movement Component)
    ↓
  입력이 없음

수정
  Cast to Character Movement Component
    ↓
  As Character Movement Component (반환값)
    ↓
  Set (Movement Component)
```

## 🎯 Orient Rotation to Movement

### 1. 개념 이해

**Orient Rotation to Movement란?**

```
정의
  └─ "이동 방향으로 회전 조정"

True (기본값 - 걷기)
  ├─ 캐릭터가 이동하는 방향을 봄
  ├─ W 누르면 앞 보고 이동
  ├─ A 누르면 왼쪽 보고 이동
  └─ 카메라와 무관

False (비행)
  ├─ 이동 방향과 무관
  ├─ 다른 방식으로 회전 제어
  └─ Controller Rotation 사용 가능
```

**비유**

```
True = 자동차
  └─ 핸들 돌린 방향으로 차 돌아감

False = 드론
  └─ 조종기 방향대로 기체 회전
```

### 2. 비행 시작 시 설정

```
Set Movement Mode (Flying)
  ↓
Set Orient Rotation to Movement
  └─ False
```

**왜 False로?**

```
이유
  └─ 이동 방향 말고 Controller로 회전 제어

효과
  └─ 카메라 방향으로 캐릭터 회전 준비
```

### 3. 비행 종료 시 설정

```
Set Movement Mode (Walking)
  ↓
Set Orient Rotation to Movement
  └─ True
```

**왜 True로?**

```
이유
  └─ 걷기는 이동 방향 보는게 자연스러움

효과
  └─ 걷는 방향으로 자동 회전
```

## 🎮 Use Controller Rotation Yaw

### 1. 개념 이해

**Controller란?**

```
정의
  └─ 캐릭터를 조종하는 컨트롤러
  └─ 보통 Player Controller

Controller Rotation
  └─ 컨트롤러(카메라)가 향하는 방향

Yaw
  └─ 좌우 회전 (수평 회전)

Pitch
  └─ 상하 회전 (위아래)

Roll
  └─ 기울기 회전 (좌우 기울임)
```

**Use Controller Rotation Yaw란?**

```
True
  ├─ 캐릭터 회전 = 카메라 회전
  ├─ 카메라 돌리면 캐릭터도 돌아감
  └─ 즉각 반영 (스냅)

False (기본값)
  ├─ 캐릭터 회전 ≠ 카메라 회전
  ├─ 카메라 자유롭게 회전 가능
  └─ 캐릭터는 독립적
```

### 2. 비행 시작 시 설정

```
Controlled Character (Get, Validated)
  ↓
Set Use Controller Rotation Yaw
  └─ True
```

**효과**

```
카메라 왼쪽 회전
  └─ 캐릭터도 왼쪽 회전

카메라 오른쪽 회전
  └─ 캐릭터도 오른쪽 회전

결과
  └─ 카메라 방향 = 캐릭터 방향
```

### 3. 비행 종료 시 설정

```
Set Use Controller Rotation Yaw
  └─ False
```

**효과**

```
카메라 회전
  └─ 캐릭터는 그대로

이동 방향
  └─ Orient Rotation to Movement로 제어
```

## 🔄 Use Controller Desired Rotation

### 1. 문제 발견

```
Use Controller Rotation Yaw = True
  └─ 즉각 스냅됨
  └─ 뚝뚝 끊기는 느낌
  └─ 부자연스러움
```

### 2. Use Controller Desired Rotation

**개념**

```
Use Controller Rotation Yaw
  └─ 즉각 회전 (스냅)
  └─ 0.1초 만에 180도 회전 가능

Use Controller Desired Rotation
  └─ 부드럽게 보간 (Interpolation)
  └─ 서서히 목표 회전으로 이동 ✅
```

**Interpolation이란?**

```
정의
  └─ 두 값 사이를 부드럽게 전환

예시
  └─ 현재: 0도
  └─ 목표: 180도
  └─ 보간: 0 → 45 → 90 → 135 → 180 (부드럽게)
```

### 3. 설정 변경

```
비행 시작
  ├─ Use Controller Rotation Yaw 제거
  └─ Use Controller Desired Rotation = True

비행 종료
  └─ Use Controller Desired Rotation = False
```

### 4. Rotation Rate 조정

**Character Movement Component**

```
Rotation Rate
  ├─ 기본값: 720
  └─ 변경값: 1440
```

**Rotation Rate란?**

```
정의
  └─ 초당 회전 속도 (도/초)

720
  └─ 1초에 720도 회전 (2바퀴)
  └─ 0.5초에 1바퀴

1440
  └─ 1초에 1440도 회전 (4바퀴)
  └─ 0.25초에 1바퀴
  └─ 더 빠른 반응 ✅
```

**왜 늘리나?**

```
문제
  └─ 720은 조금 느림
  └─ 비행 중 반응 느린 느낌

해결
  └─ 1440으로 증가
  └─ 빠른 방향 전환
```

**주의**

```
카메라 회전 속도에도 영향
  └─ Rotation Rate 공유
  └─ 너무 크면 어지러움
  └─ 1440 정도가 적당
```

## 🎓 용어 정리

**Movement Mode (이동 모드)**

- 캐릭터가 움직이는 방식
- Walking, Flying, Swimming 등

**Yaw (요)**

- 좌우 회전 (수평 회전)
- 나침반처럼 0~360도

**Pitch (피치)**

- 상하 회전 (위아래)
- 고개 끄덕임

**Roll (롤)**

- 좌우 기울임
- 비행기 날개 기울이기

**Interpolation (보간)**

- 두 값 사이 부드러운 전환
- 급격한 변화 방지

**Rotation Rate (회전 속도)**

- 초당 회전하는 각도
- 단위: 도/초

**Controller (컨트롤러)**

- 캐릭터를 조종하는 객체
- 보통 Player Controller

**Braking (제동)**

- 멈추는 힘
- 클수록 빨리 정지

## 📍 Get Actor Up Vector

### 1. 개념 이해

**Actor Up Vector란?**

```
정의
  └─ 액터의 위쪽 방향 벡터

특징
  ├─ 액터의 로컬 좌표계 기준
  ├─ 항상 크기 1인 단위 벡터
  └─ 액터 회전에 따라 변함
```

**왜 (0, 0, 1)이 아닌가?**

```
(0, 0, 1)
  └─ 월드의 절대 위쪽
  └─ 항상 하늘 방향

Get Actor Up Vector
  └─ 캐릭터 기준 위쪽
  └─ 캐릭터가 기울어지면 방향도 변함
```

**예시**

```
캐릭터가 똑바로 서있음
  └─ Up Vector = (0, 0, 1)
  └─ 월드 위쪽과 동일

캐릭터가 옆으로 누움
  └─ Up Vector = (1, 0, 0) 또는 (-1, 0, 0)
  └─ 캐릭터 기준으로는 여전히 "위"

우리 경우 (일반적)
  └─ 캐릭터는 항상 똑바로 서있음
  └─ Up Vector = (0, 0, 1)
  └─ 하지만 안전하게 Get Actor Up Vector 사용
```

### 2. Vector 곱셈

**벡터 \* 스칼라**

```
Up Vector: (0, 0, 1)
  ×
Scalar: 0.25
  =
Result: (0, 0, 0.25)
```

**의미**

```
원래 벡터
  └─ 방향: 위쪽
  └─ 크기: 1

곱셈 후
  └─ 방향: 위쪽 (동일)
  └─ 크기: 0.25 (축소)

효과
  └─ 같은 방향으로 약하게 이동
```

## 🎛️ Thruster Input Factor 변수

### 1. 변수 생성

```
변수명: Thruster Input Factor
  ├─ 타입: Float
  ├─ 기본값: 0.25
  └─ Category: Kick Input
```

**Float 타입이란?**

```
정의
  └─ 소수점 있는 숫자

예시
  └─ 0.25, 1.5, -0.1

용도
  └─ 세밀한 값 조정
```

### 2. 값의 의미

**0.25의 의미**

```
벡터 크기
  └─ 매 프레임 0.25만큼 위로 이동

프레임 누적
  └─ 60 FPS 기준
  └─ 1초 = 0.25 × 60 = 15 유닛 상승
```

**값 조정**

```
값을 키우면 (예: 0.5)
  └─ 더 빠르게 상승

값을 줄이면 (예: 0.1)
  └─ 더 천천히 상승
```

### 3. 왜 변수로 만드나?

**하드코딩 vs 변수**

```
하드코딩 (0.25 직접 입력)
  ├─ 수정하려면 블루프린트 열어야 함
  ├─ 컴파일 필요
  └─ 테스트 불편

변수
  ├─ Details 패널에서 즉시 수정
  ├─ 컴파일 불필요
  └─ 빠른 테스트 ✅
```

**장점**

```
실시간 조정
  └─ 플레이 중 바로 수정 가능

균형 조정
  └─ 여러 값 시도하며 최적값 찾기

재사용
  └─ 다른 곳에서도 참조 가능
```

## 📊 2D Blend Space 개념

### 1D vs 2D Blend Space

**1D Blend Space (Idle-Walk-Run)**

```
한 축만 사용
  └─ 가로축: Speed (0 → 600)

애니메이션 배치
  ├─ 0: Idle
  ├─ 300: Walk
  └─ 600: Run

블렌딩
  └─ 속도에 따라 선형 블렌딩
  └─ Speed 150 = Idle 50% + Walk 50%
```

**2D Blend Space (비행)**

```
두 축 사용
  ├─ 가로축 (X): 좌우 입력
  └─ 세로축 (Y): 전후 입력

평면 공간
  └─ 2차원 그리드에 애니메이션 배치
  └─ XY 값에 따라 4개 애니메이션 블렌딩
```

**왜 2D가 필요한가?**

```
비행은 방향이 2차원
  ├─ 좌우 (X축)
  ├─ 전후 (Y축)
  └─ 동시 고려 필요

예시
  └─ 앞-왼쪽 대각선 비행
  └─ Forward + Left 블렌딩
```

## 🎮 Enhanced Input Action Value 분석

### IA_Move의 Action Value

```
W 키 (앞)
  └─ (X: 0, Y: 1)

S 키 (뒤)
  └─ (X: 0, Y: -1)

A 키 (왼쪽)
  └─ (X: -1, Y: 0)

D 키 (오른쪽)
  └─ (X: 1, Y: 0)
```

**Vector2D 구조**

```
정의
  └─ 2개의 float 값
  └─ (X, Y)

범위
  ├─ 키보드: -1, 0, 1 (불연속)
  └─ 조이스틱: -1.0 ~ 1.0 (연속)
```

**조이스틱의 장점**

```
키보드
  └─ -1 → 0 → 1 (갑작스러운 변화)

조이스틱
  └─ -1.0 → -0.5 → 0 → 0.5 → 1.0
  └─ 부드러운 전환
  └─ 세밀한 제어
```

Vector2D ✅
  └─ 파란색 아이콘
  └─ 단일 벡터

Vector2D Array ❌
  └─ 배열 아이콘
  └─ 벡터들의 리스트

올바른 선택
  └─ 단일 Vector2D 선택

## 💾 Cached Pose (포즈 캐싱)

### 문제: 같은 포즈를 여러 곳에 사용

```
Locomotion State Machine
  ├─ Walking Pose에 연결
  └─ Falling Pose에도 연결 필요

문제
  └─ 핀 하나를 두 곳에 연결 불가
```

**시도**

```
Locomotion → Walking 연결
  ↓
Locomotion → Falling 연결 시도
  ↓
❌ Walking 연결이 Falling으로 이동
  └─ 동시 연결 불가
```

### Cached Pose 개념

**정의**

```
Cached Pose
  └─ 애니메이션 포즈를 "저장"
  └─ 변수처럼 여러 곳에서 사용
```

**비유**

```
일반 변수
  └─ 데이터를 저장
  └─ 여러 곳에서 Get으로 사용

Cached Pose
  └─ 애니메이션 포즈를 저장
  └─ 여러 곳에서 Use로 사용
```

용도
  └─ 상태별 애니메이션
  └─ Movement Mode별 분기

확장성
  └─ Pin 추가로 케이스 확장
```

### Cached Pose

```
기능
  └─ 포즈 저장 후 재사용

장점
  ├─ 중복 계산 방지
  ├─ 성능 향상
  └─ 여러 곳에 사용 가능

사용법
  ├─ Save: 저장
  └─ Use: 사용 (여러 개 가능)
```

### Smoothing Time

```
정의
  └─ 목표값까지 도달 시간

효과
  └─ 부드러운 전환
  └─ 불연속 입력 완화

설정
  └─ 0.1 ~ 0.3초 권장
```

  └─ 협업 시 충돌 감소
```

## ⚠️ 주의사항

### 1. Vector2D 타입 선택

```
❌ Vector2D Array
  └─ 배열 아이콘

✅ Vector2D
  └─ 파란색 단일 아이콘
```

### 2. Blend Space 축 범위

```
Enhanced Input과 일치
  └─ -1.0 ~ 1.0

다르면
  └─ 값 변환 필요
  └─ 복잡해짐
```

### 3. Smoothing Time 과다

```
너무 크면 (1초 이상)
  └─ 반응 느림
  └─ 입력 지연 느낌

적절한 값
  └─ 0.1 ~ 0.3초
```

### 4. Default Pose

```
사용 안 하더라도
  └─ 연결 권장

이유
  └─ 예상 밖 상황 대비
  └─ T-Pose 방지
```

### 5. Interface 함수 vs 이벤트

```
출력 있으면
  └─ 함수 ✅

출력 없으면
  └─ 이벤트 OK
```

## 🎓 용어 정리

**2D Blend Space**

- 2개 축으로 애니메이션 블렌딩
- 방향성 움직임에 사용

**Vector2D**

- 2차원 벡터 (X, Y)
- 2D 입력 표현

**Enum (열거형)**

- 정해진 값들의 목록
- 타입 안전한 선택

**Cached Pose**

- 저장된 애니메이션 포즈
- 재사용 가능

**Smoothing Time**

- 값 전환 시간
- 부드러운 애니메이션

**Split Struct Pin**

- 구조체를 개별 핀으로 분리
- 각각 따로 연결 가능

**Pure Node**

- 실행 핀 없는 노드
- 값만 반환

**Interpolation (보간)**

- 두 값 사이 부드러운 전환
- 중간값 자동 계산
