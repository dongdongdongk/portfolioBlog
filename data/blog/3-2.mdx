## 1. 오디오 시스템의 기본 요소

유니티에서 오디오를 구현하려면 **세 가지 필수 구성 요소**가 필요합니다.

- **🎵 오디오 파일 (Audio Clip)**
  실제 재생될 소리(mp3, ogg, wav 등).
- **🔊 오디오 소스 (Audio Source)**
  오디오를 게임 오브젝트에서 재생하는 컴포넌트.
- **👂 오디오 리스너 (Audio Listener)**
  소리를 "듣는" 역할, 일반적으로 메인 카메라에 존재.

➡️ 오디오 파일은 **콘텐츠**, 오디오 소스는 **플레이어(재생기)**, 오디오 리스너는 **귀**라고 비유할 수 있습니다.

---

## 2. 오디오 파일(Audio Clip) 이해하기

- 오디오 파일은 **실제 녹음된 소리**입니다.
- 지원되는 대표 형식:
  - **MP3** : 용량 적당, 압축률 높음, 범용적
  - **OGG** : 고음질 + 용량 효율 → 유니티에서 권장
  - **WAV** : 무손실, 하지만 용량 큼

📌 **Tip**: 효과음(SFX)은 보통 짧으므로 OGG 권장, 음악은 MP3도 괜찮음.

---

## 3. 오디오 소스(Audio Source)

- 게임 오브젝트에 붙여야 소리가 재생됨.
- 위치 기반 재생이 가능 → 3D 공간에서 거리/방향에 따라 음량이 달라짐.
- 예: 로켓 오브젝트에 Audio Source 붙이면 로켓에서 나는 소리처럼 들림.

---

## 4. 오디오 리스너(Audio Listener)

- **소리를 듣는 주체**, 보통 **메인 카메라**에 자동으로 붙어 있음.
- 게임 내에서 **귀 역할**을 담당.
- 3D 오디오 지원 → 소리가 가까우면 커지고, 멀면 작아짐.

⚠️ **주의**: 씬(Scene)에 **리스너는 반드시 하나만 존재해야 함**. (여러 개 있으면 경고 발생)

## 5. 오디오 파일 관리하기 (Assets/Audio 폴더)

- Assets 안에 **Audio 폴더**를 만들어 관리.
- 다운로드한 효과음을 정리해 넣으면 프로젝트가 깔끔해짐.

## 6. 무료 음향 효과 얻는 방법

- [**Freesound.org**](https://freesound.org/) : 무료 효과음 라이브러리
- **OpenGameArt.org** : 무료 음악/효과음 제공
- 검색 예시: “rocket booster”, “explosion”, “jump”

---

## 7. Audacity로 직접 음향 효과 만들기

- 무료 오디오 편집 툴
- 기능:
  - 직접 녹음 → 불필요한 부분 잘라내기
  - **Pitch(음정)**, **Tempo(속도)** 조정
  - **Delay(딜레이), Reverb(리버브)** 같은 효과 추가
- 만든 소리를 MP3, OGG, WAV 등으로 내보내 사용 가능

## 8. Audio Source의 주요 옵션

### 🔑 자주 쓰는 옵션 정리

- **Audio Clip**
  어떤 소리를 재생할지 지정하는 필드.
- **Play On Awake**
  - ✔️ 체크 시: 게임 오브젝트가 활성화되면 자동 재생
  - ❌ 체크 해제 시: 스크립트나 이벤트로 직접 재생해야 함
- **Loop**
  - ✔️ 체크 시: 소리가 끝나면 자동으로 다시 재생
  - ❌ 체크 해제 시: 한 번만 재생 후 멈춤
- **Volume**
  소리 크기 (0.0 ~ 1.0)
- **Pitch**
  소리의 높낮이 조절 (0.5 → 낮고 느림, 2.0 → 높고 빠름)
- **3D Sound Settings**
  소리의 공간감 조절
  - **Spatial Blend** : 2D ↔ 3D 비율
  - **Min Distance** : 이 거리 이내에서는 항상 최대 볼륨
  - **Max Distance** : 이 거리 이상에서는 거의 안 들림

---

## 9. 오디오 파일 형식과 권장 사항

- **OGG** : 유니티에서 가장 추천 (효율적 + 호환성 높음)
- **MP3** : 음악에 적합, 파일 크기 작음
- **WAV** : 음질 최고, 하지만 용량 큼 → 잘 안 씀

## 10. 자주 겪는 문제와 해결 방법

- **문제 1: 게임 시작 시 원하지 않는 소리가 들림**

- **문제 2: 소리가 한 번만 나오고 멈춤**
  → `Loop` 옵션 체크
- **문제 3: 씬에 소리가 전혀 안 들림**

## 1. 오디오 시스템 기본 개념

- **오디오를 재생하기 위해 필요한 3요소**
  1. 🎧 **Audio Listener**
     - 기본적으로 `Main Camera`에 붙어 있음.
     - 게임에서 "플레이어의 귀" 역할.
     - 오디오 소스를 감지해서 소리를 출력.
  2. 🔊 **Audio Source**
     - 소리를 내는 주체.
     - 오디오 클립(AudioClip)을 재생/중지할 수 있음.
  3. 🎶 **Audio Clip**
     - 실제 음원 파일(mp3, wav 등).
     - Audio Source가 이 클립을 재생함.

---

## 2. AudioSource 컴포넌트 이해하기

- `AudioSource`는 오디오를 재생하는 **실행 장치**.
- 주요 옵션들:
  - **Volume** : 소리 크기 (0~1).
  - **Loop** : 체크하면 무한 반복 재생.
  - **Play on Awake** : 씬이 시작되자마자 자동 재생.
  - **Spatial Blend** : 2D 사운드 / 3D 사운드 설정.

---

## 3. AudioClip 연결 및 Play on Awake 옵션

- **AudioClip 연결** : Inspector에서 AudioSource에 원하는 사운드 파일 드래그.
- **Play on Awake** 옵션
  - ✅ 켜짐: 게임 시작과 동시에 자동 재생됨.
  - ❌ 꺼짐: 코드나 이벤트를 통해서만 재생됨.
  - 이번 강의에서는 **Play on Awake를 꺼야 함**. (엔진 소리가 자동으로 나오면 안 되기 때문)

---

## 4. AudioSource 주요 메서드와 속성

| 메서드 / 속성           | 설명                               |
| ----------------------- | ---------------------------------- |
| `audioSource.Play()`    | 오디오 클립 재생 시작              |
| `audioSource.Stop()`    | 오디오 재생 즉시 중지              |
| `audioSource.isPlaying` | 현재 오디오 재생 여부 (true/false) |

---

## 5. if / else 문을 활용한 사운드 제어

- 기본 구조:

```csharp
if (조건) {
    // 조건이 참일 때 실행
} else {
    // 조건이 거짓일 때 실행
}
```

- 이번 구현에서는:
  - **if (Space bar 누름)** → 추진력 발생 + 오디오 재생
  - **else (Space bar 안 누름)** → 오디오 중지

---

## 6. 논리 연산자와 ! (not) 사용하기

- `!` 는 **not(부정)** 연산자.
- `!audioSource.isPlaying` → "오디오가 재생 중이 아니면"
- 이걸 체크하는 이유:
  - 이미 소리가 재생 중인데 `Play()`를 또 호출하면 **중복 재생** 발생.
  - 예: 로켓 소리가 겹쳐져서 7000개가 동시에 울리는 상황 😂
  - 따라서 "재생 중이 아닐 때만 실행" 조건을 넣어야 함.

---

## 7. 최적의 오디오 재생 처리하기

- 단순히 `Play()`와 `Stop()`만 쓰면 소리가 중복되거나 어색할 수 있음.
- 그래서 조건을 이렇게 나눔:

```csharp
if (thrust.IsPressed())
{
    // 추진력 입력 O
    if (!audioSource.isPlaying)
    {
        audioSource.Play();
    }
}
else
{
    // 추진력 입력 X
    audioSource.Stop();
}
```

- ✅ Space bar 누를 때 → 소리가 한 번만 시작
- ✅ Space bar 뗄 때 → 소리 즉시 중단

---

## 8. 전체 코드 흐름 분석

```csharp
private void ProcessThrust()
{
    if (thrust.IsPressed()) // Space bar 누르면
    {
        rb.AddRelativeForce(Vector3.up * thrustStrength * Time.fixedDeltaTime);

        if (!audioSource.isPlaying) // 소리가 안 나고 있으면
        {
            audioSource.Play(); // 소리 재생
        }
    }
    else // Space bar 안 누르면
    {
        audioSource.Stop(); // 소리 중지
    }
}
```

### 🔑 핵심 정리

1. **조건문 if / else** → "입력 있으면 / 없으면" 구분.
2. **논리 연산자 !** → "재생 중이 아니면 실행" 제어.
3. **AudioSource.Play() / Stop()** → 소리 On/Off.
4. **isPlaying 속성** → 중복 재생 방지.

---

👉 이번 강의의 핵심은 단순히 오디오를 켜고 끄는 게 아니라,

- **조건문(if/else)**
- **논리 연산자(!)**
- **컴포넌트 참조(GetComponent)**
- **AudioSource 동작 원리**

이 네 가지 개념을 함께 이해하는 데 있습니다.

## 1. 조건문과 switch 문의 개념

- **조건문**: 특정 상황(조건)에 따라 다른 동작을 실행하도록 제어하는 구문.
- 기존에는 **if / else if / else** 구조를 사용했음.
- 이번에는 **switch 문**을 사용:
  - 하나의 **변수 값**을 여러 경우(case)와 비교 가능.
  - 각 case마다 다른 동작 수행.
  - 가독성이 좋고 “분기 처리”를 깔끔하게 정리할 수 있음.
  - `default` 문으로 모든 case에 해당하지 않는 상황 처리 가능.

✅ 문법 구조:

```csharp
switch (변수) {
    case 값1:
        // 동작
        break;
    case 값2:
        // 동작
        break;
    default:
        // 나머지 동작
        break;
}
```

---

## 2. 태그(Tag) 시스템 이해하기

- **Tag**는 게임 오브젝트를 구분하는 **라벨(이름표)**.
- 특정 오브젝트를 코드에서 식별하거나 조건 분기할 때 활용.
- 예시:
  - `"Friendly"` : 플레이어에게 무해한 오브젝트
  - `"Finish"` : 레벨 완료 지점
  - `"Fuel"` : 아이템, 연료 등
- Unity에서 태그 추가:
  1. 오브젝트 선택 → **Inspector 상단**의 Tag 메뉴.
  2. `Add Tag...` 클릭 → + 버튼 → 새로운 태그 이름 입력.
  3. 다시 오브젝트 선택 후, 원하는 태그 적용.

## 3. Collider(콜라이더)와 충돌 감지

- **Collider**: 물리적 충돌을 감지하는 보이지 않는 경계.
- 오브젝트에 Collider가 있어야 **충돌 이벤트** 발생.
- 종류:
  - Box Collider (박스 형태)
  - Sphere Collider (구체 형태)
  - Capsule Collider (원통 형태)
  - Mesh Collider (메시 모양 그대로)
- 옵션:
  - **Is Trigger**:
    - 체크 O → 충돌은 감지하되 실제 물리적 반응(튕김, 멈춤)은 없음.
    - 주로 아이템 획득, 영역 진입 이벤트에 사용.
    - 관련 메서드: `OnTriggerEnter()`
    - 반대로, 체크 X → 물리 충돌이 실제로 발생.
    - 관련 메서드: `OnCollisionEnter()`

## 4. Rigidbody(리지드바디)와 물리 엔진

- Rigidbody를 추가해야 오브젝트가 **물리 법칙(중력, 질량, 마찰 등)**을 따름.
- 주요 옵션:
  - **Mass** : 질량 (값이 클수록 무겁게 움직임)
  - **Drag** : 공기 저항 (값이 클수록 빨리 멈춤)
  - **Angular Drag** : 회전 저항
  - **Use Gravity** : 중력 적용 여부
  - **Is Kinematic** : 물리 엔진의 힘을 받지 않고 스크립트로만 제어할지 여부
- 🚨 충돌 감지 조건:
  - 두 오브젝트 중 **하나 이상**은 Rigidbody 필요.
  - Collider만 있으면 물리 충돌 인식이 안 됨.

## 5. OnCollisionEnter() 메서드 이해하기

- Unity의 **이벤트 메서드** 중 하나.
- 물리적 충돌이 발생했을 때 자동 실행됨.
- 기본 구조:

```csharp
void OnCollisionEnter(Collision collision) {
    // collision은 충돌한 대상에 대한 정보
}
```

- `collision.gameObject` : 충돌한 오브젝트
- `collision.gameObject.tag` : 충돌한 오브젝트의 태그

---

## 6. switch 문을 이용한 충돌 분기 처리

- 태그(Tag)를 기준으로 충돌 처리.
- 장점:
  - if/else보다 깔끔하게 정리 가능.
  - 새로운 태그 추가 시 case만 늘리면 됨.
- case 작성 시 주의사항:
  - 문자열 비교 → 반드시 철자 정확해야 함 (`"Finish"` vs `"Finnish"` 실수 주의)
  - 각 case 뒤에는 **break** 필요 (없으면 아래 case까지 실행됨)

---

## 7. 코드 예제와 분석

```csharp
using UnityEngine;

public class CollisionHandler : MonoBehaviour
{
    void OnCollisionEnter(Collision collision)
    {
        switch (collision.gameObject.tag)
        {
            case "Friendly":
                Debug.Log("Friendly: 안전한 오브젝트입니다.");
                break;

            case "Finish":
                Debug.Log("Finish: 레벨 완료!");
                break;

            case "Fuel":
                Debug.Log("Fuel: 연료 아이템을 발견했습니다.");
                break;

            default:
                Debug.Log("Default: 알 수 없는 오브젝트와 충돌.");
                break;
        }
    }
}
```

### 🔎 분석

- `OnCollisionEnter()` → 충돌 발생 시 자동 호출.
- `collision.gameObject.tag` → 충돌한 오브젝트의 태그를 문자열로 가져옴.
- case마다 상황에 맞는 Debug.Log 메시지 출력.
- default → 태그가 없는 오브젝트와 충돌했을 때 실행.

---

## 8. 실습 아이디어와 응용

- 🚀 **플레이어 로켓 충돌 처리**
  - Friendly → 단순 메시지 출력
  - Finish → 축하 애니메이션 + 다음 레벨 로드
  - Fuel → 연료 증가
  - Default → 폭발 효과 + 게임 오버
- 🎮 **응용하기**
  - 태그 대신 **Layer**를 사용해 분류 가능.
  - switch문에서 Debug.Log 대신 → 효과음, 파티클, 씬 전환 등 실행.
  - Trigger 충돌(`OnTriggerEnter`)로 아이템 획득 구현.

## 1. 씬(Scene)과 레벨(Level)의 개념

- **Scene** : 유니티에서 게임의 한 화면, 하나의 맵 또는 레벨을 의미.
  → 예: 메뉴 화면(Scene 0), 스테이지 1(Scene 1), 스테이지 2(Scene 2).
- **Level** : 게임 진행 단계, 주로 Scene과 동일하게 쓰임.
- 따라서 **Scene = Level** 로 이해해도 무방하다.

## 2. Build Settings(빌드 세팅)과 Scene List 관리

- [File] → [Build Settings] 창에서 **Scene List**를 확인할 수 있음.
- **Scene List**는 최종 빌드에 포함될 씬들을 순서대로 저장.
- 각 씬은 **인덱스(Index)** 를 가진다. (0부터 시작)
  - Scene 0 → 첫 번째 씬
  - Scene 1 → 두 번째 씬
- 씬을 등록하는 방법:
  1. `Add Open Scenes` 버튼 클릭 → 현재 열려 있는 씬 추가
  2. 프로젝트 창에서 씬 파일을 드래그해서 추가

👉 **중요:** 씬 인덱스는 `SceneManager.LoadScene(int index)`에서 사용됨.

## 3. SceneManager 클래스 이해하기

**Namespace:** `using UnityEngine.SceneManagement;`

→ 씬 관리와 관련된 기능을 제공하는 클래스.

### 주요 메소드

- **LoadScene()**
  - `SceneManager.LoadScene(int sceneBuildIndex)`
  - `SceneManager.LoadScene(string sceneName)`
  - 씬을 새로 로드 (기존 씬은 언로드됨).
- **GetActiveScene()**
  - 현재 활성화된 씬의 정보를 가져옴.
  - `.buildIndex` → 씬 인덱스 반환
  - `.name` → 씬 이름 반환
- **SetActiveScene()**
  - 특정 씬을 활성화된 씬으로 지정
- **MergeScenes()**
  - 두 씬을 합쳐서 하나로 병합

👉 여기서는 **LoadScene() + GetActiveScene()** 조합이 핵심.

## 4. 충돌 이벤트와 Scene Reload 구현

- **충돌 이벤트:**
  - `void OnCollisionEnter(Collision collision)` → 물리 충돌이 발생했을 때 호출.
  - `collision.gameObject.tag`로 어떤 오브젝트와 부딪혔는지 확인 가능.
- **목표:**
  → 플레이어가 특정 오브젝트(벽, 땅 등)에 충돌하면 씬을 다시 로드.

## 5. switch문으로 충돌 유형 구분하기

```csharp
switch (collision.gameObject.tag)
{
    case "Friendly":
        Debug.Log("Friendly");
        break;
    case "Finish":
        Debug.Log("Finish");
        break;
    case "Fuel":
        Debug.Log("Fuel");
        break;
    default:
        ReloadLevel();
        break;
}
```

- `"Friendly"`, `"Finish"`, `"Fuel"` 태그는 충돌해도 게임이 유지됨.
- **default** → 그 외의 모든 경우(벽, 땅 등) → **레벨 리로드**

👉 태그(Tag) 기반 충돌 처리는 확장성이 높음 (필요시 태그만 추가).

## 6. 메소드 분리와 코드 정리 (ReloadLevel)

- **문제점:** switch문 안에 바로 `SceneManager.LoadScene(0)`을 쓰면 가독성 저하.
- **해결책:** 메소드로 분리 → 유지보수 용이.

```csharp
private static void ReloadLevel()
{
    int currentScene = SceneManager.GetActiveScene().buildIndex;
    SceneManager.LoadScene(currentScene);
}
```

## 7. 매직 넘버 제거와 Scene 인덱스 활용

- `SceneManager.LoadScene(0)` → 숫자(매직 넘버)만 보면 의미 불명확.
- `SceneManager.GetActiveScene().buildIndex` → 현재 씬 인덱스를 가져옴.
- 이렇게 하면 **현재 플레이 중인 씬을 그대로 다시 로드** 가능.
- 확장성 ↑ (씬이 여러 개 있을 때도 자동으로 동작).

## 1. 여러 개의 레벨(씬) 만들기

- 유니티에서는 게임의 각 단계를 **씬(Scene)** 으로 관리한다.
- `File > New Scene` 또는 **Ctrl+D(복제)** 를 통해 새로운 레벨을 추가할 수 있다.
- 이번 강의에서는 **Over, Under, Through** 라는 3개의 씬을 사용한다.

👉 씬 = 레벨이라고 생각하면 이해가 쉽다.

---

## 2. 씬 이름 정하기: 기능적 네이밍

- 단순히 `Level1, Level2` 같은 이름은 유지보수가 어렵다.
  - 나중에 레벨 순서를 바꾸면 전부 다시 이름을 바꿔야 함.
- 대신 **씬의 특징**을 반영한 이름을 붙인다.
  - 예: Over, Under, Through

👉 "기능적 이름 짓기"는 팀 프로젝트에서도 협업 효율을 높인다.

---

## 3. Prefab(프리팹)과 적용하기

- 프리팹이란?
  오브젝트를 **재사용 가능한 원본(템플릿)** 으로 만들어 놓은 것.
- 씬에서 오브젝트를 수정했으면 **Apply(적용)** 해서 프리팹에 반영해야 한다.
- 이렇게 하면 모든 씬에서 동일한 오브젝트가 최신 상태로 유지된다.

👉 예: 로켓 프리팹을 수정하면, Over/Under/Through 모든 씬에 자동 반영.

---

## 4. 씬 빌드 세팅(Build Settings)

- `File > Build Settings` 에서 게임에 포함할 씬들을 관리한다.
- 씬 목록에 추가한 순서대로 **Build Index** (번호)가 부여된다.
  - Over = 0
  - Under = 1
  - Through = 2

👉 코드에서 `SceneManager.LoadScene(인덱스)` 로 불러올 때 이 인덱스를 사용한다.

---

## 5. 씬 전환 개념 이해하기

- 플레이어가 특정 조건을 만족하면 **다음 레벨(씬)로 이동**해야 한다.
- 조건 예시:
  - 착륙장에 도착 (Finish 태그 오브젝트와 충돌)
  - 특정 아이템 획득

👉 이를 구현하기 위해 충돌 감지 + 씬 로드 코드를 작성한다.

---

## 6. Collision(충돌)과 Switch 문

Unity의 `OnCollisionEnter` 메서드를 활용한다:

```csharp
void OnCollisionEnter(Collision collision)
{
    switch (collision.gameObject.tag)
    {
        case "Friendly":
            Debug.Log("Friendly");
            break;
        case "Finish":
            LoadNextLevel();
            break;
        case "Fuel":
            Debug.Log("Fuel");
            break;
        default:
            ReloadLevel();
            break;
    }
}
```

- **collision.gameObject.tag** → 충돌한 오브젝트의 태그 확인
- **Switch 문** → 태그에 따라 다른 동작 실행
  - `Friendly`: 단순 로그 출력
  - `Finish`: 다음 레벨 로드
  - `Fuel`: 연료 관련 처리 (현재는 로그만 출력)
  - `default`: 충돌 시 현재 레벨 다시 로드

👉 태그 시스템은 충돌 처리 로직을 단순화할 수 있는 강력한 도구.

---

## 7. LoadNextLevel() 구현하기

```csharp
void LoadNextLevel()
{
    int currentScene = SceneManager.GetActiveScene().buildIndex;
    int nextScene = currentScene + 1;

    SceneManager.LoadScene(nextScene);
}
```

- `SceneManager.GetActiveScene().buildIndex` → 현재 씬의 인덱스 가져오기
- `+1` → 다음 씬으로 이동
- `SceneManager.LoadScene(nextScene)` → 해당 인덱스의 씬 로드

---

## 8. 씬 인덱스 순환 처리 (마지막 → 처음)

마지막 씬에서 더 이상 씬이 없으면 다시 처음으로 돌아가야 한다.

```csharp
if (nextScene == SceneManager.sceneCountInBuildSettings)
{
    nextScene = 0; // 다시 처음으로
}
```

- `SceneManager.sceneCountInBuildSettings` → 빌드에 포함된 씬의 개수
- nextScene 값이 개수와 같으면 (즉, 마지막을 넘어갔을 때) `0`으로 초기화

👉 이렇게 하면 **순환 구조**가 된다. (마지막 → 처음)

---

## 9. ReloadLevel() 구현하기

```csharp
private static void ReloadLevel()
{
    int currentScene = SceneManager.GetActiveScene().buildIndex;
    SceneManager.LoadScene(currentScene);
}
```

- 현재 씬 인덱스를 다시 불러와 로드
- 충돌 시 레벨이 다시 시작되는 효과

---

## 10. 정리와 학습 포인트

- 씬(Scene) = 게임 레벨 단위
- Prefab(프리팹) = 재사용 가능한 원본 오브젝트
- Build Index = 씬의 고유 번호 (순서)
- Switch 문 = 태그별 충돌 처리 로직
- LoadNextLevel() = 현재 씬 인덱스 + 1 → 다음 레벨 이동
- ReloadLevel() = 현재 씬 다시 로드
- 마지막 씬에서 순환 처리 → `if (nextScene == SceneManager.sceneCountInBuildSettings)`

👉 이 강의의 핵심은 **씬 전환 로직을 이해하고, 인덱스를 활용해 레벨을 순환시키는 것**이다.

## 1. Invoke() 개념과 사용법

- **정의**: 특정 메소드를 지정한 시간 후에 호출할 수 있도록 하는 유니티의 메소드.
- **기본 문법**:
  ```csharp
  Invoke("메소드이름", 지연시간초);
  ```
- **예시**:
  ```csharp
  Invoke("ReloadLevel", 2f); // 2초 후 ReloadLevel() 호출
  ```
- **장점**
  ✅ 작성이 빠르고 간단하다
  ✅ 작은 딜레이 연출에는 적합하다
- **단점**
  ❌ 문자열 참조(메소드 이름을 문자열로 입력) → 리팩터링 시 자동 변경 안 됨
  ❌ 성능이 `코루틴(Coroutine)`보다 좋지 않다 (큰 시스템에는 비효율적)

---

## 2. 충돌 처리(콜라이전)와 OnCollisionEnter

- **OnCollisionEnter(Collision collision)**
  : 두 오브젝트가 충돌했을 때 호출되는 유니티의 이벤트 메소드.
- **태그(Tag)를 이용한 충돌 분기 처리**:

  ```csharp
  void OnCollisionEnter(Collision collision)
  {
      switch (collision.gameObject.tag)
      {
          case "Friendly":
              Debug.Log("안전한 오브젝트");
              break;
          case "Finish":
              StartSuccessSequence();
              break;
          default:
              StartCrashSequence();
              break;
      }
  }
  ```

  - `"Friendly"` → 무해한 오브젝트
  - `"Finish"` → 골 지점 (다음 레벨로 이동)
  - 그 외 → 충돌로 간주하고 재시작

---

## 3. 컨텍스트(Context)와 메소드 범위

- 문제 상황: `OnCollisionEnter` 내부에서만 `ReloadLevel()`을 정의하면 **Invoke()**가 접근하지 못함.
- 해결책:
  - `ReloadLevel()` 같은 메소드를 **클래스 전체 범위**로 옮겨야 함.
  - 이렇게 하면 **다른 메소드(Invoke 포함)**에서도 호출 가능.

➡️ **개념적으로**

- 메소드 위치 = 접근 가능 범위(Context)에 영향
- `OnCollisionEnter` 내부에 있으면 "지역(local)"
- 클래스 전체에 있으면 "전역(global for the class)"

---

## 4. 플레이어 컨트롤 비활성화

- 충돌 후에도 플레이어가 계속 움직이는 문제 발생 → 제어를 차단해야 함.
- 해결 방법:
  - `GetComponent<Movements>().enabled = false;`
  - 이 코드는 **Movement 스크립트 자체를 비활성화**시켜 이동/회전/추진 불가능하게 만듦.

```csharp
private void StartCrashSequence()
{
    GetComponent<Movements>().enabled = false; // 플레이어 조작 차단
    Invoke("ReloadLevel", levelLoadDelay);     // 지연 후 재시작
}

```

## 6. 직렬화된 변수(SerializedField)와 Inspector 노출

- **SerializedField**: private 변수를 Inspector에서 수정 가능하게 만들어줌.
- 사용 예시:

  ```csharp
  [SerializeField] float levelLoadDelay = 2f;

  ```

- **장점**
  ✅ 코드 수정 없이 Inspector에서 조정 가능
  ✅ 개발/테스트 과정에서 유연하게 값 변경 가능

➡️ 이 변수를 `Invoke` 지연 시간으로 사용하면,

- 충돌 후 재시작/다음 레벨 로드 시간을 Inspector에서 직접 설정 가능

## 7. 정리: 충돌 후 지연 처리의 전체 흐름

1. 플레이어가 **Collider**와 충돌 → `OnCollisionEnter` 호출됨
2. 태그(Tag)에 따라 행동 분기
   - `"Finish"` → 성공 시퀀스 실행
   - 그 외 → 실패 시퀀스 실행
3. **StartSuccessSequence / StartCrashSequence**
   - `Movement` 스크립트 비활성화 → 플레이어 조작 차단
   - `Invoke()`로 일정 시간 후 다음 동작 실행
     - 성공: `LoadNextLevel()`
     - 실패: `ReloadLevel()`
4. **SceneManager**가 씬 전환 처리
   - 다음 씬 이동 or 현재 씬 재시작

---

## 📌 최종 코드 예시 (정리본)

```csharp
using System;
using UnityEngine;
using UnityEngine.SceneManagement;

public class CollisionHandler : MonoBehaviour
{
    [SerializeField] float levelLoadDelay = 2f; // Inspector에서 지연 시간 조절 가능

    void OnCollisionEnter(Collision collision)
    {
        switch (collision.gameObject.tag)
        {
            case "Friendly":
                Debug.Log("안전한 오브젝트");
                break;
            case "Finish":
                StartSuccessSequence();
                break;
            default:
                StartCrashSequence();
                break;
        }
    }

    private void StartSuccessSequence()
    {
        GetComponent<Movements>().enabled = false;     // 플레이어 조작 차단
        Invoke("LoadNextLevel", levelLoadDelay);       // 지연 후 다음 레벨
    }

    private void StartCrashSequence()
    {
        GetComponent<Movements>().enabled = false;     // 플레이어 조작 차단
        Invoke("ReloadLevel", levelLoadDelay);         // 지연 후 현재 레벨 재시작
    }

    void LoadNextLevel()
    {
        int currentScene = SceneManager.GetActiveScene().buildIndex;
        int nextScene = currentScene + 1;

        if (nextScene == SceneManager.sceneCountInBuildSettings)
        {
            nextScene = 0; // 마지막 씬 → 첫 씬으로 순환
        }
        SceneManager.LoadScene(nextScene);
    }

    private void ReloadLevel()
    {
        int currentScene = SceneManager.GetActiveScene().buildIndex;
        SceneManager.LoadScene(currentScene);
    }
}

```

---

👉 이렇게 정리하면 **Invoke → 충돌 처리 → 컨트롤 비활성화 → 씬 전환**이라는 흐름을 체계적으로 공부할 수 있습니다.

## 왜 코드 레이아웃이 중요한가?

- 코드가 정상적으로 동작하기 위해 **특정 순서를 반드시 따라야 하는 것은 아님**.
- 하지만 협업이나 본인 스스로의 유지보수 측면에서 **읽기 쉽고, 빠르게 찾을 수 있도록 정리**하는 것이 중요하다.
- 특히 **Unity 개발**에서는 `MonoBehaviour`의 여러 콜백 함수(`Start`, `Update` 등)가 섞여 있기 때문에 체계적으로 관리하지 않으면 금방 복잡해진다.

---

## 클래스 내 코드의 기본 배치 순서

GameDev.tv에서 권장하는 **표준 구조**는 다음과 같다:

1. **변수 (Fields)**
   - `[SerializeField]` 붙은 조정 가능한 변수
   - 캐싱된 참조 변수 (Rigidbody, AudioSource 등)
   - 상태 관련 변수 (bool isAlive 등)
2. **Unity 콜백 메소드**
   - `Awake()` → `OnEnable()` → `Start()` → `Update()` 순서로 작성
   - 생명 주기(Lifecycle)에 따라 코드 흐름을 파악하기 쉽다.
3. **Public 메소드**
   - 외부에서 접근해야 하는 메소드
   - 예: `TakeDamage()`, `Respawn()` 등
4. **Private 메소드**
   - 클래스 내부에서만 사용하는 보조 메소드
   - 예: `ProcessThrust()`, `ProcessRotation()`

---

## 변수 선언의 3가지 그룹화 방식

### 1) 매개변수(Parameter)

- 주로 `[SerializeField]`와 함께 사용
- Unity Inspector에서 수정 가능
- 게임 밸런스/튜닝할 때 가장 자주 확인하는 값이므로 **맨 위에 배치**

```csharp
// 🚀 매개변수 예시
[SerializeField] float thrustPower = 100f;   // 로켓 추진력
[SerializeField] float rotationSpeed = 1f;   // 회전 속도
```

---

### 2) 캐싱된 참조(Cached Reference)

- `GetComponent<>()`를 통해 가져온 Unity 컴포넌트 참조
- 한 번만 가져와서 저장해두면 **매번 호출하는 성능 낭비를 줄일 수 있음**

```csharp
// 🔗 캐싱된 참조 예시
Rigidbody rb;
AudioSource audioSource;

void Start() {
    rb = GetComponent<Rigidbody>();        // Rigidbody 캐싱
    audioSource = GetComponent<AudioSource>(); // 오디오 소스 캐싱
}
```

---

### 3) 상태(State)

- 현재 객체가 어떤 상태인지 나타내는 변수
- 주로 `bool`, `enum`, `int` 같은 간단한 값
- 예: 살아있는지 여부, 현재 체력, 점프 가능 여부 등

```csharp
// ⚡ 상태 예시
bool isAlive = true;
int currentHealth = 100;
```

---

## 메소드(Methods)의 배치 순서

1. **Unity 생명주기 메소드**
   - `Awake()`
   - `OnEnable()`
   - `Start()`
   - `Update()`
2. **Public 메소드**
   - 외부에서 호출할 수 있는 기능
3. **Private 메소드**
   - 클래스 내부에서만 동작하는 보조 기능

---

## 가독성을 위한 추가 팁

- **그룹 사이에는 한 줄씩 띄어쓰기** → 변수, 메소드 간격이 명확해짐
- **주석으로 구분**하면 한눈에 보기 쉬움

예:

```csharp
// -------------------- Parameters --------------------
// -------------------- Cached References --------------------
// -------------------- State --------------------
```

## 예시 코드 정리

```csharp
using UnityEngine;

public class Rocket : MonoBehaviour
{
    // -------------------- Parameters --------------------
    [SerializeField] float thrustPower = 100f;   // 로켓 추진력
    [SerializeField] float rotationSpeed = 1f;   // 회전 속도

    // -------------------- Cached References --------------------
    Rigidbody rb;
    AudioSource audioSource;

    // -------------------- State --------------------
    bool isAlive = true;

    // -------------------- Unity Callbacks --------------------
    void Start() {
        rb = GetComponent<Rigidbody>();           // Rigidbody 캐싱
        audioSource = GetComponent<AudioSource>(); // 오디오 소스 캐싱
    }

    void Update() {
        if (isAlive) {
            ProcessThrust();   // 추진 처리
            ProcessRotation(); // 회전 처리
        }
    }

    // -------------------- Private Methods --------------------
    void ProcessThrust() {
        if (Input.GetKey(KeyCode.Space)) {
            rb.AddRelativeForce(Vector3.up * thrustPower * Time.deltaTime);
        }
    }

    void ProcessRotation() {
        if (Input.GetKey(KeyCode.A)) {
            transform.Rotate(Vector3.forward * rotationSpeed * Time.deltaTime);
        }
        else if (Input.GetKey(KeyCode.D)) {
            transform.Rotate(-Vector3.forward * rotationSpeed * Time.deltaTime);
        }
    }
}
```

---

✅ 이렇게 정리하면

- 변수가 **위에서부터 순서대로 Parameter → Cached → State**
- 메소드는 **콜백 → Public → Private** 구조로 깔끔하게 관리 가능

## 1. Unity에서 오디오 시스템 이해하기

Unity에서 **소리를 재생하기 위해 필요한 세 가지 요소**:

- 🎧 **Audio Listener** : 플레이어가 듣는 귀 (기본적으로 카메라에 붙음)
- 🎵 **Audio Clip** : 실제 음향 파일 (예: mp3, wav)
- 🔊 **Audio Source** : 소리를 내는 스피커 역할 (게임 오브젝트에 붙음)

👉 즉, **AudioSource + AudioClip + AudioListener** 조합이 있어야 게임에서 소리를 들을 수 있음.

---

## 2. AudioSource vs PlayOneShot 차이

- `audioSource.Play()`
  - 오디오 소스에 **연결된 단 하나의 Clip**만 재생 가능
  - 클립을 코드에서 바꿔치기하지 않으면 항상 같은 소리만 재생
- `audioSource.PlayOneShot(AudioClip clip)`
  - **특정 AudioClip을 매개변수로 전달**하여 재생 가능
  - 한 오디오 소스에서 여러 개의 클립을 동시에 재생할 수 있음
  - 두 번째 매개변수로 **볼륨 조절** 가능 (`0.0f ~ 1.0f`)

```csharp
// 예시
audioSource.PlayOneShot(mainEngine); // 기본 사용
audioSource.PlayOneShot(crashClip, 0.7f); // 70% 볼륨으로 재생
```

## 3. AudioClip 직렬화(SerializeField)로 연결하기

Unity Inspector에서 **스크립트와 오디오 파일을 연결**하기 위해 `SerializeField`를 사용.

```csharp
[SerializeField] AudioClip mainEngine; // 엔진 추진음
[SerializeField] AudioClip success;    // 성공 효과음
[SerializeField] AudioClip crash;      // 충돌 효과음
```

- Inspector 창에서 직접 `AudioClip` 드래그 앤 드롭 가능
- 코드 수정 없이 다양한 효과음을 쉽게 교체할 수 있음

## 4. 엔진 소리 구현하기 (Movement.cs)

### ✅ 핵심 개념

- **Space Bar를 누를 때만 엔진 소리 재생**
- 소리를 매번 시작/중복해서 내지 않도록 `PlayOneShot` 사용
- 키를 떼면 `audioSource.Stop()`으로 소리 정지

### 📝 예시 코드

```csharp
using UnityEngine;

public class Movements : MonoBehaviour
{
    [SerializeField] AudioClip mainEngine; // 엔진 사운드
    AudioSource audioSource;

    void Start()
    {
        audioSource = GetComponent<AudioSource>(); // AudioSource 가져오기
    }

    void Update()
    {
        ProcessThrust();
    }

    void ProcessThrust()
    {
        if (Input.GetKey(KeyCode.Space)) // 스페이스바 누르고 있으면
        {
            if (!audioSource.isPlaying) // 중복 방지
            {
                audioSource.PlayOneShot(mainEngine); // 엔진 소리 재생
            }
        }
        else
        {
            audioSource.Stop(); // 손 떼면 정지
        }
    }
}
```

## 5. 충돌 상황에 따른 효과음 구현하기 (CollisionHandler.cs)

### ✅ 핵심 개념

- `OnCollisionEnter()`에서 **오브젝트 태그(Tag)**에 따라 다른 효과음 재생
- 성공(`Finish`) → Success 효과음
- 충돌(`Obstacle`) → Crash 효과음
- 효과음 재생 후 → `Invoke()`로 씬 전환(딜레이 추가)

### 📝 예시 코드

```csharp
using System;
using UnityEngine;
using UnityEngine.SceneManagement;

public class CollisionHandler : MonoBehaviour
{
    [SerializeField] float levelLoadDelay = 2f;
    [SerializeField] AudioClip success; // 성공 효과음
    [SerializeField] AudioClip crash;   // 충돌 효과음

    AudioSource audioSource;

    void Start()
    {
        audioSource = GetComponent<AudioSource>(); // AudioSource 캐싱
    }

    void OnCollisionEnter(Collision collision)
    {
        switch (collision.gameObject.tag)
        {
            case "Friendly":
                Debug.Log("Friendly");
                break;
            case "Finish":
                StartSuccessSequence();
                break;
            case "Fuel":
                Debug.Log("Fuel");
                break;
            default:
                StartCrashSequence();
                break;
        }
    }

    void StartSuccessSequence()
    {
        audioSource.PlayOneShot(success); // 성공 효과음 재생
        GetComponent<Movements>().enabled = false; // 조작 금지
        Invoke("LoadNextLevel", levelLoadDelay);   // 다음 레벨 이동
    }

    void StartCrashSequence()
    {
        audioSource.PlayOneShot(crash); // 충돌 효과음 재생
        GetComponent<Movements>().enabled = false; // 조작 금지
        Invoke("ReloadLevel", levelLoadDelay);     // 현재 레벨 다시 불러오기
    }

    void LoadNextLevel()
    {
        int currentScene = SceneManager.GetActiveScene().buildIndex;
        int nextScene = (currentScene + 1) % SceneManager.sceneCountInBuildSettings;
        SceneManager.LoadScene(nextScene);
    }

    void ReloadLevel()
    {
        int currentScene = SceneManager.GetActiveScene().buildIndex;
        SceneManager.LoadScene(currentScene);
    }
}
```

## 6. Prefab과 Inspector 연결하기

- Player Rocket(GameObject)에 `CollisionHandler`와 `Movements` 스크립트가 붙어 있음
- Inspector에서 `AudioClip` 슬롯을 찾아 **직접 연결해야 함**

예:

- Main Engine → `mainEngine` 슬롯에 연결
- Success 효과음 → `success` 슬롯에 연결
- Crash 효과음 → `crash` 슬롯에 연결

⚠️ **주의**: Prefab에 적용(Apply)하지 않으면 다음 레벨에서 사라짐!

- Player Rocket → Overrides → `Apply All`

---

## 7. 자주 발생하는 오류와 해결 방법

1. **PlayOneShot was called with a null AudioClip**
   - Inspector에서 `AudioClip`을 연결하지 않음
   - Prefab에 적용하지 않아 다음 씬에서 빠짐
2. **소리가 계속 겹쳐서 재생됨**
   - `audioSource.Play()` 사용 시 발생
   - 해결 → `PlayOneShot()` 사용하거나 `isPlaying` 체크
3. **씬 이동 후 효과음이 사라짐**
   - Prefab에 적용하지 않은 경우
   - 항상 `Apply All`로 저장 필요

## 8. 정리 및 확장 아이디어

- ✅ **개념 정리**
  - AudioSource는 "스피커", AudioClip은 "소리 파일"
  - PlayOneShot으로 여러 소리 상황별로 재생 가능
  - Inspector에서 직렬화된 변수로 오디오 클립 연결
- 💡 **확장 아이디어**
  - 배경 음악(BGM) 추가 → `AudioSource.loop = true`
  - 소리 볼륨 조절 슬라이더 → `AudioMixer` 사용
  - 3D 사운드 효과 → AudioSource의 `Spatial Blend` 조정
