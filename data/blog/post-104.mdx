# 미들웨어 개념

```jsx
Express의 미들웨어는 HTTP 요청 및 응답 사이에 위치하며,

이를 통해 애플리케이션에 다양한 기능을 추가하고 조작할 수 있다.
```

# **미들웨어 함수 구조**

```jsx
매개변수: 미들웨어 함수는 세 개의 매개변수를 가진다.

req: 요청 객체 (request)

res: 응답 객체 (response)

next: 다음 미들웨어나 라우터로 제어를 전달하는 함수
```

```jsx
function middleware(req, res, next) {
  // 미들웨어에서 수행할 작업

  // 다음 미들웨어나 라우터로 제어를 전달
  next()
}
```

# **미들웨어의 활용**

```jsx
**Express.js와 함께 사용**:

주로 Express.js와 같은 웹 프레임워크에서 미들웨어가 활발히 사용된다.

**작업 예시**:

로깅: 요청과 응답에 대한 로그 기록

인증: 사용자 인증 처리

세션 관리: 세션 데이터 관리

데이터 변환: 요청이나 응답의 데이터 형식 변환
```

# **미들웨어 체인과 순서**

```jsx
**체인 형태 적용**:

여러 개의 미들웨어를 순차적으로 적용할 수 있으며, 이들은 체인을 형성한다.

**순서의 중요성**:

미들웨어는 적용된 순서대로 실행되므로, 순서에 따라 동작이 크게 영향을 받을 수 있다.
```

```jsx
// 미들웨어를 적용하기 위해 use() 메서드를 사용
app.use(middleware1)
app.use(middleware2)
```

# **미들웨어의 종류**

## **애플리케이션 레벨 미들웨어 (Application-level Middleware):**

```jsx
애플리케이션 전체에 적용되는 미들웨어

app.use()를 사용하여 정의되며, 일반적으로 요청 처리, 로깅, 사용자 인증과 같은 전역적인 작업을 수행한다.
```

```jsx
const express = require('express')
const app = express()

app.use((req, res, next) => {
  console.log('미들웨어가 실행됐습니다!')
  next()
})

// 나머지 라우트 및 미들웨어 정의
```

## **라우터 레벨 미들웨어 (Router-level Middleware):**

```jsx
특정 라우터에만 영향을 미치는 미들웨어

express.Router()를 사용하여 라우터를 생성하고, 라우터에 미들웨어를 적용한다.
```

```jsx
const express = require('express')
const router = express.Router()

router.use((req, res, next) => {
  console.log('라우터 미들웨어가 실행됐습니다!')
  next()
})

// 라우트 정의
```

### 라우트 미들웨어의 함수

```jsx
HTTP 메서드(Method):

라우터는 HTTP 요청 메서드에 따라 처리되는데, 예를 들어 get, post, put, delete 등이 있다.

각 메서드는 특정 종류의 요청을 처리하는 데 사용된다.

라우트 경로(Path):

라우트 경로는 클라이언트에서 서버로 요청이 전달되는 URL 경로를 나타낸다.

경로는 문자열로 지정되며, 특정 패턴이나 파라미터를 포함할 수 있다.

예를 들어, /users/:userId와 같이 :userId는 동적으로 변경되는 사용자 ID를 나타낸다.

미들웨어 함수(Middleware Functions) 배열:

Express 라우터는 미들웨어 함수의 배열을 받을 수 있다. 미들웨어는 요청을 처리하고 응답을 생성하기 전에 실행되는 함수이다.

미들웨어 함수 배열은 특정 경로에 대한 요청이 도착했을 때 실행되는 순서대로 정의된다.

미들웨어 함수에서는 주로 요청의 유효성 검사, 데이터 처리, 권한 확인 등을 수행한다.

콜백 함수 또는 컨트롤러 함수:

라우터에 등록된 경로 및 미들웨어 함수를 통과한 후 실행되는 함수이다.

주로 해당 경로 및 미들웨어에서 처리된 요청에 대한 실질적인 로직을 담당한다.

데이터베이스 조회, 업데이트, 새로운 데이터 생성 등과 같은 작업을 수행한다.

router.post(
  '/api/places/',
  [
    // 미들웨어 함수 배열
    check('title').not().isEmpty(),
    check('description').isLength({ min: 5 }),
    check('address').not().isEmpty(),
  ],
  placeControllers.createPlace  // 콜백 함수
);
```

## **에러 핸들링 미들웨어 (Error Handling Middleware):**

```jsx
에러가 발생했을 때 처리하기 위한 미들웨어

에러 핸들링 미들웨어는 네 개의 매개변수를 받는다. 첫 번째 매개변수(err)에는 에러 객체
```

```jsx
app.use((err, req, res, next) => {
  console.error(err.stack)
  res.status(500).send('에러가 발생했습니다!')
})
```

## **미들웨어 함수 정의**

```jsx
Express에서 미들웨어 함수는 req, res, next라는 세 개의 매개변수를 받는다.

이 중 next는 다음 미들웨어를 호출하는 함수이다.

이렇게 정의한 미들웨어는 next()를 호출하면 다음으로 넘어가게 된다
```

```jsx
app.use((req, res, next) => {
  console.log('내 첫 미들웨어!!!')
  next() // 다음 미들웨어 호출
})

app.use((req, res, next) => {
  console.log('두 번째 미들웨어!!!')
  next() // 다음 미들웨어 호출
})
```

## **미들웨어에서 next 반환하기**

```jsx
next() 이하에 코드를 실행하지 않고, next를 반환하여 다음 미들웨어의 실행을 막는 방법을 소개
```

```jsx
app.use((req, res, next) => {
  console.log('내 첫 미들웨어!!!')
  return next() // 다음 미들웨어 호출
})

app.use((req, res, next) => {
  console.log('다음 미들웨어 실행됨')
})
```

```jsx
이렇게 하면 다음 미들웨어 실행됨이 출력되지 않는다
```

# 미들웨어 더 알아보기

## 사용자 인증 미들웨어

```jsx
인증은 나중에 다룬다 간단하게 설명하면 응답 객체로

사용자 인증을 발급받게 되면 크리덴셜을 갖게 되는데

인증되었다는 기표인 셈이다 크리덴셜이 없는 사용자가

특정 라우트에 접근 못 하게 하고 싶다면

인증을 받은 요청인지 확인할 수 있는

미들웨어를 작성할 수 있다
```

```jsx
const express = require('express')
const app = express()

// 가상의 사용자 데이터베이스
const users = [
  { id: 1, username: 'user1', password: 'password1' },
  // 다른 사용자 정보들...
]

// 미들웨어: 사용자가 토큰을 가지고 있는지 확인
const authenticateUser = (req, res, next) => {
  const token = req.headers.authorization

  if (!token) {
    return res.status(401).json({ message: '인증되지 않은 사용자입니다.' })
  }

  // 토큰을 검증하는 로직을 추가해야 합니다.
  // 예를 들어, jsonwebtoken 패키지를 사용할 수 있습니다.

  // 여기에서는 간단하게 토큰이 유효한 경우에만 통과하도록 처리합니다.
  next()
}

// 미들웨어를 라우트에 적용
app.use('/secure-route', authenticateUser)

// 보호된 라우트
app.get('/secure-route/data', (req, res) => {
  // 여기에는 토큰이 유효한 사용자만 접근 가능한 로직이 들어갑니다.
  res.json({ message: '이 데이터는 로그인한 사용자만 볼 수 있습니다.' })
})

// 서버 시작
const PORT = 3000
app.listen(PORT, () => {
  console.log(`서버가 http://localhost:${PORT} 에서 실행 중입니다.`)
})
```

```jsx
이 예제에서 /secure-route로 시작하는 모든 요청에 대해 authenticateUser 미들웨어가 토큰의 존재 여부를 확인한다.

토큰이 없으면 401 Unauthorized 응답을 보내고, 토큰이 있는 경우에는 라우트에 접근할 수 있게 한다.
```

## **예제: 현재 시각 추가하는 미들웨어**

### **현재 시각을 추가하는 미들웨어 정의**

```jsx
// 현재 시각을 추가하는 미들웨어
const addRequestTime = (req, res, next) => {
  req.requestTime = Date.now()
  next()
}
```

```jsx
addRequestTime 함수는 세 개의 매개변수를 받는다

( req (요청 객체), res (응답 객체), next (다음 미들웨어로 이동하기 위한 콜백 함수) )

함수 내부에서 Date.now()를 사용하여 현재 시각을 milliseconds로 얻어온 후, 이를 req.requestTime에 저장한다.

next()를 호출하여 다음 미들웨어로 이동한다.
```

### **예시 라우트 핸들러에 미들웨어 적용**

```jsx
// 예시 라우트 핸들러
app.get('/time-route', addRequestTime, (req, res) => {
  const formattedTime = new Date(req.requestTime).toLocaleString()
  res.send(`Current request time: ${formattedTime}`)
})
```

```jsx
/time-route 경로로 들어오는 GET 요청에 대한 라우트 핸들러를 정의한다.

addRequestTime 미들웨어를 라우트 핸들러 앞에 위치시켜서 요청이 처리되기 전에 먼저 실행되도록 한다.

미들웨어가 실행되면 req.requestTime에 현재 시각이 추가되었으므로,

라우트 핸들러에서는 이를 활용하여 응답을 생성한다.

new Date(req.requestTime).toLocaleString()을 통해 milliseconds로 저장된 현재 시각을 읽고, 사람이 읽기 쉬운 형식으로 변환한다.

최종적으로 클라이언트에게 "Current request time: [formattedTime]" 형태의 응답을 보낸다.

( addRequestTime 로 들어오는 req 는 Express가 요청을 받을때 자동으로 넣어준다 )
```

### 데코레이트

```jsx
데코레이트"라는 용어는 객체나 함수에 추가적인 기능이나 속성을 동적으로 부여하는 개념을 나타낸다.

Express에서는 미들웨어를 사용하여 요청 객체를 데코레이트하여 추가적인 정보나 기능을 제공할 수 있다.

"다음으로 매칭될 라우트 핸들러에서 사용할 정보를 추가하는 것을 데코레이트한다"는 것은,

미들웨어를 통해 요청 객체에 정보를 추가하고, 이 정보는 그 이후에 실행될 라우트 핸들러에서 활용된다는 의미이다.

위의 예시에서는 addRequestTime 미들웨어를 사용하여 현재 시각을 요청 객체에 추가했다.

이때 추가된 정보(req.requestTime)는 라우트 핸들러인 /time-route에 의해 활용된다.

**즉, addRequestTime 미들웨어를 통해 추가된 req.requestTime은 라우트 핸들러 의** **요청(req) 객체를 데코레이트한 것**
```

```jsx
기존에는 app.use로 모든 라우트에 미들웨어를 적용했었다

/secret 라우트에서만 미들웨어를 사용하기 위해

app.get 또는 app.post 등에서 미들웨어를 직접 전달 가능.
```

```jsx
// 미들웨어 정의
const verifyPassword = (req, res, next) => {
  // 패스워드 확인 로직
  if (req.query.password === 'chickennugget') {
    next() // 올바른 패스워드면 다음 미들웨어 또는 라우트 핸들러로 이동
  } else {
    res.send('패스워드가 필요합니다!!!') // 올바르지 않은 패스워드면 응답 전송
  }
}

// /secret 라우트에만 verifyPassword 미들웨어 사용
app.get('/secret', verifyPassword, (req, res) => {
  // (req, res 앞에 미들웨어 전달 )
  res.send('누구와도 대화하지 않으려고 공공장소에서도 헤드폰을 쓴다')
})

// 다른 라우트에는 verifyPassword 미들웨어가 적용되지 않음
app.get('/dogs', (req, res) => {
  res.send('멍멍!')
})
```
