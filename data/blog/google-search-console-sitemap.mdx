# 왜 Google Search Console 등록 + Sitemap 제출이 중요한가?

```jsx
당신이 만든 사이트가 아무리 멋지고 완벽해도,

		❌ 구글이 당신의 사이트를 “모르면” 검색에 안 나옵니다.

즉, 사이트를 검색 결과에 노출시키려면 구글에게 "내 사이트 여기 있어!" 하고 알려야 합니다.

바로 이 역할을 해주는 것이:

		Google Search Console 등록

		Sitemap 제출
```

# 전체 요약 정리

## 1️⃣ Google Search Console(GSC) 등록 – "구글에 사이트 존재 알리기”

| 목적             | 설명                                          |
| ---------------- | --------------------------------------------- |
| 소유권 인증      | 구글이 "이 사이트는 당신 거 맞군요" 라고 인식 |
| 색인 요청        | 특정 페이지를 빠르게 구글 검색에 반영 가능    |
| SEO 도구 제공    | 검색 키워드, 클릭률, 오류 등 통계 제공        |
| 구글에 공식 등록 | 신뢰도 증가, 크롤링 우선순위 향상             |

## 2️⃣ `<meta name="google-site-verification">` 태그 삽입 – "소유자임을 증명"

```jsx
Google Search Console이 제공하는 메타 태그를 사이트에 삽입

Next.js App Router에서는 metadata.verification.google에 설정
```

```jsx
verification: {
  google: '4186ce357af861ff',
}
```

```jsx
Vercel에 배포한 뒤 GSC에서 "확인" 누르면 ✅ 인증 완료
```

## 3️⃣ Sitemap 제출 – "사이트 전체 구조 알려주기”

| 항목         | 설명                                     |
| ------------ | ---------------------------------------- |
| Sitemap 역할 | 사이트 내 모든 페이지 구조를 구글에 전달 |
| 효과         | 새 페이지/수정된 페이지 빠르게 검색 반영 |
| 제출 위치    | GSC 좌측 메뉴 > `Sitemaps` 메뉴에서 제출 |

```jsx
✅ next-sitemap 라이브러리를 사용하면 sitemap.xml, robots.txt 자동 생성 가능
```

```jsx
npm install next-sitemap
```

```jsx
next-sitemap.config.js 설정 예:
```

```jsx
module.exports = {
  siteUrl: 'https://base64-web.vercel.app',
  generateRobotsTxt: true,
}
```

# { 구글 서치 콘솔 중복 페이지 문제 해결 }

## **1. 문제 상황**

```jsx
Google Search Console에서 "페이지 색인이 생성되지 않음: 사용자가 선택한 표준이 없는 중복 페이지" 오류가 발생했습니다.

이로 인해 이게 원인인지 모르겠지만 내 사이트가 구글에서 보이지 않음
```

### **문제 원인**

```jsx
다국어 웹사이트에서 같은 내용의 페이지가 여러 언어로 존재할 때,

Google이 어떤 페이지를 기본(canonical)으로 설정해야 할지 모르기 때문입니다.
```

```jsx
예시:
- `/en` (영어 버전)
- `/ko` (한국어 버전)
- `/ja` (일본어 버전)
```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380313/notion-blog/SEO_/Google_Search_Console_Sitemap_/image_9.png)

## **2. 해결 방법**

### **Canonical URL 및 Hreflang 메타데이터 추가**

```jsx
**파일:** `src/app/[locale]/layout.tsx`

기존 코드에서 메타데이터 부분을 수정했습니다:
```

```jsx
// 추가된 코드
const baseUrl = 'https://jsonformatter.roono.net'

const alternates: Record<string, string> = {}
locales.forEach(loc => {
  alternates[loc] = `${baseUrl}/${loc}`
})

return {
  title,
  description,
  keywords: ['JSON formatter', 'JSON 포맷터', 'TypeScript interface generator', 'JSON to TypeScript', 'JSON validator', 'JSON beautifier'],
  authors: [{ name: 'JSON Formatter Web' }],

  // 🆕 새로 추가된 부분
  alternates: {
    canonical: `${baseUrl}/en`,  // 영어 버전을 기본으로 설정
    languages: alternates        // 모든 언어 버전 명시
  },

  openGraph: {
    title,
    description,
    type: 'website',
    siteName: 'JSON Formatter',
    locale: locale === 'ko' ? 'ko_KR' : locale === 'ja' ? 'ja_JP' : 'en_US',
    url: `${baseUrl}/${locale}`, // 🆕 현재 페이지 URL 명시
  },
  // ... 나머지 코드
}
```

````jsx
**효과:**
- `canonical`: Google에게 `/en`이 기본 페이지임을 알려줌
- `languages`: 다른 언어 버전들을 hreflang으로 연결
- HTML에서는 다음과 같이 출력됩니다:

```html
<link rel="canonical" href="https://jsonformatter.roono.net/en" />
<link rel="alternate" hreflang="en" href="https://jsonformatter.roono.net/en" />
<link rel="alternate" hreflang="ko" href="https://jsonformatter.roono.net/ko" />
<link rel="alternate" hreflang="ja" href="https://jsonformatter.roono.net/ja" />
````

### **루트 경로 리디렉션 설정**

````jsx
**파일:** `next.config.js`

```javascript
/** @type {import('next').NextConfig} */
const nextConfig = {
  sassOptions: {
    includePaths: ['./src/styles'],
  },

  // 🆕 새로 추가된 부분
  async redirects() {
    return [
      {
        source: '/',           // 루트 경로(/)로 접근하면
        destination: '/en',    // 영어 페이지(/en)로 리디렉션
        permanent: true,       // 301 리디렉션 (SEO에 좋음)
      },
    ]
  },
}
````

```jsx
**효과:**
- 사용자가 `https://jsonformatter.roono.net/`로 접근하면 자동으로 `https://jsonformatter.roono.net/en`으로 이동
- 301 리디렉션으로 SEO 점수 유지
```

### **루트 페이지 파일 생성**

````jsx
**파일:** `src/app/page.tsx` (새로 생성)

```typescript
import { redirect } from 'next/navigation'

export default function RootPage() {
  redirect('/en')
}
````

```jsx
**효과:**
- Next.js 라우팅 차원에서도 루트 경로를 영어 페이지로 리디렉션
- `next.config.js`의 리디렉션과 이중 보장
```

## **3. 작동 원리**

### **Before (문제 상황)**

```jsx
https://jsonformatter.roono.net/en  ← Google이 혼란스러워함
https://jsonformatter.roono.net/ko  ← 어떤 게 기본인지 모름
https://jsonformatter.roono.net/ja  ← 중복으로 인식
```

### **After (해결 후)**

```jsx
https://jsonformatter.roono.net/en  ← canonical (기본 페이지)
https://jsonformatter.roono.net/ko  ← alternate (한국어 버전)
https://jsonformatter.roono.net/ja  ← alternate (일본어 버전)
```

## **4. 핵심 개념 설명**

### **Canonical URL이란?**

```jsx
- 중복된 내용의 페이지들 중 **"이게 원본이야!"**라고 검색엔진에 알려주는 URL
- 검색 결과에는 canonical URL이 우선적으로 노출됨
```

### **Hreflang이란?**

```jsx
- 같은 내용의 다른 언어 버전 페이지들을 서로 연결해주는 속성
- "이 페이지는 한국어 버전이고, 영어 버전은 여기 있어"라고 알려줌
```

### **301 리디렉션이란?**

```jsx
- 영구적으로 페이지가 이동했다고 알려주는 HTTP 상태 코드
- SEO 점수가 새 URL로 완전히 이전됨
```
