## 1. 액션 카메라 시스템 기본 설정

### 문제점 인식 및 목적

현재 게임은 오버헤드 카메라를 사용하여 전체 전장을 보기에는 좋지만, 슈팅 액션의 디테일을 제대로 보여주지 못합니다. 액션 카메라는 슈팅 액션 발생 시 자동으로 유닛의 어깨 높이로 전환되어 시네마틱한 앵글을 제공합니다.

### Cinemachine 가상 카메라 복제

Hierarchy에서 기존 Cinemachine Virtual Camera를 복제(`Ctrl + D`)하고 이름을 **"Action Virtual Camera"**로 변경합니다. 이 카메라는 스크립트에서 직접 제어할 것이므로 **Follow**와 **Look At** 필드를 모두 제거합니다(필드 클릭 후 `Delete` 키).

### 카메라 위치 설정 방법

- **방법 1**: Scene 뷰에서 원하는 위치 조정 후 `Ctrl + Shift + F` 단축키
- **방법 2**: GameObject → Align With View 메뉴 사용

### Priority 시스템 이해하기

Cinemachine의 Priority 값은 어떤 카메라를 활성화할지 결정합니다. 숫자가 높을수록 우선순위가 높습니다.

- **메인 카메라**: Priority **10** (기본 오버헤드 뷰)
- **액션 카메라**: Priority **20** (슈팅 액션 시 활성화)

카메라 전환은 GameObject의 활성화/비활성화로 처리하며, Cinemachine이 자동으로 부드러운 블렌딩을 처리합니다. Inspector에서 Action Virtual Camera를 비활성화하여 게임 시작 시 메인 카메라가 활성화되도록 합니다.

## 2. CameraManager와 이벤트 시스템 구축

### CameraManager 스크립트 생성

**CameraManager** 스크립트를 생성하고, 빈 GameObject에 부착합니다(Transform Reset).

```csharp
using System;
using UnityEngine;

public class CameraManager : MonoBehaviour
{
    // Inspector에서 액션 카메라 GameObject 할당
    // [SerializeField]: private 필드를 Inspector에 노출
    [SerializeField] private GameObject actionCameraGameObject;

    // 액션 카메라 활성화 - GameObject 활성화로 카메라 전환
    private void ShowActionCamera()
    {
        actionCameraGameObject.SetActive(true);
    }

    // 액션 카메라 비활성화 - 메인 카메라로 복귀
    private void HideActionCamera()
    {
        actionCameraGameObject.SetActive(false);
    }
}

```

Inspector에서 **Action Camera Game Object** 필드에 Action Virtual Camera를 할당합니다.

### BaseAction에 제네릭 이벤트 추가

모든 액션 타입을 단일 이벤트로 처리하는 가장 범용적인 방식을 사용합니다.

```csharp
public abstract class BaseAction : MonoBehaviour
{
    // 모든 액션 시작 시 발생하는 정적 이벤트
    // static: 클래스의 모든 인스턴스가 공유하는 이벤트
    public static event EventHandler OnAnyActionStarted;

    // 모든 액션 완료 시 발생하는 정적 이벤트
    public static event EventHandler OnAnyActionCompleted;

    protected Unit unit;
    protected bool isActive = false;
    protected Action onActionComplete;

    protected virtual void Awake()
    {
        unit = GetComponent<Unit>();
    }

    protected void ActionStart(Action onActionComplete)
    {
        isActive = true;
        this.onActionComplete = onActionComplete;

        // 이벤트 발생: 구독자가 있을 때만 호출
        // ?. (null-conditional operator): NullReferenceException 방지
        // this: 어떤 액션이 이벤트를 발생시켰는지 전달
        OnAnyActionStarted?.Invoke(this, EventArgs.Empty);
    }

    protected void ActionComplete()
    {
        isActive = false;
        onActionComplete();

        OnAnyActionCompleted?.Invoke(this, EventArgs.Empty);
    }

    // 액션 소유 유닛 접근 메서드
    public Unit GetUnit()
    {
        return unit;
    }
}

```

**핵심 개념**:

- `static`: 모든 ShootAction, MoveAction 인스턴스가 하나의 이벤트 공유
- `?.Invoke`: 구독자가 있을 때만 호출하여 안전성 확보
- `EventHandler`: .NET 표준 이벤트 델리게이트 (시그니처: `void Method(object sender, EventArgs e)`)

## 3. 이벤트 타이밍 최적화

### ActionStart 호출 타이밍의 중요성

이벤트는 '이미 발생한 일'을 알리는 것입니다. `OnActionStarted` 이벤트는 액션이 완전히 초기화된 후 발생해야 합니다. 카메라 매니저가 이벤트를 받을 때 액션의 모든 데이터가 준비되어 있어야 합니다.

### ShootAction 수정

**수정 전** (잘못된 예시):

```csharp
public override void TakeAction(GridPosition gridPosition, Action onActionComplete)
{
    // 잘못된 위치: 초기화 시작 시점에 호출
    ActionStart(onActionComplete);

    targetUnit = LevelGrid.Instance.GetUnitAtGridPosition(gridPosition);
    state = State.Aiming;
    // ...
}
```

**수정 후** (올바른 예시):

```csharp
public override void TakeAction(GridPosition gridPosition, Action onActionComplete)
{
    // 1. 먼저 모든 초기화 수행
    targetUnit = LevelGrid.Instance.GetUnitAtGridPosition(gridPosition);
    state = State.Aiming;
    float aimingStateTime = 1f;
    stateTimer = aimingStateTime;
    canShootBullet = true;

    // 2. 모든 초기화 완료 후 마지막에 ActionStart 호출
    // 이제 이벤트 리스너가 완전히 준비된 액션 데이터에 접근 가능
    ActionStart(onActionComplete);
}
```

TakeAction() 메서드의 **마지막 줄**에 ActionStart()를 배치합니다.

## 4. 액션 타입별 카메라 제어

### CameraManager에서 이벤트 리스닝

```csharp
using System;
using UnityEngine;

public class CameraManager : MonoBehaviour
{
    [SerializeField] private GameObject actionCameraGameObject;

    private void Start()
    {
        // 이벤트 구독
        // += 연산자: 이벤트에 메서드를 등록
        BaseAction.OnAnyActionStarted += BaseAction_OnAnyActionStarted;
        BaseAction.OnAnyActionCompleted += BaseAction_OnAnyActionCompleted;

        // 게임 시작 시 액션 카메라 확실히 비활성화
        HideActionCamera();
    }

    // 액션 시작 시 호출되는 이벤트 핸들러
    // sender: 이벤트를 발생시킨 액션 객체 (ShootAction, MoveAction 등)
    private void BaseAction_OnAnyActionStarted(object sender, EventArgs e)
    {
        // switch expression으로 타입 기반 분기
        switch(sender)
        {
            // case [타입] [변수명]: 타입 패턴 매칭
            // 1. sender가 ShootAction인지 확인
            // 2. 맞으면 자동 캐스팅하여 shootAction 변수에 저장
            case ShootAction shootAction:
                // ShootAction인 경우에만 실행
                // 다른 액션(MoveAction, SpinAction)은 액션 카메라 미사용

                // 유닛 정보 가져오기
                Unit shooterUnit = shootAction.GetUnit();
                Unit targetUnit = shootAction.GetTargetUnit();

                // 카메라 위치 계산 (다음 섹션)

                break;
        }
    }

    // 액션 완료 시 호출되는 이벤트 핸들러
    private void BaseAction_OnAnyActionCompleted(object sender, EventArgs e)
    {
        switch(sender)
        {
            case ShootAction shootAction:
                // ShootAction 완료 시 액션 카메라 숨김
                // Priority가 낮은 메인 카메라로 자동 전환
                HideActionCamera();
                break;
        }
    }

    private void ShowActionCamera()
    {
        actionCameraGameObject.SetActive(true);
    }

    private void HideActionCamera()
    {
        actionCameraGameObject.SetActive(false);
    }
}

```

### Switch Expression의 장점

- **타입 패턴 매칭**: 타입 확인과 캐스팅을 동시에 수행
- **확장성**: 새로운 액션 타입에 쉽게 카메라 로직 추가 가능
- **간결성**: 기존 if-else 방식보다 읽기 쉬움

### 전체 흐름 정리

1. 슈팅 액션 시작 → `BaseAction.OnAnyActionStarted` 이벤트 발생
2. CameraManager 감지 → ShootAction 확인 → 액션 카메라 활성화
3. Cinemachine 자동 블렌딩 (Priority 20으로 전환)
4. 슈팅 애니메이션 재생 (Aiming → Shooting → Cooloff)
5. 슈팅 액션 완료 → `BaseAction.OnAnyActionCompleted` 이벤트 발생
6. 액션 카메라 비활성화 → 메인 카메라 복귀 (Priority 10)

## 5. 카메라 블렌딩 속도 조정

### 문제점 발견

첫 테스트에서 카메라 전환이 너무 느립니다(기본값 2초). 액션의 흐름이 끊기고 게임이 답답하게 느껴집니다.

### Cinemachine Brain 설정 변경

1. Hierarchy에서 **Main Camera** 선택
2. Inspector에서 **Cinemachine Brain** 컴포넌트 확인
3. **Default Blend** 섹션:
   - Blend Time: **0.2초**로 변경 (기존 2초)
   - Blend Type: **Ease In Out** 유지

### 블렌드 타입 설명

- **Ease In Out**: 전환 시작 시 천천히, 중간에 빠르게, 끝날 때 천천히 (가장 자연스러움)
- **Cut**: 블렌드 없이 즉시 전환 (순간 이동 효과)
- **Linear**: 일정한 속도로 전환

### Custom Blend (선택사항)

각 카메라 전환마다 다른 블렌드 설정이 필요할 때 사용합니다. 예를 들어, 슈팅 액션은 0.1초로 빠르게, 폭발 액션은 0.5초로 천천히 전환하고 싶을 때입니다.

**설정 방법**:

1. Default Blend 드롭다운에서 **Custom Blends** 선택
2. **Create Asset** 버튼 클릭
3. Blend List에 카메라 쌍과 블렌드 설정 추가

이번 프로젝트에서는 모든 전환이 동일한 속도여도 되므로 Default Blend만 사용합니다.

## 6. 카메라 위치 계산 - 벡터 수학

### 어깨 높이 측정 및 설정

Unit Prefab에서 빈 GameObject를 생성하여 Y축을 조정하면서 어깨 높이를 측정합니다. 약 **1.6 ~ 1.7** 정도가 적당합니다.

```csharp
case ShootAction shootAction:
    Unit shooterUnit = shootAction.GetUnit();
    Unit targetUnit = shootAction.GetTargetUnit();

    // 어깨 높이 벡터
    // Vector3.up = (0, 1, 0) - Unity의 위쪽 방향 벡터
    // Vector3.up * 1.7f = (0, 1.7, 0) - Y축으로 1.7 유닛 상승
    Vector3 cameraCharacterHeight = Vector3.up * 1.7f;

```

**Unity의 기본 방향 벡터들**:

- `Vector3.up` = `(0, 1, 0)` (위), `Vector3.down` = `(0, -1, 0)` (아래)
- `Vector3.right` = `(1, 0, 0)` (오른쪽), `Vector3.left` = `(-1, 0, 0)` (왼쪽)
- `Vector3.forward` = `(0, 0, 1)` (앞), `Vector3.back` = `(0, 0, -1)` (뒤)

### 슈팅 방향 벡터 계산

```csharp
    // 슈터에서 타겟으로의 방향 벡터
    // 벡터 빼기: 목표 위치 - 시작 위치 = 방향 벡터
    // normalized: 방향은 유지하고 크기를 1로 만듦 (단위 벡터)
    Vector3 shootDir = (targetUnit.GetWorldPosition() - shooterUnit.GetWorldPosition()).normalized;

```

**정규화(Normalized)의 이유**:

- 방향만 필요하고 거리는 중요하지 않음
- 슈터와 타겟이 10m든 100m든 동일한 카메라 위치 유지
- 일정한 크기의 오프셋 적용에 유용

**벡터 수학 예시**:

```csharp
// A에서 B로의 방향 벡터 = B - A
Vector3 A = new Vector3(1, 0, 1);  // 슈터 위치
Vector3 B = new Vector3(5, 0, 3);  // 타겟 위치
Vector3 direction = B - A;         // (4, 0, 2)

// 정규화
Vector3 v = new Vector3(3, 0, 4);
float magnitude = v.magnitude;  // 크기 = 5 (√(3²+4²))
Vector3 normalized = v.normalized;  // (0.6, 0, 0.8) - 크기가 1

```

### 어깨 오프셋 계산 - Quaternion 회전

```csharp
    // 어깨 오프셋 거리
    float shoulderOffsetAmount = 0.5f;

    // shootDir을 Y축 기준 90도 회전 (오른쪽 방향으로 전환)
    // Quaternion.Euler(0, 90, 0): Y축 기준 90도 회전을 나타내는 쿼터니언
    // 쿼터니언 * 벡터: 벡터에 회전 적용
    // 결과에 shoulderOffsetAmount를 곱해서 오프셋 거리 조정
    Vector3 shoulderOffset = Quaternion.Euler(0, 90, 0) * shootDir * shoulderOffsetAmount;

```

**Quaternion 개념**:

- 3D 공간에서 회전을 표현하는 수학적 개념 (4개의 숫자 x, y, z, w)
- Euler 각도보다 안정적 (짐벌 락 문제 없음)
- `Quaternion.Euler(0, 90, 0)`: Y축 기준 90도 회전

**왜 90도인가?**:

- `shootDir`는 앞쪽(타겟 방향)을 향함
- 90도 회전하면 오른쪽을 향함
- 오른쪽 어깨에 카메라를 두기 위함

**시각적 설명**:

```
슈터에서 타겟 방향 (shootDir): ↑
90도 회전 후 (오른쪽):          →
최종 카메라 위치:     [슈터] → [카메라]
                              (오른쪽 어깨 뒤)
```

### 최종 카메라 위치 계산

```csharp
    // 최종 카메라 위치 = 슈터 위치 + 높이 + 오프셋 + 뒤로 이동
    // 여러 벡터를 더해서 최종 위치를 구함
    Vector3 actionCameraPosition =
        shooterUnit.GetWorldPosition() +      // 슈터 발 위치 (기준점)
        cameraCharacterHeight +               // 어깨 높이로 상승 (0, 1.7, 0)
        shoulderOffset +                      // 오른쪽으로 이동 (회전된 방향 * 0.5)
        (shootDir * -1);                      // 뒤로 물러남 (-1 곱하면 방향 반전)

    // 계산된 위치를 액션 카메라의 Transform에 적용
    actionCameraGameObject.transform.position = actionCameraPosition;

```

**각 요소의 역할**:

1. `shooterUnit.GetWorldPosition()`: 슈터의 발 위치 (모든 계산의 기준점)
2. `cameraCharacterHeight`: Y축으로 1.7 유닛 상승 (어깨 높이)
3. `shoulderOffset`: 오른쪽으로 0.5 유닛 이동 (어깨 옆)
4. `shootDir * -1`: 뒤쪽으로 1 유닛 이동 (슈터 뒤에 배치)

**실제 계산 예시**:

```
슈터 위치: (5, 0, 5)
타겟 위치: (8, 0, 5)

shootDir = (3, 0, 0).normalized = (1, 0, 0)
cameraCharacterHeight = (0, 1.7, 0)
shoulderOffset = Quaternion.Euler(0,90,0) * (1,0,0) * 0.5
               = (0, 0, 1) * 0.5 = (0, 0, 0.5)
shootDir * -1 = (-1, 0, 0)

최종 위치 = (5, 0, 5) + (0, 1.7, 0) + (0, 0, 0.5) + (-1, 0, 0)
          = (4, 1.7, 5.5)

```

## 7. 카메라 회전 및 최종 테스트

### LookAt으로 카메라 회전 설정

```csharp
    // 카메라가 타겟의 어깨 높이를 바라보도록 설정
    // Transform.LookAt: Transform을 특정 위치를 바라보도록 자동 회전
    actionCameraGameObject.transform.LookAt(
        targetUnit.GetWorldPosition() + cameraCharacterHeight
    );

    // 액션 카메라 활성화
    ShowActionCamera();
    break;

```

**LookAt 메서드**:

- 현재 위치에서 target 위치로의 방향 벡터를 계산
- 이 방향이 Transform의 forward(앞쪽)가 되도록 회전 계산
- Transform.rotation을 자동으로 설정

**왜 cameraCharacterHeight를 더하는가?**:

- `GetWorldPosition()`은 유닛의 발 위치 반환
- 카메라가 발을 바라보면 시야각이 이상함
- 타겟의 어깨 높이를 바라보도록 높이 추가

### 최종 완성 코드

```csharp
private void BaseAction_OnAnyActionStarted(object sender, EventArgs e)
{
    switch(sender)
    {
        case ShootAction shootAction:
            // 1. 유닛 정보 가져오기
```

## 1. Grid Visual의 문제점 파악하기

### 현재 문제점

Grid Visual 시스템은 현재 **매 프레임마다 업데이트**되고 있습니다.

```csharp
private void Update()
{
    UpdateGridVisual();  // 매 프레임 실행 - 비효율적!
}
```

**문제가 되는 이유:**

- 아무것도 변하지 않을 때도 계속 업데이트됨
- 불필요한 연산 낭비
- 성능에 부정적 영향

### 언제 업데이트가 필요한가?

실제로 Grid Visual이 업데이트되어야 하는 경우는 두 가지뿐입니다:

1. **선택된 액션이 변경될 때** (Move → Shoot 등)
2. **유닛이 그리드 위치를 이동할 때**

이 두 경우에만 업데이트하도록 **이벤트 기반 시스템**으로 변경해야 합니다.

## 3. Unit 이동 이벤트 추가하기

### LevelGrid에 이벤트 생성

유닛이 그리드 위치를 이동할 때 알림을 받기 위한 이벤트를 만듭니다:

```csharp
public class LevelGrid : MonoBehaviour
{
    // 유닛이 그리드 위치를 이동했을 때 발생하는 이벤트
    public event EventHandler OnAnyUnitMovedGridPosition;

    // 유닛이 그리드 위치를 이동했을 때 호출되는 함수
    public void UnitMovedGridPosition(Unit unit, GridPosition fromGridPosition, GridPosition toGridPosition)
    {
        // 이전 위치에서 유닛 제거
        RemoveUnitAtGridPosition(fromGridPosition, unit);

        // 새 위치에 유닛 추가
        AddUnitAtGridPosition(toGridPosition, unit);

        // 이벤트 발생 - 구독자들에게 알림
        OnAnyUnitMovedGridPosition?.Invoke(this, EventArgs.Empty);
    }
}

```

**코드 설명:**

- `OnAnyUnitMovedGridPosition`: 어떤 유닛이든 이동했을 때 발생하는 이벤트
- `?.Invoke()`: null이 아닐 때만 이벤트 실행 (안전한 호출)
- `EventArgs.Empty`: 추가 데이터가 필요 없으므로 빈 EventArgs 전달

```csharp
private void Start()

// 이벤트 핸들러
```

## 4. 이벤트 순서 오류 수정하기

### 발견된 버그

테스트 중 유닛을 이동시키면 이동 범위가 **한 박자 늦게** 업데이트되는 버그가 발견되었습니다.

**문제 상황:**

- 유닛을 2칸 위로 이동 → 이동 범위가 즉시 업데이트되지 않음
- 뒤로 이동할 때 → 범위가 늘어났다가 줄어드는 이상한 동작

### 원인 분석

문제는 `Unit.cs`의 Update 함수에 있었습니다:

```csharp
// Unit.cs - 문제가 있는 코드
private void Update()
{
    GridPosition newGridPosition = LevelGrid.Instance.GetGridPosition(transform.position);

    if (newGridPosition != gridPosition)
    {
        // 여기서 이벤트 발생
        LevelGrid.Instance.UnitMovedGridPosition(this, gridPosition, newGridPosition);

        // 그 다음에 위치 업데이트 - 순서가 잘못됨!
        gridPosition = newGridPosition;
    }
}

```

**문제점:**

1. `UnitMovedGridPosition()` 호출 → 이벤트 발생
2. 이벤트에서 `UpdateGridVisual()` 호출
3. 하지만 이 시점에 `gridPosition`은 아직 **이전 위치**
4. 그래서 이동 범위 계산이 잘못됨

### 해결 방법

이벤트를 발생시키기 **전에** 위치를 업데이트해야 합니다:

```csharp
// Unit.cs - 수정된 코드
private void Update()
{
    GridPosition newGridPosition = LevelGrid.Instance.GetGridPosition(transform.position);

    if (newGridPosition != gridPosition)
    {
        // 1. 먼저 이전 위치 저장
        GridPosition oldGridPosition = gridPosition;

        // 2. 현재 위치 업데이트
        gridPosition = newGridPosition;

        // 3. 그 다음에 이벤트 발생 (이미 위치가 업데이트된 상태)
        LevelGrid.Instance.UnitMovedGridPosition(this, oldGridPosition, newGridPosition);
    }
}

```

**수정 내용:**

- `oldGridPosition` 변수에 이전 위치 저장
- `gridPosition`을 먼저 새 위치로 업데이트
- 그 후에 이벤트 발생
- 이제 이벤트가 발생했을 때 유닛의 위치는 이미 새 위치로 업데이트된 상태

```csharp
private Material GetGridVisualTypeMaterial(GridVisualType gridVisualType)
```

### ShowGridPositionRange 함수 구현

```csharp
// 특정 위치를 중심으로 원형 범위를 표시하는 함수
private void ShowGridPositionRange(GridPosition gridPosition, int range, GridVisualType gridVisualType)
{
    // 범위 내의 모든 그리드 위치를 저장할 리스트
    List<GridPosition> gridPositionList = new List<GridPosition>();

    // X축 방향으로 순회 (-range ~ +range)
    for (int x = -range; x <= range; x++)
    {
        // Z축 방향으로 순회 (-range ~ +range)
        for (int z = -range; z <= range; z++)
        {
            // 테스트할 그리드 위치 계산
            GridPosition testGridPosition = gridPosition + new GridPosition(x, z);

            // 유효한 그리드 위치인지 확인
            if (!LevelGrid.Instance.IsValidGridPosition(testGridPosition))
            {
                continue;  // 유효하지 않으면 건너뛰기
            }

            // 맨해튼 거리 계산 (원형 범위를 만들기 위함)
            int testDistance = Mathf.Abs(x) + Mathf.Abs(z);
            if (testDistance > range)
            {
                continue;  // 범위를 벗어나면 건너뛰기
            }

            // 조건을 통과한 위치는 리스트에 추가
            gridPositionList.Add(testGridPosition);
        }
    }

    // 리스트의 모든 위치를 지정된 색상으로 표시
    ShowGridPositionList(gridPositionList, gridVisualType);
}

```

**코드 설명:**

1. **이중 for 루프:**
   - `x`와 `z`를 `range`부터 `+range`까지 순회
   - 사각형 영역을 만듦
2. **IsValidGridPosition 체크:**
   - 맵 밖의 위치는 제외
3. **맨해튼 거리 계산:**
   - `Mathf.Abs(x) + Mathf.Abs(z)`: 원점에서의 거리
   - 사각형을 원형으로 변환
   - 예: range=2일 때 거리가 2 이하인 위치만 선택
4. **결과:**
   - 원형 범위의 모든 유효한 그리드 위치가 리스트에 저장됨

## 2. 상태 머신(State Machine) 개념과 구조

### 상태 머신이란?

- **상태 머신(State Machine)**: 객체가 가질 수 있는 여러 상태를 정의하고, 각 상태에서 특정 행동을 수행하도록 관리하는 패턴
- 게임 AI에서 매우 자주 사용되는 패턴으로, 복잡한 행동을 명확하게 분리할 수 있음

### 적 AI의 3가지 상태

```csharp
private enum State
{
    WaitingForEnemyTurn,  // 적 턴을 기다리는 상태 (플레이어 턴일 때)
    TackingTurn,          // 적이 턴을 진행 중인 상태
    Busy,                 // 적이 행동을 실행 중인 상태
}
```

**각 상태의 역할:**

1. **WaitingForEnemyTurn (대기 상태)**
   - 플레이어가 턴을 진행하는 동안 적은 이 상태로 대기
   - 아무 행동도 하지 않음
   - 턴이 바뀌면 TackingTurn으로 전환
2. **TackingTurn (턴 진행 상태)**
   - 적의 턴이 시작되면 이 상태로 진입
   - 타이머를 카운트다운하여 행동 사이의 간격을 둠
   - 행동을 시도하면 Busy 상태로 전환
3. **Busy (행동 실행 상태)**
   - 실제로 행동(SpinAction 등)을 수행 중
   - 행동이 완료되면 다시 TackingTurn으로 돌아감
   - 더 이상 행동할 수 없으면 턴을 종료

## 3. 적 AI 상태 머신 구현하기

### 상태 변수와 초기화

```csharp
private State state;        // 현재 상태를 저장하는 변수
private float timer;        // 행동 간격을 위한 타이머

private void Awake()
{
    // 게임 시작 시 플레이어가 먼저 턴을 가지므로
    // 적은 대기 상태로 시작
    state = State.WaitingForEnemyTurn;
}
```

### Update에서 상태에 따른 행동 처리

```csharp
private void Update()
{
    // 플레이어 턴이면 적은 아무것도 하지 않음
    if (TurnSystem.Instance.IsPlayerTurn())
    {
        return;
    }

    // 현재 상태에 따라 다른 로직 실행
    switch (state)
    {
        case State.WaitingForEnemyTurn:
            // 대기 상태: 아무것도 하지 않음
            break;

        case State.TackingTurn:
            // 턴 진행 상태: 타이머 감소
            timer -= Time.deltaTime;

            if (timer <= 0f)  // 타이머가 다 되면
            {
                // 행동 시도
                if (TryTakeEnemyAIAction(SetStateTakingTurn))
                {
                    state = State.Busy;  // 성공하면 Busy 상태로
                }
                else
                {
                    // 더 이상 행동할 수 없으면 턴 종료
                    TurnSystem.Instance.NextTurn();
                }
            }
            break;

        case State.Busy:
            // 행동 실행 중: 아무것도 하지 않음
            // 행동이 끝나면 콜백으로 상태 변경
            break;
    }
}
```

**타이머의 역할:**

- `Time.deltaTime`: 이전 프레임과 현재 프레임 사이의 시간 (약 0.016초)
- 매 프레임마다 타이머에서 시간을 빼서 카운트다운
- 타이머가 0 이하가 되면 다음 행동 실행
- **목적**: 적이 너무 빠르게 행동하지 않도록 간격을 둠 (자연스러운 플레이 경험)

### 턴 변경 시 상태 전환

```csharp
private void Start()
{
    // 턴 변경 이벤트 구독
    TurnSystem.Instance.OnTurnChanged += TurnSystem_OnTurnChanged;
}

private void TurnSystem_OnTurnChanged(object sender, EventArgs e)
{
    // 적의 턴이 되면
    if (!TurnSystem.Instance.IsPlayerTurn())
    {
        state = State.TackingTurn;  // 턴 진행 상태로 전환
        timer = 2f;                 // 2초 대기 후 첫 행동 시작
    }
}
```

### 행동 완료 후 상태 복귀 함수

```csharp
private void SetStateTakingTurn()
{
    timer = 0.5f;               // 다음 행동까지 0.5초 대기
    state = State.TackingTurn;   // 다시 턴 진행 상태로
}
```

**콜백 패턴의 이해:**

- `SetStateTakingTurn`은 행동이 완료되면 호출되는 **콜백 함수**
- 행동을 시작할 때 이 함수를 전달하여, 행동이 끝나면 자동으로 호출되게 함
- 플레이어의 UnitActionSystem에서 사용한 `ClearBusy`와 같은 역할
- 이를 통해 **행동 → 대기 → 다음 행동** 순환 구조를 만듦

## 4. UnitManager로 유닛 관리 시스템 만들기

### UnitManager가 필요한 이유

현재 문제:

- 적 AI가 모든 적 유닛을 순회하면서 행동을 시켜야 함
- 하지만 씬에 있는 모든 적 유닛 리스트가 없음
- `GameObject.FindObjectsOfType` 같은 함수는 성능이 좋지 않음

해결책:

- **UnitManager**라는 중앙 관리자를 만들어 모든 유닛을 추적
- 유닛이 생성/제거될 때 자동으로 리스트 업데이트

### UnitManager 기본 구조

```csharp
public class UnitManager : MonoBehaviour
{
    // 싱글톤 패턴: 어디서든 접근 가능한 단 하나의 인스턴스
    public static UnitManager Instance { get; private set; }

    // 3개의 리스트로 유닛 분류 관리
    private List<Unit> unitList;           // 모든 유닛
    private List<Unit> friendlyUnitList;   // 아군 유닛만
    private List<Unit> enemyUnitList;      // 적 유닛만
```

**3개 리스트를 사용하는 이유:**

- `unitList`: 전체 유닛 관리 (게임 종료 조건 체크 등)
- `friendlyUnitList`: 아군만 필요한 경우 (UI 표시, 특정 효과 등)
- `enemyUnitList`: 적 AI가 자신의 유닛들에게 명령을 내릴 때

### 싱글톤 패턴 구현

```csharp
private void Awake()
{
    // 이미 인스턴스가 존재하면 중복 생성 방지
    if (Instance != null)
    {
        Debug.LogError("There is more than one UnitActionsSystem! " + transform + " - " + Instance);
        Destroy(gameObject);
        return;
    }

    // 인스턴스 설정
    Instance = this;

    // 리스트 초기화 (Awake에서 해야 Start 전에 준비됨)
    unitList = new List<Unit>();
    friendlyUnitList = new List<Unit>();
    enemyUnitList = new List<Unit>();
}
```

**Awake에서 리스트를 초기화하는 이유:**

- `Awake`는 `Start`보다 먼저 실행됨
- `Start`에서 유닛 이벤트를 구독하기 때문에, 그 전에 리스트가 준비되어 있어야 함

### Unit 클래스에 이벤트 추가

```csharp
// Unit.cs
public static event EventHandler OnAnyUnitSpawned;  // 유닛 생성 이벤트
public static event EventHandler OnAnyUnitDead;     // 유닛 사망 이벤트
```

**static 이벤트를 사용하는 이유:**

- 일반 이벤트: 특정 인스턴스의 이벤트 (예: "이 유닛"이 죽었을 때)
- static 이벤트: 클래스 차원의 이벤트 (예: "어떤 유닛이든" 생성/사망했을 때)
- UnitManager는 모든 유닛의 생성/사망을 감지해야 하므로 static 사용

### 유닛 생성 이벤트 발생

```csharp
// Unit.cs - Start()
private void Start()
{
    gridPosition = LevelGrid.Instance.GetGridPosition(transform.position);
    LevelGrid.Instance.AddUnitAtGridPosition(gridPosition, this);

    TurnSystem.Instance.OnTurnChanged += TurnSystem_OnTurnChanged;
    healthSystem.OnDead += HealthSystem_OnDead;

    // 유닛이 완전히 초기화된 후 생성 이벤트 발생
    OnAnyUnitSpawned.Invoke(this, EventArgs.Empty);
}
```

**EventArgs.Empty의 의미:**

- `EventArgs`: 이벤트와 함께 전달할 추가 데이터
- `Empty`: 추가 데이터가 없다는 의미
- `this`: 이벤트를 발생시킨 유닛 자신을 sender로 전달

### 유닛 사망 이벤트 발생

```csharp
// Unit.cs
private void HealthSystem_OnDead(object sender, EventArgs e)
{
    LevelGrid.Instance.RemoveUnitAtGridPosition(gridPosition, this);
    Destroy(gameObject);

    // 오브젝트가 파괴되기 직전에 사망 이벤트 발생
    OnAnyUnitDead.Invoke(this, EventArgs.Empty);
}
```

### UnitManager에서 이벤트 구독 및 처리

```csharp
private void Start()
{
    // Unit 클래스의 static 이벤트 구독
    Unit.OnAnyUnitSpawned += Unit_OnAnyUnitSpawned;
    Unit.OnAnyUnitDead += Unit_OnAnyUnitDead;
}

private void Unit_OnAnyUnitSpawned(object sender, EventArgs e)
{
    // sender를 Unit 타입으로 변환
    Unit unit = sender as Unit;

    // 모든 유닛 리스트에 추가
    unitList.Add(unit);

    // 적/아군 구분하여 해당 리스트에 추가
    if (unit.IsEnemy())
    {
        enemyUnitList.Add(unit);
    }
    else
    {
        friendlyUnitList.Add(unit);
    }
}
```

**`as` 키워드의 역할:**

- `sender`는 `object` 타입 (가장 기본 타입)
- `as Unit`: object를 Unit 타입으로 안전하게 변환
- 변환 실패 시 예외 대신 `null` 반환

```csharp
private void Unit_OnAnyUnitDead(object sender, EventArgs e)
{
    Unit unit = sender as Unit;

    // 모든 리스트에서 제거
    unitList.Remove(unit);

    if (unit.IsEnemy())
    {
        enemyUnitList.Remove(unit);
    }
    else
    {
        friendlyUnitList.Remove(unit);
    }
}
```

### 외부 접근용 공개 메서드

```csharp
// 각 리스트를 외부에서 읽기만 가능하도록 제공
public List<Unit> GetUnits()
{
    return unitList;
}

public List<Unit> GetFriendlyUnitList()
{
    return friendlyUnitList;
}

public List<Unit> GetEnemyUnitList()
{
    return enemyUnitList;
}
```

**왜 리스트를 직접 public으로 만들지 않나?**

- `public List<Unit> enemyUnitList;` 이렇게 하면 외부에서 리스트를 직접 수정 가능
- Get 메서드를 사용하면 읽기만 가능하도록 제어할 수 있음 (캡슐화)

## 5. 스크립트 실행 순서 문제 해결하기

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380475/notion-blog/_/3D_/_/_5_Enemies_Combat_-_4/image_2.png)

### 문제 상황

```
1. Unit.Start()가 먼저 실행됨
   → OnAnyUnitSpawned 이벤트 발생

2. UnitManager.Start()가 나중에 실행됨
   → 이벤트 구독 시작

결과: 이미 발생한 이벤트를 놓침 → 유닛이 리스트에 추가되지 않음
```

### 스크립트 실행 순서 (Script Execution Order)

Unity는 기본적으로 스크립트 실행 순서를 보장하지 않음:

- 여러 스크립트의 `Awake`, `Start`가 임의의 순서로 실행될 수 있음
- 이벤트 시스템에서는 **구독자가 먼저 준비되어야** 이벤트를 받을 수 있음

### 해결 방법: Script Execution Order 설정

Unity 에디터에서 설정:

1. **Edit → Project Settings** 메뉴 열기
2. **Script Execution Order** 항목 선택
3. UnitManager 스크립트를 목록에 추가
4. 실행 순서 값을 **음수**로 설정 (예: -100)

```
실행 순서 값:
-100: UnitManager  ← 가장 먼저 실행
   0: (기본값) Unit, EnemyAI 등
```

**실행 순서 값의 의미:**

- 숫자가 작을수록 먼저 실행됨
- 음수: 기본 스크립트들보다 먼저 실행
- 양수: 기본 스크립트들보다 나중에 실행
- 같은 값: 순서 보장 안 됨

### 적용 후 실행 흐름

```
1. UnitManager.Awake() 실행
   → 리스트 초기화

2. UnitManager.Start() 실행
   → 이벤트 구독 시작

3. Unit.Start() 실행
   → OnAnyUnitSpawned 발생
   → UnitManager가 이벤트를 받아서 리스트에 추가
```

### 테스트 로그 추가

```csharp
// UnitManager.cs
private void Unit_OnAnyUnitSpawned(object sender, EventArgs e)
{
    Unit unit = sender as Unit;

    Debug.Log("Unit spawned: " + unit.name);  // 테스트용 로그

    unitList.Add(unit);
    // ... 나머지 코드
}

private void Unit_OnAnyUnitDead(object sender, EventArgs e)
{
    Unit unit = sender as Unit;

    Debug.Log("Unit died: " + unit.name);  // 테스트용 로그

    unitList.Remove(unit);
    // ... 나머지 코드

```

**테스트 결과:**

- 게임 시작: "Unit spawned: Unit (Player)", "Unit spawned: Unit (Enemy)" 로그 확인
- 적을 처치: "Unit died: Unit (Enemy)" 로그 확인
- 모든 이벤트가 정상 작동 확인 후 로그 제거

## 6. 적 행동 실행 로직 구현하기

### 기본 행동 시도 함수 - TryTakeEnemyAIAction (오버로드 1)

```csharp
// 모든 적 유닛을 순회하면서 행동 시도
private bool TryTakeEnemyAIAction(Action onEnemyAIActionComplete)
{
    // UnitManager에서 적 유닛 리스트 가져오기
    foreach (Unit enemyUnit in UnitManager.Instance.GetEnemyUnitList())
    {
        // 각 적 유닛에 대해 행동 시도
        if (TryTakeEnemyAIAction(enemyUnit, onEnemyAIActionComplete))
        {
            return true;  // 한 유닛이라도 행동하면 성공
        }
    }
    // 모든 적이 행동할 수 없으면 실패
    return false;
}
```

**함수 오버로딩(Overloading):**

- 같은 이름의 함수를 여러 개 만들되, 매개변수만 다르게 설정
- `TryTakeEnemyAIAction(콜백)` ← 모든 적 순회
- `TryTakeEnemyAIAction(특정 유닛, 콜백)` ← 특정 적의 행동 시도
- C#이 매개변수를 보고 자동으로 어느 함수를 호출할지 결정

### 개별 유닛 행동 시도 - TryTakeEnemyAIAction (오버로드 2)

```csharp
private bool TryTakeEnemyAIAction(Unit enemyUnit, Action onEnemyAIActionComplete)
{
    // 1. 해당 유닛에서 SpinAction 컴포넌트 가져오기
    SpinAction spinAction = enemyUnit.GetSpinAction();

    // 2. 행동을 실행할 그리드 위치 결정 (자기 위치)
    GridPosition actionGridPosition = enemyUnit.GetGridPosition();

    // 3. 해당 위치에서 행동이 유효한지 검증
    if (!spinAction.IsValidActionGridPosition(actionGridPosition))
    {
        return false;  // 유효하지 않으면 실패
    }

    // 4. 액션 포인트를 소모할 수 있는지 검증
    if (!enemyUnit.TrySpendActionPointsToTakeAction(spinAction))
    {
        return false;  // 포인트가 부족하면 실패
    }

    // 5. 모든 검증 통과 → 실제 행동 실행
    spinAction.TakeAction(actionGridPosition, onEnemyAIActionComplete);

    return true;  // 성공
}
```

**각 단계 상세 설명:**

1. **SpinAction 가져오기**

   ```csharp
   SpinAction spinAction = enemyUnit.GetSpinAction();
   ```

   - 현재는 SpinAction만 사용하지만, 나중에 다른 행동도 추가 예정
   - 각 유닛이 가진 행동 컴포넌트에 접근

2. **그리드 위치 결정**

   ```csharp
   GridPosition actionGridPosition = enemyUnit.GetGridPosition();
   ```

   - SpinAction은 제자리에서 회전하므로 자신의 현재 위치가 타겟
   - 다른 행동(이동, 공격 등)은 다른 위치를 타겟으로 할 수 있음

3. **유효성 검증**

   ```csharp
   if (!spinAction.IsValidActionGridPosition(actionGridPosition))
   ```

   - 해당 위치에서 이 행동을 수행할 수 있는지 확인
   - SpinAction은 항상 자기 위치에서 가능하므로 보통 true

4. **액션 포인트 검증 및 소모**

   ```csharp
   if (!enemyUnit.TrySpendActionPointsToTakeAction(spinAction))
   ```

   - 행동에 필요한 포인트가 있는지 확인
   - 있으면 포인트를 소모하고 true 반환
   - 없으면 false 반환하여 행동 취소

5. **행동 실행**

   ```csharp
   spinAction.TakeAction(actionGridPosition, onEnemyAIActionComplete);
   ```

   - 실제로 회전 애니메이션 시작
   - 완료되면 `onEnemyAIActionComplete` 콜백 호출
   - 이 콜백이 `SetStateTakingTurn`을 실행하여 다음 행동 준비

### Unit 클래스의 행동 검증 메서드

```csharp
// Unit.cs
public bool TrySpendActionPointsToTakeAction(BaseAction baseAction)
{
    // 포인트가 충분한지 먼저 확인
    if (CanSpendActionPointsToTakeAction(baseAction))
    {
        // 충분하면 포인트 소모하고 true 반환
        SpendActionPoints(baseAction.GetActionPointCost());
        return true;
    }
    else
    {
        // 부족하면 false 반환
        return false;
    }
}

public bool CanSpendActionPointsToTakeAction(BaseAction baseAction)
{
    // 현재 포인트 >= 행동에 필요한 포인트
    if (actionPoints >= baseAction.GetActionPointCost())
    {
        return true;
    }
    else
    {
        return false;
    }
}
```

**2단계 검증의 이유:**

- `CanSpend`: 검증만 하고 상태 변경 없음 (UI 표시 등에 사용)
- `TrySpend`: 검증 + 실제 포인트 소모 (실제 행동 시작 시 사용)

## 7. 턴 종료 조건 처리하기

### 현재 문제점

초기 구현에서는 행동이 완료된 후 턴이 자동 종료되지 않고 무한 루프에 빠짐:

```
1. 적이 SpinAction 실행 (포인트 2 → 1)
2. 행동 완료, SetStateTakingTurn 호출
3. 다시 TryTakeEnemyAIAction 호출
4. 포인트 부족으로 false 반환
5. 하지만 턴을 종료하지 않고 계속 대기
6. 게임이 멈춤
```

### 함수명 변경: Take → Try

```csharp
// 변경 전
private void TakeEnemyAIAction(Unit enemyUnit, Action onEnemyAIActionComplete)
{
    // 항상 성공한다고 가정
}

// 변경 후
private bool TryTakeEnemyAIAction(Unit enemyUnit, Action onEnemyAIActionComplete)
{
    // 성공/실패를 bool로 반환
}
```

**Try 접두사의 의미:**

- C# 네이밍 규칙: "Try"로 시작하는 함수는 성공/실패를 bool로 반환
- 예: `int.TryParse()`, `Dictionary.TryGetValue()` 등
- 명확한 의미 전달: "시도했는데 실패할 수도 있다"

### Update에서 턴 종료 처리

```csharp
case State.TackingTurn:
    timer -= Time.deltaTime;

    if (timer <= 0f)
    {
        // 행동 시도
        if (TryTakeEnemyAIAction(SetStateTakingTurn))
        {
            // 성공: Busy 상태로 전환하여 행동 실행
            state = State.Busy;
        }
        else
        {
            // 실패: 더 이상 행동할 수 없으므로 턴 종료
            TurnSystem.Instance.NextTurn();
        }
    }
    break;
```

**전체 흐름 이해:**

```
턴 시작 → TackingTurn 상태
    ↓
타이머 대기 (2초)
    ↓
행동 시도
    ↓
성공? → Busy → 행동 실행 → 완료 → SetStateTakingTurn → 다시 시도
실패? → 모든 적이 포인트 없음 → NextTurn() 호출 → 플레이어 턴
```

### 왜 모든 적을 순회하나?

```csharp
foreach (Unit enemyUnit in UnitManager.Instance.GetEnemyUnitList())
{
    if (TryTakeEnemyAIAction(enemyUnit, onEnemyAIActionComplete))
    {
        return true;  // 첫 번째 성공한 유닛에서 멈춤
    }
}
return false;  // 모두 실패

```

**순회 방식:**

- 적 유닛 리스트를 앞에서부터 순서대로 확인
- 첫 번째 유닛이 행동 가능하면 → 그 유닛이 행동하고 종료
- 첫 번째 유닛이 포인트 없으면 → 두 번째 유닛 확인
- 모든 유닛이 행동 불가능하면 → false 반환하여 턴 종료

**공정성 문제:**

- 현재는 항상 리스트의 첫 번째 적이 우선권을 가짐
- 나중에 개선: 랜덤 순서, 우선순위 시스템 등 추가 가능

## 3. BaseAction에서 AI 액션 평가 시스템 구축

### GetBestEnemyAIAction 메서드 구현

모든 액션이 상속받는 BaseAction 클래스에 AI 평가 시스템을 추가합니다.

```csharp
public EnemyAIAction GetBestEnemyAIAction()
{
    // 모든 가능한 AI 액션을 저장할 리스트
    List<EnemyAIAction> enemyAIActionList = new List<EnemyAIAction>();

    // 이 액션으로 이동/공격 가능한 모든 그리드 위치 가져오기
    List<GridPosition> validActionGridPositionList = GetValidActionGridPositionList();

    // 각 유효한 위치에 대해
    foreach(GridPosition gridPosition in validActionGridPositionList)
    {
        // 해당 위치에서의 AI 액션 평가 (각 자식 클래스에서 구현)
        EnemyAIAction enemyAIAction = GetEnemyAIAction(gridPosition);

        // 리스트에 추가
        enemyAIActionList.Add(enemyAIAction);
    }

    // 액션이 하나라도 있으면
    if (enemyAIActionList.Count > 0)
    {
        // actionValue 기준으로 내림차순 정렬
        // (b.actionValue - a.actionValue)는 큰 값이 앞으로 오도록 함
        enemyAIActionList.Sort((EnemyAIAction a, EnemyAIAction b) => b.actionValue - a.actionValue);

        // 가장 높은 점수의 액션 반환 (정렬 후 첫 번째 요소)
        return enemyAIActionList[0];
    }
    else
    {
        // 가능한 액션이 없으면 null 반환
        return null;
    }
}

```

### 정렬 알고리즘 설명

```csharp
enemyAIActionList.Sort((EnemyAIAction a, EnemyAIAction b) => b.actionValue - a.actionValue);
```

- **람다 표현식 사용**: 익명 함수로 정렬 기준 정의
- **비교 로직**:
  - `b.actionValue - a.actionValue`가 양수면 → b가 더 큼 → b를 앞으로
  - 음수면 → a가 더 큼 → a를 앞으로
  - 0이면 → 같음 → 순서 유지
- **결과**: actionValue가 큰 것부터 작은 순서로 정렬

### 추상 메서드 선언

각 액션 클래스가 반드시 구현해야 하는 메서드를 추가합니다.

```csharp
}

// 오버로드 메서드 - 임의의 위치 기준
public List<GridPosition> GetValidActionGridPositionList(GridPosition unitGridPosition)
{
    List<GridPosition> validGridPositionList = new List<GridPosition>();

    // maxShootDistance 범위 내의 모든 위치 검사
    for (int x = -maxShootDistance; x <= maxShootDistance; x++)
    {
        for (int z = -maxShootDistance; z <= maxShootDistance; z++)
        {
            GridPosition offsetGridPosition = new GridPosition(x, z);
            GridPosition testGridPosition = unitGridPosition + offsetGridPosition;

            // 유효하지 않은 그리드 위치면 스킵
            if (!LevelGrid.Instance.IsValidGridPosition(testGridPosition))
            {
                continue;
            }

            // 실제 거리 계산 (맨하탄 거리)
            int testDistance = Mathf.Abs(x) + Mathf.Abs(z);
            if (testDistance > maxShootDistance)
            {
                continue;
            }

            // 해당 위치에 유닛이 없으면 스킵
            if (!LevelGrid.Instance.HasAnyUnitOnGridPosition(testGridPosition))
            {
                continue;
            }

            Unit targetUnit = LevelGrid.Instance.GetUnitAtGridPosition(testGridPosition);

            // 아군이면 스킵 (적만 공격 가능)
            if (targetUnit.IsEnemy() == unit.IsEnemy())
            {
                continue;
            }

            validGridPositionList.Add(testGridPosition);
        }
    }

    return validGridPositionList;
}
```

### GetTargetCountAtPosition 메서드

특정 위치에서 공격 가능한 타겟 수를 반환합니다.

```csharp
public int GetTargetCountAtPosition(GridPosition gridPosition)
{
    // 해당 위치에서의 유효한 사격 대상 리스트를 가져와서 개수 반환
    return GetValidActionGridPositionList(gridPosition).Count;
}
```

## 7. MoveAction AI 구현 - 전술적 이동

### Unit에 ShootAction 노출

MoveAction에서 ShootAction을 참조할 수 있도록 Unit 클래스에 getter 추가:

```csharp
public ShootAction GetShootAction()
```

### MoveAction의 AI 전략

단순히 랜덤하게 이동하는 것이 아니라, **가장 많은 적을 공격할 수 있는 위치**로 이동합니다.

```csharp
public override EnemyAIAction GetEnemyAIAction(GridPosition gridPosition)
{
    // 이 위치로 이동했을 때 공격 가능한 타겟 수 계산
    int targetCountAtGridPosition = unit.GetShootAction().GetTargetCountAtPosition(gridPosition);

    return new EnemyAIAction
    {
        gridPosition = gridPosition,
        actionValue = targetCountAtGridPosition * 10,  // 타겟 수 × 10
    };
}
```

### 점수 계산 로직

- **타겟 1명 있는 위치**: actionValue = 1 × 10 = **10점**
- **타겟 2명 있는 위치**: actionValue = 2 × 10 = **20점**
- **타겟 0명 있는 위치**: actionValue = 0 × 10 = **0점**

### 전략적 의미

1. **우선순위**: 많은 적을 공격할 수 있는 위치를 선호
2. **Shoot vs Move 비교**:
   - Shoot의 기본 점수 = 100
   - Move의 최대 점수 = (타겟 수 × 10)
   - 따라서 사격 가능하면 항상 사격 우선
3. **Move 내 우선순위**: 2명 공격 가능 위치 > 1명 공격 가능 위치 > 0명 위치

## 8. EnemyAI에서 최적 액션 선택 로직

### TryTakeEnemyAIAction 메서드 수정

기존의 단순한 SpinAction 로직을 완전히 교체합니다.

```csharp
private bool TryTakeEnemyAIAction(Unit enemyUnit, Action onEnemyAIActionComplete)
{
    // 최고 점수의 AI 액션을 저장할 변수
    EnemyAIAction bestEnemyAIAction = null;
    BaseAction bestBaseAction = null;

    // 이 적 유닛이 가진 모든 액션을 순회
    foreach (BaseAction baseAction in enemyUnit.GetBaseActionArray())
    {
        // 1단계: 액션 포인트 체크
        // 이 액션을 수행할 만큼의 액션 포인트가 있는지 확인
        if (!enemyUnit.CanSpendActionPointsToTakeAction(baseAction))
        {
            continue;  // 액션 포인트 부족하면 다음 액션으로
        }

        // 2단계: 첫 번째 유효한 액션 처리
        if (bestEnemyAIAction == null)
        {
            // 아직 비교 대상이 없으면 이것을 기준으로 설정
            bestEnemyAIAction = baseAction.GetBestEnemyAIAction();
            bestBaseAction = baseAction;
        }
        else
        {
            // 3단계: 더 좋은 액션 찾기
            // 현재 액션의 최고 점수 계산
            EnemyAIAction testEnemyAIAction = baseAction.GetBestEnemyAIAction();

            // 유효하고 && 기존 최고점보다 높으면
            if (testEnemyAIAction != null &&
                testEnemyAIAction.actionValue > bestEnemyAIAction.actionValue)
            {
                // 새로운 최고 액션으로 갱신
                bestEnemyAIAction = testEnemyAIAction;
                bestBaseAction = baseAction;
            }
        }
    }

    // 4단계: 최종 액션 실행
    // 유효한 액션이 있고 && 액션 포인트 소모 성공하면
    if (bestEnemyAIAction != null &&
        enemyUnit.TrySpendActionPointsToTakeAction(bestBaseAction))
    {
        // 선택된 최고 액션 실행
        bestBaseAction.TakeAction(bestEnemyAIAction.gridPosition, onEnemyAIActionComplete);
        return true;
    }
    else
    {
        // 실행할 수 있는 액션이 없음
        return false;
    }
}
```

### 로직 흐름 상세 분석

### 1단계: 액션 포인트 체크

```csharp
if (!enemyUnit.CanSpendActionPointsToTakeAction(baseAction))
{
    continue;
}
```

- 액션 포인트가 부족한 액션은 평가조차 하지 않음
- 효율성 향상

### 2단계: 첫 번째 유효 액션

```csharp
if (bestEnemyAIAction == null)
{
    bestEnemyAIAction = baseAction.GetBestEnemyAIAction();
    bestBaseAction = baseAction;
}

```

- 비교 기준이 필요하므로 첫 번째로 발견한 유효 액션을 기준으로 설정

### 3단계: 더 좋은 액션 탐색

```csharp
EnemyAIAction testEnemyAIAction = baseAction.GetBestEnemyAIAction();

if (testEnemyAIAction != null &&
    testEnemyAIAction.actionValue > bestEnemyAIAction.actionValue)
{
    bestEnemyAIAction = testEnemyAIAction;
    bestBaseAction = baseAction;
}
```

- 각 액션의 최고 점수를 계산하고
- 현재 최고점보다 높으면 갱신

### 4단계: 실행

```csharp
if (bestEnemyAIAction != null &&
    enemyUnit.TrySpendActionPointsToTakeAction(bestBaseAction))
{
    bestBaseAction.TakeAction(bestEnemyAIAction.gridPosition, onEnemyAIActionComplete);
    return true;
}
```

- 최종 선택된 액션을 실제로 실행
- 액션 포인트 소모 후 액션 수행

## 9. ShootAction AI 고도화 - 체력 기반 우선순위

### 전략적 개선

현재는 모든 적에게 100점을 부여하지만, 실제 전략 게임에서는 **약한 적을 먼저 처치**하는 것이 유리합니다.

### Unit에 체력 정보 노출

```csharp
public float GetHealthNormalized()
{
    // HealthSystem에서 정규화된 체력 값 반환 (0.0 ~ 1.0)
    return healthSystem.GetHealthNormalized();
}
```

### 개선된 ShootAction AI

```csharp
public override EnemyAIAction GetEnemyAIAction(GridPosition gridPosition)
{
    // 공격 대상 유닛 가져오기
    Unit targetUnit = LevelGrid.Instance.GetUnitAtGridPosition(gridPosition);

    return new EnemyAIAction
    {
        gridPosition = gridPosition,
        // 기본 100점 + (1 - 체력비율) × 100
        actionValue = 100 + Mathf.RoundToInt((1 - targetUnit.GetHealthNormalized()) * 100f),
    };
}

```

### 점수 계산 상세 분석

### 체력 100% 적

```
actionValue = 100 + (1 - 1.0) × 100
            = 100 + 0 × 100
            = 100 + 0
            = 100점

```

### 체력 50% 적

```
actionValue = 100 + (1 - 0.5) × 100
            = 100 + 0.5 × 100
            = 100 + 50
            = 150점

```

### 체력 10% 적

```
actionValue = 100 + (1 - 0.1) × 100
            = 100 + 0.9 × 100
            = 100 + 90
            = 190점

```

### 전략적 효과

1. **약한 적 우선**: 체력이 낮을수록 점수가 높음
2. **완전 처치 우선**: 거의 죽어가는 적을 먼저 제거
3. **전력 감소**: 적의 수를 빠르게 줄여 화력 감소
4. **동점 방지**: `Mathf.RoundToInt`로 정수 변환

### Mathf.RoundToInt 필요성

```csharp
Mathf.RoundToInt((1 - targetUnit.GetHealthNormalized()) * 100f)
```

- **actionValue는 int 타입**: 정수만 저장 가능
- **GetHealthNormalized()는 float**: 0.0 ~ 1.0 사이의 실수
- **반올림 필요**: 0.753 × 100 = 75.3 → 75 (int로 변환)

### 테스트 시나리오 1: 사격 우선순위

- 이동하지 않고 바로 공격

**결과**:

- ✅ 적이 사격 액션 우선 실행
- ✅ 액션 포인트가 있으면 연속 공격

**상황 설정**:

- 적 1은 사거리 안에 플레이어 있음
- 적 2는 사거리 밖에 있음 (거리 11칸)

**예상 동작**:

- 적 1: 즉시 사격
- 적 2: 플레이어에게 접근 → 사거리 안 들어오면 사격

**결과**:

- ✅ 적 1이 먼저 사격
- ✅ 적 2가 점진적으로 이동
- ✅ 사거리 안에 들어오자마자 사격

### 테스트 시나리오 3: 약한 적 우선 공격

**상황 설정**:

- 플레이어 A: 체력 100% (2타 맞은 상태)
- 플레이어 B: 체력 100%
- 적 2명 배치

**예상 동작**:

- 첫 번째 적이 플레이어 A 공격 (이미 데미지 입음)
- 두 번째 적도 플레이어 A 공격 (더 약하므로)

**결과**:

- ✅ 두 적 모두 같은 타겟(더 약한 플레이어) 공격
- ✅ 체력 기반 우선순위 정상 작동

### 실제 게임 플레이 확인 사항

강사가 실제로 테스트하며 확인한 내용:

1. **사격 범위 확인**:
   - 적과 플레이어 모두 사거리 7칸
   - 맨하탄 거리로 계산됨
2. **액션 포인트 관리**:
   - 적이 액션 포인트 2개로 연속 행동
   - 포인트 소진 시 턴 종료
3. **이동 경로**:
   - 적이 가장 많은 플레이어를 공격할 수 있는 위치로 이동
   - 2명 공격 가능한 위치 > 1명 공격 가능한 위치
4. **체력 기반 타겟팅**:
   - 같은 위치에서 여러 타겟 공격 가능할 때
   - 항상 체력이 낮은 적 우선 선택

## 🎯 핵심 개념 정리

### 1. AI 평가 시스템 구조

```
BaseAction.GetBestEnemyAIAction()
    ↓
각 그리드 위치마다 GetEnemyAIAction() 호출
    ↓
actionValue 기준으로 정렬
    ↓
최고 점수 액션 반환
```

### 2. 액션별 우선순위

```
ShootAction: 100~200점 (체력 기반)
MoveAction: 0~20점 (타겟 수 × 10)
SpinAction: 0점 (최후의 수단)
```

### 3. 전략적 의사결정 흐름

```
1. 사격 가능? → Yes: 즉시 사격 (특히 약한 적)
2. 사격 불가능? → 가장 많은 적 공격 가능한 위치로 이동
3. 이동도 불가능? → SpinAction (실제로는 거의 발생 안 함)
4. 아무것도 불가능? → 턴 종료
```

### 4. 확장성

- 새로운 액션 추가 시 `GetEnemyAIAction()` 구현만 하면 됨
- 액션별로 독립적인 점수 계산 로직 가능
- 전체 시스템 수정 없이 각 액션의 AI 개선 가능
