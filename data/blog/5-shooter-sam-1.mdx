# { 언리얼 엔진 게임 에셋 임포트 가이드 }

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380641/notion-blog/_/_/_5_C_/_5_Shooter_Sam_-_1/image.png)

이 강의는 언리얼 엔진에 게임 에셋을 가져오는 방법을 설명합니다.

## 주요 작업 내용

### 1단계: Fab Store에서 캐릭터 에셋 가져오기

1. Fab Store 웹사이트 접속 (에픽게임즈 계정 로그인 필요)
2. "파라곤 레이스(Paragon Wraith)" 검색
3. 내 라이브러리에 추가
4. 에픽게임즈 런처 → 라이브러리 → 팹 라이브러리에서 프로젝트에 추가

### 2단계: 추가 에셋 마이그레이션하기

1. 강의 리소스에서 "어썸 에셋" 프로젝트 다운로드
2. 다운받은 프로젝트를 열어서 필요한 에셋 선택
3. 마우스 우클릭 → "마이그레이션" 선택 (이주)
4. 작업 중인 프로젝트의 콘텐츠 폴더 선택하여 복사

## 가져온 에셋들

### 파라곤 레이스 팩

- 스켈레탈 메시 (뼈대가 있어 애니메이션 가능한 캐릭터 모델)
- 내부에 애니메이션용 본(뼈대) 구조 포함

### 슈팅 게임 팩

- 무기 메시 (소총, 런처 등)
- 음향 효과
- 시각 효과 (파티클)
- 보이스오버

## 핵심 용어

- **스태틱 메시**: 움직이지 않는 고정된 3D 모델 (건물, 소품 등)
- **스켈레탈 메시**: 뼈대 구조가 있어 애니메이션이 가능한 3D 모델 (캐릭터)
- **마이그레이션**: 한 프로젝트의 에셋을 다른 프로젝트로 복사하는 기능

## 주의사항

마이그레이션 과정에서 간혹 일부 폴더나 파일이 복사되지 않을 수 있습니다.
이런 경우 원본 프로젝트로 돌아가서 해당 파일/폴더를 개별적으로 마이그레이션하면 됩니다.

---

**요약**: 게임 제작에 필요한 캐릭터, 무기, 효과음 등을 프로젝트에 추가하는 과정입니다.

## 1. 입력 액션 바인딩 이해하기

### 플레이어 입력 컴포넌트 설정 위치

3인칭 캐릭터 클래스의 코드를 보면 **플레이어 입력 컴포넌트 설정** 섹션이 있습니다. 여기서 입력과 함수를 연결합니다.

### 이동 액션 바인딩 방식

```cpp
// 이동 액션이 트리거될 때마다 Move 함수를 호출
PlayerInputComponent->BindAction("MoveAction", ETriggerEvent::Triggered, this, &AThirdPersonCharacter::Move);
```

**바인딩의 의미:**

- **"MoveAction"** : 입력 액션의 이름
- **ETriggerEvent::Triggered** : 이 이벤트 타입은 "액션이 활성화되어 있는 동안 계속 호출"을 의미
- **Move 함수** : 입력 값을 받아서 처리할 함수

**기존 Bool/Float 방식과의 차이:**

- 이전에는 True/False 값을 받는 Bool 타입이나 단일 숫자를 받는 Float 타입을 사용했습니다.
- 이동의 경우 **앞뒤 + 좌우** 2가지 방향 정보가 필요하므로 새로운 타입이 필요합니다.

## 2. FVector2D 타입 이해하기

### FVector2D란?

```cpp
void AThirdPersonCharacter::Move(const FInputActionValue& Value)
{
    // Value에서 FVector2D 타입으로 값을 가져옴
    FVector2D MovementVector = Value.Get<FVector2D>();

    // MovementVector.X → 좌우 입력 값 (-1 ~ 1)
    // MovementVector.Y → 앞뒤 입력 값 (-1 ~ 1)
}
```

**FVector2D 구조:**

```
FVector2D
├── X (float) : 수평(좌우) 값
└── Y (float) : 수직(앞뒤) 값
```

**값 접근 방법:**

```cpp
float HorizontalInput = MovementVector.X;  // 점(.) 연산자로 X 값 가져오기
float VerticalInput = MovementVector.Y;    // 점(.) 연산자로 Y 값 가져오기
```

**FVector와의 차이점:**

- **FVector** : X, Y, Z 세 개의 float 값 (3D 공간용)
- **FVector2D** : X, Y 두 개의 float 값 (2D 입력용)

## 3. 입력 액션 에셋 설정 분석

### 입력 액션 에셋 확인하기

언리얼 엔진 에디터에서 이동 입력 액션 에셋을 열어봅니다.

**Value Type 설정:**

- **Axis2D (Vector 2D)** 로 설정되어 있음
- 이는 2개의 float 값을 담을 수 있는 타입입니다.

**다른 Value Type 옵션들:**

- **Digital (Bool)** : True/False 값만 필요할 때 (예: 점프)
- **Axis1D (Float)** : 단일 숫자 값이 필요할 때 (예: 줌)
- **Axis2D (Vector 2D)** : 두 방향 입력이 필요할 때 (예: 이동)
- **Axis3D (Vector)** : 세 방향 입력이 필요할 때 (예: 비행)

### 매핑 컨텍스트의 역할

입력 액션 에셋 자체는 "어떤 타입의 값을 받을지"만 정의합니다. 실제로 "어떤 키를 누르면 어떤 값이 들어가는지"는 **매핑 컨텍스트(Mapping Context)** 에서 설정합니다.

## 4. 매핑 컨텍스트에서 4방향 입력 구현

### 매핑 컨텍스트 구조 살펴보기

매핑 컨텍스트를 열고 Move 입력 액션을 펼쳐보면 여러 키가 바인딩되어 있습니다:

```
MoveAction
├── A 키 (왼쪽)
├── D 키 (오른쪽)
├── W 키 (앞)
├── S 키 (뒤)
├── 방향키 상하좌우
└── 게임패드 왼쪽 스틱
```

이 강의에서는 **A, D, W, S 키**에 집중합니다.

---

### A와 D 키 설정 (좌우 이동)

### D 키 설정

```
D 키
├── 기본 값: 1.0 (양수)
├── 수정자(Modifiers): 없음
└── 결과: MovementVector.X = 1.0 (오른쪽)
```

**작동 방식:**

- D 키를 누르면 기본적으로 **양수(+1.0)** 값이 생성됩니다.
- 수정자가 없으므로 그대로 Vector2D의 **X 속성**에 들어갑니다.
- X가 양수이므로 **오른쪽** 방향을 의미합니다.

### A 키 설정

```
A 키
├── 기본 값: 1.0 (양수)
├── 수정자: Negate (부정 수정자)
└── 결과: MovementVector.X = -1.0 (왼쪽)
```

**Negate 수정자의 역할:**

- **Negate** : 값을 음수로 바꾸는 수정자
- 원래 값 1.0에 Negate를 적용하면 → **1.0**
- A 키를 누르면 X = -1.0이 되어 **왼쪽** 방향을 의미합니다.

**Float 입력과의 유사성:**

- 단일 Float 값을 사용할 때도 이런 방식으로 작동합니다.
- 한 키는 양수, 반대 키는 Negate로 음수를 만듭니다.
- 하지만 지금은 Vector2D이므로 X와 Y 두 개의 값이 있습니다.

---

### W와 S 키 설정 (앞뒤 이동)

### 기본 동작의 한계

**문제 상황:**

- A, D 키가 이미 X 속성을 사용하고 있습니다.
- W, S 키도 같은 방식으로 설정하면 X 속성에 값이 들어갑니다.
- **하나의 Float는 한 번에 하나의 값만** 담을 수 있습니다.

**해결책:**

- W, S 키는 **Y 속성**에 값을 넣어야 합니다.
- 이를 위해 **Swizzle Input Axis Values** 수정자를 사용합니다.

---

### Swizzle 수정자 이해하기

**W 키 설정:**

```
W 키
├── 기본 값: 1.0
├── 수정자 1: Swizzle Input Axis Values
│   └── Order: YXZ
└── 결과: MovementVector.Y = 1.0 (앞)
```

**Swizzle의 의미:**

- **Swizzle** : 벡터의 속성 위치를 바꾸는 것
- **Order: YXZ** : 원래 순서(XYZ)를 YXZ로 재배치
  - 원래 X에 들어갈 값 → Y로 이동
  - 원래 Y에 들어갈 값 → X로 이동
  - Z는 이 경우 사용 안 함 (Vector2D는 Z가 없음)

**작동 과정:**

```
1. W 키 누름 → 기본 값 1.0 생성
2. 기본적으로 X 속성에 들어가려고 함
3. Swizzle 수정자 적용 → Y 속성으로 이동
4. 최종 결과: MovementVector.Y = 1.0
```

---

**S 키 설정:**

```
S 키
├── 기본 값: 1.0
├── 수정자 1: Negate (부정 수정자)
├── 수정자 2: Swizzle Input Axis Values
│   └── Order: YXZ
└── 결과: MovementVector.Y = -1.0 (뒤)
```

**수정자 적용 순서:**

```
1. S 키 누름 → 기본 값 1.0 생성
2. Negate 적용 → -1.0으로 변경
3. Swizzle 적용 → X에서 Y로 이동
4. 최종 결과: MovementVector.Y = -1.0
```

**중요한 점:**

- Negate가 **Swizzle보다 위에** 있어야 합니다 (수정자는 위에서 아래로 적용됨)
- A, D 키에는 Swizzle이 없으므로 여전히 X 속성을 사용합니다.

---

### 최종 결과 정리

**각 키를 눌렀을 때:**

| 키 누름 | MovementVector.X | MovementVector.Y | 의미   |
| ------- | ---------------- | ---------------- | ------ |
| D 키    | 1.0              | 0.0              | 오른쪽 |
| A 키    | -1.0             | 0.0              | 왼쪽   |
| W 키    | 0.0              | 1.0              | 앞     |
| S 키    | 0.0              | -1.0             | 뒤     |

**대각선 이동:**

| 키 조합 | MovementVector.X | MovementVector.Y | 의미      |
| ------- | ---------------- | ---------------- | --------- |
| D + W   | 1.0              | 1.0              | 오른쪽 앞 |
| A + W   | -1.0             | 1.0              | 왼쪽 앞   |
| D + S   | 1.0              | -1.0             | 오른쪽 뒤 |
| A + S   | -1.0             | -1.0             | 왼쪽 뒤   |

## 8. 회전 행렬로 방향 벡터 계산하기

### 전체 코드 구조

```cpp
void AThirdPersonCharacter::DoMove(float Right, float Forward)
{
    if (Controller != nullptr)
    {
        // === 1단계: 요(Yaw) 회전 추출 ===
        const FRotator Rotation = Controller->GetControlRotation();
        const FRotator YawRotation(0, Rotation.Yaw, 0);

        // === 2단계: 방향 벡터 계산 ===
        const FVector ForwardDirection = FRotationMatrix(YawRotation).GetUnitAxis(EAxis::X);
        const FVector RightDirection = FRotationMatrix(YawRotation).GetUnitAxis(EAxis::Y);

        // === 3단계: 이동 입력 추가 ===
        AddMovementInput(ForwardDirection, Forward);
        AddMovementInput(RightDirection, Right);
    }
}
```

이제 각 단계를 자세히 살펴보겠습니다.

---

### 1단계: 요(Yaw) 회전 추출

### 컨트롤러 회전 가져오기

```cpp
// 컨트롤러의 현재 회전 정보를 가져옴
const FRotator Rotation = Controller->GetControlRotation();
```

**FRotator란?**

- 3D 공간에서 회전을 나타내는 구조체
- 세 가지 축의 회전 값을 가짐:
  ```
  FRotator├── Pitch (float) : X축 회전 (위아래 보기)├── Yaw (float)   : Z축 회전 (좌우 회전)└── Roll (float)  : Y축 회전 (기울이기)
  ```

**Controller->GetControlRotation()의 의미:**

- 플레이어가 카메라를 어느 방향으로 보고 있는지 반환
- 예: 카메라를 위로 30도, 오른쪽으로 45도 돌렸다면
  ```
  Rotation.Pitch = 30.0Rotation.Yaw = 45.0Rotation.Roll = 0.0
  ```

---

### Yaw(요) 회전이란?

**Yaw 회전 시각화 (게임 내):**

```
위에서 본 모습:
        앞(북쪽)
          ↑
          |
왼쪽 ← 캐릭터 → 오른쪽
          |
          ↓
        뒤(남쪽)

Yaw = 0°   : 북쪽을 바라봄
Yaw = 90°  : 동쪽을 바라봄
Yaw = 180° : 남쪽을 바라봄
Yaw = 270° : 서쪽을 바라봄
```

**Z축 중심 회전:**

```
   Z축 (위쪽)
    ↑
    |
    ●────→ (캐릭터)

이 Z축을 중심으로 빙글빙글 도는 것이 Yaw 회전
```

---

### Yaw만 추출하기

```cpp
// Pitch와 Roll은 0으로 설정하고 Yaw만 유지
const FRotator YawRotation(0, Rotation.Yaw, 0);
```

**FRotator 생성자 형식:**

```cpp
FRotator(Pitch, Yaw, Roll)
```

**왜 Yaw만 필요한가?**

- **이동 방향 계산에는 "플레이어가 좌우 어디를 보고 있는지"만 필요**
- Pitch(위아래)는 이동과 무관
  - 위를 보면서도 앞으로 이동
  - 아래를 보면서도 앞으로 이동
- Roll(기울임)도 이동과 무관

**예시:**

```cpp
// 플레이어가 카메라를 위로 30도, 오른쪽으로 45도 돌린 상태
Rotation.Pitch = 30.0
Rotation.Yaw = 45.0
Rotation.Roll = 0.0

// Yaw만 추출
YawRotation = FRotator(0, 45.0, 0)
// → 좌우 방향(45도)만 남김
```

---

### 2단계: 방향 벡터 계산

### 회전 행렬(Rotation Matrix) 이해하기

**회전 행렬이란?**

- 회전 정보를 수학적 행렬로 변환한 것
- 이를 통해 "어떤 방향"을 벡터로 계산 가능

**간단한 개념:**

```
캐릭터가 북쪽(0도)을 보고 있을 때:
- 앞 방향 = (1, 0, 0)  // X축 양의 방향
- 오른쪽 방향 = (0, 1, 0)  // Y축 양의 방향

캐릭터가 동쪽(90도)을 보고 있을 때:
- 앞 방향 = (0, 1, 0)  // 회전되어 Y축 방향이 앞이 됨
- 오른쪽 방향 = (-1, 0, 0)  // 회전되어 -X축 방향이 오른쪽

→ 회전 행렬은 이런 변환을 자동으로 계산해줌
```

---

### Forward(앞) 방향 벡터 계산

```cpp
// YawRotation 정보로 회전 행렬을 만들고
// X축의 단위 벡터를 가져옴 (앞 방향)
const FVector ForwardDirection = FRotationMatrix(YawRotation).GetUnitAxis(EAxis::X);
```

**코드 분해:**

1. **FRotationMatrix(YawRotation)** :
   - YawRotation을 회전 행렬로 변환
   - 수학적 계산을 가능하게 함
2. **GetUnitAxis(EAxis::X)** :
   - 회전된 X축의 방향을 가져옴
   - "단위 벡터"이므로 길이가 1인 벡터 (방향만 나타냄)
3. **EAxis::X** :
   - X축을 의미하는 열거형 값
   - 언리얼 엔진에서 X축 = 앞 방향

**결과:**

```
ForwardDirection = (X, Y, Z) 벡터
- 이 벡터는 캐릭터가 보고 있는 "앞쪽" 방향을 가리킴
- 길이가 1인 단위 벡터 (방향만 표현)

```

**예시:**

```cpp
// 캐릭터가 북쪽(0도)을 보고 있으면
ForwardDirection = (1, 0, 0)  // X축 양의 방향

// 캐릭터가 동쪽(90도)을 보고 있으면
ForwardDirection = (0, 1, 0)  // Y축 양의 방향

// 캐릭터가 북동쪽(45도)을 보고 있으면
ForwardDirection = (0.707, 0.707, 0)  // 대각선 방향
```

---

### Right(오른쪽) 방향 벡터 계산

```cpp
// YawRotation 정보로 회전 행렬을 만들고
// Y축의 단위 벡터를 가져옴 (오른쪽 방향)
const FVector RightDirection = FRotationMatrix(YawRotation).GetUnitAxis(EAxis::Y);
```

**코드 분해:**

1. **GetUnitAxis(EAxis::Y)** :
   - 회전된 Y축의 방향을 가져옴
   - 언리얼 엔진에서 Y축 = 오른쪽 방향

**결과:**

```
RightDirection = (X, Y, Z) 벡터
- 이 벡터는 캐릭터의 "오른쪽" 방향을 가리킴
- ForwardDirection과 항상 수직
```

**예시:**

```cpp
// 캐릭터가 북쪽(0도)을 보고 있으면
ForwardDirection = (1, 0, 0)   // 앞 = 북쪽
RightDirection = (0, 1, 0)     // 오른쪽 = 동쪽

// 캐릭터가 동쪽(90도)을 보고 있으면
ForwardDirection = (0, 1, 0)   // 앞 = 동쪽
RightDirection = (0, 0, 1)     // 오른쪽 = 남쪽
```

### 3단계: 이동 입력 추가

### AddMovementInput 함수 이해하기

---

### 첫 번째 호출: 앞뒤 이동

```cpp
AddMovementInput(ForwardDirection, Forward);
```

**작동 과정:**

```cpp
// Forward 값에 따른 동작

```

### 대각선 이동의 원리

**W + D 키를 동시에 누르면:**

```cpp
// 1. Move 함수가 호출됨

MovementVector.Y = 1.0  // W 키 (앞)

```

```

        ↑
        |
        |
        ●────→ 오른쪽(RightDirection)

      /

```

## 4. Negate 수정자의 역할

### 왜 Y축에만 Negate가 필요한가?

**문제 상황:**

기본 마우스 동작으로는 카메라 움직임이 부자연스럽습니다:

```
마우스를 위로 움직임
→ Y = 양수
→ 카메라가 아래를 봄 (반대!)

마우스를 아래로 움직임
→ Y = 음수
→ 카메라가 위를 봄 (반대!)
```

**이는 마치 카메라가 거꾸로 작동하는 것처럼 느껴집니다.**

---

### Negate 수정자 적용

```
Mouse Y
└── 수정자: Negate
    └── Order: Y축에만 적용
```

**Negate의 효과:**

```cpp
// 원래 값
마우스 위로 → Y = 1.0 (양수)
마우스 아래로 → Y = -1.0 (음수)

// Negate 적용 후
마우스 위로 → Y = -1.0 (음수로 반전)
마우스 아래로 → Y = 1.0 (양수로 반전)
```

---

### 최종 결과 (Negate 적용 후)

**수평 이동 (X축) - 변화 없음:**

| 마우스 동작 | X 값 | 카메라 동작 |
| ----------- | ---- | ----------- |
| 왼쪽 이동   | 음수 | 왼쪽 회전   |
| 오른쪽 이동 | 양수 | 오른쪽 회전 |

**수직 이동 (Y축) - Negate 적용됨:**

| 마우스 동작 | 기본 Y 값 | Negate 후 | 카메라 동작 |
| ----------- | --------- | --------- | ----------- |
| 위로 이동   | 양수      | **음수**  | 위를 봄     |
| 아래로 이동 | 음수      | **양수**  | 아래를 봄   |

---

### Negate 없이 플레이하면?

**실험: Negate 수정자 제거**

```
매핑 컨텍스트에서 Negate 제거
↓
게임 실행
↓
마우스 위로 → 카메라 아래를 봄 (반대!)
마우스 아래로 → 카메라 위를 봄 (반대!)
```

**결과:**

- 조작감이 매우 어색함
- "역방향 조작" 느낌
- 대부분의 게임에서 사용하지 않는 방식

**그래서 Negate 수정자가 필수입니다.**

**빠른 오른쪽 이동:**

```
LookValue: X=14.235 Y=0.000
LookValue: X=12.874 Y=0.000
LookValue: X=11.523 Y=0.000
```

**빠른 왼쪽 이동:**

```
LookValue: X=-15.342 Y=0.000
LookValue: X=-13.891 Y=0.000
```

**빠른 위 이동:**

```
LookValue: X=0.000 Y=-16.127
LookValue: X=0.000 Y=-14.663
```

**특징:**

- 값이 매우 큼 (10~16 범위)
- 천천히 움직일 때보다 100배 이상 차이

---

### 속도 감지의 목적

**게임 플레이 경험 개선:**

```
천천히 마우스 움직임:
└── 작은 값 (0.07)
    └── 카메라 조금만 회전
        └── 정밀한 조준 가능

빠르게 마우스 움직임:
└── 큰 값 (14.0)
    └── 카메라 많이 회전
        └── 빠른 주변 확인 가능
```

**실용적 예시:**

```cpp
// 저격수가 정밀 조준할 때
마우스 천천히 이동 → 값 = 0.05
→ 카메라가 아주 조금만 회전 (정밀 조준)

// 적 발견 시 빠르게 돌아볼 때
마우스 빠르게 이동 → 값 = 15.0
→ 카메라가 크게 회전 (빠른 반응)
```

```
- 고정된 값 (-1, 0, 1)

- 디지털 입력
```

**마우스 (카메라 입력):**

```

빠르게 이동 → 값 = 14.0 (큰 값)

특징:
- 가변적인 값 (무한대 범위)
- 속도에 비례
- 아날로그 입력
```

## 7. DoLook 함수와 Yaw/Pitch 회전

### DoLook 함수 정의

```cpp
void AThirdPersonCharacter::DoLook(float Yaw, float Pitch)
{
    // Yaw: 좌우 회전 값 (X축 마우스 이동)
    // Pitch: 상하 회전 값 (Y축 마우스 이동)

    // 컨트롤러에 Yaw 입력 추가 (좌우 회전)
    AddControllerYawInput(Yaw);

    // 컨트롤러에 Pitch 입력 추가 (상하 회전)
    AddControllerPitchInput(Pitch);
}
```

**매개변수 이름의 의미:**

| 매개변수 | 원본 값 | 의미      | 제어하는 회전 |
| -------- | ------- | --------- | ------------- |
| Yaw      | X       | 좌우 이동 | Z축 회전      |
| Pitch    | Y       | 상하 이동 | Y축 회전      |

---

### Yaw 회전 이해하기

**Yaw란?**

Z축(수직축)을 중심으로 한 회전입니다.

```
위에서 본 플레이어:

        앞
        ↑
        |
왼쪽 ← 플레이어 → 오른쪽
        |
        ↓
        뒤

Yaw 회전 = 이 평면에서 좌우로 돌아보기
```

**시각화:**

```
     Z축 (위쪽)
      ↑
      |
      ●────→ 플레이어가 보는 방향

이 Z축을 중심으로 회전
→ 좌우로 고개 돌리기
```

---

**AddControllerYawInput 함수:**

```cpp
AddControllerYawInput(Yaw);
```

**작동 과정:**

```cpp
// 마우스를 오른쪽으로 천천히
Yaw = 0.07
AddControllerYawInput(0.07)
→ 컨트롤러가 Z축 중심으로 0.07도 회전
→ 카메라가 오른쪽으로 조금 회전

// 마우스를 왼쪽으로 빠르게
Yaw = -12.5
AddControllerYawInput(-12.5)
→ 컨트롤러가 Z축 중심으로 -12.5도 회전
→ 카메라가 왼쪽으로 크게 회전
```

---

### Pitch 회전 이해하기

**Pitch란?**

Y축(좌우축)을 중심으로 한 회전입니다.

```
옆에서 본 플레이어:

       위
       ↑
       |
       ●────→ 플레이어가 보는 방향
       |
       ↓
       아래

Pitch 회전 = 위아래로 고개 들고 숙이기
```

**시각화:**

```
    플레이어 옆모습:

    ●───→  수평으로 봄 (Pitch = 0)

    ●
     ╲
      ↘  위를 봄 (Pitch < 0)

      ↗
     ╱
    ●    아래를 봄 (Pitch > 0)
```

---

**AddControllerPitchInput 함수:**

```cpp
AddControllerPitchInput(Pitch);
```

**작동 과정:**

```cpp
// 마우스를 위로 천천히 (Negate 적용됨)
Pitch = -0.07
AddControllerPitchInput(-0.07)
→ 컨트롤러가 Y축 중심으로 -0.07도 회전
→ 카메라가 위를 조금 봄

// 마우스를 아래로 빠르게 (Negate 적용됨)
Pitch = 11.3
AddControllerPitchInput(11.3)
→ 컨트롤러가 Y축 중심으로 11.3도 회전
→ 카메라가 아래를 많이 봄
```

---

### Yaw와 Pitch 동시 적용

**대각선 마우스 이동:**

```cpp
// 마우스를 오른쪽 위로 대각선 이동
Yaw = 5.2 (오른쪽)
Pitch = -4.8 (위)

AddControllerYawInput(5.2)    // 오른쪽 회전
AddControllerPitchInput(-4.8) // 위를 봄

→ 카메라가 오른쪽 위 대각선 방향을 봄
```

---

### 회전 제한 (Pitch Clamp)

**Pitch에는 제한이 있습니다:**

```
일반적인 Pitch 제한:
├── 최소: -89° (거의 수직 위)
└── 최대: +89° (거의 수직 아래)

→ 완전히 뒤집어지는 것 방지
```

**왜 제한이 필요한가:**

```
제한 없으면:
마우스를 계속 위로 → Pitch -180°
→ 카메라가 뒤집어짐 (짐벌 락 현상)

제한 있으면:
마우스를 계속 위로 → Pitch -89°에서 멈춤
→ 자연스러운 시야 유지
```

---

### 전체 흐름 정리

**마우스 입력부터 카메라 회전까지:**

```
1. 플레이어가 마우스를 오른쪽 위로 빠르게 이동
   ↓
2. 마우스 시스템이 이동량 감지
   └─ 수평 이동: 빠름 → 큰 값
   └─ 수직 이동: 빠름 → 큰 값
      ↓
3. 입력 시스템 처리
   └─ Mouse X → X = 12.5 (양수, 큰 값)
   └─ Mouse Y → Y = 10.3 (양수)
      └─ Negate 적용 → Y = -10.3 (음수)
         ↓
4. Look 함수 호출
   └─ LookAxisVector = (12.5, -10.3)
      ↓
5. DoLook(12.5, -10.3) 호출
   └─ Yaw = 12.5, Pitch = -10.3
      ↓
6. 회전 입력 추가
   └─ AddControllerYawInput(12.5)
      └─ Z축 중심으로 12.5도 오른쪽 회전
   └─ AddControllerPitchInput(-10.3)
      └─ Y축 중심으로 -10.3도 위를 봄
         ↓
7. 최종 결과
   └─ 카메라가 오른쪽 위 대각선 방향으로 크게 회전
```

## 💡 핵심 요약

### 입력 시스템

- **MouseLook 액션** : 별도의 매핑 컨텍스트 사용
- **FVector2D** : X(좌우), Y(상하) 마우스 이동량
- **Mouse X** : 자동으로 Vector2D.X에 할당
- **Mouse Y** : 자동으로 Vector2D.Y에 할당 + **Negate 적용**

### Negate 수정자

- **목적** : Y축 입력을 반전시켜 자연스러운 카메라 조작감 제공
- **효과** : 마우스 위 → 카메라 위, 마우스 아래 → 카메라 아래
- **적용** : Y축에만 적용, X축은 그대로 유지

### 마우스 입력 특성

- **속도 감지** : 마우스 이동 속도에 비례하는 값 생성
- **천천히** : 0.05~0.1 범위의 작은 값 → 정밀한 조작
- **빠르게** : 10~20 범위의 큰 값 → 빠른 회전
- **키보드와 차이** : 키보드는 고정값(-1, 0, 1), 마우스는 가변값

### 회전 처리

- **Yaw** : Z축 중심 좌우 회전 (고개 돌리기)
- **Pitch** : Y축 중심 상하 회전 (고개 들고 숙이기)
- **AddControllerYawInput** : 좌우 회전 추가
- **AddControllerPitchInput** : 상하 회전 추가 (제한 있음)

### 전체 구조

```
마우스 이동 → 속도 감지 → Vector2D 생성
→ Negate(Y만) → Look 함수 → DoLook 함수
→ Yaw/Pitch 입력 → 카메라 회전
```

## 3. 캐릭터 회전 방식 변경하기

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380641/notion-blog/_/_/_5_C_/_5_Shooter_Sam_-_1/image_6.png)

### 현재 문제점 파악

**기본 3인칭 템플릿 동작:**

```
A 키 누름 → 캐릭터가 왼쪽 회전 + 왼쪽 이동
D 키 누름 → 캐릭터가 오른쪽 회전 + 오른쪽 이동
S 키 누름 → 캐릭터가 뒤로 회전 + 뒤로 이동

문제:
- 캐릭터가 항상 이동 방향을 바라봄
- 뒤로 가면 카메라 쪽을 바라봄
```

**슈팅 게임에서 원하는 동작:**

```
A 키 누름 → 캐릭터는 정면 보면서 왼쪽 스트레이프
D 키 누름 → 캐릭터는 정면 보면서 오른쪽 스트레이프
S 키 누름 → 캐릭터는 정면 보면서 뒤로 이동

목표:
- 캐릭터가 항상 카메라(조준) 방향을 바라봄
- 총을 들고 있을 때 자연스러운 움직임
```

---

### Orient Rotation to Movement 옵션

**BP_ShooterCharacter 열기:**

```
1. BP_ShooterCharacter 더블클릭
   ↓
2. Components 패널에서 "CharacterMovement" 선택
   ↓
3. Details 패널에서 아래로 스크롤
   ↓
4. "Character Movement (Rotation Settings)" 섹션 찾기
```

---

**Orient Rotation to Movement란?**

```cpp
// 이 옵션이 체크되어 있으면
OrientRotationToMovement = true;

// 캐릭터의 회전 방향 = 이동 방향
if (moving_left) {
    character_rotation = left;  // 왼쪽을 바라봄
}
if (moving_right) {
    character_rotation = right; // 오른쪽을 바라봄
}
```

**비활성화:**

```
Orient Rotation to Movement 체크 해제
  ↓
컴파일 & 저장
  ↓
플레이 테스트
```

---

**결과:**

```
A 키 누름:
- 이전: 캐릭터가 왼쪽으로 회전
- 현재: 캐릭터가 같은 방향 보면서 왼쪽 스트레이프 ✓

S 키 누름:
- 이전: 캐릭터가 뒤를 돌아봄 (카메라 쪽)
- 현재: 캐릭터가 앞을 보면서 뒤로 이동 ✓
```

**주의:**

```
현재 애니메이션:
- 걷기 전진 애니메이션만 사용
- 옆/뒤로 이동 시 부자연스러워 보임

나중에:
- Paragon 애니메이션으로 교체
- 모든 방향 이동 애니메이션 포함
- 자연스러운 움직임
```

---

### Use Controller Desired Rotation 옵션

**두 번째 문제:**

```
현재 상태:
마우스로 카메라 회전
  ↓
캐릭터는 가만히 서 있음
  ↓
조준선과 캐릭터가 다른 방향

슈팅 게임 문제:
- 총을 쏘려면 캐릭터가 카메라 방향을 바라봐야 함
- 조준과 발사 방향이 일치해야 함
```

---

**Use Controller Desired Rotation 활성화:**

```
Character Movement (Rotation Settings):
  ↓
"Use Controller Desired Rotation" 체크 ✓
  ↓
컴파일 & 저장
```

**옵션 의미:**

```cpp
UseControllerDesiredRotation = true;

// 캐릭터 회전 = 컨트롤러(카메라) 회전
character_yaw = controller_yaw;

// 마우스로 카메라 회전하면
// 캐릭터도 같은 방향으로 회전
```

---

**결과:**

```
마우스 오른쪽 이동:
- 카메라 오른쪽 회전
- 캐릭터도 오른쪽 회전 ✓

마우스 왼쪽 이동:
- 카메라 왼쪽 회전
- 캐릭터도 왼쪽 회전 ✓

최종 동작:
- 항상 카메라가 바라보는 방향을 캐릭터도 바라봄
- 조준과 발사 방향 일치
```

---

### 최종 회전 설정 정리

**Character Movement 설정:**

| 옵션                            | 상태     | 효과                     |
| ------------------------------- | -------- | ------------------------ |
| Orient Rotation to Movement     | ☐ 비활성 | 이동 방향으로 회전 안 함 |
| Use Controller Desired Rotation | ☑ 활성  | 카메라 방향으로 회전     |

**종합 동작:**

```
WASD 이동:
- 캐릭터 방향 유지
- 모든 방향 스트레이프 가능

마우스 회전:
- 카메라와 캐릭터 동시 회전
- 조준 방향 = 캐릭터 정면
```

## 5. 카메라 위치 조정하기

### 슈팅 게임 카메라의 목표

**현재 카메라:**

```
위치: 캐릭터 정중앙 뒤
거리: 너무 멀리
각도: 중앙

문제:
- 조준선이 화면 중앙
- 캐릭터가 화면을 너무 많이 가림
```

**목표 카메라:**

```
위치: 오른쪽 어깨 너머 (over-the-shoulder)
거리: 더 가까이
각도: 총신 너머를 볼 수 있도록

장점:
- 오른손 무기 위치와 일치
- 조준과 발사 방향 명확
- 전방 시야 확보
```

---

### 스프링 암 컴포넌트 이해

**Spring Arm이란?**

카메라를 캐릭터에서 일정 거리 떨어뜨려주는 막대기 같은 컴포넌트입니다.

```
구조:
캐릭터 ●────────────● 카메라
       └ Spring Arm ┘

기능:
- 카메라를 멀리 배치
- 벽과 충돌 시 자동으로 가까워짐
- 부드러운 카메라 움직임
```

---

### 도전 과제

카메라를 오른쪽 어깨 위치로 조정하세요.

---

### 카메라 위치 조정 - 해답

**1단계: Spring Arm 높이 조정**

```
Components 패널:
  ↓
SpringArm 선택
  ↓
Details → Transform
  ↓
Location 섹션
```

**Z축 (높이) 올리기:**

```
Location:
├── X: 0.0 (전후)
├── Y: 0.0 (좌우)
└── Z: 70.0 (위로 70cm) ← 변경

효과:
- 스프링 암의 시작점이 캐릭터 어깨 높이로
- 카메라도 함께 올라감
```

---

**2단계: 오른쪽으로 이동**

```
Location:
├── X: 0.0
├── Y: 60.0 (오른쪽으로 60cm) ← 추가 변경
└── Z: 70.0

효과:
- 카메라가 오른쪽 어깨 위치로
```

---

**3단계: 카메라 거리 조정**

```
Details 패널:
  ↓
Camera Settings 섹션
  ↓
Target Arm Length
```

**거리 줄이기:**

```
Target Arm Length: 250.0 (기본 300에서 감소)

효과:
- 카메라가 캐릭터에 더 가까워짐
- 3인칭 슈팅 게임 느낌
```

**시각화:**

```
기본 설정 (300):
캐릭터 ●──────────────────● 카메라 (너무 멀리)

조정 후 (250):
캐릭터 ●────────────● 카메라 (적당한 거리)
```

---

**4단계: Socket Offset 사용**

```
Details 패널:
  ↓
Camera Settings
  ↓
Socket Offset (소켓 오프셋)
```

**Y축 오프셋 추가:**

```
Socket Offset:
├── X: 0.0
├── Y: 20.0 (오른쪽으로 20 추가) ← 설정
└── Z: 0.0

효과:
- 카메라가 조금 더 오른쪽으로
- 미세 조정 가능
```

---

### Location vs Socket Offset 차이

**Location (위치):**

```
Spring Arm의 시작점 이동
- 캐릭터 기준 절대 위치
- X, Y, Z 모두 자유롭게 설정
```

**Socket Offset (소켓 오프셋):**

```
Spring Arm의 끝점(카메라 부착점) 오프셋
- Spring Arm 끝에서의 상대 위치
- 미세 조정용
```

**시각화:**

```
Location으로 조정:
캐릭터 ●
         ╲
          ╲ (Spring Arm 시작점 이동)
           ●────────────● 카메라

Socket Offset으로 조정:
캐릭터 ●──────────────● (원래 카메라 위치)
                        ↓
                        ● (오프셋 적용 위치)
```

---

### 최종 Spring Arm 설정

```
Transform → Location:
├── X: 0.0
├── Y: 60.0 (오른쪽 어깨)
└── Z: 70.0 (어깨 높이)

Camera Settings:
├── Target Arm Length: 250.0 (거리)
└── Socket Offset:
    ├── X: 0.0
    ├── Y: 20.0 (미세 조정)
    └── Z: 0.0
```

**게임 플레이 테스트:**

```
결과:
- 캐릭터가 화면 왼쪽에 배치
- 오른쪽 시야 확보
- 전방 시야 넓음
- 3인칭 슈팅 게임 카메라 완성 ✓
```

## 6. 스프링 암의 Pawn Control Rotation

### 회전 설정 시도와 문제

**직접 회전 시도:**

```
Spring Arm 선택
  ↓
Transform → Rotation
  ↓
Y축 회전 시도 (예: 10도)
  ↓
결과: 아무 변화 없음 ✗
```

**왜 회전이 안 되나?**

---

### Use Pawn Control Rotation 옵션

**Spring Arm의 특별한 옵션:**

```
Details 패널:
  ↓
Camera Settings
  ↓
Use Pawn Control Rotation ← 체크됨
```

**이 옵션의 의미:**

```cpp
UsePawnControlRotation = true;

// Spring Arm의 회전 = Pawn의 컨트롤 회전
SpringArmRotation = ControllerRotation;

// 직접 설정한 Rotation 값은 무시됨
// 대신 플레이어의 마우스 입력이 회전을 제어
```

---

### 옵션 비활성화 실험

**체크 해제하면:**

```
Use Pawn Control Rotation: ☐ 비활성

결과:
- Transform → Rotation 값 적용됨
- 수동으로 회전 설정 가능
```

**하지만 문제 발생:**

```
마우스로 카메라 회전 시도
  ↓
카메라가 움직이지 않음
  ↓
이유: 컨트롤 회전과 연결 끊어짐
```

---

### 왜 Use Pawn Control Rotation을 사용하나?

**장점:**

```
1. 마우스 입력과 자동 연동
   - AddControllerYawInput
   - AddControllerPitchInput
   ↓
   자동으로 Spring Arm 회전

2. 캐릭터 회전과 동기화
   - Use Controller Desired Rotation
   - 캐릭터와 카메라가 같은 방향

3. 부드러운 카메라 움직임
```

---

### Location vs Rotation 사용 규칙

**Spring Arm 설정 시:**

```
Use Pawn Control Rotation = true (기본값, 유지)
  ↓
위치 조정:
- Location 사용 ✓
- Socket Offset 사용 ✓

회전 조정:
- Transform → Rotation 사용 ✗ (무시됨)
- Socket Offset으로 미세 조정만 가능
```

---

### 완전한 카메라 시스템 이해

**전체 흐름:**

```
1. 마우스 입력
   ↓
2. PlayerController에서 처리
   ↓
3. AddControllerYawInput/PitchInput
   ↓
4. Controller Rotation 업데이트
   ↓
5. Spring Arm이 Controller Rotation 따라감
   (Use Pawn Control Rotation = true)
   ↓
6. Camera가 Spring Arm 끝에 부착
   (Location + Socket Offset 적용)
   ↓
7. Character도 Controller Rotation 따라감
   (Use Controller Desired Rotation = true)
```

```
BP_ShooterCharacter:
├── CapsuleComponent (루트)

│       └── Camera
```

| Use Pawn Control Rotation | true | 마우스 회전 연동 |
