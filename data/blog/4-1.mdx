## 1. 새로운 유니티 프로젝트 생성하기

- **Unity Hub 실행 → 새 프로젝트(Create Project)** 클릭.
- **에디터 버전**: **Unity 6** 선택.
- **템플릿**: **Universal 3D(URP)** → 최신 유니버설 렌더 파이프라인(URP) 설정 포함.
- **프로젝트 이름**: 원하는 이름(예: _Galaxy Strike_).
- **위치(Location)**: 하드 드라이브의 적절한 경로 선택.
- **Unity Cloud 연결**: 선택 해제 (이번 강의에서는 불필요).
- 모든 설정 완료 후 **Create Project** 버튼 클릭 → 에디터가 실행되며 빈 3D 씬 생성.

---

## 2. 에디터 환경 설정 및 기본 정리

- **URP Readme 에셋**: 필요 없으므로 삭제 가능.
- **Assets 폴더 정리**:
  - `input` 폴더 생성 → 입력 시스템의 기본 액션 맵 저장용.
  - 이번 강의에서는 직접 액션 맵을 만들 예정 → 정리를 위해 `input` 폴더에 임시 저장.
- **계층 구조(Hierarchy) 패널 위치 조정**:
  - 일부 사용자는 **왼쪽 상단**을 선호.
  - 강의에서는 **왼쪽 하단** 배치 → 장면(Scene) 뷰와 게임(Game) 뷰를 나란히 유지하며 공간 확보.
- **AI Navigation 팝업**: 현재 필요 없으므로 닫거나 오른쪽 상단에 고정. 나중에 필요할 때 끌어내 사용.

## 3. 지형(Terrain) 생성 및 이동 속도 조정

- **지형 생성**:
  - Hierarchy → 우클릭 → **3D Object → Terrain** 선택 → 거대한 흰색 지형 오브젝트 생성.
  - 지형 선택 후 **F 키** → 카메라 초점 이동.
- **카메라 이동 속도 조정**:
  - Scene 뷰 우측 상단 **카메라 속도 드롭다운** 클릭.
  - **Camera Speed**: 최대값 2로 올림.
  - **Min Value**: 0.001 → **0.2** 로 변경 → 너무 느린 이동 방지.
  - **Camera Acceleration**: 체크 해제 → 일정한 이동 속도 유지.

## 4. 지형 도구 살펴보기: 올리기·내리기와 브러시 활용

- **Inspector** → Terrain 선택 시 도구 아이콘 표시.
- **Paint Terrain(지형 색칠)** → 드롭다운에서 **Raise or Lower Terrain(지형 올리기/내리기)** 선택.
- **사용 방법**:
  - **왼쪽 클릭 + 드래그** → 지형을 올림(산 생성).
  - **Shift + 왼쪽 클릭** → 지형을 내림.
- **브러시 크기 조절**: 슬라이더 사용 → 넓은 산/좁은 산 만들기 가능.
- **Opacity(불투명도)**: 높이면 더 빠르게 올리거나 내림.
- **브러시 모양**:
  - 포토샵의 하드 브러시처럼 다양한 패턴 존재.
  - 다른 브러시를 시험해 다양한 텍스처 느낌과 높이 변화를 연습.

## 5. 지형 크기 및 해상도 조정

- 기본 크기: **1000 x 1000** → 너무 커서 다루기 어려움.
- **Inspector → Terrain Settings(지형 설정)** → **Mesh Resolution** 항목 아래:
  - **Width & Length**: **600 x 600** 으로 변경 → 편리한 크기로 축소.
- 다시 **F 키**로 포커스 맞추고 마우스 휠로 빠르게 스크롤 → 편리하게 지형 탐색.

## 6. 높이 설정(Set Height)과 평탄화(Flatten) 기능

- **Set Height 도구**:
  - **Height 값 = 0** → 클릭하면 지형이 y축 0으로 평평해짐.
  - **Height 값 = 100** → 지형을 y축 100까지 올림.
  - 음수 값(-100)은 불가능 → Terrain 시스템이 지형을 오브젝트 하단보다 아래로 이동시키지 않음.
- **우회 방법(트릭)**:
  1. Set Height = 100으로 지형 올림. ( 이건 필요 없는거 같은데 )
  2. **Flatten Tile(타일 평탄화)** 클릭 → 지형이 전체적으로 100 유닛 위로.
  3. **Transform 컴포넌트**의 **Position Y** 값을 -100으로 변경 → 결과적으로 지형이 월드 좌표 y=0에 위치.
  4. 필요 없어진 큐브 참조 오브젝트 삭제.
- 이 방법을 통해 **골짜기나 도랑**처럼 음수 공간을 시뮬레이션 가능.

## 7. 실습 도전 과제와 프로토타입 환경 만들기

- **연습**:
  - 600x600 지형 생성.
  - 여러 브러시 사용 → 산/골짜기 만들기.
  - Shift를 사용해 y축을 낮추고 다시 평탄화.
- **레벨 프로토타입 구성**:
  - **가운데에 큰 산** 추가 → 플레이어의 주 시각 포인트.
  - **장면 가장자리**를 따라 산맥 생성 → “사물이 실제보다 커 보이는” 착시 효과 제공.
  - **작은 골짜기 및 텍스처링** 추가 → 씬이 너무 평평해 보이지 않도록.
- **WASD + 마우스 오른쪽**으로 장면 뷰 탐색 → 우주선을 날리는 듯한 느낌으로 지형 테스트.
- 이 단계에서는 **레벨 디자인의 세부 사항**보다 **기본 메커니즘 테스트용 환경**에 초점.

## 8. 지형 에셋 정리 및 마무리

- 새로운 Terrain 오브젝트 생성 시 **Assets** 디렉토리에 Terrain 데이터 에셋 자동 생성.
- 깔끔한 프로젝트 유지를 위해 **Assets/Terrain** 폴더 생성 → Terrain 에셋 이동.
- 이렇게 정리하면 나중에 여러 지형을 추가할 때 관리가 쉬움.
- 이번 강의 핵심:
  - URP 프로젝트 생성 → Terrain 생성 및 탐색
  - 카메라 속도 및 브러시 조절
  - Raise/Lower, Set Height, Flatten 사용법
  - 작은 트릭으로 음수 공간 구현
  - 간단한 산악 지형을 만들어 프로토타입 환경 마련

✅ **정리 포인트**

- **Terrain Tools**는 월드 제작의 핵심 기능 → 산, 골짜기, 언덕 등 레벨 지형을 빠르게 프로토타입.
- **카메라 속도/브러시 크기/불투명도** 조정은 효율적인 지형 제작의 필수 팁.
- **Set Height & Flatten** 조합은 높이 제어와 음수 공간 구현에 유용.
- **계층 구조와 에셋 정리**는 프로젝트 규모가 커질수록 중요.
- 이 강의 내용만으로도 기본적인 지형 편집과 환경 프로토타입을 자유롭게 실습할 수 있음.

## 1. Terrain Tools 패키지 개요와 설치

- **Terrain Tools**: 유니티 기본 Terrain 시스템의 기능을 확장하는 공식 패키지.
  - **기본 제공 도구**: 높이 올리기(Raise), 높이 설정(Set Height), 평탄화(Flatten), 텍스처 페인팅(Paint Texture).
  - **추가 제공 기능**: 지형을 **밀기(Push)**, **번지기(Smear)**, **침식(Erosion)**, **비틀기(Twist)** 등.
  - 지형 제작 시 보다 자연스러운 산악 지형, 계곡, 풍화 효과 등을 쉽게 구현 가능.
- **설치 방법**:
  1. 메뉴 **`Window → Package Manager`** 열기.
  2. 좌측 상단에서 **Unity Registry** 선택 → 검색창에 `terrain` 입력.
  3. **Terrain Tools** 선택 후 **Install** 클릭.
  4. 설치 완료 후 **Console** 창에서 오류 대신 **경고(Warnings)** 만 표시될 수 있음 → 경고는 무시하거나 지워도 무방.

## 2. 추가 지형 타일 생성 및 연결

- **Create Neighbor Terrains (인접 타일 생성)**
  - 지형을 선택한 상태에서 **W** 키 → 생성 UI 표시.
  - 네 방향(위/아래/좌/우) 중 원하는 방향 클릭해 타일 추가.
  - **Fill Heightmap Using Neighbor** 옵션을 **True**로 설정해야 기존 타일과 부드럽게 연결됨.
    - 꺼져 있으면 새 타일은 평평한 0 높이로 생성 → 불연속적인 경계 발생.
- **높이 평탄화(Flatten)**
  - 새 타일의 높이가 기존보다 낮거나 높으면 **Height** 값(예: `50`, `100`) 입력 후 **Flatten Tile** 클릭 → 원하는 높이로 맞춤.
  - **Flatten All** 은 모든 연결된 타일을 한 번에 평탄화 → 원치 않으면 Ctrl+Z로 취소 가능.

## 3. Terrain Tools의 추가 조형/침식 기능

- **조형(Deform)**: 기본 Raise/Lower Height 외에 비틀기(Twist), 밀기(Push) 등 포함.
  - _예: Twist_ → 클릭 후 드래그하면 지형을 꼬아 독특한 모양 생성.
- **침식(Erosion)** → `Erosion → Wind` 사용:
  - **Wind Erosion** 은 바람이 지형을 깎아내린 듯한 효과.
  - 브러시를 한 방향으로 이동시키면 실제 바람이 그 방향으로 지형을 침식한 느낌을 줌.

---

## 4. 단축키 변경 및 브러시 설정

- **단축키 변경**
  - Terrain Tools 설치 전: 높이 낮추기 = **Shift**.
  - 설치 후: 높이 낮추기 = **Control(Ctrl)** 로 변경됨.
- **브러시 제어 단축키**
  - **A**: 브러시 강도(Strength) 조절.
  - **S**: 브러시 크기(Size) 조절.
  - **D**: 브러시 회전(Rotation) 변경.
    - 단순 Raise/Lower에는 영향 없음.
    - `Erosion → Wind` 사용 시, D로 바람 방향 회전 가능.
- **브러시 옵션 패널**
  - **Strength**: 조형 강도 (값이 높을수록 빠르고 강하게 변형).
  - **Size**: 브러시 반경.
  - **Rotation**: 브러시의 회전 방향.

---

## 5. 지형 구멍(Paint Holes)과 한계

- **Paint Holes** 기능: 지형에 **구멍**을 그려서 메쉬를 직접적으로 뚫을 수 있음.
  - 예: 동굴 입구처럼 보이게 만들 수 있지만, 사실상 단순히 아래가 뚫린 상태.
  - 구멍 안쪽에 모델이 없으면 완전한 동굴처럼 보이지 않음.
  - **해결 방법**: 별도의 3D 오브젝트(예: 터널 모델)를 장면에 추가하여 동굴이나 다리를 구현.
- 유니티 에셋 스토어: 무료·유료 플러그인 사용 시 보다 정교한 지형/동굴 제작 가능.

---

## 6. 레일 슈터용 지형 계획 세우기 (실습 도전)

- **실습 과제**:
  1. 첫 번째 지형 타일 옆에 **두 번째 타일** 추가.
  2. Terrain Tools를 사용해 레일 슈터의 **플레이어 경로**를 계획하고 지형 조형.
  3. 산악, 골짜기, 개방된 평지 등을 섞어 흥미로운 비행 경로 설계.
- **강의 예시 계획**:
  - 첫 번째 타일: 플레이어 시작점.
    - 중앙: 산악 화산 배치, 그 안쪽을 파서 **우주선 이륙 지점** 확보.
  - 두 번째 타일: 플레이어가 **지그재그**로 비행할 수 있는 골짜기 범위.
  - 경로:
    - 출발 → 주변 산맥을 우회 → 큰 개방 지대를 지나 → 왼쪽 급선회 → 두 번째 타일로 진입 → 지그재그 비행 → 보스전 후 멀리 비행.

## 7. 정리 및 관리 팁

- **Hierarchy 정리**
  - Ctrl+Shift+N → **빈 게임 오브젝트 생성** (예: 이름 `Terrain`).
  - 두 개의 Terrain 오브젝트를 이 빈 오브젝트 아래로 드래그 → 깔끔한 계층 구조 유지.
- **시간 관리**
  - 타일 제작은 빠르게 하거나, 더 섬세하게 조형해도 됨.
  - 이후 메커니즘(적, 아이템, 보스 등) 추가 시 지형을 다시 수정할 가능성 많음 → 완벽에 집착하지 않아도 됨.
- **탐색 팁**
  - Scene 뷰에서 WASD + 마우스 오른쪽 클릭으로 탐색.
  - Q/E: 높낮이 이동.
  - 우주선 시점으로 직접 비행하듯 장면 탐색 → 경로 검증에 유용.

## 1. Terrain Tools와 텍스처 개념 이해

- **Terrain Tools**: Unity가 제공하는 공식 확장 도구로, 기본 터레인(Terrain) 기능보다 더 다양한 브러시·텍스처 옵션을 제공.
- **텍스처 페인트(Paint Texture)**: 지형에 색상과 질감을 입혀 환경에 생동감을 주는 과정.
- **텍스처의 구성 요소**
  - **디퓨즈(Diffuse)**: 표면의 기본 색상과 무늬를 표현하는 이미지.
  - **노멀 맵(Normal Map)**: 조명과 그림자 효과를 시뮬레이션하여 입체적인 질감을 부여.
  - **마스크 맵(Mask Map)**: 금속성(Metallic), 앰비언트 오클루전(AO), 부드러움(Smoothness) 등의 특성을 채널(R/G/B/A)별로 저장해 텍스처 변화를 제어.

## 2. 터레인 텍스처 에셋 다운로드 및 임포트

1. **Package Manager 열기** → Unity 레지스트리에서 **Terrain Tools** 검색.
2. **에셋 스토어(Asset Store) 연결** → **Download Asset Samples** 버튼 클릭.
   - Unity 계정이 로그인되어 있어야 함.
3. **Terrain Sample Asset Pack** 다운로드.
   - 여러 텍스처, 덤불, 풀 등이 포함.
   - HDRP용 폴더도 포함되어 있으나 우리는 **URP**를 사용할 예정 → 필요 없지만 함께 설치 권장.
4. **Import(가져오기)** 클릭 → 종속성 설치 경고가 떠도 계속 진행.

## 4. 텍스처 속성: 디퓨즈·노멀 맵·마스크 맵

| 항목          | 설명                                                                   | 예시 활용                                   |
| ------------- | ---------------------------------------------------------------------- | ------------------------------------------- |
| **디퓨즈**    | 표면의 실제 색상/무늬를 표현하는 이미지 (TIFF 또는 PNG 유사).          | 초록 잔디, 갈색 흙, 회색 바위의 기본 이미지 |
| **노멀 맵**   | 빛 반사 방향과 표면의 요철을 시뮬레이션 → 평면을 입체적으로 보이게 함. | 바위 표면의 울퉁불퉁함, 모래의 입자 느낌    |
| **마스크 맵** | RGB 채널에 금속성/부드러움/앰비언트 오클루전 정보를 저장.              | 풀에 금속성 효과를 주거나 빛 반사 강도 조절 |

> 💡 높이 맵(Height Map) 개념: Terrain의 실제 높낮이를 결정하는 그레이스케일 이미지. Terrain Settings에서 내보내기 가능하며, 흰색은 높은 곳, 검은색은 낮은 곳을 의미. 이번 강의에서는 참고용으로만 사용.

## 5. 타일링(Tiling)과 레이어 팔레트 관리

- **타일링(Tiling)**: 텍스처의 반복 밀도를 설정 → 너무 촘촘하면 인공적, 너무 적으면 흐릿함.
  - 권장 값: `30 × 30`.
- **레이어 팔레트(Layer Palette)**
  - 여러 Terrain 간 동일한 레이어 구성을 공유 가능.
  - **Save As** → `Default Layer Palette` 저장.
  - 다른 Terrain 선택 후 **Load** → 동일한 다섯 개 텍스처를 불러옴.
  - 새로운 레이어를 추가하면 팔레트에도 반영되어 다른 Terrain에서도 동일하게 유지.

## 1. 타임라인(Timeline) 개념과 역할

- **타임라인** : Unity의 _Sequencing_ 도구. 키프레임 단위로 오브젝트의 이동, 회전, 이벤트를 애니메이션처럼 제어.
- 게임 시네마틱 또는 이벤트 연출에 활용.
- 프레임(Frame) 또는 초(Seconds) 단위 표시 가능 → 초 단위 설정이 제어하기 편리.
- 마스터 타임라인(Master Timeline) 아래에 여러 트랙(Track)과 오브젝트를 연결하여 전체 장면을 조정.

## 2. 에셋 임포트 및 우주선 모델 준비

- **리소스 탭** → `GameDevTVSpaceships.unitypackage` 다운로드.
- `.unitypackage`를 프로젝트 창에 드래그 앤 드롭 → 우주선 모델, 재질, 텍스처 임포트.
- `Models` 폴더 → 7~8대의 우주선 포함.
  - **파란/노란 우주선** → 아군/플레이어용.
  - **빨간/흰색 우주선** → 적군용.
- 초보자라면 강의에서 사용한 **노란 전투기**를 그대로 따라 사용 권장.

## 3. 플레이어 릭(Player Rig)과 계층 구조 설정

- **빈 게임 오브젝트 생성 (Ctrl+Shift+N)** → 이름: `Player Rig`.
  - 플레이어 우주선과 카메라를 묶어 움직이는 부모 역할.
- `Player Rig` 내부에 또 다른 **빈 오브젝트(Model)** 생성.
  - 실제 모델(우주선 메쉬)은 `Model` 하위에 배치.
  - **스케일** : 모델의 **Scale = (1,1,1)** 유지 → 부모 오브젝트(`Player Rig`) 스케일만 변경.
  - 루트 오브젝트에 모델을 바로 배치하지 않는 이유 → 스케일 및 회전 오류 방지.
- 적절한 크기 : 부모 스케일을 **2**로 조정 → `Uniform Scale`(비율 고정) 활성화 후 한 축만 수정.

## 7. 위치·회전 애니메이션 실습과 수정 방법

1. **0초 → 1초**
   - 플레이어 릭을 살짝 **위로 이동** → 부드러운 이륙 느낌.
2. **1초 → 3초**
   - **앞으로 이동** + 필요 시 **약간 위로** → 비행 경로 생성.
3. **3초 → 5초**
   - **위치 + 회전** 결합 → 우주선이 오른쪽으로 기울며 방향 전환.
   - **장면 뷰 정렬(Align With View)** :
     - 플레이어 릭 선택 → **Ctrl+Shift+F** → 장면 뷰 카메라 위치와 정렬.
   - 회전 키가 잘못된 프레임에 기록된 경우:
     - **Timeline → Animation Track 더블 클릭** → 애니메이션 창에서 키프레임 직접 삭제 또는 수정.
     - 초기 회전 값을 복사 → 적절한 프레임(예: 3초/180프레임)에 붙여넣기.

- **재생 테스트** : 부드럽게 이륙 → 3초 지점부터 회전 시작 → 5초까지 자연스러운 전환 확인.

## 1. 모델과 메시 초기화

- **문제 상황**: 모델 내부 메시(mesh)가 위치 변환에서 완전히 초기화되지 않음 → 예상치 못한 위치 오류 발생 가능.
- **해결 방법**:
  - 모델과 메시의 위치(Position)를 **(0, 0, 0)** 으로 리셋.
  - 초기화 후, 월드 좌표계(World Space) 기준에서 올바르게 배치되었는지 확인.
  - 초기화되지 않은 메시가 있으면 애니메이션 중 불필요한 이동·회전이 발생할 수 있으므로 반드시 확인.

---

## 2. Master Timeline 수정 및 재생 확인

- **Master Timeline** 에서 **Player Rig** 의 위치를 약간 조정.
- 재생(Play) 버튼을 클릭하여 모든 요소가 정상적으로 보이는지 확인.
- 추가 리소스 및 효과를 적용하기 전에, **약 10~15초의 타임라인 구간**을 확보하여 애니메이션 작업 공간을 준비.

---

## 3. Dopesheet와 Curves 개념 및 활용

### ◾ Dopesheet

- **키프레임(Keyframe)** 의 시간 배치를 한눈에 보고 쉽게 이동/복사/삭제할 수 있는 패널.
- 빠른 스크럽(scrub) → 애니메이션의 타이밍과 흐름을 손쉽게 조정.

### ◾ Curves (곡선)

- 키프레임 사이의 **보간(Interpolation)** 을 시각적으로 곡선으로 표현.
- 회전(특히 Z축)이나 위치 변화의 부드러움을 조정하는 데 효과적.
- **F 키**: 선택한 곡선을 화면에 맞게 확대/축소 → 모든 키프레임을 한눈에 보기.
- 곡선 핸들(Bezier Handles)을 조정 → 애니메이션의 가속, 감속, 스무딩을 세밀하게 제어.

## 4. 회전 키프레임 제어 방법

- **Z축 회전 예시**:
  1. 녹화(Record) 버튼 활성화.
  2. 회전시키고 싶은 시점에서 Z축 값을 약간 변경.
  3. Curves 탭에서 곡선을 확인 → 핸들을 드래그해 부드러운 움직임 또는 극적인 효과 연출.
  4. 회전 키프레임 복사(Ctrl+C) 및 붙여넣기(Ctrl+V) → 특정 구간에서 같은 회전 값을 유지 가능.
  5. 이렇게 하면 우주선이 **Tokyo Drift** 처럼 미끄러지지 않고 자연스러운 비행 경로를 유지.

---

## 5. 키프레임 속도 조절 및 배치

- 속도가 너무 빠르거나 느리면:
  - Dopesheet에서 **모든 키프레임 선택 → 좌우로 드래그**.
  - 오른쪽으로 이동 → **느려짐**.
  - 왼쪽으로 압축 → **빠르게 재생**.
- **특정 속도만 변경하고 싶을 때**: 위치(Position)나 회전(Rotation) 키프레임만 선택 가능.
- 이 방법으로 타이밍 조절 시 전체 애니메이션의 흐름을 쉽게 미세 조정.

---

### ✅ **핵심 개념 요약**

- **도프시트(Dopesheet)**: 키프레임의 타이밍과 순서를 손쉽게 관리하는 도구.
- **애니메이션 곡선(Curves)**: 속도 변화와 부드러움을 시각적으로 조정하여 자연스러운 움직임 구현.
- **회전 키 복사/붙여넣기**: 불필요한 미끄러짐 방지 및 일관된 방향 유지.
- **속도 조절**: 도프시트에서 키프레임을 이동해 전체 또는 부분 속도를 간단히 변경.
- **적 비행 경로 확보**: 이후 강의에서 사용할 공간을 미리 계획.

이 모든 과정을 통해, **플레이어 우주선의 비행 경로와 회전을 정교하게 제어**하여 보다 **현실적이고 부드러운 애니메이션**을 만들 수 있습니다.

## 1. 타임라인과 적 배치 개념 이해하기

- **타임라인(Timeline)** : Unity의 강력한 시퀀싱 도구.
  - 컷신, 애니메이션, 이벤트 등을 시간 순서에 따라 조작 가능.
  - 플레이어의 시점에서 **적의 움직임과 연출**을 미리 확인할 수 있음.
- **첫 번째 적의 역할**:
  - 플레이어 우주선이 코너를 돌 때 직선 구간에서 적이 날아와 **쏘거나 피해야 하는 상황**을 연출.
  - 게임 플레이의 몰입감과 긴장감을 높임.

## 2. 적 게임 오브젝트 생성 및 모델 배치

- **빈 게임 오브젝트 생성**:
  - 계층(Hierarchy)에서 **Create Empty** → 이름: `Enemy`.
  - 추후 여러 적을 만들 예정이므로, 이번에는 **기본 실험용**으로 사용.
- **모델 오브젝트 생성 및 연결**:
  1. `Enemy`를 선택한 상태에서, 마우스 오른쪽 클릭 → **Create Empty** → 이름: `Model`.
  2. **Imported Assets → GDTV SciFi Spaceships → Models**로 이동.
  3. **기본 빨간 전투기 모델**(크기가 적절한 모델)을 드래그하여 `Model` 오브젝트에 배치.
- **위치 초기화**:
  - 모델과 상위 오브젝트(`Enemy`) 모두의 `Position`을 `(0,0,0)`으로 설정 → 중심에서 정확히 시작.

## 4. 위치(Position) 키프레임 추가 및 움직임 설정

  - 마지막 키프레임에서는 **플레이어 시야 밖 지형 바깥**으로 멀리 이동시켜 사라지도록 설정.

## 1. Input 액션 맵 개념 이해하기

- **Input System의 여러 제어 방식**: 기존 Input Manager, Event 방식 등 다양한 방법이 있지만, **Input Actions와 액션 맵**은 복잡한 프로젝트에서 강력하고 유연함.
- **액션 맵(Action Map)**:
  - 입력을 논리적인 **행동 단위(Action)**로 묶어 관리.
  - 예:
    - **Player 액션 맵** → Move, Jump, Attack 등
    - **UI 액션 맵** → Navigate, Submit 등
  - 미니게임, 인벤토리 등 **다양한 시스템마다 별도의 액션 맵**을 가질 수 있어 관리 용이.
- **장점**:
  - 코드에서 특정 버튼(예: W키) 대신 **"Move" 또는 "Attack"** 같은 의미 단위로 접근.
  - 하나의 액션에 여러 입력 장치를 바인딩 가능 (예: 스페이스바, 게임패드 버튼 등).

## 2. 새 Input Actions 에셋 생성 및 Move 바인딩 설정하기

1. **Input 폴더 → 우클릭 → Create → Input Actions**
   - 이름: `PlayerControls` (띄어쓰기 없이, 끝에 S 포함).
2. **더블 클릭**하여 편집기 열기 → **"+" 아이콘 → 새 액션 맵 추가**
   - 이름: `Player`.
3. **Actions 영역 → "+" 아이콘 → 새 동작 생성**
   - 이름: `Move`.
   - **Action Type**: `Value` (버튼보다 복잡한 값 반환).
   - **Control Type**: `Vector2` (x, y 두 축 값 반환).
4. **바인딩 설정**:
   - Move 옆 **"+" → Add Up/Down/Left/Right Composite** 선택.
   - 각 방향 바인딩:
     - **Up**: Listen → `W` 키 입력.
     - **Down**: Listen → `S` 키 입력.
     - **Left**: Listen → `A` 키 입력.
     - **Right**: Listen → `D` 키 입력.
   - **참고**: W/A/S/D 외에 방향키도 추가 바인딩 가능.
5. **Save Asset** 클릭 → 편집기 닫기.

## 3. Player Ship과 Player Input 컴포넌트 구성

1. **빈 게임 오브젝트 생성** → 이름: `Player Ship`.
   - 우주선 모델을 `Player Ship`의 **자식 오브젝트**로 배치.
2. **Player Ship 선택 → Add Component → Player Input** 추가.
   - **Actions Asset**: `PlayerControls` 선택.
   - 하나의 액션 맵만 있으므로 기본 설정 유지.
3. **입력 처리 방식**:
   - 여러 방법 중 **Send Messages** 사용 (가장 간단).
   - **동일 게임 오브젝트**에 입력 처리 스크립트를 붙여야 작동.
   - 자동 생성되는 함수 예시: `OnMove(InputValue value)` (Move 액션에 연결).

## 4. 첫 번째 C# 스크립트(PlayerMovement) 작성하기

1. **Assets → Scripts 폴더 생성 → 우클릭 → Create → C# Script → 이름: `PlayerMovement`**.
2. 스크립트 내용 개념:
   - **네임스페이스 추가**:
     ```csharp
     using UnityEngine.InputSystem;
     ```
   - **OnMove 메소드 작성**:
     - 메소드 형식: `public void OnMove(InputValue value)`
     - 입력 값 읽기:
       ```csharp
       Vector2 moveInput = value.Get<Vector2>();
       Debug.Log(moveInput);
       ```
   - 이 스크립트를 **Player Ship 오브젝트에 부착**.

## 5. 입력 값 테스트 및 콘솔 확인

1. **재생 버튼 클릭 → W/A/S/D 키 입력**.
2. 콘솔 출력 확인:
   - `A` 키 → `x = -1` (왼쪽).
   - `D` 키 → `x = +1` (오른쪽).
   - `W` 키 → `y = +1` (앞/위).
   - `S` 키 → `y = -1` (뒤/아래).
3. 값이 정상적으로 변하면 **Input 액션 맵과 스크립트가 올바르게 연결된 것**.

### ✅ **핵심 개념 정리**

- **액션 맵(Action Map)**: 여러 입력 장치에 대응하는 **의미 단위 액션 집합**.
- **Move 액션 설정**: `Value` + `Vector2` → 2D 이동값(WASD).
- **Player Input**: `Send Messages` 방식 → **OnMove 메소드** 자동 호출.
- **테스트 방법**: 콘솔에서 입력값(Vector2) 확인 → 플레이어 우주선 움직임 구현 준비 완료.

이 강의를 통해 **Input System의 기본 흐름**과 **첫 번째 입력 처리 스크립트 작성법**을 이해했으므로, 다음 강의에서 이 값을 활용하여 실제 **Player Ship 이동 로직**을 구현할 수 있게 됩니다.
