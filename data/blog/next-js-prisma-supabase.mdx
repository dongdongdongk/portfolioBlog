# 1. Next.js, Prisma, Supabase란?

```jsx
Next.js:

		React 기반의 프레임워크로, 서버 사이드 렌더링(SSR), 정적 사이트 생성(SSG), API 라우팅 등을 지원합니다.

Prisma:

		현대적인 ORM(Object-Relational Mapping)으로, 데이터베이스 작업을 간소화하고 타입 안정성을 제공합니다.

Supabase:

		PostgreSQL 기반의 오픈소스 BaaS(Backend as a Service)로, 인증, 데이터베이스, 실시간 기능, 스토리지 등을 제공합니다.

이 조합은 빠르게 확장 가능한 풀스택 애플리케이션을 구축하기에 이상적입니다.
```

# 3. Prisma와 Supabase 설정

## 3.1. Prisma 스키마 정의

```jsx
prisma/schema.prisma 파일을 열어 데이터 모델을 정의합니다. 예를 들어, 사용자와 게시물을 관리하는 스키마:
```

```jsx
// Prisma 클라이언트 생성기 설정: TypeScript/JavaScript로 Prisma 코드를 생성
generator client {
  provider = "prisma-client-js"
}

// 데이터베이스 연결 설정: Supabase의 PostgreSQL 데이터베이스 URL 사용
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL") // .env 파일에서 DATABASE_URL을 가져옴
}

// 사용자 테이블 정의
model User {
  id        String   @id @default(cuid()) // 고유 ID, cuid()로 자동 생성
  email     String   @unique              // 이메일, 중복 불가
  name      String?                     // 이름, 선택적 필드 (null 가능)
  posts     Post[]                      // 이 사용자가 작성한 게시물 (1:N 관계)
  createdAt DateTime @default(now())     // 계정 생성 시간, 기본값은 현재 시간
}

// 게시물 테이블 정의
model Post {
  id        String   @id @default(cuid()) // 고유 ID, cuid()로 자동 생성
  title     String                      // 게시물 제목
  content   String?                     // 게시물 내용, 선택적 필드
  published Boolean  @default(false)     // 게시물 공개 여부, 기본값은 비공개
  author    User?    @relation(fields: [authorId], references: [id]) // 작성자 (User와 연결)
  authorId  String?                     // 작성자의 ID, 외래 키
}
```

```jsx
@id: 해당 필드가 테이블의 기본 키(primary key)임을 나타냅니다.

@default(cuid()): Prisma가 자동으로 고유한 ID를 생성합니다.

@unique: 이메일은 중복될 수 없습니다.

@relation: Post의 authorId가 User의 id를 참조하여 관계를 설정합니다.

마이그레이션 명령어: npx prisma migrate dev --name init를 실행하여 이 스키마를 Supabase 데이터베이스에 적용합니다.
```

## 3.3. Supabase 클라이언트 설정

```jsx
lib/supabase.ts 파일을 만들어 Supabase 클라이언트를 설정합니다:
```

```jsx
// lib/supabase.ts
// Supabase SSR 클라이언트와 Next.js 쿠키 유틸리티를 가져옴
import { createServerClient, type CookieOptions } from '@supabase/ssr';
import { cookies } from 'next/headers';

// Supabase 클라이언트를 생성하는 함수
export function createSupabaseClient() {
  // Next.js의 쿠키 스토어를 가져옴 (인증 세션을 저장/관리)
  const cookieStore = cookies();

  // Supabase 클라이언트 생성
  return createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!, // Supabase 프로젝트 URL
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!, // Supabase 공개 키
    {
      // 쿠키 관리 설정: 서버에서 쿠키를 읽고 쓰는 방법 정의
      cookies: {
        // 쿠키 값을 가져오는 함수
        get(name: string) {
          return cookieStore.get(name)?.value;
        },
        // 쿠키 값을 설정하는 함수
        set(name: string, value: string, options: CookieOptions) {
          cookieStore.set({ name, value, ...options });
        },
        // 쿠키를 삭제하는 함수
        remove(name: string, options: CookieOptions) {
          cookieStore.delete({ name, ...options });
        },
      },
    }
  );
}
```

# \* Supabase 로그인 과정 ( 쿠키 )

## 🍪 쿠키(Cookie)란?

```jsx
쿠키는 웹사이트가 사용자의 브라우저에 저장하는 작은 텍스트 파일이에요. 마치 출입증이나 회원카드같은 역할을 합니다.
```

```jsx
예시:
쿠키 이름: "user_session"
쿠키 값: "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

## 🔐 로그인 상태는 어떻게 유지될까?

### 1단계: 로그인할 때

```jsx
javascript // 사용자가 로그인하면
const { data, error } = await supabase.auth.signInWithPassword({
  email: 'user@example.com',
  password: 'password123',
})

// Supabase가 자동으로 쿠키에 토큰을 저장
// 브라우저 쿠키: sb-access-token=abc123xyz...
```

### 2단계: 페이지를 새로고침하거나 다른 페이지로 이동할 때

```jsx
// 브라우저가 자동으로 쿠키를 서버에 전송
// 서버에서 쿠키를 읽어서 "아, 이 사용자는 로그인된 상태구나!" 확인
const cookieStore = cookies()
const token = cookieStore.get('sb-access-token')?.value
```

## 📋 코드 상세 분석

```jsx
export function createSupabaseClient() {
  const cookieStore = cookies(); // Next.js에서 쿠키를 읽고 쓰는 도구

  return createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        // 1. 쿠키 읽기 - "출입증 확인하기"
        get(name: string) {
          // name = "sb-access-token" 같은 쿠키 이름
          return cookieStore.get(name)?.value; // 쿠키 값 반환
        },

        // 2. 쿠키 저장 - "새로운 출입증 발급하기"
        set(name: string, value: string, options: CookieOptions) {
          cookieStore.set({ name, value, ...options });
          // 예: sb-access-token에 새로운 토큰 저장
        },

        // 3. 쿠키 삭제 - "출입증 회수하기"
        remove(name: string, options: CookieOptions) {
          cookieStore.delete({ name, ...options });
          // 로그아웃할 때 토큰 삭제
        },
      },
    }
  );
}
```

## 🎯 실제로 어떻게 작동하는지 예시

```jsx
로그인 과정:

		1. 사용자: "로그인하기" 버튼 클릭

		2. Supabase: 이메일/비밀번호 확인 → 토큰 생성

		3. 브라우저: 쿠키에 토큰 저장 (sb-access-token=abc123...)

다른 페이지 방문 시:

		1. 브라우저: 자동으로 쿠키를 서버에 전송

		2. 서버: cookieStore.get('sb-access-token') → 토큰 확인

		3. Supabase: 토큰이 유효하면 "로그인된 사용자"로 인식

로그아웃 시:

		1. 사용자: "로그아웃" 버튼 클릭

		2. 서버: cookieStore.delete('sb-access-token') → 쿠키 삭제

		3. 결과: 다음번에 접속하면 로그인이 필요함
```

## 🤔 토큰 vs 쿠키 구분

```jsx
// 쿠키 안에 토큰이 들어있어요!
쿠키 = {
  이름: 'sb-access-token',
  값: '실제토큰문자열abc123xyz...', // 이게 토큰!
  만료시간: '2025-07-25 12:00:00',
}
```

```jsx
// lib/prisma.ts
// Prisma 클라이언트를 가져옴
import { PrismaClient } from '@prisma/client';

// 전역 변수로 Prisma 클라이언트를 저장 (개발 환경에서 재사용)

  var prisma: PrismaClient | undefined;

// Prisma 클라이언트 인스턴스 생성
export const prisma = global.prisma || new PrismaClient();

// 개발 환경에서는 전역 변수에 저장하여 재사용 (성능 최적화)
if (process.env.NODE_ENV !== 'production') global.prisma = prisma;
```

# 4. 기본적인 문법과 예제

## 4.1. 인증(Authentication) 구현

```jsx
Supabase의 인증 기능을 사용해 로그인/로그아웃/회원가입을 구현합니다.
```

### 로그인 페이지 (app/login/page.tsx)

```jsx
// '@/lib/supabase' 경로에 있는 사용자 정의 라이브러리에서 `createSupabaseClient` 함수를 가져옵니다.
// '@'는 프로젝트의 루트 디렉토리를 가리키는 별칭입니다. 이 파일은 Supabase 데이터베이스나 인증 서비스와 상호작용하기 위한 Supabase 클라이언트를 설정하는 로직을 포함하고 있을 가능성이 큽니다.
import { createSupabaseClient } from '@/lib/supabase';

// Next.js에서 제공하는 `redirect` 함수를 가져옵니다. 이 함수는 사용자를 다른 페이지(예: 로그인 페이지에서 홈페이지)로 프로그래밍 방식으로 이동시키는 데 사용됩니다.
import { redirect } from 'next/navigation';

// Next.js에서 제공하는 `Link` 컴포넌트를 가져옵니다. 이 컴포넌트는 페이지 간 클라이언트 측 내비게이션을 가능하게 하며, 전체 페이지를 새로고침하지 않고 링크를 통해 이동할 수 있도록 합니다. 여기서는 "회원가입" 링크에 사용됩니다.
import Link from 'next/link';

// 이 파일의 기본 내보내기(export default)로 `LoginPage`라는 비동기 함수 컴포넌트를 정의합니다.
// Next.js에서 이 컴포넌트는 기본적으로 서버 컴포넌트로, 서버에서 실행되며 인증과 같은 서버 측 로직을 처리할 수 있습니다.
export default async function LoginPage() {
  // `createSupabaseClient` 함수를 호출하여 Supabase 클라이언트 인스턴스를 생성합니다.
  // 이 클라이언트는 Supabase의 인증 서비스 등과 상호작용하는 데 사용됩니다.
  const supabase = createSupabaseClient();

  // Supabase 클라이언트를 사용해 현재 로그인된 사용자가 있는지 확인합니다.
  // `supabase.auth.getUser()`는 현재 사용자의 정보를 가져오는 비동기 메서드입니다.
  // `await` 키워드는 이 작업이 완료될 때까지 기다리도록 합니다.
  // 반환된 데이터는 객체 구조분해 할당({ data: { user } })을 통해 `user` 변수에 저장됩니다.
  const { data: { user } } = await supabase.auth.getUser();

  // 만약 `user`가 존재하면(즉, 사용자가 이미 로그인한 상태라면),
  // `redirect` 함수를 호출해 사용자를 홈페이지('/')로 리다이렉트합니다.
  if (user) {
    redirect('/');
  }

  // `handleLogin` 함수를 정의합니다. 이 함수는 로그인 폼 데이터를 처리하는 비동기 서버 액션입니다.
  // `formData`는 HTML 폼에서 제출된 데이터를 담고 있는 `FormData` 객체입니다.
  async function handleLogin(formData: FormData) {
    // 'use server' 지시자는 이 함수가 서버에서만 실행되는 서버 액션임을 나타냅니다.
    // 이는 Next.js의 서버 컴포넌트 또는 서버 액션 기능으로, 클라이언트가 아닌 서버에서 실행되도록 보장합니다.
    'use server';

    // 다시 Supabase 클라이언트를 생성합니다.
    // 서버 액션 내에서 새로운 클라이언트 인스턴스가 필요하므로 다시 호출합니다.
    const supabase = createSupabaseClient();

    // `formData.get('email')`를 사용해 폼에서 입력된 이메일 값을 가져옵니다.
    // `as string`은 TypeScript에서 이 값이 문자열임을 명시적으로 지정합니다.
    const email = formData.get('email') as string;

    // 마찬가지로 폼에서 입력된 비밀번호 값을 가져옵니다.
    const password = formData.get('password') as string;

    // Supabase의 `signInWithPassword` 메서드를 호출해 이메일과 비밀번호로 로그인을 시도합니다.
    // 이 메서드는 비동기적으로 실행되며, 성공 또는 실패 여부와 함께 결과를 반환합니다.
    const { error } = await supabase.auth.signInWithPassword({ email, password });

    // 로그인 중 오류가 발생하면(예: 잘못된 이메일/비밀번호),
    // 콘솔에 오류를 출력하고 함수를 종료합니다.
    if (error) {
      console.error(error);
      return;
    }

    // 로그인에 성공하면 사용자를 홈페이지('/')로 리다이렉트합니다.
    redirect('/');
  }

  // JSX를 반환하여 로그인 페이지의 UI를 렌더링합니다.
  // `div`는 전체 화면 높이(`min-h-screen`)를 채우며, flexbox를 사용해 내용물을 중앙에 정렬합니다.
  return (
    <div className="flex min-h-screen items-center justify-center">
      {/* `action={handleLogin}`은 폼 제출 시 `handleLogin` 함수를 호출하도록 설정합니다. */}
      <form action={handleLogin} className="space-y-4">
        {/* 이메일 입력 필드 */}
        <div>
          {/* `htmlFor`는 라벨이 `email` ID를 가진 입력 필드와 연결되도록 합니다. */}
          <label htmlFor="email">이메일</label>
          {/* `input` 태그로 이메일 입력 필드를 생성합니다. `type="email"`은 이메일 형식을 요구하며, `required`는 필수 입력 필드임을 나타냅니다. */}
          <input id="email" name="email" type="email" required className="border p-2" />
        </div>
        {/* 비밀번호 입력 필드 */}
        <div>
```

```jsx
  // 이 클라이언트는 Supabase의 인증 서비스(여기서는 현재 사용자 확인)를 사용합니다.

  // 이 메서드는 비동기적으로 실행되며, `await`를 사용해 결과가 반환될 때까지 기다립니다.

  // 기본적으로 HTTP 200 상태 코드를 반환합니다(성공).
  return NextResponse.json(post);
```

```jsx
        // `form` 태그는 새 게시물을 생성하기 위한 폼입니다.
        // `action` 속성은 폼 제출 시 실행되는 비동기 서버 액션을 정의합니다.
        <form
          action={async (formData: FormData) => {
            // 'use server' 지시자는 이 함수가 서버에서만 실행되는 서버 액션임을 나타냅니다.
            // 이는 Next.js의 서버 액션 기능으로, 클라이언트가 아닌 서버에서 로직을 처리합니다.
            'use server';

            // 폼에서 입력된 제목(`title`)과 내용(`content`)을 가져옵니다.
            // `formData.get('key')`는 폼 필드의 값을 가져오며, `as string`은 TypeScript에서 값이 문자열임을 명시합니다.
            const title = formData.get('title') as string;
            const content = formData.get('content') as string;

            // `/api/posts` 엔드포인트로 POST 요청을 보내 새 게시물을 생성합니다.
            // `fetch`는 HTTP 요청을 보내는 JavaScript 함수입니다.
            // `JSON.stringify`를 사용해 `title`과 `content`를 JSON 형식으로 변환합니다.
            // `headers`에 `'Content-Type': 'application/json'`을 설정해 요청 본문이 JSON임을 서버에 알립니다.
            await fetch('/api/posts', {
              method: 'POST',
              body: JSON.stringify({ title, content }),
              headers: { 'Content-Type': 'application/json' },
            });
          }}
          className="space-y-4 my-4"
        >
          {/* 제목 입력 필드: `input` 태그로 제목을 입력받습니다. */}
          <input name="title" placeholder="제목" className="border p-2" />
          {/* 내용 입력 필드: `textarea` 태그로 긴 텍스트를 입력받습니다. */}
          <textarea name="content" placeholder="내용" className="border p-2" />
          {/* 제출 버튼: 클릭 시 폼 데이터를 서버 액션으로 보냅니다. */}
          <button type="submit" className="bg-blue-500 text-white p-2">게시물 작성</button>
        </form>
      )}

      {/* 게시물 목록을 표시하는 리스트 */}
      <ul>
        {/* `posts` 배열을 `map` 메서드로 순회하며 각 게시물을 `<li>`로 렌더링합니다. */}
        {posts.map((post) => (
          // `key={post.id}`는 React에서 리스트 렌더링 시 각 항목을 고유하게 식별하기 위해 필요합니다.
          // `className="border-b py-2"`는 Tailwind CSS로 각 게시물에 하단 경계선과 패딩을 적용합니다.
          <li key={post.id} className="border-b py-2">
            {/* 게시물 제목 */}
            <h2>{post.title}</h2>
            {/* 게시물 내용 */}
            <p>{post.content}</p>
            {/* 작성자 이름: `post.author?.name`은 작성자 정보가 있을 경우 이름을 표시합니다. */}
            {/* `?.`는 옵셔널 체이닝으로, `author`가 `null` 또는 `undefined`일 경우 에러를 방지합니다. */}
            <p>작성자: {post.author?.name}</p>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

# **{ Supabase 클라이언트 방식**과 **Supabase + Prisma 방식**의 차이 }

## 🧠 먼저 개념부터 확실히 잡자

### 1. Supabase는 뭐 하는 건가요?

```jsx
Supabase는 Firebase와 비슷한 백엔드 서비스예요.

인증, 데이터베이스(PostgreSQL), Storage, 서버리스 함수 등을 제공해요.

웹 프론트엔드(Next.js 등)에서 쉽게 연결해서 쓸 수 있어요.

→ 즉, 프론트엔드 개발자도 서버 없이 로그인, 데이터 저장이 가능!
```

### 2. Prisma는 뭐 하는 건가요?

```jsx
Prisma는 Node.js 서버에서 PostgreSQL 같은 데이터베이스와 연결할 때 사용하는 ORM 도구예요.

ORM이란? → SQL 안 쓰고 JS/TS 문법으로 DB를 다룰 수 있게 해주는 도구!

→ Supabase가 이미 DB를 제공하니까,

Prisma는 그 DB에 "서버에서 안전하게 접근"할 때 쓰는 거예요.
```

## 두 가지 방식 비교

| 구분      | Supabase 클라이언트 방식                                       | Supabase + Prisma 방식             |
| --------- | -------------------------------------------------------------- | ---------------------------------- |
| 인증      | Supabase 클라이언트에서 처리 (`supabase.auth`)                 | 동일                               |

| 사용 시기 | 빠른 개발, MVP                                                 | 민감한 정보, SSR, 보안 필요한 경우 |

# npx prisma generate와 npx prisma db push?

## 1. npx prisma generate는 뭐야?

```jsx
쉽게 말하면: 이 명령어는 Prisma가 데이터베이스와 소통할 수 있도록 "도구"를 만들어주는 작업이에요.

자세히 설명하면:

		schema.prisma 파일에 데이터베이스의 구조(예: User 테이블의 id, email, name 같은 필드 정보)를 정의했죠?

		npx prisma generate를 실행하면, Prisma가 이 schema.prisma 파일을 읽어서 자바스크립트/타입스크립트 코드로 변환해줍니다.

		이 변환된 코드는 Prisma Client라는 걸 만들어줘요. Prisma Client는 우리가 데이터베이스에 데이터를 추가하거나, 조회하거나, 수정하거나, 삭제할 때 편리하게 사용할 수 있는 도구입니다.

		예를 들어, schema.prisma에 User 모델을 정의했으면, Prisma Client를 이용해서 prisma.user.create() 같은 코드로 새 사용자를 데이터베이스에 추가할 수 있게 됩니다.

왜 필요해?

schema.prisma는 그냥 "설계도"일 뿐이에요. 이 설계도를 실제로 코드에서 사용할 수 있게 변환하려면 prisma generate가 필요합니다.

그래야 나중에 서버 코드에서 데이터베이스 작업을 할 때 편하게 명령어를 쓸 수 있어요!
```

## 2. npx prisma db push는 뭐야?

```jsx
쉽게 말하면: 이 명령어는 schema.prisma에 정의한 데이터베이스 구조를 실제 데이터베이스(예: Supabase의 PostgreSQL)에 적용해주는 작업이에요.

자세히 설명하면:

		schema.prisma 파일에 User 테이블의 구조(예: id, email, name 필드)를 작성했죠? 하지만 이건 아직 실제 데이터베이스에 반영되지 않은 상태예요.

		npx prisma db push를 실행하면 Prisma가 schema.prisma에 정의된 구조를 보고, 실제 데이터베이스(Supabase의 PostgreSQL)에 그 구조를 만들어줍니다.

		예를 들어, User 테이블이 데이터베이스에 없으면 새로 만들고, 이미 있다면 구조를 업데이트해줍니다.

		이 과정은 데이터베이스에 테이블을 만들거나 수정하는 걸 **"마이그레이션(migration)"**이라고 부르는데, db push는 간단한 마이그레이션 방식이에요.

왜 필요해?

		schema.prisma에 정의한 테이블 구조가 실제 데이터베이스에 없으면, 나중에 데이터를 저장하거나 조회할 때 오류가 나요.

		db push는 이 구조를 실제 데이터베이스에 적용해서 우리가 코드로 데이터를 다룰 수 있게 준비해줍니다.
```

## 비유로 쉽게 이해하기

```jsx
schema.prisma를 집 짓기의 설계도라고 생각해보세요:

prisma generate: 설계도를 보고, 집을 짓기 위해 필요한 공구(망치, 드릴 같은)를 만드는 과정이에요. 이 공구(Prisma Client)를 이용해서 나중에 집(데이터베이스)을 쉽게 다룰 수 있어요.

prisma db push: 설계도를 보고 실제로 땅(데이터베이스)에 집(테이블)을 짓는 과정이에요. 설계도대로 테이블을 만들거나 수정해서 데이터베이스를 준비해줍니다.
```

# { 로그인 상태 추적 }

## 1. Supabase의 로그인 상태 추적

### 개념

```jsx
session: 현재 로그인된 사용자의 정보 (id, email, access_token 등)

onAuthStateChange(): 로그인/로그아웃 등의 인증 상태가 바뀔 때 자동으로 알려주는 함수
```

### 문법

```jsx
const { data: session } = await supabase.auth.getSession()
```

```jsx
supabase.auth.onAuthStateChange((event, session) => {
  // event: signedIn, signedOut, passwordRecovery 등
  // session: 로그인된 유저의 정보
})
```

```jsx
'use client'

import { useEffect, useState } from 'react'
import { supabase } from '@/lib/supabase'

export default function AuthTracker() {
  const [user, setUser] = useState(null)

  useEffect(() => {
    // 최초 로그인 상태 확인
    supabase.auth.getSession().then(({ data }) => {
      setUser(data.session?.user ?? null)
    })

    // 로그인/로그아웃 시 자동 추적
    const { data: listener } = supabase.auth.onAuthStateChange((event, session) => {
      console.log('🔥 Auth 상태 변경:', event)
      setUser(session?.user ?? null)
    })

    return () => {
      listener.subscription.unsubscribe() // cleanup
    }
  }, [])

  return <div>{user ? <p>로그인됨: {user.email}</p> : <p>로그아웃 상태</p>}</div>
}
```

| `where`       | 조건 검색 (SQL의 `WHERE`)                                    |
| `include`     | 관계된 다른 테이블 정보도 같이 가져옴                        |
| `updateMany`  | 여러 레코드를 한 번에 수정                                   |
| `transaction` | 여러 작업을 하나의 묶음으로 처리 (모두 성공하거나 모두 실패) |

### 문법 & 예시

```jsx
await prisma.user.findMany({
  where: {
    email: 'test@email.com',
  },
})
```

```jsx
await prisma.user.findMany({
  include: {
    posts: true, // user의 posts까지 같이 가져옴
  },
})
```

```jsx
await prisma.user.updateMany({
  where: { role: 'user' },
  data: { role: 'member' },
})
```

```jsx
await prisma.$transaction([
  prisma.user.create({ data: { email: 'a@b.com' } }),
  prisma.profile.create({ data: { bio: 'hello' } }),
])
```

## 3. SSR에서 로그인된 사용자 정보 가져오기

### 개념

```jsx
클라이언트에 있는 토큰을 서버로 보내서, 서버에서 인증된 사용자의 정보를 얻는 방식

서버 컴포넌트에서 Supabase 서버 클라이언트를 사용해야 함
```

### Supabase 서버 클라이언트 생성 (예시)

```jsx
// lib/supabase-server.ts
import { createServerComponentClient } from '@supabase/auth-helpers-nextjs'
import { cookies } from 'next/headers'

export const createSupabaseServerClient = () => createServerComponentClient({ cookies })
```

### SSR 컴포넌트에서 사용자 정보 가져오기

```jsx
// app/page.tsx
import { createSupabaseServerClient } from '@/lib/supabase-server'

export default async function Home() {
  const supabase = createSupabaseServerClient()

  const {
    data: { session },
  } = await supabase.auth.getSession()

  return <div>{session?.user ? <p>환영합니다, {session.user.email}</p> : <p>로그인 필요</p>}</div>
}
```

| 항목                  | 설명                                        |
| --------------------- | ------------------------------------------- |
| `session`             | 현재 로그인한 사용자 정보 (email 등)        |
| `onAuthStateChange()` | 로그인/로그아웃 추적 가능                   |
| Prisma `where`        | 조건으로 찾기                               |
| Prisma `include`      | 연관된 테이블도 같이 조회                   |
| Prisma `updateMany`   | 조건에 맞는 여러 데이터 수정                |
| Prisma `transaction`  | 모든 DB 작업을 묶어서 처리                  |
| SSR 로그인 처리       | 서버에서 쿠키 기반 인증 처리 (SEO에도 유리) |
