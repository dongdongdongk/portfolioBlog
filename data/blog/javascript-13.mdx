# **콜 스택 (Call Stack)**

```jsx
콜 스택은 자바스크립트 엔진이 함수 호출을 관리하는 메커니즘 중 하나이다.

함수가 호출될 때마다 해당 함수의 정보(함수 호출 시의 매개변수, 지역 변수 등)가 콜 스택에 추가되고,

함수의 실행이 끝나면 해당 정보가 스택에서 제거된다

콜 스택은 후입선출(LIFO, Last-In-First-Out) 구조를 가지며,

현재 실행 중인 함수가 제일 위에 위치하게 된다. 즉, 가장 최근에 호출된 함수가 가장 먼저 실행을 완료하고 스택에서 제거된다
```

```jsx
function greet(name) {
  console.log('안녕하세요, ' + name + '님!')
}

function welcome() {
  console.log('어서오세요!')
}

function sayHello() {
  const userName = 'John'
  greet(userName)
  welcome()
}

sayHello()
```

```jsx
1. sayHello 함수가 호출되면 sayHello 함수의 정보가 콜 스택에 추가됨

2. sayHello 함수에서 greet 함수가 호출되면 greet 함수의 정보가 콜 스택에 추가 콜 스택의 상태는 다음과 같다

	 [sayHello, greet]

3. greet 함수의 실행이 완료되면 해당 정보가 콜 스택에서 제거된다 콜 스택의 상태는 다음과 같다

	 [sayHello]

4. 이어서 welcome 함수가 호출되면 welcome 함수의 정보가 콜 스택에 추가

	 [sayHello, welcome]

5. welcome 함수의 실행이 완료되면 해당 정보가 콜 스택에서 제거

	 [sayHello]

6. 마지막으로 sayHello 함수의 실행이 완료되면 해당 정보가 콜 스택에서 제거 이제 콜 스택은 비어 있는 상태가 된다
```

```jsx
이러한 과정을 통해 자바스크립트 엔진은 함수 호출과 실행을 관리하며,

콜 스택을 사용하여 실행 흐름을 추적
```

# **Web API와 단일 스레드**

## **1. 단일 스레드**

```jsx
자바스크립트는 단일 스레드 언어이다

이는 한 번에 하나의 작업만을 수행할 수 있음을 의미

자바스크립트는 브라우저의 메인 스레드에서 실행되며, 이 스레드는 이벤트 루프를 통해 비동기 작업을 처리한다
```

## **2. 이벤트 루프**

```jsx
메인 스레드에서 실행되는 이벤트 루프는 계속해서 이벤트 큐를 확인하고 처리할 작업이 있다면 순차적으로 처리한다

이벤트 루프를 통해 비동기 작업이 가능하며, 작업이 완료되면 해당 작업의 콜백 함수가 이벤트 큐에 추가되어 실행된다
```

## **3. Web API**

```jsx
브라우저는 Web API를 제공하여 비동기 작업을 처리한다

Web API는 브라우저에 내장된 API로, 주로 비동기적인 작업을 처리하는 역할을 한다

대표적인 Web API에는 setTimeout, fetch, XMLHttpRequest와 같은 것들이 있다.
```

## **4. 비동기 작업의 처리**

```jsx
비동기 작업을 처리할 때, Web API를 사용하여 요청을 시작하면 해당 작업은 백그라운드에서 별도의 스레드에서 수행

작업이 완료되면 콜백 함수 또는 프로미스를 사용하여 이벤트 큐에 해당 작업을 추가하고,

메인 스레드의 이벤트 루프에 의해 순차적으로 실행
```

## 예제

```jsx
console.log('시작')

setTimeout(function () {
  console.log('비동기 작업 완료')
}, 1000)

console.log('끝')
```

```jsx
이 코드에서 setTimeout은 비동기 작업을 시작하고, 메인 스레드는 계속해서 다음 작업을 진행

1초 후에 비동기 작업이 완료되면 해당 콜백 함수가 이벤트 큐에 추가되고,

메인 스레드의 이벤트 루프에 의해 실행됨
```

## **결론**

```jsx
자바스크립트의 단일 스레드 구조에서 Web API를 이용한 비동기 작업은 브라우저의 멀티 스레드 환경에서 일어난다

이로 인해 웹 페이지가 응답성 있게 동작하면서도 비동기 작업을 처리할 수 있다
```

# **콜백 지옥(Callback Hell)**

```jsx
콜백 지옥은 콜백 함수를 중첩하여 사용할 때 코드가 가독성이 떨어지고 유지보수가 어려워지는 상황을 말한다.

주로 비동기적인 작업을 연속적으로 처리할 때 발생하는 문제로, 코드가 계속해서 들여쓰기되어 가독성이 나빠지는 현상
```

```jsx
setTimeout(function () {
  console.log('첫 번째 작업 완료')

  setTimeout(function () {
    console.log('두 번째 작업 완료')

    setTimeout(function () {
      console.log('세 번째 작업 완료')

      // ... 더 많은 작업
    }, 1000)
  }, 1000)
}, 1000)
```

# **Promise(프로미스)**

```jsx
프로미스는 자바스크립트에서 비동기 작업을 보다 간편하게 처리할 수 있는 객체

프로미스는 비동기 작업의 성공 또는 실패와 같은 최종 완료 상태에 대한 결과를 나타낸다

주로 비동기 코드를 더 읽기 쉽고 관리하기 쉽게 만드는 데 사용된다
```

## **프로미스의 세 가지 상태(States)**

```jsx
Pending(대기): 초기 상태로, 프로미스가 만들어진 직후

Fulfilled(이행): 비동기 작업이 성공적으로 완료된 상태

Rejected(거부): 비동기 작업이 실패한 상태
```

```jsx
// 비동기 작업을 수행하는 함수
function asyncTask(success = true) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (success) {
        resolve('작업 성공!')
      } else {
        reject('작업 실패!')
      }
    }, 1000)
  })
}

// 프로미스 사용 예제
asyncTask(true)
  .then((result) => {
    console.log(result) // 작업 성공!
    return '다음 작업'
  })
  .then((result) => {
    console.log(result) // 다음 작업
    return asyncTask(false) // 실패하는 작업으로 변경
  })
  .catch((error) => {
    console.error(error) // 작업 실패!
  })
  .finally(() => {
    console.log('마지막에 항상 실행되는 부분')
  })
```

```jsx
* asyncTask 함수는 프로미스를 반환 비동기 작업이 완료되면 resolve로 성공을, 실패하면 reject로 실패를 전달

* .then은 프로미스가 이행됐을 때의 동작을 정의하며, 여러 개의 .then을 연결하여 연속적인 작업을 수행할 수 있다.

* .catch는 프로미스가 거부됐을 때의 동작을 정의

* .finally는 프로미스가 성공 또는 실패와 상관없이 항상 실행되는 부분
```

# 비동기라는 키워드

```jsx
JavaScript에서 비동기 함수는 자동으로 Promise를 반환

이는 ES6(ECMAScript 2015)에서 비동기 프로그래밍을 보다 편리하게 만들기 위해 도입된 특징 중 하나
```

```jsx
// 비동기 함수 예제
async function asyncFunction() {
  return '비동기 함수가 반환하는 값'
}

// 비동기 함수 호출
const promise = asyncFunction()

promise.then((result) => {
  console.log(result) // '비동기 함수가 반환하는 값'
})
```

```jsx
이러한 동작은 내부적으로 JavaScript 엔진이 비동기 함수를 만날 때,

해당 함수를 실행하여 반환된 값으로 이행된(resolve) Promise를 자동으로 생성하기 때문

비동기 함수에서 명시적으로 Promise를 반환하지 않아도,

자동으로 Promise로 래핑되어 반환되므로, 기존의 콜백 패턴보다 코드가 간결해지고,

Promises와 관련된 다양한 메서드 (예: .then, .catch, .finally)를 사용하여 비동기 코드를 보다 효과적으로 다룰 수 있다.
```

# **async와 await**

```jsx
async와 await는 JavaScript에서 비동기 코드를 보다 명확하고 동기식으로 작성할 수 있도록 도와주는 키워드

이 두 키워드는 ES2017(ES8)에서 도입되었으며, Promise를 더 쉽게 다룰 수 있도록 해준다
```

**`async`**와 **`await`**

## **`async` 함수**

```jsx
async 키워드는 함수를 비동기 함수로 선언

비동기 함수는 항상 Promise를 반환하며, 내부에서 await 키워드를 사용하여 다른 Promise나 값을 기다릴 수 있다.
```

```jsx
async function fetchData() {
  return '비동기 데이터'
}
```

## **`await` 표현식**

```jsx
await 키워드는 Promise가 이행(resolve)될 때까지 함수의 실행을 일시 중지하고, Promise 가 완료되면

 Promise가 이행된 결과 값을 반환. await는 반드시 async 함수 내부에서 사용되어야 한다.
```

```jsx
async function fetchData() {
  const result = await someAsyncFunction()
  console.log(result)
}
```

```jsx
// 실제 서버와의 통신을 시뮬레이션하는 함수
function simulateLogin(username, password) {
  // 서버 URL (가정)
  const serverURL = 'https://example.com/login'

  // fetch를 사용하여 서버와 통신
  return fetch(serverURL, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({ username, password }),
  }).then((response) => {
    if (!response.ok) {
      throw new Error('로그인 실패: 잘못된 사용자명 또는 비밀번호')
    }
    return response.json()
  })
}

async function loginUser(username, password) {
  try {
    // 로그인 함수 호출
    const user = await simulateLogin(username, password)

    // 로그인에 성공한 경우
    console.log('로그인 성공:', user)
    return user
  } catch (error) {
    // 로그인에 실패한 경우
    console.error(error.message)
    throw error // 예외를 다시 던져서 호출자에게 전달
  }
}

// 사용 예제
loginUser('user', 'password')
  .then((user) => {
    // 로그인에 성공한 경우의 후속 작업
    console.log('환영합니다, ' + user.username + '님!')
  })
  .catch((error) => {
    // 로그인에 실패한 경우의 후속 작업
    console.error('로그인 실패:', error.message)
  })
```

# 비동기 함수의 오류 처리하기

```jsx
비동기 함수에서의 오류 처리는 try/catch 블록과 함께 async/await를 사용하여 처리된다
```

## 1.**`async`/`await`를 사용하여 비동기 함수 선언**

```jsx
async function fetchData() {
  // 비동기 작업 수행 (예: 네트워크 요청, 파일 읽기 등)
  // 성공적으로 완료되면 데이터 반환
  // 실패할 경우 에러를 throw
}
```

## 2.**`try`/`catch` 블록 사용**

```jsx
async function fetchDataWithHandling() {
  try {
    const result = await fetchData()
    // 비동기 작업이 성공한 경우의 후속 작업
    console.log('데이터 가져오기 성공:', result)
  } catch (error) {
    // 비동기 작업 중 에러가 발생한 경우의 처리
    console.error('데이터 가져오기 실패:', error.message)
  }
}
```

## 3.**`throw`를 통해 에러 발생**

```jsx
async function fetchData() {
  return new Promise((resolve, reject) => {
    // 가정: 비동기 작업 중 에러 발생
    setTimeout(() => {
      reject(new Error('데이터를 가져오는 중 에러 발생'))
    }, 1000)
  })
}
```

## 4.**`try` 블록에서 `await`로 비동기 함수 호출**

```jsx
async function fetchDataWithHandling() {
  try {
    const result = await fetchData()
    // 비동기 작업이 성공한 경우의 후속 작업
    console.log('데이터 가져오기 성공:', result)
  } catch (error) {
    // 비동기 작업 중 에러가 발생한 경우의 처리
    console.error('데이터 가져오기 실패:', error.message)
  }
}
```

## 5.**`catch` 블록에서 에러 처리**

```jsx
async function fetchDataWithHandling() {
  try {
    const result = await fetchData()
    // 비동기 작업이 성공한 경우의 후속 작업
    console.log('데이터 가져오기 성공:', result)
  } catch (error) {
    // 비동기 작업 중 에러가 발생한 경우의 처리
    console.error('데이터 가져오기 실패:', error.message)
    // 에러를 다시 던질 수도 있음 (호출자에게 전달)
    throw error
  }
}
```

## 6.**호출자에서의 오류 처리**

```jsx
async function main() {
  try {
    await fetchDataWithHandling()
    // fetchDataWithHandling 함수가 성공적으로 완료되었을 경우의 후속 작업
  } catch (error) {
    // fetchDataWithHandling 함수에서 에러가 발생한 경우의 처리
    console.error('메인 함수 실행 중 에러:', error.message)
  }
}

// main 함수 호출
main()
```

```jsx
* fetchData 함수는 비동기 작업을 수행하고, 성공할 경우 데이터를 반환하며 실패할 경우 에러를 reject로 전달

* fetchDataWithHandling 함수에서는 fetchData 함수를 호출하고, 성공과 실패 여부에 따라 try/catch 블록에서 적절한 처리를 한다

* 에러가 발생하면 catch 블록에서 해당 에러를 처리하고 필요에 따라 다시 던질 수 있다.

* main 함수에서는 fetchDataWithHandling 함수를 호출하고, 해당 함수에서 발생한 에러를 try/catch 블록으로 처리
```
