# Claude Code 전문 에이전트 완전 가이드

> 최신 공식 문서 + 커뮤니티 실전 사례 기반 | 2026년 2월 기준

---

## 먼저 알아야 할 핵심 개념 3가지

Claude Code에는 비슷해 보이지만 다른 3가지 도구가 있어요.

| 도구               | 위치                | 언제 쓰나                              | 호출 방법                        |
| ------------------ | ------------------- | -------------------------------------- | -------------------------------- |
| **Slash Commands** | `.claude/commands/` | 내가 직접 트리거하는 반복 작업         | `/명령어`                        |
| **Subagents**      | `.claude/agents/`   | Claude가 자동 위임 OR 내가 명시적 호출 | 자동 or "debugger 에이전트 써줘" |
| **Skills**         | `.claude/skills/`   | 전문 지식 패키지 (자동 로드)           | 자동 인식                        |

**초보자 추천 순서**: Commands → Subagents → Skills 순으로 익히세요.

## PART 1 — 환경 설정

### 1-1. 폴더 구조 만들기

```bash
# 터미널에서 프로젝트 루트에서 실행
mkdir -p .claude/commands
mkdir -p .claude/agents

# 글로벌 설정 (모든 프로젝트에서 사용)
mkdir -p ~/.claude/commands
mkdir -p ~/.claude/agents
```

최종 구조:

```
내프로젝트/
├── CLAUDE.md                     ← 프로젝트 기본 규칙 (필수)
├── .claude/
│   ├── commands/                 ← 내가 직접 호출하는 명령어
│   │   ├── debug.md
│   │   ├── review.md
│   │   ├── test.md
│   │   ├── commit.md
│   │   └── refactor.md
│   ├── agents/                   ← Claude가 자동 위임하는 전문가
│   │   ├── debugger.md
│   │   ├── reviewer.md
│   │   └── tester.md
│   └── settings.json             ← 서브에이전트 라우팅 규칙
└── (소스코드들...)
```

### 1-2. CLAUDE.md 설정 (가장 중요한 파일)

Claude Code가 시작할 때 자동으로 읽는 "프로젝트 설명서"예요.
이 파일이 잘 되어 있을수록 에이전트 퀄리티가 올라가요.

```markdown
# 프로젝트 기본 규칙

## 기술 스택

- Frontend: React + TypeScript
- Backend: Node.js + Express
- DB: PostgreSQL
- 테스트: Jest

## 코딩 규칙

- TypeScript 필수
- 함수는 50줄 이하
- 모든 async 함수에 try-catch
- 변수명은 영어, 주석은 한국어

## 빌드/테스트 명령어

- 빌드: `npm run build`
- 테스트: `npm test`
- 린트: `npm run lint`

## 서브에이전트 라우팅 규칙

### 병렬 실행 (동시에 돌려도 되는 경우)

- 3개 이상의 독립적인 작업
- 파일이 겹치지 않는 경우
- 프론트/백/테스트가 분리된 경우

### 순차 실행 (순서가 필요한 경우)

- 앞 작업 결과가 뒤에 필요할 때
- 같은 파일을 여러 에이전트가 건드릴 때

## 응답 규칙

- 항상 한국어로 답변
- 코드 변경 전 계획을 먼저 설명
```

## PART 2 — Slash Commands (수동 호출형)

가장 간단한 방법이에요. `.md` 파일을 만들어두고 `/명령어`로 호출해요.

### 2-1. 디버깅 명령어 — `.claude/commands/debug.md`

```markdown
---
description: 버그와 에러를 체계적으로 분석하고 수정합니다
allowed-tools: Read, Bash, Grep, Glob
---

# 디버깅 전문 분석

다음 버그/에러를 분석해주세요: $ARGUMENTS

## 분석 순서

**Step 1 — 에러 파악**

- 에러 메시지와 스택 트레이스 전체 읽기
- 에러가 발생하는 정확한 위치 파악

**Step 2 — 가설 3개 수립**
관련 파일을 직접 읽은 뒤, 원인 후보를 3개 나열해요:

- 가설 A: [첫 번째 가능한 원인]
- 가설 B: [두 번째 가능한 원인]
- 가설 C: [세 번째 가능한 원인]

**Step 3 — 검증**
각 가설을 코드에서 직접 확인하고, 가장 가능성 높은 원인 특정

**Step 4 — 수정**
수정 코드 제안 + 수정 후 재발 방지책 함께 제시

## 출력 형식
```

원인: [한 줄 요약]
위치: [파일명:줄번호]
수정 코드: [코드 블록]
재발 방지: [조치사항]

```

```

### 2-2. 코드 리뷰 명령어 — `.claude/commands/review.md`

```markdown
---
description: PR 전 코드를 시니어 개발자 관점에서 검토합니다
allowed-tools: Read, Glob, Grep
---

# 코드 리뷰

리뷰 대상: $ARGUMENTS

## 체크리스트 (순서대로 확인)

1. **🔴 보안** — SQL injection, XSS, 인증 누락, 민감정보 노출
2. **🔴 에러 처리** — 예외 상황 대응, 미처리 Promise
3. **🟡 성능** — N+1 쿼리, 불필요한 루프, 메모리 누수
4. **🟡 가독성** — 변수명, 함수 분리, 중복 코드
5. **🟢 테스트** — 커버리지, 엣지케이스 누락 여부

## 출력 형식

🔴 필수 수정 / 🟡 권장 / 🟢 잘된 점으로 구분해서
우선순위가 명확하게 보이도록 정리해주세요.

너무 사소한 것(들여쓰기, 세미콜론 등)은 언급하지 마세요.
버그와 보안 이슈에 집중해주세요.
```

### 2-3. 테스트 작성 명령어 — `.claude/commands/test.md`

```markdown
---
description: 지정한 함수나 파일의 테스트 코드를 작성합니다
allowed-tools: Read, Write, Bash, Glob
---

# 테스트 코드 작성

대상: $ARGUMENTS

## 작성 순서

1. 대상 코드를 먼저 읽고 핵심 동작 파악
2. 정상 케이스 (happy path) 테스트
3. 경계값 테스트 (빈 값, null, 최대값, 음수 등)
4. 에러 케이스 테스트
5. 비동기 처리가 있으면 async/await 테스트 포함

## 규칙

- 테스트 이름: "~하면 ~해야 한다" 형식
- 각 테스트는 하나의 동작만 검증
- Mock은 최소화 (실제 로직 테스트에 집중)
- 기존 테스트 파일이 있으면 같은 스타일 유지

작성 완료 후 `npm test`로 실행 결과 확인해주세요.
```

### 2-4. 커밋 명령어 — `.claude/commands/commit.md`

```markdown
---
description: staged 변경사항을 검토하고 커밋합니다
allowed-tools: Bash(git diff:*), Bash(git add:*), Bash(git commit:*)
disable-model-invocation: true
---

# 안전한 커밋

$ARGUMENTS 메시지로 커밋합니다. (비어있으면 Claude가 자동 작성)

## 커밋 전 체크 (아래 발견 시 커밋 중단)

- TODO, FIXME, HACK 주석
- console.log, print 디버그 코드
- 하드코딩된 API 키, 비밀번호
- 주석 처리된 코드 블록
- DEBUG=true, test_mode=1 같은 플래그

## 커밋 형식
```

feat: 새 기능 추가
fix: 버그 수정
refactor: 리팩토링
test: 테스트 추가
docs: 문서 수정

```

문제 없으면 git add -A 후 커밋 실행.
문제 발견 시 목록을 보여주고 중단.
```

### 2-5. 리팩토링 명령어 — `.claude/commands/refactor.md`

```markdown
---
description: 동작은 유지하면서 코드 품질을 개선합니다
allowed-tools: Read, Write, Bash
---

# 리팩토링

대상: $ARGUMENTS

## 핵심 원칙

- 동작은 절대 바꾸지 않음
- 한 번에 하나씩만 변경
- 변경 전 계획을 먼저 제시하고 진행

## 자주 개선하는 패턴

- 함수 100줄 초과 → 분리
- 중복 코드 → 공통 함수 추출
- 깊은 중첩(3단계+) → 조기 반환(early return)
- 매직 넘버/문자열 → 상수화
- 긴 파라미터 목록(4개+) → 객체로 묶기

## 순서

1. 현재 문제점 목록 제시
2. 우선순위 확인 (내가 승인 후 진행)
3. 단계별 실행 + 각 단계 후 테스트 실행
```

## PART 3 — Subagents (자동 위임형) ← 핵심

Slash Commands와 다른 점은 **Claude가 스스로 판단해서 자동으로 호출**한다는 거예요.
`description`을 잘 쓰는 게 전부예요.

### 3-1. Subagent 만드는 방법 (2가지)

**방법 A — Claude Code 안에서 자동 생성 (추천)**

```bash
# Claude Code 세션에서 실행
/agents
# → "Create new agent" 선택
# → "Project" or "User" 선택
# → Claude가 프로젝트 보고 자동 생성
```

**방법 B — 직접 파일 생성**

`.claude/agents/` 폴더에 `.md` 파일로 만들어요.

### 3-2. 디버거 에이전트 — `.claude/agents/debugger.md`

```markdown
---
name: debugger
description: 버그, 에러, 예외가 발생했을 때 호출. 에러 메시지나 예상치 못한 동작을 분석해 근본 원인을 찾고 수정안을 제시한다. "왜 작동 안 하지", "에러 났어", "버그" 키워드에 반응.
model: sonnet
tools: Read, Bash, Grep, Glob
color: red
---

당신은 10년 경력의 디버깅 전문가입니다.

## 역할

에러와 버그의 근본 원인을 찾아 수정안을 제시합니다.
섣불리 결론 내리지 않고, 코드를 직접 읽은 뒤 판단합니다.

## 디버깅 원칙

1. 에러 스택 트레이스 전체를 먼저 읽기
2. 최소 3개의 원인 가설 수립
3. 각 가설을 코드에서 직접 검증
4. 가장 근거 있는 원인 특정 후 수정

## 출력

- 원인 (한 줄)
- 위치 (파일:줄번호)
- 수정 코드
- 재발 방지책

비판적으로 생각하세요. 첫 번째 그럴듯한 원인에 안주하지 마세요.
```

### 3-3. 코드 리뷰어 에이전트 — `.claude/agents/reviewer.md`

```markdown
---
name: reviewer
description: 코드 리뷰, PR 검토, 품질 검사가 필요할 때 호출. 보안 취약점, 성능 문제, 버그 가능성을 찾아낸다. "리뷰해줘", "확인해줘", "커밋 전" 키워드에 반응.
model: sonnet
tools: Read, Glob, Grep
color: orange
---

당신은 엄격하지만 건설적인 시니어 개발자입니다.

## 리뷰 우선순위

1. 🔴 보안 취약점 (SQL injection, XSS, 인증 누락)
2. 🔴 런타임 에러 가능성 (null 참조, 타입 오류)
3. 🟡 성능 문제 (N+1, 불필요한 반복)
4. 🟡 유지보수성 (중복, 복잡한 로직)
5. 🟢 잘된 부분도 언급

## 규칙

- 사소한 스타일 지적 금지 (린터가 할 일)
- 버그와 보안에 집중
- 수정 방법도 함께 제시
- 너무 장황하게 쓰지 않기

솔직하게 평가하세요. 동의하지 않으면 이유를 말하세요.
```

### 3-4. 테스터 에이전트 — `.claude/agents/tester.md`

```markdown
---
name: tester
description: 테스트 코드 작성, 테스트 실패 분석, 커버리지 개선이 필요할 때 호출. "테스트", "test", "jest", "커버리지" 키워드에 반응.
model: haiku
tools: Read, Write, Bash, Glob
color: green
---

당신은 테스트 자동화 전문가입니다.
(비용 절약을 위해 haiku 모델 사용 — 반복적인 테스트 작성에 충분)

## 테스트 작성 원칙

- 테스트 이름: "~하면 ~해야 한다"
- 각 테스트는 하나만 검증
- AAA 패턴: Arrange → Act → Assert
- 경계값 케이스 반드시 포함

## 작성 후

반드시 `npm test` 실행해서 통과 확인.
실패하면 수정 후 재실행.
```

## PART 4 — 모델 비용 최적화

에이전트별로 다른 모델을 써서 비용을 아낄 수 있어요.

```
메인 세션 (복잡한 판단)  → Opus  (비쌈, 정확함)
디버거/리뷰어 에이전트   → Sonnet (중간)
테스터/반복 작업 에이전트 → Haiku  (저렴, 빠름)
```

에이전트 `.md` 파일에서:

```yaml
model: haiku    # 저렴하고 빠른 작업
model: sonnet   # 대부분의 에이전트에 적합
model: opus     # 복잡한 판단이 필요할 때만
model: inherit  # 메인 세션 모델 그대로 사용 (기본값)
```

## PART 5 — 실제 사용법

### 5-1. Slash Commands 호출

```bash
# Claude Code 세션에서

# 에러 디버깅
/debug TypeError: Cannot read property 'id' of undefined in userService.js line 42

# 파일 리뷰
/review src/api/auth.js

# 테스트 작성
/test getUserById 함수

# 커밋 (메시지 자동 생성)
/commit

# 커밋 (메시지 지정)
/commit feat: 로그인 기능 추가

# 리팩토링
/refactor src/components/Dashboard.jsx
```

### 5-2. Subagent 호출

```bash
# 자동 위임 — Claude가 알아서 판단
"이 에러 왜 나는지 찾아줘"
→ Claude가 debugger 에이전트를 자동으로 씀

# 명시적 호출
"reviewer 에이전트로 auth.js 리뷰해줘"
"tester 에이전트로 userService 테스트 만들어줘"

# /agents 명령으로 현재 에이전트 목록 확인
/agents
```

### 5-3. 사용 가능한 명령어 목록 확인

```bash
# Claude Code에서 / 만 입력하면 목록 나옴
/
```

## PART 6 — 실전 워크플로우

```
[새 기능 개발 시작]
       ↓
단일 Claude Code로 구현
       ↓
버그 발생?
  예 → /debug [에러 내용]  또는  "debugger 에이전트로 찾아줘"
       ↓
기능 완성
       ↓
/review [파일명]          ← PR 전 필수 체크
       ↓
테스트 없음?
  예 → /test [함수명]
       ↓
/commit                   ← 안전 체크 + 자동 메시지
       ↓
코드 길어짐?
  예 → /refactor [파일명]
       ↓
배포
```

## PART 7 — 글로벌 설정 (모든 프로젝트에서 사용)

특정 프로젝트가 아니라 어디서나 쓰고 싶으면:

```bash
# 글로벌 에이전트 설정
~/.claude/agents/debugger.md
~/.claude/agents/reviewer.md

# 글로벌 명령어 설정
~/.claude/commands/commit.md
~/.claude/commands/review.md

# 글로벌 CLAUDE.md (개인 선호 설정)
~/.claude/CLAUDE.md
```

`~/.claude/CLAUDE.md` 예시:


## PART 8 — 자주 묻는 것들

**Q. Commands와 Agents 중 뭘 먼저 만들어야 하나요?**

Commands부터 시작하세요. 더 단순하고 즉시 효과를 확인할 수 있어요.

**Q. Subagent description을 어떻게 써야 잘 작동하나요?**

"언제 호출해야 하는지"를 구체적으로 쓰세요. 키워드와 상황을 명시할수록 자동 위임이 잘 돼요.

**Q. 에이전트 파일 수정하면 바로 적용되나요?**

세션 재시작이 필요하거나, `/agents`를 실행하면 즉시 로드돼요.

**Q. 몇 개까지 만드는 게 좋나요?**

실전 경험상 3~4개가 한계예요. 그 이상이면 오히려 본인 생산성이 떨어질 수 있어요.

**Q. 명령어 파일에 `allowed-tools`를 왜 쓰나요?**

쓸 도구를 명시하면 매번 권한 승인 팝업이 안 뜨고 자동으로 실행돼요.

**Q. `disable-model-invocation: true`는 뭔가요?**

Claude가 자동으로 이 명령어를 호출하지 못하게 막는 설정이에요. 배포나 커밋처럼 Claude가 멋대로 실행하면 안 되는 작업에 써요.
