# 장소 조회하기 ( CRUD : R )

```jsx
// 특정 장소 ID에 대한 정보를 반환하는 함수입니다.
const getPlacesById = async (req, res, next) => {
  // 요청 파라미터에서 장소 ID를 추출합니다.
  const placeId = req.params.pid

  let places

  try {
    places = await Place.findById(placeId)
  } catch (err) {
    const error = new HttpError('오류발생 장소를 찾지 못했습니다', 500)
    return next(error)
  }

  // 만약 장소를 찾지 못했다면 HttpError를 발생시키지 않고, next 함수를 통해 에러를 전달합니다.
  if (!places) {
    const error = new HttpError('유효한 장소 아이디를 찾지 못했습니다', 404)
    return next(error)
  }

  // 찾은 장소를 JSON 형태로 응답합니다.
  res.json({ places: places.toObject({ getters: true }) })
}
```

```jsx
두개의 오류 처리가 있는 이유는 GET 요청에 문제가 생겼을때와

DB 에 id 가 없는 경우 이렇게 2가지다

findById는 save 메서드와는 작동 방식이 약간 다르다

findById는 프로미스를 반환하지 않는다

만약 진짜 프로미스가 필요하다면 findById 뒤에 exec를 호출하면 된다 ( 여기선 필요하지 않음 )

( 왜냐하면 Mongoose 고유 기능인 findById 덕에 async await를 사용할 수 있으니까 그래도 진짜 프로미스는 아님 )

여기서 문제가 2가지 있었는데

1. 지금 작업하고 있는 객체 places는 결국 Mongoose 고유 객체이다 그래서 이 객체에 여러 특별한 Mongoose 메서드가 적용되는 거

데이터를 생성할 때나 Mongoose로 작업할 때는 괜찮다

하지만 응답이 돌아왔을 때 객체를 일반 JavaScript 객체로 변환한다면

사용하기가 더 쉬워진다

해결법 : place 객체를 일반 JavaScript 객체로 바꾼다 toObject 메서드를 객체에 추가하기만 하면 된다

2. _id 부분이다 저기서 밑줄을 없애줄 것이다 크게 문제 될 부분은 아니지만

프로퍼티를 깔끔히 유지하는 게 좋으니까 _를 빼고 id가 되게 해주는게 좋다

대개 이런 getter는 객체를 호출할 때 없어지는데 getter가 true면 그대로 남게 되면서
```

```jsx
// 특정 사용자 ID에 대한 장소 정보를 반환하는 함수입니다.
const getPlaceByUserId = async (req, res, next) => {
  // 요청 파라미터에서 사용자 ID를 추출합니다.
  const userId = req.params.uid

  let place
  try {
    place = await Place.find({ creator: userId })
  } catch (err) {
    const error = new HttpError('장소를 불러오는데 실패했습니다', 500)
    return next(error)
  }

  // 만약 사용자를 찾지 못했다면 HttpError를 발생시킵니다.
  if (!place || place.length === 0) {
    return next(new HttpError('유저를 찾을 수 없습니다', 404))
  }

```

```jsx
이번엔 findById 메서드를 쓰지 않는다 대신 find 메서드를 쓴다

find는 findById와 비슷하게 작동한다 프로미스(Promise)는 반환하지 않지만

프로미스를 원한다면 exec을 사용할 수 있다 또한 async await나 catch도 사용할 수 있다

그리고 Mongoose 고유 기능으로 프로미스를 쓸 수 있다 진짜 프로미스는 아니지만 비동기식 작업이 가능한 거

res.json({ place: place.map(place => place.toObject({ getters: true })) }); 는 Mongoose에서 조회한 데이터를 클라이언트에게 응답할 때,

표준적인 JSON 형식으로 변환하고 필요한 가공을 적용하기 위해 사용된다.

클라이언트가 받는 데이터가 Mongoose의 내부 표현이 아니라 일반적인 JavaScript 객체로 되어 있어야 하며,

이를 위해 toObject() 메서드를 사용한다.

( map을 사용함으로써 Mongoose에서 반환된 배열의 각 요소를 일괄적으로 변환하고,

	이를 통해 클라이언트에게 필요한 형태로 데이터를 제공할 수 있다. )
```

## toObject() 를 꼭 사용해 주어야 하나?

```jsx
toObject() 메서드는 몽구스(Mongoose)의 Document에서 JavaScript 객체로 변환하는 메서드이다.

이 메서드를 사용하는 이유는 주로 몽구스 Document의 특수한 기능과 메타데이터를 제거하고 순수한 JavaScript 객체를 얻기 위함이다.

그러나 toObject()를 사용하지 않아도 몽구스 Document를 JavaScript 객체로 사용할 수 있다.

몽구스 Document는 사실상 JavaScript 객체와 매우 유사하게 동작하며, 일반적인 경우에는 toObject()를 사용하지 않아도 무방하다.

몽구스는 Document를 반환할 때 자동으로 JavaScript 객체로 변환해주기 때문이다.

따라서 toObject()를 사용할지 여부는 개발자의 선호 및 상황에 따라 다를 수 있다.

만약 특별한 이유가 없다면, 몽구스 Document 그대로를 사용하는 것이 편리하며 코드도 더 간결해진다.
```

## **MongoDB에서의 find 메서드:**

```jsx
MongoDB에서 find 메서드는 쿼리에 해당하는 문서를 찾아주는 역할을 한다.

find 메서드는 커서(Cursor)를 반환한다.

커서는 쿼리 결과를 가리키는 포인터로, 문서가 많은 경우에는 커서를 사용하여 효율적으로 결과를 처리할 수 있다.

예를 들어, 수백 개의 문서가 있다면 한 번에 모든 데이터를 가져오는 것은 부하를 일으킬 수 있다.

따라서 커서를 사용하여 필요한 만큼의 데이터를 일부분씩 가져올 수 있다.

* 몽고 DB 만 단독으로 사용할 일은 거의 없을것 참고만
```

```jsx
// MongoDB에서 find 메서드 사용 예시
const cursor = db.collection('places').find({ creator: userId })

// 커서를 이용한 반복 처리
while (cursor.hasNext()) {
  const document = cursor.next()
  // 문서(document)에 대한 처리
}
```

## **Mongoose에서의 find 메서드:**

```jsx
Mongoose에서도 find 메서드를 사용할 수 있다.

Mongoose의 find 메서드는 MongoDB와 달리 배열을 직접 반환한다.

Mongoose에서는 find 메서드를 통해 쿼리에 해당하는 모든 문서를 배열로 얻을 수 있다.

하지만, Mongoose에서도 find 메서드에 cursor 속성을 추가하여 커서를 얻을 수 있다.
```

```jsx
// Mongoose에서 find 메서드 사용 예시
const places = await Place.find({ creator: userId })

// 커서를 이용한 반복 처리 (Mongoose)
const cursor = Place.find({ creator: userId }).cursor()
for (let doc = await cursor.next(); doc != null; doc = await cursor.next()) {
  // 문서(doc)에 대한 처리
}
```

```jsx
이 코드는 특정 사용자가 만든 모든 장소를 찾아와서 하나씩 처리하는 과정을 나타낸다

.cursor(): Mongoose의 find 메서드에 .cursor()를 추가하여 커서(cursor)를 생성한다.

이 커서는 데이터를 반복적으로 처리하기 위한 도구이다.

for (let doc = await cursor.next(); doc != null; doc = await cursor.next()) { ... }

let doc = await cursor.next(): 커서를 이용하여 다음 문서를 가져온다. await를 사용하여 비동기적으로 처리한다.

doc != null: 가져온 문서가 없을 때까지 반복한다.

doc = await cursor.next(): 다음 문서를 가져와서 doc 변수에 저장한다.
```

## 포인터란?

```jsx
포인터:

포인터는 메모리 내의 특정 위치를 가리키는 변수이다.

메모리는 여러 칸으로 나뉘어져 있는데, 각 칸은 주소를 가지고 있다.

포인터는 이러한 주소를 저장하고 있어서 해당 주소가 가리키는 메모리 위치에 저장된 값을 참조할 수 있다.

커서와 함께:

커서는 데이터를 순회하거나 검색할 때 사용되는 도구로, 포인터의 개념을 포함하고 있다.

MongoDB의 find 메서드에서 반환되는 커서는 데이터 집합을 가리키는 포인터로 이해할 수 있다.

이 커서를 사용하면 데이터를 효과적으로 탐색하거나 가져올 수 있다.

예시로 설명:

가령, 여러 국가의 수도와 인구를 나타내는 데이터가 있다고 가정해 보자.

이 데이터는 메모리의 여러 칸에 저장되어 있다. 여기서 포인터는 특정 국가의 정보가 어디에 있는지 가리키는 것이다.

커서는 이 데이터들을 차례대로 탐색하면서, 특정 국가의 정보에 접근할 수 있도록 도와주는 역할을 한다.

커서를 통해 현재 위치를 알 수 있고, 그 위치에서 데이터를 가져오거나 조작할 수 있다.

결국, 포인터와 커서는 데이터를 효과적으로 다루기 위한 도구로 생각할 수 있다.

MongoDB에서의 find 메서드는 이러한 원리를 활용하여 데이터를 조회하고 가져올 때 사용되는데,

Mongoose에서는 find 메서드를 사용할 때 커서를 직접 다루지 않아도 결과를 배열로 얻을 수 있다.
```

# 장소 업데이트하기 ( CRUD : U )

```jsx
const updatePlaceById = async (req, res, next) => {
  const errors = validationResult(req)
  if (!errors.isEmpty()) {
    console.log(errors)
    throw new HttpError(`${errors.errors[0].path}는 비어있을 수 없습니다`, 422)
  }
  // 요청에서 필요한 데이터를 추출합니다.
  const { title, description } = req.body
  const placeId = req.params.pid

  let place
  try {
    place = await Place.findById(placeId)
  } catch (err) {
    const error = new HttpError('업데이트 실패', 500)
    return next(error)
  }

  place.title = title
  place.description = description

  try {
    await place.save()
  } catch (err) {
    const error = new HttpError('문제가 발생하였습니다 업데이트 할 수 없습니다', 500)
```

# **Mongoose에서의 트랜잭션**

```jsx
트랜잭션은 데이터베이스 작업을 논리적인 단위로 묶어,

모든 작업이 성공적으로 수행될 때만 변경 사항을 커밋하고, 그렇지 않은 경우에는 변경 사항을 롤백하는 개념이다.
```

```jsx
const mongoose = require('mongoose');

mongoose.connect('mongodb://localhost:27017/mydatabase', { useNewUrlParser: true, useUnifiedTopology: true });
const connection = mongoose.connection;

connection.on('error', console.error.bind(console, 'MongoDB connection error:'));
connection.once('open', () => {
  console.log('Connected to MongoDB');

  // 트랜잭션 시작
  const session = await mongoose.startSession();
  session.startTransaction();

  try {
    // 트랜잭션 내에서 수행할 작업
    const result1 = await SomeModel.create({ name: 'Example' });
    const result2 = await AnotherModel.findOneAndUpdate({ field: 'value' }, { $set: { updatedField: 'updatedValue' } });

    // 트랜잭션 커밋
    await session.commitTransaction();
    session.endSession();

    console.log('Transaction committed successfully');
  } catch (error) {
    // 트랜잭션 롤백
    await session.abortTransaction();
    session.endSession();

    console.error('Transaction aborted:', error);
  }
});
```

```jsx
Mongoose에서 트랜잭션을 사용하는 방법을 알아보겠다. 트랜잭션은 여러 쿼리를 묶어서 원자성을 보장하는데 사용된다

* 이 예제에서 SomeModel 및 AnotherModel는 단순히 예시일 뿐이며, 실제 데이터 모델로 대체해야 한다.
```

## 트랜잭션 특징

```jsx
트랜잭션의 특징:

원자성(Atomicity): 트랜잭션이 원자적인 단위로 수행되어야 하는데,

이는 모든 연산이 전부 성공하거나 전부 실패하여 롤백되어야 함을 의미한다.

마치 원자가 원자력 반응에서 나오는 에너지처럼 트랜잭션도 전체가 하나의 덩어리로 취급되어야 한다.

따라서 중간에 어떠한 부분이라도 실패하면 트랜잭션 전체가 롤백되어 데이터 일관성을 유지한다.

일관성(Consistency): 트랜잭션이 수행되기 전과 후에 데이터베이스는 항상 일관된 상태를 유지해야 한다.

이는 트랜잭션이 완료된 후 데이터베이스가 일관된 규칙을 따라야 함을 의미한다.

예를 들어, 트랜잭션이 사용자 계좌 이체를 수행하는 경우, 이체 전후에도 계좌 잔액 등이 일관된 상태여야 한다.

격리성(Isolation): 트랜잭션은 서로 간에 영향을 미치지 않고 독립적으로 실행되어야 한다.

한 트랜잭션이 진행 중일 때, 다른 트랜잭션의 작업이 현재 트랜잭션에 영향을 주어서는 안 된다.

격리성은 동시에 여러 트랜잭션이 수행될 때 각 트랜잭션이 서로 간섭하지 않도록 하는 원칙이다.

지속성(Durability): 트랜잭션이 성공적으로 완료되면 그 결과가 영원히 지속되어야 한다.

즉, 시스템이나 디스크 장애가 발생하더라도 트랜잭션이 성공적으로 완료된 데이터는 계속해서 보존되어야 한다.

지속성은 데이터베이스 시스템이 신뢰성 있게 데이터를 저장하고 보존해야 함을 강조하는 원칙이다.
```

## **트랜잭션 시작과 종료:**

```jsx
1. mongoose.startSession()을 사용하여 세션을 시작한다.

2. session.startTransaction()을 호출하여 트랜잭션을 시작한다.

3. 성공적으로 모든 작업이 수행된 후 session.commitTransaction()을 호출하여 트랜잭션을 커밋한다.

4. 예외가 발생하면 session.abortTransaction()을 호출하여 트랜잭션을 롤백한다.

5. session.endSession()을 사용하여 세션을 종료한다.
```

  ## 몽구스 세션 사용

  ```jsx
  Mongoose에서 세션을 사용하는 방법을 알아보겠다. 세션은 데이터베이스 작업 간에 상태를 유지하고자 할 때 사용된다:
  ```

  ```jsx
  const mongoose = require('mongoose')

  mongoose.connect('mongodb://localhost:27017/mydatabase', {
    useNewUrlParser: true,
    useUnifiedTopology: true,
  })
  const connection = mongoose.connection

  connection.on('error', console.error.bind(console, 'MongoDB connection error:'))
  connection.once('open', () => {
    console.log('Connected to MongoDB')

    // 세션 생성
    const session = mongoose.startSession()

    // 세션 내에서 수행할 작업
    session
      .withTransaction(async () => {
        const result1 = await SomeModel.create({ name: 'Example' })
        const result2 = await AnotherModel.findOneAndUpdate(
          { field: 'value' },
          { $set: { updatedField: 'updatedValue' } }
        )

        console.log('Transaction committed successfully')
      })
      .then(() => {
        // 세션 종료
        session.endSession()
      })
      .catch((error) => {
        console.error('Transaction aborted:', error)

        // 세션 종료
        session.endSession()
      })
  })
  ```

  ```jsx
  세션 생성과 종료:

  mongoose.startSession()을 사용하여 세션을 생성한다.

  작업이 완료된 후에는 session.endSession()을 호출하여 세션을 종료한다.

  세션 내에서의 작업:

  세션 내에서는 여러 데이터베이스 작업을 수행할 수 있다.

  세션은 일반적으로 트랜잭션과 함께 사용되며, session.withTransaction()을 사용하여 트랜잭션 내에서 세션을 처리할 수 있다.

  세션 내에서 예외가 발생하면, 해당 세션은 종료되고 롤백된다.
  ```

  ## 트랜젝션으로 충분한데 왜 세션도 사용하는가?

  ```jsx
  트랜잭션만 사용해도 데이터베이스의 일관성과 무결성을 유지하는 데는 일부 측면에서 충분할 수 있다.

  그러나 세션은 특히 여러 사용자 간의 작업이 동시에 발생하는 경우에 추가적인 이점을 제공한다
  ```

  ```jsx
  트랜잭션:

  트랜잭션은 여러 데이터베이스 작업을 논리적으로 묶어서 원자성을 보장하고, 일관성과 무결성을 지키기 위한 주요 메커니즘이다.

  주로 한 번에 여러 데이터베이스 작업을 실행하고자 할 때 사용된다.

  여러 작업 간에 원자성을 유지하고, 하나의 작업이 실패하면 모든 작업을 롤백하는 데에 중점을 둔니다.

  세션:

  세션은 특히 동시성을 다루거나 사용자 간에 상태를 유지해야 할 때 유용하다.

  여러 사용자가 동시에 데이터베이스에 접근하는 경우, 각 사용자는 자신만의 세션을 유지하여 다른 사용자의 작업에 영향을 받지 않는다.

  세션은 특정 사용자의 작업 간에 일관성을 유지하고, 작업이 완료되면 세션을 종료하여 다른 사용자와의 간섭을 최소화한다.

  세션을 사용하는 이유:

  사용자 독립성: 각 세션은 독립적이기 때문에, 여러 사용자가 동시에 작업해도 서로 영향을 주지 않는다.

  상태 유지: 세션을 사용하면 특정 사용자의 상태를 유지하고, 사용자 간의 작업을 분리할 수 있다.

  동시성 제어: 여러 사용자가 동시에 작업하는 환경에서, 세션은 충돌을 최소화하고 데이터 일관성을 보장한다.
  ```

## 예제

### **두 개의 도큐먼트를 업데이트하는 트랜잭션:**

```jsx
const mongoose = require('mongoose')

// MongoDB 연결 설정
mongoose.connect('mongodb://localhost:27017/mydatabase', {
  useNewUrlParser: true,
  useUnifiedTopology: true,
})
const db = mongoose.connection

// 스키마 정의
const userSchema = new mongoose.Schema({
  username: String,
  balance: Number,
})

// 모델 생성
const User = mongoose.model('User', userSchema)

// 트랜잭션 실행
async function updateBalanceWithTransaction(userId1, userId2, amount) {
  const session = await mongoose.startSession()
  session.startTransaction()

  try {
    const options = { session }
    // 첫 번째 사용자의 잔고 업데이트
    await User.findByIdAndUpdate(userId1, { $inc: { balance: -amount } }, options)
    // 두 번째 사용자의 잔고 업데이트
    await User.findByIdAndUpdate(userId2, { $inc: { balance: amount } }, options)

    // 트랜잭션 커밋
    await session.commitTransaction()
  } catch (error) {
    // 에러 발생 시 롤백
    await session.abortTransaction()
  } finally {
    // 세션 닫기
    session.endSession()
  }
}

// 사용 예시
updateBalanceWithTransaction('userId1', 'userId2', 100)
```

### **도큐먼트 삽입과 업데이트를 수행하는 트랜잭션:**

```jsx
const mongoose = require('mongoose')

// MongoDB 연결 설정
mongoose.connect('mongodb://localhost:27017/mydatabase', {
  useNewUrlParser: true,
  useUnifiedTopology: true,
})
const db = mongoose.connection

// 스키마 정의
const productSchema = new mongoose.Schema({
  name: String,
  price: Number,
})

// 모델 생성
const Product = mongoose.model('Product', productSchema)

// 트랜잭션 실행
async function insertAndUpdateWithTransaction(newProduct, productIdToUpdate, newPrice) {
  const session = await mongoose.startSession()
  session.startTransaction()

  try {
    const options = { session }
    // 새로운 제품 삽입
    await Product.create([newProduct], options)
    // 제품 가격 업데이트
    await Product.findByIdAndUpdate(productIdToUpdate, { $set: { price: newPrice } }, options)

    // 트랜잭션 커밋
    await session.commitTransaction()
  } catch (error) {
    // 에러 발생 시 롤백
    await session.abortTransaction()
  } finally {
    // 세션 닫기
    session.endSession()
  }
}

// 사용 예시
insertAndUpdateWithTransaction({ name: 'New Product', price: 50 }, 'productId123', 60)
```

# 장소 삭제 및 사용자로부터 제거하기

```jsx
const deletePlaceById = async (req, res, next) => {
  // 요청 파라미터에서 장소의 ID를 가져옵니다.
  const placeId = req.params.pid
  let place

  // 장소를 찾아서 해당 ID로 검색한 결과를 가져옵니다.
  try {
    place = await Place.findById(placeId).populate('creator')
  } catch (err) {
    // 에러가 발생하면 500 상태 코드와 함께 에러 메시지를 반환합니다.
    const error = new HttpError('문제발생 삭제에 실패했습니다', 500)
    return next(error)
  }

  // 검색된 장소가 없으면 404 상태 코드와 함께 에러 메시지를 반환합니다.
  if (!place) {
    const error = new HttpError('장소 id 를 찾지 못하였습니다', 404)
    return next(error)
  }

  // MongoDB 세션을 사용하여 트랜잭션을 시작합니다.
  try {
    const sess = await mongoose.startSession()
    sess.startTransaction()

    // 검색된 장소를 삭제합니다.
    await place.deleteOne({ session: sess })

    // 해당 장소를 생성한 사용자의 데이터에서 해당 장소를 제거합니다.
    place.creator.places.pull(place)

    // 수정된 사용자 데이터를 저장합니다.
    await place.creator.save({ session: sess })

    // 트랜잭션을 커밋하여 변경 사항을 영구적으로 반영합니다.
    await sess.commitTransaction()
  } catch (err) {
    // 트랜잭션 도중 에러가 발생하면 500 상태 코드와 함께 에러 메시지를 반환합니다.
    const error = new HttpError('삭제에 실패했습니다', 500)
    return next(error)
  }

  // 모든 작업이 성공적으로 완료되면 200 상태 코드와 함께 성공 메시지를 반환합니다.
  res.status(200).json({ message: '삭제성공' })
}
```

```jsx
사용자 컬렉션에서 해당 장소가 등록되어 있는지 확인하고, 사용자 문서를 수정해야 한다.

이를 위해 populate 메서드를 사용하며, 관계 설정이 필요한데, 이미 user.js 파일에서는

ref: 'Place'로, place.js 파일에서는 ref: 'User'로 설정되어 있어야 한다.

장소의 존재 여부 확인: 장소 ID의 존재 여부를 확인하는 코드를 추가한다.

장소가 없으면 '장소 id 를 찾지 못하였습니다' 메시지와 함께 오류 코드 404를 반환한다.

트랜잭션 사용: 장소를 삭제할 때와 동일한 접근법을 사용하여 사용자 문서에서 장소 ID를 삭제하는 코드를 작성한다.

이때 remove와 pull을 사용하며, 트랜잭션은 세션을 시작하고 해당 조건이 맞을 때에만 실행된다.

세션 및 트랜잭션: 코드에서 세션을 시작하고 트랜잭션을 실행하는 부분을 작성한다.

세션은 startSession()을 사용하고, 트랜잭션은 startTransaction()을 사용한다.

세션을 참조하여 삭제된 장소 정보를 사용자 문서에서도 수정할 수 있도록 한다.
```
