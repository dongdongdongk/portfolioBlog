# { 마우스 커서 제어 시스템 구현 강의 정리 }

이 강의는 게임 중 마우스 커서를 보이게 하고, 플레이어가 죽으면 숨기는 기능을 구현하는 내용입니다.

---

## 🎯 해결하려는 문제

### 문제 상황

```
게임 시작 → 뷰포트 클릭 → 마우스 커서 사라짐 ❌
→ 타워를 조준하기 매우 어려움!
```

**왜 이런 일이 발생하나?**

- 언리얼 엔진은 기본적으로 게임이 시작되면 마우스 커서를 숨김
- 이유: 일반적인 FPS나 3인칭 게임에서는 커서가 필요 없기 때문
- 하지만 우리 게임은 마우스로 조준하므로 커서가 **필수**

---

## 📋 구현 단계

### 1단계: 플레이어 컨트롤러 블루프린트 생성

**왜 필요한가?**

- 마우스 커서 설정은 **플레이어 컨트롤러**가 관리함
- 기본 플레이어 컨트롤러는 수정할 수 없음
- 따라서 우리만의 커스텀 플레이어 컨트롤러 필요

**생성 방법:**

```
1. 블루프린트 폴더에서 우클릭
2. "플레이어 컨트롤러" 상속 클래스 생성
3. 이름: "BP_BattleBlasterPlayerController"
```

**결과:** 화살표 → 십자선 조준점으로 변경! 🎯

## 💡 추가 요구사항: 죽으면 커서 숨기기

### 왜 이 기능이 필요한가?

```
플레이어가 죽은 후:
- 조준할 필요 없음
- 커서가 계속 보이면 이상함
- 게임이 끝났다는 느낌을 주기 위해 커서 숨김
```

### C++로 제어하는 이유

**블루프린트 vs C++:**

- 블루프린트: 항상 커서를 보여주거나 숨기는 **고정 설정**
- C++: 게임 상황에 따라 **동적으로** 커서를 보이거나 숨김

---

## 🔧 C++ 구현

### bShowMouseCursor 변수 찾기

**탐색 과정:**

```
1. 플레이어 컨트롤러 블루프린트에서 확인
   → "Show Mouse Cursor" 변수 이름 확인

2. Visual Studio에서 검색
   → "ShowMouseCursor" 입력
   → 자동완성: "bShowMouseCursor" 발견!
```

**왜 'b' 접두사?**

- 언리얼 엔진 명명 규칙
- `b` = Boolean(부울) 변수
- 예: `bShowMouseCursor`, `bIsAlive`, `bCanFire`

---

### SetPlayerEnabled 함수 수정

**방법 1: 처음 시도한 코드 (작동은 하지만 길다)**

```cpp
void ATank::SetPlayerEnabled(bool Enabled)
{
    if (PlayerController)
    {
        if (Enabled)  // 입력 켜기
        {
            EnableInput(PlayerController);
            PlayerController->bShowMouseCursor = true;  // 커서 보이기
        }
        else  // 입력 끄기
        {
            DisableInput(PlayerController);
            PlayerController->bShowMouseCursor = false; // 커서 숨기기
        }
    }
}
```

**문제점:**

- 같은 로직을 두 곳에서 반복
- 코드가 길어짐

---

**방법 2: 개선된 코드 (더 짧고 깔끔)**

```cpp
void ATank::SetPlayerEnabled(bool Enabled)
{
    if (PlayerController)
    {
        if (Enabled)
        {
            EnableInput(PlayerController);
        }
        else
        {
            DisableInput(PlayerController);
        }

        // 핵심: Enabled 값을 그대로 사용!
        PlayerController->bShowMouseCursor = Enabled;
    }
}
```

**왜 이렇게 하면 되나?**

```
Enabled = true  → bShowMouseCursor = true  → 커서 보임
Enabled = false → bShowMouseCursor = false → 커서 숨김

→ 조건문 없이 한 줄로 처리 가능!
```

## 💡 핵심 개념 정리

### 1. 블루프린트 vs C++ 제어

**블루프린트 설정:**

- 장점: 빠르고 직관적
- 단점: **고정 값**만 설정 가능

**C++ 제어:**

- 장점: **동적으로** 값 변경 가능
- 단점: 코드 작성 필요

### 2. 변수 접두사 규칙

```cpp
bool bShowMouseCursor;    // b = Boolean
float fSpeed;             // f = Float
int32 iCount;             // i = Integer
AActor* ActorPtr;         // * = Pointer
```

### 3. 효율적인 코드 작성

**비효율:**

```cpp
if (condition) {
    variable = true;
} else {
    variable = false;
}
```

**효율적:**

```cpp
variable = condition;  // 조건 결과를 직접 대입!
```

## 📋 구현 과정

### 1단계: 부울 변수 생성

```cpp
void ABattleBlasterGameMode::ActorDied(AActor* DeadActor)
{
    bool IsGameOver = false;  // 게임이 끝났는가?
    bool IsVictory = false;   // 이겼는가?
}
```

**두 변수의 차이:**

- `IsGameOver`: 게임 종료 여부 (이기든 지든 끝났으면 true)
- `IsVictory`: 승리 여부 (이겼을 때만 true)

---

### 2단계: 조건에 따라 값 설정

```cpp
if (DeadActor == Tank)
{
    Tank->HandleDestruction();
    IsGameOver = true;   // 플레이어 죽음 → 게임 오버
    // IsVictory는 false 그대로 → 패배!
}
else
{
    ATower* DeadTower = Cast<ATower>(DeadActor);
    if (DeadTower)
    {
        DeadTower->HandleDestruction();
        TowerCount--;

        if (TowerCount == 0)  // 마지막 타워 파괴
        {
            IsGameOver = true;   // 게임 오버
            IsVictory = true;    // 승리!
        }
    }
}
```

**로직 정리:**

```
플레이어 죽음 → IsGameOver=true, IsVictory=false → 패배
마지막 타워 파괴 → IsGameOver=true, IsVictory=true → 승리
```

## 🔧 삼항 연산자 (Ternary Operator)

### 기본 문법

```cpp
조건 ? 참일_때_값 : 거짓일_때_값;
```

### if-else vs 삼항 연산자

**방법 1: if-else 문 (전통적)**

```cpp
FString GameOverString;

if (IsVictory)
{
    GameOverString = "Victory!";
}
else
{
    GameOverString = "Defeat!";
}
```

**방법 2: 삼항 연산자 (간결)**

```cpp
FString GameOverString = IsVictory ? "Victory!" : "Defeat!";
```

**동작 원리:**

```
IsVictory가 true → "Victory!" 반환
IsVictory가 false → "Defeat!" 반환
```

---

### 삼항 연산자 구조 분석

```cpp
GameOverString = IsVictory ? "Victory!" : "Defeat!";
                 ↑          ↑           ↑
                 조건      참일 때     거짓일 때
```

---

## 💡 삼항 연산자 장단점

### 장점 ✅

- 매우 간결함 (1줄로 처리)
- 가독성 좋음 (단순한 조건일 때)
- 값을 바로 반환

### 단점 ❌

- 복잡한 로직에는 부적합
- 여러 줄 코드 블록 사용 불가
- 단일 표현식만 가능

**언제 사용?**

```cpp
// ✅ 좋은 사용: 간단한 값 선택
int max = (a > b) ? a : b;
FString status = IsAlive ? "Alive" : "Dead";

// ❌ 나쁜 사용: 복잡한 로직
result = (condition) ?
    (complexCalculation() && anotherCheck()) :
    (otherComplexLogic() || yetAnotherCheck());
```

## 📋 구현 단계

### 1단계: 지연 시간 변수 생성

**BattleBlasterGameMode.h:**

```cpp
class ABattleBlasterGameMode : public AGameModeBase
{
    UPROPERTY(EditAnywhere)
    float GameOverDelay = 3.0f;  // 재시작 전 대기 시간 (초)

    void OnGameOverTimerTimeout();  // 타이머 종료 시 호출될 함수
};
```

**왜 변수로 만드나?**

- `EditAnywhere`: 블루프린트에서 값 조정 가능
- 예: 3초가 너무 짧으면 5초로 변경 가능
- 하드코딩보다 유연함

---

### 2단계: 타이머 설정하기

**ActorDied() 함수 내부:**

```cpp
if (IsGameOver)
{
    FString GameOverString = IsVictory ? "Victory!" : "Defeat!";
    UE_LOG(LogTemp, Display, TEXT("Game Over: %s"), *GameOverString);

    // 타이머 설정
    FTimerHandle GameOverTimerHandle;  // 1. 타이머 핸들 생성
    GetWorldTimerManager().SetTimer(   // 2. 타이머 설정
        GameOverTimerHandle,            // 핸들 (타이머 식별자)
        this,                           // 어떤 객체의 함수를 호출할지
        &ABattleBlasterGameMode::OnGameOverTimerTimeout,  // 호출할 함수
        GameOverDelay,                  // 대기 시간 (3초)
        false                           // 반복 여부 (false = 한 번만)
    );
}
```

---

### 타이머 파라미터 상세 설명

```cpp
GetWorldTimerManager().SetTimer(
    GameOverTimerHandle,     // 1. 핸들: 타이머를 추적하는 ID
    this,                    // 2. 타겟: 이 게임모드 객체
    &ABattleBlasterGameMode::OnGameOverTimerTimeout,  // 3. 함수 주소
    GameOverDelay,           // 4. 지연 시간: 3.0초
    false                    // 5. 반복: false = 한 번만 실행
);
```

**각 파라미터 역할:**

1. **FTimerHandle**: 타이머를 식별하는 "표찰"
2. **this**: "이 게임모드 안의 함수를 실행해줘"
3. **함수 주소**: `&클래스명::함수명` 형식
4. **지연 시간**: float 값 (초 단위)
5. **반복 여부**:
   - `true` = 계속 반복 (타워의 발사 타이머처럼)
   - `false` = 한 번만 실행 (게임 재시작용)

---

### 3단계: 타이머 콜백 함수 구현

```cpp
void ABattleBlasterGameMode::OnGameOverTimerTimeout()
{
    // 1. 현재 레벨 이름 가져오기
    FString CurrentLevelName = UGameplayStatics::GetCurrentLevelName(GetWorld());

    // 2. 해당 레벨 다시 열기 (재시작)
    UGameplayStatics::OpenLevel(GetWorld(), *CurrentLevelName);
}
```

## 🔍 핵심 함수 설명

### 1. GetCurrentLevelName()

```cpp
FString CurrentLevelName = UGameplayStatics::GetCurrentLevelName(GetWorld());
```

**동작:**

- 현재 플레이 중인 레벨의 이름을 문자열로 반환
- 예: `"MainLevel"`, `"TestMap"`, `"Level_01"`

**왜 필요한가?**

- 레벨 이름을 하드코딩하면 레벨 이름이 바뀔 때마다 코드 수정 필요
- 자동으로 가져오면 어떤 레벨에서도 작동

---

### 2. OpenLevel()

```cpp
UGameplayStatics::OpenLevel(GetWorld(), *CurrentLevelName);
```

**파라미터:**

- `GetWorld()`: 현재 월드 객체
- `CurrentLevelName`: 열 레벨 이름 (FString → FName 변환)
- **연산자의 역할:**

```cpp
FString CurrentLevelName;        // 문자열 타입
*CurrentLevelName;               // FName 타입으로 변환

// OpenLevel은 FName을 요구하므로 * 필요!
```

**동작:**

- 지정된 레벨을 언로드하고 다시 로드
- 모든 액터가 초기 상태로 리셋됨

## 💡 타이머 vs 즉시 재시작

### 즉시 재시작하면 안 되는 이유

```cpp
// ❌ 나쁜 방식: 즉시 재시작
if (IsGameOver)
{
    UGameplayStatics::OpenLevel(GetWorld(), *CurrentLevelName);
}
```

**문제점:**

1. 플레이어가 죽는 순간 바로 재시작 → 너무 갑작스러움
2. 승리/패배 메시지를 볼 시간이 없음
3. 사용자 경험(UX)이 나쁨

### 타이머 사용의 장점

```cpp
// ✅ 좋은 방식: 3초 대기 후 재시작

```

**장점:**

1. 죽는 애니메이션을 볼 시간 제공
2. 승리/패배를 인지할 시간
3. 자연스러운 흐름

## 📝 요약

**이 강의에서 배운 것:**

1. **타이머 시스템**: 일회성 타이머 설정 (`false` 파라미터)

## 🎯 해결하려는 문제

### 현재 상황의 문제점

```
승리 → 같은 레벨 재시작 ❌
패배 → 같은 레벨 재시작 ✅

문제: 승리했는데 왜 같은 레벨을 다시 플레이해야 하나?
→ 다음 레벨로 넘어가야 함!
```

### 게임 모드로는 해결 불가능한 이유

```cpp
// 게임 모드 안에서 이렇게 하면 안 될까?
int32 CurrentLevelIndex = 1;

void OnGameOverTimerTimeout()
{
    if (IsVictory)
    {
        CurrentLevelIndex++;  // 다음 레벨로!
        // 레벨 2 로드...
    }
}
```

**문제 발생:**

```
1. 레벨 1 시작 → CurrentLevelIndex = 1
2. 승리! → CurrentLevelIndex = 2
3. OpenLevel() 호출 → 레벨 2 로드
4. 새 게임 모드 생성 → CurrentLevelIndex = 1로 리셋! ❌
```

**핵심 문제: 게임 모드는 레벨이 바뀔 때마다 새로 생성됨!**

### 1단계: IsVictory를 멤버 변수로 변경

- 타이머 콜백 함수에서 접근 불가능
- 멤버 변수로 만들어서 클래스 전체에서 사용

**BattleBlasterGameMode.h:**

```cpp
class ABattleBlasterGameMode : public AGameModeBase
{
    GENERATED_BODY()

private:
    bool IsVictory = false;  // 멤버 변수로 승격!

public:
    void ActorDied(AActor* DeadActor);
    void OnGameOverTimerTimeout();
};
```

**ActorDied() 수정:**

```cpp
void ABattleBlasterGameMode::ActorDied(AActor* DeadActor)
{
    // bool IsVictory = false; ← 삭제! 이제 멤버 변수 사용

    if (DeadActor == Tank)
    {
        IsVictory = false;  // 멤버 변수에 저장
    }
    else if (TowerCount == 0)
    {
        IsVictory = true;   // 멤버 변수에 저장
    }
}
```

**OnGameOverTimerTimeout() 수정:**

```cpp
void ABattleBlasterGameMode::OnGameOverTimerTimeout()
{
    if (IsVictory)  // 이제 접근 가능!
    {
        // 다음 레벨 로드 (다음 강의에서 구현)
    }
    else
    {
        // 현재 레벨 재시작

}
```

```cpp
        Cast<UBattleBlasterGameInstance>(GetGameInstance());

    if (GameInstance)

        if (IsVictory)
        {

            {
                GameInstance->CurrentLevelIndex++;

                // 레벨 이름 생성: "Level_2", "Level_3"...
                FString NextLevel = FString::Printf(
                    TEXT("Level_%d"),
                    GameInstance->CurrentLevelIndex
                );

                UGameplayStatics::OpenLevel(GetWorld(), *NextLevel);
            }
            else
            {
                // 모든 레벨 클리어! → 엔딩 화면
            }
        }
```

## 🔧 2. 핵심 함수들

### ⚙️ ChangeLevel() - 실제 레벨 전환 담당

```cpp
void UBattleBlasterGameInstance::ChangeLevel(int32 Index)
{
    // 1단계: 유효한 레벨 번호인지 확인
    if (Index > 0 && Index <= LastLevelIndex)
    {
        // 2단계: 현재 레벨 번호 업데이트
        CurrentLevelIndex = Index;

        // 3단계: 레벨 이름 만들기
        // Index가 1이면 → "Level_1"
        // Index가 2이면 → "Level_2"
        FString LevelNameString = FString::Printf(TEXT("Level_%d"), CurrentLevelIndex);

        // 4단계: 실제 레벨 열기
        UGameplayStatics::OpenLevel(GetWorld(), *LevelNameString);
    }
}
```

**왜 private일까?**

- 이 함수는 내부에서만 사용하는 "헬퍼 함수"
- 외부에서는 아래의 3가지 함수만 사용하면 됨

### 🎯 LoadNextLevel() - 다음 레벨로

```cpp
void UBattleBlasterGameInstance::LoadNextLevel()
{
    // 마지막 레벨이 아니라면
    if (CurrentLevelIndex < LastLevelIndex)
    {
        ChangeLevel(CurrentLevelIndex + 1);  // 다음 레벨로
    }
    else  // 마지막 레벨을 클리어했다면
    {
        RestartGame();  // 처음부터 다시!
    }
}
```

**예시:**

- 레벨 1 클리어 → 레벨 2로
- 레벨 2 클리어 → 레벨 3으로
- 레벨 3 클리어 → 레벨 1로 (다시 처음부터)

**언제 사용?**

## 🔍 6. 핵심 개념 상세 설명

### FTimerHandle이 멤버 변수인 이유

```cpp
// ❌ 잘못된 방법 (지역 변수)
void BeginPlay()
{
    FTimerHandle LocalHandle;  // 함수가 끝나면 사라짐!
    SetTimer(LocalHandle, ...);
}

void SomeOtherFunction()
{
    ClearTimer(LocalHandle);  // 에러! LocalHandle에 접근 불가
}

// ✅ 올바른 방법 (멤버 변수)
class GameMode
{
    FTimerHandle CountdownTimerHandle;  // 클래스 멤버
};

void BeginPlay()
{
    SetTimer(CountdownTimerHandle, ...);  // 저장됨
}

void OnCountdownTimerTimeout()
{
    ClearTimer(CountdownTimerHandle);  // 다른 함수에서도 접근 가능!
}
```

### GetWorldTimerManager() 이해하기

```cpp
GetWorldTimerManager()

    .ClearTimer(...)  // 타이머 정지
    .PauseTimer(...)  // 타이머 일시정지
```

- **World**: 게임의 전체 세계 (레벨)
- **TimerManager**: 그 세계의 시간을 관리하는 관리자
- 모든 타이머는 이 매니저가 중앙 집중식으로 관리

```cpp
// 메모리 낭비는 아니지만 불필요한 함수 호출
// → 깔끔하게 정리하는 게 좋은 프로그래밍!
```

## 🤔 자주 하는 질문

**Q: 왜 하필 -1까지 가나요?**

- 역할 분리: 0에서는 게임 시작 로직, -1에서는 정리 작업
- 명확한 구조: 각 단계가 명확히 구분됨

**Q: SetTimer의 마지막 파라미터 true/false 차이는?**

- `true`: 반복 타이머 (1초마다 계속 호출)
- `false`: 원샷 타이머 (1초 후 딱 한 번만)

**Q: 타이머를 안 지우면 어떻게 되나요?**

- 메모리 누수는 아니지만 계속 함수 호출됨
- 2, -3, -4... 불필요하게 계속 감소
- 베스트 프랙티스: 사용 안 하면 정리!

**Q: 다음 레벨에서도 카운트다운이 되나요?**

- 네! GameMode는 레벨마다 새로 생성됨
- BeginPlay()가 다시 호출 → 카운트다운 재시작

**Q: CountdownDelay를 레벨마다 다르게?**

- `UPROPERTY(EditAnywhere)`라서 가능!
- 에디터에서 각 레벨의 GameMode 설정에서 변경
