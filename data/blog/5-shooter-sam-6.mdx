
## 💥 데미지 시스템이란?

### 언리얼의 데미지 시스템

**구조:**

```
공격자 (Attacker)

```

### 코드 완벽 이해하기

**Step 1: 맞은 액터 가져오기**


**HitResult에 뭐가 들어있나요?**


**파라미터 4: DamageCauser (Actor)**

```cpp

```

- **무엇으로** 데미지를 줬나?
- 데미지를 일으킨 액터

**EventInstigator vs DamageCauser:**

```
EventInstigator (Controller):
→ 누가 쏘았나? (플레이어/AI)
→ 책임자

DamageCauser (Actor):
→ 무엇으로 쏘았나? (총/폭탄)
→ 도구
```

**예시:**

```
플레이어(Controller)가
  ↓
총(Actor)을 사용해서
  ↓
적을 공격함

EventInstigator = 플레이어 Controller
DamageCauser = 총 Actor
```

### StaticClass()가 뭔가요?

**StaticClass() = 클래스 정보 가져오기**

```cpp
UDamageType::StaticClass()
```

**의미:**

```
"UDamageType의 클래스 정보를 줘"

인스턴스 X → 클래스 자체의 정보 O
```

**비유:**

```
사과 하나(인스턴스)가 아니라
"사과"라는 개념 자체(클래스)
```

**다른 예시:**

```cpp
// 클래스 정보 얻기
UClass* MyClass = AActor::StaticClass();

// 해당 클래스로 액터 생성
SpawnActor<AActor>(MyClass);
```

## 📡 Step 3: 데미지 받기 (Delegate)

### Delegate가 뭔가요?

**Delegate = 이벤트 알림 시스템**

```
A: "나 데미지 받으면 알려줘!"
B: "OK!"
    ↓
(데미지 발생)
    ↓
B: "A야! 데미지 받았어!"
A: "알았어, 처리할게!"
```

**코드로:**

```cpp
// 구독 (Subscribe)
OnTakeAnyDamage.AddDynamic(this, &MyFunction);

// 데미지 받으면 자동으로 MyFunction 호출됨!
```

---

### 3-1: Delegate 시그니처 확인

**어떤 함수를 바인딩해야 하나요?**

**방법:**

```
1. Ctrl + OnTakeAnyDamage 클릭
2. DECLARE_DYNAMIC_MULTICAST_SPARSE_DELEGATE_FiveParams 찾기
3. 파라미터 확인
```

**시그니처:**

```cpp
DECLARE_DYNAMIC_MULTICAST_SPARSE_DELEGATE_FiveParams(
    FTakeAnyDamageSignature,           // 델리게이트 이름
    AActor, OnTakeAnyDamage,           // 소속 클래스
    AActor*, DamagedActor,             // 파라미터 1
    float, Damage,                     // 파라미터 2
    const UDamageType*, DamageType,    // 파라미터 3
    AController*, InstigatedBy,        // 파라미터 4
    AActor*, DamageCauser             // 파라미터 5
);
```

**이 정보를 바탕으로 함수 만들기!**

---

### 3-2: 헤더 파일 (ShooterSamCharacter.h)

```cpp
UCLASS()
class AShooterSamCharacter : public ACharacter
{
    GENERATED_BODY()

public:
    // ... 기존 코드 ...

protected:
    virtual void BeginPlay() override;

    // ===== 데미지 받는 함수 =====
    UFUNCTION()
    void OnDamageTaken(
        AActor* DamagedActor,
        float Damage,
        const UDamageType* DamageType,
        AController* InstigatedBy,
        AActor* DamageCauser
    );
};
```

**코드 설명:**

```cpp
UFUNCTION()
```

- 델리게이트에 바인딩하려면 필수!
- 언리얼 리플렉션 시스템에 등록

**파라미터:**

- 델리게이트 시그니처와 **정확히 일치**해야 함
- 순서, 타입, const 모두 같아야 함

### 3-3: 구현 파일 (ShooterSamCharacter.cpp)

**BeginPlay에서 바인딩:**

```cpp
void AShooterSamCharacter::BeginPlay()
{
    Super::BeginPlay();

    // ===== 데미지 델리게이트 바인딩 =====
    OnTakeAnyDamage.AddDynamic(this, &AShooterSamCharacter::OnDamageTaken);

    // ... 기존 코드 (무기 숨기기, 총 생성 등) ...
}
```

**AddDynamic 설명:**

```cpp
OnTakeAnyDamage.AddDynamic(this, &AShooterSamCharacter::OnDamageTaken);
```

**파라미터 1: this**

```
어떤 객체의 함수?
→ 이 캐릭터 자신
```

**파라미터 2: 함수 주소**

```cpp
&AShooterSamCharacter::OnDamageTaken
```

- `&` = 주소 연산자
- `클래스::함수명` = 멤버 함수 지정

**전체 의미:**

```
"이 캐릭터가 데미지 받으면
 이 캐릭터의 OnDamageTaken 함수를 호출해줘!"
```

### 벽은 왜 안 되나요?

**질문:**

```
"벽을 쏘면 왜 데미지 로그가 안 나와요?"
```

**답변:**

```
벽 = Geometry Brush
→ 액터가 아님
→ OnTakeAnyDamage 델리게이트 없음
→ 데미지 시스템 작동 안 함
```

**해결:**

```
벽을 Static Mesh Actor로 만들기
→ 액터가 됨
→ 델리게이트 바인딩 가능
→ 데미지 받을 수 있음
```

```

4. 반복...

```

## 📝 Step 1: 체력 변수 추가

### 1-1: 헤더 파일 (ShooterSamCharacter.h)

```cpp
UCLASS()
class AShooterSamCharacter : public ACharacter
```

### 변수 설명

**1. MaxHealth (최대 체력)**

```cpp
UPROPERTY(EditAnywhere)

```

**역할:**

- 시작할 때 체력
- 기본값: 100

**왜 EditAnywhere?**

```
블루프린트에서 수정 가능
→ 캐릭터마다 다른 최대 체력 설정

예시:
  일반 적: MaxHealth = 100
  보스: MaxHealth = 1000
  플레이어: MaxHealth = 200
```

### 코드 한 줄씩 완벽 이해

**Step 1: 생존 확인**

```cpp
if (!IsAlive) return;
```

**의미:**

```
if (!IsAlive)  // IsAlive가 false면
    return;     // 함수 종료
```

**왜 필요한가요?**

```
죽은 캐릭터가 또 맞으면?
→ 이미 죽었으니 무시!
→ return으로 함수 종료
→ 아래 코드 실행 안 됨

살아있으면?
→ 조건 통과
→ 계속 진행
```

---

**Step 2: 디버그 로그**

```cpp
UE_LOG(LogTemp, Display, TEXT("Damage taken: %f"), Damage);
```

**개발 중 확인용:**

```
데미지가 제대로 적용되는지 확인
나중에 삭제 가능
```

---

**Step 3: 체력 감소**

```cpp
Health -= Damage;
```

**복합 대입 연산자:**

```cpp
// 이 둘은 같은 의미:
Health -= Damage;
Health = Health - Damage;
```

**예시:**

```
Health = 100
Damage = 10

Health -= Damage;
→ Health = 100 - 10
→ Health = 90
```

**다른 복합 연산자:**

```cpp
+=  // 더하기
-=  // 빼기
*=  // 곱하기
/=  // 나누기

예:
Health += 20;  // 회복
Ammo -= 1;     // 탄약 소모
Damage *= 2;   // 데미지 2배
```

---

**Step 4: 사망 확인**

```cpp
if (Health <= 0.f)
```

**왜 <= (작거나 같음)?**

```
만약 = (같음)만 체크하면:

Health = 100
Damage = 150
Health = 100 - 150 = -50

if (Health == 0)  // -50 ≠ 0
    // 실행 안 됨!
    // 죽지 않음! ❌

if (Health <= 0)  // -50 ≤ 0
    // 실행됨!
    // 제대로 죽음! ✅
```

**안전한 체크:**

```cpp
<=  // 0 이하면 모두 죽음
==  // 정확히 0만 죽음 (위험!)
```

---

**Step 5: 사망 처리**

```cpp
IsAlive = false;
Health = 0.f;
```

**IsAlive = false:**

```
더 이상 데미지 안 받음
(맨 위 if (!IsAlive) return 때문)
```

**Health = 0.f:**

```
과잉 데미지 방지

예:
  Health = 10
  Damage = 50
  Health = 10 - 50 = -40 ❌

Health = 0으로 고정:
  체력이 음수 안 되게!
  UI 표시할 때 깔끔
```

# { 함수 오버로딩 (Function Overloading) }

## 🎯 함수 오버로딩이란?

**같은 이름의 함수를 여러 개 만들되, 파라미터만 다르게!**

```cpp
// 같은 이름 "Add"
int Add(int a, int b);           // 버전 1
int Add(int a, int b, int c);    // 버전 2
int Add(int a, int b, int c, int d);  // 버전 3

// 호출 시 자동으로 선택됨!
Add(1, 2);        // 버전 1 호출
Add(1, 2, 3);     // 버전 2 호출
Add(1, 2, 3, 4);  // 버전 3 호출
```

---

## 🤔 왜 필요한가요?

### 오버로딩 없이 (❌ 나쁜 방법)

```cpp
int Add2(int a, int b)
{
    return a + b;
}

int Add3(int a, int b, int c)
{
    return a + b + c;
}

int Add4(int a, int b, int c, int d)
{
    return a + b + c + d;
}

// 사용:
Add2(1, 2);        // 함수 이름 외워야 함 😵
Add3(1, 2, 3);     // 이름 또 외워야 함 😵
Add4(1, 2, 3, 4);  // 또... 😵
```

**문제점:**

```
1. 함수 이름 너무 많음
2. 외우기 어려움
3. 본질적으로 같은 일 하는데 이름만 다름
4. 코드 가독성 떨어짐
```

---

### 오버로딩 사용 (✅ 좋은 방법)

```cpp
// 같은 이름!
int Add(int a, int b)
{
    return a + b;
}

int Add(int a, int b, int c)
{
    return a + b + c;
}

int Add(int a, int b, int c, int d)
{
    return a + b + c + d;
}

// 사용:
Add(1, 2);        // ✅ 간단!
Add(1, 2, 3);     // ✅ 직관적!
Add(1, 2, 3, 4);  // ✅ 쉬움!
```

**장점:**

```
1. 함수 이름 하나만 기억
2. 파라미터 개수만 다르게 호출
3. 코드가 깔끔하고 읽기 쉬움
4. 같은 일 하는 함수는 같은 이름!
```

---

## 📝 오버로딩 규칙

### 무엇으로 구분하나요?

**파라미터 리스트(매개변수 목록)만 달라야 함!**

```cpp
// ✅ 올바른 오버로딩
void Print(int x);              // 정수 1개
void Print(float x);            // 실수 1개
void Print(int x, int y);       // 정수 2개
void Print(string text);        // 문자열 1개
void Print(int x, string text); // 정수 + 문자열
```

---

### 파라미터 개수로 구분

```cpp
void Foo(int a);           // 파라미터 1개
void Foo(int a, int b);    // 파라미터 2개
void Foo(int a, int b, int c);  // 파라미터 3개
```

---

### 파라미터 타입으로 구분

```cpp
void Foo(int x);      // 정수
void Foo(float x);    // 실수
void Foo(string x);   // 문자열
void Foo(bool x);     // 불린
```

---

### 파라미터 순서로 구분

```cpp
void Foo(int x, float y);    // 정수, 실수
void Foo(float x, int y);    // 실수, 정수 (순서 다름!)
```

---

### ❌ 안 되는 것들

**반환 타입만 다른 것:**

```cpp
// ❌ 컴파일 에러!
int Foo(int x);
float Foo(int x);  // 파라미터 같은데 반환 타입만 다름
```

**파라미터 이름만 다른 것:**

```cpp
// ❌ 컴파일 에러!
void Foo(int x);
void Foo(int y);  // 이름만 다름, 타입은 같음
```

**const만 다른 것 (일부 경우):**

```cpp
// ⚠️ 주의: 포인터/레퍼런스는 가능, 값은 불가능
void Foo(int x);
void Foo(const int x);  // ❌ 에러

void Foo(int* x);
void Foo(const int* x); // ✅ OK
```

```cpp
// 오버로딩 (여러 함수)
void Spawn(TSubclassOf<AActor> Class);
void Spawn(TSubclassOf<AActor> Class, FVector Location);
void Spawn(TSubclassOf<AActor> Class, FVector Location, FRotator Rotation);

// 기본값 (한 함수)
void Spawn(
    TSubclassOf<AActor> Class,
    FVector Location = FVector::ZeroVector,
    FRotator Rotation = FRotator::ZeroRotator
);

// 둘 다 가능:
Spawn(MyClass);  // 기본값 사용
Spawn(MyClass, Location);  // 위치만 지정
Spawn(MyClass, Location, Rotation);  // 모두 지정
```

---

### 언제 오버로딩, 언제 기본값?

**오버로딩 사용:**

```
- 파라미터 타입이 다를 때
- 내부 로직이 완전히 다를 때
- 파라미터 순서가 다를 때
```

**기본값 사용:**

```
- 파라미터 타입이 같을 때
- 단순히 선택적 파라미터일 때
- 내부 로직이 비슷할 때
```

---

### 좋은 오버로딩 설계

**원칙:**

```cpp
// ✅ 좋은 예: 직관적
void Move(FVector Direction);           // 방향으로 이동
void Move(FVector Direction, float Speed);  // 속도 추가
void Move(FVector From, FVector To);    // 시작-끝 지점

// ❌ 나쁜 예: 헷갈림
void Move(float X, float Y);
void Move(float Speed, float Direction);  // 순서 애매
```

## 📚 핵심 개념 정리

### 함수 오버로딩

같은 이름, 다른 파라미터

```cpp
void Foo(int x);
void Foo(float x);
void Foo(int x, int y);
```

### 오버로드 선택 기준

컴파일러가 자동으로 선택

```
호출 시 전달된 파라미터 타입/개수/순서
→ 가장 일치하는 오버로드 자동 선택
```

### 구분 요소

```
✅ 파라미터 개수
✅ 파라미터 타입
✅ 파라미터 순서
❌ 반환 타입
❌ 파라미터 이름
```

## 🎯 요약

**함수 오버로딩 = 같은 이름, 다른 파라미터**

**장점:**

```
1. 코드 가독성 향상
2. 직관적인 API
3. 유연한 사용
```

**규칙:**

```
- 파라미터가 달라야 함
- 반환 타입만 다르면 안 됨
- 컴파일러가 자동으로 선택
```

**실전에서:**

```
- 언리얼 엔진이 많이 사용
- SetTimer, SpawnActor 등
- 자신의 함수에도 적용 가능
```
