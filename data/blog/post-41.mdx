# 쿼리를 분석하는 순서

```jsx
1. SELECT: 어떤 컬럼을 선택하고 있는지 확인합니다.

2. FROM: 데이터가 어떤 테이블에서 오는지 확인합니다.

3. JOIN: 테이블 간의 관계를 확인하고, 조인 조건을 살펴봅니다.

4. WHERE: 데이터 필터링 조건을 확인합니다.

5. GROUP BY: 데이터 집계의 기준이 되는 컬럼을 확인합니다.

6. HAVING: 집계 결과에 대한 추가 필터링 조건을 확인합니다.

7. ORDER BY: 결과의 정렬 기준을 확인합니다.

8. LIMIT: 결과의 최대 개수를 제한하는 조건을 확인합니다.

* 서브 쿼리가 여러개 있다면 가장 내부의 서브 쿼리부터 분석하고 위로 위로 분석
```

# 쿼리 튜닝을 통한 성능 최적화

```jsx
쿼리 튜닝은 데이터베이스 성능을 최적화하는 중요한 작업입니다.

다음은 쿼리 성능을 향상시키기 위한 기본적인 방법부터 고급 기술까지의 단계입니다.
```

```jsx
1. 기본적인 쿼리 튜닝 방법:

적절한 인덱스 사용:

	인덱스는 쿼리의 검색 성능을 크게 향상시킵니다. 인덱스를 활용하면 데이터베이스가 테이블의 모든 행을 스캔하지 않고,

	필요한 데이터에 빠르게 접근할 수 있습니다.

	인덱스는 WHERE 절, JOIN 절, ORDER BY 절, 그리고 GROUP BY 절에 사용되는 열에 대해 생성하는 것이 좋습니다.


불필요한 데이터 제거:

	필요한 열만 선택하십시오(SELECT * 대신 필요한 열만 나열).

	WHERE 절을 사용하여 불필요한 데이터를 필터링하십시오.

복잡한 쿼리 단순화:

	복잡한 서브쿼리나 중첩 쿼리는 성능을 저하시킬 수 있습니다. 가능하다면 JOIN으로 대체하거나, 서브쿼리를 단순화하세요.

조인 순서 최적화:

	JOIN 시 테이블의 순서가 중요합니다. 일반적으로 큰 테이블은 마지막에 조인하는 것이 성능에 유리할 수 있습니다.

DISTINCT, ORDER BY, GROUP BY 최소화:

	DISTINCT, ORDER BY, GROUP BY는 성능에 큰 영향을 줄 수 있으므로, 꼭 필요한 경우에만 사용하세요.

2. 중급 쿼리 튜닝 방법:

서브쿼리와 조인의 활용:

때로는 서브쿼리를 JOIN으로 대체하는 것이 성능에 더 좋을 수 있으며, 반대로도 마찬가지입니다. 상황에 맞게 적절한 방법을 선택하세요.

결합 인덱스(Composite Index) 사용:

여러 열을 조합한 인덱스를 생성하여, 다중 조건 검색 시 성능을 높일 수 있습니다.
정렬된 데이터 처리:

ORDER BY나 GROUP BY와 관련된 열에 인덱스를 적용하면 정렬 성능이 향상될 수 있습니다.
매개변수화된 쿼리:

매개변수화된 쿼리를 사용하면 SQL이 재컴파일되는 것을 방지하고, 쿼리 계획을 캐싱할 수 있습니다.
파티셔닝(Partitioning):

큰 테이블을 파티션으로 나누어 쿼리 성능을 향상시킬 수 있습니다. 파티션 키를 적절하게 설정하여 쿼리가 특정 파티션에서만 데이터를 검색하도록 할 수 있습니다.
3. 고급 쿼리 튜닝 방법:
히스토그램 사용:

데이터 분포를 히스토그램으로 분석하여, 옵티마이저가 더 정확한 쿼리 계획을 수립할 수 있도록 돕습니다.
인덱스 힌트 사용:

데이터베이스 옵티마이저가 잘못된 쿼리 계획을 선택할 때, 특정 인덱스를 사용하도록 힌트를 주어 쿼리를 최적화할 수 있습니다.
Materialized Views:

자주 사용하는 복잡한 쿼리의 결과를 미리 계산하여 저장하는 Materialized Views를 사용하면 성능을 크게 향상시킬 수 있습니다.
Explain Plan 및 실행 계획 분석:

EXPLAIN PLAN 명령어를 사용하여 쿼리의 실행 계획을 분석하고, 옵티마이저가 선택한 경로를 평가하여 튜닝할 수 있습니다.
프로파일링 및 모니터링:

데이터베이스 프로파일링 도구를 사용하여 쿼리의 성능을 모니터링하고, 병목 현상을 파악하여 최적화할 수 있습니다.
쿼리 리팩토링:

복잡한 쿼리를 작은 쿼리로 나누어 쿼리 결과를 중간 테이블에 저장하고, 이를 다시 조합하여 최종 결과를 도출하는 방법도 있습니다. 이를 통해 데이터 처리가 보다 효율적으로 이루어질 수 있습니다.
```

# 질의 명령문(Data Query Language, DQL)

```sql
데이터 집계 및 정렬을 위한 질의 = DQL (SELECT 문과 그에 관련된 구문(예: FROM, WHERE, GROUP BY, HAVING, ORDER BY 등)
```

## SELECT

```sql
**SELECT 컬럼명 FROM 테이블명**

테이블의 칼럼명 데이터를 불러오는 구문 모든 칼럼을 불러오고 싶을때는 컬럼명에 * 넣기
```

```sql
**SELECT 컬럼명 FROM 테이블명 WHERE 조건**

WHERE 구문을 추가해서 WHERE 절 뒤에오는 조건이 참인 데이터만 불러옴
```

```sql
**SELECT 컬럼명 FROM 테이블명 WHERE 조건 ORDER BY 컬럼명 ASC or DESC**

ORDER BY 뒤에오는 칼럼명을 기준으로 불러오는 데이터를 정렬 ASC 는 오름차순 DESC 내림차순
(기본값은 오름차순)
```

## FROM

```sql
개념

쿼리에서 사용되는 절 중 하나로, 데이터를 조회하는 대상 테이블을 지정하는 데 사용
```

```sql
기본 문법

SELECT column1, column2, ...
FROM table_name;
```

```sql
예제

SELECT first_name, last_name, salary
FROM employees;
```

## WHERE

```sql
개념

데이터를 필터링하거나 특정 조건을 만족하는 행(레코드)을 선택하는 데 사용
```

```sql
기본문법

SELECT column1, column2, ...
FROM table_name
WHERE 필터링 조건;
```

```sql
예제

SELECT first_name, last_name, salary
FROM employees
WHERE salary >= 50000;

SELECT customer_id, first_name, last_name, city
FROM customers
WHERE city = 'New York';

SELECT first_name, last_name, hire_date
FROM employees
WHERE hire_date >= '2022-01-01';

SELECT first_name, last_name, department_id, salary
FROM employees
WHERE department_id = 10 AND salary >= 60000;
```

## **GROUP BY**

```sql
개념

데이터를 그룹화하고 그룹 단위로 집계 함수를 적용하는 데 사용

ex)

- 부서별 급여 평균을 구하시오

- 국가별 인구 총계를 구하시오

- 성별 최대 임금

- 부서별 수당의 표준편차
```

```sql
기본 문법

SELECT column1, aggregate_function(column2)
FROM table_name
GROUP BY column1;

* SELECT: 조회할 열(컬럼) 목록을 나열합니다.

* aggregate_function: 그룹 내에서 집계할 열(컬럼)에 대한 집계 함수를 선택합니다. 일반적으로 SUM, AVG, COUNT, MAX, MIN 등의 함수를 사용합니다.

* FROM: 데이터를 가져올 테이블을 지정합니다.

* GROUP BY: 그룹화할 열(컬럼)을 지정합니다.
```

```sql
예제

SELECT customer_id, COUNT(order_id) AS total_orders
FROM orders
GROUP BY customer_id;

//orders 테이블에서 각 고객(customer_id)별로 주문의 총 수를 계산합니다.

SELECT CASE
```

### GROUPING

```jsx
개념

GROUPING은 ROLLUP이나 CUBE, GROUPING SETS 등의 그룹함수에 의해 컬럼 값이 소계나 총합등 집계된 데이터일 경우 1을 리턴하고 만약 집계된 데이터가 아니면 0을 리턴하는 함수

* 주로 ROLLUP 및 CUBE와 함께 사용되며, 데이터 큐브를 생성하고 롤업(상위 수준 그룹)한 결과를 효과적으로 다룰 때 유용
```

```jsx
기본 문법

GROUPING(expression)
```

```jsx

       GROUPING(order_date) AS is_grouped // GROUPING 함수를 사용하여 order_date 열이 그룹화 키로 사용되었는지 여부를 확인하고 is_grouped 열로 표시(열에 1 또는 0 만 나온다)
```

## **HAVING**

```sql
개념

쿼리에서 그룹화된 데이터에 대한 필터링을 수행하는데 사용
```

```sql
기본 문법

SELECT column1, aggregate_function(column2)
FROM table_name
GROUP BY column1
HAVING condition;

* SELECT: 조회할 열(컬럼) 목록을 나열합니다.

* aggregate_function: 그룹 내에서 집계할 열(컬럼)에 대한 집계 함수를 선택합니다. 일반적으로 SUM, AVG, COUNT, MAX, MIN 등의 함수를 사용합니다.

* FROM: 데이터를 가져올 테이블을 지정합니다.

* GROUP BY: 그룹화할 열(컬럼)을 지정합니다.

* HAVING: 그룹 단위에서 필터링할 조건을 지정합니다.
```

```sql
예제

SELECT customer_id, COUNT(order_id) AS total_orders
FROM orders
GROUP BY customer_id
HAVING COUNT(order_id) >= 2;

// orders 테이블에서 각 고객(customer_id)별로 주문의 총 수가 2건 이상인 고객을 조회합니다.

customer_id | total_orders
-------------------------
101         | 5
102         | 3
103         | 7

SELECT department_id, job_id, MIN(salary) AS min_salary
FROM employees
GROUP BY department_id, job_id
HAVING MIN(salary) >= 5000;

// employees 테이블에서 부서(department_id) 및 직무(job_id)에 따라 그룹화하고, 각 그룹에서 최소 급여(MIN(salary))가 5000 이상인 경우를 조회

department_id | job_id   | min_salary
------------------------------------
10            | IT_PROG  | 6000
50            | SA_MAN   | 9500
50            | SA_REP   | 6000
70            | PR_REP   | 10000
90            | FI_MGR   | 12000

SELECT customer_id, COUNT(order_id) AS total_orders, SUM(order_total) AS total_amount
FROM orders
GROUP BY customer_id
HAVING COUNT(order_id) >= 3 OR SUM(order_total) >= 1000;

// orders 테이블에서 각 고객(customer_id)별로 주문의 총 수와 총 금액(SUM(order_total))을 계산하고, 총 주문 수가 3건 이상이거나 총 금액이 1000 이상인 경우를 조회

customer_id | total_orders | total_amount
----------------------------------------
101         | 5            | 3300
103         | 7            | 4100

SELECT department_id, AVG(salary) AS avg_salary
FROM employees
GROUP BY department_id
HAVING AVG(salary) = (SELECT MAX(avg_salary)
                       FROM (SELECT department_id, AVG(salary) AS avg_salary
                               FROM employees
                             GROUP BY department_id)
                             );

// employees 테이블에서 각 부서(department_id)별로 평균 급여(AVG(salary))가 가장 높은 부서를 조회합니다. 이때 HAVING 절에 서브쿼리를 사용합니다.

department_id | avg_salary
-------------------------
90            | 9962.5
```

## **ORDER BY**

```sql
개념

SQL 쿼리에서 결과 집합을 정렬하는 데 사용됩니다. 정렬은 하나 이상의 열(컬럼)을 기준으로 데이터를 순서대로 나열하는 데 도움이 됩니다.
```

```sql
기본 문법

SELECT column1, column2, ...
FROM table_name
ORDER BY column1 [ASC or DESC], column2 [ASC or DESC], ...;

* SELECT: 조회할 열(컬럼) 목록을 나열합니다.

* FROM: 데이터를 가져올 테이블을 지정합니다.

* ORDER BY: 정렬을 수행하는 키워드로, 하나 이상의 열을 지정하여 결과를 정렬합니다.

* column1, column2, ...: 정렬할 열(컬럼)을 나열합니다. 여러 열을 지정하여 복합 정렬을 수행할 수 있습니다.

* [ASC | DESC]: 정렬 방향을 지정합니다. 기본적으로 오름차순(ASC)으로 정렬됩니다. 내림차순으로 정렬하려면 DESC를 사용합니다.
```

```sql
예제

SELECT product_name
FROM products
ORDER BY product_name;

// products 테이블에서 제품(product_name)을 오름차순으로 정렬하여 조회합니다.

SELECT department_id, salary
FROM employees
ORDER BY department_id ASC, salary DESC;

// employees 테이블에서 부서(department_id)와 급여(salary)를 복합 정렬( 데이터를 한 열의 값에 따라 정렬한 다음, 정렬된 결과에서 다른 열의 값에 따라 더 세부적으로 정렬)
// 하고, 급여는 내림차순으로 정렬합니다.

SELECT order_id, order_date, order_total
FROM orders
WHERE order_total >= 1000
ORDER BY order_date DESC;

// orders 테이블에서 주문일(order_date)을 내림차순으로 정렬하되, 주문 금액(order_total)이 1000 이상인 주문만 조회합니다.

SELECT customer_id, order_id, order_date
  FROM orders
WHERE customer_id = (
                      SELECT customer_id
                      FROM (
	                           SELECT customer_id, COUNT(order_id) AS total_orders  // 서브쿼리 시작: orders 테이블에서 각 고객별로 주문 수를 계산하고 내림차순으로 정렬합니다.
                               FROM orders
                             GROUP BY customer_id
                             ORDER BY total_orders DESC
                            )
                      WHERE ROWNUM = 1 // 최종적으로 선택된 첫 번째 행의 customer_id를 반환합니다. 이것은 가장 많은 주문을 한 고객의 고객 ID를 나타냅니다.
                     )
ORDER BY order_date ASC;

// orders 테이블에서 가장 많은 주문을 한 고객을 찾고, 해당 고객의 주문을 주문일(order_date)을 기준으로 오름차순으로 정렬하여 조회합니다.
// 이때 서브쿼리를 사용하여 최대 주문 수를 찾습니다.
```

# 조건 함수 (Conditional Functions):

```sql
조건 함수 (Conditional Functions): CASE 표현식과 같이 조건에 따라 값을 반환하는 함수나 표현식입니다. CASE 표현식 이외에도 IF, COALESCE, NULLIF 등이 있습니다.
```

## CASE

```jsx
개념

오라클의 CASE 문은 조건에 따라 다른 값을 반환하는데 사용됩니다.

* CASE 키워드로 시작하고 END로 끝납니다.

* WHEN 키워드 다음에 조건을 지정하고, 해당 조건이 참일 때 실행될 결과를 지정합니다.

* 여러 WHEN 블록을 사용하여 다양한 조건을 처리할 수 있습니다.

* ELSE 블록은 모든 조건이 거짓인 경우 실행됩니다. 선택적으로 사용할 수 있습니다.
```

```sql
기본문법

CASE
    WHEN condition1 THEN result1
    WHEN condition2 THEN result2
    ...
    ELSE resultN
END
```

```sql
예제

SELECT
    EMPLOYEE_ID,
    SALARY,
    CASE
        WHEN SALARY >= 50000 THEN 'Manager'
        WHEN SALARY >= 30000 THEN 'Supervisor'
        WHEN SALARY >= 20000 THEN 'Associate'
        ELSE 'Assistant'
    END AS JOB_TITLE  -- SELECT 절에서 CASE 문을 사용 , 끝난뒤 결과를 JOB_TITLE 열로 별칭
FROM
    EMPLOYEES;
```

```sql
SELECT
    EMPLOYEE_ID,
    SALARY
FROM
    EMPLOYEES
ORDER BY
    CASE
        WHEN SALARY >= 50000 THEN 1
        WHEN SALARY >= 30000 THEN 2
        WHEN SALARY >= 20000 THEN 3
        ELSE 4
    END;  -- ORDER BY 절에서 CASE 문을 사용
```

```sql
SELECT
    EMPLOYEE_ID,
    SALARY
FROM
    EMPLOYEES
WHERE
    CASE
        WHEN SALARY >= 30000 THEN 1
        WHEN SALARY >= 20000 THEN 0
        ELSE -1
    END = 1;  -- WHERE 절에서 CASE 문을 사용
```

## **DECODE**

```jsx
개념

DECODE 함수는 조건에 따라 다른 값을 반환하는 함수로, 주로 데이터 변환 작업에 사용
```

```jsx
기본 문법

DECODE(expression, search1, result1, search2, result2, ..., default)

* expression: 비교할 표현식 또는 열입니다.

* search1, search2, ...: 비교할 값 또는 조건입니다.

* result1, result2, ...: 각 조건에 대한 결과 값입니다.

* default (선택 사항): 모든 조건이 일치하지 않을 때 반환할 기본값입니다.

DECODE 함수는 expression을 search1, search2, ...와 차례대로 비교하며, 일치하는 조건을 찾으면 해당하는 result 값을 반환합니다.

모든 조건이 일치하지 않을 때 default 값을 반환할 수 있습니다.
```

```sql
예제

-- 주문 금액에 따라 등급을 지정합니다.
SELECT order_id, order_amount,
       DECODE(order_amount, 0, '무료', 100, '싼 상품', 500, '보통 상품', '고가 상품') AS product_grade
FROM orders;

// 값에 따라 등급 지정하기

-- 학생의 성적에 따라 학점을 부여합니다.
SELECT student_id, score,
       DECODE(score, 90, 'A', 80, 'B', 70, 'C', 60, 'D', 'F') AS grade
FROM exam_scores;

// 성적에 따라 학점 부여하기

-- 직원의 부서에 따라 보너스를 계산합니다.
SELECT employee_id, salary, department,
       DECODE(department, 'HR', salary * 0.1, 'Sales', salary * 0.15, salary * 0.05) AS bonus
FROM employees;

// 부서에 따라 보너스 계산하기
```

## **집계 함수 (Aggregate Functions)**

```sql
집계 함수 (Aggregate Functions): MAX 함수와 같이 여러 행의 값을 집계하여 하나의 결과를 반환하는 함수들을 집계 함수라고 합니다.
```

### MAX,MIN

```sql
개념

MAX 함수는 SQL에서 가장 큰 값을 찾는 데 사용되는 집계 함수 중 하나 이 함수는 데이터 집합에서 최댓값을 반환하며, 주로 숫자나 날짜 열에서 사용

MIN 은 최솟값
```

```sql
기본 문법

MAX(열의이름 or 표현식)
```

```sql
예제

-- SELECT 절에서 MAX 함수 사용
SELECT
    MAX(salary) AS maximum_salary
FROM
    employees;

-- WHERE 절에서 MAX 함수 사용
SELECT
    employee_name,
    salary
FROM
    employees
WHERE
    salary = (SELECT MAX(salary) FROM employees);

-- GROUP BY 절에서 MAX 함수 사용
SELECT
    department_id,
    MAX(salary) AS max_salary
FROM
    employees
GROUP BY
    department_id;

-- HAVING 절에서 MAX 함수 사용
SELECT
    department_id,
    MAX(salary) AS max_salary
FROM
    employees
GROUP BY
    department_id
HAVING
    MAX(salary) > 5000;

-- ORDER BY 절에서 MAX 함수 사용
SELECT
    department_id,
    MAX(salary) AS max_salary
FROM
    employees
GROUP BY
    department_id
ORDER BY
    MAX(salary) DESC;
```

```sql
문자열 함수 (String Functions): SUBSTR 함수와 같이 문자열을 다루는 함수들을 문자열 함수라고 합니다. 다른 문자열 함수로는 CONCAT, UPPER, LOWER, LENGTH 등이 있습니다.
```

### **SUBSTR**

```jsx
개념

SUBSTR 함수는 문자열에서 특정 부분을 추출하는 함수
```

```jsx
기본 문법

SUBSTR(string, start_position, length)

* string: 추출할 문자열입니다.

* start_position: 추출을 시작할 위치입니다. 첫 번째 문자의 위치는 1부터 시작합니다.

* length: 추출할 문자열의 길이를 지정합니다. 이 부분은 선택 사항이며, 생략하면 시작 위치부터 문자열 끝까지 추출됩니다.
```

```sql
예제

-- 'Hello, World!' 문자열에서 'World!'를 추출합니다.
SELECT SUBSTR('Hello, World!', 7) AS result;
-- 결과: 'World!'

//문자열에서 시작 위치부터 끝까지 추출하기 (빈 공간도 7에 포함)

-- 'OpenAI' 문자열에서 4번째 문자부터 3글자를 추출합니다.
SELECT SUBSTR('OpenAI', 4, 3) AS result;
-- 결과: 'nAI'

//문자열에서 일부분 추출하기

-- '2023-10-04'와 같은 날짜 문자열에서 '월-일' 부분을 추출합니다.
SELECT SUBSTR('2023-10-04', 6, 5) AS result;
-- 결과: '10-04'

//문자열에서 특정 패턴 추출하기
```

### **LISTAGG**

```sql
개념

그룹 내에서 값을 결합하여 문자열로 만드는 함수로, 주로 문자열 데이터를 처리하고 집계할 때 사용
```

```sql
기본 문법

LISTAGG(expression, delimiter) WITHIN GROUP (ORDER BY order_column)

* expression: 결합할 열(컬럼)이나 표현식입니다.

* delimiter: 값 사이에 삽입할 구분 문자열입니다. 구분 문자열은 문자열로 지정됩니다.

* WITHIN GROUP (ORDER BY order_column): 결과 문자열을 정렬하기 위한 옵션으로, 생략 가능합니다.

LISTAGG 함수는 expression으로 지정한 열(컬럼)의 값을 delimiter로 구분하여 그룹 내에서 결합하고, 정렬 옵션을 사용하여 원하는 순서로 정렬할 수 있습니다.
```

```sql
예제

-- 부서별로 직원 이름을 쉼표로 구분하여 결합합니다.
SELECT department, LISTAGG(employee_name, ', ') WITHIN GROUP (ORDER BY employee_name) AS employees
FROM employees
GROUP BY department;

//구분 문자열로 결합하기

//결과
DEPARTMENT | EMPLOYEES
-----------------------------------
HR         | Alice, Bob, Carol
IT         | David, Emma
Sales      | Frank, Grace, Henry

-- 주문 번호별로 주문 상품을 세미콜론으로 구분하여 결합합니다.
SELECT order_id, LISTAGG(product_name, '; ') AS product_list
FROM order_details
GROUP BY order_id;

// 주문 상품을 목록으로 만들기

-- 주문 번호별로 고유한 상품 목록을 알파벳 순으로 결합합니다.
SELECT order_id, LISTAGG(DISTINCT product_name, ', ') WITHIN GROUP (ORDER BY product_name) AS unique_products
FROM order_details
GROUP BY order_id;

// 중복 값 제거 및 정렬

```

### LPAD, RPAD

```sql
개념

LPAD (Left Pad)와 RPAD (Right Pad) 함수는 문자열을 특정 길이로 패딩(채움)하는 데 사용되는 SQL 문자열 함수
```

```sql
기본 문법

LPAD,RPAD(string, length, pad_string)

* string: 패딩할 대상 문자열

* length: 최종 문자열 길이

* pad_string: 왼쪽, 오른쪽에 추가할 패딩 문자열
```

```sql
예제

SELECT LPAD('42', 5, '0') AS PaddedValue FROM dual;
-- 결과: '00042'

-- 결과: '-----Hello'

SELECT LPAD('OpenAI', 15, '*') AS PaddedText FROM dual;
-- 결과: '*******OpenAI'

SELECT RPAD('ABC', 6, '-') AS PaddedValue FROM dual;
-- 결과: 'ABC---'

SELECT RPAD('SQL', 7, ' ') AS PaddedString FROM dual;
-- 결과: 'SQL    '

SELECT RPAD('Database', 12, '#') AS PaddedText FROM dual;
-- 결과: 'Database####'
```

## 숫자형 함수

### ROUND

```jsx
개념

숫자를 지정한 소수 자리수로 반올림하는 함수로, 주로 숫자 데이터를 처리할 때 사용
```

```jsx
기본 문법

ROUND(number, decimal_places)

* number: 반올림할 숫자나 숫자 열입니다.

* decimal_places: 소수 자리수를 지정합니다. 이 자리수까지 반올림됩니다. 소수 자리수를 0으로 설정하면 정수로 반올림됩니다.

ROUND 함수는 number를 decimal_places로 지정한 소수 자리수로 반올림하고 결과 값을 반환합니다.
```

```sql
예제

-- 3.141592를 소수 둘째 자리까지 반올림합니다.
SELECT ROUND(3.141592, 2) AS rounded_number;
-- 결과: 3.14

//간단한 반올림

-- 상품 가격에서 10% 세금을 계산하고 반올림합니다.
SELECT product_name, price,
       ROUND(price * 0.1, 2) AS tax
FROM products;

//세금 계산하기

       ROUND(AVG(score), 1) AS rounded_average_score

GROUP BY student_id, subject;
```

# 연산자

### || (이중 수직 막대)

```sql
개념

문자열을 연결(concatenate)하는 데 사용되는 연산자
```

```sql
기본 문법

기본 문법: string1 || string2

* string1: 연결할 첫 번째 문자열.

* string2: 연결할 두 번째 문자열.
```

```sql
예제

SELECT 'Hello' || ' ' || 'World' AS ConcatenatedString FROM dual;
-- 결과: 'Hello World'

SELECT first_name || ' ' || last_name AS Full_Name FROM employees WHERE employee_id = 101;
-- 결과: 'John Doe'

SELECT 'Product: ' || product_name || ', Price: $' || TO_CHAR(price, '9999.99') AS Product_Info FROM products WHERE product_id = 123;
-- 결과: 'Product: XYZ Widget, Price: $45.99'
```

### IN

```sql
개념

주어진 목록 내에 특정 값이 존재하는지 여부를 확인하는 데 사용
```

```sql
기본 문법

value IN (value1, value2, ...)

* value: 검사할 값.

* (value1, value2, ...): 값의 목록 또는 서브쿼리. value가 목록 내에 하나라도 존재하면 조건은 참이 됩니다.
```

```sql
예제

SELECT product_name FROM products WHERE category_id IN (1, 3, 5);
-- category_id가 1, 3, 또는 5인 제품의 이름을 조회

SELECT order_id, customer_name FROM orders WHERE customer_id IN (SELECT customer_id FROM preferred_customers);
-- 우선 고객 목록에 있는 고객의 주문을 조회

SELECT employee_name FROM employees WHERE department_id IN (SELECT department_id FROM departments WHERE division = 'Sales');
-- Sales 부문에 속한 부서에 근무하는 직원의 이름을 조회

* 위의 경우 사실 아래와 같이 서브쿼리 보다 join 을 사용해서 연결하는것이 가독성과 성능에 좋다.

SELECT e.employee_name
FROM employees e
JOIN departments d ON e.department_id = d.department_id
WHERE d.division = 'Sales';
```

# 인덱스

## 1. 인덱스란?

```jsx
인덱스는 데이터베이스 테이블의 특정 열에 대한 데이터 구조로,

해당 열의 값을 기반으로 데이터를 빠르게 검색할 수 있도록 돕습니다.

인덱스는 책의 목차나 색인과 비슷한 역할을 합니다.

인덱스가 없다면 데이터베이스는 원하는 데이터를 찾기 위해 모든 데이터를 일일이 탐색해야 합니다(Full Table Scan).

반면, 인덱스가 있으면 특정 데이터를 더 빠르게 찾을 수 있습니다.
```

## 2. 인덱스 생성 및 사용 예제

```jsx
예제 시나리오:

	EMPLOYEES라는 테이블이 있다고 가정합니다.

	이 테이블에는 EMPLOYEE_ID, FIRST_NAME, LAST_NAME, DEPARTMENT_ID, SALARY, HIRE_DATE 등의 열이 있습니다.
```

### 인덱스 생성:

```jsx
REATE INDEX idx_department_id ON EMPLOYEES(DEPARTMENT_ID);
```

```jsx
여기서 idx_department_id라는 이름으로 DEPARTMENT_ID 열에 인덱스를 생성했습니다.

이제 데이터베이스는 DEPARTMENT_ID를 사용하여 데이터를 더 빠르게 검색할 수 있습니다.
```

### 인덱스를 사용하는 쿼리:

```sql
SELECT
    EMPLOYEE_ID,
    FIRST_NAME,
    LAST_NAME,
    SALARY
FROM
    EMPLOYEES
WHERE
    DEPARTMENT_ID = 10;
```

```sql
이 쿼리는 DEPARTMENT_ID가 10인 직원을 검색합니다.

DEPARTMENT_ID에 인덱스가 생성되어 있으므로, 이 쿼리는 인덱스를 사용하여 검색 성능을 최적화할 수 있습니다.
```

## 3. 인덱스의 종류와 사용 방법

### 1) 기본(B-tree) 인덱스:

```sql
1) 기본(B-tree) 인덱스:

	가장 일반적인 인덱스입니다.

	B-tree 인덱스는 대부분의 경우에 적합하며, 특히 범위 검색, 정렬된 검색에 유리합니다.
```

```sql
CREATE INDEX idx_last_name ON EMPLOYEES(LAST_NAME);

구조 : CREATE INDEX index_name ON table_name(column_name);
```

```sql
 	LAST_NAME에 인덱스를 생성하여 성을 기준으로 직원 데이터를 빠르게 검색할 수 있습니다.
```

### 2) 유니크 인덱스 (Unique Index):

```sql
중복된 값을 허용하지 않는 인덱스입니다.

일반적으로 기본 키(PRIMARY KEY)나 고유 키(UNIQUE) 제약 조건에 사용됩니다.
```

```sql
CREATE UNIQUE INDEX idx_employee_id ON EMPLOYEES(EMPLOYEE_ID);
```

```sql
EMPLOYEE_ID는 고유한 값이어야 하므로, 유니크 인덱스를 사용하여 중복을 방지합니다.
```

### 3) 복합(Composite) 인덱스:

```sql
여러 열을 결합하여 생성된 인덱스입니다.

여러 조건이 결합된 검색에서 유리합니다.
```

```sql
CREATE INDEX idx_dept_last_name ON EMPLOYEES(DEPARTMENT_ID, LAST_NAME);
```

```sql
DEPARTMENT_ID와 LAST_NAME 열에 복합 인덱스를 생성했습니다.

이 인덱스는 부서별로 직원의 성을 검색하는 쿼리에서 성능을 향상시킵니다.
```

### 4) 함수 기반 인덱스 (Function-based Index):

```sql
열의 값을 기반으로 하는 특정 함수나 표현식에 대해 인덱스를 생성합니다.

이 인덱스는 특정 함수를 적용한 결과에 대해 검색할 때 유용합니다.
```

```sql
CREATE INDEX idx_upper_last_name ON EMPLOYEES(UPPER(LAST_NAME));
```

```sql
LAST_NAME의 대문자 변환 결과에 대한 인덱스를 생성했습니다.

WHERE UPPER(LAST_NAME) = 'SMITH'와 같은 쿼리에서 성능이 향상됩니다.
```

## 4. 인덱스를 사용할 때 고려할 점

```sql
1) 인덱스의 오버헤드:

	공간: 인덱스는 추가적인 저장 공간을 차지합니다.

	성능: 인덱스가 많으면 데이터 삽입, 삭제, 갱신 작업의 성능이 저하될 수 있습니다. 데이터가 변경될 때마다 인덱스도 갱신되어야 하기 때문입니다.

2) 인덱스 사용이 적절하지 않은 경우:

	작은 테이블: 테이블 크기가 작다면 전체 테이블을 스캔하는 것이 더 빠를 수 있습니다.

	자주 변경되는 열: 데이터가 자주 변경되는 열에 인덱스를 설정하면 인덱스 갱신 오버헤드가 발생할 수 있습니다.

3) 인덱스 스캔 유형:

	Index Range Scan: 인덱스의 일부 범위를 스캔합니다. 범위 조건 검색에서 주로 사용됩니다.

	Index Full Scan: 인덱스의 모든 항목을 스캔합니다. 특정 조건 없이 데이터를 가져올 때 사용됩니다.

	Index Unique Scan: 고유 인덱스를 사용하여 정확히 하나의 행을 검색합니다.
```

## 5. 인덱스 활용을 최적화하는 팁

```sql
1) WHERE 절에 인덱스 열 사용:

	쿼리의 WHERE 절에 인덱스가 적용된 열을 포함시키면, 데이터베이스가 인덱스를 활용하여 데이터를 빠르게 검색할 수 있습니다.


SELECT * FROM EMPLOYEES WHERE LAST_NAME = 'SMITH';

이 쿼리에서 LAST_NAME에 인덱스가 적용되어 있으면 성능이 크게 향상됩니다.
```

```sql
2) JOIN에서 인덱스 사용:

	테이블 간의 JOIN에서 연결되는 열에 인덱스를 설정하면 JOIN 성능이 향상됩니다.


SELECT
    E.EMPLOYEE_ID,
    E.FIRST_NAME,
    E.LAST_NAME,
    D.DEPARTMENT_NAME
FROM
    EMPLOYEES E
JOIN
    DEPARTMENTS D
ON
    E.DEPARTMENT_ID = D.DEPARTMENT_ID;


EMPLOYEES와 DEPARTMENTS 테이블의 DEPARTMENT_ID에 인덱스가 있으면, JOIN 성능이 향상됩니다.
```

```sql
3) ORDER BY, GROUP BY에서 인덱스 사용:

	ORDER BY나 GROUP BY 절에서 인덱스가 적용된 열을 사용하면 데이터 정렬이나 그룹화 성능이 개선됩니다.


SELECT
    DEPARTMENT_ID,
    COUNT(*)
FROM
    EMPLOYEES
GROUP BY
    DEPARTMENT_ID;


 DEPARTMENT_ID에 인덱스가 있다면, 그룹화 작업이 더 빠르게 수행됩니다.
```
