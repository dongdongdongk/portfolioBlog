# { ✈️ 전투기 블루프린트 기본 설정 }

## 🎯 목표

전투기(F-18) 블루프린트를 만들고 레벨에서 실행할 수 있도록 기본 설정을 완료합니다.

---

## 🔧 1단계: 블루프린트 생성

### 📁 폴더 구조 만들기

```
Content
  └─ Fighter Jet
      └─ Blueprints (새로 생성)
```

**작업 순서**

1. Content → Fighter Jet 폴더에서 우클릭
2. 새 폴더 생성 → 이름: `Blueprints`

### 🎮 전투기 블루프린트 만들기

```
Blueprints 폴더 내부
  ├─ 우클릭 → Blueprint Class
  └─ Wheeled Vehicle Pawn 선택
      → 이름: BP_F18
```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380589/notion-blog/_/_/BG/1/image.png)

**Wheeled Vehicle Pawn이란?**

- 차량이나 비행기 같은 탈것을 만들 때 사용하는 기본 틀
- 이동 기능이 미리 포함되어 있음

---

## ⚙️ 2단계: 전투기 메시 설정

### 비행기 모델 적용

```
BP_F18 더블클릭 → 메시 컴포넌트 선택
  ├─ Skeletal Mesh Asset
  │   └─ F18 Skeletal Mesh 선택
  │
  └─ Physics
      └─ ✅ Simulate Physics 체크
```

**Simulate Physics를 켜는 이유**

- 물리 법칙을 적용하여 중력, 충돌 등이 작동하게 함
- 실제처럼 떨어지고 부딪히는 효과 구현

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380583/notion-blog/_/_/BG/1/image_1.png)

---

## 📷 3단계: 카메라 설정

### 스프링 암 + 카메라 추가

```
컴포넌트 구조
Mesh
  └─ Spring Arm (추가)
      └─ Camera (추가)
```

**작업 순서**

1. Mesh 선택 → Add → Spring Arm 검색/추가
2. Spring Arm 선택 → Add → Camera 검색/추가

### 스프링 암 설정

```
Spring Arm 속성
  ├─ Target Arm Length: 1500
  │   (비행기가 커서 멀리 봐야 함)
  │
  ├─ Location: 전투기 중심으로 이동
  │   (기본값은 하단이라 조정 필요)
  │
  └─ ✅ Use Pawn Control Rotation
      (컨트롤러로 카메라 회전 가능)
```

**Spring Arm이란?**

- 카메라를 일정 거리에 유지하는 '팔' 역할
- 벽이나 장애물을 만나면 카메라가 자동으로 당겨짐

**Use Pawn Control Rotation**

- 마우스나 컨트롤러로 시점을 움직일 수 있게 함
- 비행기 내부를 둘러볼 수 있음

# { 🎥 전투기 카메라 회전 설정 (Enhanced Input) }

## 🎯 목표

마우스로 전투기 주변을 자유롭게 둘러볼 수 있도록 카메라 회전 기능을 구현합니다.

---

## 📁 1단계: 입력 시스템 준비

### 폴더 및 파일 생성

```
Content
  └─ Fighter Jet
      └─ Inputs (새로 생성)
          ├─ IMC_FighterJet (Input Mapping Context)
          └─ IA_LookAround (Input Action)
```

**작업 순서**

1. Fighter Jet 폴더 → 우클릭 → 새 폴더 `Inputs`
2. Inputs 폴더 내부 → 우클릭
   - Input → Input Mapping Context → 이름: `IMC_FighterJet`
   - Input → Input Action → 이름: `IA_LookAround`

**용어 설명**

- **Input Mapping Context**: 여러 입력 설정을 묶어놓은 세트
- **Input Action**: 특정 행동(둘러보기)을 정의하는 단위

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380588/notion-blog/_/_/BG/1/image_7.png)

---

## ⚙️ 2단계: Input Action 설정

### IA_LookAround 설정

```
IA_LookAround 더블클릭
  └─ Value Type
      ├─ 기본값: Axis1D (1차원)
      └─ 변경값: Axis2D (Vector 2D)
          ↓
      마우스 X, Y축 동시 입력 가능
```

**Axis2D를 선택하는 이유**

- X축: 좌우 회전
- Y축: 위아래 회전
- 두 방향을 동시에 받아야 하므로 2D 필요

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380589/notion-blog/_/_/BG/1/image_8.png)

---

## 🗺️ 3단계: Input Mapping Context 연결

### IMC_FighterJet에 매핑 추가

```
IMC_FighterJet 열기
  ├─ Mappings 섹션
  │   └─ + 버튼 클릭
  │       └─ IA_LookAround 선택
  │
  └─ 매핑 확장 (▼ 클릭)
      └─ 입력 선택
          └─ Mouse → Mouse XY 2D-Axis
```

**Mouse XY 2D-Axis란?**

- 마우스의 X, Y 이동값을 동시에 전달하는 입력
- 마우스를 움직이면 그 방향과 속도 정보가 전달됨

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380589/notion-blog/_/_/BG/1/image_9.png)

---

## 🎮 4단계: 블루프린트 이벤트 그래프 설정

### Enhanced Input 활성화

```
BP_F18 → Event Graph

Event BeginPlay
  ↓
Get Player Controller
  ↓ (Return Value)
Get Enhanced Input Local Player Subsystem
  ↓ (Enhanced Input Local Player Subsystem)
Add Mapping Context
  ├─ Mapping Context: IMC_FighterJet
  └─ Priority: 0
```

**각 노드 설명**

1. **Event BeginPlay**
   - 게임이 시작될 때 한 번 실행되는 이벤트
   - 초기 설정에 사용
2. **Get Player Controller**
   - 플레이어의 입력을 담당하는 컨트롤러 가져오기
   - 키보드, 마우스 입력을 처리하는 객체
3. **Get Enhanced Input Local Player Subsystem**
   - 새로운 입력 시스템을 사용하기 위한 시스템 가져오기
   - Enhanced Input의 핵심 기능 제공
4. **Add Mapping Context**
   - 입력 설정(IMC_FighterJet)을 게임에 등록
   - 이제부터 설정한 입력이 작동함

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380583/notion-blog/_/_/BG/1/image_10.png)

## 🔄 5단계: 카메라 회전 구현

### 입력 이벤트 추가

```
Event Graph에서 우클릭
  └─ IA_LookAround 검색
      └─ Event IA_LookAround (Triggered) 선택
```

**Triggered란?**

- 입력이 발생하는 동안 계속 호출됨
- 마우스를 움직이는 내내 실행됨

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380583/notion-blog/_/_/BG/1/image_11.png)

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380584/notion-blog/_/_/BG/1/image_12.png)

### Vector 2D 분리

```
Event IA_LookAround
  └─ Action Value (Vector 2D)
      └─ Break Vector 2D
          ├─ X (좌우 회전용)
          └─ Y (위아래 회전용)
```

**Break Vector 2D 노드**

- 2D 값을 X, Y로 분리
- 각각 다른 회전에 사용하기 위함
-

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380584/notion-blog/_/_/BG/1/image_13.png)

## 🎯 6단계: 회전 노드 연결

### 좌우 회전 (Yaw)

```
Break Vector 2D
  └─ X
      └─ Add Controller Yaw Input
          └─ Target: Self (전투기 자신)
```

**Add Controller Yaw Input 노드**

- Z축 중심 회전 (좌우 회전)
- 입력값만큼 카메라를 좌우로 회전시킴

### 위아래 회전 (Pitch)

```
Break Vector 2D
  └─ Y
      └─ Add Controller Pitch Input
          └─ Target: Self
```

**Add Controller Pitch Input 노드**

- Y축 중심 회전 (위아래 회전)
- 입력값만큼 카메라를 위아래로 회전시킴

---

## 🔧 7단계: Y축 반전 설정

### 문제 상황

```
마우스를 위로 → 카메라도 위로
마우스를 아래로 → 카메라도 아래로
  ↓
일반적인 게임과 반대 (불편함)
```

### Negate 모디파이어 추가

```
IMC_FighterJet → IA_LookAround 매핑
  └─ Modifiers 섹션
      └─ + 버튼 → Negate 선택
          ├─ ❌ X (체크 해제)
          ├─ ✅ Y (체크 유지)
          └─ ❌ Z (체크 해제)
```

**Negate 모디파이어**

- 입력값에 -1을 곱함
- Y만 체크 → Y값만 반전 (위↔아래 뒤집기)
- 결과: 마우스 위로 → 카메라 아래로 (자연스러움)

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380584/notion-blog/_/_/BG/1/image_14.png)

## 📊 완성된 블루프린트 구조

```
Event BeginPlay
  ↓
Get Player Controller
  ↓
Get Enhanced Input Local Player Subsystem
  ↓
Add Mapping Context (IMC_FighterJet)

───────────────────────────────

Event IA_LookAround (Triggered)
  ↓
Action Value (Vector 2D)
  ↓
Break Vector 2D
  ├─ X → Add Controller Yaw Input (좌우)
  └─ Y → Add Controller Pitch Input (위아래, 반전됨)
```

**플레이 시 동작**

```

  → 전투기 주변을 좌우로 회전

마우스 위아래 이동
  → 전투기를 위아래에서 바라봄 (반전 적용)
```

## ⚠️ 주의사항

- Vector Type을 Axis2D로 반드시 변경
- Negate에서 Y만 체크 (X, Z는 해제)
- Add Mapping Context는 BeginPlay에서 한 번만 실행
- Target은 항상 Self (전투기 자신)

## 💡 핵심 개념 정리

**Enhanced Input 시스템 흐름**

```
1. Input Action 생성
   → 어떤 행동인지 정의

2. Input Mapping Context에 등록
   → 실제 키/마우스와 연결

3. BeginPlay에서 활성화
   → 게임에 등록

4. Event로 입력 받기
   → 실제 기능 구현
```

**카메라 회전 축**

```
Yaw (좌우)
  └─ Z축 중심 회전

Pitch (위아래)
  └─ Y축 중심 회전

Roll (기울기)
  └─ X축 중심 회전 (이번엔 미사용)
```

# {🛞 전투기 바퀴(Wheel) 설정 }

## 🎯 목표

Vehicle Movement Component에 바퀴 정보를 등록하여 전투기가 움직일 수 있는 기반을 만듭니다.

---

## 📋 바퀴 구조 확인

### 전투기의 바퀴 구성

```
F-18 전투기
  ├─ 앞바퀴: 1개 (전방)
  └─ 뒷바퀴: 2개 (후방 좌우)
      ↓
  총 3개의 바퀴
```

**왜 바퀴 위치를 알려줘야 하나?**

- Vehicle Movement Component가 바퀴 위치를 알아야 물리 계산 가능
- 각 바퀴의 "뼈(Bone)" 이름으로 위치 인식

---

## 🔧 1단계: Wheel 블루프린트 생성

### Chaos Vehicle Wheel 만들기

```
Content → Fighter Jet → Blueprints
  ├─ 우클릭 → Blueprint Class
  └─ Chaos Vehicle Wheel 선택
      → 이름: BP_F18_Wheel
```

**Chaos Vehicle Wheel이란?**

- 차량/비행기의 바퀴를 정의하는 클래스
- 바퀴 크기, 마찰력, 브레이크 설정 등 포함

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380584/notion-blog/_/_/BG/1/image_15.png)

---

## ⚙️ 2단계: Wheel 속성 설정

### BP_F18_Wheel 설정값

```
BP_F18_Wheel 더블클릭

Wheel Properties
  ├─ Wheel Radius: 40
  │   (바퀴 반지름)
  │
  ├─ Wheel Width: 30
  │   (바퀴 너비)
  │
  ├─ ✅ Affected by Handbrake
  │   (핸드브레이크 영향 받음)
  │
  └─ ✅ ABS Enabled
      (급제동 방지 시스템)
```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380584/notion-blog/_/_/BG/1/image_16.png)

**각 설정 설명**

- **Wheel Radius/Width**
  - 바퀴 크기 정의
  - 3D 모델과 맞지 않으면 조정 필요
- **Affected by Handbrake**
  - 핸드브레이크 사용 시 이 바퀴가 잠김
  - 전투기가 특정 지점에 멈출 때 사용
- **ABS Enabled**
  - Anti-lock Braking System
  - 브레이크 시 바퀴가 미끄러지지 않고 회전 유지

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380585/notion-blog/_/_/BG/1/image_17.png)

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380585/notion-blog/_/_/BG/1/image_18.png)

## 🎮 3단계: BP_F18에 Wheel 등록

### Vehicle Movement Component 설정

```
BP_F18 → Vehicle Movement Component

Wheel Setups
  └─ 배열 크기: 3개로 확장
      ├─ [0] 첫 번째 바퀴
      ├─ [1] 두 번째 바퀴
      └─ [2] 세 번째 바퀴
```

**작업 순서**

1. Wheel Setups 섹션 찾기
2. - 버튼 3번 클릭 (총 3개 요소)
3. 각 요소의 Wheel Class 변경

   ```
   기본값: 기본 Wheel 클래스  ↓변경값: BP_F18_Wheel
   ```

### Wheel Bone 검색

```
  └─ 검색창에 "wheel" 입력

  3개의 Wheel Bone 표시
    ├─ wheel_f (앞바퀴)
    ├─ wheel_l (왼쪽 뒷바퀴)
    └─ wheel_r (오른쪽 뒷바퀴)
```

**Bone이란?**

- 3D 모델의 '뼈대'
- 각 부품의 위치와 움직임을 정의
- 바퀴가 어디 달려있는지 이름으로 구분

**Bone 확인 방법**

```

  ↓

  ↓
뷰포트에서 해당 위치로 카메라 이동
  ↓
실제 바퀴 위치 확인 가능
```

# { ✈️ 전투기 에어포일(Airfoil) 설정 }

## 🎯 목표

Wing(날개), Rudder(방향타), Elevator(승강타)를 정의하여 전투기가 비행할 수 있는 공기역학 시스템을 구축합니다.

---

## 📚 에어포일 기본 개념

### 비행기의 주요 제어 표면

```
전투기 구조
  ├─ Wing (날개)
  │   └─ 양력 발생 (위로 뜨게 함)
  │
  ├─ Rudder (방향타)
  │   └─ 좌우 방향 제어
  │
  └─ Elevator (승강타)
      └─ 위아래 방향 제어
```

**에어포일이란?**

- 공기와 접촉하여 양력/항력을 만드는 표면
- 날개, 방향타, 승강타 모두 에어포일의 일종
- Vehicle Movement Component에 각각 정의 필요

---

## 🔍 1단계: 에어포일 구조 확인

### Skeleton에서 부품 확인

```
F-18_Skeleton 열기
  └─ 검색: "rudder" / "elevator"
      ├─ Rudder (방향타) - 수직 꼬리날개
      └─ Elevator (승강타) - 수평 꼬리날개
```

**왜 확인하나?**

- 각 부품의 Bone 이름 파악
- 실제 위치 확인 (F 키로 포커스)

```
      └─ + 버튼으로 3개 추가
          ├─ [0] Wing (날개)
          ├─ [1] Rudder (방향타)
```

## 🪽 3단계: Wing (날개) 설정

### [0] Wing 설정값

```
Airfoil Type
  └─ Wing 선택

Bone Name
  └─ COG_joint (전체 동체 사용)
```

**왜 전체 동체를 날개로?**

- 전투기는 동체 전체에서 양력 발생
- 물리 계산에 포함되려면 정의 필요
- COG_joint = Center of Gravity Joint (무게중심)

### Wing 속성 설정

```
Offset
  └─ 기본값 유지 (0, 0, 0)

Up Axis
  ├─ 기본값: -1
  └─ 변경값: 1
      (위쪽 방향 반전)

Area (평방미터)
  └─ 15
      ├─ 더 크면: 양력 증가, 항력도 증가
      └─ 더 작면: 이륙 어려움
```

**Area (면적) 설명**

- 에어포일의 표면적
- 면적이 클수록:
  - ✅ 양력(Lift) 증가 → 빨리 뜸
  - ⚠️ 항력(Drag) 증가 → 저항 커짐
- 게임 플레이에 맞게 조정 필요

**나머지 옵션**

- 기본값 유지
- 마우스 오버 시 툴팁으로 설명 확인 가능

## 🎯 4단계: Rudder (방향타) 설정

### [1] Rudder 설정값

```
Airfoil Type
  └─ Rudder 선택

Bone Name
  └─ COG_joint (동체 전체)

Up Axis
  └─ 1

Area
  └─ 1 (방향타는 작아도 충분)
```

### Rudder 특수 설정

```
Camber
  ├─ 기본값: 1
  └─ 변경값: 0
      (방향타는 캠버 불필요)

Max Control Angle (최대 조종 각도)
  └─ 90 (또는 60)
      └─ 방향타가 움직일 수 있는 최대 각도
```

**Camber란?**

- 날개의 휘어진 정도
- 날개는 휘어져야 양력 발생
- 방향타는 평평해야 좌우 제어 정확
- **방향타는 0으로 설정**

**Max Control Angle 설명**

```
0도
  └─ 고정면 (움직이지 않음)

90도
  └─ 완전히 돌릴 수 있음

실제 전투기
  └─ 보통 60~90도 사용
```

**Fixed Surface vs Control Surface**

- Fixed Surface: 움직이지 않는 면 (날개 본체)
- Control Surface: 움직이는 면 (방향타, 승강타)
- Max Control Angle > 0 → Control Surface

---

## ⬆️ 5단계: Elevator (승강타) 설정

### [2] Elevator 설정값

```
Airfoil Type
  └─ Elevator 선택

Bone Name
  └─ COG_joint

Up Axis
  └─ 1

Area
  └─ 3
      (방향타보다 크게, 날개보단 작게)
```

### Elevator 특수 설정

```
Camber
  └─ 약간 증가 (예: 0.3)
      └─ 위아래 제어에 약간의 곡률 필요

Max Control Angle
  └─ 90
      └─ 위아래 기동성 확보
```

**왜 Area가 3인가?**

- Elevator는 비행기 자세 제어
- 면적이 커야 빠른 반응 가능
- 너무 크면 과민 반응 → 제어 어려움

## 💡 중요 개념 설명

### 양력과 항력

```
Lift (양력)
  └─ 비행기를 위로 띄우는 힘
      └─ Area 크면 증가

Drag (항력)
  └─ 비행기를 뒤로 당기는 저항

균형
  └─ Area를 조정하여 적절한 비행감 찾기
```

```
-1
  └─ 아래쪽이 위

1
  └─ 위쪽이 위 (일반적)

설정 이유
  └─ 모델의 방향과 맞추기 위함
```

### Bone Name을 모두 COG_joint로?

```
이유
  ├─ 전투기는 동체 전체가 공기역학 영향
  ├─ 각 에어포일이 동체에서 작용
  └─ 세밀한 제어는 Type으로 구분

만약 분리하려면
  └─ 각 부품의 실제 Bone 사용
      (예: rudder_bone, elevator_bone)
```

# { 🚀 전투기 Thruster (추진기) 설정 }

## 🎯 목표

엔진/추진기를 정의하여 전투기가 앞으로 나아갈 수 있는 추진력을 부여합니다.

---

## 📋 현재 상황

```
Vehicle Movement Component가 아는 것
  ├─ ✅ Wheels (바퀴)
  ├─ ✅ Wing (날개)
  ├─ ✅ Rudder (방향타)
  └─ ✅ Elevator (승강타)

아직 모르는 것
  └─ ❌ Motor/Engine/Thruster (추진력)
```

**추진기 없으면?**

- 양력만 있고 앞으로 가는 힘 없음
- 비행기가 제자리에 떠 있기만 함

## 🔧 Thruster Setup 설정

### Thruster 추가

```

  └─ Thruster Setup 섹션
      └─ + 버튼 클릭
```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380586/notion-blog/_/_/BG/1/image_23.png)

### 설정값

```
Thruster Type
  └─ Fixed (고정형)
      └─ 방향이 바뀌지 않는 추진기

Bone Name
  └─ COG_joint
      └─ 동체 전체에 추진력 전달

Offset
  └─ 기본값 유지 (0, 0, 0)

Thrust Axis
  └─ (1, 0, 0) - X축 방향
      └─ 전방으로 밀어내는 힘

Max Thrust Force
  └─ 35000
      └─ 최대 추진력 (뉴턴 단위)
```

---

## 💡 주요 개념

### Thruster Type: Fixed

```
Fixed (고정형)
  └─ 한 방향으로만 추진
  └─ 일반 전투기 엔진

Vectored (가변형)
  └─ 방향 전환 가능
  └─ VTOL 같은 특수 기체
```

### Thrust Axis (추진 방향)

```
언리얼 엔진 좌표계
  ├─ X축: Forward (앞)
  ├─ Y축: Right (오른쪽)
  └─ Z축: Up (위)

설정값 (1, 0, 0)
  └─ X축 양의 방향으로 추진
  └─ 비행기를 앞으로 밀어냄
```

### Max Thrust Force

```
35000 뉴턴
  ├─ 전투기를 밀어내는 최대 힘
  ├─ 클수록: 빠른 가속
  └─ 작을수록: 느린 가속

조정 기준
  ├─ 너무 약함 → 값 증가
  └─ 너무 빠름 → 값 감소
```

```
  ├─ Bone: COG_joint
  ├─ Offset: (0, 0, 0)
  ├─ Thrust Axis: (1, 0, 0)

```

# { 🎮 Arcade Control (아케이드 컨트롤) 설정 }

## 🎯 목표

실제 전투기처럼 어렵지 않고, 플레이어가 쉽게 조종할 수 있도록 아케이드 스타일 제어 시스템을 구현합니다.

---

## 📚 아케이드 컨트롤이란?

```
실제 전투기
  ├─ 복잡한 조종
  ├─ 섬세한 입력 필요
  └─ 일반 플레이어는 제어 어려움
      ↓
아케이드 컨트롤
  ├─ 단순화된 조종
  ├─ 직관적인 반응
  └─ 게임처럼 쉬운 제어
```

**왜 필요한가?**

- 시뮬레이션 ≠ 게임
- 플레이어 편의성 > 현실성
- 재미있는 조종감 구현

## 🔧 Arcade Control 설정

### 기본 활성화

```
BP_F18 → Vehicle Movement Component
  └─ Arcade Control 섹션
      └─ ✅ Enable Arcade Control
```

## ⚙️ Torque Scaling (회전력 조정)

### 설정값

```
Yaw Torque Scaling
  └─ 0.1
      └─ 좌우 회전력 (약하게)

Pitch Torque Scaling
  └─ 1
      └─ 위아래 회전력 (보통)

Roll Torque Scaling
  └─ 1
      └─ 기울기 회전력 (보통)
```

**각 축 설명**

```
Yaw (좌우 회전)
  ├─ Z축 중심 회전
  ├─ 비행기가 수평으로 방향 전환
  └─ 0.1 = 부드럽고 안정적

Pitch (위아래)
  ├─ Y축 중심 회전
  ├─ 비행기가 올라가거나 내려감
  └─ 1 = 민감한 반응

Roll (좌우 기울기)
  ├─ X축 중심 회전
  ├─ 날개가 좌우로 기울어짐
  └─ 1 = 민감한 반응
```

**왜 Yaw만 0.1인가?**

- Yaw는 전투기에서 보조적 역할
- 너무 민감하면 제어 어려움
- Roll + Pitch 조합으로 주로 방향 전환

### 설정값

```

  └─ 1
```

**Rotation Damping이란?**

```
감쇠 없음 (0)
  └─ 회전 시작하면 계속 회전
  └─ 멈추기 어려움

감쇠 있음 (1)
  └─ 입력 멈추면 회전도 서서히 멈춤
  └─ 자연스러운 제어감
```

**효과**

- 플레이어가 입력 놓으면 자동으로 안정화

- 섬세한 조종 가능

# { 🎮 Fighter Jet 스로틀(엔진 출력) 제어 시스템 만들기 }

## 🎯 목표

- Ctrl 키: 엔진 출력 감소 (감속)

---

## 💡 핵심 개념

### Throttle (스로틀)이란?

```
실제 비행기의 스로틀 레버
  ↓
앞으로 밀면 → 엔진 출력 최대 (빠르게 비행)
  ↓
뒤로 당기면 → 엔진 출력 최소 (느리게 비행 또는 정지)
  ↓
값의 범위: 0.0 (꺼짐) ~ 1.0 (최대 출력)
```

**Joystick (조이스틱)**

- 비행기가 어느 방향으로 갈지 조종 (좌우, 상하)

**Throttle (스로틀)**

- 비행기가 얼마나 빠르게 갈지 조종 (속도)

```
스로틀 값: 0.0 → 1.0 (급격한 변화)
  ↓
비행기: 갑자기 최고속도로 가속
  ↓
비현실적이고 조종하기 어려움
```

---

## 💡 핵심 개념: Interpolation (보간)

### Interpolation이란?

```
두 값 사이를 부드럽게 연결하는 기법

예시:
  현재값: 0
  목표값: 1
  ↓
  중간 과정: 0 → 0.3 → 0.6 → 0.9 → 1.0
  (시간에 따라 점진적으로 변화)
```

**실생활 비유**

- 급브레이크 (Interpolation 없음): 갑자기 멈춤 → 위험
- 부드러운 브레이크 (Interpolation 적용): 천천히 감속 → 안전

## 🔧 1단계: 변수 생성

### 왜 변수가 필요한가?

```
Interpolation 노드의 작동 원리:
  ↓
현재 스로틀 값 저장 필요
  ↓
매 프레임마다 조금씩 증가
  ↓
변수에 새로운 값 저장
  ↓
다음 프레임에서 다시 사용
```

### 변수 생성 방법

```
Variables 패널에서 + 버튼 클릭
  ↓
변수 이름: Throttle Value
  ↓
타입: Float
  ├─ 기본값: 0.0
  └─ 이유: 스로틀도 Float 타입이므로 동일하게 설정
```

## 🔧 2단계: FInterp To 노드 구성

### FInterp To 노드란?

```
기능: Float 값을 부드럽게 보간하는 노드
  ├─ F = Float (소수점 값)
  ├─ Interp = Interpolation (보간)
  └─ To = 목표 값까지

작동 방식:
  현재값에서 목표값까지
  시간에 따라 점진적으로 변화
```

### 노드 입력값 설명

**1. Current (현재값)**

```
의미: 지금 현재 스로틀이 얼마인지
연결: Throttle Value 변수 (GET)
  ↓
처음 시작: 0.0
매 프레임: 이전에 계산된 값 사용

```

**2. Target (목표값)**

```
의미: 최종적으로 도달할 값
연결: Action Value (IA_Thrust 이벤트의 출력)
  ↓
Shift 누를 때: 1.0
Shift 안 누를 때: 0.0

```

**3. Delta Time (델타 타임)**

```
의미: 이전 프레임과 현재 프레임 사이의 시간 간격

연결 방법 1:
  Event Tick → Delta Seconds 출력 사용

연결 방법 2 (강의에서 사용):
  Get World Delta Seconds 노드 사용
  ↓
  둘 다 같은 기능
```

**Delta Time이 왜 필요한가?**

```
문제 상황:
  고성능 PC: 1초에 120프레임
  저성능 PC: 1초에 30프레임
  ↓
  같은 시간에 다른 변화량 발생
  ↓
해결:
  Delta Time으로 프레임 간격 계산
  ↓
  모든 PC에서 동일한 속도로 변화
```

**4. Interp Speed (보간 속도)**

```
값: 0.5 (강의 예시)

의미:
  - 높을수록 → 빠르게 변화
  - 낮을수록 → 천천히 변화

조정 가능:
  0.5 → 적당한 속도
  1.0 → 더 빠름
  0.2 → 더 느림
```

## 💡 브레이크 vs 핸드브레이크 개념

### 일반 브레이크 (Brake)

```
기능: 엔진 출력을 줄임
  ↓
스로틀 값: 1.0 → 0
  ↓
결과:
  - 엔진 추진력 감소
  - 관성은 그대로 유지
  - 서서히 감속 (완전 정지 X)
```

**실제 비행기 비유**

```
엔진 출력을 낮춤
  ↓
추진력은 사라지지만
  ↓
공기 중에서 관성으로 계속 미끄러짐
```

### 핸드브레이크 (Handbrake)

```
기능: 바퀴/브레이크 시스템 강제 작동
  ↓
물리적으로 움직임 차단
  ↓
결과:
  - 즉시 정지 (또는 빠른 감속)
  - 관성 무시
  - 완전 정지 가능
```

**자동차 비유**

```
일반 브레이크:
  액셀에서 발을 뗌
  ↓
  차가 서서히 멈춤 (관성으로 조금 굴러감)

핸드브레이크:
  브레이크를 확 당김
  ↓
  바퀴 고정으로 즉시 정지
```

### 왜 둘 다 필요한가?

```
일반 브레이크만 있으면:
  - 완전히 멈추기 어려움
  - 미끄러지는 문제 발생
  - 정밀한 위치 조정 불가

핸드브레이크 추가:
  - 원하는 위치에 정확히 정지
  - 비상 상황 대응 가능
  - 조종 편의성 향상

```
