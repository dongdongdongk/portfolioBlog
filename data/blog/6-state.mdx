## 1. State란 무엇인가?

- **정의**:
  State는 **게임의 전역적 상태를 나타내는 오디오 동기화(Game Sync)** 방식입니다.
  특정 이벤트(예: 플레이어가 죽음, 물 속에 들어감, 보스전 시작 등)에 따라 **게임 전체의 사운드 환경**을 바꾸는 데 사용됩니다.
- **특징**:
  - 단순히 값이 변하는 RTPC와 달리, State는 **불연속적인 상태 전환**을 다룹니다.
  - 예:
    - Alive ↔ Dead
    - Normal ↔ Underwater
    - SafeZone ↔ BattleZone
- **활용 예시**:
  - 플레이어가 죽었을 때 **모든 사운드를 로우패스 처리** → 흐릿하게 들리게 만들기.
  - 전투가 시작되면 **음악 트랙을 바꾸기**.
  - 심장 박동 소리를 **플레이어가 살아있을 때만 반복**하다가, 죽으면 멈추도록 하기.

---

## 2. State Group 만들기

- **개념**:
  State는 항상 **State Group(상태 그룹)** 안에 속합니다.
  그룹은 “상태의 집합”이며, 각 그룹에는 최소 두 개 이상의 상태가 있어야 합니다.
- **예시**:
  - State Group: `PlayerCondition`
    - State 1: Alive
    - State 2: Dead
- **만드는 방법(Wwise 내부)**:
  1. **Project Explorer → Game Syncs → States** 경로에서 `Default Work Unit` 선택.
  2. **Create New State Group** 클릭.
  3. 이름 지정: 예) `PlayerCondition`.
  4. 그 안에 상태 추가: `Alive`, `Dead`.

---

## 3. State의 전환(Transition) 이해하기

- **Transition**이란?
  하나의 State에서 다른 State로 넘어갈 때, **오디오 효과가 바뀌는 데 걸리는 시간**을 지정하는 기능.
- **옵션들**:
  - **Instant(즉시)**: 바로 전환됨.
  - **Fade(페이드)**: 부드럽게 전환됨 (값을 서서히 변화시킴).
  - **Custom Curve**: 사용자가 정의한 곡선을 따라 점진적으로 전환.
- **예시**:
  - Alive → Dead로 넘어갈 때 1초 동안 볼륨이 줄어들고 로우패스 필터가 점점 적용됨.

---

## 4. State를 활용한 사운드 제어

- **State는 오브젝트 속성(Property)에 영향을 줌**.
- 적용할 수 있는 대표 속성:
  - **Volume**: 소리 크기
  - **Low-Pass Filter (LPF)**: 소리가 탁하게 변함
  - **High-Pass Filter (HPF)**: 저음이 깎이고 고음만 남음
  - **Pitch**: 소리의 높낮이
  - **Bus Routing**: 특정 오디오 버스로 신호를 보낼지 결정
- **예시**:
  - Alive 상태 → 심장 박동 소리 활성화, Volume 100%
  - Dead 상태 → 심장 박동 소리 중지, 전체 사운드에 LPF 적용

---

## 5. Transport Control에서 State Group 테스트하기

- **Transport Control**: Wwise에서 사운드를 테스트하는 창.
- **State Group 테스트 방법**:
  1. Transport Control 열기.
  2. `Display States` 버튼 클릭.
  3. 만든 State Group (`PlayerCondition`)이 표시됨.
  4. Alive ↔ Dead를 전환하면서 심장 박동 사운드 변화를 들어봄.

---

## 6. 레벨 시작 시 사운드 트리거하기

- **목적**: 게임에서 특정 레벨이 시작될 때 자동으로 특정 사운드를 재생하도록 설정.
- **방법**:
  - Event를 생성 → 레벨 시작 시 호출되도록 스크립트에 연결.
  - Event 안에서 특정 State를 **초기 상태로 설정** 가능.
- **예시**:
  - 레벨 시작 시 → Alive State 활성화 + 심장 박동 소리 실행.
  - 플레이어가 죽는 순간 → Dead State로 전환 + 심장 박동 소리 멈춤.

---

## 7. State와 다른 Game Sync 비교

| 구분      | RTPC                  | Switch                     | State                  |
| --------- | --------------------- | -------------------------- | ---------------------- |
| 변화 방식 | 연속 값(슬라이더)     | 선택적, 특정 오브젝트 한정 | 전역적, 게임 전체 상태 |
| 예시      | 체력(0~100)           | 무기 종류 (총, 칼)         | 플레이어 생존 상태     |
| 사용처    | 볼륨·피치 점진적 변화 | 개별 사운드 교체           | 전체 사운드 환경 전환  |

---

## 8. 실전 예시: 심장 박동 멈추게 하기

- **상황**: 플레이어가 살아 있을 때 → 심장 박동이 반복 재생.
- **변화 조건**: 플레이어가 Dead 상태에 들어가면 → 심장 박동 정지.
- **구현 단계**:
  1. `PlayerCondition` State Group 생성.
  2. Alive / Dead 상태 추가.
  3. Alive 상태에서 → 심장 박동 소리 활성화.
  4. Dead 상태에서 → 심장 박동 소리 중단.
  5. 전환 시 LPF(저음 필터) 추가하여 “죽은 듯한” 효과 강조.

## 1. State와 State Group 개념 이해하기

- **State Group**
  - 여러 개의 **State(상태)**를 묶어 관리하는 컨테이너.
  - 게임 내에서 특정 상황에 따라 오디오를 다르게 재생할 때 사용.
  - 예: 플레이어 생존 여부, 날씨 상태, 게임 난이도 등.
- **State**
  - State Group 안에 들어가는 개별 상태.
  - 게임이 현재 어떤 상태인지 나타냄.
  - 예: PlayerLife 그룹 안의 `Alive`(살아있음), `Defeated`(패배).

👉 **핵심**: State Group은 "상태 카테고리", State는 "그 안의 실제 상태"라고 생각하면 됨.

## 2. Cube 실행 및 연결하기

- **Cube 실행 이유**
  - Cube는 학습용 샘플 게임으로, 실제 게임 환경에서 오디오 동작을 테스트하기 위함.
  - 우리가 만든 **State 변경**이 Cube에서 즉시 반영되는지 확인 가능.
- **연결 방법**
  1. Cube 실행.
  2. Wwise 실행 후 프로젝트 파일(Module 6) 열기.
  3. Wwise와 Cube를 연결(Connect)하여 실시간 테스트 가능하게 설정.

## 3. State Group 생성하기

- **위치**: `Project Explorer → Game Syncs 탭 → States 폴더 → Default Work Unit`
- **생성 방법**
  1. `Create new 'State Group'` 아이콘 클릭.
  2. 새 Group 이름을 `PlayerLife`로 지정.

👉 **중요 포인트**:

- 게임 코드에서 이 이름(`PlayerLife`)을 그대로 사용하므로 정확히 입력해야 함.
- 잘못된 이름 사용 시, 게임과 Wwise 간 동기화 불가.

## 4. State 생성 및 관리하기

- **생성 방법**
  1. `PlayerLife` State Group 선택.
  2. `Create new 'State'` 버튼 클릭.
  3. 첫 번째 State 이름: `Alive`
  4. 두 번째 State 이름: `Defeated`
- **State 특징**
  - 같은 그룹 안에서는 항상 **하나의 State만 활성화** 가능.
  - 즉, `Alive` 상태일 때는 `Defeated`가 꺼지고, 반대도 마찬가지.

## 5. State 활용 예시 (Alive / Defeated)

- `Alive` State → 플레이어가 살아 있을 때의 오디오 설정 (예: 배경 음악 정상 재생, 심장 박동 소리 유지).
- `Defeated` State → 플레이어가 죽었을 때의 오디오 설정 (예: 음악 정지, 사운드 이펙트 "죽음 효과음" 실행).

👉 이렇게 하면, **게임 상황에 따라 오디오가 자동 전환**됨.

## 6. 게임 디자인에서의 협업 포인트

- **사운드 디자이너 ↔ 게임 프로그래머 협업**
  - State Group과 State 이름은 반드시 **합의된 명칭**을 사용해야 함.
  - 예: 사운드팀에서 `Alive`라고 했는데, 개발팀에서 `Living`으로 코드를 작성하면 동기화 실패.
  - 즉, 이름은 단순 텍스트 기반 매칭이므로 오타/불일치에 매우 민감.

👉 실제 프로젝트에서는 문서화된 **State 정의서**를 작성하고 공유하는 게 일반적임.

## 1. State 전환의 개념 이해하기

- **State**: 게임 내 전역적인 변화에 반응하는 *Game Sync*의 한 종류.
- **전환 효과**: 단순히 “즉시 전환”하는 것이 아니라, 일정 시간 동안 점진적으로 사운드 속성(볼륨, 필터, 이펙트 등)을 바꿀 수 있음.
- 이렇게 하면 플레이어의 체감이 더욱 자연스럽고 몰입감 있는 오디오 경험을 제공.

---

## 2. State Transition Time(전환 시간) 기능

- **정의된 시간 동안** 오브젝트 속성 변화가 *부드럽게 적용*되도록 함.
- 효과:
  - 갑작스러운 변화(ON/OFF 느낌) → 부드러운 변화(자연스러운 Fade-in/out).
  - 플레이 상황을 더 사실적으로 반영할 수 있음.

## 3. 예시: 물속/물밖 효과

- 상황: 배 위에서 플레이하다가 **물에 빠질 때**.
- 적용 방법:
  - 물에 빠지는 순간 → **즉시 로우패스 필터 적용** (고주파수 차단 → 물속 소리 느낌).
  - 물에서 나올 때 → **몇 초 동안 점진적으로 원래 소리로 복귀**.
- 결과:
  - 플레이어 귀에 물이 빠져나오는 듯한 효과 연출.
  - 사운드가 다시 전체 주파수로 서서히 회복됨.

## 4. 실습: Alive → Defeated 전환 설정

1. **Project Explorer** 열기 → **Game Syncs 탭** 선택.
2. **PlayerLife State Group** 선택.
3. 기본 편집기(프로퍼티 창)에서 **Insert** 클릭.
4. **Custom Transition Time** 창이 열림.
   - From 목록: **Alive** 선택.
   - To 목록: **Defeated** 선택.
   - Transition Time: **5초** 입력.
5. 저장 후, Cube 게임과 연결해 테스트하면 Alive 상태에서 Defeated 상태로 바뀔 때 **5초 동안 점진적으로 변화**가 일어남.

## 5. Custom Transition Time 옵션

- **From**: 전환이 시작되는 State (현재 상태).
- **To**: 전환이 도착하는 State (목표 상태).
- **Transition Time**: 전환이 걸리는 시간(초 단위).
  - 0초 → 즉시 전환.
  - n초 → n초 동안 점진적으로 변화.

## 1. State와 속성(Property) 연결하기

- **개념**:
  - State는 게임의 전역적인 상태 변화를 의미합니다. (예: Alive, Defeated)
  - 오디오 오브젝트의 다양한 **속성(Properties)** 과 연결하여, 특정 상태일 때 어떤 소리 변화를 줄지 정의할 수 있습니다.
  - 즉, State는 "조건", 속성(Property)은 "조건에 따른 변화"라고 볼 수 있습니다.
- **핵심**:
  - 단순히 소리를 켜고 끄는 것이 아니라, **볼륨, 필터, 피치 등 다양한 오디오 속성**을 제어할 수 있다는 점이 중요합니다.

## 2. Heartbeat 오브젝트 선택하기

  Project Explorer → **Audio 탭** → Actor-Mixer Hierarchy → Default Work Unit → **Heartbeat 오브젝트 선택**
- **이유**:
  - Heartbeat 사운드가 플레이어의 상태(State)에 따라 반응해야 하기 때문에, 해당 오브젝트에서 설정을 진행합니다.

## 1. Event 개념 이해하기

- **Event란?**
  게임 내에서 발생하는 특정 상황을 Wwise가 감지하고, 사운드 재생/정지/상태 변화 같은 **오디오 동작을 실행하도록 연결하는 트리거**.
- **이번 단원에서 필요한 Event**:
  - 게임 시작 또는 맵 로드 시 심장 박동 사운드가 자동으로 시작되도록 하는 Event.

---

## 2. Heartbeat 재생 Event 생성하기

- **Heartbeat 오브젝트에서 Event 만들기**
  1. Property Editor에서 **Heartbeat 오브젝트** 우클릭.
  2. **New Event > Play** 선택.
- 이렇게 하면 `Play_Heartbeat`라는 이름의 Event가 자동 생성됨.
- 기본 동작: 이 Event가 호출되면 Heartbeat 사운드가 재생됨.

## 3. Map_Loaded Event와 이름 변경

- 게임에는 "게임 시작" 또는 "맵 로드" 시 발생하는 **게임 호출(Game Call)** 이 이미 존재.
- Wwise에서 Event 이름을 **Map_Loaded**로 변경 → 이 호출과 매핑됨.
- 결과: 맵이 로드될 때마다 심장 박동 소리가 시작됨.

---

## 4. 중복 재생 문제와 해결 방법

- **문제 상황**:
  - 맵이 다시 로드될 때마다 `Map_Loaded` Event가 실행 → 새로운 심장 박동이 계속 겹쳐서 재생됨.
  - 플레이어 체력이 꽉 찬 상태라면 들리지 않아서 눈치채기 어려움.
- **해결 방법**:
  - `Map_Loaded` Event에 **두 가지 동작(Action)** 추가:
    1. **Stop**: 이미 재생 중일 수 있는 Heartbeat 멈추기.
    2. **Play**: Heartbeat 다시 시작하기.

```csharp
실제 프로젝트에서는 stopAll 을 하고 그다음 Play 를 실행시키고 있다.
```

## 5. Stop과 Play 동작 순서 이해하기

- Event 안에서 여러 동작이 있으면 **작성된 순서대로 실행**됨.
- 따라서:
  - 먼저 Stop → 기존 Heartbeat 종료.
  - 이어서 Play → 새로운 Heartbeat 시작.
- 결과: 맵 로드 시 **중복 재생 없이 항상 하나의 Heartbeat만 유지**.

## 6. Cube에서 Event 테스트하기

- Cube 게임 내에서 Event 동작 확인 가능.
- 테스트 절차:
  1. `Esc` → 메뉴 열기 → `load map` 선택 → 원하는 맵 선택 후 Enter.
  2. 같은 레벨이 다시 로드됨.
  3. 체력은 가득 차 있으므로 Heartbeat는 들리지 않음.
  4. 적에게 피해를 받아 체력이 줄면 Heartbeat 소리가 점점 **크고 선명하게** 들림.

## 7. State와 Event의 연동

- **문제**:
  Cube는 PlayerLife State를 직접 설정하지 않음 → 플레이어가 패배해도 Heartbeat는 계속 재생됨.
- **해결**:
  Event를 활용하여 State를 간접적으로 제어 가능.
  - 즉, Event → State 변경 → 사운드 속성 변화.

## 8. 추가 Event로 State 제어하기

- 플레이어 패배 & 부활 시 상태(State) 자동 전환을 위해 Event 생성.

1. **Defeated_Player Event**
   - Action Type: `Set State`
   - Target: `PlayerLife\Defeated`
   - 효과: 패배 시 Heartbeat가 **서서히 사라짐**.
2. **Spawn_Player Event**
   - Action Type: `Set State`
   - Target: `PlayerLife\Alive`
   - 효과: 플레이어가 부활하면 Heartbeat가 다시 정상적으로 작동.
