# { 🎮 바퀴 애니메이션 및 회전 구현하기 }

## 🎯 목표

정지된 바퀴에 회전 애니메이션 추가

- 비행기 이동 시 바퀴가 함께 회전
- Vehicle Animation Blueprint 사용
- 물리 엔진과 연동된 자연스러운 회전

---

## ⚠️ 발견된 문제점

### 현재 상황

```
게임 실행 → Shift로 이동
  ↓
비행기는 앞으로 이동
  ↓
바퀴는 회전하지 않음 (정지 상태)
  ↓
비현실적이고 이상해 보임
```

### 왜 바퀴가 안 움직이나?

```
✅ 물리 엔진 활성화됨
✅ Vehicle Movement Component 설정 완료
✅ 바퀴 설정도 완료
  ↓
하지만 바퀴 회전 애니메이션이 없음!
  ↓
애니메이션 Blueprint 필요
```

---

## 💡 핵심 개념: Vehicle Animation Instance

### Animation Blueprint란?

```
캐릭터의 걷기/뛰기 애니메이션처럼
바퀴의 회전 애니메이션을 제어하는 시스템

일반 Animation Blueprint:
  - 캐릭터 동작 제어
  - 걷기, 뛰기, 점프 등

Vehicle Animation Instance:
  - 바퀴 회전 제어
  - 물리 엔진과 자동 연동
  - 속도에 따라 자동 회전
```

### Skeletal Mesh의 이해

```
F18 전투기 = Skeletal Mesh (뼈대 메쉬)
  ↓
Skeletal Mesh란?
  - 내부에 "뼈대(Bone)" 구조가 있는 3D 모델
  - 각 부분(바퀴, 날개 등)이 개별적으로 움직일 수 있음
  - Animation Blueprint로 제어 가능

예시:
  캐릭터 팔 = 뼈대로 연결 → 팔을 구부림
  전투기 바퀴 = 뼈대로 연결 → 바퀴를 회전
```

## 🔧 1단계: Vehicle Animation Blueprint 생성

### 생성 경로

```
Content Drawer
  ↓
FighterJet 폴더 → Blueprint 폴더
  ↓
우클릭 → Blueprint Class
  ↓
All Classes 검색창에 입력
```

### 클래스 선택

```
검색: Vehicle Animation Instance
  ↓
선택: Vehicle Animation Instance
  ↓
이름: ABP_F18
  (ABP = Animation BluePrint의 약자)
```

**Vehicle Animation Instance란?**

```
기능: 바퀴가 있는 탈것 전용 애니메이션 클래스
제공:
  ├─ 자동 바퀴 회전 계산
  ├─ 물리 엔진과 연동
  └─ 속도에 따른 회전 속도 조절

차량용 특화 기능:
  - 일반 Animation Blueprint보다 간편
  - 바퀴 회전을 자동으로 처리
  - 복잡한 계산 불필요
```

## 🔧 2단계: Skeleton 설정

### ⚠️ 주의사항

```
ABP_F18 생성 직후 더블클릭 금지!
  ↓
이유: Skeleton(뼈대) 설정 안 됨
  ↓
에러 메시지: "No Skeleton selected"
```

### Skeleton 설정 방법

```
ABP_F18 우클릭 (또는 선택 후 Details 패널)
  ↓
Skeleton 항목 찾기
  ↓
드롭다운 클릭 → F18_Skeleton 선택
  ↓
이제 더블클릭으로 열기 가능
```

**Skeleton이란?**

```
3D 모델의 뼈대 구조 정보
  ├─ 어떤 부분이 움직일 수 있는지 정의
  ├─ 바퀴, 날개, 문 등의 연결 정보
  └─ Animation Blueprint가 제어할 대상

예시:
  캐릭터 Skeleton: 머리, 팔, 다리 뼈대
  F18 Skeleton: 바퀴, 랜딩기어 등 뼈대
```

## 🔧 4단계: Animation Blueprint 노드 구성

### ABP_F18 열기

```
더블클릭으로 Animation Blueprint 에디터 열기

### 필수 노드 구성

```
[Mesh Space Ref Pose]
  ↓
[Wheel Controller]
  ↓
[Component To Local]
  ↓
[Output Pose]
```

### 각 노드 설명

**1. Mesh Space Ref Pose**

```
기능: 전투기 골격 메쉬의 기본 자세 정보 제공

제공 정보:
  ├─ 각 뼈대의 위치
  ├─ 각 뼈대의 회전값
  └─ 메쉬의 기준 상태

왜 필요한가?
  - 바퀴를 회전시키려면 기준 위치가 필요
  - "원래 위치"를 알아야 "회전 후 위치" 계산 가능
```

**2. Wheel Controller**

```
기능: 바퀴가 있는 차량 전용 자동 회전 제어 노드

자동 처리 기능:
  ├─ Vehicle Movement Component에서 속도 정보 가져오기
  ├─ 속도에 따라 바퀴 회전 속도 자동 계산
  ├─ 각 바퀴별로 개별 회전 적용
  └─ 핸드브레이크 시 회전 정지

매우 편리한 이유:
  - 복잡한 수식 계산 불필요
  - 자동으로 물리 엔진과 동기화
  - 노드 하나로 모든 바퀴 제어
```

**3. Component To Local**

```
기능: 좌표 공간 변환

변환 과정:
  Component Space (컴포넌트 공간)
    ↓
  Local Space (로컬 공간)
    ↓
  최종 애니메이션 출력

왜 필요한가?
  - Wheel Controller는 Component Space에서 작동
  - Output은 Local Space가 필요
  - 좌표계 변환이 필수
```

**좌표 공간이란?**

```
Local Space (로컬 공간):
  - 객체 자신을 중심으로 한 좌표
  - 예: "바퀴의 중심에서 얼마나 떨어졌나"

Component Space (컴포넌트 공간):
  - 부모 컴포넌트 기준 좌표
  - 예: "전투기 전체에서 바퀴의 위치"

World Space (월드 공간):
  - 게임 월드 전체 기준 좌표
  - 예: "맵의 어느 위치에 있나"
```

## 💡 추가 설명

### Animation Blueprint의 강력함

```
직접 구현한다면:
  1. 바퀴 속도 계산
  2. 회전 각도 계산
  3. 각 바퀴에 개별 적용
  4. 물리 엔진과 동기화
  5. 핸드브레이크 처리
  → 복잡한 수학과 코딩 필요

Wheel Controller 노드:
  1. 노드 하나 연결
  → 모든 것이 자동 처리 ✅
```

### 좌표 공간 변환의 중요성

```
잘못된 좌표 공간 사용:
  - 바퀴가 이상한 위치에 표시
  - 회전이 엉뚱한 방향으로 발생
  - 애니메이션 깨짐

올바른 변환 (Component To Local):
  - 정확한 위치에 표시
  - 올바른 회전 적용
  - 부드러운 애니메이션
```

### Wheel Radius의 의미

```
Radius (반지름):
  바퀴의 중심에서 끝까지의 거리

영향:
  ├─ 바퀴가 땅에 얼마나 닿는지
  ├─ 차체 높이
  └─ 물리 충돌 계산

잘못 설정 시:
  - 너무 크면: 바퀴가 공중에 뜸
  - 너무 작으면: 차체가 땅에 박힘
```

### 실제 게임 개발 팁

```
복잡한 탈것 제작 시:
  ├─ 각 부품별로 별도 클래스 생성
  ├─ 앞바퀴, 뒷바퀴 분리
  ├─ 좌측, 우측 바퀴 분리 (필요시)
  └─ 세밀한 조정 가능

간단한 탈것:
  - 하나의 Wheel 클래스로 통일
  - 빠른 프로토타입에 적합
```

# { 🎮 앞바퀴/뒷바퀴 별도 클래스로 문제 해결하기 }

## 🎯 목표

앞바퀴와 뒷바퀴의 크기 차이 해결

- 앞바퀴 전용 Wheel 클래스 생성
- 뒷바퀴 전용 Wheel 클래스 생성
- 각각 적절한 반지름 값 설정

## 💡 문제 분석

### 왜 별도 클래스가 필요한가?

```
현재 상황:
  BP_F18_Wheel (하나의 클래스)
  ├─ Radius: 25
  └─ 모든 바퀴에 동일 적용
  ↓
문제:
  - 앞바퀴: 25 → 적합 ✅
  - 뒷바퀴: 25 → 너무 작음 ❌
  ↓
해결책:
  앞바퀴용 클래스 (Radius: 25~28)
  뒷바퀴용 클래스 (Radius: 35~40)
```

## 🔧 1단계: 뒷바퀴 클래스 복제

### 복제 방법

```
Content Drawer → FighterJet → Blueprint
  ↓
BP_F18_Wheel 선택
  ↓
Ctrl + D (복제 단축키)
  ↓
이름 변경
```

### 이름 설정

```
원본 클래스:
  BP_F18_Wheel → BP_F18_Wheel_Front (앞바퀴)

복제된 클래스:
  New_BP_F18_Wheel → BP_F18_Wheel_Rear (뒷바퀴)
```

**Front vs Rear**

```
Front (프론트):
  - 앞쪽을 의미
  - 전면, 정면
  - 앞바퀴

Rear (리어):
  - 뒤쪽을 의미
  - 후면, 후방
  - 뒷바퀴
```

## 🔧 3단계: 어느 바퀴가 앞/뒤인지 확인

### 문제 상황

```
Vehicle Movement Component의 Wheels 배열:
  [0] Wheel
  [1] Wheel
  [2] Wheel
  [3] Wheel
  ↓
어느 것이 앞바퀴? 어느 것이 뒷바퀴?
  ↓
Skeleton을 확인해야 함!
```

### Skeleton 확인 방법

```
BP_F18 → Components 패널
  ↓
Mesh (F18_Skeletal_Mesh) 선택
  ↓
Viewport에서 Skeleton 표시
  ↓
뼈대 구조 확인
```

### 뼈대 이름으로 판별

```
Skeleton 뼈대 이름:
  ├─ Wheel_joint_LF → 앞바퀴 (Left Front)
  ├─ Wheel_joint_?? → 뒷바퀴
  ├─ Wheel_joint_?? → 뒷바퀴
  └─ Wheel_joint_?? → 뒷바퀴

LF = Left Front (왼쪽 앞)
  ↓
나머지는 뒷바퀴임을 확인
```

**뼈대 이름 규칙 (일반적)**

```
LF = Left Front (왼쪽 앞)
RF = Right Front (오른쪽 앞)
LR = Left Rear (왼쪽 뒤)
RR = Right Rear (오른쪽 뒤)

이 강의의 경우:
  - 뼈대 이름이 명확하지 않음
  - 직접 확인하여 판별
```

## 🔧 4단계: Wheel 클래스 할당

### Vehicle Movement Component 설정

```
BP_F18 → Vehicle Movement Component
  ↓
Details 패널 → Wheels 섹션
  ↓
각 바퀴에 적절한 클래스 할당
```

### 설정 내용

```
Wheels 배열:

## 💡 핵심 개념

### VFX (Visual Effects)란?

```
게임에서 보이는 시각적 효과
  ├─ 불꽃, 연기, 폭발
  ├─ 마법 이펙트
  ├─ 날씨 효과 (비, 눈)
  └─ 이 강의: 제트 엔진 화염

목적:
  - 게임을 더 생생하게
  - 상태를 시각적으로 표현
  - 플레이어에게 피드백 제공
```

### Niagara Particle System이란?

```
언리얼 엔진의 파티클(입자) 효과 시스템
  ↓
Particle (파티클):
  - 작은 입자들의 집합
  - 수백~수천 개가 모여 하나의 효과 생성
  - 예: 불꽃 = 수많은 작은 불똥들

Niagara:
  - 언리얼의 최신 파티클 시스템
  - 강력하고 유연한 제어
  - GPU 가속으로 성능 우수
```

## 🔧 13단계: 기본값 추가 (Offset)

### Add 노드 추가

```
Throttle Value와 Set Float Parameter 사이에
  ↓
[Add] + 0.5 노드 추가
```

### 노드 구조

```
[GET] Throttle Value (0~1)
  ↓
[Add] + 0.5
  ↓
결과: 0.5~1.5
  ↓
[Set Float Parameter]
  └─ In Float: 0.5~1.5
```

**왜 0.5를 더하나?**

```
Before:
  스로틀 0 → Gain 0 → 소리 없음 ❌
  스로틀 1 → Gain 1 → 약간 커짐

After:
  스로틀 0 → Gain 0.5 → 최소 볼륨 유지 ✅
  스로틀 1 → Gain 1.5 → 충분히 큼 ✅

효과:
  - 항상 기본 소리 유지
  - 완전히 조용해지지 않음
  - 더 자연스러운 엔진 소리
```

## 💡 추가 설명

### MetaSound vs Sound Cue

```
Sound Cue (기존 시스템):
  ├─ 간단한 사운드 재생
  ├─ 기본적인 믹싱
  └─ 제한적인 제어

MetaSound (최신 시스템):
  ├─ 복잡한 오디오 처리
  ├─ 실시간 파라미터 제어
  ├─ DSP 효과 추가
  └─ 더 강력하고 유연함 ✅
```

### Mono vs Stereo

```
Mono (모노):
  - 단일 채널
  - 공간감 적음
  - 파일 크기 작음
  - 3D 사운드에 적합 ✅

Stereo (스테레오):
  - 좌/우 2채널
  - 공간감 풍부
  - 파일 크기 2배
  - 음악에 적합

엔진 소리:
  - Mono 사용 권장
  - 3D 위치 기반 재생
  - Audio Component가 공간감 제공
```

### Gain vs Volume

```
기술적으로는 다르지만 비슷:

Gain (게인):
  - 신호 증폭
  - Linear 값 (선형)
  - 0.5 = 절반, 2.0 = 2배

Volume (볼륨):
  - 인간이 느끼는 소리 크기
  - dB (데시벨) 단위
  - 로그 스케일

MetaSound:
  - Gain이라 부르지만
  - 실제로는 Volume 제어
```

### Loop의 중요성

```
Loop 없이:
  - 소리 한 번 재생 → 끝
  - 다시 재생 필요
  - 끊김 현상
  - 비현실적

Loop 있음:
  - 자동 반복
  - 끊김 없음
  - 연속적인 소리
  - 실제 엔진과 유사 ✅
```
