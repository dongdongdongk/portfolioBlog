# { 🎵 2단원: 하나의 WAV 파일을 여러 용도로 활용하기 }

## 1. **학습 목표**

이 단원에서는 **하나의 WAV 파일에 들어 있는 여러 소리를 각각 나눠 활용**하는 방법을 배웁니다.

이를 통해:

- 사운드를 세밀하게 조정하고,
- 애니메이션에 맞게 타이밍을 수정하며,
- 메모리 효율도 개선할 수 있습니다.

---

## 2. **실습 예제: Gem_Recharge.wav**

- **파일**: `Gem_Recharge.wav`
- **프로젝트 오브젝트**: `Gem_Recharge Sound SFX`
- **사용 상황 (Cube 게임, Wwizard 캐릭터)**
  1. **지팡이를 오른쪽으로 휙 움직일 때** → “쉭” 사운드 필요
  2. **얼음 보석이 새로 충전되어 지팡이에 장착될 때** → “크리스탈 울림” 사운드 필요

👉 이 두 가지 소리가 **하나의 WAV 파일 안에 순서대로 포함**되어 있음.

---

## 3. **하나의 WAV 파일에 여러 소리가 들어 있을 때 문제점**

1. **애니메이션 타이밍 변화 문제**
   - 게임 개발 중 애니메이션 타이밍이 자주 바뀌면, 사운드도 그에 맞게 세밀 조정이 필요.
   - 하지만 WAV가 한 파일로 묶여 있으면 수정이 불편함.
2. **메모리 낭비**
   - 소리 사이에 **빈 공간(silence)** 이 있으면, 그 부분도 메모리에 불필요하게 로드됨.
3. **사운드 조절의 제약**
   - 한 파일 안에서 개별 소리를 따로 조정하기 어려움 (예: 볼륨, 페이드 처리, 타이밍 등).

---

## 4. **Wwise에서 해결 방법**

이 단원에서 배우는 주요 기술은 다음과 같음:

### (1) **게임과 연결하기**

- Cube ↔ Wwise 연결 (앞 단원과 동일).
- 실시간으로 수정한 소리를 Cube에서 테스트.

### (2) **하나의 WAV 파일로 여러 사운드 생성**

- 한 WAV 파일을 잘라 **여러 개의 SFX 오브젝트**로 활용 가능.

### (3) **사운드 다듬기**

- **시작·종료 지점 조정 (Trim)**
  → 불필요한 부분 제거, 정확한 소리만 사용.
- **페이드 인/아웃 적용**
  → 사운드가 갑자기 시작/끝나지 않도록 자연스럽게 처리.

### (4) **애니메이션과의 동기화**

- 애니메이션 동작(지팡이 휙, 크리스탈 충전)에 맞춰 사운드 타이밍 조정.
- 동일 WAV에서도 각 소리를 **별도로 제어 가능**.

### (5) **하나의 동작에 여러 사운드 연결**

- 예: "보석 충전 동작" → 휙 소리 + 크리스탈 울림 소리 함께 재생.
- 각각의 사운드를 독립적으로 조정 가능 (볼륨, 페이드, 시작 지점).

---

## 5. **이 단원을 마치면 할 수 있는 것**

- Cube와 Wwise 연결.
- 하나의 WAV 파일을 나눠 여러 개의 사운드처럼 사용.
- WAV 파일의 **시작/종료 지점 트리밍**.
- 사운드의 **페이드 인/아웃** 조정.
- 애니메이션에 맞춰 사운드 **타이밍 미세 조정**.
- 하나의 동작에 여러 사운드를 매핑하고 조정.

---

# { 🎵 사운드 오브젝트 복사하기 }

## 1. **왜 오브젝트를 복사할까?**

- 하나의 WAV 파일 안에는 여러 소리가 들어 있을 수 있음.
  (예: `Gem_Recharge.wav` → “쉭” 소리 + “크리스탈 울림” 소리)
- 이걸 각각 따로 활용하려면 **Sound SFX 오브젝트를 복사**해서 별도로 다루는 게 편리함.
- 오브젝트 복사 시 **WAV 파일이 중복 저장되지 않음** → 메모리 효율 유지.

👉 즉, 복사된 오브젝트는 “새로운 오디오 파일”이 아니라, **같은 파일을 다른 방식으로 참조**하는 개념.

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380561/notion-blog/_/WWISE/Wwise_/2_WAV_/image.png)

```jsx
한 파일에 2가지 소리가 들어가 있음
```

---

## 2. **준비 작업**

1. **Cube 실행** → 실제 게임 환경 준비.
2. **Wwise 실행 후 Module 2 프로젝트 열기**.
3. **Cube와 Wwise 연결** → 수정한 내용이 바로 게임에서 테스트 가능.

---

## 3. **복사 과정**

1. **Project Explorer 열기**
   - `Actor-Mixer Hierarchy > Default Work Unit`에서
     `Gem_Recharge Sound SFX` 선택.
2. **오디오 파일 확인**
   - 보조 편집기(Source Editor)에 `Gem_Recharge.wav` 파일이 연결된 걸 확인.
   - Transport Control → Play(▶) 또는 스페이스바 → 소리 미리듣기.
     - 순서: “쉭” → “크리스탈 울림”.
3. **오브젝트 복사하기**
   - `Gem_Recharge Sound SFX` → 우클릭 → **Copy**.
   - `Default Work Unit` → 우클릭 → **Paste**.
   - 새로운 오브젝트 생성됨 → 이름 끝에 자동으로 `_01` 붙음.
4. **이름 변경하기**
   - `Gem_Recharge` → `Gem_Recharge_Magic` (크리스탈 울림 사운드용).
   - `Gem_Recharge_01` → `Gem_Recharge_Woosh` (쉭 사운드용).

   [Tip] 이름 바꾸는 방법
   - 오브젝트 클릭 후 잠시 있다가 다시 클릭
   - F2 키
   - 우클릭 → Rename
   - Property Editor → Name 입력란 수정

---

## 4. **개념 정리**

- **오브젝트 복사 = 새로운 오디오 파일을 만드는 것 아님**
  - 원본 WAV(`Gem_Recharge.wav`)는 그대로 유지.
  - 복사된 오브젝트는 같은 WAV를 **다른 방식으로 활용할 수 있는 레퍼런스**임.
- **메모리 효율성**
  - 파일이 두 배로 저장되지 않으므로, 메모리 점유량도 늘어나지 않음.
- **활용성 증가**
  - `Gem_Recharge_Woosh` → “쉭” 소리 전용.
  - `Gem_Recharge_Magic` → “크리스탈 울림” 전용.
  - 이후 각각 시작 지점, 종료 지점, 페이드 등을 따로 조절 가능.

---

## 5. **핵심 요약**

- 오브젝트 복사는 **사운드 파일을 복제하는 게 아니라, 같은 파일을 다른 이름/목적으로 참조하는 것**.
- 이렇게 하면 하나의 WAV 파일에서 **여러 사운드 파트를 독립적으로 관리** 가능.
- Cube와 연결해 실제 게임 상황에서 테스트하면서 **사운드 타이밍과 효과를 개별적으로 조정**할 수 있음.

---

# { 🎵 Source Editor 사용하기 }

## 1. **왜 Source Editor를 사용할까?**

- 하나의 WAV 파일에 여러 소리가 들어 있으면 그대로는 불편:
  - 필요 없는 **빈 구간**도 함께 재생됨.
  - 타이밍에 맞게 소리를 나눠 쓰기 어려움.
- **Source Editor**는 오디오 파일의 **시작/끝 구간을 잘라내고, 페이드 처리**를 적용할 수 있음.
- 이 방식은 원본 WAV 파일을 직접 수정하는 게 아니라, **특정 오브젝트에서의 재생 방식만 바꾸는 것**.

👉 즉, **같은 파일을 다른 구간으로 나눠서 각각의 사운드 오브젝트처럼 활용**할 수 있게 해줌.

---

## 2. **실습 상황**

- 이미 두 개의 오브젝트를 만들어 둠:
  - `Gem_Recharge_Woosh` → “쉭” 소리 전용
  - `Gem_Recharge_Magic` → “마법 충전(크리스탈 울림)” 전용

---

## 3. **Woosh 오브젝트 다듬기**

1. **`Gem_Recharge_Woosh` 선택**
   - Project Explorer → `Gem_Recharge_Woosh`
   - 오른쪽 편집기 → **Sound SFX 탭** 열림
   - 파형(오디오 신호) 확인 가능.
2. **끝 지점(Trim End) 조정**
   - 파형에서 “쉭” 소리가 끝나는 지점까지 드래그.
   - 이제 이 오브젝트는 “쉭” 소리까지만 재생됨.
3. **재생 테스트**
   - 스페이스바 → “쉭” 소리만 들림.
4. **클릭/팝 노이즈 처리**
   - 끝부분에 잡음이 있으면 **Fade-out Duration** 삼각형을 왼쪽으로 드래그.
   - → 소리가 부드럽게 사라지도록 조정.

   ![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380559/notion-blog/_/WWISE/Wwise_/2_WAV_/image_1.png)

   ```jsx
   SoundSFX 창
   ```

---

## 4. **Magic 오브젝트 다듬기**

1. **`Gem_Recharge_Magic` 선택**
   - Source Editor가 전체 WAV 파일을 다시 표시.
2. **시작 지점(Trim Start) 조정**
   - 파형에서 “마법 충전” 소리가 시작되는 지점까지 드래그.
3. **재생 테스트**
   - 스페이스바 → “마법 충전” 소리만 들림.
4. **클릭/팝 노이즈 처리**
   - 시작 부분에 잡음이 있으면 **Fade-in Duration** 삼각형을 오른쪽으로 드래그.
   - → 소리가 부드럽게 시작되도록 조정.

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380559/notion-blog/_/WWISE/Wwise_/2_WAV_/image_2.png)

```jsx
FadeOut 만들기
```

---

## 5. **개념 정리**

- **Source Editor의 Trim 기능**
  - 시작/끝을 잘라내서 특정 부분만 사용.
  - 원본 WAV 파일은 그대로 유지됨.
  - 다른 오브젝트에는 영향 없음.
- **Fade-in / Fade-out**
  - 사운드의 시작과 끝을 부드럽게 처리.
  - 클릭음, 팝 노이즈 제거.
- **결과**
  - 하나의 WAV 파일(`Gem_Recharge.wav`)이
    → `Gem_Recharge_Woosh` (쉭 사운드)
    → `Gem_Recharge_Magic` (마법 사운드)
    로 성공적으로 분리됨.

---

## 6. **핵심 요약**

- Source Editor는 **WAV 파일을 직접 편집하는 도구가 아니라, 오브젝트별로 재생할 구간을 조정하는 도구**.
- Trim Start/End → 필요한 구간만 사용.
- Fade-in/Out → 소리의 시작/끝을 매끄럽게.
- 덕분에 하나의 WAV 파일을 여러 오브젝트에서 **각각 다른 소리처럼 활용** 가능.

# { 🎵 오브젝트 속성 변경하기 (Pitch 조정) }

## 1. **왜 Pitch를 조정할까?**

- 애니메이션 상황:
  Wwizard의 지팡이가 **빠르게 옆으로 휘두르는 동작**.
- 원래 사운드(`Gem_Recharge_Woosh`)는 속도가 느려서 동작과 잘 맞지 않음.
- \*Pitch(피치)\*\*를 올리면 → 소리가 더 빠르고 높게 들려서 애니메이션에 자연스럽게 맞음.

👉 Pitch 조정은 **재생 속도와 음높이를 동시에 변화**시켜, 같은 파일을 다른 분위기의 소리로 활용할 수 있게 함.

---

## 2. **독립적인 오브젝트의 장점**

- 이미 `Gem_Recharge_Woosh`와 `Gem_Recharge_Magic`을 따로 만들어 두었음.
- 따라서 `Gem_Recharge_Woosh`의 속성을 바꿔도 `Gem_Recharge_Magic`에는 **영향 없음**.
- 오브젝트 복사의 이점이 여기서 드러남.

---

## 3. **실습 과정**

1. **오브젝트 선택**
   - Project Explorer → `Gem_Recharge_Woosh` 선택.
2. **Property Editor 열기**
   - 오른쪽 → **General 카테고리** 확인.
   - 여기에는 오브젝트 재생 방식(Pitch, Volume, Loop 등)을 조정할 수 있는 속성이 있음.
3. **Pitch 값 변경**
   - Pitch 속성 → 클릭 & 길게 눌러 슬라이더 열기.
   - 슬라이더 오른쪽으로 이동 → **약 1200**으로 설정.
   - (1200 cents = 한 옥타브 ↑ = 두 배 빠르고 높은 소리)
4. **테스트 재생**
   - 스페이스바 → 오디오 확인.
   - 한 옥타브 높은 “쉭” 소리 확인 가능.
5. **적절한 값으로 조정**
   - 1200은 지나치게 높음.
   - Pitch 값 → 직접 입력 **600** → Enter.
   - 스페이스바로 재생 → 애니메이션과 잘 맞는 자연스러운 소리 완성.

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380559/notion-blog/_/WWISE/Wwise_/2_WAV_/image_3.png)

```jsx
피치 조절 부분
```

---

## 4. **개념 정리**

- **Pitch 속성**
  - 단위: **cents** (센트, 음정을 미세 단위로 조정).
  - 범위: **2400 ~ +2400** (총 4옥타브).
  - +1200 = 한 옥타브 ↑ (소리 두 배 빠르고 높음).
  - 1200 = 한 옥타브 ↓ (소리 두 배 느리고 낮음).
- **Pitch 조정의 효과**
  - 음높이와 재생 속도가 동시에 변함.
  - 같은 WAV 파일도 **다른 상황에 맞게 다양하게 활용** 가능.

---

## 5. **핵심 요약**

- Pitch를 조정하면 소리의 **속도와 높낮이**를 바꿀 수 있다.
- 오브젝트별로 독립적인 속성 변경이 가능하다.
- 적절한 Pitch 값을 찾아 애니메이션과 사운드를 **시각·청각적으로 일치**시킬 수 있다.

👉 쉽게 말해, 이번 단계는 **“소리의 톤과 속도를 바꿔서 애니메이션 동작에 딱 맞게 튜닝하는 과정”**이에요.

# { 🎵 하나의 Event에 여러 동작 적용하기 }

## 1. 왜 Event를 쓰는가?

- **게임과 사운드 연결 고리**
  - 게임 엔진에서는 애니메이션이나 액션이 발생할 때 **“이 시점에 이 소리를 재생해!”**라는 요청(Game Call)을 보냄.
  - 이 요청이 **Event**를 트리거함.
- **Event의 역할**
  - 단순히 “사운드를 재생한다”가 아니라,
    - 어떤 사운드를 재생할지,
    - 어떤 속성(Pitch, Volume, Delay 등)을 적용할지,
    - 여러 개의 사운드를 동시에/순차적으로 재생할지,
      등을 **하나의 묶음**으로 정의함.

👉 즉, Event는 **게임과 오디오 사이의 통역사** 역할을 하며, **하나의 Game Call로 여러 사운드 연출을 제어할 수 있게 해줌.**

---

## 2. 왜 하나의 Event에 여러 동작을 넣는가?

- **애니메이션은 변하지 않음**
  - 예) 얼음 보석 발사 애니메이션 → 폭발 → “쉭” → 충전
  - 순서는 항상 동일. 따라서, 각각을 따로 Game Call로 받을 필요가 없음.
- **효율성**
  - 프로그래머가 매번 Game Call을 따로 만들지 않아도 됨.
  - 사운드 디자이너(Wwise) 입장에서 한 Event만 수정하면 타이밍 전체를 관리 가능.
- **유연성**
  - 사운드 타이밍이나 속성 변경이 필요하면, 코드 수정 없이 Wwise에서 Delay 값만 바꿔도 됨.

👉 하나의 Event에 여러 동작을 넣으면, **게임과 코드의 의존도를 줄이고, 사운드 디자이너가 직접 타이밍과 연출을 제어**할 수 있음.

---

## 3. 왜 Delay를 사용하는가?

- **현실적인 타이밍 반영**
  - 폭발과 동시에 충전음이 나면 어색함.
  - 실제로는 **폭발 → 0.5초 후 지팡이 휘두르는 소리 → 0.7초 후 충전음** 순서로 와야 자연스러움.
- **애니메이션과 동기화**
  - Delay는 “게임 Call이 들어온 순간”을 기준으로 **얼마 뒤에 실행할지**를 결정.
- **게임 엔진에 부담 줄이기**
  - 코드에서 복잡하게 타이밍을 계산할 필요 없음.
  - 오디오 미들웨어(Wwise)에서 바로 제어 가능.

👉 Delay는 **게임 애니메이션과 오디오의 싱크를 맞추는 핵심 도구**임.

## 5. 이번 단원의 핵심 개념

- **Event** = 게임 호출을 오디오 연출로 변환하는 “명령 묶음”.
- **Action** = Event 안에서 실제 실행되는 구체적 동작 (Play, Stop, Delay 등).
- **Delay** = 사운드를 애니메이션 타이밍에 맞춰 싱크시키는 필수 도구.
- **이점**
  1. 프로그래머 의존 줄임 (코드 수정 없이 오디오 팀이 제어 가능).
  2. 같은 애니메이션 안에서 여러 소리를 **효율적으로 관리**.
  3. 사운드 반복 테스트와 수정이 빠르고 유연해짐.

---

✅ 결론:

이번 단원은 단순히 “여러 소리를 재생한다”가 아니라, **“게임 속 하나의 장면을 하나의 Event로 묶어, 사운드 타이밍을 컨트롤하며 애니메이션과 완벽하게 싱크를 맞추는 방법”**을 배우는 것이 핵심입니다.
