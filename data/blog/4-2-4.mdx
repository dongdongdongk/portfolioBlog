## 2. Search 컴포넌트

### 전체 코드 + 주석

```tsx
// components/search.tsx

import { useState } from "react";
import { View, TouchableOpacity, Image, TextInput } from "react-native";
import { useLocalSearchParams, router, usePathname } from "expo-router";
import { useDebouncedCallback } from "use-debounce";
import icons from "@/constants/icons";

const Search = () => {

  // usePathname: 현재 화면 경로 가져오기
  // 예: 홈이면 "/" 탐색이면 "/explore"
  const path = usePathname();

  // useLocalSearchParams: URL 쿼리 파라미터 읽기
  // 예: URL이 /?query=house 이면 params.query = "house"
  const params = useLocalSearchParams<{ query?: string }>();

  // 검색어 상태 — 초기값으로 URL의 query 파라미터 사용
  // 검색 결과 화면에서 돌아와도 검색어가 유지됨
  const [search, setSearch] = useState(params.query);

  // 디바운싱된 검색 함수 (500ms 딜레이)
  // 사용자가 입력을 멈춘 뒤 500ms 후에만 URL 파라미터 업데이트
  const debouncedSearch = useDebouncedCallback((text: string) => {
    // router.setParams: URL 쿼리 파라미터 업데이트
    // 예: /?query=house 로 URL 변경
    router.setParams({ query: text });
  }, 500);

  const handleSearch = (text: string) => {
    setSearch(text);          // 1. 입력창 즉시 업데이트 (타이핑 느낌)
    debouncedSearch(text);    // 2. 500ms 후에 URL 파라미터 업데이트
  };

  return (
    <View className="flex flex-row items-center justify-between w-full px-4 rounded-lg bg-accent-100 border border-primary-100 mt-5 py-2">

      {/* 검색 아이콘 + 입력창 */}
      <View className="flex-1 flex flex-row items-center justify-start z-50">
        <Image source={icons.search} className="size-5" />
        <TextInput
          value={search}
          onChangeText={handleSearch}   {/* 텍스트 변경 시 handleSearch 호출 */}
          placeholder="Search for anything"
          className="text-sm font-rubik text-black-300 ml-2 flex-1"
        />
      </View>

      {/* 필터 버튼 — 나중에 필터 화면으로 이동 예정 */}
      <TouchableOpacity>
        <Image source={icons.filter} className="size-5" />
      </TouchableOpacity>

    </View>
  );
};

export default Search;
```

## 3. 디바운싱(Debouncing) 완전 이해

### 왜 필요한가?

```
디바운싱 없을 때 — "house" 타이핑 시:

h       → API 호출 1번
ho      → API 호출 2번
hou     → API 호출 3번
hous    → API 호출 4번
house   → API 호출 5번

총 5번 API 호출 → 불필요한 서버 요청, 느린 UX
```

```
디바운싱 있을 때 (500ms):

h       → 타이머 시작
ho      → 타이머 리셋
hou     → 타이머 리셋
hous    → 타이머 리셋
house   → 타이머 리셋
(500ms 경과)
house   → API 호출 1번

총 1번만 API 호출 → 효율적!
```

### 설치

```bash
npm install use-debounce
```

### 사용법

```tsx
import { useDebouncedCallback } from 'use-debounce'

// 첫 번째 인자: 실행할 함수
// 두 번째 인자: 지연 시간 (ms)
const debouncedSearch = useDebouncedCallback((text: string) => {
  // 이 코드는 입력이 멈춘 뒤 500ms 후에 실행
  router.setParams({ query: text })
}, 500)
```

## 4. URL 파라미터로 검색어 관리하기

### 왜 URL 파라미터를 쓰나?

```
일반 useState만 사용할 때:
  다른 화면으로 이동 → 검색어 날아감
  뒤로가기 → 검색어 없음

URL 파라미터 사용할 때:
  /?query=house
  다른 화면으로 이동해도 URL에 검색어 유지
  뒤로가기 → 검색어 그대로
  공유 시 검색 결과 URL 공유 가능
```

### 관련 훅 정리

```tsx
// 현재 경로 읽기
const path = usePathname()
// 홈: "/"  탐색: "/explore"

// URL 파라미터 읽기
const params = useLocalSearchParams<{ query?: string }>()
// /?query=house → params.query = "house"
// / → params.query = undefined

// URL 파라미터 업데이트 (페이지 이동 없이)
router.setParams({ query: 'house' })
// 현재 URL: / → /?query=house 로 변경
```

## 5. TextInput — React Native의 입력창

웹의 `<input>`과 비슷하지만 이름과 props가 다릅니다.

```tsx
// 웹 HTML
<input
  type="text"
  value={search}
  onChange={(e) => setSearch(e.target.value)}  // e.target.value로 값 추출
  placeholder="검색어 입력"
/>

// React Native
<TextInput
  value={search}
  onChangeText={(text) => setSearch(text)}  // text가 바로 문자열로 들어옴
  placeholder="검색어 입력"
/>
```

> 💡 **핵심 차이**: 웹은 `onChange`에서 `e.target.value`로 값을 꺼내야 하지만,
> React Native의 `onChangeText`는 **문자열을 바로** 인자로 받습니다.

## 6. 컴포넌트를 분리하는 이유

Search 컴포넌트를 `index.tsx` 안에 직접 쓰지 않고 별도 파일로 만드는 이유:

```
컴포넌트 분리 전:
  홈 화면에 검색 코드 전체 작성
  탐색 화면에도 같은 검색 코드 전체 복사

컴포넌트 분리 후:
  components/search.tsx 에 한 번만 작성
  홈 화면: <Search />
  탐색 화면: <Search />

→ 코드 중복 없음, 수정할 때 한 곳만 수정하면 됨
```

## 🔑 핵심 요약

1. **`TextInput`** = React Native의 입력창, `onChangeText`로 값 바로 수신
2. **디바운싱** = 입력이 멈춘 뒤 N ms 후에 실행 → API 호출 횟수 최소화
3. **`router.setParams`** = 페이지 이동 없이 URL 쿼리 파라미터만 변경
4. **`useLocalSearchParams`** = URL 파라미터 읽기 (검색어 유지에 활용)
5. **Search 컴포넌트 분리** = 홈/탐색 화면에서 재사용하기 위해 별도 파일로 분리
6. **`handleSearch`의 두 역할** = 입력창 즉시 반영 (`setSearch`) + 딜레이 후 URL 업데이트 (`debouncedSearch`)

## 1. Props 타입 정의

```tsx
import { Models } from 'react-native-appwrite'

interface Props {
  item: Models.Document // Appwrite 문서 타입
  onPress?: () => void // 클릭 핸들러 (선택적)
}
```

### `Models.Document`란?

Appwrite에서 데이터를 가져오면 각 항목은 `Models.Document` 타입입니다.
`$id`, `$createdAt` 같은 기본 필드 + 우리가 만든 커스텀 필드를 포함합니다.

```tsx
// Appwrite가 자동으로 만들어주는 기본 필드
item.$id // 고유 ID
item.$createdAt // 생성 시각

// 우리가 Appwrite에 만든 커스텀 필드
item.name // 매물 이름
item.address // 주소
item.price // 가격
item.rating // 평점
item.image // 이미지 URL (string)
```

## 4. 핵심 개념 정리

### 로컬 이미지 vs 인터넷 이미지

```tsx
// 로컬 파일 (assets 폴더에 있는 이미지)
<Image source={require("../assets/images/japan.png")} />
<Image source={images.japan} />  // constants에서 import한 경우

// 인터넷 URL (Appwrite 등 서버에서 가져온 이미지)
<Image source={{ uri: "https://cloud.appwrite.io/..." }} />
<Image source={{ uri: item.image }} />  // item.image가 URL 문자열인 경우
```

### `absolute` 레이어 쌓기

```
FeaturedCard의 레이어 구조:

┌─────────────────────────────┐
│  레이어 4: 텍스트 (absolute) │ ← 제일 위
│  레이어 3: 뱃지 (absolute)  │
│  레이어 2: 그라디언트 (abs)  │
│  레이어 1: 배경 이미지       │ ← 제일 아래
└─────────────────────────────┘

부모에 relative, 자식에 absolute를 쓰면
자식이 부모를 기준으로 위치를 잡습니다.
```

```tsx
// 부모: relative (기준점 역할)
<TouchableOpacity className="relative">

  // 자식: absolute (부모 기준으로 위치 지정)
  <View className="absolute top-5 right-5">  {/* 부모 오른쪽 상단 */}
  <View className="absolute bottom-5 inset-x-5"> {/* 부모 하단 + 좌우 여백 */}

</TouchableOpacity>
```

### `numberOfLines` — 텍스트 자르기

```tsx
// numberOfLines={1}: 한 줄 초과 시 "..." 처리
<Text numberOfLines={1}>매우 긴 매물 이름이 들어와도 한 줄로 잘림...</Text>

// 없으면: 텍스트가 줄바꿈되어 카드 레이아웃이 깨질 수 있음
```

### `tintColor` — 아이콘 색상 변경

```tsx
// PNG 아이콘의 색상을 코드로 바꿀 수 있음
// 검은색 하트 아이콘을 다크 네이비로 변경
<Image source={icons.heart} tintColor="#191D31" />
```

### `bg-white/90` — Tailwind 투명도 표기법

```
bg-white/90   = 흰색 배경, 90% 불투명 (10% 투명)
bg-white/70   = 흰색 배경, 70% 불투명 (30% 투명)
bg-black/50   = 검정 배경, 50% 불투명 (반투명)
```

### Named Export vs Default Export

```tsx
// Named Export — 파일 하나에서 여러 개 내보낼 때
export const FeaturedCard = () => { ... }
export const Card = () => { ... }

// 사용할 때: { } 로 가져와야 함
import { FeaturedCard, Card } from "@/components/cards";

// Default Export — 파일 하나에서 하나만 내보낼 때
export default function Search() { ... }
```

# { 🔖 Filters 컴포넌트 가이드 }

> 가로 스크롤 카테고리 필터 — 선택/해제 + URL 파라미터 연동

---

## 📋 이번 강의에서 만드는 것

```
components/
└── filters.tsx   ← 가로 스크롤 카테고리 필터 칩

All  Houses  Condos  Duplexes  Studios  Villas  Apartments ...
 ↑선택됨  ← 가로로 스크롤 가능
```

Search 컴포넌트처럼 **URL 파라미터**로 상태를 관리해서
홈 화면과 탐색 화면 양쪽에서 재사용할 수 있습니다.

## 1. 전체 코드 + 주석

```tsx
// components/filters.tsx

import { useState } from 'react'
import { router, useLocalSearchParams } from 'expo-router'
import { Text, ScrollView, TouchableOpacity } from 'react-native'
import { categories } from '@/constants/data'

const Filters = () => {
  // URL에서 현재 선택된 필터 읽기
  // 예: /?filter=Houses → params.filter = "Houses"
  const params = useLocalSearchParams<{ filter?: string }>()

  // 선택된 카테고리 상태 관리
  // 초기값: URL 파라미터에 값이 있으면 그걸 쓰고, 없으면 "All"
  const [selectedCategory, setSelectedCategory] = useState(params.filter || 'All')

  const handleCategoryPress = (category: string) => {
    // 이미 선택된 카테고리를 다시 클릭하면 → 선택 해제 (초기화)
    if (selectedCategory === category) {
      setSelectedCategory('')
      router.setParams({ filter: '' })
      return // 함수 종료 (아래 코드 실행 안 함)
    }

    // 새 카테고리 클릭 → 해당 카테고리 선택
    setSelectedCategory(category)
    router.setParams({ filter: category })
  }

  return (
    // horizontal: 가로로 스크롤 가능한 ScrollView
    // showsHorizontalScrollIndicator={false}: 스크롤바 숨김
    <ScrollView horizontal showsHorizontalScrollIndicator={false} className="mt-3 mb-2">
      {/* categories 배열을 순회하며 필터 칩 렌더링 */}
      {categories.map((item, index) => (
        // 각 카테고리 칩 — 클릭 가능
        // key={index}: 리스트 렌더링 시 React가 각 항목을 구분하는 고유값
        <TouchableOpacity
          onPress={() => handleCategoryPress(item.category)}
          key={index}
          className={`mr-4 flex flex-col items-start rounded-full px-4 py-2 ${
            selectedCategory === item.category
              ? 'bg-primary-300' // 선택됨: 파란색
              : 'bg-primary-100 border-primary-200 border' // 미선택: 연한 파란색
          }`}
        >
          <Text
            className={`text-sm ${
              selectedCategory === item.category
                ? 'font-rubik-bold mt-0.5 text-white' // 선택됨: 흰 굵은 글씨
                : 'text-black-300 font-rubik' // 미선택: 검정 일반 글씨
            }`}
          >
            {item.title}
          </Text>
        </TouchableOpacity>
      ))}
    </ScrollView>
  )
}

export default Filters
```

## 3. 동적 className — 조건에 따라 스타일 바꾸기

선택 여부에 따라 칩의 색상을 다르게 적용합니다.

```tsx
// 기본 방식 — 항상 같은 스타일
<TouchableOpacity className="bg-primary-300 rounded-full">

// 동적 방식 — 조건에 따라 다른 스타일

  }`}
>
```

> 💡 백틱(`) +` ${}` = 템플릿 리터럴. 문자열 안에 변수나 조건식을 넣을 수 있습니다.
>
> ```tsx
> const name = '동훈'
> ;`안녕하세요 ${name}님` // → "안녕하세요 동훈님"
> ```

## 4. `.map()` 으로 리스트 렌더링

```tsx
// categories 배열 (constants/data.ts에 정의)
const categories = [
  { title: 'All', category: 'All' },
  { title: 'Houses', category: 'Houses' },
  { title: 'Condos', category: 'Condos' },
  // ...
]

// .map(): 배열의 각 항목을 JSX로 변환
{
  categories.map((item, index) => (
    <TouchableOpacity key={index}>
      <Text>{item.title}</Text>
    </TouchableOpacity>
  ))
}
```

### `key` prop이 왜 필요한가?

```
key 없을 때:
  React가 리스트 항목들을 구분 못함
  → 항목 추가/삭제/정렬 시 버그 발생 가능
  → 콘솔에 경고 출력

key 있을 때:
  React가 각 항목을 고유하게 식별
  → 변경된 항목만 효율적으로 다시 렌더링
```

```tsx
// key는 리스트 안에서 고유해야 함
{categories.map((item, index) => (
  <TouchableOpacity key={index}>  // index를 key로 사용 (간단한 경우)
  // 또는
  <TouchableOpacity key={item.category}>  // 고유한 값을 key로 사용 (더 좋음)
))}
```

## 5. 토글 로직 — 선택/해제

```tsx
const handleCategoryPress = (category: string) => {
  // 같은 카테고리를 다시 클릭하면 → 해제
  if (selectedCategory === category) {
    setSelectedCategory('') // 선택 상태 초기화
    router.setParams({ filter: '' }) // URL도 초기화
    return // 여기서 함수 종료!
  }

  // 다른 카테고리 클릭 → 새로 선택
  setSelectedCategory(category)
  router.setParams({ filter: category })
}
```

**`return`으로 조기 종료하는 이유:**

```tsx
// return 없으면 (잘못된 코드):
if (selectedCategory === category) {
  setSelectedCategory('') // 해제 처리
  router.setParams({ filter: '' })
  // return 없으면 아래 코드도 실행됨!
}
setSelectedCategory(category) // 다시 선택되어 버림 (버그!)

// return 있으면 (올바른 코드):
if (selectedCategory === category) {
  setSelectedCategory('')
  router.setParams({ filter: '' })
  return // 함수 종료 → 아래 코드 실행 안 함
}
setSelectedCategory(category) // 다른 카테고리 클릭 시만 실행
```

## 6. 왜 디바운싱이 필요 없나?

Search 컴포넌트에서는 키스트로크마다 이벤트가 발생하므로 디바운싱이 필요했습니다.
Filters는 **탭(클릭) 한 번**에 하나의 이벤트만 발생하므로 불필요합니다.

```
Search: h → ho → hou → hous → house  (여러 번 이벤트)
         → 디바운싱 필요

Filters: [Houses] 클릭 → 1번 이벤트
          → 디바운싱 불필요
```

## 1. ScrollView 대신 FlatList를 쓰는 이유

```
ScrollView:
  - 모든 항목을 한 번에 메모리에 올림
  - 항목이 100개면 100개 전부 렌더링 → 느림
  - 단순한 화면에 적합

FlatList:
  - 화면에 보이는 항목만 렌더링 (가상화)
  - 스크롤하면 보이는 것만 순서대로 로드 → 빠름
  - 동적 데이터, 긴 리스트에 적합 ← 매물 목록에 딱!
```

### 중요 제약 — 두 방향 중첩 불가

```
❌ 안 됨:
ScrollView (세로)
  └── FlatList (가로)  ← 두 개의 가상화 리스트를 서로 다른 방향으로 중첩 불가

✅ 됨:
FlatList (세로)
  └── ListHeaderComponent 안에
      └── FlatList (가로)  ← 헤더 안에 넣으면 가능!
```

> 💡 이게 바로 전체 화면을 FlatList로 감싸고
> 기존 UI를 `ListHeaderComponent`로 옮긴 이유입니다.

## 4. 실제 데이터 연결 — useAppwrite 활용

```tsx
const Home = () => {
  const { user } = useGlobalContext() // 로그인된 유저 정보
  const params = useLocalSearchParams<{ query?: string; filter?: string }>()

  // Featured 섹션 — 최신 매물 5개 (자동 실행)
  const { data: latestProperties, loading: latestPropertiesLoading } = useAppwrite({
    fn: getLatestProperties, // skip 없음 → 컴포넌트 마운트 시 자동 실행
  })

  // 추천 섹션 — 검색/필터 조건 매물 (수동 실행)
  const {
    data: properties,
    refetch,
    loading,
  } = useAppwrite({
    fn: getProperties,
    params: {
      filter: params.filter!,
      query: params.query!,
      limit: 6,
    },
    skip: true, // 처음엔 실행 안 함 → useEffect에서 조건이 바뀔 때만 실행
  })

  // URL 파라미터(검색어/필터)가 바뀔 때마다 데이터 다시 가져오기
  useEffect(() => {
    refetch({
      filter: params.filter!,
      query: params.query!,
      limit: 6,
    })
  }, [params.filter, params.query]) // 이 값이 바뀔 때마다 실행

  // 카드 클릭 시 매물 상세 페이지로 이동
  const handleCardPress = (id: string) => router.push(`/properties/${id}`)
}
```

### `skip: true`가 필요한 이유

```
skip 없을 때:
  컴포넌트 마운트 → 빈 파라미터로 API 호출 → 불필요한 요청

skip: true 사용 시:
  컴포넌트 마운트 → API 호출 안 함
  URL 파라미터 변경 → useEffect → refetch() → API 호출 ✅

결론: 검색/필터처럼 조건이 정해진 뒤에 호출해야 하면 skip: true
```

```tsx

) : (
```

## 6. 실제 유저 데이터 표시

```tsx
// 이전: 하드코딩

<Image source={{ uri: user?.avatar }} />  // Appwrite 아바타 URL
<Text>{user?.name}</Text>                 // 구글 계정 이름

// ?. (옵셔널 체이닝): user가 null일 수도 있으므로
// user?.avatar → user가 있으면 avatar를, 없으면 undefined 반환 (에러 없음)
// user.avatar  → user가 null이면 에러 발생!
```

## 1. 데이터베이스 설계 — 왜 여러 컬렉션인가?

부동산 하나에는 다음 정보가 필요합니다.

```
매물 (Property)
├── 기본 정보: 이름, 유형, 설명, 주소, 가격
├── 에이전트 정보 (담당자)  ← agents 컬렉션
├── 갤러리 이미지들         ← galleries 컬렉션
└── 리뷰들                 ← reviews 컬렉션
```

> 💡 하나의 컬렉션에 모든 것을 넣으면 데이터가 중복되고 관리가 어렵습니다.
> 역할별로 컬렉션을 나눠서 **관계(Relationship)** 로 연결하는 것이 올바른 설계입니다.

## 3. Enum이란?

```
Enum (열거형) = 미리 정해진 선택지만 입력 가능한 필드

예시: type 필드
  ✅ "House"      → 유효
  ✅ "Condo"      → 유효
  ❌ "Castle"     → 허용 안 됨 (선택지에 없음)

장점:
  - 잘못된 데이터 입력 방지
  - 필터링이 쉬움 (type === "House" 검색 가능)
```

## 4. 컬렉션 관계(Relationship)

```
단방향 (One-way):        양방향 (Two-way):
A → B                   A ↔ B
A에서 B를 참조           A에서 B도, B에서 A도 참조 가능
```

**properties 컬렉션의 관계 3개:**

```
property ─ (다대일) → agent    한 에이전트가 여러 매물 담당 가능
property ─ (일대다) → gallery  한 매물에 여러 이미지
property ─ (일대다) → reviews  한 매물에 여러 리뷰
```

> 💡 관계 설정 시 **Cascade(계단식) 삭제** 선택 → 매물 삭제 시 연결된 리뷰/갤러리도 자동 삭제

### getProperties — 필터/검색 조건으로 매물 조회

```tsx
export async function getProperties({ filter, query, limit }) {
  try {
    // 쿼리를 배열로 쌓아서 조건을 동적으로 구성
    const buildQuery = [Query.orderDesc('$createdAt')] // 기본: 최신순

    // 필터가 있고 "All"이 아니면 → 유형 필터 추가
    if (filter && filter !== 'All') buildQuery.push(Query.equal('type', filter))

    // 검색어가 있으면 → 이름/주소/유형에서 검색
    if (query)
      buildQuery.push(
        Query.or([
          Query.search('name', query), // 이름에서 검색
          Query.search('address', query), // 주소에서 검색
          Query.search('type', query), // 유형에서 검색
        ])
      )

    // 개수 제한이 있으면 추가
    if (limit) buildQuery.push(Query.limit(limit))

    const result = await databases.listDocuments(
      config.databaseId!,
      config.propertiesCollectionId!,
      buildQuery
    )
    return result.documents
  } catch (error) {
    console.error(error)
    return []
  }
}
```

### getPropertyById — 특정 매물 하나 조회

```tsx
export async function getPropertyById({ id }: { id: string }) {
  try {
    const result = await databases.getDocument(
      config.databaseId!,
      config.propertiesCollectionId!,
      id // 조회할 문서의 $id
    )
    return result
  } catch (error) {
    console.error(error)
    return null
  }
}
```

## 8. Query 메서드 정리

```tsx
Query.orderAsc('필드명') // 오름차순 정렬
Query.orderDesc('필드명') // 내림차순 정렬
Query.limit(숫자) // 최대 개수 제한
Query.equal('필드명', '값') // 정확히 일치
Query.search('필드명', '검색어') // 텍스트 검색 (부분 일치)
Query.or([쿼리1, 쿼리2]) // 여러 조건 중 하나라도 해당
```

### 동적 쿼리 빌드 패턴

```tsx
// 조건이 있을 때만 쿼리를 추가하는 패턴
const buildQuery = [Query.orderDesc('$createdAt')] // 기본 조건

if (filter) buildQuery.push(Query.equal('type', filter)) // 조건부 추가
if (query) buildQuery.push(Query.search('name', query)) // 조건부 추가
if (limit) buildQuery.push(Query.limit(limit)) // 조건부 추가

// buildQuery 배열이 완성되면 한 번에 전달
databases.listDocuments(dbId, collectionId, buildQuery)
```

> 💡 조건이 없으면 쿼리에 추가 안 해도 됩니다.
> 배열에 넣고 싶은 조건만 골라서 쌓는 유연한 패턴입니다.

## 3. 전체 코드 + 주석

```tsx
// lib/seed.ts

import { ID } from 'react-native-appwrite'
import { databases, config } from './appwrite'
import { agentImages, galleryImages, propertiesImages, reviewImages } from './data'

// 컬렉션 ID를 한 곳에 모아두기 (코드 가독성을 위해)
const COLLECTIONS = {
  AGENT: config.agentsCollectionId,
  REVIEWS: config.reviewsCollectionId,
  GALLERY: config.galleriesCollectionId,
  PROPERTY: config.propertiesCollectionId,
}

// Enum 필드와 정확히 일치해야 함 — 대소문자, 철자 주의!
const propertyTypes = [
  'House',
  'Townhomes',
  'Condos',
  'Duplexes',
  'Studios',
  'Villa',
  'Apartments',
  'Others',
]

const facilities = [
  'Laundry',
  'Car Parking',
  'Sports Center',
  'Cutlery',
  'Gym',
  'Swimming pool',
  'Wifi',
  'Pet Center',
]

// ── 헬퍼 함수: 배열에서 무작위로 N개 뽑기 ──────────────
// T는 제네릭: 어떤 타입의 배열이든 사용 가능
function getRandomSubset<T>(array: T[], minItems: number, maxItems: number): T[] {
  // minItems ~ maxItems 사이의 무작위 개수 결정
  const subsetSize = Math.floor(Math.random() * (maxItems - minItems + 1)) + minItems

  // Fisher-Yates 알고리즘으로 배열 무작위 섞기
  const arrayCopy = [...array] // 원본 배열을 건드리지 않기 위해 복사
  for (let i = arrayCopy.length - 1; i > 0; i--) {
    const randomIndex = Math.floor(Math.random() * (i + 1))
    // 구조 분해 할당으로 두 요소 위치 교환
    ;[arrayCopy[i], arrayCopy[randomIndex]] = [arrayCopy[randomIndex], arrayCopy[i]]
  }

  return arrayCopy.slice(0, subsetSize) // 앞에서 N개만 반환
}

// ── 메인 시드 함수 ──────────────────────────────────────
async function seed() {
  try {
    // ── STEP 1: 기존 데이터 전부 삭제 ──────────────────
    for (const key in COLLECTIONS) {
      const collectionId = COLLECTIONS[key as keyof typeof COLLECTIONS]

      // 해당 컬렉션의 모든 문서 목록 가져오기
      const documents = await databases.listDocuments(config.databaseId!, collectionId!)

      // 각 문서 삭제
      for (const doc of documents.documents) {
        await databases.deleteDocument(config.databaseId!, collectionId!, doc.$id)
      }
    }
    console.log('기존 데이터 삭제 완료')

    // ── STEP 2: 에이전트 5명 생성 ──────────────────────
    const agents = []
    for (let i = 1; i <= 5; i++) {
      const agent = await databases.createDocument(
        config.databaseId!,
        COLLECTIONS.AGENT!,
        ID.unique(), // Appwrite가 고유 ID 자동 생성
        {
          name: `Agent ${i}`,
          email: `agent${i}@example.com`,
          // 에이전트 이미지 목록에서 무작위로 하나 선택
          avatar: agentImages[Math.floor(Math.random() * agentImages.length)],
        }
      )
      agents.push(agent) // 나중에 매물과 연결하기 위해 저장
    }
    console.log(`에이전트 ${agents.length}명 생성 완료`)

    // ── STEP 3: 리뷰 20개 생성 ──────────────────────────
    const reviews = []
    for (let i = 1; i <= 20; i++) {
      const review = await databases.createDocument(
        config.databaseId!,
        COLLECTIONS.REVIEWS!,
        ID.unique(),
        {
          name: `Reviewer ${i}`,
          avatar: reviewImages[Math.floor(Math.random() * reviewImages.length)],
          review: `This is a review by Reviewer ${i}.`,
          rating: Math.floor(Math.random() * 5) + 1, // 1~5 무작위 평점
        }
      )
      reviews.push(review)
    }
    console.log(`리뷰 ${reviews.length}개 생성 완료`)

    // ── STEP 4: 갤러리 이미지 생성 ──────────────────────
    const galleries = []
    for (const image of galleryImages) {
      const gallery = await databases.createDocument(
        config.databaseId!,
        COLLECTIONS.GALLERY!,
        ID.unique(),
        { image }
      )
      galleries.push(gallery)
    }
    console.log(`갤러리 ${galleries.length}개 생성 완료`)

    // ── STEP 5: 매물 20개 생성 + 연결 ──────────────────
    for (let i = 1; i <= 20; i++) {
      // 에이전트 무작위 배정
      const assignedAgent = agents[Math.floor(Math.random() * agents.length)]

      // 리뷰 5~7개 무작위 선택
      const assignedReviews = getRandomSubset(reviews, 5, 7)

      // 갤러리 3~8개 무작위 선택
      const assignedGalleries = getRandomSubset(galleries, 3, 8)

      // 시설 무작위 선택
      const selectedFacilities = facilities
        .sort(() => 0.5 - Math.random()) // 무작위 섞기
        .slice(0, Math.floor(Math.random() * facilities.length) + 1)

      // 매물 이미지 순서대로 배정 (없으면 무작위)
      const image =
        propertiesImages.length - 1 >= i
          ? propertiesImages[i]
          : propertiesImages[Math.floor(Math.random() * propertiesImages.length)]

      const property = await databases.createDocument(
        config.databaseId!,
        COLLECTIONS.PROPERTY!,
        ID.unique(),
        {
          name: `Property ${i}`,
          type: propertyTypes[Math.floor(Math.random() * propertyTypes.length)],
          description: `This is the description for Property ${i}.`,
          address: `123 Property Street, City ${i}`,
          geolocation: `192.168.1.${i}, 192.168.1.${i}`,
          price: Math.floor(Math.random() * 9000) + 1000, // 1000~10000
          area: Math.floor(Math.random() * 3000) + 500, // 500~3500 sqft
          bedrooms: Math.floor(Math.random() * 5) + 1, // 1~5개
          bathrooms: Math.floor(Math.random() * 5) + 1, // 1~5개
          rating: Math.floor(Math.random() * 5) + 1, // 1~5점
          facilities: selectedFacilities,
          image: image,
          agent: assignedAgent.$id, // 에이전트 ID로 연결
          reviews: assignedReviews.map((review) => review.$id), // 리뷰 ID 배열
          gallery: assignedGalleries.map((gallery) => gallery.$id), // 갤러리 ID 배열
        }
      )
      console.log(`매물 생성: ${property.name}`)
    }

    console.log('시딩 완료!')
  } catch (error) {
    console.error('시딩 에러:', error)
  }
}

export default seed
```

## 4. 핵심 개념

### `ID.unique()` — 고유 ID 자동 생성

```tsx
// Appwrite가 랜덤 고유 ID를 자동으로 만들어줌
// 예: "6751ab3d000b123456"
databases.createDocument(dbId, collectionId, ID.unique(), data)

// ID.unique() 대신 직접 ID를 지정할 수도 있음
databases.createDocument(dbId, collectionId, 'my-custom-id', data)
```

### 관계 연결 방법

```tsx
// 다른 컬렉션의 문서와 연결할 때는 $id를 사용
{
  agent: assignedAgent.$id,                          // 단일 관계 → ID 하나
  reviews: assignedReviews.map((r) => r.$id),        // 다중 관계 → ID 배열
  gallery: assignedGalleries.map((g) => g.$id),      // 다중 관계 → ID 배열
}
```

### `Math.random()` 패턴 정리

```tsx
// 0 이상 N 미만 랜덤 정수
Math.floor(Math.random() * N)

// 1 이상 5 이하 랜덤 정수 (평점, 침실 수 등)
Math.floor(Math.random() * 5) + 1 // → 1, 2, 3, 4, 5 중 하나

// 배열에서 랜덤 항목 하나 선택
array[Math.floor(Math.random() * array.length)]
```

### Fisher-Yates 셔플 알고리즘

```tsx
// 배열을 완전히 무작위로 섞는 알고리즘
// 뒤에서부터 앞으로 순회하며 무작위 위치와 교환

for (let i = array.length - 1; i > 0; i--) {
  const j = Math.floor(Math.random() * (i + 1)) // 0 ~ i 사이 랜덤 인덱스
  ;[array[i], array[j]] = [array[j], array[i]] // 두 요소 위치 교환
}
```

```tsx
// Appwrite DB에 등록한 Enum 값
```
