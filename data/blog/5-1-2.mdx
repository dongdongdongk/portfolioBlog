### \* 로컬과 실제 배포 환경에서 다른 방식을 사용하는 이유

```jsx
비용 절감:

		SendGrid와 같은 이메일 전송 서비스는 유료입니다.

		로컬 개발 중에도 실시간 전송을 위해 SendGrid를 사용하면 비용이 크게 증가할 수 있습니다.

		하지만 nodemailer를 사용하면 무료로 로컬에서 기능을 테스트할 수 있습니다.

안정성:

		로컬 환경에서는 테스트 시 여러 번 이메일을 전송해야 하므로,

		실제 사용자에게 잘못된 이메일이 발송되지 않도록 방지해야 합니다.

		nodemailer는 로컬 SMTP 서버를 통해 가상 이메일 전송을 수행하므로 테스트 과정에서 실제 이메일 발송 사고를 방지할 수 있습니다.

성능:

		SendGrid와 같은 서비스는 이메일 발송을 대규모로 처리할 수 있도록 최적화되어 있어,

		실제 운영 중인 서비스에서는 성능과 안정성 면에서 유리합니다.
```

```jsx
import nodemailer from 'nodemailer'; // nodemailer 패키지를 가져와서 이메일 전송 기능 구현에 사용
import Mail from 'nodemailer/lib/mailer'; // nodemailer의 메일 타입을 가져와 메일 옵션 정의에 사용
import Logger from 'bunyan'; // bunyan 로깅 라이브러리로, 메일 전송 상태 로그 남김
import sendGridMail from '@sendgrid/mail'; // SendGrid 패키지를 사용하여 배포 환경에서 이메일 전송
import { config } from '@root/config'; // 환경 설정 파일에서 설정 값 가져옴
import { BadRequestError } from '@global/helpers/error-handler'; // 오류 처리용 클래스 정의

// 이메일 옵션 인터페이스
// 이메일을 보낼 때 필요한 필수 항목을 지정한 인터페이스입니다.
interface IMailOptions {
  from: string;  // 발신자 이메일
  to: string;    // 수신자 이메일
  subject: string; // 이메일 제목
  html: string;  // 이메일 본문 (HTML 형식)
}

// 로깅 설정 및 SendGrid API 키 설정
const log: Logger = config.createLogger('mailOption'); // 로거 생성 (이메일 전송 관련 로그 저장)
sendGridMail.setApiKey(config.SENDGRID_API_KEY!); // SendGrid API 키 설정 (배포 환경에서 사용)

class MailTransport {

  // 이메일 전송 메서드
  // 이 메서드는 개발 환경과 배포 환경을 구분하여 알맞은 메일 전송 방법을 선택합니다.
  public async sendEmail(receiveEmail: string, subject: string, body: string): Promise<void> {
    // NODE_ENV가 'test' 또는 'development'일 때는 로컬 이메일 전송 메서드를 사용
    if (config.NODE_ENV === 'test' || config.NODE_ENV === 'development') {
      this.developmentEmailSender(receiveEmail, subject, body);
    } else {
      // 배포 환경에서는 SendGrid를 사용하여 이메일 전송
      this.productionEmailSender(receiveEmail, subject, body);
    }
  }

  // 개발 환경에서 이메일 전송 메서드
  // 이 메서드는 nodemailer를 사용하여 로컬 SMTP 서버 (Ethereal)로 이메일을 전송합니다.
  private async developmentEmailSender(receiveEmail: string, subject: string, body: string): Promise<void> {
    // nodemailer의 transport 설정: Ethereal SMTP 서버를 사용하여 이메일 전송
    const transporter: Mail = nodemailer.createTransport({
      host: 'smtp.ethereal.email', // Ethereal SMTP 서버
      port: 587, // 일반적인 SMTP 포트
      secure: false, // true로 설정하면 보안 연결 (TLS) 사용, 여기서는 false
      auth: {
        user: config.SENDER_EMAIL!, // 발신자 이메일 (환경 변수에서 가져옴)
        pass: config.SENDER_EMAIL_PASSWORD! // 발신자 이메일 비밀번호 (환경 변수에서 가져옴)
      }
    });

    // 이메일 옵션 설정
    const mailOption: IMailOptions = {
      from: `Chatty App <${config.SENDER_EMAIL!}`, // 이메일 발신자 설정
      to: receiveEmail, // 수신자 이메일 주소
      subject, // 이메일 제목
      html: body // 이메일 본문 내용 (HTML 형식)
    };

    try {
      // 이메일 전송 시도
      await transporter.sendMail(mailOption); // transporter 객체로 이메일 전송
      log.info('Development email sent successfully'); // 성공 시 로그 메시지 출력
    } catch (error) {
      // 전송 실패 시 로그 메시지 출력 및 오류 던짐
      log.error('Error sending email', error); // 오류 로그 남기기
      throw new BadRequestError('Error sending email'); // BadRequestError로 오류 처리
    }
  }

  // 배포 환경에서 이메일 전송 메서드
  // 이 메서드는 SendGrid를 사용하여 실제 사용자에게 이메일을 전송합니다.
  private async productionEmailSender(receiveEmail: string, subject: string, body: string): Promise<void> {

    // 이메일 옵션 설정
    const mailOption: IMailOptions = {
      from: `Chatty App <${config.SENDGRID_SENDER!}`, // SendGrid를 통한 이메일 발신자 설정
      to: receiveEmail, // 수신자 이메일 주소
      subject, // 이메일 제목
      html: body // 이메일 본문 내용 (HTML 형식)
    };

    try {
      // 이메일 전송 시도
      await sendGridMail.send(mailOption); // SendGrid API로 이메일 전송
      log.info('Production email sent successfully'); // 성공 시 로그 메시지 출력
    } catch (error) {
      // 전송 실패 시 로그 메시지 출력 및 오류 던짐
      log.error('Error sending email', error); // 오류 로그 남기기
      throw new BadRequestError('Error sending email'); // BadRequestError로 오류 처리
    }
  }
}

// 클래스 인스턴스 생성 및 내보내기
export const mailTransport: MailTransport = new MailTransport(); // 다른 모듈에서 사용할 수 있도록 인스턴스 생성 및 내보내기

```

# { 이메일 큐와 워커 작성 }

```jsx
이 강의에서는 이메일 전송 시스템을 효율적으로 관리하기 위해

**이메일 큐(Queue)**와 **이메일 워커(Worker)**를 설정하는 방법을 다룹니다.

이 과정은 서버에서 이메일을 동기식으로 즉시 보내지 않고 큐에 작업을 추가하여 비동기식으로 처리하게 함으로써,

서버의 성능을 최적화하고 이메일 전송이 더욱 안정적으로 이루어지도록 돕습니다.
```

## 개요: 이메일 큐와 워커

```jsx
이메일 큐(Queue):

		이메일 전송 요청을 일정한 순서대로 관리하여 즉시 전송하지 않고 큐에 넣어 관리합니다.

		여러 작업이 동시에 들어와도 처리 순서를 제어할 수 있습니다.

이메일 워커(Worker):

		큐에 담긴 작업을 실제로 처리하는 역할을 합니다.

		이메일 전송 시 큐에서 요청을 꺼내 sendEmail 메서드를 호출하여 메일을 전송합니다.




이 두 개념을 활용하면, 예를 들어 비밀번호 재설정 이메일을 보내거나,

회원가입 완료 시 이메일을 보내는 등의 기능을 서버 부하 없이 처리할 수 있습니다.
```


### `email.queue.ts` 파일 생성 및 기본 큐 설정

```jsx
먼저 email.queue.ts 파일을 생성하여 기본 큐를 설정합니다.
```

```jsx
import { BaseQueue } from '@service/queues/base.queue';
import { IEmailJob } from '@user/interfaces/user.interface';
import { emailWorker } from '@worker/email.worker';

class EmailQueue extends BaseQueue {
  constructor() {
    super('emails');
    // 'forgotPasswordEmail' 작업을 큐에 추가하고, 5개의 작업을 동시에 처리할 수 있도록 설정
    this.processJob('forgotPasswordEmail', 5, emailWorker.addNotificationEmail);
  }

  // 이메일 작업을 추가하는 메서드
  public addEmailJob(name: string, data: IEmailJob): void {
    this.addJob(name, data);
  }
}

export const emailQueue: EmailQueue = new EmailQueue();

```

```jsx
super('emails'):

		상위 클래스 BaseQueue를 상속받아 이메일 큐 이름을 'emails'로 설정합니다.

processJob('forgotPasswordEmail', 5, emailWorker.addNotificationEmail):

		forgotPasswordEmail 작업을 5개의 동시성으로 처리하고,
```

```jsx
import { DoneCallback, Job } from 'bull';
import Logger from 'bunyan';
import { config } from '@root/config';
import { mailTransport } from '@service/emails/mail.transport';

const log: Logger = config.createLogger('emailWorker');

class EmailWorker {
  async addNotificationEmail(job: Job, done: DoneCallback): Promise<void> {
    try {
      const { template, receiverEmail, subject } = job.data;
      await mailTransport.sendEmail(receiverEmail, subject, template);
      job.progress(100); // 작업 진행 상태를 100%로 표시
      done(null, job.data); // 작업 성공 시 종료
    } catch (error) {
      log.error(error);
      done(error as Error); // 작업 실패 시 에러를 로깅하고 종료
    }
  }
}
```

## 사전 작업: Schema 및 Interface 수정

### `User` Schema 수정

```jsx
사용자 모델에서 비밀번호 초기화 관련 필드를 제거합니다.

passwordResetToken: { type: String, default: '' },
passwordResetExpires: { type: Number },

User 스키마에서 위의 필드들을 삭제합니다. 비밀번호 초기화와 관련된 필드는 Auth 모델에 두는 것이 더 논리적입니다.

비밀번호 초기화 필드를 User 모델에서 Auth 모델로 옮기는 것은

**설계 원칙(책임 분리, 보안 강화)**를 준수하고 유지보수와 효율성을 높이기 위한 결정입니다.

User 모델은 사용자 프로필과 관련된 정보만, Auth 모델은 인증과 관련된 정보만 관리하도록 분리하는 것이 이상적입니다.
```

```jsx
import { Request, Response } from 'express';
import HTTP_STATUS from 'http-status-codes';
import { authService } from '@service/db/auth.service';
import { BadRequestError } from '@global/helpers/error-handler';
import { joiValidation } from '@global/decorators/joi-validation.decorator';
import { emailSchema } from '@auth/schemes/password';

export class Password {
  // @joiValidation: 요청(req.body)을 emailSchema로 검증합니다.
  // emailSchema는 올바른 이메일 형식인지 확인하는 데 사용됩니다.
  @joiValidation(emailSchema)
  public async create(req: Request, res: Response): Promise<void> {
    // 1. 클라이언트에서 요청으로 받은 이메일 추출
    const { email } = req.body;

    // 2. 이메일로 사용자를 조회
    // authService의 getAuthUserByEmail 메서드를 사용하여 이메일에 해당하는 사용자가 있는지 확인합니다.
    const existingUser = await authService.getAuthUserByEmail(email);
    if (!existingUser) {
      // 사용자가 존재하지 않으면 에러를 발생시킵니다.
      throw new BadRequestError('Invalid credentials');
    }

    // 3. 랜덤 토큰 생성
    // 비밀번호 재설정을 위한 고유 토큰을 생성합니다.
    // crypto.randomBytes를 사용해 20바이트의 랜덤 데이터를 생성한 후, 이를 16진수 문자열로 변환합니다.
    const randomBytes = await Promise.resolve(crypto.randomBytes(20)); // 바이트당 2개의 16진수 문자를 가지므로, 최종적으로 40개의 16진수 문자
    const randomCharacters = randomBytes.toString('hex'); // 데이터를 사람이 읽을 수 있는 문자열로 변환합니다. 여기서 'hex'는 **16진수(hexadecimal)**를 의미합니다.

    // 4. 데이터베이스에 토큰과 만료 시간을 업데이트
    // - 사용자 ID를 사용해 데이터베이스에서 해당 사용자 레코드를 업데이트합니다.
    // - randomCharacters: 비밀번호 재설정 링크에 포함될 고유 토큰.
    // - Date.now() + 60 * 60 * 1000: 현재 시간에서 1시간 후를 토큰 만료 시간으로 설정합니다.
    await authService.updatePasswordToken(
      `${existingUser._id}`, // 사용자 ID
      randomCharacters,      // 생성된 토큰
      Date.now() + 60 * 60 * 1000 // 토큰 만료 시간 (1시간 후)
    );

    // 5. 비밀번호 재설정 링크 생성
    // - 클라이언트 URL 뒤에 토큰을 추가해 비밀번호 재설정 링크를 생성합니다.
    const resetLink = `${config.CLIENT_URL}/reset-password?Token=${randomCharacters}`;

    // 6. 이메일 템플릿 생성
    // - forgotPasswordTemplate.passwordResetTemplate 메서드로 사용자 이름과 링크를 포함한 이메일 내용을 생성합니다.
    const template = forgotPasswordTemplate.passwordResetTemplate(existingUser.username!, resetLink);

    // 7. 이메일 발송 작업 추가
    // - emailQueue.addEmailJob을 사용해 이메일 발송 작업을 큐에 추가합니다.
    // - 템플릿, 수신자 이메일, 제목 등의 정보를 전달합니다.
    emailQueue.addEmailJob('forgotPasswordEmail', {
      template,              // 이메일 템플릿
      receiverEmail: email,  // 이메일 수신자
      subject: 'Reset your password', // 이메일 제목
    });

    // 8. 클라이언트에 성공 응답 전송
    // - HTTP 상태 코드 200(OK)와 함께 비밀번호 재설정 이메일이 전송되었음을 알리는 메시지를 반환합니다.
    res.status(HTTP_STATUS.OK).json({ message: 'Password reset email sent' });
  }
}
```

## 새로운 비밀번호 설정 (`update` 메서드)

```jsx
password.ts 에 새로운 메서드를 추가해준다
```

```jsx
@joiValidation(passwordSchema) // Joi를 이용해 요청 데이터를 검증
public async update(req: Request, res: Response): Promise<void> {
  const { password, confirmPassword } = req.body; // 요청 본문에서 비밀번호와 확인 비밀번호를 추출
  const { token } = req.params; // URL 매개변수에서 토큰을 추출

  // 비밀번호와 확인 비밀번호가 다르면 에러 발생
  if (password !== confirmPassword) {
    throw new BadRequestError('Passwords do not match');
  }

  // 토큰이 유효하고 만료되지 않았는지 확인
  const existingUser: IAuthDocument = await authService.getAuthUserByPasswordToken(token);
  if (!existingUser) {
    throw new BadRequestError('Reset token has expired'); // 토큰이 없거나 만료된 경우
  }

  // 사용자의 비밀번호를 업데이트
  existingUser.password = password; // 새로운 비밀번호 설정
  existingUser.passwordResetExpires = undefined; // 만료 시간 제거
  existingUser.passwordResetToken = undefined; // 토큰 제거
  await existingUser.save(); // 변경 사항 저장

  // 비밀번호 재설정 확인 이메일 발송
  const templateParams: IResetPasswordParams = {
    username: existingUser.username!,
    email: existingUser.email!,
    ipaddress: publicIP.address(), // 현재 IP 주소
    date: moment().format('DD/MM/YYYY HH:mm') // 현재 날짜와 시간
  };
  const template: string = resetPasswordTemplate.passwordResetTemplate(templateParams);
  emailQueue.addEmailJob('forgotPasswordEmail', {
    template,
    receiverEmail: existingUser.email!,
    subject: 'Password Reset Confirmation'
  });

  // 성공 메시지 반환
  res.status(HTTP_STATUS.OK).json({ message: 'Password successfully updated' });
}

```

```jsx
입력 데이터 검증

		@joiValidation(passwordSchema)를 통해 요청 본문의 데이터(password, confirmPassword)를 검증합니다.

		예: 비밀번호가 최소 길이를 만족하는지, 확인 비밀번호가 비밀번호와 일치하는지 등.

토큰 유효성 확인

		데이터베이스에서 passwordResetToken이 일치하는 사용자를 찾습니다.

		passwordResetExpires가 현재 시간보다 큰지 확인하여 토큰이 유효한지 판단합니다.

		토큰이 만료되었거나 존재하지 않으면 에러를 반환합니다.

비밀번호 업데이트

		사용자의 password 필드를 새로운 비밀번호로 업데이트합니다.

		passwordResetToken 및 passwordResetExpires 필드는 더 이상 필요하지 않으므로 제거(undefined로 설정)합니다.

		save() 메서드를 호출하여 변경 사항을 데이터베이스에 저장합니다.

확인 이메일 발송

		비밀번호 변경 사실을 사용자에게 알리기 위해 확인 이메일을 보냅니다.

		이메일에는 사용자 이름, 이메일, IP 주소, 변경된 시간 등의 정보가 포함됩니다.

성공 메시지 반환
```

## `getAuthUserByPasswordToken` 메서드 추가


```jsx
public async getAuthUserByPasswordToken(token: string): Promise<IAuthDocument> {
  const user: IAuthDocument = (await AuthModel.findOne({
    passwordResetToken: token, // 토큰이 일치하고
    passwordResetExpires: { $gt: Date.now() } // 만료 시간이 현재 시간보다 큰 경우
  }).exec()) as IAuthDocument;
  return user; // 유효한 사용자 반환
}
```

```jsx
		MongoDB에서 사용하는 비교 연산자로, **"greater than" (크다)**를 의미합니다.

		passwordResetExpires > Date.now() 조건과 같습니다.

		문서의 passwordResetExpires 값이 현재 시간(Date.now())보다 큰 경우에만 해당 문서를 반환합니다.
```

```jsx
1% 커버리지 기준:

테스트 통과를 위해 커버리지 비율이 최소 1%만 되어도 충분하다는 설정

이 설정은 초기 개발 단계에서 엄격하지 않게 설정해두고, 나중에 커버리지를 더 높게 요구할 수 있다

(예: 80%, 90% 이상)
```

### "커버리지(coverage)"란?

```jsx
커버리지는 테스트 코드가 실제 프로그램 코드를 얼마나 실행했는지를 나타내는 비율

쉽게 말하면, 작성한 테스트가 코드의 어느 부분까지 검사했는지를 숫자로 보여준다

		100% 커버리지라면, 모든 코드(분기, 함수, 줄)가 테스트를 통해 실행되고 검사된 거

		커버리지가 낮다면, 테스트되지 않은 코드가 많다는 뜻
```

```jsx
jest.config.ts를 TypeScript 컴파일 대상에서 제외하도록 설정합니다:
```

```jsx

    "rootDir": "./src"
  },
  "exclude": ["jest.config.ts"] // 제외
}
```

## **테스트 실행 스크립트 추가**

```jsx
package.json의 "scripts" 섹션에 테스트 실행 스크립트를 추가.
```

```jsx
"test": "jest --coverage=true -w=1 --forceExit --detectOpenHandles --watchAll=false"

```

```jsx
사용된 옵션 설명

(1) --coverage=true

		의미: 테스트 실행 후 코드 커버리지 보고서를 생성합니다.

		커버리지는 테스트 코드가 실제 애플리케이션 코드의 몇 퍼센트를 실행했는지 보여주는 지표입니다.

		장점: 테스트가 충분히 작성되었는지 확인 가능.

(2) -w=1 또는 --maxWorkers=1

		의미: 테스트 실행 시 사용할 작업자(worker) 프로세스의 개수를 지정합니다.

		디폴트: CPU 코어 수 - 1

		설정 이유: 단일 프로세스로 실행(w=1)하여 성능을 제어하고 과부하를 방지.

(3) --forceExit

		의미: 테스트 실행이 끝난 후 강제로 Jest 프로세스를 종료합니다.

		필요한 이유:

		데이터베이스 연결 해제 등의 클린업(clean-up)이 제대로 이루어지지 않아 Jest가 무한 대기 상태에 빠지는 문제를 방지.

		주의사항: 클린업 문제를 해결하기보다 회피하는 방법이므로 남용하지 않아야 함.

(4) --detectOpenHandles

		의미: 테스트 종료를 방해하는 **열려 있는 핸들(open handles)**을 탐지합니다.

		사용 목적:

		Jest가 무한 대기 상태에 빠질 경우, 문제의 원인을 콘솔에 출력하여 디버깅 가능.

		핸들의 예:

		닫히지 않은 파일, 미완료된 비동기 작업, 연결되지 않은 데이터베이스 등.

(5) --watchAll=false

		의미: Jest가 파일 변경을 감지하고 테스트를 자동으로 다시 실행하는 watch 모드를 비활성화합니다.

		설정 이유:

		CI/CD 파이프라인 등에서 테스트 실행 후 종료가 필요.

		로컬 개발 환경에서는 --watchAll=true를 설정하면 파일 변경 시 테스트가 자동 재실행되어 편리.

```

## 결론

```jsx
이 스크립트는 Jest의 유닛 테스트를 실행하고 커버리지까지 확인할 수 있는 설정을 포함하고 있습니다.

로컬 개발 환경에서는 --watchAll=true를 활용하여 편리하게 테스트를 자동으로 실행할 수 있습니다.

배포나 CI 환경에서는 테스트를 강제 종료(--forceExit), 열려 있는 핸들 디버깅(--detectOpenHandles),

파일 감지 비활성화(--watchAll=false) 등의 옵션으로 안정성을 높입니다.
```

# { Jest 사용법 예제 총 저리 } \* 참고 하기

```jsx
아래 예제는 Jest의 주요 기능인 Mock, spyOn, 비동기 함수 호출,

그리고 expect를 한꺼번에 사용하여 테스트를 작성하는 방법을 보여줍니다.
```

```jsx
예제 시나리오:

UserService는 사용자 데이터를 가져오는 함수(getUserData)를 제공합니다.

NotificationService는 특정 작업이 완료되면 알림을 보냅니다.

우리는 두 서비스가 제대로 동작하고 상호작용하는지를 테스트합니다.
```

## 서비스 코드

```jsx
// 실제 서비스 코드
const NotificationService = {
  sendNotification: (message) => {
    console.log('Notification sent:', message)
  },
}

const UserService = {
  async getUserData(userId) {
    return { id: userId, name: 'John Doe' }
  },

  async processUser(userId) {
    const user = await this.getUserData(userId)
    NotificationService.sendNotification(`User ${user.name} processed.`)
    return user
  },
}

module.exports = { UserService, NotificationService }
```

## 테스트 코드

```jsx
const { UserService, NotificationService } = require('./services')

describe('UserService Tests', () => {
  it('should process user and send notification', async () => {
    // 1. Mock NotificationService의 sendNotification 함수
    const mockSendNotification = jest.spyOn(NotificationService, 'sendNotification')

    // 2. Mock UserService의 getUserData 함수
    const mockGetUserData = jest.spyOn(UserService, 'getUserData').mockResolvedValue({
      id: 1,
      name: 'Mock User',
    })

    // 3. processUser 호출
    const result = await UserService.processUser(1)

    // 4. 기대 값 확인
    expect(mockGetUserData).toHaveBeenCalled() // getUserData가 호출되었는지 확인
    expect(mockGetUserData).toHaveBeenCalledWith(1) // getUserData에 전달된 인수 확인
    expect(mockSendNotification).toHaveBeenCalled() // sendNotification 호출 여부 확인
    expect(mockSendNotification).toHaveBeenCalledWith('User Mock User processed.') // 호출된 메시지 확인
    expect(result).toEqual({ id: 1, name: 'Mock User' }) // 반환된 사용자 정보 확인

    // 5. Mock 복원
    mockSendNotification.mockRestore()
    mockGetUserData.mockRestore()
  })
})
```

## 단계별 설명

```jsx
1. Mock 진행

		jest.spyOn(NotificationService, "sendNotification")을 사용해 sendNotification 함수를 감시하고 호출을 추적합니다.

		jest.spyOn(UserService, "getUserData").mockResolvedValue()로 getUserData의 반환값을 임의로 설정합니다.

2. SpyOn 사용

		spyOn은 특정 메서드가 호출되었는지, 어떤 인수로 호출되었는지 추적하는 데 사용됩니다.

3. 비동기 함수 호출

		await UserService.processUser(1)로 비동기 함수 호출 결과를 확인합니다.

4. Expect와 toHaveBeenCalled

		toHaveBeenCalled로 함수가 호출되었는지 확인합니다.

		toHaveBeenCalledWith로 함수 호출 시 전달된 인수를 확인합니다.

		toEqual로 함수의 반환값이 예상과 일치하는지 확인합니다.
```

# { Node.js와 Express로 유닛 테스트(Unit Test) 작성하기 }

```jsx
Node.js와 Express를 이용한 프로젝트에서는 데이터베이스나 외부 API를 직접 연결하지 않고도

유닛 테스트는 각각의 코드 단위를 독립적으로 테스트하여 문제를 발견하고 유지 보수를 쉽게 만듭니다.

이 글에서는 유닛 테스트 작성 방법과, 특히 Express의 요청(Request) 및 응답(Response)을 **모킹(Mock)**하여
```

## 유닛 테스트와 통합 테스트의 차이

```jsx
유닛 테스트(Unit Test):

		특정 함수나 메서드의 동작을 단독으로 테스트.

		외부 종속성(DB, API 등)은 모두 모킹(Mock) 처리.

		빠르게 수행되고, 디버깅이 간편.

통합 테스트(Integration Test):

		여러 구성 요소(DB, API 등)를 실제로 연결하여 시스템 동작 확인.

		설정 복잡도가 높고, 속도가 느림.


* 이 글에서는 유닛 테스트를 다룹니다.
```

## 모킹(Mock)이란?

```jsx
모킹은 실제 객체를 대신해 동작을 흉내 낸 가짜 객체를 사용하는 방법입니다.

테스트 코드에서 의존성을 제거하고, 특정 값이나 에러를 반환하도록 설정할 수 있습니다.
```

```jsx
Express의 Request/Response 객체 모킹

		요청(req) 객체: body, params, session 등을 포함.

		응답(res) 객체: status, json 메서드 등이 필요.
```

```jsx
mocks 디렉터리 생성

		mocks 폴더는 Request와 Response 객체 및 기타 데이터의 모킹 로직을 저장합니다.
```

# { Mock, Spy, fn() 설명 }

## `jest.mock`의 역할

```jsx
jest.mock은 지정한 모듈 전체를 자동으로 Mock 객체로 대체합니다.

Mock 객체로 대체된 메서드는 기본적으로 jest.fn()으로 구현됩니다.

따라서, 모든 메서드 호출은 기본적으로 아무것도 하지 않는 함수로 처리됩니다.

실제 메서드가 실행되지 않으므로, 외부 의존성을 제거하고 테스트 환경에서 안전하게 실행됩니다.

jest.mock('@service/queues/email.queue'); // email.queue 모듈을 모의 처리
jest.mock('@service/db/auth.service');   // auth.service 모듈을 모의 처리

위 코드는 @service/queues/email.queue와 @service/db/auth.service 모듈의 모든 메서드를 Mock으로 대체합니다.

이로 인해, jest.spyOn(emailQueue, 'addEmailJob')을 사용하면,

addEmailJob은 기본적으로 jest.fn()으로 처리되며 아무 동작도 하지 않습니다.
```

## `jest.mock`과 `jest.spyOn`의 차이

```jsx
jest.mock

		모듈 전체를 모의 처리합니다.

		해당 모듈의 메서드들이 jest.fn()으로 대체되어, 실제 동작을 호출하지 않습니다.

		이후 필요에 따라 특정 메서드에 대해 mockImplementation, mockReturnValue

		등을 추가로 설정하여 원하는 동작을 정의할 수 있습니다.

jest.spyOn

		특정 메서드를 스파이 처리하여 호출 추적 및 Mock 구현 설정을 허용합니다.

		스파이 처리 후 별도의 mockImplementation 또는 mockResolvedValue를

		설정하지 않으면, 원래 메서드가 호출됩니다.

		기존 동작을 유지하면서 호출을 감시하거나 대체하려는 경우에 사용됩니다.
```

```jsx
이후 스파이를 추가하면 아래와 같이 동작을 커스터마이즈할 수 있습니다:
```

## `jest.fn()`에 대해 알아보기

```jsx
jest.fn()은 Jest에서 제공하는 모의(Mock) 함수를 생성하는 도구입니다.

이를 사용하면 실제 함수 대신 호출을 추적하거나,

원하는 대로 동작을 정의할 수 있는 가짜 함수를 만듭니다.

jest.fn()은 다음과 같은 상황에서 사용됩니다:

1. 함수를 대신할 가짜 함수를 만들고 싶을 때.

2. 함수 호출 여부, 호출 횟수, 전달된 인자 등을 추적하고 싶을 때.

3. 함수의 결과를 테스트 시점에 정의하고 싶을 때.

간단히 말해, jest.fn()은 실제 코드가 실행되지 않아도 테스트를 수행할 수 있도록 도와줍니다.

jest.fn()의 주요 특징

호출 횟수와 호출된 인자를 자동으로 추적합니다.

기본적으로 아무 일도 하지 않는 함수입니다.

원하는 동작을 설정할 수 있습니다.

		값을 반환하도록 설정 (mockReturnValue)

		비동기 결과를 반환하도록 설정 (mockResolvedValue)

		특정 구현 로직을 설정 (mockImplementation)
```

### 간단한 Mock 함수 생성

```jsx
const mockFunction = jest.fn() // 아무 동작도 하지 않는 가짜 함수 생성

mockFunction() // 호출
mockFunction('arg1', 'arg2') // 호출하며 인자 전달

// 호출 추적
console.log(mockFunction.mock.calls)
// 출력: [ [], ['arg1', 'arg2'] ] (각각의 호출과 전달된 인자)
console.log(mockFunction.mock.calls.length)
// 출력: 2 (총 2번 호출됨)
```

### 값을 반환하도록 설정

```jsx
mockReturnValue를 사용하여 함수 호출 시 반환값을 설정할 수 있습니다.
```

```jsx
const mockFunction = jest.fn().mockReturnValue('Hello, Jest!')

console.log(mockFunction()) // 출력: Hello, Jest!
console.log(mockFunction()) // 출력: Hello, Jest!
console.log(mockFunction.mock.calls.length) // 출력: 2 (총 2번 호출됨)
```

### 비동기 동작 설정

```jsx
mockResolvedValue를 사용하면 Promise를 반환하는 함수로 만들 수 있습니다.
```

```jsx
const mockFunction = jest.fn().mockResolvedValue('Async Result')

mockFunction().then((result) => console.log(result)) // 출력: Async Result
```

### 호출 추적 기능

```jsx
jest.fn()으로 생성한 함수는 호출 내역을 자동으로 기록합니다.

이를 통해 테스트에서 함수가 올바르게 호출되었는지 확인할 수 있습니다.
```

```jsx
const mockFunction = jest.fn()

mockFunction('first call')
mockFunction('second call', 123)

console.log(mockFunction.mock.calls)
// 출력: [ ['first call'], ['second call', 123] ]

console.log(mockFunction.mock.calls.length)
// 출력: 2 (총 2번 호출됨)

console.log(mockFunction.mock.calls[mockFunction.mock.calls.length - 1])
// 출력: ['second call', 123] (마지막 호출의 인자)
```

### 함수 호출 여부 테스트

```jsx
테스트에서 특정 함수가 호출되었는지 확인:
```

```jsx

  const mockFunction = jest.fn()

  // 함수 호출
  mockFunction('test argument')

  // 호출 확인
  expect(mockFunction).toHaveBeenCalled() // 호출 여부
  expect(mockFunction).toHaveBeenCalledWith('test argument') // 전달된 인자
  expect(mockFunction.mock.calls.length).toBe(1) // 호출 횟수
})
```

### 예제 프로젝트에서 적용

```jsx
Mock 함수로 이메일 전송 테스트:
```

```jsx
  await emailQueue.addEmailJob({ email: 'test@example.com' })

})
```

## jest.spyOn


### 감시(Spy)와 모의(Mock)가 뭐죠?

```jsx
1. 감시(Spy):

		감시(Spy)는 "이 메서드가 어떻게 호출되었는지 확인"하는 도구예요.

		메서드가 몇 번 호출되었는지, 어떤 값을 사용했는지, 결과는 무엇인지 추적할 수 있어요.

2. 모의(Mock):

		모의(Mock)는 "진짜 메서드처럼 보이지만, 실제로는 우리가 정한 방식대로 동작하는 가짜"예요.

		진짜 메서드를 쓰지 않고 우리가 원하는 값이나 행동을 대신 실행해요.

		예) "이 함수가 호출되면 무조건 사용자 정보를 반환해!"라고 지정하면,

			  데이터베이스 없이도 테스트를 실행할 수 있어요.

			  jest.spyOn(authService, 'getUserByUsernameOrEamil').mockResolvedValue({
				  username: 'testUser',
				  email: 'test@example.com'
				});


				jest.spyOn: getUserByUsernameOrEmail 함수를 감시합니다.

				mockResolvedValue: 이 함수가 호출될 때 "결과를 진짜 계산하지 말고,

													 username: testUser, email: test@example.com 값을 반환해!"라고 지정합니다.
```

```jsx
mockImplementation: 함수 자체의 구현을 직접 제공합니다.
```


## `mockImplementation`과 `mockResolvedValue`를 쉽게 설명

### `mockImplementation`이란?

```jsx
1. mockImplementation이란?

한마디로:

		"이 함수가 호출되면 내가 직접 짠 코드를 실행해!"

언제 사용하나요?

		함수가 어떤 방식으로 작동해야 할지 직접 정의하고 싶을 때 사용해요.

		예를 들어, 호출할 때마다 다른 결과를 반환하거나, 복잡한 로직을 테스트해야 할 때 유용해요.
```

```jsx
// 어떤 함수를 만들었다고 가정
const calculate = jest.fn()

// 이 함수가 호출되면 10 + 20을 계산하게 만들고 싶어요
calculate.mockImplementation(() => 10 + 20)

console.log(calculate()) // 30 출력
```

```jsx
`mockImplementation은 함수가 호출될 때 내가 정한 동작을 실행하게 합니다.

위의 경우, calculate라는 가짜 함수가 호출되면 10 + 20을 계산해서 30을 반환하도록 만든 거예요.
```

### `mockResolvedValue`란?

```jsx
한마디로:

		"이 함수가 호출되면 항상 Promise로 내가 준 값을 반환해!"

언제 사용하나요?

		비동기 함수를 테스트할 때 사용해요.

		보통 async 함수나 Promise를 반환하는 API 호출 같은 것들에 사용합니다.
```

```jsx
// 비동기 함수가 있다고 가정
const fetchData = jest.fn()

// 이 함수가 호출되면 항상 'Hello, World!'를 Promise로 반환하게 만들어요
fetchData.mockResolvedValue('Hello, World!')

fetchData().then((data) => {
  console.log(data) // 'Hello, World!' 출력
})
```

```jsx
비동기 함수는 일반적으로 데이터를 받아오는 데 시간이 걸리지만,

mockResolvedValue를 쓰면 항상 동일한 결과를 즉시 반환하도록 만들 수 있어요.

위의 경우, fetchData 함수는 호출될 때마다 "Hello, World!"를 Promise로 감싸서 반환해요.
```

### 요약

```jsx
mockImplementation: "이 함수는 이렇게 작동해야 해!" → 동작을 직접 구현.

mockResolvedValue: "이 함수는 항상 이 값을 Promise로 줄 거야!" → 비동기 함수의 결과를 간단히 설정.
```

# { Jest Hooks: 테스트를 깨끗하게 유지하는 방법 }

```jsx
Hooks (후크)

		Jest에서 제공하는 **beforeEach**와 afterEach 같은 후크를 사용하면

		테스트가 실행되기 전이나 후에 특정 작업을 자동으로 수행할 수 있습니다.

		beforeEach: 각 테스트가 실행되기 전에 공통적으로 실행할 작업을 정의합니다.

		afterEach: 각 테스트가 종료된 후 실행할 작업을 정의합니다.

Timers (타이머)

		자바스크립트의 setTimeout이나 setInterval 같은 타이머 함수의 동작을 테스트 환경에서 관리하기 쉽게 만들어줍니다.

		jest.useFakeTimers()를 사용하여 실제 타이머를 가짜 타이머로 대체합니다.

		이를 통해 테스트에서 시간에 의존하는 코드를 더 쉽게 다룰 수 있습니다.

		jest.clearAllTimers()는 모든 타이머를 정리합니다.

Mocks 관리 (Reset and Clear)

		테스트 중에는 모킹된 함수나 타이머가 남아 있을 수 있으므로,

		**jest.resetAllMocks()**와 **jest.clearAllMocks()**를 사용해 테스트 간 상태를 초기화합니다.

		이러한 초기화를 통해 테스트 간 간섭(interference)을 방지할 수 있습니다.
```

```jsx
jest.useFakeTimers();
jest.mock('@service/queues/base.queue');
jest.mock('@service/redis/user.cache');
jest.mock('@service/queues/user.queue');
jest.mock('@service/queues/auth.queue');
jest.mock('@global/helpers/cloudinary-upload');

describe('SignUp', () => {
  beforeEach(() => {
    jest.resetAllMocks();
  });

  afterEach(() => {
    jest.clearAllMocks();
    jest.clearAllTimers();
  });

  it('should throw an error if username is not available', () => {
    const req: Request = authMockRequest({}, {
      username: '',
      email: 'many@test.com',
      password: 'qwerty',
      avatarColor: 'red',
      avatarImage: 'data:text/dfjakejrk341;base64'
    }) as Request;
    const res: Response = authMockResponse();

    SignUp.prototype.create(req, res).catch((error: CustomError) => {
      expect(error.statusCode).toEqual(400);
      expect(error.serializeErrors().message).toEqual('Username is a required field');
    });
  });
```
