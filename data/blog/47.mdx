- 인터페이스도 메소드 재정의와 타입 변환이 되므로 다형성을 구현할 수 있다.
- 인터페이스 사용 방법은 동일하지만 구현 객체를 교체하여 프로그램 실행 결과를 다양화

```java
[프로그램]
I i = new A();// i 에 어떤 객체가 들어가는지에 따라서
I i = new B();

i.method1(); // 메소드의 실행이 달라진다
i.method2();

inter face I {
	void method1(); // 인터페이스 I 뒤에 어떤 객체가 있는냐에 따라서 (A,B) 다양한 실행결과를
	void method2(); // 얻을 수 있다.
}
```

- 부모가 어떤 인터페이스를 구현하고 있다면 자식 구현 클래스 또한 대입 될 수 있다.
- 구현 객체와 자식 객체는 인터페이스 타입으로 자동 타입 변환 된다.

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381039/notion-blog/_/JAVA/_/47_/Untitled_2.png)

- 인터페이스로 선언된 필드(Tire forntLeftTire = new HankookTire) 에는 다양한 구현 객체가 대입 될 수 있다. 그렇게 됨으로서 해서 인터페이스의 메소드를 호출할 경우 다양한 실행 결과가 나올 수 있다.

```java
// 예전 강의 에서는 타이어가 클래스 타입 이였는데(또는 추상 클래스 타입) 이번에는 인터페이스
// 타입

public class Car {
	Tire frontLeftTire = new HankookTire();  // 인터페이스는 생성자를 만들지 못하기 때문에
	Tire frontRightTire = new HankookTire(); // HankookTire 구현 객체를 대입해둠
	Tire backLeftTire = new HankookTire();
	Tire backRightTire = new HankookTire();

void run() {
	frontLeftTire.roll(); // 구현객체의 roll 을 호출하게됨 ( HankookTire)
	frontRightTire.roll();
	backLeftTire.roll();
	backRightTire.roll();
}

Car myCar = new Car();
myCar.frontLeftTire = new KumhoTire(); // 이렇게 필드에 다른 구현객체가 대입되면 roll 또한
myCar.frontRightTire = new KumhoTire();// kumhoTire 의 메소드가 실행된다.(필드의 다형성)
```

## 매개변수의 다형성

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381041/notion-blog/_/JAVA/_/47_/Untitled_9.png)

```java
public interface Vehicle { //인터페이스 run 메소드 구현
	public void run();
}

public class Driver {
	public void drive(Vehicle vehicle) { // 메소드의 매개변수 타입으로 사용
		vehicle.run();                     // 매개값으로 구현 객체를 사용할 수 있다.
	}                                    // 그에 따른 구현 객체의 run 이 실행
}
```

## 강제 타입 변환

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381038/notion-blog/_/JAVA/_/47_/Untitled_15.png)

```java
문법 : 구현클래스 변수 = (구현클래스) 인터페이스 변수;

       Bus bus = (Bus) vehicle; //강제 타입 변환
```

- 구현 객체가 인터페이스 타입으로 자동 변환하면 인터페이스에 선언된 메소드만 사용 가능하다.
- 이때 구현 클래스에만 선언된 필드나 메소드를 사용하고 싶을 경우 강제 타입 변환을 사용한다. (예전 상속 에서 하던 강제 타입 변환이랑 비슷하다.

```java
RemoteControl // 인터페이스
turnOn();
turnOff();
setVolum(int volume);

Television
//호출 가능 RemoteControl 에 있으니까
turnOn() {...}
turnOff() {...}
setVolume(int volume);
//RemoteControl 에 없기 때문에 사용불가
setTime() {...}
record() {...}

```

```java
interface Vehicle {
	void run();
}

//Vehicle 구현 클래스
class bus implements Vehicle {
	void run() {...};
	void checkFare() {...};
}

Vehicle vehicle = new Bus();

vehicle.run(); //가능
vehicle.checkFare(); //불가능 (Vehicle 에 없으니까)

Bus bus = (Bus) vehicle; // 강제 타입 변환

bus.run(); //가능 Bus에 있으니까
bus.checkFare(); //가능 Bus 에 있으니까
```

## 객체 타입 확인 instanceof

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381038/notion-blog/_/JAVA/_/47_/Untitled_16.png)

- 상속 파트의 타입 변형과 비슷하다
- instanceof 를 사용하여 구현 객체가 변환되어 있는지 확인한다.

```java
Vehicle vehicle = new Taxi();
Bus bus = (Bus) vehicle; //ClassCastException 발생 (vehicle 에는 Taxi 객체가)

public void drive(Vehicle vehicle) {
	Bus bus = (Bus) vehicle;
	bus.checkFare();

// instanceof 연산자로 확인 후 안전하게 강제 타입 변환

public class Driver
	public void drive(Vehicle vehicle) { // bus ,taxi 구현객체 대입 가능하다
		if(vehicle instanceof Bus) { //vehicle 이 참조하는 객체가 Bus인지 확인
			Bus bus = (Bus) vehicle; //Bus 객체일 경우 강제 변환
			bus.chekFare(); // Bus 의 메소드 사용
	}
		vehicle.run(); // 아닐경우 그냥 run 메소드 호출 사용
}
```

## 인터페이스 상속

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381038/notion-blog/_/JAVA/_/47_/Untitled_17.png)

```java
문법 : public interface 하위인터페이스 extends 상위 인터페이스1, 상위인터페이스2 {...}
```

- 자바의 클래스는 단일 상속만 가능하지만 인터페이스는 다중 상속이 가능하다.

```java

 public interface InterfaceC extends InterfaceA, InterfaceB
// 인터페이스 C를 구현한 클래스를 만들때 인터페이스 A 와 B의 메소드도 재정의 해줘야 한다.

// 구현 클래스는 A,B,C로 타입변환 가능하다.
하위(Interface C)인터페이스 변수 = new 구현클래스(...);
상위(A)인터페이스1 변수 = new 구현클래스(...);
상위(B)인터페이스2 변수 = new 구현클래스(...);
```

```java
public class ImplementationC implements InterfaceC {

ImplementationC impl = new ImplementationC();

InterfaceC ic = impl;

InterfaceA ia = impl;

InterfaceB ib = impl;

// 인터페이스 C 로 구현객체를 만들었고
// 구현클래스로 구현 객체를 만들고 나서 그 구현객체를 인터페이스 A,B,C 모두 대입 가능하다
```
