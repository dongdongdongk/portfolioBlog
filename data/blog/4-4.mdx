## 1. UI 캔버스 개념 이해하기

- **캔버스(Canvas)**: UI 요소를 표시하기 위한 컨테이너.
- **Scene 뷰에서 F 키**: 선택한 UI 요소에 포커스하면, **16:9 비율의 흰 직사각형**이 나타남 → 게임 뷰의 화면 비율을 시각적으로 보여줌.
- **Screen Space - Overlay 모드**:
  - UI가 화면 공간에 직접 렌더링됨.
  - z축 값은 의미가 거의 없음 → 3D 오브젝트처럼 깊이 이동 불필요.

---

## 2. TextMeshPro(TMP) 요소 생성하기

- 계층 구조(Hierarchy)에서 `UI → Text - TextMeshPro` 생성.
- 프로젝트에서 처음 TMP를 쓸 경우 → **TMP Essentials 리소스** 가져오기 팝업 등장.
  - Essentials(필수) + Extras(선택, 추가 폰트 제공).
  - 팝업이 안 뜨면 메뉴 → `Window > TextMeshPro > Import TMP Essential Resources` 선택.
- 새 TMP 텍스트 생성 후 이름을 `Scoreboard Text`로 변경.

## 3. RectTransform, 앵커, 피봇 설정하기

- UI 요소는 모두 `RectTransform` 컴포넌트를 가짐.
  → 일반 오브젝트의 `Transform`과 다르게, **UI 전용 좌표계**를 사용함.
  → 위치, 크기, 회전뿐 아니라 **앵커(Anchor)와 피봇(Pivot)** 개념이 추가됨.

---

### 📌 앵커(Anchor)

- **부모(Canvas나 Panel 등)** 기준으로 **UI가 고정되는 위치**를 의미.
- 기본값은 중앙에 고정되어 있음 → 화면 크기가 변하면 상대적으로 움직일 수 있음.
- 예시:
  - Scoreboard Text의 앵커를 `왼쪽 상단`으로 설정 → 해상도가 변해도 항상 왼쪽 상단에 위치.
  - 미니맵 아이콘의 앵커를 `오른쪽 하단`으로 설정 → 화면 크기와 상관없이 오른쪽 하단에 붙음.

---

### 📌 피봇(Pivot)

- **UI 요소의 중심점**을 의미 (회전, 스케일, 위치 이동의 기준점).
- 기본값은 (0.5, 0.5) → 즉, 정가운데.
- 예시:
  - 피봇이 (0,0) → 왼쪽 아래 모서리를 기준으로 크기 조절/회전.
  - 피봇이 (1,1) → 오른쪽 위 모서리를 기준으로 크기 조절/회전.

---

### 📌 단축키

- `Alt` : **앵커 + 위치** 이동 (현재 위치를 기준으로 앵커 설정).
- `Shift` : **피봇**만 변경.
- `Shift + Alt` : **피봇 + 위치** 동시에 변경 (가장 많이 쓰임).

---

### 🛠 실습

1. **Scoreboard Text** 오브젝트 선택.
2. `RectTransform`의 **앵커 프리셋(Anchor Presets)** 버튼 클릭.
   - (작은 사각형 버튼, 씬 뷰의 "사각형 아이콘")
3. 프리셋 중 **왼쪽 상단** 선택.
4. **Shift + Alt** 누른 상태에서 클릭.
   - → 피봇과 앵커가 동시에 왼쪽 상단으로 고정됨.
   - → Scoreboard Text는 어떤 해상도에서도 항상 왼쪽 상단에 위치하게 됨.

---

✅ **정리**

- 앵커 = 부모 기준 **고정 위치**.
- 피봇 = UI 요소 자체의 **중심점**.
- **Shift + Alt** 조합 → “해상도 변해도 흔들리지 않는 UI”의 핵심!

## 5. TMP 텍스트 옵션 조정하기

- **Text 입력값**: `00000` (플레이스 홀더 → 자리 확보용)
  → 나중에는 `0` 하나만 남김 (자리수 변화 시 보기 깔끔).
- **Font Asset**: Roboto (프로젝트 테마와 어울림).
- **Font Size**: 약 100.
- **Wrapping Mode**:
  - Normal(기본) → 줄바꿈 발생.
  - No Wrap → 줄바꿈 없음 (또는 RectTransform 크기 늘려 해결).
- **Vertex Color**: 색상 스포이드로 프로젝트 테마 컬러 매칭.
- **Underlay(드롭 섀도우)**:
  - 체크 활성화 → 알파값/오프셋 조절.
  - 가독성 및 시각적 강조 효과 제공.

## 6. Scoreboard 스크립트 구현하기

```csharp
using UnityEngine;
using TMPro;

public class Scoreboard : MonoBehaviour
{
    [SerializeField] TMP_Text scoreboardText;
    int score = 0;

    public void IncreaseScore(int amount)
    {
        score = score + amount;
        scoreboardText.text = score.ToString();
    }
}
```

- **핵심 포인트**:
  - `TMP_Text` 타입을 사용하려면 `using TMPro;` 필요.
  - Inspector에서 `Scoreboard Text`를 드래그해 `scoreboardText` 필드에 연결.
  - `score.ToString()` : `int` → `string` 변환 필수 (`scoreboardText.text`는 문자열만 받음).

## 7. 버그 및 문제 해결 팁

- **TMP SubMeshUI 자식 오브젝트 생성**: 필요 없는 경우 삭제 가능.
- **NullReferenceException 발생**: `scoreboardText`에 텍스트 컴포넌트가 연결되지 않은 경우.
- **줄바꿈 문제**: No Wrap 설정 또는 RectTransform 크기 확장으로 해결.

## 1. 타임라인과 컨트롤 트랙 개념 이해하기

- **Timeline** : 애니메이션, 이벤트, 오브젝트 활성화/비활성화를 시간축 기반으로 제어하는 도구.
- **Playable Asset (.playable)** : 타임라인 데이터를 담는 파일.
- **Control Track** : 다른 타임라인이나 오브젝트의 동작을 제어하는 트랙.
  - 마스터 타임라인이 서브 타임라인을 제어할 수 있음 → “타임라인 인셉션(Timeline Inception)”
  - 특정 구간에서 오브젝트 활성화/비활성화도 자동 처리 가능.

## 2. 마스터 타임라인과 서브 타임라인 구성하기

1. **마스터 타임라인**
   - 현재 장면(Scene)에 존재하는 최상위 타임라인.
   - 적 웨이브를 관리하는 중심이 됨.
2. **서브 타임라인 생성**
   - 계층 구조에서 **빈 게임 오브젝트(Timeline Holder)** 생성 → 마스터 타임라인 배치.
   - 또 다른 빈 오브젝트 생성 → 이름을 `Enemy Waves`로 지정 (적 웨이브 관리용).
3. **기존 적 오브젝트 정리**
   - 테스트용 적 오브젝트들(`Enemy 1,2,3,4,5`)과 `Enemies` 부모 오브젝트는 삭제 → 계층 구조 정리.

## 3. 첫 번째 웨이브(Three Butterflies) 만들기

1. **프리팹 배치**
   - `Prefabs → Ships` 폴더에서 **Butterfly Ship** 프리팹을 드래그.
   - 플레이어 앞쪽, 산 주변에서 등장하도록 배치.
2. **스케일 조정**
   - 나비가 너무 작으면, **부모 오브젝트**를 직접 스케일 업 → 콜라이더도 함께 확대됨.
   - 모델 스케일은 `1,1,1` 유지.
   - 이 상태를 다시 프리팹에 적용하여 모든 나비 크기를 통일.
3. **웨이브 그룹 생성**
   - `Enemy Waves` 오브젝트 아래에 빈 오브젝트 생성 → `Three Butterflies`라고 이름 지정.
   - 나비 프리팹을 `Three Butterflies` 안에 넣고, 3개 복제.
   - 각각의 나비 위치를 약간 다르게 배치 → 자연스럽게 날아오는 편대 느낌.

## 4. 웨이브 애니메이션 녹화하기

1. **새로운 타임라인 생성**
   - `Assets → Timelines` 폴더에 `Three Butterflies Timeline` 생성.
   - `Three Butterflies` 오브젝트를 선택한 상태에서 타임라인 열기.
2. **애니메이션 트랙 추가**
   - 세 마리 나비를 모두 선택 → 타임라인에 드래그.
   - 각 나비별 **애니메이션 트랙**이 자동 생성됨.
3. **키프레임 애니메이션 설정**
   - 시작 지점 (0초) → 위치 A (언덕 근처).
   - 종료 지점 (7~8초) → 위치 B (멀리 사라지는 지점).
   - 중간 지점(3~4초)에 변화를 추가 →
     - 나비1 : 아래로 이동
     - 나비2 : 앞쪽으로 이동
     - 나비3 : 위로 이동
   - → 유기적이고 자연스러운 웨이브 비행 경로 완성.

## 1. 타임라인 시그널 개념 이해하기

- **타임라인 신호(Timeline Signal)** : 타임라인에서 특정 지점에 도달했을 때 이벤트를 발생시키는 시스템.
- 신호를 제대로 활용하려면 세 가지 요소가 필요합니다:
  1. **Signal Emitter (방출기)**
     - 신호를 내보내는 역할.
     - 타임라인 상에서는 **마커(Marker)** 형태로 표현됨.
     - 특정 위치에 배치하여 “여기서 이벤트 실행!”을 지정.
  2. **Signal Receiver (수신기)**
     - 신호를 받아서 **어떤 동작을 실행할지 정의**하는 컴포넌트.
     - UnityEvent 리스트를 가지고 있어, 여기서 원하는 함수 호출 가능.
  3. **Signal Asset (에셋)**
     - 방출기와 수신기를 연결해주는 데이터 자원.
     - 한 번 만들어두면 여러 타임라인에서 재사용 가능.

## 3. Dialogue Lines 스크립트 작성하기

### ✅ 스크립트 생성 및 구조

- `DialogueLines.cs` 라는 새 MonoBehaviour 스크립트 생성.
- 빈 오브젝트 **Manager > Dialogue** 에 부착.

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380427/notion-blog/_/3D_/3D_/_4_-_4/image_16.png)

### ✅ 핵심 코드

```csharp
using UnityEngine;
using TMPro;

public class DialogueLines : MonoBehaviour
{
    [SerializeField] TMP_Text dialogueText;   // UI 텍스트 참조
    [SerializeField] string[] timelineTextLines; // 인스펙터에서 입력할 대화 문자열 배열

    int currentLine = 0; // 현재 표시 중인 대사 인덱스

    // 타임라인 신호에 의해 호출될 함수
    public void NextDialogueLine()
    {
        // 다음 줄로 이동
        dialogueText.text = timelineTextLines[currentLine];
        currentLine++;
    }
}
```

### ✅ 인스펙터에서 설정

- `timelineTextLines` 배열에 **8개의 음성 라인 텍스트**를 입력.
- `dialogueText` 필드에는 UI 캔버스의 Dialogue Text 오브젝트를 드래그 앤 드롭.

## 6. 실행 및 테스트

- Timeline 재생만으로는 Signal이 작동하지 않음 → 반드시 **Play Mode에서 실행**해야 이벤트가 발생.
- 오디오 음성 라인과 동일한 타이밍에 텍스트가 업데이트되는지 확인.
- 모든 대사(8줄)가 올바른 타이밍에 전환되면 성공.

---

# ✅ 최종 정리

- **Signal** = 타임라인에서 이벤트를 발생시키는 시스템.
- UI 캔버스에 **하단 텍스트 영역**을 배치 → TextMeshPro 활용.
- **DialogueLines 스크립트**에서 문자열 배열 + public 메서드(`NextDialogueLine`)로 관리.
- **Signal Asset** + **Signal Receiver** + **Signal Emitter**를 연결해 타임라인에서 호출.
- Signal Track을 쓰면 구조적으로 더 깔끔.
- 반드시 Play 모드에서 테스트해야 정상 동작.

# 💡 쉽게 이해하는 원리와 동작 순서

---

## 1️⃣ 오디오(음성)와 텍스트가 따로 있음

- 게임에는 **음성 대사(오디오 파일)** 가 있고,
- 같은 내용을 **글자로 보여줄 텍스트(UI)** 가 있음.

👉 하지만 Unity는 자동으로 “음성 나오면 텍스트도 바꿔줘!” 라고 해주지 않음.

👉 그래서 **타임라인 신호(Signal)** 를 써서 두 개를 맞춰주는 거예요.

---

## 2️⃣ 신호(Signal)란?

- **타임라인 위에서 “여기!” 하고 알려주는 마커(표식)** 같은 것.
- 예: 타임라인이 5초 지점에 오면 신호를 발사 → “다음 텍스트 보여줘!”

---

## 3️⃣ 신호의 3가지 요소

1. **방출기 (Emitter)** : 신호를 내보내는 역할.

   → 타임라인에 “이 시점에서 신호 발사!”라고 표시하는 마커.

2. **수신기 (Receiver)** : 신호를 받으면 무언가 실행하는 역할.

   → “신호 받았네? 그럼 텍스트를 다음 줄로 바꿔야지.”

3. **신호 에셋 (Signal Asset)** : 방출기와 수신기를 연결해주는 다리.

👉 쉽게 말해 **벨 누르는 사람(Emitter) → 초인종 소리(Asset) → 문 열어주는 사람(Receiver)** 구조예요.

---

## 4️⃣ DialogueLines 스크립트의 역할

- 신호가 왔을 때 실행할 “문 열기 동작”을 코드로 만든 거예요.

```csharp
public void NextDialogueLine() {
   dialogueText.text = timelineTextLines[currentLine];
   currentLine++;
}
```

순서:

1. 배열(`timelineTextLines[]`)에 여러 줄의 대사를 저장해둠.
   - 예:
     - 0번: "여기 와 주셔서 감사합니다, 중위님"
     - 1번: "정말로 도움이 필요합니다"
     - 2번: "함정입니다" ...
2. 신호가 오면 → `NextDialogueLine()` 실행.
3. 배열에서 `현재 줄(currentLine)`을 가져와 텍스트 UI에 넣음.
4. 줄 번호(`currentLine`)를 1 증가시킴.

   → 다음 신호 때는 다음 줄이 출력됨.

---

## 5️⃣ 실제 동작 흐름 예시

👉 플레이어가 게임을 실행하면…

1. **0초**
   - 오디오: "여기 와 주셔서 감사합니다, 중위님"
   - 신호 발생 → 텍스트: "여기 와 주셔서 감사합니다, 중위님"

3. **10초**
   - 오디오: "함정입니다"
   - 신호 발생 → 텍스트: "함정입니다"

👉 이런 식으로 **오디오 타이밍에 맞춰 텍스트가 한 줄씩 바뀌는 것**이에요.

## 1. 초상화 카메라 개념 이해하기

- **목적**
  - 플레이어의 실제 게임 화면은 3인칭/1인칭 시점에서 보여지지만,
    동시에 캐릭터의 얼굴이나 특정 부분을 **UI(예: 초상화, 미니맵, 장비 화면)**에 따로 보여주고 싶을 때 사용한다.
  - 예를 들어, RPG 게임에서 **대화창 옆에 캐릭터 얼굴이 표시**되거나,
    FPS 게임에서 **무기 스코프 화면**이 따로 UI에 표시되는 것도 같은 원리이다.

---

- **방법**
  1. **별도의 카메라 생성하기**
     - 게임의 메인 카메라와는 다른 **전용 카메라**를 만든다.
     - 이 카메라는 **오직 캐릭터의 얼굴(또는 원하는 부분)**만 비춘다.
     - 카메라 위치를 캐릭터 정면 가까이에 두고, 필요하다면 전용 레이어를 지정해서 **원하는 오브젝트만 보이게 설정**한다.
  2. **Render Texture 사용하기**
     - 일반적으로 카메라가 보는 화면은 **모니터(게임 화면)**에 출력되지만,
       Unity에서는 이 출력 결과를 **파일처럼 저장 가능한 텍스처(Render Texture)**로 받을 수 있다.
     - **Render Texture란?**
       - 말 그대로 카메라가 찍은 화면을 **“실시간으로 그려주는 그림(텍스처)”**이다.
       - 보통 2D 스프라이트나 사진은 **고정된 이미지(Texture2D)**인데,
         Render Texture는 **카메라 시점이 변하면 그 즉시 갱신되는 영상**을 텍스처처럼 다룰 수 있다.
       - 즉, **움직이는 영상도 하나의 텍스처로 취급**할 수 있어서 UI나 3D 오브젝트에 붙일 수 있다.
       - 예시:
         - 캐릭터 초상화
         - CCTV 화면
         - 미니맵 (전용 카메라 + Render Texture)
         - 스코프 화면
     - Render Texture의 속성
       - **해상도**: 초상화가 흐릿하지 않게 적당한 크기(예: 512x512)로 설정.
       - **포맷**: 색상, 깊이 버퍼 등을 지원. (일반적으로 기본값 사용해도 무방)
       - **갱신 방식**: 카메라가 Render Texture를 대상으로 렌더링할 때마다 자동으로 업데이트됨.
  3. **UI에 표시하기 (Raw Image)**
     - UI 캔버스에 `Raw Image` 컴포넌트를 추가한다.
     - `Raw Image`는 일반 `Image`와 달리 **실시간 텍스처(Render Texture)** 같은 동적인 그림도 표시 가능하다.
     - Render Texture를 `Raw Image`의 `Texture` 슬롯에 넣으면,
       카메라가 비춘 캐릭터 얼굴이 UI에 실시간으로 출력된다.

---

👉 요약하면,

- 메인 카메라 = 플레이어 전체 화면
- 초상화 카메라 = 캐릭터 얼굴만 전용으로 촬영
- Render Texture = 촬영된 영상을 텍스처처럼 저장
- Raw Image = UI에서 그 텍스처를 출력

## Render Texture vs Raw Image

### 1. **Render Texture**

- **정의**: 카메라가 찍은 화면을 저장하는 **특수한 텍스처(영상 저장소)**
- **역할**: **카메라 출력물**을 담는 그릇
- **특징**:
  - 스스로는 보이지 않는다 (UI나 게임 화면에 직접 표시되지 않음).
  - 다른 오브젝트가 이 텍스처를 “참조”해야만 보인다.
  - 실시간으로 계속 갱신된다 → 움직이는 화면도 저장 가능.
- **비유**:
  - 카메라가 찍은 영상을 **USB 메모리**에 기록해 둔 것.
  - 혼자서는 보이지 않고, TV나 모니터에 연결해야 화면이 나온다.

---

### 2. **Raw Image**

- **정의**: UI에서 텍스처를 그대로 보여주는 **UI 컴포넌트**
- **역할**: **텍스처 소비자(화면 출력 장치)**
- **특징**:
  - `Texture` 슬롯에 넣은 텍스처(Render Texture, 일반 이미지 등)를 UI로 표시한다.
  - Unity UI(Canvas) 위에 뜨기 때문에 항상 화면에 보인다.
  - Render Texture 외에도 PNG, JPG 같은 **고정 이미지(Texture2D)**도 넣을 수 있다.
- **비유**:
  - USB에 저장된 영상을 TV 화면에 띄워주는 **모니터**.
  - 스스로 영상을 만들지 않고, 그냥 받은 걸 보여주는 역할.

---

### 3. **정리**

- Render Texture = **카메라 영상 저장소 (Producer)**
- Raw Image = **저장된 영상을 보여주는 UI 컴포넌트 (Consumer)**

---

👉 그래서 **둘은 세트처럼 움직여요**:

카메라 → Render Texture (저장) → Raw Image (표시)

## 7. 타임라인에서 초상화 제어하기

- **초상화 활성/비활성 전환**을 Timeline에서 제어.
- 방법:
  1. 계층 구조에서 초상화 GameObject 기본값을 **비활성화**.
  2. Timeline에서 **Control Track** 추가.
  3. Raw Image 오브젝트를 드래그 → 특정 대사(Voice Line)와 동기화.
- 여러 캐릭터(예: `General Kcir`)도 같은 방식으로 **카메라 + Render Texture + Raw Image**를 복제하여 설정 가능.

## 8. 해상도와 겹침 문제 해결하기

1. **텍스트 겹침 문제**
   - 대화 텍스트를 **Portrait 옆으로 이동**.
   - 앵커를 오른쪽 정렬.
   - 글꼴 크기 조정 (`44` 정도).
2. **저해상도 문제**
   - Render Texture 기본 크기: `256x256`.
   - 더 선명하게 하려면: `512x512` 이상으로 변경.
   - 단, 성능에 영향 있음 → 상황에 맞게 조정.
