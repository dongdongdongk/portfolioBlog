## 게시글 스키마 작성

```jsx
import mongoose, { model, Model, Schema } from 'mongoose';
import { IPostDocument } from '@post/interfaces/post.interface';

/**
 * `postSchema`는 MongoDB의 데이터 구조를 정의하는 청사진입니다.
 * 이 스키마는 'Post'라는 컬렉션에 저장될 데이터를 설명합니다.
 * 각각의 필드는 게시물(Post)의 속성을 나타냅니다.
 */

const postSchema: Schema = new Schema({
  // 게시물을 작성한 사용자의 고유 ID.
  // MongoDB의 ObjectId로 저장되며, 'User' 컬렉션의 문서를 참조(ref)합니다.
  // `index: true`는 검색 성능을 높이기 위해 인덱스를 생성합니다.
  userId: { type: mongoose.Schema.Types.ObjectId, ref: 'User', index: true },

  // 게시물을 작성한 사용자의 이름.
  // 단순한 문자열로 저장됩니다.
  username: { type: String },

  // 게시물을 작성한 사용자의 이메일 주소.
  // 단순한 문자열로 저장됩니다.
  email: { type: String },

  // 사용자의 아바타(프로필 이미지) 색상.
  // 사용자 맞춤화를 위해 사용할 수 있습니다.
  avatarColor: { type: String },

  // 사용자의 프로필 사진 URL.
  // 외부 스토리지 서비스에 저장된 프로필 사진 경로를 저장합니다.
  profilePicture: { type: String },

  // 게시물 내용(텍스트).
  // 사용자가 작성한 게시물의 본문을 저장합니다.
  // 기본값은 빈 문자열(`''`)입니다.
  post: { type: String, default: '' },

  // 게시물의 배경색.
  // 사용자가 게시물의 배경색을 지정하면 저장됩니다.
  bgColor: { type: String, default: '' },

  // 게시물에 첨부된 이미지의 버전 정보.
  // 이미지 업로드 시스템에서 사용될 수 있습니다.
  imgVersion: { type: String, default: '' },

  // 게시물에 첨부된 이미지의 고유 ID.
  // 이미지 업로드 시스템에서 파일을 식별하는 데 사용됩니다.
  imgId: { type: String, default: '' },

  // 사용자가 게시물에 추가한 감정(예: "행복", "슬픔" 등).
  // 감정을 문자열로 저장합니다.
  feelings: { type: String, default: '' },

  // 게시물에 포함된 GIF 이미지 URL.
  // 사용자가 게시물에 추가한 GIF 이미지의 경로를 저장합니다.
  gifUrl: { type: String, default: '' },

  // 게시물의 공개 범위(예: "공개", "비공개").
  // 게시물의 접근 권한을 설정합니다.
  privacy: { type: String, default: '' },

  // 게시물에 달린 댓글의 수.
  // 댓글의 개수를 숫자로 저장하며, 기본값은 0입니다.
  commentsCount: { type: Number, default: 0 },

  // 게시물에 대한 반응(리액션) 정보.
  // 리액션 종류별(좋아요, 사랑해요, 기뻐요 등)로 카운트를 저장합니다.
  reactions: {
    like: { type: Number, default: 0 }, // '좋아요' 수
    love: { type: Number, default: 0 }, // '사랑해요' 수
    happy: { type: Number, default: 0 }, // '기뻐요' 수
    wow: { type: Number, default: 0 }, // '놀라워요' 수
    sad: { type: Number, default: 0 }, // '슬퍼요' 수
    angry: { type: Number, default: 0 } // '화나요' 수
  },

  // 게시물이 생성된 날짜 및 시간.
  // MongoDB에 저장될 때 자동으로 현재 날짜와 시간으로 설정됩니다.
  createdAt: { type: Date, default: Date.now }
});

// `PostModel`은 MongoDB와 상호작용할 수 있는 모델을 생성합니다.
// 'Post'라는 이름의 컬렉션을 사용하고, `IPostDocument` 인터페이스를 기반으로 타입을 정의합니다.
// 첫 번째 매개변수 'Post': 모델 이름.
// 두 번째 매개변수 postSchema: 데이터 구조를 정의하는 스키마.
// 세 번째 매개변수 'Post': 컬렉션 이름을 'Post'로 강제.
const PostModel: Model<IPostDocument> = model<IPostDocument>('Post', postSchema, 'Post');

// PostModel을 외부에서 사용할 수 있도록 내보냅니다.
export { PostModel };

```

## 인덱스(Index)란?

```jsx
인덱스의 개념

		인덱스는 데이터베이스에서 특정 컬럼에 대한 검색 속도를 향상시키기 위해 사용하는 구조입니다.

		인덱스를 설정하면, 해당 필드를 기준으로 데이터를 빠르게 검색할 수 있습니다.

장점

		검색 속도 향상: 대량의 데이터에서도 빠르게 결과 반환.

단점

		저장 공간 증가: 인덱스를 유지하기 위해 추가적인 저장 공간 필요.

		쓰기 작업 속도 저하: 데이터가 추가되거나 변경될 때 인덱스를 업데이트해야 하므로 속도가 느려질 수 있음.

사용 시 주의사항

		인덱스는 자주 검색되는 필드에만 설정해야 함.

		불필요한 인덱스는 쿼리 속도를 느리게 만들 수 있음.
```

### 인덱스 예시

```jsx
예제 코드: userId 인덱스 설정

적용 시점

특정 사용자의 모든 게시글을 검색할 때 사용:
```


## `postSchema` 설명

```jsx
const postSchema: ObjectSchema = Joi.object().keys({
  post: Joi.string().optional().allow(null, ''),
  bgColor: Joi.string().optional().allow(null, ''),
  privacy: Joi.string().optional().allow(null, ''),
  feelings: Joi.string().optional().allow(null, ''),
  gifUrl: Joi.string().optional().allow(null, ''),
  profilePicture: Joi.string().optional().allow(null, ''),
  imgVersion: Joi.string().optional().allow(null, ''),
  imgId: Joi.string().optional().allow(null, ''),
  image: Joi.string().optional().allow(null, '')
});

```

```jsx
Joi.object().keys(): 객체의 구조를 정의합니다.

Joi.string().optional(): 문자열이며 필수 항목이 아님을 나타냅니다.

.allow(null, ''): null 값이나 빈 문자열도 허용됩니다.

예를 들어, 사용자가 post를 빈 문자열이나 null로 보낸 경우, 에러 없이 서버에서 허용합니다.
```

## `postWithImageSchema` 설명

```jsx
const postWithImageSchema: ObjectSchema = Joi.object().keys({
  image: Joi.string().required().messages({
    'any.required': 'Image is a required field',
    'string.empty': 'Image property is not allowed to be empty'
  }),
  post: Joi.string().optional().allow(null, ''),
  bgColor: Joi.string().optional().allow(null, ''),
  privacy: Joi.string().optional().allow(null, ''),
  feelings: Joi.string().optional().allow(null, ''),
  gifUrl: Joi.string().optional().allow(null, ''),
  profilePicture: Joi.string().optional().allow(null, ''),
  imgVersion: Joi.string().optional().allow(null, ''),
  imgId: Joi.string().optional().allow(null, '')
});

```

```jsx
image: 필수 항목입니다. 사용자가 이미지를 보내지 않으면 에러 메시지를 반환합니다.

'any.required': 이미지가 없을 때 반환할 메시지.

'string.empty': 이미지가 빈 문자열일 때 반환할 메시지.

이 스키마를 사용해 게시물에 이미지가 반드시 포함되었는지 확인합니다. 만약 이미지가 없거나 빈 문자열이면 에러 메시지가 반환됩니다.
```

# { Socket.IO와 실시간 통신 구현 }

## Socket.IO와 실시간 통신 이해하기

```jsx
Socket.IO는 실시간 양방향 통신을 가능하게 해주는 JavaScript 라이브러리입니다.

이를 통해 클라이언트와 서버 간의 데이터를 빠르게 주고받을 수 있습니다.

특히 실시간 채팅, 알림 시스템, 라이브 피드와 같은 기능 구현에 유용합니다.
```

## 실시간 통신이 필요한 이유

```jsx
기존 방식 vs. 실시간 통신 방식

		기존 HTTP 요청-응답 방식:

				사용자가 서버에 요청을 보내면, 서버가 응답할 때까지 사용자는 기다려야 함.

				예: 포스트 생성 → 데이터베이스 저장 → 클라이언트에 응답.


		실시간 통신 방식:

				사용자가 서버에 요청을 보내면, 서버가 즉시 응답하며, 데이터가 처리되면서 결과를 업데이트함.

				예: 포스트 생성 → 클라이언트 즉시 알림 → 데이터베이스 저장 후 결과 확인.
```

## 주요 기술 스택

```jsx
Express: Node.js 기반 웹 애플리케이션 프레임워크로 서버 개발에 사용.

Socket.IO: 실시간 양방향 통신을 지원하는 라이브러리.

Redis: 데이터를 중앙에서 관리하여 다중 서버에서도 일관된 데이터 처리가 가능하도록 함.
```

### Redis를 사용한 중앙 데이터 관리: 쉽게 이해하기

```jsx
상황을 가정해보자

		서버 하나로 웹사이트를 운영하고 있다면, 모든 사용자는 그 서버로 접속해 데이터를 주고받습니다.

		예: 채팅 메시지, 게시글 등.

		하지만 사용자가 많아지면, 하나의 서버로는 감당이 어려워 여러 서버를 추가해야 합니다.

		예: 서버 A, 서버 B, 서버 C.

문제점

		사용자가 서버 A에 접속해 채팅 메시지를 보냈는데, 서버 B에 접속한 사용자는 그 메시지를 받지 못하는 경우가 발생할 수 있습니다.

		→ 이유: 각 서버가 각각의 데이터를 따로 관리하기 때문입니다.

Redis가 문제를 해결하는 방법

		Redis는 모든 서버가 공유할 수 있는 하나의 중앙 저장소 역할을 합니다.

		서버 A, B, C가 모두 Redis에 연결되어 같은 데이터를 확인하고 저장할 수 있습니다.

결과

		사용자가 어느 서버에 접속하든 모든 데이터가 실시간으로 동기화됩니다.

		서버 A에서 보낸 메시지가 서버 B와 C에서도 즉시 확인 가능합니다.
```

## 서버 설정

```jsx
const SERVER_PORT = 5000;
// 서버가 사용할 포트 번호. 기본적으로 5000번 포트를 사용합니다.

const log: Logger = config.createLogger('server');
// 로그 출력을 위한 Logger 객체를 생성합니다.
// 서버 실행 중 발생하는 이벤트나 에러 정보를 기록합니다.

export class ChattyServer {
// 서버를 구성하고 실행하는 주요 클래스입니다.
// 이 클래스는 Socket.IO 및 Express 서버 설정을 포함합니다.

  private app: Application;
  // Express 애플리케이션 인스턴스를 저장하는 속성입니다.

  constructor(app: Application) {
  // 생성자 함수로 Express 애플리케이션 객체를 받아 초기화합니다.
    this.app = app;
  }

  public start(): void {
  // 서버 실행을 위한 메인 함수입니다.
  // 미들웨어, 라우팅, 에러 핸들러 설정 후 서버를 시작합니다.
    this.securityMiddleware(this.app);  // 보안 관련 미들웨어 설정
    this.standardMiddleware(this.app);  // 일반적인 미들웨어 설정
    this.routeMiddleware(this.app);     // 라우팅 설정
    this.globalErrorHandler(this.app);  // 전역 에러 핸들러 설정
    this.startServer(this.app);         // 서버 시작
  }

  private securityMiddleware(app: Application): void {
  // 보안을 강화하기 위한 미들웨어 설정 함수입니다.
    app.use(
      cookieSession({
      // 세션 쿠키 설정을 위한 미들웨어입니다.
        name: 'session',
        keys: [config.SECRET_KEY_ONE!, config.SECRET_KEY_TWO!],
        // 쿠키 암호화를 위한 키 설정입니다.
        maxAge: 24 * 7 * 360000,
        // 쿠키의 유효 기간 설정 (1주일).
        secure: config.NODE_ENV !== 'development'
        // 개발 환경이 아닌 경우 HTTPS를 사용합니다.
      })
    );
    app.use(hpp());
    // HTTP Parameter Pollution 공격 방지를 위한 미들웨어입니다.

    app.use(helmet());
    // HTTP 헤더 보안을 강화하기 위한 미들웨어입니다.

    app.use(
      cors({
      // CORS 설정을 위한 미들웨어입니다.
        origin: config.CLIENT_URL,
        // 허용할 클라이언트 URL 설정.
        credentials: true,
        // 인증 정보를 포함한 요청을 허용.
        optionsSuccessStatus: 200,
        methods: ['GET', 'POST', 'PUT', 'DELETE', 'OPTIONS']
        // 허용할 HTTP 메서드 목록.
      })
    );
  }

  private standardMiddleware(app: Application): void {
  // 데이터 압축, JSON 및 URL 인코딩 처리 설정.
    app.use(compression());
    // 응답 데이터를 압축해 전송량을 줄입니다.
    app.use(json({ limit: '50mb' }));
    // JSON 본문 요청 크기 제한을 설정합니다.
    app.use(urlencoded({ extended: true, limit: '50mb' }));
    // URL-encoded 데이터의 파싱을 설정합니다.
  }

  private routeMiddleware(app: Application): void {
  // 라우트 설정을 위한 함수입니다.
    applicationRoutes(app);
    // 애플리케이션 라우트 초기화.
  }

  private globalErrorHandler(app: Application): void {
  // 전역 에러 핸들러를 설정합니다.
    app.all('*', (req: Request, res: Response) => {
    // 정의되지 않은 경로에 대한 에러 처리.
      res.status(HTTP_STATUS.NOT_FOUND).json({ message: `${req.originalUrl} not found` });
    });

    app.use((error: IErrorResponse, _req: Request, res: Response, next: NextFunction) => {
    // 에러 발생 시 로그를 기록하고 응답합니다.
      log.error(error);
      if (error instanceof CustomError) {
      // CustomError 클래스의 에러 처리.
        return res.status(error.statusCode).json(error.serializeErrors());
      }
      next();
    });
  }

  private async startServer(app: Application): Promise<void> {
  // 서버를 비동기적으로 시작하는 함수입니다.
    try {
      const httpServer: http.Server = new http.Server(app);
      // HTTP 서버 인스턴스를 생성합니다.
      const socketIO: Server = await this.createSocketIO(httpServer);
      // Socket.IO 서버를 생성하고 HTTP 서버와 연결합니다.
      this.startHttpServer(httpServer);
      // HTTP 서버를 시작합니다.
      this.socketIOConnections(socketIO);
      // Socket.IO 연결을 설정합니다.
    } catch (error) {
      log.error(error);
      // 에러 발생 시 로그를 기록합니다.
    }
  }

  private async createSocketIO(httpServer: http.Server): Promise<Server> {
  // Socket.IO 서버를 생성하고 Redis 어댑터를 설정하는 함수입니다.
    const io: Server = new Server(httpServer, {
      cors: {
        origin: config.CLIENT_URL,
        methods: ['GET', 'POST', 'PUT', 'DELETE', 'OPTIONS']
      }
    });
    const publicClient = createClient({ url: config.REDIS_HOST });
    // Redis 클라이언트를 생성합니다.
    const subClient = publicClient.duplicate();
    // Redis 구독 클라이언트를 생성합니다.
    await Promise.all([publicClient.connect(), subClient.connect()]);
    // Redis 클라이언트를 비동기적으로 연결합니다.
    io.adapter(createAdapter(publicClient, subClient));
    // Redis 어댑터를 Socket.IO에 설정합니다.
    return io;
  }

  private startHttpServer(httpServer: http.Server): void {
  // HTTP 서버를 시작하고 상태를 로그로 출력합니다.
    log.info(`Server has started with process ${process.pid}`);
    httpServer.listen(SERVER_PORT, () => {
      log.info(`Server running on port ${SERVER_PORT}`);
    });
  }

  private socketIOConnections(io: Server): void {
  // Socket.IO 연결을 관리하고 이벤트를 처리합니다.
    const postSoketHandler: SocketIOPostHandler = new SocketIOPostHandler(io);
    // Socket.IO 게시글 이벤트 핸들러 객체를 생성합니다.
    postSoketHandler.listen();
    // 연결 이벤트를 수신합니다.
  }
}
```

```jsx
      'gifUrl', `${gifUrl}` // GIF 이미지 URL
    ];

    // 두 번째 리스트: 게시글의 추가 정보 저장
    const secondList: string[] = [
      'commentsCount', `${commentsCount}`, // 댓글 수
      'reactions', JSON.stringify(reactions), // 반응 정보 (JSON 문자열로 변환)
      'imgVersion', `${imgVersion}`, // 이미지 버전 정보
      'imgId', `${imgId}`, // 이미지 ID
      'createdAt', `${createdAt}` // 게시글 생성 날짜
    ];

    // 두 리스트를 합쳐 저장할 데이터를 하나의 배열로 생성
    const dataToSave: string[] = [...firstList, ...secondList];

    try {
      // Redis 클라이언트가 열려 있지 않다면 연결
      if (!this.client.isOpen) {
        await this.client.connect();
      }

      // 현재 사용자의 게시글 수를 가져옴 (Redis의 HMGET 명령 사용)
      const postCount: string[] = await this.client.HMGET(`users:${currentUserId}`, 'postsCount');

      // ZADD 명령: 게시글 키를 정렬된 집합(zset)에 저장. uId를 점수(score)로 사용
      await this.client.ZADD('post', { score: parseInt(uId, 10), value: `${key}` });

      // HSET 명령: 게시글 정보를 해시 형태로 저장
      for (let i = 0; i < dataToSave.length; i += 2) {
        // dataToSave 배열에서 한 번에 키와 값을 추출해 Redis에 저장
        await this.client.HSET(`posts:${key}`, dataToSave[i], dataToSave[i + 1]);
      }

      // 게시글 수(postCount)를 증가시킴
      const count: number = parseInt(postCount[0], 10) + 1; // 기존 게시글 수에 1 추가
      await this.client.HSET(`users:${currentUserId}`, 'postsCount', count); // 업데이트된 게시글 수 저장
    } catch (error) {
      // 오류 발생 시 로그를 남기고 사용자 정의 에러를 던짐
      log.error(error);
      throw new ServerError('Server error. Try again.');
    }
  }
}

```

# { "Socket.IO로 실시간 게시물 알림 구현하기” }

## Socket.IO란?

```jsx
Socket.IO는 서버와 클라이언트가 실시간으로 데이터를 주고받을 수 있도록 도와주는 라이브러리입니다.

예를 들어:

		사용자가 게시물을 작성하면, 다른 사용자의 화면에 즉시 새 게시물이 보이게 할 수 있습니다.

		채팅 애플리케이션에서 메시지를 보낼 때, 상대방에게 실시간으로 메시지가 전달됩니다.
```

## 이 코드에서 Socket.IO의 역할

```jsx
soketIOPostObject.emit('add post', createdPost)
```

```jsx
이 한 줄은 Socket.IO를 사용해 이벤트를 클라이언트에 전송하는 핵심 부분입니다. 여기서 중요한 내용을 하나씩 살펴보겠습니다.
```

## 1. `emit` 메서드란?

```jsx
emit은 이벤트를 발생시키는 함수입니다.

여기서 이벤트란, "서버가 클라이언트에게 무언가를 알리는 신호"라고 생각하면 됩니다.
```

```jsx
soketIOPostObject.emit(eventName, data)
```

```jsx
eventName: 이벤트의 이름입니다. 클라이언트가 이 이름을 통해 특정 동작을 수행합니다.

		예: 'add post' → "새 게시물이 추가되었습니다"라는 신호를 보냅니다.

data: 클라이언트로 보내는 데이터입니다.

		예: createdPost → 방금 생성된 게시물 데이터.
```

## 2. 왜 이벤트를 보내나요?

```jsx
이벤트를 전송하는 이유는 실시간 반응을 구현하기 위해서입니다.

		사용자가 게시물을 작성했을 때, 이 정보를 즉시 다른 사용자 화면에 표시하려고 합니다.

		이를 위해 서버는 emit을 통해 클라이언트에게 데이터를 보내고, 클라이언트는 이 데이터를 화면에 렌더링합니다.
```

## 3. `add post` 이벤트의 의미

```jsx
soketIOPostObject.emit('add post', createdPost)
```

```jsx
'add post': 이 이벤트 이름은 "게시물이 추가되었음"을 클라이언트에게 알리는 신호입니다.

클라이언트는 'add post'라는 이벤트를 감지(listen)한 뒤, 화면에 새 게시물을 표시하는 동작을 수행합니다.
```

## 4. 이벤트 전송 시점

```jsx
soketIOPostObject.emit('add post', createdPost);
await postCache.savePostToCache({ ... });
```

```jsx
emit 메서드는 Redis 캐시에 데이터를 저장하기 전 또는 저장한 후에 호출할 수 있습니다.

여기에서는 emit을 먼저 호출했습니다.

		이렇게 하면 사용자가 데이터를 빠르게 확인할 수 있습니다.

		Redis 저장 등 백그라운드 작업은 나중에 진행되므로, 사용자 경험이 개선됩니다.

💡 왜 먼저 호출하나요?

		데이터를 캐시에 저장하거나 데이터베이스에 추가하는 작업은 시간이 걸릴 수 있습니다.

		하지만 emit은 즉시 실행되므로, 사용자가 빠르게 결과를 확인할 수 있습니다.
```

## 5. 클라이언트에서 이벤트 처리

```jsx
서버가 emit으로 이벤트를 보냈다면, 클라이언트에서는 다음과 같이 이벤트를 수신할 수 있습니다:
```

```jsx
socket.on('add post', (data) => {
  console.log('새 게시물 도착:', data)
  // 클라이언트 화면에 게시물을 표시하는 로직
})
```

```jsx
socket.on('add post', callback):

		클라이언트는 'add post'라는 이름의 이벤트를 계속 듣고 있습니다.

		서버가 이 이벤트를 보내면, 콜백 함수가 실행되고 데이터를 처리합니다.

data:

		서버가 보낸 createdPost 객체가 클라이언트로 전달됩니다.
```

```jsx
		이처럼 Socket.IO는 실시간 데이터 전송을 간단하고 효율적으로 구현할 수 있는 강력한 도구입니다P!
```

# { Post 큐 워커 작성 }

## 1. 기본 개념

```jsx
Queue(큐): 작업들을 순서대로 처리하기 위해 사용하는 데이터 구조.

		작업들을 등록하면 큐가 차례로 작업을 처리.

Worker(워커): 큐에 등록된 작업을 실제로 처리하는 역할.

		각 작업의 내용을 실행.
```

## 2. Post를 처리하기 위한 구조

### 2.1. PostService

```jsx
역할: Post 데이터를 데이터베이스(DB)에 저장하거나, 사용자 정보(예: 게시물 개수)를 업데이트.

addPostToDB 메서드:

		첫 번째 작업: PostModel.create(createdPost)을 통해 새로운 게시물 데이터를 DB에 저장.

		두 번째 작업: UserModel.updateOne()을 이용해 사용자 정보(예: 게시물 개수)를 1 증가.

		두 작업을 병렬로 처리하기 위해 Promise.all 사용.
```

```jsx
// PostService 클래스 내부
public async addPostToDB(userId: string, createdPost: IPostDocument): Promise<void> {
    // 1. 새로운 게시물을 데이터베이스에 저장하는 작업을 정의
    // `PostModel.create()`는 MongoDB에 새로운 게시물을 생성하고 저장.
    // 결과는 비동기로 반환되며, 실제 데이터 저장이 완료될 때까지 기다릴 필요가 없으므로 Promise로 반환.
    const post: Promise<IPostDocument> = PostModel.create(createdPost);

    // 2. 사용자의 게시물 수(postCount)를 1 증가시키는 작업을 정의
    // UserModel.updateOne()`은 MongoDB에서 특정 사용자를 찾아서 해당 필드(postCount)를 업데이트.
    // $inc 연산자는 MongoDB에서 숫자 값을 특정 숫자만큼 증가시킬 때 사용.

    const user: UpdateQuery<IUserDocument> = UserModel.updateOne(
        { _id: userId }, // 조건: 사용자의 ID와 일치하는 문서를 찾음
        { $inc: { postCount: 1 } } // 작업: postCount 필드 값을 1 증가
    );

    // 3. Promise.all을 사용하여 두 작업을 동시에 실행
    // - 두 작업(post 생성, 사용자 업데이트)은 서로 독립적임.
    // - 따라서 순차적으로 실행할 필요 없이 동시에 실행 가능.
    // - Promise.all을 사용하면 두 작업이 모두 완료될 때까지 기다림.

    await Promise.all([post, user]);
}
```

### Promise.all이란?

```jsx

여러 Promise를 배열로 받아서 동시에 실행.

모든 Promise가 성공해야만 결과를 반환.

하나라도 실패하면, 즉시 거부 상태(Rejected)로 변환하며 오류를 반환.

Promise.all의 장점

		병렬 실행: 서로 독립적인 작업들을 동시에 실행하므로 처리 속도가 빨라짐.

		코드 간결화: 여러 비동기 작업의 결과를 한 번에 처리 가능.
```

### 2.2. PostQueue

```jsx
역할: Post와 관련된 작업을 큐에 등록.

주요 메서드:

		addPostJob: 새로운 작업을 큐에 추가.

		processJob: 특정 작업이 실행될 때 처리 방식을 정의.
```

```jsx
// PostQueue 클래스: 게시물 처리 작업을 관리하는 큐를 정의
// BaseQueue 클래스를 상속받아 큐의 기본 기능을 활용.
class PostQueue extends BaseQueue {
    // 생성자 메서드: PostQueue 클래스가 생성될 때 실행
    constructor() {
        // 부모 클래스(BaseQueue)의 생성자를 호출하면서 'posts'라는 큐 이름 전달
        super('posts');

        // 큐에서 처리할 작업을 정의
        // 'addPostToDB'라는 작업 유형을 등록하고, 해당 작업을 처리하는 메서드로 postWorker.savePostToDB를 지정.
        // 5는 동시 처리(concurrency) 수준을 나타냄: 한 번에 최대 5개의 작업을 병렬로 처리 가능.
        this.processJob('addPostToDB', 5, postWorker.savePostToDB);
    }

    // addPostJob 메서드: 새로운 작업을 큐에 추가
    // name: 작업의 이름 (예: 'addPostToDB')
    // data: 작업에 필요한 데이터를 포함한 객체
    public addPostJob(name: string, data: IPostJobData): void {
        // BaseQueue에서 상속받은 addJob 메서드를 호출해 작업을 큐에 추가.
        this.addJob(name, data);
    }
}

```

### 2.3. PostWorker

```jsx
역할: 큐에 등록된 작업을 실행.

savePostToDB 메서드:

		큐에서 작업 데이터를 받아 PostService의 메서드를 호출해 DB에 데이터를 저장.

		작업 상태(예: 진행률, 성공/실패 여부)를 로그로 기록.
```

```jsx
// savePostToDB 메서드: 큐에서 전달받은 작업(job)을 처리하여 게시물을 데이터베이스에 저장
// 작업이 완료되었는지 상태를 업데이트하고, 오류 발생 시 처리.
async savePostToDB(job: Job, done: DoneCallback): Promise<void> {
    try {
        // 1. 작업 데이터에서 key와 value를 구조 분해 할당으로 추출
        // - key: 작업에 포함된 사용자 ID
        // - value: 작업에 포함된 게시물 데이터
        const { key, value } = job.data;

        // 2. 게시물 데이터를 데이터베이스에 저장
        // - key: 사용자 ID를 통해 어떤 사용자가 게시물을 작성했는지 식별.
        // - value: 새로 생성된 게시물 데이터를 포함.
        // - postService.addPostToDB는 데이터베이스에 게시물을 저장하고 사용자의 게시물 개수를 업데이트.
        await postService.addPostToDB(key, value);

        // 3. 작업 진행 상태를 100%로 업데이트
        // - 작업이 정상적으로 완료되었음을 Bull 큐가 알 수 있도록 업데이트.
        job.progress(100);

        // 4. 작업 완료 콜백 호출
        // - 첫 번째 인자(null): 작업이 성공적으로 완료되었음을 나타냄 (에러 없음).
        // - 두 번째 인자(job.data): 작업에 사용된 데이터를 다시 반환.
        done(null, job.data);
    } catch (error) {
        // 5. 에러 발생 시 로깅
        // - 문제가 발생하면 해당 오류를 로그로 기록.
        log.error(error);

        // 6. 작업 완료 콜백 호출 (에러 전달)
        // - 첫 번째 인자(error): 에러 정보를 전달하여 작업이 실패했음을 알림.
        done(error as Error);
    }
}
```

# { 게시물 생성 이미지 포함 & 텍스트만 포함 구현 }

## 기능 개요

```jsx
게시물을 생성하는 기능 구현.

텍스트만 포함된 게시물과 이미지를 포함한 게시물의 두 가지 기능을 개발.

이미지는 Cloudinary를 활용해 업로드.

업로드된 이미지는 데이터베이스에 저장될 게시물 데이터에 포함.
```

## 주요 개념 및 메서

```jsx
1. post 메서드 (텍스트 게시물)

				사용자가 텍스트로만 이루어진 게시물을 생성.

				데이터는 Redis(캐시)에 저장되고, 이후 MongoDB에 저장하는 작업이 비동기로 처리.

2. postWithImage 메서드 (이미지 게시물)

				사용자가 텍스트와 이미지를 포함한 게시물을 생성.

				이미지 업로드는 Cloudinary 서비스를 이용.

				Cloudinary에서 반환된 public_id와 version 정보는 게시물 데이터에 포함되어 저장.
```

```jsx
public async post(req: Request, res: Response): Promise<void> {
  const { post, bgColor, privacy, gifUrl, profilePicture, feelings } = req.body;

  // MongoDB ObjectId 생성
  const postObjectId: ObjectId = new ObjectId();

  // 게시물 객체 생성
  const createdPost: IPostDocument = {
    _id: postObjectId,
    userId: req.currentUser!.userId,
    username: req.currentUser!.username,
    email: req.currentUser!.email,
    avatarColor: req.currentUser!.avatarColor,
    profilePicture,
    post,
    bgColor,
    feelings,
    privacy,
    gifUrl,
    commentsCount: 0,
    imgVersion: '',
    imgId: '',
    createdAt: new Date(),
    reactions: { like: 0, love: 0, happy: 0, sad: 0, wow: 0, angry: 0 }
  };

  // Socket.IO를 통해 실시간 알림 전송
  soketIOPostObject.emit('add post', createdPost);

  // Redis 캐시에 게시물 저장
  await postCache.savePostToCache({
    key: postObjectId,
    currentUserId: `${req.currentUser!.userId}`,
    uId: `${req.currentUser!.uId}`,
    createdPost
  });

  // MongoDB 저장 작업 큐에 추가
  postQueue.addPostJob('addPostToDB', { key: req.currentUser!.userId, value: createdPost });

  // 성공 응답
  res.status(HTTP_STATUS.CREATED).json({ message: 'Post created successfully' });
}
```

```jsx
모의 설정은 마치 "역할극"과 같습니다.

실제 사용자, 서버, 데이터베이스 등이 연기자라면, Mock은 그들을 대신해 행동하는 대역입니다.
```

```jsx
왜 필요한가?

1. 테스트를 독립적으로 수행하기 위해:

		테스트는 특정 기능만 검증해야 합니다. 외부 요소(예: 데이터베이스, 네트워크)가 테스트 결과에 영향을 주지 않아야 합니다.

2. 빠르고 효율적으로 테스트하기 위해:

		실제 환경을 항상 준비하거나 사용하는 데 시간이 오래 걸릴 수 있으므로 Mock 데이터를 사용해 간단히 처리합니다.
```

## 모의 설정과 테스트 과정

### 1. 환경 준비

```jsx

테스트를 위해 필요한 데이터, 요청(Request), 응답(Response) 객체를 만듭니다.

예를 들어:

		요청(Mock Request): 게시물을 작성할 때 사용자가 보낸 데이터를 흉내냄.

		응답(Mock Response): 서버가 사용자에게 반환할 데이터를 흉내냄.
```

```jsx
export const postMockRequest = (body, currentUser) => ({
  body, // 요청 본문 (예: 게시물 내용)
  currentUser, // 현재 사용자 정보
})

export const postMockResponse = () => {
  const res = {}
  res.status = jest.fn().mockReturnValue(res)
  res.json = jest.fn().mockReturnValue(res)
  return res
}
```

### 2. 가짜 동작 정의

```jsx
어떤 함수나 메서드가 호출될 때, 실제로 실행되는 대신 "예상되는 결과"를 반환하도록 설정합니다.

비유: 누군가 "계좌 잔액"을 묻는다면, 실제로 은행 서버를 호출하지 않고 그냥 미리 준비된 잔액을 말하는 것.
```

```jsx
jest.spyOn(PostCache.prototype, 'savePostToCache').mockImplementation(() => true)
```

### 3. **테스트 수행**

```jsx
테스트 코드에서 Mock 데이터를 사용해 기능을 실행하고, 결과를 검증합니다.

검증 포인트:

		함수가 올바르게 호출되었는지?

		기대한 응답이 반환되었는지?

		에러가 발생해야 할 때, 제대로 발생했는지?
```

```jsx
it('should send correct json response', async () => {
  const req = postMockRequest(newPost, authUserPayload)
  const res = postMockResponse()

  await Create.prototype.post(req, res)

  expect(res.status).toHaveBeenCalledWith(201)
  expect(res.json).toHaveBeenCalledWith({ message: 'Post created successfully' })
})
```

## 요약된 과정

```jsx
Mock 데이터 만들기: 요청(Request), 응답(Response), 기타 외부 서비스 대신할 데이터를 준비.

Mock 설정: 테스트 중에 호출될 함수나 메서드의 동작을 가짜로 설정.

테스트 실행: 테스트 코드를 작성하고 실행.

결과 검증: 실행 결과가 기대한 대로 동작했는지 확인.
```

## 비유: 레스토랑 테스트

```jsx
실제 환경: 음식을 요리하려면 주방에서 모든 재료와 요리사를 준비해야 함.

Mock 환경: 재료와 요리사를 대신해 모형 음식과 가짜 손님을 사용.

목적: 음식 맛 평가가 아닌, 주문 프로세스가 올바르게 동작하는지 확인.
```
