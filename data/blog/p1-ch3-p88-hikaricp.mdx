## HikariCP

### 개념

```java
HikariCP 개념:

* 커넥션 풀:

	HikariCP는 데이터베이스 연결을 미리 만들어 놓고 저장하는 곳 그래서 요청이 들어올 때마다 연결을 새로 만들 필요가 없다. 이미 만들어진 연결을 재사용해서 어플리케이션을 빠르게 만들어준다.

* 풀 크기 관리:

	HikariCP를 사용하면 데이터베이스 연결을 몇 개나 유지할지 설정할 수 있다. 최소 연결 수와 최대 연결 수를 정할 수 있어서 필요한 만큼 연결을 관리할 수 있다.

* 커넥션 설정:

	HikariCP는 데이터베이스에 연결할 때 필요한 정보를 받아들인다. 이 정보에는 어떤 데이터베이스를 사용하고, 어떤 사용자 이름과 암호를 사용할지 등이 포함된다.

* 풀 관리:

	HikariCP는 커넥션의 유효성을 검사하고 필요에 따라 커넥션을 다시 생성한다. 또한 커넥션의 최대 수명과 유휴 시간을 설정하여 풀 내 커넥션의 상태를 관리한다.
```

```java
<dependency>
	<groupId>com.zaxxer</groupId>
	<artifactId>HikariCP</artifactId>
	<version>3.4.5</version>
</dependency>
```

```java
HikariCP는 자바 어플리케이션에서 데이터베이스 연결 풀을 관리하기 위한 경량의 데이터베이스 커넥션 풀 라이브러리

HikariCP는 데이터베이스 연결을 관리하는 작업을 간단하게 만들어주는 라이브러리로, 어플리케이션의 성능을 향상시키고 데이터베이스 리소스를 효과적으로 활용할 수 있게 도와준다
```

### HikariCP Bean 등록

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381151/notion-blog/_/_/_/_/P1_ch3_p88_HikariCP_/Untitled.png)

```java
 	<bean id="hikariConfig" class="com.zaxxer.hikari.HikariConfig">
		<property name="driverClassName" value="oracle.jdbc.driver.OracleDriver"></property>
		<property name="jdbcUrl" value="jdbc:oracle:thin:@localhost:1521:XE"></property>
		<property name="username" value="book_ex"></property>
		<property name="password" value="book_ex"></property>
	</bean>
```

```java
root-context.xml 에 HikariCP Bean 등록을 해준다
```

```java
<!-- HikariCP configuration -->
	<bean id="dataSource" class="com.zaxxer.hikari.HikariDataSource" destroy-method="close">
		<constructor-arg ref="hikariConfig" />
	</bean>
```

```java
추가적으로 HikariCP 설정을 Bean 에 추가해준다 ("hikariConfig" 와 연결)
```

![Untitled](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381151/notion-blog/_/_/_/_/P1_ch3_p88_HikariCP_/Untitled_1.png)

```java
스프링이 시작되면 root-context.xml 을 읽어서 위와 같은 형태로 id 가 dataSource 인 객체가 처리된다

조금더 상세하게 설명하자면

1. <bean> 태그를 사용하여 스프링 애플리케이션 컨텍스트에 dataSource라는 이름으로 객체를 등록 이 객체는 데이터베이스와의 연결을 관리하는 HikariCP 데이터 소스 객체이다.

2. class 속성은 com.zaxxer.hikari.HikariDataSource 클래스를 지정하여 HikariCP 데이터 소스 객체를 생성하도록 스프링에 알린다.

3. destroy-method 속성은 스프링이 이 데이터 소스 객체를 폐기할 때 어떤 메서드를 호출해야 하는지 지정 여기서는 데이터 소스 객체를 닫는 close 메서드를 호출

4. <constructor-arg> 태그는 생성자에 전달할 인자를 설정한다. ref 속성을 사용하여 hikariConfig라는 다른 빈 객체를 참조하고, 이를 데이터 소스 객체의 생성자에 전달한다. (hikariConfig는 HikariCP 설정을 가지고 있을 것으로 예상)
```

```java
package org.zerock.persistence;

import javax.sql.DataSource;

import org.junit.runner.RunWith;

import org.springframework.test.context.ContextConfiguration;
import org.springframework.test.context.junit4.SpringJUnit4ClassRunner;

import lombok.extern.log4j.Log4j;

@RunWith(SpringJUnit4ClassRunner.class)
@ContextConfiguration("file:src/main/webapp/WEB-INF/spring/root-context.xml")
@Log4j
public class DataSourceTests {

	@Autowired
	private DataSource ds;


	@Test
	public void testConnection() {

		try(Connection con = ds.getConnection()) {

			log.info(con);
		} catch(Exception e) {

			e.printStackTrace(); // 예외 상황을 분석하기 위한 용도로 사용 (개발자에게 디버깅 할 수 있는 힌트를 제공) 사용하지 말아야함

			log.error(e.getMessage()); // getMessage는 오류의 원인을 사람이 이해하기 쉬운 형태로 리턴
		}

	}

}
```
