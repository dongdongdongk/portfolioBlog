# { 🎮 Character 클래스와 Skeletal Mesh 기초 }

## 🎯 이번 강의 목표

Character 클래스의 특징과 Skeletal Mesh(스켈레탈 메시)의 구조를 이해합니다.
Pawn과 Character의 차이점을 파악하고, 게임 캐릭터 제작을 준비합니다.

---

## 📊 클래스 계층구조 복습

```
Actor (액터)
  ↓
Pawn (폰) - 빙의 가능
  ↓
Character (캐릭터) - 게임 캐릭터 전용
```

### 각 클래스의 특징

**Actor**

- 레벨에 배치/스폰 가능
- 기본 기능만 제공

**Pawn (Actor 상속)**

- Actor의 모든 기능
- 빙의(조종) 가능
- Movement Component 직접 추가 필요

**Character (Pawn 상속)**

- Actor + Pawn의 모든 기능
- 게임 캐릭터에 특화된 추가 기능

---

## 🔧 Character 클래스의 기본 구성

### 자동 포함 컴포넌트

**1. Character Movement Component**

```
기능: 캐릭터 전용 이동 처리
특징:
  ├─ Pawn과 달리 자동으로 포함됨
  ├─ 걷기, 점프, 수영 등 캐릭터 동작 지원
  └─ 캐릭터에 맞는 물리 처리
```

**2. Skeletal Mesh Component (스켈레탈 메시)**

```
기능: 애니메이션 가능한 3D 모델
특징:
  ├─ Static Mesh와 다름 (뼈대 구조 있음)
  ├─ 애니메이션 재생 가능
  └─ 자동으로 포함됨
```

**3. Arrow Component (화살표)**

```
기능: 캐릭터가 바라보는 방향 표시
특징:
  ├─ 에디터에서만 보임
  ├─ 게임 실행 시 안 보임
  └─ 방향 설정용
```

### 일반적으로 추가하는 컴포넌트

**Spring Arm + Camera**

```
구조:
Character
  └─ Spring Arm (카메라 지지대)
      └─ Camera (시점)

목적: 플레이어 캐릭터 시점 제공
```

## 🦴 Skeletal Mesh vs Static Mesh

### Static Mesh (정적 메시)

```
특징:
  ├─ 움직이지 않는 3D 모델
  ├─ 뼈대 없음
  ├─ Collision Hull로 충돌 처리
  └─ 건물, 소품 등에 사용

예: 바위, 벽, 상자
```

### Skeletal Mesh (스켈레탈 메시)

```
특징:
  ├─ 뼈대(Skeleton) 구조
  ├─ 애니메이션 가능
  ├─ Physics Asset으로 충돌 처리
  └─ 캐릭터, 생물 등에 사용

예: 사람, 동물, 움직이는 캐릭터
```

## 🦴 Skeleton(스켈레톤) 구조

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380746/notion-blog/_/_/_5_/_8_-_3D_-_1/image.png)

### 정의

뼈대 = 본(Bone)들의 계층구조

```
계층 구조 예시:
Pelvis (골반) - 루트
  ├─ Spine (척추)
  │   ├─ Chest (가슴)
  │   │   ├─ Neck (목)
  │   │   │   └─ Head (머리)
  │   │   ├─ Left Shoulder (왼쪽 어깨)
  │   │   │   └─ Left Arm (왼쪽 팔)
  │   │   │       └─ Left Hand (왼쪽 손)
  │   │   │           └─ Fingers (손가락들)
  │   │   └─ Right Shoulder (오른쪽 어깨)
  │   │       └─ ... (대칭 구조)
  ├─ Left Leg (왼쪽 다리)
  └─ Right Leg (오른쪽 다리)
```

### 본(Bone)의 특징

**부모-자식 관계**

```
부모 본이 움직이면
  ↓
자식 본도 따라 움직임

예:
팔 본 회전
  ↓
손 본도 함께 회전
  ↓
손가락 본도 함께 회전
```

**Skinning (스키닝)**

```
본 ←→ 메시 폴리곤 연결

본이 움직이면
  ↓
연결된 폴리곤도 변형
  ↓
자연스러운 애니메이션
```

### Weight (가중치)

각 폴리곤이 본에 영향받는 정도

```
Weight 색상 표시:
  ├─ 빨강: 100% 영향 (완전히 따라감)
  ├─ 주황/노랑: 50-80% 영향
  ├─ 초록: 20-50% 영향
  └─ 파랑: 거의 영향 없음

예:
팔꿈치 부분
  ├─ 위쪽: 위팔 본에 강하게 연결
  ├─ 중간: 두 본에 골고루 연결
  └─ 아래: 아래팔 본에 강하게 연결

→ 부드러운 굽힘 표현
```

## 🔍 Physics Asset (피직스 애셋)

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380741/notion-blog/_/_/_5_/_8_-_3D_-_1/image_1.png)

### 정의

Skeletal Mesh의 충돌 처리용 형태 모음

### Static Mesh와의 차이

**Static Mesh**

```
Collision Hull
  └─ 하나의 단순한 형태
      (박스, 캡슐, 구 등)
```

**Skeletal Mesh**

```
Physics Asset
  └─ 여러 개의 Physics Body
      ├─ 각 본에 부착
      ├─ 본과 함께 움직임
      └─ 동적인 충돌 처리

예:
팔 본 → 캡슐 형태
다리 본 → 캡슐 형태
머리 본 → 구 형태
```

### Physics Body (피직스 바디)

```
특징:
  ├─ 간단한 형태 (캡슐, 박스, 구)
  ├─ 특정 본에 부착
  ├─ 본 움직임에 따라 이동
  └─ 모든 본에 필요하진 않음

목적:
애니메이션하는 메시의
역동적인 충돌 처리
```

## 🛠️ Skeletal Mesh 에디터 살펴보기

### SKM_Kicks 열기

```
Content Browser
  ↓
Kicks 폴더
  ↓
SKM_Kicks 더블클릭
  ↓
Skeletal Mesh Editor 실행
```

### 주요 패널

**1. Viewport (뷰포트)**

```
기능: 3D 메시 확인
조작:
  ├─ 마우스 드래그: 회전
  ├─ 우클릭 드래그: 이동
  └─ 스크롤: 확대/축소
```

**2. Skeleton Tree (왼쪽)**

```
기능: 본 계층구조 표시

표시 내용:
  ├─ 모든 본 이름
  ├─ 부모-자식 관계 (들여쓰기)
  └─ 선택 가능

사용법:
본 클릭 → 뷰포트에서 강조 표시
```

**3. Asset Details (오른쪽)**

```
기능: 메시 설정 확인/변경

주요 정보:
  ├─ 연결된 Skeleton
  ├─ 머티리얼 설정
  ├─ LOD 설정
  └─ Physics Asset 연결
```

### 본 선택 및 조작

**본 선택 방법**

```
방법 1: Skeleton Tree에서 클릭
방법 2: Viewport에서 본 직접 클릭
```

**본 회전 테스트**

```
1. 본 선택
   ↓
2. 회전 도구(E) 활성화
   ↓
3. 드래그로 회전
   ↓
4. 메시가 따라 움직임 확인

⚠️ 주의: 에디터 닫으면 변경사항 저장 안 됨
       (테스트용일 뿐)
```

### 뷰 옵션 조정

**Character 메뉴 → Show**

```
Bones
  ├─ All Hierarchy: 모든 본 표시
  └─ Selected Only: 선택한 본만 표시

Mesh
  └─ Draw Mesh Overlay: 가중치 색상 표시
```

## 🔗 에셋 간 연결 관계

```
Skeletal Mesh ←→ Skeleton
       ↓

       ↓
```

**재사용성**

```

  ↓

  ↓

  ↓

  ↓
같은 걷기/뛰기 애니메이션 공유
```

### 에디터 간 빠른 전환

```
우측 상단 아이콘으로 즉시 이동:

🦴 → Skeleton

🎬 → Animation
```

## 💡 핵심 개념 정리

### Character vs Pawn

```
Pawn
  ├─ 기본 빙의 기능
  ├─ Movement Component 수동 추가
  └─ Mesh Component 수동 추가

Character (Pawn 상속)
  ├─ Character Movement Component 자동
  ├─ Skeletal Mesh Component 자동
  ├─ 캐릭터 전용 함수들
  └─ 게임 캐릭터에 최적화
```

### Static vs Skeletal Mesh

```
Static Mesh
  ├─ 뼈 없음
  ├─ 애니메이션 불가
  ├─ 단순 충돌
  └─ 환경, 소품용

Skeletal Mesh
  ├─ 뼈 구조
  ├─ 애니메이션 가능
  ├─ Physics Asset 충돌
  └─ 캐릭터, 생물용
```

### 애니메이션 구조

```
Skeleton (뼈대)
  ↓
본들의 계층구조
  ↓
각 본에 폴리곤 가중치 부여
  ↓
본 움직임 → 메시 변형
  ↓
애니메이션 완성
```

## ⚠️ 주의사항

### 에디터에서 본 회전

```
❌ 저장되지 않음
   단순 테스트용

✅ 실제 애니메이션은
   Animation Asset에서 제작
```

### 에셋 연결

```
⚠️ Skeletal Mesh와 Animation은
   반드시 같은 Skeleton 공유해야 함

다른 Skeleton → 오류 발생
```

### Physics Asset

```
⚠️ 모든 본에 Physics Body 필요 없음

필요한 부위만:
  ├─ 충돌 감지 필요 부위
  ├─ 물리 시뮬레이션 필요 부위
  └─ 게임 성능에 따라 조절
```

### 1. CapsuleComponent (캡슐)

```
특징:
  ├─ 루트 컴포넌트 (고정)
  ├─ 이름 변경 불가
  ├─ 삭제 불가
  └─ Character의 필수 요소

역할:
  ├─ 충돌 감지 (벽, 바닥, 천장)
  ├─ 캐릭터 배치 기준점
  └─ 대부분의 물리 처리
```

**왜 Capsule인가?**

```
장점:
  ├─ 회전 시 충돌 처리 안정적
  ├─ 계단/경사 이동 부드러움
  └─ 모든 방향 동일한 너비

다른 형태(박스 등)는
회전 시 충돌 범위 변경 → 문제 발생
```

### 2. ArrowComponent (화살표)

```
기능: 캐릭터가 바라보는 방향 표시

특징:
  ├─ 에디터에서만 보임
  ├─ 게임 실행 시 보이지 않음
  └─ 방향 설정 참고용
```

### 3. Mesh (Skeletal Mesh Component)

```
이름: "Mesh" (기본값)

특징:
  ├─ Character 클래스에서 자동 생성
  ├─ CapsuleComponent에 부착
  └─ Skeletal Mesh Asset 할당 필요

⚠️ Static Mesh 할당 불가
   오직 Skeletal Mesh만 가능
```

### 4. CharacterMovement

```
위치: 수평선 아래 분리 표시

이유:
  ├─ Actor Component 기반
  ├─ 다른 컴포넌트에 부착 불가
  ├─ 위치/회전 속성 없음
  └─ 독립적 존재

기능:
캐릭터 이동 로직 처리
(걷기, 달리기, 점프 등)
```

## 📏 Capsule Component 크기 조정

### 왜 조정이 필요한가?

```
Capsule의 역할:

1. 배치 기준점
   └─ Capsule 바닥 = 바닥에 닿는 지점

2. 충돌 감지
   └─ 벽, 바닥, 천장과 충돌

→ 캐릭터 메시와 크기가 맞아야 함
```

### 레벨에 배치해서 확인

```
BP_Kicks를 레벨에 드래그
  ↓
문제 발견:
  ├─ Capsule은 바닥에 있음
  └─ 발은 공중에 떠있음

이유:
Capsule 바닥이 배치 기준점이므로
메시 발이 Capsule 바닥에 없으면
공중에 뜬 상태로 배치됨
```

### Capsule 크기 조정

**1. Capsule Half Height (높이)**

```
CapsuleComponent 선택
  ↓
Details 패널
  ↓
Shape 섹션
  ↓
Capsule Half Height 조정

설명:
  ├─ "Half Height" = 절반 높이
  ├─ 실제 높이 = 이 값 × 2
  └─ 캡슐 중심에서 위/아래 거리

권장값: 70
  └─ 실제 높이 = 140
```

**조정 방법**

```
방법 1: 값 클릭 후 좌우 드래그
방법 2: 직접 숫자 입력

실시간으로 Viewport에서 변화 확인
```

**2. Capsule Radius (반지름)**

```
역할: 캐릭터의 가로 충돌 범위

너무 얇으면:
  ├─ 팔이 벽 통과
  └─ 부자연스러움

너무 두꺼우면:
  ├─ 좁은 길 통과 불가
  └─ 답답한 느낌

권장값: 34
  └─ 메시와 벽 사이 여유 공간 확보
```

### 메시 위치 최종 조정

```
CapsuleComponent 설정:
  ├─ Half Height: 70
  └─ Radius: 34

Mesh 위치 조정:
  └─ Location Z: -70

의미:
발이 Capsule 바닥에 정확히 위치
(Half Height = -Z 위치)
```

**확인**

```
레벨에 배치
  ↓
발이 바닥에 정확히 닿는지 확인
  ↓
필요시 미세 조정
```

## 🔍 추가 설명

### Static Mesh vs Skeletal Mesh Component

```
Static Mesh Component:
  ├─ Static Mesh Asset 할당
  └─ 움직이지 않는 물체

Skeletal Mesh Component:
  ├─ Skeletal Mesh Asset만 할당
  └─ 애니메이션 가능한 캐릭터

⚠️ 서로 호환 안 됨
   Mesh 컴포넌트에 Static Mesh 할당 불가
```

### Component 부착 계층

```
부착 가능 컴포넌트:
  ├─ Scene Component
  ├─ Static/Skeletal Mesh
  ├─ Camera, Light 등
  └─ 위치/회전/스케일 있음

부착 불가 컴포넌트:
  ├─ Movement Component
  ├─ AI Controller 등
  └─ Actor Component 직속
  └─ 위치/회전 속성 없음

→ Components 패널에서 선으로 구분
```

## 🚫 God Class란?

### 정의


## 🔧 회전 방향 문제 해결

### 문제: Y축 반전

**현상**

```

```

**원인**

```
Unreal Engine의 Y축 방향
  ↓
위로 = 양수
아래로 = 음수
  ↓
일반적인 마우스 감각과 반대
```

### 해결: Negate Modifier

**IA_Look 에셋 수정**

```
IA_Look 열기
  ↓
Modifiers 섹션
  ↓
+ 버튼 (Add Modifier)
  ↓
Negate (부정, 반전)
  ↓
설정:
  ├─ X: ❌ (체크 해제)
  ├─ Y: ✅ (체크) - Y축만 반전
  └─ Z: ❌ (체크 해제)
```

**Modifier란?**

```
Input Action의 값을 변형하는 기능

Negate Modifier:
  └─ 값을 반전 (양수 ↔ 음수)

예:
Y 체크 시
  ├─ 마우스 위 (+1) → 입력값 -1
  └─ 마우스 아래 (-1) → 입력값 +1
```

**결과**

```
마우스 위로 → 카메라 위 봄 ✅
마우스 아래로 → 카메라 아래 봄 ✅
```

## 🔧 Modifier로 키 조정하기

### 이해하기: 축(Axis)이란?

```
2D 평면:
  ├─ X축: 좌우 (-)왼쪽 / (+)오른쪽
  └─ Y축: 전후 (-)뒤 / (+)앞

키보드 하나당 1개 축만 사용 가능
  ↓
Modifier로 어느 축에 넣을지 결정
```

### A 키 설정 (왼쪽 = 음수)

```
A 키 확장
  ↓
Add Modifier → Negate (반전)
  ↓
설정:
  ├─ X: ✅ (체크)
  ├─ Y: ❌
  └─ Z: ❌

결과: A 누르면 X = -1 (왼쪽)
```

### D 키 설정 (오른쪽 = 양수)

```
D 키는 Modifier 불필요

기본값 그대로 사용
  ↓
결과: D 누르면 X = +1 (오른쪽)
```

### W 키 설정 (앞 = Y축 양수)

```
W 키 확장
  ↓
Add Modifier → Swizzle Input Axis Values
  (축 변경: X → Y로 이동)
  ↓
Order 설정:
첫 글자를 Y로 (YXZ)

결과: W 누르면 Y = +1 (앞)
```

**Swizzle이 뭐야?**

```
Swizzle = 축 순서 바꾸기

기본: X축 입력
  ↓
Swizzle로 Y로 변경
  ↓
Y축에 입력됨
```

### S 키 설정 (뒤 = Y축 음수)

```
S 키는 2개 Modifier 필요!

1. Swizzle (Y축으로 이동)
   ↓
   Add Modifier → Swizzle
   Order: YXZ

2. Negate (음수로 변경)
   ↓
   Add Modifier → Negate
   설정:
     ├─ X: ❌
     ├─ Y: ✅ (체크)
     └─ Z: ❌

결과: S 누르면 Y = -1 (뒤)
```

## 📐 Blueprint 구현 - 전방 이동 (W/S)

### 전체 흐름

```
[IA Move Triggered]
  ↓
[Get Control Rotation] → 컨트롤러 회전
  ↓

  ↓

  ↓
[벡터 × Y값] → 최종 이동 방향
  ↓
[Add Input Vector] → Movement Component에 전달
```

### 노드 연결 순서

**1. 컨트롤러 회전 가져오기**

```
Get Control Rotation
  └─ Target: Self (Player Controller)

출력: Rotator (회전값)
```

**2. 앞 방향 벡터로 변환**

```
Get Forward Vector
  └─ In Rot: Control Rotation

출력: Vector (0~1 사이 방향)
```

**3. W/S 입력값 가져오기**

```
Get IA_Move
  └─ Return Value 우클릭
      → Split Struct Pin

출력: X, Y 값 분리
```

**4. 방향과 입력 곱하기**

```
Forward Vector × Y값

결과:
  ├─ Y=1 (W): 앞 방향
  ├─ Y=-1 (S): 뒤 방향 (반대)
  └─ Y=0: 이동 없음
```

**5. Movement Component 가져오기**

```
Get Controlled Pawn → Get Movement Component

이유:
Player Controller → Pawn 찾기
  ↓
Pawn → Movement Component 찾기
```

**6. 이동 입력 전달**

```
Add Input Vector
  ├─ Target: Movement Component
  └─ World Vector: (Forward × Y)
```

## 💡 핵심 개념 정리

### 1. 방향 벡터 (Direction Vector)

```
벡터 = 방향 + 크기

Forward Vector:
  └─ 회전값의 "앞" 방향

Right Vector:
  └─ 회전값의 "오른쪽" 방향

크기 1로 정규화됨 (단위 벡터)
```

### 2. 벡터 × 스칼라

```
Vector × Float = 새로운 Vector

예:
Forward(1, 0, 0) × 0.5
  = (0.5, 0, 0)

의미: 같은 방향, 절반 속도
```

### 3. Movement Component가 하는 일

```
우리가 주는 것:
"이 방향으로 가고 싶어요"

Component가 하는 일:
  ├─ 속도 계산 (가속/감속)
  ├─ 최대 속도 제한
  ├─ 중력 적용
  ├─ 충돌 감지
  ├─ 경사면 처리
  └─ 실제 위치 변경
```

### 4. Control Rotation vs Pawn Rotation

```
Control Rotation:
  ├─ Player Controller의 회전
  ├─ 마우스로 변경
  └─ 카메라 방향

Pawn Rotation:
  ├─ Character 메시의 회전
  ├─ 이동 방향으로 변경
  └─ 캐릭터가 바라보는 방향

서로 독립적!
```

## 💡 캐스팅(Casting)이란?

### 정의

```
Casting = 형변환
상위 클래스 → 하위 클래스로 변환

예:
Pawn (부모) → Character (자식)
```

### 왜 필요한가?

```
Get Controlled Pawn:
  └─ 반환 타입: Pawn

하지만:
Jump 함수는 Character 클래스에만 있음
  ↓
Pawn에는 Jump 없음
  ↓
Character로 캐스팅 필요!
```

**클래스 계층**

```
Pawn (부모)
  ├─ 기본 기능만
  └─ Jump 함수 없음
      ↓
Character (자식)
  ├─ Pawn의 모든 기능 +
  └─ Jump 함수 있음
```

### 캐스팅 원리

```
Cast to Character:

입력: Pawn 타입 객체
  ↓
확인: "이게 실제로 Character인가?"
  ↓
성공: Character 기능 사용 가능
실패: Cast Failed 실행
```

## 💡 성능 최적화 원리

### 캐스팅 비용

```
Cast to Character:
  ├─ 타입 확인
  ├─ 메모리 접근
  └─ 상대적으로 비싼 작업

매 프레임 반복하면:
  ↓
누적되어 성능 저하

```

### 캐싱의 효과

```
기존 (비효율):
점프 10번 = 캐스팅 10번

최적화 (캐싱):
점프 10번 = 캐스팅 1번 (초기화 시)
          + 변수 읽기 10번

변수 읽기 >>> 캐스팅보다 훨씬 빠름

```

### 언제 캐싱하나?

```
✅ 캐싱하면 좋은 경우:
  ├─ 자주 사용하는 값
  ├─ 변하지 않는 값
  └─ 가져오기 비싼 값

❌ 캐싱 불필요한 경우:
  ├─ 1번만 사용
  ├─ 자주 변하는 값
  └─ 가져오기 저렴한 값

```

## ⚠️ 주의사항

### Cast Failed 처리

```
Cast to Character
  ├─ As Character (성공)
  └─ Cast Failed (실패)

실패 시:
Jump 함수 호출 안 됨
  ↓
크래시 방지

```

### Is Valid 중요성

```
변수 사용 전 항상 확인:

❌ 바로 사용:
   Null일 경우 크래시

✅ Is Valid 후 사용:
   안전하게 사용

```

### Started vs Triggered

```
IA_Jump는 Started 사용

Started:
  └─ 키를 누르는 순간 1번만

Triggered:
  └─ 키를 누르고 있는 동안 계속

점프는 1번만 실행되어야 함
  ↓
Started 적합

```
