## 1. 🎯 Cinemachine 개념 이해하기

- **Cinemachine = Unity의 카메라 제어를 자동화해 주는 공식 패키지**
- 장점:
  - 감도/부드러움/회전 등 카메라 기능을 **코딩 없이** 조절 가능
  - **Virtual Camera가 실제 Main Camera를 조종**하는 구조
- 구조:
  - **Main Camera** → “뇌(Brain)” 역할
  - **Virtual Camera** → “지시자(Director)” 역할
    → 어떤 위치를 바라볼지, 따라갈지 설정

즉, 직접 Main Camera를 움직이는 게 아니라

**Virtual Camera가 설정을 담당하고 Main Camera는 이를 따라감**.

## 2. 📦 패키지 설치 및 확인

1. Unity 상단 메뉴 → **Window → Package Manager**

4. 강의에서는 **2.8.6** 버전 사용

- 상단 메뉴에 **Cinemachine** 탭이 생기면 설치 완료
- Main Camera Inspector를 보면
  **Cinemachine Brain** 컴포넌트가 추가됨

## 4. 🎯 Camera Controller(목표 지점) 만들기

Virtual Camera가 **무엇을 따라갈지(Follow)**,

**무엇을 바라볼지(LookAt)** 지정해야 하므로

빈 오브젝트 하나를 타겟으로 사용한다.

### ✔ 생성

1. Hierarchy → **Create Empty**
2. 이름: **CameraController**
3. Transform Reset:
   - Position = (0, 0, 0)
   - Rotation = (0, 0, 0)
   - Scale = (1, 1, 1)

### ✔ 역할 개념

- 이 오브젝트는 **카메라 타겟**
- 직접 눈에 보이지 않음 (Mesh 없음)
- 카메라를 움직이고 싶을 때 이 오브젝트를 이동하면 됨

## 6. 🎥 카메라 렌즈(Lens) 설정

Virtual Camera → **Lens** 영역

### ✔ Vertical FOV

- 기본값: 60
- 강의에서는 **50**으로 설정
  - 이유: 탑다운 게임은 화면 왜곡이 크면 보기 어려움
  - FOV가 낮으면 더 "정돈된" 느낌

## 7. 🧱 Body(바디) 설정 – 카메라 움직임 방식

Virtual Camera Inspector → **Body**

### ✔ Body = Transposer 선택

강의에서 선택한 옵션은:

> “Body: Framing Transposer 또는 Transposer 중
>
> 강의에서는 **Basic → Transposer** 선택”

### ✔ Binding Mode = **World Space**

- 카메라 위치 계산을 월드 좌표 기준으로 함
- 탑다운, RTS, 전략 게임에서 일반적으로 사용

### ✔ Follow Offset 설정

현재 카메라가 CameraController 기준

어디에 위치할지 정하는 값

강의에서 설정한 값:

| 축  | 값      | 설명                                 |
| --- | ------- | ------------------------------------ |
| Y   | **7**   | 카메라를 위로 띄워서 내려다보는 시점 |
| Z   | **-10** | 캐릭터 뒤쪽에 위치                   |

이 값 덕분에:

- 카메라가 위에서 보고
- 뒤로 충분히 빠져서 전체 맵이 보이는 각도가 된다

## 🔗 Binding Mode 종류 (짧고 핵심만)

### 1) **World Space**

- 카메라가 **월드 좌표 기준**으로 움직임.
- 타겟이 회전해도 카메라의 회전은 따라가지 않음.
- 가장 “독립적인” 따라다니기 방식.

### 2) **Lock To Target On Assign**

- **따라가기 시작하는 순간의 위치/회전만 한 번 복사**하고,
- 그 이후에는 타그의 회전을 따라가지 않음.
- “시작할 때만 맞춰놓고 이후엔 독립” 느낌.

### 3) **Lock To Target With World Up**

- 타겟의 회전은 따라가지만,
  **월드 Up 방향(y축)을 항상 유지**함.
- 즉, 타겟이 기울어져도 카메라는 기울어지지 않음.
- 흔히 사용하는 “안전한 추적 모드”.

### 4) **Lock To Target No Roll**

- 타겟 회전을 따라가되,
  **Z축 회전(roll, 카메라 옆으로 기울기)** 만 무시함.
- FPV(기울기 회전)만 막고 싶을 때 사용.

### 5) **Lock To Target**

- 타겟의 **모든 회전(X/Y/Z)을 100% 그대로 따라감**.
- 타겟이 뒤집히면 카메라도 뒤집힘.
- 캐릭터 뒤에 완전히 붙는 3rd-person 카메라 등에 사용.

### 6) **World Space (중복 항목 아님)**

- 앞의 1번과 동일.
  (Cinemachine UI 버전에 따라 두 번 보이기도 함.)

### 7) **Simple Follow With World Up**

- 타겟을 따라가되,
- **간단한 방식으로 부드럽게 회전 + 월드 Up 유지**
- 초보자에게 가장 쓸만한 “무난한 추적 모드”.

## 8. 🎯 Aim(조준) 설정 – 카메라 회전 방식

Virtual Camera → **Aim**

기본값 Composer 상태에서 강의는

대부분 기본값 유지하지만, **Damping(부드러움)** 에 대해 설명함.

또한 CameraController를 **회전**하면

카메라가 회전에 따라 자연스럽게 도는 방식도 시연했다.

---

## 9. 🌀 뎀핑(Damping) 설명 및 설정

### ✔ Damping이란?

- 카메라가 Follow 대상에 얼마나 **부드럽게** 따라가는지 결정
- 값이 높을수록 → **느리고, 부드럽고, 탄력 있는 느낌**
- 탑다운 전술 게임에서는 보통 **0**으로 설정해 즉각적인 반응 제공

### 강의 설정

모든 damping = **0**

### Body Damping

- X Damping = 0
- Y Damping = 0
- Z Damping = 0

### Aim Damping

- Horizontal Damping = 0
- Vertical Damping = 0

### 효과

- CameraController가 그대로 즉각적으로 따라감
- 부드러운 카메라 효과가 필요 없다면 이 설정이 최적

(강의 말: smoothing은 추후 **CameraController에 직접 추가**할 예정)

# { 🚀 카메라 이동 & 회전 제어하기 }

이번 강의는 **플레이어 입력(WASD / QE)** 을 이용해 카메라를 **부드럽게 이동하고 회전**시키는 방법을 배운다.

또한, 왜 단순 축 이동이 아니라 **transform.forward / transform.right** 벡터를 사용해야 하는지 개념적으로 이해하는 내용이 포함되어 있다.

## 1. 카메라 이동 입력 처리 개념 이해

- \*Update()\*\*는 매 프레임 호출되므로 입력 처리에 적합.
- 기본적으로 카메라는:
  - **W / S → 앞뒤 이동**
  - **A / D → 좌우 이동**
  - 입력을 통해 만들어지는 값을 먼저 “방향 벡터”로 만든 후,
  - 그 방향을 이용해 실제 위치를 변경하는 구조.

---

## 2. WASD 입력으로 이동 방향 벡터 만들기

### 🎯 개념

- 방향을 표현하기 위한 3D 벡터가 필요 → `Vector3 inputMoveDir`.
- 이동은 x, z축만 사용한다. (y는 카메라의 높이)

### ⚙️ 처리 방식

- W → z = +1
- S → z = -1
- A → x = -1
- D → x = +1

➡️ 입력값을 이용해 방향 벡터를 만든다.

➡️ 이 벡터는 “원하는 방향을 가리키는 신호”일 뿐, 실제 이동은 아직 아님.

---

## 3. 단순 축 이동이 잘못된 이유

강의에서 강조한 실수:

```csharp
transform.position += inputMoveDir * moveSpeed * Time.deltaTime;
```

→ **이렇게 하면 카메라가 항상 월드 기준 x,z 축으로 이동함.**

🛑 문제점

- 카메라가 회전해도 이동 방향이 변하지 않음
- 예: 카메라가 90° 회전한 상태에서 W를 눌러도 앞으로 안 가고 옆으로 감
- 즉, “카메라 앞 방향”을 기준으로 이동하지 않기 때문에 어색해짐

---

## 4. transform.forward / transform.right 개념과 적용

### ✔ 핵심 개념

- `transform.forward` = **오브젝트가 바라보는 방향(전방)**
- `transform.right` = **오브젝트가 오른쪽으로 향하는 방향**

➡️ 카메라가 회전하면 이 벡터값도 자동으로 변경됨

➡️ 따라서 이 벡터로 이동하면 “카메라 기준으로” 움직이게 됨

### ✔ 실제 적용 방식

- 전진/후진(W/S)은 forward 방향
- 좌/우 이동(A/D)은 right 방향과 연결

---

## 5. 카메라 회전(Q/E) 처리하기

### 🎯 개념

- 카메라의 Y축을 회전시키면 카메라가 주변을 도는 효과가 생김
- Cinemachine 카메라의 “Follow” 역할을 하는 빈 오브젝트를 회전시키는 방식

### ⚙ 입력

- Q → 반시계 방향
- E → 시계 방향

### ✔ 적용 방법

- `transform.eulerAngles`의 y 값에 회전 벡터를 추가한다

---

## 6. 최종 코드(모든 부분 상세 주석 포함)

```csharp
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class CameraController : MonoBehaviour
{
    private void Update()
    {
        // 1. 이동 입력값을 담을 벡터 생성 (x, z만 사용할 것)
        Vector3 inputMoveDir = new Vector3(0, 0, 0);

        // W : 전진 → z를 +1로
        if (Input.GetKey(KeyCode.W))
        {
            inputMoveDir.z = +1;
        }
        // S : 후진 → z를 -1로
        if (Input.GetKey(KeyCode.S))
        {
            inputMoveDir.z = -1;
        }
        // A : 왼쪽 → x를 -1로
        if (Input.GetKey(KeyCode.A))
        {
            inputMoveDir.x = -1;
        }
        // D : 오른쪽 → x를 +1로
        if (Input.GetKey(KeyCode.D))
        {
            inputMoveDir.x = +1;
        }

        // 이동 속도
        float moveSpeed = 10f;

        /*
            2. transform.forward / transform.right를 사용해서
               "카메라 기준" 이동 벡터를 생성

               - forward * z 입력 → 전진/후진
               - right * x 입력   → 좌/우 이동

               이 둘을 더하면 최종 이동 방향이 됨.
        */
        Vector3 moveVector =
            transform.forward * inputMoveDir.z +
            transform.right * inputMoveDir.x;

        // 3. 실제 위치 이동 (Time.deltaTime으로 프레임 보정)
        transform.position += moveVector * moveSpeed * Time.deltaTime;

        // ----------------------------------------------
        // 회전 처리 (Q/E)
        // ----------------------------------------------

        // 회전 방향을 담을 벡터 (y축만 회전)
        Vector3 rotationVector = new Vector3(0, 0, 0);

        // Q : y를 -1 (왼쪽으로 회전)
        if (Input.GetKey(KeyCode.Q))
        {
            rotationVector.y = -1;
        }
        // E : y를 +1 (오른쪽으로 회전)
        if (Input.GetKey(KeyCode.E))
        {
            rotationVector.y = +1;
        }

        float rotationSpeed = 100f;

        /*
            현재 오브젝트의 EulerAngles(Y축 회전)에
            rotationVector를 더해주는 방식.
            → 카메라를 기준점 기준으로 회전시키는 효과.
        */
        transform.eulerAngles += rotationVector * rotationSpeed * Time.deltaTime;
    }
}

/*GetKey = 키를 계속 누르고 있는 동안 신호가 계속 ON
→ "계속 달려!" 느낌

GetKeyDown = 버튼이 눌린 '찰나'만 감지
→ "점프해!" 느낌
*/
```

# 1️⃣ **Cinemachine 카메라를 Zoom하는 3가지 방식**

강의에서 말한 Zoom 방식 3가지를 먼저 정리하면 아래와 같아.

### **① Field of View(FOV) 줄이기 — FPS 카메라에서 흔함**

- 값이 작아질수록 줌인(Zoom In)
- 값이 커질수록 줌아웃(Zoom Out)

📌 하지만 _탑뷰 카메라에서는 어울리지 않음_

---

### **② Follow Offset에서 Y, Z를 함께 줄이기**

- Y ↓ → 카메라가 땅에 가까워짐
- Z ↑ → 카메라가 대상 뒤쪽으로 이동

📌 3D 공간에서 "카메라가 다가간다"는 느낌을 만들 수 있지만

조정 범위가 넓어서 관리하기 까다로움.

---

### **③ Follow Offset 중 ‘Y’ 값만 줄이기 (강의에서 최종 선택한 방식)**

➡️ **현재 카메라 위치에서 수직 높이만 조절**

장점:

- 줌할 때 “카메라가 대상 위‧아래로 오르락내리락하는” 느낌을 자연스럽게 연출
- 탑뷰 RTS에서 가장 일반적인 느낌

---

# 2️⃣ **문제: Follow Offset 값을 직접 접근할 수 없다**

처음 생각하는 방법은 이렇게 하고 싶겠지?

```csharp
cinemachineVirtualCamera.m_FollowOffset.y -= 1;
```

하지만 ❌ 불가능하다.

왜?

---

## ✔ Cinemachine 구조가 "컴포넌트를 쪼개놓은 방식"이기 때문

CinemachineVirtualCamera 안에는 여러 **CinemachineComponent**가 들어있음:

- Transposer
- Composer
- POV
- FramingTransposer
  등등…

이 중 **Follow Offset**은 `CinemachineTransposer` 안에 있음.

즉, 우리가 원하는 값은 여기 있음:

```
CinemachineVirtualCamera
 └── CinemachineTransposer
        └── m_FollowOffset (여기를 바꿔야 함)
```

그래서 먼저 이렇게 해야 한다:

```csharp
cinemachineTransposer = virtualCamera.GetCinemachineComponent<CinemachineTransposer>();
```

이제야 우리가 원하는 `"Follow Offset Y"`에 접근할 수 있는 것.

---

# 3️⃣ **Zoom 핵심 로직: FollowOffset.y 조절**

스크롤 입력을 받는다:

```csharp
Input.mouseScrollDelta.y
```

- +1 : 휠 위로 → 줌 인
- 1 : 휠 아래로 → 줌 아웃

그래서 코드로는:

```csharp
if (Input.mouseScrollDelta.y > 0)
    targetFollowOffset.y -= zoomAmount;
if (Input.mouseScrollDelta.y < 0)
    targetFollowOffset.y += zoomAmount;
```

---

# 4️⃣ **문제: 너무 갑작스럽게 변경됨 (Snappy)**

Follow Offset 값을 바로 바꾸면 줌이 **퍽!** 하고 즉시 바뀌어서 부드럽지 않다.

그래서 **보간(Lerp)으로 부드럽게 만든다**.

---

# 5️⃣ **Lerp를 이용한 부드러운 Zoom(Smoothed Zoom)**

현재 값 → 목표 값으로 부드럽게 이동시키는 방식

```csharp
cinemachineTransposer.m_FollowOffset =
    Vector3.Lerp(
        cinemachineTransposer.m_FollowOffset,
        targetFollowOffset,
        Time.deltaTime * zoomSpeed
    );
```

이러면 자연스럽게 카메라가 이동함.

---

# 6️⃣ **Clamp로 줌 범위 제한**

줌이 너무 많이 되면 바닥에 박히거나 너무 멀리 가는 문제가 있음.

그래서 최소~최대 값 제한.

```csharp
targetFollowOffset.y =
    Mathf.Clamp(targetFollowOffset.y, 2f, 12f);
```

---

# 7️⃣ **전체 흐름 요약**

카메라 줌을 구현하려면 흐름은 아래와 같아.

---

## ✔ 1단계: 스크롤 입력 감지

➡️ 얼마나 줌할지 결정

## ✔ 2단계: targetFollowOffset.y 변경

➡️ 즉시 바꾸지 않고 목표값을 설정

## ✔ 3단계: Clamp

➡️ 줌 한계를 설정

## ✔ 4단계: Lerp로 부드럽게 따라가기

➡️ 현재 FollowOffset이 targetFollowOffset으로 부드럽게 이동

## ✔ 5단계: Threshold로 미세한 떨림 제거

➡️ 거의 도달하면 딱 맞게 고정

---

# 8️⃣ 최종 코드가 말해주는 구조적 특징

전체 구조는 이렇게 되어 있어:

- Update()는 읽기 쉽도록 세 가지 동작만 호출

```csharp
HandleMovement();
HandleRotation();
HandleZoom();
```

- 줌은 "입력 → 목표값 설정 → 보간 적용" 순서로 이루어져 있음
- CinemachineTransposer를 가져온 후 offset을 조절함
- 갑작스런 변화 대신 Lerp로 부드럽게 변화시킴

---

# 💡 **이 기능 구현의 핵심 개념 요약 (초보자용)**

1. **CinemachineVirtualCamera 자체는 Offset 값을 가지고 있지 않다.**

   → 실제 값은 "CinemachineTransposer" 컴포넌트 안에 있음.

2. **스크롤 이동은 Input.mouseScrollDelta.y 로 감지한다.**
3. **줌은 FollowOffset.y 값을 늘렸다 줄였다 하며 구현할 수 있다.**
4. **바로 적용하면 너무 튀므로 Lerp로 부드럽게 이동시킨다.**
5. **줌 범위를 Clamp로 제한해야 한다.**
6. **줌은 “목표값(target)”을 설정하고 실제 카메라값은 천천히 따라가게 한다.**

# Camera Frustum 설명 📹

## 📌 한 줄 요약

**카메라가 보는 영역(시야)을 Scene 뷰에 시각적으로 표시하는 디버그 기능**

---

## 🎯 Camera Frustum이란?

### **Frustum = 절두체 (깎인 피라미드)**

```
        카메라
          📷
         /|\
        / | \
       /  |  \
      /   |   \
     /_________\  ← 이 영역이 화면에 보임

이 피라미드 모양 영역 = Frustum

```

**Show Camera Frustum 체크 시:**

- Scene 뷰에 노란색 선으로 카메라 시야 표시
- 이 선을 **매 프레임 그리는 작업**이 성능 소모
- 화면 모서리 떨림의 원인!

---

## 🔍 왜 떨림이 발생했나?

```
매 프레임마다:
1. 카메라 이동
2. Cinemachine 업데이트
3. Frustum 선 다시 그리기 ← 여기서 떨림!
4. 화면 렌더링

→ Frustum 그리기가 타이밍 충돌 유발

```

---

## 💡 언제 사용하나?

### **체크 ON (개발 중):**

- 카메라 범위 확인할 때
- 오브젝트가 화면에 보이는지 테스트
- 레벨 디자인 중

### **체크 OFF (실행/빌드):**

- 실제 플레이 시
- 성능 최적화 필요 시
- **떨림 해결 시** ✅

---

---

## ✅ 결론

- **개발 중**: 체크 ON (편리함)
- **플레이/빌드**: 체크 OFF (성능)
- **떨림 있으면**: 무조건 OFF! ✅

**이제 떨림 없이 부드럽게 작동합니다!** 🎉

## CameraController.cs

```csharp
using System.Collections;
using System.Collections.Generic;
using Cinemachine;
using UnityEngine;

public class CameraController : MonoBehaviour
{
    // 줌 가능한 최소/최대 높이 값
    // 카메라가 너무 땅속에 들어가거나, 너무 멀리 가지 않도록 제한하기 위해 사용
    private const float MIN_FOLLOW_OFFSET_Y = 2f;
    private const float MAX_FOLLOW_OFFSET_Y = 12f;

    // 인스펙터에서 연결할 Cinemachine Virtual Camera
    [SerializeField] private CinemachineVirtualCamera cinemachineVirtualCamera;

    // Virtual Camera 내부의 'Transposer' 컴포넌트를 저장할 변수
    // Follow Offset(카메라 거리/높이)을 조절할 때 필요
    private CinemachineTransposer cinemachineTransposer;

    // 목표로 하는 FollowOffset 값
    // 현재 값이 아니라, "카메라가 가야 하는 목표값"을 저장해두고
    // 부드럽게 Lerp로 이동시킬 때 사용함
    private Vector3 targetFollowOffset;

    // 줌 작업 중인지 판단하는 용도(지금은 사용되지 않지만 확장성용)
    private bool isZooming = false;

    private void Start()
    {
        // Virtual Camera에서 "CinemachineTransposer" 컴포넌트를 가져옴
        // FollowOffset은 Transposer 안에 있기 때문
        cinemachineTransposer = cinemachineVirtualCamera.GetCinemachineComponent<CinemachineTransposer>();

        // 현재 FollowOffset 값을 초기 목표값으로 설정
        // 처음엔 "지금 있는 위치로 유지"하도록 하는 과정
        targetFollowOffset = cinemachineTransposer.m_FollowOffset;
    }

    private void Update()
    {
        // 매 프레임마다 카메라 이동/회전/줌을 처리
        HandleMovement();
        HandleRotation();
        HandleZoom();
    }

    // ------------------------------
    // 1. 카메라 이동 처리 (WASD)
    // ------------------------------
    private void HandleMovement()
    {
        // 입력 벡터 (x=왼/오, z=앞/뒤)
        Vector3 inputMoveDir = new Vector3(0, 0, 0);

        // W : 앞으로 이동
        if (Input.GetKey(KeyCode.W))
        {
            inputMoveDir.z = +1;
        }
        // S : 뒤로 이동
        if (Input.GetKey(KeyCode.S))
        {
            inputMoveDir.z = -1;
        }
        // A : 왼쪽
        if (Input.GetKey(KeyCode.A))
        {
            inputMoveDir.x = -1;
        }
        // D : 오른쪽
        if (Input.GetKey(KeyCode.D))
        {
            inputMoveDir.x = +1;
        }

        // 이동 속도 (1초에 얼마나 움직일지)
        float moveSpeed = 10f;

        // 카메라가 바라보는 방향 기준으로 이동 방향을 만들어줌
        // transform.forward  : 카메라의 앞 방향
        // transform.right    : 카메라의 오른쪽 방향
        Vector3 moveVector =
            transform.forward * inputMoveDir.z +
            transform.right * inputMoveDir.x;

        // 실제 이동 적용
        transform.position += moveVector * moveSpeed * Time.deltaTime;
    }

    // ------------------------------
    // 2. 카메라 회전 처리 (Q,E)
    // ------------------------------
    private void HandleRotation()
    {
        // 회전 입력 벡터 (y축만 사용)
        Vector3 rotationVector = new Vector3(0, 0, 0);

        // Q : 왼쪽 회전
        if (Input.GetKey(KeyCode.Q))
        {
            rotationVector.y = -1;
        }
        // E : 오른쪽 회전
        if (Input.GetKey(KeyCode.E))
        {
            rotationVector.y = +1;
        }

        // 입력이 있을 때만 회전 실행
        if (rotationVector != Vector3.zero)
        {
            float rotationSpeed = 100f;

            // EulerAngles로 y축 회전을 변경
            transform.eulerAngles += rotationVector * rotationSpeed * Time.deltaTime;
        }
    }

    // ------------------------------
    // 3. 카메라 줌 처리 (마우스 휠)
    // ------------------------------
    private void HandleZoom()
    {
        // zoomAmount : 휠 한 칸에 얼마나 줌할지
        float zoomAmount = 1f;

        // 휠 위로 → 줌 인 (카메라 높이를 줄임)
        if (Input.mouseScrollDelta.y > 0)
        {
            targetFollowOffset.y -= zoomAmount;
        }
        // 휠 아래 → 줌 아웃 (카메라 높이를 늘림)
        if (Input.mouseScrollDelta.y < 0)
        {
            targetFollowOffset.y += zoomAmount;
        }

        // 줌 범위 제한(클램프)
        // 최소 2, 최대 12 사이에 머물도록 강제
        targetFollowOffset.y = Mathf.Clamp(targetFollowOffset.y,
                                           MIN_FOLLOW_OFFSET_Y,
                                           MAX_FOLLOW_OFFSET_Y);

        // Lerp를 이용하여 부드럽게 FollowOffset 변경
        float zoomSpeed = 5f;

        cinemachineTransposer.m_FollowOffset =
            Vector3.Lerp(
                cinemachineTransposer.m_FollowOffset, // 현재값
                targetFollowOffset,                   // 목표값
                Time.deltaTime * zoomSpeed            // 보간 속도
            );

        // Lerp만 쓸 경우 무한히 99.999%만 가까워지는 문제가 있어
        // 일정 거리 이하로 가까워지면 "그냥 목표값으로 스냅" 시킴
        float threshold = 0.01f;

        if (Vector3.Distance(cinemachineTransposer.m_FollowOffset, targetFollowOffset) < threshold)
        {
            cinemachineTransposer.m_FollowOffset = targetFollowOffset;
        }
    }
}

```
