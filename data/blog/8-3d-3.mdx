# { ⚙️ Character Movement 파라미터 조정 }

## 🎯 이번 강의 목표

Character Movement Component의 다양한 파라미터를 조정해서 원하는 게임 느낌을 만듭니다.
점프, 가속, 공중 제어, 경사면 등을 커스터마이징합니다.

---

## 🦘 점프 파라미터

### 1. Gravity Scale (중력 배율)

```
BP_Kicks
  ↓
CharacterMovement 선택
  ↓
Character Movement (Walking)
  ↓
Gravity Scale
```

**기본값: 1.0**

```
의미:
기본 중력의 몇 배로 떨어질지

값 증가:
  ├─ 2.0: 2배 빠르게 낙하
  ├─ 3.0: 3배 빠르게 낙하
  └─ 5.0: 5배 빠르게 낙하

효과:
더 빠른 낙하
  ↓
스타일화된 느낌
```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380754/notion-blog/_/_/_5_/_8_-_3D_-_3/image.png)

### 2. Jump Z Velocity (점프 속도)

```
Character Movement (Walking)
  ↓
Jump / Fall
  ↓
Jump Z Velocity
```

**기본값: 420**

```
단위: cm/s (센티미터/초)

값 증가:
  ├─ 600: 조금 높게
  ├─ 1200: 많이 높게
  ├─ 1600: 매우 높게
  └─ 1800: 아주 높게

⚠️ 주의:
1600 입력 시 자동으로 16m/s로 변환
  ↓
16미터/초 = 1600cm/초
  ↓
단위 변환 자동 처리
```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380753/notion-blog/_/_/_5_/_8_-_3D_-_3/image_1.png)

### 권장 조합 (스타일화된 게임)

```
Gravity Scale: 3~5
Jump Z Velocity: 1200~1800

효과:
  ├─ 높이 점프
  ├─ 빠른 낙하
  └─ 탱탱한 느낌 (마리오 스타일)
```

## 🏃 이동 파라미터

### 1. Max Acceleration (최대 가속도)

```
Character Movement (Walking)
  ↓
Max Acceleration
```

**기본값: 2048**

```
의미:
최대 속도까지 얼마나 빨리 가속하는가

낮은 값 (기본):
  └─ 부드러운 가속 (램프 업)
      W 누름 → 서서히 빨라짐

높은 값 (100,000):
  └─ 즉시 최대 속도
      W 누름 → 바로 최대 속도

```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380753/notion-blog/_/_/_5_/_8_-_3D_-_3/image_2.png)

**테스트**

```
100,000으로 설정
  ↓
Play → W 누름
  ↓
즉시 전속력 이동
  ↓
램프 없음
```

### 2. Ground Friction (지면 마찰)

```
Character Movement (Walking)
  ↓
Ground Friction
```

**기본값: 8.0**

```
의미:
멈출 때 얼마나 빨리 감속하는가

낮은 값:
  └─ 미끄러짐 (아이스 스케이트)

높은 값 (10):
  └─ 즉시 정지
```

### 3. Braking Friction Factor

```

  ↓
Braking Friction Factor
```

**기본값: 2.0**

```
의미:

Ground Friction과 함께 작동
  ↓
감속 속도 결정
```

## 🌬️ 공중 제어

### Air Control

```
Character Movement (Walking)
  ↓
Jump / Fall
  ↓
Air Control
```

**기본값: 0.05**

```
의미:
공중에서 방향 전환 가능 정도

값 범위: 0.0 ~ 1.0

0.0:
  └─ 공중 제어 불가
      점프 후 방향 못 바꿈

0.5:
  └─ 제한적 제어
      약간 방향 조정 가능

1.0:
  └─ 완전한 제어
      지면과 동일하게 조작
```

### 현실적 vs 스타일화

**현실적 (0.05~0.2)**

```
점프 후:
  └─ 방향 거의 못 바꿈
      현실 물리학과 유사

용도:
리얼리즘 중시 게임
```

**스타일화 (0.5~1.0)**

```
점프 후:
  └─ 자유롭게 방향 전환

장점:
  ├─ 절벽에서 점프 → 되돌아올 수 있음
  ├─ 공중 아이템 수집
  └─ 플랫포머 게임 느낌

⚠️ Max Acceleration도 높여야 함
   (안 그러면 느리게 반응)
```

### 권장 조합 (플랫포머)

```
Max Acceleration: 100,000
Air Control: 1.0

효과:
공중에서 즉시 방향 전환 가능
```

### 1. Max Step Height (최대 계단 높이)

```
Character Movement (Walking)
  ↓
Max Step Height
```

**기본값: 45cm**

```
의미:
점프 없이 올라갈 수 있는 최대 높이

45cm 이하:
  └─ 자동으로 걸어 올라감

45cm 초과:
  └─ 점프 필요
```

**테스트**

```

  ├─ Modeling Mode
  ├─ Box 선택
  ├─ Height: 45
  └─ Accept

Max Step Height: 45
  └─ 박스 위로 걸어 올라감 ✅

Max Step Height: 42
  └─ 박스 못 올라감 ❌
      (점프 필요)

Max Step Height: 100
  └─ 100cm까지 올라감 ✅
```

### 2. Walkable Floor Angle (걷기 가능한 바닥 각도)

```
Character Movement (Walking)
  ↓
Walkable Floor Angle
```

**기본값: 44.76° (약 45°)**

```
의미:
몇 도 경사까지 걸어 올라갈 수 있는가

45° 미만:
  └─ 걸어서 올라감

45° 이상:
  └─ 미끄러짐 (못 올라감)
```

**테스트**

```
45° 경사면 생성:
  ├─ Box 크기 조정
  ├─ Rotation Z: 45°
  └─ 배치

Walkable Floor Angle: 44.76
  └─ 45° 경사 못 올라감 ❌

Walkable Floor Angle: 50
  └─ 45° 경사 올라감 ✅

Walkable Floor Angle: 90
  └─ 벽도 올라감 (부자연스러움)
```

**권장값**

```
일반 게임: 44~50°
  └─ 현실적인 느낌

특수 게임: 더 높게
  └─ 벽 타기 등
```

## 💡 조정 팁

### 1. 반복 테스트

```
파라미터 변경
  ↓
Play 테스트
  ↓
느낌 확인
  ↓
다시 조정
  ↓
반복

완벽한 값은 테스트로만 찾을 수 있음
```

### 2. 한 번에 하나씩

```
❌ 여러 개 동시 변경:
   어떤 게 영향 주는지 모름

✅ 하나씩 변경:
   효과 명확히 파악
```

### 3. 기본값 기억

```
테스트 전:
기본값 메모 또는 스크린샷

Reset 버튼:
  └─ 파라미터 옆 곡선 화살표
      기본값으로 복구
```

### 4. 게임 장르에 맞게

```
플랫포머:
  └─ 높은 점프, 강한 제어

슈팅:
  └─ 빠른 반응, 현실적 중력

  └─ 적당한 균형
```

# { 🔄 연속 점프와 State Alias }

## 🎯 이번 강의 목표

점프 버튼을 누르고 있으면 연속으로 점프하도록 만듭니다.
State Alias를 사용해 State Machine을 깔끔하게 정리합니다.

---

## 🦘 현재 점프의 문제점

### Started vs Triggered

**현재 설정 (Started)**

```
BP_KicksPlayerController

IA Jump (Started)
  ↓
Jump 함수 호출

동작:
스페이스바 누르는 순간 1번만
  ↓
누르고 있어도 1번만 점프
  ↓
다시 점프하려면:
  └─ 버튼 떼기 → 다시 누르기
```

**Triggered로 변경**

```
IA Jump (Triggered)
  ↓
Jump 함수 호출

동작:
누르고 있는 동안 계속 호출
  ↓
매 프레임 Jump 함수 실행
  ↓
연속 점프!
```

---

## 🎬 연속 점프 애니메이션 문제

### 문제 발생

```
점프 버튼 계속 누름
  ↓
Jump 함수 계속 호출
  ↓
연속으로 점프함

하지만 애니메이션:
JumpEnd → IdleWalkRun → JumpStart
  ↓
착지 애니메이션 전부 재생
  ↓
다시 점프 시작 재생
  ↓
부자연스러움!
```

**원하는 것**

```
착지 직후 다시 점프하면
  ↓
JumpEnd 스킵
  ↓
바로 JumpStart로
  ↓
자연스러운 연속 점프
```

---

## 🔧 해결: JumpEnd → JumpStart 전환

### 새 Transition 추가

**State Machine (Locomotion)**

```
JumpEnd에서 드래그
  ↓
JumpStart로 연결
  ↓
새 화살표 생성
```

**Transition Rule**

```
화살표 더블클릭
  ↓
[GET Is In Air] → [Result]

의미:
JumpEnd 중에 다시 공중으로 올라가면
  (= 연속 점프)
  ↓
JumpStart로 즉시 전환
```

### 결과

```
연속 점프:

1번 점프:
IdleWalkRun → JumpStart → JumpMid → JumpEnd

착지 중 2번 점프:
JumpEnd → JumpStart (바로!)
  ↓
착지 애니메이션 스킵
  ↓
자연스러운 연속 점프
```

## 🎨 State Alias - 깔끔한 정리

### 문제: 중복 화살표

```
현재 State Machine:

IdleWalkRun → JumpStart (Is In Air)
JumpEnd → JumpStart (Is In Air)

2개 화살표
  ↓
같은 목적지 (JumpStart)
  ↓
같은 조건 (Is In Air)
  ↓
중복!
```

**복잡해지는 경우**

```
State가 많아지면:
  ├─ State1 → JumpStart
  ├─ State2 → JumpStart
  ├─ State3 → JumpStart
  └─ ...

화살표가 너무 많음
  ↓
복잡하고 지저분
```

---

## 🔖 State Alias란?

### 정의

```
State Alias (상태 별칭):
여러 State에서 하나의 State로
가는 전환을 묶어주는 기능

비유:
"JumpStart로 가는 관문"
```

### 작동 원리

```
일반 방식:
State A → State X
State B → State X
State C → State X

State Alias 방식:
State A ┐
State B ├→ [Alias] → State X
State C ┘

화살표 3개 → 1개
```

## 🔄 Before & After

### Before (기존 방식)

```
State Machine:

IdleWalkRun ─────→ JumpStart
                   ↑
JumpEnd ───────────┘

화살표 2개
각각 Transition Rule 필요
```

### After (State Alias 사용)

```
State Machine:

IdleWalkRun ┐
            ├→ [To Jump Start] → JumpStart
JumpEnd ────┘

화살표 1개 (Alias 화살표)
Transition Rule 1개만
```

---

## 💡 State Alias의 장점

### 1. 깔끔한 시각화

```
Before:
화살표가 많음
  ↓
복잡하고 지저분

After:
Alias로 묶음
  ↓
깔끔하고 명확
```

### 2. 유지보수 용이

```
조건 변경 시:

Before:
모든 Transition Rule 수정
  ├─ IdleWalkRun → JumpStart
  ├─ JumpEnd → JumpStart
  └─ ... 각각 수정

After:
Alias Transition Rule 1개만 수정
  ↓
한 번에 모두 적용
```

### 3. 확장성

```
새 State 추가 시:

Before:
새 화살표 그리기
  ↓
Transition Rule 새로 작성

After:
Alias 설정에서 체크만
  ↓
자동으로 연결
```

## 🎨 State Alias 고급 기능

### 여러 Transition Rule

```
Alias에서 여러 화살표 가능:

[To Jump Start] → JumpStart (조건 1)
[To Jump Start] → IdleWalkRun (조건 2)

하지만 복잡해지므로
  ↓
가급적 단순하게 유지
```

### 양방향 Alias

```
To Jump Start (들어오기)
From Jump Start (나가기)

둘 다 만들 수 있음
```

## 🔍 전체 흐름 정리

### 연속 점프 시나리오

```
1. 첫 점프
   IdleWalkRun → JumpStart → JumpMid → JumpEnd

2. 착지 직전 스페이스바 계속 누름
   JumpEnd 중 Is In Air = True
   ↓

3. Alias 작동
   JumpEnd → [To Jump Start] → JumpStart
   ↓

4. 즉시 다시 점프
   JumpStart → JumpMid → JumpEnd

5. 반복 가능
```

### State Machine 구조

```
Entry → IdleWalkRun
         ↓ (Is In Air)
      [To Jump Start] ─→ JumpStart
         ↑ (Is In Air)     ↓ (애니메이션 끝)
      JumpEnd ←─── JumpMid
         ↓ (NOT Is In Air)
      IdleWalkRun
```

## ⚠️ 주의사항

### Started vs Triggered 선택

```
Started (권장):
  ├─ 버튼 1번 누름 = 1번 점프
  └─ 의도적인 점프

Triggered:
  ├─ 버튼 누르고 있음 = 계속 점프
  └─ 연속 점프 (튀어오르기)

게임 디자인에 따라 선택
```

### State Alias 남용 주의

```
❌ 모든 전환에 Alias 사용:
   오히려 복잡해짐

✅ 중복되는 전환만 사용:
   같은 목적지 + 같은 조건

원칙:
간단할 때는 직접 연결
복잡할 때만 Alias
```

### Transition Rule 공유

```
Alias의 Transition Rule:
  └─ 모든 출발 State에 적용

다른 조건 필요하면:
  └─ Alias 사용 안 함
      개별 전환 사용
```
