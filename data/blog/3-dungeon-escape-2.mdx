# { 언리얼 수학 라이브러리와 부드러운 움직임 구현 }

## 1. 전체 시스템 설계

### 움직임 로직 개요

```
StartLocation (시작 위치)
    +
MoveOffset (이동 거리)
    =
TargetLocation (목표 위치)
    ↓
VInterpConstantTo() 함수로 부드럽게 이동
    ↓
목표 도달 시 자동 정지
```

---

## 2. 필요한 변수 선언

### Mover.h

```cpp
UCLASS(ClassGroup=(Custom), meta=(BlueprintSpawnableComponent))
class DUNGEONESCAPE_API UMover : public UActorComponent
{
    GENERATED_BODY()

private:
    // 일반 멤버 변수 (코드에서만 사용)
    FVector StartLocation;      // 시작 위치
    FVector TargetLocation;     // 목표 위치

    // UPROPERTY 변수 (에디터에서 수정 가능)
    UPROPERTY(EditAnywhere)
    FVector MoveOffset;         // 이동 오프셋 (거리와 방향)

    UPROPERTY(EditAnywhere)
    float MoveTime = 4.0f;      // 이동 시간 (초)

    UPROPERTY(EditAnywhere)
    bool ShouldMove = false;    // 움직일지 여부
};
```

### 변수 설명

**StartLocation**:

- 액터의 시작 위치
- BeginPlay에서 한 번만 저장
- 에디터 노출 불필요

**TargetLocation**:

- 최종 도착 위치
- `StartLocation + MoveOffset`으로 계산
- 에디터 노출 불필요

**MoveOffset** (UPROPERTY):

- **이동 거리와 방향**을 정의
- 예: `(0, 0, 150)` = Z축으로 150cm 위로
- **에디터에서 조정 가능** ✅

**MoveTime** (UPROPERTY):

- 목표까지 도달하는 **시간 (초 단위)**
- 기본값: 4초
- **에디터에서 조정 가능** ✅

**ShouldMove** (UPROPERTY):

- 움직임 **켜기/끄기** 스위치
- 기본값: false (정지 상태)
- **게임 실행 중 실시간 토글 가능** ✅

## 6. VInterpConstantTo() 함수

### 헤더 파일 포함

```cpp
#include "Mover.h"
#include "Math/UnrealMathUtility.h"  // FMath 함수 사용
```

**Include 지시문**:

- 다른 파일의 코드를 **현재 파일에 붙여넣기**
- `#include "Mover.h"` → Mover.h의 내용을 여기 붙여넣음
- `#include "Math/UnrealMathUtility.h"` → FMath 클래스 사용 가능

### 함수 시그니처

```cpp
static FVector VInterpConstantTo(
    const FVector& Current,      // 현재 위치
    const FVector& Target,       // 목표 위치
    float DeltaTime,             // 델타 타임
    float InterpSpeed            // 이동 속도 (cm/s)
);
```

**파라미터 설명**:

| 파라미터        | 타입    | 설명                  |
| --------------- | ------- | --------------------- |
| **Current**     | FVector | 현재 위치             |
| **Target**      | FVector | 목표 위치             |
| **DeltaTime**   | float   | 프레임 간 경과 시간   |
| **InterpSpeed** | float   | 초당 이동 속도 (cm/s) |

**반환값**:

- **FVector** - 새로운 위치

### 함수 특징

**"Constant" (일정한) 의미**:

- 일정한 **속도**로 이동
- 가속/감속 없음
- 선형적(직선적) 움직임

**"To" (향해) 의미**:

- 목표 **지점까지만** 이동
- 목표 도달 시 **자동 정지**
- 목표를 넘어가지 않음

## 7. 속도 계산하기

### 공식

```cpp
float Speed = MoveOffset.Length() / MoveTime;
```

**수학 공식**:

```
속도 = 거리 / 시간
Speed = Distance / Time
```

### 계산 예시

```cpp
MoveOffset = (0, 0, 150)      // Z축 150cm
MoveTime = 4.0f               // 4초

// Length() = 벡터의 길이(크기)
Distance = MoveOffset.Length() = 150.0f

// 속도 계산
Speed = 150.0f / 4.0f = 37.5 cm/s
```

### Length() 함수

```cpp
FVector MyVector(3, 4, 0);
float Length = MyVector.Length();  // 5.0

// 피타고라스 정리: √(3² + 4²) = √25 = 5
```

**3D 공간**:

```cpp
FVector MoveOffset(10, 20, 30);
float Length = MoveOffset.Length();
// √(10² + 20² + 30²) = √1400 ≈ 37.42
```

## 8. 완성된 이동 코드

### Tick 함수

```cpp
void UMover::TickComponent(float DeltaTime, ...)
{
    Super::TickComponent(DeltaTime, ...);

    if (ShouldMove)
    {
        // 1. 현재 위치 가져오기
        FVector CurrentLocation = GetOwner()->GetActorLocation();

        // 2. 속도 계산
        float Speed = MoveOffset.Length() / MoveTime;

        // 3. 새 위치 계산 (부드러운 이동)
        FVector NewLocation = FMath::VInterpConstantTo(
            CurrentLocation,  // 현재 위치
            TargetLocation,   // 목표 위치
            DeltaTime,        // 델타 타임
            Speed             // 속도
        );

        // 4. 새 위치 적용
        GetOwner()->SetActorLocation(NewLocation);
    }
}
```

## 9. 동작 방식 상세 분석

### 프레임별 동작

**초기 상태**:

```
CurrentLocation = (70, 45, 135)
TargetLocation = (70, 45, 285)
Speed = 37.5 cm/s
```

**프레임 1 (DeltaTime = 0.0167초, 60 FPS)**:

```
이동 거리 = 37.5 * 0.0167 = 0.626cm
NewLocation = (70, 45, 135.626)
```

**프레임 2**:

```
CurrentLocation = (70, 45, 135.626)
이동 거리 = 37.5 * 0.0167 = 0.626cm
NewLocation = (70, 45, 136.252)
```

**4초 후 (약 240 프레임)**:

```
NewLocation = (70, 45, 285) ← 목표 도달!
VInterpConstantTo()가 자동으로 정지
```

### VInterpConstantTo의 내부 로직 (의사코드)

```cpp
FVector VInterpConstantTo(Current, Target, DeltaTime, Speed)
{
    // 1. 방향 벡터 계산
    FVector Direction = Target - Current;
    float Distance = Direction.Length();

    // 2. 이번 프레임 이동 거리
    float MaxDistance = Speed * DeltaTime;

    // 3. 목표 도달 체크
    if (Distance <= MaxDistance)
    {
        return Target;  // 목표 도달 - 정확히 목표 위치 반환
    }
    else
    {
        // 아직 목표 미도달 - 조금씩 이동
        Direction.Normalize();  // 단위 벡터로 변환
        return Current + Direction * MaxDistance;
    }
}
```

## 목표

**ShouldMove 값에 따라 양방향 이동**

- `ShouldMove = true` → 목표 위치로 이동
- `ShouldMove = false` → 시작 위치로 복귀

---

## 1. 동작 원리

### 기존 방식 (문제점)

```cpp
if (ShouldMove)
{
    // 이동 코드
}
// ShouldMove = false면 아무것도 안 함 (멈춤)
```

### 새로운 방식 (개선)

```cpp
if (ShouldMove)
{
    TargetLocation = StartLocation + MoveOffset;  // 목표로 이동
}
else
{
    TargetLocation = StartLocation;  // 시작점으로 복귀
}

// 항상 TargetLocation으로 이동 (방향만 바뀜)
```

## 6. 현재 코드의 문제점 (인정된 결함)

### 문제 1: 매 프레임 TargetLocation 재계산

```cpp
// 매 프레임마다 실행됨 (비효율적)
if (ShouldMove)
{
    TargetLocation = StartLocation + MoveOffset;
}
```

**문제점**:

- ShouldMove가 변하지 않아도 계속 재계산
- 불필요한 연산

**해결 예정**: 다음 강의에서 개선

### 문제 2: 목표 도달 후에도 계속 이동 시도

```cpp
// 목표에 도달해도 계속 실행
FVector NewLocation = FMath::VInterpConstantTo(...);
GetOwner()->SetActorLocation(NewLocation);
```

**문제점**:

- 목표 위치에 있어도 매 프레임 계산
- SetActorLocation() 계속 호출

## 2. 해결 방법: 벡터 비교

### Equals() 함수

```cpp
bool FVector::Equals(const FVector& V, float Tolerance = KINDA_SMALL_NUMBER) const;
```

**기능**:

- 두 벡터가 **거의 같은지** 비교
- 정확히 같지 않아도 허용 오차 내면 `true`
- 부동소수점 오차 고려

**사용법**:

```cpp
FVector A(100, 200, 300);
FVector B(100, 200, 300);

bool IsSame = A.Equals(B);  // true
```

### 왜 == 대신 Equals()?

```cpp
// ❌ 부동소수점 문제
FVector A(100.0f, 200.0f, 300.0f);
FVector B(100.0000001f, 200.0f, 300.0f);

A == B;        // false (정확히 다름)
A.Equals(B);   // true (허용 오차 내)
```

**부동소수점 연산의 특성**:

- 계산 과정에서 미세한 오차 발생
- `Equals()`는 이를 고려한 비교

## 3. ReachedTarget 변수 추가

### Mover.h

```cpp
UCLASS()
class DUNGEONESCAPE_API UMover : public UActorComponent
{
    GENERATED_BODY()

private:
    FVector StartLocation;
    FVector TargetLocation;

    UPROPERTY(EditAnywhere)
    FVector MoveOffset;

    UPROPERTY(EditAnywhere)
    float MoveTime = 4.0f;

    UPROPERTY(EditAnywhere)
    bool ShouldMove = false;

    // 새로 추가: 목표 도달 여부
    UPROPERTY(VisibleAnywhere)
    bool ReachedTarget = false;
};
```

### UPROPERTY 옵션 비교

| 옵션                  | 읽기 | 쓰기 | 용도                   |
| --------------------- | ---- | ---- | ---------------------- |
| **EditAnywhere**      | ✅   | ✅   | 에디터에서 수정 가능   |
| **VisibleAnywhere**   | ✅   | ❌   | 에디터에서 읽기만 가능 |
| **BlueprintReadOnly** | ✅   | ❌   | Blueprint에서 읽기만   |

**ReachedTarget은 VisibleAnywhere**:

- 코드에서만 값 변경
- 에디터에서는 확인만 가능
- 디버깅에 유용

## 4. 완성된 코드

### TickComponent() 전체

```cpp
void UMover::TickComponent(float DeltaTime, ...)
{
    Super::TickComponent(DeltaTime, ...);

    // 1. 목표 위치 설정
    if (ShouldMove)
    {
        TargetLocation = StartLocation + MoveOffset;
    }
    else
    {
        TargetLocation = StartLocation;
    }

    // 2. 현재 위치와 목표 위치 비교
    FVector CurrentLocation = GetOwner()->GetActorLocation();
    ReachedTarget = CurrentLocation.Equals(TargetLocation);

    // 3. 목표 미도달 시에만 이동
    if (ReachedTarget == false)  // 또는 if (!ReachedTarget)
    {
        float Speed = MoveOffset.Length() / MoveTime;
        FVector NewLocation = FMath::VInterpConstantTo(
            CurrentLocation, TargetLocation, DeltaTime, Speed
        );
        GetOwner()->SetActorLocation(NewLocation);
    }
}
```

# { 논리 NOT 연산자 (!) - 코드 간결화 }

## 논리 NOT 연산자란?

**기호**: `!` (느낌표)

**기능**: 표현식의 결과를 **반전**시킴

- `true` → `false`
- `false` → `true`

---

## 기본 예제

```cpp
// 1. 리터럴 값
!true    // false
!false   // true

// 2. 비교 연산
!(8 < 7)   // false를 반전 → true
!(10 > 9)  // true를 반전 → false

// 3. 변수
bool IsAlive = false;
!IsAlive   // true
```

**읽는 방법**: "~가 아니다"

- `!IsAlive` = "IsAlive가 아니다"
- `!ReachedTarget` = "ReachedTarget이 아니다"

---

## 코드 개선 적용

### 변경 전 (길고 명시적)

```cpp
if (ReachedTarget == false)
{
    // 이동 코드
}
```

### 변경 후 (간결하고 관용적) ✅

```cpp
if (!ReachedTarget)
{
    // 이동 코드
}
```

**의미**:

- "목표에 도달하지 않았다면"
- "ReachedTarget이 false라면"

# { C++ 언리얼 프로젝트 컴파일 과정 }

## 컴파일이란?

**사람이 읽는 코드 → 컴퓨터가 실행하는 프로그램**

```
C++ 코드 (.cpp, .h)
    ↓ 컴파일
실행 파일 (.exe)
```

---

## 전체 컴파일 단계

### 언리얼 C++ 프로젝트의 컴파일 흐름

```
1. 소스 코드 (.cpp, .h)
    ↓
2. Unreal Header Tool (언리얼 전용)
    ↓
3. Preprocessor (전처리기)
    ↓
4. Compiler (컴파일러)
    ↓
5. Linker (링커)
    ↓
6. 실행 파일 (.exe)
```

---

## 1단계: 소스 코드

### 우리가 작성하는 파일들

```cpp
// Mover.h (헤더 파일)
class UMover : public UActorComponent
{
    // 선언
};

// Mover.cpp (소스 파일)
#include "Mover.h"

void UMover::BeginPlay()
{
    // 구현
}
```

---

## 2단계: Unreal Header Tool (언리얼 전용)

### 역할

**언리얼 특수 구문을 처리하여 추가 코드 생성**

### 언리얼 특수 구문 예시

```cpp
UCLASS()                          // 언리얼 매크로
class DUNGEONESCAPE_API UMover    // 언리얼 API 키워드
{
    GENERATED_BODY()              // 언리얼 매크로

    UPROPERTY(EditAnywhere)       // 언리얼 매크로
    FVector MoveOffset;
};
```

**처리 결과**:

- 이 구문들을 분석
- C++과 언리얼 엔진을 연결하는 추가 코드 생성
- 에디터와의 통신 가능하게 함

---

## 3단계: Preprocessor (전처리기)

### 역할

**`#`으로 시작하는 지시어 처리**

### 주요 전처리기 지시어

```cpp
#include "Mover.h"                    // 파일 포함
#include "Math/UnrealMathUtility.h"   // 파일 포함
#define MAX_PLAYERS 4                 // 상수 정의
#if DEBUG                             // 조건부 컴파일
#endif
```

### #include의 작동 방식

**처리 전**:

```cpp
// Game.cpp
#include "Math.h"

void MyGame()
{
    Add(1, 2);
}
```

**처리 후** (중간 파일 .i):

```cpp
// Game.i
// Math.h의 내용이 여기 복사됨
int Add(int a, int b);  // ← Math.h에서 복사

void MyGame()
{
    Add(1, 2);
}
```

**핵심**:

- `#include`는 **파일 내용을 복사-붙여넣기**
- 헤더 파일의 모든 내용이 cpp 파일로 들어감

---

## 4단계: Compiler (컴파일러)

### 역할

**C++ 코드 → 기계어(바이너리 코드)로 변환**

```
Game.i (사람이 읽을 수 있는 코드)
    ↓ 컴파일러
Game.o (기계어, 0과 1)
```

### 각 .cpp 파일마다 .o 파일 생성

```
Mover.cpp → Mover.o
Character.cpp → Character.o
GameMode.cpp → GameMode.o
```

**아직 실행 불가**: 파일들이 분리되어 있음

---

## 5단계: Linker (링커)

### 역할

**여러 .o 파일들을 하나의 실행 파일로 연결**

```
Mover.o
Character.o      → [Linker] → Game.exe
GameMode.o
```

### 링커가 하는 중요한 일

**함수 호출 연결**:

```cpp
// Game.cpp에서
Add(1, 2);  // Add 함수 호출

// Math.cpp에 정의됨
int Add(int a, int b) { return a + b; }

→ 링커가 이 둘을 연결!
```


**Math.cpp** (정의):

```cpp
void MyGame()
{
    int Result = Add(1, 2);  // 3
}
```

### 컴파일 과정

**1. 전처리기**:

Game.cpp → Game.i

```cpp
// Math.h 내용 복사됨
int Add(int a, int b);

void MyGame()
{
    int Result = Add(1, 2);
}
```

Math.cpp → Math.i

```cpp
int Add(int a, int b);

int Add(int a, int b)
{
    return a + b;
}
```

**2. 컴파일러**:

```
Game.i → Game.o (기계어)
Math.i → Math.o (기계어)
```

**3. 링커**:

- Game.o에서 `Add()` 호출 발견
- Math.o에서 `Add()` 정의 발견
- 둘을 연결!
- Game.exe 생성

## 왜 #include가 필요한가?

### 실험: #include 제거

**Mover.cpp에서**:

```cpp
// #include "Mover.h"  ← 주석 처리!

void UMover::BeginPlay()
{
    // ...
}
```

### 컴파일 에러 발생

```
Error: 'UMover' is not a class
Error: 'UMover' undeclared identifier
Error: missing type specifier
```

**이유**:

- 컴파일러가 `UMover`가 무엇인지 모름
- 헤더 파일에 클래스 선언이 있는데 포함 안 함
- 선언 없이 정의할 수 없음

### 올바른 방법

```cpp
#include "Mover.h"  // ✅ 필수!

void UMover::BeginPlay()
{
    // 이제 컴파일러가 UMover가 뭔지 알아요
}
```

## 헤더 파일 (.h) vs 소스 파일 (.cpp)

### 헤더 파일 (.h)

**역할**: **선언** (Declaration)

- "이런 것이 있다"고 알림
- 함수 시그니처
- 클래스 구조

```cpp
// Math.h
int Add(int a, int b);  // 선언만

class UMover  // 클래스 구조
{
    void BeginPlay();  // 선언만
};
```

### 소스 파일 (.cpp)

**역할**: **정의/구현** (Definition)

- 실제로 어떻게 동작하는지
- 함수 본문
- 실제 코드

```cpp
// Math.cpp
int Add(int a, int b)  // 정의
{
    return a + b;  // 실제 구현
}

// Mover.cpp
void UMover::BeginPlay()  // 정의
{
    StartLocation = GetOwner()->GetActorLocation();
}
```

```
Mover.cpp 수정
    ↓
Mover.cpp만 재컴파일  // 빠름!
    ↓
다른 파일은 그대로
    ↓
링커로 다시 연결
```

## 언리얼에서의 실전 예제

### 우리 프로젝트의 include

```cpp
// Mover.cpp
#include "Mover.h"                    // 1. 자기 자신의 헤더
#include "Math/UnrealMathUtility.h"   // 2. FMath 사용 위해
```

**왜 필요?**

1. `#include "Mover.h"`:
   - `UMover` 클래스가 뭔지 알려줌
   - 이거 없으면 컴파일 에러!
2. `#include "Math/UnrealMathUtility.h"`:
   - `FMath::VInterpConstantTo()` 사용 가능
   - 이거 없으면 `FMath`를 모름

## 컴파일 흐름 요약

### 단계별 변화


## 핵심 정리

### 1. 컴파일 = 번역 과정

```
사람 언어(C++) → 컴퓨터 언어(기계어)
```

### 2. 주요 도구들

- **Unreal Header Tool**: 언리얼 구문 처리
- **Preprocessor**: `#include` 등 처리
- **Compiler**: C++ → 기계어
- **Linker**: 파일들 연결

### 3. #include의 역할

```cpp
#include "Mover.h"  // 헤더 내용을 여기 복사-붙여넣기
```

### 4. 헤더 vs 소스

- **.h**: 선언 (무엇이 있는지)
- **.cpp**: 정의 (어떻게 동작하는지)

### 5. 왜 분리?

- 재사용성
- 빠른 컴파일
- 코드 구조화
