# { 충돌 애니메이션 }

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380501/notion-blog/_/Game_Development_in_JS_TS_-_The_Complete_Guide_w_/_3_Dino_Game_Clone_-_4_-/image.png)

## 1. **플레이어 충돌 시 처리**

```jsx
플레이어가 장애물과 충돌하면 게임이 멈추고 텍스처를 변경해야 합니다.

player.die() 함수는 애니메이션을 멈추고, 플레이어의 텍스처를 dino-hurt로 변경합니다.
```

### PlayScene.ts

```jsx
this.physics.add.collider(this.obstacles, this.player, () => {
  this.physics.pause() // 물리 엔진 멈춤
  this.isGameRunning = false // 게임 중단 상태 설정
  this.player.die() // 플레이어 애니메이션 정지 및 텍스처 변경

  // 게임 초기화 준비
  this.spawnTime = 0
  this.gameSpeed = 5
})
```

### Player.ts

```jsx
die() {
    this.anims.pause(); // 애니메이션 멈춤
    this.setTexture('dino-hurt'); // '게임 오버' 상태를 나타내는 텍스처로 변경
}
```

## 2. **게임 속도 및 스폰 시간 초기화**

```jsx
게임이 종료되었을 때 gameSpeed와 spawnTime을 초기값으로 재설정하여

게임이 처음 상태로 돌아가도록 합니다.

추후 게임 진행에 따라 게임 속도를 증가시키는 로직을 구현할 계획입니다.
```

### PlayScene.ts

```jsx
this.spawnTime = 0 // 장애물 스폰 간격 초기화
this.gameSpeed = 5 // 게임 속도 초기화
```

## 3. **애니메이션 멈춤 및 텍스처 변경 로직**

```jsx
플레이어의 die() 함수에서 애니메이션이 멈추고,

setTexture를 호출해 새로운 이미지(텍스처)를 설정합니다.
```

### Player.ts

```jsx
die() {
    this.anims.pause(); // 현재 실행 중인 애니메이션 멈춤
    this.setTexture('dino-hurt'); // 'dino-hurt' 텍스처 설정
}
```

## 4. **PreloadScene에서 이미지 로드**

```jsx
PreloadScene은 게임 실행 전에 필요한 리소스(이미지, 애니메이션 등)를 미리 로드합니다.

dino-hurt 텍스처를 포함하여 모든 텍스처를 로드합니다.
```

### PreloadScene.ts

```jsx
this.load.image('dino-hurt', 'assets/dino-hurt.png') // 게임 종료 텍스처
this.load.image('ground', 'assets/ground.png') // 바닥 이미지
this.load.spritesheet('dino-run', 'assets/dino-run.png', {
  frameWidth: 88,
  frameHeight: 94,
}) // 달리기 애니메이션 스프라이트
```

## **게임 오버 화면 생성하기** (Play Scene)

```jsx
1) 변수 선언

		PlayScene 클래스에서 게임 오버 화면과 관련된 변수를 선언합니다.

				gameOverContainer: Phaser.GameObjects.Container;

2) 이미지 생성 및 컨테이너 추가

		create 함수에서 이미지를 생성하고 컨테이너로 묶어 화면 중앙에 배치합니다.


				create() {
			    // 게임 오버 텍스트와 재시작 버튼 생성
			    this.gameOverText = this.add.image(0, 0, 'game-over');
			    this.restartText = this.add.image(0, 80, 'restart');

			    // 컨테이너 생성 및 이미지 추가
			    this.gameOverContainer = this.add
			        .container(this.gameWidth / 2, (this.gameHeight / 2) - 50)
			        .add([this.gameOverText, this.restartText]);

			    // 컨테이너 숨기기 (게임 시작 시)
			    this.gameOverContainer.setVisible(false); // 이거 말고 setAlpha(0) 로 숨겨두는것도 가능하다
				}

3) 충돌 처리

		플레이어가 장애물과 충돌하면 게임 오버 화면을 표시하고 게임을 멈춥니다.

				this.physics.add.collider(this.obstacles, this.player, () => {
			    this.physics.pause(); // 게임 멈춤
			    this.isGameRunning = false; // 게임 상태 변경
			    this.gameOverContainer.setVisible(true); // 게임 오버 화면 표시
			    this.player.die(); // 플레이어 사망 애니메이션
				});

```

## 1. **초기 상태에서 게임 오버 UI 숨기기**

```jsx
강의에서는 gameOverContainer라는 컨테이너(Phaser.GameObjects.Container)를 사용해

게임 오버 텍스트와 재시작 버튼을 묶어 관리합니다. 이 컨테이너를 생성한 후,

기본적으로 보이지 않도록 setAlpha(0)를 사용해 투명하게 만듭니다.
```

```jsx
this.gameOverContainer = this.add
  .container(this.gameWidth / 2, this.gameHeight / 2 - 50)
  .add([this.gameOverText, this.restartText])
  .setAlpha(0)
```

```jsx
setAlpha(0)는 화면에서 투명도를 설정하는 기능입니다.

Phaser에서 Alpha는 물체가 얼마나 투명한지(또는 불투명한지)를 나타내는 값입니다.

		setAlpha(0): 완전히 투명하게 만듭니다. 화면에 보이지 않게 됩니다.
		setAlpha(1): 완전히 불투명하게 만듭니다. 화면에 정상적으로 보입니다.
		setAlpha(0.5)처럼 0과 1 사이 값을 사용하면 반투명 효과를 줄 수 있습니다.
```

## 2. **장애물과 충돌 시 게임 오버 UI 표시**

```jsx
create 메서드에서 obstacles와 player 간 충돌 이벤트를 설정했습니다.

플레이어가 장애물과 충돌하면 게임이 종료되며, 이때 gameOverContainer를 표시합니다.
```

```jsx
this.physics.add.collider(this.obstacles, this.player, () => {
  this.physics.pause() // 물리 시뮬레이션 중지
  this.isGameRunning = false // 게임 실행 상태 비활성화

  this.player.die() // 플레이어의 사망 처리
  this.gameOverContainer.setAlpha(1) // 게임 오버 UI 표시
  this.spawnTime = 0 // 장애물 스폰 타이머 초기화
  this.gameSpeed = 5 // 게임 속도 초기화
})
```

```jsx
this.physics.pause(): 물리 시뮬레이션을 멈춥니다.

this.isGameRunning = false: 게임의 실행 상태를 false로 설정합니다.

this.player.die(): 플레이어의 죽음에 대한 애니메이션이나 효과를 처리합니다.

this.gameOverContainer.setAlpha(1): 숨겨져 있던 게임 오버 UI를 화면에 표시합니다.
```

## 1. **`create` 메서드 구조 개선**

```jsx
create 메서드에 너무 많은 기능이 몰려 있어 가독성이 떨어지고 관리가 어렵다는 문제가 제기되었습니다.

이를 해결하기 위해 주요 기능을 별도의 메서드로 분리했습니다.
```

```jsx
분리된 메서드:

1. createObstacles

		장애물 그룹 생성 로직을 처리합니다.

		this.obstacles = this.physics.add.group();

2. createGameoverContainer

		게임 오버 UI 요소를 생성하고 컨테이너에 추가합니다.

		게임 오버 텍스트와 재시작 텍스트를 컨테이너에 추가하고 초기 투명도를 설정합니다.

3. handleGameStart

		게임 시작 로직을 처리합니다.

		플레이어와 시작 트리거 간의 충돌을 감지하고 게임 시작 애니메이션을 실행합니다.

4. handleObstacleCollisions

		플레이어와 장애물 간의 충돌을 처리합니다.

		충돌 시 게임을 멈추고 물리 엔진을 일시 정지하며 게임 오버 UI를 표시합니다.

5. handleGameRestart

		게임 재시작 클릭 이벤트를 처리합니다.
```

## 2. **`handleGameStart` 세부 내용**

```jsx
시작 트리거(startTrigger):
```

## 3. **`handleObstacleCollisions` 세부 내용**

## 2. **Phaser 라이프사이클 활용**

```jsx
create 안에 모든 로직을 작성하면 코드가 복잡해지고 읽기 어려워질 수 있습니다.

예를 들어, 아래와 같이 코드가 길어질 경우:

이렇게 되면 초기화 로직과 게임 진행 로직이 뒤섞여서 코드 가독성이 크게 떨어집니다.
```

```jsx
create() {
    this.player = new Player(this, 0, this.gameHeight);
    this.ground = this.add.tileSprite(0, this.gameHeight, 88, 26, "ground").setOrigin(0, 1);

    // Start trigger setup
    this.startTrigger = this.physics.add.sprite(0, 10, null)
        .setAlpha(0)
        .setOrigin(0, 1);
    this.physics.add.overlap(this.startTrigger, this.player, () => {
        // ... 복잡한 동작 로직
    });

    // Collision setup
    this.obstacles = this.physics.add.group();
    this.physics.add.collider(this.obstacles, this.player, () => {
        // ... 충돌 처리 로직
    });

    // Game over UI
    this.gameOverText = this.add.image(0, 0, "game-over");
    this.restartText = this.add.image(0, 80, "restart").setInteractive();
    this.gameOverContainer = this.add
        .container(this.gameWidth / 2, (this.gameHeight / 2) - 50)
        .add([this.gameOverText, this.restartText])
```

### 해결 방법:

```jsx
별도의 함수로 나눠 create에서 호출하면, create는 단순히 초기화 함수 호출만 담고 있게 됩니다:

이제 각 함수는 개별 책임을 가지므로, 코드를 더 쉽게 관리할 수 있습니다.
```

```jsx
create() {
    this.createEnvironment();
    this.createPlayer();
    this.createObstacles();
    this.createGameoverContainer();
    this.handleGameStart();
    this.handleObstacleCollisions();
    this.handleGameRestart();
}
```

## create 에 함수 호출만 만들고 update 에 코드 상세를 만드는 이유

```jsx
예를들어 update 내부에서 createObstacles()와 같은 함수를 직접 호출하지 않는 한, 해당 함수는 계속 호출되지 않습니다.

현재 제공된 코드에서는 createObstacles()가 create()에서 한 번만 호출되도록 작성되어 있습니다.

즉 createObstacles()가 create()에서 한 번만 호출되므로, update() 내부에서 호출되지 않습니다.

따라서 매 프레임 장애물 그룹이 재생성되지 않으며, 필요에 따라 장애물을 추가하는 방식으로 정상 동작합니다.

만약 실수로 update에 createObstacles()를 넣는다면 성능 문제와 예기치 않은 동작을 초래할 수 있습니다. ( 계속 호출 )

create()와 update()의 역할을 명확히 구분하는 것이 중요합니다.
```

# { 게임 재시작 처리 }

## 1. 게임 재시작 처리 개요

```jsx
게임 재시작은 다음과 같은 작업을 포함합니다:

1. 게임의 물리 엔진을 다시 시작.

2. 플레이어의 상태 초기화.

3. 게임 내 장애물 제거.

4. 게임 오버 화면 숨김.

5. 애니메이션 재개.

6. 게임 상태 플래그 업데이트.

```

## 2. 구현 코드와 설명

```jsx
다음은 handleGameRestart 메서드의 코드입니다:

이 코드는 게임 재시작 버튼(여기서는 restartText)을 클릭했을 때 실행됩니다.
```

```jsx
handleGameRestart() {
    this.restartText.on("pointerdown", () => {
        this.physics.resume();
        this.player.setVelocityY(0);
        this.obstacles.clear(true, true);
        this.gameOverContainer.setAlpha(0);
        this.anims.resumeAll();

        this.isGameRunning = true;
    });
}
```

## 3. 코드의 각 단계 설명

### (1) 물리 엔진 재시작

```jsx
this.physics.resume()
```

```jsx
물리 엔진이란? 물리 엔진은 게임에서 충돌, 중력, 속도와 같은 물리적 상호작용을 처리하는 도구입니다.

여기서의 역할 게임 오버 시 물리 엔진이 정지(pause)되었기 때문에, 재시작 시 물리 엔진을 다시 시작(resume)해야 합니다.
```

### (2) 플레이어 속도 초기화

```jsx
this.player.setVelocityY(0)
```

```jsx
속도(velocity)란? 물체가 움직이는 방향과 속력을 나타냅니다.

setVelocityY(0)은 Y축(수직 방향) 속도를 0으로 설정합니다.

왜 필요한가? 플레이어가 게임 종료 상태에서 공중에 떠 있는 경우,

속도를 초기화하지 않으면 재시작 시 이상한 위치에서 시작할 수 있습니다.
```

### (3) 장애물 제거

```jsx
this.obstacles.clear(true, true)
```

```jsx
clear(true, true)의 의미

		첫 번째 true: 장애물을 장면(scene)에서 제거.

		두 번째 true: 장애물을 그룹에서 제거.

왜 필요한가? 게임 재시작 시 이전 장애물이 그대로 남아 있다면

혼란스럽거나 버그가 발생할 수 있으므로 초기화해야 합니다.

Phaser에서 그룹(group) 내의 모든 오브젝트를 제거하는 함수입니다. 이 함수는 두 개의 인수를 받으며, 각각 특정 동작을 제어합니다.

clear() 함수는 그룹(group) 내부의 오브젝트를 제거합니다.

첫 번째 인수: removeFromScene

		타입: boolean (참/거짓 값)

		설명:

				true: 장면(scene)에서 모든 오브젝트를 제거합니다.

				false: 장면에는 남겨두고 그룹에서만 제거합니다.

		장면(scene)이란?

				게임의 시각적 요소가 그려지고 상호작용하는 공간입니다.

				만약 장애물을 장면에서 제거하지 않으면, 시각적으로는 여전히 남아 있게 됩니다.

두 번째 인수: removeFromGroup

		타입: boolean

		설명:

				true: 그룹에서 오브젝트를 완전히 제거합니다.

				false: 그룹에는 남겨두고 다른 작업에서 계속 참조할 수 있습니다.



결과적으로 장애물은 화면에서도 사라지고, 그룹에서도 제거되어 완전히 초기화됩니다.
```

### (4) 게임 오버 화면 숨김

```jsx
this.gameOverContainer.setAlpha(0)
```

```jsx
setAlpha(0)란? alpha는 투명도를 나타냅니다. 0은 완전히 투명(보이지 않음), 1은 불투명(완전히 보임)입니다.

왜 필요한가? 게임 오버 화면은 재시작 시 보이지 않아야 하므로 투명도로 숨깁니다.
```

### (5) 애니메이션 재개

```jsx
this.anims.resumeAll()
```

```jsx
애니메이션이란? 캐릭터나 게임 오브젝트에 동작을 부여하는 시각적 효과입니다.

왜 필요한가? 게임 오버 시 애니메이션이 멈췄을 가능성이 있으므로,

재시작 시 모든 애니메이션을 다시 시작해야 합니다.
```

### (6) 게임 상태 플래그 업데이트

```jsx
this.isGameRunning = true
```

```jsx
isGameRunning란? 게임의 현재 상태를 나타내는 변수입니다.

true이면 게임이 실행 중이고, false이면 멈춘 상태를 의미합니다.

왜 필요한가? 게임 로직은 이 변수를 확인하여 진행 여부를 결정하므로,

재시작 시 실행 상태를 true로 설정해야 합니다.
```

```jsx
목표: 플레이어 캐릭터(공룡)가 '아래 화살표' 키를 눌러 웅크리고, 키를 놓으면 원래 상태로 돌아오는 기능 구현
```

## 1. 웅크리는 기능 개요

```jsx
공룡이 '아래 화살표 키'를 누르면 몸집이 줄어들고, 위치가 조금 아래로 이동합니다.

키를 놓으면 원래의 크기와 위치로 돌아옵니다.

이 기능을 통해 특정 장애물을 피할 수 있습니다.
```

## 2. 코드 개요

### 2.1 Phaser.Input.Keyboard.JustDown과 Phaser.Input.Keyboard.JustUp

```jsx
JustDown: 키를 "처음 눌렀을 때"만 true를 반환합니다.

JustUp: 키를 "처음 뗐을 때"만 true를 반환합니다.
```

### 2.2 `Body`의 크기 및 위치 변경

```jsx
setSize(width, height): 캐릭터의 충돌 영역 크기를 설정합니다.

		이 크기는 캐릭터의 물리적 충돌 판정을 결정합니다.

setOffset(x, y): 충돌 영역의 기준점을 설정합니다.

		기준점은 충돌 영역이 캐릭터와 겹치는 위치를 조정합니다.

```

## 3. 코드 단계별 구현

### 3.1 키 입력 처리

```jsx
1. 아래 화살표 키를 눌렀는지 확인:

2. 아래 화살표 키를 뗐는지 확인
```

### 3.2 웅크릴 때 크기 및 위치 조정

### 3.3 키를 뗐을 때 원래 상태로 복구

## 4. 최종 코드

```jsx
update() {
    const { space, down } = this.cursors;
    const isSpaceJustDown = Phaser.Input.Keyboard.JustDown(space);
    const isDownJustDown = Phaser.Input.Keyboard.JustDown(down);
    const isDownJustUp = Phaser.Input.Keyboard.JustUp(down);

    const onFloor = (this.body as Phaser.Physics.Arcade.Body).onFloor();

    // 점프
    if (isSpaceJustDown && onFloor) {
        this.setVelocityY(-1600);
    }

    // 웅크리기
    if (isDownJustDown && onFloor) {
        this.body.setSize(this.body.width, 58);
        this.setOffset(60, 34);
        this.play("dino-down", true); // 웅크리는 애니메이션 재생
    }

    // 웅크리기 해제
    if (isDownJustUp && onFloor) {
        this.body.setSize(44, 92);
        this.setOffset(20, 0);
        this.playRunAnimation(); // 원래 달리기 애니메이션 재생
    }

    if (!this.scene.isGameRunning) {
        return;
    }

    // 점프 중인지 확인
    const isJumping = this.body.deltaAbsY() > 0;
    if (isJumping) {
        this.anims.stop();
        this.setTexture("dino-run", 0);
    } else {
        this.playRunAnimation();
    }
}
```

```jsx

		바디의 크기를 줄이거나 늘리면 충돌 영역은 커지거나 작아집니다.

setOffset(x, y): 바디의 기준점을 조정합니다.

		충돌 영역의 위치를 캐릭터 이미지와 맞추기 위해 사용됩니다.
```

```jsx
웅크릴 때 충돌 영역의 높이를 줄이면:

		1. 바디의 기준점이 그대로 유지됩니다.
```

# { 공룡이 앉는 애니메이션 재생 }

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380500/notion-blog/_/Game_Development_in_JS_TS_-_The_Complete_Guide_w_/_3_Dino_Game_Clone_-_4_-/image_4.png)

## 1. 목표

```jsx
down 키를 눌렀을 때:

		공룡이 앉는 애니메이션(dino-down)이 재생된다.

		몸의 크기와 위치가 변한다.

down 키를 뗐을 때:

		공룡이 다시 서는 애니메이션(dino-run)이 재생된다.

		몸의 크기와 위치가 원래대로 돌아온다.
```

## 2. 구현된 코드 내용

```jsx
a. 몸 크기와 위치 조정

		down 키가 눌리면:

				공룡의 몸 크기를 변경:

						높이를 58로 줄임.

						공룡의 위치를 약간 오른쪽(x: 60)과 아래(y: 34)로 이동.

		down 키를 떼면:

				공룡의 몸 크기를 원래 크기(92)로 복구.

				위치를 초기값(x: 20, y: 0)으로 복구.

b. 애니메이션 변경

		애니메이션 조건:

				body.height <= 58: 공룡이 앉아 있는 상태 → dino-down 애니메이션 재생.

				그 외: 공룡이 서 있는 상태 → dino-run 애니메이션 재생.


		이를 구현하기 위해 삼항 연산자를 사용:

				this.body.height <= 58 ? this.play('dino-down', true) : this.play("dino-run", true);



c. 점프 시 처리

		공룡이 점프 중이면(위로 뜨면) 애니메이션을 멈추고:

				공룡 이미지를 첫 번째 프레임으로 고정.
```

## 2. **장애물 생성 로직 수정**

### `spawnObstacle` 함수 변경

```jsx
spawnObstacle() {
    // 장애물의 총 개수: 선인장(cactus) + 새(bird)
    const obstaclesCount = PRELOAD_CONFIG.cactusesCount + PRELOAD_CONFIG.birdsCount;

    // Math.random()은 0 이상 1 미만의 실수(float)를 생성합니다.
    // Math.floor()는 소수점 이하를 버리고 가장 가까운 아래 정수로 변환
    // 기본적으로 Math.floor(Math.random() * obstaclesCount)는 0부터 obstaclesCount - 1까지의 정수를 생성합니다.
		// 여기에 + 1을 하면, 최종 결과는 1부터 obstaclesCount까지의 정수가 됩니다.
    const obstacleNum = Math.floor(Math.random() * obstaclesCount) + 1;

    const distance = Phaser.Math.Between(600, 900); // 장애물 간 거리
    let obstacle;

    // 생성된 숫자가 선인장 개수보다 크면 Enemy Bird 생성
    if (obstacleNum > PRELOAD_CONFIG.cactusesCount) {
        const enemyPossibleHeight = [20, 70]; // 생성 높이 배열
        const enemyHeight = enemyPossibleHeight[Math.floor(Math.random() * 2)]; // 랜덤 높이 선택

        obstacle = this.obstacles.create(
            distance,
            this.gameHeight - enemyHeight, // 높이 반영
            'enemy-bird'
        );
    } else {
        // 기존 선인장 장애물 생성
        obstacle = this.obstacles.create(
            distance,
            this.gameHeight,
            `obstacle-${obstacleNum}`
        );
    }

    // 장애물 속성 설정
    obstacle
        .setOrigin(0, 1)
        .setImmovable();
}

```

## 3. **적 배치 로직**

### 장애물 높이 설정

```jsx
새로운 적 Enemy Bird는 고정된 두 가지 높이(20px, 70px)에서 랜덤으로 생성됩니다.

		enemyPossibleHeight 배열을 활용해 높이 선택.

		적이 생성되는 높이는 this.gameHeight - enemyHeight로 설정.

장애물 생성 조건

		선인장 (Cactus): obstacleNum이 PRELOAD_CONFIG.cactusesCount 이하인 경우.

		새 (Enemy Bird): obstacleNum이 PRELOAD_CONFIG.cactusesCount보다 큰 경우.
```

#
