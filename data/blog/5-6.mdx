## 🔷 Static Mesh Collision 이해

### Complex vs Simple Collision

**Complex Collision (복잡한 콜리전)**

```
메시의 실제 폴리곤 사용
  ├─ 모든 삼각형 개별 계산
  ├─ 정확하지만 성능 저하
  └─ 일반적으로 사용 안 함
```

**Simple Collision (단순 콜리전)**

```
기본 도형으로 근사
  ├─ Box, Sphere, Capsule 등
  ├─ 계산량 적음
  ├─ 최적화됨
  └─ 게임에서 주로 사용
```

### 확인 방법

```
Static Mesh Editor
  ↓
Show → Complex Collision
  → 실제 메시 폴리곤

Show → Simple Collision
  → 단순화된 콜리전 볼륨
```

## 📐 Normal Vector로 방향 설정

### Normal Vector란?

```
표면에 수직(직교)인 벡터
  ├─ 90도로 튀어나옴
  ├─ 표면 방향 나타냄
  └─ 보통 길이 1로 정규화됨

주의:
  Normal Vector ≠ Normalized Vector
  (표면 법선) ≠ (정규화된 벡터)
```

### 시각적 이해

```
벽 (평면)
  │
  │ ← Normal Vector (표면에 수직)
  │
  └─────
```

### Rotation 생성

```
Break Hit Result
  ↓
Normal (Vector 출력)
  ↓
Make Rot from X
  ↓
Return Value (Rotator)
  ↓
Spawn System at Location → Rotation
```

**Make Rot from X 선택 이유**

```
언리얼 엔진 규칙:
  X축 = Forward (전방)
  ↓
Normal 벡터를 X축으로 설정
  ↓
해당 방향을 향하는 Rotation 생성
```

### 다른 옵션들

```
Make Rot from X: X축 기준 회전
Make Rot from Y: Y축 기준 회전
Make Rot from Z: Z축 기준 회전
Make Rot from XY: X, Y축 기준
Make Rot from XZ: X, Z축 기준
...
```

## ⚠️ 주의사항

### 1. Collision Complexity

```
❌ 설정 안 하면
  → Simple Collision 무시됨
  → Complex Collision 사용
  → 성능 저하

✓ Use Simple as Complex 설정
  → Simple Collision 사용
  → 최적화됨
```

### 2. Socket 위치

```
Socket이 Collision 내부에 있으면
  → 즉시 자기 자신과 충돌
  → 발사 안 됨

해결:
  → Socket을 Collision 밖으로
```

### 3. Hit Event 조건

```
Hit Event 발생 조건:
  ├─ Generate Hit Events = True
  ├─ Collision 활성화
  └─ 차단(Block) 설정
```

### 4. Normal Vector

```
Normal = 표면 법선 벡터
  ↓
표면에 수직
  ↓
Make Rot from X로 변환
```

### 5. Destroy Actor

```
Self 파괴 시:
  ├─ 모든 컴포넌트 파괴
  ├─ 더 이상 이벤트 발생 안 함
  └─ 파티클 먼저 Spawn 필수
```

## 🔧 Expose on Spawn 설정

### 개념 이해

**일반 변수**

```
Blueprint 내부에서만 설정 가능
  ↓
외부에서 접근 불가
```

**Expose on Spawn**

```
액터를 Spawn할 때
  ↓
외부에서 변수 값을 설정 가능
  ↓
"생성하면서 초기화"
```

### 설정 방법

```
Target Pawn 변수 선택
  ↓
Details Panel
  ↓
1. Instance Editable: ✓ 체크
   (눈 아이콘이 열림)

2. Expose on Spawn: ✓ 체크
```

### 각 옵션의 의미

**Instance Editable**

```
레벨에 배치된 액터의 변수를
Details Panel에서 수정 가능

예:
레벨의 BP_Bot 선택
  → Details에서 값 변경 가능
```

**Expose on Spawn**

```
Spawn Actor 노드에서
변수를 입력 핀으로 노출

SpawnActor 노드
  ├─ Class
  ├─ Transform
  └─ Target Pawn ← 추가됨!

```

**왜 둘 다 필요한가?**

```
Instance Editable이 먼저 켜져야
  ↓
Expose on Spawn을 켤 수 있음
  ↓
단계적 접근 제어

```

```
BP_Bot 열기
  ↓
Spawn Blaster Beam 함수
  ↓
SpawnActor BP_Blaster_Beam 노드 우클릭
  ↓
Refresh Node
```

**왜 Refresh가 필요한가?**

```
다른 Blueprint를 수정했을 때
  ↓
현재 Blueprint는 변경사항을 모름
  ↓
Refresh로 최신 정보 가져옴
```

### 2. Target Pawn 연결

```
SpawnActor 노드 확장
  ↓
Target Pawn 입력 핀 표시됨
  ↓
BP_Bot의 Target Pawn 변수 연결
```

**연결 흐름**

```
BP_Bot
  ├─ Target Pawn (플레이어 저장됨)
  │   ↓
  └─ SpawnActor
      └─ Target Pawn (블라스터 빔에 전달)
```

**결과**

```
블라스터 빔 생성 시
  ↓
자동으로 Target Pawn이 설정됨
  ↓
"이 빔은 누구를 맞춰야 하는지 앎"
```

## 🎯 Hit Actor와 Target Pawn 비교

### BP_Blaster_Beam에서 구현

### 1. 비교 노드 추가

```
OnComponentHit_Event
  ↓
Other Actor (맞은 대상)
  ↓
== (Equal) 노드
  ├─ A: Other Actor
  └─ B: Target Pawn
  ↓
Bool (참/거짓)
```

**Equal 노드 찾기**

```
Other Actor 드래그
  ↓
"==" 입력
  ↓
Equal (Object) 선택
```

### 2. 왜 비교하나?

```
Other Actor: 실제로 맞은 대상
Target Pawn: 맞춰야 할 대상

Other Actor == Target Pawn?
  ├─ True: 플레이어를 맞춤!
  └─ False: 다른 것을 맞춤 (벽 등)
```

## 🌿 Branch로 조건 분기

### Branch 노드란?

```
if문과 동일

if (조건) {
  // True 실행
} else {
  // False 실행
}
```

### 구현

```
OnComponentHit_Event
  ↓
Branch
  ├─ Condition ← (Other Actor == Target Pawn)
  ├─ True → Quit Game
  └─ False → Spawn System + Destroy Actor
```

### 흐름 이해

**Case 1: 플레이어 피격 (True)**

```
블라스터 빔 충돌
  ↓
Other Actor == Target Pawn? → Yes
  ↓
Branch → True 핀 실행
  ↓
Quit Game

```

**Case 2: 벽 충돌 (False)**

```
블라스터 빔 충돌
  ↓
Other Actor == Target Pawn? → No
  ↓
Branch → False 핀 실행
  ↓
Spawn System → Destroy Actor

```

## 🔍 개념 심화 이해

### Expose on Spawn 원리

**일반적인 변수 초기화**

```
액터 생성
  ↓
변수는 기본값
  ↓
나중에 Set 노드로 변경
```

**Expose on Spawn 사용 시**

```
액터 생성하면서 동시에 변수 설정
  ↓
생성 즉시 올바른 값을 가짐
  ↓
별도 Set 노드 불필요
```

**왜 더 좋은가?**

```
타이밍 문제 없음
  ├─ 생성과 동시에 설정
  └─ 빔이 날아가기 전에 Target 설정 보장

코드 간결
  ├─ SpawnActor 한 번에 처리
  └─ 추가 Set 노드 불필요
```

### Branch의 동작 원리

```
Branch = 코드의 갈림길

Condition이 True
  ↓
True 핀에 연결된 노드들만 실행
  ↓
False 핀은 무시

Condition이 False
  ↓
False 핀에 연결된 노드들만 실행
  ↓
True 핀은 무시
```

**예시**

```
플레이어 피격 (True)
  ├─ Quit Game 실행
  └─ Spawn System/Destroy는 실행 안 됨!

벽 충돌 (False)
  ├─ Quit Game 실행 안 됨
  └─ Spawn System/Destroy만 실행
```

## ⚠️ 주의사항

### 1. Expose on Spawn 설정 순서

```
❌ 순서 틀리면 작동 안 됨

올바른 순서:
1. Instance Editable 먼저 체크
2. 그 다음 Expose on Spawn 체크
```

### 2. 노드 Refresh

```
다른 Blueprint 수정 후
  ↓
반드시 Refresh Node
  ↓
안 하면 변경사항 반영 안 됨
```

### 3. Branch Condition

```
Condition에는 Bool만 연결
  ├─ True/False 값만 가능
  └─ 비교 연산자 (==, !=, >, < 등) 사용
```

### 4. Target Pawn 타입

```
Pawn 타입으로 설정
  ↓
Actor는 너무 광범위
  ↓
Character는 너무 구체적
  ↓
Pawn이 적절
```

### 5. 게임 시작 딜레이

```
딜레이 없으면 즉시 공격
  ↓
플레이어가 반응 못 함
  ↓
1~2초 여유 필수
```

## 💡 개념 비유

### Expose on Spawn

```
음식 주문에 비유:

일반 변수:
  1. 음식 만들기
  2. 나중에 토핑 추가
  (두 단계)

Expose on Spawn:
  1. 주문하면서 토핑까지 지정
  (한 단계에 완료)
```

### Branch

```
교차로에 비유:

조건이 신호등
  ├─ 초록불 (True): 직진
  └─ 빨간불 (False): 우회전

한쪽만 갈 수 있음
```

### Target Pawn

```
택배에 비유:

Target Pawn = 받는 사람 주소
  ↓
블라스터 빔 = 택배 상자
  ↓
충돌 = 도착
  ↓
주소 확인 = 비교
  ├─ 맞으면: 배달 완료 (게임 종료)
  └─ 틀리면: 반송 (그냥 파괴)
```

## 🚀 전진 이동 구현

### 요구사항

```
구체가 계속 앞으로 이동
  ├─ 자신의 Forward 방향
  ├─ 속도 변수로 제어
  └─ 프레임 독립적 (Delta Time 사용)
```

### Event Graph 구현

### 1. Event Tick 사용

```
Event Graph
  ↓
Event Tick (이미 있음)
```

**왜 Event Tick인가?**

```
매 프레임마다 실행
  ↓
지속적인 이동 구현
```

### 2. Add Actor World Offset

```
Event Tick
  ↓
Add Actor World Offset
```

**이 노드의 역할**

```
Actor의 위치를 이동
  ├─ World 좌표계 기준
  ├─ 상대적 오프셋 추가
  └─ 누적 이동
```

### 3. Forward Vector 계산

```
Get Actor Forward Vector
  ↓
Actor가 바라보는 방향 (X축)
```

**Forward Vector란?**

```
Actor의 로컬 X축 방향
  ├─ 길이 1의 단위 벡터
  ├─ 회전에 따라 변함
  └─ 이동 방향 결정
```

### 4. 속도로 스케일링

**Speed 변수 생성**

```
Variables 패널
  ↓
+ 버튼
  ↓
이름: Speed
  ├─ Type: Float
  ├─ Default: 100
  └─ Category: Movement
```

**Multiply 연결**

```
Get Actor Forward Vector
  ↓
Multiply (Vector × Float)
  ├─ A: Forward Vector
  └─ B: Speed
  ↓
스케일된 방향 벡터
```

**의미**

```
Forward Vector (길이 1)
  × Speed (100)
  = 초당 100 유닛 이동
```

### 5. Delta Time 적용

**왜 Delta Time이 필요한가?**

```
Event Tick = 매 프레임 실행
  ├─ 60fps: 1초에 60번
  ├─ 30fps: 1초에 30번
  └─ 프레임마다 다름

Delta Time 없으면:
  60fps: 빠름
  30fps: 느림 (문제!)

Delta Time 있으면:
  모든 프레임레이트에서 동일한 속도 ✓
```

**구현**

```
Event Tick
  ↓
Delta Seconds (출력 핀)
  ↓
Multiply
  ├─ A: Speed
  └─ B: Delta Seconds
  ↓
Multiply
  ├─ A: (Speed × Delta)
  └─ B: Forward Vector
```

### 최종 연결

```
Event Tick
  ↓
[계산 파트]
  Get Actor Forward Vector
    ↓
  Speed × Delta Seconds
    ↓
  Result × Forward Vector
    ↓
[이동 파트]
  Add Actor World Offset
    └─ Delta Location
```

## 📐 이동 수식 이해

### 최종 수식

```
Delta Location = Forward Vector × Speed × Delta Time
```

### 단계별 분해

```
1. Get Actor Forward Vector
   → (1, 0, 0) 방향 단위 벡터

2. Speed × Delta Seconds
   → 100 × 0.0167 (60fps 기준)
   → 1.67

3. Forward × (Speed × Delta)
   → (1, 0, 0) × 1.67
   → (1.67, 0, 0)

4. Add Actor World Offset
   → 현재 위치 + (1.67, 0, 0)
   → 매 프레임 1.67 유닛 이동
```

### 1초 후 총 이동 거리

```
60fps 기준:
  1.67 × 60 = 100 유닛

30fps 기준:
  3.33 × 30 = 100 유닛

결과:
  프레임레이트 무관하게 초당 100 유닛 ✓
```

## 📐 회전 크기 조정

```

+ 버튼
  ↓

  ├─ Type: Float
  ├─ Default: 0.25
  └─ Category: Sphere Movement

```
Event Begin Play
  ↓
Random Rotator
  ↓
Multiply (Rotator × Float)
  ├─ A: Random Rotator
  └─ B: Rotation Scale (0.25)
  ↓
Set Delta Rotation

```
Random Rotator: -180 ~ 180

  =

  ↓

**테스트 결과**

  ↓

```

**권장 값**

```
0.05 ~ 0.1: 큰 원호
0.2 ~ 0.5: 중간 원호
0.5 ~ 1.0: 작은 원호
```

## ⚠️ 주의사항

### 1. Random 호출 위치

```
❌ Event Tick에서 Random
  → 매 프레임 다른 값
  → 불규칙한 떨림

✓ Begin Play에서 Random
  → 1회만 결정
  → 일관된 움직임
```

### 2. Roll 회전

```
대부분의 경우 Roll 불필요
  ↓
Yaw + Pitch만으로 충분
  ↓
Roll은 시각적 혼란
```

### 3. Rotation Scale

```
너무 크면 (>0.5):
  ├─ 작은 원호
  └─ 빠른 회전

너무 작으면 (<0.01):
  ├─ 거의 직선
  └─ 회전 효과 미미

권장: 0.05 ~ 0.1
```

### 4. Delta Time 필수

```
회전도 이동처럼
  ↓
반드시 Delta Time 곱하기
  ↓
프레임 독립성 보장
```

### 5. 함수 입력 이름

```
기본 이름 (A, B): 의미 불명
  ↓
명확한 이름 (Delta Seconds): 이해 쉬움
  ↓
코드 가독성 향상
```
