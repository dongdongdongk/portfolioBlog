## 🎯 목표

압력판을 밟으면 아래로 눌리고, 떼면 다시 올라오는 인터랙티브 오브젝트 제작

---

## 📋 전체 구조 개요

```
압력판 시스템
  ├─ Box Component (충돌 감지)
  ├─ Platform (눌리는 부분)
  ├─ Press Target (목표 위치)
  └─ Timeline (움직임 애니메이션)
```

## 🔧 1단계: 기본 설정

### 1-1. 이벤트 그래프 준비

**작업**

```
Components 패널
  └─ Box Component 선택
      └─ 우클릭 → Add Event → On Component Begin Overlap
```

**노드 생성 결과**

- `On Component Begin Overlap (Box)` 이벤트 노드 추가됨
- 뭔가 Box와 겹칠 때 실행되는 시작점

**노드 출력 핀 설명**

```
On Component Begin Overlap
  ├─ Overlapped Component: 충돌한 내 컴포넌트
  ├─ Other Actor: 충돌한 상대 액터
  ├─ Other Comp: 충돌한 상대 컴포넌트
  ├─ Other Body Index: 물리 바디 인덱스
  ├─ From Sweep: 쓸어서 충돌했는지 여부
  └─ Sweep Result: 충돌 상세 정보
```

💡 **초보 설명**: 이 노드는 "누군가 Box 영역에 들어왔을 때" 신호를 보내는 센서입니다.

## ⏱️ 2단계: Timeline 생성

```

  → Timeline 검색
```

**Float Track 추가**

```
Timeline 더블클릭 → 편집 창 열림
  ↓
Add Float Track 클릭
  ├─ Track 이름: "Elevation"
  └─ 용도: 0~1 사이 값으로 높이 조절
```

**키 추가**

```
키 1
  ├─ Time: 0.0
  └─ Value: 0.0

키 2
  ├─ Time: 0.5
  └─ Value: 1.0
```

💡 **초보 설명**: 0.5초 동안 0에서 1로 부드럽게 변하는 값을 만듭니다.

**커브 부드럽게 만들기**

```
두 키 모두 선택 (Shift + 클릭)
  ↓
우클릭 → Auto
  ↓
선형이 아닌 부드러운 S자 곡선으로 변경
```

### 2-3. Timeline 노드 연결

```
On Component Begin Overlap
  ↓
PlatformElevation (Timeline)
  └─ Play 핀 연결
```

**Timeline 노드 출력 핀**

```
PlatformElevation
  ├─ Update: 매 프레임 실행 (값 변화 중)
  ├─ Finished: 재생 완료 시 실행
  ├─ Direction: 재생 방향 (Forward/Reverse)
  └─ Elevation: Float Track의 현재 값 (0~1)
```

💡 **초보 설명**:

- `Play`: 타임라인 시작
- `Update`: 값이 변하는 동안 계속 실행
- `Elevation`: 현재 진행도 (0% → 100%)

## 🔄 4단계: 보간(Lerp) 시스템

### 4-1. Lerp 노드 이해

**Lerp (Linear Interpolation) = 선형 보간**

```
두 값 사이를 부드럽게 이동

A (시작값) ─────────── B (끝값)
              ↑
            Alpha (0~1)

Alpha = 0.0 → A 값 반환
Alpha = 0.5 → A와 B 중간 값
Alpha = 1.0 → B 값 반환
```

### 4-2. Update Plate Location 함수 생성

**노드 구조**

```
Timeline Update 출력
  ↓
[새 함수: Update Plate Location]
  ↓
Lerp (Vector)
  ├─ A: Initial Plate Location (변수)
  ├─ B: Platform Press Target의 World Location
  └─ Alpha: Elevation (Timeline 값)
  ↓
Return Value
  ↓
Set World Location
  ├─ Target: Platform (컴포넌트)
  ├─ New Location: Lerp 결과값
  ├─ Sweep: false (충돌 무시)
  └─ Teleport: false (물리 적용)
```

**각 노드 기능 설명**

**Get World Location**

```
용도: 컴포넌트의 월드 좌표 가져오기
입력: Target (어떤 컴포넌트?)
출력: Return Value (Vector 위치)
```

**Lerp (Vector)**

```
용도: 두 위치 사이를 부드럽게 보간
입력:
  ├─ A: 시작 위치
  ├─ B: 목표 위치
  └─ Alpha: 진행도 (0~1)
출력: Return Value (계산된 중간 위치)
```

**Set World Location**

```
용도: 오브젝트를 특정 위치로 이동
입력:
  ├─ Target: 이동할 오브젝트
  ├─ New Location: 목표 위치
  ├─ Sweep: 이동 중 충돌 검사 여부
  └─ Teleport: 순간이동 여부
```

### 4-3. Timeline Update 연결

```
PlatformElevation → Update 핀
  ↓
Update Plate Location (함수 호출)
```

💡 **작동 원리**

```
Timeline이 재생되면
  ↓
매 프레임 Update 실행
  ↓
Elevation 값이 0 → 1로 변화
  ↓
Lerp가 초기 위치 → 목표 위치로 계산
  ↓
Platform이 부드럽게 이동
```

## ⚠️ 6단계: 충돌 문제 해결

### 6-1. 문제 발견

**테스트 시 발생한 문제**

```
압력판이 자기 자신과 계속 충돌
  ↓
On Begin Overlap이 계속 트리거됨
  ↓
Timeline이 재생/역재생 반복
```

**디버깅 방법**

```
On Component Begin Overlap
  ↓
Print String
  └─ String: Other Actor의 Display Name
```

실행 결과: "BP_Pressure_Plate" 계속 출력 → 자기 자신과 충돌 중

### 6-2. Collision Preset 변경

**기존 Pickup Preset 사용**

```
Box Component 선택
  ↓
Details 패널
  └─ Collision
      ├─ Collision Presets: Pickup
      └─ 효과: Pawn(플레이어)하고만 Overlap
```

**Pickup Preset 설정**

```
Collision Enabled: Query Only (물리 없이 감지만)
Object Type: WorldDynamic
  ├─ WorldStatic: Ignore
  ├─ WorldDynamic: Ignore
  ├─ Pawn: Overlap (★ 플레이어만 감지)
  ├─ PhysicsBody: Ignore
  └─ 나머지: Ignore
```

💡 **초보 설명**: Pickup은 "플레이어가 주울 수 있는 아이템" 설정입니다. Pawn(플레이어)하고만 반응합니다.

### 6-3. 커스텀 Preset 생성 (선택사항)

**이유**: Pickup은 이름이 압력판과 안 맞음

**작업**

```
Edit → Project Settings
  ↓
Collision
  ↓
Preset 섹션에서 New... 클릭
  ↓
설정
  ├─ Name: PressurePlate
  ├─ Collision Enabled: Query Only
  ├─ Object Type: WorldStatic
  ├─ Description: "Pressure plate overlapping with player"
  └─ Collision Responses
      ├─ Default: Ignore
      └─ Pawn: Overlap
```

**적용**

```
Box Component
  └─ Collision Presets: PressurePlate
```

**작업**


**Boolean 변수란?**

- True(참) 또는 False(거짓) 두 가지 값만 가짐

- 레벨에 배치된 각 인스턴스마다 다른 값 설정 가능
- Details 패널에서 편집 가능

**작동 과정**

```
For Each Loop 시작
  ↓
Array Element = Actors[0]
  ↓
Loop Body 실행
  ↓
Array Element = Actors[1]
  ↓
Loop Body 실행
  ↓
... (반복)
  ↓
Completed 실행
```

## 🔍 작동 순서 상세 분석

### 시나리오 1: 누를 때 (Does Un Press = true)

```
1️⃣ 플레이어가 압력판 위에 올라감
   ↓
2️⃣ On Component Begin Overlap 발생
   ↓
3️⃣ PlatformElevation → Play 실행
   ├─ Direction = Forward
   └─ Timeline 0초 → 0.5초 재생 시작
   ↓
4️⃣ Update 핀 매 프레임 실행
   ├─ Elevation: 0 → 1로 변화
   └─ Update Plate Location 호출
       └─ Platform이 아래로 이동
   ↓
5️⃣ Timeline 0.5초 도달
   ├─ Press Event 발생
   └─ On Press 함수 실행
       ↓
6️⃣ Branch: Direction == Forward?
   └─ True (정방향이므로)
       ↓
7️⃣ For Each Loop 시작
   ├─ Actors to Activate[0] → Activate
   │   └─ Platform_1: "Activated" 출력
   ├─ Actors to Activate[1] → Activate
   │   └─ Platform_2: "Activated" 출력
   └─ Loop 완료
```

### 시나리오 2: 뗄 때 (Does Un Press = true)

```
1️⃣ 플레이어가 압력판에서 내려옴
   ↓
2️⃣ On Component End Overlap 발생
   ↓
3️⃣ Branch: Does Un Press?
   └─ True (체크되어 있음)
       ↓
4️⃣ PlatformElevation → Reverse 실행
   ├─ Direction = Backward
   └─ Timeline 0.5초 → 0초 역재생 시작
   ↓
5️⃣ Update 핀 매 프레임 실행
   ├─ Elevation: 1 → 0으로 변화
   └─ Update Plate Location 호출
       └─ Platform이 위로 이동
   ↓
6️⃣ Timeline 0.0초 도달
   ├─ UnPress Event 발생
   └─ On Unpress 함수 실행
       ↓
7️⃣ Branch: Direction == Backward?
   └─ True (역방향이므로)
       ↓
8️⃣ For Each Loop 시작
   ├─ Actors to Activate[0] → DeActivate
   │   └─ Platform_1: "DeActivated" 출력
   ├─ Actors to Activate[1] → DeActivate
   │   └─ Platform_2: "DeActivated" 출력
   └─ Loop 완료
```

### 시나리오 3: 버튼 스타일 (Does Un Press = false)

```
1️⃣ 플레이어가 압력판 위에 올라감
   ↓
   [2️⃣~7️⃣은 시나리오 1과 동일]
   ↓
8️⃣ 플레이어가 압력판에서 내려옴
   ↓
9️⃣ On Component End Overlap 발생
   ↓
🔟 Branch: Does Un Press?
   └─ False (체크 안 됨)
       ↓
⓫ 아무 일도 일어나지 않음
   ├─ Reverse 실행 안 됨
   ├─ Platform 눌린 상태 유지
   └─ DeActivate 호출 안 됨
```

## 🧩 핵심 시스템 원리

### Interface 통신 구조

```
압력판 (Sender)
  │
  │ "Activate" 메시지
  │
  ├─→ Platform_1 (Receiver)
  │     └─ 자기만의 방식으로 반응
  │
  ├─→ Platform_2 (Receiver)
  │     └─ 자기만의 방식으로 반응
  │
  └─→ Door_3 (Receiver)
        └─ 자기만의 방식으로 반응
```

**장점**

```
1. 느슨한 결합 (Loose Coupling)
   └─ 압력판은 받는 쪽 타입을 몰라도 됨

2. 확장성
   └─ 새 타입 추가 쉬움 (Interface만 구현)

3. 메모리 효율
   └─ 하드 레퍼런스 없음

4. 재사용성
   └─ 같은 압력판으로 다양한 오브젝트 제어
```

### Timeline Event Track 원리

```
Event Track의 역할
  ├─ 특정 시점에서 신호 발생
  ├─ Direction과 조합하여 방향 구분
  └─ Finished보다 정확한 타이밍 제어

Press Event (0.5초)
  ├─ Play 시: 정방향 완료
  └─ Reverse 시: 통과 (하지만 Direction != Forward라 실행 안 됨)

UnPress Event (0.0초)
  ├─ Reverse 시: 역방향 완료
  └─ Play 시: 통과 (하지만 Direction != Backward라 실행 안 됨)
```

## 💡 주의사항

1. **Direction 체크 필수**
   - Event Track은 방향 무관 발동
   - Branch로 정방향/역방향 구분 필요
2. **Interface 구현 확인**
   - 배열에 추가한 Actor가 Interface 구현 필수
   - 미구현 시 아무 일도 안 일어남
3. **Event Track 타이밍**
   - Press Event: Timeline 끝 (0.5초)
   - UnPress Event: Timeline 시작 (0.0초)
   - 위치 정확히 설정
4. **배열 인덱스**
   - 0부터 시작
   - 빈 슬롯 주의
5. **Eyedropper 사용**
   - 같은 레벨의 액터만 선택 가능
   - 다른 레벨 액터는 직접 드래그

## 🔄 6단계: Lerp 시스템 구현

### 6-1. Update Platform Location 함수

**노드 구조**

```
Float Timeline → Update
  ↓
Get Actor Location
  ├─ Target: Self
  └─ Return Value: Scene Root 위치 (시작점)
  ↓
Lerp (Vector)
  ├─ A: Actor Location (Scene Root)
  ├─ B: Interp Location의 World Location
  └─ Alpha: Float (Timeline 값 0~1)
  ↓
Set World Location
  ├─ Target: Platform Mesh
  └─ New Location: Lerp 결과
```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380665/notion-blog/_/_/_5_/1/image_20.png)

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380665/notion-blog/_/_/_5_/1/image_21.png)

**각 노드 설명**

**Get Actor Location**

```
용도: Actor의 루트 위치 가져오기
입력: Target (Self)
출력: Vector (Scene Root 위치)
특징: Scene Root = Actor의 기준점
```

**Get World Location (Interp Location)**

```
용도: Scene Component의 월드 좌표
입력: Target (Interp Location)
출력: Vector (목표 위치)
```

**Lerp (Vector)**

```
A: Scene Root 위치 (0, 0, 0)
B: Interp Location 위치 (0, 0, 500)
Alpha: 0~1 (Timeline 진행도)

Alpha = 0.0 → (0, 0, 0)
Alpha = 0.5 → (0, 0, 250)
Alpha = 1.0 → (0, 0, 500)
```

**Set World Location**

```
Target: Platform Mesh (움직일 오브젝트)
New Location: Lerp 계산 결과
Sweep: false
Teleport: false
```

### 6-2. Activate 이벤트 연결

**노드 구조**

```
Activate (Interface Event)
  ↓
Float Timeline → Play from Start
  ↓
Update 핀 → Update Platform Location 함수
```

**작동 흐름**

```
1. 압력판 밟음
   ↓
2. Activate 호출
   ↓
3. Float Timeline 재생 시작
   ↓
4. 매 프레임 Update 실행
   ↓
5. Alpha 값이 0 → 1로 변화
   ↓
6. Platform Mesh가 Scene Root → Interp Location으로 이동
   ↓
7. 3초 후 도착
```

### 6-3. 함수로 정리

**작업**

```
Lerp + Set World Location 노드 선택
  ↓
우클릭 → Collapse to Function
  └─ 이름: Update Platform Location
```

```
  ✅ 중앙 관리
  ✅ 재사용
  ✅ 일관성
  ✅ 수정 편의
```

### Scene Component

```
용도: 위치 마커
특징:
  ├─ 렌더링 안 됨 (보이지 않음)
  ├─ 충돌 없음
  ├─ 위치 정보만 저장
  └─ 매우 가벼움

활용:
  ├─ 목표 위치
  ├─ 기준점
  ├─ 스폰 포인트
  └─ 웨이포인트
```

### Lerp 보간

```
공식: A + (B - A) × Alpha

예시: 높이 100 → 600으로 이동
  Alpha = 0.0 → 100 + (600-100) × 0 = 100
  Alpha = 0.25 → 100 + (600-100) × 0.25 = 225
  Alpha = 0.5 → 100 + (600-100) × 0.5 = 350
  Alpha = 0.75 → 100 + (600-100) × 0.75 = 475
  Alpha = 1.0 → 100 + (600-100) × 1 = 600
```

## 💡 주의사항

1. **Scene Root vs Interp Location**
   - Scene Root = 시작 위치 (Actor 기준점)
   - Interp Location = 도착 위치 (수동 설정)
   - 둘의 차이가 이동 거리
2. **Platform Mesh는 루트가 아님**
   - Scene Root가 기준점
   - Platform Mesh는 움직이는 부분
   - Get Actor Location은 Scene Root 반환
3. **External Curve 수정**
   - Timeline에서 직접 수정 불가
   - Curve Asset 파일 열어서 수정
   - 모든 사용처에 자동 반영
4. **Timeline Length**
   - Curve 길이와 일치해야 함
   - 3초 Curve면 Length도 3.0
5. **배열 인덱스**
   - 여러 Platform 추가 가능
   - 한 번에 모두 활성화
   - 각각 다른 동작 가능
