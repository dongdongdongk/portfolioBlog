# **{ 공통 기능을 관리하는 기반 클래스(Base Class) }**

```jsx
강의의 주요 내용은 **공통 기능을 관리하는 기반 클래스(Base Class)**를 만들어,

중복된 코드나 공통적으로 사용되는 데이터를 효율적으로 관리하고 활용하는 방법에 대한 것입니다.
```

## 1. **문제 정의**

```jsx
현재 PlayScene 클래스에서 다음과 같은 코드가 있습니다:

		gameHeight와 gameWidth라는 화면 크기를 나타내는 값.

		isGameRunning이라는 게임의 실행 상태를 관리하는 변수.
```

```jsx
이 변수들은 PlayScene에서 사용되지만, 다른 장면(Scene)에서도 재사용될 가능성이 높습니다.

따라서 이를 효율적으로 관리하기 위해

공통 속성 및 기능을 제공하는 기반 클래스를 만들고 이를 확장하여 사용하자는 것입니다.
```

## 2. **기본 개념: 상속(Inheritance)**

```jsx
상속은 객체지향 프로그래밍(OOP)의 핵심 개념 중 하나로,

기존 클래스의 기능을 물려받아 새로운 클래스를 만드는 것을 의미합니다.

		부모 클래스(기반 클래스):

		다른 클래스가 확장할 수 있도록 공통 기능과 데이터를 정의한 클래스.


		자식 클래스(파생 클래스):

		부모 클래스를 확장(extend)하여, 부모의 기능을 그대로 사용하거나 필요에 따라 추가 및 변경하는 클래스.


Phaser에서는 Phaser.Scene이 기본적으로 장면(Scene)을 관리하는 부모 클래스입니다.

이 강의에서는 이 Phaser.Scene을 확장한 GameScene이라는 기반 클래스를 만들고,

PlayScene이 이를 상속받아 사용하도록 변경합니다.
```

## 3. **구현 계획**

```jsx
1. GameScene이라는 새로운 클래스를 만든다.

		공통적으로 사용될 속성과 메서드를 정의한다.

		예: gameHeight, gameWidth, isGameRunning 등.

2. 기존의 PlayScene을 Phaser.Scene 대신 GameScene을 상속받도록 변경한다.

		이렇게 하면 PlayScene에서도 GameScene의 공통 속성과 메서드를 사용할 수 있다.

3. Player 클래스에서도 새로운 GameScene 타입을 인식하도록 변경한다.

		이를 통해 isGameRunning 같은 속성에 쉽게 접근할 수 있게 한다.
```

## 4. **세부 구현**

### Step 1: `GameScene` 클래스 생성

```jsx
import Phaser from "phaser";

export class GameScene extends Phaser.Scene {
    constructor(key: string) {
        super(key); // Phaser.Scene의 생성자 호출
    }

    // 화면 높이와 너비를 반환하는 게터(getter)
    get gameHeight() {
        return this.scale.height; // Phaser에서 화면 높이를 반환
    }

    get gameWidth() {
        return this.scale.width; // Phaser에서 화면 너비를 반환
    }

    // 게임 실행 상태를 나타내는 변수
    isGameRunning: boolean = false;
}

```

```jsx
gameHeight, gameWidth:

		화면 크기를 가져오는 게터 메서드로, 장면(Scene) 내에서 항상 정확한 크기를 사용할 수 있도록 한다.

isGameRunning:

		게임이 실행 중인지 여부를 나타내는 변수로, 기본값은 false이다.
```

### Step 2: `PlayScene`에서 `GameScene`을 상속

```jsx
import { GameScene } from './GameScene'

class PlayScene extends GameScene {
  constructor() {
    super('PlayScene') // GameScene 생성자 호출
  }

  create() {
    // 게임 실행 상태를 설정하는 예시
    this.isGameRunning = true
    console.log('Game height:', this.gameHeight) // GameScene의 속성 사용
    console.log('Game width:', this.gameWidth)
  }
}
```

```jsx
PlayScene이 GameScene을 상속하므로, gameHeight, gameWidth, isGameRunning에 바로 접근할 수 있습니다.
```

### Step 3: `Player` 클래스에서 `GameScene` 사용

```jsx
import { GameScene } from "../GameScene";

export class Player extends Phaser.Physics.Arcade.Sprite {
    scene: GameScene; // 장면(Scene) 타입을 GameScene으로 설정

    constructor(scene: GameScene, x: number, y: number) {
        super(scene, x, y, "dino-idle");
        this.scene = scene; // GameScene 타입의 장면 저장
    }

    update() {
        // GameScene의 isGameRunning 속성에 접근
        if (!this.scene.isGameRunning) {
            return;
        }

        // 캐릭터의 업데이트 로직 작성
    }
}

```

```jsx
Player 클래스에서 scene의 타입을 GameScene으로 설정하고

사용하는 부분을 초보자도 이해하기 쉽도록 상세히 설명
```

### 1. **`scene`이란?**

```jsx
Phaser에서 scene은 게임 화면을 구성하는 하나의 단위를 뜻합니다. 예를 들어:

게임 시작 화면

실제 플레이 화면

게임 종료 화면 이러한 각각의 화면이 하나의 scene입니다.

Player 클래스는 캐릭터(플레이어)를 나타내는 객체인데, 이 캐릭터는 반드시 특정 scene 안에서 동작해야 합니다.

즉, Player 클래스는 자신이 속한 scene을 알고 있어야 합니다. 이 정보는 생성자의 첫 번째 매개변수로 전달됩니다.
```

### 2. **기존의 `scene` 문제**

```jsx
기본적으로 scene의 타입은 Phaser.Scene입니다. Phaser.Scene은 Phaser에서 제공하는 기본 scene 클래스인데,

이 클래스는 기본적인 기능만 가지고 있습니다.

예를 들어, 우리가 새롭게 추가한 isGameRunning 같은 변수는 Phaser.Scene에는 없습니다.

그래서 기존 방식으로는 Player 클래스에서 isGameRunning 같은 변수를 사용하려면 추가 작업(예: 타입 캐스팅)이 필요했습니다.
```

### 3. **`GameScene` 타입 지정으로 문제 해결**

```jsx
GameScene은 우리가 Phaser.Scene을 확장해서 만든 클래스입니다. 이 클래스에는 다음과 같은 추가 기능이 포함되어 있습니다:

gameHeight, gameWidth: 게임 화면의 높이와 너비를 가져오는 속성.

isGameRunning: 게임이 실행 중인지 확인하는 속성.

따라서, scene의 타입을 GameScene으로 지정하면,

Player 클래스는 isGameRunning 같은 추가 기능을 바로 사용할 수 있습니다.
```

### 타입을 지정하는 이유

```jsx
scene:

GameScene 이 부분은 Player가 어떤 타입의 scene에 속해 있는지를 명확히 지정한 것입니다.

이렇게 하면 다음과 같은 장점이 있습니다:

isGameRunning에 바로 접근 가능:

GameScene에서 제공하는 속성(isGameRunning)을 사용할 수 있습니다.

코드 작성 시 오류 방지:

잘못된 타입의 scene이 전달되면 컴파일 시점에 오류를 알 수 있습니다.

코드 가독성 증가:

scene이 GameScene 타입임을 명시적으로 나타내므로, 어떤 속성과 기능을 사용할 수 있는지 한눈에 알 수 있습니다.
```

# { 장애물 생성하기 }

## 1. `update` 함수의 역할

```jsx
update 함수는 게임 루프의 핵심입니다.

게임에서 매 프레임마다 호출되며, 프레임마다 변경되는 데이터를 처리하거나,

움직임, 애니메이션, 충돌 체크 등을 수행합니다.
```

## 2. `time`과 `delta`의 의미

```jsx
time:

		게임이 시작된 이후 누적된 시간을 밀리초(ms) 단위로 나타냅니다.

		예를 들어, 게임이 시작되고 3초가 지났다면 time 값은 3000입니다.

delta:

		이전 프레임과 현재 프레임 사이의 시간 간격을 밀리초(ms) 단위로 나타냅니다.

		일반적으로 **프레임 속도(FPS)**에 따라 값이 변합니다.

		예: 60 FPS → 16.67ms, 120 FPS → 8.33ms.
```

## 3. FPS(프레임 속도) 계산

```jsx
FPS는 초당 프레임 수를 의미합니다.

계산 방법:

		1000 ÷ delta = FPS

		예: delta가 16.67이라면 FPS는 약 60입니다.
```

## 4. 장애물 생성하기

```jsx
장애물을 생성하려면 특정 시간 간격(예: 1.5초)마다 장애물을 생성해야 합니다. 이를 위해 두 가지 변수를 사용합니다:

spawnInterval: 장애물을 생성하는 시간 간격 (기본값: 1500ms).

spawnTime: 장애물이 생성된 이후 누적된 시간 (초기값: 0).
```

## 5. 장애물 생성 로직

```jsx
1. pawnInterval과 spawnTime 변수 선언:

		spawnInterval은 장애물을 얼마나 자주 생성할지 결정합니다 (예: 1.5초 = 1500ms).

		spawnTime은 delta 값을 누적해 현재까지의 경과 시간을 기록합니다.

2. update 함수에서 시간 누적:

		매 프레임마다 delta 값을 spawnTime에 더합니다.

3. 시간이 일정 간격을 초과하면 장애물 생성:

		spawnTime이 spawnInterval보다 크거나 같아지면 장애물을 생성합니다.

		이후 spawnTime을 0으로 초기화하여 다시 누적이 시작됩니다.

```

## 6. 코드 설명

```jsx
// 장애물 생성 간격 (1.5초 = 1500ms)
spawnInterval: number = 1500;
// 누적 시간 초기화
spawnTime: number = 0;

// update 함수
update(time: number, delta: number): void {
    // delta(프레임 간 시간)를 누적
    this.spawnTime += delta;

    // 누적된 시간이 생성 간격을 초과하면
    if (this.spawnTime >= this.spawnInterval) {
        // 장애물 생성 (지금은 콘솔에 메시지만 출력)
        console.log("장애물 생성!");

        // 누적 시간을 초기화
        this.spawnTime = 0;
    }
}

```

## 요약

```jsx
1. update 함수는 매 프레임 호출되며 게임의 동적인 요소를 처리합니다.

2. **delta**는 프레임 간 시간 간격이며, FPS에 따라 값이 달라집니다.

3. 장애물은 spawnInterval을 기준으로 1.5초 간격으로 생성됩니다.

4. spawnTime에 delta 값을 더해 시간을 측정하고, 조건에 따라 초기화합니다.
```

## `time` 대신 `delta`를 사용하는 이유

```jsx
게임의 **프레임 속도(FPS)**는 항상 일정하지 않습니다. 예를 들어:

느린 기기에서 FPS가 30으로 떨어지면, 각 프레임의 delta 값은 약 33ms입니다.

빠른 기기에서 FPS가 120이면, 각 프레임의 delta 값은 약 8ms입니다.

만약 time을 기반으로 코드를 작성하면, 프레임 속도가 낮아지는 상황에서 문제가 발생할 수 있습니다.

반면, delta를 사용하면 프레임 속도에 관계없이 동일한 시간 간격으로 동작을 구현할 수 있습니다.
```

## 3. 장애물 생성 함수

```jsx
장애물을 무작위로 생성합니다. 이를 위해 장애물 이미지를 무작위로 선택하고, 생성 위치를 지정합니다.

주요 개념:

		무작위 숫자 생성: Math.random()과 Math.floor()를 사용하여 1부터 6 사이의 정수를 생성합니다.

		위치 지정: 장애물을 특정 범위(예: X좌표 600~900)에서 생성하고 Y좌표는 게임의 바닥 높이에 고정합니다.
```

```jsx
spawnObstacle() {
    const obstacleNum = Math.floor(Math.random() * 6) + 1; // 1부터 6까지 무작위 선택
    const distance = Phaser.Math.Between(600, 900); // X좌표 범위 내에서 무작위

    // 장애물 생성
    this.obstacles.create(distance, this.gameHeight, `obstacle-${obstacleNum}`)
        .setOrigin(0, 1); // 좌하단을 기준으로 설정
}
```

## 1. 프리로드 설정이란?

```jsx
프리로드 설정은 게임 시작 전 필요한 리소스(이미지, 소리 등)를 미리 로드하는 작업입니다.

이를 통해 게임 도중 리소스가 로드되지 않아 생기는 지연이나 문제가 방지됩니다.


		장애물들은 같은 이름과 같은 에셋을 공유하지만 번호(1, 2, 3 등)만 다릅니다.

		따라서 반복문을 사용해 이름과 번호를 조합하여 간편하게 로드하도록 구현합니다.

```

## 2. 프리로드 설정 구현

```jsx
A. 프리로드 설정 변수 생성

이 설정은 로드할 장애물의 개수를 포함하며,

다른 파일에서도 사용할 수 있도록 **내보내기(export)**합니다.
```

```jsx
B. 프리로드 장면에서 반복문으로 장애물 로드

PreloadScene에서 반복문을 이용해 장애물을 로드합니다.

반복문 사용하기

PRELOAD_CONFIG의 cactusesCount 값을 기준으로 1부터 6까지 장애물을 로드합니다.

파일명은 obstacle-1, obstacle-2처럼 구성되므로 번호만 바꿔가며 로드하면 됩니다.
```

```jsx
import { PRELOAD_CONFIG } from '..'

class PreloadScene extends Phaser.Scene {
  constructor() {
    super('PreloadScene')
  }

  preload() {
    // 배경과 기본 캐릭터 로드
    this.load.image('ground', 'assets/ground.png')
    this.load.image('dino-idle', 'assets/dino-idle-2.png')

    // 장애물 반복 로드
    for (let i = 0; i < PRELOAD_CONFIG.cactusesCount; i++) {
      const cactusNum = i + 1 // 번호는 1부터 시작
      this.load.image(`obstacle-${cactusNum}`, `assets/cactuses_${cactusNum}.png`)
    }

    // 추가 스프라이트 로드
    this.load.spritesheet('dino-run', 'assets/dino-run.png', {
      frameWidth: 88,
      frameHeight: 94,
    })
  }

  create() {
    // 다음 PlayScene으로 전환
    this.scene.start('PlayScene')
  }
}

export default PreloadScene
```

### Phaser.Actions ???

```jsx
Phaser.Actions는 Phaser 게임 엔진의 유틸리티 클래스로,

그룹이나 배열에 포함된 여러 객체에 동일한 동작을 일괄 적용할 수 있도록 설계된 도구입니다.

반복문을 직접 작성하지 않아도 여러 객체의 속성을 간단하게 수정할 수 있어, 효율적이고 간결한 코드를 작성하는 데 유용합니다.
```

```jsx
1. Phaser.Actions의 개념

역할: 게임 내 여러 객체(예: 장애물, 적, 배경 요소 등)의 위치, 크기, 속성 등을 한 번에 변경.

적용 대상: Phaser의 그룹(Phaser.Group)이나 배열(Array)로 관리되는 객체들.

장점:

		여러 객체에 대한 반복적인 동작을 단순화.

		코드 가독성을 높이고 유지보수성을 향상.

주요 특징 요약

1. 일괄 처리: 한 번의 호출로 그룹 내 모든 객체에 동일한 동작 적용.

2. 다양한 조작: 위치, 크기, 회전, 투명도 등 다양한 속성을 쉽게 변경 가능.

3. 유연성: 배열뿐 아니라 Phaser의 그룹에서도 바로 사용 가능.
```

```jsx

SetX

SetY

모든 객체의 Y 좌표를 특정 값으로 설정.
```

## 1. **현재 상황**

```jsx
장애물이 맵에서 이동하면서 플레이어에게 다가오고 있지만,
```

## 2. **문제 확인**

```jsx
update() 함수에서 장애물의 개수를 확인하기 위해 this.obstacles.getChildren().length를 console.log로 출력.

맵을 벗어난 장애물도 obstacles 그룹에 남아 있는 것을 확인.
```

## 3. **문제 해결 방법**

```jsx
목표: 맵을 벗어난 장애물을 감지하고 제거.

장애물의 오른쪽 경계(getBounds().right) 값을 사용해 경계가 0보다 작아질 경우 해당 장애물을 삭제.
```

## 4. **코드 수정**

```jsx
update() 함수에 아래와 같은 로직 추가:

		모든 장애물을 반복(forEach()) 순회.

		각 장애물의 오른쪽 경계(getBounds().right) 값 확인.

		값이 0보다 작으면 this.obstacles.remove(obstacle)을 호출하여 장애물을 그룹에서 제거.
```

```jsx
this.obstacles.getChildren().forEach((obstacle: SpriteWithDynamicBody) => {
    if (obstacle.getBounds().right < 0) {
        this.obstacles.remove(obstacle);
    }
});
```

```jsx

3. 각 장애물의 경계(getBounds().right)를 확인.

4. 경계가 0보다 작아지면 해당 장애물을 this.obstacles.remove()를 사용해 제거.

5. 장애물 제거 후, 남아 있는 장애물의 개수를 확인(console.log)하여 잘 작동하는지 검증.
```

```jsx
이 강의에서는 게임의 **땅(ground)**을 움직이는 것처럼 보이게 하는 효과를 구현하는 방법을 다룹니다.

이 효과는 사실 땅이 이동하는 것이 아니라, 재활용(recycling) 되는 방식으로 구현됩니다.

* 쉽게 말하면 왼쪽으로 저 타일의 시작점 ( 맨 왼쪽 ) 을 계속 움직이는 것 ( 그러면 타일스프라이트는 계속 반복 되니까 오른쪽에는 계속 생긴다 )
```

## 1. **문제 정의: 땅을 어떻게 움직일까?**

```jsx
플레이어는 땅 위에서 달리고 있습니다.

땅을 왼쪽으로 계속 이동시키려면, 땅이 화면 끝에 도달했을 때 사라지지 않고 연속적인 움직임을 보여야 합니다.

실제로 땅을 이동시키는 대신, 땅의 타일 스프라이트(Tile Sprite) 속성을 사용하여 재활용하면 훨씬 효율적으로 구현할 수 있습니다.
```

## 2. **타일 스프라이트(Tile Sprite)란?**

```jsx
타일 스프라이트는 패턴이 반복되는 텍스처를 가진 게임 오브젝트입니다.

특정 속성을 조작하면 텍스처가 스크롤되는 것처럼 보이게 할 수 있습니다.

즉, 땅 전체를 움직이는 대신 텍스처만 움직여 화면에 땅이 반복적으로 나타나는 효과를 줄 수 있습니다.
```

## 3. **구현 원리**

```jsx
3.1 땅의 움직임 효과

		땅의 텍스처를 왼쪽으로 이동시키면, 앞쪽에 있던 텍스처 일부가 뒤쪽으로 재활용됩니다.

		이렇게 하면 텍스처가 계속해서 움직이는 것처럼 보입니다.

		실제로는 땅이 이동하지 않고, 텍스처만 순환(scroll) 되기 때문에 성능이 훨씬 효율적입니다.

3.2 기본 개념

		텍스처를 조작하는 핵심은 tilePositionX 속성을 변경하는 것입니다.

				tilePositionX는 텍스처가 렌더링되는 시작 지점을 나타냅니다.

				매 프레임마다 이 값을 증가시키면 텍스처가 왼쪽으로 이동하는 것처럼 보입니다.
```

## 4. **구현 코드 설명**

```jsx
4.1 타일 스프라이트 생성

this.ground = this.add.tileSprite(0, this.gameHeight, 88, 26, "ground").setOrigin(0, 1);

		tileSprite로 땅을 생성합니다.

				0, this.gameHeight: 땅의 시작 위치입니다.

				88, 26: 땅의 크기(너비와 높이)입니다.

				"ground": 땅의 텍스처 이름입니다.

				.setOrigin(0, 1): 땅의 기준점을 왼쪽 하단으로 설정합니다.



4.2 땅 텍스처를 이동시키는 로직

this.ground.tilePositionX += this.gameSpeed;

		매 프레임마다 tilePositionX 값을 증가시킵니다.

				this.gameSpeed는 땅이 움직이는 속도를 제어합니다.

				예: gameSpeed = 5라면, 땅의 텍스처가 한 프레임당 5픽셀씩 왼쪽으로 이동하는 효과가 나타납니다.
```

```jsx
				우리는 땅을 왼쪽으로 움직이는 것처럼 보이게 하고 싶어요.

				하지만 실제로는 땅이 움직이지 않고, 텍스처(그림)만 스르륵 밀리는 효과를 만들어냅니다.
```

```jsx
				[초록][갈색][돌][풀]

				여기서 중요한 점은 게임 화면이 텍스처의 특정 부분만 보여주고 있다는 겁니다.



		3.2 텍스처는 무한히 반복되는 그림

				텍스처는 실제로 끝이 없고, 계속 이어지는 무한한 그림처럼 작동합니다:

				...[초록][갈색][돌][풀][초록][갈색][돌][풀]...

				텍스처의 앞쪽과 뒤쪽이 자연스럽게 연결된다고 생각하면 돼요.
```

```jsx
4. 화면에서 텍스처가 움직이는 원리

4.1 tilePositionX가 텍스처의 시작 지점을 옮김

		tilePositionX는 "화면에 표시될 텍스처의 시작 위치"를 결정합니다.

		아래처럼 tilePositionX를 살짝 증가시키면 텍스처가 왼쪽으로 밀리는 것처럼 보입니다.


				1. 처음 상태 (tilePositionX = 0):

				[초록][갈색][돌][풀]

				텍스처의 맨 앞부분 [초록]이 화면의 왼쪽 끝에 보입니다.


				2. tilePositionX가 1 증가:

				[갈색][돌][풀][초록]

				텍스처의 시작 지점이 오른쪽으로 살짝 옮겨져, [초록]이 화면에서 사라지고 [갈색]이 앞으로 옵니다.

				뒤쪽에서는 [초록]이 다시 붙어서 계속 이어집니다.


				3. 계속 증가:

				매번 tilePositionX가 증가하면 텍스처가 계속 밀리는 효과를 만듭니다

				[돌][풀][초록][갈색]  ←  tilePositionX = 2
				[풀][초록][갈색][돌]  ←  tilePositionX = 3
```

# { 충돌 처리 및 장애물 고정하기 }

```jsx
이 강의에서는 플레이어와 장애물 간 충돌 처리를 구현하고,

장애물이 움직이지 않도록 설정하는 방법을 다룹니다.
```

## 1. 충돌 처리

```jsx
Phaser에서는 그룹 단위로 충돌을 처리할 수 있습니다.

장애물 그룹과 플레이어 간 충돌이 발생하면 게임을 멈추고,

모든 물리적 상호작용(속도, 중력 등)을 중지하도록 설정합니다.

다음은 주요 구현 단계입니다:

		1. Physics Collider 추가

				충돌 처리를 위해 this.physics.add.collider()를 사용합니다.

				충돌 시 호출할 콜백 함수도 함께 정의합니다.


		2. 게임 상태를 멈추기

				충돌이 발생하면 isGameRunning 변수를 false로 설정하고,

				this.physics.pause()로 모든 물리 연산을 중지합니다.
```

```jsx
this.physics.add.collider(this.obstacles, this.player, () => {
  // 충돌 발생 시
  this.physics.pause() // 물리 엔진 정지
  this.isGameRunning = false // 게임 실행 중단
})
```

## 2. 장애물 고정하기

```jsx
플레이어가 장애물과 충돌했을 때 장애물이 움직이지 않도록 설정합니다.

이를 위해 setImmovable() 메서드를 사용합니다.

1. spawnObstacle 메서드 수정

		장애물을 생성한 후 setImmovable()를 호출하여 고정 상태로 만듭니다.

		이렇게 하면 충돌로 인해 장애물이 움직이지 않습니다.
```

```jsx
spawnObstacle() {
    const obstacleNum = Math.floor(Math.random() * PRELOAD_CONFIG.cactusesCount + 1);
    const distance = Phaser.Math.Between(600, 900);

    const obstacle = this.obstacles
        .create(distance, this.gameHeight, `obstacle-${obstacleNum}`)
        .setOrigin(0, 1)
        .setImmovable(); // 장애물 고정
}
```

## 3. 동작 확인

```jsx
장애물과 충돌하면 게임이 멈춥니다.

장애물이 움직이지 않고 고정됩니다.
```

## 전체 코드

```jsx
import Phaser from "phaser";
import { SpriteWithDynamicBody } from "../types";
import { Player } from "../entities/Player";
import { GameScene } from "../GameScene";
import { PRELOAD_CONFIG } from "..";

class PlayScene extends GameScene {
    player: Player;
    startTrigger: SpriteWithDynamicBody;
    ground: Phaser.GameObjects.TileSprite;
    obstacles: Phaser.Physics.Arcade.Group;
    spawnInterval: number = 1500;
    spawnTime: number = 0;
    gameSpeed: number = 5;

    constructor() {
        super("PlayScene");
    }

    create() {
        this.createEnvironment();
        this.createPlayer();
        this.obstacles = this.physics.add.group();
        this.startTrigger = this.physics.add.sprite(0, 10, null)
            .setAlpha(0)
            .setOrigin(0, 1);

        // 장애물과 플레이어 충돌 처리
        this.physics.add.collider(this.obstacles, this.player, () => {
            this.physics.pause(); // 물리 엔진 정지
            this.isGameRunning = false; // 게임 실행 중단
        });
    }

    update(time: number, delta: number): void {
        if (!this.isGameRunning) {
            return;
        }

        this.spawnTime += delta;

        if (this.spawnTime > this.spawnInterval) {
            this.spawnObstacle(); // 장애물 생성
            this.spawnTime = 0;
        }

        Phaser.Actions.IncX(this.obstacles.getChildren(), -this.gameSpeed);

        this.obstacles.getChildren().forEach((obstacles: SpriteWithDynamicBody) => {
            if (obstacles.getBounds().right < 0) {
                this.obstacles.remove(obstacles);
            }
        });

        this.ground.tilePositionX += this.gameSpeed;
    }

    createPlayer() {
        this.player = new Player(this, 0, this.gameHeight);
    }

    createEnvironment() {
        this.ground = this.add.tileSprite(0, this.gameHeight, 88, 26, "ground").setOrigin(0, 1);
    }

    spawnObstacle() {
        const obstacleNum = Math.floor(Math.random() * PRELOAD_CONFIG.cactusesCount + 1);
        const distance = Phaser.Math.Between(600, 900);

        const obstacle = this.obstacles
            .create(distance, this.gameHeight, `obstacle-${obstacleNum}`)
            .setOrigin(0, 1)
            .setImmovable(); // 장애물 고정
    }
}

export default PlayScene;

```
