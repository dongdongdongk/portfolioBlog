# Express 라우터에서 미들웨어를 사용하는 방법

```jsx
미들웨어는 요청과 응답 사이에서 동작하며 필요에 따라 라우트에 추가할 수 있다.
```

```jsx
router.use((req, res, next) => {
  // 미들웨어 로직 수행
  console.log('This middleware runs for all routes.')
  next() // 다음 미들웨어로 넘어가거나 다음 라우트로 진행
})

router.get('/admin', (req, res) => {
  res.send('Admin page')
})
```

```jsx
이 예제에서는 /admin 경로에 대한 라우트 앞에 미들웨어를 추가했다.

이 미들웨어는 모든 라우트에 적용되며, 해당 라우트로 이동하기 전에 로그를 출력한다.
```

## 특정 라우트에만 미들웨어를 추가

```jsx
예를 들어, admin 라우터 파일에서 다음과 같이 미들웨어를 추가할 수 있다. ( admin 라우터 파일 내부 )
```

```jsx
const express = require('express')
const router = express.Router()

const requireAdmin = (req, res, next) => {
  if (req.query.isAdmin) {
    next()
  } else {
    res.send('SORRY NOT AN ADMIN!')
  }
}

router.use(requireAdmin) // 아예 함수를 넣어서 사용도 가능

router.get('/topsecret', (req, res) => {
  res.send('THIS IS TOP SECRET')
})

router.get('/deleteeverything', (req, res) => {
  res.send('OK DELETED IT ALL!')
})

// 미들웨어를 추가해서 사용하기
router.get('/deleteeverything', requireAdmin, (req, res) => {
  res.send('OK DELETED IT ALL!')
})

module.exports = router
```

```jsx
이 예제에서는 requireAdmin 미들웨어를 /topsecret 및 /deleteeverything 라우트에만 적용하도록 했다.

쿼리 문자열에 isAdmin이 있으면 다음 라우트로 이동하고,

없으면 'SORRY NOT AN ADMIN!'을 응답으로 보낸다.

이렇게 Express 라우터를 사용하면 코드를 모듈화하고 유지 관리하기 쉽게 만들 수 있으며,

미들웨어를 특정 라우트에만 적용할 수 있어 매우 유연한 웹 애플리케이션을 구축할 수 있다.
```

# 쿠키 개요

## **쿠키란 무엇인가**

```jsx
쿠키는 작은 정보 조각으로, 웹 페이지 방문 시 사용자의 브라우저에 저장된다.

이 정보는 서버에서 반환되어 브라우저에 저장되며, 사용자의 다음 요청에 함께 전송된다.

주로 사용자의 상태를 추적하거나 선호 사항을 저장하기 위해 활용된다.

* 쿠키를 확인하려면 개발자 모드에서 어플리케이션에 들어가면 확인 가능하다
```

## **쿠키의 필요성은 무엇인가**

```jsx
HTTP는 무상태 프로토콜이므로 각각의 요청은 개별적이다.

하지만 쿠키를 사용하면 서버는 사용자에 대한 정보를 브라우저에 저장하고,

사용자가 재방문할 때마다 해당 정보를 전송받아 상태를 유지할 수 있다.
```

## **쿠키의 활용 예시**

```jsx
**개인화 (Personalization)**:

사용자에 대한 정보를 저장하여 사용자 경험을 향상시킨다.

예를 들어, 다크 모드 또는 라이트 모드와 같은 사용자 환경 설정을 기억할 수 있다.

**장바구니 관리**:

온라인 쇼핑에서는 장바구니에 담긴 상품 정보를 쿠키에 저장하여 사용자가 페이지를 이동하더라도 장바구니를 기억한다.
```

## **쿠키의 동작 방식**

```jsx
1. 사용자가 웹 페이지를 방문하면 서버에서 쿠키를 생성하고 브라우저에 전송한다.

2. 브라우저는 쿠키를 저장하고, 해당 웹 사이트에 재방문할 때마다 쿠키를 함께 전송한다.

3. 서버는 전송된 쿠키를 해석하여 사용자를 식별하거나 저장된 정보를 활용한다.
```

## **쿠키의 주의 사항**

```jsx
**개인 정보 보호**:

쿠키를 통한 추적은 개인 정보 보호 문제를 유발할 수 있다. 관련 법률에 따라 쿠키 사용 시 동의를 받아야 하는 경우도 있다.

**보안**:

민감한 정보를 담는 쿠키는 안전한 방식으로 전송되고 저장되어야 한다.
```

# 쿠키 찾아서 파싱하기

```jsx
const express = require('express')
const app = express()

app.get('/greet', (req, res) => {
  res.send('HEY THERE')
})

app.get('/setname', (req, res) => {
  res.cookie('name', 'dongdongk')
  res.send('OK Cookie')
})

app.listen(3000, () => {
  console.log('Server---3000')
})
```

```jsx
위의 내용에서 setname 라우터에서 name이 dongdongk인 쿠키를 생성하여 클라이언트에게 전송하였다

( 서버는 클라이언트에게 name이 "dongdongk"인 쿠키를 설정하고, 이를 응답(response) 헤더에 포함시켜 클라이언트에게 전했다. )

이제 /greet 로 이동해보면 역시 name : dongdongk 가 있다

/greet 엔드포인트로 요청을 보낼 때 브라우저는 자동으로 이전에 설정된 쿠키를 요청에 포함시켜 서버에 전달한다.

서버는 이를 request.cookies 객체에 담아 해당 요청을 처리한다 ( 고로 개발자는 해당 값을 쉽게 활용할 수 있다 )
```

## cookie parser

```jsx
Express는 기본적으로 요청에서 쿠키를 파싱하여 request.cookies에 저장한다.

그러나 외부에서 ( Express 앱의 설정 파일이나 라우터 등)

이 값을 사용하려면 cookie-parser 패키지를 설치하고 미들웨어로 사용해야 한다.

cookie-parser를 사용하면 request.cookies에 들어있는 쿠키 값을 쉽게 다룰 수 있다.
```

```jsx
npm i cookie-parser
```

```jsx
위의 npm 을 설치해주고 아래와 같이 모듈을 넣고

app.use 를 작성해주고 콘솔을 이용해서 /greet 로 이동해서 확인해보면
```

```jsx
const express = require('express')
const app = express()

const cookieParser = require('cookie-parser')
app.use(cookieParser())

app.get('/greet', (req, res) => {
  console.log(req.cookies)
  res.send('HEY THERE')
})

  res.cookie('name', 'dongdongk')
  res.send('OK Cookie')
})

  console.log('Server---3000')
})
```

# 서명된 쿠키

```jsx
서명된 쿠키는 일종의 보안 기술로, 정보의 무결성을 확인하고 조작 여부를 방지하는 데 사용된다.

서명된 쿠키를 활용하려면 쿠키 파서를 사용하며, 이를 위해 비밀 문자열을 전달해야 한다.

서명된 쿠키를 사용하면 쿠키에 직접 값을 보내는 대신 쿠키 파서가 지정한 비밀 코드로 서명하여 클라이언트에게 전송합한다.

클라이언트는 서명된 쿠키를 다른 쿠키들과 동일하게 돌려주지만, 서버 측에서는 쿠키를 확인하여 누군가가 쿠키를 변경하지 않았는지를 검증한다.

이렇게 서명된 쿠키를 사용하면 정보의 무결성을 확인하고,

클라이언트에서 서버로 전송된 데이터가 변경되지 않았음을 보장할 수 있다.

이는 암호화와는 다른 원리로 작동하며, 주로 데이터의 무결성을 확보하는 데 활용된다.
```

## 서명된 쿠키의 진짜 기능 ( 무결성 확인 )

```jsx
서명된 쿠키는 디지털 서명이나 암호화된 서명과는 달리 정보를 암호화하거나 감추는 것이 아니라,

정보의 무결성을 확인하는 방식이다. 예를 들어, 편지를 밀랍으로 봉인하는 것과 유사한 개념으로 이해할 수 있다.

밀랍 봉인이 파손되지 않으면 편지가 온전히 보존되었다는 뜻이며,

서명된 쿠키도 클라이언트와 서버 간의 통신에서 정보의 무결성을 확인하는 역할을 한다.
```

## 서명된 쿠키의 원리

```jsx
서명된 쿠키를 사용하면 쿠키에 직접 값을 보내는 대신 쿠키 파서가 지정한 비밀 코드로 서명하여 클라이언트에게 전송한다.

클라이언트는 서명된 쿠키를 다른 쿠키들과 동일하게 돌려주지만, 서버 측에서는 쿠키를 확인하여 누군가가 쿠키를 변경하지 않았는지를 검증한다.

이렇게 서명된 쿠키를 사용하면 정보의 무결성을 확인하고,

클라이언트에서 서버로 전송된 데이터가 변경되지 않았음을 보장할 수 있다.

이는 암호화와는 다른 원리로 작동하며, 주로 데이터의 무결성을 확보하는 데 활용된다.
```

## 예제

```jsx
const express = require('express')
const app = express()

const cookieParser = require('cookie-parser')
app.use(cookieParser('thisismysecret')) //안에 문자가 쿠키 파서가 쿠키에 사인할 때 쓰임 그리고 쿠키를 돌려받았을 때 변함이 없는지도 확인

app.get('/greet', (req, res) => {
  const { name = '기본값' } = req.cookies
  res.send(`${name} Hi THERE`)
})

app.get('/setname', (req, res) => {
  res.cookie('name', 'dongdongk')
  res.send('OK Cookie')
})

app.get('/getsignedcookie', (req, res) => {
  res.cookie('fruit', 'grape', { signed: true }) // 비밀키 설정 true
  res.send('OK SIGNED')
})

app.listen(4000, () => {
  console.log('Server---3000')
})
```

# HMAC

```jsx
HMAC은 Hash-based Message Authentication Code의 약자로,

메시지 무결성과 인증을 보장하기 위한 해시 함수를 사용하는 기술이다.

여러 보안 애플리케이션에서 메시지의 무결성을 검증하고 메시지가 신뢰할 수 있는지 확인하는 데 사용된다.
```

## HMAC의 특징

```jsx
**안전한 해시 함수 사용**:

HMAC은 안전하게 알려진 해시 함수(예: SHA-256)를 사용하여 메시지에 대한 해시 값을 계산한다.

이로써 알려진 공격으로부터 안전한 해시 함수의 안전성을 누릴 수 있다.

**비밀 키 활용**:

HMAC은 메시지에 대한 해시 값을 생성할 때 비밀 키를 사용한다.

이는 메시지의 인증을 담당하며, 비밀 키가 없으면 올바른 해시 값을 생성할 수 없다.

**무결성과 진정성 확인**:

HMAC은 메시지의 무결성을 보장하여 메시지가 변조되지 않았음을 확인한다.

또한, 메시지를 생성한 소스가 신뢰할 만한지 인증하여 진정성을 확인한다.

**보안 강화**:

기본적인 해시 함수만 사용하는 것보다 HMAC은 추가적인 보안 계층을 제공한다.

이는 일반적인 해시 함수로 인한 여러 공격을 방어할 수 있게 해준다.
```

## HMAC 서명하기

```jsx

**서명과 HMAC(Hash-based Message Authentication Code) 소개**:

서명은 메시지의 무결성과 진정성을 보장하기 위한 과정이다.

HMAC은 Hash-based Message Authentication Code의 약자로, 서명에 사용되는 메시지 인증 코드이다.

서명은 주로 쿠키를 대상으로 하지만, 다양한 환경에서 활용 가능하다.

**쿠키 파서와 cookie signature 패키지**:

쿠키 파서는 서명 작업을 위해 cookie signature 패키지와 함께 사용된다.

'cookie signature' 패키지는 서명과 서명 해제 기능을 제공한다.

**서명 작업의 구체적인 과정**:

서명을 위해서는 값을 서명하려는 값과 비밀 키가 필요하며, 이 둘 중 하나가 빠지면 오류가 발생한다.

HMAC을 사용하여 sha256 해시 함수와 비밀 키를 이용하여 쿠키에 서명한다.

서명된 쿠키는 무결성과 진정성을 확인하는 데 도움이 된다.

**쿠키 서명의 시각적 확인**:

COMPUTE HMAC을 사용하여 쿠키를 서명하고, 서명 값을 확인하는 과정을 시각적으로 확인해본다

결과를 복사하여 원래 쿠키와 비교함으로써 무결성을 확인할 수 있다
```
