## 3. app.json 주요 설정

```json
{
  "expo": {
    "name": "ReState", // 앱 이름 (홈 화면에 표시)
    "slug": "restate", // Expo 고유 식별자
    "version": "1.0.0", // 앱 버전

    "newArchEnabled": true // 새 아키텍처 활성화 (성능 향상)
  }
}
```

## 4. 새 아키텍처(Bridgeless Architecture)란?

React Native의 성능을 크게 향상시킨 핵심 업데이트입니다.

### 기존 아키텍처 (브릿지 방식)

```
JavaScript 코드
      ↕ (브릿지를 통해 통신 — 느림, 병목 발생)
네이티브 코드 (iOS/Android)
```

**문제점**: 브릿지가 모든 통신을 중계해서 성능 병목, 화면 끊김 등 발생

### 새 아키텍처 (브릿지 없음)

```
JavaScript 코드
      ↕ (JSI로 직접 통신 — 빠름)
네이티브 코드 (iOS/Android)
```

**개선점**: 브릿지 제거 → 직접 통신으로 성능 대폭 향상

### 새 아키텍처의 3가지 핵심 기술

| 기술                           | 역할                                    |
| ------------------------------ | --------------------------------------- |
| **JSI** (JavaScript Interface) | JS ↔ 네이티브 직접 통신                |
| **Fabric**                     | UI 렌더링 최적화                        |
| **Turbo Modules**              | 필요한 모듈만 불러오기 (시작 속도 향상) |

> 💡 `app.json`에 `"newArchEnabled": true` 한 줄만 추가하면 Expo가 자동으로 활성화해줍니다.

## 📋 만들 화면 구조 미리 보기

```
앱 전체 구조
├── 로그인 화면 (탭 없음)          → /signin
├── (root)/                        ← 루트 그룹
│   ├── (tabs)/                    ← 탭 네비게이션 그룹
│   │   ├── index.tsx              → /          (홈)
│   │   ├── explore.tsx            → /explore   (탐색)
│   │   └── profile.tsx            → /profile   (프로필)
│   └── properties/
│       └── [id].tsx               → /properties/1 (매물 상세)
```

> 💡 **핵심 포인트**: 홈/탐색/프로필은 탭이 있고, 로그인/매물 상세는 탭이 없습니다.
> 이걸 구분하기 위해 폴더 구조를 나눕니다.

---

## 1. 라우트 그룹이 필요한 이유

탭 네비게이션(하단 메뉴)을 **특정 화면에만** 보여주려면
화면들을 그룹으로 묶어야 합니다.

```
탭이 있는 화면: 홈, 탐색, 프로필
탭이 없는 화면: 로그인, 매물 상세

→ 탭 있는 화면끼리 (tabs) 폴더로 묶기
→ 탭 없는 화면은 바깥에 배치
```

## 3. 각 파일 코드

### 로그인 화면

```tsx
// app/signin.tsx

import { View, Text } from 'react-native'

export default function SignIn() {
  return (
    <View>
      <Text>로그인 화면</Text>
    </View>
  )
}
```

### 홈 화면

```tsx
// app/(root)/(tabs)/index.tsx

import { View, Text } from 'react-native'
import { Link } from 'expo-router'

export default function Home() {
  return (
    <View>
      {/* Link: 다른 화면으로 이동하는 컴포넌트 — 웹의 <a href>와 같음 */}
      <Link href="/signin">로그인 화면으로</Link>
      <Link href="/explore">탐색 화면으로</Link>
      <Link href="/profile">프로필 화면으로</Link>

      {/* 동적 라우트 예시: 1번 매물의 상세 페이지 */}
      <Link href="/properties/1">매물 상세 (1번)</Link>
    </View>
  )
}
```

### 탐색 화면

```tsx
// app/(root)/(tabs)/explore.tsx

import { View, Text } from 'react-native'

export default function Explore() {
  return (
    <View>
      <Text>탐색 화면</Text>
    </View>
  )
}
```

### 프로필 화면

```tsx
// app/(root)/(tabs)/profile.tsx

import { View, Text } from 'react-native'

export default function Profile() {
  return (
    <View>
      <Text>프로필 화면</Text>
    </View>
  )
}
```

### 매물 상세 화면 (동적 라우트)

```tsx
// app/(root)/properties/[id].tsx
// [id]: URL의 숫자/문자가 여기로 들어옴
// 예: /properties/42 → id = "42"

import { View, Text } from 'react-native'
import { useLocalSearchParams } from 'expo-router'

export default function Property() {
  // URL 파라미터에서 id 꺼내기
  // /properties/42 접속 시 → id = "42"
  const { id } = useLocalSearchParams()

  return (
    <View>
      <Text>{id}번 매물 상세 페이지</Text>
    </View>
  )
}
```

## 4. 라우트 그룹 `()` 폴더의 역할

```
(root)  → URL에 나타나지 않음
(tabs)  → URL에 나타나지 않음

/properties/1         ← URL (root와 tabs는 URL에 미포함)
/signin               ← URL
/explore              ← URL (tabs 폴더 안이지만 URL엔 없음)
```

> 💡 괄호로 감싼 폴더명은 URL에 포함되지 않습니다.
> 화면을 논리적으로 묶는 **코드 구조 용도**로만 쓰입니다.

---

## 5. 라우트 이동 방법 2가지

### 방법 1: Link 컴포넌트 (버튼처럼 클릭)

```tsx
import { Link } from "expo-router";

// 클릭하면 해당 경로로 이동
<Link href="/signin">로그인으로 이동</Link>
<Link href="/properties/42">42번 매물 보기</Link>
```

### 방법 2: useRouter (코드로 이동)

```tsx
import { useRouter } from 'expo-router'

export default function Home() {
  const router = useRouter()

  // 버튼 누를 때 등 특정 조건에서 코드로 이동
  const handleLogin = () => {
    router.push('/signin') // 새 화면으로 이동
  }

  const handleBack = () => {
    router.back() // 이전 화면으로 돌아가기
  }
}
```

> 💡 **Link vs useRouter**
>
> - `Link`: 단순히 눌러서 이동하는 버튼 → 간단한 이동에 적합
> - `useRouter`: 조건에 따라 코드로 이동 → 로그인 성공 후 이동 등에 적합

## 7. 네이티브 뒤로가기 동작

Expo Router를 쓰면 OS별 뒤로가기가 자동으로 동작합니다.

| OS          | 뒤로가기 방법                                                |
| ----------- | ------------------------------------------------------------ |
| **iOS**     | 화면 왼쪽 끝에서 오른쪽으로 스와이프 또는 상단 뒤로가기 버튼 |
| **Android** | 하드웨어 뒤로가기 버튼 또는 제스처                           |

별도 코드 없이 파일 기반 라우팅만으로 자동 구현됩니다.

| 파일 경로                        | URL               | 탭 여부 | 설명        |
| -------------------------------- | ----------------- | ------- | ----------- |
| `app/signin.tsx`                 | `/signin`         | ❌      | 로그인 화면 |
| `app/(root)/(tabs)/index.tsx`    | `/`               | ✅      | 홈 화면     |
| `app/(root)/(tabs)/explore.tsx`  | `/explore`        | ✅      | 탐색 화면   |
| `app/(root)/(tabs)/profile.tsx`  | `/profile`        | ✅      | 프로필 화면 |
| `app/(root)/properties/[id].tsx` | `/properties/:id` | ❌      | 매물 상세   |

## 🔑 핵심 요약

1. **`(폴더명)` 그룹** = URL에 안 보이고 화면 구조 정리용으로만 쓰임
2. **`[id].tsx`** = 동적 라우트, URL의 값을 `useLocalSearchParams`로 읽음
3. **탭 있는 화면** = `(tabs)` 폴더 안에 배치
4. **탭 없는 화면** = `(tabs)` 폴더 밖에 배치 (로그인, 매물 상세)
5. **새 파일 추가 후 `r`** = 리로드해야 새 라우트 인식
6. **`Link`** = 클릭으로 이동 / **`useRouter`** = 코드로 이동

## 💡 NativeWind가 뭐야?

웹에서는 Tailwind CSS로 `className="font-bold text-lg"`처럼 스타일을 씁니다.
React Native에서도 똑같이 쓸 수 있게 해주는 라이브러리가 **NativeWind**입니다.

```tsx
// 기존 React Native 스타일링 방식
<Text style={{ fontWeight: "bold", fontSize: 18, marginVertical: 10 }}>
  안녕하세요
</Text>

// NativeWind 방식 (훨씬 간결!)
<Text className="font-bold text-lg my-10">
  안녕하세요
</Text>
```

> 💡 NativeWind는 **컴포넌트 라이브러리가 아닙니다.**
> Button, Card 같은 완성된 컴포넌트를 주는 게 아니라,
> 기존 React Native 컴포넌트를 더 쉽게 스타일링하게 해주는 **스타일링 도구**입니다.

## 2단계: tailwind.config.js 수정

```jsx
// tailwind.config.js

/** @type {import('tailwindcss').Config} */
module.exports = {
  // content: Tailwind가 어느 파일에서 className을 찾을지 지정
  // 여기 없는 폴더의 파일은 스타일이 적용되지 않음!
  content: [
    './app/**/*.{js,jsx,ts,tsx}', // app 폴더 전체
    './components/**/*.{js,jsx,ts,tsx}', // components 폴더 전체
  ],
  theme: {
    extend: {
      // 커스텀 색상, 폰트 등을 여기에 추가
    },
  },
  plugins: [],
```

## 3. \_layout.tsx — 폰트 로딩 + 스플래시 스크린 제어

```tsx
// app/_layout.tsx

import { useEffect } from 'react'
import { useFonts } from 'expo-font'
import { SplashScreen, Stack } from 'expo-router'
import './globals.css'

// 폰트 로딩이 완료되기 전에 스플래시 스크린이 사라지는 것을 방지
SplashScreen.preventAutoHideAsync()

export default function RootLayout() {
  // useFonts: 폰트 파일을 불러오고 로딩 완료 여부를 반환
  const [fontsLoaded] = useFonts({
    // 왼쪽: 코드에서 사용할 이름  오른쪽: 실제 파일 경로
    'Rubik-Bold': require('../assets/fonts/Rubik-Bold.ttf'),
    'Rubik-ExtraBold': require('../assets/fonts/Rubik-ExtraBold.ttf'),
    'Rubik-Light': require('../assets/fonts/Rubik-Light.ttf'),
    'Rubik-Medium': require('../assets/fonts/Rubik-Medium.ttf'),
    'Rubik-Regular': require('../assets/fonts/Rubik-Regular.ttf'),
    'Rubik-SemiBold': require('../assets/fonts/Rubik-SemiBold.ttf'),
  })

  useEffect(() => {
    // 폰트 로딩이 완료되면 스플래시 스크린을 숨기고 앱 진입
    if (fontsLoaded) {
      SplashScreen.hideAsync()
    }
  }, [fontsLoaded]) // fontsLoaded가 바뀔 때마다 실행

  // 폰트가 아직 로딩 중이면 아무것도 표시하지 않음
  // (스플래시 스크린이 대신 보이고 있음)
  if (!fontsLoaded) return null

  // 폰트 로딩 완료 → 앱 정상 렌더링
  return (
    <Stack>
      <Stack.Screen name="(root)" options={{ headerShown: false }} />
      <Stack.Screen name="signin" options={{ headerShown: false }} />
    </Stack>
  )
}
```

### 스플래시 스크린 동작 흐름

```
앱 실행
  ↓
SplashScreen.preventAutoHideAsync() 호출
  → 스플래시 스크린이 자동으로 사라지지 않도록 막음
  ↓
폰트 로딩 중 (스플래시 스크린이 보임)
  ↓
fontsLoaded = true
  ↓
SplashScreen.hideAsync() 호출
  → 스플래시 스크린 사라짐 → 앱 화면 표시
```

## 5. images.d.ts — 이미지 TypeScript 타입 선언

TypeScript는 `.png`, `.jpg` 같은 이미지 파일을 모듈로 임포트하면 타입을 모릅니다.
이 파일로 "이미지 파일을 임포트하면 `any` 타입이다"라고 알려줍니다.

```tsx
// images.d.ts (루트 폴더에 생성)

// PNG 파일 임포트 타입 선언
declare module '*.png' {
  const value: any
  export default value
}

// JPG 파일 임포트 타입 선언
declare module '*.jpg' {
  const value: any
  export default value
}

// JPEG 파일 임포트 타입 선언
declare module '*.jpeg' {
  const value: any
  export default value
}

// GIF 파일 임포트 타입 선언
declare module '*.gif' {
  const value: any
  export default value
}

// SVG 파일 임포트 타입 선언
declare module '*.svg' {
  const value: any
  export default value
}
```

> 💡 이 파일이 없으면 `constants/icons.ts`에서 이미지를 임포트할 때
> **"Cannot find module"** 에러가 납니다.

## 3. login() — 구글 OAuth 로그인

```tsx
export async function login() {
  try {
    // STEP 1: 딥링크 리디렉트 URI 생성
    // 구글 로그인 완료 후 앱으로 돌아올 주소
    // 예: "exp://192.168.0.1:8081/" 또는 "restate://"
    const redirectUri = Linking.createURL('/')

    // STEP 2: Appwrite에 구글 OAuth 토큰 요청
    // → 구글 로그인 페이지 URL을 응답으로 받음
    const response = await account.createOAuth2Token(
      OAuthProvider.Google, // 구글로 로그인
      redirectUri // 로그인 완료 후 돌아올 주소
    )
    if (!response) throw new Error('OAuth2 토큰 생성 실패')

    // STEP 3: 앱 내부 브라우저로 구글 로그인 창 열기
    // 사용자가 구글 계정을 선택하는 팝업이 뜸
    const browserResult = await openAuthSessionAsync(
      response.toString(), // 구글 로그인 페이지 URL
      redirectUri // 완료 후 돌아올 주소
    )
    if (browserResult.type !== 'success') throw new Error('로그인 실패')

    // STEP 4: 완료 후 리디렉트된 URL에서 인증 정보 추출
    // 예: restate://?secret=abc123&userId=xyz789
    const url = new URL(browserResult.url)
    const secret = url.searchParams.get('secret')?.toString()
    const userId = url.searchParams.get('userId')?.toString()
    if (!secret || !userId) throw new Error('인증 정보 추출 실패')

    // STEP 5: 추출한 정보로 Appwrite 세션 생성 → 로그인 완료
    const session = await account.createSession(userId, secret)
    if (!session) throw new Error('세션 생성 실패')

    return true // 로그인 성공
  } catch (error) {
    console.error(error)
    return false // 로그인 실패
  }
}
```

```tsx
export async function getCurrentUser() {
  try {
    // Appwrite에서 현재 로그인된 유저 정보 가져오기
    const result = await account.get()

    if (result.$id) {

        avatar: userAvatar.toString(), // 아바타 이미지 URL 추가
      }
    }

    return null // 로그인된 유저 없음
  } catch (error) {
    console.log(error)
    return null
  }
}
```

## 6. OAuth 로그인 핵심 개념 — 딥링크(Deep Link)

```
딥링크란?
→ URL로 앱의 특정 화면을 바로 열 수 있는 기능

예시:
  https://youtube.com/watch?v=abc → 유튜브 앱의 특정 영상
  restate://              → ReState 앱의 홈 화면
  restate://properties/1  → ReState 앱의 1번 매물 화면

OAuth에서 쓰이는 방식:
  구글 로그인 완료
      ↓
  구글이 restate:// 주소로 리디렉트
      ↓
  앱이 열리면서 URL에 포함된 secret, userId 읽음
      ↓
  Appwrite 세션 생성 완료
```

> 💡 `app.json`에 `"scheme": "restate"` 설정이 이것 때문입니다.
> 딥링크 URL에서 앱을 구분하는 고유 식별자 역할을 합니다.

## 1. useAppwrite 훅 — 범용 데이터 페칭

영화 앱에서 만든 `useFetch`와 동일한 개념입니다.
Appwrite API 호출마다 반복되는 로딩/에러/데이터 관리를 한 곳에 모읍니다.

```tsx
// lib/useAppwrite.ts

import { Alert } from 'react-native'
import { useEffect, useState, useCallback } from 'react'

// T: 반환될 데이터 타입 (예: User, Property[])
// P: 함수에 넘길 파라미터 타입 (예: { query: string, filter: string })
export const useAppwrite = <T, P extends Record<string, string | number>>({
  fn, // 실행할 Appwrite 함수 (예: getCurrentUser, getProperties)
  params = {} as P, // 함수에 넘길 파라미터 (기본값: 빈 객체)
  skip = false, // true면 자동 실행 안 함 (수동 refetch용)
}) => {
  const [data, setData] = useState<T | null>(null) // 받아온 데이터
  const [loading, setLoading] = useState(!skip) // 로딩 상태
  const [error, setError] = useState<string | null>(null) // 에러 메시지

  // useCallback: fetchData 함수를 메모이제이션
  // fn이 바뀌지 않는 한 같은 함수 참조를 유지 → 불필요한 재생성 방지
  const fetchData = useCallback(
    async (fetchParams: P) => {
      setLoading(true)
      setError(null)
      try {
        const result = await fn(fetchParams) // 실제 API 호출
        setData(result)
      } catch (err: unknown) {
        const errorMessage = err instanceof Error ? err.message : '알 수 없는 에러'
        setError(errorMessage)
        Alert.alert('에러', errorMessage) // 에러 발생 시 알림창 표시
      } finally {
        setLoading(false) // 성공이든 실패든 로딩 종료
      }
    },
    [fn]
  )

  // 컴포넌트 마운트 시 자동 실행 (skip이 false일 때만)
  useEffect(() => {
    if (!skip) fetchData(params)
  }, [])

  // refetch: 새 파라미터로 다시 데이터 가져오기
  const refetch = async (newParams: P) => await fetchData(newParams)

  return { data, loading, error, refetch }
}
```

### 사용 예시

```tsx

// 파라미터가 있는 함수

  fn: getProperties,
  params: { filter: 'House', query: 'Seoul' },
})

// 자동 실행 없이 수동으로만 실행
const { data, refetch } = useAppwrite({ fn: searchProperties, skip: true })
// 나중에 원할 때 refetch({ query: "강남" }) 호출
```

## 2. GlobalProvider — 앱 전체 로그인 상태 관리

### React Context란?

```
일반적인 props 전달 방식:
  App → Screen → Component → SubComponent
  (단계마다 직접 넘겨야 함 — "props drilling")

Context 방식:
  GlobalProvider (최상위에서 데이터 보관)
       ↓ 어디서든 useGlobalContext() 한 번으로 바로 접근
  App / Screen / Component / SubComponent
```

> 💡 Context는 "전역 변수"처럼 앱 어디서든 데이터에 접근할 수 있게 해줍니다.
> 로그인 상태처럼 **여러 화면에서 공통으로 필요한 데이터**에 적합합니다.

### 코드

```tsx
// lib/global-provider.tsx

import React, { createContext, useContext, ReactNode } from 'react'
import { getCurrentUser } from './appwrite'
import { useAppwrite } from './useAppwrite'

// GlobalContext에 담을 데이터의 타입 정의
interface GlobalContextType {
  isLogged: boolean // 로그인 여부
  user: User | null // 현재 유저 정보
  loading: boolean // 유저 정보 로딩 중 여부
  refetch: () => void // 유저 정보 다시 가져오기
}

// 유저 데이터 구조 정의
interface User {
  $id: string // Appwrite 자동 생성 ID
  name: string
  email: string
  avatar: string // 이니셜 아바타 이미지 URL
}

// Context 생성 (초기값 undefined)
const GlobalContext = createContext<GlobalContextType | undefined>(undefined)

// GlobalProvider: 앱 전체를 감싸서 하위 어디서든 데이터 접근 가능하게 함
export const GlobalProvider = ({ children }: { children: ReactNode }) => {
  // useAppwrite로 현재 로그인된 유저 정보 가져오기
  const {
    data: user,
    loading,
    refetch,
  } = useAppwrite({
    fn: getCurrentUser, // Appwrite에서 현재 유저 조회
  })

  // !! (이중 부정): 값을 boolean으로 변환
  // user가 null/undefined → false (로그인 안 됨)
  // user가 객체 → true (로그인 됨)
  const isLogged = !!user

  return (
    // value: 하위 컴포넌트에서 접근할 수 있는 데이터
    <GlobalContext.Provider value={{ isLogged, user, loading, refetch }}>
      {children}
    </GlobalContext.Provider>
  )
}

// useGlobalContext: 어느 컴포넌트에서든 Context 데이터를 꺼내는 훅
export const useGlobalContext = (): GlobalContextType => {
  const context = useContext(GlobalContext)

  // Provider 밖에서 사용하면 에러 발생
  if (!context) throw new Error('useGlobalContext must be used within a GlobalProvider')

  return context
}

export default GlobalProvider
```

### `!!` (이중 부정) 쉽게 이해하기

```tsx
// 값을 boolean으로 변환할 때 사용
const user = null
!!user // → false  (null은 falsy → !null = true → !true = false)

const user = { name: '김동훈' }
!!user // → true   (객체는 truthy → !{...} = false → !false = true)

// 결론: !!값 → 값이 있으면 true, 없으면 false
const isLogged = !!user // user가 있으면 true, null이면 false
```

## 4. signin.tsx — 실제 로그인 연결 + 자동 리디렉트

```tsx
// app/signin.tsx (변경된 부분만)

import { login } from '@/lib/appwrite'
import { useGlobalContext } from '@/lib/global-provider'
import { Redirect } from 'expo-router'

const SignIn = () => {
  // GlobalContext에서 로그인 상태 가져오기
  const { refetch, loading, isLogged } = useGlobalContext()

  // 이미 로그인된 상태라면 홈으로 자동 이동
  if (!loading && isLogged) return <Redirect href="/" />

  const handleLogin = async () => {
    // 실제 구글 로그인 실행
    const result = await login()

    if (result) {
      // 로그인 성공 → 유저 정보 다시 가져오기
      // refetch 후 isLogged가 true가 되면 위의 Redirect가 실행됨
      refetch()
    } else {
      Alert.alert('에러', '로그인에 실패했습니다')
    }
  }

  // ... 나머지 UI 코드
}
```

## 5. (root)/\_layout.tsx — 미로그인 유저 접근 차단

로그인이 필요한 화면들(홈, 탐색, 프로필, 매물상세)을 한 번에 보호합니다.
각 화면마다 체크하지 않고 **부모 레이아웃에서 한 번만** 처리합니다.

```tsx
// app/(root)/_layout.tsx

import { ActivityIndicator } from 'react-native'
import { SafeAreaView } from 'react-native-safe-area-context'
import { Redirect, Slot } from 'expo-router'
import { useGlobalContext } from '@/lib/global-provider'

export default function AppLayout() {
  const { loading, isLogged } = useGlobalContext()

  // 유저 정보 로딩 중 → 로딩 스피너 표시
  if (loading) {
    return (
      <SafeAreaView className="flex h-full items-center justify-center bg-white">
        <ActivityIndicator size="large" className="text-primary-300" />
      </SafeAreaView>
    )
  }

  // 로그인 안 된 유저 → 로그인 화면으로 리디렉트
  if (!isLogged) return <Redirect href="/signin" />

  // 로그인 된 유저 → 현재 화면 표시
  // Slot: 현재 라우트에 해당하는 화면을 렌더링
  return <Slot />
}
```

### Slot vs Stack

```
Stack  → 화면 스택(뒤로가기 히스토리)을 직접 관리
Slot   → 현재 라우트의 화면을 그냥 표시 (스택 관리 X)

(root)/_layout.tsx 에서는 Slot이 적합:
  탭 네비게이션과 properties 페이지를 모두 포함하는
  부모 레이아웃이므로 단순히 현재 화면만 표시하면 됨
```

## 📊 전체 인증 흐름

```
앱 시작
    ↓
GlobalProvider → getCurrentUser() 호출
    ├── 로딩 중 → (root)/_layout.tsx에서 스피너 표시
    ├── 유저 없음 (비로그인) → /signin 으로 리디렉트
    └── 유저 있음 (로그인됨) → 현재 화면 표시

/signin 화면
    ├── 이미 로그인 → / 로 자동 리디렉트
    └── 구글 로그인 버튼 클릭
            ↓
        login() 실행 → 구글 OAuth
            ↓
        refetch() → getCurrentUser() 재호출
            ↓
        isLogged = true → / 로 자동 리디렉트
```

## 🔑 핵심 요약

1. **`useAppwrite`** = `useFetch`의 Appwrite 버전 — 로딩/에러/데이터/리페치를 한 번에 관리
2. **`GlobalProvider`** = React Context로 앱 전체에 로그인 상태 공유
3. **`useGlobalContext()`** = 어느 화면에서든 로그인 상태를 한 줄로 가져오기
4. **`!!user`** = null/undefined → false, 객체 → true 변환
5. **`(root)/_layout.tsx`** = 로그인 필요 화면들을 한 번에 보호 (각 화면마다 체크 불필요)
6. **`Slot`** = 현재 라우트 화면을 렌더링하는 컴포넌트 (레이아웃에서 사용)
7. **`refetch()`** = 로그인 성공 후 유저 정보 다시 가져오기 → isLogged 업데이트 → 자동 리디렉트
