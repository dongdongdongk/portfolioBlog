# { 🚀 Expo 프로젝트 세팅 완전 가이드 }

> 안드로이드 스튜디오 없이, 5분 안에 앱 실행까지!

---

## 📋 순서 한눈에 보기

```
1. 빈 폴더 생성
   ↓
2. Expo 프로젝트 초기화 (명령어 1개)
   ↓
3. 폰에 Expo Go 앱 설치
   ↓
4. 개발 서버 실행
   ↓
5. QR코드 스캔 → 폰에서 앱 실행!
```

---

## 1단계: 프로젝트 생성

원하는 위치에 빈 폴더를 만들고, 터미널에서 해당 폴더로 이동한 뒤 아래 명령어를 실행합니다.

```bash
npx create-expo-app@latest ./
```

> 💡 `./` 는 "현재 폴더에 설치하겠다"는 의미입니다.
>
> 잠시 기다리면 필요한 패키지가 자동으로 설치됩니다.

---

## 2단계: 폰에 Expo Go 설치

- **iOS**: App Store에서 `Expo Go` 검색 후 설치
- **Android**: Play Store에서 `Expo Go` 검색 후 설치

설치 후 앱을 열어 계정을 만들어 두세요.

---

## 3단계: 개발 서버 실행

```bash
npx expo start
```

실행하면 터미널에 아래와 같이 **QR코드**와 단축키들이 표시됩니다.

```
› Metro waiting on exp://192.168.x.x:8081
› Scan the QR code above with Expo Go (Android)
  or the Camera app (iOS)

› Press a │ open Android
› Press w │ open web

› Press r │ reload app
› Press m │ toggle menu
```

---

## 4단계: QR코드 스캔

- **iOS**: 기본 카메라 앱으로 QR코드 스캔
- **Android**: Expo Go 앱 안에서 스캔

몇 초 후 폰에서 앱이 실행됩니다! 🎉

---

## ⚠️ 안 될 때 체크리스트

| 증상                     | 해결 방법                                           |
| ------------------------ | --------------------------------------------------- |
| QR 스캔해도 앱이 안 열림 | 컴퓨터와 폰이 **같은 Wi-Fi**에 연결됐는지 확인      |
| 공공장소 Wi-Fi 사용 중   | `npx expo start --tunnel` 명령어로 실행             |
| iOS에서 연결 거부        | 설정 → Expo Go → 로컬 네트워크 접근 허용            |
| 기타 오류                | Expo Go 앱이 화면에 표시하는 메시지 그대로 따라하기 |

## 5단계: 코드 수정 → 실시간 반영 확인

`app/(tabs)/index.tsx` 파일을 열어서 텍스트를 수정하고 저장하면,

**폰에서 즉시 변경사항이 반영**되는 걸 확인할 수 있습니다.

```tsx
// 예시: 이렇게 바꾸면 폰에 바로 보임
<Text>Welcome to my Movie App!</Text>
```

> 💡 이게 바로 **핫 리로딩** — 저장할 때마다 자동으로 앱이 업데이트됩니다.

## 📁 생성된 파일/폴더 구조 설명

```
my-movie-app/
├── app/                  ← 📱 화면(스크린) 파일들이 들어가는 곳
│   └── (tabs)/           ← 탭 네비게이션 그룹
│       └── index.tsx     ← 첫 번째 화면
├── assets/               ← 이미지, 폰트 등 정적 파일
├── components/           ← 재사용 가능한 컴포넌트
├── constants/            ← 색상, 폰트 등 상수값
├── hooks/                ← 커스텀 훅
├── scripts/              ← 유틸리티 스크립트
├── app.json              ← ⚙️ 앱 전체 설정 파일
├── package.json          ← 📦 패키지 및 스크립트 목록
├── tsconfig.json         ← TypeScript 설정
└── .gitignore            ← Git에서 제외할 파일 목록
```

---

## ⚙️ app.json — 앱 설정 파일 이해하기

가장 중요한 설정 파일입니다. 주요 항목만 알면 됩니다.

```json
{
  "expo": {
    "name": "MyMovieApp",        // 앱 이름 (홈 화면에 표시됨)
    "slug": "my-movie-app",      // Expo에서 쓰는 고유 식별자
    "version": "1.0.0",          // 앱 버전
    "orientation": "portrait",   // 화면 방향 (portrait=세로, landscape=가로)
    "icon": "./assets/icon.png", // 앱 아이콘 이미지 경로
    "scheme": "movies",          // 딥링크 URL 스킴 (예: movies://home)
    "userInterfaceStyle": "automatic", // 다크/라이트 모드 (automatic=시스템 따름)
    "newArchEnabled": true,      // React Native 신규 아키텍처 활성화 (성능 향상)
    "ios": {
      "supportsTablet": true     // 아이패드 지원 여부
    },
    "android": {
      "adaptiveIcon": { ... }    // 안드로이드 적응형 아이콘
    }
  }
}
```

## 🧹 프로젝트 초기화 (깨끗하게 시작하기)

Expo가 기본으로 만들어주는 예제 코드가 많아서 복잡해 보일 수 있습니다.

아래 명령어로 **최소한의 코드**만 남기고 깔끔하게 시작할 수 있습니다.

```bash
npm run reset-project
```

실행하면 예제 파일들을 삭제할지 물어봅니다. `y` 입력하면 깨끗한 상태로 시작됩니다.

리셋 후 다시 서버 실행:

```bash
npx expo start
```

폰에서 `R` 키를 눌러 앱을 리로드하면 깔끔한 화면이 보입니다.

# { 🎨 NativeWind(Tailwind CSS) 세팅 완전 가이드 }

> React Native에서 Tailwind CSS처럼 스타일링하기

```csharp
https://www.nativewind.dev/docs/getting-started/installation

위의 사이트에 설정 방법이 다 나와있다
```

---

## 💡 NativeWind란?

웹에서 Tailwind CSS를 쓰듯이, React Native에서도 `className`으로 스타일을 줄 수 있게 해주는 패키지입니다.

```jsx
// 기존 방식 (StyleSheet)
<View style={{ flex: 1, justifyContent: 'center', alignItems: 'center' }}>

// NativeWind 방식 (훨씬 간결!)
<View className="flex-1 justify-center items-center">
```

---

## 📋 세팅 순서 한눈에 보기

```
1. 패키지 설치
   ↓
2. tailwind.config.js 생성 및 수정
   ↓
3. globals.css 파일 생성
   ↓
4. babel.config.js 설정
   ↓
5. metro.config.js 설정
   ↓
6. _layout.tsx에 CSS 임포트
   ↓
7. nativewind-env.d.ts 생성
   ↓
8. 앱 재시작
```

---

## 1단계: 패키지 설치

**개발 서버는 켜둔 채로** 새 터미널을 열어서 실행합니다.

```bash
npm install nativewind tailwindcss react-native-reanimated react-native-safe-area-context
```

설치가 끝나면 Tailwind 설정 파일을 생성합니다.

```bash
npx tailwindcss init
```

> 💡 루트 폴더에 `tailwind.config.js` 파일이 생성됩니다.

---

## 2단계: tailwind.config.js 수정

생성된 파일을 열어서 아래 내용으로 교체합니다.

```jsx
/** @type {import('tailwindcss').Config} */
module.exports = {
  // Tailwind를 적용할 파일 범위 지정
  content: ['./app/**/*.{js,jsx,ts,tsx}'],

  theme: {
    extend: {
      colors: {
        // 커스텀 색상 — 프로젝트에 맞게 자유롭게 추가
        primary: '#030014',
        secondary: '#151312',
        accent: '#AB8BFF',
        light: {
          100: '#D6C7FF',
          200: '#A8B5DB',
          300: '#9CA4AB',
        },
        dark: {
          100: '#221F3D',
          200: '#0F0D23',
        },
      },
    },
  },

  plugins: [],
}
```

> 💡 `colors`에 커스텀 색상을 등록하면 `text-primary`, `bg-accent` 처럼 간단하게 쓸 수 있습니다.

---

## 3단계: globals.css 생성

`app/` 폴더 안에 `globals.css` 파일을 새로 만들고 아래 내용을 붙여넣습니다.

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381486/notion-blog/_/React_Native/React_Native_-_/_3_-_1/image_1.png)

```css
/* app/globals.css */
@tailwind base;
@tailwind components;
@tailwind utilities;
```

> 💡 이 세 줄은 Tailwind의 기본 스타일을 불러오는 필수 선언입니다. 매번 그대로 복붙하면 됩니다.

---

## 4단계: babel.config.js 설정

루트 폴더에 `babel.config.js` 파일을 만들고 아래 내용을 붙여넣습니다.

```jsx
// babel.config.js
module.exports = function (api) {
  api.cache(true)
  return {
    presets: [['babel-preset-expo', { jsxImportSource: 'nativewind' }], 'nativewind/babel'],
  }
}
```

> 💡 Babel은 코드를 변환해주는 도구입니다. NativeWind가 작동하려면 이 설정이 반드시 필요합니다.

---

## 5단계: metro.config.js 설정

터미널에서 아래 명령어로 metro 설정 파일을 생성합니다.

```bash
npx expo customize metro.config.js
```

생성된 `metro.config.js` 파일을 열어 아래 내용으로 교체합니다.

```jsx
// metro.config.js
const { getDefaultConfig } = require('expo/metro-config')
const { withNativeWind } = require('nativewind/metro')

const config = getDefaultConfig(__dirname)

module.exports = withNativeWind(config, {
  input: './app/globals.css', // globals.css 경로와 반드시 일치해야 함!
})
```

> ⚠️ `input` 경로가 실제 `globals.css` 위치와 다르면 스타일이 적용 안 됩니다. 꼭 확인하세요!

---

## 6단계: \_layout.tsx에 CSS 임포트

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381486/notion-blog/_/React_Native/React_Native_-_/_3_-_1/image_2.png)

`app/_layout.tsx` 파일을 열어 맨 위에 한 줄 추가합니다.

```tsx
// app/_layout.tsx
import './globals.css' // 이 줄 추가

import { Stack } from 'expo-router'

export default function RootLayout() {
  return <Stack />
}
```

---

## 7단계: nativewind-env.d.ts 생성

루트 폴더에 `nativewind-env.d.ts` 파일을 만들고 아래 내용을 붙여넣습니다.

```tsx
/// <reference types="nativewind/types" />
```

> 💡 이 파일은 TypeScript가 `className` 속성을 오류로 표시하지 않도록 해줍니다.
> 이 파일이 없으면 코드는 동작하지만 빨간 밑줄이 계속 표시됩니다.

---

## 8단계: 앱 재시작

설정 변경 후에는 반드시 서버를 **완전히 재시작**해야 합니다.

```bash
# 1. 기존 서버 종료
Ctrl + C

# 2. 캐시 초기화하며 재시작 (중요!)
npx expo start -c

# 3. 폰에서 R 눌러 리로드
```

> ⚠️ 설정 파일을 바꿨는데 적용이 안 된다면 99%는 재시작으로 해결됩니다.

## 커스텀 색상 사용법

`tailwind.config.js`에 등록한 색상은 이렇게 씁니다.

```tsx
// 텍스트 색상
<Text className="text-primary">    // #030014
<Text className="text-accent">     // #AB8BFF
<Text className="text-light-100">  // #D6C7FF

// 배경 색상
<View className="bg-dark-200">     // #0F0D23
<View className="bg-secondary">    // #151312

// 테두리 색상
<View className="border border-light-200">
```

> 💡 색상을 직접 쓰는 것보다 이름을 등록해두면, 나중에 색상을 바꿀 때 설정 파일 한 곳만 수정하면 됩니다.

| `rounded-xl`     | 모서리 둥글게                 |
| `w-full`         | 너비 100%                     |
| `h-screen`       | 높이 화면 전체                |

# { 🗺️ Expo 라우팅 & 하단 네비게이션 완전 가이드 }

> 파일 이름 = URL 주소! Next.js와 같은 파일 기반 라우팅

---

## 💡 파일 기반 라우팅이란?

Expo Router는 **파일 이름 자체가 URL**이 됩니다.
별도의 라우터 설정 없이 파일만 만들면 자동으로 경로가 생깁니다.

```
app/index.tsx          →  /          (홈 화면)
app/onboarding.tsx     →  /onboarding
app/profile.tsx        →  /profile
app/movie/[id].tsx     →  /movie/어벤져스, /movie/인터스텔라 ...
```

---

## 1. 기본 라우팅

### 새 화면(페이지) 만들기

`app/` 폴더에 파일을 만들면 바로 라우트가 됩니다.

```tsx
// app/onboarding.tsx
import { View, Text } from 'react-native'

export default function Onboarding() {
  return (
    <View>
      <Text>온보딩 화면입니다!</Text>
    </View>
  )
}
```

## 2. 동적 라우팅 (Dynamic Routes)

영화 상세 페이지처럼 **ID에 따라 내용이 달라지는 화면**에 사용합니다.

### 파일 생성

파일 이름을 `[대괄호]`로 감싸면 동적 파라미터가 됩니다.

```
app/movie/[id].tsx   →  /movie/어벤져스
                        /movie/인터스텔라
                        /movie/기생충  ...
```

### 파라미터 읽기

```tsx
// app/movie/[id].tsx
import { View, Text } from 'react-native'
import { useLocalSearchParams } from 'expo-router'

export default function MovieDetails() {
  const { id } = useLocalSearchParams() // URL의 [id] 값을 가져옴

  return (
    <View>
      <Text>현재 보고 있는 영화: {id}</Text>
      {/* /movie/어벤져스 → id = "어벤져스" */}
    </View>
  )
}
```

### Type '"/movie/avangers"' is not assignable to type '"/onboarding" | RelativePathString | ExternalPathString | "/" | 에러

`app/movie/[id].tsx` 가 있어서

타입은 **"/movie/[id]"** 로 정의돼 있는데

너는 **"/movie/avangers"** 를 직접 써서 타입 에러 난 것.

---

### ✅ 올바른 방법 (짧게)

```tsx
<Link
  href={{
    pathname: '/movie/[id]',
    params: { id: 'avangers' },
  }}
/>
```

---

### 📌 요약

- `[id]` 는 동적 라우트
- 문자열로 완성된 경로 직접 쓰면 타입 에러
- 객체 형태로 `params` 넘기면 해결

끝 👍

### 동적 링크 연결

```tsx
// 어딘가에서 영화 상세 페이지로 이동
<Link href="/movie/어벤져스">어벤져스 보기</Link>
<Link href="/movie/인터스텔라">인터스텔라 보기</Link>
```

## 3. 라우트 그룹 (Route Groups)

화면을 논리적으로 묶되, **URL에는 폴더명이 나타나지 않게** 하는 방법입니다.

```
app/(tabs)/index.tsx    →  /        ← (tabs)가 URL에 안 나타남!
app/(tabs)/search.tsx   →  /search
app/(tabs)/profile.tsx  →  /profile
```

> 💡 괄호 `()` 로 감싼 폴더는 URL에 포함되지 않습니다.

## 7. 커스텀 탭 아이콘 만들기

기본 탭은 단순한 텍스트 탭입니다. 아이콘을 추가해 예쁘게 꾸며봅니다.

### 재사용 가능한 TabIcon 컴포넌트

```tsx
// app/(tabs)/_layout.tsx
import { Tabs } from 'expo-router'
import { View, Image, ImageBackground, Text } from 'react-native'
import { icons, images } from '@/constants' // 아이콘/이미지 파일들

// 탭 아이콘 컴포넌트 — focused(현재 선택된 탭 여부)에 따라 다른 모습
const TabIcon = ({ focused, icon, title }: { focused: boolean; icon: any; title: string }) => {
  // 현재 선택된 탭: 배경 + 아이콘 + 텍스트 표시
  if (focused) {
    return (
      <ImageBackground
        source={images.highlight}
        className="mt-4 flex min-h-16 w-full min-w-[112px] flex-1 flex-row items-center justify-center overflow-hidden rounded-full"
      >
        <Image source={icon} tintColor="#151312" className="size-5" />
        <Text className="text-secondary ml-2 text-base font-semibold">{title}</Text>
      </ImageBackground>
    )
  }

  // 선택 안 된 탭: 아이콘만 표시
  return (
    <View className="mt-4 size-full items-center justify-center rounded-full">
      <Image source={icon} tintColor="#A8B5DB" className="size-5" />
    </View>
  )
}
```

> 💡 **컴포넌트 분리의 이유**: 탭 4개가 모두 같은 구조를 쓰므로, 반복 코드 대신 재사용 가능한 컴포넌트로 만듭니다.

### 탭에 커스텀 아이콘 적용

| 개념          | 문법                     | 예시                                    |
| ------------- | ------------------------ | --------------------------------------- |
| 기본 라우트   | `파일명.tsx`             | `search.tsx` → `/search`                |
| 동적 라우트   | `[파라미터].tsx`         | `[id].tsx` → `/movie/어벤져스`          |
| 라우트 그룹   | `(폴더명)/`              | `(tabs)/` → URL에 미포함                |
| 화면 이동     | `<Link href="">`         | `<Link href="/search">`                 |
| 파라미터 읽기 | `useLocalSearchParams()` | `const { id } = useLocalSearchParams()` |
| 헤더 숨기기   | `headerShown: false`     | Stack.Screen options에 설정             |
| 탭 아이콘     | `tabBarIcon`             | focused 상태에 따라 다른 UI             |

## 🔑 핵심 요약

1. **파일 = 화면** — `app/` 폴더에 파일을 만들면 자동으로 라우트 생성
2. **`[id].tsx`** — 대괄호로 감싸면 동적 파라미터 라우트
3. **`(폴더명)`** — 괄호 폴더는 URL에 나타나지 않음 (그룹핑 용도)
4. **`_layout.tsx`** — 해당 폴더의 레이아웃/네비게이션 설정 파일
5. **재사용 컴포넌트** — 반복되는 UI는 props를 받는 컴포넌트로 분리
6. **새 파일 추가 후 `r`** — 리로드해야 새 라우트가 인식됨

## 2. SearchBar 컴포넌트 만들기

### 왜 컴포넌트로 분리할까?

검색창은 홈 화면, 검색 화면 등 **여러 곳에서 쓸 수 있습니다.**
한 번 만들어두면 어디서든 `<SearchBar />` 한 줄로 재사용 가능합니다.

```tsx
// components/SearchBar.tsx

import { View, Image, TextInput } from 'react-native'
import { icons } from '@/constants'

// TypeScript: 이 컴포넌트가 받을 props의 타입을 미리 정의
// → 잘못된 값을 넘기면 에러를 바로 알 수 있어서 버그 예방에 좋음
interface Props {
  placeholder: string // 입력창에 표시될 안내 문구 (필수)
  onPress?: () => void // 클릭 시 실행할 함수 (선택, ?는 없어도 됨을 의미)
  value?: string // 현재 입력된 값 (선택)
  onChangeText?: (text: string) => void // 텍스트 변경 시 실행할 함수 (선택)
}

export default function SearchBar({ placeholder, onPress, value, onChangeText }: Props) {
  return (
    // 검색창 전체 컨테이너
    // flex-row: 아이콘과 입력창을 가로로 나란히 배치
    <View className="bg-dark-200 flex-row items-center rounded-full px-5 py-4">
      {/* 돋보기 아이콘 */}
      <Image
        source={icons.search}
        className="size-5"
        resizeMode="contain"
        tintColor="#AB8BFF" // 아이콘 색상을 accent 색으로
      />

      {/* 텍스트 입력창 — HTML의 <input type="text">와 같은 역할 */}
      <TextInput
        placeholder={placeholder} // 입력 전 표시되는 안내 문구
        placeholderTextColor="#A8B5DB" // 안내 문구 색상
        value={value} // 현재 입력된 값
        onChangeText={onChangeText} // 타이핑할 때마다 실행
        onPress={onPress} // 클릭 시 실행 (홈에서는 검색 화면으로 이동)
        className="ml-2 flex-1 text-white" // flex-1: 남은 공간 전부 차지
      />
    </View>
  )
}
```

> 💡 **props를 통한 부모→자식 데이터 전달 흐름**
>
> ```
> 홈 화면 (index.tsx)         →      SearchBar 컴포넌트
> onPress={() => router.push("/search")}  →  onPress prop으로 전달
> placeholder="영화를 검색해보세요"          →  placeholder prop으로 전달
> ```

## 3. TMDB 영화 API 연동

### 환경변수 설정

API 키는 코드에 직접 쓰면 외부에 노출될 위험이 있습니다.
`.env` 파일에 따로 보관합니다.

```bash
# 루트 폴더에 .env 파일 생성
# Expo에서 클라이언트(앱)에서 쓸 변수는 반드시 EXPO_PUBLIC_ 으로 시작해야 함
EXPO_PUBLIC_MOVIE_API_KEY=여기에_발급받은_API_키_붙여넣기
```

> ⚠️ `.env` 파일은 절대 GitHub에 올리면 안 됩니다! `.gitignore`에 추가하세요.

### API 설정 + fetch 함수

```tsx
// services/api.ts

// TMDB API의 기본 설정값을 한 곳에 모아둠
// → 나중에 base URL이나 키가 바뀌어도 여기 한 곳만 수정하면 됨
export const tmdbConfig = {
  baseUrl: 'https://api.themoviedb.org/3', // API 기본 주소

  // 환경변수에서 API 키 읽어오기 (코드에 직접 키를 쓰지 않음)
  apiKey: process.env.EXPO_PUBLIC_MOVIE_API_KEY,

  headers: {
    accept: 'application/json', // JSON 형식으로 응답 받겠다는 선언
    // Bearer 인증: API를 쓸 권한이 있음을 증명하는 방식
    Authorization: `Bearer ${process.env.EXPO_PUBLIC_MOVIE_API_KEY}`,
  },
}

// 영화 목록을 가져오는 함수
// query가 있으면 검색 결과, 없으면 인기 영화를 가져옴
export const fetchMovies = async (query: string) => {
  // query 값에 따라 호출할 API 주소가 달라짐
  const endpoint = query
    ? // 검색어가 있으면: 검색 API 사용
      // encodeURIComponent: "어벤져스 2"같은 문자를 URL에 안전한 형태로 변환
      `${tmdbConfig.baseUrl}/search/movie?query=${encodeURIComponent(query)}`
    : // 검색어가 없으면: 인기 영화 목록 API 사용
      `${tmdbConfig.baseUrl}/discover/movie?sort_by=popularity.desc`

  // API 호출 (GET 요청)
  const response = await fetch(endpoint, {
    method: 'GET',
    headers: tmdbConfig.headers,
  })

  // 응답이 실패했다면 에러 발생
  if (!response.ok) {
    throw new Error(`영화 데이터를 가져오는 데 실패했습니다: ${response.statusText}`)
  }

  // 응답을 JSON으로 파싱
  const data = await response.json()

  // data.results 안에 실제 영화 목록이 담겨 있음
  return data.results
}
```

## 4. 커스텀 훅 (useFetch) 만들기

### 왜 커스텀 훅이 필요할까?

API를 호출할 때마다 아래 코드가 반복됩니다:

```tsx
// 이런 코드가 화면마다 반복된다면?
const [data, setData] = useState(null) // 데이터 상태
const [loading, setLoading] = useState(false) // 로딩 상태
const [error, setError] = useState(null) // 에러 상태

useEffect(() => {
  setLoading(true)
  fetchMovies('')
    .then((result) => setData(result))
    .catch((err) => setError(err))
    .finally(() => setLoading(false))
}, [])
```

→ 이걸 **커스텀 훅으로 한 번만 만들어두면** 어느 화면에서든 한 줄로 해결됩니다:

```tsx
const { data, loading, error } = useFetch(() => fetchMovies(''))
```

### useFetch 커스텀 훅 구현

```tsx
// services/useFetch.ts

import { useState, useEffect } from "react";

// <T>는 제네릭(Generic) — 어떤 타입의 데이터도 처리할 수 있게 해줌
// 영화 데이터든, 사용자 데이터든 같은 훅으로 처리 가능
const useFetch = <T>(
  // fetchFunction: 실제 데이터를 가져오는 함수를 인자로 받음
  // → fetchMovies가 될 수도 있고, fetchMovieDetails가 될 수도 있음
  fetchFunction: () => Promise<T>,

  // autoFetch: 컴포넌트가 처음 렌더링될 때 자동으로 fetch할지 여부
  // 기본값 true → 대부분의 경우 화면이 열리면 자동으로 데이터를 가져옴
  autoFetch: boolean = true
) => {

  // 세 가지 상태 관리
  const [data, setData] = useState<T | null>(null);         // 받아온 데이터
  const [loading, setLoading] = useState(false);            // 로딩 중 여부
  const [error, setError] = useState<Error | null>(null);   // 에러 정보

  // 실제 데이터를 가져오는 함수
  const fetchData = async () => {
    try {
      setLoading(true);   // 로딩 시작
      setError(null);     // 이전 에러 초기화

      // 인자로 받은 fetchFunction을 실행해서 데이터를 가져옴
      const result = await fetchFunction();
      setData(result);    // 받아온 데이터를 상태에 저장

    } catch (err) {
      // 에러가 발생하면 에러 상태에 저장
      setError(err instanceof Error ? err : new Error("알 수 없는 에러가 발생했습니다"));

    } finally {
      // 성공이든 실패든 로딩은 항상 종료
      setLoading(false);
    }
  };

  // 데이터를 초기 상태로 되돌리는 함수
  const reset = () => {
    setData(null);
    setLoading(false);
    setError(null);
  };

  // useEffect: 컴포넌트가 처음 화면에 나타날 때 자동 실행
  useEffect(() => {
    if (autoFetch) {
      fetchData(); // autoFetch가 true면 자동으로 데이터 가져오기 시작
    }
  }, []); // [] → 처음 한 번만 실행 (의존성 배열이 빈 배열)

  // 훅을 사용하는 곳에서 필요한 것들을 모두 반환
  return {
    data,           // 가져온 데이터
    loading,        // 로딩 중 여부 (로딩 스피너 표시에 활용)
    error,          // 에러 정보 (에러 메시지 표시에 활용)
    refetch: fetchData, // 수동으로 다시 fetch하고 싶을 때 호출
    reset,          // 상태를 초기화하고 싶을 때 호출
  };
};

export default useFetch;
```

## 💡 왜 커스텀 훅이 필요할까?

API를 호출할 때마다 아래 코드를 **매번 화면마다 반복**해야 합니다.

```tsx
// 홈 화면
const [movies, setMovies] = useState(null)
const [loading, setLoading] = useState(false)
const [error, setError] = useState(null)

useEffect(() => {
  setLoading(true)
  fetchMovies()
    .then((result) => setMovies(result))
    .catch((err) => setError(err))
    .finally(() => setLoading(false))
}, [])

// 검색 화면에서도 똑같이 반복...
// 상세 화면에서도 똑같이 반복...
```

**이 반복을 `useFetch` 하나로 해결합니다.**

```tsx
// useFetch를 쓰면 이 한 줄로 끝!
const { data: movies, loading, error } = useFetch(() => fetchMovies())
```

## 🧠 훅(Hook)이란?

React/React Native에서 `use`로 시작하는 함수를 **훅**이라고 합니다.

| 훅 이름     | 역할                                    |
| ----------- | --------------------------------------- |
| `useState`  | 상태(데이터) 관리                       |
| `useEffect` | 컴포넌트 로딩 시 실행할 코드            |
| `useFetch`  | 우리가 만들 커스텀 훅 — 위 두 개를 조합 |

> 💡 `use`로 시작하는 이름 → 이건 훅이다! 라고 바로 알아볼 수 있습니다.

## 📝 전체 코드 + 상세 주석

```tsx
// services/useFetch.ts

import { useEffect, useState } from "react";

// ────────────────────────────────────────────────
// <T> 란? — 제네릭(Generic)
//
// "어떤 타입의 데이터든 처리할 수 있는 범용 훅"을 만들기 위한 문법입니다.
//
// 예시:
//   useFetch<Movie[]>  → 영화 목록을 다룰 때
//   useFetch<User>     → 유저 정보를 다룰 때
//
// <T>를 쓰면 하나의 훅으로 모든 상황에 재사용 가능합니다.
// 처음엔 그냥 "유연한 타입 자리"라고만 이해해도 충분합니다.
// ────────────────────────────────────────────────
const useFetch = <T>(
  // 첫 번째 인자: 실행할 fetch 함수를 외부에서 받아옴
  // fetchMovies, fetchMovieDetails 등 어떤 함수든 넣을 수 있음
  fetchFunction: () => Promise<T>,

  // 두 번째 인자: 화면이 열릴 때 자동으로 fetch할지 여부
  // 기본값이 true이므로 대부분은 화면이 열리자마자 자동으로 데이터를 불러옴
  autoFetch = true
) => {

  // ── 상태 3가지 ──────────────────────────────────

  // 받아온 데이터 저장 (초기값: null — 아직 아무것도 없음)
  const [data, setData] = useState<T | null>(null);

  // 현재 로딩 중인지 여부 (초기값: false — 아직 시작 안 함)
  const [loading, setLoading] = useState(false);

  // 에러 정보 저장 (초기값: null — 에러 없음)
  const [error, setError] = useState<Error | null>(null);
  // ────────────────────────────────────────────────

  // ── 실제 데이터를 가져오는 함수 ─────────────────
  const fetchData = async () => {
    try {
      // 1. 로딩 시작 → 화면에 스피너가 나타남
      setLoading(true);

      // 2. 이전에 발생한 에러가 있다면 초기화
      setError(null);

      // 3. 외부에서 받은 fetch 함수를 실행해서 데이터를 가져옴
      //    fetchMovies()가 될 수도 있고, fetchMovieDetails()가 될 수도 있음
      const result = await fetchFunction();

      // 4. 받아온 데이터를 상태에 저장 → 화면에 렌더링됨
      setData(result);

    } catch (err) {
      // fetch 도중 에러가 발생하면 여기서 처리
      // err이 Error 객체면 그대로, 아니면 새 Error로 감싸서 저장
      setError(err instanceof Error ? err : new Error("알 수 없는 에러가 발생했습니다"));

    } finally {
      // try 성공이든, catch 에러든 상관없이 마지막엔 무조건 실행
      // 로딩 종료 → 스피너 사라짐
      setLoading(false);
    }
  };
  // ────────────────────────────────────────────────

  // ── 상태를 초기값으로 되돌리는 함수 ─────────────
  const reset = () => {
    setData(null);     // 데이터 초기화
    setError(null);    // 에러 초기화
    setLoading(false); // 로딩 초기화
  };
  // ────────────────────────────────────────────────

  // ── 컴포넌트가 처음 화면에 나타날 때 자동 실행 ──
  useEffect(() => {
    // autoFetch가 true일 때만 자동으로 데이터 fetch
    if (autoFetch) {
      fetchData();
    }
  }, []);
  // [] → 빈 배열 = 처음 한 번만 실행
  //       만약 [query]처럼 값을 넣으면 query가 바뀔 때마다 재실행됨
  // ────────────────────────────────────────────────

  // 훅을 사용하는 곳에서 필요한 것들을 반환
  return {
    data,               // 가져온 데이터
    loading,            // 로딩 중 여부 → 스피너 표시에 활용
    error,              // 에러 정보  → 에러 메시지 표시에 활용
    refetch: fetchData, // 수동으로 다시 불러오고 싶을 때 호출
    reset,              // 모든 상태를 초기화하고 싶을 때 호출
  };
};

export default useFetch;
```

## 🔀 try / catch / finally 흐름 이해하기

처음 보면 헷갈릴 수 있어서 따로 설명합니다.

```
API 호출 시작
    ↓
┌─────────────────────────────┐
│  try                        │  ← 정상적으로 실행할 코드
│    로딩 시작                 │
│    API 호출                  │
│    데이터 저장               │
│                             │
│  에러 발생 시 → catch로 이동  │
└─────────────────────────────┘
    ↓ (에러 발생 시)
┌─────────────────────────────┐
│  catch                      │  ← 에러가 났을 때만 실행
│    에러 상태에 저장           │
└─────────────────────────────┘
    ↓ (항상)
┌─────────────────────────────┐
│  finally                    │  ← 성공이든 실패든 무조건 실행
│    로딩 종료                 │
└─────────────────────────────┘
```

## 💡 제네릭 `<T>` 쉽게 이해하기

```tsx
// T 없이 만들면 → 영화 전용 훅이 돼버림
const useFetch = (fetchFunction: () => Promise<Movie[]>) => { ... }

// T 있으면 → 어떤 데이터든 처리 가능한 범용 훅
const useFetch = <T>(fetchFunction: () => Promise<T>) => { ... }
```

실제 사용할 때 T가 자동으로 결정됩니다.

```tsx
// fetchMovies가 Movie[]를 반환하므로 T = Movie[] 로 자동 결정
const { data } = useFetch(() => fetchMovies(''))
// data의 타입이 자동으로 Movie[] | null 이 됨
```

> 💡 제네릭은 처음엔 어렵게 느껴지지만, 그냥 "타입도 변수처럼 유연하게 받겠다"는 것이라고만 이해해도 충분합니다.

## 1. 홈 화면에서 영화 데이터 불러오기

이전에 만든 `useFetch` + `fetchMovies`를 조합하면 단 몇 줄로 끝납니다.

```tsx
// app/(tabs)/index.tsx

import { ActivityIndicator, FlatList, Image, ScrollView, Text, View } from 'react-native'
import { images, icons } from '@/constants'
import { useRouter } from 'expo-router'
import useFetch from '@/services/useFetch'
import { fetchMovies } from '@/services/api'
import SearchBar from '@/components/SearchBar'
import MovieCard from '@/components/MovieCard'

export default function Home() {
  const router = useRouter()

  // useFetch에 fetchMovies를 넘기면
  // 로딩/에러/데이터 관리를 알아서 해줌
  const {
    data: movies, // data를 movies로 이름 변경
    loading: moviesLoading,
    error: moviesError,
  } = useFetch(() => fetchMovies(''))
  // 빈 문자열("") → 인기 영화 목록 가져오기
  // "Iron Man" 처럼 검색어를 넣으면 검색 결과 가져오기

  return (
    <View className="bg-primary flex-1">
      {/* 배경 이미지 */}
      <Image source={images.bg} className="absolute z-0 w-full" />

      <ScrollView
        className="flex-1 px-5"
        showsVerticalScrollIndicator={false}
        contentContainerStyle={{ minHeight: '100%', paddingBottom: 10 }}
      >
        {/* 앱 로고 */}
        <Image source={icons.logo} className="mx-auto mt-20 mb-5 h-10 w-12" />

        {/* 로딩 중 → 스피너 표시 */}
        {moviesLoading ? (
          <ActivityIndicator size="large" color="#0000ff" className="mt-10 self-center" />
        ) : // 에러 발생 → 에러 메시지 표시
        moviesError ? (
          <Text className="mt-10 text-center text-red-500">에러: {moviesError?.message}</Text>
        ) : (
          // 정상 → 검색바 + 영화 목록 표시
          <View className="mt-5 flex-1">
            {/* 검색창 — 누르면 검색 화면으로 이동 */}
            <SearchBar placeholder="영화를 검색해보세요" onPress={() => router.push('/search')} />

            {/* 영화 목록 섹션 */}
            <>
              <Text className="mt-5 mb-3 text-lg font-bold text-white">최신 영화</Text>

              {/* FlatList로 영화 목록 렌더링 */}
              <FlatList
                data={movies} // 영화 배열 데이터
                renderItem={({ item }) => (
                  <MovieCard {...item} /> // 각 영화를 카드로 표시
                )}
                keyExtractor={(item) => item.id.toString()} // 각 항목의 고유 키
                numColumns={3} // 3열로 표시
                columnWrapperStyle={{
                  justifyContent: 'flex-start',
                  gap: 20,
                  paddingRight: 5,
                  marginBottom: 10,
                }}
                className="mt-2 pb-32"
                scrollEnabled={false} // ScrollView 안에 있으므로 자체 스크롤 끄기
              />
            </>
          </View>
        )}
      </ScrollView>
    </View>
  )
}
```

## 3. MovieCard 컴포넌트 만들기

```
components/
└── MovieCard.tsx   ← 새로 생성
```

### 전체 코드 + 주석

```tsx
// components/MovieCard.tsx

import { Link } from 'expo-router'
import { Image, Text, TouchableOpacity, View } from 'react-native'
import { icons } from '@/constants/icons'

// Movie 타입에서 필요한 props만 받아옴
// (id, poster_path, title, vote_average, release_date)
const MovieCard = ({ id, poster_path, title, vote_average, release_date }: Movie) => {
  return (
    // Link: 카드 클릭 시 영화 상세 페이지로 이동
    // href={`/movie/${id}`} → 동적 라우트 /movie/[id]로 이동
    // asChild: Link 자체가 아닌 안에 있는 자식(TouchableOpacity)이 클릭 영역이 됨
    <Link href={`/movie/${id}`} asChild>
      {/* TouchableOpacity: 눌렀을 때 투명도가 낮아지는 시각적 피드백 */}
      {/* w-[30%]: 화면 너비의 30% (3열 레이아웃에 맞춤) */}
      <TouchableOpacity className="w-[30%]">
        {/* 영화 포스터 이미지 */}
        <Image
          source={{
            uri: poster_path
              ? // 포스터가 있으면 TMDB 이미지 서버에서 불러옴
                `https://image.tmdb.org/t/p/w500${poster_path}`
              : // 포스터가 없으면 회색 placeholder 이미지 표시
                'https://placehold.co/600x400/1a1a1a/FFFFFF.png',
          }}
          className="h-52 w-full rounded-lg"
          resizeMode="cover" // 이미지가 영역을 꽉 채우도록 크롭
        />

        {/* 영화 제목 — numberOfLines={1}로 한 줄만 표시 (넘치면 ... 처리) */}
        <Text className="mt-2 text-sm font-bold text-white" numberOfLines={1}>
          {title}
        </Text>

        {/* 별점 영역 */}
        <View className="flex-row items-center justify-start gap-x-1">
          <Image source={icons.star} className="size-4" />
          <Text className="text-xs font-bold text-white uppercase">
            {/* vote_average는 10점 만점 → 2로 나눠서 5점 만점으로 변환 */}
            {Math.round(vote_average / 2)}
          </Text>
        </View>

        {/* 개봉 연도 */}
        <View className="flex-row items-center justify-between">
          <Text className="text-light-300 mt-1 text-xs font-medium">
            {/* "2024-07-15" → "2024" (연도만 추출) */}
            {release_date?.split('-')[0]}
          </Text>
          <Text className="text-light-300 text-xs font-medium uppercase">Movie</Text>
        </View>
      </TouchableOpacity>
    </Link>
  )
}

export default MovieCard
```

## 4. 핵심 개념 정리

### FlatList 주요 props

| prop                 | 역할                      | 예시                           |
| -------------------- | ------------------------- | ------------------------------ |
| `data`               | 렌더링할 배열             | `data={movies}`                |
| `renderItem`         | 각 항목을 어떻게 표시할지 | `({ item }) => <MovieCard />`  |
| `keyExtractor`       | 각 항목의 고유 키         | `(item) => item.id.toString()` |
| `numColumns`         | 몇 열로 표시할지          | `numColumns={3}`               |
| `columnWrapperStyle` | 각 행의 스타일            | `{ gap: 20 }`                  |
| `scrollEnabled`      | 자체 스크롤 여부          | `scrollEnabled={false}`        |

> 💡 `numColumns`를 바꾸면 앱을 **반드시 재시작**해야 적용됩니다.
>
> 저장만 해서는 반영되지 않습니다.

### props 전달 방법 — 스프레드 연산자

```tsx
// 방법 1: 하나씩 전달 (번거로움)
<MovieCard
  id={item.id}
  title={item.title}
  poster_path={item.poster_path}
  vote_average={item.vote_average}
  release_date={item.release_date}
/>

// 방법 2: 스프레드로 한 번에 전달 (간결함) ✅
<MovieCard {...item} />
// item 객체의 모든 속성이 props로 전달됨
```

### 날짜에서 연도만 추출

```tsx
const release_date = '2024-07-15'

release_date.split('-')
// → ["2024", "07", "15"]

release_date.split('-')[0]
// → "2024"  ← 연도만 가져옴
```

### 별점 변환 (10점 → 5점)

```tsx
// TMDB는 10점 만점 기준
const vote_average = 7.8

Math.round(vote_average / 2)
// 7.8 / 2 = 3.9 → Math.round → 4
// → 별 4개로 표시
```

```csharp
🔍 1. 근본 원인: "E: 가 뭐야? 새로운 인터넷 주소야?"
최신 자바스크립트 모듈 시스템(ESM, import 문법)을 다루는 Node.js v24는 주소를 읽을 때 굉장히 깐깐한 규칙을 가지고 있습니다. 외부 파일을 불러올 때 인터넷 URL 형식(http://, https://, file:// 등)을 선호하죠.

정상적인 웹 URL: http://naver.com (앞의 http:를 프로토콜/스킴이라고 부릅니다.)

정상적인 로컬 파일 URL: file:///E:/WebProject2026/... (file: 스킴을 사용합니다.)

그런데 React Native의 번들러인 Metro(정확히는 metro-config 패키지)가 Node.js에게 파일을 불러오라고 시킬 때, URL 형식이 아니라 Windows의 생짜 절대 경로를 툭 던져버린 겁니다.

Metro: "야, 설정 파일 좀 가져와. 주소는 E:\WebProject2026\RnBasic\...\metro.config.js 야."

이때 깐깐한 Node.js v24는 이 주소를 받고 이렇게 오해합니다.

Node.js: "음? 주소록 규칙상 맨 앞에는 http: 같은 스킴이 와야 하는데? 아하! 콜론(:) 앞에 있는 E가 스킴이구나! 근데 나는 http:, file:, data:는 알아도 e: 라는 인터넷 프로토콜은 배운 적이 없는데? 에러!!!"

이것이 바로 로그에 찍혔던 Received protocol 'e:' 에러의 완벽한 실체입니다. 맥(Mac)이나 리눅스는 드라이브 문자(C:, E:)가 없어서 /Users/... 형태로 시작하므로 이 에러가 발생하지 않지만, Windows 환경 + 최신 Node.js 조합에서만 발생하는 고질적인 문제였던 것이죠.

🛠️ 2. 해결법 1: 주소 번역기 달아주기 (patch-package)
개발자님은 Metro가 주소를 잘못 넘겨주는 부분을 직접 찾아내서, Node.js가 알아듣기 쉬운 말로 번역해 주는 코드를 삽입하신 겁니다.

수정 전: import(absolutePath) (생짜 E: 드라이브 경로를 그대로 던짐)

수정 후: import(pathToFileURL(absolutePath).href)

여기서 pathToFileURL 이라는 함수가 마법을 부립니다.
E:\WebProject2026\... 라는 윈도우 경로를 넣으면, file:///E:/WebProject2026/... 라는 완벽한 URL 형식으로 번역해 줍니다.
이제 Node.js는 "아~ file: 프로토콜이구나! 내 컴퓨터 하드디스크에 있는 파일이네!" 하고 정상적으로 파일을 불러오게 된 것입니다.

⚙️ 3. 해결법 2: 수정한 코드 영구 보존하기 (postinstall)
node_modules 폴더 안에 있는 남의 라이브러리 코드를 직접 수정하면 치명적인 단점이 하나 있습니다. 나중에 npm install을 다시 치면 수정한 내용이 초기화되어 다 날아가 버린다는 것이죠.

그래서 **patch-package**라는 훌륭한 도구를 쓰신 겁니다.

내가 수정한 내역(Patch)을 백업 파일로 저장해 둡니다. (patches/metro-config...)

package.json의 postinstall에 등록해 두면, 앞으로 누군가(혹은 내가) npm install을 실행해서 패키지들이 초기화될 때마다, 자동으로 내가 만든 패치(수정본)를 덧발라 줍니다.

이제 이 프로젝트는 평생 지긋지긋한 e: 드라이브 에러에서 해방된 것입니다!

🎨 4. 해결법 3: Tailwind 설정 (tailwind.config.js)
이 부분은 에러 해결과는 별개로, NativeWind(Tailwind CSS)가 정상적으로 작동하기 위한 필수 세팅입니다.
Tailwind에게 "우리 프로젝트의 어떤 파일들에 있는 클래스명(예: className="text-red-500")을 읽어서 스타일을 적용해야 해?"라고 알려주는(content 설정) 작업입니다. 이 설정을 마쳐야 앱 화면에 디자인이 제대로 반영됩니다.
```
