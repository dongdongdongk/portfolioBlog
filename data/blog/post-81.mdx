# 스프링 프레임 워크의 간략한 역사

## 프레임 워크의 장점

```java
프레임워크는 말 그대로 뼈대나 근간을 이루는 코드들의 묶음 이라고 할 수 있다 중요한건 이 뼈대가 왜 필요한지다

개발자는 각 개개인의 능력 차이가 큰 직종이고 개발자 구성에 따라 프로젝트의 결과 역시 큰 차이를 낳는다 프레임 워크는 이런 상황을 극복하게 해준다

프로그램의 기본 흐름이나 구조를 정하고 모든 팀원이 이 구조에 자신의 코드를 추가하는 방식으로 개발하게 된다

이렇게 되면 이미 개발에 필요한 구조를 이미 코드로 만들어 놓았기 때문에 실력이 부족한 개발자라 하더라도 반쯤 완성한 상태에서 필요한 부분을 조립하는 형태의 개발이 되기 때문에 일정한 품질과 결과물을 보장 가능하고 개발 시간또한 단축 가능하다

* 요악

프레임워크 : 프로그램의 기존 흐름이나 구조를 정하고 작업하는 뼈대나 근간을 이루는 코드들의 묶음

프레임 워크의 장점

1. 일정한 품질과 결과를 보장

2. 개발시간 단축

3. 협업에 유리

```

## 경량 프레임 워크

```java
경량 프레임 워크는 과거 J2EE 기술은 너무 복잡하고 방대했기 때문에 그 전체를 이해하고 개발하기는 어려운 점이 많아서 특정 기능을 위주로 간단한 jar 파일 등을 이용해서 모든 개발이 가능하도록 구성된 프레임워크

(경량 프레임워크는 소프트웨어 개발 시 사용되는 도구와 지침을 제공합니다. 하지만 이 프레임워크는 무척 가벼워서 필요한 기능만을 제공하며, 복잡하지 않습니다. 예를 들어,

큰 웹 애플리케이션을 만들 때, 전체적인 구조나 기본 기능을 간단하게 제공하면서 필요한 다양한 기능은 개발자가 직접 추가할 수 있도록 돕습니다.)
```

## 스프링과 당시 기존에 나왔던 프레임 워크들의 차이점

```java
* 복잡한에 반기를 들어서 만들어진 프레임워크

스프링은 기존 프레임워크들의 복잡성을 해결하기 위해 나온 경략 프레임워크 이다.

* 프로젝트의 전체 구조를 설계할 때 유용한 프레임워크

다른 프레임 워크는 데이터 베이스나 웹 영역 같은 전문적인 영역에 대해서만 지원하는 경우가 많았고 비즈니스 로직을 처리하는 부분에 대한 설계는 개발자의 역량에 맡기는 경우가 많았다 반면 스프링은 전체를 설계하는 용도로 사용가능

* 다른 프레임워크들의 포용

스프링의 최대 장점은 기본 뼈대를 흔들지 않고 여러 종류의 프레임워크를 혼용해서 사용할 수 있다는 점이다

* 개발 생산성과 개발도구의 지원

스프링의 경우 STS 나 이클립스 인텔리제이 등의 플러그 인의 지원이 다른 프레임 워크들에 비해서 빠르게 업데이트 되었기 때문에 별도의 새로운 개발도구에 대한 적응이 없이 개발이 가능
```

```java
* POJO 기반의 구성

* 의존성 주입(DI) 를 통한 객체 간의 관계 구성

* AOP 지원

* WAS의 종속적이지 않은 개발환경
```

### POJO 기반의 구성

```java
스프링은 객체관의 관계를 구성할 때 별도의 API 를 사용하지 않는 POJO(Plain Old Java Object) 의 구성만으로 가능하도록 제작되어있다

쉽게 말하면 일반적인 Java 코드를 이용해서 객체를 구성하는 방식을 그대로 스프링에서 사용할 수 있다는 말이다

비유설명

POJO란 "Plain Old Java Object"의 약자로, 간단하고 기본적인 자바 객체를 의미합니다. POJO는 특별한 규칙이나 프레임워크에 의존하지 않고, 순수하게 자바 언어의 기능만을 사용하여 만든 객체를 말합니다.

이것을 비유하자면, POJO는 마치 기본 재료로 맛있는 요리를 만드는 것과 비슷합니다. 요리사가 고급 조리법이나 특별한 조리 도구를 사용하지 않고, 단순한 재료와 주방 도구만을 이용해 요리를 만든다면 그것이 바로 진정한 실력을 보여주는 것처럼,

 POJO도 자바 객체를 만들 때 특별한 라이브러리나 프레임워크를 사용하지 않고 순수한 자바 언어만으로 객체를 만드는 것을 의미합니다.

POJO는 자바의 간결한 문법과 기본적인 객체 지향적인 특징을 따르며, 복잡한 기능이나 규칙을 따르지 않아도 되기 때문에 개발자가 더 자유롭게 객체를 정의하고 사용할 수 있습니다. 이렇게 단순하고 순수한 형태의 객체를 만드는 것은 유지 보수가 쉽고 확장성이 높은 코드를 작성하는데 도움을 줄 수 있습니다.
```

### 의존성 주입(DI) 와 스프링

```java
의존성 이라는 것은

하나의 객체가 다른 객체 없이 제대로 된 역할을 할 수 없다는 것을 의미한다 예를 들어 A객체가 B객체 없이 동작이 불가능한 상황을 A가 B에 의존적이다 라고 표현한다

주입은 말 그대로 외부에서 밀어 넣는 것 을 의미한다

외부에서 주입하는 것과 그렇지 않은것을 이해하기 위해서 음식점의 식재료를 생각해 보면 쉽다 어떤 음식점은 매일 가게를 열기 전 직접 식재료를 구하기 위해 시장을 가지만 프랜차이즈 식당들은 본사가 트럭 등을 이용해서 식재료를 공급한다

이 두 방식의 차이는 필요한 객체를 얻기 위해서 주체가 능동적인지 수동적인지(본인 스스로 하는지)에 대한 문제이다

그럼 의존성 주입을 결합해서 생각해 보면 "어떤 객체가 필요한 객체를 외부에서 밀어 넣는다" 는 의미가 된다

그렇다면 왜 외부에서 객체를 주입하는 방식 을 사용하는지에 대해서 알 필요가 생긴다

음식점의 예에서 직접 식재료를 사지 않고 대행업체에서 배송해 주는 것을 사용하는 경우에 장점을 생각해보면 "편리하다", "장사에만 집중할 수 있다" 같은 장점이 있다 이를 코드에 대입해 보면 주입 받는

입장에서는 "어떤 객체인지 신셩 쓸 필요가 없다" "어떤 객체에 의존하든 자신의 역할은 변하지 않느다" 와 같은 의미로 볼 수 있다
```

### ApplicationContext

```java
스프링은 이러한 구조를 만드는데 적합한 구조로 설계되어 있다

스프링에서는 ApplicationContext 라는 존재가 필요한 객체들을 생성하고 필요한 객체들을 주입하는 구조를 가지고 있다

따라서 스프링을 사용하면 기존의 프로그래밍과 달리 객체와 객체를 분리해서 생서하고 이러한 객체들을 엮는(wiring) 작업을 하는 형태의 개발을 하게 된다

스프링 에서는 ApplicationContext 가 관리하는 객체들을 "빈(Bean)" 이라는 용어로 부르고 빈과 빈 사이의 의존관계를 처리하는 방식으로 XML설정, 어노테이션 설정, Java 설정 방식을 이용할 수 있다

```

### AOP 지원

```java
좋은 개발환경의 중요 원칙은 개발자가 비즈니스 로직에만 집중할 수 있게 한다 이다

이 목표를 이루기 위한 원칙중 하나는 "반복적인 코드의 제거" 라고 할 수 있다.

대부분의 시스템이 공통으로 가지고 있는 보안이나 로그 트랜잭션 같이 비즈니스 로깆은 아니지만 반드시 처리가 필요한 부분을 스프링에서는

"횡단 관심사(cross - concern)" 한다 스프링에서는 이러한 횐단 관심사를 분리해서 제작하는 것이 가능하다

AOP 는 이러한 횡단 관심사를 모듈로 분리하는 프로그래밍 패러담이이다

스프링 AOP 를 AspectJ 의 문법을 통해서 작성할 수 있는데 이를 통해서 개발자는

1) 핵심 비즈니스 로직에만 집중해서 코드를 개발할 수 있게 되었ㄷ고

2) 각 프로젝트 마다 다른 관심사를 적용할 때 코드의 수정을 최소화 시킬 수 있었으며

3) 원하는 관심사의 유지 보수가 수월한 코드를 구성할 수 있다
```

### 트랜잭션의 지원

```java
데이터 베이스를 이용할 때 반드시 신경 써야 하는 부분은 하나의 업무가 여러 작업으로 이루어지는 경우의 트랜잭션 처리이다

이 트랜잭션 처리는 상황에 따라서 복잡하게 구성 될수도 있고 아닐수도 있는데 그때마다 코드를 이용해서 처리하는 작업은 개발자 에게 상당히 피곤하다

스프링은 트랜잭션의 관리를 어노테이션이나 XML 로 설정할 수 있기 때문에 개발자가 매번 상황에 맞는 코드를 작성할 필요가 없다
```
