# { 🎮 Blueprint와 Animation Blueprint 연동하기 }

## 🎯 목표

BP_F18의 Pitch 값을 ABP_F18로 전달

- Blueprint 변수 생성
- Animation Blueprint에서 접근
- Elevator가 실시간으로 움직이도록

---

## 💡 핵심 원리: 데이터 흐름 이해

### 전체 데이터 흐름

```
1. 플레이어 입력
   W/S 키 누름
   ↓
2. BP_F18 (게임 로직)
   IA_Pitch → Set Pitch Input
   ↓
   Pitch_Value 변수에도 저장
   ↓
3. ABP_F18 (애니메이션)
   BP_F18의 Pitch_Value 가져오기
   ↓
4. Transform (Modify) Bone
   Elevator 회전 적용
   ↓
5. 화면
   Elevator가 움직이는 모습 표시
```

**왜 이런 복잡한 과정인가?**

```
Blueprint와 Animation Blueprint는:
  완전히 분리된 시스템
  ↓
Blueprint:
  - 게임 로직
  - 물리 제어
  - 입력 처리

Animation Blueprint:
  - 애니메이션만
  - 뼈대 제어
  - 시각적 표현

연결 필요:
  변수를 통한 데이터 전달 ✅
```

---

## 🔧 1단계: BP_F18에 변수 생성

### Pitch_Value 변수 생성

```
BP_F18 → Variables 패널
  ↓
+ 버튼 클릭
  ↓
이름: Pitch_Value
타입: Float
기본값: 0.0
```

**왜 같은 이름인가?**

```
ABP_F18에도 Pitch_Value 존재
  ↓
같은 이름 사용:
  - 헷갈리지 않음
  - 용도가 명확
  - 디버깅 쉬움 ✅

주의:
  - 서로 다른 변수!
  - 단지 이름만 같음
  - 값은 별도로 관리
```

---

## 🔧 2단계: IA_Pitch에 변수 저장 추가

### Triggered 이벤트 수정

```
기존:
  [IA_Pitch] Triggered
    ↓
  [Set Pitch Input]
    └─ Pitch: Action Value

추가:
  [IA_Pitch] Triggered
    ↓
  Action Value
    ├────────────────────┐
    ↓                    ↓
  [SET] Pitch_Value   [Set Pitch Input]
    (변수 저장)         (엔진 제어)
```

**왜 두 곳에 연결하나?**

```
Set Pitch Input:
  - Vehicle Movement 제어
  - 실제 비행 움직임

SET Pitch_Value:
  - 변수에 값 저장
  - Animation Blueprint에서 사용
  ↓
둘 다 필요! ✅
```

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788380602/notion-blog/_/_/BG/4/image.png)

### Completed 이벤트도 수정

```
[IA_Pitch] Completed
  ↓
0.0 (상수)
  ├────────────────────┐
  ↓                    ↓
[SET] Pitch_Value   [Set Pitch Input]
```

**왜 둘 다 0으로?**

```
Set Pitch Input (0):
  - 회전 멈춤

SET Pitch_Value (0):
  - Elevator 중립 위치로
  ↓
완전한 중립 복귀 ✅
```

---

## 🔧 3단계: ABP_F18에서 BP_F18 참조 얻기

### Event Blueprint Begin Play 사용

```
ABP_F18 → Event Graph
  ↓
Event Blueprint Begin Play 이미 존재
```

**Event Blueprint Begin Play란?**

```
Animation Blueprint 전용 BeginPlay
  ↓
차이점:
  - Event BeginPlay: Actor용
  - Event Blueprint Begin Play: Animation용

실행 시점:
  Animation Blueprint 시작 시 1회
  ↓
  초기화에 적합 ✅
```

---

## 🔧 4단계: Try Get Pawn Owner 노드

### 노드 추가

```
[Event Blueprint Begin Play]
  ↓
[Try Get Pawn Owner]
```

**Try Get Pawn Owner란?**

```
기능:
  이 Animation Blueprint를 소유한
  Pawn(조종 가능한 객체)을 가져옴
  ↓
  F18 비행기가 소유자
  ↓
  BP_F18을 반환

왜 "Try"인가?
  - 실패할 수 있음
  - 소유자 없을 수도 있음
  - 안전한 접근 방식 ✅
```

---

## 🔧 5단계: Cast To BP_F18 노드

### Casting(형변환) 필요성

```
Try Get Pawn Owner 반환값:
  타입: Pawn (일반적인 Pawn)
  ↓
문제:
  일반 Pawn에는 Pitch_Value 없음!
  ↓
해결:
  BP_F18 타입으로 변환 필요
```

### Cast To 노드 추가

```
[Try Get Pawn Owner] Return Value
  ↓
[Cast To BP_F18]
  ├─ Object: Return Value
  ├─ As BP_F18 (성공 시 출력)
  └─ Cast Failed (실패 시)
```

**Casting(형변환)이란?**

```
비유:
  "이게 사과인가?" 확인하고 변환
  ↓
일반 과일 → 사과로 명확히 지정
  ↓
사과의 기능 사용 가능

실제:
  일반 Pawn → BP_F18로 변환
  ↓
  BP_F18의 변수(Pitch_Value) 접근 가능 ✅

실패하면?
  - Cast Failed 핀 실행
  - 안전한 에러 처리
```

## 🔧 6단계: BP_F18을 변수로 저장

### Promote to Variable

```
[Cast To BP_F18] As BP_F18 핀
  ↓
우클릭 → Promote to Variable
  ↓
이름: BP_F18
```

**왜 변수로 저장하나?**

```
저장 안 하면:
  - 매번 Try Get Pawn Owner 호출
  - 매번 Cast 필요
  - 비효율적 ❌

저장하면:
  - 1회만 가져옴 (BeginPlay)
  - 이후 변수만 사용
  - 효율적 ✅
```

### 노드 구조

```
[Event Blueprint Begin Play]
  ↓
[Try Get Pawn Owner]
  ↓
[Cast To BP_F18]
  ↓
[SET] BP_F18 (변수 저장)
```

---

## 🔧 7단계: Event Blueprint Update Animation에서 사용

### Update Animation 이벤트란?

```
Animation Blueprint의 Event Tick
  ↓
매 프레임 실행 (초당 60회)
  ↓
실시간 업데이트에 사용
```

**왜 BeginPlay가 아닌 Update Animation인가?**

```
BeginPlay:
  - 1회만 실행
  - 초기화용
  - 값 변화 감지 못함 ❌

Update Animation:
  - 매 프레임 실행
  - 실시간 감지
  - 값 변화 즉시 반영 ✅
```

## 🔧 8단계: Is Valid 체크

### 노드 구성

```
[Event Blueprint Update Animation]
  ↓
[GET] BP_F18 (저장한 변수)
  ↓
[Is Valid]
  ├─ Is Valid (성공)
  └─ Is Not Valid (실패)
```

**Is Valid 노드란?**

```
기능: 객체가 유효한지 확인
  ↓
유효함 (Valid):
  - 객체 존재
  - 메모리에 있음
  - 사용 가능 ✅

무효함 (Not Valid):
  - null/없음
  - 삭제됨
  - 사용 불가 ❌
```

**왜 필요한가?**

```
가능한 문제 상황:
  - BP_F18이 아직 생성 안 됨
  - 게임 중 삭제됨
  - Cast 실패

Is Valid 없이 접근 시:
  - 크래시 발생 ❌

Is Valid로 확인:
  - 안전한 접근
  - 에러 방지 ✅
```

## 🔧 10단계: 값 증폭 (Multiply)

### 문제점

```
BP_F18.Pitch_Value:
  범위: -1.0 ~ 1.0
  ↓
Elevator 회전:
  -1도 ~ 1도
  ↓
너무 작아서 안 보임 ❌
```

### 해결: Multiply 추가

```
AnimGraph:

[GET] Pitch_Value
  ↓
[Multiply] × 10
  ↓
[Transform (Modify) Bone] Rotation Y
  ↓
결과: -10도 ~ 10도 (더 명확 ✅)
```

**배수 조정**

```
× 5: 작은 움직임
× 10: 적당 ✅
× 20: 큰 움직임
× 30: 과도함

실제 비행기 참고하여 조정
```

# { 🎮 부드러운 조종면 애니메이션 구현하기 (FInterp To) }

## 🎯 목표

즉각적인 회전을 부드러운 애니메이션으로 개선

- FInterp To로 점진적 변화
- Timeline으로 중립 복귀
- 자연스러운 조종 느낌

---

## ⚠️ 현재 문제점

### 스냅 현상

```
W 누름:
  Pitch_Value: 0 → 1 (즉시)
  ↓
  Elevator가 뚝 하고 회전 ❌

S 누름:
  Pitch_Value: 1 → -1 (즉시)
  ↓
  역시 뚝 하고 회전 ❌

비현실적이고 어색함
```

---

## 💡 핵심 개념: FInterp To

### FInterp To란?

```
Float Interpolation To (부동소수점 보간)
  ↓
기능:
  현재값에서 목표값까지
  시간에 따라 부드럽게 변화

비유:
  엘리베이터처럼 천천히 이동
  (계단처럼 뚝뚝 끊기지 않음)
```

**입력 파라미터:**

```
Current (현재값):
  - 지금 어디에 있는가?
  - Pitch_Value (GET)

Target (목표값):
  - 어디로 가야 하는가?
  - Action Value (1 또는 -1)

Delta Time (델타 타임):
  - 이전 프레임 이후 경과 시간
  - Get World Delta Seconds

Interp Speed (보간 속도):
  - 얼마나 빠르게 변할까?
  - 5.0 (적당한 속도)
```

## 🔧 5단계: Elevator 설정 (핵심!)

### 왜 Pitch 값을 변경하나?

**중요한 개념:**

```
Roll_Value를 사용하지만
  ↓
변경하는 것은 Pitch (Y축 회전)!
  ↓
이유:
  - Elevator는 상하로만 움직임
  - Roll(X축) 회전은 비현실적
  - Pitch 회전이 올바름 ✅
```

**비유:**

```
잘못된 생각:
  "Roll 값이니까 Roll 축으로 회전?"
  ↓
  Elevator가 옆으로 눕는 이상한 모습 ❌

올바른 방법:
  "Roll을 만들기 위해 Pitch 축으로 회전"
  ↓
  Elevator가 위/아래로 움직임 ✅
```

### 왼쪽 Elevator 설정

```
Transform (Modify) Bone
  ├─ Bone: lf_elevator_jnt
  └─ Rotation Y (Pitch):
      [Roll_Value] × 10
```

### 오른쪽 Elevator 설정 (반대!)

```
Transform (Modify) Bone
  ├─ Bone: rt_elevator_jnt
  └─ Rotation Y (Pitch):
      [Roll_Value] × -10 (← 음수!)
```

**작동 예시:**

```
D 키 누름:
  Roll_Value = 1.0
  ↓
왼쪽 Elevator:
  1.0 × 10 = +10도 (위로)

오른쪽 Elevator:
  1.0 × -10 = -10도 (아래로)
  ↓
오른쪽으로 기울어짐 ✅
```
