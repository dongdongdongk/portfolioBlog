### Prisma 소개: 초보자를 위한 기본 개념

Prisma는 Node.js와 TypeScript(또는 JavaScript)에서 데이터베이스를 쉽게 다루기 위한 도구입니다. ORM(Object-Relational Mapping)이라고 불리는데,

이는 SQL 데이터베이스(예: PostgreSQL, MySQL)를 코드로 안전하게 쿼리할 수 있게 해줍니다. SQL 문법을 직접 쓰지 않고,

JavaScript 객체처럼 쿼리를 작성할 수 있어서 초보자도 쉽게 배울 수 있어요.

Prisma의 주요 구성 요소:

- **Prisma Schema**: 데이터베이스 구조를 정의하는 파일 (모델과 관계를 적음).
- **Prisma Client**: 실제 쿼리를 실행하는 JavaScript 라이브러리.
- **Prisma Migrate**: 데이터베이스 스키마를 업데이트하는 도구.

"조인(join)"은 관계형 데이터베이스에서 테이블을 연결하는 개념인데, Prisma에서는 SQL 조인을 직접 쓰지 않고

**관계(relations)**를 통해 처리합니다. 예를 들어, 사용자(User)와 게시물(Post)의 관계를 정의하면, 쿼리에서 자동으로 연결된 데이터를 가져올 수 있어요.

이 설명에서는 Prisma의 기본 문법부터 조인(관계 쿼리), 예시를 단계별로 설명하겠습니다.

모든 예시는 Prisma 공식 문서에서 기반한 내용입니다. 설치 방법: `npm install @prisma/client` 후, `npx prisma init`으로 시작하세요.

### 1. 기본 개념: 모델과 관계

- **모델(Model)**: 데이터베이스 테이블을 나타냅니다. 예: User, Post.
- **관계(Relations)**: 모델 간 연결.
  - **One-to-One (1:1)**: 한 사용자에 한 프로필 (e.g., User has one Profile).
  - **One-to-Many (1:N)**: 한 사용자에 여러 게시물 (e.g., User has many Posts).
  - **Many-to-Many (N:M)**: 여러 게시물에 여러 카테고리 (e.g., Post has many Categories, Category has many Posts).

초보 팁: 관계를 생각할 때, "누가 누구를 가지는가?"를 먼저 정의하세요.

### 2. Prisma Schema 정의 (문법 기초)

Prisma 스키마 파일 (`schema.prisma`)에 모델과 관계를 씁니다. 예시:

```
datasource db {
  provider = "postgresql"  // 데이터베이스 종류 (mysql 등 변경 가능)
  url      = env("DATABASE_URL")
}

generator client {
  provider = "prisma-client-js"
}

model User {
  id    Int     @id @default(autoincrement())  // 기본 키, 자동 증가
  email String  @unique  // 유일한 이메일
  name  String?
  posts Post[]  // 관계: User가 여러 Post를 가짐 (One-to-Many)
}

model Post {
  id        Int     @id @default(autoincrement())
  title     String
  published Boolean @default(false)
  author    User    @relation(fields: [authorId], references: [id])  // 외래 키
  authorId  Int
  categories Category[]  // Many-to-Many 관계
}

model Category {
  id    Int    @id @default(autoincrement())
  name  String
  posts Post[]  // Many-to-Many 관계 (자동으로 중간 테이블 생성)
}

```

- `@id`: 기본 키.
- `@relation`: 관계 정의 (fields: 외래 키 필드, references: 참조하는 키).
- `[]`: 배열로 Many 관계 표시.

이 스키마를 적용하려면 `npx prisma migrate dev`를 실행하세요. Prisma Client를 업데이트하려면 `npx prisma generate`.

### 3. 기본 쿼리 문법

Prisma Client로 쿼리를 합니다. 주요 메서드:

- `findMany()`: 여러 레코드 찾기.
- `findUnique()` 또는 `findFirst()`: 하나 찾기.
- `create()`: 생성.
- `update()`: 업데이트.
- `delete()`: 삭제.

예시: 사용자 찾기

```jsx
const users = await prisma.user.findMany() // 모든 사용자 가져오기
```

필터링: where 사용

```jsx
const user = await prisma.user.findUnique({
  where: { id: 1 }, // ID가 1인 사용자
})
```

### 4. 조인(관계 쿼리): 관련 데이터 가져오기

Prisma에서 "조인"은 `include`나 `select`로 관련 레코드를 함께 가져오는 것입니다. 이는 Eager Loading(미리 로드)이라고 해요. SQL JOIN처럼 데이터베이스에서 한 번에 가져옵니다.

### 4.1 include 사용 (전체 관련 데이터 가져오기)

- 모든 필드를 포함.
  예시: 사용자와 게시물 함께 가져오기

```jsx
const user = await prisma.user.findFirst({
  include: {
    posts: true, // posts 배열 포함
  },
})
```

// 결과: { id: 1, email: '...', posts: [{id:..., title:...}, ...] }

### 4.2 select 사용 (특정 필드만 선택)

- 필요한 필드만 골라서 가져옴 (성능 좋음).
  예시: 사용자 이름과 게시물 제목만

```jsx
const user = await prisma.user.findFirst({
  select: {
    name: true,
    posts: {
      select: {
        title: true,
      },
    },
  },
})
```

// 결과: { name: 'Alice', posts: [{title: 'Post1'}, {title: 'Post2'}] }

초보 팁: `include`는 전체 포함, `select`는 세밀한 선택. 둘을 섞어 쓸 수 있어요 (e.g., include 안에 select).

### 4.3 깊은 중첩 (Nested Relations)

예시: 사용자 -> 게시물 -> 카테고리

```jsx
const user = await prisma.user.findFirst({
  include: {
    posts: {
      include: {
        categories: true,
      },
    },
  },
})
```

### 4.4 관계 로드 전략 (Advanced, Prisma 5.8+)

`relationJoins` 기능을 활성화하면 `relationLoadStrategy: 'join'` 또는 `'query'` 선택 가능. 'join'이 기본으로 효율적.

```
// schema.prisma에 추가
previewFeatures = ["relationJoins"]

```

```jsx
const users = await prisma.user.findMany({
  relationLoadStrategy: 'join',
  include: { posts: true },
})
```

### 5. 관계 필터링 (조건으로 조인 필터)

관계 기반으로 필터링. One-to-Many: some(하나 이상), every(모두), none(없음). One-to-One: is, isNot.

예시: 게시물이 하나 이상 있는 사용자 찾기 (some)

```jsx
const users = await prisma.user.findMany({
  where: {
    posts: {
      some: { published: true }, // published가 true인 게시물이 하나 이상
    },
  },
  include: { posts: true },
})
```

예시: 게시물이 없는 사용자 (none {})

```jsx
const usersWithNoPosts = await prisma.user.findMany({
  where: { posts: { none: {} } },
})
```

Many-to-Many도 비슷: categories { some: { name: 'Cooking' } }

### 6. Fluent API (체인 쿼리)

관계를 체인으로 탐색. 단일 레코드부터 시작.
예시: 이메일로 사용자 찾고 게시물 가져오기

```jsx
const posts = await prisma.user.findUnique({ where: { email: 'alice@prisma.io' } }).posts()
```

### 7. 중첩 쓰기 (Nested Writes): 생성/업데이트 시 관계 처리

한 번에 관련 데이터 생성/연결/삭제. 트랜잭션으로 안전함.

### 7.1 생성 시 관련 레코드 만들기

One-to-Many 예시:

```jsx
const result = await prisma.user.create({
  data: {
    email: 'elsa@prisma.io',
    posts: {
      create: [{ title: 'Post1' }, { title: 'Post2' }],
    },
  },
  include: { posts: true },
})
```

Many-to-Many 예시:

```jsx
const result = await prisma.post.create({
  data: {
    title: 'New Post',
    categories: {
      create: { name: 'Cooking' },
    },
  },
})
```

### 7.2 기존 레코드 연결 (connect)

```jsx
const result = await prisma.user.update({
  where: { id: 1 },
  data: {
    posts: {
      connect: { id: 10 }, // ID 10 게시물 연결
    },
  },
})
```

// 여러 개: connect: [{id:8}, {id:9}]

### 7.3 업데이트/업서트

```jsx
const result = await prisma.user.update({
  where: { id: 1 },
  data: {
    posts: {
      update: {
        where: { id: 10 },
        data: { title: 'Updated Title' },
      },
    },
  },
})
```

### 7.4 연결 해제/삭제 (disconnect, delete)

```jsx
const result = await prisma.user.update({
  where: { id: 1 },
  data: {
    posts: {
      disconnect: { id: 10 }, // 연결 해제 (레코드 유지)
      delete: { id: 11 }, // 삭제
    },
  },
})
```

초보 팁: connect 시 레코드가 없으면 에러 발생. 먼저 findUnique로 확인하세요. Many-to-Many는 자동 중간 테이블 관리.
