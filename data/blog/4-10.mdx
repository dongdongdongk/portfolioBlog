# {`params.slug` 와 `[slug]` 폴더 이름의 관계 }

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381297/notion-blog/_/Next_js/Next_js_15_React_-_/_4_-_/image.png)

## `params.slug` 와 `[slug]` 폴더 이름의 관계

```jsx
필요하다면 slug 대신 다른 이름도 쓸 수 있습니다.

예를 들어 [id]로 바꾸면 params.id로 접근해야 합니다.

즉, 파일/폴더 이름과 params의 key는 반드시 일치해야 작동합니다. ✅
```

### 1. **파일 이름 `[slug]`**

```jsx
Next.js에서 대괄호([])를 사용한 파일 또는 폴더는 동적 라우팅(Dynamic Routing) 을 의미합니다.

[slug]는 URL 경로의 일부를 변수처럼 받아오겠다는 뜻입니다.

예:
/news/some-news-id 라는 URL은 news/[slug]/page.jsx로 라우팅됩니다.
```

### 2. **`params.slug` 의 의미**

```jsx
Next.js의 서버 컴포넌트나 파일 기반 라우팅에서 params 객체는 URL에서 동적으로 추출한 값을 담고 있습니다.

params.slug는 [slug]에 들어온 URL 경로 값을 의미합니다.
```

### 3. **둘의 연결**

```jsx
[slug] 라는 폴더명은 params.slug 로 자동 매핑됩니다.

예를 들어, 사용자가 /news/dog-update 에 접근하면:
```

```jsx
params = { slug: 'dog-update' }
```

# { 병렬 라우트(Parallel Routes)란? }

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381296/notion-blog/_/Next_js/Next_js_15_React_-_/_4_-_/image_1.png)

## 개념 요약:

```jsx
하나의 URL 경로에서 여러 페이지를 나란히 렌더링할 수 있는 Next.js 기능.

예: /archive 페이지에서 왼쪽에는 연도별 뉴스 아카이브, 오른쪽에는 최신 뉴스 리스트를 동시에 보여주기.
```

## 폴더 구조 미리보기

```jsx
app/
├── archive/
│   ├── layout.js       ← 병렬 라우트가 들어가는 공통 레이아웃
│   ├── @archive/       ← 병렬 라우트 1: 연도별 아카이브
│   │   └── page.js
│   └── @latest/        ← 병렬 라우트 2: 최신 뉴스
│       └── page.js
```

```jsx
@archive, @latest 폴더 이름에 @ 기호를 붙이는 게 Next.js 병렬 라우트의 규칙입니다.

layout.js에서 두 병렬 라우트를 받아서 하나의 화면에 함께 출력합니다.
```

## 기본 흐름과 구성

| 역할               | 설명                                                 |
| ------------------ | ---------------------------------------------------- |
| `/archive` 페이지  | 아카이브 전체 페이지 경로 (병렬로 구성됨)            |
| `@archive/page.js` | 왼쪽/상단 영역의 콘텐츠 (예: 뉴스 목록 필터)         |
| `@latest/page.js`  | 오른쪽/하단 영역의 콘텐츠 (예: 최신 뉴스 리스트)     |
| `layout.js`        | 두 개의 병렬 라우트를 받아 하나로 묶는 레이아웃 구성 |

## 코드 설명

### `layout.js` – 병렬 라우트 통합 뷰

```jsx
export default function ArchiveLayout({ archive, latest }) {
  return (
    <div>
      <h1>News Archive</h1>
      <section id="archive-filter">{archive}</section>
      <section id="archive-latest">{latest}</section>
    </div>
  )
}
```

```jsx
archive, latest: @archive, @latest 폴더에서 자동으로 들어오는 콘텐츠.

각각을 <section> 태그로 구분해서 원하는 위치에 배치.
```

### `@archive/page.js` – 아카이브 콘텐츠

```jsx
export default function ArchivePage() {
  return <h1>Archive Page</h1>
}
```

### `@latest/page.js` – 최신 뉴스 콘텐츠

```jsx
export default function LatestNewsPage() {
  return <h1>Latest News Page</h1>
}
```

## 왜 병렬 라우트가 유용할까?

```jsx
하나의 URL 경로에서 여러 콘텐츠 블록을 분리해서 관리할 수 있어 유지보수가 쉬움.

페이지마다 독립적으로 구성되므로 코드 분리도 잘 됨.

사용자가 동시에 여러 정보를 확인할 수 있어 UX가 좋아짐.
```

## 정리된 제목과 요약

### 병렬 라우트 이해하기: `/archive`에서 두 콘텐츠를 동시에 보여주는 방법

```jsx
병렬 라우트는 하나의 경로에 여러 페이지 콘텐츠를 나란히 보여주는 기능.

폴더 이름에 @를 붙이고, layout.js에서 이를 props로 받아 렌더링.

Next.js가 자동으로 병렬 라우트를 layout에 props로 주입해 줌.

유용한 상황: 좌우로 나뉜 UI, 탭 구성, 다중 정보 영역 등.
```

# { 병렬 라우팅 (Parallel Routing) 심화 }

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381296/notion-blog/_/Next_js/Next_js_15_React_-_/_4_-_/image_2.png)

```jsx
Next.js의 병렬 라우팅 (Parallel Routing) 기능을 이용해서

한 페이지 내에 서로 독립적인 라우트(예: 최신 뉴스, 연도별 뉴스)를 동시에 표시하는 구조입니다.
```

## 1. 병렬 라우팅이란?

```jsx
동일한 페이지에서 여러 라우트를 나란히 보여주는 Next.js의 기능입니다.

예: /archive 페이지에선 왼쪽엔 연도별 뉴스, 오른쪽엔 최신 뉴스를 동시에 보여주고 싶을 때 사용합니다.

기존 라우팅은 한 경로 = 한 페이지였지만, 병렬 라우팅은 한 경로 안에서 여러 경로를 동시에 조합할 수 있습니다.
```

## 2. 프로젝트 구조 설명 (폴더 구조)

```jsx
app/
├─ archive/
│  ├─ @latest/
│  │  └─ default.js       ← 항상 보여줄 최신 뉴스용
│  ├─ @archive/
│  │  ├─ page.js          ← 연도 링크들 출력
│  │  └─ [year]/
│  │     └─ page.js       ← 연도별 뉴스 출력
├─ news/
│  ├─ page.js             ← 전체 뉴스 목록
│  └─ [slug]/
│     └─ page.js          ← 뉴스 상세 보기 (생략됨)
components/
├─ news-list.js           ← 뉴스 리스트 출력용 컴포넌트
lib/
├─ news.js                ← 연도/뉴스 데이터 유틸리티
```

### 병렬 라우팅을 위한 키포인트:

```jsx
@latest, @archive ← 이게 병렬 슬롯 이름입니다.

같은 archive/ 라우트 안에 병렬로 동작합니다.

각 슬롯에서 사용하는 page.js 또는 default.js가 독립적으로 렌더링됩니다.
```

## 3. `default.js`란?

```jsx
병렬 슬롯(@슬롯이름) 안에서,

사용자가 특정 하위 경로를 방문하지 않았을 때

기본적으로 보여줄 콘텐츠를 정의하는 파일입니다.
```

```jsx
app/
└─ archive/
   ├─ @archive/
   │  ├─ page.js             ← 왼쪽에 연도 링크들
   │  └─ [year]/page.js      ← 특정 연도 뉴스
   ├─ @latest/
   │  └─ default.js          ← 최신 뉴스 (기본 콘텐츠)
```

```jsx
사용자가 /archive에 방문했을 때:

@archive 슬롯 → page.js 실행 → 연도 링크 출력

@latest 슬롯 → default.js 실행됨 → 최신 뉴스 출력
```

### 왜 `default.js`가 필요한가요?

```jsx
병렬 라우팅에서는 각 슬롯(@이름)이 독립적인 라우트처럼 작동합니다.

하지만 때로는 특정 슬롯에 대해 URL 경로가 정해지지 않았을 때 기본적으로 보여줄 내용이 필요하죠.
```

### 예시 시나리오

| URL 경로        | @archive 슬롯    | @latest 슬롯                                 |
| --------------- | ---------------- | -------------------------------------------- |
| `/archive`      | `page.js`        | ✅ `default.js` 사용                         |
| `/archive/2023` | `[year]/page.js` | ❌ `default.js`가 아닌 해당 year 라우트 필요 |

```jsx
만약 default.js가 없으면?

슬롯 안에서 보여줄 콘텐츠가 없기 때문에 에러 페이지가 나타날 수 있어요 (404).
```

### 주의할 점

```jsx
1. default.js는 @슬롯 내부에서만 사용할 수 있어요.

		일반 폴더에서는 page.js만 사용해야 해요.

2. default.js는 폴더 내 "fallback" 콘텐츠이기 때문에, 다른 하위 라우트가 존재하면 그쪽이 우선합니다.

		즉, /archive/2023으로 접근하면 → @archive/[year]/page.js가 우선됨

3. page.js와 default.js는 같은 슬롯에서 동시에 사용할 수 없어요.

		둘 다 있으면 충돌 위험이 있고, 보통 default.js 하나만 사용합니다.
```

## 4. 병렬 라우트 작동 방식

```jsx
예: /archive/2023

		app/archive/ 경로는 병렬 슬롯인 @archive, @latest 두 개를 동시에 렌더링합니다.


		@archive: 사용자 인터랙션을 위한 메뉴 (연도 리스트)


		@latest:

				/archive 경로일 경우엔 default.js가 표시

				/archive/2023처럼 연도가 있으면 @archive/[year]/page.js가 오른쪽 콘텐츠로 표시됨
```

# { 동적 라우팅(dynamic routing)**과 **모두 캐치 라우트(catch-all routes) }

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381297/notion-blog/_/Next_js/Next_js_15_React_-_/_4_-_/image_4.png)

## 강의 목표

```jsx
기존 뉴스 아카이브 페이지의 문제를 해결합니다.

		문제 1: 연도를 선택하면 내비게이션이 사라짐.

		문제 2: 특정 월을 선택해 뉴스를 필터링할 수 없음.

해결책: Next.js의 모두 캐치 라우트([...filter])를 사용해 동적 경로를 처리하고,

연도와 월별로 뉴스를 필터링하며 내비게이션을 유지합니다.
```

## 폴더 구조

```jsx
📁 app
├── 📁 archive
│   └── 📁 [[...filter]]
│       └── 📄 page.js          # FilteredNewsPage 컴포넌트 (연도/월 필터링)
├── 📁 news
│   ├── 📁 [slug]
│   │   └── 📄 page.js          # 개별 뉴스 상세 페이지 (예: /news/some-news)
│   └── 📄 page.js              # LatestNewsPage 컴포넌트 (최신 뉴스 목록)
├── 📁 components
│   └── 📄 news-list.jsx        # NewsList 컴포넌트 (뉴스 목록 렌더링)
├── 📁 lib
│   └── 📄 news.js              # 유틸리티 함수들 (getAvailableNewsYears, getNewsForYear 등)
├── 📁 public
│   └── 📁 images
│       └── 📁 news             # 뉴스 이미지 파일들
└── 📄 layout.js                # 루트 레이아웃 (전체 앱의 기본 레이아웃)
```

## 1. 기존 문제점

```jsx
현재 애플리케이션의 뉴스 아카이브 페이지(/archive)는 다음과 같은 한계가 있습니다:

		1. 연도 선택 시 내비게이션 소실:

		연도를 선택하면(/archive/2024) 해당 연도의 뉴스는 표시되지만, 연도/월 선택 내비게이션이 사라집니다.


		2. 월별 필터링 불가:

		연도를 선택한 상태에서 특정 월(예: 3월)의 뉴스를 볼 수 없습니다.


		3. 경로 처리의 유연성 부족:

		현재는 단일 동적 라우트(/archive/[year])로 설계되어 있어,

		더 세부적인 경로(예: /archive/2024/3)를 처리할 수 없습니다.
```

## 2. 해결책: 모두 캐치 라우트(Catch-All Routes)

```jsx
Next.js의 모두 캐치 라우트를 사용하면 /archive 이후의 모든 경로 세그먼트를 처리할 수 있습니다.

이를 통해 연도와 월별 필터링을 구현하고, 내비게이션을 유지할 수 있습니다.
```

### 모두 캐치 라우트란?

```jsx
Next.js에서 동적 라우트를 정의할 때,

폴더 이름을 [...이름] 형식으로 설정하면 모든 하위 경로 세그먼트를 배열로 받을 수 있습니다.

예: [[...filter]] 폴더는 /archive, /archive/2024, /archive/2024/3 등 모든 경로를 처리합니다.

		/archive → filter = undefined

		/archive/2024 → filter = ['2024']

		/archive/2024/3 → filter = ['2024', '3']
```

### 구현 방법

```jsx
1. 기존 동적 라우트 [year]를 [[...filter]]로 변경:

		app/archive/[year]/page.js → app/archive/[[...filter]]/page.js

		폴더 이름 앞에 점 세 개(...)를 추가하고, 식별자를 filter로 변경.

2. page.js에서 params.filter를 사용해 경로 세그먼트를 배열로 받음.

3. filter 배열을 분석해 연도(filter[0])와 월(filter[1])을 추출.
```

## 3. 코드 분석 및 동작 원리

### FilteredNewsPage 컴포넌트

```jsx
이컴포넌트는 뉴스 아카이브 페이지를 렌더링하며,

Next.js의 모두 캐치 라우트([[...filter]])를 사용해 /archive, /archive/2024, /archive/2024/3 같은 경로를 처리합니다.

연도와 월별로 뉴스를 필터링하고, 내비게이션을 동적으로 표시합니다.
```

```jsx
동적 라우팅: [[...filter]]를 사용해 /archive 이후 모든 경로를 처리.

옵셔널 체이닝: filter?.[0]로 안전하게 경로 세그먼트 접근.

조건부 렌더링: selectedYear와 selectedMonth에 따라 뉴스와 내비게이션을 동적으로 처리.

내비게이션: 연도 선택 시 월 목록 표시, 연도+월 선택 시 내비게이션 숨김.
```

```jsx
// Next.js의 Link 컴포넌트를 가져옵니다. 클라이언트 측 내비게이션을 위한 링크 생성에 사용됩니다.
import Link from 'next/link'

// NewsList 컴포넌트를 가져옵니다. 뉴스 목록을 렌더링하는 재사용 가능한 컴포넌트입니다.
import NewsList from '@/components/news-list'

// 뉴스 데이터를 처리하는 유틸리티 함수들을 가져옵니다. lib/news.js에 정의되어 있습니다.
import {
  getAvailableNewsYears, // 사용 가능한 뉴스 연도 목록 반환 (예: ['2023', '2024'])
  getAvailableNewsMonths, // 주어진 연도의 사용 가능한 월 목록 반환 (예: ['1', '2'])
  getNewsForYear, // 특정 연도의 뉴스 목록 반환
  getNewsForYearAndMonth, // 특정 연도와 월의 뉴스 목록 반환
} from '@/lib/news'

// FilteredNewsPage 컴포넌트: 동적 라우트(/archive/[[...filter]])를 처리하는 페이지
// params: Next.js가 동적 라우트에서 제공하는 객체로, URL 세그먼트를 포함
export default function FilteredNewsPage({ params }) {
  // params.filter: [[...filter]] 라우트에서 받은 경로 세그먼트 배열
  // 예: /archive → undefined, /archive/2024 → ['2024'], /archive/2024/3 → ['2024', '3']
  const filter = params.filter

  // 선택된 연도와 월을 추출
  // filter?.[0]: 첫 번째 세그먼트(연도), filter가 undefined면 undefined 반환
  // filter?.[1]: 두 번째 세그먼트(월), filter가 없거나 월이 없으면 undefined
  const selectedYear = filter?.[0]
  const selectedMonth = filter?.[1]

  // 뉴스 데이터를 저장할 변수 초기화
  let news
  // 내비게이션에 표시할 링크 목록 초기화 (기본: 연도 목록)
  let links = getAvailableNewsYears()

  // 연도만 선택된 경우 (/archive/2024)
  if (selectedYear && !selectedMonth) {
    // getNewsForYear를 호출해 선택된 연도의 뉴스 목록을 가져옴
    news = getNewsForYear(selectedYear)
    // 내비게이션 링크를 해당 연도의 월 목록으로 업데이트
    links = getAvailableNewsMonths(selectedYear)
  }

  // 연도와 월 모두 선택된 경우 (/archive/2024/3)
  if (selectedYear && selectedMonth) {
    // getNewsForYearAndMonth를 호출해 특정 연도와 월의 뉴스 목록을 가져옴
    news = getNewsForYearAndMonth(selectedYear, selectedMonth)
    // 내비게이션을 비활성화 (월별 뉴스 조회 시 연도/월 선택 메뉴 숨김)
    links = []
  }

  // 뉴스 콘텐츠 초기화: 기본적으로 "뉴스 없음" 메시지 표시
  let newsContent = <p>No news found for the selected period.</p>

  // 뉴스가 존재하고, 뉴스 배열의 길이가 0보다 크면
  if (news && news.length > 0) {
    // NewsList 컴포넌트를 사용해 뉴스 목록을 렌더링
    newsContent = <NewsList news={news} />
  }

  // JSX 반환: 헤더(내비게이션)와 뉴스 콘텐츠를 렌더링
  return (
    // Fragment(<>): 루트에 여러 요소를 반환하기 위해 사용
    <>
      {/* 헤더: 내비게이션 메뉴를 포함 */}
      <header id="archive-header">
        <nav>
          <ul>
            {/* links 배열을 순회하며 내비게이션 링크 생성 */}
            {links.map((link) => {
              // href 동적 생성
              // 연도가 선택된 경우: /archive/[연도]/[월]
              // 연도가 없는 경우: /archive/[연도]
              const href = selectedYear ? `/archive/${selectedYear}/${link}` : `/archive/${link}`
              return (
                // 각 링크는 고유 key를 가짐 (React 렌더링 최적화)
                <li key={link}>
                  {/* Link 컴포넌트로 클라이언트 측 내비게이션 구현 */}
                  <Link href={href}>{link}</Link>
                </li>
              )
            })}
          </ul>
        </nav>
      </header>
      {/* 뉴스 콘텐츠 렌더링: 뉴스 목록 또는 폴백 메시지 */}
      {newsContent}
    </>
  )
}
```

## 기본 개념 정리

### 1. `error.js` 파일이란?

```jsx
특정 페이지에서 에러가 발생하면 대신 보여줄 컴포넌트를 만드는 파일이에요.

not-found.js와 비슷하게 작동하지만, 에러 전용이에요.
```

### 2. 어디에 만들면 되나요?

```jsx
에러를 처리하고 싶은 page.js 파일과 같은 폴더에 error.js 파일을 만들면 됩니다.
```

```jsx
/app/filter/page.js
/app/filter/error.js   ← 여기에 에러 처리 컴포넌트!
```

## error.js 예제 코드

```jsx
'use client' // 클라이언트 컴포넌트임을 명시

export default function FilterError({ error }) {
  return (
    <div id="error">
      <h2>오류가 발생했습니다!</h2>
      <p>{error.message}</p>
    </div>
  )
}
```

| 코드           | 설명                                                                                                             |
| -------------- | ---------------------------------------------------------------------------------------------------------------- |
| `'use client'` | **클라이언트 컴포넌트**라는 것을 명시함. 에러는 브라우저에서도 발생할 수 있기 때문에 클라이언트 컴포넌트여야 함. |
| `FilterError`  | 에러가 났을 때 렌더링될 컴포넌트 이름이에요. 마음대로 바꿔도 상관 없어요.                                        |
| `{error}`      | Next.js가 에러 정보를 자동으로 넘겨줘요. `error.message`를 통해 실제 에러 메시지를 출력할 수 있어요.             |

## 왜 클라이언트 컴포넌트여야 하나요?

```jsx
에러는 다음 두 가지 상황에서 발생할 수 있어요:

		1. 서버에서 페이지를 렌더링하는 도중 (Server Side Error)

		2. 브라우저에서 사용자가 페이지와 상호작용 중 (Client Side Error)

이 둘을 모두 처리하기 위해 error.js는 클라이언트 컴포넌트여야 해요. 그래서 꼭 상단에 'use client'를 써줘야 해요.

( 클라이언트 컴포넌트는 두가지다 커버 가능 )

* 서버 컴포넌트(page.js 등)는 브라우저에서 실행되지 않아요.

그래서 사용자 상호작용 중 생긴 클라이언트 측 오류를 잡을 수 없어요.
```

### 서버 컴포넌트 vs 클라이언트 컴포넌트 간단 구분

| 구분           | 서버 컴포넌트          | 클라이언트 컴포넌트                |
| -------------- | ---------------------- | ---------------------------------- |
| 어디서 실행됨? | 서버 (Node.js 환경)    | 브라우저 (사용자 PC)               |
| 언제 실행됨?   | 페이지 처음 로드 시    | 로드 이후 사용자와 상호작용 시     |
| 예시           | `page.js`, `layout.js` | 버튼 클릭, 입력 처리, 오류 캐치 등 |

### 에러는 어디서 발생할 수 있을까?

| 발생 위치          | 예시                              | 설명                                              |
| ------------------ | --------------------------------- | ------------------------------------------------- |
| 서버에서           | 데이터 요청 실패, 코드 오류 등    | 페이지 로딩 중 서버에서 문제가 생김               |
| **클라이언트에서** | 버튼 클릭 후 오류, 사용자 입력 등 | 사용자가 페이지를 이용하는 **도중**에 생기는 에러 |

# **{ 서버 컴포넌트(Server Component)**, **클라이언트 컴포넌트(Client Component)**, 그리고 `usePathname` }

```jsx
강의 내용은 Next.js의 서버 컴포넌트(Server Component),

클라이언트 컴포넌트(Client Component), 그리고 usePathname 훅을 활용한 동적 링크 강조 표시 방법에 대한 내용입니다.
```

## 1. 서버 컴포넌트와 클라이언트 컴포넌트란?

### 서버 컴포넌트 (Server Component)

```jsx
기본적으로 Next.js의 모든 컴포넌트는 서버 컴포넌트입니다.

서버 컴포넌트는 오직 서버에서만 실행되고 렌더링됩니다.

즉, 브라우저에서는 전혀 실행되지 않기 때문에 클라이언트에 불필요한 JS가 전송되지 않습니다.

✅ 장점: 빠르고 가볍다 (클라이언트에서 불필요한 실행 없음)

예시: 페이지를 새로고침할 때 서버 터미널에만 console.log가 찍히고 브라우저 콘솔에는 찍히지 않음 → 서버 컴포넌트라는 증거
```

### 클라이언트 컴포넌트 (Client Component)

```jsx
use client라는 지시어를 파일 맨 위에 추가해야 합니다.

이 컴포넌트는 서버에서 렌더링되긴 하지만, 브라우저에서도 실행됩니다.

주로 다음과 같은 경우에 필요합니다:

		useState, useEffect, usePathname 등 React 훅을 쓸 때

		사용자 인터랙션이 필요할 때 (버튼 클릭, 폼 입력 등)

		브라우저 API (window, localStorage 등)를 사용할 때
```

## 2. 왜 `error.js`는 클라이언트 컴포넌트여야 하나요?

```jsx
error.js는 에러가 발생했을 때 보여줄 폴백 UI입니다.

서버에서 오류가 날 수도 있고, 클라이언트 코드에서도 오류가 날 수 있기 때문에,

따라서 error.js에는 use client 지시어가 꼭 필요합니다.
```

### 목적


## 4. 문제점: `usePathname`은 클라이언트에서만 작동

```jsx
서버 컴포넌트에서는 훅을 사용할 수 없습니다.

usePathname을 쓰려면 해당 컴포넌트를 use client로 클라이언트 컴포넌트로 바꿔야 합니다.

문제는 전체 main-header.js를 클라이언트 컴포넌트로 바꾸면,

불필요한 마크업도 클라이언트에 전송됨 → 성능 낭비
```

## 5. 해결책: 클라이언트 전용 NavLink 컴포넌트 분리

```jsx
👉 핵심 전략: "클라이언트 기능만 따로 분리해서 최소한의 코드만 클라이언트 컴포넌트로 작성"
```

### `nav-link.js` (클라이언트 컴포넌트)

```jsx
'use client'

import Link from 'next/link'
import { usePathname } from 'next/navigation'

export default function NavLink({ href, children }) {
  const path = usePathname() // 현재 브라우저 경로 가져오기

  return (
    <Link
      href={href}
      className={path.startsWith(href) ? 'active' : undefined} // 경로 일치하면 강조
    >
      {children}
    </Link>
  )
}
```

```jsx
use client 지시어 추가

usePathname()으로 현재 경로 확인

startsWith(href)를 통해 현재 페이지가 /news 또는 /archive로 시작하는지 확인

조건에 따라 active 클래스를 부여하여 강조 표시
```

```jsx
  )
}
```


## 1. 인터셉팅 라우트란?

```jsx
'같은 URL이라도 어떤 방식으로 접근했는지에 따라 서로 다른 페이지를 보여주는 기능'
```

### 개념 정리

| 접근 방식             | 어떤 페이지가 보여질까?    |
| --------------------- | -------------------------- |
| 내부 링크 클릭        | 모달처럼 오버레이된 페이지 |
| 새로 고침 / 직접 입력 | 전체 화면 페이지           |

### 왜 필요할까?

```jsx
예를 들어 뉴스 리스트에서 이미지를 클릭했을 때:

		페이지 전체를 이동하지 않고

		뉴스 상세 페이지 위에 모달처럼 띄워서

		사용자 경험을 더 부드럽게 만들고 싶을 수 있어요.

그런데 새로고침하거나 직접 URL을 입력하면 모달만 있는 건 어색하니, 그럴 땐 전체 페이지로 보여주는 게 더 적절합니다.

이때 사용하는 게 인터셉팅 라우트입니다.
```

## 3. 주요 개념 설명

### 1. ( ) 괄호로 만든 인터셉팅 라우트 폴더

```jsx
예: (image)/image/page.js

		괄호 ( )는 인터셉팅 라우트 폴더를 뜻해요.

		이 폴더는 특정 라우트를 내부 탐색 시 가로채기 위해 사용됩니다.

		예: 내부 탐색으로 image로 이동하면, 이 폴더가 우선 표시됩니다.

💡 page.js 내부에서 Intercepted! 같은 텍스트가 보인다면

→ 인터셉팅 라우트가 정상 작동 중입니다.
```

### (.)와 (..)의 의미 요약

| 표기법 | 의미                                                                  |
| ------ | --------------------------------------------------------------------- |
| `(.)`  | **현재 폴더**에서 인터셉트 (같은 위치의 라우트를 가로챔)              |
| `(..)` | **한 단계 상위 폴더**로 올라가서 인터셉트 (부모 폴더 라우트를 가로챔) |

### 왜 사용하는가?

```jsx
인터셉팅 라우트를 만들 때,

가로챌 대상 라우트가 다른 위치에 있을 수 있기 때문이에요.

		인터셉팅은 폴더 이름이 중요한데,

		Next.js는 "이 라우트는 어디서 인터셉트하길 원하는가?"를 경로로 표현해야 해요.

따라서 가로챌 대상의 위치를 상대 경로처럼 표현합니다.
```

### 예시 1 — `(.)` 사용

```jsx
│   │   └── image/

│   └── image/
│       └── page.js     ← 원래의 전체 화면 라우트
```


```jsx
사용자를 이전 페이지로 되돌리는 메서드

브라우저의 "뒤로 가기 버튼"처럼 동작

router.back을 함수처럼 실행할 수 있지만, 클릭 이벤트에 넣을 땐 함수 참조만 넘겨야 해요
```

```jsx
onClick={router.back} // ✅ 괄호 X
```

## 코드 전체 설명

```jsx
'use client' // ✅ 클라이언트 컴포넌트에서만 작동하는 훅 사용 시 꼭 필요

import { notFound, useRouter } from 'next/navigation'
import { DUMMY_NEWS } from '@/dummy-news'

export default function InterceptedImagePage({ params }) {
  const router = useRouter() // ✅ 라우터 객체 생성

  const newsItemSlug = params.slug // URL에서 slug 파라미터 꺼냄
  const newsItem = DUMMY_NEWS.find((newsItem) => newsItem.slug === newsItemSlug)

  if (!newsItem) {
    notFound() // ❌ 존재하지 않는 slug면 404 페이지 보여줌
  }

  return (
    <>
      {/* ✅ 백드롭 클릭 시 router.back() 호출 */}
      <div className="modal-backdrop" onClick={router.back} />

      <dialog className="modal" open>
        <div className="fullscreen-image">
          <img src={`/images/news/${newsItem.image}`} alt={newsItem.title} />
        </div>
      </dialog>
    </>
  )
}
```

## 동작 흐름 요약

```jsx
1. 사용자가 뉴스 목록에서 이미지를 클릭

2. 모달이 열리고 URL은 변함

3. 모달 백그라운드를 클릭하면

		👉 onClick={router.back} 실행

		👉 사용자가 원래 위치한 뉴스 리스트 페이지로 돌아감
```

## 문법 요약

| 코드                    | 설명                                      |
| ----------------------- | ----------------------------------------- |
| `"use client"`          | 클라이언트 컴포넌트임을 명시              |
| `useRouter()`           | 라우터 기능 사용을 위한 훅                |
| `router.back`           | 이전 페이지로 되돌아감                    |
| `notFound()`            | 존재하지 않는 항목일 경우 404 페이지 표시 |
| `onClick={router.back}` | 클릭 시 함수 실행 (함수 참조 전달)        |

## 참고: 함수 호출 vs 함수 참조

| 코드                      | 의미                                                         |
| ------------------------- | ------------------------------------------------------------ |
| `onClick={router.back}`   | 클릭되었을 때 실행되도록 **함수 자체를 전달**                |
| `onClick={router.back()}` | 컴포넌트 렌더링 시점에 **바로 실행됨** (❌ 원하는 동작 아님) |

# **{ 라우트 그룹(Route Groups)** 기능 }

![image.png](https://res.cloudinary.com/du1acdhxq/image/upload/v1788381297/notion-blog/_/Next_js/Next_js_15_React_-_/_4_-_/image_6.png)

## 목표

```jsx
애플리케이션 시작 페이지(홈페이지)에는 헤더 없는 레이아웃을 적용

나머지 페이지(뉴스 등)는 **기존 레이아웃(MainHeader 포함)**을 유지

이를 위해 Next.js의 라우트 그룹 기능을 사용
```

## 1. 현재 상태

```jsx
app/layout.js 안에 있는 MainHeader가 모든 페이지에 공통적으로 렌더링되고 있음

하지만 시작 페이지(루트 /)에서는 헤더가 없는 깔끔한 첫 화면(landing page)을 원함
```

## 2. 라우트 그룹이란?

```jsx
Next.js에서는 괄호(( ))로 감싼 폴더를 만들면 라우트 그룹으로 인식합니다.

		라우트 그룹 폴더 이름은 URL에 나타나지 않음

		그 안에만 적용되는 별도의 layout.js를 만들 수 있음

		따라서 페이지마다 다른 레이아웃을 적용할 수 있음!
```

## 3. 폴더 구조 설정

### 예시 구조

```jsx
app/
│
├── (marketing)/          👉 시작 페이지 전용 그룹
│   ├── layout.js         👉 헤더 없는 레이아웃
│   └── page.js           👉 홈페이지
│
├── (content)/            👉 뉴스 등 일반 페이지 그룹
│   ├── layout.js         👉 MainHeader 포함된 레이아웃
│   ├── archive/
│   ├── news/
│   └── not-found.js      👉 에러 페이지도 여기 포함
│
├── globals.css
```

## 4. 라우트 그룹 적용 방법

### ① `(marketing)` 폴더 만들기

```jsx
app/(marketing)/ 폴더를 만들고, layout.js 와 page.js 파일을 이 안에 넣습니다.
```

```jsx
app / marketing / layout.js

import '../globals.css'

export const metadata = {
  title: 'Next.js Page Routing & Rendering',
  description: 'Learn how to route to different pages.',
}

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
```

```jsx
여기서는 MainHeader를 제거했어요.

헤더 없이 깔끔하게 시작 페이지를 렌더링하려고 한 거죠.
```

### ② `page.js` (시작 페이지) 이동

```jsx
원래 /app/page.js에 있던 시작 페이지 파일을 (marketing) 폴더로 이동시킵니다.
```

```jsx
import logo from '@/assets/logo.jpg'
import Link from 'next/link'

export default function HomePage() {
  return (
    <div id="home">
      <img src={logo.src} alt="A newspaper" />
      <h1>A News Site For The Next Generation</h1>
      <p>Next News is here to deliver you all the latest news - concise & unbiased!</p>
      ...
      <p>
        <Link href="/news">Read the latest news</Link>
      </p>
    </div>
  )
}
```

### ③ `(content)` 폴더 만들기

```jsx
app/(content)/ 폴더를 만들고, 기존에 있던 뉴스 페이지, 아카이브 등을 이 안으로 옮깁니다.

app/news, app/archive → app/(content)/news, app/(content)/archive
```

```jsx
app / content / layout.js

import MainHeader from '@/components/main-header'
import '../globals.css'

export const metadata = {
  title: 'Next.js Page Routing & Rendering',
  description: 'Learn how to route to different pages.',
}

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>
        <div id="page">
          <MainHeader />
          {children}
        </div>
      </body>
    </html>
  )
}
```

```jsx
기존 layout을 그대로 유지하고, MainHeader도 포함되어 있어요.

이 레이아웃은 (content) 폴더 내 라우트에만 적용됩니다.
```

### ④ 에러 페이지도 이동

```jsx
Next.js에서는 not-found.js도 라우트 그룹 내부에 있어야 동작합니다.

app/(content)/not-found.js 파일을 만들어서 404 페이지 처리
```

## 최종 결과

| 경로                   | 적용되는 레이아웃                            |
| ---------------------- | -------------------------------------------- |
| `/` (홈페이지)         | 헤더 없는 레이아웃 (`(marketing)/layout.js`) |
| `/news`, `/archive` 등 | 헤더 있는 레이아웃 (`(content)/layout.js`)   |
| 존재하지 않는 URL      | `(content)/not-found.js`가 처리              |

## 라우트 그룹의 장점

```jsx
페이지마다 다른 레이아웃 적용 가능

URL 경로에는 전혀 영향 없음

큰 프로젝트에서 레이아웃 분리가 필요할 때 매우 유용
```

## 기억할 것

```jsx
괄호 ( )로 만든 폴더는 라우트에 영향 주지 않는 그룹

각각의 그룹은 별도 layout.js를 가질 수 있음

글로벌 스타일(globals.css) 경로는 현재 파일 위치 기준으로 정확히 맞춰줘야 함
```

# { 라우트 핸들러 }

## 라우트 핸들러란?

### 개념 요약

```jsx
라우트 핸들러(route handler) 는 화면을 렌더링하지 않고,

JSON 데이터를 주고받기 위한 API 엔드포인트를 만드는 기능이에요.

즉, 클라이언트(브라우저 또는 모바일 앱) 가 데이터를 요청하거나 저장할 수 있는 API 서버 기능을 하는 거죠.
```

## 폴더 및 파일 구조

```jsx
app/
├─ api/
│  └─ route.js  ← 여기에 라우트 핸들러를 작성해요!
```

```jsx
api는 우리가 원하는 디렉토리 이름이에요 (필수 아님)

route.js는 Next.js가 자동으로 감지하는 예약 파일 이름입니다.

page.js나 layout.js는 사용하지 않아요 (왜냐면 페이지를 보여주는 게 아니니까요!)
```

## 언제 사용하나요?

```jsx
로그인 요청 처리

폼 제출 처리

데이터 저장, 불러오기

외부 API 요청 처리

모바일 앱과 통신

➡ 즉, 브라우저에서 화면 보여주기와는 별개로 "데이터 처리"에 사용돼요.
```

## 기본 예제

```jsx
// app/api/route.js
export async function GET(request) {
  return new Response('Hello!')
}
```

```jsx
이 코드는 /api 주소에 GET 요청이 들어왔을 때 "Hello!" 라는 텍스트를 응답하는 예시입니다.

브라우저에서 /api 주소에 접속하면 텍스트가 출력돼요.
```

## request 객체란?

```jsx
라우트 핸들러에서 첫 번째 매개변수인 request는 아래처럼 다양한 정보를 담고 있어요:
```

```jsx
export async function GET(request) {
  console.log(request.method) // 요청 방식 (GET, POST 등)
  console.log(request.url) // 요청 URL
  console.log(await request.json()) // POST 요청 시 body에 담긴 JSON 데이터
}
```

## 다양한 HTTP 메서드 지원

```jsx
라우트 핸들러는 여러 HTTP 요청을 처리할 수 있어요:
```

```jsx
export async function GET(request) { ... }
export async function POST(request) { ... }
export async function PUT(request) { ... }
export async function DELETE(request) { ... }
```

## JSON 응답 보내기

```jsx
텍스트 말고 JSON 형식으로 응답을 보낼 수도 있어요:

브라우저나 클라이언트에서 이 주소에 요청을 보내면 JSON 응답을 받아볼 수 있어요.
```

```jsx
export async function GET() {
  return Response.json({ message: 'Hello from API!' })
}
```

## 라우트 핸들러는 페이지가 아니다!

```jsx
page.js처럼 화면을 만드는 게 아니에요

layout.js도 필요 없습니다

HTML이 아닌 데이터 (JSON, 텍스트 등)를 응답하는 라우트입니다
```

## 라우트 핸들러는 왜 필요한가요?

| 기능                      | 예시                                 |
| ------------------------- | ------------------------------------ |
| 프론트엔드 ↔ 백엔드 통신 | 클라이언트에서 JSON 보내고 결과 받기 |
| 모바일 앱 연결            | 앱에서 서버에 데이터 요청하기        |
| 외부 서비스 연동          | 예: 외부 API 결과 가져오기           |
| 폼 제출 처리              | 사용자 입력값 저장 등                |

## 전체 흐름 요약

```jsx
1. GET, POST 등 HTTP 요청을 받는다

2. request 객체로 요청 내용을 확인한다

3. 데이터를 처리한다 (예: DB 저장, 외부 API 호출 등)

4. Response 객체로 응답을 보낸다 (텍스트 또는 JSON)
```

## 예제 테스트

```jsx
브라우저에서 /api 주소를 입력하거나,

Postman / fetch / axios 같은 도구로 테스트할 수 있어요.
```

```jsx
// 클라이언트 측 fetch 예시
fetch('/api', {
  method: 'GET',
})
  .then((res) => res.text())
  .then(console.log) // "Hello!" 출력
```

# { 미들웨어(Middleware) }

## 1. 미들웨어(Middleware)란?

```jsx
💡 모든 요청(Request) 에 대해 가로채서 처리하거나 리디렉션(redirect) 하는 기능입니다.

middleware.js는 Next.js에서 특별히 예약된 파일 이름이에요.

이 파일을 만들면 Next.js가 자동으로 해당 함수를 실행합니다.

목적은 인증 처리, 요청 검사, 리디렉션, 로그 기록 등을 하기 위함이에요.
```

## 2. 미들웨어 기본 구조

```jsx
// middleware.js (루트에 위치해야 함)
import { NextResponse } from 'next/server'

export function middleware(request) {
  console.log('요청이 들어왔습니다:', request.url)

  // 조건에 따라 리디렉션 가능
  // 예: 인증되지 않은 사용자는 로그인 페이지로 보내기
  if (!request.cookies.get('auth-token')) {
    return NextResponse.redirect(new URL('/login', request.url))
  }

  // 그냥 다음 단계로 진행하고 싶다면
  return NextResponse.next() // 원래 가려던 페이지로 요청 전달
}
```

## 3. 필수 포인트

| 항목                 | 설명                                                  |
| -------------------- | ----------------------------------------------------- |
| `middleware`         | 예약된 함수 이름 (변경하면 작동 안함)                 |
| `NextResponse`       | 응답을 만드는 객체 (next, redirect 등 메서드 제공)    |
| `request`            | 요청 정보 (URL, 헤더, 쿠키 등 포함됨)                 |
| `middleware.js` 위치 | 반드시 **루트 디렉토리** (`package.json`과 같은 폴더) |

## 4. 미들웨어 작동 원리

### 예를 들어 `/news` 페이지를 방문하면:

```jsx
브라우저는 /news, /favicon.ico, /이미지들 등 다양한 요청을 함께 보냄

모든 요청이 미들웨어를 거쳐 감

미들웨어에서 URL을 검사하여 조건에 맞게 처리하거나 리디렉션 가능
```

## 5. 요청 필터링하기 – `config.matcher`

```jsx
💡 어떤 요청에만 미들웨어를 적용할지 정할 수 있어요
```

### 예시: `/news` 경로만 필터링

```jsx
export const config = {
  matcher: ['/news'],
}
```

### 예시: 여러 경로 필터링

```jsx
export const config = {
  matcher: ['/news/:path*', '/profile/:path*'],
}
```

```jsx
:path* 는 해당 경로 하위 모든 경로를 의미함
```

## 6. 미들웨어의 활용 예시

| 기능                | 예시 설명                                     |
| ------------------- | --------------------------------------------- |
| 🔐 인증             | 로그인 안 했으면 `/login`으로 리디렉션        |
| 📊 로깅             | 요청 URL이나 IP 주소 콘솔에 출력              |
| 🌍 지역 리디렉션    | 한국 IP면 `/ko`, 미국 IP면 `/en`으로 리디렉션 |
| 🛑 특정 페이지 차단 | 블랙리스트 유저는 접근 불가                   |

## 7. 주의할 점

```jsx
app 폴더를 사용하지 않습니다 (middleware.js는 pages와 app 외부 루트에 있어야 함)

매 요청마다 실행되므로 너무 많은 로직은 넣지 말기

정적 파일(favicon, 이미지 등) 요청도 포함되니 matcher로 필터링 권장
```

## 요약

| 항목      | 설명                                                    |
| --------- | ------------------------------------------------------- |
| 목적      | 요청을 가로채서 검사, 리디렉션, 로그 등 수행            |
| 위치      | 프로젝트 루트 폴더에 `middleware.js` 파일 생성          |
| 함수 이름 | 반드시 `middleware`                                     |
| 리턴값    | `NextResponse.next()` 또는 `NextResponse.redirect()` 등 |
| 필터링    | `config.matcher`로 특정 경로만 적용 가능                |
