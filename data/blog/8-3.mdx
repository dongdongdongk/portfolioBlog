# { 프로퍼티별 사용 단위 }

## 1. CSS 단위의 종류와 소개

```jsx
픽셀(px):

		웹 요소의 크기를 고정된 크기로 설정할 때 사용합니다.

백분율(%):

		부모 요소의 크기에 비례해 크기를 설정할 때 사용합니다.

rem (root em):

		루트 폰트 크기를 기준으로 하는 단위로, 페이지의 최상위 요소(html)의 폰트 크기를 기준으로 계산됩니다.

em:

		부모 요소의 폰트 크기를 기준으로 계산되는 단위로, 상대적인 크기 설정에 유용합니다.

vh (viewport height):

		뷰포트(브라우저 창)의 높이를 기준으로 비율을 계산합니다. 예를 들어, 1vh는 전체 뷰포트 높이의 1%를 의미합니다.

vw (viewport width):

		뷰포트 너비를 기준으로 비율을 계산합니다. 1vw는 전체 뷰포트 너비의 1%를 의미합니다.
```

## 2. 각 단위의 적용 방법

### 예제 1: 폰트 크기 (font-size)

```jsx
픽셀(px): font-size: 16px;

		요소의 폰트 크기를 16px로 고정합니다.

rem: font-size: 1.5rem;

		루트 폰트 크기의 1.5배 크기로 폰트를 설정합니다. 루트 폰트 크기가 16px이라면, 결과적으로 24px 크기의 폰트가 설정됩니다.

em: font-size: 1.5em;

		부모 요소의 폰트 크기의 1.5배로 폰트를 설정합니다.
```

### 예제 2: 패딩 (padding)

```jsx
백분율(%): padding: 10%;

		부모 요소의 너비의 10%만큼 패딩을 설정합니다.

픽셀(px): padding: 20px;

		고정된 20px만큼 패딩을 설정합니다.
```

### 예제 3: 너비와 높이 (width, height)

```jsx
vh, vw:
```

```jsx
width: 50vw;

height: 50vh;
```

```jsx
뷰포트 너비의 50%와 뷰포트 높이의 50%만큼 요소의 너비와 높이를 설정합니다.

( 뷰포트 : 브라우저 창 )
```

# { 크기 계산과 단위 }

## 1. 절대 길이 (Absolute Lengths)

```jsx
절대 길이 단위는 화면 크기나 사용자의 설정과 상관없이 고정된 크기를 가지며, 그 중 가장 중요한 단위는 px입니다.
```

```jsx
픽셀(px):

		특징: 픽셀 단위로 설정한 크기는 사용자가 변경할 수 없으며, 화면 크기와 무관하게 고정된 크기를 유지합니다.
```

```jsx
font-size: 20px;

* 위 설정은 사용자가 폰트 크기를 변경하더라도 20px 크기를 유지합니다.
```

```jsx
다른 절대 길이 단위들:

		cm, mm 등은 존재하지만, 디스플레이에서는 실제 크기와 다르기 때문에 웹 개발에서는 사용하지 않습니다.
```

## 2. 뷰포트 길이 (Viewport Lengths)

```jsx
뷰포트 길이 단위는 웹 페이지가 표시되는 브라우저 창(뷰포트)의 크기를 기준으로 크기를 조절할 때 사용됩니다.
```

```jsx
vh (Viewport Height):

		뷰포트의 전체 높이를 기준으로 비율을 계산합니다.
```

```jsx
height: 50vh;

* 이 설정은 뷰포트 너비의 75%를 의미합니다.

vmin: 뷰포트 너비와 높이 중 작은 값을 기준으로 계산됩니다.

vmax: 뷰포트 너비와 높이 중 큰 값을 기준으로 계산됩니다.
```

## 3. 폰트 상대적 길이 (Relative Lengths)

```jsx
폰트 상대적 길이 단위는 부모 요소 또는 루트 요소의 폰트 크기를 기준으로 크기를 설정할 때 사용됩니다.
```

```jsx
rem (Root em):

		루트 요소(html)의 폰트 크기를 기준으로 계산됩니다.
```

```jsx
font-size: 1.5rem;

* 이 설정은 루트 요소의 폰트 크기의 1.5배 크기를 의미합니다.
```

```jsx
em:

		부모 요소의 폰트 크기를 기준으로 계산됩니다.
```

```jsx
font-size: 2em;

* 이 설정은 부모 요소의 폰트 크기의 2배 크기를 의미합니다.
```

## 4. 백분율 (%)

```jsx
백분율 단위는 주로 부모 요소를 기준으로 크기를 설정할 때 사용되며, 특정한 특성을 가지고 있습니다.
```

```jsx
% (백분율):

		부모 요소나 컨테이너 요소를 기준으로 크기를 계산합니다.
```

```jsx
width: 80%;

* 이 설정은 부모 요소 너비의 80%를 의미합니다.
```

## 컨테이닝 블록 이해

```jsx
컨테이닝 블록(Containing Block):

		백분율 단위가 적용될 때, 백분율의 기준이 되는 요소를 말합니다.

		보통은 부모 요소나 조상 요소가 컨테이닝 블록이 되며, width: 80%와 같은 설정은 부모 요소의 너비를 기준으로 계산됩니다.
```

# { % 단위의 원리 }

```jsx
% 단위는 주로 웹 요소의 크기나 위치를 상대적으로 설정할 때 사용됩니다.

이 단위가 무엇을 기준으로 작동하는지 이해하려면 다음 세 가지 핵심 규칙을 기억해야 합니다.
```

## 규칙 1: 컨테이닝 블록(Containing Block)

```jsx
% 단위는 컨테이닝 블록을 기준으로 합니다.

컨테이닝 블록은 특정 요소가 속한 부모 요소를 의미합니다.

예를 들어, 부모 요소의 너비가 100px이라면, 자식 요소의 너비를 10%로 설정하면 자식 요소의 너비는 10px이 됩니다.
```

## 규칙 2: Position 프로퍼티의 영향 ( `position: fixed )`와 % 단위

```jsx
position 프로퍼티는 % 단위가 어떤 기준을 참조하는지를 결정하는 중요한 요소입니다. 특히, position: fixed가 설정된 요소의 경우 기준이 달라집니다.


		Position: Fixed:

				이 설정이 적용된 요소는 **뷰포트(Viewport)**를 기준으로 합니다.

				뷰포트는 브라우저 창에서 웹 페이지가 표시되는 영역을 의미합니다.


				예시:

				내비게이션 바가 position: fixed로 설정되면, 너비가 100%일 때 이 너비는 뷰포트의 너비와 동일하게 설정됩니다.

				뷰포트 크기가 변하면 내비게이션 바의 크기도 그에 맞춰 변합니다.
```

## 규칙 3: 실습 예시

```jsx
예시 1: 내비게이션 바:

		내비게이션 바에 position: fixed와 width: 100%가 설정되면, 뷰포트 너비 전체를 차지합니다.

		뷰포트 크기를 줄이거나 늘리면, 내비게이션 바의 크기도 함께 조절됩니다.

예시 2: 너비 조정:

		내비게이션 바의 width를 50%로 변경하면, 바의 너비는 뷰포트 너비의 절반이 됩니다.

		뷰포트 크기가 변할 때마다 바의 크기도 그에 따라 변합니다.
```

# { `position: absolute`와 % 단위 }

## 컨테이닝 블록의 변화

```jsx
position: absolute가 설정된 요소는 컨테이닝 블록이 조상(Ancestor) 요소로 변합니다.

이 조상 요소는 보통 position: relative나 position: absolute로 설정된 가장 가까운 부모 요소입니다.
```

## 중요한 원리

```jsx
position:

		absolute인 요소의 % 단위는 해당 요소의 **컨테이닝 블록의 콘텐츠와 안쪽 여백(padding)**을 기준으로 합니다.

		예를 들어, 자식 요소의 너비를 50%로 설정했다면, 이 너비는 조상 요소의 콘텐츠와 안쪽 여백을 기준으로 절반이 됩니다.
```

## 실습 예시: 슬로건과 컨테이닝 블록

```jsx
슬로건의 설정:

		슬로건은 position: absolute로 설정되어 있습니다.

		이 슬로건의 부모 요소인 #product-overview는 position: relative로 설정되어 있습니다.

		이 부모 요소가 컨테이닝 블록이 됩니다.

컨테이닝 블록의 너비 조정:

		#product-overview의 너비를 기준으로 슬로건의 너비를 100%로 설정하면, 슬로건의 너비는 부모 요소의 너비와 동일해집니다.

		부모 요소의 너비를 50%로 조정하면, 슬로건의 너비도 50%로 줄어듭니다.

		즉, 슬로건의 너비는 부모 요소의 콘텐츠와 안쪽 여백을 포함한 너비의 50%가 됩니다.

Top, Bottom, Left, Right 값의 조정:

		슬로건의 bottom 값을 0%로 설정하면, 슬로건이 컨테이닝 블록의 아래쪽에 딱 붙게 됩니다.

		top을 50%로 설정하면, 슬로건이 컨테이닝 블록의 중앙에 위치하게 됩니다.
```

# { `position: static` 또는 `relative`와 % 단위 }

## 컨테이닝 블록의 기준

```jsx
컨테이닝 블록: % 단위는 가장 가까운 조상 블록 레벨 요소를 기준으로 합니다.

블록 레벨 요소란 기본적으로 div, section 등의 요소를 말합니다.
```

## 중요한 원리

```jsx
position: static 또는 relative인 요소의 % 단위는 해당 요소의 가장 가까운 조상 블록 레벨 요소의 콘텐츠를 기준으로 합니다.

이 경우 padding(안쪽 여백)은 기준에 포함되지 않고 콘텐츠만 기준으로 삼습니다.
```

## 실습 예시: 이미지 컨테이너와 컨테이닝 블록

```jsx
이미지 컨테이너 설정:

		testimonial__image-container 클래스는 width가 65%로 설정되어 있습니다.

		이 컨테이너의 부모인 testimonial 클래스는 position이 명시되어 있지 않거나 static으로 설정되어 있어, 블록 레벨 요소가 됩니다.

컨테이닝 블록의 너비 조정:

		testimonial 클래스의 너비가 912px이라면, testimonial__image-container의 너비 65%는 약 593px이 됩니다.

		이 너비를 100%로 변경하면 testimonial의 너비와 동일해집니다.

Padding의 적용:

		testimonial에 padding을 추가하면 콘텐츠 너비가 줄어들지만, % 단위는 여전히 콘텐츠의 너비만 기준으로 적용됩니다.

		예를 들어, testimonial의 너비가 892px로 줄어들면, testimonial__image-container의 너비는 50%로 설정할 경우 446px이 됩니다.

Position의 변경:

		testimonial__image-container의 position을 relative로 바꿔도 너비나 위치에는 영향을 주지 않습니다.

		이는 % 단위가 여전히 블록 레벨 조상의 콘텐츠를 기준으로 하기 때문입니다.

Display 속성의 변경:

		testimonial 클래스를 인라인 요소로 변경하면 규칙이 깨지며,

		더 이상 블록 레벨 요소가 아니기 때문에 컨테이닝 블록이 변경됩니다.

		이 경우, % 단위는 다음으로 가까운 블록 레벨 조상인 래핑 div를 기준으로 하게 됩니다.
```

## 비교 요약

```jsx
조상의 기준:

		absolute는 가장 가까운 position이 지정된 조상 또는 뷰포트를 기준으로 배치됩니다.

		relative는 자신의 원래 위치를 기준으로 합니다.

문서 흐름:

		absolute는 문서 흐름에서 벗어나고, 주변 요소에 영향을 주지 않습니다.

		relative는 문서 흐름에 그대로 남아 있으며, 자신의 위치를 기준으로 이동합니다.
```

# { `max-width`와 `min-width` 프로퍼티 }

## 1. 반응형 디자인과 이미지 크기 조정

```jsx
백분율(%):

		요소의 크기를 설정할 때 주로 사용되며, 컨테이닝 블록의 크기에 따라 상대적으로 크기가 조정됩니다.

		예를 들어, 이미지 컨테이너가 페이지 너비의 65%로 설정되면, 그 내부의 이미지도 그에 맞춰 크기가 조정됩니다.

문제점:

		페이지 크기가 커지면 이미지도 비례적으로 커지기 때문에 너무 큰 이미지가 표시될 수 있습니다.

		이를 방지하기 위해 최대 너비를 설정할 필요가 있습니다.
```

## 2. `max-width`와 `min-width` 프로퍼티

```jsx
max-width:

		요소의 최대 너비를 제한합니다. 예를 들어, max-width: 580px로 설정하면,

		이미지가 페이지 크기에 따라 커지더라도 580px 이상 커지지 않게 됩니다.

min-width:

		요소의 최소 너비를 제한합니다. 예를 들어, min-width: 350px로 설정하면,

		페이지 크기가 줄어도 이미지가 350px 이하로 작아지지 않게 됩니다.
```

# { ‘rem’과 ‘em’ }

## EM과 REM 단위에 대한 이해

```jsx
CSS에서 em과 rem은 폰트 크기를 기준으로 산출되는 상대적인 단위입니다.

이 단위들은 웹페이지의 요소들이 브라우저 설정이나 상위 요소의 폰트 크기에 따라 유동적으로 크기를 조정할 수 있도록 도와줍니다.
```

## EM 단위

```css
정의:

		em은 요소의 부모 요소로부터 폰트 크기를 상속받아, 그 크기를 기준으로 계산됩니다.

사용 예:

		font-size: 2em은 부모 요소의 폰트 크기에서 2배로 설정됩니다.

		예를 들어, 부모 요소의 폰트 크기가 20px이라면, 해당 요소의 폰트 크기는 40px이 됩니다.

문제점:

		em 단위는 상속된 크기에서 다시 상속이 이루어지므로,

		여러 번 중첩될 경우 의도치 않은 크기로 폰트가 커지거나 작아질 수 있습니다. 이는 계산이 복잡해져서 관리가 어려워질 수 있습니다.
```

## REM 단위

```css
정의:

		rem은 루트 요소(보통 <html> 요소)의 폰트 크기를 기준으로 계산됩니다.

사용 예:

		font-size: 2rem은 HTML 요소에 정의된 기본 폰트 크기에서 2배로 설정됩니다.

		보통 브라우저의 기본 폰트 크기는 16px이므로, 이 경우 폰트 크기는 32px이 됩니다.

장점:

		rem 단위는 상속을 받지 않기 때문에, 의도하지 않은 크기 변화가 발생하지 않습니다.

		페이지 전체의 크기를 유동적으로 조정하는 데 유리합니다.
```

## 실습 예시

```css
고정된 폰트 크기의 문제:

		페이지 내 텍스트가 브라우저 폰트 크기 설정에 반응하지 않는 문제를 해결하기 위해, 고정된 px 단위 대신 em이나 rem 단위를 사용합니다.

		예를 들어, testimonial 클래스의 폰트 크기를 20px에서 1.2em으로 변경하면, 부모 요소의 폰트 크기에 따라 유동적으로 변경됩니다.

em 단위의 문제점 해결:

		여러 요소가 em 단위를 상속받아 예상치 못하게 크기가 커지는 문제를 방지하기 위해 rem 단위를 사용합니다.

		예를 들어, testimonial__subtitle 클래스에서 1.1em 대신 1.1rem을 사용하면, 폰트 크기가 예상한 대로 루트 폰트 크기 기준으로 설정됩니다.

적용 결과 확인:

		rem 단위를 사용하여, 브라우저 설정에서 폰트 크기를 변경하면 모든 요소의 폰트 크기가 동적으로 조정됩니다.

		이는 사용자 경험을 향상시키는 데 도움이 됩니다.
```

# { rem 단위 활용하기 }

```css
rem 단위를 폰트 크기뿐만 아니라 다양한 CSS 프로퍼티에 적용하는 방법을 배웠습니다.

이로 인해 웹사이트의 크기와 공간이 브라우저 설정에 따라 유연하게 변화하도록 할 수 있습니다.
```

## 1. rem의 이해와 활용

```css
rem의 의미:

		rem은 root em의 약자로, HTML 요소의 초기 폰트 크기를 기준으로 계산됩니다.

		일반적으로 브라우저의 기본 폰트 크기는 16px이므로, 1rem은 16px을 의미합니다.

rem의 활용:

		폰트 크기뿐만 아니라 margin, padding과 같은 다른 CSS 프로퍼티에도 rem 단위를 적용할 수 있습니다.

		이를 통해 요소들의 크기가 브라우저의 폰트 크기 설정에 따라 유연하게 변하도록 할 수 있습니다.
```

## 2. 실습: rem 단위를 활용한 CSS 조정

```css
testimonial 클래스

		font-size:

				기존의 px 단위에서 rem으로 변경하여 더 동적인 폰트 크기를 구현했습니다.

		margin: margin:

				48px을 3rem으로 변경하여 브라우저 설정에 따라 동적으로 변하도록 설정했습니다.



		위아래 바깥쪽 여백 조정

				margin-bottom과 margin-top을 각각 3rem과 6rem으로 변경하여 요소 간 간격이 브라우저 설정에 따라 유동적으로 변하게 했습니다.


		.testimonial__info 클래스

				padding: padding: 14px을 0.9rem으로 변경하여 안쪽 여백도 동적으로 만들었습니다.


		기타 요소

				다른 요소들의 margin, padding 등을 px에서 rem으로 변경하여 전체적인 CSS를 더 동적으로 개선했습니다.
```

## 3. CSS 파일의 동적 처리

```css

		rem 단위의 사용은 페이지의 레이아웃과 스타일링을 더 유연하게 만듭니다.

box-shadow와 border:

		이들 프로퍼티는 rem으로 바꾸지 않고 px 단위를 유지하는 것이 더 적합할 수 있습니다.

		이는 해당 속성들이 폰트 크기에 비례해서 증가하거나 감소할 필요가 없기 때문입니다.
```

# { ‘rem’ 최종 정리 }

## 1. rem 단위의 활용

```css
rem은 root em의 약자로, HTML의 기본 폰트 크기를 기준으로 한 상대적인 단위입니다.

폰트 크기: 기본 폰트 크기가 16px일 때, 1rem = 16px, 2rem = 32px처럼 계산됩니다.

다른 속성에의 적용: rem 단위는 폰트 크기뿐만 아니라 margin, padding, width, height 등 다양한 CSS 속성에 적용할 수 있습니다.
```

## 2. rem 단위의 장점

```css
반응형 디자인:

		브라우저 기본 폰트 크기에 따라 레이아웃이 자동으로 조정되므로 반응형 웹 디자인에 적합합니다.

일관성 유지:

		사이트 전체에서 일관된 크기 조정을 쉽게 할 수 있어 유지보수가 용이합니다.
```

## 3. 특정 속성의 예외 처리

```css
border 및 box-shadow:

		rem 단위를 사용할 경우, 폰트 크기 변화에 따라 크기가 변동되는 것을 원치 않는 경우에는 px 단위를 유지하는 것이 좋습니다.

		이는 고정된 크기를 원하는 요소에 적합합니다.

border-radius:

		비슷한 이유로, 대부분의 경우 border-radius 역시 px 단위로 유지합니다.
```

# { 뷰포트 단위 ‘vw’와 ‘vh’ 이해하기 }

## 1. 뷰포트 단위(VW, VH, VMIN, VMAX)

```css
vw (Viewport Width):

		뷰포트 너비의 1%를 의미합니다. 예를 들어, 50vw는 뷰포트 너비의 50%를 차지합니다.

vh (Viewport Height):

		뷰포트 높이의 1%를 의미합니다. 예를 들어, 100vh는 뷰포트 높이의 100%를 차지합니다.

vmin:

		뷰포트의 너비와 높이 중 작은 쪽의 1%를 의미합니다. 따라서 vmin은 더 작은 쪽에 맞춰 크기를 조정합니다.

vmax:

		뷰포트의 너비와 높이 중 큰 쪽의 1%를 의미합니다. 따라서 vmax는 더 큰 쪽에 맞춰 크기를 조정합니다.
```

## 2. 뷰포트 단위 사용 예시

```css
백드롭(Backdrop):

		웹페이지를 덮는 배경 요소로, width: 100vw; height: 100vh;를 사용하여 화면 전체를 덮도록 설정할 수 있습니다.

이미지 크기 조정:

		고정된 픽셀 값을 뷰포트 단위로 변경하여 이미지가 화면 크기에 맞게 조정되도록 할 수 있습니다.

		예를 들어, height: 33vh;로 설정하면 뷰포트 높이의 33%를 이미지 높이로 설정합니다.
```

## 3. 뷰포트 단위의 장점

```css
반응형 디자인:

		뷰포트 단위를 사용하면 다양한 화면 크기에 대응하는 디자인을 쉽게 구현할 수 있습니다.

동적 조정:

		화면 크기에 따라 요소의 크기가 자동으로 조정되므로, 고정된 픽셀 값보다 더 유연한 디자인이 가능합니다.
```

## 4. 단점 및 고려 사항

```css
브라우저 호환성:

		대부분의 현대 브라우저는 뷰포트 단위를 지원하지만, 일부 예전 브라우저(예: Internet Explorer 11)는 vmax 단위를 지원하지 않으므로

		사용 전에 브라우저 지원 여부를 확인하는 것이 좋습니다.

대안:

		경우에 따라 뷰포트 단위 대신 position: fixed와 백분율 값을 사용하는 것이 더 적합할 수 있습니다.
```

## 5. 요약

```css
뷰포트 단위는 요소의 크기를 뷰포트 크기에 맞게 설정하는 데 유용합니다.

사용하기 전에 브라우저 호환성을 확인하고, 특정 상황에서는 다른 방법을 사용하는 것이 더 나을 수 있습니다.
```

## 백드롭을 만드는 두 가지 방법

### 1. **백분율(%)을 사용하는 백드롭**

```css
이 방법에서는 width와 height를 백분율로 설정하여 요소가 부모 요소의 크기에 따라 조정됩니다.
```

```css
.backdrop {
  position: fixed;
  top: 0;
  left: 0;
  z-index: 100;
  width: 100%;
  height: 100%;
  background: rgba(0, 0, 0, 0.5);
}
```

```css
width: 100%; height:

		100%;는 부모 요소의 크기에 비례하여 백드롭의 크기가 결정됩니다. 이 경우, 부모 요소는 기본적으로 뷰포트를 기준으로 설정됩니다.

position:

		fixed;로 설정되어 있기 때문에 뷰포트에 상대적으로 고정됩니다.
```

### 2. **뷰포트 단위(`vh`, `vw`)를 사용하는 백드롭**

```css
이 방법에서는 vh와 vw 단위를 사용하여 요소가 뷰포트의 크기에 따라 조정됩니다.
```

```css
.backdrop {
  position: fixed;
  top: 0;
  left: 0;
  z-index: 100;
  width: 100vw;
  height: 100vh;
  background: rgba(0, 0, 0, 0.5);
}
```

```css
width: 100vw; height:

		100vh;는 뷰포트의 너비와 높이에 비례하여 백드롭의 크기가 결정됩니다. 이 경우, 백드롭은 뷰포트 크기에 정확히 맞춰집니다.

position:

		fixed;로 설정되어 있어 요소가 뷰포트에 고정됩니다.
```

## 비교:

```css
백분율(%) 방법은 뷰포트가 아닌 부모 요소의 크기에 따라 조정될 수 있는 유연성을 제공합니다.

하지만 position: fixed;를 사용했기 때문에, 결국 뷰포트를 기준으로 작동하게 됩니다.

**뷰포트 단위(vh, vw)**는 뷰포트 크기를 직접적으로 참조하여 더 명확하게 뷰포트에 맞춰 크기를 조정합니다.

두 방법 모두 백드롭을 뷰포트 크기에 맞춰 설정하는 데 유용하지만,

vh와 vw를 사용하는 방법이 더 직관적이고 명확하게 뷰포트를 기준으로 조정됩니다.
```

## **Windows 기기에서 스크롤바 숨기기**

```css
Windows에서 작업할 경우, vw를 추가하면 스크롤바가 나타나는 것을 경험했을 것입니다. 스크롤바가 포함되지 않은 Windows에서 vw를 사용할 때 일어나는 현상입니다. - vw: 100 = 뷰포트 너비의 100% + 스크롤바 Mac에서는 문제가 없지만, Windows에서는 스크롤바가 자동으로 표시되는 문제가 발생합니다.

스크롤바를 표시하고 싶지 않은 경우, 다음 방법 중 하나를 활용하시면 됩니다.

- shared.css 파일에서 body 선택자에 overflow-x: hidden을 추가해 가로 스크롤바 숨기기 (세로 스크롤바를 숨기려면 overflow-y: hidden 추가)

body: :-webkit-scrollbar {
    width: 0
}
```

```css
대체 방법:

		margin 속성 대신 margin-left와 margin-right에 특정 백분율 값을 설정하여 수동으로 요소를 가운데 정렬할 수 있지만,

		margin: auto가 더 간편하고 직관적인 방법입니다.

주의사항:

		margin: auto는 항상 완벽한 해결책은 아니며, 주로 너비가 명시된 블록 레벨 요소에만 적용된다는 점을 기억해야 합니다.



* 좌우 가운데 정렬은 margin auto 가 되지만 상하 정렬은 flexbox 를 사용해야 한다
```
